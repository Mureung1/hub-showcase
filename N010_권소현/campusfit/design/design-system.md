# 캠퍼스핏 디자인 시스템

`prototype.html`에서 만든 화면(온보딩 2단계 → 메인 → 카테고리별 목록 5종 → 팀원모집 게시판 → 게시글 상세 → 지원 완료)에서 추출한 규칙. 개발 단계(React)에서 이 문서 + `design-tokens.css`를 그대로 기준으로 삼는다.

**온보딩엔 "관심분야" 단계가 없다.** 처음엔 관심분야를 따로 고르게 했는데, 그러면 메인 화면
카테고리 6개와 똑같은 선택을 두 번 하게 돼서 삭제했다 (2026-07-09). 온보딩은 국립/사립 · 지역
2단계로 끝나고, 카테고리는 메인 화면에서 바로 클릭해 들어간다 — "고르기"와 "둘러보기"를 분리하지 않는다.

**웹사이트다, 모바일 앱이 아니다.** 처음엔 380px 폰 카드 프레임으로 만들었다가 "너무 앱 같다"는
피드백을 받고 상단 네비게이션 + 넓은 페이지 레이아웃으로 다시 만들었다 (2026-07-09). 이후 화면을
추가할 때도 폰 프레임으로 되돌아가지 않는다.

**넓혀도 내용물이 작으면 소용없다.** 1차로 페이지 폭만 넓혔더니, 실제로는 그 안의 카드·글자
크기가 그대로라 넓은 화면에 작은 카드 하나만 덩그러니 있고 나머지가 빈 백지로 남았다 — 여전히
"앱 화면을 넓은 브라우저에 띄워놓은 것"처럼 보였다. 그래서 타이포를 한 단계씩 키우고
(제목 18→28px), 온보딩을 좌우 2단(질문 폼 + 설명 카피)으로 바꾸고, 메인 카드에 설명 문구를
추가하고, 상단 네비게이션에 실제 메뉴를 넣어 빈 공간을 의도적으로 채웠다 (2026-07-09 2차 개정).

## 색상 역할

| 토큰 | 역할 | 쓰는 곳 / 쓰지 않는 곳 |
|---|---|---|
| `--bulb` | 브랜드 primary | 주요 버튼(`.btn`), 선택된 상태, 강조 pill. 화면당 강조는 이 색 하나로 통일 |
| `--alert` | 마감 임박 전용 경고 | `D-3`처럼 7일 이내 마감에만 사용. 그 외 상황엔 쓰지 않는다 (색의 의미가 흐려짐) |
| `--card` | 은은한 강조 배경 | 팀원모집처럼 "다른 성격의 카드"를 표시할 때만. 일반 카드엔 `--paper` |
| `--ink / --ink-soft / --ink-faint` | 텍스트 위계 | 제목/본문/캡션 3단계로만 나눈다. 임의 회색 추가 금지 |

## 타이포 & 형태

- 폰트: Pretendard (한글), 폴백은 시스템 산세리프
- 제목(h1): 28px / 700 (2026-07-09 18px에서 상향 — 넓은 화면 기준으로 존재감을 키움)
- 온보딩 카피 제목(h2): 32px / 800
- 본문: 14~15px, 캡션: 12~12.5px (2026-07-09 1px씩 상향)
- 카드/버튼 radius: 10~14px, 온보딩 폼 카드 radius: 16px — 반경 두 단계로만 통일
- 카드/옵션 테두리: `1px solid var(--line)`, hover 시 `var(--bulb)`로 전환 (별도 그림자 없음)

## 레이아웃 구조 (웹사이트 셸)

- **상단 네비게이션(`.topnav`)**: 화면 전체 폭. 로고 + 실제 메뉴(홈/팀원모집)가 있는 바 —
  로고만 있으면 허전해서 앱 헤더처럼 보인다. 모든 화면에서 항상 보임.
- **페이지 컨테이너(`.page`)**: `max-width: 1040px`, 중앙 정렬. 실제 콘텐츠는 이 안에서만 배치.
- **온보딩 화면(`.screen.onboard`)**: `max-width: 960px`, 좌우 2단 그리드(`1fr 1fr`) —
  왼쪽은 질문 폼(`.onboard-form`, 카드형), 오른쪽은 설명 카피(`.onboard-copy`, 카드 없이 텍스트만).
  860px 이하에서는 1단으로 접히고 카피가 폼 아래로 내려간다(`order:2`). **주의**: 화면 전환은
  `:checked ~ #scr-id{display:block}` 규칙에 의존하는데, `.onboard`는 `display:grid`가 필요하다
  — 두 규칙을 한 셀렉터에 섞으면 나중 규칙이 이겨서 grid가 깨진다(2026-07-09에 실제로 겪음).
  onboard 두 개는 `display:grid`, 나머지는 `display:block`으로 셀렉터를 분리해서 쓴다.
- **목록형 화면(`.screen.reading`)**: 카테고리 목록·팀원모집 게시판·상세처럼 읽는 화면은
  `max-width: 680px`로 좁혀서 가독성 확보. 그리드가 필요한 메인 화면만 페이지 폭을 그대로 씀.
- 640px 이하에서는 지역 선택 그리드가 3열 → 2열로 줄어드는 정도만 반응형으로 처리 (레이아웃 골격은 유지).

## 컴포넌트 패턴

- **pill**: 상태/필터 배지. `--bulb-soft` 배경 + `--bulb-ink` 텍스트가 기본, 경고는 `--alert-soft`/`--alert-ink`
- **row**: 목록의 한 줄 (제목 + 보조텍스트 + 우측 메타). 카테고리 목록, 마감 임박 리스트에 재사용
- **post-card**: row보다 무거운 카드형 목록 아이템 (팀원모집 게시글처럼 클릭해서 상세로 들어가는 경우)
- **btn / btn-line / btn-ghost**: 강조 3단계 — 확정 행동(지원하기 등) / 보조 행동(공식 페이지 확인) / 건너뛰기같은 최소 강조
- **option-grid**: 지역처럼 선택지가 많을 때(17개 시·도) 세로로 길게 나열하지 않고 3열 그리드로 배치.
- **cat-card**: 메인 화면 카테고리 카드. 제목만 있는 라벨이 아니라 `.cat-card__title` +
  `.cat-card__desc`(한 줄 설명) 세트로 구성 — 이름만 봐서 뭔지 바로 안 와닿는 카테고리도
  설명 한 줄로 채운다. `minmax(220px,1fr)` 그리드라 넓은 화면에서 자연스럽게 여러 열로 늘어난다.
- **row.link (공식 페이지 이동)**: 팀원모집이 아닌 일반 공고는 인앱 상세 화면이 없다 — 기획서대로
  "공식 페이지"로 나가는 게 원래 설계다. 그런 행은 `.row`에 `.link` 클래스를 더하고 제목 옆에
  `<span class="ext">↗</span>`을 붙여서 "여기서 끝나는 화면이 아니라 밖으로 나간다"는 걸 표시한다.
  반대로 팀원모집 배지가 붙은 행은 인앱 게시판으로 가는 거라 `↗`를 붙이지 않는다 — 아이콘 하나로
  "여기 남는다 / 나간다"를 구분하는 규칙이니 섞어 쓰지 않는다.

## 원칙 (기획서에서 그대로 이어짐)

1. **조건에 안 맞는 정보는 애초에 안 보여준다** — 화면에 "필터"라는 개념을 강조하지 않고, 온보딩 이후엔 이미 걸러진 목록만 보여준다.
2. **마감 임박은 항상 상단에, 항상 같은 pill 스타일로** — 사용자가 놓치면 안 되는 정보이므로 시각 언어를 하나로 고정.
3. **팀원모집은 "다른 서비스"처럼 보이면 안 된다** — 같은 토큰만 쓰고, 구분은 `--card` 배경 하나로 충분히 한다.
4. **화면마다 강조색은 하나** — `--bulb`와 `--alert`를 동시에 남발하지 않는다.
5. **카테고리 5개는 실제로 다른 화면·다른 데이터로 이어진다** — 프로토타입이라도 진입점마다 결과가
   같으면 안 된다 (처음엔 5개 카드가 전부 같은 "공모전" 화면으로 연결되는 실수가 있었다).
6. **필터링은 "카테고리를 보여줄지"가 아니라 "카테고리 안 목록에" 적용된다** — 장학금·공모전 같은
   내비게이션 카테고리 자체는 항상 다 보인다. 조건(국립/사립·지역)으로 걸러지는 건 그 안의
   개별 공고 목록이다. 온보딩에 관심분야 단계를 넣어 카테고리 자체를 걸렀던 게 이 원칙과
   충돌해서 삭제했다.
7. **지원 방법은 두 가지뿐이다** — 팀원모집 공고만 인앱 게시판(댓글 지원), 나머지는 전부 공식
   페이지로 나간다. 일반 공고에 인앱 상세 화면을 새로 만들지 않는다.
8. **넓은 화면에서 내용물이 빈 공간에 비해 너무 작으면 안 된다** — 컨테이너 폭만 넓히고
   안의 글자·카드 크기를 그대로 두면 여전히 앱처럼 보인다. 화면을 넓힐 땐 타이포·카드
   크기·콘텐츠 밀도를 같이 키운다.

## 아직 안 만든 화면 (다음 디자인 세션에서)

- 사장님(운영자) 화면 없음 — 캠퍼스핏은 학생 전용 서비스라 해당 없음
- 지원 확정 후 게시글 상태 변화(예: "모집 마감" 뱃지)
- 마이페이지 / 온보딩 조건 재설정 화면
