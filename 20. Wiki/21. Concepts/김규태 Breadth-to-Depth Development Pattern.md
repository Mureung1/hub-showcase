# 김규태 Breadth-to-Depth Development Pattern

## Current State

김규태는 관심 분야가 많고 넓게 아는 반면 한 가지를 깊게 파고드는 힘이 부족하다고 본다. T자형 인재가 되고 싶어 Python 알고리즘 문제를 공부하고 있다.

알고리즘의 역할은 두 가지다.

- 대기업 코딩 테스트라는 취업 관문 통과
- 컴퓨팅 사고, 문제 분해, 문제 해결 과정을 훈련하는 기본기

알고리즘은 중요한 기반이지만 그 자체가 장기 전문 분야로 확정된 것은 아니다.

## Provisional Vertical Axis

현재 세로축 후보는 **AI 에이전트를 이용한 개발**이다. 그러나 사용자가 "아직 자세히는 모르겠다"고 확인했으므로 확정 전문성으로 표시하면 안 된다. 지금은 탐색 가설이다.

## Development Risk

- 프로젝트를 여러 개 시작하면서 학습 깊이를 착각할 수 있다.
- AI가 구현 세부를 대신하면 결과물 수와 직접 설명 가능한 깊이가 분리될 수 있다.
- 코딩 테스트 점수가 올라도 제품 개발·운영 전문성이 자동으로 생기지는 않는다.

## Evidence Needed

- 한 시스템을 수개월 유지하며 설계 변경 이유를 기록한 사례
- AI 없이 핵심 알고리즘이나 기능을 구현하고 설명한 기록
- 실패 원인과 성능·품질 변화를 직접 측정한 기록
- AI 에이전트 개발 안에서 어느 문제를 전문적으로 풀 것인지에 대한 정의

## Current Rule

새 프로젝트를 추가할 때는 "현재 세로축을 깊게 하는가, 단순히 관심 폭만 넓히는가"를 먼저 묻는다. 세로축이 확정되기 전에는 `AI 에이전트 개발 탐색 중`으로 표현한다.

> [!note] Bias Check
> Counter-argument: 넓은 관심은 초기 경력에서 탐색 자산이 될 수 있으므로 성급하게 한 분야를 고정하면 오히려 기회를 줄일 수 있다.
> Data gap: 각 분야에 투입한 시간과 산출물의 질을 비교한 기록이 없다.
