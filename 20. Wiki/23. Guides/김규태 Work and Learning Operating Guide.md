# 김규태 Work and Learning Operating Guide

## Observed Working Style

- 마감이 멀 때 낙천적으로 미루고 직전에 몰입한다.
- 최소요건을 먼저 맞추려는 성향이 있어 빠른 MVP에는 유리하다.
- 늦게 시작해 수면을 줄이고, 미리 시작했으면 결과물 품질이 더 좋았을 것이라고 반복해서 느낀다.
- 한 번 만든 결과물 위에 다음 날 다시 쌓는 방식이 완성도를 높인다고 믿는다.
- 실제 사용자 반응이나 수치가 보이면 유지보수 동기가 높아진다.
- 어려운 알고리즘 문제가 풀리지 않으면 침대에서 YouTube를 보며 회피하기 쉽다.

## Recommended Operating Loop

### Before Starting

1. 최소요건과 최종 품질 기준을 분리한다.
2. 첫 제출 가능 버전을 마감보다 앞선 개인 마감으로 둔다.
3. 개선 회차를 처음부터 작업으로 계산한다.

### During Work

1. 문제를 작게 분해하고 현재 막힌 지점을 한 문장으로 기록한다.
2. AI에게 맡긴 일, 본인이 판단한 일, 직접 검증한 일을 분리한다.
3. 사용자 반응이 없는 학습에서는 시간·정답률·재풀이 성공률을 가시적 지표로 만든다.

### After Completion

1. 완료와 유지보수를 분리 평가한다.
2. 다음 날 다시 봤을 때 바꾼 점을 기록한다.
3. 반복되는 실패 원인을 다음 작업의 체크리스트로 승격한다.

## Algorithm Study Role

알고리즘 공부는 취업 관문이면서 컴퓨팅 사고 훈련이다. 정답 수만 세기보다 다음을 남겨야 장기 깊이로 이어진다.

- 처음 접근이 막힌 이유
- 문제를 어떤 하위 문제로 분해했는지
- 사용한 자료구조·알고리즘의 선택 근거
- 다음 날 AI 없이 다시 풀 수 있는지

## Failure Trigger

문제가 풀리지 않을 때 YouTube를 켜는 행동은 단기 회복일 수도 있지만, 복귀 시점이 정해져 있지 않으면 회피다. 휴식 전에 다시 시작할 시간과 첫 행동을 정해야 한다.

> [!note] Bias Check
> Counter-argument: 사용자가 아직 이 운영 루프를 실제로 지속했다고 확인하지 않았으므로 현재 습관이 아니라 권장 실험이다.
> Data gap: 주간 계획 준수율, 알고리즘 재풀이율, 수면 변화, 마감 전 첫 버전 완료율을 측정해야 한다.
