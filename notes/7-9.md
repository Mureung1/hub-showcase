## 2. Round Trip

### 2.1. step by step
 1. something happen (click or etc)
 2. request : FE request HTTP to server
 3. operation : BE operate verification or follow by logic 
 4. inquiry : BE ask data to DB (SQL)
 5. DATA : return the result
 6. response : BE send JSON to FE
 7. 갱신 : rewrite the interface

#### 6.1.1. what is SQL

**SQL (Structured Query Language)**은 관계형 데이터베이스(RDB)에 저장된 데이터를 조회·추가·수정·삭제하기 위한 언어입니다. JS나 Python 같은 범용 프로그래밍 언어와 달리 **선언형(declarative)**이에요 — "어떻게 찾아라"가 아니라 "무엇을 원한다"만 적으면 DB 엔진이 알아서 최적의 방법으로 실행합니다.

7-9.md 노트의 Round Trip 흐름 기준으로 보면:

2. request  : FE → HTTP → BE
3. operation: BE가 로직 처리
4. inquiry  : BE → SQL → DB          ← 바로 여기
5. DATA     : DB → BE
6. response : BE → JSON → FE

노트에 이미 써둔 todos API 예시를 SQL로 이어보면:

POST /api/todos {"text": "장보기"}
  → BE 내부: INSERT INTO todos (text) VALUES ('장보기');

GET /api/todos
  → BE 내부: SELECT * FROM todos;

DELETE /api/todos/:id
  → BE 내부: DELETE FROM todos WHERE id = ?;

즉 FE는 SQL을 절대 모릅니다. FE는 JSON만 주고받고, "JSON ↔ SQL row" 변환은 전부 BE 담당이라는 게 핵심(6.1에 적으신 "server ↔ DB : SQL"이 정확히 이 뜻).

퀀트투자 상황 예시

퀀트 워크플로우에서는 보통 가격 데이터·재무 데이터를 DB(PostgreSQL, 또는 시계열 특화 TimescaleDB/ClickHouse)에 쌓아두고 SQL로 뽑아 씁니다.

1) 특정 종목 기간 조회
SELECT date, close
FROM prices
WHERE ticker = '005930'
  AND date BETWEEN '2024-01-01' AND '2024-12-31'
ORDER BY date;

2) 이동평균 (window function으로 SQL 안에서 계산)
SELECT date, close,
       AVG(close) OVER (ORDER BY date ROWS BETWEEN 19 PRECEDING AND CURRENT ROW) AS ma20
FROM prices
WHERE ticker = '005930';

3) 팩터 스크리닝 (가격 테이블 + 재무 테이블 JOIN)
SELECT p.ticker, p.close, f.per, f.pbr
FROM prices p
JOIN fundamentals f ON p.ticker = f.ticker AND p.date = f.date
WHERE f.per < 10 AND f.pbr < 1;

4) 백테스트 결과 집계
SELECT strategy_id, SUM(pnl) AS total_pnl, AVG(pnl)
FROM backtest_results
GROUP BY strategy_id
ORDER BY total_pnl DESC;

### 6.2. Brwoser
- Browser : 화면을 그리는 프로그램 (Chrome, Safari, Edge …)

- JS Engine : 브라우저 안에서 JS를 실행 (Chrome = V8)

- HTML · CSS · JS : 웹의 3요소 — 구조 / 스타일 / 동작

- React : FE 화면을 효율적으로 그리는 대표적인 JS 라이브러리

### 6.3. server 
- Web Server : 요청을 받는 입구이자 정적 파일 전달 (Nginx, Apache)

- WAS (Web Application Server) : 로직을 실행해 동적 응답을 만드는 곳

- 우리 스택 = Node.js(런타임) + Express(프레임워크)

- Java 진영 = JVM + Spring

- Runtime (Node.js) : 브라우저 밖에서 JS를 실행하는 환경

- DB : 데이터를 저장 (PostgreSQL / Supabase, MySQL …)
