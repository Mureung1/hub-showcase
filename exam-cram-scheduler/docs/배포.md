# 배포 가이드

FE(React)는 **Vercel**, BE(Express)는 **Render**, 참고 데이터는 **Supabase**에 올린다.
이 문서는 각 서비스에 넣을 설정과 환경변수 이름, 배포 후 검증 절차를 정리한 것이다.
(관련 이슈: #30 FE 주소 env화 · #31 CORS · #32 배포 설정 · #33 실제 배포·검증)

## 저장소 구조 주의

이 프로젝트는 저장소(`hub`) 루트가 아니라 `exam-cram-scheduler/` 안에 있다. 그 안에 다시
`client/`(FE)와 `server/`(BE)가 있으므로, **배포 서비스마다 기준(루트) 폴더를 깊은 경로로
지정**해야 한다.

```
hub/                          ← 깃 저장소 루트
└── exam-cram-scheduler/
    ├── client/               ← Vercel 기준 폴더
    └── server/               ← Render 기준 폴더
```

---

## 1. Vercel (FE)

| 항목 | 값 |
|---|---|
| Root Directory | `exam-cram-scheduler/client` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Framework Preset | Vite |

- 새로고침·딥링크 시 404를 막는 SPA rewrite는 [client/vercel.json](../client/vercel.json)에
  이미 들어 있다(모든 경로 → `/index.html`). React Router가 index.html 로드 후 경로를 처리한다.

### Vercel 환경변수

| 이름 | 값 | 비고 |
|---|---|---|
| `VITE_API_BASE_URL` | 배포된 Render 서버 주소 (예: `https://exam-cram-api.onrender.com`) | 비우면 상대경로로 나가 배포에선 BE에 못 닿음 |

---

## 2. Render (BE)

Render는 `render.yaml`을 저장소 루트에 둬야 해서 다른 프로젝트와 섞이므로, **대시보드 설정**으로 잡는다.

| 항목 | 값 |
|---|---|
| Root Directory | `exam-cram-scheduler/server` |
| Build Command | `npm install && npm run build` |
| Start Command | `npm start` (= `node dist/index.js`) |
| 포트 | 지정 안 함 — Express가 `process.env.PORT`를 그대로 사용 |

### Render 환경변수

| 이름 | 값 | 비고 |
|---|---|---|
| `CLIENT_ORIGIN` | 배포된 Vercel 주소 (예: `https://exam-cram.vercel.app`) | CORS 허용 출처. 비우면 모든 출처 허용(개발용) |
| `SUPABASE_URL` | Supabase 프로젝트 URL | 🔒 비밀 |
| `SUPABASE_ANON_KEY` | Supabase anon key | 🔒 비밀 |
| `PORT` | (설정 불필요) | Render가 자동 주입 |

> 🔒 표시는 실제 비밀이라 GitHub에 올리면 안 되는 값. `.env`는 gitignore돼 있고, 값은 각
> 서비스 대시보드에만 넣는다.

## 3. 배포 순서 (닭·달걀 문제)

FE는 BE 주소가 필요하고, BE는 FE 주소가 필요하다. 그래서 한 번에 안 되고 순서가 있다.

1. **Render(BE) 먼저 배포** → 서버 주소 확보. (`CLIENT_ORIGIN`은 아직 비워두거나 임시로 둠)
2. 그 주소를 **Vercel `VITE_API_BASE_URL`** 에 넣고 FE 배포 → FE 주소 확보.
3. FE 주소를 **Render `CLIENT_ORIGIN`** 에 채우고 BE 재배포.

## 5. 실제 배포에서 겪은 문제와 해결 (2026-07-28, #33)

첫 배포를 실제로 돌리며 막혔던 지점 3가지. 다음에 재발하지 않게 기록한다.
(결과: FE `https://hub-dodeho1.vercel.app`, BE `https://exam-cram-api.onrender.com` 로 배포 완료. `/health`·`/health/db` 응답, 화면에서 "계산하기" → BE·Supabase 왕복까지 확인.)

### 문제 1 — 서버가 Supabase 키 없이는 부팅 자체가 안 됨

- **증상**: Render 첫 배포에서 `Error: SUPABASE_URL / SUPABASE_ANON_KEY가 .env에 설정되어 있지 않습니다.` 로 실패.
- **원인**: 위 2장은 "Supabase 키는 3장에서 나중에"라고 미뤄뒀지만, 계산 API가 `supabaseClient`를 **정적 import**한다
  (`index.ts → scheduleCalculate.ts → referenceData.ts → supabaseClient.ts`). `supabaseClient.ts`는 **모듈 로드 시점에** 키가
  없으면 `throw`하므로, 서버가 부팅되는 순간 이 사슬이 로드되며 죽는다. (`/health/db`만 동적 import라 안전할 뿐, 계산 API는 아님.)
  즉 `CLIENT_ORIGIN`처럼 "없어도 뜨는" 값이 아니라, **Supabase 키는 부팅 선결조건**이다.
- **해결**: Render **Environment에 `SUPABASE_URL`·`SUPABASE_ANON_KEY`를 먼저** 넣고 재배포. 값은 로컬 `server/.env`의 것을
  그대로 옮기면 된다(이미 3주차에 만든 프로젝트라 테이블·데이터도 존재).

### 문제 2 — `main`은 옛 구조라 배포하면 안 됨

- **증상**: Vercel Root Directory 탐색기에 `exam-cram-scheduler` 폴더가 안 보임 / main으로 빌드 시 `sh: line 1: vite: command not found`(exit 127).
- **원인**: `main`은 앱을 `exam-cram-scheduler/` 아래로 재정리하기 **전의 옛 구조**(앱이 저장소 루트에 흩어져 있음)다. 실제 앱은
  작업 브랜치 **`N110_안정연`** 에만 있다. main을 빌드하면 옛 루트 앱을 잡아 실패한다.
- **해결**: 배포 대상 브랜치를 **`N110_안정연`** 으로 지정.

### 문제 3 — Vercel은 import 시 기본 브랜치(main)를 강제

- **증상**: Render는 서비스 생성 폼에서 Branch를 바로 고를 수 있었지만, **Vercel은 import 화면에서 브랜치를 못 고르고
  기본 브랜치(main)로 첫 배포**를 만든다.
- **해결**:
  1. 일단 첫 배포를 진행한다(main이라 실패해도 **프로젝트 자체는 생성**됨).
  2. **Settings → Environments → Production → Branch Tracking** 을 `N110_안정연` 으로.
  3. **Settings → Build and Deployment → Root Directory** 를 `exam-cram-scheduler/client` 로.
  4. `N110_안정연` 에 **새 커밋을 push**해 프로덕션 배포를 트리거한다. (Deployments의 **Redeploy는 "같은 커밋 재빌드"**라
     브랜치가 안 바뀌므로 이 목적엔 쓸 수 없다 — 반드시 새 push.)
  - 기본 브랜치를 바꾸는 방법(GitHub Settings → Branches)도 되지만, 포크 기본 브랜치를 옮기고 싶지 않으면 위 방법을 쓴다.

### 연결(CORS)

- Render `CLIENT_ORIGIN` = `https://hub-dodeho1.vercel.app`(Vercel **고정 대표 주소**. 배포마다 바뀌는 해시 주소가 아니라
  이 주소로 통일해야 접속 출처와 CORS 허용 출처가 어긋나지 않는다).
- FE→BE가 다른 출처라 브라우저가 먼저 **preflight(OPTIONS)** 를 보낸다. Network 탭에 `preflight 204` + `calculate 200`이
  같이 보이면 CORS 통과 + 요청 성공이라는 뜻(같은 출처면 preflight가 아예 안 뜬다).
