# 계산 모델 리서치 노트

> 계산 엔진(Two-Process Model + 카페인 상호작용 모델) 구현을 위해 논문들을 찾아본 기록. 아직 완성된 스펙이 아니라 **진행 중인 리서치 메모**이며, 실제 구현 전 빈 곳을 마저 채워야 한다.



## 1. 확보한 수식

### Process S (수면압, homeostatic process)

```
자는 동안:    H(t) = H₀ · e^((t₀−t)/χs)          χs = 4.2시간
깨어있는 동안: H(t) = μ + (H₀−μ) · e^((t₀−t)/χw)   χw = 18.2시간, μ = 1(상한)
```
- H₀⁻ = 0.17 (수면→각성 전환 임계값의 기준점)
- 출처: Two-Process Model 표준형 (Daan, Beersma, Borbély 1984 계열), arXiv 1311.1734에서 확인

### Process C (일주기리듬, circadian process) — 용도별로 두 버전이 있음

**(a) 수면/각성 "시각"을 정할 때 (임계값 게이팅용)**
```
C(t) = sin(ω(t−α))     ω = 2π/24
전환 임계값: H⁺(t) = H₀⁺ + a·C(t),  H⁻(t) = H₀⁻ + a·C(t)     a = 0.10(진폭)
```

**(b) "각성도 수치" 자체를 예측할 때 (우리 프로젝트가 필요한 쪽)**
5개 하모닉(배음)을 더한 형태:
```
C(t) = a₁sin(2πt/τ + Φ) + a₂sin(4πt/τ + Φ) + ... (5개 항)
a₁=0.97, a₂=0.22, a₃=0.07, a₄=0.03, a₅=0.001
τ ≈ 24시간, Φ = 위상(개인차 있음, 정확한 기준값 미확인)
```

**Φ(위상) 값 확정 (2주차 화요일, 2026-07-13)**

논문 계열(arXiv 1311.1734)에서도 Φ(원문 표기 α)는 "논문마다 고정된 하나의 숫자가 아니라, 원하는 기상 시각에 맞게 각자 조정해서 쓰는 값"이라고 되어 있어 직접 정하기로 함. 공개 자료 기준 **몸의 심부체온이 가장 낮은 시각(≈새벽 4시)에 각성도도 함께 최저점**을 찍는다는 게 여러 자료에서 일관되게 확인돼서, 5개 하모닉을 전부 더한 곡선의 최저점이 새벽 4시에 오도록 역산했다.

- a1(기본음) 하나만 고려한 계산으로는 최저점이 2.4시로 어긋남 — a2(=0.22)가 무시 못 할 크기라 실제로는 5개 항을 다 더한 상태로 최적값을 탐색해야 함
- 탐색 결과: **Φ = −π**, 이때 최저점 4.0시 / 최고점 20.0시(늦은 저녁)로 계산됨 — "각성도 최고점은 이른 저녁"이라는 공개 자료 내용과도 부합
- 출처: 심부체온·각성도 최저점 관련 — https://www.ncbi.nlm.nih.gov/books/NBK331/ , https://pmc.ncbi.nlm.nih.gov/articles/PMC10225333/

### 결합 공식 (카페인 없을 때 기본 각성도)
```
P₀(t) = S(t) + κ·C(t)
```

**κ 값 근사 확정 (2주차 화요일, 2026-07-13)**

Ramakrishnan et al. (2016) 논문 원문(PMC, bhsai.org PDF 둘 다 시도)에서 κ의 정확한 수치를 다시 찾아봤지만, Table 3 수치 자체가 텍스트로 추출되지 않아 **이번에도 확보 실패**. 대신 같은 논문 계열의 "게이팅용" 버전(위 (a))에 나온 일주기 진폭 a=0.10을 참고해서, 일주기 리듬이 수면압(0~1 범위)을 압도하지 않으면서도 의미 있게 흔들리는 크기로 **κ = 0.2**를 근사치로 채택했다.

- **⚠️ 근거 없는 근사치.** 2B-Alert Web 비교 검증에서 결과가 이상하면 이 값부터 조정한다.
- 시도한 출처: https://pmc.ncbi.nlm.nih.gov/articles/PMC5020365/ (Table 3 참조만 있고 수치 미표시), https://bhsai.org/pubs/Ramakrishnan_2016_A_Unified_Model_of_Performance.pdf (PDF 표 추출 실패)

**⚠️ S(t) 부호 반전 필요 (구현 중 발견, 2026-07-13)**

노트의 수식을 그대로 구현(Process S의 H(t)를 그대로 더함)했더니 "깨어있을수록 각성도가 높다"는 반대 결과가 나옴. 실제 구현에서는 **P₀(t) = (1 − S(t)) + κ·C(t)** 로 S(t)를 뒤집어서 사용한다 — H(t)는 "피로도"(클수록 피곤함)라서, 각성도로 쓰려면 여력(1−피로도)으로 바꿔야 함. 원 논문에서 말하는 "S(t)"가 우리가 구현한 H(t)와 정확히 같은 정의인지, 아니면 처음부터 여력 개념인지는 확인 못 했지만(유료 논문), 결과가 훨씬 타당해서 이렇게 확정.

### 수면 관성 (Process W, 검증 중 발견해서 추가)

원 리서치 노트(1장)엔 없던 항인데, **기상 직후엔 각성도가 오히려 낮았다가 서서히 회복된다**는 실제 현상(수면 관성, sleep inertia)이 반영이 안 되어 있는 걸 검증 중 확인해서 추가했다(2026-07-13).

```
Inertia(t) = −W · e^(−Δt/τ)      Δt = t − 기상시각 (자는 동안·Δt<0이면 0)
P₀(t) = (1 − S(t)) + κ·C(t) + Inertia(t)
```

| 파라미터 | 값 | 근거 |
|---|---|---|
| τ (시간상수) | 0.67시간(≈40분) | Jewett & Kronauer (1999) — 주관적 각성도 기준 시간상수. 완전히 사라지는 데는 2~4시간 걸린다고도 확인됨 |
| W (최대 하락폭) | 0.3 | **근거 없는 근사치.** 얼마나 깊게 떨어지는지에 대한 구체적 수치는 논문 초록/요약 수준에선 못 찾음 |

- 출처: https://onlinelibrary.wiley.com/doi/10.1111/j.1365-2869.1999.00128.x (초록만 확인, 시간상수만 인용 가능)
- 검증: 23시 취침·7시 기상 예시로, 기상 직후 0.405 → 15분 후 0.493 → 30분 후 0.552 → 1시간 후 0.617 → 2시간 후 0.658(거의 회복)로 확인

### 카페인 효과 결합 (UMP)
```
P(t) = P₀(t) × gPD(t, c)
```
- `gPD`: 카페인 효과 인자(0~1), Hill 방정식 기반이라고 언급되나 **정확한 수식 아직 못 찾음**
- 관련 파라미터로 M0(용량 효과 크기), k0(기본 제거율), z(용량-지속시간 관계), ka(흡수율, 캡슐 2.06/h vs 껌 3.21/h)가 언급됨

### 다중 시험 최적화 알고리즘 (Vital-Lopez 2024, 초록 수준만 확인)
- SciPy류 최적화 라이브러리가 아니라 **직접 반복문으로 후보를 시도해보는 방식**(iterative modification)
- 카페인 투약 후보 12가지 × 수면시간표 후보 8가지를 매 반복마다 평가, 최대 600회 반복
- 제약 조건: 카페인 100/200/300mg만 허용, 정시(on the hour) 투약만, 최소 투약 간격 2시간, 수면시간은 0.5시간 단위

## 2. 카페인 근사 모델 최종 확정 (2주차 월요일, 2026-07-13 웹 검색으로 PK 파라미터 보강)

> 1장의 카페인 효과 결합(UMP)에 나온 Hill 방정식은 유료 논문(Ramakrishnan et al. 2014)에 막혀 원 계수를 구하지 못했다. 대신 공개된 표준 약동학(PK)·약력학(PD) 모델로 근사한다. PK(흡수·제거·분포)는 공개 자료로 근거를 보강했고, PD(농도→각성도 %)는 여전히 근사치다.

### 2.1 약동학(PK) — 혈중 카페인 농도

```
C(t) = (F·Dose·ka) / (Vd·(ka−ke)) · (e^(−ke·(t−t0)) − e^(−ka·(t−t0)))   (t ≥ t0, 섭취 전엔 0)
```

| 파라미터 | 값 | 근거 |
|---|---|---|
| F (생체이용률) | 1 | 경구 카페인은 거의 완전 흡수(~99%)됨이 공개적으로 알려진 값 |
| ka (흡수 속도 상수) | 5 /h (음료 기준) | 커피/콜라 최고 혈중농도 도달 시간이 39~42분이라는 공개 연구값(캡슐 67분보다 훨씬 빠름)을 5시간 반감기 기준으로 역산해서 도출. 기존에 캡슐·껌 값을 단순 평균했던 2.5/h보다 실제 음료 흡수 속도에 더 가까움 |
| ke (제거 속도 상수) | ln(2)/half-life | half-life는 카페인 민감도 입력에 따라 3단계로 분기(아래) |
| Vd (분포용적) | 체중(kg) × 0.7 L/kg | NCBI Bookshelf 자료(공개) 기준. **정보 입력 화면에 몸무게 필드를 추가해서** 개인화하기로 결정(2026-07-13) — spec.md에 반영 필요 |

**반감기(half-life) — 카페인 민감도 입력값과 연결**

| 민감도 | half-life |
|---|---|
| 낮음 | 4시간 |
| 보통(기본값) | 5시간 |
| 높음 | 7시간 |

공개 자료 기준 건강한 성인 평균 반감기는 약 5시간, 정상 범위는 3~7시간(개인차 크면 1.5~9.5시간)이라 이 3단계가 그 범위 안에 든다. 참고로 흡연(반감기 최대 절반 감소), 임신·경구피임약 복용(최대 2배 이상 증가) 같은 요인도 있는데, "건강상태" 입력값으로 더 세분화할지는 추후 검토.

→ Supabase `sensitivity_halflife` 테이블에 그대로 들어갈 구조(3주차 작업).

### 2.2 약력학(PD) — 농도 → 각성도 보정 계수

```
gPD(t) = 1 + Gmax(t) · C(t)^n / (EC50^n + C(t)^n)
```

**Gmax(t) — 피로도(수면압)에 비례해서 커지는 최대 부스트 (2026-07-13 결정)**

기존엔 Gmax를 15%로 고정했었는데, "피곤할수록 카페인 효과가 더 크게, 안 피곤할수록 더 작게 반영돼야 한다"는 논의를 거쳐 **수면압 H(t)(1장 Process S)에 비례해서 Gmax 자체가 움직이도록** 바꿨다.

```
Gmax(t) = Gmax_최소 + (Gmax_최대 − Gmax_최소) × 피로비율(t)
피로비율(t) = (H(t) − 0.17) / (1 − 0.17)      ※ H(t)는 1장 Process S의 값, 0.17(가장 안 피곤)~1(가장 피곤) 범위
```

| 파라미터 | 값 | 근거 |
|---|---|---|
| Gmax_최소 | 0.05 (5%) | **근거 없는 근사치.** 안 피곤할 때(피로비율≈0)는 카페인 효과가 거의 안 느껴진다는 통념을 반영 |
| Gmax_최대 | 0.25 (25%) | **근거 없는 근사치.** 많이 피곤할 때(피로비율≈1)는 카페인 효과가 크게 느껴진다는 통념을 반영. 두 값의 평균(15%)이 기존 고정값과 비슷한 수준이 되도록 설정 |
| EC50 (반포화 농도) | 2 mg/L | 표준 200mg 1회 섭취 시 최대 혈중농도가 대략 4~6mg/L에 도달한다는 공개 자료 기준, 그 절반 지점으로 설정 |
| n (Hill 계수) | 1 | 단순 포화 곡선(협동결합 없음)으로 가정 — 별도 근거 없음, 가장 단순한 형태로 채택 |

이 결과로 안 피곤할 때(P0가 높을 때)는 카페인 부스트 자체가 작게 잠겨있고, 많이 피곤할 때(P0가 낮을 때)는 부스트가 크게 열려있어서, "피곤할수록 카페인이 더 크게 작용한다"는 방향이 공식 안에 직접 반영된다.

**ke·ka 값이 어떻게 나오는지 (구현 중 질문에 답하며 보강, 2026-07-14)**

`ke`는 반감기(half-life)의 정의에서 대수적으로 정확히 유도된다. "1차 반응(농도가 남은 양에 비례해서 줄어듦)"을 가정하면:

```
C(t) = C₀ · e^(−ke·t)                      (제거 과정 가정)
정의: t = half-life일 때 C(t) = C₀/2

C₀/2 = C₀ · e^(−ke·half-life)
1/2  = e^(−ke·half-life)
ln(1/2) = −ke·half-life                    (양변에 자연로그)
−ln(2)  = −ke·half-life                    (ln(1/2) = −ln(2))
ke = ln(2) / half-life
```

`ka`는 반대로 근사치다. 정확한 대수적 해가 없어서, "최고 혈중농도 도달 시각(Tmax)" 공식을 거꾸로 대입해보며 목표 시간(39~42분)에 가까운 값을 찾는 방식으로 역산했다.

```
Tmax = ln(ka/ke) / (ka − ke)     (C(t) 곡선의 기울기가 0이 되는 지점=최고점에서 유도되는 표준 공식)

ke = ln(2)/5시간 ≈ 0.1386/h (반감기 5시간 "보통" 기준으로 역산)
ka = 5/h를 대입해서 검산하면:
  Tmax = ln(5/0.1386) / (5−0.1386) = ln(36.07) / 4.8614 ≈ 3.585/4.8614 ≈ 0.7375시간 ≈ 44.2분
```

⚠️ 목표였던 39~42분보다 조금 높게 나온다 — 대수적으로 정확히 일치하는 값이 아니라, 여러 ka 후보를 시도해보며 **가장 가까운 근사치로 5(깔끔한 정수)를 채택**한 것으로 보인다. 웹 검색 당시의 정확한 중간 계산 과정은 남아있지 않아 이 역산 결과로만 검증 가능하다.

### 2.3 최종 결합

```
P(t) = P0(t) × gPD(t)         (P0(t) = S(t) + κ·C_circadian(t), 1장 5-하모닉 버전)
```

카페인을 섭취하지 않으면 gPD(t) = 1이라 P(t) = P0(t)로 자연스럽게 수렴한다. Gmax(t)가 화요일에 만들 Process S(H(t))의 결과값을 그대로 참조하므로, **실제 코드 연결은 수요일(카페인 함수 구현) 작업에서 진행**한다.

**Gmax_최소·Gmax_최대·EC50·n은 여전히 근거 없는 근사치**다. 4장의 2B-Alert Web 비교 검증 결과가 터무니없이 다르면 이 값들부터 조정한다.

우리가 직접 구현한 계산 결과가 이 도구의 결과와 비슷하게 나오는지 비교해보는 방식으로 "검증"할 수 있을 것 같음 (지난번 멘토링 질문 목록 중 "정답이 하나로 안 떨어지는 코드를 어떻게 테스트하나"에 대한 답 후보).

## 6. 판단 — 계산 서버를 따로 둘 필요는 없어 보임

지금까지 확인된 수식은 전부 지수함수·사인함수·간단한 곱셈/덧셈 수준이고, 최적화도 SciPy 같은 라이브러리가 아니라 직접 짠 반복문 방식이다. 즉 **NumPy/SciPy 같은 별도 계산 라이브러리가 필요한 문제가 아니라서, Express(Node/JS) 안에서 직접 구현해도 무리 없어 보인다.** 카페인 Hill 방정식과 κ값은 2·1장에서 근사로 해결했고, Vital-Lopez 최적화 상세만 여전히 남아있다.
