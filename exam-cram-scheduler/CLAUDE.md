# 시험 벼락치기 스케줄러

시험 날짜·남은 공부량·평소 수면 패턴·카페인 섭취 상태를 입력하면, 검증된 생물수학 모델(Two-Process Model + 카페인 상호작용 모델)로 "시험 시작 시각에 각성도가 최고가 되는" 수면·카페인 스케줄을 계산해주는 웹 도구. 시험이 여러 개 겹치는 시험기간 전체를 한 번에 고려해 스케줄을 짜준다는 점이 핵심 차별점이다.

## 기술 스택

| 층 | 기술 | 비고 |
|---|---|---|
| FE | React (`client/`) | TypeScript + Vite + react-router-dom, CSS Modules로 스타일링 |
| BE | Express | 계산 엔진 API + 참고 데이터 제공 API (아직 미착수) |
| DB | Supabase (Postgres) | 음료별 카페인 함량, 반감기, 안전 섭취 한도 등 참고용 정적 데이터만 저장. 사용자 스케줄은 저장하지 않음(브라우저 localStorage 사용, 아직 미착수) |

실제 개발 중인 앱 코드는 저장소 루트가 아니라 **`client/`** 폴더 안에 있다 (`client/src/components/`, `client/src/pages/`, `client/src/styles/tokens.css`). 저장소 루트에는 더 이상 별도 React 앱이 없다(예전 초기 이식 버전은 제거함).

## 컨벤션

**컴포넌트**
- 컴포넌트 파일명은 `PascalCase.tsx`
- 같은 폴더에 동일한 이름의 `.module.css`를 짝으로 둔다 (예: `ExamCard.tsx` + `ExamCard.module.css`)
- 스타일은 CSS Modules로 작성하고, `docs/prototype/styles.css`의 `:root` 디자인 토큰(`--brand`, `--surface`, `--ink-900` 등)을 그대로 재사용한다

**커밋**
- Conventional Commits 형식: `타입: 한국어 설명`
- 타입 예시: `feat`(기능 추가), `fix`(버그 수정), `docs`(문서), `style`(스타일링), `refactor`, `test`, `chore`, `ci`
- 예: `feat: 시험 일정 입력 폼 추가`, `fix: 카페인 반감기 계산 오류 수정`

**발표자료(PPT, `docs/presentation/`)**
- 긴 문장은 자동 줄바꿈(단어 중간 절단)에 맡기지 않는다. 문맥상 자연스러운 어절·구 단위로 직접 줄바꿈(`breakLine`) 위치를 지정한다
- 모든 도형·텍스트·이미지는 슬라이드 프레임(16:9, 10×5.625in) 안에 완전히 들어와야 한다. 좌표를 계산한 뒤에는 실제 렌더링 결과(PDF→PNG)를 확인해서 잘리거나 겹치는 부분이 없는지 검증하고 나서 완료로 본다
- 아이콘 배지·불릿점처럼 텍스트와 나란히 놓이는 요소는 같은 세로 중심(cy)을 공유하도록 계산한다. 배지는 중심 좌표(cx, cy) 기준으로, 옆 텍스트는 `valign:"middle"` + 같은 높이(h)로 배치해서 실제로 중심이 맞는지 렌더링 결과로 확인한다
- 슬라이드 상단 여백(제목/이어브로우 시작 y)과 하단 여백(마지막 요소의 bottom ~ 슬라이드 끝)을 비교해서, 하단 여백이 상단 여백보다 좁아지지 않게 한다(같거나 더 넓은 건 괜찮음). 내용이 프레임 안에 다 들어와도 하단 여백이 상단보다 좁으면 전체적으로 아래로 쏠려 보이므로, 마지막 요소의 y+h를 항상 확인한다

**코드 설명 (이 프로젝트는 학습 목적이 크다)**
- "코드 설명해줘"라고 요청받으면 (1)목적 (2)방식 (3)근거(상수·수식 출처) (4)구현, 이 4단계 틀로 설명한다
- 파일/함수 하나씩만 설명하고, 여러 개를 한 번에 몰아서 보내지 않는다 — 다음 요청이 올 때까지 기다린다
- 구현 설명 시 `const`, `boolean`, 연산자 같은 프로그래밍 기초 문법도 안다고 가정하지 않고 글자 단위로 풀어서 설명한다

## 하지 말 것

- 사용자가 명시적으로 실행하라고 지시하지 않은 작업은 스스로 실행하지 않는다
- 프롬프트에 빈틈(정해지지 않은 부분)이 있으면 임의로 판단해서 채우지 말고, 사용자에게 다시 질문해서 함께 결정한다
