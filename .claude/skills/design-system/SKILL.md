# 식비구조대 디자인 시스템 가드

이 프로젝트는 `DESIGN_SYSTEM.md`(저장소 루트)에 공식 디자인 토큰이 정의되어 있다. UI 관련 작업을 시작하기 전에 반드시 이 문서를 먼저 읽는다.

## 절차

1. **`DESIGN_SYSTEM.md`를 읽는다.** 색상/타이포/radius/spacing 토큰과 컴포넌트 패턴 카탈로그, Do/Don't를 확인한다.

2. **`DESIGN_SYSTEM.md`의 "실제 앱 (Tailwind v4)" 섹션을 따른다.** `src/index.css`에 `@theme` 토큰이 아직 없다면, 스타일링 작업을 시작하기 전에 먼저 그 블록을 추가할지 사용자에게 확인한다(기존 컴포넌트의 오렌지 톤을 건드리는 일이라 조용히 바꾸지 않는다). 이미 추가돼 있다면 `bg-primary`, `rounded-card` 같은 토큰 기반 유틸리티만 쓴다. 절대 문서에 없는 임의의 hex 값이나 px 값을 하드코딩하지 않는다.

3. **컴포넌트 재사용 원칙을 지킨다.** (`CLAUDE.md`에 이미 명시됨) 같은 모양의 UI가 두 군데 이상 필요하면 `src/components`에 컴포넌트로 만들어 재사용한다. 정렬·필터링 로직은 `src/data/selectors.js`에 분리한다. 이 스킬은 그 원칙 위에 "어떤 토큰을 쓸지"만 얹는다.

4. **새 UI 패턴을 만들면 카탈로그를 갱신한다.** `DESIGN_SYSTEM.md`의 "컴포넌트 패턴 카탈로그" 표에 없는 새로운 컴포넌트(예: 새로운 종류의 카드, 배지)를 만들었다면, 같은 작업 안에서 그 표에 한 줄 추가해 문서를 최신 상태로 유지한다.

5. **Do/Don't를 지킨다.** 특히: `primary` 노랑은 CTA·활성 상태·배지 같은 좁은 영역에만 쓰고 큰 배경 전체를 채우지 않는다. 카드는 항상 `radius-card`(16px), 버튼/칩/배지는 항상 `radius-pill`로 통일한다.
