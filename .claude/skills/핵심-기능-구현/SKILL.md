# 핵심 기능 구현 워크플로우

이 스킬은 "요구사항 한 줄"에서 "e2e 검증까지 끝난 기능"으로 가는 여정 전체를 다룬다. 단계마다 되돌릴 수 없거나 사용자 판단이 필요한 지점이 있으므로, 그 지점에서는 반드시 멈추고 사용자의 다음 지시를 기다린다. 절차를 건너뛰거나 다음 단계로 자동으로 넘어가지 않는다 — 이 워크플로우가 존재하는 이유 자체가 각 단계에서 사람이 검토하고 승인하게 만드는 것이다.

## 전체 흐름

1. 계획 수립 (planner agent)
2. 계획 제시 → **사용자 승인 대기**
3. GitHub 이슈 등록 → **등록 전 초안 승인 대기**
4. 이슈 순서대로 구현 + 레이어별 test agent 검증
5. 기능 전체 e2e 검증 (Claude 직접 수행)

---

## 1단계: 계획 수립

사용자가 말한 핵심 기능 요구사항을 그대로 Agent 도구로 `planner` 서브에이전트(`subagent_type: "planner"`)에 전달한다. 관련해서 이미 파악한 컨텍스트(관련 파일 경로, 기존 구현 방식, 제약사항)가 있으면 함께 넘겨서 planner가 다시 조사하는 시간을 아껴준다.

planner는 조사와 계획만 하고 구현은 하지 않는다. 반환된 계획에는 각 세부 작업이 클라이언트/서버/DB 중 어디에 속하는지, 완료 기준이 무엇인지가 포함되어 있어야 한다 — 없다면 이 두 가지를 채워서 정리한다.

## 2단계: 계획 제시 (승인 대기 지점)

planner가 반환한 계획을 사용자에게 그대로, 세부 작업 단위로 보여준다. 여기서 **절대 이어서 구현을 시작하거나 이슈를 등록하지 않는다.** 사용자가 계획을 수정하라고 하면 반영해서 다시 보여주고, 승인(예: "이대로 진행해", "이슈로 등록해줘")이 명시적으로 있을 때만 3단계로 넘어간다.

## 3단계: GitHub 이슈 등록 (승인 대기 지점)

계획의 각 세부 작업을 이슈 하나씩으로 매핑한다. 이슈 제목과 본문(배경/작업 내용/완료 기준/영역: 클라이언트|서버|DB)을 초안으로 작성해서 사용자에게 보여주고, **명시적 승인을 받은 뒤에만** 사용자 계정의 `issue-repo` 저장소에 `gh issue create --repo meatbest9/issue-repo`로 실제 등록한다. 현재 작업 중인 코드 저장소가 아니라 이슈 전용 저장소이므로, `--repo`를 빠뜨려 현재 디렉터리 기준 저장소에 잘못 등록하지 않도록 주의한다.

이슈 등록은 저장소에 공개적으로 남는 행동이므로, 이미 승인받은 이전 세션의 이슈 목록이라도 매 실행마다 다시 승인을 받는다 — 한 번의 승인이 이후 반복 실행을 자동으로 정당화하지 않는다.

등록 후에는 이슈 번호와 링크 목록을 사용자에게 보여준다.

## 4단계: 이슈 순서대로 구현 + 레이어별 검증

등록된 이슈를 순서대로 하나씩 구현한다. 한 이슈 안에서도 클라이언트/서버/DB에 걸친 작업이 있을 수 있는데, **그중 한 레이어(예: 서버의 route→controller→service, 혹은 클라이언트의 page→api 호출)의 내부 흐름이 완성될 때마다** — 전체 이슈가 끝나기를 기다리지 말고 — Agent 도구로 `test-agent` 서브에이전트(`subagent_type: "test-agent"`)를 호출해 그 흐름을 검증한다. 검증 대상 흐름과 기대 동작을 test-agent에게 명확히 전달한다.

test-agent가 실패를 보고하면 원인을 분석해서 고치고, 같은 레이어를 다시 검증한 뒤 다음 레이어로 넘어간다. test-agent는 실행이 끝나면 테스트 코드를 정리(삭제)하고 결과만 보고하므로, 통과 여부와 발견된 문제만 사용자에게 요약해서 전달하면 된다.

한 이슈의 모든 레이어 검증이 끝나면 다음 이슈로 넘어간다. 이슈 사이에는 별도 승인 없이 계속 진행해도 되지만, 계획과 다른 판단(설계 변경, 범위 확장 등)이 필요해지면 멈추고 사용자에게 확인한다.
또한, 한 이슈 작업이 완료될 때마다 해당 작업 내용을 커밋한다.
## 5단계: 기능 전체 e2e 검증

계획에 포함된 모든 이슈의 구현과 레이어별 검증이 끝나면, 서브에이전트에 위임하지 않고 **Claude가 직접** 핵심 기능 전체를 처음부터 끝까지(예: 실제 화면 흐름을 브라우저로 조작하거나, 여러 API를 순서대로 호출) e2e로 검증한다. 이 단계는 개별 레이어가 아니라 사용자가 실제로 겪는 흐름 전체가 맞물려 동작하는지 확인하는 것이 목적이다.

검증 결과(성공한 시나리오, 발견된 문제와 조치)를 사용자에게 요약해서 보고하며 워크플로우를 마무리한다.

## 주의사항

- 계획 승인과 이슈 등록 승인, 이 두 지점은 절대 생략하지 않는다. 자동 모드이거나 이전에 비슷한 요청을 승인받은 적이 있어도 매번 새로 확인한다.
- test-agent와 e2e 검증은 이 워크플로우 안에서 명시적으로 요청된 것이므로, "테스트는 시킬 때만 한다"는 일반 원칙과 충돌하지 않는다 — 이 스킬 자체가 그 지시다.
- planner에게 넘길 때 요구사항을 임의로 축소하거나 확장하지 않는다. 사용자가 말한 핵심 기능 그대로 전달한다.
