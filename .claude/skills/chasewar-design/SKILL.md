# ChaSeWar 디자인 skill

차세워 프론트엔드 UI를 만들거나 리뷰할 때 항상 이 디자인 시스템을 따른다.

## 원본
- 토큰(값의 단일 원본): `docs/design/tokens.css`
- 요약/규칙: `docs/design/design-system.md`
- 값은 직접 쓰지 말고 항상 `var(--토큰)`으로 참조한다.

## 핵심 규칙
- 브랜드색 `--brand`(#03C75A, 네이버 그린) — 로고·강조·버튼.
- 상태색: 여유 `--ok-*` / 보통 `--warn-*` / 혼잡 `--busy-*` / 정보없음 `--none-*`.
  - 판정: 여유율(가용/총) >50% 여유, 10~50% 보통, ≤10% 혼잡, 실시간 없음 → 정보없음.
- 폰트 `--font`(iOS 시스템 폰트), 타이포 스케일은 design-system.md 준수.
- 간격 `--s1~s6`(4px 기준), 라운드 `--r-*`, 그림자 `--shadow`.
- 새 화면은 기존 컴포넌트(검색창·칩·카드·뱃지·정보카드·실시간카드·버튼·상태화면)를 **재사용**해 구성한다.

## 디자인 결과 점검 체크리스트
UI를 만든 뒤 확인한다:
- [ ] 하드코딩 값 없이 모두 토큰(var) 참조하는가
- [ ] 상태 뱃지/숫자 색이 여유율 규칙과 일치하는가
- [ ] 폰트·크기·굵기가 타이포 스케일을 따르는가
- [ ] 카드·라운드·그림자·간격이 기존 컴포넌트와 일관적인가
- [ ] 새로 만들기보다 기존 컴포넌트를 재사용했는가
- [ ] 모바일 우선(최대폭 420px 중앙 정렬) 레이아웃인가

## 벗어날 때
디자인 시스템에 없는 색·컴포넌트가 필요하면 임의로 만들지 말고, 먼저 사용자에게 확인하고 tokens.css/design-system.md에 추가한다.
