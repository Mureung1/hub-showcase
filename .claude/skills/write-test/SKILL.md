# 테스트 작성 절차 (TDD)

`client/src/utils/weekly.test.js`가 이 절차를 처음 적용한 예시다.

## 절차

1. **대상 선별** — 조건 분기나 계산이 있는 함수/컴포넌트를 고른다. DB 요청 함수는 건너뛴다.
2. **케이스 목록 작성 (승인 전 코드 작성 금지)** — 정상, 빈 값, 경계값, 실패 케이스를 표로 정리해
   사용자 승인을 받는다.
3. **Red** — 승인된 케이스로 테스트 파일부터 쓰고 실행해서 실패(빨강)를 확인한다.
   서버는 `node:test`(`server/tests/`), 클라이언트는 vitest(`*.test.js`, 대상 파일 옆).
4. **Green** — 테스트를 통과시키는 최소 구현을 작성하고 다시 실행해 통과를 확인한다.
5. **막히면** — 구조가 얽혀 테스트하기 어려우면, 코드를 바로 고치지 말고 왜 어려운지와
   테스트하기 쉬운 구조로 바꾸는 법을 먼저 논의한다.

## 완료 후

기능 요구사항 충족 여부는 `feature-verifier` 에이전트로 별도 검증한다 (이 스킬은 테스트 작성까지만).
