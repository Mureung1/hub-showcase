# PlaceSync 화면 제작 Skill

`docs/design.md`에 정의된 PlaceSync 디자인 시스템을 실제 화면(신규/수정)에 적용할 때 따르는 실행 가이드입니다.
토큰 값(색상·타이포·간격·radius)의 출처는 항상 `docs/design.md`이며, 이 Skill은 그 값을
"어떤 절차와 판단으로 적용하는가"만 다룹니다. 값 자체를 이 파일에 복제하지 않습니다 — 항상 `docs/design.md`를 열어 최신 값을 확인하세요.

## 이 Skill의 목적

- PlaceSync의 모든 화면이 같은 사람이 만든 것처럼 일관된 톤·구조·컴포넌트를 갖도록 한다.
- 새 화면을 매번 처음부터 디자인하지 않고, 이미 검증된 셸(사이드바+헤더)과 컴포넌트 패턴을 재사용한다.
- 색상·간격·radius 같은 디자인 판단을 임의로 하지 않고 `docs/design.md`를 그대로 조회·적용한다.
- 결과적으로 소상공인 사장님이 어떤 화면을 봐도 "같은 서비스"라고 느끼게 만든다.

## 원칙

1. **신뢰감 우선** — 화려함보다 정확함. 장식은 최소, 정보는 명확하게.
2. **초록은 강조색이지 배경색이 아니다** — primary는 버튼·활성 상태·성공 표시에만.
3. **흰 카드 위에서만 정보가 산다** — 배경에는 텍스트를 직접 얹지 않고 항상 카드에 담는다.
4. **상태는 넷 중 하나로 말한다** — success / warning / danger / neutral. 색을 새로 만들지 않는다.
5. **사장님 언어로 쓴다** — API/DB/플랫폼 내부 용어가 아니라 "반영 완료", "확인 필요"처럼 행동 중심 문구.
6. **밀도보다 여백** — 억지로 욱여넣지 않는다.

## 절차

1. **토큰 확인**: 작업 전 `docs/design.md`를 읽어 이번 작업에 필요한 색상/타이포/간격/radius 값을 확인한다. 값이 없으면 새로 정의하지 말고 사용자에게 확인한다.
2. **셸 재사용**: 좌측 사이드바(264px, 그룹형 nav + 검색 + 하단 매장카드) + 상단 브레드크럼 헤더를 그대로 가져온다. 새로 그리지 않는다.
3. **페이지 제목 배치**: 콘텐츠 최상단에 페이지 제목(28–30px/700) + muted 부제.
4. **핵심 동작 배치**: 화면의 목적에 맞는 primary 버튼을 헤더 우측 또는 화면 하단 우측에 **1개만** 배치.
5. **정보 카드 분해**: 화면에 넣을 정보를 의미 단위로 나누고, 각 단위를 카드(`docs/design.md` 6절 규칙)로 만든다. 카드 하나에 서로 다른 주제를 섞지 않는다.
6. **상태 표현 적용**: 완료/진행/실패가 있다면 `docs/design.md` 8절(상태 배지 규칙)에 따라 배지/배너를 붙인다.
7. **간격 정리**: `docs/design.md` 5절 값으로 카드 간격·콘텐츠 최대폭을 맞춘다.
8. **반응형 확인**: `docs/design.md` 11절에 따라 grid를 `auto-fit minmax()`로 두고, 모바일에서 사이드바가 상단 탭으로 접히는지 확인한다.
9. **접근성 통과**: `docs/design.md` 12절 체크리스트를 확인한다.
10. **자체 검토**: `docs/design.md` 13절(체크리스트)·14절(금지 목록)로 마무리 점검 후 완료 처리한다.

## 새 화면/컴포넌트 작업 전 체크리스트

- [ ] 이 화면은 핵심 흐름(대시보드→편집→미리보기→승인→결과→수동수정) 중 어디에 속하는가?
- [ ] 이 화면에 필요한 주요 동작(primary 버튼) 1개는 무엇인가?
- [ ] 보여줘야 할 상태값이 있는가?
- [ ] 기존 화면 중 재사용 가능한 카드/레이아웃 패턴이 있는가? (있으면 새로 만들지 않는다)
- [ ] 예시 데이터는 기존 세트(카페 하루, 메뉴 3종, 플랫폼 3개)를 그대로 쓰는가?
- [ ] 모바일에서 이 레이아웃이 어떻게 접히는지 미리 생각했는가?

## 컴포넌트 사용 규칙

| 컴포넌트 | 언제 쓰나 | 규칙 근거 |
|---|---|---|
| Summary Card | 화면 상단 핵심 지표 3~4개 | design.md 6절 — 다크 아이콘 타일 → 큰 숫자 → muted 라벨 |
| Info Card (라벨-값 그리드) | 매장 정보, 상세 데이터 표시 | design.md 6절 |
| Alert Banner | 문제·주의가 필요한 상황 | design.md 6·8절 — warning/danger 매핑 |
| 안내 배너(정보성) | 팁, 기능 안내 | design.md 6절 |
| Platform/List Row | 플랫폼별 상태, 목록성 정보 | design.md 6절 |
| Step Indicator | 여러 단계로 이어지는 플로우 | design.md 6절 |
| Button | 모든 동작 | design.md 7절 — 화면당 primary 1개 |
| Input/Select/Checkbox | 모든 입력 | design.md 9절 |
| Table | 메뉴·가격 등 구조화된 데이터 | design.md 10절 — 좁은 화면 가로 스크롤, 절대 줄바꿈 금지 |

새 컴포넌트가 필요하면 위 표에 없는 패턴을 만들기 전에 기존 컴포넌트 조합으로 표현할 수 있는지 먼저 검토한다.

## 하면 안 되는 것

`docs/design.md` 14절("하면 안 되는 디자인")을 그대로 따른다. 특히:
- 강한 그라데이션, 과한 그림자, 채도 높은 색 남용
- 색상만으로 상태 전달
- 근거 없는 숫자·아이콘(데이터 슬롭)
- primary 초록을 큰 배경 면적에 사용
- 화면마다 카드 radius/padding/색상을 임의로 다르게 정하는 것

## 사용 예시

새 화면을 만들 때:
> "/design-skill-default 적용해서 [화면 이름] 화면을 만들어줘. 기존 셸을 재사용하고 예시 데이터는 카페 하루 세트 그대로 써줘."

기존 화면을 수정할 때:
> "/design-skill-default 규칙에 따라 [화면 이름]의 [부분]을 수정해줘. 색상·radius·간격은 docs/design.md 토큰만 쓰고 다른 부분은 건드리지 마."

디자인 QA를 요청할 때:
> "지금 만든 [화면 이름]이 /design-skill-default의 접근성·체크리스트를 통과하는지 점검하고, 위반 사항이 있으면 목록으로 알려줘."
