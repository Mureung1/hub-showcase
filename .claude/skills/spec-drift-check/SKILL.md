# 기획서-코드 드리프트 체크 (spec-drift-check)

이 저장소는 기획서(`review-assistant-react/기획서.md`)와 두 `CLAUDE.md`(루트, `review-assistant-react/`)가 "지금 뭐가 어떻게 되어 있는지"를 설명하는 문서다. 코드는 빠르게 바뀌는데 이 문서들은 매번 같이 안 고쳐지는 경우가 많다 — 예를 들어 실제로는 이미 Claude API로 교체됐는데 문서엔 "3주차 예정"이라고 남아있거나, DB를 SQLite에서 Supabase로 옮겼는데 예전 스키마 설명이 그대로 남아있는 식이다. 이 스킬은 문서의 "현재 상태 서술"이 실제 코드/git 히스토리와 맞는지 점검한다.

## 언제 쓰는가
- 기획서/CLAUDE.md를 최신화하고 싶을 때
- PR을 올리기 전, 이번 변경으로 문서가 오래된 내용을 담게 되진 않았는지 확인하고 싶을 때
- 다른 작업(테스트 보강, 리팩토링 등) 중 우연히 문서 드리프트를 발견했을 때, 그 자리에서 바로 점검 범위를 넓히고 싶을 때

## 절차

### 1. 점검 대상 문서 확인
기본 대상은 다음 세 파일이다. 사용자가 다른 문서를 지목하면 그것도 포함한다.
- `CLAUDE.md` (루트) — 개발 환경/컨벤션/DB·인증 결정
- `review-assistant-react/CLAUDE.md` — 디자인 시스템
- `review-assistant-react/기획서.md` — 기능 스펙, API 설계, 데이터 모델, "향후 확장" 로드맵

### 2. "현재 상태 서술"을 추출한다
문서에서 다음 패턴을 찾는다 — 이런 문장이 드리프트가 생기기 가장 쉬운 지점이다.
- 미래형 서술: "~예정", "~할 것이다", "아직 미구현", "3주차에" 같은 표현
- 구현 방식/아키텍처 서술: "DB는 X를 쓴다", "인증은 Y 방식이다", "분석은 규칙 기반이다" 같은 단정적 현재 서술
- 결정 로그 항목: "(YYYY-MM-DD 결정)" 형식 — 이건 히스토리라 지우면 안 되지만, 그 뒤에 "현재도 유효한 최신 결정인지" 확인 대상

### 3. 실제 코드/git 로그와 대조한다
각 서술에 대해:
- 관련 파일/심볼을 Grep으로 확인한다 (예: "규칙 기반"이라고 써 있으면 실제로 `POSITIVE_WORDS`/`classifySentiment` 같은 규칙 기반 코드가 아직 있는지, 아니면 이미 API 호출로 바뀌었는지)
- `git log --oneline -20`이나 특정 파일의 `git log`로 최근 변경 이력을 확인해, 문서에 없는 결정이 이미 커밋되어 있는지 확인한다
- `package.json`의 실제 dependencies, 라우트/컨트롤러 목록 등도 문서의 주장과 대조한다

### 4. 발견한 드리프트를 분류해 보고한다
표로 정리한다:

| 문서 위치 | 문서 내용 | 실제 상태 | 근거 | 권장 조치 |
| --- | --- | --- | --- | --- |
| 기획서.md 8절 | "3주차 예정" | 이미 구현 완료 | `reviews.service.js`가 `callClaudeTool` 호출, 커밋 9d4b0d6 | 현재형으로 수정 |

권장 조치는 세 가지 중 하나로 분류한다:
- **현재형으로 수정** — 이미 끝난 걸 "예정"으로 남겨둔 경우
- **결정 로그 추가** — 아키텍처가 바뀌었는데 그 결정 자체가 문서에 아예 없는 경우 (기존 결정 로그 항목은 지우지 않고, 새 날짜로 변경 이력을 추가하는 이 저장소 컨벤션을 따른다 — 예: "(2026-07-22 결정 변경: ...)")
- **코드 쪽 확인 필요** — 문서와 코드가 다른데 어느 쪽이 맞는지 모호한 경우 (예: 문서엔 있는데 코드에 없는 에러 코드 등). 이건 추측해서 자동으로 고치지 않고 사용자에게 확인한다.

### 5. 실제로 고칠 때
- 사용자가 "고쳐줘"라고 확인하면, 표에서 "현재형으로 수정"/"결정 로그 추가"로 분류된 항목만 바로 적용한다.
- 결정 로그 스타일(`> YYYY-MM-DD: ...` 또는 `(YYYY-MM-DD 결정 변경: ...)`)은 그 문서에 이미 쓰인 형식을 그대로 따른다 — 새 스타일을 만들지 않는다.
- "코드 쪽 확인 필요" 항목은 문서를 먼저 고치지 않고, 어떤 게 맞는지 사용자에게 질문한다.
