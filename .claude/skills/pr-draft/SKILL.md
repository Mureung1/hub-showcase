# PR 초안 작성 스킬

이 프로젝트의 업스트림 PR은 `.github/pull_request_template.md`의 고정 양식을 따른다. 이 스킬은 그 양식에 맞는 **초안**을 만든다 — 특히 "내가 설명할 수 있는 부분"과 "아직 이해 못 한 부분"은 본인이 실제로 이해한 정도를 반영해야 하는 항목이므로, 초안을 그대로 제출하지 말고 검토·수정 후 사용한다.

## 절차

### 1. 컨텍스트 수집
```bash
git log --oneline dev..HEAD          # 이 브랜치에서 dev 대비 쌓인 커밋
git diff dev --stat                   # 변경 파일 요약
```
오늘 세션에서 `docs/decisions.md`·`docs/log.md`에 새로 추가된 항목이 있다면 함께 확인한다 — 설계 결정과 그 이유가 이미 정리돼 있어 "내가 설명할 수 있는 부분"의 재료가 된다.

### 2. 제목 초안
형식: `[N034_김선호] - <이번 작업을 한 문장으로 요약>`
예: `[N034_김선호] - 이슈/레포 추천 API 구현 및 규칙 기반 매칭`

### 3. 본문 초안 — 템플릿 4개 섹션

**주요 작업 리스트**
커밋 로그를 의미 단위로 묶어 불릿으로 정리한다. "무엇을 했는지"뿐 아니라 "왜"가 드러나게 — 이 프로젝트 커밋 메시지 자체가 이미 그렇게 쓰여 있으므로 커밋 메시지를 재료로 삼는다. 스크린샷이 필요한 화면 변경이 있으면 자리를 비워두고 사용자에게 첨부를 요청한다.

**내가 설명할 수 있는 부분**
diff에서 기술적으로 흥미로운 지점(설계를 바꾼 이유, 트레이드오프를 고민한 부분, 버그를 피하려고 순서를 바꾼 부분 등) 하나를 골라 초안을 쓴다. `docs/decisions.md`에 오늘 기록이 있다면 그 결정을 우선 후보로 삼는다. **이 섹션은 반드시 "초안이니 본인 말로 다시 확인·수정하라"고 사용자에게 명시한다** — 그대로 제출하면 본인이 이해했다는 것의 의미가 없어진다.

**아직 이해 못 한 부분**
절대 지어내지 않는다. 빈 칸으로 남기고 "diff를 보면서 스스로 채울 것"이라고 안내하거나, 세션 중 사용자가 실제로 질문했던 개념(예: 오늘 물어본 async/await, WebFlux, 가상 스레드 같은 것)이 있으면 후보로만 제시한다.

**새로 알게 된 것**
오늘 세션에서 실제로 논의된 새 개념·결정을 후보로 제시한다(예: 레포 우선 검색으로 전환한 이유, GraphQL alias 배치, rate limit 판정 우선순위 등). 마찬가지로 확정하지 말고 후보로 제시해 사용자가 고르게 한다.

### 4. 출력 형식
`gh pr create`에 바로 쓸 수 있는 형태로 제시한다:
```bash
gh pr create --repo connect-AIAgentChallenge-26-1/hub \
  --title "[N034_김선호] - ..." \
  --body "$(cat <<'EOF'
## 주요 작업 리스트
- ...

## 내가 설명할 수 있는 부분
...

## 아직 이해 못 한 부분
...

## 새로 알게 된 것
...
EOF
)"
```
라벨(예: BE/FE/docs)은 과거 PR 이력(`gh pr list --repo connect-AIAgentChallenge-26-1/hub`)의 라벨 패턴을 참고해 후보를 제시한다.

### 5. 실행 확인
초안을 보여주고 **사용자 확인 없이 `gh pr create`를 바로 실행하지 않는다** — PR 생성은 외부에 공개되는 행위이므로 반드시 승인 후 실행한다.

## 하지 말 것
- "아직 이해 못 한 부분"을 그럴듯하게 지어내기 (템플릿의 취지 자체가 훼손됨)
- "내가 설명할 수 있는 부분"을 사용자 검토 안내 없이 확정문처럼 제시하기
- 라벨·제목 형식을 임의로 바꾸기 (템플릿·과거 PR 이력과 어긋나면 리뷰에서 반려될 수 있음)
