# One-Step 디자인 시스템 Skill (Warm Achievement)

이 Skill은 **진입점 + 실행 규칙**만 담는다. 상세 디자인 자료는 작업 목적에 맞는 참고 파일만 읽는다.

| 참고 파일 | 담는 내용 |
|-----------|-----------|
| `tokens.md` | 디자인 원칙 · 색상 토큰 · 타이포그래피 · 간격 · 엘리베이션 · 아이콘 |
| `components.md` | 재사용 공통 컴포넌트(헤더 · 탭바 · 버튼 · 퀘스트 카드) |
| `screens.md` | 화면 단위 조립 스펙 + 프로토타입 반영 가이드 |
| `verification.md` | 완료 검증 기준 체크리스트 |

## 목적

- 이 Skill은 **One-Step 앱의 Flutter UI를 일관된 디자인 시스템으로 구현하고 검증**하기 위한 것이다.
- 색상·타이포그래피·간격·라운드·컴포넌트·화면 스펙에 관한 한 **이 Skill(SKILL.md + 참고 파일)을 디자인 정본(Source of Truth)으로 사용**한다.
- 화면을 새로 만들거나 고칠 때, 정의된 토큰과 컴포넌트 규칙에서 벗어나지 않는 것이 목표다.

## 사용 대상

다음 작업을 할 때 이 Skill을 사용한다.

- 신규 Flutter 화면 구현
- 기존 화면 리디자인
- 공통 위젯 생성 및 수정
- `ThemeData` 및 디자인 토큰 적용
- 색상, 타이포그래피, 간격, 라운드 수정
- 로딩, 빈 상태, 오류 상태 구현
- UI 결과 검증
- 반응형 레이아웃 및 접근성 검토

## 작업 절차

1. 요청된 화면과 관련된 디자인 스펙을 참고 파일에서 먼저 확인한다(→ 아래 `참고 문서 선택 규칙`).
2. 기존 `ThemeData`, 디자인 토큰, 공통 위젯을 프로젝트에서 먼저 검색한다.
3. 기존 토큰과 컴포넌트를 **우선 재사용**한다. 새로 만들기 전에 이미 있는지 확인한다.
4. 화면 파일에 임의의 HEX 색상, `TextStyle`, 간격 값을 **직접 작성하지 않는다**. 토큰/테마를 참조한다.
5. 정상 상태뿐 아니라 **로딩, 빈 상태, 오류 상태**를 함께 고려한다.
6. 기존 코드와 디자인 문서가 충돌하면 **임의로 수정하지 않고 충돌 내용을 보고**한다.
7. 구현 후 `verification.md`의 완료 검증 기준을 확인한다.

## 허용 범위

이 Skill로는 다음 작업만 수행한다.

- Flutter UI 화면 생성 및 수정
- 공통 UI 컴포넌트 구현
- `ThemeData`와 디자인 토큰 적용
- 레이아웃 및 반응형 UI
- 애니메이션 및 사용자 피드백
- 로딩, 빈 화면, 오류 화면
- 접근성 및 터치 영역 검토

## 역할 제한

다음 항목은 이 Skill로 **임의로 변경하지 않는다.**

- Firestore 컬렉션 또는 데이터 모델
- API 요청·응답 계약
- AI 프롬프트 및 응답 스키마
- 퀘스트 비즈니스 규칙
- 코인 및 XP 보상 정책
- 인증 및 권한 로직

디자인 구현을 위해 위 항목의 변경이 필요해 보이더라도, **직접 변경하지 말고 변경 필요성을 별도로 보고**한다.

## Flutter 구현 원칙

작업 전 **현재 프로젝트 구조를 먼저 확인하고 실제 경로에 맞게** 적용한다.

가능하면 다음 디자인 값을 중앙에서 관리한다: 색상 토큰 · 타이포그래피 · 간격 · 라운드 · `ThemeData` · 공통 컴포넌트.

화면 위젯 안에 다음 값을 **직접 하드코딩하지 않는다.**

- HEX 색상
- 반복되는 `EdgeInsets`
- 반복되는 `BorderRadius`
- 반복되는 `TextStyle`
- 반복되는 `BoxShadow`

참고 파일의 CSS 표현(예: `tokens.md`의 그림자)은 Flutter 코드로 변환해 적용한다.

- CSS `box-shadow` → Flutter `BoxShadow`
- `hover` → Flutter Web/Desktop에서만 적용
- `press` → `InkWell`, `GestureDetector`, `ButtonStyle`
- `full radius` → 충분히 큰 `BorderRadius.circular(...)`
- `tint`(틴트) → 프로젝트에서 사용하는 `Color` alpha API(예: `Color.withValues(alpha: ...)`)

## 색상 역할 불변 규칙 (핵심 금지 규칙)

> 이 3~4색 역할 분리가 One-Step 디자인의 핵심이다. **어떤 경우에도 아래 역할을 섞지 않는다.** (이 규칙이 색상 역할의 정본)

- 🟡 **노랑(선플라워 `#ef9900`)** — **코인·보상·스트릭 전용.** 그 외 용도에 절대 사용 금지.
- 🔵 **블루(`#0058be`)** — **AI·정보·링크·보조 행동.**
- 🟢 **그린(`#006e2f`)** — **성장·완료·주요 행동.**
- 🔴 **Error(`#ba1a1a`)** — **오류 및 어려움(Hard) 난이도.**

## 참고 문서 선택 규칙

작업과 관련된 파일만 읽는다. **작업과 관련 없는 참고 파일을 무조건 모두 읽지 않는다.** 상대 경로는 이 파일과 같은 폴더 기준이다.

- 색상 · 폰트 · 간격 · 라운드 · 엘리베이션 · 아이콘 작업 → `tokens.md`
- 공통 위젯(헤더 · 탭바 · 버튼 · 퀘스트 카드) 작업 → `components.md`
- 특정 화면(홈 · AI 분해 · 완료/인증 · 상점 · 보관함) 작업 → `screens.md` 중 **해당 화면 항목만**
- 구현 후 검증 → `verification.md`
