# One-Step 디자인 시스템 Skill (Warm Achievement)

이 Skill은 **진입점 + 실행 규칙**만 담는다. 상세 자료는 참고 파일에 있다.

## 목적

- One-Step 앱의 Flutter UI를 일관된 디자인 시스템으로 구현하고 검증한다.
- 색상, 타이포그래피, 간격, 라운드, 컴포넌트, 화면 스펙에 관한 한 **이 Skill(SKILL.md + 참고 파일)이 디자인 정본(Source of Truth)이다.**
- 화면을 새로 만들거나 고칠 때 정의된 토큰과 컴포넌트 규칙에서 벗어나지 않는 것이 목표다.

## 참고 파일 선택 (필요한 것만 연다)

상대 경로는 이 파일과 같은 폴더 기준이다.

| 참고 파일 | 담는 내용 | 언제 여는가 |
|-----------|-----------|-------------|
| `tokens.md` | 디자인 원칙, 색상 토큰, 타이포그래피, 간격, 엘리베이션, 아이콘 | 색상, 폰트, 간격, 라운드, 엘리베이션, 아이콘 작업 |
| `components.md` | 재사용 공통 위젯 (헤더, 탭바, 버튼, 퀘스트 카드) | 공통 위젯을 만들거나 고칠 때 |
| `screens.md` | 화면 단위 조립 스펙 + 프로토타입 반영 가이드 | 특정 화면(홈, AI 분해, 완료/인증, 상점, 보관함) 작업. **해당 화면 항목만 읽는다** |
| `verification.md` | 완료 검증 기준 체크리스트 | 구현을 마친 뒤 검증할 때 |

## 이 Skill을 쓰는 경우 (순서 없음)

- 신규 Flutter 화면 구현
- 기존 화면 리디자인
- 공통 위젯 생성 및 수정
- `ThemeData` 및 디자인 토큰 적용
- 색상, 타이포그래피, 간격, 라운드 수정
- 로딩, 빈 상태, 오류 상태 구현
- UI 결과 검증
- 반응형 레이아웃 및 접근성 검토

## 이 Skill로 하는 작업 (순서 없음)

- Flutter UI 화면 생성 및 수정
- 공통 UI 컴포넌트 구현
- `ThemeData`와 디자인 토큰 적용
- 레이아웃 및 반응형 UI
- 애니메이션 및 사용자 피드백
- 로딩, 빈 화면, 오류 화면
- 접근성 및 터치 영역 검토

## 작업 절차 (순서대로 실행)

1. 현재 프로젝트 구조를 먼저 확인하고, 실제 경로에 맞게 적용한다.
2. 위 표를 보고 이번 작업에 필요한 참고 파일만 골라 디자인 스펙을 확인한다.
3. 기존 `ThemeData`, 디자인 토큰, 공통 위젯이 프로젝트에 이미 있는지 검색한다.
4. 있으면 **재사용한다.** 없을 때만 새로 만든다.
5. 화면을 구현한다. 값은 토큰과 테마를 참조한다.
6. 정상 상태뿐 아니라 로딩 상태, 빈 상태, 오류 상태를 함께 구현한다.
7. `verification.md`의 완료 검증 기준을 확인한다.

## 색상 역할 불변 규칙 (색상 역할의 정본)

이 색 역할 분리가 One-Step 디자인의 핵심이다. **어떤 경우에도 아래 역할을 섞지 않는다.**

| 색 | HEX | 전용 용도 |
|----|-----|-----------|
| 🟡 노랑 (선플라워) | `#ef9900` | **코인, 보상, 스트릭 전용.** 그 외 용도에 절대 사용 금지 |
| 🔵 블루 | `#0058be` | AI, 정보, 링크, 보조 행동 |
| 🟢 그린 | `#006e2f` | 성장, 완료, 주요 행동 |
| 🔴 Error | `#ba1a1a` | 오류, 어려움(Hard) 난이도 |

## 디자인 값 중앙 관리

가능하면 아래 값을 중앙에서 관리한다: 색상 토큰, 타이포그래피, 간격, 라운드, `ThemeData`, 공통 컴포넌트.

참고 파일의 CSS 표현은 Flutter 코드로 변환해 적용한다.

| 참고 파일의 CSS 표현 | Flutter 대응 |
|----------------------|--------------|
| `box-shadow` | `BoxShadow` |
| `hover` | Flutter Web/Desktop에서만 적용 |
| `press` | `InkWell`, `GestureDetector`, `ButtonStyle` |
| `full radius` | 충분히 큰 `BorderRadius.circular(...)` |
| `tint` (틴트) | 프로젝트에서 쓰는 `Color` alpha API (예: `Color.withValues(alpha: ...)`) |

## 금지

화면 위젯 안에 아래 값을 **직접 하드코딩하지 않는다.** 토큰과 테마를 참조한다.

- HEX 색상
- 반복되는 `EdgeInsets`
- 반복되는 `BorderRadius`
- 반복되는 `TextStyle`
- 반복되는 `BoxShadow`

아래 항목은 이 Skill로 **임의로 변경하지 않는다.** 디자인 구현을 위해 변경이 필요해 보이더라도 직접 고치지 말고, 변경 필요성만 별도로 보고한다.

- Firestore 컬렉션 및 데이터 모델
- API 요청과 응답 계약
- AI 프롬프트 및 응답 스키마
- 퀘스트 비즈니스 규칙
- 코인 및 XP 보상 정책
- 인증 및 권한 로직

그 밖에:

- 작업과 관련 없는 참고 파일을 열지 않는다.
- 기존 코드와 디자인 문서가 충돌하면 임의로 수정하지 않는다. 충돌 내용을 보고한다.
