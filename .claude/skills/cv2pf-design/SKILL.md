# CV2PF Design — 앱 셸 디자인 시스템 & 리뷰 스킬

CV2PF(“CV → 포트폴리오 생성기”) **도구 UI의 디자인 의도**를 한 곳에 못 박고, 만들어진 화면이
그 의도와 맞는지 **같은 기준으로 검수**하기 위한 스킬이다. 마음에 안 들면 이 파일에 피드백을
남기고(§피드백 루프) 반복해서 고친다.

## 무엇을 다스리는가 (범위)

- **적용 대상:** CV2PF **도구 화면**(앱 셸) — 상단 앱바, 좌측 4단계 사이드바, 카드, 스텝퍼,
  버튼, 입력, DESIGN.md 뷰어, 생성 로그 터미널, 결과 미리보기 프레임.
- **적용 대상 아님:** 사용자가 **생성해서 다운로드하는 포트폴리오**의 디자인. 그건 `client/designs/`
  의 6개 테마(minimal-clean·terminal-dark·…)가 담당한다. 헷갈리지 말 것.
- **의도의 출처(Source of truth):**
  - 스티치 시안 4종 — `cv-to-portfolio/stitch_designs/{1._cv_kr,2._kr,3._kr,4._kr}/screen.png`
  - 디자인 명세 — `cv-to-portfolio/stitch_designs/professional_career_engine/DESIGN.md`
  - 구현 토큰 — `cv-to-portfolio/client/src/index.css` 의 `:root`

## 언제 쓰나

- CV2PF 화면/컴포넌트를 새로 만들거나 스타일을 바꿀 때 → 아래 토큰·컴포넌트 규격을 따른다.
- “이 화면이 시안(의도)과 맞아?”를 확인할 때 → **§디자인 리뷰 워크플로**를 돌린다.
- 색/폰트/간격이 애매할 때 → `reference/design-system.md` 를 연다.

## 핵심 원칙 (3줄 요약)

1. **Corporate Modern** — 신뢰감 있는 파랑, 넉넉한 여백, 카드 기반, 콘텐츠가 주인공.
2. **한 가지 파랑(액션)과 한 가지 초록(전환)** — 파랑은 액션/활성, 초록은 “생성·다운로드”에만.
3. **접근성은 기본값** — 본문 대비 WCAG AA 이상, 상태는 색만이 아니라 텍스트+ARIA로도.

## 디자인 토큰 (빠른 참조)

전체 표·근거는 `reference/design-system.md`. 아래는 검수 시 눈으로 대조할 핵심값.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| Primary (Corporate Blue) | `#2563EB` | 버튼·활성 스텝·링크·진행바 |
| Primary strong | `#004AC6` | 강조 텍스트/hover |
| Primary soft | `#EFF4FF` | 선택/활성 배경 틴트 |
| Success (Green) | `#059669` | **생성·다운로드 전환 액션에만** |
| Ink (본문) | `#0F172A` | 배경 대비 ≈ 15.6:1 |
| Muted | `#64748B` | 보조 텍스트·라벨 |
| Line | `#E2E8F0` | 카드 테두리·구분선 |
| Surface/BG | `#FFFFFF` / `#F8FAFC` | 카드 / 작업 영역 |
| Font | **Inter** → Pretendard → 시스템 | 전 화면 공통(한글 폴백) |

## 레이아웃 & 컴포넌트 (요지)

- **셸:** 상단 앱바(좌: `CV2PF` 워드마크 / 중: 도움말 / 우: 임시저장·아바타) + **좌측 세로
  사이드바에 4단계 내비**(CV 업로드 → 디자인 선택 → 생성 → 완성) + 넓은 콘텐츠 영역.
- **스텝퍼:** 활성=파란 원+굵은 라벨, 완료=초록 원+체크, 대기=회색. **색만이 아니라
  체크/번호 글리프 + `aria-current="step"`** 로도 상태 전달.
- **버튼:** Primary=파란 채움 / Success=초록 채움(생성·다운로드) / Ghost=테두리만(뒤로).
  반경 8px, 포커스 링 2px offset.
- **카드:** 흰 배경, 1px `#E2E8F0` 테두리, L1 그림자, 반경 12–16px. hover 시 살짝 떠오름.
- 컴포넌트 상세(입력 상태, 선택 카드, DESIGN.md 뷰어, 생성 로그, 미리보기 프레임)는
  `reference/design-system.md` 참조. 화면별 의도는 `reference/screens.md` 참조.

## 디자인 리뷰 워크플로 — “의도와 맞는지 확인”

새/수정 화면을 검수할 때 이 순서로 돈다. 결과는 `PASS / 개선 / 불일치`로 표시한다.

1. **의도 로드** — 해당 화면의 스티치 시안(`screen.png`)과 `reference/screens.md`를 연다.
2. **토큰 대조** — 실제 색/폰트/반경/간격이 위 토큰 표와 일치하는가? (하드코딩 값 발견 시 불일치)
3. **레이아웃 대조** — 셸(앱바+좌측 사이드바), 그리드, 여백이 시안 구조와 맞는가?
4. **컴포넌트 대조** — 스텝퍼/버튼/카드/입력이 규격대로인가? Success 초록이 전환 액션에만 쓰였나?
5. **체크리스트 통과** — 아래 항목을 전부 확인.
6. **판정 기록** — 불일치/개선 항목을 파일·라인과 함께 적고, 필요하면 고친 뒤 재검수.

### 검수 체크리스트

- [ ] 팔레트: Primary `#2563EB`, Success `#059669` 사용. 인디고/다른 파랑 섞이지 않음.
- [ ] Success 초록은 **생성·다운로드 등 전환 액션에만** (그 외 액션은 파랑/고스트).
- [ ] 폰트: Inter 우선 + 한글 폴백. 도구 UI에 세리프/모노 본문 없음.
- [ ] 반경: 버튼·입력 8px, 카드 12–16px. 제각각(예: 라운드 999px 버튼) 아님.
- [ ] 본문 대비 WCAG AA(≥ 4.5:1) 이상. muted 텍스트도 보조 용도 한정.
- [ ] 셸 구조: 상단 앱바 + 좌측 4단계 사이드바(넓은 뷰). 좁은 뷰 대응 있음.
- [ ] 상태 전달이 **색만이 아님**: 스텝 상태에 글리프+`aria-current`, 로딩에 `role="status"`.
- [ ] 포커스 가시성: 인터랙티브 요소에 포커스 링, 논리적 탭 순서.
- [ ] 입력 라벨/에러: 라벨 존재, 에러는 색+텍스트로 즉시 안내.
- [ ] 여백/그림자가 “Corporate Modern”의 차분함을 유지(과한 그라디언트·네온 없음).

## 피드백 루프 — 스킬을 반복해서 고치기

이 스킬은 **살아있는 기준**이다. 검수 결과가 마음에 안 들거나 의도가 바뀌면:

1. 무엇이 어긋났는지 한 줄로 적는다. (예: “활성 스텝 파랑이 너무 연하다”)
2. **토큰/규격을 이 파일에서 직접 고친다.** (값이면 표에서, 규칙이면 체크리스트에서)
3. 아래 **변경 이력**에 날짜·이유를 남긴다.
4. 바뀐 기준으로 화면을 재검수한다.

> 피드백 예시 문장: *“cv2pf-design 스킬로 완성 화면 검수해줘 — 다운로드 버튼이 초록 맞는지랑
> 카드 반경만 봐줘”*, *“활성 스텝 배경을 EFF4FF보다 진하게 바꾸고 체크리스트에 추가해줘”*.
