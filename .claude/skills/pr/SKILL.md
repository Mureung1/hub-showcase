# 과제 PR 생성 절차

## 1. 사전 확인

```bash
git status                 # 커밋 안 된 변경이 없어야 함
git log --oneline -10      # 이번 PR에 담길 커밋 확인
gh run list --branch <브랜치> --limit 1   # CI 통과 확인 (push된 경우)
```

- 커밋 안 된 변경이 있으면 먼저 `/commit`으로 정리한다.
- push가 필요하면 사용자에게 확인 후 push한다 (CLAUDE.md: 푸시는 요청 시에만 — `/pr` 요청에 push 의사가 포함됐는지 애매하면 묻는다).
- **base 저장소·브랜치 확인**: origin(개인 fork `Catsmanager/hub`)인지 upstream(과제 조직)인지, 대상 브랜치가 무엇인지 사용자에게 확인한다. 참고: 과제 auto-merge 워크플로는 **main 타겟 PR은 자동 머지하지 않고**, 비-main 타겟 PR을 매일 자동 머지한다.

## 2. 타이틀·본문 작성

- 타이틀: `[N166_진현지] 이번 작업 한 문장 요약`
- 본문: `.github/pull_request_template.md`의 4개 섹션을 전부 채운다.

| 섹션 | 작성 주체 |
|---|---|
| 주요 작업 리스트 | 커밋 로그·diff에서 요약해 작성. 동작 화면·스크린샷이 있으면 첨부 안내 |
| 내가 설명할 수 있는 부분 | **사용자에게 질문해서 사용자의 말로** — 코드 한 곳을 골라 왜 그렇게 짰는지. 대필 금지 (학습 회고는 본인 것이어야 과제 의미가 있다) |
| 아직 이해 못 한 부분 | **사용자에게 질문해서 사용자의 말로** — 없다고 하면 "없음"으로 |
| 새로 알게 된 것 | **사용자에게 질문해서 사용자의 말로** |

회고 3개 섹션은 초안을 대신 써주지 않는다. 대신 이번 diff에서 물어볼 만한 지점(예: "sessionStorage 동기화 부분을 직접 설명할 수 있겠어요?")을 골라 질문으로 유도하는 것까지만 한다.

## 3. 생성

```bash
gh pr create --title "[N166_진현지] ..." --body "..." [--repo <base저장소>] [--base <브랜치>] --label <라벨>
```

- 라벨은 저장소의 라벨 목록(`gh label list`)에서 작업 성격에 맞는 것을 골라 제안하고 사용자 확인 후 지정.
- 생성 후 PR URL을 보고하고, Vercel 프리뷰가 있으면(T17 이후) 프리뷰 URL을 본문에 추가한다.
