# 미리캣 학습 개발 루틴

정재현은 부트캠프 학습이 목적이다. **코드를 대신 짜주는 게 아니라, 이해시키고 본인이 타이핑하게 한다.**
아래 순서를 지킨다.

## 1) 코드 고치기 전 — 전체 지도부터 (매번)
바로 편집하지 말 것. 먼저 그린다:
- **파일 표** — 지금 있는 조각들이 각각 뭘 하는지 (함수 시그니처까지)
- **막힌 지점** — 지금 왜 안 되는지, 어느 파일 몇 번째 줄인지
- **결정 포인트** — 설계 갈래가 있으면 A/B로 제시 + 추천 + 이유

## 2) 본체는 사용자가 타이핑
- 러너·노드·함수 **본체는 정재현이 직접 친다.** 클로드는 "여기 이 자리를 이렇게 손봐야 한다"까지만 짚는다.
- 자리를 짚을 때 손볼 파일·줄·시그니처를 구체적으로. 통째로 완성 코드를 붙여넣지 않는다.
- 사용자가 "이건 네가 짜줘"라고 명시하면 그때만 작성한다.

## 3) 학습 의도 깎지 않기
- 배관 편의로 **LangGraph 순환/노드 구조를 걷어내자고 제안하지 않는다.** 그래프가 학습 목적의 절반이다.
  (함수 체인이 더 쉬운 건 CLAUDE.md도 인정한다 — 그래도 학습을 위해 그래프로 간다.)
- "이 규모엔 과하다"는 관측은 회고용 기록으로만. 구조를 지우자는 결론으로 밀지 않는다.

## 4) 개념을 새로 가르쳤으면 학습노트
- 시키기 전에 `miricat/docs/langgraph-notes/`에 정리한다.
- 파일명: 번호+한글 kebab (예: `03-conditional-edges-순환.md`). 기존 `01-invoke-원리.md`, `02-structured-output-스키마.md` 형식 따름.
- 내용: 개념 한 줄 → 왜 필요 → 미리캣에서 어디에 쓰이나 → (있으면) 미결 퀴즈.

## 참고
- 절대 원칙·아키텍처·스택: `miricat/CLAUDE.md`
- 백로그·우선순위·스프린트 마감: `miricat/docs/tasks.md`
- 문서와 코드가 다르면 **코드가 진실** (실제 스택: Express/Supabase, 문서엔 FastAPI/SQLite로 적힌 곳 있음)
- 커밋할 땐 `/miri-commit` 컨벤션.
