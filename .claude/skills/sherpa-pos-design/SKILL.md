# Sherpa 시각 디자인 시스템 · UI 원칙 (헌법)

## 1. 목적

`sherpa-pos-design`은 Sherpa의 **모든 화면·컴포넌트가 반드시 따라야 할 시각 디자인 시스템과 UI 원칙의 단일 기준**이다. 기능 로직이나 도메인 규칙이 아니라 **"어떻게 보이고, 어떻게 최소한으로 조작되는가"**만 다룬다.

새 화면·컴포넌트를 만들거나 색·간격·버튼을 정하기 전에 이 문서를 먼저 읽고, 여기 정의된 토큰과 원칙 안에서만 결정한다. 이 문서에 없는 색·컴포넌트·기능을 임의로 추가하지 않는다.

## 2. 이 스킬이 하는 일 (IN)

- 색 역할(role)과 hex 토큰 정의
- 타이포그래피 · 간격 · 모서리 규칙 (기존 `src/styles.css` 값 재사용)
- 핵심 UI 원칙: 최소 버튼, 점진적 노출, 맥락형 UI, 우아한 오류 처리
- 컴포넌트가 이 시스템을 어떻게 준수해야 하는지의 기준

## 3. 이 스킬이 하지 않는 일 (OUT) — 중요

- **도메인 로직**(상품 모델, FEFO 정렬, 스캔 입력 파이프라인, IndexedDB/Dexie 등) → 별도 스킬 소관. 여기서 다루지 않는다.
- **화면별 기능 명세** → 별도 스킬 소관.
- **Sherpa 범위 밖 기능은 UI로도 만들지 않는다:** 결제 처리, 현금 서랍, 영수증 출력, 멀티기기 동기화.
- **벤치마크 스크린샷의 요소를 그대로 복제하지 않는다.** (→ §7)

## 4. 디자인 토큰 (색 역할)

색은 반드시 아래 "역할"에 따라 배정한다. 한 색이 두 역할을 맡지 않는다 — 역할이 겹치면 의미가 흐려진다.

핵심 원리: **같은 초록 계열이라도 명도(value)를 크게 벌리면 역할이 분리된다.** 브랜드 초록은 어두운 구간, 콘텐츠 초록은 밝은 구간에 둔다.

| 역할 | 용도 | 값 | 규칙 |
|---|---|---|---|
| 브랜드 / 크롬 | 상단바, 활성 탭 밑줄 | 포레스트 그린 `#1F4436` | 어둡게, 오직 하나. 밝은 초록 띠 금지 |
| 콘텐츠(카테고리) | 사장님이 고르는 카드 색 | 밝은 팔레트 — 예: 주황 `#D98A4E`, 초록 `#8CB56A` | 밝은 구간 유지. **딥그린은 이 팔레트에서 제외** |
| 핵심 액션(CTA) | 저장·입고 확정 등 주요 액션 | 브랜드와 다른 색 — 예: 파랑 `#3182F6` | **초록 금지.** 브랜드/콘텐츠 초록과 섞이면 CTA가 파묻힌다 |
| 시맨틱 | 상태 신호 | 재고부족=빨강 `#d6482f`, 유통기한 임박=앰버 `#e0912a`, 성공=밝은 초록 `#1f8a54` | 브랜드 딥그린과 명확히 구분되는 밝은 초록만 성공색으로 |
| 중립 | 배경·텍스트·보더 | 그레이 스케일 — `--paper #fbfcf9`, `--ink #16241c`, `--inkSoft #4c5c52`, `--line #dde7df` | 화면의 기본 바탕 |

### 토큰 출처
- **새로 확정(이 스킬):** 브랜드 `#1F4436`, 카테고리 `#D98A4E`·`#8CB56A`, CTA `#3182F6`.
- **기존 `src/styles.css` `:root` 재사용:** 시맨틱(`--red #d6482f`, `--amber #e0912a`, 성공 `--fresh #1f8a54`), 중립(`--paper`, `--ink`, `--inkSoft`, `--line`), 타이포(`--font-sans` = IBM Plex Sans KR / `--font-mono` = 가격 등 숫자는 tabular-nums), 모서리(`--radius 18px`, `--radius-sm 12px`).
- 카테고리 팔레트의 2색은 **예시**다. 색을 더 늘려야 하면 임의로 추가하지 말고 확인을 받는다.

### 텍스트 대비 (색 위 글자색)
색은 반드시 그 위 텍스트가 읽히도록 배정한다. 검증된 조합:

| 배경 | 텍스트 | 대비 | 판정 |
|---|---|---|---|
| 브랜드 `#1F4436` | 흰색 | ~10:1 | 통과 |
| CTA `#3182F6` | 흰색 | ~3.7:1 | 큰/굵은 버튼 텍스트만 통과 (≥16px bold) |
| 카테고리 `#D98A4E` | 짙은 잉크 `#16241c` | ~5.7:1 | 통과 |
| 카테고리 `#8CB56A` | 짙은 잉크 `#16241c` | ~6.7:1 | 통과 |

- **밝은 카테고리 카드의 라벨·가격은 흰색이 아니라 짙은 잉크(`--ink`)로 둔다** — 밝은 팔레트 위 흰 글씨는 대비를 통과하지 못한다.
- CTA 파랑 위 흰 글씨는 버튼 텍스트가 크고 굵을 때만 쓴다.
- 새 색을 확정하기 전 항상 대비를 계산하고, 기준 미달이면 임의로 색을 바꾸지 말고 보고한다.

## 5. UI 원칙 (모든 생성에 강제 적용)

1. **최소 버튼** — 기본 화면에는 핵심 동작만 노출. 부가 기능은 숨기거나 2차 진입으로.
2. **점진적 노출(progressive disclosure)** — 옵션은 필요한 순간에만 등장.
3. **맥락형 UI** — 지금 상황에 필요한 것만 보여준다.
4. **우아한 오류 처리** — 실패를 복구 가능하게, 파괴적 동작(삭제 등)은 확인 절차 필수.
5. **비전문가 기준** — 훈련된 계산원이 아니라 가끔 쓰는 사장님이 대상. 학습 없이 조작 가능해야 한다.
6. **빠른 반복 입력 최적화** — 스캔 → 목록 누적 → 확정 흐름이 매끄러워야 한다.
7. **색은 의미를 담을 때만** — 장식 목적의 색 사용 금지. 상태는 색 단독이 아니라 **색 + 텍스트**로 전달한다 (기존 `src/status.js`·`src/components/StatusBadge.jsx`의 접근성 철학 계승).

## 6. 안티패턴 (생성 금지 목록)

- 실제로 쓰지 않는 버튼으로 화면을 채우는 것
- 카페/음식점 POS 요소 복제 (매장/포장 토글, S/M/L·컵 옵션, 분할결제 등)
- 브랜드 딥그린을 카드 색이나 성공 색으로 재사용
- 핵심 액션(CTA)을 브랜드 초록과 같은 색으로 두는 것
- 파괴적 동작을 확인 없이 즉시 실행
- 명세에 없는 기능·요소를 "POS니까 보통 있으니까"라며 임의 추가

## 7. 벤치마크 스크린샷 취급 방침

토스플레이스 등 참고 스크린샷은 **패턴 학습용이지 복제 대상이 아니다.**

- **추출할 것:** 통합 상품 데이터 모델, 탭 구조, 우측 장바구니 레이아웃 개념
- **무시할 것:** 카페 전용 기능 전부 (§6 안티패턴 참고)
