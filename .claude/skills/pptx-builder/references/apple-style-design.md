# 애플 스타일 — PPT용으로 옮긴 디자인 언어

원본은 apple.com(홈페이지·environment·store·iPhone 구매 페이지·액세서리 목록)을 분석한 웹 디자인 시스템이다. 이 문서는 그중 **정적인 16:9 슬라이드에 옮길 수 있는 부분만** 골라서 pptx-builder용으로 재구성한 것 — 반응형 브레이크포인트처럼 슬라이드에 적용할 수 없는 항목은 뺐다. "고급스럽고 조용한, 사진(또는 실제 화면 캡처) 중심의 발표 자료"를 만들 때 이 문서를 참고 톤으로 쓴다. 발표 대상이 이미 자체 브랜드 톤(로고색 등)을 갖고 있으면 이 문서 대신 그 브랜드 값을 우선한다 — SKILL.md의 "디자인 토큰부터 정한다" 원칙이 항상 이 문서보다 위에 있다.

## 핵심 철학
UI가 존재감을 지우고 콘텐츠(제품 사진, 실제 화면 스크린샷)가 주인공이 되게 한다. 장식은 최소, 여백은 크게, 색은 한 가지 포인트 컬러만 쓴다. "화려하게 채운다"가 아니라 "불필요한 걸 다 뺀다"가 이 스타일의 본질이다.

## 컬러
색 하나만 강조색으로 쓰고, 밝은/어두운 배경 두 모드를 번갈아 써서 리듬을 만든다.

| 용도 | 색 | 비고 |
|---|---|---|
| 포인트(강조) | `#0066CC` | 링크·버튼·포커스 전부 이 한 색. 두 번째 강조색을 만들지 않는다 |
| 어두운 배경용 링크 | `#2997FF` | 어두운 타일 위에서 포인트색이 너무 안 보일 때만 |
| 밝은 캔버스 | `#FFFFFF` | 기본 배경 |
| 오프화이트 캔버스 | `#F5F5F7` | 밝은 타일을 두 개 연속으로 안 쓰기 위한 중간톤 |
| 어두운 타일 | `#1D1D1F` ~ `#2A2A2C` | 타일마다 살짝 다른 톤(1~2단계 차이)을 써서 어두운 타일이 연속될 때 미세한 구분을 준다 |
| 순검정 | `#000000` | 진짜 여백이 필요한 곳에만(예: 표지 배경) — 본문엔 안 씀 |
| 본문 텍스트 | `#1D1D1F` | 순검정 대신 이 톤 — 인쇄물이 아니라 사진처럼 보이게 함 |
| 어두운 배경 위 텍스트 | `#FFFFFF` / `#CCCCCC`(보조) | |
| 테두리/구분선 | `#E0E0E0` | 카드 테두리 등, 아주 옅게만 |

이 팔레트를 쓸 땐 `pptx_helpers.py`의 `PRIMARY`, `INK`, `PAPER`, `SURFACE`, `BORDER` 상수를 이 값들로 덮어쓴다.

## 타이포그래피
- 영문: 시스템 기본 폰트(`Segoe UI`, `Calibri` 등)로 대체 — SF Pro는 임베드가 안 되면 다르게 보이니 원본 폰트를 그대로 쓰려 하지 않는다.
- 한글: `맑은 고딕`.
- **큰 제목엔 자간을 살짝 좁힌다.** `add_text()`에 자간 조정 파라미터는 없지만, 큰 제목(28pt 이상)일 땐 폰트 크기를 1~2pt 낮추는 방식으로 시각적으로 "타이트한" 느낌을 흉내낼 수 있다.
- 굵기는 400(본문) / 600(제목) 두 단만 쓴다. 500은 일부러 안 쓴다 — 중간 굵기가 필요하면 600을 쓴다.
- 본문은 다른 발표자료보다 약간 크게(17pt 전후) 잡아서 "읽는" 속도로 가게 한다. 12pt 이하로는 절대 안 내려간다(각주 제외).

| 슬라이드 요소 | 크기 | 굵기 |
|---|---|---|
| 히어로(표지) 제목 | 40~44pt | 600 |
| 일반 슬라이드 제목 | 26~28pt | 600 |
| 부제목/리드 | 13~15pt | 400 |
| 본문 | 12~13pt | 400 |
| 캡션/각주 | 10~10.5pt | 400 |

## 레이아웃 — 헤더는 항상 같은 자리에
가장 중요한 규칙: **챕터명(eyebrow)·제목·부제목은 슬라이드가 바뀌어도 항상 같은 y좌표에 있어야 한다.** 애플 사이트가 페이지마다 같은 내비게이션 위치·같은 히어로 레이아웃을 쓰는 것과 같은 이유 — 위치가 흔들리면 발표가 어수선해 보인다.

`pptx_helpers.py`에 이미 이 그리드가 상수로 박혀 있다:
- `HEADER_X` — 왼쪽 시작 x좌표
- `HEADER_EYEBROW_Y` / `HEADER_TITLE_Y` / `HEADER_SUBTITLE_Y` — 챕터명/제목/부제목 y좌표
- `CONTENT_TOP_Y` — 본문이 시작되는 공식 y좌표

새 슬라이드를 만들 때 제목을 직접 `add_text()`로 그리지 말고 **`add_slide_header(slide, title, eyebrow=..., subtitle=...)`를 거쳐서** 그린다. 이렇게 하면 좌표를 슬라이드마다 다시 계산할 필요가 없고, 구조적으로 흔들림이 안 생긴다.

여백은 애플처럼 크게 준다 — 제목 위 최소 0.5인치, 본문 시작 전 최소 0.3인치.

## 본문 밀도 — 비워두지 않는다 (표지·목차는 예외)
여백을 크게 준다는 것과 "슬라이드 하단이 텅 비어 보인다"는 건 다른 문제다. 애플은 여백을 의도적으로 쓰지만, 콘텐츠가 부족해서 생긴 빈 공간은 없다 — 모든 타일이 제목+부제목+CTA+제품 이미지로 프레임을 다 채운다.

슬라이드를 다 그린 뒤 렌더링 결과를 볼 때 이렇게 체크한다:
1. 슬라이드 세로 길이의 아래쪽 20~25% 이상이 완전히 빈 여백이면 밀도가 부족한 것이다.
2. 채울 때는 **장식을 더하지 말고 실제 정보를 더한다** — 예: 근거가 되는 수치 한 줄, 관련 화면 스크린샷 하나 더, `add_footnote()`로 출처/요약 한 줄. 빈 도형이나 의미 없는 아이콘으로 채우지 않는다.
3. 그래도 자연스럽게 채울 내용이 없다면(예: 클로징 슬라이드), 억지로 채우기보다 제목 자체를 크게 키워서(hero 크기로) 여백을 "의도된 여백"으로 바꾼다 — 애매하게 반쯤 빈 것보다 확실히 크게 비우는 쪽이 낫다.
4. **표지(첫 슬라이드)와 목차 슬라이드는 이 규칙을 적용하지 않는다.** 이 두 슬라이드의 역할은 정보 전달이 아니라 "소개"이므로, 메타 카드 몇 개 + 여백 정도가 오히려 맞는 밀도다. 목차가 필요하면 표지에 얹지 말고 별도 슬라이드(번호+제목+한 줄 설명 리스트)로 분리한다 — 표지 하나에 소개와 목차를 모두 욱여넣으면 "난잡하다"는 인상을 준다.
5. **각주는 청중을 위한 내용만.** 저장소명·브랜치명·"이 자료도 코드로 만들었다" 같은 제작 메타정보는 밀도를 채우는 용도로 쓰지 않는다 — 청중에게 무의미한 정보로 하단을 채우는 건 밀도가 아니라 잡음이다.

## Elevation(그림자) — 딱 하나만
그림자는 실제 사진/스크린샷이 배경 위에 놓일 때만 쓴다 (`rgba(0,0,0,0.22) 3px 5px 30px` 느낌). 카드·버튼·제목엔 그림자를 절대 안 쓴다. `add_box()`는 기본적으로 그림자 없음(`shadow.inherit = False`)이라 이미 이 원칙을 따르고 있다 — 일부러 그림자를 추가하지 않는다.

## 도형(radius)
| 용도 | 반경 |
|---|---|
| 풀블리드 섹션(배경 전체를 채우는 타일) | 0 — 각 안 둥글림 |
| 유틸리티 카드(스크린샷 프레임 등) | `radius=0.08~0.09` (지금 `add_box()` 기본값과 비슷) |
| 캡슐형 버튼/배지 | `radius=0.5` (완전한 필 모양, `add_eyebrow()`가 이미 이 값을 씀) |

## 슬라이드 패턴 (컴포넌트 → 슬라이드 유형 매핑)
원본의 "product-tile-light/dark", "store-utility-card" 같은 웹 컴포넌트를 슬라이드 유형으로 옮기면:

- **히어로/표지 슬라이드**: 큰 제목(40pt+) + 짧은 한 줄 부제 + 대표 이미지. 배경은 밝은 캔버스 또는 순검정.
- **밝은 타일 슬라이드 ↔ 어두운 타일 슬라이드**: 연속되는 정보 슬라이드를 밝음/어두움으로 번갈아 배경을 바꿔서, 별도 구분선 없이 "여기서 섹션이 바뀌었다"는 걸 색으로만 알려준다. `add_slide(prs, bg=...)`의 `bg` 값만 바꾸면 된다.
- **유틸리티 카드 그리드 슬라이드**: 스크린샷·기능 목록처럼 여러 항목을 나열할 때 — 얇은 테두리 카드를 격자로 배치(`add_box()` + `add_picture_framed()` 조합).
- **클로징 슬라이드**: 큰 인사말 + 여백. 억지로 채우지 말고 위 "본문 밀도" 3번 원칙대로 제목을 키운다.

## Do / Don't
**Do**
- 포인트 컬러 하나만 쓰고 끝까지 지킨다.
- 제목/부제목은 항상 `add_slide_header()`로만 그린다.
- 그림자는 실제 이미지에만.
- 본문이 짧아서 하단이 비면 실제 정보로 채우거나(각주, 보충 이미지), 제목을 키워서 여백을 의도적으로 만든다.

**Don't**
- 카드·버튼·텍스트에 그림자 넣지 않기.
- 강조색을 두 개 이상 쓰지 않기.
- 빈 공간을 도형·아이콘 같은 장식으로 채우지 않기 — 채울 정보가 없으면 차라리 크게 비운다.
- 슬라이드마다 제목 y좌표를 다르게 잡지 않기.
