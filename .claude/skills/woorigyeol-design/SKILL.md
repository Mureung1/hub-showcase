# 우리결 디자인 skill

우리결 서비스의 톤앤매너(따뜻한 살구빛 파스텔 + 룸메이트=민트/과팅=핑크 카테고리 구분)를
모든 화면에서 깨지지 않게 유지하기 위한 skill이다.

## 언제 이 skill을 확인해야 하는가

- 우리결의 새 화면을 목업/와이어프레임/컴포넌트로 만들 때
- 기존 화면(로그인, 회원가입, 테스트, 매칭 결과 등)을 수정할 때
- 색상, 버튼, 카드, 인풋 등 특정 컴포넌트 스타일을 정할 때
- Claude Code에서 `intro-page`(React) 또는 `vanillla-prototype`(바닐라 HTML/CSS) 폴더 안의 화면을 작업할 때
- Claude.ai 채팅에서 우리결 관련 화면을 시각화/디자인해달라는 요청을 받을 때

## 작업 순서

1. **`references/DESIGN.md`를 먼저 읽는다.** 색상 팔레트, 타이포그래피, 컴포넌트 규칙, 레이아웃 원칙이 전부 정리되어 있다. 이 문서가 유일한 정답 소스(source of truth)다.
2. 만들려는 화면이 **룸메이트 트랙**인지 **과팅 트랙**인지 **공통(온보딩 등)**인지부터 판단한다. → 컬러가 바로 결정됨 (룸메=민트, 과팅=핑크, 공통=코랄/크림)
3. 화면 유형이 아래 8가지 컴포넌트 패턴 중 무엇에 가장 가까운지 확인하고, 해당 패턴의 구조를 그대로 따른다 (DESIGN.md 4장 참고):
   - Primary 버튼 / 인풋 필드 / 양자택일 카드(테스트) / 선택 카드(목적 선택) / 리스트 카드(매칭 결과) / 팀 구성 화면 / 궁합 상세 화면 / 아이콘·이모지 톤
4. 새로운 컴포넌트 패턴이 필요해서 DESIGN.md에 없는 걸 새로 만들어야 한다면, **기존 팔레트/타이포/여백 규칙 안에서만** 새로 디자인하고, 다 만든 뒤 "DESIGN.md에 이 패턴을 추가할지" 사용자에게 물어본다. (Section 6 참고 — 새 화면도 카테고리 컬러 규칙을 반드시 따를 것)
5. 결과물을 보여줄 때, 어떤 DESIGN.md 규칙을 적용했는지 간단히 한 줄로 언급한다 (예: "룸메이트 트랙이라 민트 계열, 리스트 카드 패턴 적용했어요"). 장황한 설명은 피하고 핵심만.

- [ ] 배경은 크림(#FBE8DA) 계열인가?
- [ ] 룸메/과팅 카테고리 컬러가 맞게 들어갔는가? (섞이면 안 됨)
- [ ] Primary 버튼은 풀와이드 + 완전 라운드 + 코랄인가?
- [ ] 텍스트 계층(제목=진한 브라운, 본문=웜그레이)이 지켜졌는가?
- [ ] 카드 모서리, 그림자, 여백이 기존 화면들과 비슷한 톤인가?
- [ ] 아직 없는 화면(랜딩/채팅방/신고하기/마이페이지)을 새로 만드는 거라면 DESIGN.md 7장의 원칙을 그대로 적용했는가?

## 이 skill을 최신 상태로 유지하기

우리결 프로젝트의 화면이 실제로 새로 만들어지거나 디자인이 바뀌면, 그 내용을 `references/DESIGN.md`에도 반영해서 skill과 실제 프로젝트 상태가 어긋나지 않게 한다. 프로젝트 레포 루트의 `DESIGN.md`와 이 skill의 `references/DESIGN.md`는 항상 같은 내용을 유지해야 한다.
