## 원칙: 기능 구현 없이 시각만 먼저 보여준다

- 화면 디자인을 보여줄 때는 실제 훅/상태/로직을 연결하지 않는다. 하드코딩된 더미 데이터로 레이아웃·색·타이포·여백만 보여준다.
- 실제 `hub` 앱 소스(`src/pages/*`, `src/features/*`)를 먼저 고쳐서 미리보기하지 않는다. **Artifact 도구**로 정적 HTML 목업을 만들어 보여준다 — 앱 라우팅/기존 기능을 건드릴 위험이 없고 재배포가 빨라 반복에 적합하다. Artifact 발행 전에는 반드시 `artifact-design` 스킬을 먼저 로드한다(이건 우리 프로젝트 스킬이 아니라 Artifact 도구 자체의 필수 준비 단계).
- 같은 화면을 반복 수정할 때는 새 Artifact를 만들지 않고 같은 `file_path`로 다시 `Artifact` 호출해서 같은 URL을 유지한다.
- 사용자가 "이제 실제로 적용해줘"라고 명확히 요청하면 그때 실제 소스 파일에 반영한다 — 이 단계부터는 기존 기능/훅 연결을 유지하면서 스타일만 갈아끼운다(트리 페이지 작업 때 방식).
- **스킬 자체를 만들거나 갱신하는 건 사용자가 명시적으로 요청했을 때만.** 디자인 방향이 아직 안 정해졌는데 먼저 스킬화부터 하지 않는다 — 실제로 이 프로젝트에서 "아직 디자인 정하지도 않았는데 왜 스킬부터 만드냐"는 피드백을 받은 적 있음.

## 확정된 디자인 규칙 (2026-07-13 기준)

### 색 — `src/index.css`의 `:root`가 단일 소스
- 배경: `--color-bg-page: #0b0d12`(페이지) → `--color-bg-card: #181c26`(카드, page보다 명도 확실히 높게) → `--color-bg-card-hover: #1f2430`
- 카드는 반드시 페이지 배경과 눈에 띄게 구분되어야 한다 — 이전에 카드 배경(#14171f)이 페이지 배경(#0b0d12)과 너무 비슷해서 "뭐가 바뀐 건지 모르겠다"는 피드백을 받았음. 명도 차이 + `--color-border-card-strong`(0.12 alpha, `--color-border-card` 0.06은 outer 카드엔 너무 약함) + `--shadow-card`(elevation) 세 가지를 항상 같이 써서 depth를 준다.
- 시맨틱 역할은 고정, 값만 조정: 주색(accent)=cyan `#22d3ee`, compare=orange `#f7931a`, success=teal-green `#5dcaa5`, danger=red `#ef4444`, secondary-accent=indigo `#6366f1`. 역할 자체를 바꾸려면 사용자에게 먼저 확인.
- 글자: `--color-text-primary` `#f5f6f8` / `--color-text-secondary` `#c7cad1` / `--color-text-muted` `#8b909c`
- 모서리: 배지 6px / 컨트롤 10px / 카드 16px / pill 9999px / 코드블록 10px

### 카드 vs IDE 창 — 적용 범위
- **기본은 카드**(`Card.tsx`: `rounded-16px`, `border-card-strong`, `shadow-card`) — 화학과·생명과학·물리학·기능 B(스택/큐/덱)·로그인·AI Q&A 등 전부.
- **IDE 창 모티브**(`CodeWindow.tsx`: 트래픽라이트 점 + 모노스페이스 타이틀바)는 **코드/의사코드 패널에만** — CS/수학과 알고리즘 콘텐츠. 일반화학처럼 코드가 없는 화면 전체를 IDE 창으로 감싸지 않는다.
- 이 프로젝트는 "코드만 시각화하는 게 목표가 아니다"라는 게 이 구분의 근거 — 확장 과목(화학/생명/물리)엔 코드가 없으므로 카드가 기본이어야 함.

### 글로우 강조 — 상태를 나타낼 때만
- 강조 대상: 비교/활성 노드, 활성 엣지, primary 버튼(재생), 사이드바 active 항목, 완료된 step tick, 플로팅 패널 테두리.
- 강도는 **뚜렷하게** — 처음엔 약하게 넣었다가 "글로우 강도 더 있어도 될거같다" 피드백을 받고 올림. 기준값: `drop-shadow` alpha 0.7~0.9, blur 10~16px / box-shadow 링 글로우는 `0 0 0 1px 강한색 alpha 0.3~0.4, 0 0 24~32px 같은색 alpha 0.2~0.4`. 은은한 정도가 아니라 눈에 바로 들어오는 정도로.
- 장식이 아니라 상태 인코딩 수단으로만 쓴다 — 아무 요소에나 은은하게 깔지 않는다.

### 사이드바
- 아이콘+라벨 항목, 학과별 그룹, 그룹 라벨은 무채색 소문자+letter-spacing uppercase 배지 톤.
- active 항목은 텍스트 색만 바꾸지 않고 **박스 자체가 채워지고 테두리+글로우가 생기는 방식**(Pinterest 레퍼런스의 "Project" active 항목 참고).
- 아이콘은 Tabler 등 외부 아이콘 폰트를 못 쓰는 컨텍스트(Artifact)에선 손으로 그린 단순 stroke SVG(2~4 primitive, `stroke="currentColor"`)로 대체 — 실제 앱에선 SVG 아이콘 라이브러리 사용 가능.
- 하단 promo/teaser 카드 자리에는 가짜 업셀 대신 **실제 로드맵 내용**을 넣는다(예: "화면 상태를 아는 AI Q&A · 2주차 목표 · 준비 중").
- 검색줄은 향후 4주차 검색 기능의 미리보기 자리로 겸용 가능.

### 노드-그래프 시각화 (트리, 분자 뷰어)
- 원(노드)+선(엣지) 구조는 이미 이 계열 레퍼런스(네트워크 그래프, 레이더 플롯)와 데이터 형태가 동일 — "우리 시각화가 너무 단순해서 저런 느낌 못 낸다"는 우려는 근거 없음, 표현 기법만 얹으면 됨.
- 캔버스 배경: 완전 검정 대신 아주 옅은 도트 그리드(`radial-gradient(rgba(255,255,255,0.05) 1px, transparent 1px)`, 22px 간격) + 중심부 은은한 accent-color radial glow.
- 활성/비교 노드·엣지에만 강한 drop-shadow 글로우, 나머지는 무채색 유지.
- 대기/미확정 요소(삽입 예정 값 등)는 점선(`stroke-dasharray`) + 같은 글로우 톤으로 "아직 배치 안 됨"을 표현.

### 배지 패턴
- 닷(원) + 라벨 pill. 색은 배지가 나타내는 상태의 시맨틱 색을 그대로 사용(장식용 랜덤 색 금지).

### 플로팅 오버레이 패널 (예: AI Q&A)
- 원형 게이지/레이더 위젯은 텍스트 대화엔 부적합(멀티라인 텍스트를 원 안에 구겨넣게 됨) — 대화형 콘텐츠는 항상 사각형 패널.
- "레이더 HUD" 느낌은 반투명 배경(`rgba(11,13,18,0.88)` + `backdrop-filter: blur`) + accent color 링 글로우 테두리로 재현.
- 시각화를 완전히 가리지 않는 위치(코드 패널 옆/아래 구석)에 겹쳐서 배치.
- AI 답변에는 항상 "참고용이며 부정확할 수 있다" 문구를 작은 muted 텍스트로 동반.

### 방사형(radial) 노드-그래프 + 검색 위젯 (홈페이지에서 확립, 2026-07-13)
- **극좌표 배치**: 중심 앵커에서 학과가 사방으로 뻗는 구조는 손으로 좌표를 찍지 말고 각도 기반 공식으로 계산한다 — `x = cx + r·sin(θ), y = cy - r·cos(θ)` (θ=0°가 위쪽, 시계방향 증가). 학과(트렁크)는 60° 간격 등 균등 배치, 리프는 트렁크 각도 기준 ±spread 범위 안에서 균등 분산.
- **라벨 겹침 방지의 핵심은 "라벨을 노드와 같은 각도로 더 바깥에" 두는 것**: 처음엔 라벨을 노드 위/아래로 손으로 오프셋해서 배치했다가 학과가 6개·리프가 20개 가까이 늘어나자 겹치기 시작함. 노드 반경보다 큰 반경으로 **같은 각도** 위치에 라벨을 놓고 `text-anchor`를 `sin(θ)` 부호로 자동 계산(오른쪽 방향이면 start, 왼쪽이면 end, 위/아래면 middle)하면, 노드가 사방으로 퍼질수록 라벨도 자연스럽게 벌어져서 겹침이 구조적으로 사라짐. 실제 적용 후 31개 라벨 bounding box를 좌표로 검사해 겹침 0건 확인함.
- **연결선은 완만한 이차 베지어 곡선**: 직선 대신 `M from Q control to` 형태로, control point는 두 점의 중점에서 직선에 수직 방향으로 소량(10~16px) 밀어서 계산. 형제 리프끼리는 밀어내는 방향(bow 부호)을 번갈아 줘서 유기적인 느낌을 줌.
- **학과 정체성 색은 기존 시맨틱 색과 별개의 새 팔레트**: compare(주황)/success(초록)/danger(빨강) 등 "행동 의미" 색과 겹치지 않는 새 hex 6개(`--dept-cs` cyan/`--dept-chem` 보라/`--dept-math` 금색/`--dept-physics` 파랑/`--dept-ee` 초록/`--dept-bio` 핑크)를 `index.css`에 별도로 정의해서 씀 — 기존 색의 "의미"를 재활용하지 않음.
- **연관 연결선(cross-link) 큐레이션은 기술이 아니라 판단의 문제**: 리프 하나 추가하는 건 배열에 한 줄이라 쉽지만, "어디에 정확히" 이어야 하는지가 어려움. 리프-리프 연결은 **구체적인 과목 대 과목 관계**(예: 물리화학↔양자역학)에만 쓰고, "컴퓨터공학 분야 전체가 선형대수학을 쓴다" 같은 분야 수준의 막연한 관계는 특정 리프에 억지로 붙이지 않는다(정확성 훼손). 이런 경우는 트렁크(학과 노드) 연결로 하거나, 아예 넣지 않는 것도 정당한 선택.
- **검색은 리프 라벨만 보면 안 되고 학과명도 봐야 함**: 리프 라벨에만 매치시키면 학과명(예: "컴퓨터공학")을 검색했을 때 아무것도 안 걸리는 버그가 남. 학과명이 쿼리에 매치되면 그 학과의 모든 리프를 자동으로 매치 목록에 포함시켜야, "학과명 검색 → 학과+소속 과목 전체 하이라이트"가 됨.
- **hover/검색 하이라이트는 CSS 구조적 선택자에 기대지 말 것**: 정적 HTML 목업 때 `.search-hit .node-label`(자손 선택자)로 원-라벨을 묶으려다, 실제 마크업에서 라벨이 원의 형제 요소라 전혀 매칭이 안 됐던 적이 있음(눈에 잘 안 띄는 실패라 "글로우가 특정 과목에 안 걸린다"는 사용자 피드백을 받고서야 발견). 실제 React 구현에서는 이 문제 자체가 없음 — `isHit(id)` 같은 함수 하나로 판정한 boolean을 원/라벨/연결선 JSX 세 곳에 각각 직접 적용하면 DOM 구조에 무관하게 항상 정확함.
- **미확정 미래 항목을 리프로 채우는 것도 사용자가 명시적으로 요청하면 가능**: 기존 원칙(가짜 리프를 지어내지 않음)은 "아직 확정 안 된 걸 확정된 것처럼 보이면 안 된다"는 뜻이지, "미래 항목을 아예 안 보여줘야 한다"는 뜻은 아님. 사용자가 "다양해 보이게 유명 과목 채워달라"고 명시적으로 요청하면, 실제로 존재하는 과목명을 점선+흐림+비활성(클릭 불가) 톤으로 채워도 됨 — 밝기/점선으로 "구현 여부"를, 색으로 "소속 학과"를 구분하는 원칙만 지키면 됨.
- **좁은 화면 대응은 리사이즈 리스너 없이 CSS만으로**: 그래프 컨테이너에 `hidden lg:block`, 대체 카드 리스트에 `lg:hidden`을 동시에 걸어두면 JS 없이 뷰포트에 따라 자동 전환됨.

## 참고 이미지로 톤 재추출하기

1. 이미지에서 배경/카드/글자/강조색/모서리 반경/여백/글로우 느낌을 읽어낸다.
2. 위에 정리된 시맨틱 색 역할은 유지하고 값(명도·채도·그림자 강도)만 조정하는 걸 기본으로 한다.
3. 카드-페이지 명도 대비, glow 강도를 특히 신경 써서 확인한다(위 "확정된 디자인 규칙" 참고 — 과거에 둘 다 약해서 피드백 받음).
4. 업데이트된 값을 실제 `src/index.css`에 반영하기 전에 먼저 Artifact 목업으로 보여주고 승인받는다.

## 적용 범위 제한

- 아직 스타일링 안 된 페이지(정렬/화학/스택-큐-덱/HomePage/Sidebar 등 실제 소스)에 이 규칙을 일괄 적용하는 건 사용자가 명시적으로 요청할 때만 — 임의로 확장하지 않는다.
- 지금까지 실제로 적용 완료된 화면: 트리 페이지(`src/pages/cs/TreePage.tsx` 및 `src/features/tree/components/*`), 홈페이지(`src/pages/HomePage.tsx`, `src/components/DepartmentGraph.tsx`), 사이드바(`src/components/Sidebar.tsx`, 데이터만 `src/data/navigation.ts`로 분리 — 시각 디자인 자체는 이전과 동일). 나머지(정렬/화학/스택-큐-덱)는 전부 Artifact 목업 단계이거나 미착수.
