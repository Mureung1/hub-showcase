# 보안 컨벤션 스킬

`docs/security.md`를 **단일 진실 소스**로 삼아 예외 처리·입력 검증·배포 보안 설정 규칙을 적용하는 스킬.

## 실행 순서

1. **`docs/security.md`를 먼저 읽는다.** 규칙이 갱신됐을 수 있으므로 항상 최신 문서를 기준으로 한다. 이 스킬 요약과 문서가 다르면 `docs/security.md`가 우선.
2. 작업 대상이 새 라우트/컨트롤러 작성인지, 기존 코드 수정인지, 배포 설정 변경인지 판단한다.
3. 아래 체크리스트로 대상 코드를 검토·수정한다.
4. `code-convention` 스킬의 레이어 분리 규칙과 함께 적용한다 (검증=컨트롤러, throw=서비스, 응답 포맷=컨트롤러/전역 핸들러).

## 체크리스트

### 새 라우트/컨트롤러 작성 시
- [ ] 요청 경계(컨트롤러)에서 `body`/`params`/`query`를 **화이트리스트 정규식**으로 검증했는가 (금지 문자 나열 방식 지양)
- [ ] 배열·문자열 입력에 **길이 상한**을 뒀는가
- [ ] 검증 실패 시 openapi.yaml 명세대로 400 + `{ error: { code, message } }`를 반환하는가
- [ ] 서비스에서 실패는 `err.status`/`err.code`를 붙여 throw하고, 컨트롤러는 `next(error)`로 전역 핸들러에 위임하는가
- [ ] 사용자 입력이 외부 API 쿼리(GitHub 검색 qualifier 등)나 DB raw 쿼리에 들어간다면, 조립 직전에 위험 문자를 한 번 더 제거하는 **이중 방어**를 했는가

### 기존 코드 수정 시
- [ ] 500 에러 응답에 `err.message`/스택이 그대로 노출되지 않는가 (고정 문구만 노출, 상세는 로그로만)
- [ ] 로그에 토큰·DB 접속 문자열 등 비밀값이 그대로 찍히지 않는가

### 배포/환경변수 관련 작업 시
- [ ] 새 환경변수를 `.env`에만 추가하고 `backend/.env.example`에는 키만(값 없이) 추가했는가
- [ ] 프론트엔드 `VITE_*` 환경변수에 비밀값(API 키·토큰)을 넣지 않았는가 — 빌드물에 그대로 노출됨
- [ ] `helmet()`/`cors({ origin })` 설정을 건드렸다면 origin을 여전히 제한하고 있는가

## 하지 말 것
- 컨트롤러에서 500 에러 바디에 내부 예외 메시지·스택트레이스를 그대로 넣기.
- 배열/문자열 입력에 상한 없이 검증 통과시키기.
- `.env`·시크릿을 커밋하거나 `VITE_` 접두사에 비밀값 넣기.
- `$queryRaw`에 문자열을 직접 조합해 넣기 (파라미터화 없이).
