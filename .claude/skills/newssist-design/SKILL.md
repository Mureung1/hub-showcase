# Newssist 디자인 가이드

Newssist는 여러 매체의 뉴스를 키워드로 모아 AI가 해설하고, 읽은 기사를 클러스터링해 개인화된 "시사 흐름"을 설명해주는 서비스. 타겟은 취준생(면접 전 빠른 시사 파악)과 직장인(출퇴근길 업계 뉴스 확인) — 정보 밀도는 높지만 이해 부담은 낮아야 한다.

이 가이드는 세 소스를 종합한 것:
- **와이어프레임** (`prototype` 브랜치, `01_home.html`~`06_mypage.html`) — 실제 구현된 Tailwind 디자인 토큰과 레이아웃 구조. 데이터 대시보드에 가까운 "블루프린트" 톤.
- **기획서** (GitHub Wiki) — 기능 우선순위와 화면 구성(IA).
- **Pinterest 컨셉** (MAGZIN 매거진 템플릿) — 더 따뜻하고 편집숍(에디토리얼) 감성의 무드보드. 대시보드 톤을 그대로 구현하면 딱딱해 보일 수 있어, 이 컨셉으로 톤을 누그러뜨리는 참고용.

기본 방향: **와이어프레임의 구조·토큰을 그대로 따르되, MAGZIN의 편집숍 감성(둥근 알약형 배지, 여유로운 이미지, 임팩트 있는 헤드라인)을 카드·태그·히어로 영역에 섞어 넣는다.** 데이터가 조밀한 화면(트렌드 랭킹, 클러스터 맵, AI 사이드패널)은 와이어프레임의 정밀한 톤을 유지한다.

## 1. 디자인 토큰 (와이어프레임에서 그대로 가져올 것)

### 색상 (Material Design 3 스타일 팔레트)
```
primary            #004ac6   (핵심 CTA, 활성 상태, 링크, 트렌드 상승 아이콘)
primary-container  #2563eb
tertiary           #943700   (클러스터 보조색 — 오렌지 계열, 차트/분류 강조)
secondary          #505f76   (보조 텍스트, 중립 배지)
background/surface #faf8ff / #F8FAFC
on-surface         #131b2e   (본문 텍스트)
on-surface-variant #434655   (메타 텍스트, 캡션)
outline-variant    #c3c6d7   (카드/구분선 보더 — 거의 모든 카드가 이 얇은 보더를 씀)
surface-container-low #f2f3ff (배지·필 배경, 사이드패널 배경)
error              #ba1a1a
btn-gray           #E4E6EC   (버튼/네비/아바타 등 UI 크롬 전용 — 2026-07 결정, 아래 "버튼 색상 규칙" 참고)
```
- 브랜드 컬러는 **블루(#004ac6) 하나**로 절제. 클러스터/데이터 시각화에서만 tertiary(오렌지), secondary(블루그레이)를 추가로 써서 카테고리를 구분.
- 순수 블랙(#000) 배경은 쓰지 않음 — MAGZIN의 블랙 유틸리티 바 같은 요소를 넣더라도 `on-surface`(#131b2e) 톤으로.

### 버튼 색상 규칙 (2026-07 결정)
- 기본은 **연한 그레이(`btn-gray` #E4E6EC) + `text-on-surface`**: 사이드바 네비 활성 상태, 필터 pill 활성 상태, 아바타, 카드 내부의 보조 버튼 등 대부분의 UI 크롬이 여기 해당.
- **오직 화면의 핵심 CTA 1개만 진한 블루(`bg-primary` + `text-white`)** — 예: PRO 업그레이드 카드의 "업그레이드" 버튼. 그레이 버튼들 사이에서 시각적으로 튀어야 하는 단 하나의 액션에만 쓴다.
- 필터 pill(키워드 카테고리 등)은 그림자·hover 상승 같은 입체감을 주지 않는다 — 평평하게 유지.

### 그라데이션 (2026-07 결정)
- 브랜드 그라데이션은 **`primary → transparent`(또는 `primary → primary-container`) 리니어(linear), 위→아래(`to bottom`) 방향만** 쓴다. **원형(radial)이나 블러로 뭉갠 블롭 금지** — Pinterest/Gemini 랜딩 참고 결과, 이 프로젝트 톤엔 "조명이 위에서 곧게 내려쬐는" 느낌의 직선 그라데이션이 맞다고 결론남.
- 배경 전체를 덮지 않고, **로고 위·섹션 제목(H1) 위·섹션 구분선 아래**처럼 특정 지점에서만 은은하게 퍼지도록 국소적으로 사용 (`opacity`와 알파값으로만 페이드, `filter: blur()`는 쓰지 않거나 최소화 — 블러를 세게 걸면 좁은 박스가 원형 블롭처럼 뭉개져 버림).
- **풀 블리드 주의**: 그라데이션 요소를 `max-w-*`로 폭이 제한된 컨테이너(`<main>` 등) 안에 두면 양옆이 잘려 보인다. 사이드바 옆 전체 폭까지 이어지게 하려면, `max-w-*` 제약이 없는 상위 컨테이너(예: 사이드바와 형제인 `flex-1` 래퍼)의 직계 자식으로 두고 `inset-x-0`을 줄 것.
- 섹션 구분에는 `border-t border-outline-variant` 라인 + 그 바로 아래로 번지는 리니어 그라데이션 조합을 쓴다 (인사이트/홈 피드 사이 구분선이 이 패턴의 기준 예시).

### 타이포그래피
- 본문/UI(영문·숫자): **Inter** (400/500/600/700)
- 한글 포함 전체 UI: **Pretendard**를 Inter와 함께 폰트 스택에 넣을 것(`font-family: 'Pretendard', 'Inter', sans-serif`) — Inter/JetBrains Mono는 한글 글리프가 없어 그냥 두면 브라우저가 시스템 폰트(굴림 등)로 폴백해 톤이 깨진다. mono 라벨 안에 한글이 섞이는 경우(`PRO 업그레이드` 등)도 `font-family: 'JetBrains Mono', 'Pretendard', monospace`로 폴백을 지정해 통일할 것.
- 라벨·메타·데이터: **JetBrains Mono**, `uppercase`, `tracking-wide` (예: "테크크런치", "PRO 업그레이드", 사이드바 메뉴 라벨) — 이게 이 프로젝트 톤을 결정짓는 핵심 디테일. 숫자/랭킹/타임스탬프는 항상 mono체.
- 아이콘: **Material Symbols Outlined** (`FILL 0, wght 400`)
- 스케일: display-lg 36/44 (-0.02em, bold) · headline-md 24/32 (-0.01em, semibold) · headline-sm 18/24 semibold · body-lg 16/24 · body-md 14/20 · caption 12/16 · label-mono 12/16 (uppercase, 0.05em)

### 간격 & 형태
- spacing 단위: 4px 기본, `stack-sm 8 / stack-md 16 / gutter 16 / container-padding 24 / stack-lg 32`
- **border-radius는 의도적으로 작다**: default 2px, lg 4px, xl 8px, full 12px. 완전히 둥근 pill(9999px)은 프로필 사진, 알림 배지 등 소수 요소에만 — 카드·버튼은 거의 각지거나 살짝만 둥글다. MAGZIN 무드보드처럼 과하게 둥근 카드를 그대로 베끼지 말 것.
- 카드는 배경색 대신 **1px `outline-variant` 보더**로 구분하는 게 기본 패턴 (그림자는 최소한으로, 클러스터 맵 같은 플로팅 요소에만 `shadow-sm/lg` 사용).

## 2. 레이아웃 구조 (기획서 IA 그대로)

- **좌측 고정 사이드바** (280px, `bg-surface border-r`): 로고 "Newssist" + "AI INTELLIGENCE" 서브라벨(mono) → 홈/트렌드/인사이트/마이페이지/설정 네비 → 하단 PRO 업그레이드 카드 + 도움말/로그아웃
- **상단 헤더** (80px, sticky): 검색창(왼쪽) + 알림/설정 아이콘 + 사용자 프로필(오른쪽)
- **홈 (피드)**: 상단 헤더 아래 전체 폭 그라데이션 밴드 → 키워드 필터 pill(평평하게, 입체감 없음) → **기사 그리드 4열×2행**(맨 앞 7개 기사만, 좌측 1열은 두 행을 병합해 "톱 이슈" 카드로, 나머지 6칸은 자동 배치), 그리드 컨테이너 전체 높이는 **60vh를 넘지 않음** (2026-07 결정, 아래 컴포넌트 레시피 "홈 피드 그리드 카드" 참고) → 그 아래로 넘치는 나머지 기사는 "뉴스 카드(리스트형)"로 이어서 나열. 우측엔 **`w-[360px]` sticky 패널**(그리드/리스트와 같은 `flex` 행의 형제 요소, 기획서 5절의 "우측 1/3 AI 위젯"을 구현한 것)이 나란히 붙는다 — 연관 기사 AI 인사이트 카드 + 트렌드 랭킹 위젯 (2026-07 배치 확정, `components/InsightSidebar.js`). ⚠️ 두 위젯 다 아직 데이터가 없는 스트레치 기능(`/api/articles/:id/related`, `/api/trend`)이라 레이아웃/빈 상태만 구현된 상태 — 실제 데이터 연동 시 내용만 채우면 됨.
- **기사 상세**: 본문 + 용어 하이라이트(클릭 시 툴팁) + "요약/쉽게 설명" 버튼 → 우측에 AI 사이드패널이 **본문을 가리지 않고 나란히** 열림 (Gemini 스타일 — 모달 아님)
- **트렌드**: 랭킹 리스트(차트 아님, 네이버 실검 방식 — 순위 + 전 순위 대비 등락 화살표) → 키워드 클릭 시 관련 기사 그리드
- **인사이트**: 클러스터 카드 리스트(기사 수 많은 순 정렬, 카드당 클러스터 이름/키워드/기사수/흐름 설명/대표 기사) + 클러스터별 최근 4주 활동 미니 스파크라인 + 주간 리포트 (2026-07 변경: 기존 UMAP 산점도는 타겟 유저에게 안 읽혀 폐기, `기획서.md` 8절 참고)
- **마이페이지**: 읽은 기사(날짜순) + 북마크 목록, 인사이트/주간리포트 진입점

## 3. 컴포넌트 레시피

**뉴스 카드(리스트형)** (`article`): 이미지 없이 텍스트 위주로 나열하는 곳(마이페이지 읽은 기사 목록, 관련 기사 리스트 등)에서 사용. 흰 배경, `border border-outline-variant`, hover 시 `border-primary`. 상단에 출처 배지(mono, `bg-surface-container-low` 필박스) + 시간(캡션), 헤드라인(headline-md, hover 시 primary), 본문 3줄 요약(`line-clamp-3`), 하단 "상세 리포트 읽기" 링크(mono, 화살표 아이콘). 각진 배지 유지.

**홈 피드 그리드 카드** (2026-07 결정, MAGZIN 감성이 실제로 적용되는 지점): 사진 배경 + 하단 오버레이 텍스트 패널로 구성. ⚠️ 네이버 뉴스 검색 API가 썸네일을 안 줘서, 실제 이미지 소스가 붙기 전까지는 `utils/placeholderImage.js`(picsum.photos, article id 시드)로 대체 중 — 실제 기사 사진이 아니라 그냥 랜덤 사진이니 디자인 검수 시 "사진과 기사 내용이 안 맞는 것"은 이 임시 처리 때문이지 버그가 아님.
- 배지(카테고리): 사진 좌상단, `bg-white/40 backdrop-blur-md border border-white/50 text-on-surface` 둥근 필 — 사진 위에서만 이 정도로 투명한 글래스 처리를 쓴다.
- 하단 텍스트 패널: **흰색 불투명 그라데이션**(`bg-gradient-to-t from-white/55 via-white/25 to-transparent` + `backdrop-blur-sm`)만 쓴다. 블루/그레이 톤으로 물들이지 않음(사진 원본 색感 유지가 목적). 패널은 **카드 높이의 40%를 넘지 않도록** `h-[40%]` + `flex flex-col justify-end` + `overflow-hidden`으로 캡을 건다. 헤드라인은 2줄 캡(`line-clamp-2`)의 작은 폰트, 톱 이슈 칸만 살짝 크게 — 긴 요약 문단은 넣지 않는다.
- 톱 이슈(그리드 좌측 1열, 2행 병합) 칸은 같은 레시피를 크기만 키워서 쓴다.
- 사진 자체에 색 오버레이(듀오톤 등)를 씌우지 않는다 — 사진은 원본 그대로, 톤은 배지·패널의 투명도로만 조절.

**AI 인사이트 카드** (사이드패널): `bg-surface-container-low`, 우상단에 큰 아이콘을 10% 투명도로 배치(워터마크), 상단 mono 라벨("AI 인사이트"/"구조적 연결", primary색), 이탤릭 본문(**핵심어는 bold**), 하단 보더 구분 후 관련 기사 제목 + 메타.

**트렌드 랭킹 아이템**: mono 순위 숫자 + 등락 아이콘(`expand_less`=상승/primary, `expand_more`=하락, `remove`=유지), 키워드(semibold), hover 시 좌측에 4px primary 보더.

**클러스터 카드** (인사이트 페이지): `bg-surface-container-low`, 상단 mono 라벨(클러스터 이름) + 우측 기사 수 배지, 흐름 설명 문단(이탤릭, 핵심어 bold), 하단 보더 구분 후 대표 기사 2~3개, 우하단에 최근 4주 활동 미니 스파크라인(SVG, 색상은 클러스터마다 primary/tertiary/secondary 순환 — 별도 차트 라이브러리 없이 구현). 상세는 dataviz 스킬과 함께 참고.

**배지/태그**: 기본은 mono uppercase 각진 필박스. 카테고리 필터(전체/테크/개발 등)는 `border-2` 강조(선택 시 `bg-btn-gray text-on-surface` — 위 "버튼 색상 규칙" 참고, primary 블루 아님).

**버튼**: 위 "버튼 색상 규칙" 참고 — 기본은 `bg-btn-gray text-on-surface`, 화면당 핵심 CTA 1개만 `bg-primary text-white`. 필터 pill류는 그림자·hover 이동 없이 평평하게.

**카드 호버 인터랙션** (2026-07 결정): 사진이 있는 카드(홈 피드 그리드 등)는 hover 시 **사진이 확대되는 게 아니라 카드 자체가 살짝 커지며(`scale-[1.03~1.04]`) 앞으로 떠오르는 느낌**을 준다. 그림자는 방향성 있는 `shadow-2xl`(아래로만 깔리는 그림자, "위로 들리는" 느낌)이 아니라 **오프셋 없는 블러 그림자**(예: `shadow-[0_0_24px_rgba(15,23,42,0.2)]`, 사방에 고르게)를 쓴다. 그리드처럼 이웃 카드와 붙어 있으면 `hover:z-10`을 같이 줘서 확대된 카드가 옆 카드에 가리지 않게 한다.

## 4. 톤 체크리스트

- [ ] 색은 primary 블루 하나가 지배적이고, 나머지는 중립 그레이 톤인가 (컬러 남발 금지)
- [ ] 메타/라벨/숫자는 JetBrains Mono + uppercase로 처리했는가
- [ ] radius를 과하게 키우지 않았는가 (카드=거의 각짐, 버튼=최대 8px, pill은 배지/아바타 한정)
- [ ] 데이터 밀도 높은 화면(트렌드/인사이트)은 장식보다 가독성을 우선했는가
- [ ] 히어로/카드 이미지가 들어가는 곳은 MAGZIN처럼 사진에 여백을 주고 임팩트 있는 헤드라인을 배치했는가
- [ ] 모든 UI 텍스트는 한국어, 톤은 신뢰감 있고 전문적이되 어렵지 않게
- [ ] 버튼 중 진한 블루(`bg-primary`)는 화면당 핵심 CTA 하나뿐이고, 나머지는 `btn-gray`인가
- [ ] 그라데이션을 썼다면 원형(radial)이 아니라 리니어(위→아래)이고, 폭 제한 컨테이너에 갇혀 양옆이 잘리지 않는가
- [ ] 한글이 들어간 요소(mono 라벨 포함)에 Pretendard 폴백이 적용돼 시스템 폰트로 깨지지 않는가

## 6. 유지보수
이 문서는 프로젝트가 진행되며 계속 고쳐 쓰는 살아있는 가이드다. 실제 컴포넌트 구현이 여기 적힌 값과 달라지면, 구현 코드를 기준으로 이 문서를 업데이트할 것 (문서가 아니라 코드가 항상 우선).

이 문서를 수정할 땐 **바뀐 이유(reason) 단위로 커밋을 쪼갤 것.** 같은 결정에서 나온 수정이면 여러 섹션을 고쳐도 커밋 1개로 묶고, 이유가 다른 수정(오타 정정, 새 디자인 결정, 다른 결정의 후속 반영 등)은 시점이 붙어 있어도 별도 커밋으로 남긴다. 다른 작업 커밋에 묻지 않아야 나중에 특정 디자인 결정이 언제·왜 바뀌었는지 추적하고 필요하면 그 결정만 되돌리기 쉽다.
