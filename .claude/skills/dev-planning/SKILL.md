# 개발 및 기획 유의사항

## 먼저 확인
- 기획서: @서비스 기획서.md
- 실행 방법: @README.md
- 디자인 시스템/코드 위치: `.claude/skills/design/SKILL.md`

## 기획 원칙
- 서비스명 `We should do..` 고정. 이름 새로 짓지 않기.
- 생산성:게임 = 7:3. 게임 요소가 일정관리를 가리면 안 됨.
- 핵심 루프: 일정 등록 → 수행 → 영상 인증 → 친구 반응 → 포인트 → 두두/마이홈 꾸미기.
- 모든 일정은 개인 소유. 그룹 소유 일정 만들지 않기.
- 공개 범위는 카테고리 단위 상속 + 일정별 예외. 새 카테고리 기본값 `나만 보기`.
- 캘린더 아젠다는 통합 표시. 요청 없이 카테고리별로 묶지 않기.
- 탭: 홈 · 두두 · 친구 · 마이페이지. `두두` ≠ `할 일` 탭.

## 두두(DODO)
- 이름/설정 변경 금지. 미루는 마음에서 태어난 유일한 마스코트종.
- 사용자를 혼내거나 죄책감 주는 반응 금지.
- 실존 브랜드 캐릭터 모작 금지.
- 도트/외형 규칙은 design skill 참조.

## 두두 일기
- 영상 인증 완료 후에만 생성.
- 말투: 귀엽고 장난스럽게. 비난·죄책감 문구 금지.
- 예시: "오늘 주인은 40분 동안 운동했다. 나는 소파에서 응원했다."

## 개인정보 · 알림
- 기본값은 항상 비공개.
- 영상 인증 공개 전 공개 대상 확인 단계 필수.
- 영상/일기는 사용자가 언제든 삭제 가능해야 함.
- 재촉·불안·죄책감 유발 알림 문구 금지.
- 정확한 위치정보 기본 노출 금지.

## 코드 규칙
- 기본 개발 스택: 프론트엔드 React, 백엔드 Express. 다른 프레임워크로 임의 변경하지 않기.
- TS strict 유지. `any` 금지 — 모르는 타입은 `unknown` + 타입가드.
- 상태(`useScheduleManager.ts`) / 타입(`types.ts`) / 목데이터(`data.ts`) / UI를 한 파일에 몰아넣지 않기.
- 일정 아이템은 제목수정 · 시간수정 · 삭제 · 완료체크박스 4가지 항상 지원.
- 일정 시간이 없으면 빈 값. `시간 미정` 같은 대체 문구 쓰지 않기.
- 새 화면/컴포넌트는 `src/components/scheduler/` 아래에 추가.

## 인프라 · 배포
- 로컬호스트 전용으로 개발하지 않기. 항상 외부 서버(PaaS)에 배포하는 것을 전제로 설계·구현.
- 프론트엔드: Vercel 배포. 백엔드(Express): Render/Railway 같은 PaaS 배포.
- DB: Postgres (Neon/Supabase 무료 티어). ORM은 Prisma.
- 영상 파일: Cloudflare R2에 저장. 클라이언트가 presigned URL로 R2에 직접 업로드하고, Express 서버는 파일 바이너리를 중계하지 않음. DB에는 storage key/URL만 저장.
- 인증: 커스텀 JWT (access 15분 + refresh 30일). refresh token은 해시로 DB에 저장해 즉시 무효화 가능하게 하고, 클라이언트에는 httpOnly 쿠키로 전달. Supabase Auth 등 외부 인증 서비스로 대체하지 않기.

## PR 작성
- 기능 하나당 개별 브랜치를 만들어 작업한다 — 여러 기능을 한 브랜치에 몰아넣지 않기.
- 작업 시작 전 GitHub Issue를 먼저 등록하고, PR에서 그 이슈를 참조(closes #N)한다.
- **본레포(`connect-AIAgentChallenge-26-1/hub`, base `N012_금소현`)에는 세션/작업 묶음당 PR을 1개만 올린다.** 로컬 브랜치는 기능별로 나눠도 되지만(위 항목), 그 브랜치들을 각각 본레포에 개별 PR로 올리지 않는다 — 한 세션에서 나온 브랜치들을 하나로 합쳐서(머지) 통합본 PR 1개로 제출한다. `fork`(`95x8x9/hub`) 쪽에 브랜치별로 개인 PR을 올리는 것은 이 규칙과 무관하게 자유롭게 해도 된다.
- 필수 양식: @.github/pull_request_template.md — `주요 작업 리스트` / `내가 설명할 수 있는 부분` / `아직 이해 못 한 부분` / `새로 알게 된 것` 4개 섹션을 채운다.
- 타이틀: `[루카스아이디_실명] - 이번 작업 한 문장 요약` (예: `[N100_윤솔빈] 주문정보 페이지 개발`).
- `## 요약`/`## 테스트 계획` 같은 임의 형식으로 대체하지 않기 — 항상 이 템플릿을 채운다.
- 작업이 끝나면 `docs/개발백로그.md`의 해당 Task 상태를 갱신한다 — 완료 여부, 새로 발견한 제약, 관련 이슈 번호까지 반영.

## 하지 말 것
- 앱 이름 · 두두 이름 변경.
- 랭킹 · 순위 중심 경쟁 설계 (응원 · 성장 비교로 대체).
- 유료 아이템이 일정관리 · 포인트 보상에 직접 우위를 주는 설계.
- 일정 기본 공개 또는 그룹 소유화.
- 두두 외 마스코트 추가.
- 고해상도 사실적 캐릭터 아트.
- `any` 사용, God 컴포넌트, 인라인 목데이터.
- PR 본문을 템플릿(`.github/pull_request_template.md`) 대신 임의 형식으로 쓰기.
