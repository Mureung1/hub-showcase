# TDD 기능 루프

작은 기능 하나를 테스트 가능한 행동으로 좁히고, 최소 변경으로 완료한다.

## 절차

1. 기능을 하나의 Given/When/Then 수용 기준으로 적는다. 범위 밖 변경과 외부 의존성을 함께 명시한다.
2. 기존 테스트 명령과 가까운 테스트 위치를 확인한다. 테스트 도구가 없으면 런타임 기본 도구를 우선 사용한다.
3. 수용 기준을 실패하는 테스트로 작성하고 실행한다. 실패 원인이 구현 부재인지 확인한다.
4. 테스트를 통과시키는 최소 구현만 추가한다. 필요하면 순수 함수로 경계를 분리한다.
5. 새 테스트와 전체 테스트를 실행한다. 이어서 lint와 production build를 실행한다.
6. 테스트 이름, 수용 기준, 구현이 같은 행동을 설명하는지 확인한다. 통과 후에만 작은 리팩터를 한다.

## 완료 기준

- 테스트는 실패(Red) 후 통과(Green)한 기록이 있다.
- 정상·거부·경계 사례가 각각 하나 이상 있다.
- 테스트, lint, build 결과를 함께 보고한다.
- 테스트를 통과시키기 위한 범위 밖 모킹·예외 처리·스키마 변경을 추가하지 않는다.
