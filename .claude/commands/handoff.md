당신은 지금 Briefy 세션을 마무리하고 다음 세션(다른 CLI 툴일 수도 있음)에게 인수인계하는 중이다. 목적은 **다음 세션이 `checklist.md`와 `HANDOFF.md` 두 파일만 읽으면 바로 이어서 작업할 수 있게 만드는 것**이다. 아래 3단계를 순서대로 수행한다.

## 1단계 — `HANDOFF.md` 작성 (저장소 루트, 덮어쓰기)

이번 대화 세션에서 실제로 한 작업을 근거로 작성한다. 기억이 불확실하면 추측하지 말고 `git status`, `git diff`, `git log -5` 로 실제 변경 내역을 확인한 뒤 작성한다.

최상단에 작성 시각을 Asia/Seoul 기준으로 기록한다 (`TZ='Asia/Seoul' date '+%Y-%m-%d %H:%M (%a)'` 실행해서 얻은 값 사용, 임의로 지어내지 않는다).

다음 6개 섹션을 이 순서로 포함한다:

```markdown
# HANDOFF

> 작성 시각: {TZ=Asia/Seoul 로 확인한 실제 시각}

## 마지막 작업 요약
이번 세션에서 수정/생성한 파일과 변경 내용을 파일 단위로 나열. 각 항목은
`- \`path/to/file\` — 무엇을 왜 바꿨는지 한 줄` 형식.

## 현재 상태
- 동작하는 것: 실제로 실행/검증까지 한 기능만 적는다 (코드만 쓰고 실행 안 해본 것은 여기 넣지 않는다).
- 미완성인 것: 절반만 구현됐거나 목데이터에 의존 중인 부분.
- 알려진 이슈: 발견했지만 이번 세션에 고치지 않은 버그·불일치.

## 다음 할 일
`checklist.md`를 열어, 아직 `[ ]`인 항목 중 우선순위(P0 → P1 → Phase 2 → Phase 3) 순서로
다음에 이어서 할 항목을 뽑아 나열한다. checklist.md에 없는 임시 작업이면 그 사실을 명시한다.

## 주의사항
다음 세션(특히 이 프로젝트를 처음 보는 다른 CLI 툴)이 알아야 할 것:
- 이번 세션에서 내린 결정과 그 이유 (예: 왜 이 방식을 선택했는지, 왜 다른 대안을 버렸는지)
- 빠지기 쉬운 함정 (예: 아직 안 만들어진 테이블, 목업과 실제 API가 섞여 있는 지점)
- CLAUDE.md/docs/plan.md에 없는, 이번 세션에서만 합의된 임시 규칙이 있다면 명시

## 검증 방법
이어받는 쪽이 현재 상태를 그대로 재현/확인할 수 있는 실행 가능한 명령어 목록.
최소한 다음을 포함하고, 이번 세션에서 실제로 건드린 영역에 맞게 추가한다:
- `npm run typecheck`
- `npm run lint`
- `npm run dev` (그리고 확인해야 할 URL/화면)
```

## 2단계 — `checklist.md` 동기화

1. `checklist.md`를 읽는다.
2. 이번 세션에서 실제로 완료한 작업(1단계에서 정리한 "마지막 작업 요약" 기준)이 `[x]`로 반영돼 있는지 확인한다.
3. 완료했는데 아직 `[ ]`로 남아있는 항목이 있으면:
   - `[x]`로 바꾸고, 완료일(Asia/Seoul 기준 오늘 날짜)과 한 줄 비고를 덧붙인다. 기존 checklist.md에 쓰인 형식(`- [x] 항목 — 완료일 / 비고`)을 그대로 따른다.
4. 반대로 `checklist.md`에 없는 새 작업 단위를 이번 세션에서 만들었다면, 적절한 우선순위 섹션(P0/P1/Phase2/Phase3)에 새 항목으로 추가한다. 임의로 섹션 구조를 바꾸지 않는다.

## 3단계 — 커밋 여부 확인

1. `git status`를 실행해 커밋되지 않은 변경사항(수정/추가/삭제, untracked 포함)을 확인한다.
2. 변경사항이 있으면 목록을 사용자에게 보여준다 (파일별로 상태 표시).
3. **절대 먼저 커밋하지 않는다.** 커밋할지 사용자에게 명시적으로 물어본다. 사용자가 승인하면 그때 CLAUDE.md의 커밋 컨벤션(Conventional Commits, 예: `chore: 세션 인수인계 문서 정리`)을 따라 커밋한다.
4. 변경사항이 없으면 "커밋할 변경사항 없음"이라고만 보고하고 넘어간다.

## 완료 후 보고

작업이 끝나면 사용자에게 다음을 간단히 요약해서 보여준다:
- `HANDOFF.md`가 새로 작성됐다는 것과 핵심 요약 2~3줄
- `checklist.md`에서 몇 개 항목을 체크했는지
- 커밋 대기 중인 변경사항이 있는지, 있다면 커밋 여부를 물었는지
