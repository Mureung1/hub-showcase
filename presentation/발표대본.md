안녕하세요. 오늘 소개해드릴 프로젝트는 **GameForge Agent**입니다.

한 줄로 말씀드리면, Unity 게임을 만드는 과정을 여러 AI 에이전트가 단계별로 도와주는 개발 지원 도구예요. 요구사항 분석부터 최종 문서화까지, **9단계 워크플로우**로 프로젝트 컨텍스트를 계속 유지하면서 진행하는 게 핵심입니다.

지금부터 왜 이 도구가 필요한지, 어떻게 만들고 있는지, 그리고 지금까지 뭐가 실제로 동작하는지 순서대로 보여드리겠습니다.

## 2. 왜 GameForge Agent인가 (약 45초)

Unity 게임 하나를 만드는 과정은 기획, 설계, 코드 생성, 리뷰까지 여러 단계로 쪼개져 있습니다. 그런데 그 사이를 이어주는 맥락, 컨텍스트는 문서와 대화 속에 흩어진 채로 쉽게 사라지고, 매번 처음부터 다시 설명해야 하는 경우가 많습니다.

정리하면 세 가지 문제가 있습니다.

- 기획, 설계, 코드가 서로 다른 문서와 대화에 흩어지는 **파편화된 워크플로우**
- 매번 처음부터 다시 설명해야 하는 **휘발되는 프로젝트 컨텍스트**
- 코드 품질과 중복을 사람이 매번 수작업으로 체크해야 하는 **반복되는 리뷰 부담**

GameForge Agent는 이 전체 흐름을 하나의 프로젝트 Context, 즉 Markdown 문서로 묶어서, Multi-Agent가 단계마다 이어받아 작업하도록 설계했습니다.

## 3. 9단계 워터폴 워크플로우 (약 45초)

핵심 컨셉은 **9단계 워터폴 워크플로우**입니다.

요구사항 분석, 게임 기획, 게임 시스템 설계, 클래스 설계, 프로젝트 구조 설계, ScriptableObject 설계, 코드 생성, 리팩토링과 코드 리뷰, 마지막으로 문서화까지 — 이렇게 아홉 단계가 순서대로 진행됩니다.

여기서 중요한 설계 원칙이 하나 있는데요, **완료되거나 진행 중인 단계만 열람할 수 있고, 아직 오지 않은 단계는 잠겨 있습니다.** 즉 순서를 건너뛸 수 없습니다. 이렇게 해야 각 단계의 결과물이 다음 단계의 정확한 입력이 되고, 프로젝트 컨텍스트가 흔들리지 않습니다.

## 4. 기술 아키텍처 (약 45초)

구조를 간단히 보여드리면 이렇습니다.

React와 Vite, TypeScript로 만든 **클라이언트**가 REST API로 Node Express **서버**와 통신합니다. 서버는 다시 세 곳과 연동되는데요,

- **GitHub API**로 OAuth 로그인과 저장소·브랜치 정보를 가져오고
- **.NET 기반 Roslyn 분석기**를 child_process로 실행해서 코드를 분석하고
- **Anthropic Claude API**로 단계별 코드와 문서를 생성합니다

별도 데이터베이스 없이 서버의 JSON 파일로 데이터를 관리하는, 가볍고 빠르게 검증할 수 있는 구조로 시작했습니다.

## 5. 지금 바로 볼 수 있는 것 (약 45초)

말로만 설명드리면 감이 잘 안 오실 텐데, 지금 실제로 동작하는 부분을 보여드릴게요.

GitHub 계정으로 로그인하고, 내 저장소 목록에서 하나를 고르고, 그 저장소의 브랜치까지 선택할 수 있습니다.

로그인은 **Authorization Code Flow**로 구현했고, 액세스 토큰은 서버에만 저장돼서 브라우저에는 절대 노출되지 않습니다. 오른쪽 화면이 실제 앱 화면 구조를 그대로 재현한 목업이에요. 이 부분은 이번 스프린트에서 완성한 첫 번째 실제 동작 단위입니다.

현재 진행 상황을 정리하면 이렇습니다.
