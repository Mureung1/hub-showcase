# 소상공인 SNS 마케팅 에이전트 — 4주 MVP 기획안

## Context

소상공인(특히 음식점·카페)은 SNS 마케팅의 필요성을 알면서도, 콘텐츠 제작에 필요한 시간과 글쓰기 역량이 없어 홍보를 포기하는 경우가 많다. 이 프로젝트는 메뉴 사진 몇 장과 한 줄 설명만으로 인스타그램 게시물, 블로그 글, 이벤트 문구를 채널별 톤에 맞게 자동 생성해주는 웹 서비스를 4주 안에 MVP로 만드는 것을 목표로 한다. 개발은 1인(본인)이 새 프로젝트로 진행하며, 4주차 종료 시점에는 배포된 데모를 소수의 실제 사장님에게 베타 테스트하는 것을 "완료"의 기준으로 삼는다.

---

## 1. 문제 정의와 타깃 페르소나

**타깃 업종**: 음식점·카페 전용 (범용 업종 대응은 제외)
- 이유: 메뉴 사진이라는 입력 소재가 균일하고, "맛있다/신선하다" 등 톤 예측이 쉬워 4주 안에 프롬프트 품질을 안정화하기 유리함. 소매점·뷰티샵 등은 추후 확장 대상으로 남겨둠.

**페르소나**: 정미경 사장님(가명), 40~50대, 동네 백반집/카페 운영
- SNS 계정은 있으나 게시물 업로드가 뜸하거나 방치됨. "뭘 써야 할지 모르겠고, 매번 사진 고르고 글 쓰는 게 번거롭다"가 핵심 페인포인트.
- 디지털 친숙도: **중간 수준** — 카카오톡 등은 능숙하지만 앱 설치보다는 **웹 포털**(브라우저 접속) 방식이 진입장벽이 낮다고 판단. 별도 앱 설치·심사 부담 없이 4주 내 배포 가능.

## 2. 핵심 기능 (4주 MVP 범위)

- **출력 포맷 3종 동시 지원**: 인스타 게시물 / 블로그 글 / 이벤트 문구
  - 한 입력(사진+설명)으로 3개 프롬프트 템플릿을 동시 실행하는 구조라 구현 복잡도가 크게 늘지 않음. 대신 3개 톤 모두 품질 검증에 시간이 필요.
- **사진 Vision 분석**: 사용자가 올린 메뉴 사진을 Claude Vision으로 실제 분석해 "먹음직스러운 비주얼, 플레이팅" 등 시각적 디테일을 문구에 반영. 텍스트 설명만 쓰는 방식보다 차별화된 결과물 품질 확보.
- **채널별 고정 톤**: 인스타=캐주얼·이모지, 블로그=정보성 중심, 이벤트=짧고 자극적. 사장님이 브랜드 보이스를 직접 고르게 하는 대신 톤을 고정해 품질 예측 가능성을 높임(브랜드 개성은 약해지지만 4주 튜닝 범위 안에 들어옴).
- **포맷당 결과 1개만 생성**: 여러 안을 비교하는 UX 대신 바로 결과를 받고, 마음에 안 들면 "재생성" 버튼으로 재요청. API 비용과 UI 복잡도를 최소화.
- **간단 계정 + 생성 이력 저장**: 가게 프로필(상호, 업종, 톤 설정)과 과거 생성 결과를 저장해 매번 새로 입력하지 않도록 함.

## 3. 사용자 시나리오 (입력 → 출력 흐름)

1. 사장님이 웹 포털에 로그인(간단 계정) → 가게 프로필이 없으면 최초 1회 등록(상호/업종)
2. 메뉴 사진 1~3장 업로드 + 한 줄 설명 입력 (예: "matjip 제육볶음, 점심 특가")
3. 백엔드가 사진을 Claude Vision에 전달해 시각적 특징 추출 → 추출 결과 + 사용자 설명을 조합해 3개 채널별 프롬프트 템플릿에 주입
4. 인스타 게시물 / 블로그 글 / 이벤트 문구가 동시 생성되어 화면에 표시
5. 사장님은 결과를 복사하거나 다운로드해서 본인이 직접 인스타그램 등에 게시 (SNS 직접 게시 연동은 MVP 범위 밖 — Meta Graph API 심사·토큰 관리 등 외부 종속 리스크를 4주 내에 감당하지 않기 위함)
6. 생성 결과는 이력에 자동 저장되어 마이페이지에서 다시 확인 가능

## 4. 기술 스택과 아키텍처

- **프론트엔드/백엔드**: Next.js (TypeScript), API Routes/Server Actions로 백엔드 로직 처리, Vercel 배포
  - 1인 개발 기준 하나의 레포에서 풀스택을 처리할 수 있어 개발 속도가 빠르고 인프라 관리 부담이 거의 없음.
- **DB/인증/스토리지**: Supabase (Postgres + Auth + Storage 통합)
  - 인증, 가게 프로필/생성 이력 테이블, 사진 저장소를 하나의 관리형 서비스로 해결. 직접 구축(NextAuth+Prisma 등) 대비 셋업 시간을 크게 절약.
- **AI**: Anthropic Claude API (Vision + 텍스트 생성)
  - 사진 분석과 텍스트 생성을 하나의 벤더로 처리해 통합 복잡도를 낮춤 (대안: GPT-4o Vision — 품질 차이는 크지 않으나 벤더를 이원화할 이유가 없어 채택하지 않음).
  - 파이프라인: (1) 사진 → Vision 분석으로 시각적 특징 텍스트 추출 → (2) 특징+사용자 설명 → 채널별 프롬프트 3종 → 병렬 생성.
- **핵심 데이터 모델**: `stores`(상호/업종/톤 설정), `generations`(입력 사진 URL, 추출 특징, 생성 결과 3종, 생성 시각)

## 5. 4주 마일스톤

- **1주차 — 기반 구축**: Next.js 프로젝트 셋업, Supabase 연동(Auth/DB 스키마/Storage), 사진 업로드 UI, 가게 프로필 등록 화면
- **2주차 — AI 파이프라인 코어**: Claude Vision 연동(사진 분석), 채널별 프롬프트 템플릿 설계·튜닝, 텍스트 생성 파이프라인, 결과 화면 뼈대
- **3주차 — 기능 통합**: 3포맷 동시 생성 플로우 완성, 생성 이력 저장/조회(마이페이지), 복사·다운로드 기능, 재생성 버튼, UI 다듬기
- **4주차 — 베타 & 배포**: 프로덕션 배포(Vercel), 실제 사장님 3~5명 베타 테스트 진행, 피드백 기반 프롬프트 튜닝 및 긴급 버그 수정

## 검증 방법
- 로컬/배포 환경에서 실제 메뉴 사진으로 3개 포맷 생성 결과를 직접 확인 (사진 다양성: 한식/카페 음료 등 최소 5종 테스트)
- Supabase 대시보드에서 가게 프로필/생성 이력 테이블에 데이터가 정상 적재되는지 확인
- 4주차에는 실제 베타 사용자에게 URL을 전달해 처음 접속부터 결과 복사까지 온보딩 마찰이 없는지 관찰
