## 0. 배경 및 목표

FR-1~13 위에 게임성·경쟁·개인화를 더해 매일 앱을 열 이유를 늘린다. 서버(`server/proxy.js`)가 이번에
처음으로 Supabase를 직접 호출한다(`server/supabaseAdmin.js`, FR-21/FR-15) — 그 외 모든 기존 라우트는
여전히 클라이언트가 anon key + RLS로 직접 접근한다.

**조사 결과 원래 전제와 달랐거나, 구현 중 해석·조정한 지점**

| 항목 | 원래 전제 | 실제 구현 |
|---|---|---|
| 비밀번호 찾기 | "이메일로 비밀번호 찾기" 가능할 것으로 생각했을 수 있음 | 로그인 ID가 실제 메일을 주고받지 않는 합성 이메일(`<id>@mealyze.app`)로 등록되어 이메일 인증이 원천적으로 불가능 — **보안 질문 방식**으로 대체 |
| 리더보드 가상 유저 | 단순 목업 데이터로 가능할 것으로 생각했을 수 있음 | `profiles.id`가 `auth.users(id)` FK라 프로필만 가짜로 만들 수 없음 — **Admin API로 실제 auth 계정 30개 시딩** |
| 퀘스트 kind(auto/manual) | 기존 FR-11의 수동 클레임 버튼 유지 예상 | 로테이션 개편과 함께 **전부 자동 판정+자동 수령**으로 단순화(수동 "수령하기" 버튼 제거) — MY 탭 방문 시 자동으로 조용히 지급되어 사용자가 챙길 것이 줄어듦 |
| XP 리더보드 신원 노출 | 기존 "다른 사용자 신원 절대 비노출" 원칙 유지 예상 | `get_xp_leaderboard()`에 한해 **닉네임을 의도적으로 노출**(듀오링고식 UI 성립 조건) — `get_daily_leaderboard()`는 원칙 그대로 유지 |

| 커스텀 조합 재료 그룹 | "베이스/토핑/소스" 3그룹 | DB `category`에 "소스" 자체가 없어 **베이스(rice·noodle)/토핑(main·side·kimchi·dessert)/국물·음료(soup·drink)** 3그룹으로 재구성 |

## 1. FR-14 — 레벨업 팝업 시각 강화

기존 `LevelUpPopup.jsx`(FR-12)를 원형 배지(`AchievementRing`, `Result.jsx`에서 추출해 공용화) +
신규 keyframe(`tds-levelup-badge-in`)으로 강화했다. props/호출 계약은 변경 없음 — `Analyze.jsx`는
전혀 수정하지 않는다.

## 2. FR-15 — XP 리더보드

MY 탭 `LevelCard` 바로 아래 `LeaderboardSummaryCard`(내 순위 한 줄 요약) → 터치 시
`XpLeaderboardModal`(듀오링고 스타일 전체 순위, 상위 3명 메달 강조). 신규 SQL 함수
`get_xp_leaderboard()`가 `total_xp` 내림차순 + 닉네임을 반환하고, 레벨은 클라이언트가
`getLevelProgress()`로 계산한다. 가상 유저 30명은 `scripts/seed-leaderboard-users.mjs`로 1회
시딩한다(실제 활동 유저가 대략 5등 근처에 오도록 XP 분포 설계).

## 3. FR-16 — 퀘스트 일간/주간 로테이션

일간 풀 30개 중 3개, 주간 풀 20개 중 3개를 `hashString` 기반 결정적 해시로 매일/매주 로테이션
노출한다. 리셋은 자정이 아니라 **오전 4시**(`logicalDateKey`/`logicalWeekKey`, `src/lib/logicalDate.js`)
기준. 로테이션 3개를 전부 수령하면 전클리어 보너스(일간 +10XP, 주간 +30XP)를 추가 지급한다. 모든
퀘스트는 자동 판정+자동 수령이다(수동 클레임 버튼 없음 — MY 탭 방문 또는 끼니 저장 시 조용히 지급).

## 4. FR-17 — 식단 퀴즈 & 밸런스게임

MY 탭에 10초 제한 4지선다 카드. 오늘의 대상 음식을 결정적으로 골라 서버(`/api/quiz/calorie-neighbors`)가
1인분 칼로리 기준 근접/원거리 후보를 찾아준다. 정답이면 `special-quiz` 퀘스트로 XP를 지급하고,
오답/시간초과는 페널티 없이 바로 다시 도전할 수 있다.

## 5. FR-18 — 지도 탭 음식 듀얼 비교

"주변 식당" 목록에서 다중 선택 모드로 카드 2개를 고르면 `PlaceDuelModal`이 열려 대표메뉴·가격·
영양소별 승/패와 종합 승자를 보여준다. 서버 호출 없이 `MapPage.jsx`가 이미 계산해둔
`place.expected`/`priceRange`/`representativeMenu`만으로 비교한다.

## 6. FR-19 — 커스텀 조합 음식 빌더

홈 화면 3번째 탭("커스텀 조합")에서 베이스/토핑/국물·음료를 DB 항목에서 직접 선택해(이름 매칭 없음 —
정확도·속도의 근거) 실시간으로 합산한다. 완료 시 기존 `AnalysisResultCard`/저장 흐름으로 그대로
합류한다.

## 7. FR-20 — 동적 수분 섭취 목표

고정 8잔 → `체중(kg)×30ml × 활동량 보정` 개인별 mL 목표로 전환, `AchievementRing`(FR-14 추출)으로
시각화. 신체정보가 없으면 기존 8잔 상당(1600ml)으로 폴백한다.

## 8. FR-21 — 비밀번호 찾기(보안 질문 방식)

가입 시 보안 질문 5개 중 하나를 고르고 답을 등록한다(`crypto.scrypt` 해시, 신규 `security_questions`
테이블 — RLS는 켜되 정책 없음, 서버(`SUPABASE_SERVICE_ROLE_KEY`)만 접근). 비밀번호를 잊으면
`/forgot-password`에서 아이디 → 질문 확인 → 답 + 새 비밀번호로 재설정한다. 계정 단위 5회 실패 시
15분 잠금이 주 방어선이다.

## 성공 지표

- 퀘스트 게시판이 매일 오전 4시, 매주 월요일 오전 4시에 새 3개로 바뀐다.
- MY 탭에서 내 순위·레벨을 확인하고, 터치하면 전체 리더보드를 볼 수 있다.
- 홈 화면에서 커스텀 조합을 만들어 저장까지 이어갈 수 있다.
- 지도에서 두 식당을 골라 영양/가격을 1:1로 비교할 수 있다.
- 비밀번호를 잊은 사용자가 이메일 없이도 보안 질문으로 계정을 복구할 수 있다.
