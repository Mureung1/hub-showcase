## 0. 배경 및 목표

사용자가 4가지를 요청했다: ① 챗봇 입력창에서 한글 종성(받침)이 조합되지 않고 분리되는 버그 수정
② 듀오링고식 레벨업 시스템(경험치 기반, 퀘스트 게시판 포함, CSV+Supabase 이중 저장) ③ 홈 화면에서
미션 완료 시 경험치가 레벨 카드로 들어가는 실시간 애니메이션 + 레벨업 팝업 ④ MY 탭 건강 달성
배지·도감.

조사(Explore 에이전트 병렬 조사 + Plan 에이전트 설계, 핵심 파일 직접 재확인) 결과 원래 전제와
달랐던 점:

1. **챗봇 버그의 진짜 원인은 `useFocusTrap.js` 자체의 결함이었다.** ChatBotSheet 컴포넌트만의
   문제가 아니라, 이 훅을 공유하는 6개 모달(ConfirmDialog/MealCardExporter/BarcodeScanButton/
   GuestMigrationPrompt/ImportConflictDialog 포함) 전부에 잠재된 문제였다 — 컨트롤드 input이 있는
   ChatBotSheet에서만 증상(한글 종성 분리)이 눈에 보였을 뿐이다.
2. **스트릭(연속 기록) 계산 로직이 이미 있었다.** `src/lib/streak.js`의 `calcStreak`을
   `StreakBadge.jsx`가 이미 쓰고 있어 새로 만들 필요 없이 XP 보너스·뱃지 조건에 재사용했다.
3. **"학식 영양왕" 같은 학식/급식 이용 기반 뱃지 조건은 이번 범위에서 구현하지 않았다.** 학식·급식
   이용 자체를 상시 집계하는 저장소가 없어, 새 스키마 추가 없이 만들 수 있는 대체 조건
   (`nutrition-master`: 단백질·나트륨 관리 퀘스트 누적 20회)으로 같은 취지를 구현했다.
4. **레벨/XP는 `total_xp` 정수 하나만 저장**하고 레벨·진행률은 클라이언트 순수 함수
   (`levelSystem.js`)로 항상 다시 계산한다 — `nutritionScore.js`류 "단일 소스" 원칙을 그대로
   따라, SQL에 레벨 공식을 복제하지 않는다.

**목표**
1. 신뢰성: 챗봇의 심각한 입력 버그(한글을 정상적으로 칠 수 없음)를 근본 원인부터 수정한다.
2. 리텐션: 듀오링고식 진행 루프(미션 수행 → XP 획득 → 레벨업 → 뱃지 수집)로 매일 앱을 열 동기를
   강화한다.
3. 게임성: 홈 화면에서 즉각적인 시각·감각 피드백(XP 획득 연출, 레벨업 팝업, 컨페티)을 제공한다.
4. 데이터 안전성: 레벨 데이터는 게스트(localStorage)/로그인(Supabase) 양쪽에서 동일하게 저장되고,
   CSV 백업·복원과도 호환된다.

**성공 지표**
- 챗봇 입력창에 한글을 연속으로 입력해도 종성이 분리되지 않는다.
- 끼니를 저장하면 조건을 만족한 퀘스트가 자동으로 완료 처리되고 XP가 지급된다.
- 레벨 경계를 넘기면 홈 화면에 레벨업 팝업이 짧게 나타났다 사라진다.
- MY 탭에서 현재 레벨, 오늘의 퀘스트 목록, 획득한 뱃지를 확인할 수 있다.
- 레벨(XP) 데이터가 CSV 백업/복원과 Supabase 계정 전환 양쪽에서 보존된다.

## 1. FR-9 — 챗봇 입력창 한글 조합 깨짐 버그 수정

**증상**: 챗봇 입력창에 "안녕"을 입력하면 "아ㄴ녀ㅇ"처럼 자모가 분리되어 표시됨.

**원인**: `src/lib/useFocusTrap.js`의 포커스 트랩 설정 `useEffect`가 `[active, onEscape]`에
의존하는데, `ChatBotSheet.jsx`가 `onEscape`로 매 렌더 새 화살표 함수를 넘겨 컨트롤드 input에
타이핑할 때마다(리렌더 → `onEscape` 참조 변경) 이 effect가 재실행되며 강제 blur→focus를
일으켰다. 이 blur가 브라우저 IME의 한글 조합을 매번 중간에 커밋시켰다.

**수정**: `onEscape`를 ref로 안정화해 트랩 설정 effect의 의존성에서 제거 — 포커스 이동/keydown
리스너 등록은 `active`의 논리적 변화(모달 열림/닫힘)에만 반응하고, Escape 키는 항상 ref를 통해
최신 콜백을 호출한다. 이 훅을 쓰는 6개 모달 전부가 근본적으로 안전해졌다.

**영향 범위**: `src/lib/useFocusTrap.js` 하나만 수정 — Tab 순환, Escape 처리, 언마운트 시 포커스
복원 등 기존 동작은 전혀 바뀌지 않는다.

## 2. FR-10 — 레벨/경험치(XP) 시스템

**레벨 공식**: 레벨 `n`에서 `n+1`로 가는 데 필요한 XP = `10 × n` (1→2레벨 10, 2→3레벨 20 ...
요청 원문 그대로). 100레벨이 만렙이며, 만렙 도달에 필요한 누적 총 XP는 49,500이다.

**연속 기록 보너스**: 스트릭이 2일 이상(어제도 기록해 오늘이 최소 2일째 연속)일 때 획득 XP에
10% 가산(요청 원문: "연속 기록 시 획득 경험치량 10% 증가"). 임계값·가산율 모두 상수 하나로
조정 가능.

**저장**: `profiles.total_xp` 컬럼 하나만 저장하고, 레벨/진행률은 항상 클라이언트에서 다시
계산한다. 퀘스트 수령 이력(`quest_claims`, 날짜+퀘스트 유니크 제약으로 중복 XP 지급 방지)과
뱃지 잠금해제 이력(`badge_unlocks`, 영구 보존)은 별도 테이블에 저장한다. 게스트는 동일한
데이터를 localStorage에 저장한다(`dataStore.js`의 기존 게스트/로그인 자동 분기 패턴 재사용).

**CSV 백업**: MY 탭 전체 백업의 `[profile]` 섹션에 `totalXp` 행 하나가 추가된다(0이면 생략 —
레벨 필드 없는 기존 백업과 형태가 같아짐). 복원 시 기존 값보다 클 때만 반영해 레벨 하락을
방지한다. 퀘스트/뱃지 "이력"은 이번 범위의 CSV 백업 대상이 아니다(총 XP만 백업).

## 3. FR-11 — 퀘스트 게시판 + 레벨 카드 (MY 탭)

기존 "오늘의 미션"(`missions.js`, 하루 1개 결정적 선택, 완료 이력 없음)과는 별개의 새 시스템
이다. 퀘스트 게시판은 여러 개를 동시에 노출하고, 완료(수령)를 영구 저장해 중복 XP 지급을
막는다.

**퀘스트 7개**(전부 쉬움 — "너무 어려운 미션 금지" 반영, 기존 기능 재활용):

| 퀘스트 | XP | 판정 방식 |
|---|---|---|
| 오늘 한 끼 기록 | 10 | 자동 (끼니 저장 시) |
| 세 끼 모두 기록 | 15 | 자동 |
| 단백질 80% 채우기 | 15 | 자동 |
| 나트륨 관리 | 15 | 자동 |
| 3일 연속 기록 | 20 | 자동 |
| 물 4잔 마시기 | 10 | 수동 (MY 탭에서 수령) |
| 영양제 챙겨 먹기 | 5 | 수동 |

MY 탭에 레벨 카드(현재 레벨 + 다음 레벨까지 진행바) → 퀘스트 게시판(위 7개 항목) 순서로
배치된다.

## 4. FR-12 — 홈 화면 실시간 XP/레벨업 애니메이션

홈 화면(Analyze.jsx) 상단에 항상 보이는 레벨 표시(LevelPill)가 애니메이션 목적지가 된다.
끼니를 저장해 auto 퀘스트가 완료되면: ① "+N XP" 텍스트가 저장 지점에서 레벨 표시로 날아가는
연출(Web Animations API) → ② 레벨 표시의 진행바가 채워짐 → ③ 레벨 경계를 넘겼으면 "🎉 레벨 N
달성!" 팝업이 짧게 나타났다 사라짐(컨페티 동반). 전부 라이브러리 없이 기존 프로젝트 관례(CSS
keyframe, `position:fixed` 오버레이, transform/opacity만 애니메이션)로 구현했다.

## 5. FR-13 — 건강 달성 배지 · 도감

`src/lib/badgeSystem.js`에 뱃지 9개를 정의(스트릭 3종·레벨 3종·퀘스트 누적 2종·영양 관리
1종) — 전부 이미 저장되는 데이터만으로 계산 가능한 조건이다. MY 탭의 "건강 달성 배지" 카드에서
획득 개수를 보여주고, "도감 보기"를 누르면 잠금/해제 상태를 3열 그리드로 보여주는 모달이
열린다. 새로 조건을 만족한 뱃지는 모달이 열릴 때 잠금해제되며 컨페티가 재생된다. 도감 화면은
조건을 재평가하지 않고 저장된 잠금해제 이력만 신뢰한다 — 스트릭이 끊기거나 상태가 바뀌어도 이미
딴 뱃지는 사라지지 않는다.
