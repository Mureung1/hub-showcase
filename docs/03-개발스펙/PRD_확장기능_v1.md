# PRD — 확장 기능 (리텐션·바이럴·추천 고도화)

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |
| 작성일 | 2026-07-29 |
| 전제 | 지도·학식 탭 UX 개선(카드 순서·주변 식당 5개 제한+다양화) 완료 상태. 안드로이드 APK는 미배포 — 개발자 모드로 사용자 본인 기기에만 설치돼 있고, 카카시터 `server.url` 원격 모드는 그대로 유지한다 |
| 범위 | ① 물 섭취·영양제 체크리스트 ② 인증샷 카드 익스포터 ③ 컨페티 ④ 식당 추천 2차원 스코어링 ⑤ API 응답 캐싱 ⑥ Meal-Bot 대화형 AI 영양사 ⑦ 바코드 스캔(스캔 UI만) ⑧ 식약처 검색 매칭 로컬 폴백 |
| 비범위 | 햅틱 피드백(네이티브 재빌드 필요), 실시간 정부 바코드 DB 연동(2018년 이후 갱신 중단 확인됨), 진짜 백그라운드 푸시 알림(서비스워커 금지 규칙과 충돌) |

---

## 0. 배경 및 목표

사용자가 제시한 9개 확장 아이디어를 실제 코드·API 기준으로 검증한 뒤 8개로 확정했다(1개는 네이티브
재빌드가 필요해 이번 범위에서 제외). 검증 과정에서 두 가지가 원래 전제와 달랐다:

1. **끼니 사진은 저장되지 않는다.** 분석 직후에만 메모리에 있다가 저장 시 버려진다 — "인증샷 카드"
   기능은 사진이 실제로 남아있는 화면(분석 직후 결과 카드)에 붙여야 한다.
2. **네이버 지역 검색에는 평점/리뷰 필드가 없다.** "3차원 추천 스코어(영양+거리+평점)"는 현재 데이터로
   구현 불가능해 2차원(영양+거리)으로 재설계했다.
3. **정부 바코드 DB는 2018년 이후 갱신이 끊겼다.** 바코드 스캔 UI 자체(브라우저 내장 `BarcodeDetector`
   API)는 네이티브 플러그인 없이 만들 수 있지만, "스캔하면 즉시 정확한 영양정보가 뜬다"는 약속은
   지킬 수 없어 범위를 조정했다.

**목표**
1. 리텐션: 매일 앱을 열 이유를 하나 더 만든다(물 섭취 체크리스트, 컨페티).
2. 바이럴 유입: 사용자가 자신의 식사 기록을 SNS로 자연스럽게 공유하게 만든다(인증샷 카드).
3. 추천 품질: 실제로 존재하는 데이터만으로 식당 추천의 설득력을 높인다(2차원 스코어).
4. 비용 방어: 신규 기능(챗봇)이 기존 기능의 API 한도·비용에 영향을 주지 않게 분리한다.
5. 정확도: 새 대형 인프라 없이, 이미 검증된 코드를 재사용해 매칭 실패율을 낮춘다.

**성공 지표**
- MY 탭에서 물 섭취를 하루 안에 기록할 수 있고, 자정이 지나면 초기화된다.
- 분석 결과 카드에서 인증샷 이미지를 생성해 다운로드 또는 공유할 수 있다.
- 끼니 저장 시 컨페티가 1회 재생된다.
- 지도 탭 식당 카드에 영양+거리 기반 추천도 점수가 표시된다.
- 챗봇이 기존 30회/10분 리미터를 갖는 사진 분석 기능과 별도로 동작해, 챗봇을 많이 써도 사진 분석이
  막히지 않는다.
- 바코드 스캔 지원 기기에서 스캔 버튼이 보이고, 캐시에 있는 제품은 즉시, 없는 제품은 기존 OCR로
  자연스럽게 이어진다.

## 1. FR-1 — 물 섭취·영양제 체크리스트

- MY 탭, 로그인/로그아웃 버튼 바로 아래에 카드 형태로 노출.
- 하루 목표 8잔 기준 물잔 아이콘, 영양제 복용 체크박스 1개.
- 기기별 로컬 저장(day-key), 계정 이동 시 동기화되지 않음 — 게스트도 동일하게 사용 가능.
- **알림이 아니다**: 앱을 열어야만 기록·확인 가능하고, 화면 문구도 "알림" 대신 "기록"으로 표현한다.

## 2. FR-2 — 인증샷 카드 익스포터

- 위치: 분석 결과 저장 직후 화면(사진이 메모리에 남아있는 유일한 지점).
- 구성: 방금 분석한 사진 배경 + 오늘 하루 누적 기준 영양 스코어(기존 공식 재사용) + 그 끼니의 영양
  뱃지(예: #고단백, #나트륨주의) + Mealyze 워터마크.
- 템플릿: 인스타그램 스토리(9:16), 피드(1:1) 2종.
- 공유: Web Share API 지원 시 바로 공유 시트, 미지원 시 이미지 다운로드로 자동 폴백.

## 3. FR-3 — 컨페티

- 끼니 저장 성공 시 화면에 짧게(1.5초) 컨페티 효과.
- 외부 라이브러리 없이 Canvas로 직접 구현 — 이 프로젝트의 기존 "모션은 CSS/캔버스로, 라이브러리는
  피한다" 원칙을 따른다.

## 4. FR-4 — 식당 추천 2차원 스코어링

- `Score = W1 × 영양 보충 충족도 + W2 × 거리 근접도`.
- 이미 계산돼 있는 값(예상 섭취량, 거리)만 조합 — 새 외부 데이터 불필요.
- 지도 탭 식당 카드에 "추천도 92점" 형태로 노출. 리뷰 평점 관련 문구는 넣지 않는다(데이터 없음).

## 5. FR-5 — API 응답 캐싱

- 식약처 조회·네이버 장소 검색 응답을 서버 메모리에 24시간 캐싱.
- **환경별 차이 명시**: Render(상시 프로세스)에서는 TTL이 그대로 유효하지만, Vercel 서버리스는
  인스턴스가 언제든 재생성될 수 있어 캐시 지속을 보장하지 않는다 — 화면·문서 어디에도 "항상 빠르다"고
  단정하지 않는다.
- 캐시 히트/미스 로그를 남겨, 운영 후 실측치로 효과를 검증할 수 있게 한다.

## 6. FR-6 — Meal-Bot 대화형 AI 영양사

- 오늘 누적 섭취량·권장량을 컨텍스트로 주입한 대화형 Q&A.
- 기존 사진 분석 API(`/api/gemini`, 10분당 30회)와 완전히 분리된 전용 라우트·리미터를 쓴다 — 챗봇
  사용량이 사진 분석 기능을 잠그지 않는다.
- 대화 이력은 서버에 영구 저장하지 않는다(세션 한정).
- 크기·리스크: 이번 확장 기능 중 가장 크고, 사용량에 비례해 비용이 늘어나는 유일한 항목이다.

## 7. FR-7 — 바코드 스캔 (스캔 UI, 자동완성은 자체 캐시 기반)

- 브라우저 내장 `BarcodeDetector` API 사용(네이티브 플러그인 아님, 미지원 기기는 버튼 자체를 숨김).
- 스캔한 바코드가 앱 자체 캐시(과거 OCR로 인식했던 결과)에 있으면 즉시 채우고, 없으면 기존 영양성분표
  OCR 스캔 경로로 자연스럽게 이어진다 — 사용할수록 좋아지는 자체 DB.
- "즉시 완벽한 자동완성"은 이번 범위가 아님을 화면에서도 정직하게 안내한다.

## 8. FR-8 — 식약처 검색 매칭 로컬 폴백

- 개인 사진 분석의 식품 매칭이 기존 7단계 모두 실패했을 때, 이미 구현·검증된 로컬 유사 매칭(학식·급식
  분석 엔진이 쓰는 것과 같은 코드)을 8번째 최후 수단으로 재사용한다.
- 새 형태소 분석·벡터 인프라를 만들지 않는다 — 이미 있는 걸 새 경로에 연결하는 것뿐이라 회귀 위험이
  낮다.

---

## 9. 비범위 (Out of Scope)

- **햅틱 피드백**: `AndroidManifest.xml`에 `VIBRATE` 권한이 없어 네이티브 재빌드가 필요 — 이번 범위
  제외, 다음에 네이티브 리빌드를 하게 되면 재검토.
- **정부 바코드 DB 실시간 연동**: 무료로 접근 가능한 국내 바코드 DB는 2018년 이후 갱신이 중단됐다 —
  자체 캐시 방식으로 대체.
- **진짜 백그라운드 푸시 알림**: 서비스워커가 필요한데, 이 프로젝트는 "웹 배포 = 앱 갱신" 속성을
  지키기 위해 의도적으로 서비스워커를 두지 않는다 — 이 규칙은 APK 배포 여부와 무관하게 유지된다.
