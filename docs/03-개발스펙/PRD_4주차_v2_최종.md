## 0. 배경 및 목표

지도 탭의 주변 식당 검색이 완성됨에 따라, 4주차는 **"매일 실제로 먹는 곳"**(학교 급식, 대학 학식)을 앱 안으로 가져오고, 사용자 맥락(직업)에 맞는 추천과 축적된 기록 기반의 AI 분석으로 **개인화 단계**로 넘어간다.

**목표**
1. 학교 급식·대학 학식 식단을 앱에서 조회하고, 그 식단의 영양 정보를 기존 분석 파이프라인으로 연결
2. 프로필에 직업을 추가하고, 직업에 맞는 식당 유형을 지도에서 **다른 색 핀**으로 자동 추천
3. 달력 탭의 축적 기록을 Gemini로 분석하는 **AI 식습관 비서** (최소 4문장)
4. 신규 기능이 기존 흐름과 충돌 없이 동작함을 검증하고, 보안·실사용 관점 보완점 도출

**성공 지표 (데모 기준)**
- 학교/학식당 선택 시 이번 주 식단 + 알레르기 태그 + 영양 정보 확인 가능
- 직업 설정 후 지도 진입 시 직업 맞춤 식당이 구분된 색 핀으로 자동 표시
- 달력 탭에서 내 기록 기반 4문장 이상의 자연스러운 한국어 분석 출력
- 기존 6개 화면 전부 회귀 없이 정상 동작, 새 API 키 노출 0건

## 1. 학식·급식 식단 조회 (P0)

### 1.1 데이터 소스 — 이원화 (확정)

| 대상 | 데이터 소스 | 영양 정보 | 알레르기 정보 |
|---|---|---|---|
| **초·중·고 급식** | 나이스(NEIS) 「급식식단정보」 API | API 직접 제공 (칼로리 + 영양정보 필드) | NEIS 번호 제공 → **밀라이즈 코드로 변환** (1.4) |
| **대학 학식** | **C안 하이브리드** (아래 1.2) | 없음 → 기존 텍스트 분석 경로로 추정 | 없음 → **밀라이즈 규칙으로 자동 태깅** (1.4) |

### 1.2 대학 학식 — C안 하이브리드 (확정)

동작 순서:
1. **1차 — 크롤링**: 프록시 서버가 충남대 생협 식단 페이지를 크롤링 (`/api/univ-meal`)
2. **2차 — 수동 JSON 폴백**: 크롤링 실패(페이지 구조 변경, 접속 불가, 파싱 결과 0건) 시 저장소의 `server/data/univ-meals.json`을 대신 반환
3. **3차 — 빈 상태**: 폴백 JSON에도 해당 날짜가 없으면 "오늘은 식단 정보가 없어요"

요구사항:
- 응답에 **출처 필드 포함**: `source: 'live' | 'fallback'` — 폴백 데이터일 때 화면에 "○월 ○주 기준 식단" 작은 안내 표시 (오래된 데이터를 최신처럼 보이지 않게)
- 크롤링 실패는 서버 로그에 원인과 함께 기록 (구조 변경 감지용)
- 폴백 JSON 스키마는 크롤링 결과와 **완전히 동일** — 화면은 출처를 몰라도 됨
- 폴백 JSON은 주 1회 수동 갱신 (내가 할 일에 포함, 갱신일 필드 필수)
- 대학 추가를 위한 어댑터 구조: `univMealAdapters/cnu.js` 형태 — 이번 주 구현은 충남대만

### 1.3 기능 요구사항

#### FR-1.1 학교 선택
- 사용자가 자신의 학교를 검색·선택해 프로필에 저장 (1회 설정, 변경 가능)
- 초중고: NEIS 「학교기본정보」 API로 학교명 검색 → 시도교육청코드 + 학교코드 저장
- 대학: 지원 목록에서 선택 (초기엔 충남대 1개)

#### FR-1.2 식단 조회 화면
- 위치: **지도 탭 내 서브 영역** — 상단 토글 "주변 식당 | 학식·급식"
- 표시 범위: 오늘 기준 **이번 주** (일별 이동 가능)
- 급식(NEIS): 조·중·석식 구분, 메뉴 목록, **알레르기 태그(밀라이즈 코드)**, 칼로리
- 학식: 식당(코너)별 메뉴 + 가격 + 알레르기 태그 + (폴백 시) 기준 주차 안내
- 데이터 없음(방학·휴무·주말): 빈 상태 표시 — 에러 아님

#### FR-1.3 영양 정보 분석 연결
- 급식(NEIS): API 영양정보 필드를 파싱해 기존 영양소 카드 형식으로 표시
- 학식: "영양 분석" 버튼 → 기존 텍스트 분석 경로(Gemini 표준 1인분 추정 → 보정)로 전달 — 기존 3갈래 분석 경로에 4번째 입구만 추가
- 분석 결과에서 **[식단으로 저장]** 가능 — 기존 결과 카드·저장 흐름(같은 상태 머신) 재사용

### 1.4 밀라이즈 알레르기 구분 규칙 (신규 확정 스펙)

**목적**: 급식(NEIS 번호 있음)과 학식(정보 없음)을 **하나의 번호 체계**로 통일해 표시한다.

#### FR-1.4a 밀라이즈 알레르기 코드 정의
- 단일 상수 파일 `src/lib/allergyRules.js`에 정의 — 코드·이름·아이콘·매칭 키워드의 **단일 소스**
- 코드 체계: 식품 알레르기 **법정 표시 대상 19종**을 기반으로 밀라이즈 번호 M1~M19 부여:

| 코드 | 항목 | 코드 | 항목 | 코드 | 항목 |
|---|---|---|---|---|---|
| M1 | 난류(계란) | M8 | 게 | M15 | 닭고기 |
| M2 | 우유 | M9 | 새우 | M16 | 쇠고기 |
| M3 | 메밀 | M10 | 돼지고기 | M17 | 오징어 |
| M4 | 땅콩 | M11 | 복숭아 | M18 | 조개류(굴·전복·홍합 포함) |
| M5 | 대두 | M12 | 토마토 | M19 | 잣 |
| M6 | 밀 | M13 | 아황산류 | | |
| M7 | 고등어 | M14 | 호두 | | |

#### FR-1.4b 급식(NEIS) — 번호 매핑
- NEIS가 주는 알레르기 번호(1~19)를 밀라이즈 코드(M1~M19)로 변환하는 매핑 테이블 포함
- 화면에는 번호가 아닌 **이름 태그**로 표시 (예: `계란` `우유`) — 탭하면 "알레르기 유발 식품 안내" 시트에서 전체 코드표 확인 가능

#### FR-1.4c 학식·일반 메뉴 — 키워드 규칙 자동 태깅
- 알레르기 정보가 없는 메뉴명에 대해 **키워드 매칭 규칙**으로 코드를 자동 부여:
  - 예: 메뉴명에 `돈까스·제육·삼겹` 포함 → M10(돼지고기), `새우` → M9, `우동·칼국수·빵` → M6(밀) …
  - 규칙은 `allergyRules.js`의 키워드 배열로 관리 — 규칙 추가가 파일 수정만으로 가능
- **자동 태깅의 한계 고지 필수**: 자동 부여된 태그 옆에 `추정` 배지 + 안내 문구
  *"메뉴명 기반 자동 분류로, 실제 재료와 다를 수 있습니다. 알레르기가 있다면 반드시 직접 확인하세요."*
  — NEIS 제공 정보(공식)와 키워드 추정을 시각적으로 구분해, 알레르기 사용자가 추정을 공식 정보로 오인하지 않게 한다 (안전 요구사항)

#### FR-1.4d 확장 적용
- 이 규칙은 학식·급식 외에 **기존 분석 결과 카드에도 동일 적용 가능**한 구조로 설계 (이번 주 필수 범위는 학식·급식 화면까지, 결과 카드 적용은 여유 시)

### 1.5 서버 (프록시 확장)
- `/api/school-meal` (NEIS 중계 — 키는 서버에만), `/api/univ-meal` (크롤링 + 폴백)
- 캐싱: 급식·학식은 하루 단위 데이터이므로 서버 메모리 캐시(당일 TTL) — NEIS 쿼터 절약
- 요청 검증: 학교코드 형식·날짜 범위 체크 (프록시를 임의 크롤러로 악용 방지)

### 1.6 수용 기준
- [ ] 학교 검색·선택 → 프로필 저장·복원
- [ ] 초중고 선택 시 이번 주 급식 + 알레르기 이름 태그 + 칼로리 표시
- [ ] 충남대 선택 시 학식 표시 → "영양 분석" → 결과 카드 → 저장까지 동작
- [ ] **크롤링을 강제로 실패시켰을 때 폴백 JSON이 대신 표시되고 기준 주차 안내가 뜸**
- [ ] 학식 메뉴에 키워드 기반 알레르기 태그가 `추정` 배지와 함께 표시됨
- [ ] NEIS 번호 ↔ 밀라이즈 코드 매핑이 코드표와 일치 (테스트로 검증)
- [ ] 주말/방학 빈 상태 정상, NEIS 키 노출 0건

## 2. 직업 기반 식당 자동 추천 + 핀 색 구분 (P1)

### 2.1 기능 요구사항

#### FR-2.1 프로필 직업 필드 (선택지 5개 확정)
- 프로필에 직업 선택 추가: `초등학생 / 중·고등학생 / 대학생 / 직장인 / 기타(선택 안 함)`
- 저장: 기존 dataStore 규칙 그대로 — 게스트=localStorage, 로그인=Supabase `profiles` 컬럼 추가(마이그레이션)
- 미설정 시 기존 동작 완전 유지 — **직업은 선택 사항**

#### FR-2.2 직업 → 추천 매핑
| 직업 | 자동 추천 |
|---|---|
| 초등학생 / 중·고등학생 | 급식 식단 바로가기(지도 탭 진입 시 학식·급식 토글 우선) + 분식·간식 키워드 |
| 대학생 | 학식 바로가기 + `백반`, `가성비 맛집` 키워드 |
| 직장인 | `백반`, `한식 뷔페`, `구내식당`, `점심 특선` 키워드 |
| 기타/미설정 | 기존 부족 영양소 기반 추천만 |

- 매핑은 단일 상수 파일 `occupationKeywords.js`로 관리
- 검색은 기존 `/api/naver-places` 재사용 (검색어만 다름)

#### FR-2.3 지도 핀 구분
- 기존 영양소 추천 핀(현재 색 유지) + 신규 직업 맞춤 핀(**다른 색**, 네이버 맵 커스텀 마커)
- 지도 위 범례: `● 영양소 추천  ● 직업 맞춤` — 색만으로 구분 강요 금지(접근성)
- 중복 해당 식당은 직업 핀 우선 + 상세 카드에 두 사유 모두 표시

### 2.2 수용 기준
- [ ] 직업 설정 → 게스트/로그인 모두 저장·복원
- [ ] 직장인 설정 후 지도 진입 시 백반집 계열이 다른 색 핀으로 표시
- [ ] 학생 직업 설정 시 학식·급식 화면 유도 노출
- [ ] 직업 미설정 시 기존 지도 동작과 완전히 동일 (회귀 없음)
- [ ] 범례로 두 핀 의미 즉시 구분 가능

## 3. AI 식습관 분석 비서 (P1)

### 3.1 기능 요구사항

#### FR-3.1 위치와 트리거
- 위치: **달력 탭 상단** "AI 식습관 분석" 카드
- 트리거: 사용자가 버튼을 눌러 실행 (자동 실행 금지)
- 분석 기간: 기본 최근 7일, 옵션 최근 30일

#### FR-3.2 분석 파이프라인
1. 클라이언트가 기간 내 기록을 **집계 요약**으로 변환 (원본 전체 전송 금지):
   일별 총 칼로리·영양소 합계, 권장량 대비 달성률, 자주 등장 음식 상위 목록, 기록 일수
2. `/api/gemini`(기존 프록시)로 전송 — 새 엔드포인트 불필요, 프롬프트만 분리 관리
3. 응답 계약: **한국어 4문장 이상**, 구조 = ① 잘한 점 1가지 → ② 주의 패턴 1~2가지 → ③ 구체적 실천 제안 1~2가지 → ④ 격려 마무리
4. 4문장 미만이면 클라이언트가 1회 자동 재요청, 그래도 실패 시 오류 안내

#### FR-3.3 비용·품질 제어 (확정: "다시 분석" 버튼 없음)
- **당일 캐시 고정**: 같은 기간에 대한 분석은 **하루 1회만** 실제 호출. 당일 재방문·재클릭 시 캐시된 결과만 표시하고 **재분석 수단은 노출하지 않는다**
- 캐시 무효화는 자연 조건만: 날짜가 바뀌거나, 분석 기간 옵션(7일↔30일)을 바꾼 경우
- 캐시 표시 시 분석 시각 표기: "오늘 오전 9:12 분석" — 왜 새로 안 도는지 사용자가 납득하게
- 기록 2일 미만이면 호출하지 않고 "기록이 더 쌓이면 분석해드릴게요" 안내
- 프롬프트 금지 사항: 질병 진단·치료 표현 금지, 전달된 요약 수치 외 기록 언급 금지
- 하단 고정 고지: *"이 분석은 참고용이며 의학적 조언이 아닙니다."*

#### FR-3.4 표시
- 로딩: "이번 주 식단을 살펴보고 있어요…" (수 초 소요 안내)
- 결과: 문단 카드 + 분석 기간·기록 일수 표기 (예: "7. 21 ~ 7. 27 · 6일 기록 기준")
- 결과는 로컬 저장 — 재방문 시 마지막 분석 즉시 표시

### 3.2 수용 기준
- [ ] 7일 기록 기준 4문장 이상 분석 출력, 요약 수치와 모순 없음
- [ ] 같은 날 재클릭·재방문 시 API 재호출 0회, 분석 시각 표시
- [ ] **화면 어디에도 "다시 분석" 류의 재실행 버튼이 없음**
- [ ] 기간 옵션 변경 시에만 새 분석 실행
- [ ] 기록 부족 시 호출 없이 안내, 의학적 조언 아님 고지 상시 표시

## 4. 안정화·보안 점검 (P0 — 릴리즈 게이트)

### 4.1 회귀 방지
- 기존 6개 화면 핵심 흐름 수동 회귀 체크리스트 통과
- 지도 탭 집중 확인: 토글 추가로 인한 기존 주변 식당 검색 회귀 여부
- 기존 Vitest 전부 그린 유지 + 신규 순수 로직 테스트 추가:
  직업 매핑 / 분석 요약 집계 / NEIS 응답 파싱 / **알레르기 매핑·키워드 태깅** / 학식 폴백 판정

### 4.2 보안 점검
- NEIS 키·크롤링 엔드포인트 프론트 노출 0건
- `/api/school-meal`·`/api/univ-meal` 요청 검증 (학교코드 형식·날짜 범위)
- AI 분석 요청에 개인 식별 정보 미포함 — 집계 수치만 전송

### 4.3 실사용 흐름 점검
- 학교 미설정 사용자가 학식·급식 토글을 눌렀을 때의 안내 흐름
- 직업·학교 설정 불일치(직장인 + 학교 설정) 시 동작 정의
- AI 분석 응답 지연 시 타임아웃 안내
- APK에서 신규 화면 3종 레이아웃·터치 검증
- **알레르기 `추정` 배지가 공식 정보와 혼동되지 않는지** 제3자 확인

### 4.4 수용 기준
- [ ] 회귀 체크리스트 전 항목 통과, 기존+신규 테스트 전부 그린
- [ ] 신규 API 키 노출 0건, 프록시 요청 검증 동작
- [ ] 발견 이슈 심각도 분류 기록, 치명·높음은 4주차 내 수정

|---|---|---|
