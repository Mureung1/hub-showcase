서버가 처음으로 Supabase를 직접 호출한다(`server/supabaseAdmin.js`, `SUPABASE_SERVICE_ROLE_KEY`).
답 해시는 Node 내장 `crypto.scrypt`(신규 의존성 없음). `security_questions` 테이블은 RLS를 켜되
정책을 하나도 두지 않아 서버만 접근 가능하다. 무차별 대입 방지는 IP 리미터(보조) + **계정(login_id)
단위 DB 잠금**(주 방어선, 5회 실패 시 15분)이 이중으로 막는다. 오답과 "계정 없음"은 같은 문구
(`아이디 또는 답변이 올바르지 않습니다`)로 응답해 계정 존재 여부를 드러내지 않는다.

가입 폼에 보안 질문(5개 중 선택) + 답 입력란을 추가했고, 기존 "복구 불가" 경고 문구를 "이메일로는
복구 불가, 보안 질문으로 복구 가능"으로 바꿨다. `registerSecurityQuestion`은 가입 성공 직후 별도
try/catch로 호출해 실패해도 가입 자체는 막지 않는다(토스트로만 안내).

분포는 실유저가 대략 5등 근처에 오도록 설계했다(상위 4명 3200~1750XP, 나머지 25명 1200~25XP로 완만히
감소).

## 확인이 필요했던 지점(제안값으로 진행, 조정 가능)

| 항목 | 제안값 | 조정 방법 |
|---|---|---|
| ① 퀘스트 수동 클레임 버튼 제거 | 전부 자동 판정+자동 수령 | 특정 퀘스트만 수동으로 되돌리려면 `quests.js`에 `kind` 필드를 다시 추가하고 `QuestBoard.jsx`에 버튼 분기를 되살려야 함 |

| ③ 커스텀 조합 3그룹(소스 없음) | 베이스/토핑/국물·음료 | 진짜 소스류를 원하면 `foodDB.json`에 category 태깅이 신규로 필요(범위 밖) |
