# 구현 프롬프트 — 게이미피케이션 v2

`PRD_확장기능_v2.md`의 FR-9~13을 실제로 구현한 방식과 파일 목록. 구현·테스트·검증까지 전부
완료된 상태를 기록한 문서다(작업 순서: FR-9 → FR-10 → FR-11 → FR-13 → FR-12 → 전체 검증).

## FR-9. 챗봇 입력창 한글 조합 깨짐 버그 수정

**파일**: `src/lib/useFocusTrap.js`(수정), `src/lib/useFocusTrap.test.js`(신규),
`src/components/ChatBotSheet.test.jsx`(회귀 케이스 추가)

`onEscape`를 `useRef`에 담아 트랩 설정 `useEffect`의 의존성 배열에서 제거하고
(`[active, onEscape]` → `[active]`), keydown 핸들러 내부에서는 그 ref를 읽는다. 포커스 이동·
keydown 리스너 등록·언마운트 시 포커스 복원은 `active`가 논리적으로 바뀔 때만 실행되며, Escape는
항상 최신 콜백을 호출한다. 이 훅을 쓰는 6개 호출부(ChatBotSheet/BarcodeScanButton/
ConfirmDialog/GuestMigrationPrompt/ImportConflictDialog/MealCardExporter) 전부 기능은 그대로다.

## FR-10. 레벨/경험치(XP) 시스템 — 저장 인프라

**파일**: `src/lib/levelSystem.js`(신규), `src/lib/db.js`(추가), `src/lib/dataStore.js`(추가),
`supabase/migrations/2026-07-29_gamification.sql`(신규), `supabase/schema.sql`(동기화),
`src/lib/backupFormat.js`(수정), `src/lib/dataBackup.js`(수정)

- `levelSystem.js`: `xpRequiredForLevel(level) = level * 10`, `MAX_LEVEL = 100`,
  `MAX_TOTAL_XP = 49500`, `getLevelProgress(totalXp)` → `{level, xpIntoLevel, xpForNextLevel,
  totalXp, isMaxLevel}`(0~MAX_TOTAL_XP 클램프), `applyStreakBonus(baseXp, streakCurrent,
  {thresholdDays=2, bonusRate=0.1})`.
- Supabase: `profiles.total_xp integer not null default 0`, `quest_claims`
  (`user_id,date,quest_id,xp_awarded`, unique(user_id,date,quest_id)), `badge_unlocks`
  (`user_id,badge_id`, unique(user_id,badge_id)), `increment_total_xp(p_delta)` RPC(SECURITY
  DEFINER, upsert로 원자적 증가 — profiles 행이 없는 온보딩 전 사용자도 안전).
- `db.js`: `getLevelState`/`saveLevelState`/`getClaimedQuestIds`/`claimQuest`(유니크 위반 시
  `alreadyClaimed:true`로 재지급 방지)/`getQuestClaimStats`/`getUnlockedBadgeIds`/`unlockBadge`.
- `dataStore.js`: 위 7개 함수를 게스트(localStorage, `levelState`/`questClaims:<dateKey>`/
  `badgeUnlocks` 키)/로그인(db.js) 자동 분기로 재노출.
- `backupFormat.js`: `buildLevelRow(totalXp)`(0이면 빈 배열), `parseProfileSection`이 `totalXp`를
  프로필 유효성과 독립적으로 추출·반환. `dataBackup.js`: 내보내기 시 `[profile]` 섹션에 XP 행
  추가, 복원 시 기존 값보다 클 때만 반영(`levelRestored` 플래그 추가).

## FR-11. 퀘스트 게시판 + 레벨 카드 (MY 탭)

**파일**: `src/lib/quests.js`(신규), `src/components/LevelCard.jsx`(신규),
`src/components/QuestBoard.jsx`(신규), `src/pages/Profile.jsx`(삽입: `WaterIntakeCard` 자리 —
로그인/로그아웃 버튼 다음, 순서는 `LevelCard → QuestBoard → BadgeShelfCard → WaterIntakeCard`)

`quests.js`의 `QUESTS`(7개, `kind:'auto'|'manual'`), `evaluateQuest`/`getQuestBoard`/
`findNewlyCompletedAutoQuests`(순수 함수, `nutrientCriteria.isMet`/`streak.calcStreak`/
`waterIntake.getWaterIntake` 재사용). `QuestBoard`는 마운트 시 auto 퀘스트를 안전망으로 한 번
더 확인해 조용히 자동 지급하고(홈 화면을 거치지 않고 MY 탭에 바로 들어온 경우 대비), manual
퀘스트는 "수령하기" 버튼으로 클레임한다.

## FR-13. 뱃지 · 도감

**파일**: `src/lib/badgeSystem.js`(신규), `src/components/BadgeShelfCard.jsx`(신규),
`src/components/BadgeDexModal.jsx`(신규), `src/pages/Profile.jsx`(삽입)

`BADGES`(9개: streak-3/7/30, level-10/30/100, quest-10/50, nutrition-master). `evaluateBadges`
(미획득 중 조건 충족분만) / `getBadgeDex`(저장된 unlockedIds만 신뢰, 조건 재평가 없음).
`BadgeDexModal`은 `ConfirmDialog`/`MealCardExporter`와 동일한 모달 셸을 재사용하고, 마운트 시
새 뱃지가 있으면 `dataStore.unlockBadge` + `playConfetti()`를 호출한다.

## FR-12. 홈 화면 실시간 애니메이션

**파일**: `src/components/LevelPill.jsx`(신규), `src/lib/xpFlyAnimation.js`(신규),
`src/components/LevelUpPopup.jsx`(신규), `src/index.css`(`tds-levelup-out` keyframe 추가),
`src/pages/Analyze.jsx`(오케스트레이션)

`LevelPill`은 `id="home-level-pill"`을 가진 순수 프레젠테이션 컴포넌트(홈 화면 헤더 바로
아래, 상시 노출). `xpFlyAnimation.playXpFly`는 Web Animations API로 "+N XP"가 날아가는 연출을
만든다(좌표 보간은 `buildXpFlyKeyframes`로 분리해 순수 테스트 가능). `LevelUpPopup`은 등장에
기존 `tds-tab-bounce`, 퇴장에 신규 `tds-levelup-out`을 쓰고 컨페티를 동반한다.

`Analyze.jsx`의 `handleConfirmSave`에 `playConfetti()` 직후 `runGamification(record)`를
추가(전체를 자체 try/catch로 감싸 실패해도 저장 성공 흐름을 막지 않음): 방금 저장한 끼니를
`todayMeals`에 직접 합쳐 ctx 구성 → `findNewlyCompletedAutoQuests` → 스트릭 보너스 적용해
`claimQuest` → XP 증가분이 있으면 `playXpFly` + (레벨업 시) `LevelUpPopup` → `evaluateBadges`로
새 뱃지 확인·지급.

## 확인이 필요했던 지점(제안값으로 진행, 조정 가능)

| 항목 | 제안값 | 조정 방법 |
|---|---|---|
| 레벨 랭킹(타인과 비교) | v1엔 미포함, 자기 레벨만 표시 | `total_xp` 정렬 SQL RPC 추가 필요 |
