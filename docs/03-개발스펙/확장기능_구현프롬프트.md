## FR-1. 물 섭취 · 영양제 체크리스트

**신규 파일**: `src/lib/waterIntake.js`, `src/components/WaterIntakeCard.jsx`
**수정 파일**: `src/pages/Profile.jsx`

```js
// src/lib/waterIntake.js
import { get, set } from './storage.js'

export const TARGET_GLASSES = 8

function key(userId, dateKey) {
  return `waterIntake:${userId}:${dateKey}`
}

export function getWaterIntake(userId, dateKey) {
  return get(key(userId, dateKey), { glasses: 0, supplementTaken: false })
}

export function setGlasses(userId, dateKey, glasses) {
  const clamped = Math.max(0, Math.min(TARGET_GLASSES, glasses))
  const current = getWaterIntake(userId, dateKey)
  const next = { ...current, glasses: clamped }
  set(key(userId, dateKey), next)
  return next
}

export function toggleSupplement(userId, dateKey) {
  const current = getWaterIntake(userId, dateKey)
  const next = { ...current, supplementTaken: !current.supplementTaken }
  set(key(userId, dateKey), next)
  return next
}
```

- `dateKey`는 호출부(`WaterIntakeCard.jsx`)에서 `src/lib/records.js`의 `toDateKey(new Date())`로 만든다
  — 반드시 이 함수를 써서 KST 자정 기준을 다른 기능들과 통일한다.
- `WaterIntakeCard.jsx`: 물잔 8개를 `flex`로 가로 배치, `i`번째 잔 탭 시 `setGlasses(userId, dateKey, i+1)`
  (이미 그 잔까지 채워진 상태에서 같은 잔을 다시 탭하면 `i`로 감소 — 토글처럼 동작). `useUser()`의
  `effectiveUserId` 사용. 카드 스타일은 `CardSettingsPanel.jsx`의 톤(라운드·패딩·타이포)을 그대로
  따른다.
- `Profile.jsx`: 로그인/로그아웃 버튼 행 바로 아래, 건강정보 폼 카드 위에 삽입.
- 문구에 "알림"이라는 단어를 쓰지 않는다 — 예: "오늘 몇 잔 마셨나요?" / "영양제 챙겨 먹었어요".

**테스트**: `waterIntake.test.js` — 초기값, clamp(0/8 경계), 토글, 서로 다른 `dateKey`가 독립적으로

## FR-3. 컨페티

**신규 파일**: `src/lib/confetti.js`

```js
// src/lib/confetti.js — 끼니 저장 성공 시 짧은 축하 이펙트. 라이브러리 없이 직접 구현
// (interaction-guide.md의 "모션은 CSS/캔버스로" 원칙 — canvas-confetti 등 npm 의존성 추가 금지).
export function playConfetti({ durationMs = 1500, particleCount = 60 } = {}) {
  const canvas = document.createElement('canvas')
  canvas.style.cssText = 'position:fixed;inset:0;pointer-events:none;z-index:9999;'
  canvas.width = window.innerWidth
  canvas.height = window.innerHeight
  document.body.appendChild(canvas)
  const ctx = canvas.getContext('2d')

  const colors = ['#059669', '#FF9F1C', '#3182F6', '#F04452', '#FFD43B']
  const particles = Array.from({ length: particleCount }, () => ({
    x: Math.random() * canvas.width,
    y: -20,
    vx: (Math.random() - 0.5) * 4,
    vy: Math.random() * 3 + 2,
    size: Math.random() * 6 + 4,
    rotation: Math.random() * 360,
    rotationSpeed: (Math.random() - 0.5) * 10,
    color: colors[Math.floor(Math.random() * colors.length)],
  }))

  const start = performance.now()
  function frame(now) {
    const elapsed = now - start
    ctx.clearRect(0, 0, canvas.width, canvas.height)
    for (const p of particles) {
      p.x += p.vx
      p.y += p.vy
      p.rotation += p.rotationSpeed
      ctx.save()
      ctx.translate(p.x, p.y)
      ctx.rotate((p.rotation * Math.PI) / 180)
      ctx.fillStyle = p.color
      ctx.fillRect(-p.size / 2, -p.size / 2, p.size, p.size)
      ctx.restore()
    }
    if (elapsed < durationMs) {
      requestAnimationFrame(frame)
    } else {
      canvas.remove()
    }
  }
  requestAnimationFrame(frame)
}
```

- `Math.random()` 사용은 순수 시각 효과라 이 프로젝트의 "결정적 로직에 `Math.random`/`Date.now` 금지"
  규칙(미션 선택 등 데이터 로직 대상)과 무관하다.
- 호출 지점: 끼니 저장 성공 직후(예: `AnalysisResultCard.jsx`의 저장 완료 핸들러) `playConfetti()` 1회.
- `position: fixed` 오버레이라 레이아웃 리플로우 없음.

**테스트**: 순수 함수가 아니라 DOM 부작용이라 유닛 테스트는 얇게(캔버스가 append/remove 되는지 정도만)
— 애니메이션 자체 확인은 사용자 몫(아래 "사용자가 할 일" 참고).

## FR-4. 식당 추천 2차원 스코어링

**신규 파일**: `src/lib/placeScore.js`
**수정 파일**: `src/pages/MapPage.jsx`, `src/components/PlaceList.jsx`

```js
// src/lib/placeScore.js
// Score = W1×영양 보충 충족도 + W2×거리 근접도. 리뷰 평점 항목은 네이버 지역 검색에 그 데이터가
// 없어서(직접 확인) 제외했다 — 있지도 않은 데이터로 점수를 지어내지 않는다.
export const NUTRITION_WEIGHT = 0.7
export const DISTANCE_WEIGHT = 0.3

// fulfillmentRatio: 0~1 (그 대표메뉴가 부족 영양소를 얼마나 채우는지, 이미 있는 expected/deficientRows로 계산)
// distance/maxDistance: 이미 있는 place.distance와 MAX_DISTANCE_METERS
export function calcPlaceScore({ fulfillmentRatio, distance, maxDistance }) {
  const nutritionScore = Math.max(0, Math.min(1, fulfillmentRatio))
  const proximityScore = Math.max(0, Math.min(1, 1 - distance / maxDistance))
  const score = NUTRITION_WEIGHT * nutritionScore + DISTANCE_WEIGHT * proximityScore
  return Math.round(score * 100)
}
```

- `fulfillmentRatio` 계산: `place.expected`(이미 `attachExpectedIntake`가 채움)와 `top3Rows`(부족
  영양소, 이미 있음)를 비교해 "이 대표메뉴가 부족량 대비 몇 %를 채우는지"의 평균 또는 최댓값(설계
  시 결정) — `src/lib/nutrition.js`의 기존 비율 계산 패턴(`buildDeficiencyRows`의 `ratio` 필드)과
  일관된 방식 재사용.
- `MapPage.jsx`: `diversifyByCategory` → `attachExpectedIntake` 다음 단계에서 각 place에
  `score: calcPlaceScore(...)` 부착.
- `PlaceList.jsx`: 기존 "추천 이유" 줄 근처에 "추천도 92점" 배지 추가. 리뷰·평점 관련 문구는 절대
  넣지 않는다.

**테스트**: `placeScore.test.js` — 충족도 100%+최단거리 → 100점 근처, 충족도 0+최장거리 → 0점 근처,
가중치 합이 항상 1인지, 값 범위(0~100) clamp 확인.

## FR-7. 바코드 스캔

**신규 파일**: `src/lib/barcodeScanner.js`, `src/lib/barcodeCache.js`
**수정 파일**: 라벨 스캔 진입점(예: `Analyze.jsx`의 모드 선택 또는 `LabelScan` 관련 컴포넌트)

```js
// src/lib/barcodeScanner.js
export function isBarcodeDetectorSupported() {
  return typeof window !== 'undefined' && 'BarcodeDetector' in window
}

export async function scanBarcodeFromStream(videoElement, { intervalMs = 300, formats = ['ean_13'] } = {}) {
  if (!isBarcodeDetectorSupported()) return null
  const detector = new window.BarcodeDetector({ formats })
  return new Promise((resolve) => {
    const timer = setInterval(async () => {
      const codes = await detector.detect(videoElement).catch(() => [])
      if (codes.length > 0) {
        clearInterval(timer)
        resolve(codes[0].rawValue)
      }
    }, intervalMs)
  })
}
```

```js
// src/lib/barcodeCache.js — storage.js 재사용, 자체 축적형 캐시

```
