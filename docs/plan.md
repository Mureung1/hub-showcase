# AI 논문 브리핑 웹 서비스 — 기획 문서

## Context (왜 이걸 만드는가)
최신 AI(특히 LLM) 분야는 arXiv 논문·뉴스의 생산 속도와 양이 개인이 따라잡을 수 있는 한계를 넘어섰다. "무엇이 중요한지 선별하고 짧은 시간에 파악하는 것" 자체가 큰 비용이 되었다. 이 프로젝트는 흩어진 최신 AI 논문을 **자동 수집 → LLM 요약 → 매일 브리핑**으로 정리해, 사용자가 웹에서 짧은 시간에 최신 동향을 따라잡게 하는 서비스다.

**한 문장 정의**: 최신 AI(LLM) 논문을 매일 자동 수집·요약하여, 연구자·개발자가 짧은 브리핑으로 최신 동향을 놓치지 않고 파악하게 해주는 정적 웹 서비스.

**성격**: 기획(문서 작성)이 목적. 본 문서는 10문항 인터뷰(Q1~Q10) 답변을 바탕으로 한 확정 기획서다.

---

## 1. 목적 & 타겟

- **주 사용자(Q1)**: AI 연구자·개발자. 전문 용어 유지, 논문 원문·기술 디테일 중시, **깊이 있는 요약**. 각 논문에 **배경(맥락) 설명**을 함께 제공.
- **핵심 가치(Q2)**: ① **놓치지 않기**(Coverage/Curation) ② **트렌드 파악**(Aggregation) — 두 가지 모두. 성공 기준 = "매일 짧은 시간에 중요 논문을 빠짐없이 파악하고 분야 흐름을 인지".

## 2. 콘텐츠 범위

- **정보 소스(Q3)**: MVP는 **arXiv 논문만** (API 무료, LLM 논문의 1차 소스).
- **주제 범위(Q4)**: **LLM 중심 + 인접 분야.** arXiv 카테고리 `cs.CL` + `cs.AI` + `cs.LG` 수집, LLM 관련 키워드로 선별.
- **갱신 주기(Q5)**: **매일 브리핑 + 주간 요약 병행.** 기본은 하루 1회 배치 → '오늘의 브리핑', 주 1회 주간 집계.

## 3. 핵심 로직 (선별·요약, Q6)

- **MVP**: **LLM 자동 요약.** arXiv 초록(및 가능 시 본문)을 LLM으로 **한국어 요약** — 핵심 기여·방법·결과를 구조화 추출. **원문 초록 병기**로 검증 가능하게.

## 4. 기능 명세

### MVP 필수 기능 (Q7)
1. **오늘의 브리핑 피드** — 날짜별 수집 논문·요약을 카드 목록으로 보여주는 메인 화면. (핵심)
2. **논문 상세 보기** — 한국어 요약 전문 + 원문 초록 + arXiv 원문 링크 + 저자·날짜·카테고리 메타정보.
3. (부수) **주간 요약** 화면 — 한 주 논문 집계/모음.

## 5. 기술 스택 & 아키텍처 (Q8, Q9)

**정적 사이트 + GitHub Actions cron + GitHub Pages (서버 0대, 비용 0원).**

```
매일 정해진 시각
  └─ GitHub Actions(무료 cron)가 파이썬 스크립트 실행
       ├─ arXiv 수집 (arxiv / feedparser 라이브러리)
       ├─ LLM으로 한국어 요약 (Gemini Flash 무료 티어)
       ├─ 결과를 JSON/정적 파일로 생성
       └─ 저장소에 커밋
  └─ GitHub Pages가 정적 파일을 웹으로 서빙 (무료)
```

- **데이터 파이프라인**: Python (수집·요약 도구가 파이썬 네이티브 — arXiv/LLM SDK 생태계).
- **프론트엔드**: 정적 사이트 (정적 HTML 또는 React 정적 빌드)로 생성된 JSON을 읽어 렌더.
- **호스팅**: GitHub Pages (정적, 무료). 상시 서버·로컬 서버 불필요.
- **로그인/다중 사용자(Q9)**: **불필요 — 공개 페이지.** 정적 구조와 부합.

## 6. LLM 비용 전략

- arXiv는 저자 영문 초록을 무료 제공 → 요약 입력 텍스트 확보 0원.
- **MVP: Gemini Flash 무료 티어**로 한국어 요약. 하루 ~30건 × ~300토큰 = 하루 ~1만 토큰 수준 → 무료 티어 내.
- 대안: ① 초록 그대로 노출(완전 무료 베이스라인) ② Claude Haiku/Gemini Flash 유료(월 수백 원) ③ 로컬 오픈모델(Ollama+Qwen/Llama). 예산 생기면 교체 용이.

## 7. 개발 제약 & 범위 (Q10)

- **일정**: 1~2주 단기. 최소 기능(수집·요약·오늘의 브리핑 피드·상세 보기)만 먼저 완성.
- 구체적 구현(디자인 고도화, 검색 기능, 카테고리 분류 등)은 **향후 개발**로 미룸.

## 8. 향후 확장 항목 (기록 — MVP 제외)

- **정보 소스 추가**: 기술 뉴스/블로그(Hacker News, 기업 AI 블로그, 뉴스레터), 커뮤니티/SNS(Papers with Code, Hugging Face 트렌딩, X/Reddit), 제품 릴리스(GitHub Releases, 모델 카드).
- **선별·요약 고도화**: 중요도 랭킹(인용·화제성·키워드), 관심사 기반 필터링/추천, 카테고리 자동 분류·그룹핑.
- **기능**: 검색/키워드 필터, 북마크/저장(→ 로그인·백엔드·DB 필요), 개인화 피드.
- **UI/UX**: 디자인 고도화.

---

## 9. MVP 개발 로드맵 (1~2주 예상)

1. **수집 스크립트** — arXiv API(cs.CL/cs.AI/cs.LG)에서 최근 논문 fetch, LLM 키워드 선별.
2. **요약 스크립트** — Gemini Flash 무료 티어로 한국어 구조화 요약, 원문 초록 병기, JSON 저장.
3. **정적 프론트** — '오늘의 브리핑' 피드 + 논문 상세 페이지, JSON 렌더.
4. **자동화** — GitHub Actions cron(매일) + GitHub Pages 배포.
5. **주간 요약** — 주 1회 집계 페이지(여유 시).

## 10. 검증 방법

- **수집·요약 파이프라인**: 스크립트를 로컬에서 1회 수동 실행 → 생성된 JSON에 논문 메타·한국어 요약·원문 초록이 올바르게 담기는지 확인.
- **프론트**: 정적 빌드를 로컬에서 서빙(예: `python -m http.server`)해 오늘의 브리핑 피드·상세 보기 동작 확인.
- **자동화**: GitHub Actions 워크플로를 수동 트리거(workflow_dispatch)해 cron 파이프라인이 끝까지 돌고 Pages에 반영되는지 확인.
