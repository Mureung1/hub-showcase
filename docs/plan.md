## 1. 프로젝트 개요

### 프로젝트명

**StockMate Agent**

### 한 줄 소개

소규모 스마트스토어 셀러의 판매 데이터를 분석해 상품별 재고 소진 시점을 예측하고, 오늘 발주하거나 확인해야 할 상품을 알려주는 재고관리 에이전트입니다.

### MVP 목표

4주 안에 더미 판매 데이터 또는 CSV 데이터를 기반으로 작동하는 재고관리 에이전트 MVP를 만듭니다.

이 MVP는 네이버 커머스 API를 직접 연동하지 않습니다. 대신 가상의 스마트스토어 데이터를 사용해 다음 기능을 검증합니다.

- 재고 소진 예측
- 발주 필요 판단
- 과잉재고 판단
- 오늘의 재고 브리핑 생성

### MVP에서 API 연동을 제외하는 이유

개인 프로젝트 단계에서 네이버 커머스 API를 바로 연동하는 것은 승인, 권한, 실제 셀러 데이터 확보 문제가 있습니다.

따라서 초기 MVP에서는 API 연동보다 핵심 가치인 **판매 데이터 기반 재고 판단**을 먼저 검증합니다.

## 2. 문제 정의

### 문제 정의 한 문장

**소규모 스마트스토어 셀러가 여러 상품의 판매량과 재고를 매일 직접 확인하지 못하는 상황에서, 어떤 상품이 곧 품절되거나 과잉재고가 되는지 제때 판단하지 못하는 불편을 겪는다.**

### 핵심 문제

소규모 셀러는 재고관리 시스템 없이 스마트스토어 관리자 화면, 엑셀, 감에 의존해 재고를 관리하는 경우가 많습니다.

이 때문에 다음 문제가 반복됩니다.

- 잘 팔리는 상품이 갑자기 품절됩니다.
- 잘 안 팔리는 상품을 많이 발주해 재고가 쌓입니다.
- 상품 수가 많아질수록 매일 모든 재고를 확인하기 어렵습니다.
- 재고표를 봐도 오늘 무엇을 먼저 확인해야 하는지 판단하기 어렵습니다.

### 왜 단순 재고표만으로는 부족한가

셀러에게 중요한 것은 단순히 “현재 재고가 몇 개인가”가 아닙니다.

진짜 필요한 판단은 다음입니다.

- 현재 판매 속도 기준으로 며칠 뒤 품절될까?
- 공급 리드타임을 고려하면 지금 발주해야 할까?
- 오늘 가장 먼저 확인해야 할 상품은 무엇일까?
- 재고가 너무 오래 쌓인 상품은 무엇일까?

StockMate Agent는 이 판단을 자동으로 도와주는 것을 목표로 합니다.

## 3. 타겟 사용자

### 대표 페르소나

**박지현, 34세**  
네이버 스마트스토어에서 홈카페 편집숍 **“모닝루틴”**을 운영하는 1인 셀러

### 운영 상황

- 본업이 있고, 스마트스토어는 부업으로 운영합니다.
- 원두, 드립백, 티백, 커피용품, 머그컵, 텀블러 등 약 40개 상품을 판매합니다.
- 상품 등록, 주문 확인, CS, 발주 관리를 혼자 처리합니다.
- 매일 모든 상품의 판매량과 재고를 꼼꼼히 확인할 시간이 없습니다.

### 사용자의 불편

박지현은 재고 숫자 자체보다 다음 판단이 어렵습니다.

- 이 상품이 며칠 뒤 품절될지
- 지금 발주해야 하는지
- 어떤 상품을 먼저 확인해야 하는지
- 너무 많이 쌓인 상품은 무엇인지

따라서 단순 표나 그래프보다 **오늘 확인해야 할 상품과 그 이유를 알려주는 서비스**가 필요합니다.

## 4. 서비스 컨셉

### 서비스 정의

**StockMate Agent는 판매 데이터와 현재 재고를 바탕으로 상품별 소진 예상일을 계산하고, 오늘 사용자가 확인해야 할 상품을 우선순위로 브리핑해주는 재고관리 에이전트입니다.**

### 에이전트로 보이기 위한 구조

이 서비스는 단순 계산기가 아니라 다음 세 단계를 수행합니다.

| 단계 | 역할 | 설명 |
|---|---|---|
| 인지 | 데이터 확인 | 상품별 판매량, 현재 재고, 리드타임, 최근 판매 추세를 확인 |
| 판단 | 상태 분류 | 품절 위험, 발주 필요, 과잉재고 상품을 분류하고 우선순위 결정 |
| 제안 | 행동 추천 | 오늘 확인해야 할 상품과 추천 행동을 문장으로 안내 |

### 예시 브리핑

> 콜롬비아 원두 250g은 최근 7일 판매량이 평소보다 60% 증가했고, 현재 재고 기준 4일 뒤 품절이 예상됩니다. 공급 리드타임이 5일이므로 오늘 발주하지 않으면 품절 가능성이 높습니다. 추천 발주 수량은 30개입니다.

## 5. MVP 범위

### 포함 기능

| 기능 | 설명 |
|---|---|
| 더미 데이터 또는 CSV 데이터 불러오기 | API 없이도 데모와 테스트 가능 |
| 상품별 판매량, 현재 재고, 리드타임 분석 | 상품 상태 판단을 위한 기본 데이터 분석 |
| 상품별 재고 소진 예상일 계산 | 최근 판매량 기반으로 예상 소진일 계산 |
| 상품 상태 자동 분류 | 품절 위험, 발주 필요, 과잉재고 등으로 분류 |
| 오늘 확인해야 할 상품 브리핑 생성 | 우선순위가 높은 상품과 추천 행동 제공 |
| 간단한 대시보드 제공 | 전체 재고 상태를 한눈에 확인 |

### 제외 기능

| 기능 | 제외 이유 |
|---|---|
| 네이버 커머스 API 자동 연동 | 승인, 권한, 실제 셀러 데이터 확보 리스크 |
| 실제 카카오톡 또는 이메일 알림 발송 | MVP에서는 화면 내 브리핑으로 대체 |
| 자동 발주 | 사용자가 최종 발주 여부를 직접 결정 |
| 머신러닝 기반 수요 예측 | 4주 MVP에서는 설명 가능한 규칙 기반 예측으로 시작 |
| 신선식품 유통기한 관리 | 유통기한, 폐기 리스크는 별도 모델이 필요 |
| 사용자 계정/로그인 기능 | 개인 프로젝트 MVP에서는 핵심 기능 검증에 집중 |
| 결제 기능 | 서비스 검증 이후 고려 |

## 7. 더미 데이터 설계

### 데이터 목적

더미 데이터는 기능 테스트용이면서 동시에 데모용 데이터입니다.  
따라서 실제처럼 보이면서도 서비스의 필요성을 보여줄 수 있어야 합니다.

### 상품 수

약 **40개 SKU**를 사용합니다.

이 정도 규모는 소규모 셀러에게 현실적이고, 사람이 매일 직접 확인하기에는 번거로운 수준입니다.

### 데이터에 포함할 상품 상태

| 상태 | 설명 |
|---|---|
| 정상 재고 | 당장 조치가 필요 없는 상품 |
| 품절 위험 | 현재 재고가 적고 판매 속도가 빨라 곧 품절될 가능성이 높은 상품 |
| 발주 필요 | 아직 재고는 있지만 리드타임을 고려하면 지금 발주해야 하는 상품 |

| 판매 급증 | 최근 7일 판매량이 이전 평균보다 크게 증가한 상품 |
| 데이터 수집 중 | 판매 이력이 부족해 예측이 어려운 신상품 |

## 8. 예측 로직

MVP에서는 설명 가능한 규칙 기반 예측을 사용합니다.

### 최근 14일 일평균 판매량

```text
최근 14일 일평균 판매량 = 최근 14일 판매량 / 14
```

### 소진 예상일

```text
소진 예상일 = 현재 재고 / 최근 14일 일평균 판매량
```

### 발주 필요 판단

```text
발주 필요 기준 = 리드타임 + 안전마진
```

기본 안전마진은 2일로 설정합니다.

예를 들어 리드타임이 5일이고 안전마진이 2일이면, 소진 예상일이 7일 이하인 상품은 발주 필요 상품으로 분류합니다.

### 판매 급증 판단

최근 7일 평균 판매량과 최근 30일 평균 판매량을 비교합니다.

```text
판매 추세 비율 = 최근 7일 평균 판매량 / 최근 30일 평균 판매량
```

| 조건 | 상태 |
|---|---|
| 1.5 이상 | 판매 급증 |
| 0.5 이하 | 판매 둔화 |
| 그 외 | 일반 상태 |

### 과잉재고 판단

예시 기준은 다음과 같습니다.

- 최근 30일 판매량이 5개 이하
- 현재 재고가 50개 이상

두 조건을 만족하면 과잉재고 후보로 분류합니다.

### 데이터 수집 중 판단

판매 이력이 7일 미만인 상품은 정확한 예측이 어렵기 때문에 “데이터 수집 중”으로 표시합니다.

## 9. 핵심 기능 2개

### 핵심 기능 1. 재고 소진 예측 및 상태 분류

사용자가 불러온 판매 데이터를 기반으로 상품별 상태를 자동 분류합니다.

분류 상태는 다음과 같습니다.

- 품절 위험
- 발주 필요
- 정상
- 과잉재고
- 판매 급증
- 데이터 수집 중

이 기능은 “어떤 상품이 위험한지 모르겠다”는 핵심 문제를 직접 해결합니다.

### 핵심 기능 2. 오늘의 재고 브리핑 생성

전체 상품 중 오늘 확인해야 할 상품 3~5개를 우선순위로 골라 문장형 브리핑을 제공합니다.

브리핑에는 다음 정보가 포함됩니다.

- 상품명
- 현재 상태
- 왜 확인해야 하는지
- 예상 소진 시점
- 추천 행동
- 추천 발주 수량

이 기능은 서비스를 단순 재고표가 아니라 **재고 담당 에이전트**처럼 보이게 만드는 핵심 기능입니다.

## 10. 사용자 시나리오

박지현은 아침에 스마트스토어 주문을 확인하기 전 StockMate Agent에 접속합니다.

1. 사용자는 서비스에 접속합니다.
2. 사용자는 더미 데이터를 불러오거나 CSV 파일을 업로드합니다.
3. 서비스는 상품별 판매량, 현재 재고, 리드타임을 분석합니다.
4. 서비스는 각 상품의 소진 예상일과 상태를 계산합니다.
5. 사용자는 대시보드에서 품절 위험, 발주 필요, 과잉재고 상품을 확인합니다.
6. 사용자는 오늘의 재고 브리핑에서 우선 확인해야 할 상품과 추천 행동을 확인합니다.
7. 사용자는 브리핑을 바탕으로 실제 발주 여부를 직접 결정합니다.

```mermaid
    H --> I[오늘의 재고 브리핑 확인]
    I --> J[발주 여부 직접 결정]
```

## 12. 화면 구성

### 1. 홈 화면

역할: 서비스 시작 화면

포함 요소:

- 서비스명
- 한 줄 설명
- 더미 데이터로 시작하기 버튼
- CSV 업로드하기 버튼

### 2. 대시보드 화면

역할: 전체 재고 상태를 한눈에 확인하는 화면

포함 요소:

- 전체 상품 수
- 품절 위험 상품 수
- 발주 필요 상품 수
- 과잉재고 상품 수
- 상품 리스트
- 상태 필터

### 3. 오늘의 브리핑 화면

역할: 에이전트가 우선 확인해야 할 상품을 알려주는 화면

포함 요소:

- 오늘 확인할 상품 3~5개
- 상품별 판단 이유
- 예상 소진일
- 추천 발주 수량
- 추천 행동

### 4. 상품 상세 화면

역할: 특정 상품의 분석 결과를 자세히 보는 화면

포함 요소:

- 상품명
- 카테고리
- 현재 재고
- 최근 판매량
- 소진 예상일
- 리드타임
- 상태
- 추천 설명

## 15. MVP 성공 기준

이 MVP는 다음이 가능하면 성공으로 봅니다.

1. 사용자가 더미 데이터 또는 CSV 데이터를 불러올 수 있다.
2. 상품별 소진 예상일이 계산된다.
3. 상품 상태가 품절 위험, 발주 필요, 정상, 과잉재고 등으로 분류된다.
4. 오늘 확인해야 할 상품 3~5개가 브리핑으로 제공된다.
5. 각 브리핑에는 판단 이유와 추천 행동이 포함된다.
6. 사용자가 브리핑을 보고 실제 발주 여부를 결정할 수 있다.

## 16. 최종 요약

StockMate Agent는 소규모 스마트스토어 셀러가 상품 재고를 직접 하나씩 확인하지 않아도 되도록 돕는 재고관리 에이전트입니다.

MVP에서는 네이버 커머스 API 연동 없이 더미 데이터 또는 CSV 데이터를 사용합니다.

핵심 기능은 두 가지입니다.

1. **재고 소진 예측 및 상태 분류**
2. **오늘의 재고 브리핑 생성**

이 두 기능을 통해 사용자는 어떤 상품이 곧 품절될지, 어떤 상품을 지금 발주해야 할지, 어떤 상품이 과잉재고인지 빠르게 판단할 수 있습니다.
