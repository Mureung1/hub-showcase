```
[화면]   App.jsx → copilotData.js (mock)        ← 서버를 안 부름
```

미완성 항목(페르소나 미수정·규칙4 미수정·테스트 0)이 전부 **"한 번도 안 돌려봤다"** 에서 파생된다.

## 목표 ② 루프 — 위반이 나오면 고쳐서 다시 받는다

지금 검증기는 위반을 **모아서 반환만** 하고 끝난다. 되돌려주고 재생성시킨다.

```
생성 → 검증 → (위반 있으면) 위반 목록과 함께 재생성 → 통과 or 포기(최대 N회)
```

**끝났다는 증거**: 1차에서 위반이 났던 공고가 **2차에서 통과**하는 로그.

---

## 목표 ③ 측정 — 나아졌는지 숫자로 안다

지표를 정하고 **루프 전/후를 같은 자로** 잰다.

| 지표 | 무엇을 보나 |
|---|---|
| **위반 수** | 검증기가 잡은 개수 — 가장 직접적 |
| **근거 밀도** | repo/wiki 태그 수, aiBar 붙은 항목 수 — **조작 방지용 짝 지표** |
| 통과율 | 공고 N개 중 위반 0으로 끝난 비율 |
| 재생성 횟수 | 통과까지 몇 번 돌았나 = **비용** |
| **모델 간 분산** | 같은 입력·다른 모델의 fit 차이 (3주차 baseline: **26~70**) |

**끝났다는 증거**: 루프 전/후 비교표 1장.

---

## 순서 — 측정을 루프보다 먼저 정의한다

```
① 연결  →  ③ 지표 정의 + 루프 없는 baseline 측정  →  ② 루프  →  ③ 다시 측정
```

**왜**: 루프를 먼저 만들고 나중에 지표를 정하면 **루프가 잘한 것처럼 보이는 지표를 무의식적으로 고르게 된다.**
사후에 고른 지표는 항상 좋아 보인다 — 백테스트의 생존편향과 같은 구조.
→ **루프 없는 상태의 숫자를 먼저 확보해야 비교 대상이 생긴다.**
(3주차 모델 비교가 "느슨한 하네스 baseline"이라 절반은 이미 있음: `docs/모델 비교 — 갭분석 baseline.md`)

## 함정 — 지표는 조작될 수 있다

**"위반 수 0"은 쉽게 달성된다.** LLM이 `aiBar`를 아예 안 쓰면 규칙 2·3 위반이 통째로 사라진다.
숫자는 좋아지고 **내용은 빈약해진다.**

→ 그래서 **두 축**으로 본다: **위반 수(↓)** 와 **근거 밀도(유지되어야 함)**. 한쪽만 보면 속는다.

## 이게 검증하는 가설

> **"좋은 하네스면 작고 무료인 로컬 모델로도 구조화 출력이 나온다"**

- 3주차: 하네스 없이 → **fit 26~70 발산**
- 4주차: 하네스+루프 → **분산이 좁혀지나?**

좁혀지면 가치명제가 숫자로 증명된다. 그 다음이 **Ollama 로컬 모델 스왑** (진짜 검증).

## 알려진 블로커 (시작 전 확인됨)

**하네스 출력과 화면 입력의 `tags` 모양이 다르다.**

```js
// 하네스 (schema.js) — validate.js도 이 모양을 읽음
tags: [ { label: 'GitHub · besession0402', type: 'repo' } ]   // 객체

// 화면 (copilotData.js:71 — JOBS_RAW)
tags: [ ['GitHub · besession0402', 'repo'] ]                  // 배열
// copilotData.js:50 — enrichReq
tags: (r.tags || []).map(([label, type]) => tag(label, type)) // 배열 구조분해
```

객체를 배열로 구조분해하면 **터진다**(`object is not iterable`). 하네스 결과를 그대로 화면에 넣을 수 없다.

**대응 후보**

| | 방법 | 문제 |
|---|---|---|
| (a) 스키마를 화면에 맞춤 | `tags`를 배열의 배열로 | LLM에 key 이름 없는 배열을 요구 → **오류율↑**. validate.js도 수정 |
| (b) 화면을 스키마에 맞춤 | mock 7개 공고 전부 수정 | 곧 버릴 mock을 손보는 비용 |
| **(c) 어댑터 함수** ← 유력 | 경계에서 한 번 변환 (~15줄) | **양쪽 안 건드림** |

(c)의 근거: `store.js` 계층 분리가 DB 교체를 파일 하나로 만든 것과 같은 논리. **단, "mock은 곧 버려진다"는 가정에 의존** — mock을 계속 쓸 거면 (b)가 나을 수 있음.

**그 외 예상 위험**
- **구조 검증기 부재** — LLM이 `gapActions`를 빼먹으면 화면이 터진다. 어댑터에서 기본값 방어가 최소 대응.
- 화면이 쓰는 필드가 스키마에 없음 (`deadlineTag`·`source`·`isNew`) → 없으면 생략되게.
