# Co-Sync — 협업 및 모임 조율 에이전트

## 0. 서비스 한눈에

| 문제 | Co-Sync의 답 |
|---|---|
| 시간·장소 맞추는 데 매번 시간 낭비 | 겹치는 시간 자동 취합, 위치 기반 장소 후보 추천 |
| 역할 배분 근거 없이 대충 정해짐 | 성향 조사 기반 역할·업무 추천 |
| 진행 상황을 몰라 답답하지만 물어보기 애매함 | 역할 단위 진행 카드로 말 없이 확인 |
| 모임 후 피드백이 관계를 겨냥해 상처가 됨 | 과정 중심 질문만, 사람 평가는 최소화 |

한 줄 정의: **초대장을 보내는 순간부터 모임이 마무리될 때까지, 조율의 마찰을 줄여주는 에이전트.**

---

## 1. 화면 흐름 (User Flow)

```
Invite → Gather → Assign → Confirm → (진행 기간) → Bloom → Harvest
 SCR0    SCR1     SCR2     SCR3                    SCR4     SCR5
```

- **SCR0→1**: 초대장 발송 후, 참여자가 링크로 입장하면 자동 이동
- **SCR1→2**: 시간·장소가 확정되면 이동
- **SCR2→3**: 역할·업무가 확정되면 이동
- **SCR3→4**: 확정 안내 이후, 협업이 진행되는 동안 상시 열람 가능
- **SCR4→5**: 모임 종료 시점에 결산 화면으로 전환

로그인 없이 링크 하나로 전체 플로우 참여 가능.

## 2. 화면 목록 (IA)

| 코드 | 화면명 | 한 줄 역할 |
|---|---|---|
| SCR0 | 초대장 만들기 | 초대장 디자인·문구 설정 후 링크 발송 |
| SCR1 | 시간·장소 조율 | 가능 시간 취합, 장소 추천·투표 |
| SCR2 | 주제·역할 조율 | 성향 조사 → 주제 투표 → 역할·업무 추천 |
| SCR3 | 확정 안내 | 확정 내용 요약, 이미지로 저장 |
| SCR4 | 진행 상황 공유 | 역할별 업무를 스와이프 카드로 열람 |
| SCR5 | 결과 결산 | 과정 중심 피드백 수집 |

MVP 범위: SCR0–SCR3 우선 구현, SCR4–SCR5는 여유 시 확장.

## 3. 핵심 기능

### A. 근거 있는 시간·장소 조율
- 참여자 입력 시간대 자동 취합, 안 겹치면 대안 제시
- 위치 기반 중간지점 장소 후보 자동 추천
- 장소는 익명 투표로 결정

### B. 성향 기반 역할·업무 추천
- 역할 배분 전 짧은 성향 조사 선행
- 주제는 익명 투표로 선정 (동점 시 재투표)
- 역할별 세부 업무까지 에이전트가 추천, 팀원이 수정·확정

### C. 말 없이 확인하는 진행 상황
- 역할 단위 스와이프 카드 (사람 단위 아님)
- 완료 항목만 조용히 쌓임, 미완료·지연 강조 없음
- 예: "B가 안 함" 대신 "자료 조사 역할, 2/3 진행 중"

### D. 안전한 결과 결산
- 과정에 대한 질문만 다룸 (시간·장소·역할 배분의 적절성)
- 협업의 경우 행동 기반 기여도 문항 추가
- 4인 이상만 개별 결과 공개, 3인 이하는 팀 전체 지표만
- 극단적으로 치우친 응답은 자동 완충
- 사람 간 관계를 겨냥하는 질문(만족도, 재모임 의향 등)은 다루지 않음

## 4. 화면별 설계

**SCR0 · 초대장 만들기**
초대장 디자인 3종 중 선택 → 문구 입력 → 발송(우편함 애니메이션) → 로그인 없이 링크로 그룹 생성

**SCR1 · 시간·장소 조율**
주간 캘린더에서 가능 요일 선택 → 위치 기반 장소 후보 카드 노출 → 익명 투표로 확정

**SCR2 · 주제·역할 조율**
성향 조사 → 주제 익명 투표 → 역할 카드(담당자+추천 업무 목록) 생성 → 확정

**SCR3 · 확정 안내**
일시·장소·주제·역할을 엽서형 카드로 요약 → 이미지로 저장

**SCR4 · 진행 상황 공유**
역할별 카드 1장씩, 좌우 스와이프로 열람 → 체크리스트는 완료 항목만 강조

**SCR5 · 결과 결산**
과정 항목 3가지(시간/장소/역할배분)를 leaf 아이콘으로 평가 → 제출

---

## 5. 설계 원칙

1. **에이전트는 사람 간 감정·관계를 판단하지 않는다.** 추천은 장소·업무처럼 검증 가능한 대상에 한정.
2. **진행 상황 확인은 사람의 시야를 빌리는 것이지, 감시가 아니다.** 역할·업무 중심으로 표시해 특정 개인을 지목하지 않는다.
3. **민감한 피드백은 공개 경로 자체를 만들지 않는다.** 결산은 과정에 대한 질문만 팀에 공개.
4. **모든 확정은 사람이 내린다.** 에이전트는 후보를 제시할 뿐, 최종 결정은 투표·확정 버튼을 통해 사람이 완료.

## 6. 디자인 방향

- **무드**: 빈티지 · 코티지 · 모리걸 — 미니멀하고 자연스러운, 거부감 없는 톤
- **색상**: 그레이 베이지(종이) · 웨지우드 파스텔 블루 · 레몬 옐로 · 잉크 브라운(텍스트)
- **타이포**: 영문 라벨은 필기체(Dancing Script), 한글 제목은 부드러운 세리프(Gowun Batang), 본문은 Gowun Dodum
- **시그니처 요소**: 초대(씨앗)에서 결산(수확)까지 이어지는 정원 덩굴 모티프 — 화면 전환 자체가 여정처럼 읽히도록 설계

## 7. 최종 워크플로우 정리

0. **초대장 보내기**
초대장 디자인·문구 커스터마이징 → 로그인 없이 링크로 그룹 생성 → 우편함 발송 애니메이션
1. **시간 및 공간 조율**
가능 시간대·위치 입력 → 겹치는 시간 취합(안 겹치면 대안 제시) → 에이전트가 참여자 위치 기반 중간지점 장소 후보 추천 → 익명 투표로 장소 확정
2. **협업 주제 선정 및 역할 조율**
성향 조사 선행 → 주제 익명 투표(동점 시 재투표) → 역할 생성 → 에이전트가 역할별 구체적 업무 추천 → 팀원 수정·확정
3. **확정 안내**
시간·장소·주제·역할 확정 시 초대장 형태 안내문 자동 생성 → 저장 가능한 이미지로 변환
4. **진행 상황 공유 카드**
역할별 업무를 스와이프 카드로 표시 → 완료 항목만 조용히 쌓임, 미완료 강조 없음 → 역할·업무 중심 문구("자료 조사 역할, 2/3 진행 중")
5. **결과 결산 (구조적 피드백)**
과정에 대한 질문만 다룸(시간·장소·역할 배분의 적절성) → 협업의 경우 행동 기반 기여도 문항 추가(4인 이상만 개별 공개, 극단값 자동 완충) → 엽서형 카드로 결과 정리, 초대장 모티프와 시각적 일관성 유지
