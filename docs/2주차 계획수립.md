## Day 6 — FE 화면 디자인 구축 + 주요 기능 세밀 설계
- **디자인 일관성 점검**: `styles.css`의 톤다운 빈티지 디자인 토큰(색상·둥근모서리·그림자)이 17개 화면에 실제로 일관되게 적용됐는지 전수 점검, 어긋난 곳 통일
- **허술하게 설계된 기능 세밀화**:
  - 일주일 식단 루틴 — 지금은 냉장고 재고·난이도 반영 없이 단순 순환 배정(`buildWeeklyPlan`)인데, 실제 화면 흐름과 알고리즘을 다시 설계
  - 조리모드 addon 스텝 삽입 UX — 체크박스로 재료 추가할 때 스텝이 자연스럽게 끼워지는지 재검토
  - 재료 직접 추가 폼의 단위 선택 UX — 지금 하드코딩된 단위 칩을 재료별로 다르게 보여줄지 결정
- **반응형 점검**: phone frame이 390px 고정인데, 실제 모바일 브라우저 뷰포트에서 깨지는 곳 없는지 확인
- **Supabase DB 마이그레이션 진행 (진행 완료)**:
  - [x] 1. **Supabase 연동 환경 설정** (`@supabase/supabase-js`, `dotenv` 설치 및 `.env`, `supabaseClient.js` 셋팅)
  - [x] 2. **DB 테이블 생성 (SQL)** (DDL 쿼리문 작성 및 잘못된 초기 데이터 수정 완료)
  - [x] 3. **`store.js` 비동기화 및 쿼리 연동** (인메모리 로직을 DB 쿼리로 교체)
  - [x] 4. **컨트롤러 비동기(async/await) 수정**
  - [x] 5. **테스트 및 검증 (완료)**
    - Vite 서버 프록시 설정 및 `httpClient.js` URL 변경으로 스마트폰 등 로컬 네트워크 접속 테스트 완료

## Day 7 — BE 수정 및 FE와의 상호작용 테스트
- 1주차에서 새로 연결된 FE 기능(재고 수정, 재료 매칭)에 맞춰 필요한 BE 쪽 조정 (응답 모양 재확인, 향후 `GET /api/ingredients` 준비)
- 지난 코드 리뷰에서 나온 BE 잔여 이슈 마무리 점검
- **FE-BE 통합 상호작용 테스트**: 브라우저 Network 탭으로 화면별 실제 요청/응답 재검증
- **에러 케이스 테스트**: 백엔드가 400/404/500을 낼 때 1주차에서 만든 FE 에러 처리가 실제로 사용자에게 잘 보이는지 확인

## Day 8 — DB 구축과 각종 API 연동
- Supabase(또는 로컬 Postgres) 세팅, `docs/api-design.md` §5 스키마를 실제 마이그레이션으로 작성
- `backend/src/store.js`의 냉장고 CRUD 함수를 실제 DB 쿼리로 전환 (컨트롤러·라우트는 그대로)
- 외부 API 연동 준비: 영수증 OCR(Naver Clova 등), 식자재 가격 API — 연동 지점 확보와 인증키 세팅까지, 실제 데이터 채우기는 Day 9로 넘김

## Day 9 — 웹페이지 기능에 필요한 각종 데이터 수집
- 레시피 데이터 확충 (현재 10개뿐 — 실제 서비스 수준으로 늘리기)
- 재료 마스터 데이터 정확도 보강 (`avgShelfLifeDays` 등 실제 보관기간 자료 조사)
- 식자재 가격 — 실제 마트 시세 조사해서 하드코딩된 가짜 숫자 교체 (또는 Day 8에서 준비한 API로 실시간 연동)
- 영수증 OCR 테스트용 실제 영수증 샘플 수집
- 위 데이터들을 Day 8에서 만든 DB에 시드로 반영

## Day 10 — 전체 통합 테스트 + 배포 준비 + 마무리
- **End-to-End 재검증**: 실제 DB + Day 9에서 채운 실데이터로 냉장고 CRUD → 영수증 인식~확정 → 레시피 필터~조리~차감 → 장보기 → 식단루틴까지 전체 플로우를 처음부터 끝까지 재확인
- **안정성 최종 점검**: 여러 화면을 빠르게 넘나들면서 1·2주차에서 고친 레이스 컨디션·에러 처리가 실제 데이터/실제 API 환경에서도 재발 안 하는지 확인
- **배포 준비**: 환경변수(`.env`, DB 접속정보·API 키) 정리, `frontend`에서 `npm run build` 후 `backend`가 정적 파일을 정상 서빙하는지 확인
- **저장소 동기화**: `fridge-recipe-app`(작업 폴더)에서 2주차 동안 진행된 내용을 커밋 규칙대로 정리해서 실제 GitHub 저장소(`hub`)에 반영
- **문서 마무리**: `docs/backlog.md` 최종 갱신(완료 항목 정리, 남은 것 재우선순위), `CLAUDE.md`에 DB/실데이터 관련 아키텍처 설명 추가
