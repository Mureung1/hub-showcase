# 제품 6축 점검표

> 기준일: 2026-07-11. 현재 저장소·테스트·문서와 소스 기반 내부 진단이며, 외부 사용자 검증 결과가 아니다. 구현 완료의 단일 기준은 `docs/CHECKLIST.md`다.

## 종합 판단

답냥이의 가장 강한 가치는 **꺼내기 어려운 말을 처음부터 설명하게 하지 않고, 관계·상황을 몇 번 선택해 비교 가능한 보낼 말까지 빠르게 연결하는 것**이다. 카드와 AI를 사용자의 선택으로 나눈 하이브리드 구조도 설명 가능하고 타당하다.

현재 단계는 “설계와 목 기반 흐름이 탄탄한 프로토타입”이다. 실제 사용자 효과, 시드·템플릿 전수 검수, 운영 AI, 배포, 원격 CI, 계측, 재사용은 아직 증명되지 않았다. 포트폴리오에서는 구현·설계·검증 대기를 분리해 말해야 한다.

## 축별 피드백과 반영 원칙

### 1. 서비스 가치

강점은 “AI가 문장을 써준다”가 아니라 **입력 부담을 줄이고 관계 리스크가 다른 세 표현을 비교하게 한다**는 점이다. 일반 챗봇과의 차이는 모델 자체가 아니라 대학생 관계 taxonomy, 카드 즉시 경로, 톤 비교, 전송 가능성 검수 절차다.

현재 “효과가 검증된 예시”는 사실이 아니다. 팀 초안과 검수 기준은 있지만 제3자 블라인드 검수(T16), 템플릿 72개 전수 검수(T25), 실제 효과 피드백은 미완료다. 출시 전에는 “검수 기준을 가진 예시”로만 표현한다.

### 2. 지속 사용 가능성

답냥이는 매일 여는 습관형 서비스보다 **필요할 때 다시 찾는 사건 발생형 도구**가 현실적이다. 로그인·히스토리·알림·즐겨찾기를 억지로 추가하지 않는다. 단일 세션 복원은 과업 연속성이지 재방문 근거가 아니다.

지속 사용 가설은 외부 파일럿 참여자가 1~2주 동안 서로 다른 실제 메시지 상황에서 자발적으로 다시 사용하는지로 확인한다. 원문이나 영구 사용자 ID를 수집하지 않고, 인터뷰·사용 일지로 이유와 상황 범주만 기록한다.

### 3. AI 활용방식

하이브리드 라우팅은 유지한다. 다만 최고급 모델을 먼저 고정하지 않고, 시드와 겹치지 않는 holdout으로 Haiku 4.5부터 평가해 품질 기준을 통과하는 가장 빠르고 저렴한 모델을 채택한다. 미달 시 상위 모델로 올린다.

Structured Outputs는 형식 오류를 크게 줄이지만 refusal·토큰 절단·provider 오류까지 없애지 않는다. `stop_reason`, 런타임 재검증, 오류 매핑을 유지한다. XML 데이터 블록도 프롬프트 주입 완화책이지 보안 경계로 표현하지 않는다.

서비스 서버·분석·DB에 원문을 저장하지 않는 것과 외부 AI provider가 요청을 처리·보존하는 것은 별개다. 실 AI 전환 전에 전송 대상과 당시 provider 보존 조건을 사용자에게 고지한다. ZDR은 실제 조직 설정·계약이 확인된 경우에만 주장한다.

### 4. 사용자 경험

카드 경로와 AI 경로의 기대를 정확히 맞춘다. 답장 카드가 받은 원문을 읽지 않는다는 점을 S0/S2에서 짧게 안내하고, 템플릿 결과의 버튼은 “내 상황에 더 맞추기”, AI 결과는 “다시 만들기”로 분리한다.

모바일 공개 전에는 내부 용어 S0~S3를 사용자 화면에서 제거하고, 단계 전환 초점·스크롤, `aria-pressed`, 목적 legend, 44px 이상 터치 영역, WCAG AA 대비, reduced motion, 키보드·safe area를 검증한다. 후보 카드는 같은 표면색으로 두고 톤 배지만 달리해 세 안의 시각적 무게를 같게 한다.

### 5. 기술적 완성도

현재 강점은 계약과 실패 케이스를 먼저 만든 것이다. 다음 위험은 프론트 빌드가 향후 `api/` 서버 함수 타입을 검사하지 않는다는 점, 클라이언트 20초 타임아웃이 provider 호출을 실제 취소하지 않는다는 점, 원격 CI가 없다는 점이다.

T18~T23에서 API 전용 타입검사·핸들러 테스트, 서버 `AbortController`, 출력 토큰 상한, 제한된 재시도, Node 버전 고정, 클라이언트+API CI와 프리뷰 검증을 완료한다.

### 6. 포트폴리오 가치

현재 말할 수 있는 것:

- S0~S3 흐름, 카드 초안 72문구 연결, 목 AI 경로, 입력 복원·삭제, 복사 폴백을 구현했다.
- 생성 요청·응답 계약과 런타임 검증, 실패·429·타임아웃 테스트, 관계별 평가 케이스의 골격을 만들었다.
- 카드와 AI의 역할, 프록시·프롬프트·품질 게이트를 설계했다.

아직 말하면 안 되는 것:

- 실제 AI를 연결·운영했다.
- 시드·템플릿이나 메시지 효과가 사용자에게 검증됐다.
- 재방문율·첫 복사 상호작용률이 확인됐다.
- CI·Vercel 배포·실기기 검증이 완료됐다.

포트폴리오 핵심 문장은 “AI를 많이 쓴 서비스”보다 **정형 상황은 결정적 자산으로, 복합 상황만 생성형 AI로 보내고 같은 계약과 평가 기준으로 품질을 관리한 제품**에 둔다.

## 외부 파일럿 기준

T22에서 대학생 5명 이상이 각자 실제에 가까운 카드 경로와 직접입력 경로를 수행한다. 아래 수치는 첫 파일럿의 잠정 합격선이며, 결과와 함께 재조정한다.

| 항목 | 잠정 기준 | 의미 |
| --- | --- | --- |
| 무도움 핵심 과업 완료 | 5명 중 4명 이상이 후보 1개를 복사 | 흐름 이해 가능성 |
| 카드 경로 시간 | S0부터 결과까지 중앙값 20초 이내 | 입력 비용 최소화 가치 |
| 직접입력 경로 시간 | S0부터 복사까지 중앙값 60초 이내 | 일반 챗봇 대비 과업 부담 |
| 전송 가능성 | 기존 SPEC 기준 80% 이상 | 실제 사용 가치 |
| 개인정보 이해 | 5명 중 4명 이상이 탭 보관·provider 전송 차이를 설명 | 신뢰와 동의 |
| 재사용 가설 | 1~2주 내 다른 실제 상황에서 자발적 재사용 여부 기록 | 사건 발생형 지속 사용 가능성 |

앞의 다섯 항목은 T22의 MVP 출시 전 파일럿 기준이다. 마지막 재사용 가설은 같은 참여자에게 동의를 받아 이어가는 **출시 게이트 밖 후속 관찰**이며, T22 완료나 MVP 출시를 1~2주 지연시키는 조건이 아니다.

복사는 실제 전송이나 효과의 증명이 아니라 **복사 상호작용 프록시**다. 동일 결과 세트에서 첫 성공 복사만 1회 집계해야 비율이 100%를 넘지 않는다.

## 출시 전 우선순위

1. T16·T25: 시드와 템플릿의 관계 호칭·사실 충실성·완결성·톤 전수 검수
2. T10·T12·T14: 복사 피드백, source별 복구, 모바일·접근성·기대 문구 정합
3. T17·T18: 실행 환경·CI/프리뷰와 서버 취소·타입검사·provider 보존 고지
4. T19~T21: holdout 평가, 모델 비교, 실 AI 품질 합격
5. T22·T23: 외부 파일럿, 키보드/스크린리더, 실기기·카톡 인앱 검증
6. T24: 현재 Vercel 플랜에서 custom events 지원 여부 확인 후 조건부 계측

## 재점검 시점

- T25 완료 후: 서비스 가치·콘텐츠 신뢰 재평가
- T21 완료 후: AI 활용·비용·품질 재평가
- T22~T23 완료 후: UX·기술 완성도·포트폴리오 점수 갱신
- 실제 1~2주 파일럿 후: 지속 사용 가설만 별도 갱신
