# 제품 6축 점검표

> 기준일: 2026-07-12. 현재 저장소·테스트·문서·집중 문헌 검토 기반 내부 진단이며, 외부 사용자 검증 결과가 아니다. 구현 완료의 단일 기준은 `docs/CHECKLIST.md`다.

## 종합 판단

답냥이의 가장 강한 가치는 **꺼내기 어려운 말을 처음부터 설명하게 하지 않고, 관계·상황을 몇 번 선택해 비교 가능한 보낼 말까지 빠르게 연결하는 것**이다. 카드와 AI를 사용자의 선택으로 나눈 하이브리드 구조도 설명 가능하고 타당하다.

현재 단계는 “설계와 목 기반 흐름이 탄탄한 프로토타입”이다. 실제 사용자 효과, 시드·템플릿 전수 검수, 운영 AI, 배포, 원격 CI, 계측, 재사용은 아직 증명되지 않았다. 포트폴리오에서는 구현·설계·검증 대기를 분리해 말해야 한다.

[문헌 기반 제품·검수 근거](RESEARCH_REVIEW.md)는 AI가 제한된 글쓰기에서 시간·평균 품질을 높일 가능성과 동시에 agency·진정성·동질화 위험을 보인다는 간접 근거를 추가했다. 이는 아래 점수를 올리는 사용자 증거가 아니라, 무엇을 검수하고 과장하지 않을지 명확히 한 설계 근거다.

## 현재 점수

점수는 5점 만점 내부 진단이다. 3점은 핵심 근거가 있으나 출시 차단 항목이 남은 상태, 5점은 사용자·운영 증거까지 확보한 상태를 뜻한다.

| 평가축 | 현재 | 강한 근거 | 가장 큰 공백 | MVP 출시 게이트 |
| --- | ---: | --- | --- | --- |
| 서비스 가치 | 4.0 | 대학생 관계 맥락, 카드 3탭 경로, 톤 3안 비교라는 명확한 과업 | 실제로 고민 시간과 수정량을 줄였다는 사용자 근거 없음 | 외부 파일럿에서 무도움 과업 완료·전송 가능성 확인 |

## 축별 피드백과 반영 원칙

### 1. 서비스 가치

강점은 “AI가 문장을 써준다”가 아니라 **입력 부담을 줄이고 관계 리스크가 다른 세 표현을 비교하게 한다**는 점이다. 일반 챗봇과의 차이는 모델 자체가 아니라 대학생 관계 taxonomy, 카드 즉시 경로, 톤 비교, 전송 가능성 검수 절차다.

현재 “효과가 검증된 예시”는 사실이 아니다. 팀 초안과 검수 기준은 있지만 제3자 블라인드 검수(T16), 템플릿 288개 전수 검수(T25), 실제 효과 피드백은 미완료다. 출시 전에는 “검수 기준을 가진 예시”로만 표현한다.

### 2. 지속 사용 가능성

답냥이는 매일 여는 습관형 서비스보다 **필요할 때 다시 찾는 사건 발생형 도구**가 현실적이다. 로그인·히스토리·알림·즐겨찾기를 억지로 추가하지 않는다. 단일 세션 복원은 과업 연속성이지 재방문 근거가 아니다.

지속 사용 가설은 동의한 외부 파일럿 참여자가 1~2주 동안 서로 다른 실제 메시지 상황에서 자발적으로 다시 사용하는지로 확인한다. 원문이나 영구 사용자 ID를 수집하지 않고, 간단 사용 일지·짧은 체크인으로 이유와 상황 범주만 기록한다. 긴 인터뷰는 필수가 아니다.

### 3. AI 활용방식

하이브리드 라우팅은 유지한다. 다만 최고급 모델을 먼저 고정하지 않고, 시드와 겹치지 않는 holdout으로 Haiku 4.5부터 평가해 품질 기준을 통과하는 가장 빠르고 저렴한 모델을 채택한다. 미달 시 상위 모델로 올린다.

문헌상 추천 문구는 감정 방향·상대 인상·작성자 ownership을 바꿀 수 있다. T21에서는 한국어 맥락 평가자 2명의 블라인드 채점을 기준으로 삼고, LLM-as-judge는 입력 없는 사실·필수 요소·형식처럼 관찰 가능한 항목의 보조 분석에만 쓴다.

Structured Outputs는 형식 오류를 크게 줄이지만 refusal·토큰 절단·provider 오류까지 없애지 않는다. `stop_reason`, 런타임 재검증, 오류 매핑을 유지한다. XML 데이터 블록도 프롬프트 주입 완화책이지 보안 경계로 표현하지 않는다.

서비스 서버·분석·DB에 원문을 저장하지 않는 것과 외부 AI provider가 요청을 처리·보존하는 것은 별개다. 실 AI 전환 전에 전송 대상과 당시 provider 보존 조건을 사용자에게 고지한다. ZDR은 실제 조직 설정·계약이 확인된 경우에만 주장한다.

### 4. 사용자 경험

카드 경로와 AI 경로의 기대를 정확히 맞춘다. 답장 카드가 받은 원문을 읽지 않는다는 점을 S0/S2에서 짧게 안내하고, 템플릿 결과의 버튼은 “내 상황에 더 맞추기”, AI 결과는 “다시 만들기”로 분리한다.

세 후보는 agency의 출발점이지 소유감의 증거가 아니다. T22에서는 복사·속도와 함께 후수정량과 5점 척도 “이 문구는 내가 실제로 할 말 같다”를 탐색값으로 기록한다. 첫 결과를 본 뒤 이 항목의 합격선을 소급해 만들지 않는다.

T14에서 내부 용어 S0~S3 비노출, 단계 전환 초점·스크롤, `aria-pressed`, 목적 legend, 44px 이상 터치 영역, WCAG AA 대비, reduced motion, 키보드·safe area를 검증했다. 후보 카드는 같은 표면색으로 두고 톤 배지만 달리해 세 안의 시각적 무게를 같게 한다. 이후 추가된 가이드형 UI는 T28에서 검증했고, 실제 모바일 가상 키보드·카카오톡 인앱 복사와 Three.js 캐릭터는 T23·T29·T31의 별도 실기기 게이트를 따른다.

### 5. 기술적 완성도

현재 강점은 계약과 실패 케이스를 먼저 만든 것이다. 다음 위험은 프론트 빌드가 향후 `api/` 서버 함수 타입을 검사하지 않는다는 점, 클라이언트 20초 타임아웃이 provider 호출을 실제 취소하지 않는다는 점, 원격 CI가 없다는 점이다.

T18~T23에서 API 전용 타입검사·핸들러 테스트, 서버 `AbortController`, 출력 토큰 상한, 제한된 재시도, Node 버전 고정, 클라이언트+API CI와 프리뷰 검증을 완료한다.

### 6. 포트폴리오 가치

현재 말할 수 있는 것:

- S0~S3 흐름, 카드 초안 288문구 연결, 목 AI 경로, 입력 복원·삭제, 복사 폴백을 구현 중이다.
- 생성 요청·응답 계약과 런타임 검증, 실패·429·타임아웃 테스트, 관계별 평가 케이스의 골격을 만들었다.
- 카드와 AI의 역할, 프록시·프롬프트·품질 게이트를 설계했다.

아직 말하면 안 되는 것:

- 실제 AI를 연결·운영했다.
- 시드·템플릿이나 메시지 효과가 사용자에게 검증됐다.
- 재방문율·첫 복사 상호작용률이 확인됐다.
- CI·Vercel 배포·실기기 검증이 완료됐다.

포트폴리오 핵심 문장은 “AI를 많이 쓴 서비스”보다 **정형 상황은 결정적 자산으로, 복합 상황만 생성형 AI로 보내고 같은 계약과 평가 기준으로 품질을 관리한 제품**에 둔다.

## 외부 파일럿 기준

T18 전에는 [경쟁가치 검증 절차](COMPETITIVE_VALIDATION.md)의 무참여자 모델 벤치마크로 원출력 품질·사실 충실성·입력량만 판정한다. T22에서는 평소 ChatGPT/Gemini와 유효 짝비교를 완료한 대학생 5명이 긴 인터뷰 없이 실제에 가까운 카드 경로와 직접입력 경로를 수행한다. 5명 미만이면 판정은 `Pending`이다. 가상 과업·교차 배정·블라인드 루브릭은 같은 절차를 따르며, 결과를 보기 전에 아래 잠정 합격선을 고정한다.

| 항목 | 잠정 기준 | 의미 |
| --- | --- | --- |
| 카드 무도움 완료 | 5명 중 4명 이상이 C1~C4 중 3개 이상에서 의도 카드를 찾아 최종 문구 확정 | 카드 발견·흐름 이해 가능성 |
| 실 AI 무도움 완료 | 5명 중 4명 이상이 배정된 A1~A4 한 과업을 답냥이 직접입력 경로로 확정 | long-tail 경로 사용성 |
| 카드 경로 내부 시간 | S0부터 결과까지 중앙값 20초 이내 | 인터페이스 진단 |
| 직접입력 경로 시간 | S0부터 최종 확정까지 중앙값 60초 이내 | 답냥이 AI 경로의 과업 부담 |
| 카드 전송 가능성 | 블라인드 합격 80% 이상이고 참여자별 비교도구 전체보다 -10%p 이내 | 속도로 품질을 희생하지 않음 |
| 실 AI 전송 가능성 | 최종문 블라인드 합격 4/5 이상 | 실제 사용 가치 |
| 경계·개인정보·관계 이해 | 카드 원문 경계, 탭 보관/provider 전송, 복합 관계 범위를 각각 4/5 이상 설명 | 기대 일치와 신뢰 |
| 카드 경쟁시간 | 답냥이가 더 빠른 참여자 3/5 이상이고, 참여자별 시간 비율 중앙값 30% 이상 단축 | 접근·로딩·후수정을 포함한 선택 이유 |
| 카드 다음 선택 | 5명 중 4명 이상, 이유가 속도·입력 부담·3안 비교·블라인드 품질·원문 비전송 중 하나 | 브랜드가 아닌 과업 가치 |
| 내가 실제로 할 말 같음 | 5점 응답의 원분포·중앙값 기록, 첫 파일럿은 hard gate 없음 | agency·ownership 탐색 신호 |
| 재사용 가설 | 1~2주 내 다른 실제 상황에서 자발적 재사용 여부 기록 | 사건 발생형 지속 사용 가능성 |

재사용 가설과 “내 말 같다” 탐색값을 제외한 항목은 T22의 MVP 출시 전 gate다. 재사용은 같은 참여자에게 동의를 받아 이어가는 **출시 gate 밖 후속 관찰**이며, T22 완료나 MVP 출시를 1~2주 지연시키는 조건이 아니다. 5명 비교는 “이 5명의 평소 사용 도구 대비” 탐색 결과일 뿐 ChatGPT·Gemini 개별 또는 시장 우월성의 확정 근거가 아니다.

복사는 실제 전송이나 효과의 증명이 아니라 **복사 상호작용 프록시**다. 동일 결과 세트에서 첫 성공 복사만 1회 집계해야 비율이 100%를 넘지 않는다.

## 출시 전 우선순위

1. RESEARCH_REVIEW 완료 → T25 대표 12문구 source preflight: 문헌의 관계·공손성 맥락과 기존 사실·완결성 계약을 출처별로 구분해 검수
2. 대표 12문구 통과 → 무참여자 모델 벤치마크: `Provisional Go` 전에는 T18 백엔드 투자 보류
3. T15→T16·T25 전체: 시드와 템플릿의 관계 호칭·사실 충실성·완결성·톤 전수 검수
4. T10·T12·T14·T17: 복사 피드백, source별 복구, 모바일·접근성·고정 프리뷰 정합
5. T18~T21: 서버 취소·타입검사·provider 고지, holdout 평가, 모델 비교, 실 AI 품질 합격
6. T22·T23: 긴 인터뷰 없는 짧은 외부 과업, 키보드/스크린리더, 실기기·카톡 인앱 검증
7. T24: 현재 Vercel 플랜에서 custom events 지원 여부 확인 후 조건부 계측

## 재점검 시점

- T25 완료 후: 서비스 가치·콘텐츠 신뢰 재평가
- T21 완료 후: AI 활용·비용·품질 재평가
- T22~T23 완료 후: UX·기술 완성도·포트폴리오 점수 갱신
- 실제 1~2주 파일럿 후: 지속 사용 가설만 별도 갱신
