# 로그인 전 온보딩 모션 설계

## 목적

로그인 전 서비스 온보딩은 사용자가 아맞다의 핵심 경험을 5초 안에 이해하도록 돕는다. 단순한 기능 설명만 보여주는 대신, 저장해둔 자료가 나중의 현재 상황과 다시 연결되는 장면을 짧은 애니메이션으로 보여준다.

이 화면은 실제 `꺼내보기` 체험이 아니다. 사용자는 CTA를 누른 뒤 로그인해야 홈과 `꺼내보기`에 접근할 수 있다.

## 확정 방향

- 기본 서사는 "저장물이 다시 연결되는 장면"이다.
- 한 줄의 현재 상황 문장을 함께 보여준다.
- 흩어진 저장 카드 2~3개가 현재 상황 문장 기준으로 작업팩처럼 모인다.
- CTA 문구는 `서비스 경험하기`를 우선 사용한다.
- 전체 흐름은 짧고 간결하게 유지하며, 긴 랜딩 페이지로 확장하지 않는다.

## 설계 인사이트

- 첫 화면의 시각 요소는 브랜드 장식이 아니라 서비스의 핵심 경험을 설명해야 한다.
- CTA는 애니메이션보다 우선한다. 사용자가 애니메이션을 끝까지 보지 않아도 로그인 화면으로 이동할 수 있어야 한다.
- 기능 설명은 모션 안에 많이 넣지 않는다. 모션은 `저장물`, `현재 상황 문장`, `작업팩`의 관계만 보여준다.
- 여러 소개 섹션을 만들더라도 모션은 첫 화면의 핵심 시그널로 유지한다. 섹션 이동 내비게이션이나 URL hash는 MVP에서 필수로 두지 않는다.
- 로그인 화면은 온보딩과 분리한다. 이 문서의 모션은 로그인 전 소개 화면에만 적용하고, 인증 버튼과 약관 안내는 로그인 화면에서 처리한다.

## 애니메이션 구조

1. 저장 카드가 흩어진 상태로 등장한다.
2. `팀 프로젝트 앱 첫 화면 참고` 같은 현재 상황 문장이 나타난다.
3. 카드들이 상황 문장 근처로 이동하며 묶인다.
4. 작업팩 카드가 나타나고 짧은 연결 단서를 보여준다.
5. CTA는 애니메이션 중에도 항상 접근 가능해야 한다.

## 라이브러리 경계

- GSAP은 로그인 전 서비스 온보딩 모션에만 사용한다.
- React 연동은 `@gsap/react`의 `useGSAP()`을 사용한다.
- 앱 내부 화면 전환, 버튼, 카드 hover, 결과 등장 같은 micro interaction은 Motion 또는 CSS transition을 우선한다.
- 같은 컴포넌트 안에서 GSAP과 Motion을 섞지 않는다.

## 접근성

- `prefers-reduced-motion: reduce`에서는 GSAP timeline을 생성하지 않는다.
- reduced motion 환경에서는 정적 작업팩 미리보기를 보여준다.
- 애니메이션 요소는 장식적이면 `aria-hidden`으로 처리하고, 핵심 설명은 텍스트로 별도 제공한다.
- CTA는 키보드로 접근 가능해야 하며, 애니메이션이 CTA 클릭을 방해하면 안 된다.

## 비목표

- 로그인 전 실제 검색 또는 실제 저장 데이터 조회를 제공하지 않는다.
- 관심 분야 선택이나 카테고리 생성은 로그인 후 개인화 온보딩에서만 다룬다.
- AI 자동화처럼 보이는 문구나 과장된 결과 연출을 쓰지 않는다.
- GSAP을 앱 전반의 기본 애니메이션 라이브러리로 확장하지 않는다.
