# 웹 레이아웃 리디자인 설계 (2026-07-24)

## 배경

현재 FE는 모바일 앱 형태다. 원인은 색이 아니라 골격이다.

- `styles/global.css:44` — `.page { max-width: 440px }` : 모든 페이지가 440px 단일 컬럼
- `App.jsx:38` — `BottomNav` 하단 탭바가 모든 폭에서 노출
- 상단 헤더(GNB)가 없어 로고·전역 메뉴·인증 상태를 놓을 자리가 없다
- 배경 오브(`Atmosphere`) + 글래스 카드 + `--radius-app: 30px` = 앱 프레임 인상

목표는 **데스크톱 웹사이트로 보이게 하는 것**이다. 기능 변경은 없다.

## 범위

**In**

- 디자인 토큰 교체(라이트/다크 양쪽)
- 레이아웃 셸 신설: `SiteHeader` + 2단 폭 컨테이너
- `BottomNav` · `Atmosphere` 제거
- 7개 페이지 전부 재배치: 홈 / 목록 / 상세 / 등록 / 수정 / 마이페이지 / 로그인 + 생년월일 게이트

**Out**

- 백엔드 일절 변경 없음 (BE 테스트 187개는 이 작업의 안전 근거가 되지 못한다 — "검증" 절 참고)
- API 요청/응답 형태 변경 없음
- 상태 관리·폼 제출·조회 로직 변경 없음. **이번 작업은 마크업과 CSS만 건드린다**
- 홈 화면의 콘텐츠 구성 변경 없음(히어로 검색바·카테고리 타일은 도입하지 않음)
- 신고(B4·H1), 인덱스(B5)는 이 작업 이후

## 핵심 설계 결정

1. **톤은 "웜 미니멀"** — 기존 오렌지(`#EA7A2B`)와 웜 계열을 유지하되 글래스·그라데이션·큰 그림자를 걷어낸다. 순백 뉴트럴(당근 그대로)과 잉크 컨트라스트 안도 검토했으나, 기존 정체성을 버리지 않으면서 앱 느낌만 제거하는 쪽을 택했다.
2. **경계는 그림자가 아니라 보더가 담당한다.** `--shadow-*`를 `none`으로 두고 1px `#EDE7DD`로 카드를 구분한다. 그림자는 카드 호버에서만 약하게 쓴다.
3. **폭은 페이지가 고른다.** `.page`는 세로 리듬(gap)만 담당하고 `max-width`를 갖지 않는다. 각 페이지가 `.container--wide`(1200px) / `.container--narrow`(720px)를 선택한다.
4. **모바일은 1열로 접히기만 한다.** 데스크톱 우선. `BottomNav`는 되살리지 않고 완전히 삭제한다.
5. **다크모드는 유지한다.** `data-theme` 블록과 `prefers-color-scheme` 블록 양쪽을 새 팔레트로 다시 칠한다.
6. **`Card`의 `variant` API는 유지한다.** `glass`/`solid`/`dark` 이름을 그대로 두고 렌더 결과만 바꾼다. 이름을 바꾸면 7개 페이지의 호출부를 전부 건드려야 하고, 그건 마크업 변경 범위를 불필요하게 넓힌다. `glass`와 `solid`는 같은 흰 카드로 수렴한다. `variant="dark"`는 현재 **11곳**에서 쓰이는데, 그중 **강조 배너 2곳만 남기고 9곳을 `solid`로 바꾼다.**

| 파일 | 행 | 처리 |
|---|---|---|
| `HomePage.jsx` | 70 | **유지** — "오늘의 번개" 배너 |
| `MyPage.jsx` | 64 | **유지** — 프로필 배너 |
| `MyPage.jsx` | 50 | → solid (비로그인 안내) |
| `MeetingDetailPage.jsx` | 241, 251, 365 | → solid (로그인 유도 / 모임장 관리 / 참여 신청) |
| `MeetingCreatePage.jsx` | 18 | → solid (비로그인 가드) |
| `MeetingEditPage.jsx` | 67, 79, 90, 104 | → solid (로그인·에러·로딩·권한 가드) |

**⚠️ 바꿀 때 안쪽의 어두운 배경용 색을 반드시 함께 교체한다** — `color: 'var(--cream-mute)'` → `'var(--ink-mute)'`, 신청자 목록의 `borderBottom: '1px solid rgba(255,255,255,0.1)'` → `'1px solid var(--line)'`. 안 바꾸면 흰 카드 위에 흰 글씨가 남는데 이건 lint도 build도 잡지 못한다.

## 레이아웃 셸

### `components/SiteHeader.jsx` (신규)

```
┌─────────────────────────────────────────────────────────────────┐
│ ⚡ 번개모임   모임 찾기  모임 등록      이상진 [신뢰도 50] │ 마이페이지  로그아웃 │
└─────────────────────────────────────────────────────────────────┘
```

- `position: sticky; top: 0`, 높이 `--header-h`(64px), 배경 `#FFFFFF`, 하단 1px `--surface-glass-border`
- 안쪽은 `--w-wide` 중앙 정렬
- **좌**: 브랜드 `⚡ 번개모임` → `/`. 로고 이미지 에셋이 없으므로 텍스트 + 이모지로 간다
- **중**: `NavLink`로 `모임 찾기`(`/meetings`) · `모임 등록`(`/meetings/new`). 활성 라우트에 오렌지 밑줄 2px
- **우**: `useAppState()`의 `authLoading` / `isLoggedIn` / `currentUser`로 분기
  - `authLoading` → 우측 영역 전체를 비운다. (비워두지 않으면 "로그인" → "이상진"으로 깜빡인다)
  - 비로그인 → `로그인` 알약 버튼(accent) → `/login`
  - 로그인 → `닉네임` + 신뢰도 배지 → **1px 세로 구분선**(`--surface-glass-border`, 높이 18px) → `마이페이지` · `로그아웃`
- 로그아웃은 context의 `logout()`을 직접 호출한다(`LoginPage`·`MyPage`가 쓰는 것과 동일)
- 신뢰도 배지는 기존 `TrustBadge`를 재사용하고 `currentUser.trustScore`를 그대로 넘긴다(`MyPage:70`과 동일). `TrustBadge`가 `score.toFixed(1)`을 직접 호출하지만 이 경로는 안전하다 — 서버 `userService.js`의 `normalizeUser`가 `trust_score`를 `Number()`로 변환해 내려주고, 비로그인 `GUEST_USER`도 `trustScore: 0`이다. **다만 새 쿼리로 사용자 정보를 가져오는 코드를 추가할 때는** pg가 `numeric`을 문자열로 준다는 점 때문에 정규화를 다시 확인해야 한다

### `PageHeader` 처리 (전 페이지 공통 규칙)

`PageHeader`는 **7개 파일에서 14번** 쓰이고 그중 **11번이 `back`을 켠다**(`MeetingCreatePage` 2, `MeetingDetailPage` 3, `MeetingEditPage` 5, `MyPage` 1). 상단에 사이트 헤더가 생기면 이 뒤로가기 버튼은 위치가 어색해진다.

규칙:

- **컴포넌트는 유지한다.** `title` / `eyebrow`는 페이지 제목(h1)으로 계속 쓴다 — 14곳을 고치는 것보다 안전하다
- **`back` prop과 그 렌더(`navigate(-1)` 버튼)를 제거한다.** 호출부 11곳에서 `back`을 지운다. 이동 수단은 사이트 헤더 nav와 브라우저 뒤로가기가 대신한다
- 상세 페이지 하단의 "← 목록으로" 버튼은 **유지한다** — 이건 뒤로가기가 아니라 `/meetings`로 가는 명시적 링크라 역할이 다르다

## 페이지별 배치

### 홈 (`HomePage`) — `--w-wide`

- 히어로 카드(현재 `Card variant="glass"`)는 전폭 유지, 안쪽 텍스트를 좌측 정렬로
- "오늘의 번개" 다크 카드는 유지 — `--surface-dark`가 남는 유일한 자리
- "최근 등록된 모임" 4건: 세로 스택 → **3열 그리드**
- 콘텐츠 구성은 그대로. 히어로 검색바·카테고리 타일은 도입하지 않는다

### 목록 (`MeetingListPage`) — `--w-wide`

```
┌────────┬──────────────────────────┐
│ 필터    │  23개의 모임 · 20개 표시 중 │
│ 사이드바 │  ┌────┐ ┌────┐ ┌────┐   │
│ (200px) │  └────┘ └────┘ └────┘   │
│ sticky  │  ┌────┐ ┌────┐ ┌────┐   │
└────────┴──────────────────────────┘
```

- 현재 필터 `Card` 하나를 좌측 사이드바로 이동(`position: sticky`, 폭 200px)
- 사이드바 내부 순서: 유형 `PillTabs` → 키워드 → 카테고리 → 시/도 → 시/군/구. 현재의 `.field-row--three` 가로 3분할은 세로 스택으로 바꾼다
- 결과 영역: 카운트 문구 + **3열 그리드**
- 로딩·에러·빈 상태 문구는 결과 영역 안에 그대로 유지
- **`total` vs `items.length` 구분을 반드시 보존한다** — 7/22 코드리뷰에서 잡힌 결함이고 명세서가 `total`을 쓰라고 명시한 부분이다

### 상세 (`MeetingDetailPage`) — `--w-wide`, 이 작업의 최대 위험 구간

```
┌──────────────────────────┬──────────────┐
│ 본문 (1fr)                │ 액션 (260px) │
│  제목·배지·호스트·메타·설명 │  sticky      │
│  신청자 목록(소모임 호스트) │              │
└──────────────────────────┴──────────────┘
```

- **좌**: 제목/상태 배지/호스트+`TrustBadge`/"내가 만든 모임"/일시·장소·인원/성인전용/설명 + 신청자 목록
- **우 sticky**: 인원 요약(확정/정원 + 진행바) + 역할별 액션 전부
- 신청자 목록은 길이가 가변이라 우측이 아니라 **본문 아래**에 둔다
- 현재 액션 카드들이 쓰는 `Card variant="dark"`는 우측 패널에서 흰 카드로 바뀐다. `variant` 자체는 삭제하지 않는다
- `PageHeader`의 `back` 제거는 위 "`PageHeader` 처리" 공통 규칙을 따른다. 하단 "← 목록으로"는 유지

`isEnded`는 `utils/status.js`의 `isMeetingEnded(meeting)`를 그대로 쓴다(Day5에서 단일화한 헬퍼). 재구현하지 않는다.

### 등록·수정 (`MeetingCreatePage` / `MeetingEditPage` / `MeetingForm`) — `--w-narrow`

- 720px 중앙 정렬. 폼 필드는 1열 유지
- `MeetingForm`은 등록·수정이 공유하므로 **한 번만 고치면 양쪽에 반영된다**
- `MeetingEditPage`의 `splitKst` 프리필 로직은 건드리지 않는다 — Day5에서 잡은 타임존 함정 자리다

### 마이페이지 (`MyPage`) — `--w-wide`

- "내가 만든 모임"과 "신청한 모임"을 **세로로 쌓고, 각 섹션 안의 모임 카드를 2열 그리드**로 놓는다. 좌우 2단으로 나누지 않는다 — 두 목록의 길이가 크게 달라서(한쪽이 0건인 경우가 흔하다) 좌우로 놓으면 한쪽이 텅 빈다
- `Promise.all` 조회 로직은 그대로. 한쪽 실패 시 양쪽이 숨는 기존 동작도 이번 범위 밖이다(Day4 백로그)

### 로그인 (`LoginPage`) · 생년월일 게이트 (`BirthDateGate`) — `--w-narrow`

- 화면 중앙 카드. 헤더 아래 여백을 크게 잡는다

## 반응형

브레이크포인트 하나만 쓴다.

```
@media (max-width: 900px)
  - 목록: 필터 사이드바 → 결과 위 가로 블록, 그리드 3열 → 1열
  - 상세: 2단 → 1단 (우측 패널이 본문 아래로, sticky 해제)
  - 홈·마이페이지: 그리드 1열
  - 헤더: 가운데 nav 링크 숨김, 브랜드 + 우측만
```

## 검증

**FE에는 자동화 테스트가 없다.** `npm run lint` + `npm run build`는 문법 오류만 잡고 "버튼이 사라졌다"는 잡지 못한다. BE 187개는 이 작업에서 한 줄도 안 건드리므로 통과하는 게 당연하고, **안전의 근거가 되지 못한다.**

따라서:

1. 단계마다 브라우저로 직접 본다: 셸 → 목록·상세 → 폼·마이페이지
2. 상세 페이지는 위 16개 분기표를 **하나씩 대조**한다
3. lint 기준선: `AppStateContext.jsx` 경고 1건은 원래 있던 것이므로 그대로. **새 경고가 늘면 실패로 본다**
4. build는 클린해야 한다

### 검증용 데이터 준비 (선행 필요)

2026-07-24 실측 기준 개발 DB의 모임 4건은 전부 종료 또는 취소 상태이고 `meeting_participants`는 0건이다. **목록·상세·신청 화면을 볼 데이터가 없다.**

- 최소: flash 1건 + small 1건을 미래 일정으로 생성
- 신청자 관점(우측 패널의 "신청하기", 대기 상태, 오픈채팅 링크 노출, 거절 후 재신청 차단)은 **두 번째 계정이 필요하다**(자기 모임엔 신청 불가). 다른 구글 계정 + 시크릿 창, 또는 `provider_id LIKE 'seed-%'` 시드
- 이 준비는 기존 "브라우저 수동 검증" 미완 항목과 겹치므로 함께 처리한다
