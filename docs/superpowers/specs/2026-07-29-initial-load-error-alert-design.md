# 초기 로딩 실패 Alert 설계

## 목적

앱 초기화 중 익명 로그인 또는 최초 API 요청이 실패했을 때 일반 텍스트 대신 깸의 마스코트를 포함한 프로젝트 전용 오류 Alert를 표시한다.

## 범위

- `shared/ui/ErrorAlertModal/`에 재사용 가능한 중앙 모달 컴포넌트를 추가한다.
- 초기 앱 로딩 실패 상태에서만 새 모달을 사용한다.
- 기존 기능별 인라인 `ErrorState`는 변경하지 않는다.
- 브라우저 기본 `alert()`와 페이지 전체 새로고침은 사용하지 않는다.

## UI

- 화면 전체를 반투명 배경으로 덮고 중앙에 흰색 모달 카드를 표시한다.
- 카드에는 마스코트, 제목, 설명, `다시 시도` 버튼을 세로로 배치한다.
- 제목은 `잠시 문제가 생겼어요`로 표시한다.
- 설명은 `콘텐츠를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.`로 표시한다.
- 마스코트는 기존 `mascot-default&complete.png` 자산을 사용하며 장식 이미지로 처리한다.
- 배경 클릭과 `Esc`로는 닫히지 않는 차단형 모달로 동작한다.

## 상태와 재시도

1. 앱 시작 시 기존과 같이 로딩 화면을 표시한다.
2. 익명 로그인 또는 최초 API 요청이 실패하면 오류 모달을 표시한다.
3. `다시 시도`를 누르면 앱 상태를 `loading`으로 변경한다.
4. 페이지를 새로고침하지 않고 익명 로그인과 최초 API 요청을 다시 실행한다.
5. 성공하면 온보딩 또는 오늘 화면으로 이동하고, 다시 실패하면 오류 모달을 재표시한다.

## 접근성

- 모달 컨테이너에 `role="alertdialog"`와 `aria-modal="true"`를 적용한다.
- 제목과 설명을 각각 `aria-labelledby`, `aria-describedby`로 연결한다.
- 마스코트는 장식 목적이므로 빈 `alt`를 사용한다.
- 사용자가 실행할 수 있는 동작은 `다시 시도` 버튼 하나로 제한한다.

## 테스트

- `ErrorAlertModal`이 마스코트, 제목, 설명, 재시도 버튼을 렌더링하는지 검증한다.
- `다시 시도` 버튼이 전달받은 콜백을 호출하는지 검증한다.
- 앱 초기화 실패 시 텍스트 대신 오류 모달이 표시되는지 검증한다.
- 재시도 시 로딩 상태로 돌아가 익명 로그인과 최초 API 요청을 다시 수행하는지 검증한다.
- 재시도가 성공하면 정상 화면으로 전환되는지 검증한다.

## 제외 범위

- 기능별 인라인 오류 화면 통합
- 자동 재시도와 재시도 횟수 제한
- 오류 유형별 메시지 구분
- Preview 배포의 CORS 처리
