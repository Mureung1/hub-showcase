# 인사이트 마이그레이션과 원문 복원력 설계

## 문서 목적

이 문서는 기존에 Chrome 북마크, Notion, Pinterest, Instagram 등에서 인사이트를 저장해 온 사용자가 아맞다로 옮겨올 때 필요한 제품 원칙과 시스템 경계를 정의한다.

마이그레이션은 외부 서비스의 데이터를 완벽히 복제하는 기능이 아니다. 지원 형식에서 추출할 수 있는 링크 기반 인사이트를 안전하게 가져오고, 중복이나 일부 오류 때문에 정상 항목의 이관이 막히지 않게 하며, 결과를 투명하게 설명하고 되돌릴 수 있게 하는 기능이다.

이 문서는 현재 구현의 기준선이다. 실제 내보내기 파일을 이용한 TDD 과정에서 가정과 다른 구조가 발견되면 문서를 먼저 수정한다.

## 제품 원칙

### 인사이트는 URL 포인터보다 크고 원문 아카이브보다 작다

- URL은 인사이트의 원문 위치다.
- 아맞다가 보존하는 핵심 가치는 제목, 설명, 사용자 메모, 카테고리, 마지막으로 확인된 메타데이터를 포함한 인사이트 기록이다.
- 원문이 삭제되거나 로그인이 필요해도 인사이트 기록은 보관함과 `꺼내보기`에 남는다.
- 원문 본문, 원본 이미지, 전체 페이지 스냅샷은 저장하지 않는다.
- 링크가 없는 이미지나 텍스트를 독립 인사이트로 가져오는 기능은 이번 범위에 포함하지 않는다.

### 자동화하되 사용자 데이터를 추측하거나 덮어쓰지 않는다

- 정상 항목 수가 늘어나도 사용자의 필수 결정 횟수는 늘어나지 않아야 한다.
- 제목, 게시물 설명, 캡션, 폴더명만 보고 사용자의 `저장 이유`를 추론하지 않는다.
- 기존 제목, 메모, 카테고리는 자동으로 덮어쓰지 않는다.
- 시스템이 결정할 수 없는 항목은 안전한 기본 정책을 적용하고 선택적 검토 대상으로 남긴다.

### 마이그레이션은 선택적 가속 기능이다

- 마이그레이션을 로그인이나 기본 온보딩의 필수 단계로 넣지 않는다.
- 사용자는 먼저 아맞다의 메인 화면을 볼 수 있어야 한다.
- 비어 있는 보관함에서 `첫 링크 저장`과 함께 `기존 저장물 가져오기`를 눈에 띄게 제공한다.
- 이후에도 보관함 메뉴나 설정에서 다시 접근할 수 있게 한다.

### 외부 서비스의 한계를 숨기지 않는다

- Chrome이나 Notion처럼 공식 내보내기가 있는 서비스는 전용 안내와 어댑터를 제공할 수 있다.
- Pinterest나 Instagram처럼 개인정보 아카이브의 구조와 URL 포함 여부가 불확실한 서비스는 완전 이관을 약속하지 않는다.
- 알 수 없는 서비스도 지원 텍스트 형식에서 URL을 찾을 수 있으면 최소 이관을 시도한다.
- 원문 접근 상태와 썸네일은 최선형 결과이며 지속적인 접근이나 표시를 보장하지 않는다.

### 자동 처리에는 되돌리기를 제공한다

- 한 번의 가져오기 실행을 하나의 작업 묶음으로 관리한다.
- 사용자는 해당 작업에서 생성되거나 자동 보충된 데이터를 작업 단위로 되돌릴 수 있다.
- 기존에 존재하던 인사이트와 가져오기 이후 사용자가 직접 수정한 데이터는 Undo가 훼손하지 않는다.

## 지원 범위

### 초기 지원 방향

- Chrome 북마크 HTML
- Notion CSV, Markdown, HTML 내보내기 구조
- CSV, HTML, JSON, Markdown, 일반 텍스트 기반의 범용 파일
- 지원 형식 안에서 URL 필드를 찾을 수 있는 알 수 없는 서비스의 최소 이관

실제 지원 형식은 익명화한 내보내기 샘플로 검증한 뒤 확정한다. 파일 형식이 목록에 있다는 이유만으로 모든 구조를 완벽히 해석한다고 약속하지 않는다.

### 제외 범위

- 외부 서비스 계정의 직접 OAuth 연결
- 외부 서비스 로그인 우회 또는 비공개 원문 수집
- 링크 없는 인사이트 생성
- 원문 본문, 원본 이미지, 스크린샷 저장
- AI를 이용한 저장 이유 추론
- AI를 이용한 유사 썸네일 생성
- 상세 원문 에러 문구와 재시도 UX
- 카테고리 일괄 연결 UI
- 대시보드

## 사용자 흐름

1. 사용자는 로그인과 기본 온보딩을 마치고 메인 화면에 진입한다.
2. 비어 있는 보관함이나 보관함 메뉴에서 `기존 저장물 가져오기`를 선택한다.
3. Chrome, Notion 등 알려진 서비스는 내보내기 안내를 제공하고 그 외에는 범용 파일 업로드를 제공한다.
4. 시스템은 파일을 분석하되 보관함 데이터는 변경하지 않는다.
5. 파일 구조를 해석할 수 없거나 URL 필드를 결정할 수 없으면 파일 단위 매핑 또는 재업로드를 한 번 요청한다.
6. 분석이 끝나면 신규, 중복, 자동 처리, 오류 개수와 기본 처리 정책을 요약한다. 원문 접근 상태의 세부 분류는 기본 요약에서 전면에 드러내지 않는다.
7. 사용자는 개별 항목을 검토하지 않고 한 번의 `가져오기` 동작으로 묶음을 반영한다.
8. 완료 후 결과 화면에서 예외 검토와 전체 작업 Undo를 선택적으로 제공한다.

예시 결과 문구는 다음 의미를 전달해야 한다.

> 신규 480개를 가져왔어요. 중복 31개는 기존 인사이트로 통합했고, 18개는 기본 정책으로 처리했어요. 형식 오류 3개는 제외했으며 원하면 검토할 수 있어요.

최종 문구와 상태 표현은 별도의 에러 UX 설계에서 확정한다.

## 시스템 구조

### 접근 방식

범용 파이프라인에 알려진 서비스용 선택적 어댑터를 결합한다.

`파일 입력 → 형식 파싱 → 선택적 서비스 어댑터 → 임시 표준 항목 → 분석 계획 → 묶음 반영 → 결과 및 Undo`

알려진 서비스 어댑터는 파일의 의미를 해석하는 역할만 한다. URL 정규화, 중복, 메모 충돌, 오류, 반영, Undo 정책은 모든 서비스가 동일한 범용 파이프라인을 사용한다.

### 구성 요소

#### 파일 입력기

- 파일 형식과 크기 등 기본 입력 조건을 확인한다.
- 원본 파일을 파싱 단계에 전달한다.
- 원본 파일을 실행하거나 브라우저 문서로 렌더링하지 않고 신뢰할 수 없는 데이터로 파싱한다.
- 매핑과 반영 확인이 끝날 때까지만 접근 범위를 제한한 임시 객체로 보관한다.
- 완료, 취소, 실패 또는 업로드 후 24시간 만료 중 먼저 도달한 시점에 삭제한다.

#### 파서와 어댑터 레지스트리

- CSV, HTML, JSON, Markdown, 텍스트 형식을 읽는다.
- 알려진 구조라면 Chrome, Notion 등의 어댑터를 선택한다.
- 알려지지 않은 구조라면 URL과 필드 후보를 찾는다.
- 서비스명은 필수 입력이 아니라 자동 매핑을 돕는 힌트다.

#### 가져오기 분석기

- 임시 표준 항목의 URL을 검증하고 정규화한다.
- 가져오기 파일 내부와 사용자의 기존 보관함에서 중복을 찾는다.
- 사용자 지정 메모와 외부 컬렉션 정보를 구분한다.
- 원문 접근 상태는 최선형 참고 정보로만 수집한다.
- 사용자에게 보여줄 묶음 요약과 반영 계획을 반환한다.
- 메타데이터 조회는 `http`와 `https` 공개 주소만 허용하고 사설망, 로컬 주소, 위험한 프로토콜을 차단한다.
- 리다이렉트 이후 주소도 같은 네트워크 안전 규칙으로 다시 검증한다.
- 대량 조회는 동시 요청 수와 시간 제한을 두어 외부 서비스와 아맞다 서버를 보호한다.

#### 가져오기 반영기

- 승인된 분석 계획의 유효 항목을 하나의 논리적 작업으로 반영한다.
- 기술적 실패로 일부만 반영되면 생성·변경 내역을 자동 복구한다.
- 정상적으로 제외하기로 계획한 오류 항목은 작업 실패로 취급하지 않는다.

#### 가져오기 기록과 Undo

- 작업 단위 처리 결과와 변경 내역을 보관한다.
- 해당 작업에서 새로 생성된 인사이트를 되돌릴 수 있게 한다.
- 기존 인사이트의 빈 필드를 자동 보충했다면 이전 값을 복원할 수 있게 한다.
- 가져오기 이후 사용자가 직접 수정한 인사이트는 보호한다.

### 공개 인터페이스 초안

공개 인터페이스는 내부 파서나 어댑터 구조보다 사용자가 관찰하는 행동을 중심으로 작게 유지한다.

- `analyzeImport(input)` — 원본을 반영하지 않고 분석 계획과 요약을 반환한다.
- `commitImport(analysisId)` — 분석 계획을 하나의 가져오기 작업으로 반영한다.
- `undoImport(batchId)` — 가져오기 작업이 만든 안전하게 복원 가능한 변경을 되돌린다.

정확한 함수명과 타입은 구현 계획에서 코드베이스 패턴에 맞춰 조정할 수 있지만, 분석과 반영을 분리하고 Undo를 작업 단위로 제공하는 공개 동작은 유지한다.

## 임시 표준 항목

파서와 어댑터는 서비스별 데이터를 바로 인사이트로 저장하지 않고 임시 표준 항목으로 변환한다. 다음 필드는 최종 DB 스키마가 아니라 파이프라인 사이의 계약 후보다.

- 원본 URL 후보
- 제목 후보
- 설명 후보
- 사용자가 명시적으로 매핑한 메모 후보
- 외부 컬렉션 이름과 경로
- 저장 시점 후보
- 썸네일 참조 URL 후보
- 파일 안의 위치 또는 행 식별 정보
- 파싱 경고

필드 의미를 확정할 수 없으면 빈 값으로 남긴다. 게시물 캡션이나 설명을 메모로 승격하지 않는다.

## 분류와 기본 처리 정책

| 분류             | 기본 처리                                                                     | 사용자 조작          |
| ---------------- | ----------------------------------------------------------------------------- | -------------------- |
| 신규 URL         | 인사이트로 가져온다.                                                          | 필요 없음            |
| 중복 URL         | 새 인사이트를 만들지 않고 기존 인사이트를 유지한다.                           | 선택적 결과 확인     |
| 원문 확인 필요   | 유효한 URL이면 가져온다.                                                      | 필요 없음            |
| URL 형식 오류    | 해당 항목만 제외한다.                                                         | 완료 후 선택적 검토  |
| 메모 충돌        | 기존 메모를 유지하고 가져온 메모를 가져오기 기록에 보존한다.                  | 완료 후 선택적 검토  |
| 구조 매핑 불가   | 파일 단위로 URL 필드 매핑 또는 재업로드를 요청한다.                           | 가져오기 전 1회      |
| 유효 URL이 없음  | 반영하지 않고 파일 단위 실패를 안내한다.                                      | 재업로드             |
| 기술적 반영 실패 | 작업에서 발생한 부분 변경을 자동 복구하고 가져오기 작업을 실패 상태로 끝낸다. | 재시도 또는 재업로드 |

### 중복의 정의

- 사용자별로 동일한 정규화 URL은 하나의 인사이트다.
- 저장 서비스, 저장 시점, 외부 컬렉션이 달라도 URL이 같으면 중복이다.
- 기존 제목, 메모, 카테고리를 자동으로 덮어쓰지 않는다.
- 기존 필드가 비어 있고 사용자가 명시적으로 매핑한 값이 있을 때만 빈 값을 보충할 수 있다.
- 외부 컬렉션을 나중에 카테고리로 연결하면 기존 중복 인사이트에도 카테고리를 추가할 수 있다.

### 메모 충돌

- 외부 데이터에 사용자가 명시적으로 만든 메모 필드가 있을 때만 메모 후보로 취급한다.
- 기존 메모만 있으면 기존 메모를 유지한다.
- 가져온 메모만 있고 기존 메모가 비어 있으면 빈 값을 보충한다.
- 두 메모가 같으면 추가 작업을 하지 않는다.
- 두 메모가 다르면 기존 메모를 유지하고 가져온 메모를 선택적 검토 대상으로 보존한다.
- 마이그레이션은 메모 충돌 때문에 중단되지 않는다.

### 외부 컬렉션과 서비스 정보

- Chrome 폴더, Pinterest 보드, Notion 속성은 사용자의 저장 이유나 아맞다 카테고리로 자동 확정하지 않는다.
- 외부 컬렉션 이름과 경로는 선택적 카테고리 일괄 연결을 위한 가져오기 작업 데이터로만 보관한다.
- 카테고리를 연결하더라도 외부 컬렉션 맥락을 영구적인 인사이트 속성으로 승격하지 않는다.
- 외부 서비스명은 인사이트마다 저장하지 않고 파일 해석과 가져오기 기록에 필요한 작업 단위 정보로만 취급한다.
- 가져오기 기록을 삭제하면 미해결 메모와 외부 컬렉션 매핑 정보도 함께 삭제할 수 있어야 한다.

## 원문 접근 상태

- 원문 접근 상태는 아맞다 서버가 관찰한 참고 정보다.
- 서버에서 로그인이 필요하거나 접근이 차단돼도 사용자의 브라우저 세션에서는 정상적으로 열릴 수 있다.
- 상태를 근거로 인사이트를 숨기거나 `꺼내보기`에서 제외하거나 원문 열기를 막지 않는다.
- 사용자는 항상 자신의 브라우저 세션으로 원문 열기를 시도할 수 있다.
- `삭제됨`, `비공개`처럼 확정적인 사용자 문구를 사용하지 않는다.
- 기본 완료 요약에서는 세부 원문 상태보다 자동 처리 결과를 먼저 보여준다.
- 구체적인 상태 구분, 문구, 배지, 재시도 시점은 후속 에러 UX 설계에서 정한다.

## 썸네일과 보기 방식

### 썸네일 정책

- `thumbnail_url`은 최근에 확인된 원격 참조값이다.
- 아맞다는 썸네일 이미지 파일이나 원본 이미지를 영구 저장하지 않는다.
- CDN 주소 만료, 로그인 요구, 원문 삭제, 외부 로딩 차단 때문에 썸네일 표시는 실패할 수 있다.
- 원문에 접근할 수 있으면 참조 URL을 다시 확인할 수 있지만 지속적인 표시를 보장하지 않는다.
- AI로 원본과 비슷한 이미지를 생성하지 않는다.

### 보기 방식

- 리스트 보기를 텍스트 중심의 안정적인 기본 보기로 둔다.
- 갤러리 보기는 조회 시 원격 썸네일을 지연 로딩한다.
- 이미지 로딩에 실패하면 출처, 제목, 카테고리 등 저장된 정보로 대체 타일을 표시한다.
- 갤러리는 개별 인사이트의 보기 방식이고, 대시보드는 집계와 요약을 위한 별도 화면으로 취급한다.
- 갤러리의 상세 UI와 대시보드는 초기 마이그레이션 기반 구현과 분리한다.

## 데이터 경계와 개인정보

### 인사이트에 저장하는 데이터

- 원문 URL과 정규화 URL
- 제목과 설명
- 사용자 메모
- 카테고리
- 마지막으로 확인된 원문 메타데이터와 썸네일 참조 URL
- 생성·수정 시점

### 가져오기 작업에만 저장하는 데이터

- 가져오기 작업 ID와 상태
- 파일 형식과 선택된 어댑터
- 신규, 중복, 원문 확인 필요, 오류 개수
- Undo에 필요한 생성·변경 내역
- 미해결 메모 충돌
- 선택적 카테고리 연결에 필요한 외부 컬렉션 경로

### 저장하지 않는 데이터

- 업로드한 원본 파일
- 인사이트별 외부 서비스명
- 중복 처리에 필요하지 않은 외부 항목 ID
- SNS 이미지 파일
- 해석하지 못한 원본 데이터 전체

원본 파일은 파싱, 파일 단위 매핑, 묶음 반영 확인에 필요한 동안만 임시 보관한다. 완료, 취소, 실패 또는 업로드 후 24시간 만료 중 먼저 도달한 시점에 삭제한다. 만료된 분석을 재실행하려면 사용자가 파일을 다시 업로드한다.

가져오기 작업 데이터는 Undo나 미해결 검토가 남아 있는 동안 인사이트 본체와 분리해 보관한다. 사용자가 가져오기 기록을 삭제하면 Undo 권한, 메모 충돌, 외부 컬렉션 매핑 정보도 함께 삭제된다. 자동 보관 기한은 실제 운영 비용과 개인정보 요구를 확인한 뒤 별도 운영 정책으로 정하되, 첫 구현에서는 사용자의 명시적 삭제를 우선 제공한다.

### 보안 경계

- 업로드 파일과 파일 안의 문자열을 신뢰하지 않는다.
- HTML과 Markdown 안의 스크립트, 이벤트 핸들러, 임베드 코드를 실행하지 않는다.
- 압축 파일을 지원할 때는 파일 개수, 압축 해제 크기, 중첩 깊이에 제한을 둔다.
- 외부 서비스 계정 비밀번호나 세션 쿠키를 요청하거나 저장하지 않는다.
- 원문 메타데이터 조회에는 기존 URL 안전 검증과 서버 측 요청 위조 방어를 동일하게 적용한다.
- 사용자는 항상 자신의 브라우저 세션으로 원문을 열며 아맞다가 외부 서비스 로그인을 대행하지 않는다.

## 논리적 원자성과 Undo

- 사용자에게 보이는 하나의 가져오기 작업은 전체가 완료되거나 기술적 부분 반영이 자동 복구돼야 한다.
- 유효한 항목 480개를 반영하고 계획상 오류 3개를 제외한 것은 정상 완료다.
- 480개 중 230개를 반영한 뒤 예기치 않은 서버 오류가 발생한 상태를 정상 완료로 남기지 않는다.
- Undo는 해당 작업에서 새로 만든 인사이트와 안전하게 복원 가능한 자동 보충만 대상으로 한다.
- 가져오기 전에 존재한 인사이트는 삭제하지 않는다.
- 가져오기 이후 사용자가 직접 수정한 데이터는 자동 삭제하거나 이전 값으로 되돌리지 않는다.
- 구체적인 대량 처리 방식은 단일 DB 트랜잭션에 고정하지 않는다. 청크 처리와 보상 작업을 사용하더라도 사용자 관점의 논리적 원자성을 유지한다.

## TDD 전략

### 원칙

- 테스트는 내부 파서 클래스나 함수 호출 횟수가 아니라 공개 인터페이스의 사용자 관찰 행동을 검증한다.
- 실제 내보내기 파일을 익명화한 픽스처로 사용한다.
- 모든 테스트를 먼저 작성하지 않고 하나의 행동마다 `RED → GREEN → REFACTOR`를 반복한다.
- 파서, 어댑터, 정규화기, 저장소는 작은 공개 인터페이스 뒤에 숨긴다.

### 첫 tracer bullet

첫 행동은 다음 한 경로만 검증한다.

> 사용자가 작은 Chrome 북마크 HTML을 분석하고 가져온 뒤, 신규 인사이트를 보관함의 공개 조회 인터페이스로 확인할 수 있다.

이 테스트가 전체 입력, 분석, 반영, 조회 경로를 통과한 뒤 다음 행동을 하나씩 추가한다.

1. 동일한 정규화 URL은 새 인사이트를 만들지 않는다.
2. 잘못된 URL이 있어도 정상 항목은 가져온다.
3. 사설망 주소와 위험한 프로토콜은 제외하고 외부 요청을 보내지 않는다.
4. 기존 메모는 덮어쓰지 않고 충돌 기록을 남긴다.
5. 알 수 없는 구조는 파일 단위 필드 매핑을 요청한다.
6. 원문을 확인할 수 없어도 유효한 URL은 가져온다.
7. 가져오기 묶음을 Undo하면 기존 데이터는 유지된다.
8. 기술적 부분 실패가 사용자에게 부분 완료로 남지 않는다.

## 단계별 출시

### 1. 실제 파일 검증

- 익명화한 Chrome, Notion, 가능한 경우 Pinterest 내보내기 샘플을 확보한다.
- 지원 가능한 필드와 구조적 한계를 기록한다.
- 테스트 픽스처와 공개 행동의 기대 결과를 정의한다.

### 2. Chrome 마이그레이션 기반

- Chrome HTML 분석
- 묶음 요약과 한 번의 반영 확인
- 신규 저장, 중복 제외, URL 오류 처리
- 원본 파일 삭제
- 가져오기 결과와 전체 Undo

### 3. Notion과 범용 파이프라인

- Notion CSV, Markdown, HTML 구조 지원
- 알 수 없는 구조에서 URL 필드 후보 감지
- 파일 단위 1회 매핑
- 메모 충돌 보존
- 외부 컬렉션의 임시 매핑 정보

### 4. 이미지 중심 서비스

- Pinterest 데이터 아카이브에서 URL을 찾을 수 있을 때 최소 이관
- Instagram 등은 실제 샘플 검증 후 지원 여부 결정
- 원격 썸네일 기반 갤러리 보기와 대체 타일

### 5. 후속 기능

- 직접 계정 연결
- 상세 원문 상태와 에러 UX
- 카테고리 일괄 연결 UI
- 대시보드
- 추가 서비스 어댑터

## 성공 기준

- 지원 형식에서 추출 가능한 신규 URL을 안전하게 가져온다.
- 사용자는 개별 항목을 선택하지 않고 마이그레이션을 완료할 수 있다.
- 신규, 중복, 원문 확인 필요, 오류 개수와 실제 처리 결과가 일치한다.
- 기존 인사이트와 메모를 자동으로 덮어쓰지 않는다.
- 원본 업로드 파일을 처리 후 보관하지 않는다.
- 잘못 가져온 작업 묶음을 되돌릴 수 있다.
- 가져온 인사이트를 즉시 검색하고 `꺼내보기`에 사용할 수 있다.
- 외부 원문의 접근성과 썸네일을 완벽히 복원했다고 과장하지 않는다.

## 변경 가능성과 재검토 기준

다음 항목은 실제 샘플과 사용자 흐름을 확인하면서 변경할 수 있다.

- 지원 파일 형식과 서비스 어댑터
- 범용 필드 감지 규칙
- 가져오기 작업 데이터의 보관 기간
- 예외 분류와 사용자 안내 문구
- 외부 컬렉션의 선택적 카테고리 연결 방식
- 갤러리와 대체 타일의 상세 UI

다음 조건이 발생하면 이 설계를 다시 검토한다.

- 실제 내보내기 파일에 URL이 충분히 포함되지 않는다.
- 하나의 URL을 하나의 인사이트로 취급하는 정책이 실제 사용 맥락을 반복적으로 훼손한다.
- 메모 충돌이 예외가 아니라 일반적인 상황으로 나타난다.
- 원격 썸네일 실패율 때문에 갤러리 사용성이 유지되지 않는다.
- 대량 가져오기에서 논리적 원자성과 Undo 비용이 허용 범위를 벗어난다.
- 외부 서비스 약관이나 권리 범위가 메타데이터 수집 방식을 제한한다.
