# Supabase 보관함 관리·검색 완성 설계

## 목표

이 문서는 #31과 #32를 하나의 작업 브랜치에서 순서대로 완료하기 위한 설계를 정의한다. 로그인한 사용자가 자신의 Supabase 인사이트를 안전하게 수정·삭제하고 원문을 열며, 원격 보관함의 데이터를 기존 결정적 검색과 `꺼내보기`에서 상태 혼동 없이 사용할 수 있게 한다.

#33의 로컬 인사이트 가져오기는 데이터 이전, 중복 요약과 부분 실패 재시도 정책이 필요한 별도 기능이므로 이번 범위에서 제외한다.

## 현재 구현 기준선

- `createSupabaseInsightRepository`는 모든 조회·수정·삭제 요청을 현재 사용자 ID로 제한한다.
- Supabase migration은 CRUD RLS와 사용자별 정규화 URL 고유 제약을 제공한다.
- `useInsightWorkspace`는 원격 성공 뒤에만 화면 목록을 변경하고 실패하면 기존 데이터를 보존한다.
- `InsightGrid`는 수정, 삭제 확인·취소·재시도와 안전한 새 탭 원문 열기를 제공한다.
- `filterInsights`, `searchInsights`, `retrieveInsights`는 원격 저장소와 분리된 결정적 순수 함수다.
- 홈 화면은 검색 결과 없음은 구분하지만 원격 로딩, 빈 원격 보관함과 원격 조회 실패를 별도 상태로 보여주지 않는다.

따라서 새로운 CRUD나 검색 알고리즘을 만들지 않고, 저장 경계와 화면 상태 계약만 보완한다.

## #31 Supabase 수정·삭제·원문 열기

### 수정 경계

사용자가 수정할 수 있는 값은 제목, 메모와 단일 카테고리뿐이다. 제목을 직접 수정하면 `title_origin`도 사용자 입력으로 유지해야 하므로 수정 페이로드는 다음 네 필드만 포함한다.

- `title`
- `title_origin`
- `memo`
- `category`

`original_url`, `normalized_url`, `domain`, `schema_version`, `user_id`, 생성 시각은 수정 페이로드에 포함하지 않는다. `updated_at`은 기존 데이터베이스 트리거가 갱신한다. UI가 URL 입력을 제공하지 않는 것에 더해 저장소 어댑터에서도 URL 불변성을 강제한다.

### 사용자 데이터 경계

수정과 삭제 쿼리는 기존과 같이 인사이트 ID와 현재 사용자 ID를 모두 조건으로 사용한다. 최종 권한 경계는 Supabase RLS가 담당하고 클라이언트 필터는 다른 사용자 행을 정상 결과로 오인하지 않게 한다.

### 실패와 원문 열기

- 수정이나 삭제가 실패하면 `useInsightWorkspace`는 기존 목록을 변경하지 않는다.
- `InsightGrid`는 입력이나 카드를 유지하고 재시도 또는 취소를 제공한다.
- 원문은 저장된 `originalUrl`을 `target="_blank"`, `rel="noreferrer"`로 연다.
- URL을 안전한 HTTP(S) 주소로 다시 확인할 수 없으면 링크 대신 안내를 표시한다.

기존 구현과 테스트가 이 동작을 이미 제공하므로, 이번 작업은 회귀 테스트를 유지하면서 수정 페이로드의 불변 경계를 추가로 고정한다.

## #32 Supabase 검색과 꺼내보기

### 데이터 흐름

```text
인증 사용자 ID
  → Supabase InsightRepository.list()
  → 사용자별 원격 Insight[]
  → 보관함 filterInsights()
  → 홈 retrieveInsights()
  → InsightGrid의 안전한 원문 링크
```

검색과 `꺼내보기`는 원격 목록을 받은 뒤 기존 순수 함수에서 실행한다. 필드 가중치, 완전 일치·접두사·부분 일치 배수, 생성 시각과 ID 동점 정렬, 최대 6개 제한은 변경하지 않는다.

### 홈 화면 상태 우선순위

홈의 결과 영역은 다음 순서로 하나의 상태만 보여준다.

1. `loading`: 원격 보관함을 불러오는 중이라는 정적 로딩 상태
2. `unavailable`: 원격 조회 실패로 `꺼내보기`를 실행할 수 없다는 오류와 새로고침 행동
3. `ready`이면서 전체 인사이트가 0개: 첫 링크 저장 행동이 있는 빈 보관함 상태
4. 제출한 상황이 없음: 기존 상황 예시
5. 제출한 상황이 있고 결과가 있음: 최대 6개 작업팩
6. 제출한 상황이 있고 결과가 없음: 입력을 보존하는 기존 결과 없음 상태

`AuthenticatedWorkspace`는 `isLoading`, `loadWarnings`와 전체 원격 인사이트 개수를 바탕으로 홈의 `libraryState`를 계산한다. `read-failed` 또는 `permission-denied`는 `unavailable`로 취급한다. `corrupted-entry`는 손상 항목을 제외하고 정상 데이터가 남으면 `ready`, 유효한 데이터가 하나도 남지 않으면 `unavailable`로 취급해 실제 빈 보관함과 구분한다.

오류 상태의 `다시 불러오기`는 현재 문서를 새로고침해 인증 세션과 Supabase 목록 조회를 다시 시작한다. 빈 보관함의 `링크 저장`은 기존 저장 탭으로 이동한다.

### 보관함 검색

보관함은 현재 동작을 유지한다.

- 검색어가 비어 있으면 현재 사용자 원격 목록 전체를 최신 저장순으로 표시한다.
- 검색어가 있으면 제목·메모·카테고리·도메인·원본 URL을 결정적으로 검색한다.
- `AuthenticatedWorkspace`는 필터링한 표시 목록과 전체 원격 인사이트 개수를 `LibraryPage`에 따로 전달한다.
- `LibraryPage`는 로딩, 원격 실패, 실제 빈 보관함, 결과 있음, 검색 결과 없음, 카테고리 결과 없음을 순서대로 구분한다.
- 전체 원격 인사이트가 0개면 검색어나 카테고리가 남아 있어도 실제 빈 보관함과 링크 저장 행동을 표시한다.
- 전체 인사이트는 있지만 카테고리만으로 표시 결과가 0개면 실제 빈 보관함 대신 조건 결과 없음과 전체 보기 행동을 표시한다.
- `read-failed`, `permission-denied` 또는 유효한 행이 없는 `corrupted-entry`이면 실제 빈 보관함 대신 원격 조회 실패와 다시 불러오기 행동을 표시한다.
- 원격 경고와 함께 유효한 인사이트가 남아 있으면 경고를 알리되 기존 카드는 계속 표시한다.

## 컴포넌트 경계

- `entities/insight/api/supabase_insight_repository.ts`: Supabase 수정 가능 필드와 사용자 조건을 소유한다.
- `entities/insight/model/*`: 검색·꺼내보기 알고리즘을 변경하지 않는다.
- `pages/home/ui/home_page.tsx`: 홈의 원격 보관함 표시 상태만 소유한다.
- `pages/library/ui/library_page.tsx`: 보관함의 로딩·원격 실패·결과 있음·검색 결과 없음·빈 상태를 구분한다.
- `app/authenticated_workspace.tsx`: 저장소 상태를 페이지 입력으로 변환하고 탭 이동·새로고침 행동을 조합한다.

페이지는 Supabase SDK나 저장소를 직접 호출하지 않는다. 외부 UI 패키지는 `@/shared/ui` 공개 API를 통해서만 사용한다.

## 검증 전략

### #31

- 저장소에 URL과 도메인이 변조된 `Insight`가 전달돼도 수정 페이로드에 URL 계열이 들어가지 않는지 검증한다.
- 기존 사용자 ID·인사이트 ID 조건과 오류 변환 테스트를 유지한다.
- 기존 수정·삭제 취소·확정·재마운트·원문 열기 테스트를 회귀 실행한다.

### #32

- `HomePage`가 로딩, 원격 조회 실패, 빈 보관함, 상황 예시, 결과 있음과 결과 없음을 서로 구분하는지 검증한다.
- 빈 보관함의 저장 행동과 조회 실패의 다시 불러오기 행동을 검증한다.
- `LibraryPage`가 원격 조회 실패, 실제 빈 보관함, 검색 결과 없음과 카테고리 결과 없음을 구분하는지 검증한다.
- 전체 행이 손상되면 원격 조회 실패로 안내하고 일부 행만 손상되면 유효한 카드를 유지하는지 검증한다.
- `AuthenticatedWorkspace`가 저장소 로딩과 경고를 올바른 홈 상태로 전달하는지 검증한다.
- 기존 골든 검색 fixture, 최대 6개 제한, 사용자 ID 조회 조건과 안전한 원문 링크 테스트를 회귀 실행한다.

## 제외 범위

- 로컬 인사이트 가져오기와 Web Storage 이전
- 검색 가중치, 토큰화 또는 랭킹 변경
- 서버 검색, 전문 검색, AI·embedding 검색
- 휴지통, URL 수정과 변경 이력
- Supabase 스키마나 RLS 정책 변경
