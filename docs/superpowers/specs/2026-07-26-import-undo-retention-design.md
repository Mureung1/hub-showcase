# 가져오기 되돌리기 데이터 보존 설계

## 배경

현재 가져오기 작업은 분석 중 `expires_at`을 두지만, 완료 시 이를 `null`로 바꾼다. 그 결과 되돌리기에 필요한 식별자뿐 아니라 원본 URL, 제목·메모 후보, 컬렉션 경로, 경고와 출처 위치를 포함한 `insight_import_items` 전체가 사용자가 기록을 삭제할 때까지 보존된다.

되돌리기의 목적은 대량 가져오기 실수를 안전하게 복구하는 것이다. 이 목적에는 새로 생성한 인사이트의 식별자와 가져오기 직후 수정 시각만 필요하다. 완료된 후보 전체를 보존하는 현재 구조는 최소 수집 원칙과 24시간 되돌리기 설명에 맞지 않는다.

## 검토한 접근

### 1. 서버 최소 원장 분리

별도 되돌리기 원장에 작업 ID, 사용자 ID, 생성된 인사이트 ID와 가져오기 직후 수정 시각만 24시간 보관한다. 완료 직후 전체 후보 항목은 삭제한다.

- 장점: 브라우저를 닫거나 기기를 바꿔도 되돌릴 수 있고, 서버가 수정 여부를 원자적으로 검증한다.
- 단점: 최소 정보라도 서버 정리 작업이 필요하다.

### 2. 브라우저 로컬 영수증

생성된 인사이트 ID와 수정 시각을 IndexedDB에만 저장하고 되돌릴 때 서버로 보낸다.

- 장점: 서버에 별도 임시 원장을 남기지 않는다.
- 단점: 저장소 삭제, 앱 재설치와 다른 기기에서 복구할 수 없어 대량 작업 안전망의 신뢰도가 낮다.

### 3. 기존 후보 항목 비식별화

현재 `insight_import_items`를 유지하되 완료 시 불필요한 열을 비운다.

- 장점: 테이블 추가가 없다.
- 단점: 분석 후보와 되돌리기 책임이 계속 결합되고, 다수의 필수 열과 제약을 완화해야 해 데이터 계약이 불명확해진다.

서버 최소 원장 분리를 채택한다. 사용 편의성과 복구 신뢰도를 유지하면서 서버 보존 범위를 목적에 필요한 데이터로 제한할 수 있기 때문이다.

## 데이터 수명

| 데이터                            | 수명과 처리                                                                      |
| --------------------------------- | -------------------------------------------------------------------------------- |
| 원본 파일                         | 브라우저에서만 읽고 업로드하지 않는다.                                           |
| 분석 후보·cursor·오류·컬렉션 매핑 | 미완료 작업 재개를 위해 최대 24시간 유지한다.                                    |
| OAuth 토큰                        | 완료·취소 시 즉시 철회하고 암호화 열을 비운다. 중단된 연결만 24시간 후 정리한다. |
| 완료된 후보 항목                  | commit 트랜잭션 안에서 즉시 삭제한다.                                            |
| 되돌리기 최소 원장                | 완료 시각부터 24시간 동안만 유효하다.                                            |
| 가져오기 요약 이력                | 사용자에게 작업 결과를 보여주기 위해 유지하며 사용자가 삭제할 수 있다.           |
| 생성된 인사이트                   | 되돌리기 또는 사용자의 일반 삭제 전까지 유지한다.                                |

24시간은 서버 DB 시각으로 판단하는 되돌리기 권한의 절대 기한이다. UI의 시각과 무관하게 RPC가 만료 이후 요청을 거부한다. Supabase Cron은 1분마다 만료 원장을 삭제한다. 예약 작업은 장애로 지연될 수 있으므로 문서에는 “24시간 동안 되돌릴 수 있으며 만료 원장은 다음 정리 실행에서 삭제된다”고 표현하고, 물리 삭제가 정확히 24시간 0초에 완료된다고 약속하지 않는다.

## 데이터 구조

`insight_import_jobs`에 nullable `undo_expires_at`을 추가한다.

- `completed`: `completed_at + interval '24 hours'`
- `undone` 또는 만료 정리 완료: `null`
- 그 밖의 상태: `null`

별도 `insight_import_undo_items` 테이블을 추가한다.

- `job_id`
- `user_id`
- `created_insight_id`
- `imported_updated_at`

원장은 URL, 제목, 메모, 카테고리, 원본 파일명, Provider cursor와 OAuth 정보를 저장하지 않는다. 사용자와 service role은 테이블을 직접 읽거나 수정하지 않고, 인증 사용자는 security-definer RPC를 통해서만 되돌린다. 원장 정리는 데이터베이스 내부 함수만 수행한다.

## 처리 흐름

### 완료

1. 현재 보관함 중복을 다시 확인한다.
2. 신규 인사이트를 생성한다.
3. 생성된 인사이트 ID와 `updated_at`을 최소 원장에 복사한다.
4. 작업 요약과 `undo_expires_at`을 기록한다.
5. 해당 작업의 전체 후보 항목을 삭제한다.
6. 한 단계라도 실패하면 트랜잭션 전체를 롤백한다.

### 되돌리기

1. 작업 소유자, `completed` 상태와 `undo_expires_at > now()`를 검증한다.
2. 원장의 인사이트 중 현재 `updated_at`이 가져오기 직후와 같은 항목만 삭제한다.
3. 사용자가 수정한 항목과 이미 삭제한 항목을 각각 집계해 보존한다.
4. 작업을 `undone`으로 바꾸고 요약 결과를 기록한다.
5. 사용한 최소 원장을 즉시 삭제하고 `undo_expires_at`을 비운다.

만료된 작업의 되돌리기 요청은 인사이트를 변경하지 않고 `undo-expired` 결과를 반환한다.

### 정리

Supabase Cron이 1분마다 데이터베이스 내부 정리 함수를 실행한다.

- `undo_expires_at <= now()`인 최소 원장을 삭제한다.
- 해당 작업의 `undo_expires_at`을 `null`로 바꾼다.
- 완료·되돌림 작업의 요약 이력과 인사이트는 유지한다.

Vercel Cron은 Notion 토큰 철회가 필요한 중단 연결과 미완료 Provider 작업을 계속 담당한다. 데이터베이스 내부 최소 원장 정리와 외부 Provider 토큰 철회를 한 작업에 결합하지 않는다.

## 기존 데이터 이전

마이그레이션 시 기존 `completed` 작업을 다음처럼 처리한다.

- `completed_at + 24시간`이 지나지 않은 작업은 `created_insight_id`와 `imported_updated_at`을 최소 원장으로 복사하고 남은 기한을 유지한다.
- 이미 24시간이 지난 작업과 `undone` 작업은 최소 원장을 만들지 않는다.
- 복사가 끝난 뒤 모든 `completed`·`undone` 작업의 전체 후보 항목을 삭제한다.
- 기존 요약 개수와 되돌림 결과는 변경하지 않는다.

## UI 계약

가져오기 이력 응답에 `undoExpiresAt`을 포함한다.

- 서버가 기한을 제공하고 클라이언트는 현재 시각 이전이면 되돌리기 행동을 노출하지 않는다.
- RPC가 `undo-expired`를 반환하면 해당 이력의 권한을 즉시 만료 상태로 갱신하고 “되돌릴 수 있는 24시간이 지났어요.”라고 안내한다.
- 완료 직후 결과 화면과 이력 화면은 같은 만료 계약을 사용한다.
- 기록 삭제는 요약 이력과 남아 있는 최소 원장을 삭제하지만 생성된 인사이트는 유지한다.

## 검증

- 새 설치 DB에서 완료 직후 후보 전체 삭제와 최소 원장 열 구성을 검증한다.
- 기존 완료·되돌림 작업이 있는 업그레이드 DB에서 24시간 이내 원장 이전과 만료 데이터 제거를 검증한다.
- 24시간 이내 되돌리기, 만료 거부, 사용자 수정 보존과 이미 삭제된 항목 집계를 검증한다.
- 정리 함수가 최소 원장만 삭제하고 요약 이력과 인사이트를 유지하는지 검증한다.
- RLS와 함수 권한으로 다른 사용자의 원장과 작업에 접근할 수 없는지 검증한다.
- UI가 서버 만료 시각에 따라 되돌리기 행동과 만료 안내를 일관되게 표시하는지 검증한다.

## 제외 범위

- 지원 Provider 추가
- Notion OAuth와 Vercel 운영 비밀값 설정
- Vercel Firewall 구성
- 운영 첫 화면의 `Buffer is not defined` 회귀 수정
