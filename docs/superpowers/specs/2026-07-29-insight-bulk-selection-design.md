# 보관함 인사이트 선택 삭제 설계

## 배경

보관함에 인사이트가 많아지면 각 카드에서 삭제 확인을 반복해야 한다. 여러 항목을 한 번에 선택할 수 있어야 하지만, 삭제 범위가 보이지 않거나 모바일 제스처가 스크롤과 충돌하면 의도하지 않은 데이터 손실로 이어질 수 있다.

- GitHub 이슈: [#103 보관함에서 여러 인사이트를 안전하게 선택해 삭제한다](https://github.com/ppre1ude/hub/issues/103)
- 관련 화면: 보관함
- 관련 데이터: 현재 사용자의 인사이트

## 목표

- 현재 보고 있는 목록에서 여러 인사이트를 선택해 한 번에 삭제한다.
- 선택 모드와 일반 카드 행동을 명확하게 분리한다.
- 모바일에서 길게 누르기나 드래그가 선택을 시작하지 않게 한다.
- 삭제 전에 대상 개수와 범위를 확인한다.
- 삭제는 전체 성공 또는 전체 실패로 끝나게 한다.
- 필요한 경계만 검증하고 관련 없는 테스트를 늘리지 않는다.

## 이번 작업에서 제외

- 모바일 길게 누르기와 드래그 선택
- 휴지통, 삭제 취소와 복구
- 선택 항목의 카테고리 일괄 변경
- 여러 검색어나 카테고리에 걸친 선택 유지
- 페이지를 나가거나 새로고침한 뒤 선택 유지
- 홈과 꺼내보기 결과의 선택 모드

카테고리 일괄 변경은 이번 선택 구조를 재사용할 수 있지만 별도 작업으로 다룬다. 삭제 복구는 저장 방식과 보존 기간을 함께 설계해야 하므로 단순한 화면 기능으로 추가하지 않는다.

## 현재 구조에서 이어받을 것

- 보관함은 `LibraryPage`가 검색, 카테고리 필터, 결과 개수와 `InsightGrid`를 조합한다.
- 홈과 보관함은 `InsightGrid`와 `InsightCard`를 공유한다.
- 카드의 수정과 단건 삭제는 카드 내부에서 상태와 포커스 복구를 처리한다.
- `InsightRepository`와 `useInsightWorkspace`는 현재 단건 삭제만 지원한다.
- 카드, 입력과 내비게이션은 `DESIGN.md`의 따뜻한 흰색 배경과 1px 경계를 유지한다.
- 터치 영역은 최소 44px, 키보드 포커스는 Electric Blue 2px 외곽선을 사용한다.
- 확인 창은 `shared/ui`의 `Modal`과 `Button`을 사용한다.

## 화면 정보 순서

선택 모드는 보관함 결과 목록 안에서만 동작한다.

```text
보관함 제목과 검색
  └─ 카테고리 필터
      └─ 결과 개수 + 선택 진입
          ├─ 일반 상태: 인사이트 카드 목록
          └─ 선택 상태
              ├─ 선택 도구
              ├─ 선택 가능한 카드 목록
              └─ 삭제 확인 창
```

사용자가 먼저 확인할 정보는 현재 목록의 범위, 선택한 개수, 실행할 행동 순서다. 삭제 확인 창에서도 같은 순서를 유지한다.

## 선택 모드 진입

- 결과가 한 개 이상일 때 결과 개수 오른쪽에 `선택` 버튼을 표시한다.
- `선택`을 누르면 선택 모드에 들어가지만 어떤 카드도 자동으로 선택하지 않는다.
- 일반 상태에서 카드를 길게 누르거나 드래그해도 선택 모드가 시작되지 않는다.
- 선택 모드가 시작되면 `선택` 버튼이 있던 위치에 `선택 끝내기`를 표시한다.
- 선택을 끝내면 모든 선택값을 비우고 일반 카드 행동을 복구한다.
- 선택을 끝낸 뒤 포커스는 `선택` 버튼으로 돌아간다.

## 카드 선택

### 공통 동작

- 선택 모드에서는 카드 위를 덮는 실제 `button`이 카드 전체의 선택 영역으로 동작한다. `article`에 클릭 역할을 임의로 추가하지 않는다.
- 카드 왼쪽 위에 체크 표시를 두고 최소 44px 터치 영역을 제공한다.
- 선택 버튼은 인사이트 제목을 접근 가능한 이름으로 사용하고 `aria-pressed`로 선택 상태를 전달한다.
- 선택 상태는 체크 표시와 경계 변화로도 함께 전달한다.
- 선택 모드에서는 `원문 열기`, `수정`, 개별 `삭제`를 렌더링하지 않는다.
- 선택 가능한 카드의 접근 가능한 이름에는 인사이트 제목과 선택 상태를 포함한다.
- Space 또는 Enter로 포커스된 카드를 선택하거나 해제할 수 있다.

### 데스크톱 범위 선택

- 일반 선택은 해당 카드 한 개를 선택하거나 해제하고 범위 선택의 시작점으로 기록한다.
- Shift를 누른 채 다른 카드를 선택하면 시작점부터 해당 카드까지 현재 화면 순서대로 모두 선택한다.
- 시작점이 없으면 Shift를 눌러도 해당 카드 한 개만 선택한다.
- 범위 선택은 기존 선택을 지우지 않고 항목을 추가한다.
- 검색이나 카테고리 변경으로 화면 순서가 바뀌면 시작점을 비운다.

### 모바일과 태블릿

- 개별 카드 선택과 `현재 목록 모두 선택`만 제공한다.
- 길게 누르기, 드래그와 가로 쓸기는 선택 동작으로 사용하지 않는다.
- 카드 위에서 스크롤한 동작은 선택으로 처리하지 않는다.

## 선택 범위

- 선택 대상은 현재 카테고리와 검색어로 화면에 표시된 인사이트다.
- `현재 목록 16개 모두 선택`처럼 범위와 개수를 함께 표시한다.
- 현재 목록을 모두 선택한 뒤 다시 누르면 `현재 목록 선택 해제`로 동작한다.
- 검색어나 카테고리를 바꾸면 선택 모드를 종료하고 선택값과 범위 시작점을 비운다.
- 다른 화면으로 이동하거나 보관함을 다시 불러오면 선택 상태를 유지하지 않는다.
- 새 목록에 존재하지 않는 ID는 선택 집합에서 제거한다.

선택 항목을 다른 검색 결과나 카테고리 뒤에 숨겨 유지하지 않는다. 사용자가 확인할 수 없는 대상을 삭제 범위에 포함하지 않기 위한 기준이다.

## 선택 도구

선택 도구는 다음 정보를 같은 영역에 표시한다.

- `3개 선택됨`
- `현재 목록 16개 모두 선택` 또는 `현재 목록 선택 해제`
- `선택 해제`
- `삭제`

선택한 항목이 없으면 `삭제`와 `선택 해제`를 비활성화한다.

### 데스크톱

- 결과 개수 아래, 카드 목록 위에 둔다.
- 카드 목록을 스크롤해도 화면 상단 내비게이션을 가리지 않는 범위에서 고정할 수 있다.
- 도구의 첫 정보는 선택 개수, 마지막 행동은 삭제로 배치한다.

### 모바일

- 고정 하단 내비게이션 바로 위에 둔다.
- `safe-area-inset-bottom`과 하단 내비게이션 높이를 반영한다.
- 카드 목록 마지막 항목이 도구와 내비게이션 뒤에 가리지 않도록 본문 아래 여백을 늘린다.
- 좁은 화면에서는 선택 개수와 삭제를 첫 줄에 두고 전체 선택과 선택 해제를 다음 줄에 배치할 수 있다.

## 삭제 확인

### 일부 또는 현재 결과 삭제

- 제목: `선택한 인사이트 7개를 삭제할까요?`
- 설명: `삭제하면 보관함에서 사라지고 되돌릴 수 없어요.`
- 확인 버튼: `인사이트 7개 삭제하기`
- 취소 버튼: `닫기`

확인 창을 열 때 삭제 버튼에 포커스를 바로 두지 않고 `닫기`에 둔다. 제목과 설명을 읽은 뒤 사용자가 삭제로 이동하게 하고, 창을 닫으면 선택 도구의 삭제 버튼으로 포커스를 돌린다.

### 보관함 전체 삭제

다음 조건을 모두 만족할 때만 보관함 전체 삭제로 판정한다.

- 카테고리가 `전체`다.
- 검색어가 없다.
- 선택한 개수가 보관함 전체 인사이트 개수와 같다.
- 전체 인사이트 개수가 한 개 이상이다.

이때는 확인 창에 `삭제` 입력란을 추가한다.

- 제목: `보관함의 인사이트 16개를 모두 삭제할까요?`
- 설명: `삭제하면 보관함의 모든 인사이트가 사라지고 되돌릴 수 없어요. 계속하려면 아래에 삭제를 입력해 주세요.`
- 입력 라벨: `확인 문구`
- 확인 조건: 앞뒤 공백을 제외한 입력값이 `삭제`와 정확히 같아야 한다.
- 확인 버튼: `인사이트 16개 모두 삭제하기`

입력 조건을 만족하기 전에는 확인 버튼을 비활성화한다. 특정 카테고리 전체나 검색 결과 전체에는 확인 문구 입력을 요구하지 않고 범위와 개수만 명확히 표시한다.

## 삭제 처리

### 저장소 계약

단건 삭제를 반복 호출하지 않고 여러 ID를 한 요청으로 처리하는 저장소 계약을 추가한다.

```ts
type DeleteInsightsResult =
  | { ok: true; deletedIds: string[] }
  | { ok: false; reason: 'invalid-request' | 'not-found' | 'permission-denied' | 'write-failed' };
```

- 빈 배열은 외부 요청 전에 거부한다.
- 중복 ID는 요청 전에 제거한다.
- 서버는 현재 사용자의 인사이트인지 전체 ID를 확인한다.
- 요청한 ID 중 하나라도 없거나 현재 사용자의 것이 아니면 아무 항목도 삭제하지 않는다.
- 검증과 삭제는 데이터베이스 함수 한 번과 같은 트랜잭션 안에서 수행한다.
- 함수는 삭제한 ID 목록을 반환하고, 클라이언트는 요청한 ID 집합과 같은지 확인한다.
- RLS와 `auth.uid()` 사용자 경계는 현재 단건 삭제와 같은 수준으로 유지한다.

### 화면 상태 갱신

- 서버 삭제가 모두 성공한 뒤에만 클라이언트 목록에서 항목을 제거한다.
- 성공하면 선택 모드와 확인 창을 닫고 남은 결과 개수를 알린다.
- 성공 뒤 포커스는 남은 결과의 `선택` 버튼으로 이동한다.
- 결과가 비었으면 해당 빈 상태의 주요 행동으로 포커스를 이동한다.
- 실패하면 카드, 선택값과 확인 창을 유지한다.
- 실패 문구는 발생한 일, 보존된 상태, 다음 행동 순서로 전달한다.

실패 문구:

> 선택한 인사이트를 삭제하지 못했어요. 인사이트와 선택은 그대로 두었어요. 다시 시도하거나 닫아 주세요.

## 상태별 화면

| 상태 | 사용자가 보는 내용 | 가능한 행동 |
| --- | --- | --- |
| 일반 | 기존 카드와 원문·수정·삭제 행동 | 선택 모드 진입 |
| 선택 시작 | 선택 표시가 있는 카드, `0개 선택됨` | 카드 선택, 현재 목록 전체 선택, 선택 끝내기 |
| 일부 선택 | 선택 개수와 활성화된 삭제 행동 | 추가 선택, 선택 해제, 삭제 |
| 확인 | 대상 개수와 삭제 결과 설명 | 닫기, 삭제 확정 |
| 보관함 전체 확인 | 대상 개수, `삭제` 확인 입력 | 닫기, 문구 입력 뒤 삭제 확정 |
| 처리 중 | 삭제 진행 문구와 비활성화된 행동 | 완료 대기 |
| 성공 | 삭제된 개수와 갱신된 목록 | 일반 보관함 사용 |
| 실패 | 오류와 보존된 선택·카드 | 다시 시도, 닫기 |
| 외부 목록 변경 | 현재 목록에 남은 ID만 선택 | 계속 선택하거나 끝내기 |

## 컴포넌트와 책임

- `pages/library`
  - 보관함에 한정된 선택 ID, 범위 시작점, 확인 창 상태를 관리한다.
  - 검색·카테고리 변경과 선택 초기화를 조합한다.
  - 데스크톱·모바일 선택 도구를 배치한다.
- `entities/insight/ui`
  - `InsightGrid`가 선택 모드와 현재 선택 상태를 카드에 전달한다.
  - `InsightCard`가 일반 상태와 선택 상태를 분리해 렌더링한다.
- `app`
  - 여러 인사이트 삭제 행동을 보관함에 전달한다.
  - 삭제 성공 뒤 공통 인사이트 상태를 한 번 갱신한다.
- `entities/insight/model`
  - 여러 ID 삭제 결과와 저장소 계약을 정의한다.
- `entities/insight/api`
  - Supabase의 일괄 삭제 함수를 호출하고 결과를 도메인 결과로 변환한다.
- `supabase/migrations`
  - 사용자 경계 확인과 전체 성공·전체 실패를 보장하는 데이터베이스 함수를 추가한다.

새 기능 전용 전역 상태나 별도 페이지는 만들지 않는다. 선택은 보관함을 벗어나면 사라지는 임시 화면 상태다.

## 접근성

- 선택 진입, 전체 선택, 선택 해제, 삭제와 선택 끝내기는 모두 키보드로 실행할 수 있다.
- 카드 선택 버튼은 `aria-pressed`로 선택 상태를 전달한다.
- 선택 개수와 삭제 성공·실패는 기존 상태 영역에서 한 번만 알린다.
- 확인 창은 제목과 설명을 연결하고 열릴 때 내부에 포커스를 둔다.
- Escape는 처리 중이 아닐 때 확인 창을 닫고, 확인 창이 없으면 선택 모드를 끝낸다.
- 모바일 선택 도구와 카드 선택 영역은 최소 44px을 유지한다.
- 본문과 상태 문구는 최소 4.5:1 대비를 유지한다.

## 최소 검증 범위

자동 테스트는 데이터 손실과 선택 경계에 직접 연결된 항목만 추가한다.

### 화면

- `선택`을 누르면 선택 모드가 시작되고 아무 카드도 자동 선택되지 않는다.
- 개별 선택, 선택 해제와 현재 목록 전체 선택이 정확한 ID 집합을 만든다.
- 검색어나 카테고리를 바꾸면 선택이 비워진다.
- 삭제 확인 전에는 삭제 요청이 발생하지 않는다.
- 보관함 전체 삭제는 `삭제` 입력 전까지 확정할 수 없다.
- 실패하면 카드와 선택 상태가 유지된다.

### 저장 상태

- 여러 ID 삭제 성공 뒤 해당 인사이트만 목록에서 제거한다.
- 삭제 실패 뒤 목록을 바꾸지 않는다.

### 데이터베이스

- 현재 사용자의 유효한 ID 전체는 한 번에 삭제된다.
- 존재하지 않거나 다른 사용자의 ID가 섞이면 아무 항목도 삭제되지 않는다.

### 수동 확인

- 390px: 하단 선택 도구가 내비게이션과 마지막 카드를 가리지 않는다.
- 768px: 두 열 카드와 선택 도구가 겹치지 않는다.
- 1280px: 세 열 카드, 결과 개수와 데스크톱 도구의 위계가 자연스럽다.
- 모바일 스크롤, 길게 누르기와 드래그가 선택 모드를 시작하지 않는다.

전체 테스트, 홈·저장·가져오기 화면 테스트, 카드 문구와 간격별 테스트는 이번 검증 범위에 포함하지 않는다. 기존 테스트는 타입과 사용자 흐름이 바뀌어 필요한 부분만 수정한다.

## 완료 기준

- 사용자는 명시적인 `선택` 버튼으로만 선택 모드에 들어간다.
- 현재 목록에서 개별, 데스크톱 연속 범위와 전체 선택을 할 수 있다.
- 선택 중에는 일반 카드 행동이 실행되지 않는다.
- 삭제 전에 대상 개수와 범위를 확인한다.
- 보관함 전체 삭제에는 `삭제` 입력 확인이 필요하다.
- 여러 항목 삭제는 전체 성공 또는 전체 실패로 끝난다.
- 실패해도 카드와 선택을 잃지 않는다.
- 모바일 선택 도구가 하단 내비게이션과 콘텐츠를 가리지 않는다.
- 관련 화면·저장 상태·데이터베이스 경계만 검증한다.
