# 온보딩·홈 디자인 고도화 설계

## 목적

온보딩과 로그인 후 홈을 흰색·파랑 중심의 일반적인 SaaS 화면에서 벗어나, 아맞다의 핵심 가치인 “저장한 기억을 필요한 순간 다시 연결하는 개인 작업 공간”이 드러나는 화면으로 바꾼다.

이 작업은 시각 디자인과 화면 구조를 고도화하지만 인증 흐름, 인사이트 데이터, 검색·저장 동작의 의미는 바꾸지 않는다.

## 확정 콘셉트

**Living Archive × Swiss Index**

- 따뜻한 종이, 메모 조각, 편집 지면의 인간적인 질감은 `기억의 서재` 방향을 따른다.
- 명확한 원색, 검은 외곽선, 색인표 같은 구조는 `컬러 인덱스` 방향을 따른다.
- 온보딩은 원색을 넓은 면적으로 사용해 첫인상을 만들고, 홈은 같은 색을 상태와 탐색 단서에 제한해 작업 도구의 차분함을 유지한다.
- 둥근 카드와 파랑 그라데이션을 반복하는 일반적인 SaaS 문법을 피한다.

## 디자인 원칙

1. **사람이 남긴 기록처럼 보인다.** 카드보다 메모 조각, 색인표, 인쇄물의 얇은 선과 작은 오프셋 그림자를 사용한다.
2. **색에는 역할이 있다.** 원색은 장식이 아니라 행동, 현재 선택, 연결 상태, 강조 정보를 구분한다.
3. **온보딩과 홈은 같은 브랜드의 다른 밀도다.** 공통 토큰과 타이포그래피를 유지하되 원색 사용 면적을 온보딩 약 70%, 홈 약 25%로 조절한다.
4. **모션은 하나의 서사를 설명한다.** GSAP은 저장 카드가 현재 상황을 기준으로 작업팩이 되는 장면에만 집중한다.
5. **콘텐츠와 CTA가 모션보다 우선한다.** 애니메이션 진행 여부와 관계없이 가치 제안과 로그인 CTA는 항상 읽고 누를 수 있다.

## 시각 시스템

### 색상

| 역할 | 토큰 | 값 | 사용처 |
| --- | --- | --- | --- |
| 종이 배경 | `--color-paper` | `#F4EDDC` | 온보딩과 홈의 기본 배경 |
| 잉크 | `--color-ink` | `#1C1B17` | 제목, 본문, 외곽선 |
| 코발트 | `--color-cobalt` | `#315BD2` | Primary CTA, 핵심 행동, 진행 상태 |
| 코럴 | `--color-coral` | `#FF5D3A` | 강조 문장, 중요한 메모, 시선 유도 |
| 선명한 노랑 | `--color-yellow` | `#F6CF3F` | 현재 선택, 상황 입력, 능동 상태 |
| 리프 그린 | `--color-leaf` | `#53A86A` | 연결 완료, 저장 완료, 보조 상태 |
| 카드 | `--color-paper-card` | `#FFFDF6` | 메모 조각과 인사이트 카드 |
| 흐린 잉크 | `--color-ink-muted` | `#6B665A` | 설명, 메타 정보 |

코발트는 계속 Primary 역할을 맡지만, 코럴·노랑·초록을 기능별로 반복해 “흰색과 파랑뿐인 화면”을 벗어난다. 홈에서는 원색을 큰 배경보다 CTA, 카드 상단 색인, 상황 버튼, 상태 표시에 사용한다.

### 타이포그래피

- Display: `Gowun Batang`, serif. 온보딩 가치 제안과 홈의 핵심 질문에 사용한다.
- Body/UI: `Pretendard`, sans-serif. 본문, 입력, 버튼, 카드 제목에 사용한다.
- Index/Meta: `DM Mono`, monospace. 섹션 번호, 상태, 카운트, 영문 인덱스에 제한한다.
- 한국어 본문은 16px 미만으로 낮추지 않는다. 모노 서체는 긴 한국어 본문에 사용하지 않는다.

`Gowun Batang`과 `DM Mono`는 `index.html`에서 웹폰트 stylesheet로 로드하고, 본문은 기존 Pretendard stack을 유지한다. 폰트 로딩 실패 시에도 레이아웃이 크게 흔들리지 않도록 역할별 fallback을 제공한다.

### 형태와 표면

- 주요 컨테이너 외곽선은 1~2px 잉크색 선을 사용한다.
- 카드 radius는 4~10px 범위로 줄이고, 원형은 상태 점·아바타·작은 배지에만 사용한다.
- 그림자는 흐린 대형 그림자보다 4~8px 오프셋된 짧은 잉크색 그림자를 사용한다.
- 온보딩에는 매우 약한 종이 질감이나 격자를 허용한다. 텍스트 대비를 방해하지 않아야 한다.
- 홈에는 질감을 최소화하고 구조와 색인만 남긴다.

## 화면 설계

### 로그인 전 온보딩

#### Hero

- 첫 viewport 안에 브랜드, 가치 제안, 짧은 설명, CTA, 저장 카드 미리보기를 함께 둔다.
- 왼쪽은 명조형 가치 제안과 CTA, 오른쪽은 코럴 배경 위에 겹친 메모 조각으로 구성한다.
- 섹션 내비게이션은 `01 문제 / 02 저장 / 03 꺼내보기`처럼 색인 구조를 사용한다.
- CTA `서비스 경험하기`는 코발트 배경과 잉크색 오프셋 그림자를 사용한다.

#### 핵심 고정 스크롤 장면

Hero 아래 한 섹션만 120~160vh 범위에서 고정한다. ScrollTrigger의 pin과 scrub을 사용하되 브라우저 스크롤 자체를 가로채지 않는다.

진행 단계:

1. 저장 카드 3개가 흩어진 상태로 보인다.
2. `팀 프로젝트 앱 첫 화면 참고` 현재 상황 문장이 나타난다.
3. 카드가 상황 문장 아래로 이동하고 정렬된다.
4. `메모와 가까워요`, `디자인 카테고리에 저장한 자료예요` 같은 연결 단서가 붙는다.
5. 세 카드가 하나의 작업팩으로 읽히는 최종 배치가 완성된다.

모션은 실제 검색 결과처럼 보이지 않아야 하며, 제품의 관계를 설명하는 브랜드 시퀀스로 인식되어야 한다.

#### 나머지 섹션

- 문제, 저장, 장점, 최종 CTA는 일반 세로 스크롤을 사용한다.
- 섹션 본문은 정적으로 표시하고 버튼·링크의 hover와 focus만 CSS transition으로 처리한다.
- 반복 pin, 가로 스크롤, 스크롤 스냅은 사용하지 않는다.

### 로그인 후 홈

#### 상단 구조

- 현재 중앙 정렬 SaaS Hero를 비대칭 편집 레이아웃으로 변경한다.
- `오늘은 어떤 일에 도움이 필요해요?`를 큰 명조 제목으로 왼쪽 정렬한다.
- 보관함·홈·저장 내비게이션은 작은 색인표 형태로 유지하고 활성 홈에 노랑을 사용한다.

#### 꺼내보기 입력

- 검색 입력은 화면의 가장 중요한 작업 영역으로 유지한다.
- 코발트 `꺼내보기` 버튼과 잉크색 외곽선으로 행동을 분명히 한다.
- 추천 상황은 동일한 둥근 칩 나열 대신 2~4열 색인 버튼으로 구성한다.
- 선택 상태에는 노랑, 보조 상태에는 낮은 채도의 그린·코럴·코발트 배경을 사용한다.

#### 인사이트 결과

- 카드 상단의 얇은 원색 띠가 카테고리나 카드 구분 단서가 된다.
- 본문은 흰 종이 카드 위에 두고 제목, 도메인, 메모의 위계를 명확히 한다.
- 카드 hover는 1~2px 이동이나 그림자 변화로 제한한다. GSAP을 사용하지 않는다.

## 온보딩과 홈의 연결 규칙

| 요소 | 온보딩 | 홈 |
| --- | --- | --- |
| 종이 배경 | 넓게 사용 | 기본 canvas로 사용 |
| 코발트 | CTA와 진행 상태 | CTA와 핵심 링크 |
| 코럴 | 큰 Hero 면과 강조 | 카드 색인과 작은 강조 |
| 노랑 | 상황 문장과 현재 단계 | 활성 탭과 선택 상황 |
| 초록 | 연결 완료 장면 | 성공·완료 상태 |
| 명조 제목 | 강한 가치 제안 | 핵심 질문과 섹션 제목 |
| 모노 인덱스 | 섹션 번호와 장면 진행 | 카운트와 메타 정보 |

두 화면의 괴리가 커 보이면 홈에 색을 추가하기보다 온보딩의 원색 면적이나 채도를 먼저 낮춘다.

## 코드 구조

프론트엔드 구조는 `docs/development-architecture.md`의 FSD 점진 도입 기준을 따른다.

```text
src/
  app/
    App.tsx
    styles/global.css
  pages/
    landing/
      index.ts
      ui/
        LandingPage.tsx
        OnboardingMotionPreview.tsx
        landing-page.css
    home/
      index.ts
      ui/
        HomeBoard.tsx
        home-board.css
```

- `App.tsx`는 인증 진입 상태와 화면 조합만 맡는다.
- `LandingPage`는 온보딩 섹션 구성과 로그인 진입 callback을 받는다.
- `OnboardingMotionPreview`는 GSAP timeline, breakpoint, reduced motion 처리를 캡슐화한다.
- `HomeBoard`는 현재 query, results, 추천 상황 callback을 props로 받아 화면만 구성한다.
- 디자인 토큰과 reset은 `global.css`에 두고 화면 전용 스타일은 각 page slice에 둔다.
- 페이지 내부에서만 쓰는 장식 컴포넌트는 섣불리 `shared`로 올리지 않는다.
- Button, TextField, Chip 등 기존 WDS 컴포넌트가 제공하는 의미와 동작은 유지하고 화면 wrapper와 토큰으로 시각 언어를 조정한다.

## GSAP 구현 경계

- `gsap`, `@gsap/react`, `ScrollTrigger`는 `OnboardingMotionPreview.tsx`에서만 import한다.
- `gsap.registerPlugin(ScrollTrigger, useGSAP)` 등록은 해당 모듈에서 한 번 수행한다.
- `useGSAP({ scope })`와 ref를 사용해 selector 범위를 컴포넌트 내부로 제한하고 unmount cleanup을 보장한다.
- 데스크톱은 pin + scrub timeline을 사용한다.
- 모바일은 pin을 사용하지 않고 4~6초 자동 timeline 또는 최종 정적 배치를 사용한다.
- `prefers-reduced-motion: reduce`에서는 timeline과 ScrollTrigger를 생성하지 않는다.
- 동일 컴포넌트에서 Motion과 GSAP을 섞지 않는다.
- pin 구간이 끝나면 자연스럽게 일반 문서 흐름으로 복귀해야 한다.

## 데이터 흐름과 동작 보존

- 인증 진입 상태 `onboarding → login → workspace`는 그대로 유지한다.
- 홈의 query, 추천 상황 선택, 결과 계산은 기존 `AuthenticatedWorkspace`가 소유한다.
- `HomeBoard`는 표시 컴포넌트로 유지하며 callback을 통해 상태를 변경한다.
- 이 작업에서 API, 저장 형식, 검색 알고리즘, 인사이트 데이터 모델은 변경하지 않는다.

## 접근성·실패 대체

- 모션 요소는 장식적이면 `aria-hidden`으로 처리하고 핵심 설명은 별도 텍스트로 제공한다.
- CTA와 입력은 애니메이션 레이어보다 높은 상호작용 우선순위를 가진다.
- JavaScript 또는 GSAP 초기화가 실패해도 CSS 최종 배치로 콘텐츠가 보여야 한다.
- 키보드 포커스 표시와 최소 44px 동작 영역을 유지한다.
- 본문 대비는 WCAG AA 4.5:1 이상을 목표로 한다.
- 모바일에서 카드가 화면 밖으로 잘리거나 가로 스크롤을 만들지 않는다.

## 테스트와 검증

### 자동 테스트

- 기존 온보딩 → 로그인 → 홈 흐름 테스트를 유지한다.
- 분리된 `LandingPage`와 `HomeBoard`가 필수 제목, CTA, 입력, 추천 상황을 렌더링하는지 검증한다.
- reduced motion 환경에서도 온보딩의 최종 작업팩과 CTA가 렌더링되는지 검증한다.
- 애니메이션의 transform 수치나 timeline 프레임을 단위 테스트에서 고정하지 않는다.

### 시각 검증

- 데스크톱: 1440px와 1024px에서 Hero 첫 viewport, pin 시작·종료, 홈 결과 그리드를 확인한다.
- 모바일: 390px에서 Hero, CTA, 자동/정적 모션 대체, 홈 입력과 상황 버튼을 확인한다.
- 온보딩과 홈을 나란히 비교해 원색 사용 면적과 채도를 조절한다.
- 구현 단계에서 실제 GSAP pin 길이와 scrub 감도를 브라우저로 확인하고 최종 수치를 결정한다.

## 비목표

- 전체 온보딩을 반복 pin으로 구성하지 않는다.
- 홈에 GSAP 기반 스크롤 효과를 추가하지 않는다.
- 로그인 화면과 보관함·저장 화면 전체를 이번 작업에서 재디자인하지 않는다.
- 데이터 모델, API, 실제 인증 구현을 변경하지 않는다.
- 캐릭터, 3D 일러스트, 파랑·보라 그라데이션을 추가하지 않는다.

## 확정 사항

- 시각 방향은 `기억의 서재` 구조와 `컬러 인덱스` 원색 팔레트를 결합한다.
- 원색은 온보딩에서 강하게, 홈에서 절제해서 사용한다.
- 온보딩과 홈의 연결감은 공통 토큰과 역할 반복으로 유지하고 구현 후 채도를 조절한다.
- GSAP은 한 개의 고정 스크롤 장면에 집중한다.
- GSAP 세부 감도는 정적 목업이 아니라 실제 구현 단계의 브라우저 검증에서 조정한다.
