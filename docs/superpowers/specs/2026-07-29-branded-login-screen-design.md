# 브랜드 로그인 화면 개편 명세

## 목적

로그인 화면을 일반적인 인증 카드가 아니라 온보딩의 브랜드 경험과 개인 보관함 진입을 연결하는 화면으로 개편한다. 사용자는 화면에 들어오자마자 아맞다의 서비스 맥락과 Google 로그인 뒤 도달할 곳을 이해하고, 하나의 주요 행동에 집중할 수 있어야 한다.

## 범위

- 로그인 화면의 데스크톱·태블릿·모바일 레이아웃
- 기존 아맞다 로고와 온보딩의 대표 색상을 활용한 브랜드 영역
- 로그인 제목, 설명, 버튼, 약관 안내와 돌아가기 문구
- Google 로그인 시작 중 상태와 실패 상태의 배치·문구
- 현재 로그인 화면 테스트 중 변경된 사용자 노출 계약

다음 항목은 바꾸지 않는다.

- 기존 `BrandLogo`의 형태, 색상과 SVG 자산
- Google OAuth, Supabase 인증, 세션 유지와 콜백 처리
- 로그인 성공 뒤 이동 경로
- 이용약관과 개인정보처리방침의 법적 의미
- 새로운 로그인 제공자, 약관 페이지 또는 약관 연결 주소 추가
- 온보딩의 히어로·기능 소개·소통 섹션
- 새로운 애니메이션

## 화면 구조

### 데스크톱

- 화면을 왼쪽 브랜드 영역과 오른쪽 로그인 영역으로 나눈다.
- `1200px` 이상에서는 두 영역을 약 `60:40` 비율로 구성한다.
- 왼쪽은 큰 문장과 대표 색상으로 브랜드 인상을 만들고, 오른쪽은 로그인 행동에 필요한 정보만 둔다.
- 기존 로그인 카드의 외곽선, 둥근 카드 형태와 회색 약관 상자를 제거한다.
- 두 영역은 배경색 차이 또는 1px 경계로 구분하며 기본 그림자와 그라데이션은 사용하지 않는다.

### 태블릿

- `768px`부터 `1199px`까지는 두 영역 구조를 유지한다.
- 로그인 영역의 읽기 폭을 확보하도록 비율을 약 `56:44`로 조정한다.
- 브랜드 문장의 글자 크기와 여백을 줄이되 문장 줄바꿈과 강조 순서는 유지한다.

### 모바일

- `767px` 이하에서는 브랜드 영역을 위, 로그인 영역을 아래에 쌓는다.
- 브랜드 영역의 높이와 글자 크기를 줄여 로그인 행동이 첫 화면에서 지나치게 멀어지지 않게 한다.
- 장식 요소는 줄이되 로고, 핵심 문장과 대표 색상은 유지한다.
- Google 로그인 버튼은 사용 가능한 너비를 채우고 최소 44px 터치 높이를 유지한다.
- 문서 순서도 브랜드 영역 다음 로그인 영역으로 두어 시각 순서와 읽기 순서를 일치시킨다.

## 브랜드 영역

- 공용 `BrandLogo`와 서비스명 `아맞다`를 함께 사용한다.
- 비교 화면에 사용했던 네 칸 컬러 마크는 임시 요소이므로 구현하지 않는다.
- 새 로고나 심볼을 만들지 않고 온보딩과 인증 후 화면에서 사용 중인 아맞다 로고를 그대로 재사용한다.
- 핵심 문장은 다음 세 줄로 고정한다.

> 저장한 인사이트를<br>
> 내 보관함에서<br>
> 이어 보세요.

- `인사이트`는 Electric Blue, `이어`는 Amber 강조 요소로 표현해 온보딩의 시각 언어를 이어간다.
- 강조 요소는 텍스트의 세로 중심에 맞추고, 앞뒤 단어 간격이 실제 띄어쓰기처럼 보이게 한다.
- 핵심 문장 외에 `환영해요`, `온보딩에서 보던 흐름 그대로` 같은 소개 문구나 내부 작업 언어를 추가하지 않는다.
- 로그인 화면에서는 별도의 GSAP 시퀀스를 만들지 않고 최종 상태를 정적으로 보여준다.

## 로그인 영역

사용자에게 다음 순서로 보여준다.

1. 제목: `내 보관함으로 들어가기`
2. 설명: `Google 계정으로 로그인하면 저장한 인사이트를 바로 볼 수 있어요.`
3. Google 로그인 버튼
4. 이용약관과 개인정보처리방침 안내
5. 서비스 소개로 돌아가는 보조 행동

다음 문구는 제거한다.

- `서비스 소개`
- `로그인`
- `아맞다에 오신 걸 환영해요`
- `간편 로그인`
- `온보딩`을 직접 언급하는 모든 문구

### 주요 행동

- 기본 버튼 문구는 `Google로 로그인하기`로 한다.
- 버튼을 누르면 기존 `onLogin`을 통해 Google OAuth를 시작한다.
- 인증을 시작하는 동안 버튼을 비활성화하고 표시 문구와 접근 가능한 이름을 모두 `Google에 연결하고 있어요.`로 맞춘다.
- 로딩 중에는 같은 상태 문구를 별도 영역에서 중복해 읽히게 하지 않는다.

### 실패 상태

- 실패 안내는 Google 로그인 버튼 가까이에 기존 `StatusMessage`로 표시한다.
- 제목은 `로그인하지 못했어요`로 한다.
- 일반적인 로그인 시작 실패의 본문은 `다시 시도해 주세요.`로 하여 제목의 실패 의미를 반복하지 않는다.
- OAuth 콜백처럼 더 구체적인 원인이 전달되면 해당 내용을 본문에 유지하되, 사용자가 다음 행동을 알 수 있어야 한다.
- 실패 뒤에도 Google 로그인 버튼을 다시 사용할 수 있어야 한다.

### 약관 안내와 돌아가기

- 약관 안내는 `로그인하면 이용약관과 개인정보처리방침에 동의해요.`로 유지한다.
- 현재 저장소에는 이용약관과 개인정보처리방침의 연결 주소가 정의되어 있지 않으므로 이번 작업에서 임의의 링크를 만들지 않는다.
- 연결 주소가 별도 정책 작업으로 정의되기 전까지 약관 문구는 비대화형 안내문으로 표시한다.
- 돌아가기 문구는 `서비스 소개로 돌아가기`로 바꾸고 기존 `onBack` 동작을 유지한다.
- 돌아가기는 Google 로그인보다 낮은 위계의 보조 행동으로 표시한다.

## 시각 규칙

- 색상, 간격, 글자 크기, 경계와 모서리는 `DESIGN.md`와 런타임 디자인 토큰을 사용한다.
- 왼쪽 브랜드 영역은 밝기 부담을 낮춘 기본 배경색을 사용하고, 오른쪽 로그인 영역은 카드·입력 배경색을 사용한다.
- Electric Blue와 Amber는 로고와 핵심 단어 강조에만 사용한다.
- 제목과 본문은 Ink와 Graphite를 사용하고, 긴 본문에 Smoke를 사용하지 않는다.
- 기본 그림자, hover 시 들림 효과와 장식용 그라데이션은 사용하지 않는다.
- 오른쪽 로그인 내용은 과도하게 넓어지지 않도록 읽기 폭을 제한하되 별도 카드처럼 감싸지 않는다.

## 접근성

- 화면의 기능 제목 `내 보관함으로 들어가기`를 유일한 `h1`으로 사용하고 `main`의 접근 가능한 제목과 연결한다.
- 왼쪽 브랜드 문장은 시각적으로 크더라도 기능 제목과 경쟁하는 별도 `h1`으로 만들지 않는다.
- 기존 로고의 `aria-hidden`과 `focusable="false"` 계약을 유지하고 서비스명 텍스트로 브랜드 이름을 전달한다.
- 버튼과 돌아가기 행동은 키보드로 접근할 수 있고 `:focus-visible` 규칙을 유지한다.
- 로딩 중 버튼은 중복 요청을 막고 상태를 접근 가능한 이름으로 전달한다.
- 실패 메시지는 `role="alert"` 계약을 유지한다.
- 일반 본문 대비는 최소 `4.5:1`을 유지한다.

## 구현 경계

- 화면 전용 구조와 스타일은 `pages/login` 범위에 둔다.
- 공용 `BrandLogo`, `Button`, `StatusMessage`는 `@/shared/ui` 공개 API로 사용한다.
- 인증 상태와 동작은 기존 props 계약을 유지하고 화면 컴포넌트에서 Supabase 또는 OAuth 구현을 직접 다루지 않는다.
- 로그인 실패 제목과 일반 실패 본문이 중복되지 않도록 인증 제공자의 로그인 실패 문구만 필요한 범위에서 조정한다.
- UX 라이팅 목록은 실제 사용자 노출 문구를 바꾸는 구현 단계에서 함께 갱신한다.

## 검증 범위

- 기존 `login_page.test.tsx`에서 변경된 제목, Google 로그인 버튼 문구, 로딩 접근 가능한 이름, 실패 뒤 재시도 동작을 갱신한다.
- 인증 제공자의 일반 로그인 실패 본문을 바꾸면 해당 기존 테스트의 문구 기대값만 갱신한다.
- 앱 조합 테스트가 이전 버튼 문구를 직접 찾는 경우 그 기대값만 변경한다.
- 레이아웃의 픽셀 값, 장식 요소와 반응형 CSS를 위한 단위 테스트는 새로 만들지 않는다.
- 시각 검증은 `390px`, `768px`, `1280px`에서 다음 항목만 확인한다.
  - 모바일에서 로그인 행동이 과도하게 아래로 밀리지 않는지
  - 태블릿에서 로그인 문구와 버튼이 좁아지거나 잘리지 않는지
  - 데스크톱에서 브랜드와 로그인 영역의 위계가 명확한지
  - 모든 크기에서 가로 넘침과 문구 잘림이 없는지
- 변경 범위의 기존 테스트와 프론트엔드 빌드로 회귀를 확인한다.

## 완료 기준

- 기존 아맞다 로고가 로그인 화면에 표시되고 임시 네 칸 마크는 존재하지 않는다.
- 데스크톱·태블릿은 두 영역, 모바일은 위아래 구조로 표시된다.
- 브랜드 문장과 로그인 문구가 이 명세와 일치한다.
- `환영해요`, `간편 로그인`, `온보딩에서 보던 흐름 그대로`가 사용자 화면에 남지 않는다.
- 로그인 시작, 로딩, 실패 뒤 재시도와 서비스 소개로 돌아가기가 기존 동작을 유지한다.
- 약관 안내는 유지되며 정의되지 않은 연결 주소가 임의로 추가되지 않는다.
- 지정한 세 화면 크기에서 가로 넘침, 잘림과 과도한 빈 공간이 없다.
