# 백로그와 주간 체크리스트 문서 구조 설계

## 배경

현재 `docs/checklist.md`는 기능별 세부 작업, P0/P1/P2 우선순위, 보류 작업, MVP 제외 범위를 관리한다. 일정과 무관하게 재정렬할 수 있도록 작성되어 있어 실제 역할은 체크리스트보다 제품 백로그에 가깝다.

개발 과제에서는 이번 주를 제외한 2주차, 3주차, 4주차의 작업 계획과 다음 주 완료 목표가 필요하다. 따라서 백로그와 주간 실행 계획을 별도 문서로 분리한다.

## 목표

- 현재 `docs/checklist.md`의 작업을 빠짐없이 백로그로 보존한다.
- 구현 여부와 관계없이 계획 대상 작업을 2주차, 3주차, 4주차에 배치한다.
- 각 주차에서 목표, 우선순위, 작업 순서, 완료 기준을 확인할 수 있게 한다.
- 상세 구현 절차는 기존 `docs/superpowers/plans/*.md`에서 계속 관리한다.
- README에서 백로그와 주간 계획에 각각 접근할 수 있게 한다.

## 문서별 역할

### `docs/backlog.md`

- 기존 `docs/checklist.md`의 기능별 세부 작업을 그대로 이어받는다.
- P0, P1, P2, 확인 필요, MVP 제외 범위를 유지한다.
- 일정과 무관한 전체 작업 범위와 우선순위의 기준 문서로 사용한다.
- 백로그의 정의, 필요성, 추가·정제·완료·제외 관리 방법을 문서 앞부분에 설명한다.
- 현재 체크 상태를 임의로 추정하지 않는다.

### `docs/checklist.md`

- 이번 주는 제외하고 2주차, 3주차, 4주차만 다룬다.
- 각 주차는 `주간 목표`, `작업 목록`, `완료 기준`으로 구성한다.
- 작업 항목에는 `[P0]`, `[P1]`, `[P2]`, `[확인 필요]` 우선순위를 표시한다.
- 구현된 기능도 생략하지 않고 계획에 포함한다.
- 기능 단위 체크박스에는 관련 백로그 항목을 연결하고, 상세 구현 계획이 있으면 함께 연결한다.
- 2주차를 다음 주 계획으로 명시하여 다음 주까지 끝낼 범위를 바로 확인할 수 있게 한다.

### `docs/superpowers/plans/*.md`

- 파일 구조, 테스트, 구현 순서 등 실행 가능한 상세 지시서 역할을 유지한다.
- 기존 계획 중 `docs/checklist.md`의 기능 백로그를 참조하는 링크는 `docs/backlog.md`로 변경한다.

## 주차 배분

### 2주차: 기반과 사용자 진입

- 프로젝트 기반
- Supabase 인증
- 데이터 모델과 RLS
- 로그인 후 개인화 온보딩
- Chrome Extension의 MVP 포함 여부 결정

완료 기준은 사용자가 Google 로그인 후 개인화 온보딩을 거쳐 보호된 앱 화면에 진입할 수 있는 것이다.

### 3주차: 저장과 보관의 전체 흐름

- 카테고리 관리
- 인사이트 저장
- 보관함, 인사이트 카드, 검색
- 인사이트 수정과 삭제

완료 기준은 사용자가 링크를 저장하고, 카테고리로 분류하고, 검색하고, 수정하거나 삭제할 수 있는 것이다.

### 4주차: 꺼내보기와 데모 완성도

- URL 메타데이터 수집
- 카테고리 추천
- 꺼내보기
- 실패 상태와 빈 상태
- 보안과 신뢰 점검
- 반응형, 접근성, 사용성 점검
- Chrome Extension이 MVP에 포함된 경우 조건부 구현
- 데모 시나리오, 배포 환경, 최종 빌드 점검

완료 기준은 저장부터 꺼내보기까지의 핵심 시나리오를 주요 화면 크기에서 안정적으로 시연하고 배포 빌드를 통과하는 것이다.

## 링크와 정합성

- README 문서 색인에 `제품 백로그`와 `2~4주차 개발 체크리스트`를 각각 추가한다.
- README의 기존 구현 계획 링크는 유지한다.
- `docs/checklist.md`를 기능 백로그로 참조하던 상세 계획 링크를 `docs/backlog.md`로 변경한다.
- `docs/discussion.md`의 문서화 계획은 실제 생성된 백로그와 주간 체크리스트 역할에 맞게 갱신한다.

## 범위 밖

- 상세 구현 계획의 코드 예시나 테스트 절차를 다시 작성하지 않는다.
- 현재 코드 상태를 조사하여 완료 체크박스를 자동으로 표시하지 않는다.
- MVP 제외 작업을 주간 계획에 배치하지 않는다.
- 아직 결정되지 않은 Chrome Extension을 확정 범위로 간주하지 않는다.
