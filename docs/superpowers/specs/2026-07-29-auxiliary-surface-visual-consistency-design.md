# 보조 화면과 핵심 화면의 시각 일관성 정리 설계

## 문서 상태

- 상태: 사용자 방향 승인 완료, 상세 명세 검토 대기

- 상위 이슈: [#90 인증 후 핵심 앱의 배경색·대표 색상 영역·반응형 내비게이션을 개편한다](https://github.com/ppre1ude/hub/issues/90)
- 기준 브랜치: `feat/92-auxiliary-surfaces-visual-system`

## 1. 배경

`#90`에서 인증 후 홈, 보관함, 저장에 밝기 부담을 낮춘 기본 배경색과 카드·입력 배경색을 적용했다. `#91`에서는 같은 원칙을 랜딩과 로그인에 확장했다. 그러나 포털로 렌더링되는 가져오기·카테고리 대화상자에는 순백색이 남아 있고, 핵심 화면에도 다음과 같은 작은 불일치가 있다.

1. 보관함 카테고리 필터의 색상 표시가 8px이라 이름과 비교해 존재감이 약하다.
2. 홈의 꺼내보기 영역만 제목과 설명이 중앙 정렬되어 보관함·저장의 왼쪽 정렬과 다르다.
3. 저장 화면의 작은 화면 이름 자리에 큰 제목과 같은 설명 문장이 중복된다.
4. 꺼내보기 입력의 검색어 지우기 기호가 44px 버튼 안에서 가로·세로 중앙에 놓이지 않는다.

이번 작업은 새 기능이나 새 화면을 추가하지 않는다. 승인된 시각 체계를 보조 화면까지 이어 가고, 같은 시각 체계를 사용하는 핵심 화면의 예외를 함께 정리한다.

## 2. 목표

- 가져오기와 카테고리 관리 대화상자에서 순백색 면적을 줄인다.
- 대화상자와 PWA 안내처럼 넓게 깔리는 배경면을 인증 후 화면과 일치시킨다.
- 홈, 보관함, 저장의 제목 정렬과 작은 화면 이름을 같은 규칙으로 맞춘다.
- 카테고리 색상 표시와 검색어 지우기 버튼의 시각적 완성도를 높인다.
- 기능, 데이터, 상태와 접근성 동작은 그대로 유지한다.
- 기존 흰색 버튼, 입력과 선택 항목의 색상은 바꾸지 않는다.
- 변경 범위에 직접 필요한 검증만 수행한다.

## 3. 범위 밖

- 가져오기 분석, 반영, 최근 기록과 되돌리기 흐름 변경
- 카테고리 생성, 수정, 삭제와 색상 팔레트 변경
- PWA 설치 노출 조건과 설치 동작 변경
- 홈 제안 문구 개인화
- 화면별 대표 색상 변경
- API, 데이터베이스 스키마와 저장 데이터 변경
- 새로운 아이콘, 애니메이션, 그림자 또는 그라디언트 추가
- 기존 버튼, 입력, 칩과 선택 항목의 배경색 변경
- 변경과 무관한 공용 컴포넌트 재설계

## 4. 승인된 방향

사용자는 세 가지 시각안 가운데 A인 `한 겹의 조용한 표면`을 승인했다.

| 항목                    | 결정                                          |
| ----------------------- | --------------------------------------------- |
| 대화상자                | 카드·입력 배경색을 사용하는 한 겹의 차분한 면 |
| 가져오기 선택 영역      | 기본 배경색으로 작업 영역과 구분              |
| 가져오기 작업 영역      | 카드·입력 배경색 유지                         |
| 카테고리 관리           | 작은 대화상자 안에 배경층을 추가하지 않음     |
| PWA 안내                | 기본 배경 위의 카드·입력 배경색 안내 패널     |
| 보조 화면 대표 색상     | 별도 색상 띠나 장식을 추가하지 않음           |
| 카테고리 필터 색상 표시 | 8px에서 12px로 확대                           |
| 홈 제목 정렬            | 왼쪽 정렬                                     |
| 저장 작은 화면 이름     | `저장`                                        |
| 검색어 지우기           | 44px 버튼 안에서 `×`를 정중앙 정렬            |

강한 색상 띠를 사용하는 B안은 보조 화면을 특정 화면의 대표 색상에 과하게 종속시키므로 제외한다. 여러 카드층을 중첩하는 C안은 작은 보조 작업을 필요 이상으로 무겁게 만들므로 제외한다.

## 5. 배경 역할

### 5.1 공용 대화상자

공용 `Modal`은 WDS 포털을 통해 인증 후 작업공간 바깥에 렌더링된다. 따라서 작업공간의 기본 배경 역할을 상속받지 못한다.

대화상자에서 넓게 깔리는 배경 영역만 카드·입력 배경색으로 지정해 다음 결과를 만든다.

- 대화상자 외곽, Header, Content와 Footer는 카드·입력 배경색을 사용한다.
- 기존 흰색 버튼, 입력, 선택 항목과 내부 카드는 현재 배경색을 유지한다.
- 전역 순백색 토큰 값은 바꾸지 않는다.
- 랜딩, 로그인과 대화상자 밖의 기존 컴포넌트에는 영향을 주지 않는다.
- 현재 공용 `Modal`을 사용하는 가져오기와 카테고리 관리만 같은 규칙을 공유한다.

대화상자에서 `--color-canvas`를 다른 값으로 재정의하지 않는다. 이렇게 해야 자식 버튼과 입력의 흰색까지 함께 바뀌는 일을 막을 수 있다. 공용 경계에는 넓은 배경 영역의 역할만 두고, 화면별 색상이나 가져오기·카테고리 전용 분기를 추가하지 않는다.

### 5.2 가져오기

기존 반응형 정보 구조를 유지한다.

- Desktop·Tablet에서는 왼쪽 가져올 위치 영역만 기본 배경색을 사용한다.
- 오른쪽 작업 영역, Header와 Footer는 카드·입력 배경색을 사용한다.
- 선택한 가져올 위치는 기존 흰색 버튼, 경계와 글자 굵기로 구분한다.
- 입력, 요약 카드, 최근 기록과 Footer 안의 버튼은 현재 흰색을 유지한다.
- Mobile에서는 상단 탭과 작업 영역을 카드·입력 배경색으로 이어 한 화면처럼 보이게 한다.
- 미리보기, 필드 연결, 결과와 최근 기록의 기능·상태 구조는 바꾸지 않는다.

### 5.3 카테고리 관리

카테고리 관리는 작은 작업이므로 내부에 기본 배경색 카드층을 추가하지 않는다.

- 대화상자와 Footer의 넓은 배경면은 카드·입력 배경색을 사용한다.
- 카테고리 행과 버튼은 현재 흰색을 유지한다.
- 카테고리 행은 기존 1px 경계와 44px 최소 높이를 유지한다.
- 생성·수정·삭제 단계의 정보 구조는 바꾸지 않는다.
- 색상 팔레트, 오류와 삭제 확인 표현은 현재 계약을 유지한다.

### 5.4 PWA 안내

PWA 설치 안내는 인증 후 작업공간 안에 있어 현재도 카드·입력 배경색을 상속받는다. 승인한 A안과 이미 일치하므로 불필요한 구조 변경은 하지 않는다.

- 현재 패널, 제목, 설명과 두 행동을 유지한다.
- 안내 패널의 넓은 배경면만 확인하고 두 버튼의 기존 색상은 유지한다.
- 화면별 대표 색상 띠, 아이콘과 장식은 추가하지 않는다.
- Android Chrome 노출 조건과 설치·나중에 행동은 바꾸지 않는다.
- Desktop과 Mobile에서 실제 배경 역할이 유지되는지만 확인한다.

## 6. 핵심 화면 일관성

### 6.1 카테고리 필터 색상 표시

보관함 카테고리 필터의 `.category-filter__mark`를 `var(--spacing-2)` 8px에서 `var(--spacing-3)` 12px로 키운다.

- 버튼 높이, 좌우 여백과 문구 간격은 유지한다.
- 12px은 카테고리 관리 목록의 색상 표시와 같은 크기다.
- 선택 상태는 기존처럼 경계, 글자 굵기와 `aria-pressed`로 전달한다.
- 색상 표시 확대를 선택 상태 표현으로 사용하지 않는다.
- 저장 화면의 카테고리 선택 표시 등 사용자가 요청하지 않은 다른 위치는 함께 키우지 않는다.

### 6.2 홈의 꺼내보기 정렬

홈 대표 색상 영역의 내부 최대 너비와 가운데 배치된 콘텐츠 컨테이너는 유지한다. 컨테이너 안의 내용만 왼쪽 정렬한다.

- 작은 화면 이름 `꺼내보기`
- 큰 제목 `지금 필요한 인사이트를 꺼내 보세요`
- 검색 라벨, 입력과 실행 버튼

Desktop, Tablet과 Mobile에서 같은 왼쪽 기준선을 사용한다. 검색 입력과 버튼의 기존 반응형 배치는 유지한다.

### 6.3 저장의 작은 화면 이름

저장 대표 색상 영역의 작은 화면 이름은 `저장`으로 고정한다.

- 일반 저장 큰 제목: `URL을 입력하면 바로 저장해요`
- 공유 저장 큰 제목: `공유한 링크를 저장할까요?`
- 일반·공유 저장 작은 화면 이름: `저장`

작은 문구는 화면 이름, 큰 제목은 현재 행동을 설명한다. 설명과 상태 문구는 `docs/ux-writing.md`의 해요체를 계속 따른다.

### 6.4 검색어 지우기 버튼

`ClearableTextField`의 검색어 지우기 버튼은 기존 44×44px 터치 영역을 유지하고, 버튼 내용만 가로·세로 중앙에 둔다.

- 접근 가능한 이름 `입력 지우기`를 유지한다.
- 값이 있을 때만 표시한다.
- 클릭 뒤 입력값을 비우고 입력으로 포커스를 돌려주는 동작을 유지한다.
- 클릭이 폼 제출을 일으키지 않는 기존 계약을 유지한다.
- WDS 내부 요소를 직접 수정하지 않고 공용 TextField adapter CSS에서 정렬한다.

## 7. 상태와 접근성

- 오류, 성공과 진행 상태의 색상·아이콘·문구는 변경하지 않는다.
- 가져오기와 카테고리 입력 오류의 `aria-invalid`, `aria-describedby`와 alert 연결을 유지한다.
- 입력, 버튼과 선택 항목의 `:focus-visible` 2px Electric Blue outline을 유지한다.
- 터치 대상은 최소 44px을 유지한다.
- 카테고리 선택은 색 외에 경계, 글자 굵기와 `aria-pressed`로 전달한다.
- 검색어 지우기 버튼의 시각 위치를 바꿔도 접근 가능한 이름과 키보드 순서는 유지한다.
- 배경면 변경이 버튼, 입력과 선택 항목의 기존 색상 및 상태 색상을 덮어쓰지 않아야 한다.

## 8. 반응형 기준

| 구간         | 가져오기                          | 카테고리 관리      | 홈·저장                                   |
| ------------ | --------------------------------- | ------------------ | ----------------------------------------- |
| `768px` 이상 | 왼쪽 선택 영역과 오른쪽 작업 영역 | 작은 팝업 대화상자 | 820px 또는 720px 내부 컨테이너, 왼쪽 정렬 |
| `767px` 이하 | 전체 화면, 상단 소스 탭           | 가용 폭 대화상자   | 한 열, 왼쪽 정렬                          |

가져오기 대화상자의 기존 `768px` 반응형 분기와 Mobile 안전 영역을 유지한다. 이번 작업 때문에 새 breakpoint를 추가하지 않는다.

## 9. 코드 경계

- 공용 대화상자 배경 역할: `src/shared/ui/modal`
- 검색어 지우기 정렬: `src/shared/ui/text-field`
- 가져오기 화면 구분: `src/features/insight-import/ui`
- PWA 안내 확인: `src/features/pwa-install/ui`
- 카테고리 표시 크기: `src/shared/ui/category-filter`
- 홈 정렬: `src/pages/home/ui`
- 저장 작은 화면 이름: `src/pages/save/ui`

기존 FSD 경계를 유지한다. 시각 값은 `DESIGN.md`의 토큰만 사용하고 raw 색상 값을 추가하지 않는다. 단순한 스타일 변경을 위해 새 공용 컴포넌트를 만들지 않는다.

## 10. 데이터와 동작 계약

이번 작업은 표현 계층의 변경이다.

- 라우트와 내비게이션 목적지는 유지한다.
- 검색, 꺼내보기, 저장, 가져오기와 카테고리 관리 동작은 유지한다.
- API 요청·응답과 데이터베이스 스키마는 변경하지 않는다.
- PWA 설치 안내의 노출 기록과 브라우저 분기는 유지한다.
- 카테고리 색상 키와 팔레트 값은 변경하지 않는다.
- 버튼, 입력과 선택 항목의 기존 색상 계약은 유지한다.

## 11. 최소 검증

새로운 테스트 종류를 늘리지 않는다.

### 자동 검증

- 의도한 문구가 바뀌는 저장 화면의 기존 테스트만 수정한다.
- 직접 수정한 공용 대화상자와 가져오기 CSS 계약의 기존 테스트를 실행한다.
- 홈과 저장의 기존 화면 테스트를 실행한다.
- 검색어 지우기 동작 테스트는 기존 테스트를 그대로 사용하며 새 시나리오를 추가하지 않는다.
- 순수 CSS 크기와 정렬을 고정하는 새 단위 테스트는 만들지 않는다.

### 수동 검증

- `390px`, `768px`, `1280px`에서 가져오기와 카테고리 관리 대화상자의 배경과 스크롤 경계를 확인한다.
- 같은 화면에서 흰색 버튼, 입력과 선택 항목의 배경색이 바뀌지 않았는지 확인한다.
- 같은 세 너비에서 홈 제목의 왼쪽 기준선과 저장의 작은 화면 이름을 확인한다.
- 보관함 카테고리 색상 표시가 12px으로 보이고 문구를 압박하지 않는지 확인한다.
- 꺼내보기 입력에 값이 있을 때 `×`가 44px 버튼 중앙에 놓이는지 확인한다.
- PWA 안내는 현재 A안과 일치하는지 확인하고, 일치한다면 코드 변경 없이 검증 기록만 남긴다.

변경하지 않은 사용자 여정, API, 저장소와 다른 화면의 테스트는 실행 범위에 추가하지 않는다.

## 12. 완료 기준

- 가져오기와 카테고리 관리 대화상자가 카드·입력 배경색을 사용한다.
- 가져오기 Desktop·Tablet의 왼쪽 선택 영역만 기본 배경색으로 구분된다.
- 기존 흰색 버튼, 입력, 카테고리 행과 선택 항목의 색상은 유지된다.
- PWA 안내가 별도 장식 없이 카드·입력 배경색 패널로 유지된다.
- 보관함 카테고리 필터의 색상 표시가 12px이다.
- 홈 대표 색상 영역의 제목과 검색이 왼쪽 정렬이다.
- 저장의 작은 화면 이름이 일반·공유 저장 모두 `저장`이다.
- 검색어 지우기 `×`가 44px 버튼 안에서 정중앙에 놓인다.
- 상태, 오류, 키보드 초점과 기능 동작에 회귀가 없다.
- 기능, API, 데이터 계약과 데이터베이스 스키마가 변경되지 않는다.
- 변경 범위와 무관한 테스트를 추가하지 않는다.
