# 오답노트 상세 모달 인라인 편집 설계

## 목표

오답노트 상세 모달을 수동 작성 페이지와 같은 폼 계층으로 정리하고, 자동 저장·직접 작성 여부와 관계없이 모달 안에서 모든 학습 내용을 수정할 수 있게 한다.

## 사용자 흐름

1. 목록 행을 선택하면 상세 모달이 읽기 모드로 열린다.
2. 출처, 레슨 이름, 레슨 ID, 실패 내용, 실패 이유, 수정 힌트를 작성 페이지와 같은 필드 순서로 보여준다.
3. `수정`을 누르면 동일한 필드가 입력 컨트롤로 전환된다.
4. `취소`는 서버 요청 없이 현재 저장값으로 되돌린다.
5. `저장`은 모든 편집 필드를 검증한 뒤 서버 또는 mock store에 반영한다.
6. 저장 성공 시 서버가 반환한 오답으로 목록과 모달을 갱신하고 읽기 모드로 돌아간다.
7. 저장 실패 시 편집값과 모달을 유지하고 원인과 재시도 행동을 표시한다.

## 편집 범위

다음 필드를 모두 편집할 수 있다.

- `source`
- `lessonTitle`
- `lessonId`
- `command`
- `reason`
- `correction`

`id`, `createdAt`, `reviewedAt`, `status`는 내용 편집에서 보존한다. 상태 전환은 기존 `해결로 표시`·`미해결로 되돌리기` 액션으로 처리한다. 출처나 레슨 ID가 바뀌면 `다시 풀기` 경로도 갱신된 오답을 기준으로 다시 계산한다.

## 화면 구조

- 모달 헤더: 출처·레슨 ID·상태 배지, 레슨 제목, 닫기
- 모달 본문: 작성 페이지와 동일한 출처 선택, 레슨 정보, 오답 내용 섹션
- 읽기 모드: 폼과 같은 배치의 비활성/읽기 전용 필드
- 편집 모드: 작성 페이지의 라벨과 입력 유형을 재사용한 활성 필드
- 푸터: 읽기 모드에는 `다시 풀기`, `수정`, 상태 전환, `삭제`, `닫기`; 편집 모드에는 `취소`, `저장`

저장 중에는 중복 요청을 막고 `저장 중` 문구를 표시한다. 필수값 누락은 서버 요청 전에 필드 근처와 요약 오류로 안내한다.

## 데이터와 API

기존 `PATCH /api/mistake-notes/:noteId`는 상태 변경 계약을 유지하면서 전체 내용 수정 요청도 받는다.

```ts
type UpdateMistakeNoteContentRequest = Pick<
  MistakeNote,
  'source' | 'lessonTitle' | 'lessonId' | 'command' | 'reason' | 'correction'
>
```

백엔드는 기존 오답을 조회하고 요청 내용을 정규화한 뒤 `id`, 생성·복습 시각, 상태를 보존하여 저장한다. 프론트엔드는 server mode에서 응답으로 받은 오답만 store에 upsert한다. mock mode에서는 같은 보존 규칙으로 로컬 store를 갱신한다.

## 오류 처리

- 존재하지 않는 오답: `404`
- 비어 있거나 지원하지 않는 필드: `400`
- 저장소 오류: 기존 공통 repository 오류 응답
- 프론트 저장 실패: 모달과 draft 유지, 저장 재시도 허용
- 저장 중 닫기: 닫기와 배경 클릭을 비활성화하여 결과 유실 방지

## 검증

위험 기반 검증을 적용한다.

- 도메인: 내용 수정 시 메타데이터 보존과 필수값 검증
- API: 전체 내용 PATCH 성공·400·404
- 프론트 client: URL, method, body
- 모달: 읽기→편집→취소, 저장 성공, 저장 실패 시 draft 유지
- 최종: typecheck, lint, 전체 테스트, build, Supabase 수정 왕복 smoke

- 여러 오답 일괄 편집
- AI 자동 해설 재생성
