# 홈·보관함 UI 개선 설계

## 배경

현재 홈의 `꺼내보기` 영역은 인증 전 온보딩에서 이미 전달한 제품 설명을 반복하고, 넓은 작업 공간의 왼쪽에 붙어 보여 핵심 입력이 시각적으로 중앙에 놓이지 않는다. 추천 상황은 카테고리명에 가까워 사용자가 실제로 눌러볼 상황으로 읽히지 않으며, 입력 전에는 같은 행동을 다시 안내하는 별도 초기 영역이 노출된다.

인사이트 카드는 도메인의 앞 두 글자를 확대한 가상 썸네일과 `작업팩`, 연결 단서를 함께 표시해 실제 콘텐츠보다 내부 개념과 장식이 먼저 보인다. 보관함도 같은 카드를 공유하므로 카드의 정보 위계 문제는 두 화면에 함께 영향을 준다.

## 목표

- 홈의 핵심 검색 영역을 사용자가 명확히 중앙으로 인식하도록 배치한다.
- 인증 이후에는 제품 소개를 반복하지 않고 현재 행동에 필요한 문구만 남긴다.
- 실제 설문에 근거한 상황형 예시로 `꺼내보기`를 시작하게 한다.
- 예시 선택, 직접 입력, 실행, 초기화가 같은 위치에서 끊김 없이 이어지게 한다.
- 인사이트 카드는 제목, 메모, 카테고리와 원문 행동이 먼저 읽히게 한다.
- 홈과 보관함의 화면 컴포넌트를 책임별로 분리하되 현재 FSD 경계를 유지한다.

## 비목표

- 다중 카테고리 저장, 편집, 데이터 마이그레이션은 포함하지 않는다.
- AI 추천, 의미 검색, 자동 상황 판단은 추가하지 않는다.
- 현재 검색 점수와 상위 6개 랭킹 규칙은 바꾸지 않는다.
- 보관함의 편집·삭제·안전하지 않은 URL 처리 동작은 바꾸지 않는다.
- 인증 전 온보딩과 저장 화면은 이번 범위에 포함하지 않는다.

## 사용자 조사 반영

최근 저장 목적을 묻는 15명 복수 선택 설문은 다음 경향을 보였다.

- 공부·학습·과제: 15명, 100%
- 개인 업무·프로젝트: 8명, 53.3%
- 공모전·경진대회 등 대외활동: 8명, 53.3%
- 취미: 6명, 40%
- 디자인·개발 레퍼런스: 5명, 33.3%
- 나중에 볼 동영상: 5명, 33.3%
- 뉴스·읽을거리: 2명, 13.3%

설문의 저장 목적을 카테고리명으로 복사하지 않고, 사용자가 바로 실행할 수 있는 현재 행동으로 바꾼다.

1. 과제 참고자료 다시 찾기
2. 프로젝트에 쓸 자료 꺼내기
3. 공모전 아이디어 발전시키기
4. 여행·취미 계획 다시 이어가기
5. 디자인·개발 레퍼런스 찾기
6. 저장해둔 영상 골라보기

기본 여섯 개에는 응답이 가장 적은 뉴스·읽을거리를 넣지 않는다. 사용자는 같은 입력창에서 원하는 상황을 자유롭게 입력할 수 있다.

## 홈 화면

### 시각적 위계

상단 `꺼내보기` 영역은 최대 너비가 제한된 열을 작업 공간 가운데에 배치한다. 제목, 입력창, 예시 상황이 같은 중심축을 공유해 CSS 수치가 아니라 사용자가 보기에 중앙으로 인식되어야 한다.

- 작은 라벨: `꺼내보기`
- 제목: `지금 필요한 인사이트를 다시 꺼내보세요`
- 보이는 입력 라벨: `지금 꺼내보고 싶은 상황`
- 입력 placeholder: `예: 과제 참고자료 다시 찾기`
- 실행 버튼: `꺼내보기`
- 도움말: `떠오르는 단어나 지금 하고 있는 일을 짧게 적어보세요.`

`아맞다는 저장해둔 링크와 메모를...` 제품 소개 문단은 제거한다. 온보딩에서 이미 설명한 내용이며 인증 후 홈의 행동 목적과 맞지 않는다.

### 입력과 예시 상황

예시 상황은 입력창 아래에 정렬된 선택 버튼으로 항상 노출한다. 예시를 누르면 해당 query를 입력하고 즉시 결과를 계산한다. 직접 입력한 경우에는 `꺼내보기` 버튼이나 Enter로 실행한다.

입력값이 있을 때만 입력 내부에 × 초기화 버튼을 노출한다. 접근 가능한 이름은 `입력 지우기`로 제공하지만 별도 보이는 문구는 추가하지 않는다. 초기화를 누르면 다음 검색 상태만 비운다.

- 현재 입력값
- 선택된 예시 상황
- 제출된 query와 결과

도움말과 예시 버튼은 검색 전후 모두 같은 자리에 유지한다. 초기화로 별도 화면 전환이나 재등장 연출을 만들지 않는다.

### 초기·결과·빈 상태

저장된 인사이트가 있고 제출 query가 없을 때 별도의 `상황 예시 / 이런 상황에서 시작해보세요` 영역을 렌더링하지 않는다. 검색 열 아래 도움말로 충분하다.

결과가 있으면 넓은 결과 영역에 `지금 상황에 맞는 인사이트` 제목과 카드를 표시한다. `작업팩` 용어는 사용자에게 노출하지 않는다. 결과 상태 문구는 내부 개념 대신 query와 결과 개수만 전달한다.

결과가 없으면 입력값을 유지하고 단어를 줄이거나 다른 예시를 선택하도록 안내한다. 보관함 로딩, 원격 조회 실패, 저장 인사이트 없음 상태의 기존 복구 행동은 유지한다.

## 보관함 화면

보관함은 관리 화면이므로 카드 그리드는 넓은 작업 공간을 사용한다. 다만 화면 제목·설명과 카테고리·검색 도구는 제한된 열 안에서 중앙에 배치해 홈과 같은 시각적 중심축을 공유한다.

- 보관함 제목과 설명은 가운데 정렬한다.
- 인사이트 개수는 제목 블록과 함께 읽히도록 배치한다.
- 카테고리 필터는 데스크톱에서 가운데 정렬하고, 모바일에서는 첫 항목이 잘리지 않도록 왼쪽에서 시작하는 가로 스크롤을 사용한다.
- 검색 입력은 제한된 너비로 중앙에 두되 보이는 라벨은 입력 기준으로 왼쪽 정렬한다.
- 결과 카드 그리드와 빈 상태, 편집·삭제 동작은 현재 넓은 콘텐츠 영역을 유지한다.

## 인사이트 카드 A3

홈과 보관함은 같은 `InsightGrid`와 `InsightCard`를 공유한다.

- 도메인 앞 두 글자를 보여주는 가상 썸네일을 제거한다.
- 상단 색상 띠나 별도 장식 색면을 추가하지 않는다.
- 연결 단서와 강조 세로선을 사용자에게 표시하지 않는다.
- 제목, 선택적 메모, 선택적 카테고리 태그 순서로 본문을 구성한다.
- 카테고리가 있으면 기존 카테고리별 tone을 태그에만 적용한다.
- 카테고리가 없으면 `미분류`나 `카테고리 없음`을 카드에 표시하지 않는다.
- 원문 열기, 수정, 삭제와 오류·포커스 복구 동작은 유지한다.

현재 데이터 계약은 단일 카테고리다. 태그 목록 CSS는 줄바꿈 가능한 구조를 유지해 미래의 다중 카테고리 화면을 막지 않지만, 이번 작업에서 배열 타입이나 저장 계약으로 확장하지 않는다.

## 연결 단서와 검색 코어

사용자는 결과 선정 과정을 납득하기 위한 별도 설명이 필요하지 않다. 제목, 메모와 카테고리로 필요한 자료인지 직접 판단할 수 있다. 따라서 일치 필드와 점수는 정렬 계산에만 사용하고 카드에는 연결 단서를 전달하지 않는다.

현재 `retrieveInsights`의 검색 점수, 일치 토큰, 상위 6개 결과 계약은 유지한다. 사용자에게 쓰이지 않는 연결 단서 문자열 생성은 제거해 도메인 모델과 UI 계약을 단순화한다. 활성 제품 문서의 `작업팩`, 사용자 노출 연결 단서 표현도 새 결정에 맞춰 갱신한다.

## 컴포넌트 경계

현재 `HomePage`와 `insight_grid.tsx`에 집중된 책임을 다음처럼 나눈다.

- `HomePage`: 원격 보관함 상태와 검색 결과 상태를 조합한다.
- `RetrieveSearchPanel`: 제목, 입력, 실행, 초기화, 예시 상황, 도움말을 렌더링한다.
- `RetrieveResults`: 결과 제목·상태, 카드 그리드, 결과 없음 복구 행동을 렌더링한다.
- `InsightGrid`: 인사이트 배열을 카드 목록으로 변환한다.
- `InsightCard`: 읽기, 편집, 삭제, 원문 열기와 포커스 복구를 담당한다.

새 컴포넌트는 각각 기존 page 또는 entity slice 내부에 두며 public API를 불필요하게 늘리지 않는다. `snake_case` 파일명과 named export 규칙을 유지한다.

## 반응형과 접근성

- 데스크톱에서 홈 입력 열은 명확히 중앙에 두고 결과 그리드는 3열을 사용한다.
- 중간 화면은 결과 2열, 모바일은 1열로 유지한다.
- 모바일에서 검색 버튼은 입력 아래 전체 너비로 이동할 수 있다.
- 입력의 보이는 label과 상태 메시지의 live region을 유지한다.
- × 버튼은 값이 있을 때만 키보드와 스크린 리더 탐색 대상이 된다.
- 예시 상황 선택 상태는 `aria-pressed`를 유지한다.
- 편집 완료·취소와 삭제 완료·취소 후 기존 포커스 복구 계약을 유지한다.
- 새 색상은 추가하지 않고 `DESIGN.md`와 런타임 design token만 사용한다.

## 검증

자동 테스트는 다음을 확인한다.

- 인증 후 제품 소개와 초기 안내 영역이 렌더링되지 않는다.
- 설문 기반 예시 여섯 개가 정확히 표시된다.
- 예시 선택은 입력과 제출 query를 함께 갱신한다.
- 초기화는 query, 선택 상태와 결과만 비우고 예시를 유지한다.
- `작업팩`, 연결 단서와 가상 썸네일이 표시되지 않는다.
- 카테고리가 있을 때 tone 태그를 표시하고 없을 때 태그 영역을 숨긴다.
- 홈과 보관함의 로딩·빈 상태·오류·편집·삭제 동작이 회귀하지 않는다.
- 390px, 768px, 1280px에서 중앙 입력 열과 카드 열 수를 확인한다.

전체 기준 테스트는 Windows CRLF 환경에서 `server/supabase_migration_ci.test.ts` 한 건이 기존 정규식 제약으로 실패한다. 이번 변경과 직접 관련된 테스트, 린트, 포맷 검사와 빌드는 별도로 통과시킨다.
