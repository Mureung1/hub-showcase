# 웹 레이아웃 리디자인 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 모바일 앱 형태의 프론트엔드를 데스크톱 웹사이트 레이아웃으로 바꾼다. 기능은 일절 바꾸지 않는다.

**Architecture:** 440px 단일 컬럼 + 하단 탭바를 걷어내고, 상단 sticky `SiteHeader` + 1200px/720px 2단 폭 컨테이너로 교체한다. 디자인 토큰(`tokens.css`)을 웜 미니멀 팔레트로 갈아끼워 글래스·그라데이션·큰 그림자를 제거하고, 카드 경계를 1px 보더가 담당하게 한다. 페이지는 아래에서 위로(토큰 → 셸 → 공용 컴포넌트 → 개별 페이지) 순서로 바꾼다.

**Tech Stack:** React 19 + Vite, react-router-dom(HashRouter), 순수 CSS(전처리기·유틸리티 프레임워크 없음), CSS 변수 기반 토큰.

**설계 문서:** `docs/superpowers/specs/2026-07-24-웹레이아웃-리디자인-design.md`

## Global Constraints

- **백엔드는 한 줄도 건드리지 않는다.** BE 테스트 187개는 이 작업의 안전 근거가 아니다.
- **로직 변경 금지.** `fetchMeetings` 등 API 호출, `useState`/`useEffect` 구조, 폼 제출 핸들러, 조건 판정식은 그대로 둔다. 이 작업은 **마크업과 CSS만** 바꾼다. 조건식을 옮길 때 `&&`/삼항의 조건 자체를 재작성하지 않는다.
- **FE에는 자동화 테스트가 없다.** 검증은 `npm run lint` + `npm run build` + 육안 확인뿐이다. lint/build는 문법 오류만 잡고 "버튼이 사라졌다"·"라운드가 0이 됐다"는 잡지 못한다. **각 태스크의 육안 확인 단계를 건너뛰면 검증이 없는 것과 같다.**
- **lint 기준선:** `AppStateContext.jsx` 경고 **1건**은 원래 있던 것이다. 이 1건은 그대로 두고, **경고가 2건 이상이 되면 실패로 본다.**
- **build는 클린해야 한다.**
- 작업 디렉터리는 `bungae-moim/` (프론트). 명령은 전부 이 디렉터리에서 실행한다.
- 커밋 메시지는 **한글**로 쓰고 `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>` 트레일러를 붙인다.
- 색상 값은 설계 문서의 토큰 표를 **그대로** 쓴다. 임의로 조정하지 않는다.

- [ ] **Step 1: `SiteHeader.jsx` 생성**

`src/components/SiteHeader.jsx`를 새로 만든다.

```jsx
import { Link, NavLink } from 'react-router-dom'
import { useAppState } from '../context/AppStateContext.jsx'
import TrustBadge from './TrustBadge.jsx'

// minimal: 생년월일 게이트에서 쓴다. 어차피 이동할 수 없는 상태라 가운데 nav를 숨긴다.
export default function SiteHeader({ minimal = false }) {
  const { currentUser, isLoggedIn, authLoading, logout } = useAppState()

  return (
    <header className="site-header">
      <div className="site-header-inner">
        <Link to="/" className="site-brand">
          ⚡ 번개모임
        </Link>

        {!minimal && (
          <nav className="site-nav" aria-label="주요 메뉴">
            <NavLink
              to="/meetings"
              className={({ isActive }) => `site-nav-link${isActive ? ' active' : ''}`}
            >
              모임 찾기
            </NavLink>
            <NavLink
              to="/meetings/new"
              className={({ isActive }) => `site-nav-link${isActive ? ' active' : ''}`}
            >
              모임 등록
            </NavLink>
          </nav>
        )}

        {/* authLoading 중에는 비워둔다. 비우지 않으면 "로그인" -> "이상진"으로 깜빡인다. */}
        <div className="site-header-right">
          {!authLoading && !isLoggedIn && (
            <Link to="/login" className="pill-btn pill-btn--accent pill-btn--sm">
              로그인
            </Link>
          )}

          {!authLoading && isLoggedIn && (
            <>
              <span className="site-user">
                <span className="site-user-name">{currentUser.nickname}</span>
                {/* MyPage:70과 같은 방식으로 그대로 넘긴다. 서버의 normalizeUser가
                    trust_score를 Number()로 변환해 내려주고, 비로그인 GUEST_USER도
                    trustScore: 0이라 TrustBadge의 toFixed(1)이 안전하다. */}
                <TrustBadge score={currentUser.trustScore} />
              </span>
              <span className="site-header-divider" aria-hidden="true" />
              <NavLink
                to="/mypage"
                className={({ isActive }) => `site-nav-link${isActive ? ' active' : ''}`}
              >
                마이페이지
              </NavLink>
              <button type="button" className="site-nav-link site-nav-button" onClick={logout}>
                로그아웃
              </button>
            </>
          )}
        </div>
      </div>
    </header>
  )
}
```

- [ ] **Step 3: `App.jsx` 교체**

`src/App.jsx`를 아래로 대체한다. `Atmosphere`/`BottomNav` import와 렌더를 지우고 `SiteHeader`를 넣는다. **라우트 목록과 `needsBirthDate` 판정식은 그대로 둔다.**

```jsx
import { Routes, Route } from 'react-router-dom'
import { AppStateProvider, useAppState } from './context/AppStateContext.jsx'
import SiteHeader from './components/SiteHeader.jsx'
import HomePage from './pages/HomePage.jsx'
import MeetingListPage from './pages/MeetingListPage.jsx'
import MeetingDetailPage from './pages/MeetingDetailPage.jsx'
import MeetingCreatePage from './pages/MeetingCreatePage.jsx'
import MeetingEditPage from './pages/MeetingEditPage.jsx'
import LoginPage from './pages/LoginPage.jsx'
import MyPage from './pages/MyPage.jsx'
import BirthDateGate from './pages/BirthDateGate.jsx'

// 라우트/게이트 분기는 컨텍스트를 읽어야 하므로 Provider 안쪽의 별도 컴포넌트에서 처리한다.
function AppContent() {
  const { authLoading, isLoggedIn, currentUser } = useAppState()
  // 로그인했는데 생년월일이 없으면 다른 화면으로 못 가고 입력부터 받는다(기획서 6.1).
  const needsBirthDate = !authLoading && isLoggedIn && currentUser.birthDate == null

  return (
    <div className="app-shell">
      <SiteHeader minimal={needsBirthDate} />
      <div className="page">
        {needsBirthDate ? (
          <BirthDateGate />
        ) : (
          <Routes>
            <Route path="/" element={<HomePage />} />
            <Route path="/meetings" element={<MeetingListPage />} />
            <Route path="/meetings/new" element={<MeetingCreatePage />} />
            <Route path="/meetings/:id/edit" element={<MeetingEditPage />} />
            <Route path="/meetings/:id" element={<MeetingDetailPage />} />
            <Route path="/login" element={<LoginPage />} />
            <Route path="/mypage" element={<MyPage />} />
          </Routes>
        )}
      </div>
    </div>
```
