## 퀵윈 팩 (5건)

구현 순서: 작은 것 → 문자 → 편집 → 데이터. 5건 독립적이라 순서 유연.

### QW-5 · 쿠폰 짧은 코드 (XS)
`apps/server/src/db/queries.ts`. `newCouponCode()` `"WP"+8hex`(10자) → **헷갈림 없는 5자**(0·O·1·I·L 제외 알파벳+숫자). `issueCouponsFor` insert 유니크 충돌 시 1회 재생성. (선택) FE `api/client.ts` `mockCouponCode` 정렬.
- **DoD**: 발송 문자 "쿠폰코드 XXXXX"가 5자, redeem 정상.

### QW-2 + QW-3 · 문자 무료수신거부 간격 + 이모지 제거 (M)
`packages/shared`에 문자 본문 조립 공용 유틸(`stripEmoji`, `buildSmsBody`) 신설 → **미리보기 = 실제 발송** 일치. BE `legal/filter.ts` `buildAdMessage`·FE `App.tsx`(미리보기)가 공용으로 사용. 무료수신거부 앞 빈 줄 2~3줄, 문자 경로에서만 이모지 제거(SNS·대시보드는 유지).
- **DoD**: 문자 본문에 이모지 없음 + 무료수신거부가 2~3줄 아래. `filter.test.ts` 기대값 갱신 + `stripEmoji` 단위테스트(로드맵 F-1 DoD 충족).

### QW-4 · 쿠폰 할인율 사장님 편집 (M)
`packages/shared` `CampaignPatchRequest`에 `editedPromo` 추가. BE `PATCH /campaigns/:id`가 `editedPromo`를 마이그레이션 없이 `proposal.promo`에 병합 저장(jsonb read-modify-write). 발송(`POST /:id/send`)은 편집 반영본 기준 + **발송 직전 서버 가드레일 ≤20% 재검사**(`agent/guardrails.ts` 재사용). FE EditView에 할인율 입력.
- **DoD**: 15%→10% 편집이 미리보기·쿠폰·발송문구에 반영, 21% 입력은 서버가 400.

### QW-1 · 진단·매출·소스배지 실데이터화 (L)
`apps/web/src/api/todayScenario.ts` `scenarioFromApi`가 diagnosis를 안 받아 매출·진단%·소스배지가 mock 플레이스홀더(소스배지는 `App.tsx`에 "AccuWeather 3개" 하드코딩). BE `GET /proposal/today`에 `diagnosis` 추가(저장 안 되므로 `diagnose(getSalesWithWeather, category)` 재계산), shared `ProposalTodayFound`에 `diagnosis` 추가, FE 어댑터가 소스배지(`weather.sources`/`sourceCount`)·진단 편차%(`byCondition`)·매출 타일(`baselineRevenue`×delta)을 실데이터로 렌더. 7일 스파크라인은 실 일별매출이 FE에 없어 **이번 스코프 제외**(후속 `GET /sales/recent`).
- **DoD**: 실모드에서 진단·매출·소스배지가 백엔드 값과 일치("흐린 날인데 맑은 날 +12%" 모순 해소, 소스 "2개 kma·owm").
