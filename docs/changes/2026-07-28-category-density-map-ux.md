# 업종 Top 7·점포 밀도 지도 UX 변경 기록

## 문서 목적

이 문서는 연남·홍대·합정 지원 상권의 업종 선택, 점포 밀도 지도, 건물 표현, 선택 점포 3D 강조를 하나의 변경 기록으로 관리한다. 같은 기능에 대해 여러 개의 일회성 Markdown을 만들지 않고 관련 후속 수정도 이 문서에 이어서 기록한다.

## 적용 범위

- 지원 상권: 연남, 홍대, 합정
- API: `/api/v1/catalog`, 선택 상권 점포 조회와 분석 API
- Web: 업종 선택 패널, 밀도 지도, 3D 건물, 선택 점포 강조, URL 상태 복원

## 1. 데이터 기반 업종 Top 7

운영 DB에서 지원 상권에 연결된 점포를 조회한 뒤 `store_id` 기준으로 중복을 제거한다. 각 점포는 소분류 → 중분류 → 대분류 순으로 확인하여 최초 일치하는 사용자용 업종 그룹 하나에만 배정한다.

순위 기준은 다음과 같다.

1. 고유 점포 수 내림차순
2. 포함 상권 수 내림차순
3. 업종 이름 오름차순

API가 운영 DB를 사용할 수 없을 때는 카페·음식점·베이커리·편의점 네 업종을 bootstrap 목록으로 제공한다. 준비 중·bootstrap·오류 상태는 실제 데이터 순위처럼 보이지 않도록 서로 다른 안내문과 재시도 동작을 제공한다.

## 2. 업종 선택 UX

업종 패널은 API가 반환한 업종을 모두 표시하며 데이터 기반 응답에서는 최대 7개를 노출한다.

각 항목은 다음 정보를 제공한다.

- 순위
- 업종명
- 업종별 아이콘
- 고유 점포 수
- 부분 지원 업종의 `일부` 배지
- 현재 선택 상태

부분 지원 업종도 선택 상태를 유지한다. 전체 지원 업종은 매출·유동인구·점수 등 기존 분석 지표와 연결하고, 부분 지원 업종은 점포 위치와 경쟁 지표 중심으로 제공한다.

## 3. 점포 밀도 지도

점포 밀도 모드는 선택 업종의 실제 점포 좌표를 GeoJSON Point FeatureCollection으로 변환하고 MapLibre heatmap layer로 표시한다.

선택 상권·업종 범위의 점포는 반경 기반 `nearby` 제한이나 3D 오브젝트 수 제한을 적용하지 않고 heatmap 데이터에 전달한다.

- zoom 15.7 미만: heatmap 우선, DOM 점포 marker 숨김
- zoom 15.7 이상: 점포 marker 표시
- zoom 16.2 이상: heatmap을 빠르게 약화
- zoom 18: heatmap opacity 0

공통 색상 단계는 다음과 같다.

| 단계 | 색상 | 의미 |
| --- | --- | --- |
| 낮음 | 파랑 `#3b82f6` | 점포가 상대적으로 적게 모인 구간 |
| 보통 | 주황 `#f59e0b` | 중간 수준으로 모인 구간 |
| 높음 | 빨강 `#ef4444` | 점포가 상대적으로 많이 모인 구간 |
| 최고 밀집 | 진한 빨강 `#b91c1c` | heatmap 최고 강도 |

유동 수요 모드에서는 밀도 범례를 재사용하지 않는다.

## 4. 기본 건물 표현과 데이터 소유권

분석 모드와 3D 점포 모드의 기본 건물 정책은 다음과 같다.

- 선택한 지원 상권 내부: LocalTwin overlay의 색상 건물
- 선택한 지원 상권 외부: OpenMapTiles의 회색 단일색 건물
- 실제 지도 모드: LocalTwin 추가 3D 건물과 선택 효과를 표시하지 않음

두 건물 데이터는 같은 위치에 동시에 표시하지 않는다.

1. OpenMapTiles 건물은 선택 상권 polygon 밖에서만 렌더링한다.
2. LocalTwin 건물은 같은 polygon 안에서만 렌더링한다.
3. 경계 판정에는 동일한 공식 상권 geometry를 사용한다.
4. 지원 상권 내부에서 OpenMapTiles와 LocalTwin extrusion을 겹쳐 그리지 않는다.

LocalTwin 건물은 `palette` 속성에 따라 기존 파스텔 계열을 사용한다. 이 색상은 밀집도·점수·업종을 뜻하는 분석 색상이 아니라 지원 범위를 시각적으로 구분하는 기본 건물 표현이다.

## 5. 선택 점포 3D 집중 표현

기존 건물을 업종별 점포 건물로 교체하는 방식은 활성 사용자 흐름에서 사용하지 않는다. 실제 건물은 숨기거나 납작하게 만들지 않는다.

3D 점포 모드의 동작은 다음과 같다.

1. 업종만 선택한 상태에서는 실제 건물과 점포 marker를 표시한다.
2. 사용자가 특정 점포를 클릭해야 3D 집중 효과를 생성한다.
3. 선택 점포를 지도 중심 근처로 이동하고 zoom 16.8로 진입한다.
4. 점포가 연결된 LocalTwin 건물을 찾으면 해당 건물 중심과 지붕 높이를 기준으로 효과를 배치한다.
5. 건물 연결에 실패하면 점포 좌표를 사용하되 기존 건물은 그대로 둔다.

선택 효과는 다음 요소로 구성한다.

- 지붕 또는 점포 좌표의 이중 원형 target
- 노란색 반투명 spotlight cone
- 수직 light stem
- 업종별 독립 3D category object
- 천천히 회전하는 category object
- pulse 애니메이션이 적용된 target ring
- 기존 점포 정보 Popup과 우측 상세 패널

한 화면에는 선택 점포의 집중 오브젝트 하나만 생성한다. 주변 점포를 임의로 3D 건물이나 옥상 오브젝트로 바꾸지 않는다.

## 6. 업종별 3D category object

기존 Three.js category geometry를 선택 집중 효과에 재사용한다.

- 카페: 커피잔
- 음식점: 그릇과 식기
- 베이커리: 빵
- 편의점: 편의점 간판
- 꽃집: 꽃
- 미용: 거울
- 의류: 행거와 옷
- 학원: 책
- 숙박: 침대
- 체육: 덤벨
- 기타 서비스: 일반 서비스 표식

오브젝트는 실제 건물을 대체하지 않으므로 건물 높이만큼 강제로 늘리지 않는다. 건물 부지 기준 목표 폭을 약 2.8~4.8m로 제한하고 균일 비율을 사용해 원래 형태를 유지한다.

## 7. 점포 marker 가독성

3D 점포 모드의 일반 marker는 선택 집중 효과보다 약하게 표시한다.

- 일반 fallback marker opacity: 0.66
- 상세 fallback marker: 32×32px
- clustered fallback marker: 30×30px
- 흰색 halo와 그림자 강도 축소
- hover·keyboard focus·선택 상태에서만 opacity 1
- 선택 집중 오브젝트로 표현된 점포의 기존 marker는 중복 표시하지 않음

## 8. 새로고침과 URL 상태 복원

사용자가 변경한 상태를 URL query parameter에 계속 기록한다. URL을 기준 상태로 사용하므로 새로고침, 링크 공유, 브라우저 이동에서 같은 분석 맥락을 복원할 수 있다.

저장 항목은 다음과 같다.

- 선택 상권
- 대표 업종과 실제 선택 업종명·코드
- 분석 반경
- 밀도·수요 layer
- 분석 topic
- 상권 경계와 점포 표시 여부
- 선택 분기
- 확정 지도 중심
- 실제 지도·분석·3D 점포 보기 모드
- 선택 점포 ID와 이름

페이지 시작 시 URL을 먼저 읽고, 점포 API 응답이 도착하면 저장된 점포 ID를 우선하여 다시 선택한다. ID가 없으면 이름을 보조 기준으로 사용한다. 실제 점포 목록에 없는 값은 제거한다.

## 9. 시간대별 활동성 데이터 상태

시간대별 활동성은 선택한 상권과 분기의 `flow_time_buckets`를 기준으로 표시한다.

- 자료를 불러오는 중: 로딩 안내
- 일부 시간대만 있음: 사용 가능한 시간대와 누락 안내
- 선택 분기에 자료 없음: `0`이나 임의의 사람 아이콘을 만들지 않고 다른 분기 선택 안내
- API 오류: 실패 원인을 숨기지 않고 재시도 가능한 오류 안내

서울 원본 시간대 컬럼은 다음 순서를 유지한다.

| 원본 컬럼 | canonical DB | API label |
| --- | --- | --- |
| `TMZON_00_06_FLPOP_CO` | `flow_00_06` | `00:00-06:00` |
| `TMZON_06_11_FLPOP_CO` | `flow_06_11` | `06:00-11:00` |
| `TMZON_11_14_FLPOP_CO` | `flow_11_14` | `11:00-14:00` |
| `TMZON_14_17_FLPOP_CO` | `flow_14_17` | `14:00-17:00` |
| `TMZON_17_21_FLPOP_CO` | `flow_17_21` | `17:00-21:00` |
| `TMZON_21_24_FLPOP_CO` | `flow_21_24` | `21:00-24:00` |

## 10. 데이터 기준 안내와 패널 가독성

`데이터 기준과 시점` modal은 본문 세로 스크롤을 제공하고 닫기 버튼을 고정 header에 유지한다. `작게`, `기본`, `크게` 설정은 헤더의 공통 보기 설정으로 제공하며 좌우 패널에 같은 크기를 적용한다.

큰 숫자는 말줄임표로 잘라내지 않고 `tabular-nums`, `auto-fit`, `minmax()`, `clamp()`와 줄바꿈을 사용한다.

## 11. 이전 건물 교체 방식의 폐기 사유

이전 구현은 다음 방식들을 시도했다.

- 단독 점포 건물 전체를 업종별 점포 모델로 교체
- 복합건물 위에 여러 업종별 옥상 오브젝트 배치
- LocalTwin 건물 중심과 OpenMapTiles 건물의 거리로 교체 대상 추정

실제 화면에서는 큰 건물 전체가 사라지고 작은 정사각형 점포 모델만 남거나, 서로 다른 건물 데이터의 polygon 불일치로 점포 모델이 기존 건물 안에 파묻히는 문제가 발생했다. 현재 설계는 건물 교체를 중단하고 선택 점포 집중 효과만 추가함으로써 이 문제를 구조적으로 제거한다.

## 12. 검증

로컬에서 다음 명령을 실행한다.

```powershell
pnpm --dir product/apps/web typecheck
pnpm --dir product/apps/web test
pnpm --dir product/apps/web build
uv run --directory product/apps/api pytest
git diff --check
```

수동 확인 항목:

- 선택 상권 내부 건물만 파스텔 색상이고 외부 건물은 회색인가
- 경계 안에서 회색 OpenMapTiles 건물과 색상 LocalTwin 건물이 겹치지 않는가
- 3D 점포 모드에 들어가도 점포를 선택하기 전에는 임의 3D 점포가 생성되지 않는가
- 특정 점포 클릭 시 카메라가 점포로 이동하는가
- 기존 건물을 유지한 채 target·spotlight·회전 category object가 지붕 위에 보이는가
- 다른 점포를 클릭하면 집중 효과가 새 점포로 이동하는가
- 선택 해제 시 집중 효과가 제거되는가
- 일반 초록 marker가 작고 반투명하며 건물을 과도하게 가리지 않는가
- 새로고침 뒤 상권·업종·분기·layer·보기 모드·선택 점포가 복원되는가
- 축소 밀도 화면에서는 marker보다 heatmap과 상권 범위가 먼저 읽히는가
- 선택하지 않은 다른 지원 상권의 LocalTwin overlay가 동시에 표시되지 않는가

## 후속 관리 원칙

이 기능과 직접 연결된 후속 변경은 새 Markdown을 만들지 않고 이 문서에 추가한다. API 계약이나 사용자 흐름이 별도 기능으로 분리될 때만 기존 기능 명세 또는 별도 Issue로 이동한다.
