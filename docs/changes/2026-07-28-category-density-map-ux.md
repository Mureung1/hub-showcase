# 업종 Top 7·점포 밀도 지도 UX 변경 기록

## 문서 목적

이 문서는 연남·홍대·합정 지원 상권의 업종 선택, 점포 밀도 지도, 건물 표현, 선택 점포 집중 효과와 제품 URL 원칙을 하나의 변경 기록으로 관리한다. 같은 기능에 대한 일회성 Markdown을 추가하지 않고 후속 수정도 이 문서에 이어서 기록한다.

## 적용 범위

- 지원 상권: 연남, 홍대, 합정
- API: `/api/v1/catalog`, 선택 상권 점포 조회와 분석 API
- Web: 업종 선택 패널, 밀도 지도, 3D 건물, 선택 점포 강조, `/home` canonical route

## 1. 데이터 기반 업종 Top 7

운영 DB에서 지원 상권에 연결된 점포를 조회하고 `store_id` 기준으로 중복을 제거한다. 각 점포는 소분류 → 중분류 → 대분류 순으로 확인하여 최초 일치하는 사용자용 업종 그룹 하나에만 배정한다.

순위 기준은 다음과 같다.

1. 고유 점포 수 내림차순
2. 포함 상권 수 내림차순
3. 업종 이름 오름차순

API가 운영 DB를 사용할 수 없을 때는 카페·음식점·베이커리·편의점 네 업종을 bootstrap 목록으로 제공한다. 준비 중·bootstrap·오류 상태는 실제 데이터 순위처럼 보이지 않도록 구분한다.

## 2. 업종 선택 UX

업종 패널은 API가 반환한 업종을 모두 표시하며 데이터 기반 응답에서는 최대 7개를 노출한다.

각 항목은 다음 정보를 제공한다.

- 순위
- 업종명
- 업종별 아이콘
- 고유 점포 수
- 부분 지원 업종의 `일부` 배지
- 현재 선택 상태

부분 지원 업종도 선택 상태를 유지한다. 전체 지원 업종은 매출·유동인구·점수 등 기존 분석 지표와 연결하고, 부분 지원 업종은 점포 위치와 경쟁 지표 중심으로 제공한다.

## 3. 점포 밀도 지도

점포 밀도 모드는 선택 업종의 실제 점포 좌표를 GeoJSON Point FeatureCollection으로 변환해 MapLibre heatmap layer로 표시한다.

- zoom 15.7 미만: heatmap 우선, DOM 점포 marker 숨김
- zoom 15.7 이상: 점포 marker 표시
- zoom 16.2 이상: heatmap을 빠르게 약화
- zoom 18: heatmap opacity 0

공통 색상 단계는 다음과 같다.

| 단계 | 색상 | 의미 |
| --- | --- | --- |
| 낮음 | 파랑 `#3b82f6` | 점포가 상대적으로 적게 모인 구간 |
| 보통 | 주황 `#f59e0b` | 중간 수준으로 모인 구간 |
| 높음 | 빨강 `#ef4444` | 점포가 상대적으로 많이 모인 구간 |
| 최고 밀집 | 진한 빨강 `#b91c1c` | heatmap 최고 강도 |

유동 수요 모드에서는 밀도 범례를 재사용하지 않는다.

## 4. 기본 건물 표현과 겹침 방지

분석 모드와 3D 점포 모드의 건물 정책은 다음과 같다.

- 선택한 지원 상권 내부: 파스텔 색상 건물
- 선택한 지원 상권 외부: 회색 단일색 건물
- 실제 지도 모드: 일반 회색 건물

건물 geometry는 상권 안팎 모두 OpenMapTiles의 동일한 `building` source를 사용한다. 서로 다른 두 건물 데이터셋을 교대로 사용하는 방식은 폐기했다.

동일 source를 공식 상권 polygon의 상보적인 필터로 나눈다.

1. 외부 레이어: `distance > 0.75m`
2. 내부 레이어: `distance <= 0.75m`
3. 경계 geometry가 아직 준비되지 않았으면 전체 건물을 회색으로 유지
4. 내부 레이어는 경계가 준비된 뒤에만 표시

따라서 한 건물이 회색과 색상으로 동시에 겹치지 않으며, LocalTwin GeoJSON에 건물 polygon이 빠져 있어 건물이 드문드문 사라지는 문제도 발생하지 않는다.

LocalTwin region GeoJSON은 건물 extrusion을 담당하지 않고 도로·공원·물·라벨 같은 지역 맥락만 추가한다.

외부 지도 스타일이 제공하는 `building` 2D fill과 `building-3d` extrusion은 모두 숨긴다.
LocalTwin의 회색·선택 상권 건물 레이어 아래에 원본 베이지·주황 건물 면이 남아
지원 범위 밖 건물처럼 보이는 현상을 막기 위함이다.

정적 경계는 `market_id`를 우선 사용하되 원격 catalog의 ID가 달라질 수 있으므로 안정적인 `market_key`를 보조 기준으로 사용한다. 선택한 상권 key로 연남·홍대·합정 overlay를 정확히 선택하며 가까운 region을 추측하지 않는다.

## 5. 선택 점포 집중 표현

기존 건물을 업종별 점포 건물로 교체하거나 숨기는 방식은 활성 사용자 흐름에서 사용하지 않는다. 실제 건물은 그대로 유지한다.

3D 점포 모드의 동작은 다음과 같다.

1. 업종만 선택한 상태에서는 건물과 점포 marker를 표시한다.
2. 특정 점포를 클릭해야 집중 효과를 생성한다.
3. 카메라가 점포 좌표로 이동하고 zoom 16.8로 진입한다.
4. 건물 연결에 성공하면 실제 건물 높이를 집중 효과의 altitude로 사용한다.
5. 집중 효과의 수평 위치는 건물 중심이 아니라 실제 클릭한 점포 좌표를 사용한다.
6. 건물 연결에 실패해도 점포 좌표의 집중 효과와 Popup은 유지한다.

Three.js 집중 효과는 다음 요소로 구성한다.

- 이중 원형 target
- 노란색 반투명 spotlight cone
- 수직 light stem
- 업종별 독립 3D category object
- 천천히 회전하는 category object
- pulse target ring

선택 집중 효과는 공간 데이터가 아니라 UI 지시자이므로 주변 건물에 완전히 가리지 않도록 해당 오브젝트에만 depth occlusion을 해제한다. 실제 건물과 일반 지도 오브젝트의 깊이 표현은 변경하지 않는다.

WebGL custom layer가 준비되지 않거나 시각적으로 묻히더라도 사용자가 선택 위치를 잃지 않도록 동일 좌표에 DOM 기반 집중 beacon도 표시한다.

- 회전하는 업종 아이콘
- 노란 pulse ring
- 반투명 빛기둥
- 점포 Popup

한 화면에는 선택 점포 집중 효과 하나만 표시한다. 시장·업종·점포·3D 모드가 바뀌면 이전 custom layer 실패 상태를 초기화하고 새 선택에 대해 다시 시도한다.

## 6. 업종별 category object

디자인 검수를 완료한 Three.js category geometry를 일반 점포와 선택 집중 효과가
함께 사용한다. 지도용으로 별도의 단순 오브젝트를 만들지 않는다.

- 카페: 김이 없는 커피색 음료, 둥근 잔, 관통되지 않는 원두 표식
- 음식점: 가운데 큰 그릇과 오른쪽 수저·젓가락
- 베이커리: 바구니에 세워진 뾰족한 바게트 3개와 사선 칼집
- 편의점: 유리 매장과 흰 fascia, 파랑·주황·초록·보라 간판 band
- 꽃집: 하늘색 투명창, 지붕의 갈색 화분과 꽃
- 미용: 지붕 위에 눕힌 큰 가위
- 의류: 소매가 몸판 아래에 놓인 큰 셔츠
- 학원: 독서대 위에 약 45도로 세운 열린 책
- 숙박: 큰 이불과 headboard 쪽 직사각 쿠션이 있는 침대
- 체육: 덤벨

`P10603` 요가·필라테스는 학원이 아니라 체육 오브젝트를 사용한다. 검수하지 않은
기타 업종은 구형 일반 서비스 오브젝트를 만들지 않고 원래 회색 건물을 유지한다.

오브젝트는 실제 건물을 대체하지 않으므로 건물 높이만큼 강제로 늘리지 않고 균일 비율을 유지한다.

## 7. 점포 marker 가독성

3D 점포 모드의 일반 marker는 선택 집중 효과보다 약하게 표시한다.

- 일반 fallback marker opacity: 0.58
- 상세 fallback marker: 29×29px
- clustered fallback marker: 28×28px
- 흰색 halo와 그림자 강도 축소
- hover·keyboard focus·선택 상태에서만 opacity 1
- 선택 집중 효과로 표현된 점포 marker는 중복 표시하지 않음

특정 점포를 선택한 뒤에는 주변 marker를 더 약하게 만든다.

- 선택하지 않은 marker opacity: 0.18
- 채도와 크기를 함께 낮춰 spotlight 뒤로 물러나게 표시
- hover 또는 keyboard focus 시 opacity 0.82와 원래 크기로 복원
- 클릭 가능 상태는 유지하여 다른 점포로 바로 전환 가능
- 분석 모드에서는 이 추가 약화 규칙을 적용하지 않음

## 8. `/home`과 제품 상태

일반 제품 화면의 canonical URL은 항상 `/home`이다. `/` 또는 이전 분석 query가 붙은 주소로 접속하면 앱 시작 시 한 번만 `history.replaceState()`로 `/home`으로 정규화한다. 이후 필터·상권·점포·지도 보기·시간대·분기를 바꿔도 주소와 browser history는 변경하지 않는다.

분석 상태의 source of truth는 React state다. 새로고침하면 다음 기본 분석 상태로 시작한다.

- catalog 첫 상권과 첫 데이터 기반 업종
- 지원하면 300m, 아니면 첫 지원 반경
- 점포 밀도와 종합 분석
- 기본 시간대, 최신 API 기본 분기
- 상권 중심 지도와 선택 점포 없음

존재하지 않는 분기만 `useAnalysisPeriodNormalization`이 API 기본 분기로 교정하며, 이 hook은 browser history를 읽거나 쓰지 않는다. API 요청의 `category`, `period`, `market_id` query parameter는 서버 contract이므로 그대로 유지한다.

`/en`, `?demo=storefront`, `?demo=flower-map`과 별도 Splat smoke-test 진입점은 `/home` 정규화 대상이 아니다. 분석 공유가 필요해지면 암묵적인 query 복원이 아니라 별도의 명시적 공유 기능과 route로 설계한다.

## 9. 시간대별 활동성 데이터 상태

시간대별 활동성은 선택한 상권과 분기의 `flow_time_buckets`를 기준으로 표시한다.

- 자료를 불러오는 중: 로딩 안내
- 일부 시간대만 있음: 사용 가능한 시간대와 누락 안내
- 선택 분기에 자료 없음: `0`이나 임의의 사람 아이콘을 만들지 않고 다른 분기 선택 안내
- API 오류: 실패 원인을 숨기지 않고 재시도 가능한 오류 안내

서울 원본 시간대 컬럼은 다음 순서를 유지한다.

| 원본 컬럼 | canonical DB | API label |
| --- | --- | --- |
| `TMZON_00_06_FLPOP_CO` | `flow_00_06` | `00:00-06:00` |
| `TMZON_06_11_FLPOP_CO` | `flow_06_11` | `06:00-11:00` |
| `TMZON_11_14_FLPOP_CO` | `flow_11_14` | `11:00-14:00` |
| `TMZON_14_17_FLPOP_CO` | `flow_14_17` | `14:00-17:00` |
| `TMZON_17_21_FLPOP_CO` | `flow_17_21` | `17:00-21:00` |
| `TMZON_21_24_FLPOP_CO` | `flow_21_24` | `21:00-24:00` |

## 10. 초기 지도 로딩 표현

브라우저 새로고침 직후 MapLibre 스타일과 vector tile이 준비되기 전에는 실제 지도 대신 지도 형태의 loading surface를 표시한다.

- `Map`의 첫 `idle` 이벤트 전까지 `aria-busy=true`
- 도로선과 녹지 형태가 있는 정적 pattern으로 빈 베이지 화면을 대체
- 중앙에 `지도를 불러오는 중` 상태 카드 표시
- 첫 `idle` 이후 loading surface 제거
- 로딩 중에는 지원 범위 밖 안내를 숨겨 서로 다른 상태 메시지가 겹치지 않게 처리
- 실제 지도와 건물 데이터가 준비된 뒤 기존 상권 경계·heatmap·marker를 그대로 사용

상권 전환에는 이 초기 loading surface를 다시 표시하지 않는다. `Map` 인스턴스는
유지하고 상권 ID를 React `key`로 사용해 지도를 재마운트하지 않는다.

### 상권 전환 먹통 원인과 재발 방지 규칙

문제가 발생한 조건은 `점포 밀도` 또는 `3D 점포`처럼 기울어진 카메라와 LocalTwin
건물·경계 layer가 활성화된 상태였다. 상권 선택 handler가 상권 상태를 교체한 같은
render 구간에 `flyTo` 또는 `easeTo`를 바로 시작하면 MapLibre가 경계 기반 건물
filter와 새 tile을 갱신하는 동안 카메라 transform까지 동시에 처리했다. 이
조합에서 WebGL 지도와 React 화면이 빈 상태로 무너졌으며 URL도 이전 상권에
머물렀다.

다음 비교로 원인을 분리했다.

- `실제 지도`에서 같은 상권 변경: 정상
- 3D layer 상태에서 상권 상태만 변경하고 카메라 호출 생략: 정상
- 3D layer 상태에서 `flyTo`를 `easeTo`로만 교체: 동일하게 실패
- 전환 중 3D layer를 일시 완화한 뒤 평면 카메라로 이동: 정상

따라서 상권 전환은 다음 하나의 transaction으로 처리한다.

1. `marketTransitionActive=true`로 설정해 선택 상권의 색상 건물, 경계, heatmap,
   검수 3D 오브젝트처럼 이동 중 다시 계산할 LocalTwin layer를 잠시 숨긴다.
2. 다음 animation frame에서 상권 상태와 확정 중심을 함께 갱신한다.
3. 같은 `Map` 인스턴스를 평면 카메라로 다음 상권 중심까지 `easeTo`한다.
4. 첫 `moveend` 뒤 사용자가 선택했던 `analysis` 또는 `storefront3d` 카메라 각도를
   복원한다.
5. 마지막 `moveend` 뒤 LocalTwin layer를 다시 표시한다.

빠르게 상권을 연속 선택하면 이전 animation frame과 `moveend` listener를
취소하고 `map.stop()` 뒤 마지막 선택만 실행한다. 전환 중에도 초기 지도 loading
surface는 다시 표시하지 않으며, 화면 전체나 `Map` 컴포넌트를 교체해서는 안 된다.

회귀 테스트는 다음 불변조건을 고정한다.

- 3D 전환 시작 시 상권 commit보다 layer 완화가 먼저 적용됨
- 첫 animation frame에서만 상권과 중심이 commit됨
- 평면 이동이 끝난 뒤 기존 presentation camera가 복원됨
- 연속 선택 시 이전 예약을 취소하고 마지막 상권만 이동함

## 11. 데이터 기준 안내와 패널 가독성

`데이터 기준과 시점` modal은 본문 세로 스크롤을 제공하고 닫기 버튼을 고정 header에 유지한다. `작게`, `기본`, `크게` 설정은 헤더의 공통 보기 설정으로 제공하며 좌우 패널에 같은 크기를 적용한다.

큰 숫자는 말줄임표로 잘라내지 않고 `tabular-nums`, `auto-fit`, `minmax()`, `clamp()`와 줄바꿈을 사용한다.

## 12. 검증

로컬에서 다음 명령을 실행한다.

```powershell
pnpm --dir product/apps/web typecheck
pnpm --dir product/apps/web test
pnpm --dir product/apps/web build
git diff --check
```

수동 확인 항목:

- `/`과 과거 분석 query로 접속하면 `/home`으로 정규화되는가
- 상권·업종·반경·시간대·layer·topic·경계·점포 표시·분기·보기 모드를 바꿔도 주소가 `/home`으로 유지되는가
- 새로고침하면 catalog 기반 기본 분석 상태와 선택 점포 없음으로 시작하는가
- 원격 업종 목록 로딩 중 카페·음식점·베이커리·편의점이 현재 선택처럼 깜빡이지 않는가
- 로딩 중에는 bootstrap 업종을 데이터 기반 순위처럼 표시하지 않는가
- 새로고침 직후 빈 지도 대신 로딩 pattern과 상태 카드가 표시되는가
- 첫 지도 idle 이후 로딩 표면이 제거되고 실제 지도와 건물이 보이는가
- 홍대와 합정을 연속으로 선택해도 지도와 앱 전체가 계속 표시되는가
- 점포 밀도와 3D 점포 각각에서 연남→홍대→합정을 전환하는 동안 `Map` region이
  항상 한 개 유지되고 주소가 `/home`으로 남는가
- 점포를 선택한 3D 화면에서 상권을 바꾸면 이전 Popup·오브젝트가 사라지고 새
  상권 지도가 loading surface 없이 표시되는가
- 경계 geometry를 불러오는 동안 건물이 사라지지 않고 회색으로 유지되는가
- 선택 상권 내부 건물은 파스텔이고 외부 건물은 회색인가
- 경계 부근에서 회색 건물과 색상 건물이 겹치지 않는가
- 화면에서 건물이 드문드문 누락되지 않는가
- 3D 점포에서 점포 클릭 시 Popup과 spotlight·회전 category object가 함께 보이는가
- 점포 선택 후 주변 marker가 약해지고 hover 시 다시 읽을 수 있는가
- WebGL custom layer가 실패해도 DOM 집중 beacon은 보이는가
- 다른 점포를 클릭하면 집중 효과가 새 위치로 이동하는가

## 13. 3D 점포 오브젝트와 지도 컨트롤

`3D 점포`의 일반 점포는 업종 marker로 탐색하고, 사용자가 한 점포를 선택했을
때만 그 위치에 검수된 업종별 3D 오브젝트를 표시한다.

- 선택 전 또는 업종 변경 직후: 3D 오브젝트 0개
- 점포 선택 후: 선택 점포 위치에 검수된 업종 오브젝트 정확히 1개
- 선택 점포: 노란 이중 포커스 링, 수직 라이트, 반투명 spotlight와 회전
  category object로 강조
- 주변 점포: 가벼운 DOM marker를 유지하고 Three.js 오브젝트를 만들지 않음
- 3D 오브젝트에는 투명한 클릭·키보드 포커스 영역을 유지해 같은 점포의 선택
  상태를 확인할 수 있어야 한다.
- 동명이점은 이름이 아니라 점포 ID를 우선하여 선택한다.
- `prefers-reduced-motion: reduce` 환경에서는 선택 오브젝트 회전과 펄스 애니메이션을
  정지한다.

Three.js 오브젝트는 클릭할 때마다 geometry와 material을 처음부터 만들지 않는다.
검수된 디자인 ID별 원본 `Group`을 앱 생명주기 동안 한 번만 prefab template으로
캐시한다. 선택 시에는 transform과 계층만 `clone(true)`하고 geometry와 material은
template과 공유한다. 점포 전환 시 이전 instance만 scene에서 제거하며 공유 자원은
dispose하지 않는다. 현재 검수 디자인 수만큼만 캐시하므로 캐시 크기도 제한된다.

선택 점포 Popup은 점포명, 업종·거리, 상권·업종 점수, `점수 근거`만 표시한다.
유동인구와 같은 업종 수는 하단 요약과 분석 패널에 이미 있으므로 Popup에서
반복하지 않는다.

업종 변경 시 이전 점포 응답은 새 요청의 key와 일치하지 않는 즉시 화면에서
제외한다. 선택 점포는 해제하고 Three.js custom layer는
`localtwin-selected-storefront` 한 슬롯만 사용한다. 같은 슬롯에 새 선택을
교체하고 unmount 시 `getLayer()`로 존재 여부를 확인해 제거하므로 이전 카페
오브젝트가 다음 업종 화면에 남지 않는다.

점포 marker, 선택 Popup, 업종 목록, 3D 오브젝트는 모두 공통 업종 의미 모듈을
사용한다. 예를 들어 음식점 화면에서는 세부 업종명이 달라도 동일한 식기 icon과
음식점 3D 오브젝트를 사용하며, 시장별로 별도 UI를 만들지 않는다.

점포 수는 용도를 구분한다.

- 업종 목록·현재 점포 수·경쟁 현황: 최신 점포 위치 데이터의 고유 점포 수
- 매출·유동인구·개폐업: 사용자가 선택한 공식 분기 분석 자료

두 자료가 함께 있는 하단 요약에는 `분기 분석 · 점포는 최신 위치`라고 표시해
서로 다른 시점을 같은 점포 수처럼 오해하지 않게 한다.

`scope=market`의 `/stores/nearby` 응답은 catalog와 동일한
`classify_category_group` 우선순위로 업종을 한 번만 분류한다.
`same_category_count`, `returned_count`, `stores.length`, 선택 업종 목록과 경쟁
현황 숫자는 같은 고유 점포 집합을 가리켜야 한다.

프론트는 API가 선택 업종으로 판정해 반환한 점포를 소분류명으로 다시 필터링하지
않는다. 백엔드는 소·중·대분류를 모두 확인하지만 응답의 `category_name`은 대표
소분류명 한 개이므로, 프론트에서 다시 판정하면 `돼지고기 구이/찜`, `중국집`,
`생맥주 전문` 같은 음식점이 누락될 수 있기 때문이다.

점포를 선택해도 목록의 전체 점포 수는 줄이지 않는다. 선택 행을 목록 안에서
강조하고, 제목은 반경 조회처럼 오해되는 `주변 점포` 대신
`상권 내 {선택 업종}`으로 표시한다. 기본 다섯 행만 펼쳐 보여도 전체보기와
업종 목록의 숫자는 동일하게 유지한다. API가 의류로 반환한 `가방 소매업`처럼
세부명이 대표 업종 단어를 포함하지 않아도 점포 선택 시 대표 업종을 세부 업종으로
교체하지 않는다.

Top 7 카탈로그와 `/stores/nearby`의 대표 업종 요청은 같은 분류 우선순위를
사용한다. 예를 들어 `독서실/스터디 카페`의 상위 분류에 스포츠가 있어도 카페로
한 번만 집계하고, `요가/필라테스 학원`은 체육으로 집계한다. 지도에서는 세부명
`펜션`과 코드 `I10103`을 숙박으로 해석하므로 API의 숙박 점포 수와 실제 marker
수가 달라지지 않는다.

지도 보기 전환, 검색, 확대·축소, `전체 상권 보기`는 같은 리퀴드 글라스 재질을
사용한다. 투명도만으로 글자를 흐리게 만들지 않고 내부 흰색 하이라이트, 녹색
경계, 내부 `focus-visible` 링으로 선택과 키보드 포커스를 구분한다.

선택 점포 Popup은 `width: min(320px, calc(100vw - 32px))` 범위에서 렌더하고,
점포명·업종·거리·점수 label은 `minmax(0, 1fr)`과 줄바꿈을 사용한다. 긴 점포명도
Popup의 `scrollWidth`가 `clientWidth`를 넘지 않아야 한다.
