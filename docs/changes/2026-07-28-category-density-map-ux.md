# 업종 Top 7·점포 밀도 지도 UX 변경 기록

## 문서 목적

이 문서는 연남·홍대·합정 지원 상권의 업종 선택과 점포 밀도 지도 개선을 하나의 변경 기록으로 관리한다. 같은 기능에 대해 여러 개의 일회성 Markdown을 만들지 않고, 관련 후속 수정도 이 문서에 이어서 기록한다.

## 적용 범위

- 지원 상권: 연남, 홍대, 합정
- API: `/api/v1/catalog`
- Web: 업종 선택 패널, 점포 밀도 지도, 지도 범례와 하단 지표, 데이터 기준 안내

## 1. 데이터 기반 업종 Top 7

운영 DB에서 지원 상권에 연결된 점포를 조회한 뒤 `store_id` 기준으로 중복을 제거한다. 각 점포는 소분류 → 중분류 → 대분류 순으로 확인하여 최초 일치하는 사용자용 업종 그룹 하나에만 배정한다.

순위 기준은 다음과 같다.

1. 고유 점포 수 내림차순
2. 포함 상권 수 내림차순
3. 업종 이름 오름차순

API가 운영 DB를 사용할 수 없을 때는 카페·음식점·베이커리·편의점 네 업종을 bootstrap 목록으로 제공한다. 프론트는 API 준비가 완료된 뒤 카탈로그를 요청하고, API 응답 성공 시 데이터 기반 목록으로 교체한다. 준비 중·bootstrap·오류 상태는 실제 순위처럼 보이지 않도록 각각 다른 안내문과 재시도 동작을 제공한다.

## 2. 업종 선택 UX

업종 패널은 API가 반환한 업종을 모두 표시한다. 데이터 기반 응답에서는 최대 7개가 노출된다.

각 항목은 다음 정보를 제공한다.

- 순위
- 업종명
- 업종별 아이콘
- 고유 점포 수
- 부분 지원 업종만 표시하는 `일부` 배지
- 현재 선택 상태

부분 지원 업종도 정상적으로 선택 상태를 유지한다. 전체 지원 업종은 매출·유동인구·점수 등 기존 분석 지표와 연결되고, 부분 지원 업종은 점포 위치와 경쟁 지표 중심으로 제공한다. 읽기 쉬운 크기를 위해 업종명은 14px, 행 높이는 최소 46px으로 유지한다.

데스크톱에서는 Top 7 전체를 한 번에 보여주며 내부 스크롤을 만들지 않는다. 좁은 화면에서는 필터 패널의 기존 스크롤 안에서 다음 분석 단계로 이동한다.

## 3. 점포 밀도 지도

점포 밀도 모드는 선택 업종의 실제 점포 좌표를 GeoJSON Point FeatureCollection으로 변환하고 MapLibre heatmap layer로 표시한다.

선택 상권·업종 범위의 점포는 반경 기반 `nearby` 제한이나 3D 점포 후보 수 제한을 적용하지 않고 지도 marker와 heatmap에 모두 전달한다. 3D 점포 배치 후보만 별도 제한을 유지한다. 따라서 지도를 이동하거나 축소해도 이미 선택된 상권 안의 점포가 viewport 변화에 따라 사라지지 않는다.

공통 색상 단계는 다음과 같다.

| 단계 | 색상 | 의미 |
| --- | --- | --- |
| 낮음 | 파랑 `#3b82f6` | 점포가 상대적으로 적게 모인 구간 |
| 보통 | 주황 `#f59e0b` | 중간 수준으로 모인 구간 |
| 높음 | 빨강 `#ef4444` | 점포가 상대적으로 많이 모인 구간 |
| 최고 밀집 | 진한 빨강 `#b91c1c` | heatmap 최고 강도 |

범례와 heatmap은 같은 색상 상수를 사용한다. 건물의 pastel palette와 점포 업종별 marker 색상은 밀집도 의미가 아니므로 별도로 유지한다.

유동 수요 모드에서는 밀도 범례를 재사용하지 않는다. 사람 아이콘 수가 많을수록 상대 수요가 높다는 별도 안내를 표시한다.

## 4. 지도 오버레이 배치

`map-legend`와 `market-quick-metrics`가 시각적으로 붙지 않도록 공통 overlay gap을 둔다. 모바일에서는 하단 Dock 높이와 줄바꿈을 고려해 더 큰 간격을 사용한다.

## 5. TypeScript GeoJSON 타입 오류

### 증상

```text
StoreDensityHeatmap.tsx(13,24): error TS2503: Cannot find namespace 'GeoJSON'.
StoreDensityHeatmap.tsx(13,50): error TS2503: Cannot find namespace 'GeoJSON'.
```

### 원인

웹 패키지에는 전역 `GeoJSON` namespace를 제공하는 별도 타입 패키지가 없었다. 컴포넌트가 `GeoJSON.FeatureCollection<GeoJSON.Point>`를 직접 참조하면서 TypeScript가 해당 namespace를 찾지 못했다.

### 해결

추가 의존성을 설치하지 않고, 이 컴포넌트가 실제로 사용하는 최소 GeoJSON 구조를 로컬 타입으로 정의했다.

- `FeatureCollection`
- `Feature`
- `Point`
- `[longitude, latitude]` 좌표 tuple
- 문자열 `id` property

이 방식은 전역 namespace에 의존하지 않으며 현재 heatmap 입력 계약을 명시적으로 유지한다.

## 6. 시간대별 활동성 데이터 상태

시간대별 활동성은 선택한 상권과 분기의 `flow_time_buckets`를 기준으로 표시한다. 다른 상권에만 유동인구가 있더라도 선택 상권에 해당 자료가 없으면 해당 분기는 `점포 데이터만`으로 표시한다.

- 자료를 불러오는 중: 로딩 안내
- 일부 시간대만 있음: 사용 가능한 시간대와 누락 안내
- 선택 분기에 자료 없음: `0`이나 사람 아이콘을 만들지 않고, 다른 분기 선택 안내
- API 오류: 실패 원인을 숨기지 않고 재시도 가능한 오류 안내

운영 DB에는 분기별 유동인구 원본이 promotion되어야 한다. Web 배포 전 API에서 각 지원 상권의 `flow_time_buckets` 6개가 실제 값인지 확인한다.

## 7. 데이터 기준 안내 모달

`EVIDENCE · SOURCE PERIODS` 모달은 화면 높이를 넘지 않도록 본문 영역에 세로 스크롤을 제공한다. 닫기 버튼은 고정된 modal header에 남기고, 제목과 설명은 일반 사용자가 이해할 수 있는 `이 숫자는 무엇을 뜻하나요?`, `가게 수의 변화`, `사람이 많은 시간` 같은 표현으로 바꾼다.

## 8. 검증

로컬에서 다음 명령을 실행한다.

```powershell
pnpm --dir product/apps/web typecheck
pnpm --dir product/apps/web test
pnpm --dir product/apps/web build
uv run --directory product/apps/api pytest
git diff --check
```

수동 확인 항목:

- API 준비 후 카탈로그가 자동 요청되고, API 서버가 7개 업종을 반환하면 패널에도 7개가 표시되는가
- bootstrap·연결 중·오류 상태가 데이터 기반 Top 7처럼 보이지 않는가
- 부분 지원 업종을 선택해도 선택 표시가 유지되는가
- 선택 상권·업종의 점포가 지도 marker와 heatmap에 모두 표시되고 지도 이동 뒤에도 사라지지 않는가
- 점포 밀도 범례와 heatmap 색상이 일치하는가
- 유동 수요 모드에서 밀도 범례가 노출되지 않는가
- 유동인구가 없는 분기는 `0` 또는 임의의 사람 아이콘 대신 자료 없음으로 표시되는가
- 데이터 기준 modal이 작은 화면에서도 내부 스크롤과 닫기 버튼을 제공하는가
- 데스크톱과 모바일에서 범례와 하단 지표가 겹치지 않는가
- 패널 글자 크기를 크게 바꿔도 수치와 버튼이 잘리지 않는가
- 확인 자료 수와 누락 지표가 판단 카드보다 먼저 이해되는가
- 3D 점포 모드에서 상권 밖과 교체되지 않은 건물은 회색 기본 건물로 유지되는가
- 업종을 바꿀 때 이전 업종 건물이 복원되고 새 업종의 교체 건물만 숨겨지는가
- 단독 점포 건물은 전체 3D 점포로 교체되고 복합건물은 기존 건물을 유지한 채 옥상 업종 오브젝트가 보이는가
- 같은 복합건물에 선택 업종 점포가 여러 개 있어도 옥상 오브젝트가 한 개만 배치되는가
- 옥상 업종 오브젝트가 준비돼도 해당 MapLibre 기본 건물이 숨겨지지 않는가
- 축소 상태에서 남은 fallback marker가 더 강하게 묶이고, 확대 상태에서 개별 업종 아이콘이 명확히 보이는가
- 건물 연결에 실패한 점포도 업종별 fallback marker로 남는가

## 9. 확장 업종의 점포 표현과 3D 배치

카탈로그 순위와 지도 검색에는 같은 업종별 검색어 묶음을 사용한다. 예를 들어 `체육`은 체육·헬스·피트니스·스포츠·요가·필라테스를 함께 찾는다. 따라서 Top 7에는 체육으로 집계되었는데 선택 뒤에는 `분석 미지원`으로 바뀌는 불일치를 막는다.

선택 상권에 실제로 일치하는 점포가 없을 때만 `이 상권에 점포 없음`을 표시한다. 이는 해당 상권의 결과이며, 세 상권을 합산한 Top 7 순위와는 별개라는 설명을 함께 제공한다.

지도 marker는 검은 `+`나 공통 상점 기호 대신 업종을 식별할 수 있는 색상과 Lucide 아이콘을 사용한다.

- 카페: 초록 커피잔
- 음식점: 주황 식기
- 베이커리: 파랑 밀 이삭
- 편의점: 남색 장바구니
- 꽃집: 노랑 꽃
- 미용: 분홍 가위
- 의류: 보라 옷걸이
- 학원: 청록 학사모
- 숙박: 자주 침대
- 체육: 빨강 덤벨

3D 점포 모드에서도 이 업종들은 단순 기호가 아니라 기존 Three.js custom map layer의 매장 오브젝트로 배치한다. 미용에는 거울, 의류에는 행거와 옷, 학원에는 책, 숙박에는 침대, 체육에는 덤벨을 추가하며, 기존 후보 수 제한은 성능 보호를 위해 유지한다.

절차적 전체 점포 모델은 실제 건물 polygon 안에 안전하게 들어가는 단독 점포 건물에만 배치한다. 한 건물에 여러 점포가 연결되면 건물 자체는 유지하고 기존 `category-attachment` geometry만 옥상 업종 오브젝트로 배치한다. 건물 연결에 실패한 점포만 업종 marker로 남긴다. geometry와 material은 storefront dispose 경로에서 정리하며 CSS 가짜 3D 오브젝트를 Three.js 대체 경로로 추가하지 않는다.

## 10. 데이터 기준 안내 가독성

`데이터 기준과 시점`의 상단 구분 제목은 13px, 기준·시점 항목은 12px으로 올린다. 긴 내용은 modal 본문에서 스크롤하므로 닫기 버튼과 확인 버튼은 항상 사용할 수 있다.

## 11. 패널 글자 크기·대비·큰 숫자

`작게`, `기본`, `크게` 세 단계 글자 크기 설정은 좌우 패널 내부가 아니라 헤더의 Docs 왼쪽에 전역 보기 설정으로 제공한다. 선택값은 브라우저에 저장하며 지도 라벨까지 무조건 확대하지 않고 분석 조건과 결과 패널에 공통 적용한다. 모바일에서는 같은 기능을 `A−`, `A`, `A+`로 축약하되 접근성 이름은 유지한다.

상태는 `ProductWorkspace`에서 한 번만 소유하고 `WorkspaceHeader`와 `WorkspaceLayout`에 전달한다. 따라서 좌측 필터와 우측 분석 결과가 서로 다른 글자 크기를 갖지 않는다.

패널 타이포그래피는 메인 제목, 섹션 제목, 본문, 보조 설명, 메타·배지, 카드 수치, 핵심 수치 단계로 구분하고 CSS 변수로 관리한다. 개별 컴포넌트에서 임의의 고정 크기를 추가하기보다 공통 토큰을 우선한다.

레이아웃은 고정 높이와 강제 한 줄 표시를 피하고 `auto-fit`, `minmax()`, `clamp()`, 줄바꿈을 사용한다. 큰 글자나 긴 매출·인구 수치가 들어오면 카드 열 수를 줄여 전체 값을 유지한다. 핵심 수치는 `tabular-nums`를 사용하고, 정보 손실이 생기는 말줄임표를 적용하지 않는다.

보조 텍스트는 배경과 구분되는 공통 대비 토큰을 사용한다. 초록 브랜드 색상 외에도 정보는 파랑, 부분 지원과 주의는 호박색, 위험은 코랄, 공간·확장 기능은 보라를 제한적으로 사용한다. 상태는 색상만으로 전달하지 않고 문구, 기호와 테두리를 함께 사용한다.

글자 크기 control 이동 뒤 컴포넌트 테스트에서는 제거된 `MarketInspector` props를 계속 전달하지 않는다. 각 테스트는 `cleanup()`으로 렌더링된 DOM을 격리하며, 시간대 자료 출처 문구는 실제 화면 문구인 `서울시 추정 길단위인구의 선택 분기 집계입니다`를 기준으로 검증한다.

## 12. 확인 자료 수와 누락 영향

`근거 부족`이라는 결과만 단독으로 보여주지 않는다. 우측 패널 상단에서 다음을 먼저 제공한다.

- 핵심 자료 3개 중 확인된 자료 수
- 점포·개폐업, 추정매출, 유동인구의 개별 상태
- 선택 분기
- 누락된 자료가 점수의 확실성에 미치는 영향
- 모든 자료가 있어도 현장 유동과 임대료를 별도로 확인해야 한다는 안내

부분 지원 업종은 전체 분석 자료가 준비된 것처럼 표시하지 않으며 이 요약을 노출하지 않는다.

| `TMZON_11_14_FLPOP_CO` | `flow_11_14` | `11:00-14:00` |
| `TMZON_14_17_FLPOP_CO` | `flow_14_17` | `14:00-17:00` |
| `TMZON_17_21_FLPOP_CO` | `flow_17_21` | `17:00-21:00` |
| `TMZON_21_24_FLPOP_CO` | `flow_21_24` | `21:00-24:00` |

회귀 테스트는 서로 다른 값을 여섯 컬럼에 넣고 import → canonical DB → API 응답까지 순서가 바뀌지 않는지 검사한다. 00~06 값이 다른 구간보다 매우 커도 임의로 낮추거나 다른 시간대로 이동하지 않는다.

이 테스트는 **컬럼 매핑 오류 여부**만 확인한다. 실제 운영 상권에서 새벽 값이 높은 이유가 정상 집계인지 원본 이상인지는 운영 DB와 서울 원본 응답을 대조해 별도로 판단한다.

## 14. 업종 선택형 3D 건물 교체와 zoom LOD

3D 점포 모드에서는 MapLibre의 회색 기본 건물을 지도 전체의 도시 맥락으로 유지한다. LocalTwin pastel 건물 extrusion은 이 모드에서 끄고, 선택 업종의 Three.js 전체 점포가 실제로 준비된 뒤 해당 건물 중심과 MapLibre 건물 feature 사이의 `distance`가 0에 가까운 경우에만 `fill-extrusion-base`와 `fill-extrusion-height`를 0으로 바꾼다. 3D 레이어가 준비되기 전에는 기본 건물을 숨기지 않으므로 빈 부지가 먼저 나타나지 않는다.

업종 변경 시 기존 Three.js layer가 제거되고 준비 상태는 `점포 ID + 업종 코드 + placement mode + 건물 ID` 조합으로 구분한다. 이후 새 업종의 점포 후보와 건물 배치를 다시 계산하므로 이전 업종의 readiness가 새 업종이나 다른 배치 방식에 재사용되지 않는다.

전체 건물 교체 조건은 다음 안전 기준을 유지한다.

- 점포 좌표가 LocalTwin overlay 건물 polygon 안에 있음
- 안전한 정사각형 plot을 계산할 수 있음
- 같은 건물에 연결된 점포가 1개 이하임
- 현재 화면의 3D 후보 수 제한 안에 있음

복합건물은 전체 교체 조건에서 제외하되 fallback marker로 바로 내리지 않는다. 기존 건물 높이보다 0.7m 위에 카페 컵, 음식점 그릇, 학원 책, 숙박 침대, 체육 덤벨 같은 독립 category object를 배치한다. 옥상 오브젝트는 약 5.5~9m 범위에서 균일 비율로 확대하지만 MapLibre와 같은 3D depth buffer를 사용하므로 실제 앞뒤 관계는 유지한다.

3D 오브젝트 총수는 기존 성능 한도인 최대 12개를 유지한다. 기존 전체 교체 후보가 한도를 채우지 못하면 남은 자리를 선택 업종의 추가 점포로 채우며, 선택한 점포를 우선한다. 같은 건물에는 전체 점포 또는 옥상 오브젝트 중 하나만 배치한다.

3D로 표현된 점포의 DOM marker는 중복 노출하지 않는다. 건물 연결에 실패해 남은 fallback marker는 3D 모드에서 분석 모드보다 1.55배 큰 거리 셀로 묶는다. zoom 16.2 이상에서는 모든 남은 점포를 개별 44px 업종 아이콘으로 전환하며, 선택 점포는 묶음 안에 들어가지 않는다.

## 15. 복합건물 fallback-only 화면의 원인과 수정

연남처럼 한 건물에 카페·음식점·미용실 등이 함께 있는 지역에서는 `storeCountInBuilding <= 1` 조건을 통과하는 건물이 적다. 이전 구현은 조건을 통과하지 못한 후보를 모두 marker로 되돌렸기 때문에 `3D 점포` 모드에서도 초록 핀과 숫자만 보이고 실제 Three.js 오브젝트가 거의 없는 화면이 생겼다.

건물 점유 수는 선택 업종만이 아니라 API가 반환한 모든 주변 점포를 사용해 계산한다. 이 판단은 건물 전체를 특정 업종으로 바꿔도 되는지를 확인하기 위한 안전 장치이므로 유지한다. 대신 결과를 `교체 성공/실패` 두 단계가 아니라 다음 세 단계로 분리한다.

1. `replace-building`: 단독 점포 건물의 MapLibre extrusion을 준비 완료 후 숨기고 전체 업종 점포 모델로 교체
2. `rooftop-marker`: 복합건물 extrusion을 유지하고 옥상에 독립 업종 3D object 배치
3. `marker fallback`: overlay 건물 연결 자체에 실패한 점포만 업종별 marker로 유지

Three.js custom layer는 `renderingMode: "3d"`를 유지한다. 옥상 오브젝트도 깊이 검사를 끄거나 건물을 투과해 그리지 않고 실제 건물 높이를 altitude로 사용한다. `renderOrder`는 Three.js 장면 내부의 category object 순서만 조정하며 MapLibre 건물과의 depth 관계를 무시하는 용도로 사용하지 않는다.
