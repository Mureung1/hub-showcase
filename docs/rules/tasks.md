# 개발 태스크 (2주 로드맵, 주 4일 + 보충일 기준)

## 원칙
- 오늘(2026-07-13, 월요일) 기준 1주차 시작. 각 주차는 월~목(Day1~4) 진행 + 금요일·주말은 그 주에 못 끝낸 부분을 채우는 **보충일**로 비워둔다.
- **Day1: 화면 라우팅 + 레이아웃 뼈대만 만든다.** 데이터가 도는 것처럼 보이게 만드는 mock이 아니라, 화면 전환만 되는 빈 껍데기(입력 폼은 있지만 제출해도 아무 처리 없음)다.
- **Day2부터는 기능 단위로, 그때그때 FE·BE·DB를 한 번에 완성한다.** mock을 거치지 않고 바로 실제 데이터로 연결해서, 나중에 "실제 데이터 연결" 단계를 따로 두지 않는다.
- 각 기능을 시작하기 전에, 그 기능의 API 요청/응답 모양(타입)을 먼저 간단히 적어두고 시작한다 (계약 우선). FE/BE가 같은 모양을 보고 짜야 나중에 안 맞아서 다시 짜는 일이 없다.
- **2주 범위에서 제외**: 프로토타입 화면 8~9의 "AI 자연어 일정 해석" 기능,투표 마감 재오픈 기능.

## 참고: 핵심 사이클(일정 입력→결과 산출)을 더 빨리 만들고 싶다면 미룰 수 있는 것들

투표/결과 산출이 로그인보다 중요한 기능이라 우선 완성하고 싶을 경우, 아래 항목들은 1차 구현에서 최소화하거나 나중으로 미뤄도 핵심 흐름엔 지장 없다.

- **일정 입력 UX**: 처음부터 드래그/long-press 선택을 구현하지 않고, 셀 클릭으로 토글하는 단순한 방식으로 먼저 만들어도 됨 (드래그 UX는 원래도 2주차 Day2에 별도로 예정돼 있음).
- **히트맵 클릭 시 근거(가능인원/선호인원) 상세 표시**: 결과 화면에 색상 순위만 먼저 보여주고, 클릭 시 상세 인터랙션은 나중에 추가해도 됨.
- **참여자 목록 개별 관리(이름별 삭제 등)**: 관리자 대시보드에 처음엔 "몇 명 중 몇 명 완료" 카운트만 보여주고, 개별 참여자 삭제 등 상세 관리는 나중으로 미뤄도 됨.
- **비밀번호 3회 이상 틀렸을 때 삭제 요청 기능** (`plan.md` 로그인 기획 13번): 처음엔 실패 횟수 제한 없이 계속 재입력만 받게 하고, 실패 횟수 카운트·삭제 요청·관리자 승인 흐름은 후순위로 미뤄도 핵심 흐름엔 지장 없음.
