## 작업 내용

1주차 Day1 "화면 라우팅 + 레이아웃 뼈대 개발" 작업. 데이터가 도는 것처럼 보이는 mock이 아니라, 화면 전환만 되는 빈 껍데기(입력 폼은 있지만 제출해도 아무 처리 없음)를 만드는 단계다.

## 라우팅 규칙

- `/` — 홈
- `/new` — 약속 만들기
- `/a/:id` — 약속 진입점. 세션 없으면 참여 화면(화면3), 있으면 role에 따라 관리자(화면5)/참여자(화면6) 대시보드로 분기. 생성 직후엔 이 경로 위에 생성 완료 모달(화면4)이 뜬다.
- `/a/:id/schedule` — 일정 입력(화면7)
- `/a/:id/result` — 최종 결과(화면10)
- 관리자·참여자가 동일 링크(`/a/:id`)로 접속한다는 `plan.md` 원칙에 따라, role별 경로를 따로 두지 않고 하나의 경로에서 분기한다.

## 완료 기준

- [ ] 5개 경로가 모두 `react-router`에 연결되어 있다.
- [ ] 10개 화면(placeholder 포함) + 모달 3종 뼈대가 모두 존재한다.
- [ ] `/a/:id` 접속 시 세션 유무·role에 따라 참여 화면/관리자 대시보드/참여자 대시보드로 갈리는 분기 골격이 동작한다.
- [ ] 공용 모달(상태 기반 오버레이, 뒤로가기로 안 닫힘)이 화면4·8·9에서 공유된다.
- [ ] 전체 화면·모달 전환이 끊김 없이 수동으로 확인된다.

## 우선순위

- 우선순위: 높음 (1주차 Day1, 이후 모든 기능 개발의 전제)

## 작업 순서

아래 순서대로 진행한다. 각 묶음이 끝날 때마다 `npm run dev`로 브라우저에서 실제 화면 전환을 확인한 뒤 다음 묶음으로 넘어간다.

### 1. 레이아웃 + 라우터
1. 공통 레이아웃(Header) 컴포넌트 — `docs/rules/design/아이콘.png` 로고 포함 헤더 + 전체 페이지를 감싸는 Layout 래퍼
2. 라우터 테이블 구성 — 5개 경로 연결, 각 경로를 Layout으로 감싸고 임시 placeholder 배치 (`App.tsx`의 `ProjectIntro` 대체)

### 2. 홈 / 약속 만들기 / 참여하기 화면
3. 홈 화면(화면1) — 약속 만들기 / 기존 약속 참여하기 진입 버튼 뼈대
4. 약속 만들기 화면(화면2) — 입력 폼 뼈대(제출 처리 없음)
5. 기존 약속 참여하기 화면(화면3) — 코드/이름/비밀번호 입력 폼 뼈대 + URL 초대 코드 자동 채움

### 3. 공용 모달 + 분기 뼈대
6. 공용 모달(오버레이) 컴포넌트 — 상태 기반, 뒤로가기로 안 닫힘, 화면4·8·9가 공유
7. `/a/:id` 진입점 분기 뼈대 — 세션 유무·role에 따른 조건 분기 골격 (실제 세션 판정 로직은 Day3 범위)

### 4. 대시보드 2종
8. 관리자 대시보드(화면5) 뼈대
9. 참여자 대시보드(화면6) 뼈대

### 5. 모달 연결 3종
10. 약속 생성 완료 모달(화면4) 연결 — 약속 만들기 제출 후 `/a/:id` 이동, 공용 Modal로 링크 공유 UI 뼈대
11. 투표 마감 확인 모달(화면9) 연결 — 관리자 대시보드 마감 버튼 클릭 시 공용 Modal
13. 투표 확정 전 확인 모달(화면8) 연결 — 일정 입력 화면 제출 시 공용 Modal

### 6. 일정 입력 / 최종 결과
12. 일정 입력 화면(화면7) 뼈대 — 가능한 시간/선호 시간 2단계 전환 골격(그리드 UX는 2주차 범위)
14. 최종 결과 화면(화면10) 뼈대 — `/a/:id/result` placeholder

### 7. 마지막 확인
15. 전체 경로 수동 워크스루 — 10개 화면·3개 모달 전체가 뼈대 수준에서 끊김 없이 연결되는지 확인 (위 완료 기준 체크)
