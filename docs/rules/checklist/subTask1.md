## 작업 내용

`docs/rules/subTasks.md`(UI/UX 고도화 전체 계획)의 화면1(홈)·화면2(약속 만들기)·화면3(기존 약속 참여하기) + 공통 인프라를 다루는 첫 묶음. 이후 모든 화면이 재사용할 `ScreenHint`(안내 문구)와 화면/모달 전환 트랜지션을 이 묶음에서 먼저 만든다. 약속 만들기 화면은 날짜/시간 입력을 각 4번 선택하던 것을 날짜 1번·시간 1번으로 줄이는 구조 변경(신규 라이브러리 2개 도입)을 포함해 이번 묶음 중 가장 무겁다.

## 확정된 설계 결정

- 날짜 range picker: `react-day-picker` 신규 도입 — 캘린더 하나에서 시작일~종료일을 선택하는 1회 인터랙션. 응답마감(단일 날짜) 선택에도 재사용.
- 시간 range 선택: `rc-slider`(dual-handle range 모드) 신규 도입 — `step`을 30분 단위(0~47, 하루 48슬롯)로 고정해 "30분 단위만 선택 가능"을 슬라이더 자체 제약으로 보장(별도 검증 로직 불필요).
- 두 컴포넌트 모두 값의 형태만 기존 zod 스키마(`shared/src/appointments.ts`)에 맞춰 매핑하고, 계약 자체는 바꾸지 않는다.

## 작업 순서

아래 순서대로 진행한다. 각 묶음이 끝날 때마다 `npm run dev`로 브라우저에서 실제 확인한 뒤 다음 묶음으로 넘어간다.

### 1. 공용 인프라
1. `client/src/components/ScreenHint.tsx` 신설 — "지금 할 일"을 작은 회색 텍스트로 표시하는 범용 컴포넌트(`text: string` prop). 화면 최상단 전용이 아니라, 화면 전체 안내로 쓸 수도 있고 특정 입력창/선택창 바로 아래처럼 필요한 위치에 개별적으로 배치할 수도 있어야 함 — 위치를 컴포넌트가 정하지 않고 호출부(각 화면)가 렌더링 위치를 자유롭게 정하는 구조(예: 마진 없는 인라인 컴포넌트로 만들고 배치는 부모의 레이아웃에 맡김)로 설계
2. 화면/모달 전환 트랜지션 CSS 유틸 작성 — `client/src/index.css`(또는 `Layout.css`)에 fade/slide 트랜지션 클래스 추가, `Modal.tsx`의 열림/닫힘에 우선 적용

이 묶음이 끝나면: `ScreenHint`를 화면 상단과 특정 입력 필드 아래 등 서로 다른 위치에 각각 임시로 붙여 봐도 정상 렌더링되는지, 모달을 열고 닫을 때 트랜지션이 부드럽게 동작하는지 확인한다.

### 2. 홈 화면
3. `HomePage.tsx` 상단에 서비스 설명 문구 + 이미지 배치, 그 아래 기존 "새 약속 만들기"/"기존 약속 참여하기" 버튼 유지. 이미지는 프로토타입(`docs/prototype`)의 캘린더 미리보기 카드를 그대로 구현하는 게 아니라 별도로 준비하는 이미지를 사용한다(이미지 에셋은 추후 전달). 프로토타입 화면1의 🔔 알림 아이콘은 넣지 않는다 — 현재 코드(`Layout.tsx`)에는 애초에 그런 아이콘이 없으니, 프로토타입을 참고하는 과정에서 실수로 새로 추가하지 않도록 주의
4. `ScreenHint` 적용

이 묶음이 끝나면: 브라우저에서 홈 화면이 설명 → 이미지 → 버튼 순서로 보이고, 알림 아이콘이 없는지 확인한다.

### 3. 약속 만들기 — 날짜/시간 입력 구조 변경
5. `react-day-picker` 설치, `client/src/components/DateRangeField.tsx`(가칭) 신설 — 캘린더 하나에서 시작일~종료일 범위 선택. `NewAppointmentPage.tsx`의 기존 `dateStart`/`dateEnd` input 2개를 이 컴포넌트 1개로 교체
6. `rc-slider` 설치, `client/src/components/TimeRangeSlider.tsx`(가칭) 신설 — dual-handle range 슬라이더, `step`을 30분 단위로 고정, 마크에 `HH:mm` 표시. `NewAppointmentPage.tsx`의 기존 `timeStart`/`timeEnd` input 2개를 이 컴포넌트 1개로 교체
7. 응답마감(선택) — 기존 형식(날짜+시간, 현재 placeholder `연도-월-일 --:--`)은 그대로 유지하고 텍스트 직접입력만 클릭 선택형으로 교체: `DateRangeField`를 단일 날짜 모드로 재사용 + 별도 시간 선택 추가. 마감은 특정 시각 하나를 고르는 것이라 `rc-slider`의 dual-handle range는 필요 없고, `<input type="time">` 또는 간단한 시간 select로 구성
8. 두 컴포넌트의 출력값을 기존 zod 스키마가 기대하는 문자열 형태(`YYYY-MM-DD`/`HH:mm`)로 매핑
9. `관리자 비밀번호` 필드 아래에 `ScreenHint`로 경고 문구 추가 — "비밀번호를 잊으면 관리자로 다시 접속할 수 없어요. 꼭 기억해주세요."(프로토타입의 `field-hint` 문구를 그대로 가져오되, 화면 전체가 아니라 특정 필드에 붙는 위치 유동적 `ScreenHint`의 첫 실사용 사례)
10. `NewAppointmentPage.test.tsx` 갱신 — 변경된 입력 UI에 맞게 테스트 보완

이 묶음이 끝나면: 브라우저에서 날짜 범위를 캘린더로, 시간 범위를 슬라이더로, 응답마감을 날짜+시간 선택형으로 선택해 실제 약속이 생성되는지, 30분 단위가 아닌 값은 시간 슬라이더에서 애초에 선택 불가능한지, 관리자 비밀번호 필드 아래 경고 문구가 뜨는지 확인한다.

### 4. 기존 약속 참여하기
11. `JoinAppointmentForm.tsx` 화면 배치/간격 정돈(참고 사진 기준), 참여 링크/이름/간편 비밀번호 필드마다 가벼운 설명 문구 추가
12. `ScreenHint` 적용

이 묶음이 끝나면: `/join`과 `/a/:id`(세션 없을 때) 양쪽에서 화면이 정돈된 배치로 보이는지 확인한다.

### 5. 통합 확인
13. 홈 → 약속 만들기(새 UI로 생성) → 생성완료 → 참여하기(새 레이아웃)까지 전체 워크스루
