# UI/UX 고도화 작업 (2주차 Day2~4 대체)

## 작업 내용

핵심 기능 사이클(약속 생성 → 참여 → 일정 입력 → 결과 확인)은 1주차~2주차 Day1까지 구현 완료됨. 원래 로드맵의 2주차 Day2~4(그리드 드래그 UX, 마감 UX 개선, 예외처리)는 이번엔 진행하지 않고, 사용자가 화면별로 직접 지정한 UI/UX 고도화 작업을 화면1(홈)부터 순서대로 진행한다. 단순 스타일링을 넘어 일부 화면(약속 만들기의 날짜/시간 입력 방식, 일정입력/결과 화면의 날짜 탐색 방식)은 상호작용 구조 자체를 바꾼다. 최종결과 화면의 "히트맵 클릭 시 근거 표시" 기능과 그 외 편의 기능은 이 작업 이후 별도로 진행한다.

## 확정된 설계 결정

- **날짜 range picker**: `react-day-picker` 신규 도입 — 약속 만들기의 후보 날짜 선택(1회)과 응답마감의 날짜 부분 선택에 재사용. 응답마감은 DB 컬럼(`appointments.deadline timestamptz`)이 날짜+시간을 함께 담으므로, 피커로 바꾸더라도 날짜+시간을 모두 선택하게 해 형식을 그대로 유지한다(시간 부분은 별도 시간 선택 UI 추가).
- **시간대 선택**: `rc-slider`(dual-handle range 슬라이더) 신규 도입 — `range` 모드로 핸들 2개(시작/종료)를 한 번의 드래그로 조작. `step`을 30분 단위(0~47, 하루 48슬롯)로 고정하면 "30분 단위만 선택 가능"이 슬라이더 자체 제약으로 보장되어 별도 검증 로직이 필요 없다. `react-datepicker`(`showTimeSelectOnly`+`timeIntervals={30}`)도 검토했으나 이는 드롭다운형 단일 시각 선택기라 시작/종료를 각각 따로 열어야 해서 "1번의 선택 흐름"에 덜 맞고, 슬라이더 쪽이 터치 기반 모바일 UX에도 더 자연스럽다. 마크(라벨)에 `HH:mm` 포맷 표시.
- **애니메이션**: framer-motion 등 신규 라이브러리 없이 우선 CSS transition으로 구현(모바일 웹 번들 크기 고려). 필요성이 커지면 그때 재검토.
- **링크 복사**: `navigator.clipboard.writeText` + 복사 완료 토스트.
- **공용 컴포넌트 신설**: `ScreenHint`(작은 회색 안내문구 — 화면 최상단에 고정되는 게 아니라, 화면 전체 안내로도 쓰고 특정 입력창/선택창 바로 아래처럼 필요한 위치에도 유동적으로 배치할 수 있는 범용 컴포넌트로 설계), `CopyLinkBox`(링크 박스+복사버튼+완료 토스트), `ProgressBar`(참여현황 막대바) — 각각 처음 필요해지는 화면에서 만들고 이후 화면은 재사용만 한다.

- 순서 자체가 우선순위(화면1→11 순차 진행, 사용자 지정)
- 공용 컴포넌트(`ScreenHint`/`CopyLinkBox`/`ProgressBar`/트랜지션 유틸)는 처음 필요해지는 화면에서 만들고 그 뒤로는 재사용만 한다.
- 이 작업 완료 후: 최종결과 히트맵 클릭 시 근거(가능/선호 인원) 표시 기능 → 그 외 편의 기능(시간 보고 추가)

## 작업 순서

각 화면 작업 후 `npm run dev`로 브라우저에서 직접 확인(design skill 활용)한 뒤 다음 화면으로 넘어간다.

### 1. 홈 (`client/src/pages/HomePage.tsx`)
상단에 서비스 설명 문구 + 별도로 준비하는 이미지 배치(프로토타입의 캘린더 미리보기 카드 아님), 그 아래 기존 버튼("새 약속 만들기"/"기존 약속 참여하기") 유지. 프로토타입 화면1의 🔔 알림 아이콘은 넣지 않는다. 이 화면에서 `ScreenHint`(위치 유동적인 작은 회색 안내문구) 공용 컴포넌트와 화면/모달 전환 트랜지션 CSS 유틸을 함께 구축해 이후 화면에서 재사용한다.

### 2. 약속 만들기 (`client/src/pages/NewAppointmentPage.tsx`)
- `react-day-picker` 도입: 현재 `<input type="date">` 2개(dateStart/dateEnd)를 캘린더 1개에서 범위 선택하는 1회 인터랙션으로 교체.
- `rc-slider`(range 모드, step=30분) 도입: 현재 `<input type="time">` 2개(timeStart/timeEnd)를 dual-handle 슬라이더 1회 인터랙션으로 교체. 30분 단위 강제가 슬라이더 step으로 자동 보장됨.
- 응답마감(선택): DB 컬럼(`deadline timestamptz`)이 날짜+시간을 함께 담으므로, 텍스트 직접입력을 날짜(`react-day-picker` 단일 날짜 모드) + 시간(`<input type="time">` 등 단일 시각 선택) 조합으로 교체해 형식은 그대로 유지한다.
- 관리자 비밀번호 필드 아래 `ScreenHint`로 경고 문구("비밀번호를 잊으면 관리자로 다시 접속할 수 없어요") 추가.
- zod 스키마(`shared/src/appointments.ts`)가 기대하는 값의 "형태"는 그대로 유지하고, FE 입력 UI만 교체한다.

### 3. 기존 약속 참여하기 (`client/src/components/JoinAppointmentForm.tsx`, `client/src/pages/JoinAppointmentPage.tsx`)
화면 간 배치·간격을 정돈하고, 참여 링크/이름/간편 비밀번호 각 필드에 가벼운 설명 문구를 추가한다. `ScreenHint` 재사용.

### 4. 약속 생성완료 모달 (`client/src/pages/AppointmentPage.tsx`의 `Modal` 사용부)
`CopyLinkBox`(링크를 별도 박스에 표시 + 복사 버튼 클릭 시 `navigator.clipboard.writeText`로 자동 복사 + 복사완료 토스트) 신설·적용. 모달 아이콘/트랜지션도 함께 개선.

### 5. 관리자 대시보드 (`client/src/components/AdminDashboard.tsx`)
- 상단에 약속 제목 + 기한(날짜/시간 범위) 표시.
- `ProgressBar`(참여현황 막대바+퍼센트) 신설·적용 — 기존 텍스트("N명 중 N명 완료")와 병기.
- `CopyLinkBox`(4번) 재사용.
- "투표 마감하기" 버튼 빨간색으로 변경, "약속 투표하기" 버튼은 파란색 유지.
- 하단에 참여자 이름 + 응답 상태 목록 표시 — 개별 참여자별 완료 여부를 내려주는 API가 현재 있는지 확인 필요(현재 `response-status`는 `completedCount` 합계만 반환할 가능성이 있음). 없다면 BE 응답을 소폭 확장한다.

### 6. 참여자 대시보드 (`client/src/components/ParticipantDashboard.tsx`)
5번과 동일한 상단 구조(제목/기한, `ProgressBar`, `CopyLinkBox`, "약속 투표하기" 버튼)를 재사용하되 "투표 마감하기" 버튼은 없음. 하단은 전체 참여자 목록 대신 "내 응답 상태"(완료 여부 배지, 입력 완료일시, "응답을 수정하고 싶다면 다시 접속해주세요" 안내)로 대체 — 완료일시 데이터가 현재 API에 없다면 확장 필요.

### 7. 일정 입력 - 가능한 시간 (`client/src/components/ScheduleGrid.tsx`, `ScheduleEditor.tsx`)
날짜를 7일 단위로 표시하고 좌우 화살표로 7일씩 페이지 이동하는 방식으로 변경(원래 계획했던 페이지네이션). 시간은 세로로 길게 나열해 스크롤로 전체 확인. `ScreenHint` 적용.

### 8. 일정 입력 - 선호 시간 (`client/src/components/ScheduleEditor.tsx` 2단계)
안내 문구("특별히 더 선호하는 시간대가 있으신가요? 가능한 시간 중 특히 원하는 시간만 선택해 주세요")와 색상 범례(진한 파랑=선호, 연한 파랑=가능(선택))를 화면에 표시. 현재 "가능한 시간" 셀이 회색으로 표시되는 부분을 1단계에서 칠했던 연한 파랑으로 유지하도록 수정 — 토글 시 연한 파랑(가능)↔진한 파랑(선호)으로 전환.

### 9. 투표 확정 전 확인 모달 (`ScheduleEditor.tsx`의 confirm modal)
상단 체크 아이콘(원형 배지), "입력을 확정할까요?" 제목, "아래와 같이 제출됩니다" 설명, 가능한 시간 n건/선호 시간 n건 선택 요약, "제출 후에도 투표 마감 전까지 수정할 수 있어요" 안내, "확정하기"/"돌아가기" 버튼으로 UI 개선. 4번에서 만든 아이콘/트랜지션 패턴 재사용.

### 10. 투표 마감 확인 모달 (`AdminDashboard.tsx`의 confirm modal)
상단 경고 아이콘(빨간/주황 원형 배지, 느낌표), "투표를 마감할까요?" 제목, 참여 현황을 여기서도 `ProgressBar`(5번)로 표시, "마감 후에는 참여자가 더 이상 응답을 수정할 수 없습니다" 안내, "마감할게요"(빨간 버튼)/"취소" 버튼으로 개선.

### 11. 최종 결과 화면 (`client/src/components/ResultHeatmap.tsx`, `client/src/pages/ResultPage.tsx`)
히트맵도 7번에서 만든 7일 단위+화살표 페이지네이션 패턴을 재사용해 동일하게 적용(현재 가로 스크롤 전체 표시 방식에서 변경).

### 12. 전체 공통 마무리
모든 화면에 `ScreenHint` 안내문구와 화면/모달 전환 트랜지션이 빠짐없이 일관되게 적용됐는지 최종 워크스루로 확인한다.

## 사용자가 언급하지 않은 추가 개선 제안

코드베이스 조사 중 파악된, 사용자가 직접 언급하지는 않았지만 함께 고려하면 좋을 항목들이다. 시간 여유에 따라 위 12개 작업과 별도로 검토한다.

- **공용 Toast/Snackbar 컴포넌트 부재**: 복사완료 등 알림에 필요한데 현재 프로젝트에 없음. 화면마다 따로 만들지 말고 4번에서 공용화해 재사용.
- **폼 제출 버튼 로딩/비활성 상태 부재**: API 호출 중 버튼이 계속 활성 상태라 중복 제출 가능성이 있음.
- **빈 상태(empty state) UI 부재**: 참여자 0명, 결과 데이터 없음 등의 경우 별도 디자인이 없음.
- **색약 접근성**: 히트맵/선택 UI가 파란 명암 차이만으로 구분됨 — 아이콘·패턴 등 보조 표시 고려.
- **아이콘 버튼 접근성**: 복사·화살표 등 아이콘 버튼에 `aria-label` 등 최소 접근성 속성이 없음.
- **잘못된 `:id` 접근 시 처리**: 현재 최소 방어만 되어 있음(1주차 Day2 알려진 한계) — 이번 기회에 에러 화면 UI도 함께 다듬을지 검토.
- **참여 정원 초과(409) 안내 문구**: BE는 이미 처리하지만 FE 문구 스타일링이 되어 있는지 확인 필요.
