# evidence-data-roadmap.md — 근거·측정·데이터 로드맵

## 1. 문서 목적

이 문서는 **MBTI 기반 공부법 및 스트레스 관리 웹앱**이 흥미 중심의 추천에서 멈추지 않고, 설명 가능하고 검증 가능한 학습·회복 가이드로 발전하기 위한 연구 및 데이터 기준을 정의한다.

현재 프로토타입의 점수와 가중치는 제품 가설을 시험하기 위한 규칙이며, 심리측정학적으로 표준화된 검사나 임상적 판단 기준이 아니다. 따라서 점수를 사용자의 능력·성격·정신건강 상태에 대한 정확한 측정치로 표현하지 않는다.

## 2. 근거를 수집하는 기준

### 2.1 근거 계층

1. 체계적 문헌고찰과 메타분석
2. 반복 검증된 실험·현장 연구
3. 학습과학 및 인지과학 교과서·학회 가이드
4. 단일 연구와 탐색적 연구
5. 사용자 인터뷰와 제품 사용 데이터

제품 사용 데이터는 추천의 사용성과 맥락 적합성을 알려주지만, 그 자체로 학습법의 인과적 효과를 입증하지 않는다. 문헌 근거와 제품 내 관측 데이터를 분리해 관리한다.

### 2.2 근거 카탈로그 필드

각 학습법은 향후 다음 정보를 갖는다.

| 필드 | 설명 |
| --- | --- |
| `methodId` | 학습법의 안정적인 식별자 |
| `claim` | 제품에서 사용자에게 전달하는 주장 |
| `sourceType` | 메타분석, 실험, 가이드, 탐색 연구 등 |
| `population` | 연구 참여자와 학습 맥락 |
| `outcome` | 기억, 전이, 수행, 지속성 등 측정 결과 |
| `boundary` | 효과가 약해지거나 일반화가 어려운 조건 |
| `reviewedAt` | 마지막 검토 시점 |
| `productUse` | 설문·추천·설명 중 어느 부분에 쓰이는지 |

실제 문헌을 확인하기 전에는 제목, DOI, 효과크기 같은 세부값을 채워 넣지 않는다.

## 3. MBTI의 역할과 한계

- MBTI는 친숙한 진입 언어이자 약한 선호 가설로만 사용한다.
- 추천의 주된 근거는 사용자가 보고한 공부 행동, 현재 맥락, 피로·회복 신호다.
- MBTI 유형 간 우열, 성적 예측, 고정된 학습 능력 차이를 주장하지 않는다.
- 베타 검증에서는 MBTI 힌트를 포함한 모델과 제외한 모델을 비교해 MBTI가 실제 추가 설명력을 제공하는지 확인한다.
- 추가 설명력이 확인되지 않으면 MBTI 가중치를 축소하거나 진입 UI에만 남기는 선택을 허용한다.

### 3.1 두 입력 경로

| 경로 | 입력 | 제품 표시 | 추천 사용 |
| --- | --- | --- | --- |
| 공식 결과 직접 입력 | 사용자가 외부 공식 MBTI 평가에서 받은 결과 | `공식 결과 직접 입력` | 약한 추가 힌트 |
| 공부습관 자체 점검 | 독자적인 소수 상황형 문항 | `4축 탐색 신호`, `공식 판정 아님` | 현재 모델에는 자동 투입하지 않음 |

자체 점검은 공식 MBTI 문항을 번역·축약·표현 변경한 도구가 아니다. 문항은 학습 상황과 행동을 바탕으로 독립적으로 작성하고, 공식 도구와의 비교는 허가·윤리·연구설계를 갖춘 별도 연구에서 수행한다.

### 3.2 공식 도구와 독자 문항의 권리 경계

- 공식 MBTI 문항, 채점 규칙, 결과 자료를 허가 없이 복제·수정·번역하지 않는다.
- 제품 내 `MBTI` 상표 사용 방식과 고지 문구를 배포 지역 기준으로 검토한다.
- 공식 assessment를 직접 제공하려면 출판사 라이선스·사용 자격·결과 해석 절차를 별도 확인한다.
- 독자 문항은 `MBTI 판정`이 아니라 `MBTI 유사 4축 탐색 신호`로 명명한다.

## 4. 측정 모델

### 4.1 현재 MVP 관측값

- MBTI 선택 또는 모름
- 공부 행동 설문 응답
- 스트레스·피로 반응 설문 응답
- 규칙 기반 행동지표
- 추천 공부법과 오늘의 루틴
- 추천 적합도 피드백
- 루틴 완료, 집중도, 피로도에 대한 자기보고

### 4.2 점수의 의미

행동지표 점수는 추천 후보를 정렬하기 위한 내부 신호다. `70점`이 높은 능력이나 정상·비정상을 의미하지 않는다. 사용자 화면에서는 순위나 판정보다 “현재 응답에서 두드러진 신호”와 추천 이유를 우선한다.

### 4.3 귀납적 정확도의 분해

| 측정 대상 | 질문 | 예시 지표 |
| --- | --- | --- |
| 신뢰도 | 반복 측정에서 축 신호가 안정적인가 | test-retest, internal consistency |
| 구조타당도 | 문항이 의도한 연속 차원을 측정하는가 | factor structure, measurement invariance |
| 수렴·판별타당도 | 관련 개념과 연결되고 다른 개념과 구분되는가 | convergent/discriminant validity |
| 증분타당도 | task/state-only보다 MBTI 추가 모델이 나은가 | out-of-sample improvement, calibration |
| 조절효과 | 특정 신호가 전략 효과의 차이를 설명하는가 | strategy × signal interaction |
| 제품 효용 | 추천이 실제 행동·학습을 개선하는가 | 실행률, 지연 인출, 부담 변화 |

사용자 수가 많다는 사실만으로 위 타당도가 성립하지 않는다. 각 claim에 맞는 측정도구, 비교군, 결과 변수와 분석 계획이 필요하다.

### 4.4 추천 품질 평가

베타 단계에서는 다음을 분리해 측정한다.

- 적합도: 이 추천이 현재 상황에 맞는가
- 이해도: 추천 이유를 납득할 수 있는가
- 실행 가능성: 오늘 실천할 수 있는가
- 실행 여부: 실제로 루틴을 시도했는가
- 단기 변화: 실행 전후의 집중도·피로도 자기보고 변화
- 학습 결과: 즉시 정답률과 분리된 지연 인출·오답 변화

이 값은 추천 시스템을 평가하는 값이지 사용자를 평가하는 점수가 아니다.

적합도·이해도·실행 가능성은 수용성 지표다. 알고리즘 정확도나 학습 효과와 동일시하지 않는다.

### 4.5 learning-styles matching 반증 기준

- 선호하는 방식과 실제로 학습효과가 높은 방식을 구분한다.
- 모든 사용자에게 제공하는 evidence-based baseline을 유지한다.
- `task/state-only`, `task/state + MBTI` 모델을 동일 결과 변수로 비교한다.
- MBTI별 고정 학습법 표를 정답처럼 만들지 않는다.
- 유형 차이가 아니라 연속 신호와 전략 사이의 조절효과를 우선 분석한다.
- 조절효과가 재현되지 않으면 MBTI를 설명·온보딩 계층으로만 남긴다.

## 5. 결측과 NMAR 대응

사용자가 설문이나 후속 평가에 응답하지 않는 이유는 무작위가 아닐 수 있다. 예를 들어 추천이 맞지 않거나, 피로가 높거나, 앱을 중단한 사용자가 후속 평가를 덜 남기면 관측된 만족도는 실제보다 높아질 수 있다.

따라서 베타 분석에서는 다음을 기록·보고한다.

- 단계별 이탈률과 문항별 무응답률
- 추천 유형·기기·세션 길이에 따른 응답률 차이
- 완료 사용자만 분석한 결과와 전체 사용자 경계를 함께 제시
- 결측을 임의의 평균값으로 채우지 않기
- 결측 메커니즘을 MCAR/MAR/NMAR 후보로 구분하되 데이터만으로 NMAR을 확정하지 않기
- 가능한 경우 최선·최악 시나리오 또는 민감도 분석 수행

## 6. 알고리즘 검증 로드맵

### 단계 A — 규칙 감사

- 모든 가중치와 조건을 표로 공개한다.
- 같은 입력에는 같은 결과가 나오는지 확인한다.
- 경계값 전후에서 결과가 과도하게 바뀌지 않는지 확인한다.
- MBTI 힌트가 설문 응답을 압도하지 않는지 확인한다.

### 단계 B — 사용성 검증

- 추천 이유의 이해도와 실행 가능성을 평가한다.
- “나를 고정적으로 판단한다”는 인상을 주는지 인터뷰한다.
- 기타 의견을 정성 코딩해 반복되는 실패 유형을 찾는다.

### 단계 C — 비교 검증

- 일반 추천과 개인화 추천을 비교한다.
- MBTI 힌트 포함·제외 결과를 비교한다.
- 사전 등록한 지표와 분석 계획을 사용한다.
- 탐색 결과와 확인 결과를 구분한다.
- 만족도, 실행률, 지연 학습성과, 부담을 별도 outcome으로 분석한다.
- MBTI 추가 모델은 task/state-only baseline 대비 증분효과를 보고한다.
- 동일 사용자의 반복 관측에서는 사용자 내 변화와 사용자 간 차이를 구분한다.

### 단계 D — 알고리즘 갱신

- 알고리즘 버전을 결과와 함께 기록한다.
- 변경 전후 지표를 비교하고 회귀 테스트를 유지한다.
- 데이터가 충분하다는 이유만으로 복잡한 모델을 도입하지 않는다.
- 설명 가능성과 실제 개선이 확인될 때만 모델 복잡도를 높인다.

## 7. 데이터 저장과 개인정보

### MVP

- 결과와 피드백은 사용자의 브라우저 `localStorage`에만 저장한다.
- 저장된 정보가 서버나 Git repository로 전송되지 않는다는 점을 명시한다.
- 사용자가 처음부터 다시 시작하거나 앱에서 결과·루틴 기록·추천 평가를 한 번에 지울 수 있게 한다.
- `resultId`, 입력 출처, 알고리즘 버전, baseline 추천, MBTI 추가 추천을 구분해 저장한다.

### 동의 기반 베타

로그인과 서버 저장은 다음 조건을 충족한 뒤 별도 단계로 도입한다.

- 수집 목적, 필수·선택 필드, 보존기간 명시
- 동의 철회와 데이터 삭제 경로 제공
- 식별정보와 설문·행동 데이터 분리
- 최소권한 접근, 전송·저장 보호, 접근 기록
- 자유응답의 개인정보 포함 가능성 안내와 필터링
- 연구 활용과 제품 개선 활용의 동의 분리
- 공식 MBTI 결과, 자체 탐색 신호, 과업·상태, 결과 데이터를 서로 다른 필드로 분리
- 평가 요청이 노출됐는지와 응답하지 않았는지 기록
- 로그인 없이 가능한 가명 파일럿과 계정 기반 종단 연구를 별도 비교

자유응답이나 사용자 데이터를 GitHub repository의 issue, commit, JSON 파일 등에 직접 저장하지 않는다. 저장소는 코드와 비식별 예시 데이터만 관리한다.

## 9. 대학 플랫폼 부가기능 검토

에브리타임이나 학교 사이트 연동은 핵심 가설이 아니라 배포 채널·맥락 확장 가설이다. 다음이 확인된 뒤 검토한다.

1. 해당 플랫폼의 공식 API 또는 허용된 연동 방식이 존재한다.
2. 사용자 동의와 학교 정책을 충족한다.
3. 과목·일정 데이터 없이도 핵심 추천 가치가 먼저 검증된다.
4. 연동이 새로운 비교·감시·성적 예측 기능으로 변질되지 않는다.

공식 연동 수단이 확인되지 않은 플랫폼을 대상으로 스크래핑이나 비공식 자동화를 전제로 기획하지 않는다.

## 10. OpenAI 기능 도입 조건

OpenAI 기능은 현재 MVP 범위에 포함하지 않는다. 추후에는 자유응답 요약, 사용자가 선택한 연구 주제의 질문 구조화, 추천 설명의 개인화 같은 보조 기능을 검토할 수 있다.

도입 전에는 다음을 확인한다.

- 규칙 기반 기능으로 해결되지 않는 구체적 사용자 문제가 있는가
- 입력 데이터 최소화와 민감정보 차단이 가능한가
- 생성 결과의 출처·불확실성을 사용자에게 표시할 수 있는가
- 비용, 지연, 실패 시 대체 흐름을 감당할 수 있는가
- 모델 출력이 진단·성적 예측·연구주제 자동 판정으로 오해되지 않는가

특정 날짜의 OpenAI 업데이트를 제품 근거로 삼을 때는 실제 공식 문서와 모델 동작을 도입 시점에 다시 확인한다.
