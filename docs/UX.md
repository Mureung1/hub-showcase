# UX 조사 — 답냥이에 가장 좋은 방식

> **상태: 조사 완료 (2026-07-07, 웹 조사 + 기존 설계 결정 대조).** 결론이 SCREENS.md 결정과 일치하면 "근거 확보"로, 빈틈이면 구체 지침으로 적었다. 구현 반영 시점은 CHECKLIST.md 해당 항목(T8, T10, T14).

## 1. 이 서비스의 UX 문제 정의

답냥이의 성공 루프는 경로별로 다르다. 외부 파일럿의 잠정 목표는 **카드 경로 S0→결과 20초**, **직접입력 경로 S0→복사 60초**다:

```
카톡에서 보낼 말이 막힘 → 진입 → 방식·관계 선택 → [상황 카드 → 즉시 결과] 또는 [다른 상황 → 목적·입력 → 생성 대기] → 3개 비교 → 복사 → 카톡 복귀
```

UX가 승부를 보는 지점은 4곳이고, 이 문서는 각 지점의 검증된 패턴을 조사해 적용을 결정한다:

1. **입력 전** — "내 상황이네"라고 3초 안에 느끼게 (시나리오 카드)
2. **대기** — 5~20초를 불안 없이 기다리게 (생성 로딩)
3. **선택** — 후보 3개를 노력 없이 비교하게 (결과 화면)
4. **복사-복귀** — 마지막 행동이 반드시 성공하게 (클립보드)

## 2. 대기 UX — 스켈레톤 + 동적 상태 문구 (스트리밍은 채택 안 함)

**조사 결과**: 생성 AI 대기의 업계 표준은 토큰 스트리밍이다 — 첫 토큰이 0.5초 안에 보이면 체감 대기가 거의 0이 된다 ([TheFrontKit](https://thefrontkit.com/blogs/what-is-streaming-ui-in-ai-applications)). 그러나 스트리밍이 불가한 경우의 권장 패턴은 **스켈레톤 스크린 + 동적 텍스트 업데이트**로, 5초를 넘는 대기에서는 정적 스피너 대신 "AI가 무엇을 하고 있는지"를 문구로 보여줘야 대기가 '생각하는 과정'으로 느껴진다 ([mindrind](https://mindrind.net/ux-ui-design-generative-ai-apps/), [UX Tigers — Think-Time UX](https://www.uxtigers.com/post/think-time-ux)).

**답냥이 결정 — 스트리밍 채택 안 함, 스켈레톤+문구 로테이션 채택**:
- 우리는 1회 호출로 후보 3개를 구조화(JSON)해 받는다. 토큰 스트리밍을 하면 후보 1이 완성될 때까지 후보 2·3 자리가 비고, 구조화 출력 파싱과도 충돌한다. **비교가 핵심 가치인 UI에서는 3개가 동시에 나타나는 편이 낫다.**
- 대신: **결과 카드와 같은 모양의 스켈레톤 3장**(도착할 결과의 예고편 역할) + **상태 문구 로테이션**(4~5초 간격): "상황을 읽고 있어요 →" "톤 3가지로 쓰고 있어요 →" "거의 다 됐어요". 10초 경과 시 "조금만 더 기다려주세요"로 전환해 20초 타임아웃 전 이탈을 줄인다.
- 생성 중단(stop) 버튼은 업계 권장이나 20초 타임아웃이 있는 MVP에서는 과잉 — 이후 단계.

## 3. 다중 후보 선택 UX — 세로 스택 3카드 + 원클릭 리롤 (현 결정에 근거 확보)

**조사 결과**: 후보 여러 개 제시는 검증된 패턴이다(ChatGPT의 2안 선택 등). 관건은 두 가지 — **비교가 노력 없이 가능해야 하고**(사용자는 비교를 위해 별도 조작을 하지 않는다), **재시도는 원클릭이어야** 한다 ([Smashing Magazine — Design Patterns for AI Interfaces](https://www.smashingmagazine.com/2025/07/design-patterns-ai-interfaces/), [Shape of AI — AI UX Patterns](https://www.shapeof.ai/patterns/follow-up)).

**답냥이 적용 — 기존 결정이 패턴과 일치, 세부 지침 추가**:
- 세로 스택 3카드(모바일에서 스와이프·탭 없이 스크롤만으로 비교) + 톤 배지 = 노력 없는 비교 ✓ (SCREENS 핵심 결정 1)
- AI 결과의 "다시 만들기" 원클릭 리롤 ✓. 템플릿 결과는 동작이 다른 "내 상황에 더 맞추기"로 분리 (SCREENS 핵심 결정 3)
- **추가 지침**: 카드 간 시각적 차이는 톤 배지로만 준다 — 카드 크기·색을 다르게 해 특정 후보를 추천하는 연출 금지(선택은 사용자 몫이라는 서비스 전제). 후보 전문을 접지 않고 모두 노출(카톡 메시지 길이면 접기가 불필요하고, 접으면 비교가 깨짐).

## 4. 복사 UX — 토스트 + 버튼 상태 전환 병행

**조사 결과**: 복사 성공 피드백은 신뢰의 필수 요소이고 토스트/스낵바가 표준이다. 단, **Android 13+는 클립보드 쓰기 시 시스템이 자체 확인 UI를 띄우므로 앱 토스트와 중복될 수 있다** ([Android Developers](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste), [flaming.codes — 클립보드 UX 연구](https://flaming.codes/en/posts/ux-study-copy-to-clipboard-action-web-api/)).

**답냥이 적용**:
- 이중 피드백 채택: **버튼 자체가 "복사됨 ✓" 상태로 1.5초 전환**(시선이 이미 버튼에 있음) + 짧은 토스트. Android 13+ 시스템 UI와 겹쳐도 짧아서 소음이 아니고, 시스템 UI가 없는 iOS·데스크톱을 커버한다.
- 토스트 위치는 **상단**: 하단은 엄지·키보드·인앱 브라우저 하단 바와 겹친다.
- 실패 폴백(텍스트 자동 선택)은 기존 결정 유지 ✓ — 카톡 인앱 브라우저에서 실기기 검증 필수 (CHECKLIST T23).

## 5. 일반 모바일 지침 (통용 원칙 — 별도 출처 없음)

- **주 CTA는 화면 하단**: S2 생성 버튼은 입력 필드 아래 고정 노출(스크롤에 묻히지 않게), 엄지 도달 범위.
- **터치 타깃 최소 44px**, 카드·버튼 간 간격은 DESIGN.md spacing 토큰(md 16px) 이상.
- **키보드 열림 대응**: S2에서 키보드가 열려도 생성 버튼 접근 가능해야 함(입력 후 키보드 닫기 강요 금지).
- 시나리오 카드 문구는 SPEC 1장 확정본 — 기능 설명이 아니라 **상황 공감 문구**("할 말은 해야 할 때")로 유지한다. 카드가 곧 서비스의 첫 신뢰 지점.
- **뷰포트**: 375×667에서 S0 선택 2개가 초기 화면에 보이고, 320×568에서 가로 넘침이 없어야 한다. 모바일 히어로는 핵심 선택을 밀어내지 않게 축소한다.
- **카드 밀도**: 상황 카드 6개는 2열 유지, "다른 상황이냥?"만 전체 폭. 탈출구가 화면 아래로 과도하게 밀리지 않게 한다.
- **초점·스크롤**: 단계 전환 시 새 제목으로 초점을 옮기고 상단으로 스크롤한다. 내부 S0~S3 이름은 사용자에게 노출하지 않는다.
- **선택·상태 접근성**: 목적 칩은 보이는 legend와 `aria-pressed`, 생성 영역은 `aria-busy`, 모든 버튼은 일관된 `:focus-visible`을 사용한다. 글자 수는 매 입력마다 전체를 읽지 않도록 과도한 `aria-live`를 피한다.
- **시각·모션**: 본문과 버튼은 WCAG 2.2 AA 대비를 충족하고, `prefers-reduced-motion`이면 스켈레톤 애니메이션을 중지한다. 긴 결과는 `overflow-wrap: anywhere`로 보호한다.
- **안전 영역**: sticky CTA는 `safe-area-inset-bottom`을 반영한다.

## 7. MVP 밖 (이후 단계 후보)

토큰 스트리밍 표시, 생성 중단 버튼, 후보 부분 수정(문장 단위 편집), 햅틱 피드백, 다크 모드.
