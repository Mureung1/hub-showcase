NAVER AI Agent Challenge · 개발 현황 발표

대학생 자취방 의사결정 도우미

매물을 찾는 서비스가 아니라, 사용자가 이 매물을 계약해도 되는지 판단하도록 돕는 AI 코파일럿입니다.

  • React/Vite
  • 브라우저 OCR
  • Gemini LLM 분석
  • localStorage 기반 MVP

01 · 문제 정의

첫 자취방 계약은 정보 탐색보다 의사결정이 어렵습니다

사용자 문제

  • 시세 대비 가격이 적절한지 판단하기 어렵다.
  • 관리비 포함 항목과 실제 월 지출을 놓치기 쉽다.
  • 부동산 용어와 계약 체크 포인트가 낯설다.
  • 통학 시간, 귀가 동선, 교통비 같은 숨은 비용을 고려하기 어렵다.
“매물을 찾는 것보다, 이 매물을 계약해도 되는지 판단하는 것이 더 어렵다.”

기존 부동산 플랫폼은 탐색에 강하지만, 첫 자취생에게 필요한 것은 계약 전 의사결정 보조입니다.

02 · 해결 방향

사용자 조건과 매물 정보를 함께 분석합니다

개인화 기준 사용자 정보

학교, 예산, 주당 등교 횟수, 귀가 시간

매물 입력 OCR + 수정

스크린샷에서 텍스트를 추출하고 사용자가 보정

결과 AI 분석

비용, 통학, 신뢰도, 체크리스트, 추가 질문

03 · 현재 구현 상황

MVP 핵심 플로우가 동작하는 상태입니다

구현 완료
  • 사용자 정보 4단계 입력 폼
  • 사용자 정보 localStorage 저장
  • 매물 스크린샷 업로드 및 미리보기
  • Tesseract.js 기반 브라우저 OCR
  • OCR 텍스트 기반 매물 필드 자동 파싱
  • Gemini API 기반 구조화 분석 결과 생성
다음 범위
  • 분석 결과 저장 및 목록화
  • 여러 매물 비교 테이블
  • 시세/교통/생활 편의 데이터 연동
  • 리포트 전용 화면과 공유 흐름

04 · 서비스 플로우

입력, OCR, 검토, LLM 분석으로 이어지는 흐름

1

사용자 정보

학교, 예산, 통학 패턴을 최초 1회 입력합니다.

2

스크린샷 업로드

부동산 플랫폼의 매물 화면을 이미지로 올립니다.

3

OCR 처리

브라우저에서 Tesseract.js로 텍스트를 추출합니다.

4

정보 보정

주소, 월세, 관리비, 면적 등을 사용자가 확인합니다.

5

AI 분석

Gemini가 비용, 통학, 위험 요소를 구조화합니다.

05 · 데이터 흐름

이미지는 서버로 보내지 않고 텍스트와 필드만 전송합니다

Frontend

  • React/Vite 기반 화면 구성
  • 사용자 정보와 매물 정보를 localStorage에 저장
  • OCR은 브라우저에서 실행해 이미지 업로드 부담을 줄임
  • 분석 요청은 Vite proxy를 통해 `/api/analyze-listing`으로 전달

Server

  • Express API 서버가 요청 유효성을 검사
  • Gemini API key와 model은 `.env`에서 관리
  • `models.generateContent`와 JSON Schema로 분석 결과 구조 고정
  • 프론트에는 `analysis` JSON만 반환

07 · 기술 선택

프론트는 단순하게, 분석은 서버에서 안전하게 처리합니다

React + Vite

빠른 개발 서버와 단순한 컴포넌트 구조로 MVP 구현 속도를 확보했습니다.

Tesseract.js

이미지를 서버로 저장하지 않고 브라우저에서 OCR을 실행해 개인정보 노출 면을 줄였습니다.

Gemini Flash 계열

비용 절감을 위해 Gemini Flash 계열 모델을 환경변수로 교체 가능하게 설계했습니다.
