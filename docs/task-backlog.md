# 개발 Task 백로그

> 팀플 올인원 — 4주 개발 계획 (큰 틀)
> 세부 작업은 GitHub Issues에서 관리한다.

## 백로그란?
주차별 큰 목표를 정리한 문서. 매주 시작할 때 이번 주 목표를 보고, 세부 작업을 GitHub Issues로 쪼개서 등록한다.

---

## 2주차 — 코어 기능 (태스크 관리)

**목표**: 브라우저에서 할 일을 추가하고 완료 체크하면 진행률이 바뀐다.

- SQLite DB 연결 + 테이블(teams, members, tasks)
- 태스크 CRUD API
- React에서 태스크 목록 표시 / 추가 / 완료 체크
- 팀 진행도 / 내 진행도 분리 표시

---

## 3주차 — 팀 + 회의시간 매칭

**목표**: 링크로 팀에 들어와 회의 시간을 맞추고 할 일을 관리한다.

- 팀 생성 (이름, 기한, 팀원 이름 목록 입력) + 초대 링크 생성
- 링크 진입 → 이름 선택 화면 (localStorage 저장)
- 내 팀 목록 화면
- 회의시간 매칭 (날짜 격자, 주 단위 전환, 겹침 색 표시, 추천)

> 로그인 방식: 아이디/비밀번호 없이 이름 선택 방식 (확정)

---

## 4주차 — 마무리 + 배포

**목표**: 배포된 URL로 누구나 접속해서 쓸 수 있다.

- 배포 (Render 또는 Railway)
- 빈 화면 처리 (태스크/팀 없을 때)
- 보관(archive) 처리 — 기한 지난 팀
- AI 진행 브리핑 (activity_log 기반 요약) — 여유 시
- 기여도 차트 — 여유 시

---

## 확장 (여유 있으면)

- 태스크 난이도 가중치
- 실시간 반영 (Socket.IO)
- 반응형 (모바일)

## 원칙

- 매주 끝 = 발표 가능한 상태
- 1개 만들고 → 바로 확인 → 커밋
- 세부 작업은 GitHub Issues로 관리
- 기능 늘리지 말고 핵심 2개(태스크 관리, 회의시간 매칭)를 꼼꼼히
