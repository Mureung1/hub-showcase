# 개발 로드맵

## 기술 스택 (전체 프로젝트 기준, 고정)

- **Frontend**: Next.js (App Router). 새로고침 없는 단일 페이지 앱(SPA)으로 만든다 — Next.js의 클라이언트 라우팅을 쓰면 페이지 전환 시 전체 새로고침이 안 일어난다. 화면이 사실상 One-Focus 화면 하나 중심이라 라우트도 거의 없을 것이다.
- **언어**: TypeScript 없이 JavaScript로 시작한다. 코딩 경험이 전혀 없어서 타입 문법까지 한 번에 배우면 부담이 크다. 나중에 익숙해지면 옮겨도 된다.
- **Backend**: 별도 서버 없이 Next.js API Routes로 처리한다 (Vercel AI SDK 호출, 노션 API 호출 둘 다 여기서).
- **AI**: Vercel AI SDK (`generateObject`로 구조화된 분할, tool calling으로 Agent 루프).
- **DB**: 없음. 노션을 데이터 저장소로 그대로 쓴다 (Zero-Input 철학과도 맞음).
- **패키지 관리**: npm. Python의 `requirements.txt`에 해당하는 건 JS 생태계에선 `package.json` + `package-lock.json`이다 (설치하면 자동 생성됨, 따로 만들 필요 없음). 버전은 `package.json`에 고정된 버전으로 명시하고, `^`(마이너 버전 자동 업데이트 허용) 없이 정확한 버전을 쓴다.
- **배포**: Vercel (Next.js와 같은 회사, 깃허브 저장소 연결만 하면 됨).

## 우선순위 (MVP 먼저, Phase 2는 시간 남으면)

MVP 안에서도 순위가 있다: A → B → **D → E(Agent가 핵심 차별화라 최우선)** → C(화면/타이머, 상대적으로 뒤로 미뤄도 되는 부분). 알파벳 순서와 실제 진행 순서가 다르니 헷갈리지 않게 GitHub 이슈의 우선순위를 기준으로 본다. **시간이 부족해지면 C(화면 다듬기)나 백로그를 줄이고, D·E(Agent 루프와 그 검증)는 끝까지 지킨다** — 여기가 이 프로젝트의 핵심 증명 부분이기 때문이다.

주차 배분(초안): 2주차(0713~0717) A+B, 3주차(0720~0724) D, 4주차(0727~0731) E+C.

### A. 기반 설정
- 앱을 실행할 수 있는 최소 상태로 뼈대만 먼저 만든다. 화면 UI와 비밀 키(API 키)를 안전하게 다루는 뒤편 처리를 한 프로젝트 안에서 같이 할 수 있는 도구(Next.js, React를 감싼 프레임워크)를 설치하고, 빈 화면이라도 브라우저에서 켜지게 하는 첫 단계다. 코딩 경험이 전혀 없어서 백엔드 서버를 따로 배우지 않아도 되고, 배포도 Next.js를 만든 회사(Vercel)에 깃허브 저장소만 연결하면 되는 방식이라 이걸로 정했다. Agent가 AI 모델을 호출하는 데 쓰는 도구 모음(Vercel AI SDK)도 이때 같이 연결한다
- 노션 API 연동 (Zero-Input 온보딩: 템플릿 복사 → 링크/토큰 붙여넣기)

### B. Brain Dump
- 단일 텍스트 입력창
- Agent가 문장을 25분 이내 마이크로 스텝으로 자동 분할. AI가 자유 형식 글이 아니라 미리 정한 형식(JSON)으로 답하게 강제하는 도구(`generateObject`)를 쓴다. "할 일 목록"처럼 구조가 정해진 결과가 필요할 때 쓰는 도구다
- (아이디어, 아직 구현 안 함) 사용자가 대충 입력한 할 일을 Agent가 정리해서 먼저 노션에 1차로 기록하고, 그 다음에 쪼갠 마이크로 스텝들을 노션에 정리한다. 부족한 정보(데드라인, 대략적인 소요 시간 — ADHD라 시간 감각이 부정확하므로 참고용으로만 취급, 얼마나 급한지)는 Agent가 질문해서 채우되, 답변 부담을 줄이기 위해 최대 2번 안에 끝내고 선택지 형태로 물어볼 수도 있게 한다.
- (미정) 노션 무료 플랜은 블록 개수 제한이 있어서, 한도에 도달했을 때 어떻게 할지(다른 DB로 교체 등) 아직 결정 안 함. 실제 사용량 보고 나중에 판단.

### C. One-Focus View + Full Screen Timer
- 오늘 할 일 1개만 보여주는 화면
- 타이머 상태 관리 (새로고침해도 안 끊기게, "시작한 시각"만 저장해두고 그 시각 기준으로 남은 시간을 다시 계산하는 방식)

### D. 나 지금 힘들어 (Agent 루프)
- 재조정/재분할 제안
- 반복 회피 패턴 학습, 휴식시간 20→40→60분 단계적 제안
- 여기가 "Agent가 계속 개입한다"는 차별화의 핵심이라 가장 오래 걸릴 가능성이 큼
- (아이디어) 지금 만든 휴식 제안 화면("괜찮아, 잠깐 쉬어도 돼")은 아직 문구만 있고 실제 쉬는 시간(분 단위)은 안 정해준다. 나중엔 Agent가 상황(반복 횟수 등)에 따라 몇 분 쉴지 직접 정해서 화면에 숫자로 보여주게 만든다.

### E. Agent 평가
- "오늘 챙겨야 할 일 10개"류 정답 세트 만들기
- 정답 중 놓친 게 없는지 보는 지표(Recall), 불필요한 제안을 줄였는지 보는 지표(Precision) 측정 스크립트

## 개발 진행 방식
- 기능을 화면/컴포넌트 단위로 작게 쪼개서 만들고, 매일 그날 개발이 끝나면 코드 리팩토링을 한다 (아직 실제로 리팩토링 라운드를 돈 적은 없음, 앞으로 매일 개발 뒤에 진행할 예정).
