# 개발 로드맵

## 기술 스택 (전체 프로젝트 기준, 고정)

- **Frontend**: Next.js (App Router). 새로고침 없는 단일 페이지 앱(SPA)으로 만든다 — Next.js의 클라이언트 라우팅을 쓰면 페이지 전환 시 전체 새로고침이 안 일어난다. 화면이 사실상 One-Focus 화면 하나 중심이라 라우트도 거의 없을 것이다.
- **언어**: TypeScript 없이 JavaScript로 시작한다. 코딩 경험이 전혀 없어서 타입 문법까지 한 번에 배우면 부담이 크다. 나중에 익숙해지면 옮겨도 된다.
- **Backend**: 별도 서버 없이 Next.js API Routes로 처리한다 (Vercel AI SDK 호출, 노션 API 호출 둘 다 여기서).
- **AI**: Vercel AI SDK (`generateObject`로 구조화된 분할, tool calling으로 Agent 루프).
- **DB**: 없음. 노션을 데이터 저장소로 그대로 쓴다 (Zero-Input 철학과도 맞음).
- **패키지 관리**: npm. Python의 `requirements.txt`에 해당하는 건 JS 생태계에선 `package.json` + `package-lock.json`이다 (설치하면 자동 생성됨, 따로 만들 필요 없음). 버전은 `package.json`에 고정된 버전으로 명시하고, `^`(마이너 버전 자동 업데이트 허용) 없이 정확한 버전을 쓴다.
- **배포**: Vercel (Next.js와 같은 회사, 깃허브 저장소 연결만 하면 됨).

## 우선순위 (MVP 먼저, 백로그는 시간 남으면)

MVP 안에서도 순위가 있다: A → B → **D → E(Agent가 핵심 차별화라 최우선)** → C(화면/타이머, 상대적으로 뒤로 미뤄도 되는 부분). 알파벳 순서와 실제 진행 순서가 다르니 헷갈리지 않게 GitHub 이슈의 우선순위를 기준으로 본다. **시간이 부족해지면 C(화면 다듬기)나 백로그를 줄이고, D·E(Agent 루프와 그 검증)는 끝까지 지킨다** — 여기가 이 프로젝트의 핵심 증명 부분이기 때문이다.

주차 배분(초안): 2주차(0713~0717) A+B, 3주차(0720~0724) D, 4주차(0727~0731) E+C.

### A. 기반 설정
- 앱을 실행할 수 있는 최소 상태로 뼈대만 먼저 만든다. 화면 UI와 비밀 키(API 키)를 안전하게 다루는 뒤편 처리를 한 프로젝트 안에서 같이 할 수 있는 도구(Next.js, React를 감싼 프레임워크)를 설치하고, 빈 화면이라도 브라우저에서 켜지게 하는 첫 단계다. 코딩 경험이 전혀 없어서 백엔드 서버를 따로 배우지 않아도 되고, 배포도 Next.js를 만든 회사(Vercel)에 깃허브 저장소만 연결하면 되는 방식이라 이걸로 정했다. Agent가 AI 모델을 호출하는 데 쓰는 도구 모음(Vercel AI SDK)도 이때 같이 연결한다
- 노션 API 연동 (Zero-Input 온보딩: 템플릿 복사 → 링크/토큰 붙여넣기)

### B. Brain Dump
- 단일 텍스트 입력창
- Agent가 문장을 25분 이내 마이크로 스텝으로 자동 분할. AI가 자유 형식 글이 아니라 미리 정한 형식(JSON)으로 답하게 강제하는 도구(`generateObject`)를 쓴다. "할 일 목록"처럼 구조가 정해진 결과가 필요할 때 쓰는 도구다
- (아이디어, 아직 구현 안 함) 사용자가 대충 입력한 할 일을 Agent가 정리해서 먼저 노션에 1차로 기록하고, 쪼갠 마이크로 스텝들도 노션에 정리한다. 데드라인, 대략적인 소요 시간(참고용), 긴급도처럼 부족한 정보는 Agent가 최대 2번, 선택지 형태로 질문해서 채운다.
- (미정) 노션 무료 플랜은 블록 개수 제한이 있어서, 한도 도달 시 대응 방식(다른 DB로 교체 등)을 아직 결정하지 않음.

### C. One-Focus View + Full Screen Timer
- 오늘 할 일 1개만 보여주는 화면
- 타이머 상태 관리 (새로고침해도 안 끊기게, "시작한 시각"만 저장해두고 그 시각 기준으로 남은 시간을 다시 계산하는 방식)
- (아이디어) 타이머 화면에 숫자 대신 원형 안에 물이 차오르는 시각 효과 추가 (남은 시간 비율만큼 색이 차오르고, 숫자는 그 위에 겹쳐서 계속 보여줌)
- (아이디어) 지금 만든 화면들이 기획 단계의 화면 흐름(`docs/images/screen-flow.png`) 디자인과 많이 달라짐 (캐릭터 없음, 전체적인 톤 차이) — 디자인 격차를 좁히는 작업 필요

### D. 나 지금 힘들어 (Agent 루프)
- 재조정/재분할 제안
- 반복 회피 패턴 학습, 휴식시간 20→40→60분 단계적 제안
- 여기가 "Agent가 계속 개입한다"는 차별화의 핵심이라 가장 오래 걸릴 가능성이 큼
- (아이디어) 지금 만든 휴식 제안 화면("괜찮아, 잠깐 쉬어도 돼")은 아직 문구만 있고 실제 쉬는 시간(분 단위)은 안 정해준다. 나중엔 Agent가 상황(반복 횟수 등)에 따라 몇 분 쉴지 직접 정해서 화면에 숫자로 보여주게 만든다.

### E. Agent 평가
- "오늘 챙겨야 할 일 10개"류 정답 세트 만들기
- 정답 중 놓친 게 없는지 보는 지표(Recall), 불필요한 제안을 줄였는지 보는 지표(Precision) 측정 스크립트

## 개발 진행 방식
- 기능을 화면/컴포넌트 단위로 작게 쪼개서 만들고, 매일 그날 개발이 끝나면 코드 리팩토링을 한다.

## 백로그 (지금 당장 안 해도 되는 것들, 떠오르는 대로 여기 추가)
- ~~2분 스타터~~: 260802 — T02(Brain Dump 분할)+T03(One-Focus View)로 이미 충족된 것으로 판단해 제외. 할 일을 작은 단위로 쪼개고 그중 하나만 보여주는 핵심 동작이 이미 동작함.
- 다시 시작해도 괜찮아: 스트릭이 끊긴 걸 벌점처럼 보여주면 아예 앱을 지워버리니, 복귀 자체를 반갑게 맞이한다 ("3일 만이네, 반가워")
- 감각 강도 조절: 같은 자극도 누군가에겐 부족하고 누군가에겐 과할 수 있어, 색·소리·움직임 세기를 직접 맞추게 한다
- 같이 있어요: 혼자 집중하기 어려운 특성상 "누가 같이 있다"는 감각만 필요하지, 소통이나 경쟁은 필요 없다. 이름도 채팅도 없이 점 몇 개로만 존재감을 준다
- 통계 화면: 며칠 연속 집중했는지, 완료한 할 일이 얼마나 되는지 등을 보여주는 화면
- 화이트노이즈 테마: 낮/밤 동기화, 숲, 카페 세 가지 테마. 테마를 바꿔도 캐릭터 위치·크기는 그대로 두고 색과 주변 디테일만 바뀐다
- 마감 임박 리마인드: Brain Dump에 입력한 데드라인이 다가오는데 아직 시작 안 한 할 일이 있으면, Agent가 먼저 개입해서 알려주는 기능.
- 데드라인·캘린더 관리: 지금은 Notion에 실제 "마감일" 개념이나 캘린더 뷰가 없다(`ScheduledDate`는 항상 오늘로 서버가 채움). 할 일마다 데드라인을 입력받고, 달력 형태로 한눈에 볼 수 있게 하는 기능.
- Zero-Input 온보딩 화면: 다른 사람이 자기 노션으로 콕을 써보려면 토큰/DB ID를 직접 발급받아야 하는데, 지금은 이 과정을 안내하는 화면이 없다. 노션 템플릿을 "웹에 공유 + 복제 허용"으로 공개해두고, 앱 안에 "템플릿 복제 → 토큰/DB ID 붙여넣기" 순서를 안내하는 온보딩 화면을 만든다. 본인 개발 중엔 필요 없고, 다른 사람이 써볼 수 있게 하려는 시점(데모 등)에 필요.
- Brain Dump 프롬프트에 퓨샷 예시 추가: 지금은 system 프롬프트로 JSON 형식만 못박아뒀는데(T02), 분류 품질(카테고리를 얼마나 정확히 고르는지, 쪼개는 적절성)은 예시 답안(few-shot)을 넣으면 더 안정적일 수 있다. T13(모델 비교)에서 같이 살펴볼 것.
- 일시정지 사유를 개인화에 반영: T20에서 쌓이는 `PauseCount`/`PauseReasons`를 T10의 행동 패턴 요약(예상 대비 실제 시간, 미룬 비율)처럼 판단 프롬프트에 참고 정보로 포함시키면, "이 시간대·카테고리에 자주 방해받는다" 같은 패턴을 반영할 수 있다. 일시정지 그 순간에 실시간으로 모델을 부르는 것보다는, 쌓인 데이터를 나중에 참고시키는 쪽이 자연스럽다고 판단해 지금은 순수 기록만 한다(S7).
