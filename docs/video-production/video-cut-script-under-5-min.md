# 「있는대로」 프로젝트 영상 대본

`영상 컷 초안.pptx`의 5개 컷을 기준으로 작성했다. 기능 시연을 포함한 전체 영상의 최대 길이는 5분이다.

## 전체 시간 구성

| 구간 | 권장 시간 | 누적 시간 |
|---|---:|---:|
| 01. 프로젝트 소개 | 20초 | 0:20 |
| 02. 문제 정의와 해결 방안 | 30초 | 0:50 |
| 03. 핵심 기능과 사용자 흐름 | 40초 | 1:30 |
| 기능 시연 녹화 | 최대 2분 | 3:30 |
| 04. 데이터 흐름과 기술 구조 | 40초 | 4:10 |
| 05. Agent Workflow 및 마무리 | 45초 | 4:55 |
| 장면 전환 여유 | 5초 | 5:00 |

말을 빠르게 하기보다 문장 사이에 짧은 호흡을 두고, 기능 시연이 2분보다 짧아지면 전체 영상을 그대로 짧게 마무리한다.

## 01. 프로젝트 소개

- 권장 시간: 0:00~0:20
- 화면: 썸네일

### 대본

안녕하세요. 냉장고 속 재료를 관리하고, 지금 사용할 수 있는 재료로 오늘의 한 끼를 추천하는 서비스, 「있는대로」를 소개합니다. 사용자 경험에서 AI 기술 흐름, 그리고 Agent와 함께 개발한 과정까지 차례로 보여드리겠습니다.

### 화면 자막

`냉장고 속 재료에서 오늘의 식탁까지`

### 편집 메모

- 제목과 서비스명을 먼저 보여주고 약 1초 뒤 부제목을 노출한다.
- 다음 컷은 기본 디졸브로 연결한다.

## 02. 문제 정의와 해결 방안

- 권장 시간: 0:20~0:50
- 화면: PROBLEM / SOLUTION

### 대본

자취 생활에서는 냉장고에 재료가 있어도 요리하기가 귀찮거나, 어떤 메뉴를 만들지 떠오르지 않는 경우가 많습니다. 소비기한이 가까운 재료를 빠르게 사용해야 한다는 부담도 있습니다. 「있는대로」는 임박 재료를 먼저 확인하고, 조리 난이도가 낮으면서 재료 구성이 균형 잡힌 메뉴를 제안해 이러한 고민을 줄입니다.

### 화면 자막

`임박 재료 우선 · 낮은 조리 난이도 · 균형 있는 식단`

### 편집 메모

- 대본의 문제 설명에서는 `PROBLEM` 영역을 강조한다.
- “「있는대로」는”부터 `SOLUTION` 영역으로 강조 위치를 이동한다.

## 03. 핵심 기능과 사용자 흐름

- 권장 시간: 0:50~1:30
- 화면: CORE USER FLOW

### 대본

사용자는 먼저 냉장고에 재료와 수량, 보관 위치, 소비기한을 등록합니다. 다음으로 오늘의 식사 상황과 추천 조건을 선택하면, 서버가 보유 재료를 바탕으로 AI 메뉴를 생성하고 추천 정책을 검증합니다. 추천 결과에서는 보유 재료와 부족 재료, 대체안, 조리 순서, 영양과 안전 정보를 확인할 수 있습니다. 요리를 완료하면 사용한 재료가 자동으로 차감되어 다음 추천에 최신 재고가 반영됩니다.

### 화면 자막

`등록 → 조건 선택 → AI 추천 → 레시피 확인 → 재고 차감`

### 편집 메모

- 설명 순서에 따라 01부터 05까지 차례로 강조한다.
- 마지막 문장이 끝나면 기능 시연 영상으로 바로 전환한다.

## 기능 시연 녹화

- 권장 시간: 1:30~3:30
- 최대 길이: 2분

### 화면

- 내 냉장고 목록과 소비기한 확인
- 새 재료 등록
- 레시피 추천 조건 선택
- 추천 카드 비교
- 레시피 상세 확인
- 요리 완료 처리와 재고 차감
- 변경된 냉장고 재고 확인

### 대본

시연 대본은 클릭 타이밍을 맞추기 쉽도록 다음 6개의 TTS 클립으로 나누어 생성한다.

| TTS 클립 | 권장 구간 | 화면 동작 | 대본 |
|---|---:|---|---|
| DEMO-01 | 1:30~1:45 | 내 냉장고 목록과 임박 재료를 보여준다. | 먼저 내 냉장고에서 현재 보유한 재료의 수량과 소비기한을 확인합니다. 소비기한이 가까운 재료는 목록에서 바로 구분할 수 있습니다. |
| DEMO-02 | 1:45~2:00 | 재료 등록 폼을 열고 이름, 수량, 보관 위치를 입력해 저장한다. | 재료 등록에서 이름과 수량, 보관 위치를 입력하면 소비기한이 계산되고 새로운 재료가 냉장고 목록에 반영됩니다. |
| DEMO-03 | 2:00~2:15 | 레시피 추천으로 이동하고 상황 및 소비기한 우선 조건을 선택한다. | 레시피 추천 화면으로 이동해 오늘의 식사 상황과 추천 조건을 선택합니다. 여기서는 소비기한이 가까운 재료를 우선하도록 설정하겠습니다. |

권장 시연 길이는 약 1분 40초다. 화면 로딩이나 클릭 대기 시간을 포함하더라도 2분을 넘기지 않는다.

### 화면 자막

`재료 등록 → 조건 선택 → 메뉴 추천 → 레시피 확인 → 요리 완료`

### 편집 메모

- 각 TTS 클립 앞에 해당 화면 동작을 0.5초 먼저 시작한다.
- 서버 응답을 기다리는 구간은 1~2초만 남기고 나머지는 잘라낸다.
- 마우스 클릭 위치는 원형 강조 요소를 1초 정도 표시한다.
- 레시피 상세 스크롤은 빠르게 넘기지 말고 설명 항목마다 잠시 멈춘다.
- 기능 시연이 1분 40초보다 길어지면 재료 입력 타이핑과 로딩 대기 시간을 우선 줄인다.

## 04. 데이터 흐름과 기술 구조

- 권장 시간: 3:30~4:10
- 화면: DATA FLOW

### 대본

데이터는 React 화면, Express 서버, Supabase 데이터베이스, Gemini API 순서로 흐릅니다. 재료 등록과 조회 요청은 Express를 거쳐 Supabase의 ingredients 테이블에 저장됩니다. 메뉴 추천이 필요하면 서버가 보유 재료를 조회해 필요한 정보만 Gemini에 전달합니다. 생성 결과는 Zod 스키마와 추천 정책으로 다시 검증한 뒤 화면으로 반환하며, 동일 조건의 반복 호출은 추천 캐시로 줄였습니다.

### 화면 자막

`React → Express → Supabase · Gemini`

### 편집 메모

- React에서 시작해 Express, Supabase, Gemini 순서로 화면을 천천히 확대한다.
- 화살표 전체를 동시에 움직이기보다 설명 중인 경로만 표시한다.

## 05. Agent Workflow 및 마무리

- 권장 시간: 4:10~4:55
- 화면: AGENT WORKFLOW

### 대본

개발 과정에서는 AI에게 프로젝트 전체를 한 번에 맡기지 않았습니다. 사용자가 목표와 완료 조건을 정하고 결과를 직접 판단하면, Codex는 요구를 분석해 작업을 나누고 구현과 원인 분석을 지원했습니다. PLAN, BUILD, RUN, CHECK, FIX, VERIFY 순서로 화면과 API를 확인했고, 오류나 개선점이 생기면 다시 계획 단계로 돌아갔습니다. 이를 통해 Agent는 개발을 대신하는 도구가 아니라, 다음 단계를 이해하고 검증하도록 돕는 협업 파트너라는 점을 배웠습니다. 이상으로 「있는대로」 프로젝트 소개를 마치겠습니다.

### 화면 자막

`Agent는 대신 개발하는 도구가 아니라, 함께 검증하는 협업 파트너`

### 편집 메모

- USER와 CODEX 역할을 차례로 강조한다.
- 여섯 단계는 대본에 맞춰 왼쪽에서 오른쪽으로 강조한다.
- Feedback Loop를 보여준 뒤 마지막 문장과 함께 천천히 페이드아웃한다.

## 녹음 및 편집 기준

- 한 문장을 읽은 뒤 0.3~0.5초 정도 짧게 쉰다.
- 자막은 대본 전체가 아니라 각 컷의 `화면 자막` 문장만 사용한다.
- 배경음악은 내레이션보다 충분히 작게 설정한다.
- 컷 전환은 디졸브 또는 페이드 한 종류로 통일한다.
- 최종 편집본이 5분을 넘으면 기능 시연 영상의 대기 구간을 먼저 줄인다.
