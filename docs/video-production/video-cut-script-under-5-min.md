## 02. 문제 정의와 해결 방안

- 권장 시간: 0:20~0:50
- 화면: PROBLEM / SOLUTION

### 대본

자취 생활에서는 냉장고에 재료가 있어도 요리하기가 귀찮거나, 어떤 메뉴를 만들지 떠오르지 않는 경우가 많습니다. 소비기한이 가까운 재료를 빠르게 사용해야 한다는 부담도 있습니다. 「있는대로」는 임박 재료를 먼저 확인하고, 조리 난이도가 낮으면서 재료 구성이 균형 잡힌 메뉴를 제안해 이러한 고민을 줄입니다.

## 04. 데이터 흐름과 기술 구조

- 권장 시간: 3:30~4:10
- 화면: DATA FLOW

### 대본

데이터는 React 화면, Express 서버, Supabase 데이터베이스, Gemini API 순서로 흐릅니다. 재료 등록과 조회 요청은 Express를 거쳐 Supabase의 ingredients 테이블에 저장됩니다. 메뉴 추천이 필요하면 서버가 보유 재료를 조회해 필요한 정보만 Gemini에 전달합니다. 생성 결과는 Zod 스키마와 추천 정책으로 다시 검증한 뒤 화면으로 반환하며, 동일 조건의 반복 호출은 추천 캐시로 줄였습니다.

### 화면 자막

`React → Express → Supabase · Gemini`

### 편집 메모

- React에서 시작해 Express, Supabase, Gemini 순서로 화면을 천천히 확대한다.
- 화살표 전체를 동시에 움직이기보다 설명 중인 경로만 표시한다.

## 05. Agent Workflow 및 마무리

- 권장 시간: 4:10~4:55
- 화면: AGENT WORKFLOW

### 대본

개발 과정에서는 AI에게 프로젝트 전체를 한 번에 맡기지 않았습니다. 사용자가 목표와 완료 조건을 정하고 결과를 직접 판단하면, Codex는 요구를 분석해 작업을 나누고 구현과 원인 분석을 지원했습니다. PLAN, BUILD, RUN, CHECK, FIX, VERIFY 순서로 화면과 API를 확인했고, 오류나 개선점이 생기면 다시 계획 단계로 돌아갔습니다. 이를 통해 Agent는 개발을 대신하는 도구가 아니라, 다음 단계를 이해하고 검증하도록 돕는 협업 파트너라는 점을 배웠습니다. 이상으로 「있는대로」 프로젝트 소개를 마치겠습니다.

### 화면 자막

`Agent는 대신 개발하는 도구가 아니라, 함께 검증하는 협업 파트너`

### 편집 메모

- USER와 CODEX 역할을 차례로 강조한다.
- 여섯 단계는 대본에 맞춰 왼쪽에서 오른쪽으로 강조한다.
- Feedback Loop를 보여준 뒤 마지막 문장과 함께 천천히 페이드아웃한다.
