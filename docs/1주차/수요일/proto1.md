# 순수 HTML/CSS 사용자 경험 화면 프로토타입 제작 지시서

이 문서는 현재 약속 시간 조율 서비스의 사용자 경험 화면만 검토하기 위한 정적 프로토타입 제작 지시서이다.  
이 문서를 받은 AI는 JavaScript, React, Node.js, API, 데이터베이스 구현 없이 **순수 HTML과 CSS만으로 화면 UI/UX를 재현**해야 한다.

목표는 기능 구현이 아니라, 사용자가 실제 서비스에서 보게 될 화면 흐름과 정보 배치, 모달, 버튼, 상태 표현, 색상 의미를 빠짐없이 확인하는 것이다.

---

## 1. 제작 범위

하나의 정적 HTML 파일과 하나의 CSS 파일로 구성한다.

권장 파일명:

```text
index.html
style.css
```

필요하다면 HTML 안에 여러 화면 섹션을 모두 배치해도 된다.  
실제 라우팅, API 호출, 폼 제출, 상태 저장은 구현하지 않는다.

화면은 다음 순서대로 모두 포함한다.

```text
1. 첫 화면
2. 새 약속 만들기 모달
3. 약속 생성 완료 및 링크 공유 모달
4. 기존 약속 참여 모달
5. 약속 메인/현황 화면 - 참여자 상태
6. 약속 메인/현황 화면 - 관리자 상태
7. 약속 투표 화면
8. AI 해석 결과 확인 화면
9. 투표 완료 화면
10. 투표 마감 확인 모달
11. 추천 결과 화면
12. 최종 확정 결과 화면
```

정적 프로토타입이므로 한 화면 안에 섹션별로 순서대로 보여줘도 된다.  
단, 실제 서비스에서 모달로 뜨는 화면은 반드시 모달 형태로 표현한다.

## 2. 전체 서비스 개념

서비스는 여러 사람이 약속 시간을 정할 때 다음 두 가지 문제를 해결한다.

```text
1. 가능한 시간과 불가능한 시간을 편하게 입력하기
2. 단순 가능 여부뿐 아니라 선호/비선호까지 반영하기
```

사용자는 두 종류이다.

```text
관리자
- 약속을 만든 사람
- 투표에 직접 참여할 수도 있음
- 투표를 마감할 수 있음
- 추천 결과 중 최종 시간을 확정할 수 있음

참여자
- 공유 링크로 들어옴
- 이름과 간편 비밀번호를 입력함
- AI 입력 또는 시간표 선택으로 응답함
- 최종 확정 결과를 확인함
```

접근 방식은 다음 정책을 따른다.

```text
공유 링크는 하나만 사용한다.
참여자와 관리자는 같은 링크로 접속한다.
이름과 비밀번호를 입력한 결과에 따라 관리자 또는 참여자로 구분된다.
생성자 이름 + 관리자 비밀번호를 입력하면 관리자 화면으로 들어간다.
일반 이름 + 참여자 비밀번호를 입력하면 참여자 화면으로 들어간다.
```

참여 코드는 사용하지 않는다.  
참여 코드 UI도 만들지 않는다.

## 3. 시각 스타일 방향

전체 스타일은 가볍고 차분한 생산성 도구 느낌이어야 한다.

권장 분위기:

```text
밝은 회색 배경
흰색 카드
부드러운 테두리
선명한 주요 버튼
과하지 않은 보라/파랑 포인트
간결한 정보 배치
```

기본 색상 제안:

```text
배경: #f5f6fa
카드: #ffffff
테두리: #e2e5ec
본문: #1f2430
보조 텍스트: #6b7280
주요 버튼: #4f6df5
주요 버튼 hover 느낌: #3b54d6
위험/불가능: #e5484d
성공/선호: #2fac66
```

상태 색상은 다음 원칙을 따른다.

```text
불가능: 빨간색 계열
비선호: 가능/선호와 같은 계열 안에서 가장 약한 긍정 또는 낮은 채도
가능: 중간 단계
선호: 가장 긍정적인 색
```

추천 색상:

```text
불가능: 연한 빨강 배경 + 진한 빨강 텍스트
비선호: 옅은 초록 또는 옅은 노랑이 아닌, 가능/선호와 연결되는 낮은 채도 색
가능: 연한 회색-초록
선호: 진한 초록 계열
```

중요:

- 비선호, 가능, 선호는 완전히 다른 색보다 같은 계열의 명도/채도 차이로 구분한다.
- 불가능만 명확히 빨간 계열로 분리한다.
- 카드 모서리는 너무 둥글지 않게 8~16px 범위로 한다.
- 버튼은 명확하고 누를 수 있어 보이게 한다.
- 화면에 기능 설명 문구를 너무 많이 넣지 말고, 필요한 안내만 짧게 둔다.

## 4. 공통 UI 요소

### 4.1 페이지 레이아웃

대부분의 화면은 다음 구조를 따른다.

```text
전체 배경
→ 중앙 정렬된 컨테이너
→ 제목 영역
→ 흰색 카드
→ 버튼 영역
```

컨테이너 최대 너비:

```text
일반 화면: 720px
투표/추천처럼 넓은 화면: 1080px
```

### 4.2 카드

카드는 다음 용도로 사용한다.

```text
약속 정보
입력 폼
공유 링크
진행 현황
투표 시간표
추천 결과
최종 결과
```

카드 내부는 충분한 여백을 둔다.

### 4.3 버튼

버튼 종류:

```text
주요 버튼: 파란색 배경
보조 버튼: 흰색 배경 + 회색 테두리
위험 버튼: 흰색 배경 + 빨간 테두리 또는 빨간 글자
작은 버튼: 복사, 전체 선택, 삭제 등에 사용
```

### 4.4 배지

상태 배지:

```text
관리자
참여자
응답 중
응답 마감
추천 결과 생성
최종 확정
가능
선호
비선호
불가능
완료
미완료
```

배지는 둥근 캡슐 형태로 만든다.

### 4.5 모달

모달은 어두운 반투명 오버레이 위에 중앙 카드로 표시한다.

모달 종류:

```text
새 약속 만들기
약속 생성 완료
기존 약속 참여
투표 마감 확인
상태 선택 팝업
```

## 5. 화면 1: 첫 화면

첫 화면은 서비스의 인상을 결정하는 화면이다.

레이아웃:

```text
왼쪽: 브랜드, 슬로건, 설명, 버튼
오른쪽: 서비스 예시 이미지 또는 예시 카드
```

왼쪽 내용:

```text
PREFER
가능한 시간보다, 더 좋은 시간을.
모두가 가능한 시간 중에서도 각자의 선호를 반영해 가장 만족스러운 약속 시간을 찾아드려요.

[새 약속 만들기]
[기존 약속 참여하기]

1. 가능한 시간 선택
2. 선호·비선호 입력
3. 최적 시간 추천
```

슬로건 표현:

```text
"가능한 시간" 주변에는 무표정 얼굴 이모지
"더 좋은 시간" 주변에는 웃는 얼굴 이모지
```

이모지는 문장 흐름 안에서 자연스럽게 배치한다.  
위치와 크기는 디자이너가 조정해도 되지만, 사용자가 의미를 직관적으로 느껴야 한다.

오른쪽 예시:

- 미니 캘린더 카드
- 선택된 날짜 몇 개
- 작은 AI 말풍선
- 예: `"목요일 오후가 좋아요"` / `선호 시간으로 반영할까요?`

첫 화면의 버튼 동작 표현:

```text
새 약속 만들기 → 새 약속 만들기 모달이 뜸
기존 약속 참여하기 → 기존 약속 참여 모달이 뜸
```

새 페이지로 이동하는 느낌을 주지 않는다.

## 6. 화면 2: 새 약속 만들기 모달

새 약속 만들기는 페이지 이동이 아니라 첫 화면 위에 뜨는 모달이다.

모달 제목:

```text
새 약속 만들기
```

입력 항목:

```text
약속 제목
후보 날짜
만남 가능 시간대
응답 마감
약속 전체 인원 수
생성자 이름
관리자 비밀번호
```

모든 필수 항목:

```text
약속 제목
후보 날짜
만남 가능 시간대
약속 전체 인원 수
생성자 이름
관리자 비밀번호
```

응답 마감은 선택 항목이다.

### 6.1 날짜 선택 UI

날짜는 시작일/종료일을 따로 입력하는 형태가 아니라, 하나의 날짜 선택 UI 안에서 범위를 선택하는 방식으로 표현한다.

예시:

```text
[2026.07.13 ~ 2026.07.17]
```

클릭 시 달력 팝오버가 뜨고:

```text
첫 번째 클릭: 시작일 선택
두 번째 클릭: 종료일 선택
```

선택된 범위는 캘린더에서 배경색으로 이어져 보여야 한다.

### 6.2 시간 선택 UI

시간도 시작 시간과 종료 시간을 따로 흩어진 입력으로 두지 말고 하나의 시간 범위 선택 UI로 표현한다.

예시:

```text
만남 가능 시간대
[09:00] ~ [21:00]
```

또는 슬라이더/범위 선택 UI처럼 보이게 해도 된다.

### 6.3 관리자 안내 문구

생성자 이름과 관리자 비밀번호 아래에 작은 안내 문구를 넣는다.

```text
관리자 비밀번호는 투표 마감과 최종 확정에 필요해요. 잊어버리면 관리자로 다시 접속할 수 없어요.
```

### 6.4 버튼

하단 버튼:

```text
[약속 만들기]
[취소]
```

약속 만들기 버튼은 주요 버튼이다.

## 7. 화면 3: 약속 생성 완료 및 링크 공유 모달

약속 만들기를 누르면 사용자는 자동으로 약속 메인 화면으로 이동한 상태가 된다.  
그 위에 생성 완료 모달이 뜬다.

중요:

```text
약속 메인 화면으로 이동 버튼을 따로 만들지 않는다.
약속 생성 직후 이미 메인 화면에 와 있어야 한다.
```

모달 내용:

```text
약속이 생성되었어요.
아래 링크를 참여자에게 공유해주세요.

참여 링크
https://example.com/m/abc123

[링크 복사]
[닫기]
```

참여 코드 UI는 만들지 않는다.

관리자 안내:

```text
관리자는 같은 링크에서 생성자 이름과 관리자 비밀번호로 접속할 수 있어요.
```

---

## 8. 화면 4: 기존 약속 참여 모달

첫 화면에서 `기존 약속 참여하기`를 누르면 뜨는 모달이다.

입력 항목:

```text
참여 링크
이름
간편 비밀번호
```

참여 코드는 사용하지 않는다.

모달 안내 문구:

```text
이름과 비밀번호로 나중에 다시 접속해 내 응답을 수정할 수 있어요.
생성자 이름과 관리자 비밀번호를 입력하면 관리자 화면으로 들어갑니다.
```

동작 의미:

```text
참여 링크 + 일반 이름 + 참여자 비밀번호
→ 참여자 화면

참여 링크 + 생성자 이름 + 관리자 비밀번호
→ 관리자 화면
```

버튼:

```text
[참여하기]
[취소]
```

## 9. 화면 5: 약속 메인/현황 화면 - 참여자 상태

공유 링크로 접속하거나 기존 약속 참여 모달에서 참여자로 입장하면 보이는 메인 화면이다.

상단:

```text
[참여자] 민수로 참여 중
팀 프로젝트 회의
7/13 ~ 7/17 · 09:00~21:00
```

메인 카드:

```text
상태: 응답 중
응답 현황: 3명 중 2명 완료
진행률 막대

참여 링크
https://example.com/m/abc123
[링크 복사]

[약속 투표하기]
[투표 마감하기]
```

참여자 상태에서도 `투표 마감하기` 버튼은 보인다.  
하지만 참여자가 누르면 동작하지 않고 아래 오류 문구가 표시된다.

```text
관리자만 가능합니다!
```

참여자 화면에서는 참여자별 목록이나 관리자 전용 현황 관리는 보이지 않는다.

---

## 10. 화면 6: 약속 메인/현황 화면 - 관리자 상태

관리자가 약속 생성 직후 들어오거나, 같은 링크에서 생성자 이름과 관리자 비밀번호를 입력하면 보이는 화면이다.

상단:

```text
[관리자] 서연으로 참여 중
팀 프로젝트 회의
7/13 ~ 7/17 · 09:00~21:00
```

메인 카드:

```text
상태: 응답 중
응답 현황: 5명 중 3명 완료
진행률 막대

참여 링크
https://example.com/m/abc123
[링크 복사]

[약속 투표하기]
[투표 마감하기]
```

관리자는 다음을 할 수 있다.

```text
약속 투표하기
투표 마감하기
마감 후 투표 다시 열기
추천 결과 보기
최종 결과 보기
```

참여 현황 관리는 별도 화면이나 별도 버튼으로 만들지 않는다.  
관리자 화면 안에 간단한 참여 현황 목록을 넣는 것은 가능하지만, `참여 현황 관리`라는 독립 버튼은 제거한다.

관리자에게만 보이는 간단 현황 예시:

```text
참여 현황
허영  완료
민수  완료
서연  완료
지훈  미완료
유진  미완료
```

## 11. 화면 7: 약속 투표 화면

참여자와 관리자 모두 투표할 수 있는 화면이다.

상단:

```text
팀 프로젝트 회의 · 일정 입력
민수님의 가능한 시간과 선호를 알려주세요.
```

설명 문구:

```text
선호 시간은 +1점, 비선호 시간은 -1점으로 계산돼요.
모든 참여자의 가능 여부와 선호도를 종합해 가장 좋은 시간을 추천합니다.
```

화면 구조:

```text
왼쪽: AI 채팅 입력
오른쪽 또는 아래: 날짜별 시간 선택 그리드
```

### 11.1 AI 채팅 영역

초기 메시지:

```text
후보 일정 중 참석할 수 없는 날짜나 선호하는 시간이 있나요?
채팅으로 편하게 알려주거나 아래 시간표에서 직접 선택할 수 있어요.
```

사용자 예시 말풍선:

```text
월요일은 안 되고, 화요일 6시 이후가 좋아요.
```

AI 응답 예시:

```text
입력한 내용을 정리했어요.
- 7/14 전체: 불가능
- 7/15 18:00 이후: 선호
아래 시간표에 반영해두었어요.
```

입력창:

```text
필요한 일정을 편하게 적어주세요
[전송]
```

### 11.2 날짜/시간 선택 그리드

현재 방식은 날짜를 누르고 다시 시간을 누르는 방식이 아니라, 날짜별 시간이 한눈에 보여야 한다.

데스크톱 권장 구조:

```text
시간      7/13 월   7/14 화   7/15 수   7/16 목   7/17 금
09:00       □         □         □         □         □
09:30       □         □         □         □         □
10:00       □         □         □         □         □
...
21:00       □         □         □         □         □
```

즉, 날짜 하나당 세로 한 줄로 시간이 쭉 보인다.  
시간은 왼쪽 고정, 날짜는 상단 고정처럼 보이면 좋다.

모바일에서는 가로 스크롤을 허용한다.

상태 범례:

```text
비선호
가능
선호
불가능
```

상태 입력 방식:

```text
1. 사용자가 시간 칸들을 드래그해서 범위를 선택한다.
2. 선택이 끝나면 작은 상태 선택 팝업이 뜬다.
3. 사용자는 가능 / 선호 / 비선호 / 불가능 중 하나를 선택한다.
4. 선택 범위 전체에 해당 상태 색상이 적용된다.
```

상태 선택 팝업 예시:

```text
선택한 시간에 적용
[가능]
[선호]
[비선호]
[불가능]
[취소]
```

클릭할 때마다 상태가 순환하는 방식은 사용하지 않는다.

### 11.3 날짜 전체 선택

각 날짜 헤더 아래에 작은 버튼을 둔다.

```text
전체 가능
전체 불가능
```

선택한 날짜의 모든 시간 슬롯에 한 번에 상태를 적용하는 기능처럼 보이게 한다.

필요하다면 다음도 포함할 수 있다.

```text
전체 초기화
```

### 11.4 현재 입력 현황 영역

별도의 `현재 입력 현황` 카드나 목록은 만들지 않는다.  
날짜별 시간 그리드 자체가 현황을 보여주기 때문이다.

하단 버튼:

```text
[투표 완료]
[현황으로 돌아가기]
```

## 12. 화면 8: AI 해석 결과 확인 화면

AI 해석 결과 확인 화면은 글자 목록 중심이 아니라 시간표 색상 중심으로 보여준다.

상단:

```text
AI 해석 결과 확인
입력한 내용을 아래 시간표에 반영했어요. 틀린 부분이 있으면 다시 선택해주세요.
```

본문:

투표 화면과 같은 날짜별 시간 그리드를 표시한다.

```text
시간      7/13 월   7/14 화   7/15 수   7/16 목   7/17 금
09:00       빨강      가능      가능      가능      가능
09:30       빨강      가능      가능      가능      가능
...
18:00       가능      선호      가능      비선호    가능
```

사용자는 색상만 봐도 어떤 날짜/시간이 어떻게 선택됐는지 알 수 있어야 한다.

하단:

```text
[수정하러 가기]
[투표 완료]
```

## 13. 화면 9: 투표 완료 화면

응답 제출 후 화면이다.

상단 카드:

```text
투표 완료!
입력한 내용을 저장했어요.
다른 참여자의 응답이 모이면 추천 결과를 확인할 수 있어요.
```

요약 카드:

텍스트 목록과 작은 색상 배지를 함께 표시한다.

```text
내 응답 요약
불가능: 7/14 09:00~12:00
선호: 7/15 18:00~21:00
비선호: 7/16 13:00~15:00
```

버튼:

```text
[내 응답 수정하기]
[약속 링크 공유하기]
[현황으로 돌아가기]
```

## 14. 화면 10: 투표 마감 확인 모달

약속 메인 화면에서 관리자가 `투표 마감하기`를 누르면 뜨는 모달이다.

모달 제목:

```text
투표를 마감할까요?
```

내용:

```text
현재 응답 현황
5명 중 3명 완료
진행률 막대

마감하면 현재까지 제출된 응답으로 추천 결과를 계산해요.
필요하면 나중에 투표를 다시 열어 재투표를 받을 수 있어요.
```

버튼:

```text
[마감할게요]
[취소]
```

`마감할게요`는 위험 버튼 또는 강조 버튼으로 표현한다.

확인 후에는 추천 결과 화면으로 이동하는 흐름처럼 보여준다.

## 15. 화면 11: 추천 결과 화면

추천 결과는 세로 카드 목록이 아니라 가로 UI로 보여준다.

상단:

```text
추천 결과
참석 가능 인원이 가장 많은 시간을 우선으로, 선호가 많고 비선호가 적은 순서로 최대 5순위까지 보여드려요.
```

결과 표시 방식:

```text
날짜/시간 그리드 안에 추천 순위를 색상으로 표시한다.
```

예시:

```text
시간      7/13 월   7/14 화   7/15 수   7/16 목   7/17 금
09:00       -         -         -         -         -
09:30       -         3         -         -         -
10:00       -         -         2         -         -
18:00       -         -         -         1         1
```

동일한 결과가 여러 개일 때:

```text
같은 순위 내부에 여러 시간으로 표시한다.
예: 1순위가 두 개면 두 칸 모두 1로 표시한다.
```

범례:

```text
1순위
2순위
3순위
4순위
5순위
해당 없음
```

추천 셀을 클릭했을 때 보이는 팝업 카드도 정적으로 표현한다.

팝업 내용 예시:

```text
1순위 · 7/16 목 18:00
5명 모두 참석 가능, 3명 선호, 비선호 없음.

가능 5
선호 3
비선호 0
불가능 0

[이 시간으로 확정]
```

관리자가 아닌 참여자 상태에서는 확정 버튼이 보이지 않거나 비활성화되어야 한다.

안내 문구:

```text
최종 시간 확정은 관리자만 할 수 있어요.
```

---

## 16. 화면 12: 최종 확정 결과 화면

관리자가 추천 결과에서 `이 시간으로 확정`을 누르면 이동하는 화면이다.  
이 화면은 기존 참여자 모두가 볼 수 있다.

상단 카드:

```text
최종 약속 시간이 확정되었어요

7월 16일 목요일
18:00 ~ 18:30
```

선정 근거:

```text
5명 모두 참석 가능
선호 3명
비선호 0명
```

공유 영역:

```text
결과 공유 링크
https://example.com/m/abc123/final
[링크 복사]
```

안내:

```text
확정 후에는 결과 조회만 가능하고 응답 수정은 제한돼요.
```

## 17. 접근 흐름별 화면 상태

프로토타입에는 아래 세 가지 접근 시나리오가 화면상으로 이해되게 표현되어야 한다.

### 17.1 관리자가 생성하기로 접속

```text
첫 화면
→ 새 약속 만들기 모달
→ 약속 생성
→ 약속 메인 화면으로 자동 이동
→ 생성 완료 링크 공유 모달 표시
→ 모달을 닫으면 관리자 상태의 메인 화면
```

관리자 상태 메인 화면에는 다음이 보여야 한다.

```text
[관리자] 이름으로 참여 중
약속 투표하기
투표 마감하기
참여 링크 복사
```

### 17.2 관리자 또는 사용자가 기존 약속 참여하기로 접속

```text
첫 화면
→ 기존 약속 참여하기 모달
→ 참여 링크, 이름, 비밀번호 입력
→ 관리자 정보면 관리자 화면
→ 참여자 정보면 참여자 화면
```

### 17.3 관리자 또는 사용자가 링크를 직접 클릭

```text
공유 링크 클릭
→ 약속 메인 화면 진입
→ 링크 정보는 이미 해당 약속으로 채워진 상태
→ 이름과 비밀번호 입력 모달 표시
→ 관리자 또는 참여자 화면으로 입장
```

이 흐름에서는 참여 링크 입력칸이 필요 없다.  
이미 링크를 클릭했기 때문에 이름과 비밀번호만 요구하면 된다.

## 18. 모바일 반응형 요구사항

모바일에서도 화면이 무너지지 않아야 한다.

모바일 규칙:

```text
첫 화면은 좌우 배치를 위아래 배치로 전환
모달은 화면 너비에 맞게 축소
투표 그리드는 가로 스크롤 허용
시간 라벨은 왼쪽에 고정된 것처럼 보이게 처리
날짜 헤더는 상단에 고정된 것처럼 보이게 처리
추천 결과 그리드도 가로 스크롤 허용
버튼은 한 줄에 무리하게 넣지 말고 세로로 쌓아도 됨
```

## 19. HTML/CSS 구현 방식 지시

순수 HTML/CSS 프로토타입이므로 실제 동작 대신 화면 상태를 정적으로 보여준다.

다음 방식으로 구현한다.

```text
각 화면을 <section>으로 구분한다.
화면 제목을 작게 표시해 검토자가 어떤 화면인지 알 수 있게 한다.
실제 서비스 화면 안에는 불필요한 개발 설명을 넣지 않는다.
모달은 실제 오버레이처럼 표현하되, 정적 화면에서는 해당 섹션 안에 모달 상태를 함께 보여준다.
```

추천 구조:

```html
<section class="prototype-screen">
  <div class="screen-label">01. 첫 화면</div>
  ...
</section>
```

클래스 이름은 의미 있게 작성한다.

예:

```text
landing
modal
card
btn
badge
meeting-hub
preference-grid
recommendation-grid
result-card
```

JavaScript는 사용하지 않는다.  
단, 정적 화면 표현을 위해 `checked`, `selected`, `active` 같은 CSS 클래스는 HTML에 직접 넣어도 된다.

## 20. 최종 산출물 기준

완성된 프로토타입은 다음 질문에 답할 수 있어야 한다.

```text
처음 사용자가 어디서 약속을 만드는가?
참여자는 링크로 들어와 무엇을 입력하는가?
관리자와 참여자는 어떻게 구분되어 보이는가?
투표 화면에서 선호/비선호/불가능이 어떻게 표현되는가?
AI가 해석한 결과를 사용자가 어떻게 확인하는가?
관리자가 투표를 마감할 때 어떤 확인을 받는가?
추천 결과는 어떻게 비교되는가?
최종 확정 결과는 참여자도 볼 수 있는가?
```

프로토타입의 목적은 예쁘기만 한 랜딩 페이지가 아니라, 실제 서비스의 화면 흐름과 UX 문제를 검토할 수 있는 정적 화면 모음이다.
