# 아맞다 1차 논의 정리

이 문서는 `plan.md` 작성 전에 참고하기 위한 1차 논의 기록이다. 최종 기획서가 아니라, 현재까지 합의한 제품 방향, MVP 범위, 보류 사항, 제외 사항을 정리한다.

현재 구현 기준은 `docs/plan.md`, `docs/onboarding.md`, `docs/retrieve.md`, `DESIGN.md`를 우선한다. 이 문서는 프로젝트 초반의 사고 과정을 보존하는 아카이브로만 사용한다.

## 프로젝트 컨셉

### 주제

**아맞다: 필요한 순간에 다시 꺼내보는 인사이트 저장소**

### 핵심 문제

사용자는 인스타그램, 유튜브, 블로그, 웹사이트 등에서 유용한 정보와 인사이트를 자주 저장하지만, 정작 필요한 순간에 다시 찾지 못하거나 저장했다는 사실 자체를 잊어버린다.

기존 북마크 앱이나 메모 도구는 저장과 분류에는 도움을 주지만, "왜 저장했는지"와 "언제 다시 써야 하는지"를 연결하는 경험은 약하다.

### 핵심 가설

사용자가 저장한 인사이트를 단순히 분류하는 데서 끝내지 않고, 나중의 상황이나 용도와 연결해두면 필요한 순간에 다시 꺼내보고 활용할 가능성이 높아진다.

### 제품 방향

- 링크 저장 앱이 아니라, 인사이트를 다시 꺼내 쓰게 하는 서비스로 정의한다.
- 정리는 카테고리로 한다.
- 다시 발견하는 경험은 `꺼내보기`로 제공한다.
- `꺼내보기`는 카테고리 탐색이 아니라, 사용자가 입력한 상황이나 용도에 맞는 인사이트를 추천하는 기능이다.

## 도메인 용어

| 용어     | 의미                                                                             |
| -------- | -------------------------------------------------------------------------------- |
| 인사이트 | 사용자가 저장한 유용한 정보. MVP에서는 링크 기반 저장물이다.                     |
| 보관함   | 사용자가 저장한 모든 인사이트가 모이는 공간이다.                                 |
| 카테고리 | 사용자가 직접 만드는 분류 기준이다. 저장과 수동 탐색에 사용한다.                 |
| 꺼내보기 | 사용자가 현재 상황이나 필요한 용도를 입력하면 관련 인사이트를 추천받는 기능이다. |
| 미분류   | 카테고리가 없는 인사이트만 모아보는 시스템 필터다. 실제 카테고리 칩은 아니다.    |

## MVP 핵심 경험

사용자가 유용한 인사이트를 빠르게 저장하고, 나중에 특정 상황이나 용도를 입력해 `꺼내보기`로 다시 발견한 뒤, 원문을 열어 활용하는 흐름이 MVP의 핵심이다.

기본 흐름:

1. 링크를 저장한다.
2. 카테고리와 메모를 선택적으로 추가한다.
3. 홈에서 `꺼내보기`를 실행한다.
4. 상황이나 용도를 입력한다.
5. 현재 상황과 유사도가 높은 인사이트가 작업팩으로 묶여 노출된다.
6. 사용자는 연결 단서를 확인하고 필요한 원문을 새 탭에서 열어본다.

## MVP 확정 범위

### 인증과 데이터

- Google 로그인만 지원한다.
- Supabase Auth와 Supabase DB를 사용한다.
- 사용자별 보관함, 카테고리, 인사이트 데이터를 분리한다.
- RLS를 적용해 사용자는 자신의 데이터만 접근할 수 있어야 한다.
- 게스트 모드, 이메일/비밀번호 회원가입, 팀 권한은 만들지 않는다.

### 온보딩

- Google 로그인 후 최초 1회 온보딩을 제공한다.
- 관심 분야를 선택하면 선택한 항목만 카테고리로 생성한다.
- 아무것도 선택하지 않아도 시작할 수 있다.
- 사용자가 직접 카테고리를 추가할 수 있다.
- 온보딩에서 만든 카테고리도 일반 카테고리처럼 수정/삭제할 수 있다.
- 온보딩 다시 보기 기능은 MVP에서 제외한다.

### 저장 대상

- MVP 저장 대상은 링크다.
- 텍스트는 링크를 보조하는 메모로만 지원한다.
- 이미지 직접 업로드는 제외한다.
- 링크 미리보기 이미지는 가능하면 OG 이미지로 표시한다.

### 저장 흐름

- 웹 앱 저장과 Chrome Extension 저장은 같은 UX 원칙을 따른다.
- 저장은 URL만으로 즉시 가능해야 한다.
- 저장 완료 후 카테고리와 메모 입력을 가볍게 제안한다.
- 카테고리와 메모는 필수가 아니다.
- 사용자는 `그냥 저장` 흐름으로 바로 끝낼 수 있어야 한다.
- 저장 전 미리보기는 만들지 않는다.
- 메타데이터는 저장 후 비동기로 수집한다.
- 메타데이터 수집 중에도 카테고리 선택과 메모 입력이 가능해야 한다.
- 메타데이터 수집 상태는 별도로 보여주지 않는다.

### URL 메타데이터

- URL 저장 시 제목, 설명, 썸네일을 자동 수집한다.
- 수집 실패해도 저장은 성공해야 한다.
- 제목 fallback은 도메인 또는 URL을 사용한다.
- 썸네일 fallback은 기본 카드 이미지를 사용한다.
- 브라우저에서 직접 크롤링하지 않고 서버 함수 또는 API에서 처리한다.
- 사용자가 제목을 직접 수정한 뒤에는 자동 수집 제목으로 덮어쓰지 않는다.

### URL과 중복 저장

- 사용자별 같은 URL 중복 저장은 방지한다.
- 중복 체크에는 `normalized_url`을 사용한다.
- 원문 열기에는 항상 `original_url`을 사용한다.
- URL은 생성 후 수정할 수 없다.
- 잘못 저장한 URL은 삭제 후 다시 저장한다.
- 제목, 메모, 카테고리만 수정 가능하다.

보수적 URL 정규화 기준:

- 앞뒤 공백 제거
- URL 파싱 가능 여부 검증
- 호스트 소문자 처리
- 기본 포트 제거
- fragment 제거
- 대표 추적 파라미터 제거
  - `utm_source`
  - `utm_medium`
  - `utm_campaign`
  - `utm_term`
  - `utm_content`
  - `fbclid`
  - `gclid`
- 루트 경로의 trailing slash만 정리
- 경로 대소문자와 일반 query parameter는 유지한다.

### 카테고리

- 카테고리는 사용자가 직접 만드는 분류 기준이다.
- 카테고리 선택은 선택 사항이다.
- 하나의 인사이트에 여러 카테고리를 붙일 수 있다.
- 카테고리를 선택하지 않아도 보관함에 저장된다.
- 사용자별 카테고리 이름은 중복 불가다.
- 앞뒤 공백을 제거하고, 대소문자만 다른 중복도 막는다.
- 카테고리는 색상을 가진다.
- 상세 디자인 시스템과 색상 정책은 추후 별도로 정한다.
- 이모지는 MVP 필수 기능에서 제외한다.
- 카테고리 순서는 생성순으로 고정한다.
- 직접 정렬 UI는 만들지 않는다.
- 단, 나중에 정렬 기능을 붙일 수 있도록 `sortOrder` 필드는 둘 수 있다.

카테고리 삭제 정책:

- 카테고리를 삭제해도 인사이트는 삭제하지 않는다.
- 카테고리와 인사이트의 연결만 제거한다.
- 카테고리가 없는 인사이트는 `미분류` 필터에서 볼 수 있다.

카테고리 추천 정책:

- MVP에서는 규칙 기반 추천 칩만 제공한다.
- AI 자동 분류는 제외한다.
- 추천은 자동 확정이 아니라 사용자가 탭해서 선택하는 보조 기능이다.
- 추천 기준은 URL 도메인, 제목 키워드, 최근 사용 카테고리, 기본 추천 후보를 활용한다.

### 보관함

- 보관함은 사용자가 저장한 인사이트를 탐색하고 관리하는 공간이다.
- 카테고리 칩, 검색창, 카드 목록을 중심으로 보관함 구조를 잡는다.
- 카테고리 필터는 `All`, 사용자 카테고리, `미분류` 순서로 둔다.
- `All`은 항상 맨 앞이다.
- `미분류`는 항상 맨 뒤다.
- `미분류`는 실제 카테고리가 아니라 시스템 필터다.
- 기본 정렬은 최신 저장순으로 고정한다.
- 정렬 옵션은 MVP에서 제공하지 않는다.

### 검색

- 검색은 사용자가 이미 찾고 싶은 단서나 키워드를 알고 있을 때 사용한다.
- 검색 대상은 제목, URL, 메모, 카테고리 이름이다.
- 검색과 `꺼내보기`는 역할이 다르다.
- 내부적으로 같은 검색 엔진 일부를 사용할 수 있지만 UX는 분리한다.
- 검색 결과는 보관함 안에서 직접 탐색하기 위한 목록이다.

### 꺼내보기

- `꺼내보기`는 서비스의 핵심 기능이다.
- 홈 화면의 중심 기능으로 둔다.
- 사용자는 추천 상황 버튼 또는 자유 입력으로 꺼내보기를 시작한다.
- 추천 상황 버튼을 먼저 보여주고, 원하는 상황이 없으면 직접 입력할 수 있게 한다.
- MVP에서는 사용자가 직접 상황이나 용도를 입력/선택해서 꺼내보기를 시작한다.
- `꺼내보기`는 고정된 상황 분류가 아니라, 입력 상황과 저장된 인사이트의 유사도를 계산하는 기능이다.
- 결과는 단순 검색 결과 목록이 아니라 작업팩 형태로 보여준다.
- `기획 참고`, `디자인 참고`, `구현 참고` 같은 고정 분류 라벨은 사용자에게 노출하지 않는다.
- 각 인사이트에는 과장된 추천 이유가 아니라 짧은 연결 단서를 보여준다.
- 자동 상황 감지, 캘린더 기반 추천, 행동 추적 기반 추천은 만들지 않는다.
- 작업팩에는 최대 6개 인사이트를 보여준다.
- 작업팩 섹션은 결과 수와 관련도에 따라 생략할 수 있다.
- 결과 개수에 따라 자연스러운 메시지를 보여주되, 숫자를 과하게 강조하지 않는다.
- 이미 열어본 인사이트도 관련 있으면 다시 보여준다.
- 읽음/안 읽음 상태는 만들지 않는다.
- 추천 결과별 피드백 기능은 만들지 않는다.

### 추천/검색 엔진

- MVP에서는 AI/LLM 기반 추천을 만들지 않는다.
- `꺼내보기`는 MiniSearch 기반 field boosting을 우선 검토한다.
- Fuse.js는 보관함 fuzzy search 또는 보조 후보로 둔다.
- 제목, 메모, 카테고리, URL, 도메인, 메타데이터 설명을 비교해 유사도를 계산한다.
- 카테고리는 유사도 계산의 한 필드일 뿐이며, 저장 시 자동 분류가 `꺼내보기`의 핵심은 아니다.
- 상세 기준은 `docs/retrieve.md`를 따른다.

### 카드 UI

- 인사이트는 카드 형식으로 보여준다.
- 필수 정보:
  - 썸네일
  - 제목
  - 도메인 또는 출처
  - 메모 일부
  - 카테고리 칩
  - 원문 열기 액션
- 저장일은 카드에 표시하지 않는다.
- 과장된 추천 이유는 표시하지 않는다. 단, `꺼내보기` 작업팩에서는 짧은 연결 단서를 표시할 수 있다.
- 메모가 없으면 메모 영역을 숨긴다.
- 카테고리가 없으면 카테고리 영역을 숨긴다.
- `미분류` 칩은 카드에 표시하지 않는다.
- 원문은 새 탭에서 연다.
- 카드 클릭 동작은 UI 설계 단계에서 최종 결정한다. 빠른 원문 접근을 우선 검토한다.

### 홈

- 홈은 `꺼내보기`를 중심으로 구성한다.
- 홈에는 다음 두 요소를 둔다.
  - 꺼내보기 진입점
  - 최근 보관한 인사이트
- 홈에 과도한 추천 섹션을 추가하지 않는다.

### 내비게이션

- 하단 중앙 내비게이션을 사용한다.
- 데스크톱과 모바일 모두 같은 구조를 유지한다.
- 순서는 `보관함 / 홈 / 저장`이다.
- 홈이 가운데에 위치한다.
- `더보기` 탭은 만들지 않는다.
- 계정과 로그아웃은 상단 프로필 메뉴에서 처리한다.

### 로그인 전 화면

- 로그인 전에는 간단한 서비스 소개 페이지를 둔다.
- 서비스명, 한 줄 소개, 짧은 설명, 핵심 경험 미리보기, Google 로그인 CTA를 중심으로 구성한다.
- 현재 구현 기준에서는 로그인 전 서비스 소개를 세로형 온보딩으로 확장할 수 있다.

### 설정

- 별도 설정 페이지는 MVP 필수 화면이 아니다.
- 기본은 상단 프로필 메뉴에서 처리한다.
- 구현 중 필요해지면 최소 설정 페이지를 허용한다.
- 알림 설정, 테마 설정, 협업 설정, 추천 설정은 MVP에서 제외한다.

### 반응형

- 모바일 앱은 만들지 않는다.
- PWA 공유 타겟도 만들지 않는다.
- 웹 앱은 모바일에서도 자연스럽게 동작해야 한다.
- 데스크톱, 태블릿, 모바일 레이아웃을 고려한다.

## Chrome Extension

Chrome Extension은 저장 마찰을 줄이는 강한 아이디어지만, MVP 필수 포함 여부는 멘토에게 확인 후 확정한다.

멘토 확인 전까지의 입장:

- Extension은 확정 MVP가 아니라 멘토 확인 후 결정한다.
- 가능하다고 판단되면 저장 전용으로 만든다.
- 어렵다고 판단되면 MVP에서는 제외하고 웹 앱 URL 저장만으로 데모한다.

Extension을 만든다면 범위:

- 현재 탭 URL 가져오기
- 현재 탭 제목 가져오기
- 저장 버튼 제공
- 저장 완료 후 카테고리/메모 선택 제안
- 기존 카테고리 선택
- 새 카테고리 이름만 추가 가능
- 로그인 안 된 경우 웹 앱 로그인으로 안내

Extension에서 하지 않을 것:

- 보관함 탐색
- 꺼내보기
- 검색

## 보안과 실패 처리

### SSRF

서버에서 사용자 제공 URL의 메타데이터를 수집할 때 SSRF 위험이 있다. MVP에서도 보수적으로 처리해야 한다.

정책:

- `http`, `https`만 허용한다.
- `file:`, `ftp:`, `data:`, `javascript:` 등은 차단한다.
- localhost, private IP, link-local IP는 차단한다.
- redirect는 안 따라가거나 1회만 허용한다.
- redirect 대상도 다시 검증한다.
- timeout을 짧게 둔다.
- 응답 크기를 제한한다.
- HTML만 파싱한다.
- URL shortener 자동 확장은 MVP에서 하지 않는다.

### SQL Injection

- 사용자 입력으로 raw SQL을 생성하지 않는다.
- 검색어를 SQL 문자열에 직접 붙이지 않는다.
- Supabase table API 또는 parameterized RPC만 사용한다.
- 모든 사용자 데이터 테이블에는 RLS를 적용한다.
- `user_id = auth.uid()` 기준 정책을 사용한다.
- service role key는 프론트엔드와 Extension에 절대 노출하지 않는다.

### XXE

- XML/SVG 파싱은 하지 않는다.
- 이미지 업로드도 하지 않는다.
- HTML metadata parser만 사용한다.
- 만약 XML parser를 쓰게 되면 DTD와 external entity를 비활성화해야 한다.

### XSS

- 외부 사이트의 title, description, metadata는 신뢰하지 않는다.
- `innerHTML`로 렌더링하지 않는다.
- 텍스트로만 렌더링한다.

### 실패 처리

- URL 형식 오류: 저장 불가, 명확한 오류 메시지 제공
- 메타데이터 수집 실패: 저장 성공, fallback 카드 유지
- DB 저장 실패: 저장 실패, 재시도 제공
- 중복 URL: 기존 인사이트 안내

## 제외 항목

MVP에서 만들지 않는 것:

- 이미지 직접 업로드
- 모바일 공유 확장
- 클립보드 자동 수집
- 캘린더 연동
- AI 추천
- AI 자동 분류
- 그래프/생각 지도 화면
- 협업 보관함
- 이메일 알림
- 브라우저 푸시 알림
- 휴지통/복구
- 정렬 옵션
- 추천 결과별 피드백
- 인사이트 URL 수정
- 설정 중심 기능

영구 제외:

- 쿠키/행동 추적 기반 추천

쿠키/행동 추적은 사용자의 신뢰 리스크가 크기 때문에, 기한이 있어도 만들지 않는다.
