# 개인 카페 스탬프 통합 서비스 기획

## 프로토타입 바로 보기

- [카페 스탬프 프로토타입 열기](https://seongha-h.github.io/cafe_prototype.html)
- 이 프로토타입은 손님용 모바일 화면 중심으로, QR 제시, 카페별 스탬프 카드, 카페 상세, 쿠폰/알림 흐름을 빠르게 확인하기 위한 시안이다.
- [사장님용 화면 프로토타입 열기](https://seongha-h.github.io/owner-prototype.html#scan)
- 사장님용 프로토타입은 운영 현황, 외부 QR/바코드 스캐너 입력 기반 스탬프 적립, 카페별 스탬프 규칙 관리, 적립/쿠폰 발급 알림을 확인하기 위한 시안이다.

## 1. 서비스 개요

개인 카페 스탬프 통합 서비스는 손님이 여러 개인 카페의 스탬프와 쿠폰을 하나의 웹 서비스에서 관리하고, 사장님이 가게의 스탬프 운영 현황과 보상 정책을 관리할 수 있도록 돕는 무료 MVP 서비스이다.

초기 버전은 네이티브 앱이 아니라 웹 기반 서비스로 구현한다. 손님은 주로 스마트폰 브라우저에서 사용하고, 사장님은 매장 운영 상황에 맞게 모바일 또는 데스크톱 브라우저에서 사용할 수 있도록 한다.

첫 화면에서는 `손님으로 로그인`과 `사장님으로 로그인`을 분리한다. 실제 회원가입이나 소셜 로그인은 초기 범위에 넣지 않고, 테스트 로그인으로 각 역할의 핵심 흐름을 검증한다.

손님은 본인의 적립용 QR 코드를 제시하고, 매장에서는 마트 계산대의 바코드 스캐너처럼 외부 QR/바코드 스캐너로 해당 QR을 읽어 스탬프를 적립한다. 브라우저 카메라로 QR을 스캔하는 화면은 MVP 핵심 흐름에서 제외한다.

카페별 스탬프가 목표 개수에 도달하면 스탬프 카드는 자동으로 초기화되고, 해당 카페의 미사용 쿠폰 개수가 1개 증가한다. 손님은 홈의 카페 상세 화면이나 하단 탭의 내 쿠폰 화면에서 쿠폰을 확인하고 사용할 수 있다.

## 2. 문제 정의

개인 카페의 스탬프 제도는 단골을 만들기 좋은 방식이지만, 종이 쿠폰 중심으로 운영될 때 다음과 같은 불편이 생긴다.

- 손님이 종이 쿠폰을 잃어버리거나 집에 두고 와서 적립 기회를 놓친다.
- 여러 카페의 쿠폰을 지갑이나 가방에 따로 보관해야 해서 관리가 번거롭다.
- 카페마다 스탬프 조건과 혜택이 달라 현재 얼마나 모았는지 한눈에 알기 어렵다.
- 쿠폰이 발급되었거나 만료일이 가까워져도 손님이 놓치기 쉽다.
- 사장님은 스탬프가 얼마나 적립되고 쿠폰이 얼마나 발행되는지 일/주/월 단위로 파악하기 어렵다.
- 사장님이 가게의 스탬프 조건과 보상 내용을 바꾸려면 종이 쿠폰을 다시 만들거나 안내를 다시 해야 한다.

이 서비스는 종이 쿠폰의 분실과 미소지 문제를 해결하고, 손님과 사장님이 웹에서 스탬프와 쿠폰 상태를 쉽게 확인할 수 있게 하는 것을 목표로 한다.

## 3. 주요 사용자

### 카페 손님

- 여러 개인 카페를 방문하며 스탬프를 모으는 사용자
- 종이 쿠폰을 자주 잃어버리거나 챙기기 번거로운 사용자
- 스마트폰에서 본인 QR을 바로 제시하고 싶은 사용자
- 카페별 스탬프 현황, 미사용 쿠폰, 쿠폰 만료 알림을 한곳에서 보고 싶은 사용자

### 카페 사장님

- 종이 쿠폰 대신 웹 기반 디지털 스탬프 플랫폼을 원하지만 구축이 어려운 사용자
- 일/주/월 단위로 스탬프 적립 수와 쿠폰 발행 수를 확인하고 싶은 사용자
- 가게별 스탬프 적립 규칙과 보상 내용을 직접 관리하고 싶은 사용자
- 복잡한 POS 연동 없이 외부 QR/바코드 스캐너 입력 기반으로 적립 흐름을 검증하고 싶은 사용자

## 4. 전체 진입 구조

서비스 첫 화면에서는 손님과 사장님이 각자의 역할로 테스트 로그인할 수 있도록 분리한다.

```text
첫 화면
-> 손님으로 로그인
   -> 손님 하단 탭 화면

첫 화면
-> 사장님으로 로그인
   -> 사장님 하단 탭 화면
```

손님과 사장님 모두 하단 탭 구조를 사용한다. 다만 각 역할의 홈 화면과 탭별 내용은 다르게 구성한다.

## 5. 손님 화면 구조

손님 화면은 스마트폰 브라우저 사용을 우선으로 설계한다. 하단 탭은 `홈`, `내 쿠폰`, `알림`, `마이페이지`로 구성한다.

```text
손님 화면
-> 홈
-> 내 쿠폰
-> 알림
-> 마이페이지
```

### 5.1 손님 홈

손님 홈은 매장에서 바로 사용할 수 있는 QR 제시와 카페별 스탬프 현황 확인을 가장 중요하게 다룬다.

- 화면 상단에 본인의 적립용 QR을 적당한 크기로 표시한다.
- QR을 누르면 전체화면 또는 큰 모달로 확대된다.
- 확대된 QR 화면에는 닫기 버튼을 제공한다.
- QR 아래에는 손님이 적립 중인 카페 목록을 보여준다.

카페 목록의 각 카드에는 다음 정보를 표시한다.

- 카페명
- 현재 스탬프 개수 / 목표 스탬프 개수
- 보상 내용
- 현재 해당 카페에 적립된 미사용 쿠폰 개수

카페 카드를 누르면 해당 카페 상세 화면으로 이동한다.

### 5.2 카페 상세 화면

카페 상세 화면은 특정 카페에 대한 손님의 스탬프와 쿠폰 상태를 자세히 확인하는 화면이다.

- 카페명
- 현재 스탬프 개수 / 목표 스탬프 개수
- 보상 내용
- 해당 카페의 미사용 쿠폰 목록
- 쿠폰 사용 처리 버튼
- 스탬프 적립 내역

스탬프 적립 내역에는 MVP 기준으로 적립 날짜와 적립된 스탬프 수를 표시한다.

```text
2026.07.08 스탬프 1개 적립
2026.07.05 스탬프 1개 적립
2026.07.01 스탬프 1개 적립
```

### 5.3 내 쿠폰

내 쿠폰 탭은 손님이 지금까지 모아놓고 아직 사용하지 않은 쿠폰을 한곳에서 확인하는 화면이다.

- 전체 카페에서 발급된 미사용 쿠폰을 통합 목록으로 보여준다.
- 사용 완료 쿠폰은 목록에 표시하지 않는다.
- 만료 쿠폰은 기본 목록에 표시하지 않는다.
- 기본 정렬은 최신 발급순이다.
- 사용자는 정렬을 `최신순`과 `만료 임박순`으로 바꿀 수 있다.

쿠폰 카드에는 다음 정보를 표시한다.

- 카페명
- 쿠폰 혜택
- 발급일
- 만료일

손님은 내 쿠폰 탭에서 원하는 쿠폰을 선택해 사용 완료 처리할 수 있다.

### 5.4 알림

알림 탭은 손님이 놓치기 쉬운 스탬프와 쿠폰 변화를 확인하는 화면이다.

- 스탬프 적립 완료 알림
- 쿠폰 발급 완료 알림
- 쿠폰 만료 임박 알림

MVP에서는 실제 푸시 알림을 구현하지 않고 서비스 내부 알림 목록으로 제공한다. 읽지 않은 알림은 일반 글자 색으로 표시하고, 읽은 알림은 회색 글자로 표시한다

### 5.5 마이페이지

마이페이지는 손님의 기본 회원정보를 관리하는 화면이다.

- 테스트 사용자 정보 표시
- 닉네임 수정
- 로그아웃

전화번호, 프로필 이미지, 계정 삭제, 상세 알림 설정은 MVP 범위에서 제외한다.

## 6. 사장님 화면 구조

사장님 화면은 가게 운영 현황 확인과 스탬프 정책 관리를 중심으로 구성한다. 하단 탭은 `홈`, `내 카페 관리`, `알림`, `마이페이지`로 구성한다.

```text
사장님 화면
-> 홈
-> 내 카페 관리
-> 알림
-> 마이페이지
```

### 6.1 사장님 홈

사장님 홈은 가게의 스탬프 운영 현황을 확인하는 대시보드 역할을 한다.

- 오늘 적립된 스탬프 수
- 이번 주 적립된 스탬프 수
- 이번 달 적립된 스탬프 수
- 오늘 발행된 쿠폰 수
- 이번 주 발행된 쿠폰 수
- 이번 달 발행된 쿠폰 수

사장님은 이 화면을 통해 현재 스탬프 제도가 얼마나 사용되고 있는지 빠르게 파악할 수 있다.

## 6.2 내 카페 관리

내 카페 관리 탭은 사장님이 가게의 스탬프 적립 규칙과 보상 체계를 설정하는 화면이다.

- 카페명
- 목표 스탬프 개수
- 1회 적립 시 부여되는 스탬프 개수
- 보상 이름
- 보상 설명
- 쿠폰 유효기간

예시는 다음과 같다.

    목표 스탬프: 10개
    1회 적립: 1개
    보상 이름: 아메리카노 무료 쿠폰
    보상 설명: 스탬프 10개 적립 시 아메리카노 1잔 무료
    쿠폰 유효기간: 발급일로부터 30일

MVP에서는 사장님이 위 항목을 수정할 수 있는 기본 관리 흐름을 제공한다.

## 6.3 사장님 알림

사장님 알림은 가게에서 발생한 적립과 쿠폰 발행 이벤트를 확인하는 화면이다.

- 손님 스탬프 적립 알림
- 손님 쿠폰 발행 알림

예시는 다음과 같다.

    테스트 손님에게 스탬프 1개가 적립되었습니다.
    테스트 손님에게 아메리카노 무료 쿠폰이 발행되었습니다.

## 6.4 사장님 마이페이지

사장님 마이페이지는 사장님의 기본 회원정보를 관리하는 화면이다.

- 사장님 닉네임 또는 계정명
- 연결된 카페 정보
- 로그아웃

## 7. 핵심 정책

### 7.1 QR과 적립 방식

손님은 본인의 적립용 QR을 스마트폰 화면에 표시한다. 매장에서는 별도의 QR/바코드 스캐너로 손님의 QR을 읽는다.

브라우저 카메라를 사용한 직원용 QR 스캔 화면은 MVP에서 구현하지 않는다. 웹 서비스는 외부 스캐너가 입력한 QR 값을 기반으로 손님과 카페를 확인하고 스탬프 적립을 처리한다.

### 7.2 스탬프와 쿠폰 발급 규칙

스탬프는 카페별로 관리한다. 손님이 특정 카페에서 적립하면 해당 카페의 현재 스탬프 개수가 증가한다.

스탬프가 목표 개수에 도달하면 다음 순서로 처리한다.

    스탬프 적립
    -> 목표 개수 도달
    -> 해당 카페 스탬프 개수 0으로 리셋
    -> 해당 카페 미사용 쿠폰 개수 1개 증가
    -> 쿠폰 발급 알림 생성

이를 통해 손님은 같은 카페에서 여러 번 보상을 쌓을 수 있다.

### 7.3 쿠폰 사용 규칙

발급된 쿠폰은 미사용 상태로 저장된다. 손님은 두 경로에서 쿠폰을 사용할 수 있다.

- 홈의 카페 목록에서 특정 카페 카드를 선택한 뒤 해당 카페 상세 화면에서 사용
- 하단 탭의 내 쿠폰 화면에서 전체 미사용 쿠폰 중 선택해 사용

MVP에서는 쿠폰 실제 사용 승인 흐름을 구현하지 않고, 손님 화면의 사용 완료 버튼으로 상태를 바꾸는 단순 처리만 제공한다.

## 8. 사용자 시나리오

### 8.1 손님 시나리오

1. 손님은 스마트폰 브라우저에서 웹 서비스에 접속한다.
2. 손님은 첫 화면에서 `손님으로 로그인`을 선택한다.
3. 손님은 손님 홈 상단에서 본인의 적립용 QR을 확인한다.
4. 결제 시 QR을 누르거나 확대해 매장에 제시한다.
5. 매장에서는 외부 QR/바코드 스캐너로 손님의 QR을 읽는다.
6. 웹 서비스는 해당 손님의 해당 카페 스탬프를 적립한다.
7. 손님은 홈의 카페 목록에서 카페별 스탬프 개수, 보상 내용, 보유 쿠폰 개수를 확인한다.
8. 카페 카드를 선택해 상세 화면에서 해당 카페 쿠폰과 적립 내역을 확인한다.
9. 스탬프가 목표 개수에 도달하면 스탬프는 초기화되고 쿠폰이 1개 발급된다.
10. 손님은 카페 상세 화면 또는 내 쿠폰 탭에서 미사용 쿠폰을 사용 완료 처리한다.
11. 손님은 알림 탭에서 스탬프 적립, 쿠폰 발급, 쿠폰 만료 임박 알림을 확인한다.

### 8.2 사장님 시나리오

1. 사장님은 웹 서비스에 접속해 `사장님으로 로그인`을 선택한다.
2. 사장님은 홈에서 일/주/월 스탬프 적립 수와 쿠폰 발행 수를 확인한다.
3. 사장님은 내 카페 관리 탭에서 목표 스탬프 개수, 1회 적립 개수, 보상 내용, 쿠폰 유효기간을 설정한다.
4. 매장에서 손님이 QR을 제시하면 외부 QR/바코드 스캐너로 QR을 읽어 적립을 처리한다.
5. 사장님은 알림 탭에서 손님 스탬프 적립과 쿠폰 발행 이벤트를 확인한다.
6. 사장님은 마이페이지에서 기본 회원정보와 연결된 카페 정보를 확인한다.

## 9. 기능

### 핵심기능
- 메인 화면에 있는 큐알코드를 눌러서 확대해서 스캔하여 적립한다..
- 손님 하단 탭: 홈, 내 쿠폰, 알림, 마이페이지를 제공한다.
- 사장님 하단 탭: 홈, 내 카페 관리, 알림, 마이페이지를 제공한다.
- 카페별 스탬프 카드: 카페명, 현재 스탬프 개수, 목표 스탬프 개수, 보상 내용, 보유 쿠폰 개수를 표시한다.
- 카페 상세 화면: 특정 카페의 쿠폰 목록, 쿠폰 사용, 스탬프 적립 내역을 확인한다.
- 자동 쿠폰 발급: 목표 스탬프 개수에 도달하면 스탬프를 초기화하고 쿠폰을 1개 발급한다.
- 통합 쿠폰 목록: 여러 카페의 미사용 쿠폰을 최신순 또는 만료 임박순으로 확인한다.
- 알림 목록: 손님은 적립/쿠폰 알림을, 사장님은 적립/쿠폰 발행 알림을 확인한다.
- 사장님 운영 현황: 일/주/월 스탬프 적립 수와 쿠폰 발행 수를 확인한다.
- 스탬프/보상 설정: 사장님이 목표 스탬프 개수와 보상 내용을 관리한다.

## 10. 이번 프로젝트에서 구현하지 않을 기능 (추후에 실제 서비스로 출시 시 추가하고 시은 기능)

- 결제/POS 연동: 실제 결제 데이터나 포스기와 연결해 자동 적립하는 기능은 구현하지 않는다.
- 브라우저 카메라 QR 스캔: 직원용 웹 카메라 스캔 화면은 구현하지 않는다.
- 지도 기반 탐색: 주변 카페를 지도에서 찾거나 추천하는 기능은 구현하지 않는다.
- 카페 검색: 카페명이나 지역으로 카페를 검색해 추가하는 기능은 구현하지 않는다.
- 쿠폰 실제 사용 승인: 직원이나 사장님이 쿠폰 사용을 승인하는 운영 흐름은 구현하지 않는다.
- 부정 적립 방지: QR 공유, 반복 제시, 위치 검증, 이상 패턴 탐지 등은 이번 버전에서 구현하지 않는다.
- 네이티브 모바일 앱: Android/iOS 앱 설치형 구현은 하지 않는다.
- 카카오 로그인 필수 구현: 카카오 로그인은 나중에 넣을 수도 있고 제외할 수도 있는 선택 기능으로 둔다.
- 유료 구독과 광고: 초기 MVP는 무료 사용을 전제로 하며, 수익화 기능은 구현하지 않는다.

## 11. MVP 방향

이번 프로젝트의 목표는 완성형 운영 시스템을 만드는 것이 아니라, 개인 카페 스탬프와 쿠폰을 웹에서 관리하는 핵심 경험이 실제 사용자에게 가치 있는지 검증하는 것이다.

따라서 초기 구현은 다음 흐름을 가장 중요하게 다룬다.

1. 역할 분리 테스트 로그인
2. 손님 QR 표시와 확대
3. 외부 스캐너 입력 기반 스탬프 적립
4. 목표 스탬프 달성 시 스탬프 초기화와 쿠폰 자동 발급
5. 손님의 카페별 스탬프 카드와 카페 상세 확인
6. 손님의 미사용 쿠폰 목록과 쿠폰 사용 처리
7. 손님과 사장님의 알림 목록
8. 사장님의 일/주/월 운영 현황 확인
9. 사장님의 스탬프 적립 규칙과 보상 체계 관리

## 현재 서비스와의 차별점
### 도도포인트
도도 포인트는 전화번호를 이용해서 각 매장에서 적립기능을 제공한다. 해당 서비스는 전화번호 입력만으로 적립이 되기 때문에 별도의 어플리케이션과 회원가입이 필요없다는 점이 장점으로 존재한다. 하지만 별도의 고객용 화면이 활성화되어있지 않기 때문에 고객의 입장에서는 어떤 매장을 얼마나 자주 가는지, 자주 가는 것의 혜택이 얼만큼인지 알기가 쉽지 않으며 이것이 매장 사용의 보상체계로 작용하지 않는다. 예를 들어 '세 잔만 더 마시면 쿠폰 받으니까 오늘은 여기 가야지'와 같은 생각을 안하게 된다
### 터칭
구상 서비스와 터칭의 서비스는 굉장히 유사하나 터칭의 경우 알뜰살뜰한 쿠폰 적립앱의 느낌이 강하다. 구상 중인 서비스는 단순히 '커피를 싸게 먹거나 공짜로 먹을 방법을 마련한다' 보다는 스탬프를 모아두는 지갑형태에 가깝다. 

## 12. 실제 웹 서비스 구현 기술스택

아래 표는 이 기획을 실제로 스마트폰과 PC 브라우저에서 접속 가능한 웹 서비스로 구현할 때 필요한 기술을 정리한 것이다. 초기 MVP에서는 복잡한 운영 시스템보다 핵심 흐름을 빠르게 만들고 검증할 수 있는 구성을 우선한다.

| 구분 | 사용할 기술 | 어디에 필요한가 | 왜 필요한가 |
| --- | --- | --- | --- |
| 화면 구현 | HTML, CSS, JavaScript | 손님 화면, 사장님 화면, QR 화면, 쿠폰/알림/마이페이지 화면 | 스마트폰과 PC 브라우저에서 보이는 화면과 기본 동작을 만들기 위해 필요 |
| 화면 개발 | React | 로그인 후 역할별 화면 전환, 하단 탭, 카페 상세, 쿠폰 목록, 알림 목록 | 화면이 여러 개이고 사용자 행동에 따라 내용이 자주 바뀌기 때문에 관리하기 좋음 |
| 개발 도구 | Vite | 웹 서비스를 개발하고 실행하는 환경 | 개발 중 수정한 내용을 바로 확인하고, 배포 가능한 웹 파일을 만들기 위해 필요 |
| 반응형 화면 | CSS 반응형 스타일 | 스마트폰 화면과 데스크톱 화면 대응 | 손님은 스마트폰으로, 사장님/직원은 스마트폰이나 PC로 접속할 수 있으므로 화면 크기에 맞게 보여야 함 |
| QR 생성 | QR 코드 생성 라이브러리 | 손님 홈의 본인 적립용 QR 코드 | 손님마다 다른 적립용 정보를 QR 코드로 만들어 매장에서 스캔할 수 있게 하기 위해 필요 |
| 스캐너 입력 처리 | 웹 입력창, 키보드 입력 처리 | 사장님/직원용 적립 화면 | 외부 QR/바코드 스캐너가 읽은 값을 웹 화면에 입력받아 스탬프 적립을 처리하기 위해 필요 |
| 임시 로그인 | 프론트엔드 상태 관리 | `손님으로 로그인`, `사장님으로 로그인` | MVP에서는 실제 회원가입보다 손님/사장님 핵심 흐름을 먼저 검증하기 위해 필요 |
| 데이터 저장 | Supabase 또는 Firebase | 사용자, 카페, 스탬프, 쿠폰, 알림 데이터 저장 | 사용자가 다시 접속해도 스탬프와 쿠폰 정보가 남아 있어야 하므로 필요 |
| 데이터 구조 | 사용자, 카페, 스탬프카드, 쿠폰, 알림 테이블 | 카페별 스탬프 수, 보상 조건, 쿠폰 발급 여부, 적립 내역 관리 | 어떤 정보를 저장할지 정해야 적립, 쿠폰 발급, 알림 흐름이 안정적으로 동작함 |
| 자동 쿠폰 발급 | JavaScript 로직 | 스탬프가 목표 개수에 도달했을 때 | 스탬프 적립 후 조건을 확인해 쿠폰을 자동 발급하고 스탬프를 초기화하기 위해 필요 |
| 배포 | Vercel 또는 Netlify | 실제 접속 가능한 웹 주소 생성 | 스마트폰이나 PC에서 링크로 접속해 서비스를 테스트하고 보여주기 위해 필요 |
