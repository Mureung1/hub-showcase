# 개인 카페 스탬프 MVP 서비스 기획

## 1. 목표와 기간

이 프로젝트는 손님용 모바일 웹과 사장님용 넓은 화면 웹으로 개인 카페의 스탬프를 확인하고 적립하는 MVP입니다. 남은 개발 기간은 3주, 하루 약 5시간, 총 약 105시간을 기준으로 합니다.

이번 목표는 일반 공개 서비스가 아니라 카페 1곳, 사장님 1명, 손님 1~2명이 실제 배포 URL과 Supabase 데이터로 며칠간 사용해볼 수 있는 파일럿 MVP입니다. 완성형 서비스보다 다음 실제 사용 흐름이 안정적으로 동작하는 것을 목표로 합니다.

```text
손님과 사장님이 각자의 고정 계정으로 로그인
→ 손님이 회원번호 또는 QR 확인
→ 사장님이 고객 회원번호 직접 입력 또는 스캐너 입력
→ 사장님 담당 카페의 고객 스탬프 조회
→ 스탬프 1개 적립
→ 카페별 목표 달성 시 쿠폰 자동 발행
→ 손님 웹 새로고침
→ 변경된 스탬프·쿠폰·알림 확인
```

QR은 적립을 바로 실행하는 기능이 아니라 회원번호 입력을 줄이는 보조 수단입니다. 손님 QR에는 `cafe-stamp:<회원번호>` 형식의 문자열을 넣고, 사장님 화면은 매장 QR·바코드 스캐너가 키보드처럼 입력한 값을 받아 고객 조회를 실행합니다. 실제 적립은 사장님이 조회 결과를 확인한 뒤 버튼으로 처리합니다.

## 2. 사용자와 로그인

### 손님

- 파일럿 카페를 포함한 카페별 스탬프와 쿠폰을 확인합니다.
- Supabase Auth의 고정 파일럿 손님 계정으로 로그인합니다.
- 본인의 회원번호와 `cafe-stamp:<회원번호>` QR을 확인합니다.
- 자신의 데이터만 조회할 수 있습니다.

### 사장님

- 한 카페에 소속된 파일럿 사장님입니다.
- Supabase Auth의 고정 파일럿 사장님 계정으로 로그인합니다.
- 자신의 담당 카페에서만 고객 조회와 적립을 할 수 있습니다.
- 매장 컴퓨터나 태블릿의 넓은 화면에서 회원번호를 직접 입력하거나 스캐너 입력으로 조회하고 적립을 처리합니다.

### 로그인 범위

- 이메일·비밀번호 로그인
- 로그아웃
- 새로고침 후 세션 유지
- 역할에 맞는 화면으로 자동 이동

회원가입, 이메일 인증, 비밀번호 재설정, 카카오·구글 로그인은 구현하지 않습니다.

## 3. 확정된 MVP 범위

### 3.1 손님 기능

- 본인의 고유 회원번호 확인
- 회원번호 QR 확인
- 여러 카페의 현재 스탬프와 서로 다른 목표 확인
- 카페별 보상 내용 확인
- 발행된 쿠폰 확인
- 스탬프 적립 알림 확인
- 쿠폰 발행 알림 확인
- 새로고침으로 최신 데이터 다시 조회

### 3.2 사장님 기능

- 로그인한 사장님의 담당 카페 확인
- 고객 회원번호 입력
- `cafe-stamp:` 접두어가 포함된 스캐너 입력값 파싱
- 스캐너 입력 후 Enter로 고객 조회
- 일치하는 고객 정보 조회
- 담당 카페에서 해당 고객의 현재 스탬프 조회
- 버튼으로 스탬프 1개 적립
- 일반 적립 또는 쿠폰 자동 발행 결과 확인

### 3.3 적립 규칙

- 카페마다 서로 다른 `stamp_goal`과 `reward_title`을 가집니다.
- 파일럿 사장님의 카페는 목표 10개를 사용합니다.
- 손님 목록의 다른 카페는 6개나 8개 등 다른 목표를 사용할 수 있습니다.
- 한 번의 적립 요청은 스탬프 1개만 추가합니다.
- 현재 스탬프가 `stamp_goal - 1`보다 작으면 1개 증가시키고 적립 알림을 만듭니다.
- 현재 스탬프가 `stamp_goal - 1`이면 적립과 동시에 해당 카페의 쿠폰 1장을 발행하고 스탬프를 0개로 초기화합니다.
- 쿠폰이 발행된 경우 적립 알림과 쿠폰 발행 알림을 각각 생성합니다.
- 쿠폰에는 발행 당시의 카페 보상명을 복사해 보관합니다.
- 쿠폰은 발행 여부와 발행 시점만 관리하며 사용 처리는 하지 않습니다.

## 4. 제외 범위

- 브라우저 카메라 기반 QR 스캔
- POS나 스캐너 장비 설정 같은 매장 인프라 연동
- 결제와 POS 연동
- 문자, 카카오톡, 이메일, 브라우저 푸시 알림
- 위치 기반 카페 탐색과 검색
- 쿠폰 사용, 승인, 만료 처리
- 사장님이 직접 카페 목표와 보상을 설정하는 기능
- 카페 등록, 운영 통계, 관리자 화면
- 여러 카페를 관리하는 사장님
- 실제 회원가입, 비밀번호 찾기, 소셜 로그인
- 부정 적립 방지
- Android·iOS 네이티브 앱

외부 QR·바코드 스캐너는 별도 SDK 연동 없이 키보드처럼 입력되는 장비를 기준으로 합니다. 장비가 QR을 읽고 Enter를 보내도록 설정되어 있으면 웹앱은 일반 입력창 제출로 처리합니다.

## 5. 화면 구성

### 5.1 로그인

- 이메일
- 비밀번호
- 로그인 버튼
- 로그인 중 상태
- 로그인 실패 오류
- 파일럿 계정 안내

로그인된 사용자의 `profiles.role`에 따라 손님 또는 사장님 화면으로 이동합니다.

### 5.2 손님 홈

- 테스트 손님 이름
- 고유 회원번호
- 고유 회원번호 QR
- 카페별 스탬프 카드
- 카페명
- 현재 스탬프 `n / 목표`
- 카페별 보상 내용
- 카페별 발행 쿠폰 수

### 5.3 손님 쿠폰

- 발행된 쿠폰 목록
- 카페명
- 발행 당시 보상명
- 발행일

사용 버튼, 만료일, 만료 임박순, 사용 완료 상태는 구현하지 않습니다.

### 5.4 손님 알림

- 스탬프 1개 적립 알림
- 쿠폰 발행 알림
- 최신 생성순 목록

읽음 처리와 외부 알림 전송은 구현하지 않습니다.

### 5.5 사장님 적립 화면

사장님 적립 화면은 매장 컴퓨터나 태블릿의 넓은 화면에서 빠르게 입력하고 확인하는 운영 화면을 기준으로 합니다. 담당 카페 정보, 회원번호 입력, 고객 조회 결과, 스탬프 상태, 적립 결과가 한 화면 안에서 자연스럽게 이어져야 합니다.

1. 로그인한 사장님의 담당 카페를 표시합니다.
2. 고객 회원번호를 직접 입력하거나 스캐너로 QR을 읽습니다.
3. 조회 버튼을 누르거나 스캐너가 보낸 Enter로 조회합니다.
4. 고객 이름과 담당 카페의 현재 스탬프를 확인합니다.
5. `스탬프 1개 적립` 버튼을 누릅니다.
6. 일반 적립 또는 쿠폰 발행 결과를 확인합니다.

회원번호가 비어 있거나 조회되지 않으면 명확한 오류 메시지를 표시합니다. `cafe-stamp:` 접두어가 없는 값도 회원번호로 조회할 수 있지만, 접두어가 잘못된 QR은 별도 오류로 안내합니다. 조회와 적립 처리 중에는 관련 버튼을 비활성화해 중복 요청을 줄입니다.

## 6. 데이터 구조

공유 데이터 저장소는 Supabase PostgreSQL을 사용합니다.

### `profiles`

| 필드 | 설명 |
| --- | --- |
| `id` | Supabase Auth 사용자 ID |
| `role` | `customer` 또는 `owner` |
| `customer_id` | 손님 역할이 연결된 고객 |
| `cafe_id` | 사장님 역할이 담당하는 카페 |

손님 프로필은 `customer_id`, 사장님 프로필은 `cafe_id`를 가집니다.

### `customers`

| 필드 | 설명 |
| --- | --- |
| `id` | 내부 식별자 |
| `member_number` | 손님에게 보여주고 사장님이 입력하는 고유 회원번호 |
| `name` | 테스트 손님 이름 |

`member_number`는 고유해야 합니다.

손님 화면의 QR은 별도 테이블에 저장하지 않고 `member_number`에서 생성합니다. QR 문자열은 `cafe-stamp:<member_number>` 형식을 사용합니다.

### `cafes`

| 필드 | 설명 |
| --- | --- |
| `id` | 카페 식별자 |
| `name` | 카페명 |
| `stamp_goal` | 해당 카페의 목표 스탬프 수 |
| `reward_title` | 목표 달성 시 발행할 보상명 |

### `stamp_cards`

| 필드 | 설명 |
| --- | --- |
| `id` | 스탬프 카드 식별자 |
| `customer_id` | 손님 |
| `cafe_id` | 카페 |
| `stamp_count` | 현재 스탬프 수 |
| `updated_at` | 마지막 변경 시각 |

손님과 카페 조합은 하나만 존재해야 합니다. 현재 스탬프는 0 이상이며 해당 카페 목표보다 작게 유지합니다.

### `coupons`

| 필드 | 설명 |
| --- | --- |
| `id` | 쿠폰 식별자 |
| `customer_id` | 발행 대상 손님 |
| `cafe_id` | 발행 카페 |
| `title` | 발행 당시의 카페 보상명 |
| `issued_at` | 발행 시각 |

### `notifications`

| 필드 | 설명 |
| --- | --- |
| `id` | 알림 식별자 |
| `customer_id` | 알림 대상 손님 |
| `type` | `stamp_earned` 또는 `coupon_issued` |
| `message` | 화면 표시 문구 |
| `created_at` | 생성 시각 |

## 7. 권한과 처리 방식

### 접근 권한

- 손님은 자신의 스탬프 카드, 쿠폰, 알림만 조회합니다.
- 사장님은 자신의 담당 카페에서만 고객 조회와 적립을 수행합니다.
- 화면의 역할 보호와 별개로 Supabase RLS와 RPC에서 실제 권한을 검증합니다.
- 프런트엔드에는 Supabase URL과 anon key만 사용하고 `service_role` 키를 노출하지 않습니다.

### 원자적 적립

스탬프 적립은 다음 작업을 하나의 PostgreSQL 함수와 Supabase RPC 요청으로 처리합니다.

1. `auth.uid()`로 로그인한 사용자가 사장님인지 확인합니다.
2. `profiles`에서 사장님의 담당 카페를 찾습니다.
3. 입력받은 회원번호로 고객을 확인합니다.
4. 해당 고객과 담당 카페의 스탬프 카드를 잠그거나 0개로 생성합니다.
5. 카페의 `stamp_goal`과 `reward_title`을 확인합니다.
6. 일반 적립이면 스탬프를 1개 증가시킵니다.
7. 목표에 도달하면 쿠폰을 만들고 스탬프를 0개로 저장합니다.
8. 적립 알림을 만들고, 쿠폰 발행 시 쿠폰 알림도 만듭니다.
9. 처리 결과를 사장님 화면에 반환합니다.

브라우저가 전달한 `cafe_id`는 신뢰하지 않습니다. 담당 카페는 로그인한 사장님 프로필에서 결정합니다. 전체 작업은 하나의 트랜잭션으로 처리하고 실패하면 모두 롤백합니다.

실시간 구독은 제외합니다. 손님 화면은 로드 또는 새로고침 시 최신 스탬프, 쿠폰, 알림을 다시 조회합니다.

## 8. 시연 데이터

- 고정 파일럿 손님 계정 1~2개
- 고정 파일럿 사장님 계정 1개
- 테스트 손님 1~2명
- 서로 다른 목표와 보상을 가진 카페 3개
- 파일럿 사장님이 담당하는 카페 1개
- 확인하기 쉬운 고정 회원번호
- `cafe-stamp:<회원번호>` QR 값
- 담당 카페의 쿠폰 발행 시연용 `stamp_goal - 1` 상태

시연 전에 데이터를 목표 직전 상태로 되돌릴 수 있는 초기화 SQL 또는 절차를 준비합니다.

## 9. 시연 시나리오

### 일반 적립

1. 손님 계정으로 로그인해 회원번호와 여러 카페의 스탬프를 확인합니다.
2. 사장님 계정으로 로그인해 담당 카페를 확인합니다.
3. 회원번호를 직접 입력하거나 QR 스캐너 입력으로 고객과 현재 스탬프를 조회합니다.
4. 스탬프 1개를 적립합니다.
5. 사장님 화면에서 증가된 스탬프를 확인합니다.
6. 손님 화면을 새로고침합니다.
7. 해당 카페의 스탬프와 적립 알림이 변경된 것을 확인합니다.
8. 다른 카페의 스탬프는 바뀌지 않은 것을 확인합니다.

### 쿠폰 자동 발행

1. 담당 카페 스탬프가 `stamp_goal - 1`인 고객을 조회합니다.
2. 스탬프 1개를 적립합니다.
3. 사장님 화면에서 쿠폰 발행 성공과 스탬프 0개를 확인합니다.
4. 손님 화면을 새로고침합니다.
5. 해당 카페의 새 쿠폰, 스탬프 0개, 적립 알림, 쿠폰 발행 알림을 확인합니다.

## 10. 기술 구성

- UI: React + Vite
- 라우팅: React Router
- 인증: Supabase Auth 이메일·비밀번호 로그인
- QR 표시: 회원번호 기반 QR 문자열 생성
- 스캐너 입력: 키보드 입력과 Enter 제출 이벤트 처리
- 스타일: 프로젝트 디자인 시스템 기반 반응형 CSS
- 데이터 저장: Supabase PostgreSQL
- 데이터 접근: Supabase JavaScript 클라이언트
- 접근 제어: Supabase RLS
- 적립 트랜잭션: PostgreSQL 함수와 Supabase RPC
- 배포: Vercel 우선
- 별도 Express 서버는 사용하지 않음

## 11. 완료 기준

- 손님과 사장님 고정 계정으로 로그인할 수 있습니다.
- 새로고침 후 로그인 세션과 역할이 유지됩니다.
- 손님은 여러 카페와 서로 다른 목표·보상을 확인할 수 있습니다.
- 유효한 회원번호로 사장님 담당 카페의 고객과 스탬프를 조회할 수 있습니다.
- 손님 화면에서 `cafe-stamp:<회원번호>` QR을 확인할 수 있습니다.
- 사장님 화면에서 스캐너가 입력한 `cafe-stamp:<회원번호>` 값을 회원번호로 조회할 수 있습니다.
- 잘못된 회원번호에는 오류가 표시됩니다.
- 한 번의 요청으로 스탬프가 정확히 1개 증가합니다.
- `stamp_goal - 1`에서 적립하면 해당 카페 쿠폰 1장 발행, 스탬프 0개, 알림 2개 생성이 함께 완료됩니다.
- 손님 화면 새로고침 후 사장님 화면의 처리 결과와 일치합니다.
- 다른 역할이나 다른 카페 데이터에 대한 허용되지 않은 접근이 차단됩니다.
- 시연 초기 데이터를 반복해서 복원할 수 있습니다.
- 손님 화면은 320~480px 모바일 화면에서 핵심 흐름을 사용할 수 있습니다.
- 사장님 화면은 1024px 이상 넓은 화면에서 핵심 흐름을 사용할 수 있습니다.
