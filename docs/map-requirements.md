# 지도 화면 — 요구사항 & 기술 스택

> 목적지 주변에서 열리는 축제·스포츠 경기·팝업 행사로 인한 혼잡을
> **출발 전에 미리** 알려주는 서비스의 지도 화면.
> SCOPE: 대전 · 충남대 권역 MVP (4주 프로젝트)

작성일: 2026-07-07

---

## 1. 화면 목적

사용자의 **출발지 → 목적지** 경로를 지도에 그리고,
그 경로 근처에서 열리는 행사를 마커로 표시해
"왜 막히는지 모른 채 갇히는 상황"을 미리 방지한다.

지도에 찍는 마커:
- 🟢 출발지 마커
- 🔴 목적지 마커
- 📍 경로 근처 이벤트(행사) 마커

---

## 2. 요구사항 (질문 답변 정리)

| # | 항목 | 결정 |
|---|------|------|
| 1 | 지도 서비스 | **네이버 지도** (API 키부터 발급) |
| 2 | 경로(가는 길) 표현 | **네이버 Directions API** — 실제 도로 경로선 |
| 3 | 출발지/목적지 입력 | **주소·장소 검색 입력** (네이버 검색/지오코딩 API) |
| 4 | 이벤트 데이터 출처 | **기존 API 연동** (형태·엔드포인트 추후 확정) |
| 5 | "경로 근처" 판단 기준 | **경로선 기준 반경 500m 이내** (반경 값 조정 가능) |
| 6 | 마커 클릭 인터랙션 | **정보 팝업(InfoWindow)** — 행사 이름·시간·예상 혼잡도 |
| 7 | 화면 범위 | **독립된 전체 화면** (지도 전용 페이지) |
| 8 | 시간대별 마커 표시 | **조회 시각에 따라 마커를 다르게 표시** (아침/저녁 등) |

### 8번 보충 필요
조회한 시간대에 따라 마커가 달라져야 함. 아래는 추후 확정 필요:
- 무엇이 달라지나? → (a) 표시되는 **행사 목록**이 바뀜 / (b) 마커의 **색·모양**이 바뀜 / (c) 둘 다
- 시간대 구간 정의 → 예: 아침(06–11) / 낮(11–17) / 저녁(17–24) 등
- 기준 시각 → 실제 현재 시각인지, 사용자가 임의로 고른 조회 시각인지

## 3. 기술 스택

### 현재 프로젝트 (기존)
- **React** 19
- **Vite** 8
- **oxlint** (린트)

### 지도 화면에 추가될 것
- **네이버 지도 JavaScript API v3** — 지도 렌더링, 마커, InfoWindow
- **네이버 Directions API** (Directions 5/15) — 실제 도로 경로 탐색
- **네이버 지오코딩/검색 API** — 주소·장소 검색으로 출발/도착 좌표 얻기
- **기존 이벤트 API** — 행사 목록 데이터 (형태 추후 연동)

### 필요 준비물
- 네이버 클라우드 플랫폼(NCP) 계정 + 결제수단 등록
- Maps 애플리케이션 등록 후 **Client ID** 발급
  - Web Dynamic Map, Directions, Geocoding 서비스 활성화
- 발급받은 Client ID를 프론트에 주입 (환경변수 권장)

> ⚠️ 네이버 지도는 Client ID 없으면 지도 자체가 렌더링되지 않음.
> Directions / Geocoding은 월 무료 사용량이 있고 초과분은 과금됨.

---

## 4. 예상 구현 흐름

1. 네이버 지도 SDK 로드 + 기본 지도 렌더링 (전체 화면 페이지)
2. 주소·장소 검색으로 출발지/목적지 입력 → 좌표 변환(지오코딩)
3. 출발지·목적지 마커 표시
4. Directions API로 경로선 그리기
5. 기존 이벤트 API에서 행사 목록 로드
6. 경로선 기준 반경 500m 필터링 → 통과한 행사만 마커 표시
7. 조회 시각(시간대)에 따라 마커 다르게 표시
8. 마커 클릭 시 InfoWindow로 행사 이름·시간·혼잡도 표시
