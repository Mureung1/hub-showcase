화요일(7/28)에 배포 **설정까지** 끝냈고 실제 배포는 하지 않았다. Vercel·Render는 계정

찾는 쪽**으로 방향을 잡았다.

## 1. 배포 문제 — 배포 경로를 로컬에서 그대로 재현

### 요청한 것
> Render와 Vercel이 실제로 도는 방식 그대로 로컬에서 돌려서, 배포하면 터질 곳을 미리 찾아줘.

### 검토하고 적용한 답
빌드 로그를 보려면 배포부터 해야 한다고 생각했는데, Agent가 **`git archive`로 커밋된
파일만 뽑아 깨끗한 폴더를 만들고** 거기서 배포 서비스와 같은 명령을 돌리는 방법을 제안했다.
`node_modules`가 없는 상태에서 시작하니 "내 컴퓨터에만 있는 파일" 때문에 되는 경우를 걸러낸다.

```
[Render]  rootDir=server  →  npm install  →  npm start
[Vercel]  Root Directory=frontend  →  npm install  →  npm run build
```

### 성공을 확인한 근거

| 확인 | 결과 |
|---|---|
| Render 방식 `npm install` | 0 vulnerabilities, 실패 없음 |
| Render 방식 `npm start` | `서버가 포트 4999 에서 실행 중입니다` |
| 환경변수 주입 확인 | `CORS: 허용 오리진 https://example.vercel.app` |
| healthCheckPath | `GET /api/health` → `{"status":"ok"}` **HTTP 200** |
| Vercel 방식 `npm run build` | `✓ built in 617ms`, `dist/` 생성 |
| 자산 경로 | `src="/assets/index-*.js"` (루트 기준 — Vercel에 맞음) |
| API 주소가 번들에 박혔는지 | `grep -c` → **1** (빌드 타임에 들어감) |

**미리 잡은 지뢰:** `render.yaml`에 `NODE_VERSION=24.17.0`을 넣어둔 것. 서버가 Node 내장
`node:sqlite`를 쓰는데 Node 22 미만에는 그 모듈이 없어서, 이걸 안 넣었으면 배포하자마자
죽었을 것이다.

## 2. 부족한 핵심 기능 — 서버가 죽었을 때 화면에 아무 표시가 없었다

### 발견한 오류
3번 미션("서버 오류가 화면에 어떻게 보이는지 확인")을 하다가 찾았다. **API 서버를 끄고
새로고침해도 화면이 멀쩡했다.** 과목도 보이고 점수도 나왔다.

폴백 설계(서버 없으면 localStorage) 덕분에 고장은 아니지만, **사용자는 서버에 저장된 줄
안다.** 실제로는 그 브라우저에만 남는다. 데모 중에 다른 기기에서 열면 아무것도 없다.

### 요청한 것
> 서버가 죽었는데 화면에 아무 표시가 없어. 저장이 어디에 되고 있는지는 알려줘야 하지 않나?

### 검토하고 적용한 답
`fetchSubjects()`가 이미 `{ ok: false }`를 돌려주고 있었는데 화면에서 쓰지 않고 있었다.
그 값을 `isServerDown` 상태로 받아 안내문 한 줄을 띄우는 것으로 정했다.

> 서버에 연결하지 못해 이 브라우저에만 저장하고 있어요. 다른 기기에서는 보이지 않아요.

색은 `--color-danger`가 아니라 `--color-primary-light`를 썼다. **고장이 아니라 상태 안내**라
빨간색으로 겁줄 일이 아니고, 그렇다고 흘려보내면 안 되니 배경은 깔았다.

### 성공을 확인한 근거
- 서버를 끈 뒤 새로고침 → 안내문 보임 (스크린샷 확인)
- 서버를 다시 켜고 새로고침 → **안내문 사라짐** (`.server-note` 엘리먼트 없음)

## 3. 배포 환경 전체 흐름 확인

배포 주소가 아직 없어서, **FE와 BE를 서로 다른 오리진에 띄운 로컬 구성**에서 확인했다.
`CORS_ORIGIN`까지 배포와 같은 방식으로 줬다.

```
FE  http://localhost:4173  (VITE_API_BASE_URL=http://localhost:3999 로 빌드)
BE  http://localhost:3999  (CORS_ORIGIN=http://localhost:4173, DB_PATH=빈 파일)
```

DB는 **빈 파일**로 새로 만들어 시작했다. 실제 데이터를 건드리지 않으면서 빈 상태부터
볼 수 있다.

| 확인 항목 | 결과 |
|---|---|
| 빈 데이터 | "아직 담은 과목이 없어요. 위에서 과목을 담아 주세요." 순위판은 숨겨짐 |
| 과목명 없이 담기 | `과목명을 입력해 주세요.` — 저장 안 됨 |
| 날짜 없이 담기 | `시험 날짜를 선택해 주세요.` — 저장 안 됨 |
| 정상 입력 | 서버에 저장, 새 디폴트대로 이해도 4 · 분량 4 |
| 핵심 흐름 | 과목 담기 → 분량·이해도 → 결과(추천 과목 + 이유 + 오늘 시간 배분)까지 완주 |
| 새로고침 | 과목·점수 유지됨 |
| 서버 다운 | 화면 유지 + 안내문 (위 2번) |
| 서버 복구 | 안내문 사라지고 서버 데이터로 복귀 |

### 여기서 하나 더 알게 된 것

빈 데이터를 보려고 DB만 비웠더니 **화면에 과목 14개가 그대로 나왔다.** 네트워크 탭을 보니
`POST /api/subjects`가 연달아 찍혀 있었다. localStorage에 있던 과목을 **앱이 빈 서버로 자동
업로드**하고 있었다. 서버 복구 시 이관하는 기존 설계였는데, 그걸 모르고 테스트하니 "빈
데이터 화면"을 볼 수 없었다.

→ **DB와 localStorage를 같이 비우고, 그 다음에 페이지를 열어야** 진짜 빈 상태가 된다.
화면만 보고 "DB를 안 비웠나?" 했으면 한참 헤맸을 텐데, 네트워크 탭의 `POST`가 답이었다.

## 5. Agent와 일하면서 효과가 있었던 방식

- **"고쳤다"로 끝내지 않고 확인 근거를 같이 요구했다.** 스크린샷·HTTP 상태코드·DB 조회
  결과처럼 눈으로 볼 수 있는 걸 붙이게 하니, 안 된 걸 됐다고 넘어가는 일이 없었다.
- **일부러 실패시켜 보게 했다.** `CORS_ORIGIN`을 틀린 주소로 두고 막히는 것까지 확인한 덕에
  가드가 진짜 동작한다는 걸 알았고, 그 과정에서 CORS가 서버가 아니라 브라우저에서 막는다는
  것도 알게 됐다.
- **되돌리기 어려운 일은 먼저 물어보게 했다.** push, PR 생성, 파일·과목 삭제 전에 확인을
  받았다. 실제로 "생리학이 없다"고 잘못 말한 걸 삭제 직전에 바로잡을 수 있었다.
- **판정 로직은 테스트부터 쓰게 했다.** 학점 입력 검사를 `parseCreditsInput`으로 빼고
  테스트 13개를 먼저 붙였다(red → green). 화면에서 눈으로 보는 것과 달리 다음에 깨지면 잡힌다.
- **모호한 요청은 구현 전에 되묻게 했다.** "공부 분량이랑 이해도를 메인으로"가 학점을
  남기는 건지 내리는 건지 갈렸는데, 먼저 물어봐서 두 번 일하지 않았다.

**Vercel 은 CLI 로 처리했다.** 처음엔 `~/.vercel` 이 없어서 "로그인 안 돼 있다"고 판단했는데
**틀렸다.** macOS 는 인증 정보를 앱 지원 폴더에 둬서 그 경로에 없었을 뿐, 이미 로그인돼 있었다.
`npx vercel whoami` 로 계정을 확인하고 나서야 알았다.
→ **파일이 없다고 상태를 단정하지 말고, 도구에게 직접 물어보는 명령이 있으면 그걸 쓴다.**

**Render 는 대시보드에서 직접 해야 했다.** 저장소 첫 연결에 GitHub 권한 승인이 있어서
CLI 로 우회할 수 없다. Blueprint(`render.yaml`)를 쓰니 빌드·시작 명령·Node 버전은 손댈 게 없었다.

### 확인한 것

- `/api/health` → `{"status":"ok"}` HTTP 200
- 배포된 번들에 Render 주소가 박혔는지 `grep` 으로 확인
- 배포 화면에서 과목 담기 → **Render DB 에 저장** → 새로고침 후에도 유지
- "서버에 연결하지 못해…" 안내가 연결 후 사라짐

### 여기서도 하나 배웠다

CORS 가 잠겼는지 확인할 때 **Vercel 오리진으로 요청해 헤더가 오는 것만 보면 안 된다.**
`CORS_ORIGIN` 이 비어 있어도(전체 허용) 똑같이 헤더가 붙기 때문이다.
**엉뚱한 오리진으로 한 번 더 찔러서 헤더가 없는 것까지** 봐야 잠긴 걸 확인할 수 있다.
성공 케이스만 봤으면 "설정됐다"고 잘못 보고할 뻔했다.
