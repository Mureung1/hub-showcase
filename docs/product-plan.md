# 사이사이 기획서

## 1. 프로젝트 개요

사이사이는 같은 건물 또는 가까운 생활권 이웃을 연결하는 생활 커뮤니티 서비스다.

사용자는 이메일로 가입하고 주소에 따라 커뮤니티에 자동 배정된 뒤 자유로운 정보 공유, 생활 도움 요청, 공동구매 모집과 참여를 할 수 있다.

## 2. 문제 정의

가까운 곳에 살아도 이웃끼리 서로 알기 어렵고 생활 문제를 혼자 해결해야 하는 경우가 많다.

- 생활권 안에서 필요한 정보를 빠르게 공유하기 어렵다.
- 전등 교체, 벌레 처리, 택배 수령 같은 작은 도움을 요청할 곳이 부족하다.
- 생필품과 식재료를 대량 구매하면 저렴하지만 혼자 사용하기 어렵다.
- 공동구매 참여자끼리 구매와 분배를 조율할 채널이 필요하다.

## 3. 타깃 사용자

- 대학가 근처 아파트, 오피스텔, 원룸, 빌라에 거주하는 대학생과 1인 가구
- 가까운 이웃과 생활 정보를 나누고 싶은 사용자
- 생활 속 작은 도움을 요청하거나 제공하고 싶은 사용자
- 공동구매로 생활비 부담을 줄이고 싶은 사용자

## 4. 커뮤니티 단위

### 건물 동 커뮤니티

아파트와 오피스텔은 정규화된 도로명 주소, 건물명과 사용자가 입력한 동 번호가 모두 같을 때 같은 커뮤니티로 배정한다.

### H3 생활권 커뮤니티

주택과 빌라는 주소 검색 좌표를 H3 해상도 9 셀로 변환한다. 같은 셀에 속하는 사용자를 같은 생활권 커뮤니티로 배정한다.

### 자동 배정 원칙

- 사용자는 회원가입 후 주거 유형, 닉네임과 주소를 입력한다.
- 주소 검색은 Kakao Local API를 사용한다.
- 사용자는 추천 목록에서 커뮤니티를 고르지 않는다.
- 서버가 건물 동 key 또는 H3 cell로 커뮤니티를 결정하고 즉시 가입시킨다.
- 주소 원문과 좌표는 배정 계산 후 저장하지 않는다.
- 이번 MVP에는 거주 사실 인증과 커뮤니티 변경이 없다.

## 5. 핵심 사용자 시나리오

### 가입과 입장

1. 사용자가 이메일과 비밀번호로 가입한다.
2. 닉네임과 주거 유형을 입력한다.
3. 주소를 검색해 한 결과를 선택한다.
4. 아파트·오피스텔 사용자는 동 번호를 입력한다.
5. 서버가 커뮤니티를 자동 배정하고 사용자를 앱에 입장시킨다.

### 자유게시판

1. 사용자가 같은 커뮤니티의 최신 글을 본다.
2. 제목과 본문으로 글을 작성한다.
3. 상세에서 오래된 순의 댓글을 보고 댓글을 작성한다.

### 도와주세요

1. 사용자가 도움 요청 글을 작성한다.
2. 같은 커뮤니티 사용자가 댓글을 작성한다.
3. 글쓴이가 댓글 작성자 옆 채팅하기로 1:1 대화를 시작한다.
4. 도움을 받은 글쓴이가 요청을 완료한다.
5. 완료 후에는 글·댓글·채팅 기록만 읽을 수 있다.

### 공동구매

1. 모집자가 상품명, 설명, 총액, 목표 인원, 마감 시각과 분배 위치로 모집을 만든다.
2. 모집자는 host 참여자로 자동 등록된다.
3. 같은 커뮤니티 사용자가 참여하고 예상 1인 부담 금액을 확인한다.
4. 목표 인원에 도달하면 추가 참여가 차단된다.
5. 모집자가 마감 전에 구매 확정을 누른다.
6. 확정 transaction에서 참여자 그룹 채팅방이 한 번 생성된다.
7. 확정 시점 참여자만 채팅에 들어가 구매와 오프라인 분배를 조율한다.

## 6. 기능 규칙

### 인증

- 이메일/비밀번호 가입·로그인·로그아웃·세션 복원
- 가입 즉시 세션 발급
- 비밀번호 8~72자, 닉네임 2~20자

### 게시판

- 자유게시글과 도움 요청 제목 2~80자, 본문 1~2,000자
- 댓글 1~500자
- 목록은 최신순, 댓글은 오래된 순
- 수정·삭제와 대댓글 없음

### 도움 요청

- 상태는 `open | resolved`
- 작성자만 완료 가능
- 글쓴이는 댓글 작성자와만 1:1 채팅 가능
- 같은 요청·같은 상대의 방은 하나
- 완료 후 댓글·채팅 쓰기 차단

### 공동구매

- 상태는 `recruiting | confirmed`
- 총액 1~100,000,000원, 목표 인원 2~50명
- 마감은 생성 시각부터 10분 이후~30일 이내
- 예상 부담금은 `ceil(totalAmount / participantCount)`
- 목표 인원 도달, 기한 경과, 확정 후 참여 차단
- 목표 인원 도달과 미만료 조건에서 모집자만 확정
- 확정 전 채팅 없음, 확정 후 참여 취소·추가 참여 없음
- 서비스는 결제·송금·정산을 직접 처리하지 않음

### 채팅

- 도움 1:1과 공동구매 그룹 채팅은 공통 conversation 모델 사용
- 메시지 1~1,000자
- 활성 화면에서 3초 REST polling
- conversation member만 조회·작성
- 메시지 수정·삭제, 읽음 표시, 파일 첨부 없음

## 7. 3주 MVP 범위

### Must

- 회원가입·로그인·로그아웃·세션 복원
- Kakao 주소 검색과 건물 동/H3 자동 배정
- 자유게시판 글·댓글
- 도와주세요 글·댓글·작성자 완료·1:1 채팅
- 공동구매 생성·참여·모집자 확정·확정 참여자 채팅
- 사용자·커뮤니티·작성자·참여자·대화 멤버 권한
- Vercel, Render, Supabase 공개 배포

### Won't

- 이메일 확인, 비밀번호 재설정, 소셜 로그인
- 나의 활동과 커뮤니티 변경
- 이미지 업로드와 이미지 URL
- 수정·삭제, 대댓글
- 공동구매 참여 취소, 모집 취소, 완료 상태
- 결제·송금·정산·주문
- Realtime/WebSocket, 알림
- 리뷰·신고, 차단, 관리자 기능

## 8. 제품 성공 조건

- 신규 사용자 두 명이 같은 커뮤니티에서 다섯 필수 기능을 실행한다.
- 다른 커뮤니티 사용자는 해당 데이터와 채팅에 접근하지 못한다.
- 도움 요청 완료와 공동구매 확정 권한이 서버와 DB에서 강제된다.
- 확정 전 공동구매 채팅방이 없고 확정 시 한 번만 생성된다.
- 서비스가 결제·송금을 처리하는 UI와 문구가 없다.
