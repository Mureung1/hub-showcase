# 데이터 모델 설계

## subjects 테이블

사용자가 등록한 시험 과목 정보를 저장한다.

| 컬럼명 | 자료형 | 필수 여부 | 설명 |
|---|---|---|---|
| id | bigint | 필수 | 과목을 구분하는 고유 번호 |
| name | text | 필수 | 과목명 |
| exam_date | date | 필수 | 시험 날짜 |
| understanding | integer | 필수 | 현재 이해도 1~7 |
| difficulty | integer | 필수 | 과목 난이도 1~7 |
| grade_weight | integer | 필수 | 성적 반영 비율 0~100(%) — 이 시험이 성적에 반영되는 비율, 기본 40 |
| grading | integer | 필수 | 교수님 학점 성향 1~7 (1=후하게, 7=짜게), 기본 4 |
| study_amount | integer | 필수 | 공부 분량(시험 범위) 1~7, 기본 4 |
| available_time | integer | 필수 | 확보 가능한 공부 시간 1~7 (1=매우 부족, 7=충분), 기본 4 |
| credits | real | 필수 | 중요도 = 과목 학점 수(예: 3, 5, 7.5), 기본 3 |
| previous_score | integer | 선택 | 이전 시험(중간·1차·2차 등) 점수 0~100. 값이 없으면 `NULL`("해당 없음") |
| created_at | timestamptz | 필수 | 과목 정보 생성 시각 |

> `previous_score`는 이 테이블에서 유일하게 진짜 선택(nullable) 필드다. 기본값으로 채우지 않고
> 입력이 없으면 그대로 `NULL`을 저장해 "몰라서 중립으로 본다"(0="모르겠다")와
> "해당 시험이 아예 없다"(NULL)를 구분한다.

> 1~7 척도는 각 단계에 뜻(라벨)을 붙여 "4"의 의미가 사람마다 달라지는 문제를 줄인다.
> 1~7 로 정하기 어려우면 **`0`("모르겠다")** 을 저장할 수 있고, 점수 계산에서는 중립(중앙값 4와 동일)으로 처리해 우선순위에 유리·불리를 주지 않는다. (grade_weight 는 % 숫자 입력이라 제외)
> 기존에 1~5 척도로 저장돼 있던 값은 서버가 처음 뜰 때 `1 + (old-1) × 6/4` 로 1~7에 비례 환산해 한 번만 이관한다(`PRAGMA user_version` 으로 재실행 방지).
> `grade_weight`(성적 반영 비율)와 `credits`(중요도=학점 수)는 이름이 비슷하지만 다르다:
> 전자는 "이 시험이 **성적**에 반영되는 비율(%)", 후자는 "이 과목이 몇 **학점**짜리인지"다.
> (옛 `importance` 1~5 컬럼은 `grade_weight = (importance-1)*25` 로 환산해 이관했다.)

> `priority_score`(우선순위 점수)는 저장하지 않는다. 위 점수형 필드와 시험까지 남은 날짜,
> 사용자가 선택한 우선순위 성향(가중치)으로 화면에서 매번 계산한다.

## 우선순위 점수 계산

각 요소를 0~100 점수로 환산한 뒤 성향별 가중치로 합산한다.

- 이해도: 낮을수록 높은 점수 `(7 - understanding) / 6 * 100`
- 난이도: 높을수록 높은 점수 `(difficulty - 1) / 6 * 100`
- 급함: 시험이 가까울수록 높은 점수 (30일 기준, 지났으면 100)
- 성적(반영 비율): 시험이 성적에 반영되는 비율(%)을 그대로 점수로 사용 `clamp(grade_weight, 0, 100)`
- 교수 성향: 짜게 줄수록 높은 점수 `(grading - 1) / 6 * 100`
- 분량: 많을수록 높은 점수 `(study_amount - 1) / 6 * 100`
- 시간: 확보 가능한 공부 시간이 적을수록(빠듯할수록) 높은 점수 `(7 - available_time) / 6 * 100`
- 이전 점수: 이전 시험 점수가 높을수록(이미 잘하므로) 낮은 점수 `100 - previous_score`. 입력이 없으면 중립(50)

| 성향 | 이해도 | 난이도 | 급함 | 성적 | 교수 | 분량 | 시간 | 이전점수 |
|---|---|---|---|---|---|---|---|---|
| 균형 | 0.18 | 0.13 | 0.18 | 0.13 | 0.08 | 0.09 | 0.09 | 0.12 |
| 난이도 중시 | 0.18 | 0.22 | 0.09 | 0.13 | 0.09 | 0.09 | 0.09 | 0.11 |
| 임박도 중시 | 0.13 | 0.09 | 0.31 | 0.13 | 0.05 | 0.09 | 0.09 | 0.11 |
| 학점 전략 | 0.09 | 0.09 | 0.13 | 0.27 | 0.13 | 0.09 | 0.09 | 0.11 |

> 각 성향의 가중치 합은 1.0 이다. 클라이언트(`priorityCalculator.js`)와
> 서버(`priorityService.js`)가 같은 값을 쓴다.

### 중요도(학점) 배수 — 최종 점수

위 가중 합(기본 점수 0~100)에 **중요도(과목 학점 수) 배수**를 곱해 최종 점수를 낸다.

```
최종 점수 = round(기본 점수 × (credits / 3))
```

3학점을 기준(1배)으로 하므로 3학점 과목은 기본 점수 그대로, 6학점은 2배, 7.5학점은 2.5배가 된다.
그 결과 **기본 점수가 같아도 학점이 높은 과목이 최종 점수가 더 높게** 나온다. (점수는 100을 넘을 수 있다.)

## 저장 방식

과목 데이터는 서버의 SQLite 파일 DB(`server/data/app.db`)에 저장한다. 서버를 재시작해도
데이터가 남는다. 서버가 없을 때(정적 배포·서버 다운)는 브라우저 `localStorage`로 폴백한다.

- `exam-priority:subjects` — 과목 배열 (폴백 캐시)
- `exam-priority:weight` — 우선순위 성향 키

```json
  "grading": 5,

  "createdAt": "2026-07-15 10:00:00"
}
```
