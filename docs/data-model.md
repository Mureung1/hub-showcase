# 데이터 모델 설계

## subjects 테이블

사용자가 등록한 시험 과목 정보를 저장한다.

| 컬럼명 | 자료형 | 필수 여부 | 설명 |
|---|---|---|---|
| id | bigint | 필수 | 과목을 구분하는 고유 번호 |
| name | text | 필수 | 과목명 |
| exam_date | date | 필수 | 시험 날짜 |
| understanding | integer | 필수 | 현재 이해도 1~5 |
| difficulty | integer | 필수 | 과목 난이도 1~5 |
| importance | integer | 필수 | 중요도(학점 비중) 1~5, 기본 3 |
| grading | integer | 필수 | 교수님 학점 성향 1~5 (1=후하게, 5=짜게), 기본 3 |
| study_amount | integer | 필수 | 공부 분량(시험 범위) 1~5, 기본 3 |
| created_at | timestamptz | 필수 | 과목 정보 생성 시각 |

> `priority_score`(우선순위 점수)는 저장하지 않는다. 위 점수형 필드와 시험까지 남은 날짜,
> 사용자가 선택한 우선순위 성향(가중치)으로 화면에서 매번 계산한다.

## 우선순위 점수 계산

각 요소를 0~100 점수로 환산한 뒤 성향별 가중치로 합산한다.

- 이해도: 낮을수록 높은 점수 `(5 - understanding) / 4 * 100`
- 난이도: 높을수록 높은 점수 `(difficulty - 1) / 4 * 100`
- 급함: 시험이 가까울수록 높은 점수 (30일 기준, 지났으면 100)
- 중요도: 높을수록 높은 점수 `(importance - 1) / 4 * 100`
- 교수 성향: 짜게 줄수록 높은 점수 `(grading - 1) / 4 * 100`
- 분량: 많을수록 높은 점수 `(study_amount - 1) / 4 * 100`

| 성향 | 이해도 | 난이도 | 급함 | 중요도 | 교수 | 분량 |
|---|---|---|---|---|---|---|
| 균형 | 0.25 | 0.15 | 0.20 | 0.20 | 0.10 | 0.10 |
| 난이도 중시 | 0.20 | 0.30 | 0.10 | 0.15 | 0.10 | 0.15 |
| 임박도 중시 | 0.15 | 0.10 | 0.40 | 0.15 | 0.10 | 0.10 |
| 학점 전략 | 0.15 | 0.10 | 0.15 | 0.30 | 0.20 | 0.10 |

> 각 성향의 가중치 합은 1.0 이다. 클라이언트(`priorityCalculator.js`)와
> 서버(`priorityService.js`)가 같은 값을 쓴다.

## 저장 방식

과목 데이터는 서버의 SQLite 파일 DB(`server/data/app.db`)에 저장한다. 서버를 재시작해도
데이터가 남는다. 서버가 없을 때(정적 배포·서버 다운)는 브라우저 `localStorage`로 폴백한다.

- `exam-priority:subjects` — 과목 배열 (폴백 캐시)
- `exam-priority:weight` — 우선순위 성향 키

## 데이터 예시

```json
{
  "id": 1,
  "name": "한방병리학",
  "examDate": "2026-07-25",
  "understanding": 2,
  "difficulty": 5,
  "importance": 5,
  "grading": 4,
  "studyAmount": 3,
  "createdAt": "2026-07-15 10:00:00"
}
```
