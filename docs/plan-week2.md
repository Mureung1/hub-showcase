## 7.22 (수) — 남은 플로우 UI 완성

**작업**: 프로젝트 생성~배정 사이의 미구현 화면 5종 (목업 데이터 기반, Soft Mint 통일)
- **AI 계획 검토**(생성자): 역할·마일스톤·태스크 인라인 수정, "다시 제안받기" 3회 카운터, "이대로 확정"
- **초대 링크 표시**: 링크 + 복사 버튼
- **join 완성판**: 프로젝트 미리보기(팀 이름·참여 현황) + 즉시 가입 + 닉네임
- **설문**: 선호 순위·기피·경험·리더 의향 + "m/n명 제출" 현황 + 정원 미달 수동 마감 시 "전체 참여 인원을 m명으로 수정할까요?" 확인 UI
- **배정 결과**(생성자 검토): "프로젝트 생성 완료"(=공개) + 공개 후 10분 내 1회 역할 맞교환

**완료 기준**
- [ ] 위저드 제출 → 계획 검토 → 확정 → 초대 → 설문 → 배정 결과까지 화면 흐름이 끊기지 않고 이어진다
- [ ] 각 화면의 예외 문구(재생성 소진, 정원 미달, 10분 경과)가 표시된다

**검증**: 목업 데이터로 전 플로우 클릭 통과

**추천 커밋**: `프로젝트 생성~배정 플로우 UI 구현`

## 7.23 (목) — 스테이지 ④: API·인증·에이전트 연결 (실데이터 전환)

**작업**
- **인증**: 회원가입(아이디 중복확인)·로그인 — bcrypt 해시 + JWT(httpOnly 쿠키)
- **프로젝트 API**: 생성(첨부는 multer→Storage), 계획 조회/수정, 재생성(3회 제한), 확정 → 초대 토큰 발급, join, 설문 제출/마감, 결정적 배정 실행
- **에이전트**: `server/services/planner.js`(structured outputs로 역할/마일스톤/태스크 JSON, 실패 시 재시도 1회 → 템플릿 폴백) + `explainer.js`(팀 단위 배정 설명) — 모델 `CLAUDE_MODEL`(기본 claude-sonnet-5)
- 프론트를 목업 데이터에서 실제 API 호출로 교체

**완료 기준**
- [ ] 브라우저 2개(생성자/팀원)로 가입→생성→플래닝→초대→설문→배정 전 과정이 실제 DB에 저장되며 통과한다
- [ ] Claude API 실패 시 템플릿 폴백으로 계획이 생성된다

**검증**: 2브라우저 시나리오 테스트 + Supabase 대시보드에서 데이터 확인

**사용자 할 일**: Anthropic API 키 발급(크레딧 ~$5) 후 `.env`에 입력 (목요일 전까지)

**추천 커밋**: `Express API·인증·Claude 에이전트 연동 — 실데이터 흐름 완성`
