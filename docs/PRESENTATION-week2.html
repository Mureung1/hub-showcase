게임 기획자 지망생이 역기획서를 틀부터 배우고, 쓰고, 사람과 AI 양쪽에게 피드백받는 웹 플랫폼. 이번 주는 그 작성 흐름을 화면 → Express → Supabase로 한 바퀴 실제로 연결했습니다.

무엇을 만들었나

역기획서를 구조부터 쓰고 피드백받는 곳

"백지 공포" 없이 직군별 템플릿과 섹션 가이드를 따라 쓰고, 같은 게임·시스템을 다룬 글을 나란히 비교하며 배웁니다.

가이드형 에디터

직군 템플릿 + 섹션별 작성 가이드가 내장된 에디터. 이번 주의 핵심 화면.

아카이브 · 코멘트

발행한 역기획서를 섹션 단위로 읽고 코멘트를 남깁니다.

AI · 챌린지

섹션별 자동 피드백(모의)과 격주 챌린지로 "일단 완성"을 강제.

이번 주 범위 작성 → 임시저장 → 발행 → 조회 → 코멘트 화면 ↔ 서버 ↔ DB 한 바퀴

라이브 데모 · 약 3분

한 바퀴를 눈으로 돌립니다

1
작성하기 → 시스템 템플릿 선택. 섹션 가이드를 보며 개요를 씁니다.
2
임시저장 → 서버가 uuid를 발급해 초안 행 생성.POST /api/documents · 201 · 마이페이지에 초안 등장
3
AI 피드백 받기 → 섹션별 코멘트(모의)가 붙습니다.
4
태그 채우고 발행 → 같은 행의 status를 flip, 상세로 이동.PATCH · /archive/<uuid> · publish_requires_tags 가드
5
섹션 코멘트 등록 → 새로고침 → 코멘트가 그대로 유지됩니다.DB 영속 — 화면 상태가 아니라 실제 저장
6
둘러보기·마이페이지 → 발행 카드와 "받은 피드백" 수가 반영.
7
DB 증거 → Supabase 테이블 또는 API 응답에서 실제 행을 확인.
