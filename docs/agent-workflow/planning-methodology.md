# 프로젝트 기획 구체화 방법 (Project Planning Skill)

> 이 문서는 `hub`(AI 논문 브리핑 서비스) 프로젝트를 기획하며 실제로 사용한 절차를 재사용 가능한 형태로 정리한 것이다. "막연한 아이디어"를 "실행 가능한 MVP 기획서 + 화면 설계"로 바꾸는 파이프라인이다.

## 언제 쓰나
- 새 프로젝트/기능 아이디어를 처음 구체화할 때
- 요구사항이 흐릿하고 무엇부터 정할지 모를 때
- 문제 정의 → 시나리오 → MVP → 화면까지 일관된 문서가 필요할 때

## 핵심 원칙 (전 단계 공통)
1. **한 번에 한 결정.** 큰 질문을 잘게 쪼개 순차적으로 확정한다. 앞 답이 뒤 질문의 전제가 된다.
2. **MVP와 향후를 항상 분리 태깅.** 모든 아이디어를 버리지 않고 `[MVP]` / `[향후 확장]`으로 기록해 스코프를 지키면서 비전을 보존한다.
3. **선택을 열어둔다.** 객관식으로 묻되 항상 "직접 입력(기타)" 여지를 남긴다.
4. **실현 가능성을 먼저 검증.** 비용·기술 제약(무료 티어, 서버 필요 여부 등)을 기획 초기에 확인해 헛된 스코프를 방지한다.
5. **매 단계 산출물은 문서로.** 대화 결과를 그때그때 `.md`로 남기고 상호 링크한다. 시각물은 아티팩트로.

---

## 파이프라인 (7단계)

### 1단계 · 목적/문제 정의 명확화
- **한다**: 사용자의 아이디어를 받아 **목적을 한 문장으로 재정의**하고, 단순 경쟁재와의 차별점(진짜 가치)을 짚는다.
- **출력**: "한 문장 정의" + 문제 상황(고통 포인트) + 해결 방향 + 타겟 + 핵심 가치.
- **팁**: 문제를 "① 무엇을 못 해서 ② 어떤 비용이 드는가"로 쪼갠다.

### 2단계 · 순차 인터뷰 (10문항 내외)
- **한다**: 기획서에 필요한 항목을 **질문 리스트로 만들고, 하나씩** 묻는다. 객관식 + 기타 입력.
- **묻는 축(권장 순서)**:
  1. 주 사용자(페르소나) → 2. 성공 기준(핵심 가치) → 3. 콘텐츠/데이터 소스 → 4. 범위(scope) →
  5. 갱신 주기/형태 → 6. 핵심 로직 → 7. MVP 필수 기능 → 8. 기술 스택/아키텍처 →
  9. 사용자·인증 필요성 → 10. 기간·예산·역량 제약
- **각 답변 처리**: 즉시 요약 기록 + `[MVP]`/`[향후]` 태깅. 사용자가 "1번만 하고 나머지는 나중에"라고 하면 그대로 반영.
- **팁**: 사용자가 되묻는 기술 질문(예: "유료 API가 꼭 필요한가?")에는 **표로 옵션·비용을 비교**하고 추천안을 제시한 뒤 다시 묻는다.

### 3단계 · 기획서 작성 (`plan.md`)
- **구성**: Context(왜) · 목적/타겟 · 콘텐츠 범위 · 핵심 로직 · 기능 명세(MVP/향후) · 기술 스택·아키텍처 · 비용 전략 · 개발 제약 · 로드맵 · 검증 방법 · (부록) 인터뷰 요약표.
- **원칙**: 스캔 가능할 만큼 간결하되 실행 가능할 만큼 구체적으로.

### 4단계 · 사용자 시나리오 도출 (`user-scenarios.md`)
- **한다**: MVP에 얽매이지 말고 **넓은 범위**에서 시나리오를 뽑는다(검색·분류 등 향후 기능 포함).
- **페르소나 전략**: 보통 **단일 페르소나 × 서로 다른 상황 4개**가 일관성이 좋다.
- **각 시나리오 항목**: 트리거 · 목표(JTBD) · 화면 구성 · 동작 흐름 · **사용 기능** · 핵심 가치.
- **마무리**: 시나리오 → 사용 기능 매핑 표로 커버리지 확인.

### 5단계 · 사용자 흐름 시각화 (User Flow)
- **한다**: 대표 시나리오 하나를 골라 **번호형 단계 흐름**으로 그린다.
- **표기 포맷**(텍스트):
  ```
  1. 사용자: (행동)
     ↓
  2. 시스템: (반응)  - 세부 요소 나열
     ↓
  3. 판단: (질문)?
     ├─ 아니오 → (대안)  ↺ N번으로 반복
     └─ 예 ↓
  ...
  N. 완료! 🎉 (달성 상태)
  ```
- **표기 규칙**: 행위자(사용자/시스템/판단)를 접두로, `↓` 진행, `├─/└─` 분기, `↺` 반복 루프.
- **아티팩트 버전**: 노드 타입(시작/끝·화면·행동·판단·반복)을 색·모양으로 구분한 플로우차트로도 시각화.

### 6단계 · MVP로 좁히기 (`mvp-plan.md`)
- **한다**: 시나리오 **1개만** 골라 그 흐름을 완주시키는 **최소 기능**만 추린다.
- **기능 도출법**: 흐름의 각 단계에서 필요한 화면/행동을 뽑아 `F1, F2 …`로 번호화하고 **흐름 단계와 매핑**(표: 기능 | 설명 | 흐름 단계).
- **구성**: 1) 문제 정의·상황 → 2) 선택 시나리오 + 사용자 흐름 첨부 → 3) 핵심 기능(F#) → 4) 화면 설계 → (뒷단 파이프라인) → (MVP 범위 밖).

### 7단계 · 화면 설계 (와이어프레임)
- **한다**: 각 핵심 기능(F#)을 담는 **로우파이 화면**을 그린다. 회색 플레이스홀더 + 요소를 F#에 매핑.
- **최소 화면 세트**: 목록/피드 → 상세 → (보조: 저장/결과) 정도로 흐름을 완주.
- **문서 삽입법(추천 A+C)**: `.md` 안에는 **ASCII 스케치**(항상 보임)를 넣고, 그 아래 **인터랙티브 HTML 링크**로 풀 디테일 연결.

---

## 산출물 & 도구 규칙
- **문서**: 각 단계 결과를 `.md`로 저장하고 상호 링크(`plan.md` ↔ `user-scenarios.md` ↔ `mvp-plan.md`).
- **시각화**: 흐름도·와이어프레임 등은 아티팩트(HTML)로. 마크다운에는 ASCII + 링크로 연결.
- **일관성**: 프로젝트 디자인 언어(팔레트·타이포)를 한 번 정하면 이후 아티팩트에서 재사용.
- **파일 예시 구성**:
  ```
  plan.md            전체 기획서
  user-scenarios.md  사용자 시나리오(넓은 범위)
  mvp-plan.md        MVP 기획(문제정의→흐름→기능→화면)
  s1-wireframe.html  인터랙티브 와이어프레임
  ```

## 안티패턴 (하지 말 것)
- 질문을 한꺼번에 10개 쏟아붓기 → 답이 얕아지고 전제가 꼬인다.
- 향후 아이디어를 그냥 버리기 → `[향후 확장]`으로 반드시 남긴다.
- 기술 스택을 먼저 정하고 문제를 끼워맞추기 → 문제·사용자·흐름 뒤에 스택을 결정한다.
- MVP에 시나리오 여러 개 욱여넣기 → 하나로 좁혀 완주 가능성을 확보한다.
