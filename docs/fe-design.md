# Photo Navigation FE Design Guide

## Product frame

- **Target**: 지도에서 촬영 지점과 프레임을 찾아 사진을 찍고 싶은 모바일 사용자.
- **Primary canvas**: 지도다. 카드는 정보 확인과 반복 목록에만 사용하며, 첫 화면을 카드 모음으로 만들지 않는다.
- **Viewport**: 모바일 기준 `390 x 844`에서 시작한다. 데스크톱에서는 휴대폰 프레임과 짧은 설명을 나란히 둔다.

## Visual language

- 네이버 지도와 어울리는 밝은 기본 지도 위에, 브랜드 포인트로 `#03C75A`를 사용한다.
- 본문은 거의 검정에 가까운 녹색 계열, 보조 설명은 차분한 회색, 구분선은 옅은 회색으로 제한한다.
- 고정된 UI는 흰색 배경, 얕은 그림자, `8px` 안팎의 작은 모서리 반경을 사용한다. 바텀시트만 상단을 크게 둥글게 처리한다.
- 아이콘 버튼은 텍스트보다 우선하며, 도구성 동작에는 Lucide 아이콘을 쓴다.

## Map screen

1. 전체 화면을 실제 네이버 지도로 채운다.
2. 상단에는 검색창, 그 아래에는 `공식 포토스팟 / 후보 보기` 세그먼트 컨트롤을 고정한다.
3. 공식 마커는 녹색 카메라 성격의 핀, 후보 마커는 흰색 바탕의 녹색 하트와 좋아요 수로 구분한다.
4. 우측에는 현재 위치/레이어 같은 작은 원형 도구 버튼을 세로로 배치한다.
5. 하단 바텀시트에는 손잡이, 공식·후보 상태, 후보 제안 버튼, 사진 썸네일 목록을 둔다.

## Detail and proposal

- 상세 화면은 큰 예시 사진, 장소명, 좋아요, 후보 등록 기준, 위치와 설명, 후보 제안 CTA 순서다.
- 좋아요는 후보 화면에서만 동작하며, 활성 상태는 녹색 채움 하트로 명확히 표시한다.
- 후보 제안은 지도 클릭으로 촬영 좌표를 정하고, 사진 선택과 `1인 / 커플` 프레임 선택을 같은 화면에서 끝낸다.
- 완료 화면은 `좋아요 기준 → 관리자 검토 → 공식 등록`의 세 단계를 세로 흐름으로 보여준다. AI 자동 승인처럼 보이게 하지 않는다.

## Responsive and accessibility

- 모바일에서는 지도와 바텀시트가 화면을 완전히 사용하고, iOS 안전 영역을 침범하지 않는다.
- 텍스트가 긴 장소명도 줄바꿈 또는 말줄임으로 제어하고 버튼 크기를 밀어내지 않도록 한다.
- 모든 아이콘 버튼에 `aria-label`을 제공하고, 지도 불러오기 실패는 화면에서 바로 설명한다.
