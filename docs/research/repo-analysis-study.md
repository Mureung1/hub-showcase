# Git Repository 분석 학습 노트

## 학습 목표

PtoP가 프로젝트 경험을 정리하기 위해 Git Repository에서 어떤 정보를 읽고, 그 정보를 어떻게 포트폴리오 초안으로 연결할 수 있는지 정리한다.

## Repository에서 분석할 수 있는 정보

| 분석 대상 | 얻을 수 있는 정보 | PtoP에서 활용하는 방식 |
| --- | --- | --- |
| README | 프로젝트 목적, 주요 기능, 실행 방법, 기술 스택 | 프로젝트 요약과 포트폴리오 소개 문장 생성 |
| 폴더 구조 | 프론트엔드/백엔드 구분, 도메인 구조, 주요 기능 영역 | 프로젝트 구조 요약과 핵심 기능 후보 추출 |
| package.json | 사용 라이브러리, 프레임워크, 스크립트 | 기술 스택 자동 정리 |
| 주요 코드 파일 | 실제 구현된 기능, 상태 관리, API 연결, 컴포넌트 구조 | 핵심 구현 내용과 기술적 어필 포인트 추출 |
| commit log | 작업 순서, 자주 수정한 파일, 기능 개발 흐름 | 내가 한 일과 기여 흐름 추론 |
| PR/Issue | 문제 상황, 논의 내용, 리뷰, 의사결정 | 문제 해결 과정과 협업 경험 정리 |

## README 분석 관점

- 프로젝트가 무엇을 해결하려는지 확인한다.
- 주요 기능 목록이 있는지 확인한다.
- 사용 기술과 실행 방법이 정리되어 있는지 확인한다.
- 배포 링크, 시연 이미지, 데모 설명이 있는지 확인한다.
- README가 부족하면 코드와 폴더 구조를 더 많이 참고해야 한다.

## 폴더 구조 분석 관점

폴더 구조는 프로젝트의 기능 단위와 관심사 분리를 파악하는 데 도움이 된다.

예시:

```text
src/
  components/
  pages/
  hooks/
  api/
  utils/
```

위 구조에서는 다음과 같이 추론할 수 있다.

- `components`: 재사용 UI 컴포넌트가 있음
- `pages`: 화면 단위 라우팅이 있음
- `hooks`: 공통 상태나 로직을 분리했을 가능성이 있음
- `api`: 서버 통신 로직이 있음
- `utils`: 공통 유틸 함수가 있음

## package.json 분석 관점

`package.json`에서는 기술 스택과 실행 방식을 확인할 수 있다.

- `dependencies`: 실제 서비스 코드에서 사용하는 라이브러리
- `devDependencies`: 개발, 빌드, 테스트 도구
- `scripts`: 실행, 빌드, 테스트 명령어

예시:

```json
{
  "dependencies": {
    "react": "...",
    "vite": "..."
  },
  "scripts": {
    "dev": "vite",
    "build": "vite build"
  }
}
```

이 경우 PtoP는 `React`, `Vite` 기반 프론트엔드 프로젝트로 정리할 수 있다.

## 주요 코드 파일 선별 기준

모든 파일을 같은 비중으로 분석하면 핵심을 놓칠 수 있다. 우선순위를 정해 분석한다.

1. README와 설정 파일을 먼저 본다.
2. 진입점 파일을 확인한다.
   - 예: `main.jsx`, `App.jsx`, `server.js`, `app.ts`
3. 화면 또는 라우팅 파일을 확인한다.
4. API 호출 파일을 확인한다.
5. 상태 관리, 비즈니스 로직, 유틸 파일을 확인한다.
6. 테스트 파일이 있다면 기능 의도를 함께 확인한다.

## commit log 분석 관점

commit log는 사용자가 어떤 순서로 작업했는지 보여준다.

확인할 수 있는 정보:

- 어떤 기능이 먼저 만들어졌는가?
- 어떤 파일을 자주 수정했는가?
- 버그 수정이나 리팩토링이 있었는가?
- 문서 작업과 기능 작업이 어떻게 나뉘었는가?

예시 commit:

```text
feat: 로그인 기능 구현
fix: 토큰 만료 처리 오류 수정
refactor: API 호출 로직 분리
docs: README 실행 방법 추가
```

이 흐름에서는 로그인 기능 구현, 인증 예외 처리, API 로직 구조 개선, 문서화 경험을 추출할 수 있다.

## 분석 결과 분류 방식

PtoP는 분석 결과를 다음 항목으로 나눠 보여준다.

- 프로젝트 목적
- 핵심 기능
- 기술 스택
- 주요 구현 내용
- 역할 후보
- 문제 해결 과정 후보
- 포트폴리오 문장 후보

## 분석 시 주의할 점

- 코드만 보고 사용자의 실제 역할을 단정하지 않는다.
- commit author가 여러 명이면 개인 기여도 추론에 주의한다.
- README가 최신 상태가 아닐 수 있다.
- 자동 분석 결과는 사용자가 수정할 수 있어야 한다.
- 분석 결과는 "정답"이 아니라 "초안"으로 제공해야 한다.
