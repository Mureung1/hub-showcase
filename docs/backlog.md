# CareerSignal 개발 백로그

이 문서는 실제 제품 개발을 위한 우선순위 있는 작업 목록이다. 정적 프로토타입의 완료 기록은 [작업 체크리스트](checklist.md)에서 관리하고, 이 문서에서는 실제 제품(백엔드 직무 기준 MVP) 작업을 관리한다.

## 1. 관리 원칙

- **P0**: 없으면 MVP의 핵심 사용자 흐름(직무 선택 → 통계 → 역산 → 합격 조건 → 로드맵)이 완성되지 않는 작업
- **P1**: MVP의 신뢰도·완성도·에이전트성을 높이는 작업
- **P2**: MVP 검증 뒤에 다루는 확장 작업
- 작업은 완료 여부를 확인할 수 있는 결과와 완료 조건을 함께 적는다.
- 이번 주에 시작할 작업만 하위 작업으로 나누고, 먼 미래의 작업은 큰 단위로 유지한다.
- 새로운 피드백·버그·아이디어는 먼저 이 문서에 추가하고 우선순위를 정한 뒤 착수한다.

## 2. 4주 개발 로드맵

| 기간 | 목표 | 완료 기준 |
| --- | --- | --- |
| 1주차 (완료) | 문제 정의·기획과 백엔드 5화면 정적 프로토타입 검증 | 5화면 HTML/CSS 프로토타입, 기획·설계·디자인 문서, Vercel 데모 완료 |
| 2주차 (완료) | 네 화면(통계·역산·합격 조건·로드맵)의 수직 슬라이스 — 프론트·데이터 계약·백·DB(Supabase 샘플 적재). 에이전트는 실제 API 경로에 놓인 fixture 입출력 | 서버가 DB에서 샘플을 읽고, 역산·합격 조건·로드맵 요청이 Express→FastAPI 경로로 fixture 응답을 받아 화면에 표시된다 |
| 3주차 | LLM·소량 실데이터(1·2·3차) 확보 → 배치 에이전트 4개 구현 → 범위별 분석 산출물 저장 → 평가 세트 테스팅 → MVP 배포·클로즈드 베타 | 소량 실데이터와 검증된 통계·역산·체크리스트·기본 로드맵이 활성 데이터 버전으로 제공되고, 배포 URL로 베타 피드백을 수집한다 |
| 4주차 | 베타 피드백 반영 → 대량 실데이터 수집 자동화 → 목표 직군 확장 → 비로그인 사용자 공고 입력 → 데모·발표 준비 | 수집·갱신 파이프라인과 직접 입력 개별 역산이 동작하고, 목표 직군 분석 데이터와 발표 자료가 완성된다 |

## 3. 다음 주 완료 목표

다음 주(3주차)에는 fixture를 생성·검증된 분석 산출물로 교체하고 MVP를 배포한다.

> 네 에이전트(통계분석 추출·해석, 역산, 합격 조건, 로드맵)가 데이터 갱신 파이프라인에서 범위별 결과를 만들고, 일반 사용자 요청은 활성 데이터 버전의 저장 결과를 조회하며, 서비스가 실제 URL로 배포되어 베타 피드백을 받는다.

3주차 첫 작업은 데이터·LLM API 신청, 실공고·근거 자료 수집, 평가 세트 구축과 에이전트 실행·저장 구조 설계다. 공고 3건 추출 스모크 테스트로 모델·프롬프트·계약을 확인한 뒤 전체 평가 세트와 범위별 분석 산출물로 확장한다. 로그인, 개인 역량 Gap 분석, 자동 클러스터링은 구현하지 않는다.

## 5. MVP 검증 시나리오

- [ ] `백엔드 개발자` 선택 시 해당 직무의 공고 수, 기술 조합·빈도, 시계열 추세가 표시된다.
- [ ] baseline 대비 기업군·개별 공고의 편차가 근거 문장·신뢰도와 함께 표시된다.
- [ ] 합격 조건 체크리스트가 자소서·포트폴리오·면접 활용처로 나뉘고, 미체크 항목이 로드맵으로 이어진다.
- [ ] 로딩·지원하지 않는 직무·오류·빈 결과 상태가 화면 흐름을 방해하지 않는다.
- [ ] 결과의 기술·역산·로드맵 항목이 입력 직무의 샘플 공고 데이터·통계와 연결된다.
