# 백로그(Backlog) 관리 — 근거 검증 Agent

`checklist.md`가 "기능을 작업 단위로 쪼갠 목록"이라면, 이 문서는 그 목록을 **언제, 어떤 순서로, 얼마나 중요하게** 처리할지 관리하는 문서다. 기획은 [plan.md](plan.md), 작업 분해는 [checklist.md](checklist.md), 스킬 계약은 [skills.md](skills.md) 참고.

## 1. 백로그란 무엇인가

**백로그**는 아직 완료하지 않은 할 일을 우선순위 순으로 정리한 목록이다. 스크럼(Scrum) 등 애자일 개발 방법론에서 쓰는 용어지만, 개념 자체는 "해야 할 일 + 순서"만 있으면 어디서든 쓸 수 있다.

### 1.1 왜 필요한가

- **할 일과 순서를 분리해서 본다.** 체크리스트(`checklist.md`)는 "무엇을 만들지"만 보여주고, 백로그는 거기에 "언제·왜 먼저 하는지"를 더한다.
- **우선순위 판단 기준이 생긴다.** 시간이 부족할 때 무엇을 포기할지(P2부터 뺀다) 미리 정해두면 매주 새로 고민하지 않아도 된다.
- **진행 상황을 한눈에 추적한다.** 이번 주에 뭘 끝냈고, 다음 주에 뭘 할지 하나의 문서에서 확인한다.
- **혼자 하더라도 "미래의 나"와 협업하는 문서다.** 1인 개발이어도 2주 뒤의 나는 지금 왜 이 순서로 했는지 기억하지 못한다.

### 1.2 어떻게 생겼나

가장 흔한 형태는 **표(테이블)** 다. 최소한 아래 컬럼이 있으면 된다.

| 컬럼 | 의미 |
|---|---|
| Task | 큰 단위의 작업 이름 (체크리스트 여러 항목을 묶은 수준) |
| 설명 | 한두 줄로 무엇을 하는 일인지 |
| 우선순위 | P0(필수) / P1(중요) / P2(선택) 등 |
| 주차 | 몇 주차에 할지 |
| 상태 | 대기 / 진행중 / 완료 |

Notion·Google Sheet·Jira·Trello는 이 표를 칸반 보드(할 일/진행중/완료 컬럼)나 DB 형태로 시각화해주는 도구일 뿐, 개념은 동일하다. 이 프로젝트는 저장소 안에서 버전 관리가 되도록 **마크다운**(이 문서)을 1차 소스로 쓰고, 필요하면 Notion·Google Sheet로 옮겨 팀과 공유할 수 있다.

### 1.3 어떻게 관리하나

- **하나의 진실 소스(single source of truth)를 유지한다.** 같은 Task를 여러 문서에 따로 적지 않는다. 세부 체크박스는 `checklist.md`에 두고, 이 문서는 그걸 우선순위·주차로 묶어서 참조한다.
- **주기적으로 재검토한다.** 매주 끝(금요일 기준)에 이번 주 완료 항목을 표시하고, 다음 주 우선순위가 바뀌었는지 확인한다.
- **우선순위는 고정이 아니다.** 새로운 리스크나 막힌 부분이 생기면 P1↔P2를 재조정한다. 단, 이유 없이 자주 바꾸면 계획 자체가 무의미해지므로 재조정 사유를 한 줄 남긴다.
- **끝난 Task는 지우지 않고 상태만 "완료"로 바꾼다.** 무엇을 왜 미뤘는지(P2로 내린 이유)가 이력으로 남아야 다음에도 같은 실수를 반복하지 않는다.

## 2. 우선순위 기준

| 우선순위 | 의미 | 이 프로젝트에서의 기준 |
|---|---|---|
| **P0** | 없으면 서비스가 성립하지 않음 | CLAUDE.md의 절대 원칙(추천 금지·환각 금지·기준일 표시)을 지키는 데 필요한 기능, 핵심 파이프라인(A·B·C) |
| **P1** | 있어야 완성도가 나오지만, 없어도 데모는 가능 | 화면 완성도, 용어 설명, 엣지 케이스 처리, 평가 스크립트 |
| **P2** | 있으면 좋음, 4주 안에 시간이 남으면 | 배포, 누적 복기 리포트(패턴 분석), 포트폴리오 문서화 |

## 3. Task 백로그

`checklist.md`의 세부 항목을 **6개의 큰 Task**로 묶고 우선순위를 매겼다. 세부 체크박스는 `checklist.md`를 그대로 따른다.

| # | Task | 설명 | 우선순위 | 주차 | 상태 |
|---|---|---|:---:|:---:|:---:|
| 1 | 데이터 기반 구축 | PostgreSQL 스키마, OpenDART 연동, 공시 파싱, 재무지표 계산 (S1~S3) | P0 | 1주차 | 대기 |
| 2 | 종목 공부 리포트 (기능 A) | 종목 검색·리포트 화면, 전문용어 설명, 공시 부족 종목 처리, 기준일 표시 (S4·S11) | P0 | 1주차 | 대기 |
| 3 | 현재가·적정가 분석 (기능 B) | 현재가 조회/입력, 적정가 범위 산출, 고평가·저평가 판정, 매수 가능 구간 (S5·S6) | P0 | 2주차 | 대기 |
| 4 | 근거 검증 프로토타입 (기능 C) | LangGraph 노드 설계, 근거 유형 추출, 공시·재무 데이터 대조 **+ 부족 시 스스로 재검색하는 반복 루프**, 체크리스트 (S7~S9) | P0 | 2~3주차 | 대기 |
| 5 | 로그·RAG·평가 지표 | Chroma RAG 연동, 복기 로그 저장, 숫자 일치율·근거 타당성·환각률 스크립트, 통합 테스트 | P1 | 3~4주차 | 대기 |
| 6 | 확장·배포·데모 | 누적 복기 리포트, 프론트-백엔드 연결, 배포, 데모 시나리오, 포트폴리오 문서화 | P2 | 4주차 | 대기 |
| 7 | 개인용 매수 주문 실행 (S12) | 증권사 Open API 연동, 모의투자 모드, 실거래 확인 단계·주문 한도. **본인 계좌 전용, 4주 MVP 밖** | P2 | 5주차 이후 | 대기 |

> Task 5(로그·RAG·평가)는 P0인 근거 검증(Task 4)이 없으면 검증할 대상이 없으므로 P1로 내렸다. 시간이 부족하면 Task 6(P2)을 가장 먼저 잘라낸다 — 배포 없이 로컬 데모로도 핵심 가치(근거 검증)는 증명 가능하기 때문이다.
>
> Task 7(개인용 매수 주문 실행)은 4주 MVP의 핵심 가치(근거 검증)와 무관한 별도 확장이라 의도적으로 5주차 이후로 분리했다. 본인 계좌 전용 기능이므로 배포·포트폴리오 데모 시에는 꺼두거나 모의투자 모드로 고정한다 — "투자자문/중개 서비스"로 오해받을 여지를 MVP 데모에서 차단하기 위함이다.

## 4. 4주 실행 계획

`checklist.md`의 5주 분해를 **4주로 압축**했다(오늘 기준 2026-07-10). 5주차의 "확장" 항목은 P2로 내려 4주차 안에 시간이 남을 때만 진행한다.

| 주차 | 기간 | 목표 (Task 매핑) |
|---|---|---|
| **1주차** | 2026-07-10 ~ 07-16 | Task 1 + Task 2 — 데이터 기반 구축, 종목 공부 리포트(기능 A) 완성 |
| **2주차** | 2026-07-17 ~ 07-23 | Task 3 + Task 4 시작 — 현재가·적정가 분석(기능 B), 근거 검증 노드 설계·추출 로직 |
| **3주차** | 2026-07-24 ~ 07-30 | Task 4 마무리 + Task 5 시작 — 근거 검증·체크리스트 완성, RAG·복기 로그 연동 |
| **4주차** | 2026-07-31 ~ 08-06 | Task 5 마무리 + Task 6 (여유 시) — 평가 지표, 통합 테스트, 배포·데모 준비 |

### 다음 주(1주차, ~2026-07-16)까지 끝낼 것

이번 주는 P0 중에서도 가장 먼저 막히는 지점(데이터 연동)부터 처리한다.

- [ ] PostgreSQL 스키마 설계 (종목·공시·재무지표 테이블)
- [ ] OpenDART API 연동 — 공시 목록 조회 성공 확인
- [ ] 재무지표 계산 로직 (매출·영업이익·부채비율·영업현금흐름) 1개 종목 기준 동작 확인
- [ ] 종목 리포트 화면 뼈대 (기업개요 + 최근 공시 섹션)에 기준일 표시까지 연결

이 4개가 끝나면 1주차 목표(Task 1)는 완료로 표시하고, 남은 시간에 Task 2(전문용어 설명, 공시 부족 처리)로 넘어간다. 못 끝내면 다음 주 계획에서 우선순위 재조정 사유를 이 문서에 한 줄 남긴다.

## 5. 운영 원칙

- 매주 금요일(또는 주차 마지막 날) 이 문서를 열어 상태 컬럼을 갱신하고, 다음 주 목표를 다시 쓴다.
- Task 상태가 바뀌면 `checklist.md`의 해당 체크박스도 함께 갱신한다 — 두 문서가 어긋나지 않게 한다.
- 우선순위를 바꿀 때는 표 아래에 이유를 한 줄 남긴다(예: "OpenDART 응답 지연으로 Task 1을 1주 연장, Task 3을 3주차로 이동").
- Notion·Google Sheet 등 외부 도구로 옮겨 관리하게 되면, 이 문서 상단에 링크만 추가하고 실제 소스는 하나만 유지한다.
