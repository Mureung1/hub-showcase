# CareerSignal 개발 백로그

이 문서는 CareerSignal의 개발 로드맵과 프로젝트 수준 이니셔티브를 관리한다. 실행 단위와 담당·일정·상태는 GitHub Issues와 GitHub Projects에서 관리하고, MVP의 배포 가능 여부는 [검증 체크리스트](checklist.md)에서 판정한다.

## 1. 관리 원칙

- 백로그 ID는 GitHub Issue 제목의 접두사로 사용한다.
- 하나의 백로그 항목은 하나 이상의 GitHub Issue로 분해할 수 있다.
- 세부 구현 단계, 일일 작업, 버그와 피드백은 GitHub Issue로 관리하고 이 문서에 중복해서 나열하지 않는다.
- GitHub Projects는 담당자, 상태, 시작일, 목표일, 스프린트와 우선순위의 실행 기준이다.
- 이 문서는 제품 범위, 마일스톤, 완료 조건과 우선순위의 기준이다.
- 완료 상태는 연결된 Issue의 완료 조건과 검증 체크리스트를 모두 충족할 때 반영한다.

| 우선순위 | 기준 |
| --- | --- |
| P0 | 없으면 MVP의 핵심 흐름이나 배포가 성립하지 않는 작업 |
| P1 | 베타 품질, 데이터 규모, 직무 확장과 발표 완성도를 높이는 작업 |
| P2 | MVP 검증 뒤 도입하는 개인화·운영 확장 작업 |

## 7. GitHub Issue 운영 규칙

GitHub Issue 제목은 `[백로그 ID] 작업 요약` 형식을 사용한다.

```text
[AGENT-03] 채용공고 해석 에이전트의 범위별 출력 구현
[PLATFORM-01] 데이터 변경 영향 범위 계산기 구현
[QA-01] 평가 세트 기반 에이전트 회귀 테스트
```

각 Issue는 다음 내용을 포함한다.

- 배경과 해결할 문제
- 작업 범위와 제외 범위
- 입력·출력 또는 변경 파일
- 완료 조건
- 검증 방법
- 관련 백로그 ID와 선행 Issue

GitHub Projects의 상태는 `Backlog`, `Ready`, `In progress`, `In review`, `Done`을 사용한다. 문서의 상태는 마일스톤 점검 시 GitHub Projects와 동기화한다.
