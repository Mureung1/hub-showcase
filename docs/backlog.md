# CareerSignal 개발 백로그

이 문서는 실제 제품 개발을 위한 우선순위 있는 작업 목록이다. 이번 주 정적 프로토타입의 완료 기록은 [작업 체크리스트](checklist.md)에서 관리하고, 이 문서에서는 다음 주부터 시작하는 실제 제품 작업을 관리한다.

## 1. 관리 원칙

- **P0**: 없으면 MVP의 핵심 사용자 흐름이 완성되지 않거나, 다른 작업을 시작할 수 없는 작업
- **P1**: MVP의 신뢰도·완성도·에이전트성을 높이는 작업
- **P2**: MVP 검증 뒤에 다루는 확장 작업
- 작업은 완료 여부를 확인할 수 있는 결과와 완료 조건을 함께 적는다.
- 이번 주에 시작할 작업만 하위 작업으로 나누고, 먼 미래의 작업은 큰 단위로 유지한다.
- 새로운 피드백·버그·아이디어는 먼저 이 문서에 추가하고 우선순위를 정한 뒤 착수한다.

## 2. 4주 개발 로드맵

| 기간 | 목표 | 완료 기준 |
| --- | --- | --- |
| 1주차 (완료) | 문제 정의와 정적 프로토타입 검증 | 3개 화면 HTML/CSS 프로토타입, 문서, Vercel 데모 완료 |
| 2주차 | 실제 MVP의 입력·데이터·API 기반 만들기 | 독립 실행되는 제품 환경에서 직무 입력에 대한 샘플 분석 결과를 API로 반환 |
| 3주차 | 분석 결과와 로드맵을 사용자 화면에 연결 | 입력·로딩·성공·지원하지 않는 직무·오류 상태를 포함한 엔드투엔드 흐름 완성 |
| 4주차 | 분석 신뢰도와 에이전트 확장 가능성 검증 | Verifier, 사용자 피드백 반영, 배포·문서·발표 준비 완료 |

## 3. 다음 주 완료 목표

다음 주에는 실제 제품의 가장 작은 흐름을 만든다.

> 사용자가 `프론트엔드 개발자`를 입력하면, 샘플 공고 데이터에 근거한 요구사항 분석 결과와 4단계 로드맵을 받는다.

이 단계에서는 실제 공고 수집, 로그인, DB 저장, 개인 역량 Gap 분석은 구현하지 않는다.

## 5. MVP 검증 시나리오

- [ ] `프론트엔드 개발자` 입력 시 해당 직무의 공고 수, 구현 범위 조합, 필수·우대사항, 4단계 로드맵이 표시된다.
- [ ] 예시 직무를 누르면 입력값과 분석 결과가 함께 갱신된다.
- [ ] 지원하지 않는 직무에는 대체 안내와 다음 행동이 표시된다.
- [ ] 로딩·오류·빈 결과 상태가 화면 흐름을 방해하지 않는다.
- [ ] 결과의 기술·요구사항·로드맵 항목이 입력 직무의 샘플 공고 데이터와 연결된다.
