# PlaceSync 확정 기능 및 구현 보조 자료

## 1. 서비스 목표

PlaceSync는 사장님이 매장의 영업시간, 휴무일, 메뉴, 가격, 공지사항을 한 번만 수정하면 각 플랫폼에 맞는 값으로 변환하고, 가능한 플랫폼에는 자동 반영하며, 자동 반영이 어려운 플랫폼에는 수정 화면과 복사 가능한 내용을 제공하는 통합 매장 정보 관리 서비스입니다.

---

## 2. 기준 정보 원칙

- PlaceSync에서 사장님이 최종 승인한 정보를 매장의 기준 정보로 사용합니다.
- 외부 플랫폼에서 별도로 수정된 정보가 발견되더라도 자동으로 덮어쓰지 않습니다.
- PlaceSync 정보와 외부 플랫폼 정보가 다르면 충돌 알림을 보내고, 사장님이 유지할 값을 선택합니다.
- 4주 MVP에서는 한 계정이 매장 한 곳만 관리합니다.
- 다지점 통합 관리는 향후 확장 기능으로 둡니다.

---

## 3. 핵심 기능 1: 매장 정보 통합 편집 및 플랫폼별 적용값 생성

### 3.1 통합 편집

사장님은 한 화면에서 다음 정보를 수정합니다.

- 영업시간
- 정기휴무일
- 임시휴무일
- 메뉴 추가·수정·삭제
- 메뉴 가격
- 공지사항

### 3.2 영구 변경과 임시 변경

수정할 때 변경 유형을 선택합니다.

#### 영구 변경

- 적용 즉시 기준 정보가 변경됩니다.
- 별도로 다시 수정하기 전까지 계속 유지됩니다.

#### 임시 변경

- 시작일, 종료일, 적용 시간을 입력합니다.
- 설정한 기간에만 변경 정보가 적용됩니다.
- 기간이 끝나면 기존 정보로 자동 복구됩니다.

예시:

- 7월 15일 하루 임시휴무
- 7월 1일부터 8월 31일까지 여름 영업시간 적용
- 오늘만 오후 6시 조기 마감

### 3.3 플랫폼별 가격 정책

사장님은 플랫폼별 가격 차이를 미리 설정할 수 있습니다.

예시:

- 네이버 플레이스: 매장 가격과 동일
- 카카오맵: 매장 가격과 동일
- 배달앱: 매장 가격보다 500원 높게 설정

가격 차이는 다음 두 단계로 관리합니다.

1. 메뉴 카테고리별 기본 가격 차이
2. 특정 메뉴별 개별 예외 가격 차이

개별 메뉴 설정이 카테고리 기본값보다 우선합니다.

예시:

- 음료 카테고리: 배달앱 +500원
- 디저트 카테고리: 배달앱 +1,000원
- 아메리카노: 개별 예외 +300원

계산 규칙:

```text
플랫폼 적용 가격 = 매장 기준 가격 + 적용할 가격 차이
```

적용 우선순위:

```text
메뉴 개별 설정 > 카테고리 기본 설정 > 플랫폼 기본값
```

### 3.4 메뉴 노출 플랫폼 정책

메뉴 카테고리별로 기본 노출 플랫폼을 설정합니다.

예시:

- 음료: 네이버, 카카오, 배달앱
- 매장 전용 메뉴: 네이버, 카카오
- 배달 전용 메뉴: 배달앱

특정 메뉴는 개별적으로 노출 플랫폼을 변경할 수 있습니다.

적용 우선순위:

```text
메뉴 개별 설정 > 카테고리 기본 설정
```

### 3.5 플랫폼별 적용값 미리보기

실제 업데이트 전에 다음 내용을 플랫폼별로 보여줍니다.

- 변경 전 정보
- 변경 후 정보
- 적용될 메뉴 가격
- 노출 또는 제외될 메뉴
- 영구 변경 또는 임시 변경
- 임시 변경 적용 기간
- 플랫폼별 공지 문구
- 자동 반영 또는 수동 반영 여부

사장님이 미리보기를 확인하고 최종 승인한 뒤 업데이트를 시작합니다.

## 4. 핵심 기능 2: 플랫폼별 정보 반영 및 결과 확인

### 4.1 혼합 업데이트 방식

플랫폼별 지원 방식에 따라 다르게 처리합니다.

#### 자동 업데이트가 가능한 플랫폼

- PlaceSync가 수정 정보를 직접 전송합니다.
- 전송 결과와 반영 상태를 저장합니다.

#### 자동 업데이트가 불가능한 플랫폼

- 해당 플랫폼의 수정 사이트 링크를 제공합니다.
- 입력해야 할 내용을 복사 버튼과 함께 제공합니다.
- 사장님이 수동으로 수정한 뒤 완료 처리할 수 있습니다.

### 4.2 플랫폼별 상태 관리

수정 요청을 보낸 즉시 반영 완료로 처리하지 않습니다.

상태는 다음과 같이 구분합니다.

- 연결됨
- 재연결 필요
- 전송 대기
- 전송 완료
- 플랫폼 검토 중
- 실제 반영 완료
- 반영 실패
- 확인 필요

### 4.3 실패 처리

일부 플랫폼이 실패해도 성공한 플랫폼의 결과는 유지합니다.

실패 처리 순서:

1. 실패한 플랫폼만 다시 시도합니다.
2. 재시도 후에도 실패하면 수정 사이트 이동 버튼을 보여줍니다.
3. 수정할 영업시간, 가격, 메뉴, 공지 내용을 복사할 수 있게 제공합니다.
4. 사장님이 수동 수정 후 완료로 표시할 수 있습니다.

### 4.4 플랫폼 연결 상태 관리

- 플랫폼 연결 상태를 미리 확인합니다.
- 로그인 또는 접근 권한이 만료되면 알림을 보냅니다.
- 대시보드에 재연결 버튼을 제공합니다.
- 연결이 끊긴 플랫폼은 자동 업데이트 대상에서 제외합니다.

## 5. 보조 기능

### 5.1 외부 수정 감지와 충돌 처리

사장님이나 직원이 PlaceSync를 거치지 않고 플랫폼에서 직접 수정하면 PlaceSync 기준 정보와 차이가 발생할 수 있습니다.

차이를 발견하면 다음 정보를 알림으로 제공합니다.

- 차이가 발생한 플랫폼
- 변경된 항목
- PlaceSync 기준값
- 플랫폼 현재값
- 확인 가능한 경우 마지막 변경 시간

사장님은 다음 중 하나를 선택합니다.

- PlaceSync 기준값을 플랫폼에 다시 적용
- 플랫폼 현재값을 PlaceSync의 새 기준값으로 가져오기
- 결정을 보류

### 5.2 항목별 묶음 알림

불일치 알림을 한 건씩 보내지 않고 종류별로 묶어서 제공합니다.

- 가격 불일치
- 메뉴 불일치
- 영업시간·휴무일 불일치

검사 방식:

- 하루에 한 번 자동 검사
- 필요할 때 수동 즉시 검사

### 5.3 수정 이력과 부분 되돌리기

수정 이력에는 다음 내용을 기록합니다.

- 수정 날짜와 시간
- 수정한 사용자
- 수정 전 정보
- 수정 후 정보
- 적용 플랫폼
- 성공·실패 상태
- 영구 변경 또는 임시 변경 여부

전체를 한꺼번에 되돌리는 것이 아니라 원하는 항목만 선택해 복구할 수 있습니다.

예시:

- 메뉴 가격만 이전 상태로 복구
- 영업시간만 이전 상태로 복구
- 휴무일만 이전 상태로 복구
- 공지사항만 이전 상태로 복구

### 5.4 사용자 권한 관리

역할별 권한을 구분합니다.

| 역할 | 권한 |
|---|---|
| 사장님 | 모든 정보 조회·수정·승인, 권한 관리 |
| 매니저 | 영업시간·휴무일·공지 수정, 가격 변경 요청 |
| 직원 | 정보 조회, 수정 요청 작성 |
| 아르바이트생 | 조회만 가능 |

가격 변경과 전체 플랫폼 업데이트는 사장님의 최종 승인이 필요하도록 설정합니다.

## 8. 플랫폼 어댑터 설계

플랫폼마다 연동 방식이 다르므로 공통 인터페이스를 만들고 플랫폼별 구현을 분리합니다.

```ts
interface PlatformAdapter {
  getCurrentInfo(storeId: string): Promise<PlatformStoreInfo>;
  transformChange(changeSet: ChangeSet): Promise<PlatformPayload>;
  pushChange(payload: PlatformPayload): Promise<SyncResult>;
  checkStatus(jobId: string): Promise<SyncStatus>;
  getEditUrl(storeId: string): string;
}
```

자동 수정이 불가능한 플랫폼은 `manualUpdateAdapter`를 사용합니다.

```ts
interface ManualUpdateResult {
  editUrl: string;
  copyText: string;
  fields: {
    label: string;
    value: string;
  }[];
}
```

## 9. 가격 계산 로직

가격 계산은 AI에게 맡기지 않고 일반 코드로 처리해야 합니다.

```ts
function calculatePlatformPrice(
  basePrice: number,
  platformDefaultDelta: number,
  categoryDelta?: number,
  menuDelta?: number
): number {
  const appliedDelta =
    menuDelta ??
    categoryDelta ??
    platformDefaultDelta;

  return basePrice + appliedDelta;
}
```

우선순위:

```text
메뉴 개별 가격 차이
→ 카테고리 가격 차이
→ 플랫폼 기본 가격 차이
```

잘못된 가격 입력을 막기 위해 다음 검증도 추가합니다.

- 가격은 0원보다 커야 함
- 설정 가능한 최대 가격 제한
- 이전 가격과 큰 차이가 나면 경고
- 적용 결과를 승인 화면에서 다시 확인

## 10. 임시 변경 처리

임시 변경은 예약 작업으로 처리합니다.

```ts
interface TemporaryChange {
  id: string;
  startAt: string;
  endAt: string;
  originalValue: unknown;
  temporaryValue: unknown;
  status: "scheduled" | "active" | "restored";
}
```

동작 순서:

1. 시작 시간이 되면 임시 정보 적용
2. 각 플랫폼에 변경 전송
3. 종료 시간이 되면 기존 정보 복구
4. 복구 결과 저장
5. 실패 시 사장님에게 알림

## 11. ChangeSet 중심 개발

한 번의 수정 요청을 `ChangeSet`으로 묶어 관리합니다.

```ts
interface ChangeSet {
  id: string;
  storeId: string;
  createdBy: string;
  changeType: "permanent" | "temporary";
  startAt?: string;
  endAt?: string;
  items: ChangeItem[];
  targetPlatforms: string[];
  status: "draft" | "approved" | "processing" | "completed" | "partial_failed";
}
```

수정 항목 예시:

```ts
interface ChangeItem {
  type: "business_hours" | "holiday" | "menu" | "price" | "notice";
  targetId?: string;
  beforeValue: unknown;
  afterValue: unknown;
}
```

이 구조를 사용하면 다음 기능을 구현하기 쉬워집니다.

- 미리보기
- 승인
- 플랫폼별 업데이트
- 수정 이력
- 부분 되돌리기
- 충돌 비교

## 12. AI가 담당할 부분과 일반 코드가 담당할 부분

### AI가 담당할 부분

- 사장님이 작성한 공지를 플랫폼별 문체로 변환
- 긴 수정 내용을 짧고 읽기 쉽게 정리
- 플랫폼별 차이를 사람이 이해하기 쉽게 설명
- 충돌 내용을 요약
- 복사해 붙여넣을 수정 문구 생성

### 일반 코드가 담당할 부분

- 가격 계산
- 권한 확인
- 날짜와 기간 계산
- 메뉴 노출 규칙
- 플랫폼별 상태 관리
- 승인 여부 확인
- 수정 이력 저장
- 자동 재시도
- 임시 변경 자동 복구

정확성이 필요한 가격, 권한, 날짜 로직은 AI의 자유로운 판단에 맡기지 않는 것이 중요합니다.

## 13. 4주 MVP 구현 범위

모든 기능을 한 번에 구현하기보다 핵심 흐름을 먼저 완성합니다.

### MVP 필수 기능

1. 매장 한 곳 등록
2. 플랫폼 3개를 가정한 연결 화면
3. 영업시간·휴무일·메뉴·가격 통합 편집
4. 카테고리별 가격 차이 설정
5. 메뉴별 개별 가격 예외
6. 플랫폼별 적용값 미리보기
7. 사장님 최종 승인
8. 플랫폼별 업데이트 시뮬레이션
9. 성공·실패 상태 표시
10. 실패 시 수정 사이트 링크와 복사 내용 제공

### MVP에서 간단하게 구현할 기능

- 실제 플랫폼 API 대신 플랫폼 어댑터를 가상 데이터로 구현
- 하루 한 번 검사는 버튼을 통한 수동 검사로 먼저 구현
- 임시 변경은 예약 데이터 저장과 화면 표시까지 구현
- 역할은 사장님과 직원 두 종류만 먼저 구현
- 수정 이력은 최근 이력 목록과 가격 부분 되돌리기부터 구현

### 향후 확장 기능

- 실제 플랫폼 API 연동
- 자동 검사 스케줄러
- 실제 반영 상태 재확인
- 모든 항목 부분 되돌리기
- 네 가지 이상 역할 관리
- 여러 지점 통합 관리
- 모바일 앱과 푸시 알림

## 15. 최종 확정 기능 요약

### 핵심 기능

1. 매장 정보를 한 번에 편집하고 플랫폼별 적용값을 생성합니다.
2. 승인된 정보를 플랫폼에 반영하고 결과와 실패 대응을 제공합니다.

### 확정한 정책

- 자동·수동 혼합 업데이트
- 플랫폼 및 카테고리별 가격 차이
- 메뉴별 가격 예외
- 카테고리별 메뉴 노출 플랫폼
- 메뉴별 노출 예외
- 영구 변경과 기간형 임시 변경
- 플랫폼별 미리보기와 최종 승인
- 실패한 플랫폼만 재시도
- 계속 실패하면 수정 사이트와 복사 내용 제공
- 역할별 권한 관리
- 항목별 부분 되돌리기
- 플랫폼 상태 단계별 표시
- 외부 수정 충돌 알림
- 가격·메뉴·영업정보별 묶음 알림
- 하루 한 번 자동 검사와 수동 검사
- MVP는 단일 매장
- 사장님이 최종 승인한 PlaceSync 정보가 기준
- 연결 만료 사전 알림과 재연결 버튼
