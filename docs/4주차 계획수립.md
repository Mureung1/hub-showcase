## Day 16 (월) — 전반적 개선/버그 수정

- [x] "아직 구현 못한 기능이 시각적으로 많이 보인다"는 지적을 구체적인 항목으로 목록화 — 코드 대조 결과 진짜 원인은 **레시피 썸네일 이미지**였음(아래 Day17 참고). 그 외 실제로 남아있는 시각적 공백은: 유통기한 임박 서버 푸시(클라이언트 `Notification`만 있음), KAMIS 미연동 잔여 71개 품목(정적 가격)
- [x] 위 목록을 backlog.md 우선순위에 맞춰 재배치 — 썸네일 버그는 P0(문서엔 완료로 기록됐는데 실제로 없었던 리그레션)로 분류해 바로 Day17에서 수정, 나머지는 기존 P1/P2 유지
- [x] **(추가 폴리시 패스, 사용자 요청으로 재검토)** 레시피 썸네일은 실제 요리와 무관한 스톡 사진이라 오히려 신뢰도를 깎는다고 판단해 최종적으로 도입 취소, 이모지 표시로 원복(`RecipeCard.jsx`, `product.md` §11 재정정)
- [x] 브라우저로 실제 화면을 훑다가 새로 발견한 버그 3건, 전부 수정 완료:
  - **냉장고 "라면 사리" 수량이 항상 "0"으로 표시** — `fresh` 카테고리 재료인데 시드/DB 데이터가 `processed` 방식(`qtyLabel`만)으로 잘못 들어가 있어 `enrichFridgeItem`이 합산할 `qtyAmount`를 못 찾음. 라이브 Supabase 행을 `PATCH /api/fridge/ramen`으로 정정 + `initialFridge.js`(backend/frontend) 시드도 동일하게 수정
  - **재료 마스터에 `kimchi`(김치)가 아예 없음** — `initialFridge.js`/`mealPrices.js`/레시피들엔 계속 쓰이는데 `ingredients.js`엔 등록이 안 돼 있어서, 부족 재료 목록에 "김치" 대신 영어 원문 "kimchi"가 그대로 노출되고 있었음. `ingredients.js`(backend/frontend)에 정식 엔트리 추가
  - **자취생 초간단 레시피 100개(`addStudentRecipes.mjs`, id 900001~900100) 전 재료가 "1단위"로 표시** — 스크립트가 전부 `amt: ''`로 비워둬서 `extractUnit('')`이 '단위'로 폴백. 58개 재료 id별 실제 계량 단위(1공기·1큰술·1/2모 등) 매핑 추가 후 스크립트 재실행(upsert라 안전)해 라이브 데이터까지 정정
  - (겸사겸사) 서버 시작 로그에 매번 찍히던 `dotenv` 패키지의 홍보성 랜덤 tip 문구(`vestauth.com` 등, 악성 아님 — 최신 dotenv가 기본으로 넣는 광고성 로그) 제거
- [x] **신규 기능: 유통기한 임박 서버 푸시 알림** — 문서에 계속 "알려진 한계"로 남아있던 진짜 미구현 기능을 구현. `web-push`(VAPID) 도입, 백엔드 `push.js`(구독 저장 + D-2 이하 재료 체크 + 발송, 하루 중복 발송 방지)와 `routes/push.js`(`GET /public-key`, `POST /subscribe`), `server.js`가 부팅 시 1회 + 1시간 간격으로 체크. 프론트는 `public/sw.js`(서비스워커) 신설, `ExpiryAlerts.jsx`의 "알림 켜기"가 실제 `pushManager.subscribe()` 후 구독 정보를 백엔드에 전송하도록 교체. `.env`에 VAPID 키 없으면 기능이 조용히 꺼지고 기존 클라이언트 확인 알림만 동작(폴백). 가짜 구독으로 발송 경로가 에러 없이 도는 것까지 확인, 실제 브라우저 알림 권한 승인 흐름은 이 세션의 Browser pane이 알림 권한을 기본 거부해서(자동화 환경 정책으로 추정) UI로는 끝까지 확인 못 함 — 실사용자 브라우저에서 재확인 필요
