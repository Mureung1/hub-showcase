# 답답

## 한 줄 소개
매번 맥락을 설명하지 않아도, 대학생이 자주 겪는 꺼내기 어려운 메시지 상황(답장·먼저 보내기)에서 몇 번의 선택만으로 상황과 관계에 맞는 보낼 말을 받을 수 있는 메시지 작성 도우미 서비스.

## 현재 단계
MVP 구현 단계 (2026-07-07 시작). 범위는 docs/MVP.md, 주차별 계획은 docs/PLAN.md를 따른다. 이 문서의 피드백 루프·예시 DB 누적 등 이후 단계 기능은 여전히 비전 기술이며 이번 단계에서 구현하지 않는다.

> **2026-07-08 개정**: 서비스 정의를 "답장 도우미"에서 "상황과 관계에 맞는 메시지 작성 도우미"로 확장 — 받은 메시지가 있으면 답장, 없으면 먼저 보내는 메시지를 생성. 시나리오 4개를 관계형(팀플·조모임 / 교수님·조교님 / 선배·동기 / 친구·연인)으로 재구성. 사용자 노출 문구는 "답장" 대신 "보낼 말"로 통일.
> **2026-07-08 2차 개정**: ① 메시지 목적 선택 추가(6종, 필수), ② 받은 메시지·상황 설명 중 1개 이상 필수, ③ 톤 공통 라벨(기본/더 부드럽게/더 분명하게 — 기본을 첫 번째로 제시), ④ 입력에 없는 사실 생성 금지 + 자리 표시자 허용, ⑤ 핵심 과업 = 후보 복사, 최소 계측 도입. 상세는 docs/MVP.md·docs/SPEC.md.

## 대상 사용자
- 대학생

## 해결하려는 문제 & 가치

### 문제
대학생은 일상에서 반복적으로 꺼내기 어려운 메시지 상황을 마주친다. 받은 메시지에 답할 때뿐 아니라, 먼저 말을 꺼내야 할 때가 오히려 더 어렵다.
- 팀플·조모임에서 무임승차 팀원에게 먼저 꺼낼 말
- 교수님·조교님께 보내는 과제 연장/결석 사유 메일
- 선배·동기 간 존댓말 수위 조절
- 친구·연인에게 꺼내기 어려운 말 (사과·부탁·마음 표현)
매번 무슨 말을 어떻게 써야 할지 고민하느라 시간과 감정 에너지를 쓴다.

### 기존 대안의 한계
ChatGPT 같은 일반 AI 챗봇으로도 보낼 메시지를 받을 수 있지만:
- 매번 상황 맥락(누구와의 대화인지, 어떤 일이 있었는지 등)을 처음부터 설명해야 한다.
- 메모리·커스텀 지시 기능으로 재설명을 일부 줄일 수 있으나, 그것만으로는 해결되지 않는 지점이 있다:
  - 챗봇이 생성한 메시지는 "실제로 그 상황에서 효과가 있었는지" 검증된 적이 없다.
  - 자유 대화형 입력은 상황을 글로 정리해서 설명하는 비용 자체가 크다.

### 가치
- **검증된 예시 기반**: 실제 그 상황을 겪어본 사람이 큐레이션하고, 효과 피드백으로 검증된 "좋은 메시지 예시"를 기반으로 보낼 말을 생성한다.
- **입력 비용 최소화**: 대학생 특유의 반복 시나리오를 카드 선택 + 톤 축 3단계 결과로 미리 구조화해, 맥락을 글로 설명할 필요 없이 몇 번의 선택만으로 원하는 보낼 말을 받는다.
- **비교·선택**: 메시지를 대신 써주는 데서 그치지 않고, 사용자가 꺼내기 어려운 말을 톤이 다른 여러 표현으로 제시해 직접 비교하고 선택하게 돕는다.

## 핵심 기능

| 기능 | 설명 |
|---|---|
| 시나리오 선택 | 대학생 특화 관계·상황 4가지를 카드 형태로 제시 |
| 목적 선택 | 부탁·사과·거절·질문·제안확인·기타 6종 중 1개 필수 선택 — 관계(시나리오) × 의도(목적)로 상황을 특정 (2026-07-08 2차 개정) |
| 톤 결과 | 톤을 미리 고르지 않는다. 후보 3개를 톤 3단계(기본 / 더 부드럽게 / 더 분명하게)로 생성해 **가장 무난한 "기본"을 먼저** 보여주고, 사용자가 결과 실물을 보고 고른다 |
| 상황 입력 | "받은 메시지 붙여넣기" + "상황 설명" 2필드, **1개 이상 필수**. 받은 메시지가 있으면 답장, 없으면 먼저 보내는 메시지를 생성 |
| 보낼 말 생성 | few-shot 프롬프트(시나리오+톤별 사전 큐레이션 예시) 기반, 1회 요청으로 톤 3단계 후보 생성. 입력에 없는 사실은 지어내지 않고 자리 표시자로 제공 |
| 결과 복사 | 생성된 보낼 말을 바로 복사해 사용 |
| 피드백 수집 | 보낸 말의 효과 여부를 평가해 예시 데이터베이스 개선에 반영 (이후 단계 — MVP 미구현) |

### 톤 3단계 — 공통 라벨 (2026-07-08 2차 개정. 확정본은 docs/SPEC.md 1장)

라벨은 전 시나리오 공통 **기본 / 더 부드럽게 / 더 분명하게**이며 기본을 첫 번째로 제시한다. 라벨은 같아도 "부드러움/분명함"의 구현은 관계마다 다르다 — 시나리오별 해석 지침:

| 시나리오 | 더 부드럽게 | 더 분명하게 |
|---|---|---|
| 팀플·조모임 | 상대 사정을 인정하며 완곡하게 | 요구·기한을 명확하게 |
| 교수님·조교님 | 격식을 갖춰 완곡하게 요청 | 간결하고 직접적으로 용건 전달 |
| 선배·동기 | 깍듯하고 조심스럽게 | 용건 중심으로 직접적으로 |
| 친구·연인 | 조심스럽게 | 적극적으로 마음 표현 |

## 사용자 흐름

1. 앱 진입
2. 시나리오 선택 (4개 카드 중 1개: 팀플·조모임 / 교수님·조교님 / 선배·동기 / 친구·연인)
3. 목적 선택 (부탁/사과/거절/질문/제안확인/기타 — 필수) + 받은 메시지 붙여넣기·상황 설명 중 1개 이상 입력 (받은 메시지가 있으면 답장, 없으면 먼저 보내는 메시지로 생성)
4. 생성 요청 ("보낼 말 3가지 만들기")
5. AI가 톤 3단계 후보 3개 제시 — 기본(가장 무난) / 더 부드럽게 / 더 분명하게 순
6. 마음에 드는 보낼 말 선택 → 복사 (**핵심 과업 완료 지점**). 마음에 안 들면 "다시 만들기"(리롤) 또는 상황 수정 후 재생성
7. (이후 단계 — MVP 미구현) 결과 평가 — "효과 있었어요" 피드백
8. (이후 단계 — MVP 미구현) 좋은 평가를 받은 예시가 데이터베이스에 누적 → 다음 생성에 반영

화면별 상태(로딩/실패/복사 폴백 등)는 docs/SCREENS.md 참고.

이후 단계 보강 후보 (시드에는 출처 태그 `source`로 구분):

## MVP
범위는 docs/MVP.md에서 정의 (In/Out 표가 구현 여부 판단의 단일 기준). 요약:
- In: 4개 시나리오, 목적 선택(필수), 톤 3단계 후보 생성(기본 먼저), 2필드 입력(1개 이상 필수), 복사(폴백 포함), 상태 처리, 시드 예시 24개, 최소 계측(generate/copy 이벤트)
- Out: 피드백 수집·예시 DB 누적, 로그인, 히스토리, 시나리오 커스텀, 결제

## 데이터 모델

**MVP는 서버 저장 데이터가 없다** (로그인·히스토리·피드백 모두 Out + 받은 메시지 비저장 원칙). 엔티티는 두 층으로 나뉜다:

- **MVP — 정적 데이터 (docs/SPEC.md에서 확정)**:
  - 시나리오(Scenario): id, 이름, 카드 문구, 톤 축 라벨 3단계 — 프론트 상수
  - 시드 예시(CuratedExample): scenarioId, situationNote, receivedMessage?, toneLevel, message, source — 프록시 상수(few-shot 재료)
- **이후 단계 — 저장 데이터 (스키마 보류)**:
  - 생성 요청/결과(GenerationLog): 프라이버시 기준(EDGE_CASES 1-3, 1-5) 확정 전에는 도입하지 않음
  - 피드백(Feedback): 피드백 2단계 분리 정책(EDGE_CASES 4-1) 기준으로 설계

### 프라이버시 고려
사용자가 입력하는 상황 세부사항과 대화 내용은 민감 정보다. 피드백 기반으로 예시를 데이터베이스에 누적할 때는 개인 식별 정보(이름, 학과, 구체적 사건 등) 제거 기준과 저장 범위 기준이 필요하다. 세부 기준은 보류.

## 성공 기준

**핵심 과업 정의 (2026-07-08 2차 개정)**: 생성된 후보 3개 중 하나를 **복사**하면 핵심 과업 완료. 최소 계측(SPEC 7장 — 내용 미포함 이벤트)으로 복사 완료율(copy/generate)을 측정한다.

**MVP 단계 — 출시 전 검수 합격선 (docs/SPEC.md 5장)**:
- 톤 3단계 블라인드 정렬 일치 90% 이상 (20세트 중 18)
- 후보의 80% 이상이 수정 없이~경미한 수정으로 전송 가능 (60개 중 48)
- 입력에 없는 사실(환각) 0건 + 자리 표시자 하이라이트 100% 동작

**이후 단계 (정량 지표 — 상세 로깅 도입 후)**:
- 생성된 보낼 말을 수정 없이(또는 소폭 수정만으로) 실제 전송한 비율
- 복사 완료율은 MVP부터 측정 (위 핵심 과업 정의)
- 재방문율 (같은 사용자가 다른 상황에서 다시 사용하는지)
- "효과 있었어요" 피드백 비율
