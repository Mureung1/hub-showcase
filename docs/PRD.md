# 답답

## 한 줄 소개
매번 맥락을 설명하지 않아도, 대학생이 자주 겪는 애매한 답장 상황에서 몇 번의 선택만으로 어울리는 답장을 받을 수 있는 답장 도우미 서비스.

## 현재 단계
아래 사용자 흐름·핵심 기능·데이터 모델 등은 서비스의 전체 비전을 기술한 것이며, 이번 단계에서 실제로 동작하도록 구현하지 않는다.

## 대상 사용자
- 대학생

## 해결하려는 문제 & 가치

### 문제
대학생은 일상에서 반복적으로 애매한 답장 상황을 마주친다.
- 조모임 무임승차자에게 보낼 말
- 교수님께 과제 연장/결석 사유 메일
- 선후배 간 존댓말 수위 조절
- 소개팅·과CC 등에서 보낼 말

매번 무슨 말을 어떻게 써야 할지 고민하느라 시간과 감정 에너지를 쓴다.

### 기존 대안의 한계
ChatGPT 같은 일반 AI 챗봇으로도 답장을 받을 수 있지만:
- 매번 상황 맥락(누구와의 대화인지, 어떤 일이 있었는지 등)을 처음부터 설명해야 한다.
- 메모리·커스텀 지시 기능으로 재설명을 일부 줄일 수 있으나, 그것만으로는 해결되지 않는 지점이 있다:
  - 챗봇이 생성한 답장은 "실제로 그 상황에서 효과가 있었는지" 검증된 적이 없다.
  - 자유 대화형 입력은 상황을 글로 정리해서 설명하는 비용 자체가 크다.

### 가치
- **검증된 예시 기반**: 실제 그 상황을 겪어본 사람이 큐레이션하고, 효과 피드백으로 검증된 "좋은 답장 예시"를 기반으로 답장을 생성한다.
- **입력 비용 최소화**: 대학생 특유의 반복 시나리오를 카드 + 톤 슬라이더로 미리 구조화해, 맥락을 글로 설명할 필요 없이 몇 번의 선택만으로 원하는 답장을 받는다.

## 핵심 기능

| 기능 | 설명 |
|---|---|
| 시나리오 선택 | 대학생 특화 상황 4가지를 카드 형태로 제시 |
| 톤 슬라이더 | 시나리오별로 다른 축을 가진 조절 UI (이산값 3~5단계) |
| 상황 입력 | 사용자가 세부 맥락을 최소한으로 입력 |
| 답장 생성 | few-shot 프롬프트(시나리오+톤별 사전 큐레이션 예시) 기반 AI 답장 후보 생성 |
| 결과 복사 | 생성된 답장을 바로 복사해 사용 |
| 피드백 수집 | 답장의 효과 여부를 평가해 예시 데이터베이스 개선에 반영 |

### 톤 슬라이더 축 후보 (확정 아님)
| 시나리오 | 축 후보 |
|---|---|
| 조모임 무임승차 | 부드럽게 ↔ 단호하게 |
| 교수님 메일 | 간결하게 ↔ 격식 갖춰서 |
| 선후배 존댓말 | 깍듯하게 ↔ 친근하게 |
| 소개팅·과CC | 조심스럽게 ↔ 적극적으로 |

## 사용자 흐름

1. 앱 진입
2. 시나리오 선택 (4개 카드 중 1개: 조모임 무임승차 / 교수님 메일 / 선후배 존댓말 / 소개팅·과CC)
3. 해당 시나리오 전용 톤 슬라이더 조작 (예: 조모임 → "부드럽게" ↔ "단호하게")
4. 상황 세부사항 간단 입력 (상대방과의 관계, 있었던 일 한두 줄)
5. 답장 생성 요청
6. AI가 답장 후보 여러 개 제시
7. 사용자가 마음에 드는 답장 선택 → 복사
8. (선택) 결과 평가 — "효과 있었어요" 피드백
9. 좋은 평가를 받은 예시가 데이터베이스에 누적 → 다음 생성에 반영

## 초기 예시 확보 (콜드스타트 대응)
> 확보 방식 확정은 보류. 후보:

- 팀이 시나리오·톤 조합별로 직접 작성 (예: 4개 시나리오 × 3~5톤 × 각 2~3개)
- 주변 대학생 지인 대상 설문/인터뷰로 "실제로 보냈고 효과 있었던 답장" 수집
- 대학생 커뮤니티(에브리타임 등)에서 공개적으로 공유된 사례 참고 (저작권·개인정보 주의)

서비스 초기에는 큐레이션 예시가 없으므로, 위 방식으로 최소한의 시드 데이터를 만든 뒤 피드백 루프(사용자 흐름 8~9단계)로 점진 개선한다.

## 화면 구성
> 보류 — 상세 와이어프레임/화면 목록 미정.

현재까지 확인된 흐름 기준으로 최소 다음 화면이 필요할 것으로 예상됨 (확정 아님):
- 시나리오 선택 화면 (4개 카드)
- 톤 슬라이더 + 상황 입력 화면
- 답장 후보 결과 화면 (복사, 피드백 포함)

## MVP
> 보류 — 정확한 범위 미정.

우선순위 후보 (확정 아님):
- 4개 시나리오 + 시나리오별 톤 슬라이더
- 최소 입력 필드 기반 답장 생성 (후보 1~3개)
- 결과 복사 기능

이후 단계로 미룰 후보:
- 피드백 수집 및 예시 데이터베이스 누적/반영 로직

## 기술 스택 & 아키텍처
- 프론트엔드: React (Vite + TypeScript로 세팅됨), 추가 UI 라이브러리 없이 순수 React
- 백엔드/AI 연동 방식: 보류
- 배포 환경: 보류

## 데이터 모델
> 보류 — 상세 스키마 미정.

필요할 것으로 예상되는 엔티티 (확정 아님):
- 시나리오(Scenario): 이름, 톤 슬라이더 축/단계
- 큐레이션 예시(CuratedExample): 시나리오, 톤, 예시 답장 텍스트
- 생성 요청/결과(GenerationLog): 입력 맥락, 생성된 답장 후보
- 피드백(Feedback): 선택된 답장, 효과 여부

### 프라이버시 고려
사용자가 입력하는 상황 세부사항과 대화 내용은 민감 정보다. 피드백 기반으로 예시를 데이터베이스에 누적할 때는 개인 식별 정보(이름, 학과, 구체적 사건 등) 제거 기준과 저장 범위 기준이 필요하다. 세부 기준은 보류.

## 성공 기준
> 목표 수치는 보류. 후보 지표:

- 생성된 답장을 수정 없이(또는 소폭 수정만으로) 실제 전송한 비율
- 답장 후보 복사율 (생성 요청 대비 복사 횟수)
- 재방문율 (같은 사용자가 다른 상황에서 다시 사용하는지)
- "효과 있었어요" 피드백 비율
