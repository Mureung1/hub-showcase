# 리뷰지기 — 리뷰 관리 AI 에이전트 기획서

> 소상공인을 위한 리뷰 자동 답글 · 분석 · 블랙컨슈머 대응 에이전트
>
> **[HTML·CSS 프로토타입 바로 보기](../prototype/index.html)**

---

## 1. 개요

### 1.1 문제 정의

- 소상공인(특히 배달 매장 사장님)은 매일 쏟아지는 리뷰에 일일이 답글을 달 시간이 부족하다.
- 리뷰는 매출에 직결되지만, 리뷰 데이터를 모아서 분석하고 개선점을 찾는 일은 사실상 불가능하다.
- 악성 리뷰·블랙컨슈머를 만났을 때 어떻게 대응해야 하는지(신고 절차, 법적 대응) 아는 사장님이 거의 없다.

### 1.2 목표

리뷰 답글 작성 → 리뷰 분석 → 악성 리뷰 대응까지, 리뷰 관리 전 과정을 대신해주는 AI 에이전트를 만든다.

### 1.3 타겟 사용자

리뷰 기능이 있는 플랫폼을 사용하는 40 ~ 60대 외식업 소상공인

## 2. 핵심 기능

### 2.1 리뷰 유형 분류

리뷰가 입력되면 유형·카테고리·분류 근거를 자동 판별한다.

- **입력**: 리뷰 본문, 별점, 주문 메뉴(선택), 유입 플랫폼, 작성 일자, 닉네임(선택)
- **출력**: 유형 1개 + 세부 카테고리(맛/양/배달/포장/서비스, 복수 가능) + 분류 근거 한 줄(리뷰 상세 화면에 표시)

| 유형 | 판정 기준 |
|---|---|
| 칭찬 | 긍정 경험 위주, 별도 요구사항 없음 |
| 불만 | 맛·양·배달·포장·서비스에 대한 구체적 부정 경험 |
| 문의 | 질문 포함(영업시간, 메뉴, 배달 범위, 원산지 등) |
| 악성 의심 | 욕설·비하, 협박(별점 테러·유포 예고), 환불·보상 강요, 허위 사실 정황, 동일인 반복 저격 중 **하나라도** 감지 |

**엣지 케이스 규칙**

| 상황 | 처리 |
|---|---|
| 복합 리뷰(칭찬+불만 혼재, 가장 흔한 케이스) | **불만**으로 분류하되 복합 플래그를 붙여 답글 구조를 "감사 → 사과 → 개선"으로 변경 (2.3) |
| 문의+불만 혼재 | 불만으로 분류, 답글에 문의 답변 포함 (2.3) |
| 별점과 본문 불일치(별 1개 + 칭찬 본문 등) | 본문 우선 판정 + 답글 상태를 "확인 필요"로 표시 |
| 분류 확신이 낮은 리뷰 | 유형을 확정하지 않고 "확인 필요" 상태로 두고 사장님이 유형을 직접 지정 |
| 악성 "의심" | 어디까지나 의심 단계. 확정은 위험도 분류(2.5)와 사장님 판단으로 |

**답글 상태 정의**: `초안 대기`(초안 생성됨, 사장님 미확인) → `확인 필요`(악성 의심·분류 애매 등 판단 필요) → `완료`(게시 후 완료 표시)

### 2.2 매장 프로필 (톤앤매너)

답글 생성과 문의 답변의 **유일한 정보 출처**. 매장 설정 화면에서 관리한다.

| 그룹 | 필드 | 용도 |
|---|---|---|
| 기본 정보 | 매장명, 업종, 대표 메뉴 | 답글 문맥 |
| 답글 톤 | 말투(존댓말 기본/친근함/간결함), 인사말, 맺음말, 이모지 사용 여부 | 초안 문체 결정 |
| 운영 정보 | 영업시간, 휴무일, 배달 범위, 주차, 원산지 등 | **문의 답변의 근거 데이터** |
| 이벤트 | 진행 중 이벤트 내용 + 기간 | 답글에 자연스럽게 반영, **기간 만료 시 자동 제외** |
| 금지 표현 | 사장님이 등록하는 금칙어 목록 | 초안에 포함 시 자동 재생성 (2.3) |

- 문의 답변은 **운영 정보에 등록된 항목만** 답한다. 등록되지 않은 질문은 "확인 후 안내드리겠습니다" 형태의 안전 문구로 생성한다.
- 설정 화면에서 선택한 톤이 반영된 **샘플 답글 미리보기**를 즉시 보여준다.

### 2.3 답글 초안 생성

| 유형 | 답글 구조 |
|---|---|
| 칭찬 | 감사 → 리뷰의 구체적 언급 반영 → 재방문 유도 |
| 불만 | 공감·사과 → 원인 설명(확인된 것만) → 개선 약속 |
| 복합(칭찬+불만) | 긍정 언급 감사 → 불만 사과 → 개선 약속 |
| 문의 | 답변(운영 정보 기반) → 감사 |
| 문의+불만 | 공감·사과 → 문의 답변(운영 정보 기반) → 개선 약속 |
| 악성 의심 | 초안을 만들지 않고 대응 매뉴얼로 연결 (2.5) |

**생성 규칙 (금칙 — 8장 리스크 표와 연동)**

1. 보상·환불 약속 금지 ("서비스 드리겠습니다" 류). 보상 언급은 사장님이 직접 수정으로만 추가 가능
2. 확인되지 않은 사실 단정 금지 (조리 상태, 배달 시간 원인 등)
3. 매장 프로필에 없는 이벤트·정보 언급 금지
4. 법적 판단·위협성 표현 금지
5. 사장님이 등록한 금지 표현 포함 시 자동 재생성

**동작 사양**

- 길이: 기본 100~200자 (톤 "짧게" 선택 시 80자 내외), 글자수 표시
- 톤 3종: `기본` / `더 정중하게` / `짧게` — 화면에서 칩으로 전환, 즉시 재생성
- "다시 생성" 무제한, 텍스트 직접 수정 가능
- **게시 방식**: "답글 복사하기" → 사장님이 플랫폼(배민 사장님 페이지 등)에 직접 붙여넣기 → "완료로 표시"로 상태 관리. 시스템이 대신 게시하지 않는다 (7.1)

### 2.4 리뷰 분석

**대시보드 조회형**

| 기능 | 사양 |
|---|---|
| 손님 반응 요약 | 긍정/부정/중립 비율 도넛 차트 |
| 별점 추이 | 주차별 평균 별점 라인 차트 |
| 카테고리별 언급 | 맛/양/배달/포장/서비스별 언급량 + 긍·부정 비율 막대 |
| 메뉴별 핵심 키워드 | 메뉴 단위 자주 언급되는 키워드 태그 |
| AI 인사이트 카드 | 직전 동기간 대비 변화가 임계값을 넘으면 생성, 최대 3개 노출 |

**AI 인사이트 생성 기준**

| 항목 | 기준 |
|---|---|
| 비교 대상 | 직전 동기간(주간 리포트면 지난 주, 월간이면 지난 달)의 같은 카테고리 |
| 변화 임계값 | 언급량 또는 부정 비율이 **1.5배 이상 증가**하거나 **1/1.5 이하로 감소**(직전의 약 67% 이하) |
| 최소 표본 | 두 기간 중 한쪽 이상에 해당 카테고리 언급이 **5건 이상**. 표본이 적어 생기는 노이즈 인사이트를 막는다 |
| 노출 개수 | 변화 폭이 큰 순으로 최대 3개 |

예: "포장 관련 칭찬이 1.8배 늘었어요", "심야 시간대 배달 지연 언급이 늘고 있어요"

- 기간: 주간 / 월간 / 직접 선택
- **콜드 스타트**: 누적 리뷰 10건 미만이면 리포트 대신 안내 + 진행 표시를 보여주고, 과거 리뷰 일괄 입력을 유도한다

### 2.5 블랙컨슈머 대응

**위험도 판정 기준과 위험도별 대응**

| 위험도 | 판정 기준 | 대응 |
|---|---|---|
| ① 단순 불만 | 감정적 표현은 있으나 실제 경험 기반, 별도 요구 없음 | **일반 불만 답글 흐름으로 복귀** (= 악성 의심 오탐) |
| ② 정당한 클레임 | 구체적 피해 사실 + 합리적 요구(환불·재배달 등) | 답글 흐름 복귀 + 클레임 처리 가이드 제공 |
| ③ 악성 | 욕설·인신공격, 협박(별점 테러·유포 예고), 과도한 보상 요구, 허위 사실 적시 정황, 반복 저격 | 대응 매뉴얼 4단계 진행 |

- **오탐 처리**: 사장님이 위험도를 직접 조정할 수 있고, ①·②로 조정하면 답글 초안 생성으로 자동 복귀한다
- 위험도가 ③이어도 **답글·신고 등 모든 실행은 사장님이 수행** — 시스템은 절대 자동 처리하지 않는다

**③ 악성 대응 매뉴얼 4단계**

1. **답글 작성 가이드**: 감정을 배제한 정중한 대응 예시문 제공 + 복사 버튼 (허위 사실에 대한 사실관계만 간결히)
2. **플랫폼 신고 절차**: 배민 셀프서비스 기준 단계별 체크리스트 (리뷰 신고 → 게시중단 요청)
3. **증거 수집 체크리스트**: 주문 내역 캡처, 리뷰 캡처, 배달 완료 기록, CCTV 등 항목별 체크 + 파일 첨부, 증거 정리 리포트 인쇄
4. **법적 대응 안내**: 일반적인 절차 정보만 제공. 화면에 **"일반적인 정보 안내이며 법률 자문이 아닙니다" 고지 필수** (8장 리스크 연동, 개별 사안 판단은 7.4에서 제외)

**사례 아카이빙**: 사건 단위 기록(리뷰 원문, 위험도, 수행 단계, 첨부 증거). 동일 닉네임 재발 시 알림. 수집·보관은 최소 원칙을 따르며 보관 기간과 파기 방법은 9장에 따른다.

### 2.6 계정과 매장

서비스 이용의 전제이자 데이터 격리의 기준이다.

| 항목 | 사양 |
|---|---|
| 회원가입 | 이메일 + 비밀번호. 비밀번호는 8자 이상. 가입 직후 ⑦ 매장 설정으로 이동해 최초 설정을 진행한다 |
| 로그인 | 이메일 + 비밀번호. 로그인 후 ① 홈으로 진입한다. 인증에 실패하면 실패로 안내할 뿐 계정을 만들지 않는다 |
| 비밀번호 재설정 | 가입 이메일로 재설정 링크를 보낸다 |
| 세션 | 로그인 상태는 브라우저에 유지되고, 로그아웃하면 종료한다. 로그아웃은 상단바에서 실행한다 |
| 매장 연결 | 계정 1개에 매장 1개를 연결한다. 여러 매장을 한 계정으로 운영하는 것은 제외한다 (7.6) |
| 데이터 격리 | 리뷰·답글·매장 프로필·사건 기록·증거 파일은 매장 소유권으로 격리한다. 다른 계정의 데이터는 조회도 수정도 할 수 없다 |
| 탈퇴 | 계정과 매장 데이터를 함께 파기한다 (9장) |

**규칙**

- 로그인하지 않은 상태에서 화면 ①~⑦에 접근하면 로그인 화면으로 돌린다.
- **계정 생성은 회원가입에서만 일어난다.** 로그인 시도는 어떤 경우에도 새 계정을 만들지 않는다. 로그인과 회원가입을 한 동작으로 합치면 오타 하나로 의도치 않은 빈 계정이 생기고, 사장님은 기존 매장 데이터가 사라진 것으로 오해하게 된다.
- 비밀번호는 평문으로 저장하지 않는다.
- 데이터 격리는 화면에서 거르는 것이 아니라 저장소 수준에서 강제한다. 화면 필터만으로는 계정 간 노출을 막을 수 없다.

## 3. 사용자 시나리오 (사장님 관점)

> 페르소나: "행복분식 강남점" 김사장님(52). 배민 리뷰 하루 5~15건, 영업 마감 후 10분 안에 리뷰를 처리하고 싶다.

### S1. 최초 설정 — 가입 직후 1회, 약 10분

| # | 사장님 행동 | 화면 | 시스템 동작 |
|---|---|---|---|
| 1 | 이메일·비밀번호로 회원가입 | ⑧ 로그인·회원가입 | 계정 생성, 매장 설정으로 이동 |
| 2 | 매장 정보·말투·인사말·운영 정보·금지 표현 입력 | ⑦ 매장 설정 | 프로필 저장, 선택한 톤의 샘플 답글 미리보기 |
| 3 | 배민에서 과거 리뷰를 복사해 한꺼번에 붙여넣기 | ④ 리뷰 입력 | 리뷰 단위 자동 분리 → 유형·카테고리 일괄 분류 |
| 4 | 홈에서 첫 현황 확인 | ① 홈 | 통계 카드 생성, 10건 이상이면 분석 리포트 활성화 |

### S2. 일상 사용 — 매일 마감 후, 핵심 루프

| # | 사장님 행동 | 화면 | 시스템 동작 |
|---|---|---|---|
| 1 | 접속해 오늘 현황 확인 ("답글 대기 5건, 악성 의심 1건") | ① 홈 | 통계 카드 + 처리 필요 리뷰 큐(악성 우선 정렬) |
| 2 | 배민 사장님 페이지에서 새 리뷰 복사 | (외부) 배민 | — |
| 3 | "한꺼번에 붙여넣기"에 붙여넣고 확인 | ④ 리뷰 입력 | 리뷰 분리 → 분류 → 결과 미리보기 |
| 4 | 리뷰함에서 "초안 대기" 필터로 미처리만 조회 | ② 리뷰함 | 상태·유형별 필터링 |
| 5 | 리뷰를 열어 초안 확인, 필요 시 수정·톤 변경·다시 생성 | ③ 리뷰 상세 | 초안 + 분류 근거 표시, 재생성 |
| 6 | "답글 복사하기" → 배민에 붙여넣어 게시 | ③ → (외부) 배민 | 클립보드 복사 + 붙여넣기 안내 문구 |
| 7 | 돌아와서 "완료로 표시" | ③ 리뷰 상세 | 상태 완료 처리, 대기 건수 차감 |
| 8 | 대기 0건 확인 후 종료 | ① 홈 | — |

## 4. 화면 구조 (UI)

### 4.1 정보 구조와 화면 이동

좌측 사이드바(로그인 후 모든 화면 공통, 상단바에 매장명·로그아웃 표시): **홈 · 리뷰함 · 리뷰 입력 · 분석 리포트 · 블랙컨슈머 대응 · 매장 설정**

⑧ 로그인·회원가입은 사이드바가 없는 단독 화면이며 사이드바 메뉴에 포함되지 않는다.

    HOME -->|AI 답글 확인| DETAIL[③ 리뷰 상세·답글]

    INBOX -->|리뷰 카드 선택| DETAIL

### 4.2 ① 홈 — 대시보드

> [프로토타입에서 홈 화면 보기](../prototype/index.html#home)

- **표시**: 통계 카드 4개(신규 리뷰/답글 대기/평균 별점/악성 의심-레드 강조), 손님 반응 추이 차트, AI 인사이트 카드, "지금 처리가 필요한 리뷰" 큐(악성 우선 정렬)
- **동작**: 리뷰 카드의 "AI 답글 확인" → ③ 리뷰 상세로 이동. 악성 의심 카드 → ⑥ 대응 센터로 이동. 로그인 후 가장 먼저 보이는 화면으로, S2 루프의 시작점과 종착점

### 4.3 ② 리뷰함 — 리뷰 목록

> [프로토타입에서 리뷰함 보기](../prototype/index.html#inbox)

- **표시**: 유형 필터 탭(전체/칭찬/불만/문의/악성 의심) + 답글 상태 드롭다운(초안 대기/확인 필요/완료), 리뷰 카드(플랫폼 칩·별점·닉네임·날짜·본문·주문 메뉴 태그·유형 배지·상태 칩), 악성 의심 카드는 레드 보더, 페이지네이션
- **동작**: 카드 클릭 → ③ 리뷰 상세. 리뷰 0건이면 빈 상태 + "리뷰 입력하러 가기" CTA

### 4.4 ③ 리뷰 상세 · 답글 작성 — 핵심 화면

> [프로토타입에서 리뷰 상세·답글 보기](../prototype/index.html#detail)

- **표시**: 좌측 원본 리뷰(플랫폼·별점·닉네임·메뉴·본문·유형 배지) + AI 분류 근거 한 줄, 우측 AI 답글 초안 에디터(톤 칩 3종, 수정 가능한 본문, 글자수, 다시 생성)
- **동작**: 톤 칩 전환·"다시 생성" → 초안 즉시 갱신. **"답글 복사하기"(1차 버튼)** → 클립보드 복사 + "배민 사장님 페이지에 붙여넣어 주세요" 안내 → "완료로 표시"로 상태 종결. 악성 의심 리뷰는 에디터 대신 경고 배너 + "대응 매뉴얼 보기" → ⑥으로 전환

### 4.5 ④ 리뷰 입력 — 수동 입력

> [프로토타입에서 리뷰 입력 보기](../prototype/index.html#input)

- **표시**: 탭 2개 — "한 건씩 입력"(유입 경로/작성 일자/별점/주문 메뉴/리뷰 내용) · "한꺼번에 붙여넣기"(대형 붙여넣기 영역 → 분리된 리뷰 목록 미리보기). 우측에 분류 결과 실시간 미리보기, 하단에 "과거 리뷰도 붙여넣으면 분석이 더 정확해져요" 안내
- **동작**: "입력하고 분류하기" → 분류 후 ② 리뷰함으로. 일괄 붙여넣기는 리뷰 단위 자동 분리 → 행별 유형 배지 확인 → 일괄 등록. **리뷰 경계 판단은 AI가 수행한다(6장).** 분리 결과는 등록 전에 미리보기로 확인·수정할 수 있다
- **구현 반영**: 반복 악성 고객 추적(2.5)을 위해 닉네임(선택) 입력 필드를 포함한다.

> [프로토타입에서 분석 리포트 보기](../prototype/index.html#report)

- **표시**: 기간 선택(주간/월간/직접 선택), 고객 반응 도넛, 별점 추이 라인, 카테고리별 언급 막대(긍·부정 분리), 메뉴별 핵심 키워드, AI 인사이트 카드
- **동작**: 기간 변경 시 전체 차트 갱신. 누적 10건 미만이면 리포트 대신 안내 + 진행 표시(콜드 스타트, 2.4)

### 4.7 ⑥ 블랙컨슈머 대응 센터

> [프로토타입에서 블랙컨슈머 대응 보기](../prototype/index.html#response)

- **표시**: 좌측 사건 리스트(위험도 필터: 전체/악성/정당한 클레임/단순 불만), 우측 사건 상세 — 고위험 감지 배너, 답글 작성 가이드(예시문+복사), 플랫폼 신고 절차 체크리스트, 증거 수집 체크리스트(첨부), 리포트 인쇄
- **동작**: 매뉴얼 4단계를 위에서 아래로 수행, 단계별 체크 저장. 위험도를 ①·②로 조정하면 ③ 리뷰 상세(일반 답글 흐름)로 복귀. 법적 안내 영역에는 "법률 자문 아님" 고지 상시 노출

### 4.8 ⑦ 매장 설정

> [프로토타입에서 매장 설정 보기](../prototype/index.html#settings)

- **구성**: 2.2 매장 프로필의 5개 그룹(기본 정보/답글 톤/운영 정보/이벤트/금지 표현)을 섹션으로 배치, 우측에 선택한 톤이 반영된 샘플 답글 미리보기 카드
- 저장 시 홈으로 돌아가며, 선택한 말투·인사말·이벤트가 반영된 샘플 답글을 같은 화면에서 확인한다.

### 4.9 ⑧ 로그인 · 회원가입

- **표시**: 서비스 로고와 한 줄 소개, 이메일·비밀번호 입력, 주 버튼 1개, 로그인 ↔ 회원가입 전환 링크, 비밀번호 재설정 링크. 사이드바와 상단바가 없는 단독 화면
- **모드 구분**: 로그인과 회원가입은 서로 다른 모드다. 지금 어느 모드인지 제목과 주 버튼 문구로 항상 드러낸다. 두 동작을 버튼 하나에 겹쳐 두지 않는다
- **동작**: 로그인 성공 → ① 홈. 가입 성공 → ⑦ 매장 설정(최초 설정 안내와 함께). 로그인하지 않은 상태로 다른 화면에 접근하면 이 화면으로 돌린다
- **로그인 실패 처리**: 가입되지 않은 이메일이거나 비밀번호가 틀리면 실패로 안내하고 로그인 모드에 머문다. **로그인 시도가 계정 생성으로 이어지지 않는다.** 가입이 필요하면 사장님이 회원가입 링크를 눌러 직접 이동한다
- **오류 표시**: 이메일 형식 오류, 비밀번호 길이 미달, 로그인 실패를 입력란 아래 문구로 안내한다. 로그인 실패 시 이메일과 비밀번호 중 무엇이 틀렸는지 구분해 알리지 않는다

### 4.10 디자인 시스템

**Traditional Premium Heritage** 단일 테마를 사용한다. 큰 본문, 명확한 상태 배지, 낮은 정보 밀도로 40~60대 사장님의 가독성을 우선하고, 외부 폰트와 CDN 없이 실행한다. 색상 토큰과 상태 표기 규칙은 `UI_GUIDE.md`에 있다.

### 4.11 프로토타입 검토 방법

- 시작 파일: **[`prototype/index.html`](../prototype/index.html)**
- 파일 구성: `index.html`에 화면 ①~⑦을 통합하고 `styles.css`에서 화면 전환과 반응형 레이아웃을 담당한다.
- 구현 범위: 공통 내비게이션, 리뷰 입력 → 리뷰함 → 답글 확인 → 완료, 악성 의심 → 대응 센터의 핵심 이동 흐름
- 기술 범위: 외부 라이브러리·프레임워크·JavaScript 없이 로컬 `HTML`과 `CSS`만 사용
- 시연 데이터: 행복분식 강남점의 가상 리뷰. AI 분석·데이터 저장·배민 게시는 구현하지 않고 화면 상태로 시연
- 권장 검토 순서: `prototype/index.html` → ④ 리뷰 입력 → ② 리뷰함 → ③ 리뷰 상세·답글 → ① 홈

## 5. 서비스 흐름 (시스템 관점)

```mermaid
flowchart TD
    L[로그인 · 매장 확인] --> A[리뷰 입력<br/>사장님이 직접 입력]
    A --> B{유형 분류}
    B -->|칭찬 · 불만 · 문의 · 복합| C[답글 초안 생성]
    B -->|악성 의심| D{위험도 분류}
    D -->|① 단순 불만 · ② 정당한 클레임<br/>= 오탐 복귀| C
    D -->|③ 악성| H[대응 매뉴얼<br/>답글 가이드 → 신고 → 증거 수집 → 법적 안내]
    C --> E[사장님 확인 · 수정]
    E --> F[답글 복사 → 사장님이 플랫폼에 직접 게시]
    H --> K[사례 아카이빙 · 재발 알림]
    A --> I[리뷰 분석 엔진]
    I --> J[리포트 · 인사이트<br/>10건 미만 시 콜드 스타트 안내]
```

1. **인증**: 사장님이 로그인하고, 이후 모든 데이터는 그 계정에 연결된 매장 범위로 제한된다 (2.6).
2. **입력**: 사장님이 리뷰를 직접 입력한다. 플랫폼에서 자동으로 가져오지 않는다 (7.1).
3. **분류**: 유형을 판별하고, 악성 의심이면 위험도를 추가 판별한다. 위험도 ①·②는 오탐으로 보고 일반 답글 흐름으로 복귀한다.
4. **대응**: 일반 리뷰는 답글 초안을 생성하고, ③ 악성은 대응 매뉴얼을 제시한다.
5. **게시**: 사장님이 초안을 복사해 플랫폼에 직접 게시하고 완료로 표시한다. **시스템이 대신 게시하는 경로는 없다** (7.1).
6. **분석**: 쌓인 리뷰를 분석해 리포트와 인사이트를 제공한다.

이 제품의 경계는 **입력과 게시 양쪽 끝이 사람 손**이라는 점이다. 리뷰를 가져오는 것도 답글을 올리는 것도 사장님이 하고, 시스템은 그 사이의 분류·작성·분석·대응 안내를 맡는다.

## 6. AI 실행 방식

### 6.1 실행 경로

AI 처리는 **외부 AI API 호출**로 수행한다. 로컬 모델 운영은 다루지 않는다 (7.2).

- API 키와 자격증명은 **서버 측에만** 둔다. 브라우저 번들에 넣지 않는다.
- 공급자는 교체 가능해야 한다. 특정 API에 코드가 묶이지 않도록 호출부를 공급자 중립 인터페이스로 두고, 테스트는 실제 호출 없이 대체 구현으로 돌린다.
- 리뷰 본문이 외부로 나가므로 전송 항목은 처리에 필요한 범위로 제한한다 (8장).

### 6.2 AI가 판정하는 것과 규칙이 판정하는 것

AI 출력이 제품 정책을 우회할 수 없도록, 안전에 직결되는 판정은 AI와 분리된 규칙이 담당한다.

| 처리 | AI가 하는 일 | 규칙이 하는 일 |
|---|---|---|
| 리뷰 유형 분류 (2.1) | 유형·세부 카테고리·분류 근거 판정 | 확신이 낮으면 "확인 필요"로 전환 |
| 답글 초안 생성 (2.3) | 매장 톤을 반영한 문장 생성 | 금칙 표현 검사, 매장 프로필에 없는 정보 차단, 보상 약속 차단 |
| 문의 답변 (2.2) | 등록된 운영 정보를 문장으로 구성 | 등록되지 않은 항목이면 안전 문구로 대체 |
| 위험도 판정 (2.5) | ①·②·③ 판정과 감지 근거 제시 | 신고·게시·법적 판단은 자동 실행하지 않음 |
| 일괄 붙여넣기 분리 (4.5) | 리뷰 경계 판단 | 등록 전 사장님 확인 단계 강제 |
| 인사이트 생성 (2.4) | 변화를 사장님이 읽을 문장으로 정리 | 1.5배 임계값·최소 표본 5건 계산 |

- 이벤트 기간 만료 제외(2.2), 콜드 스타트 10건 기준(2.4)도 AI가 아니라 규칙이 판정한다.
- 규칙 판정은 AI 없이 단독으로 검증할 수 있어야 한다.

## 7. 제외 기능

만드는 것만큼 **만들지 않는 것**이 이 제품의 경계를 결정한다. 아래 항목은 요청이 들어와도 바로 착수하지 않고, 먼저 이 문서를 고쳐 합의한 뒤에 다룬다. 만드는 범위는 2장에 있다.

### 7.1 플랫폼 연동

| 제외 항목 | 이유 |
|---|---|
| 배달의민족·쿠팡이츠·요기요·네이버·구글 등 리뷰 자동 수집 | 국내 배달 플랫폼은 공식 리뷰 API가 없어 스크래핑에 의존해야 한다. 약관 위반 소지와 계정 제재 위험을 매장 계정이 그대로 떠안는다 |
| 자동 답글 게시 | 같은 연동이 전제다. 게다가 잘못 나간 답글은 사장님이 손쓰기 전에 손님에게 노출된다 |
| 답글 자동화 수준 설정(수동 승인·조건부 자동·완전 자동) | 자동 게시 경로가 없으므로 설정 자체가 성립하지 않는다 |
| 플랫폼 계정 자격증명 보관 | 연동을 하지 않으므로 사장님의 플랫폼 아이디·비밀번호를 받지도, 저장하지도 않는다 |
| 플랫폼별 연동 어댑터 | 위 항목이 모두 빠지므로 채널별 연동 계층도 두지 않는다 |

리뷰는 사장님이 직접 입력하고(4.5), 답글은 복사해 사장님이 직접 게시한다(2.3).

### 7.2 AI 실행

| 제외 항목 | 이유 |
|---|---|
| 로컬 모델 연결·운영 | AI 처리는 외부 AI API로만 수행한다(6.1). 로컬 모델 배포·튜닝·GPU 운영은 다루지 않는다 |
| 사용자별 모델 학습·미세조정 | 매장 톤은 학습이 아니라 매장 프로필(2.2)로 맞춘다 |

### 7.3 알림과 테마

| 제외 항목 | 이유 |
|---|---|
| 정기 리포트 발송(주간·월간 요약 푸시) | 분석은 사장님이 필요할 때 화면에서 조회한다(2.4) |
| 챗봇 알림(카카오톡·텔레그램 등 외부 메시징) | 외부 메시징 채널 연동이 필요하다 |
| 매장 장르에 따른 색상 테마 최적화 | 테마는 4.10 한 가지로 고정한다 |

### 7.4 법률·신고 자동화

| 제외 항목 | 이유 |
|---|---|
| 개별 사안의 법률 판단·자문 | 변호사법 저촉 소지가 있다. 일반적인 절차 정보 안내까지만 한다(2.5) |
| 자동 신고 접수 | 신고는 사장님이 플랫폼에서 직접 한다. 시스템은 절차 체크리스트만 제공한다 |
| 자동 보상·환불 제안 | 보상 판단은 사장님 몫이다. 답글 초안에도 넣지 않는다(2.3) |

### 7.5 데이터 확장

| 제외 항목 | 이유 |
|---|---|
| 매출·POS 데이터 연동 분석 | 이 제품이 다루는 데이터는 리뷰다 |
| 경쟁 매장 리뷰 분석·벤치마킹 | 타 매장 데이터 수집이 필요해 7.1과 같은 문제에 걸린다 |
| 리뷰 작성자 신원·실명·연락처 조회 | 개인정보 최소 수집 원칙에 어긋난다. 재발 추적은 닉네임까지만 한다(2.5) |

### 7.6 계정과 클라이언트

| 제외 항목 | 이유 |
|---|---|
| 한 계정에 여러 매장 연결 | 계정 1개에 매장 1개다(2.6) |
| 직원 계정·권한 분리 | 사장님 한 사람이 쓰는 것을 전제한다 |
| 모바일 네이티브 앱 | 웹 대시보드로 제공하고 반응형으로 모바일을 지원한다(4.10) |
| 다국어 지원 | 한국어 전용이다 |

## 8. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 오답글 게시(브랜드 이미지 손상) | 모든 답글은 사장님이 확인·수정한 뒤 직접 게시한다. 시스템이 대신 게시하지 않는다(7.1). 보상 약속·미확인 사실 등 금칙 표현은 규칙 단계에서 차단(2.3) |
| AI 환각(매장에 없는 정보·이벤트 언급) | 답글의 정보 출처를 매장 프로필로 한정(2.2), 프로필 밖 정보는 규칙 단계에서 차단(6.2) |
| 악성 리뷰 오탐(정당한 불만을 악성으로 분류) | 위험도 3단계 분류 + 오탐 시 일반 답글 흐름으로 복귀(2.5) + 최종 판단은 사장님이 수행 |
| 법적 대응 안내의 변호사법 저촉 소지 | 일반적인 절차·정보 안내로 한정 + 화면에 "법률 자문 아님" 고지 상시 노출, 개별 사안 판단은 제외(7.4)하고 필요하면 외부 전문가 연결로 분리 |
| 리뷰지기 계정 탈취 | 비밀번호는 해시로만 저장, 매장 소유권 기반 접근 제어(2.6), 비밀번호 재설정은 가입 이메일로만, 로그인 실패 사유를 구분해 노출하지 않음 |
| 고객 개인정보 처리(리뷰 데이터 저장, 반복 악성 고객 추적) | 개인정보보호법 검토, 수집·보관 최소화, 개인정보 처리방침 수립, 보관 기간과 파기 방법은 9장. 작성자 신원 조회는 제외(7.5) |
| 외부 AI API로의 리뷰 데이터 전송 | 전송 항목을 처리에 필요한 범위로 제한, 공급자의 데이터 보관·학습 이용 정책을 도입 전에 확인 |
| 사장님의 입력 부담(리뷰를 직접 옮겨 적어야 함) | 일괄 붙여넣기와 AI 리뷰 분리로 건당 입력 비용을 줄인다(4.5). 자동 수집으로 해결하지 않는 것은 7.1의 판단이다 |

플랫폼 스크래핑 약관 위반, 매장 계정 제재, 플랫폼 자격증명 유출 리스크는 해당 기능을 제외해(7.1) 발생 경로 자체를 없앴다.

## 9. 개인정보 보관과 파기

### 9.1 원칙

- 수집은 서비스 제공에 필요한 최소 범위로 한정한다. 리뷰 작성자 닉네임은 선택 입력이다.
- 보관 기간이 지난 데이터는 자동 파기한다.
- 사장님은 자신의 매장 데이터를 언제든 직접 삭제할 수 있다.

### 9.2 보관 기간

| 데이터 | 보관 기간 |
|---|---|
| 리뷰·답글 | 계정 유지 기간. 탈퇴 후 30일 내 파기 |
| 블랙컨슈머 사건 기록·증거 파일 | 사건 종결 후 1년 |
| 닉네임(재발 추적용) | 사건 기록과 동일 |
| 매장 프로필·계정 정보 | 탈퇴 시 즉시 파기 |

### 9.3 삭제 방법

- **개별 삭제**: 리뷰·사건·증거 파일을 화면에서 개별 삭제할 수 있다. 삭제한 데이터는 복구되지 않으며, 삭제 전에 확인 단계를 둔다.
- **일괄 파기**: 탈퇴하면 계정과 매장 데이터를 함께 파기한다.
- **자동 파기**: 9.2의 보관 기간이 지난 데이터는 별도 요청 없이 파기한다.
- 증거 파일은 매장 소유권으로 격리 저장하며(2.6), 파기 시 원본과 함께 제거한다.
