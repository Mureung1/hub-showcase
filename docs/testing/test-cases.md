# PtoP 테스트 케이스

## 테스트 목표

PtoP의 핵심 흐름인 `GitHub 로그인 → 작업실 → Repository 분석 → Poppy 회고 → 통합 결과`가 중단 없이 동작하고, Repository 근거와 사용자 경험이 구분되어 전달되는지 검증한다.

## 1. 인증과 작업실 진입

| ID | 상황 | 기대 결과 |
| --- | --- | --- |
| TC-01 | 비로그인 사용자가 작업실에 접근 | GitHub 로그인이 필요하다는 안내를 보여준다. |
| TC-02 | GitHub 로그인 성공 | 사용자의 작업실에 진입한다. |
| TC-03 | 인증 실패 또는 취소 | 랜딩에 머물고 실패 원인을 안내한다. |
| TC-04 | 작업실 최초 로딩 | canvas, 기본 캐릭터, 새 분석 컴퓨터가 표시된다. |
| TC-05 | 게임 에셋 로딩 실패 | 빈 canvas 대신 오류와 재시도 안내를 표시한다. |

## 2. 작업실 이동과 상호작용

| ID | 상황 | 입력 | 기대 결과 |
| --- | --- | --- | --- |
| TC-06 | 캐릭터 이동 | 방향키 또는 WASD | 캐릭터가 입력 방향으로 이동한다. |
| TC-07 | 충돌 대상 접근 | 벽 또는 책상 방향 이동 | 캐릭터가 충돌 대상을 통과하지 않는다. |
| TC-08 | 컴퓨터 접근 | 활성 반경 안으로 이동 | `E 새 Repository 분석` 안내가 표시된다. |
| TC-09 | 컴퓨터에서 멀어짐 | 활성 반경 밖으로 이동 | 상호작용 안내가 사라진다. |
| TC-10 | 새 분석 컴퓨터 사용 | 활성 반경에서 `E` | Repository 입력 모달이 열린다. |
| TC-11 | 모달 사용 | 입력창에서 방향키 입력 | 게임 캐릭터가 움직이지 않는다. |
| TC-12 | 모달 닫기 | `Escape` 또는 닫기 버튼 | 모달이 닫히고 canvas로 focus와 입력이 복원된다. |
| TC-13 | 모바일 작업실 | 720px 이하 viewport | 게임 대신 새 분석 버튼을 사용할 수 있다. |

## 3. Repository 입력과 분석

| ID | 상황 | 입력 | 기대 결과 |
| --- | --- | --- | --- |
| TC-14 | 정상 URL | `https://github.com/user/project` | 분석 요청을 시작한다. |
| TC-15 | 빈 URL | 빈 문자열 | URL 입력 안내를 표시한다. |
| TC-16 | GitHub가 아닌 URL | `https://example.com/project` | 올바른 Repository 형식을 안내한다. |
| TC-17 | 사용자 GitHub ID 입력 | 로그인 사용자 ID | 해당 사용자의 활동 근거를 우선 분석한다. |
| TC-18 | GitHub rate limit | API 403/429 | 제한 원인과 재시도 시점을 안내하고 임의 결과를 만들지 않는다. |
| TC-19 | 비공개 또는 없는 Repository | API 404 | 권한 또는 주소 확인 안내를 표시한다. |
| TC-20 | 분석 성공 | 정상 GitHub/API 응답 | 결과를 보관하고 회고 완료 전 자동 이동하지 않는다. |

## 4. Poppy 회고

| ID | 상황 | 기대 결과 |
| --- | --- |
| TC-21 | 회고 시작 | 한 번에 질문 하나만 표시한다. |
| TC-22 | 짧은 답변 저장 | Repository 분석 ID에 연결해 Supabase에 저장한다. |
| TC-23 | 질문 건너뛰기 | 답변 없이 다음 질문으로 이동할 수 있다. |
| TC-24 | 이전 답변 수정 | 수정한 내용이 local draft와 서버에 반영된다. |
| TC-25 | 분석이 회고보다 먼저 완료 | 작성 화면을 유지하고 `결과 확인하기`를 활성화한다. |
| TC-26 | 새로 고침 또는 재진입 | Repository별 저장된 회고를 복원한다. |

## 5. 통합 분석 결과

| ID | 상황 | 기대 결과 |
| --- | --- |
| TC-27 | 결과 확인 | Repository 근거와 저장된 회고를 함께 반영한다. |
| TC-28 | 기술적 도전 후보 | 근거, 사용자 진술, AI 해석을 구분해 표시한다. |
| TC-29 | 근거 부족 | 확정하지 않고 `확인 필요` 상태를 표시한다. |
| TC-30 | AI가 놓친 경험 | 사용자가 `내 경험 추가`에서 짧게 보완할 수 있다. |
| TC-31 | 작업실 복귀 | 분석 결과 화면에서 항상 작업실로 돌아갈 수 있다. |
| TC-32 | 완료 분석 저장 | 작업실에 Repository 컴퓨터가 추가되고 다시 열 수 있다. |

## 6. 자동 검증

```bash
npm run test
npm run typecheck
npm run build
```

브라우저 검증 항목:

- canvas가 비어 있지 않은지 확인한다.
- 방향키/WASD 이동과 충돌을 확인한다.
- `E` 상호작용과 Repository 모달을 확인한다.
- 모달 focus, `Escape`, 입력 복원을 확인한다.
- 데스크톱과 모바일에서 겹침과 잘림을 확인한다.
- `/hub/` base path에서 정적 파일과 lazy chunk가 로드되는지 확인한다.
