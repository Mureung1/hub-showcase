# PtoP 테스트 케이스

## 테스트 목표

PtoP의 핵심 기능인 프로젝트 분석과 회고/포트폴리오 초안 생성 흐름이 사용자의 기대대로 동작하는지 검증한다.

## 1. 프로젝트 입력 테스트

| ID | 상황 | 입력 | 기대 결과 |
| --- | --- | --- | --- |
| TC-01 | 정상 GitHub Repository URL 입력 | `https://github.com/user/project` | 분석 시작 버튼을 누를 수 있다. |
| TC-02 | 빈 URL 입력 | 빈 문자열 | URL을 입력하라는 안내가 표시된다. |
| TC-03 | GitHub가 아닌 URL 입력 | `https://example.com/project` | GitHub Repository URL 형식이 아니라는 안내가 표시된다. |
| TC-04 | 잘못된 GitHub URL 입력 | `https://github.com/user` | Repository 주소 형식이 아니라는 안내가 표시된다. |
| TC-05 | 프로젝트 폴더 업로드 | mock 파일 목록 | 파일 목록을 읽고 분석 준비 상태가 된다. |

## 2. Repository 분석 테스트

| ID | 상황 | 입력 데이터 | 기대 결과 |
| --- | --- | --- | --- |
| TC-06 | README가 있는 프로젝트 | README에 목적/기능/기술 스택 포함 | 프로젝트 목적과 핵심 기능이 추출된다. |
| TC-07 | README가 없는 프로젝트 | 폴더 구조와 package.json만 존재 | 폴더 구조와 설정 파일 기준으로 분석 결과가 생성된다. |
| TC-08 | package.json이 있는 프로젝트 | dependencies에 React, Vite 포함 | 기술 스택에 React와 Vite가 표시된다. |
| TC-09 | 주요 코드 파일이 있는 프로젝트 | `src/pages`, `src/components`, `src/api` 존재 | 화면, 컴포넌트, API 구조가 요약된다. |
| TC-10 | commit log가 부족한 프로젝트 | commit 1개만 존재 | 역할 추론이 제한적이라는 안내가 표시된다. |

## 3. 회고/포트폴리오 초안 생성 테스트

| ID | 상황 | 입력 데이터 | 기대 결과 |
| --- | --- | --- | --- |
| TC-11 | 분석 결과가 정상 생성됨 | 프로젝트 목적, 기술 스택, 핵심 기능 | 회고 초안이 생성된다. |
| TC-12 | 내가 한 일 생성 | 핵심 기능 목록 | 역할 후보 문장이 생성된다. |
| TC-13 | 어려웠던 점 생성 | 오류 처리, API 연결 등 기술 키워드 | 문제 상황 초안이 생성된다. |
| TC-14 | 해결 과정 생성 | commit 또는 코드 구조 정보 | 해결 과정 문장이 생성된다. |
| TC-15 | 배운 점 생성 | 기술 스택과 구현 내용 | 배운 점 문장이 생성된다. |

## 4. Markdown 결과 테스트

| ID | 상황 | 입력 데이터 | 기대 결과 |
| --- | --- | --- | --- |
| TC-16 | Markdown 미리보기 | 생성된 회고 초안 | 제목, 목록, 문단이 Markdown 형식으로 보인다. |
| TC-17 | Markdown 복사 | 복사 버튼 클릭 | 클립보드에 Markdown 결과가 복사된다. |
| TC-18 | 사용자가 초안 수정 | 텍스트 수정 | 수정된 내용이 Markdown 결과에 반영된다. |

## 5. 예외 상황 테스트

| ID | 상황 | 기대 결과 |
| --- | --- | --- |
| TC-19 | 분석 도중 실패 | 오류 안내와 다시 시도 버튼을 보여준다. |
| TC-20 | 분석 결과가 부족함 | 부족한 정보와 사용자가 직접 보완할 항목을 안내한다. |
| TC-21 | 긴 Repository 분석 | 분석 중 상태가 유지되고 사용자가 진행 중임을 알 수 있다. |
