# 테스트 가이드

Vitest + Testing Library 기반 컴포넌트 테스트 환경에 대한 설정, 실행법, 트러블슈팅을 정리한 문서입니다. (실제 추가된 테스트 목록은 [테스트-코드-모음.md](./테스트-코드-모음.md) 참고)

## 개요

React 컴포넌트 단위 테스트 환경을 Vitest + Testing Library로 구축. `Card` 컴포넌트를 대상으로 첫 테스트 작성 및 통과 확인.

## 설치한 패키지

```
npm install -D vitest @testing-library/react @testing-library/jest-dom jsdom @vitejs/plugin-react
```

- `vitest`: 테스트 러너 (Vite 기반이라 별도 설정 거의 불필요)
- `@testing-library/react`: React 컴포넌트를 렌더링해서 테스트
- `@testing-library/jest-dom`: `toBeInTheDocument()`, `toHaveClass()` 같은 매처 확장
- `jsdom`: 브라우저 DOM을 흉내내는 테스트 환경

## 설정 변경

**vite.config.ts**

```ts
import { defineConfig } from 'vitest/config'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [react(), tailwindcss()],
  test: {
    globals: true,
    environment: 'jsdom',
    setupFiles: './src/setupTests.ts',
  },
})
```

- `defineConfig`를 `vite`가 아닌 `vitest/config`에서 가져와야 `test` 필드 타입 인식됨
- `globals: true`: `describe/it/expect`를 전역으로 사용 가능하게 함 (jest-dom이 전역 `expect`를 요구해서 필요)

**src/setupTests.ts**

```ts
import '@testing-library/jest-dom'
```

**package.json**

```json
"scripts": {
  "test": "vitest"
}
```

## 테스트 파일 작성 규칙

- 위치: 테스트할 파일과 같은 폴더에 co-location (예: `Card.tsx` 옆에 `Card.test.tsx`)
- 이름: `파일명.test.tsx` (JSX를 렌더링하는 경우) / `파일명.test.ts` (순수 로직만 테스트하는 경우)
- 기본 틀:

```tsx
import { describe, it, expect } from 'vitest'
import { render, screen } from '@testing-library/react'
import MyComponent from './MyComponent'

describe('MyComponent', () => {
  it('설명', () => {
    render(<MyComponent />)
    expect(screen.getByText('...')).toBeInTheDocument()
  })
})
```

## 실행 방법

| 명령어 | 용도 |
|---|---|
| `npx vitest run` | 한 번만 실행하고 종료 (결과 확인용) |
| `npm test` | watch 모드, 파일 저장할 때마다 자동 재실행 |
| `npx vitest run 경로/파일명.test.tsx` | 특정 파일만 실행 |

> Windows PowerShell에서 `npx`가 실행 정책 오류를 내면 아래 [트러블슈팅](#트러블슈팅) 참고.

## 결과 읽는 법

```
✓ src/components/Card.test.tsx (2 tests) 27ms
   ✓ Card (2)
     ✓ renders children 23ms
     ✓ applies custom className alongside default styles 3ms

 Test Files  1 passed (1)
      Tests  2 passed (2)
```

- `✓`: 통과, `✕`: 실패 (실패 시 기대값/실제값 차이가 상세히 출력됨)
- `Test Files`: 테스트 파일 개수 기준 통과율
- `Tests`: 개별 `it()` 케이스 기준 통과율

## 트러블슈팅

### `expect is not defined`

jest-dom이 전역 `expect`를 요구하는데 vitest 설정에 `globals: true`가 없어서 발생. → `test.globals: true` 추가로 해결.

### PowerShell 실행 정책 오류

```
npx : 이 시스템에서 스크립트를 실행할 수 없으므로 ... npx.ps1 파일을 로드할 수 없습니다.
```

Windows PowerShell 기본 보안 정책이 `.ps1` 스크립트 실행을 막아서 발생 (코드 문제 아님).

- 즉시 해결: `npx.cmd vitest run` 처럼 `.cmd` 명시
- 영구 해결: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (사용자 범위, 로컬 스크립트만 허용)

## 빌드 영향 확인

- `npm run build` 정상 작동 확인 — 설정 변경이 프로덕션 빌드에 영향 없음
- 테스트 코드는 어디서도 import되지 않아 배포 번들(`dist/`)에 포함되지 않음 확인

## 앞으로 테스트 작성 시 주의사항

- **3D/캔버스 컴포넌트(three, 3dmol, smiles-drawer 사용)**: jsdom은 WebGL을 지원하지 않아 `Structure3DViewer` 같은 컴포넌트는 그대로 테스트 불가 → mock 처리 필요
- **Supabase/Gemini API 연동 컴포넌트(`AuthStatus` 등)**: 테스트 시 실제 네트워크 호출 방지를 위해 mock 필요
- 테스트 파일도 `tsconfig.app.json`의 `include: ["src"]`에 포함되어 `tsc -b` 타입 체크 대상이 됨 → 테스트 코드 타입 오류가 빌드를 막을 수 있음
