# 5분 프로젝트 소개 영상 — 대본 초안

> 인쇄용 아님 — PR 제출용 5분 영상 녹화 시 참고할 대본. `docs/diagrams/presentation-final.html`(슬라이드 6장)과 짝을 이룬다. 슬라이드 부분은 그 파일의 문구를 그대로 말로 풀었고, 동작 시연 구간은 슬라이드가 없어서 화면을 직접 보여주며 말할 포인트만 적었다. 각 구간 옆 괄호는 목표 시간(대략)이고, 전부 합치면 5분 안쪽이다.

## 1. 표지 (~10초)

"안녕하세요, N001 강민구입니다. 지금부터 제가 만든 REFIT(리핏), 판단 없이 루틴을 재편성하는 AI 운동 코치 서비스를 소개하겠습니다."

## 2. 서비스 설명 (~40초)

"저는 통증이나 시간 부족으로 계획한 운동을 못 할 때, 오늘 뭘 해야 할지 판단하는 데 시간을 쓰거나 판단을 미루고 그냥 스킵하는 경우가 많았습니다. 그래서 이 서비스를 구현하였습니다. 핵심기능으로 통증이 생기면 아픈 부위를 고르는 것만으로 그 부위를 쓰는 운동을 걸러내고, 같은 타겟 부위 안에서 대체 운동을 추천합니다. 그리고 시간이 없어서 운동을 스킵하면, 이번 주 빈 휴식일이 있는지 확인해서 자동으로 재배치하거나, 없으면 기록만 남깁니다. 부위 필터링이나 인접 세션 중복 금지 같은 하드 제약은 코드가 결정론적으로 검증하고, LLM(엘엘엠)은 그 안에서 대체 운동 선택과 근거 문구 생성만 맡습니다."

## 3. 동작 시연 (슬라이드 없음, 화면 전환 — 60~90초)

이제 실제 서비스 화면을 보여드리겠습니다.

- "먼저 온보딩 화면입니다. 주당 운동 가능 일수를 입력하면, 그에 맞는 분할 프리셋을 추천해줍니다." (온보딩 화면 보여주기)
- "온보딩이 끝나면 오늘의 루틴 화면이 바로 뜹니다. 오늘 타겟 부위와 예정된 운동이 여기 보입니다." (오늘의 루틴 화면 보여주기)
- "통증이 있을 때는 이 버튼을 눌러서 부위를 선택합니다. 예를 들어 무릎을 선택하면, 무릎을 쓰는 운동은 제외되고 같은 타겟 부위의 대체 후보가 뜹니다. 추천 배지가 붙은 게 LLM(엘엘엠)이 고른 대체 운동이고, 다른 후보로 직접 바꿀 수도 있습니다." (통증 보고 화면 실제로 클릭해서 보여주기)
- "세션을 스킵하면, 이번 주 빈 휴식일로 자동 재배치되거나, 자리가 없으면 스킵으로만 기록됩니다." (여유 있으면 스킵 결과 화면도 보여주기, 시간 없으면 생략)

## 4. 기술적 특징 — 아키텍처 (~25초)

"구조는 단순한 화면-서버-DB 3단입니다. 화면은 React(리액트)와 Vite(비트), 서버는 Express(익스프레스), DB는 Supabase(수파베이스) PostgreSQL(포스트그레스)이고 Prisma(프리즈마)로 연결했습니다. 화면과 서버는 JSON(제이슨)으로, 서버와 DB는 Prisma로 통신합니다."

## 5. 기술적 특징 — 기술 스택 (~20초)

"기술 스택은 계층별로 명확히 나뉩니다. 화면 쪽엔 React(리액트), Vite(비트), React Router(리액트 라우터), Tailwind CSS(테일윈드 씨에스에스). 서버 쪽엔 Express(익스프레스)와 Prisma(프리즈마). DB는 PostgreSQL(포스트그레스). 그리고 품질과 배포 쪽엔 Vitest(바이테스트), Playwright(플레이라이트), GitHub Actions(깃허브 액션스), Vercel(버셀), Render(렌더)를 썼습니다."

## 6. Agent 활용방식 — 일하는 순서 (~45초)

"이 프로젝트를 AI Agent와 만들 때 지킨 순서가 있습니다. 첫째, 문제 정의는 항상 제가 먼저 합니다. 둘째, 코드보다 설계서가 먼저입니다 — 완료기준과 장단점 그리고 한계점과 다른 대안 방법이 담긴 설계서를 먼저 받아 검토한 뒤에 구현을 시작합니다. 셋째, 여러 선택지가 있는 판단은 AI가 정하지 않습니다. 예를 들어 라이브러리나 데이터 출처처럼 선택지가 여러개인 결정은 근거만 받고 제가 직접 고릅니다. 넷째, 구현 후엔 직접 눈으로 확인합니다 — lint(린트)와 테스트는 기본이고, 화면 캡처나 API(에이피아이) 직접 호출로 검증합니다. 다섯째, 커밋은 제가 직접 실행합니다 — 파일과 개념 단위로 나눈 메시지 초안만 받아서 터미널에서 직접 커밋합니다."

## 7. 마무리 (~20초)

"이 방식은 느리지만, 설명할 수 있는 결과물을 남깁니다. 판단을 매번 저한테 되묻게 해서 속도는 느리지만, 'AI가 알아서 결정한 것'이 아니라 '제가 결정하고 AI가 구현한 것'이 남아서, 이 프로젝트의 모든 선택을 제 말로 설명할 수 있습니다. 감사합니다."

## 시간 참고

슬라이드 구간만 합치면 대략 2분 40초, 동작 시연(60~90초)을 더하면 총 4~4분 반 정도로 5분 안에 들어온다. 실제로 소리 내어 읽어보고 자기 말로 다듬는 걸 권장한다 — 앞서 만든 부스 리허설 대본(`demo-day-script.md`)과 마찬가지로, 그대로 외우기보다 자기 언어로 바꿔서 자연스럽게 말하는 게 목적이다.
