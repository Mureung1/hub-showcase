## 2. 자막 작성 규칙

음성이 없으므로 **읽을 시간 확보가 전부**다.

- 한 줄 **최대 30자**, **최대 2줄** (30자를 넘으면 한 줄이 화면 밖으로 밀린다)
- 한 자막 **최소 노출 2.5초**. 2줄이면 **3.5초 이상**
- 자막 사이 간격 최소 0.1초 (붙으면 편집기에서 겹침 경고가 난다)
- **화면에 이미 크게 쓰인 문구를 자막으로 반복하지 않는다** — 화면이 말하지 않는 것만 자막으로
- 숫자·영문 고유명사는 그대로(`storedCount`, `INTJ`, `503`)

## 3. 녹화 전 체크리스트

**워밍업 (필수, 녹화 5분 전)**

```bash
curl -m 90 https://hub-backend-kymx.onrender.com/api/health && curl -sI https://hub-theta-brown.vercel.app | head -1
```

Render 무료 티어는 15분 미사용 시 슬립하고, 2026-07-28 실측 콜드스타트는 **15.4초**다. 워밍업하지 않으면 그 15초가 그대로 영상에 찍힌다. 응답의 `storedCount` **시작값을 적어둔다** — C 블록에서 "늘었다"를 보여주려면 시작값을 알아야 한다.

**브라우저**

- 시크릿 창, 창 크기 **1280×800**, 확대 **100%**
- 북마크바 숨김(`⇧⌘B`), 확장 프로그램 아이콘 정리
- `/api/health` 탭을 **미리 열어둔다**(C 블록용)
- localStorage가 빈 상태에서 시작 — 랜딩에 `이전 결과 이어보기` 버튼이 **안 떠야** 한다

**macOS**

- 방해금지 모드 ON (알림 배너가 찍히면 재촬영)
- Dock 자동 숨김
- `⇧⌘5` → 옵션에서 **마우스 클릭 표시 ON**

**절대 화면에 넣지 않는 것**

- Render 대시보드 **Environment 탭** (Supabase `service_role` 키가 노출된다) — Render는 **Logs 탭만** 사용
- Supabase 대시보드의 API 키 영역
- `.env` 파일 내용, 터미널의 환경변수 출력

## 5. 녹화 방식 두 가지 — 절차 비교

### 방식 A — 직접 조작하며 녹화 (기본 추천)

사람이 큐시트를 보며 클릭하고, 화면 기록을 켜둔다.

1. **큐시트를 두 번째 화면에 띄운다.** 노트북 한 대뿐이면 §1 표를 종이로 인쇄하거나 아이패드·휴대폰에 띄운다. **같은 화면에 띄우면 안 된다** — 녹화에 그대로 찍힌다
2. §3 체크리스트를 위에서부터 전부 실행(워밍업 → 브라우저 → macOS)
3. `⇧⌘5` → **선택 부분 기록** 으로 브라우저 창만 잡는다(전체 화면을 잡으면 Dock·메뉴바가 들어간다) → 옵션에서 **마우스 클릭 표시 ON**, 마이크 **없음**
4. 녹화 시작 → 3초 정지(편집에서 앞부분을 자르기 위한 여유) → A 블록부터 진행
5. **실수하면 멈추지 말고 3초 쉬었다가 그 블록만 다시 한다.** 편집에서 잘라내면 된다. 처음부터 다시 찍는 게 제일 손해다
6. 마지막 블록 후 3초 정지 → `⇧⌘5` 정지 → `.mov` 저장

**장점**: 커서 움직임이 자연스럽고, 화면이 느리게 뜨면 사람이 알아서 기다린다. 중간에 판단이 필요한 상황(예상 못 한 로딩)에 대응된다.
**단점**: 구간 길이가 대본과 어긋나서 자막 타이밍을 손으로 맞춰야 한다.

### 방식 B — 자동 클릭 진행, 사람은 녹화만 (타이밍 정확)

내가 CDP(Chrome DevTools Protocol)로 Chrome을 대본 타이밍에 맞춰 자동 클릭하고, 사용자는 `⇧⌘5`만 켜둔다.

1. 나는 스크래치패드에 진행 스크립트를 만든다 — 각 클릭 사이 대기시간이 §1 큐시트의 초와 **정확히 일치**한다
2. 사용자가 Chrome을 `--remote-debugging-port`로 띄운다(내가 명령을 준다). 개인 프로필이 아닌 **별도 임시 프로필**로 띄워서 북마크·확장·로그인 상태가 안 찍히게 한다
3. 사용자가 `⇧⌘5` 녹화 시작 → 나에게 "시작"이라고 말한다
4. 내가 스크립트를 실행하면 화면이 대본대로 저절로 진행된다. 사용자는 지켜보기만 한다
5. 끝나면 사용자가 녹화 정지

**장점**: `demo.srt`를 **거의 손대지 않고** 얹을 수 있다. 재촬영해도 타이밍이 똑같다. 실수가 없다.
**단점**: **마우스 커서가 움직이지 않는다** — CDP는 이벤트를 주입하므로 클릭이 "저절로 일어나는" 것처럼 보인다. 시청자가 조작을 따라가기 어려울 수 있다. (완화: 스크립트에서 `Input.dispatchMouseEvent`로 `mouseMoved`를 먼저 보내 커서를 이동시킬 수 있지만, 사람 손처럼 부드럽진 않다.)

### 어느 쪽을 고를까

**A를 기본으로 하되, 자막 얹기가 너무 번거로우면 B로 다시 찍는다.** 이 영상은 5분 안에 흐름을 보여주는 게 목적이지 조작 시연이 목적이 아니라서, B의 "커서가 안 움직인다"는 단점은 생각보다 크지 않다. 다만 A로 한 번 찍어 보면 각 구간의 실제 소요를 알 수 있어서, B로 다시 찍든 자막을 맞추든 그 데이터가 쓰인다.

| **ffmpeg** | `brew install ffmpeg` | 길이·해상도 확인, 용량 압축, SRT 하드섭 번인을 **명령 한 줄로** 처리. 설치해두면 내가 최종 mp4의 길이가 5분 미만인지 직접 검증할 수 있다 |
| Screen Studio (유료) | screen.studio | 커서를 자동으로 부드럽게 하고 클릭 지점을 자동 줌. 데모 영상 품질이 눈에 띄게 올라간다. 다만 이번 마감에는 과투자 |
| OBS Studio (무료) | obsproject.com | 씬 전환·다중 소스가 필요할 때. 이번 대본은 브라우저 하나라 불필요 |

`ffmpeg`을 설치하면 쓸 수 있는 것:

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 demo.mp4   # 길이(초) 확인
ffmpeg -i raw.mov -vf "subtitles=demo.srt" -c:a copy demo.mp4          # 자막 번인
```

> 설치는 사용자가 직접 판단한다. 없어도 CapCut만으로 제출 가능하다.

## 6. 편집·내보내기

1. QuickTime Player(또는 `⇧⌘5`)로 녹화 → `.mov`
2. CapCut에서 `.mov` 열기 → 자막 → 로컬 자막 가져오기 → [`subtitles/demo.srt`](./subtitles/demo.srt)
3. 녹화 실제 타이밍에 맞춰 자막 위치 조정(대본은 계획값이라 몇 초씩 밀린다)
4. **총 길이가 5:00 미만인지 확인** ← 제출 요구사항
5. 1080p mp4로 내보내기

> 이 맥에는 `ffmpeg`이 없어서 자막 번인 자동화 대신 CapCut 경로를 쓴다. 설치돼 있는 도구: CapCut · iMovie · QuickTime Player.

업로드와 `showcase/showcase.json`의 `demoVideoUrl` 추가는 **영상 확정 후 별도로** 한다. 스키마상 `demoVideoUrl`은 `^$|^https://` 패턴이라 로컬 파일 경로는 넣을 수 없다.
