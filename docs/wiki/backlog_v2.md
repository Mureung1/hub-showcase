# 개발 Task 백로그 v2 (세이프게이트 — 사내 LLM 보안 게이트웨이)

> ⚠️ [기획서_v2.md](기획서_v2.md) 기준 초안이다. 주제 전환이 확정되지 않았으므로 [backlog.md](backlog.md)(탑히어)는 그대로 두고 별도 문서로 관리한다.

## 백로그란?

- **정의**: 제품을 완성하기 위해 앞으로 해야 할 작업(기능·문서·QA 등)을 우선순위 순으로 쌓아둔 목록. "지금 당장 할 일"과 "나중에 할 일"을 한 곳에서 구분해두는 저장소다.
- **어떻게 생겼나**: [기획서_v2.md](기획서_v2.md) 4번의 3주 MVP 로드맵에 맞춰 `Task / 우선순위 / 영역 / 목표 주차 / 상태`만 있는 단순한 표로 관리한다.
- **어떻게 관리하나**: 매주 시작 전 우선순위를 다시 확인하고, 끝난 Task는 지우지 않고 상태만 `Done`으로 바꿔 기록을 남긴다. 개발 중 새로 발견된 작업(버그, 빠진 케이스 등)은 그때그때 표에 추가한다.

## 우선순위 기준

기획서_v2 4번의 우선순위 표(필수/중요/있으면 좋음)를 그대로 P0/P1/P2에 대응시킨다.

| 우선순위 | 의미 |
|---|---|
| P0 | 없으면 데모 시나리오가 성립하지 않는 필수 기능 (정규식 탐지, 게이트웨이 프록시, 전체 파이프라인 연결) |
| P1 | MVP 완성도를 위한 것 (NER, 로컬 LLM 위험분석, 최소 로깅) |
| P2 | 여유 있으면 하는 것 (정책 엔진 고도화, 대시보드 UI, 향후 확장) |

## 주차별 계획

### 1주차 — 학습 + 게이트웨이 뼈대
LLM API 사용법, 분류 프롬프트 작성법, PII 정규식, Ollama, 프록시/미들웨어 패턴을 학습하면서 요청을 그대로 통과시키는 최소 프록시와 `LLMProvider` 어댑터 인터페이스를 만든다. 아직 탐지 로직은 붙이지 않는다.

### 2주차 — 핵심 탐지 기능
정규식 탐지·마스킹을 완성하고, 한국어 NER 모델 후보를 조사·선정해 파이프라인에 연동한다. Ollama 로컬 LLM에 위험도 분석 프롬프트를 붙인다. [기획서_v2.md](기획서_v2.md)에서 가장 리스크가 크다고 짚은 구간이므로, 1주차가 끝나는 시점에 NER 후보 모델을 미리 로컬에서 돌려본다.

### 3주차 — 통합 + 데모
탐지 결과를 종합하는 DLP 정책 엔진을 붙이고, 요청 → 탐지 → 마스킹/차단 → LLM 호출 → 응답의 전체 파이프라인을 연결한다. 민감정보 시나리오 테스트 케이스를 작성하고 데모·발표자료를 준비한다.
