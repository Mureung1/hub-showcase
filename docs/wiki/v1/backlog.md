# 개발 Task 백로그

## 백로그란?

- **정의**: 제품을 완성하기 위해 앞으로 해야 할 작업(기능·문서·QA 등)을 우선순위 순으로 쌓아둔 목록. "지금 당장 할 일"과 "나중에 할 일"을 한 곳에서 구분해두는 저장소다.
- **어떻게 생겼나**: 스크럼의 Product Backlog처럼 스토리포인트·에픽까지 정교하게 나누지 않고, 이 프로젝트 규모(4주, 소수 인원)에 맞춰 `Task / 우선순위 / 영역 / 목표 주차 / 상태`만 있는 단순한 표로 관리한다.
- **어떻게 관리하나**: 매주 시작 전 우선순위를 다시 확인하고, 끝난 Task는 지우지 않고 상태만 `Done`으로 바꿔 기록을 남긴다. 개발 중 새로 발견된 작업(버그, 빠진 케이스 등)은 그때그때 표에 추가한다.

## 우선순위 기준

| 우선순위 | 의미 |
|---|---|
| P0 | 없으면 서비스가 성립하지 않는 MVP 필수 기능 |
| P1 | MVP엔 필요하지만 완성도를 위한 것 |
| P2 | 여유 있으면 하는 것 (향후 확장, 기획서 3.6 참고) |

## 주차별 계획

### 1주차 — 기획 & 환경 구성 (완료)
기획서·화면구조·API 설계·디자인 시스템 문서 작성, React/Express 개발 환경 세팅(`CLAUDE.md`), 프로토타입 제작.

### 2주차 — 백엔드 기초 + 프론트 상태 1~2
공공데이터 수집·행정동 원점수 배치 파이프라인과, 학교 검색부터 조건 입력까지의 화면을 완성한다. 다음 주 점수화 엔진 개발의 전제 조건이라 먼저 끝낸다.

### 3주차 — 핵심 기능 (점수화 엔진 + 지도 시각화)
가중합 점수 API와 카카오 지도 위 히트맵·TOP5 마커를 붙여 서비스의 핵심 시나리오(3~4단계)를 동작시킨다. 이 프로젝트에서 가장 리스크가 큰 구간이므로 3주차 전체를 확보한다.

### 4주차 — 상세 드로어 + 통합 + QA + 발표 준비
상세 드로어, 외부 매물 연결, 전체 플로우 통합 테스트, 버그 픽스, 발표 자료 준비로 마무리한다.
