# TEST_PLAN

**이 문서의 역할**: 제품을 무엇으로 확인하는가 — 인수 기준, 검증 절차, 테스트 계층. 기능 사양은 `PRD.md`, 하네스 실행 게이트는 `HARNESS/gates.md`에 있다. 여기서 그것들을 다시 쓰지 않는다.

## 목적

테스트는 "기능이 존재하는가"보다 "사장님이 PRD의 핵심 루프를 막힘없이 수행할 수 있는가"를 기준으로 한다.

현재 저장소는 정적 프로토타입이므로 화면 이동과 사용자 관점 검증을 중심으로 한다. 실제 제품 구현 이후에는 단위·통합·E2E 테스트를 추가한다.

참고: `HARNESS/tests/` 소스와 `run.py` 진입점은 현재 md 워크트리에 없다. 이 문서의 하네스 관련 명령은 하네스 코드가 있는 로컬 실행 브랜치 기준이다.

## 인수 기준

다음이 가능해야 완료로 본다.

- 이메일 계정으로 가입·로그인할 수 있고, 로그인하지 않으면 다른 화면에 접근할 수 없다.
- 계정이 다르면 서로의 리뷰·답글·사건 기록이 보이지 않는다.
- 리뷰를 한 건 또는 여러 건 입력할 수 있다.
- 리뷰가 칭찬, 불만, 문의, 악성 의심으로 분류된다.
- 분류 근거가 리뷰 상세 화면에 표시된다.
- 일반 리뷰는 답글 초안을 확인, 수정, 복사, 완료 처리할 수 있다.
- 악성 의심 리뷰는 답글 초안 대신 대응 센터로 이동한다.
- 분석 리포트는 콜드 스타트 상태와 리포트 상태를 구분한다.
- 매장 설정의 톤·운영 정보·금지 표현이 답글 생성 결과에 반영된다.

## 현재 프로토타입 수동 검증

### 공통

- `prototype/index.html`을 브라우저에서 연다.
- 사이드바 메뉴 6개가 모두 이동되는지 확인한다.
- 모바일 폭에서 카드와 메뉴가 깨지지 않는지 확인한다.
- 인쇄 시 대응 센터와 리포트에서 불필요한 내비게이션이 빠지는지 확인한다.

### S1 최초 설정

1. `#settings`로 이동한다.
2. 기본 정보, 답글 말투, 운영 정보, 이벤트, 금지 표현 섹션이 보이는지 확인한다.
3. 답글 미리보기 카드가 보이는지 확인한다.
4. 답글 자동화 수준 설정이 화면에 없는지 확인한다(제외 기능). 현재 프로토타입에는 "Phase 2 예정" 카드가 남아 있어 제거 대상이다.

### S2 일상 사용 루프

1. `#home`에서 답글 대기와 처리 필요 리뷰를 확인한다.
2. `#input`에서 한 건 입력 화면과 일괄 붙여넣기 화면을 확인한다.
3. `#inbox`에서 유형·상태 필터와 리뷰 카드를 확인한다.
4. `#detail`에서 원본 리뷰, 분류 근거, 답글 초안, 톤 칩, 복사 버튼을 확인한다.
5. "게시 완료로 표시"가 홈으로 돌아가는지 확인한다.

### S3 악성 리뷰 대응

1. `#home` 또는 `#inbox`에서 악성 의심 리뷰를 찾는다.
2. `#response`로 이동한다.
3. 위험도 배너, 감지 근거, 4단계 매뉴얼이 보이는지 확인한다.
4. 증거 수집 체크리스트와 법률 자문 아님 고지가 보이는지 확인한다.
5. 일반 답글로 재분류하는 복귀 버튼이 있는지 확인한다.

### S4 주간 리뷰

1. `#report`로 이동한다.
2. 기간 필터, 손님 반응, 별점 추이, 카테고리 언급, 메뉴별 키워드가 보이는지 확인한다.
3. 인사이트 카드가 행동 가능한 문장으로 표현되는지 확인한다.

텍스트와 구조가 존재해도 실제 글자 크기, 색 대비, 모바일 배치, 클릭 후 체감 흐름은 브라우저에서 별도로 확인해야 한다.

## 현재 프로토타입 자동 회귀 검증

`HARNESS/tests/test_prototype.py`는 외부 라이브러리 없이 HTML과 CSS를 읽어 다음 계약을 확인한다.

| 검증 영역 | 확인 내용 |
|---|---|
| 화면과 링크 | 필수 화면 ID 존재, 중복 ID 없음, 내부 fragment 링크 대상 존재 |
| 로컬 실행 | 외부 URL 자산 없이 로컬 `styles.css`만 사용 |
| 일상 리뷰 루프 | 한 건·일괄 입력, 분류 근거, 답글 복사, 직접 게시 안내, 완료 표시 |
| 악성 리뷰 대응 | 대응 4단계, 일반 답글 재분류, 법률 자문 아님 고지, 자동 신고·게시 금지 |
| 매장 설정 | 프로필 항목, 답글 미리보기 |
| 제외 기능 경계 | 자동 게시·답글 자동화 수준이 화면에 나타나지 않음 |
| 접근성·레이아웃 기본값 | 본문 바로가기, 주 메뉴 이름, `:target` 화면 전환, 반응형 breakpoint, 인쇄 CSS |

프로토타입 계약 테스트만 실행하려면 다음 명령을 사용한다.

```bash
python -B -m unittest HARNESS.tests.test_prototype -v
```

## 실제 제품 구현 후 추가할 테스트

테스트 러너는 Vitest, DB·인증·Edge Functions가 필요한 테스트는 로컬 Supabase(`supabase start`)와 `LLM_PROVIDER=fake` 모드를 사용한다.

| 계층 | 테스트 대상 | 도구 |
|---|---|---|
| 단위 테스트 | 분류 엣지 케이스 규칙, 금칙 정책, 위험도 규칙, 인사이트 감지, 콜드 스타트 판단 — 순수 TS 모듈 | Vitest (LLM·DB 없이 실행) |
| 컴포넌트·UI 테스트 | 화면 이동, 필터링, 입력 검증, 상태 표시 | Vitest + Testing Library |
| 통합 테스트 | 리뷰 입력 → 분류 → 답글 → 완료, S1~S4, 계정 2개로 RLS 매장 격리 | Vitest + 로컬 Supabase + fake LLM |
| 프롬프트·골든 테스트 | 보상 약속 금지, 미확인 사실 금지, 법적 자문 금지 | `tests/golden/` 골든 사례 |
| 회귀 테스트 | 악성 의심 리뷰에 답글 초안이 생성되지 않는지 확인 | 통합 테스트에 포함 |

## 테스트 게이트

- PRD 7장이 제외한 기능은 테스트 통과 조건으로 넣지 않는다.
- 자동 게시, 자동 신고, 법률 자문 문구가 들어가면 실패로 본다.
- 사용자가 실행해야 할 외부 플랫폼 작업을 시스템이 대신 수행하는 것처럼 보이면 실패로 본다.
- 로그인 시도가 계정을 생성하면 실패로 본다.

## 하네스 검증

저장소 루트에서 다음을 실행한다.

```bash
python HARNESS/run.py validate
python -B -m unittest discover -s HARNESS/tests -v
```

하네스 회귀 테스트는 위 프로토타입 계약과 함께, `HARNESS/gates.md`의 게이트가 실제로 실행을 차단하는지 확인한다 — 계약·preflight·capability·실행 범위·검증 독립성·checkpoint 게이트가 그 대상이다. 게이트 내용은 `gates.md`가 단일 기준이므로 여기에 다시 적지 않는다.

`validate`가 통과해도 제품 개발이나 배포가 자동으로 시작되지는 않는다. 기본 설정은 Worker·adapter 명령이 비어 있고 network·외부 부작용·프로덕션 capability가 모두 꺼져 있다.
