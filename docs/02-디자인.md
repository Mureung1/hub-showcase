# 디자인 시스템 (Toss 스타일)

Toss 디자인 시스템 컨벤션을 적용한 규칙 모음. `/toss` 스킬(`.claude/commands/toss.md`)이 UI 코드를
작성하기 전에 참조하는 실제 스펙 문서이므로, 색상·간격·반경·폰트 값과 컴포넌트별 상태 규칙은
근사치 없이 정확한 수치로 유지한다.

> **모든 컴포넌트/화면 공통 원칙**: 아래 "상태 설계 체크리스트"(Default/Loading/Empty/Error/Disabled/
> Focus·Pressed)를 빠짐없이 확인한다. 컴포넌트별 섹션에서는 이 원칙을 반복하지 않고, 그 컴포넌트만의
> 예외·구체값만 적는다.

---

## 전체 원칙

### 문구 톤

- **존댓말 `~해요` 체.** 부드럽고 담백하게 (명령형 `하세요`보다 `~할까요?`, `~했어요`).
- 짧게. 한 문장에 하나의 정보만.
- 전문 용어보다 쉬운 말 ("본인인증" → "본인 확인").
- 숫자·금액은 천 단위 콤마, 단위는 붙여서 (`3,200,000원`).

| 상황 | Do | Don't |
|---|---|---|
| 완료 토스트 | "링크를 복사했어요" | "복사가 완료되었습니다" |
| 확인 다이얼로그 | "송금을 취소할까요?" | "정말 취소하시겠습니까?" |
| 에러 | "올바른 이메일 형식이 아니에요" | "유효하지 않은 입력값입니다" |

### Do / Don't (전체 공통)

**Do**
- 색·글자·간격은 토큰으로만 참조한다.
- **화면당 Primary 행동은 하나.**
- 로딩·빈 상태·에러 상태를 항상 함께 디자인한다.
- 터치 타깃 최소 **44×44px**.

**Don't**
- HEX·px 하드코딩 금지.
- 강조색 2개 이상 혼용 금지.
- 그라데이션 배경·과한 그림자·불필요한 아이콘/숫자(데이터 슬롭) 금지.
- Toast로 사용자 결정을 요구하지 않기 (→ Dialog/BottomSheet).

### 상태 설계 체크리스트

컴포넌트/화면을 만들 때 아래 상태를 빠짐없이 확인한다.

- [ ] 기본 (Default)
- [ ] 로딩 (Loading / Skeleton)
- [ ] 빈 상태 (Empty)
- [ ] 에러 (Error)
- [ ] 비활성 (Disabled)
- [ ] 포커스/눌림 (Focus / Pressed)
- [ ] 접근성 — 더 큰 텍스트, 대비, 44px 타깃

### 접근성

- 본문 텍스트와 배경 대비 최소 **4.5:1** (`grey.500` 이상 권장).
- "더 큰 텍스트" 설정에 맞춰 폰트가 커지도록 상대 단위/토큰 사용.
- 색만으로 정보를 전달하지 않기 (색 + 아이콘/텍스트 병행).

## 파운데이션

### 컬러

색은 **의미 단위**로 사용한다. 값을 직접 하드코딩하지 말고 토큰 이름으로 참조한다.

> ⚠️ **이 프로젝트의 실제 편차**: 아래 "Primary" 표와 컬러 램프는 Toss 문서 원본(참고용)이다. 이 앱은
> `blue.500`을 프라이머리로 쓰지 않고, **단일 그린 액센트 하나만 프라이머리/강조색으로 사용한다**
> (`src/styles/theme.js`의 `colors.primary = '#059669'`). Blue는 완전히 제거된 게 아니라 "식약처DB

> 화면을 만들 때 `blue.500` 자리에는 이 그린을 대입해서 생각한다 — 문서 갱신 시 이 표기를 지우지 않는다.

### 타이포그래피

폰트는 **Pretendard** (한글·영문·숫자 모두 지원, 미니멀 핀테크 톤). 크기·라인 높이는 토큰으로만
참조하고 직접 하드코딩하지 않는다 — 값을 고정하면 사용자의 "더 큰 텍스트" 접근성 설정에 대응하기 어렵다.

#### 타입 스케일

| 토큰 | Size / Line height | 기본 굵기 | 용도 |
|---|---|---|---|
| Typography 1 | 30 / 40 | Bold | 매우 큰 제목 (온보딩 타이틀) |
| Typography 2 | 26 / 35 | Bold | 큰 제목 (페이지 헤드라인) |
| Typography 3 | 22 / 31 | Semibold | 일반 제목 (섹션 타이틀) |
| Typography 4 | 20 / 29 | Semibold | 작은 제목 (카드 타이틀) |
| Typography 5 | 17 / 25.5 | Regular | 일반 본문 (기본 읽기 텍스트) |
| Typography 6 | 15 / 22.5 | Regular | 작은 본문 (보조 설명) |
| Typography 7 | 13 / 19.5 | Regular | 캡션 (라벨, 메타 정보) |

> 중간 단계가 필요하면 `subTypography 1~13`(29~11px)을 사용한다 — 구체적인 px를 외울 필요 없이
> 계층화된 토큰을 그대로 쓴다.

#### 굵기 (Weight)

| 이름 | 값 | 용도 |
|---|---|---|
| Regular | 400 | 본문 |
| Medium | 500 | 살짝 강조된 라벨 |
| Semibold | 600 | 제목, 버튼 텍스트 |
| Bold | 700 | 큰 제목, 금액 강조 |

#### 사용 규칙

- 한 화면의 제목 계층은 **최대 3단계**까지만.
- 본문 최소 크기는 **15px** — 그 이하(13px)는 캡션·메타 정보에만.
- 숫자(금액)는 `Bold`로 강조하되, 통화 단위(`원`)는 같은 크기로 붙여 쓴다.
- 자간(letter-spacing)은 제목에서 `-0.02em` 정도로 살짝 좁힌다.

#### 더 큰 텍스트 (접근성)

iOS·Android의 "더 큰 텍스트" 설정은 앱 내부 웹뷰에도 동일하게 적용돼야 한다. 비율(100%·110%·120%·
135%·160%…)에 따라 실제 폰트 크기가 동적으로 커지도록 상대 단위/토큰으로 구현하고, px를 고정하지 않는다.

- **iOS**: xLarge·xxLarge·xxxLarge·A11y 단계를 비율로 추상화해서 사용.
- **Android**: `기준크기 × 비율(NN) × 0.01` 공식으로 계산 (단계 제한 없음).

```css
:root { --font-family: 'Pretendard', -apple-system, system-ui, sans-serif; }
/* Typography 3 — 일반 제목 */
.title-3 { font-size: 22px; line-height: 31px; font-weight: 600; letter-spacing: -0.02em; }
/* Typography 5 — 일반 본문 */
.body-1 { font-size: 17px; line-height: 25.5px; font-weight: 400; }
```

## 컴포넌트

각 컴포넌트는 위 "상태 설계 체크리스트"(Default/Loading/Empty/Error/Disabled/Focus·Pressed)를
전제로 하며, 아래는 컴포넌트별 예외·구체 규칙만 적는다.

### Action — 버튼 계열

사용자의 행동을 유도하는 컴포넌트. 한 화면에서 **가장 중요한 행동 하나만 Primary**로 강조한다.

**Button — 위계 (Hierarchy)**

| 종류 | 배경 | 텍스트 | 용도 |
|---|---|---|---|
| **Primary** | `blue.500` | 흰색 | 화면의 핵심 행동 (다음, 확인, 송금) |
| **Secondary** | `grey.100` | `grey.700` | 보조 행동 (취소, 뒤로) |
| **Weak** | `blue.50` | `blue.500` | 가벼운 강조 (더 알아보기) |
| **Disabled** | `grey.100` | `grey.400` | 비활성 (조건 미충족) |

- Hover/Pressed: 배경을 한 단계 진하게 (`blue.500` → `blue.600`).

**Button — 크기 (Size)**

| 크기 | 폰트 | 패딩 | 반경 |
|---|---|---|---|
| Small | 13px / 600 | 8×14px | 9px |
| Medium | 15px / 600 | 13×22px | 12px |
| Large | 17px / 700 | 16×26px | 14px |

- **로딩 상태**: 버튼 안에 스피너를 넣고 텍스트를 숨긴다. 버튼 폭은 유지(레이아웃 안 튐). 로딩 중 재클릭 무반응.
- **Do** — 라벨은 동사 위주로 짧게 ("확인", "송금하기"). **Don't** — Primary 버튼을 한 화면에 2개 이상 두지 않는다.

**Text Button** — 배경 없이 텍스트만. 리스트 안/문장 끝의 가벼운 액션. 기본 `blue.500` / 보조
`grey.500` + 오른쪽 chevron("더보기 ›"). 최소 44px 터치 영역(패딩으로 확보).

**Icon Button** — 원형 배경 + 아이콘 하나. 툴바·헤더의 반복 액션. 크기 44×44px, `radius.full`.
중립: 배경 `grey.100` + 아이콘 `grey.700`. 강조: 배경 `blue.500` + 흰 아이콘.

**BottomCTA** — 화면 하단 고정, 핵심 행동 상시 노출.

| 종류 | 구성 |
|---|---|
| **Single** | Primary 버튼 1개 (다음/확인) |
| **Double** | 좌: Secondary, 우: Primary (2:3 비율 권장) |
| **FixedBottomCTA** | 스크롤과 무관하게 하단 고정, 키보드가 올라오면 그 위에 붙음 |

- 하단 safe-area(홈 인디케이터) 여백 필수 확보.
- 배경은 흰색 + 상단에 옅은 그라데이션/구분선으로 콘텐츠와 분리.

### Display — 정보 표시 계열

**ListRow** — 목록 기본 단위: **좌측 에셋 · 본문(제목/설명) · 우측 액세서리** 3영역.
- 좌측: 아이콘/썸네일/이니셜(44×44, `radius.lg`) — 없어도 됨.
- 본문: 제목(15px/600 `grey.900`) + 설명(13px `grey.500`).
- 우측: 금액·상태·스위치·chevron 등. 이동 행은 chevron(›).
- 세로 패딩 16px, 행 사이 `1px grey.100` 구분선. 누를 수 있으면 hover 시 `grey.50` 배경.
- 금액은 지출 `grey.900`, 수입/강조 `blue.500`으로 색 통일.

**TableRow** — 좌우 **라벨 → 값** 정보 나열(주문 상세, 계좌 정보 등). 라벨 `grey.500`, 값 `grey.900`,
값은 오른쪽 정렬.

**Board Row** — 공지/게시물 목록 행. 제목 + 날짜/작성자 메타. 안 읽음은 제목 앞 점(dot) 또는 Badge.

**Badge** — 12px/700, 패딩 5×10px, `radius.sm`.

| 의미 | 배경 / 텍스트 |
|---|---|
| 신규 | `blue.50` / `blue.500` |
| 완료·성공 | `green.50` / `green.500` |
| 지연·에러 | `red.50` / `red.500` |
| 대기·주의 | `orange.50` / `orange.600` |
| 카운트 | `grey.800` / 흰색 (원형) |

**Border** — 영역 구분 선/블록. 얇은 선 `grey.100`~`grey.200`, 큰 섹션 구분은 8px 두께 `grey.100` 블록.

**Paragraph** — 본문 텍스트 블록. 17px/25.5 `grey.700`, 문단 사이 여백 16px.

**Highlight** — 문장 안 단어 강조. `blue.500` 텍스트 또는 `yellow.100` 형광펜 배경 중 **하나만**.

**Bubble** — 말풍선 형태 짧은 안내/코치마크. 꼬리(tail)로 대상을 가리킴. 배경 `grey.900` + 흰
텍스트(강조형) 또는 `blue.50`(정보형).

**Rating** — 별점 표시/입력. 채워진 별 `yellow.500`, 빈 별 `grey.200`. 0.5 단위 지원 가능.

**Chart — Bar Chart** — 막대 `blue.500`(강조 시리즈) / `grey.200`(비교 시리즈). 축·격자선 `grey.100`로
최대한 옅게, 데이터에 집중.

### Feedback — 피드백 계열

**Toast** — 화면 하단 알약형 알림. 배경 `grey.800`, 흰 텍스트 14px/600, `radius.full`, `elevation.3`.
성공은 앞에 초록 체크 아이콘. 약 2.6초 후 자동 페이드아웃. **행동을 요구하지 않는** 가벼운 피드백에만
사용(선택 필요 시 Dialog/BottomSheet).

**Progress Bar** — 트랙 `grey.200`(높이 8px, `radius.full`), 채움 `blue.500`. 불확정 상태는 좌우로
흐르는 애니메이션.

**Progress Stepper** — 완료 단계 `blue.500` + 체크, 현재 `blue.500` + 숫자, 이후 `grey.200` + `grey.400`
숫자. 단계 사이 연결선도 진행 색으로.

**Loader**
- 스피너: `3px grey.200` 링 + `blue.500` 상단 호(arc), 0.8s 회전.
- 닷(dot): 점 3개 순차 밝아짐 — 인라인 소형 로딩용.

**Skeleton** — `grey.100`↔`grey.200` shimmer 애니메이션(1.4s). 실제 콘텐츠와 **같은 모양/크기**로
만들어 레이아웃이 튀지 않게 한다.

**Result** — 작업 완료/실패 전체 화면. 중앙 일러스트(또는 아이콘) + 제목 + 설명 + 하단 CTA. 성공
`green.500` 계열, 실패 `red.500` 계열 아이콘.

**Tooltip** — 배경 `grey.900` + 흰 텍스트 13px, 꼬리로 대상 지시. 마우스 오버(웹) 또는 최초 진입 시 1회 노출.

**Bottom Info** — 화면 하단 보조 안내 문구. 12~13px `grey.500`, 약관·유의사항·환율 기준 등 부가 정보.

### Input — 입력 계열

**TextField** — 밑줄형 단일 입력 필드. 해부: 라벨 · 입력 영역 · 밑줄 · (값 있을 때) 삭제 버튼 ·
도움말/에러 메시지.

| 상태 | 라벨 | 밑줄 |
|---|---|---|
| 기본 | `grey.500` | `2px grey.200` |
| 포커스 | `blue.500` | `2px blue.500` |
| 에러 | `red.500` | `2px red.500` + 하단 에러 메시지 |
| 비활성 | `grey.400` | `grey.200` |

- 값 입력 시 오른쪽에 원형 삭제(✕) 버튼 표시.
- 에러 메시지: 밑줄 아래 13px `red.500`.
- 변형: **SplitTextField**(인증번호 등 자릿수 칸 분할, 현재 칸 `blue.500` 테두리) · **TextArea**(여러
  줄, 우하단 글자 수 카운터 선택) · **SearchField**(왼쪽 돋보기 + 알약형 배경 `grey.100`, 입력 시 삭제 버튼).

**Checkbox** — on/off, 24×24px, `radius.sm`(8px). 선택: 배경 `blue.500` + 흰 체크. 미선택: 흰 배경 +
`2px grey.300` 테두리. 약관 동의 등 목록형은 "(필수)/(선택)" 접두어를 라벨에 붙인다.

**Switch** — 즉시 반영 on/off 토글(저장 버튼 없이 켜자마자 적용될 때만 사용). 트랙 52×32px
`radius.full`, 노브 28px 흰 원. ON: 트랙 `blue.500`, 노브 오른쪽. OFF: 트랙 `grey.300`, 노브 왼쪽.
전환 0.2s.

**Slider** — 트랙 4px, 노브 24px 흰 원 + 그림자. 채워진 구간 `blue.500`. 현재 값을 우측에 숫자로 병기.

**Stepper / Numeric Spinner** — 수량 1씩 증감. `−`(중립, `grey.100`) · 숫자 · `+`(강조, `blue.500`).
최소값에서 `−`는 비활성.

**Segmented Control** — 2~4개 중 하나를 고르는 필터. `grey.100` 트랙 안에서 선택된 칸만 흰 배경 +
얕은 그림자(`elevation.1`)로 떠 보임. 탭(화면 전환)과 달리 **필터/모드 전환**에 사용.

### Overlay — 오버레이 & 내비게이션 계열

모든 오버레이는 뒤에 딤(dim) `greyOpacity` 46% 배경을 깔고, 딤 탭 또는 아래 스와이프로 닫힌다.

**Bottom Sheet** — 화면 하단에서 올라오는 시트. 선택지가 여럿이거나 맥락 유지 채 추가 입력받을 때.
상단 모서리 `radius.2xl`(24px), 중앙 40×4px 핸들 바. 진입 0.32s ease-out 슬라이드 업, 닫힘은 아래로
슬라이드. 콘텐츠 하단에 BottomCTA(Single/Double) 부착 가능. **useBottomSheet** 훅으로 열고 결과를
`await`로 받는 패턴 권장.

**Modal** — 전체를 덮는 큰 오버레이. 독립적인 하위 플로우(예: 상세 설정)를 담음. 상단에 닫기(✕) 또는
뒤로 가기. 모바일에선 전체 화면에 가깝게.

**Dialog** — 집중이 필요한 짧은 확인창. 화면 중앙, 팝 애니메이션 0.24s, 폭 최대 320px, `radius.2xl`.

| 종류 | 버튼 | 용도 |
|---|---|---|
| **AlertDialog** | 확인 1개 | 단순 알림 (되돌릴 수 없음) |
| **ConfirmDialog** | 취소 + 확인 2개 | 사용자 결정이 필요할 때 |

- 제목 19px/700 + 설명 15px `grey.600` + 하단 버튼.
- 파괴적 행동(삭제 등)의 확인 버튼만 `red.500`.
- **useDialog** 훅으로 결과(확인/취소)를 `await`.

**Menu** — 특정 요소에서 펼쳐지는 액션 목록(더보기 ⋯). 각 항목 44px 높이, 파괴적 항목은 `red.500`
텍스트. `floatedBackground` + `elevation.3`.

**Tab** — 같은 층위 화면 사이 전환. 선택 탭 텍스트 `grey.900`/700 + 하단 2px 인디케이터, 비선택
`grey.400`/500. 필터 전환이 아니라 **콘텐츠 전환**일 때 사용(필터는 Segmented Control).

**Top (App Bar)** — 화면 최상단 바. 좌측 뒤로가기/타이틀, 우측 액션(Icon Button). 스크롤 시 타이틀
축소 또는 구분선 등장 패턴 가능. 높이 56px 기준.

### Agreement · Keypad · Asset (핀테크 특화)

**Agreement (약관 동의)** — 여러 약관을 한 번에 동의받는 묶음.
- 최상단 "전체 동의" 체크박스 → 하위 항목 전체 토글.
- 각 항목 "(필수)/(선택)" 라벨 + 오른쪽 "보기 ›"로 상세 이동.
- 필수 항목이 모두 체크돼야 하단 CTA 활성화.
- 버전 **V3 / V4** — 신규 화면은 최신(V4) 권장.

**Keypad (보안 키패드)** — 민감한 숫자/문자 입력용 자체 키패드(OS 키보드 대신 사용해 입력값 보호).

| 종류 | 용도 |
|---|---|
| **Number Keypad** | 금액·전화번호 등 일반 숫자 |
| **Full Secure Keypad** | 비밀번호 — 키 배열이 매번 섞이고, 화면 캡처/로깅 방지 |
| **Alphabet Keypad** | 보안이 필요한 영문 입력 |

- 하단 고정, 키 높이 최소 44px, 삭제/완료 키 포함.
- 보안 키패드는 눌린 키를 화면에 그대로 노출하지 않음(마스킹).

**Asset (에셋 / 아이콘·일러스트)** — 브랜드 일러스트·아이콘을 규격에 맞게 감싸 쓰는 래퍼.
- **Asset 이해하기** — 크기/여백 규격(frame) 안에서 사용, 임의 배율 금지.
- **Frame** — 표준 프레임에 넣어 정렬·여백 자동 정리.
- **래핑 컴포넌트** — 자주 쓰는 에셋은 이름 붙인 컴포넌트로 감싸 재사용.
- cjmt에서 실제 일러스트가 없을 땐 **줄무늬 플레이스홀더 + 설명 라벨**로 자리를 잡고, 실 에셋 준비되면
  교체한다. 임의로 SVG를 그려 넣지 않는다.

## Figma 이관

이 앱은 Figma가 아니라 **코드(`src/styles/theme.js`)가 디자인 토큰의 단일 소스**인 시스템이다. Figma로
"지금 디자인을 그대로 옮기는" 작업은 아래 순서로 진행한다 (`docs/03-개발스펙.md` §3과 위 "컴포넌트"
섹션의 상태 목록을 함께 참고).

1. **토큰 내보내기** — `theme.js`의 색상·spacing·radius·shadow·font 값을 Figma Tokens(Tokens Studio
   플러그인) 또는 Figma Variables가 읽는 JSON으로 내보낸다(예: `primary #059669`, `spacing xs~xxxl
   4~40px`, `radius sm~pill 12~999px`, `font xs~title 12~28px`). `deficientText`/`dangerText`는 텍스트
   전용 대비 보정 토큰이라 텍스트 스타일에만 연결하고 면 채우기에는 쓰지 않는다. `brandInk`는 로고
   전용이라 일반 UI 토큰 세트에서 제외. `theme.js`가 바뀌면 이 내보내기도 수동으로 재동기화해야 한다
   (자동화 스크립트 없음).
2. **화면 그대로 가져오기** — 수작업 재현 대신 실제 렌더링 결과를 픽셀 그대로 가져온다: 로컬에서
   `npm run server` + `npm run dev`로 앱 구동 → Chrome DevTools 기기 툴바(모바일 뷰포트, `layout.
   maxWidth` 430px 근처) → "html.to.design" 같은 HTML→Figma 플러그인으로 화면별(홈/식단/달력/지도/MY)
   페이지를 통째로 가져온다(스크린샷이 아니라 편집 가능한 실제 레이어로 변환됨). 로딩/빈/에러처럼
   순간적인 상태는 강제로 트리거하거나 `components/*.md` 스펙 기준으로 별도 variant를 만든다.
3. **토큰 재연결** — 1번에서 만든 Figma Styles/Variables를 가져온 프레임의 각 레이어에 다시 연결한다
   (Tokens Studio의 "Apply to selection" 활용) — 나중에 값이 바뀔 때 원래 토큰을 계속 추적하기 위함.
4. **컴포넌트화** — 위 "컴포넌트" 섹션의 상태(Default/Loading/Empty/Error/Disabled/Focus·Pressed)를
   Figma Component의 variant 축으로 그대로 사용해, 코드 쪽 구조와 Figma 쪽 구조가 어긋나지 않게 한다.
5. **모바일 전용 제약 반영** — 상단 안전영역(`env(safe-area-inset-top)`, 예: 노치 기종 47px), 하단
   안전영역(`env(safe-area-inset-bottom)`, 예: 34px), 터치 타깃 44×44px, 화면 폭 `layout.maxWidth`
   430px 중앙 정렬(그 이상은 좌우 여백만 증가)을 Figma 프레임 가이드로 옮긴다 — 무시하고 리디자인하면
   구현 단계에서 다시 고쳐야 한다.
6. **핸드오프(되돌리기)** — "코드가 항상 최종 소스"이므로 리디자인 후에는 반대 방향으로 되돌린다:
   Figma에서 바뀐 토큰만 정리 → 새 세션에서 `theme.js` 값 갱신(대부분 화면은 토큰 값만 바뀌어도 따라
   바뀜) → 레이아웃 자체가 바뀐 컴포넌트는 변경된 프레임을 참고 이미지로 첨부해 개별 구현 요청 →
   완료 기준은 위 "전체 원칙"의 Do/Don't 체크리스트 그대로 사용.
