## 3. URL 구조 분석

### 3.1 라우팅 방식

쿼리 파라미터 기반 라우팅

```
기본: https://www.wevity.com/?c=[섹션]&s=[상태]&...
```

### 3.2 주요 섹션

| 섹션 | URL 파라미터 | 용도 |
|------|-------------|------|
| 공모전 | `c=find` | 공모전 검색/목록 |
| 대외활동 | `c=active` | 대외활동/서포터즈 |
| 아이디어 | `c=idea` | 공모전 아이디어 제공 |
| 이벤트 | `c=event` | 이벤트 참여 |
| 이용약관 | `c=intro&s=4` | 이용약관 |
| 개인정보처리방침 | `c=intro&s=5` | 개인정보 정책 |

### 3.3 공고 상세 페이지 URL

```
https://www.wevity.com/?c=find&s=1&gbn=view&gp=1&ix=[공모전ID]
https://www.wevity.com/?c=active&s=1&gbn=view&gp=1&ix=[활동ID]
```

## 8. 필터링 설계 고려사항

### 8.1 추출해야 할 데이터

**공고(Posting) 테이블:**
- id (PK, 외부 source_id와는 별도)
- title (공모전/활동명)
- category (공모전/대외활동/정책/교내행사)
- source_url (원문 링크)
- host_organization (주최사)
- reception_start_date (접수 시작일)
- reception_end_date (접수 마감일)
- event_start_date (행사 시작일, nullable)
- event_end_date (행사 종료일, nullable)
- eligibility_text (원본 자격요건 텍스트 - 전체)
- views_count (조회수)
- created_at, updated_at

**파싱된 자격요건(Eligibility) 테이블:**
- posting_id (FK)
- requirement_type (신분/학년/지역/소득 등)
- requirement_value (구체적 값)

### 8.2 초기 파싱 규칙

```
자격요건 텍스트 → 정규식/키워드 기반 파싱 → 구조화된 데이터
```

**단계별 전략:**
1. 1차: 키워드 기반 매칭 ("대학생", "제한없음", 지역명 등)
2. 2차: 구체적 조건 파싱 (필요시 NLP 고려)
3. 3차: 사람의 검증 (초기 데이터 품질 확보)

## 9. 크롤링 전략

### 9.1 크롤링 대상 페이지

**필수:**
- 공모전 목록 (`c=find&s=1`)
- 공모전 상세 (각 `ix=` 페이지)
- 대외활동 목록 (`c=active&s=1`)
- 대외활동 상세 (각 `ix=` 페이지)

**선택:**
- 다양한 필터 조합 (`mode=ing`, `mode=soon` 등)
- 카테고리별 필터 (`cidx=` 파라미터)

### 9.2 예상 스크래핑 규모

- **초기 시드 데이터**: 50~100건 (공모전+대외활동 합산)
- **주기적 업데이트**: 주 1회 (새 공고만 수집)
- **전체 데이터베이스**: 500~1000건 (2-3개월 축적 예상)

### 9.3 주의사항

- 크롤-딜레이: 요청 간 1-2초 간격 권장 (Crawl-delay 3초는 GPTBot 전용)
- User-Agent: 일반적인 크롤러 식별자 사용 (robots.txt 준수)
- 급속 크롤링 금지: IP 차단 위험, 점진적 수집 권장
- 데이터 저장: 사실정보(제목, 마감일, 자격요건 요약)만 저장, 원문 링크 제공

## 10. 다음 단계 (2단계) 준비

### 10.1 Prisma 스키마 설계 시 고려사항

1. **Posting 테이블:**
   - 중복 방지: source_site + source_id 조합으로 unique constraint
   - nullable 필드: event_start_date, event_end_date (일부 공고는 기간 미명시)
   - 확장성: 정책/지원금 카테고리도 수용 가능하도록

2. **Eligibility 테이블:**
   - requirement_type 분류: '신분', '학년', '전공', '지역', '나이', '기타'
   - 향후 소득분위, 주민등록지 등도 추가 가능하도록

3. **자격요건 파싱 신뢰도:**
   - 초기: 정규식 기반 (80% 신뢰도)
   - 점진적 개선: 샘플 검증 후 규칙 개선

### 10.2 크롤러 구현 요구사항

- BeautifulSoup 사용 (정적 HTML이므로 Playwright 불필요)
- 주기적 스케줄링: node-cron 또는 AWS Lambda
- 에러 핸들링: 네트워크 오류 시 재시도, DB 롤백 없음 (append-only)
