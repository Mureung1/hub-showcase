# 나만의 에이전트 주도 개발(ADD) 워크플로우

본 문서는 4주간의 프로젝트 기간 동안 확립한 '페어 프로그래밍 기반 에이전트 주도 개발(Agent-Driven Development)'의 반복 작업 순서와 위기관리 절차를 기록함.

## 1. 반복 작업 순서 (4단계 파이프라인)

프로젝트 개발 내내 우리는 아래의 4단계 고정 워크플로우를 반복 수행함.

* **[Step 1] 입력 (Requirement & Context)**
  * Human(인간): 개발 백로그('plan.md')를 기반으로 구현 목표를 설정하거나, 브라우저에서 관찰된 버그 현상(예: 'Resize 시 입력 락 풀림') 및 터미널 에러 로그를 수집하여 Agent에게 제공함.
  * 도구: Chrome DevTools, VS Code Terminal.

* **[Step 2] 작업 순서 기획 (Micro-Planning)**
  * Agent(주니어 페르소나): 제공된 단서를 바탕으로 1일 이내에 끝낼 수 있는 '수직 슬라이스(Vertical Slice)' 단위의 Task로 분할함.
  * Agent: 로직 초안과 함께, 파일 성격에 따라 커밋을 분할하는 '3분할 원자적 커밋(Atomic Commit)' 전략을 수립하여 보고함.

* **[Step 3] 확인 기준 및 크리티컬 리뷰 (Critical Review)**
  * Human & Agent(시니어 페르소나): 주니어가 가져온 계획서가 아키텍처 원칙에 부합하는지 교차 검증함. 
  * 확인 기준: '무분별한 GPU 가속 등 안티 패턴이 없는가?', 'CSS SoC(관심사 분리) 원칙을 어기지 않았는가?', '기존 상태 관리(State Lifting)를 훼손하지 않는가?'
  * Human: 이상이 없을 시 승인('/approve') 명령 하달.

* **[Step 4] 결과물 적용 및 검증 (Execution & Verification)**
  * Agent: 승인된 코드를 즉각 파일에 반영함.
  * Agent(QA 페르소나): 로컬 빌드('npm run build') 무결성 확인.
  * Human: 에이전트가 제시한 Git 3분할 커밋 명령어 순차 실행 및 클라우드 배포 진행.

## 2. 문제 발생 시 위기관리 (Rollback & Retry) 단계

기능 반영 후 배포 환경이나 렌더링에서 예상치 못한 충돌(예: CSS Flexbox Paint Drop 버그)이 발생했을 때 다시 확인할 단계임.

1. **현상 동결:** 버그를 덮기 위해 억지 코드('display: none' 등)를 덧대지 않음.
2. **즉각 롤백:** 이전의 안정적인 커밋 상태로 'git reset' 또는 롤백을 수행함.
3. **스모킹 건(Smoking Gun) 탐색:** 에러 로그 외에 사용자의 조작(예: 창 크기 조절, 다른 탭 클릭)에 따른 상태 변화 등 물리적 단서를 철저히 수집함.
4. **재입력:** 수집된 결정적 단서를 들고 워크플로우 [Step 1]으로 회귀함.
