# 라이브러리 공부 순서


## 1단계 — 지금 당장, 제대로 이해하고 시작해야 하는 것

여기가 흔들리면 나머지 전부가 흔들린다. 시간 투자해서 진짜 이해하고 넘어갈 것.

- **JS 비동기** — Promise, async/await (제일 먼저. 이게 안 되면 아래 전부 이해 못 함)
- **HTTP 기본기** — GET/POST 차이, status code, JSON 주고받기
- **React 기본** — 컴포넌트/props/state, `useEffect`가 왜 필요한지, 리렌더링이 언제 일어나는지
- **TypeScript 기본** — 기본 타입, interface, `any`를 피해야 하는 이유
- **Express 기본** — 라우트가 뭔지, 미들웨어가 뭔지, req → res 흐름

---

## 2단계 — "왜 쓰는지, 언제 쓰는지"만 설명할 수 있으면 되는 것

내부 동작 원리까지 몰라도 된다. 개념만 잡아두면 프로젝트 진행하면서 저절로 몸에 붙는다.

- **react-router** — 화면(페이지) 이동시켜주는 도구라는 개념 + 기본 `<Route>` 문법
- **axios / @tanstack/react-query** — 서버에 데이터 요청하고 받아오는 패턴
- **zod** — 값이 규칙에 맞는지 검사해주는 도구
- **cors** — 포트가 다르면 브라우저가 요청을 막는다는 사실, 에러 났을 때 이것 때문인 걸 알아채는 정도
- **dotenv** — 비밀값(URL, 키)은 `.env`에 넣는다는 개념

---

## 3단계 — 존재만 알고, 필요할 때 검색해서 쓰면 되는 것

지금 따로 시간 내서 공부할 필요 없음. 코드 짜다가 막히면 그때 문서 찾아보면 충분하다.

- **date-fns** — 날짜 계산 함수들 (`addDays`, `format` 등)
- **morgan** — 서버 요청 로그 찍어주는 도구
- **tsx** — TypeScript 개발용 실행 도구
- **@hookform/resolvers** — react-hook-form과 zod 이어주는 다리
- **Vitest / @testing-library/react / supertest** — 테스트 처음 짜볼 때 그때 익혀도 늦지 않음

---

## 공부 방법 제안

1. 1단계는 개념 정리 + 짧은 연습 코드로 확실히 다지기
2. 2단계는 따로 안 외우고, 실제 프로젝트 코드에 한 번씩 써보면서 "아 이래서 쓰는구나" 체감하기
3. 3단계는 아예 미리 공부하지 말고, 필요한 순간에 해당 함수/설정만 찾아서 적용하기

**핵심**: 처음부터 모든 라이브러리의 모든 기능을 이해하려는 건 비효율적이다.
"필요할 때 문서 보고 적용할 수 있는 능력" 자체가 실무 스킬이다.
