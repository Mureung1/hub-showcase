# ConGraduation 3주 개발 Task

기준일: 2026-07-10 (금) / 대상 기간: 2026-07-10 ~ 2026-07-31
전제: 계획서.md 기획 내용 + GradPlan_Prototype_dc.html(정적 프로토타입, 5개 화면)이 이미 완료된 상태.
이번 3주는 **프로토타입 → 실제 동작하는 서비스**로 전환하는 것이 핵심 목표.

---

## Week 1 (07/10 ~ 07/16) — 데이터 모델 & 핵심 계산 로직

### 1. 데이터 모델 확정 및 구축
- [ ] 졸업요건 스키마 설계 (총 학점, 전공 필수/선택, 교양, 다중전공, 창업교과목, 현장실습, 해외학점, 종합설계)
- [ ] 이수 과목(수강 이력) 스키마 설계 (과목명, 학점, 이수구분, 학기, 성적)
- [ ] 사용자 프로필 스키마 (학번, 전공, 입학년도 — 단일 전공/컴퓨터학부 기준만 우선)
- [ ] 위 스키마로 DB 테이블/컬렉션 생성 (마이그레이션 스크립트 포함)

### 2. 졸업요건 계산 엔진 (핵심 로직)
- [ ] 이수 과목 리스트 → 영역별 이수 학점 집계 함수
- [ ] 요건 대비 부족분 계산 함수 (전공/교양/총학점)
- [ ] 이진 판정 요건(다중전공, 현장실습, 해외학점, 창업, 종합설계) 충족 여부 계산 함수
- [ ] 단위 테스트 작성 (경계값: 정확히 충족/1학점 부족/초과 이수 등)

### 3. 입력 기능 실제 구현 (프로토타입의 "다단계 입력 모달" 로직화)
- [ ] 졸업요건 입력 모달 → 실제 저장 API 연동
- [ ] 현재 이수 내역 입력 모달 → 실제 저장 API 연동
- [ ] 요약 바(입력값 요약) 실데이터 바인딩 + 재수정 시 부분 업데이트 확인

**Week 1 완료 기준(DoD):** 사용자가 요건/이수내역을 입력하면 DB에 저장되고, 계산 엔진이 정확한 부족분 수치를 반환한다 (UI 연동 전, API/함수 단위 검증 가능한 상태).

## Week 2 (07/17 ~ 07/23) — 대시보드 & 수강 바구니

### 1. 대시보드 화면 실데이터 연동
- [ ] 총 이수학점/전공/교양 진행률 바 → 계산 엔진 결과 바인딩
- [ ] 세부 요건(다중전공/현장실습/해외학점/창업/종합설계) 뱃지·체크 아이콘 → 실데이터 바인딩
- [ ] success/warning/danger 상태 분기 로직 연결 (색상 하드코딩 아닌 값 기반 분기)
- [ ] 빈 데이터(입력 전) 상태 UI 처리

### 2. 과목 검색 기능
- [ ] 과목 DB(교과목 목록) 구축 또는 시딩 (본교 컴퓨터학부 기준 과목 리스트)
- [ ] 과목 검색 API (이름/이수구분/학기 필터)
- [ ] 검색 결과 리스트 UI 연동

### 3. 수강 바구니 기능
- [ ] 바구니 담기/삭제 API 및 상태 관리
- [ ] "카드 목록 + 추가(+) 카드" 패턴 실데이터 연동 (3개 이하 가로배치 / 초과 시 캐러셀)
- [ ] 바구니 담긴 과목 기준 "충족 결과 미리보기" — 계산 엔진 재호출로 가상 반영
- [ ] 인정 영역(전공/교양 등) 표시

**Week 2 완료 기준(DoD):** 사용자가 과목을 검색해 바구니에 담으면, 대시보드 진행률이 실시간(또는 담기 즉시)으로 미리보기 반영된다.

## Week 3 (07/24 ~ 07/31) — 시뮬레이션, AI 추천, 통합/배포

### 1. 미래 학기 계획 시뮬레이션
- [ ] 학기별 계획(여러 학기, 각 학기별 과목 리스트) 데이터 구조 및 저장 API
- [ ] "1안/2안" 등 복수 시나리오 카드 관리 (카드 목록 + 추가 카드 패턴 재사용)
- [ ] 누적 학점 계산 → 졸업 가능 여부 판정 로직
- [ ] 미충족 시 대안(추가로 필요한 학점/영역) 안내 로직

### 2. AI 기반 수강 추천 (Agent)
- [ ] 수강 계획 추천 Agent 프롬프트/로직: 부족 요건 + 남은 학기 수 → 추천 과목 산출
- [ ] 학기별 과목 배분 시 과도한 학점 부담 방지 규칙 적용
- [ ] 챗봇 화면(프로토타입 Screen 4) 실제 질의응답 연동 ("2학기 안에 졸업하려면?" 등 시나리오 테스트)
- [ ] 시뮬레이션 Agent: 계획대로 수강 시 졸업 가능 여부 판단 + 대안 제안 응답

### 3. 통합 테스트 & 마무리
- [ ] 전체 플로우 E2E 테스트: 요건입력 → 이수내역입력 → 대시보드 확인 → 바구니 담기 → 시뮬레이션 → AI 추천
- [ ] 디자인 자체 검수 체크리스트 통과 확인 (gradplan-design 7항목: 텍스트 컬러, 상태 3색 구분, 보더 위주 카드, point 컬러 용도, Pretendard 폰트, JS 필요 여부, 모달 분리 여부)
- [ ] 반응형(모바일) 레이아웃 점검
- [ ] 버그 픽스 및 예외 케이스 처리 (미입력 상태, 과다 입력 등)
- [ ] GitHub Wiki 정리 (기능 설명, 사용법, 아키텍처)
- [ ] 최종 배포

**Week 3 완료 기준(DoD):** MVP 범위 내 5개 화면(홈/바구니/대시보드/시뮬레이션/챗봇)이 실데이터·실로직으로 end-to-end 동작하고, 배포된 상태로 확인 가능.

---

## 우선순위 메모
- 계산 엔진(Week1)이 전체의 기반이므로 가장 먼저, 정확도 검증까지 마쳐야 이후 주차가 밀리지 않음
- AI 추천 Agent(Week3)는 MVP 상 "간단한 추천" 수준으로 범위를 제한 — 완벽한 최적화보다 부족요건 기반 규칙 추천으로 우선 출시
- 제외 범위(학사 시스템 연동, 전학과 지원, 성적표 자동분석 등)는 이번 3주 Task에 포함하지 않음
