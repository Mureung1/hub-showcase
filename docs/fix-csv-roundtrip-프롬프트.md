# 버그 수정 프롬프트 — 내보낸 CSV를 다시 가져올 수 없는 문제

## 증상

사용자 보고: "CSV 내보내기는 되는데, 내보낸 파일을 가져오기 하면 형식이 안 맞는다고 거부당한다."

## 재현 및 원인 (확정)

실제 코드로 왕복을 돌려 확인했다(Vite dev 서버에 테스트 페이지를 띄우고 다운로드 blob을 가로채
그대로 다시 파서에 넣는 방식):

```
[A] MY 탭 내보내기 -> MY 탭 가져오기
    첫 줄: "# Mealyze 데이터 백업(기기 이동용)"
    -> 가져오기 OK: 2건, 실패 0                                    ✅ 정상

[B] 달력 탭 "기간별 기록 내보내기" -> MY 탭 가져오기
    첫 줄: "date,source,item_name,brand,calories,protein,carbs,..."
    -> 가져오기 실패: 지원하지 않는 파일 형식입니다.                 ❌ 버그
```

### 근본 원인: **내보내기 진입점은 2개, 가져오기는 1개, 그런데 형식이 서로 다름**

| 진입점 | 코드 | 형식 | 읽을 수 있는 곳 |
|---|---|---|---|
| MY 탭 "데이터 내보내기(CSV)" | `dataBackup.exportBackupCSV()` | `[profile]` / `[meals]` 섹션 구분 | `dataBackup.parseBackupCSV()` ✅ |
| 달력 탭 "기간별 기록 내보내기" | `csv.exportCSV()` | 평면 컬럼 `date,source,item_name,brand,<영양소>,recommended_*,compliant` | **없음** ❌ |

`parseBackupCSV()`는 파일 안에서 `[profile]` / `[meals]` 마커를 찾는데, 달력 탭이 만든 파일에는
그런 줄이 아예 없어서 첫 검사에서 바로 거부된다.

`src/lib/csv.js`에 이 평면 형식을 읽는 `importCSV()`가 **존재하기는 하지만 어떤 화면도 호출하지
않는다**(죽은 코드). 즉 달력 탭에서 내보낸 파일은 앱 어디에서도 다시 못 읽는다.

### 문제를 키운 요인

3주차에 두 내보내기의 파일명을 `mealog_*.csv`로 통일해버려서, 사용자 입장에서는 두 파일이
**똑같아 보인다**:

- MY 탭: `mealog_2026-07-22.csv`
- 달력 탭: `mealog_2026-07-01_to_2026-07-22.csv`

같은 앱, 같은 이름 규칙, 같은 확장자인데 하나는 되고 하나는 안 되니 "내보내기가 고장났다"로
느껴지는 게 당연하다.

---

## 수정 방침

**사용자가 "어느 버튼으로 내보낸 파일인지" 기억할 필요가 없어야 한다.** 앱이 내보낸 CSV라면
가져오기 하나로 전부 읽혀야 한다. 그래서 **내보내기 형식을 통일하는 대신, 가져오기가 두 형식을
모두 자동 인식**하도록 한다.

내보내기 형식을 하나로 합치지 않는 이유:
- 두 형식은 목적이 다르다. 달력 탭 형식은 `recommended_*`/`compliant`가 들어간 **엑셀로 열어보기
  좋은 평면 표**이고, MY 탭 형식은 신체정보까지 담는 **기기 이관용**이다.
- 이미 사용자가 예전에 내보내 둔 파일이 양쪽 형식으로 존재할 수 있다. 가져오기가 둘 다 읽으면
  그 파일들이 전부 살아난다. 내보내기를 통일하면 과거 파일 중 절반은 영영 못 읽는다.

## 🤖 작업 프롬프트

```
CSV 왕복이 깨진 버그를 고친다. 원인은 docs/fix-csv-roundtrip-프롬프트.md 에 정리해뒀으니 먼저 읽어.
요약: 내보내기 진입점이 2개(MY 탭 / 달력 탭)인데 형식이 서로 다르고, 가져오기는 MY 탭 형식만
읽을 수 있다. 달력 탭에서 내보낸 파일은 앱 어디서도 다시 못 읽는다.

방침: 내보내기는 둘 다 그대로 두고, **가져오기가 두 형식을 자동으로 구분해 읽도록** 한다.

1. src/lib/dataBackup.js — 형식 자동 인식:
   - parseBackupCSV()가 파일을 읽은 뒤 형식을 판별한다:
     (a) [profile]/[meals] 마커가 있으면 -> 기존 섹션 파서
     (b) 헤더 행이 date,source,item_name,brand,<영양소들>,recommended_*,compliant 이면
         -> 평면 형식 파서(신규)
     (c) 둘 다 아니면 -> 지금처럼 거부하되, 에러 메시지에 **두 형식 모두**의 예시를 보여줄 것
   - 판별은 헤더 이름 기준으로 하고, 컬럼 순서가 조금 달라도 되게 인덱스로 찾아 읽어라
     (사용자가 엑셀로 열었다 저장하면서 순서가 바뀌는 경우가 실제로 있다)
   - 평면 형식에는 신체정보와 mealType이 없다. 프로필은 null, mealType은 'etc'로 둔다
     (src/lib/csv.js의 기존 importCSV가 하던 것과 동일한 처리)
   - 평면 형식의 recommended_* / compliant 컬럼은 **읽되 저장하지 않는다**. 그 값은 내보낸
     시점의 프로필로 계산된 스냅샷이라, 지금 프로필과 다를 수 있어 되살리면 오히려 틀린다
   - **반환 모양은 기존과 동일해야 한다** — 그래야 중복 날짜 다이얼로그(ImportConflictDialog)와
     applyBackup()이 그대로 동작한다. 2단계(parse -> apply) 구조를 깨지 말 것
   - 행 단위 실패 정책도 동일: 깨진 행은 건너뛰고 세기만 한다("N건 가져옴, M건 실패")

2. 어떤 형식으로 읽었는지 사용자에게 알려줄 것:
   - parse 결과에 형식 종류를 담고, 완료 토스트에 반영
     (예: "기간별 기록 파일에서 42건 가져옴" / "전체 백업에서 42건 가져옴")
   - 평면 형식은 신체정보가 없으므로, 그 사실도 토스트에 한 줄로 알릴 것

3. src/lib/csv.js:
   - 이제 dataBackup이 이 형식을 읽으니, 아무도 부르지 않는 importCSV()는 제거한다.
     같은 파일 형식을 읽는 코드가 두 벌 남아 서로 갈라지는 걸 막기 위해서다
   - 제거 후 dailyRecord.js에서 쓰이지 않게 되는 함수가 있으면 함께 정리하고, 무엇이 왜
     지워졌는지 알려줘. 단, 화면에서 아직 쓰는 것은 절대 건드리지 말 것(먼저 grep으로 확인)

4. 파일명으로도 구분되게:
   - 두 파일이 똑같아 보이는 게 혼란의 원인이었다. 달력 탭 것은 기간이 들어가 이미 구분되지만
     (mealog_2026-07-01_to_2026-07-22.csv), 더 명확히 할 방법이 있으면 제안해줘
     (파일명을 바꾸더라도 **가져오기는 파일명을 보지 않고 내용으로만 판별**해야 한다 —
      사용자가 파일명을 바꿔도 읽혀야 하므로)

5. scripts/generate-sample-csv.mjs:
   - 지금은 [profile]/[meals] 형식만 만든다. --format=flat 옵션을 추가해 평면 형식 샘플도
     만들 수 있게 해줘(1,000행 성능 검증과 깨진 행 처리 검증을 두 형식 모두에서 하기 위해)

6. 회귀 방지:
   - 이 버그의 본질은 "내보낸 걸 다시 못 읽는다"인데, 지금 저장소에는 그걸 잡아줄 검사가 없다.
     npm run check:csv 같은 걸 추가해서, 두 내보내기 형식 각각에 대해
     "내보낸 텍스트 -> 파서 -> 원본과 같은 건수/날짜가 나오는지"를 자동 확인하게 해줘.
     테스트 러너가 없는 저장소니 check:ads와 같은 노드 단언 스크립트 방식으로.
     브라우저 API(File 등)에 의존하는 부분은 파서가 텍스트를 받도록 살짝 분리해도 좋다.

7. 완료 후: 두 형식 각각의 왕복을 실제로 어떻게 확인했는지와 결과를 보여줘.
```

## ✅ 검증 기준

- [ ] 달력 탭 "기간별 기록 내보내기" → MY 탭 "데이터 가져오기" → **성공**
- [ ] MY 탭 내보내기 → MY 탭 가져오기 → 여전히 성공(회귀 없음)
- [ ] 두 경우 모두 중복 날짜가 있으면 덮어쓰기/건너뛰기 다이얼로그가 뜬다
- [ ] 앱과 무관한 CSV → 거부되고, 안내에 **두 형식 예시가 모두** 보인다
- [ ] 엑셀로 열었다 저장해 컬럼 순서가 바뀐 파일도 읽힌다
- [ ] 깨진 행이 섞인 파일 → "N건 가져옴, M건 실패"
- [ ] `npm run check:csv` 통과 / `npm run check:ads` 통과 / `npm run build` 통과
