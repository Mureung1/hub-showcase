## 1. 핵심 기능 (3개, 깊이 우선)

서브 기능을 늘리지 않고 아래 3개에 집중한다. 이 3개가 곧 프로토타입 화면 3개와 1:1로 대응한다.

### 기능 1. 방치·우선순위 감지 (→ 화면 1: 대시보드)

**무엇을 하는가**: 등록된 여러 GitHub 레포를 커밋 빈도, 미해결 이슈 수, 문서 노후도 3개 지표로 스코어링해 우선순위 순으로 보여준다.

**왜 이게 핵심인가**: 사이드 프로젝트가 여러 개일 때 발생하는 진짜 문제는 "능력 부족"이 아니라 "확인을 까먹는 것"이다. 이 기능이 없으면 나머지 두 기능(분류, 문서 제안)도 무의미해진다 — 애초에 어떤 프로젝트를 볼지조차 못 정하기 때문.

**동작 방식**: 각 프로젝트마다 세 팩터(커밋 빈도 팩터, 이슈 팩터, 문서 노후도 팩터)를 가중합하여 최종 점수 산출. 가중치는 하드코딩하지 않고 조정 가능하게 설계(설정값 분리).

### 기능 2. 구조 기반 변경 분류 (→ 화면 2: 프로젝트 상세)

**무엇을 하는가**: 커밋 메시지가 아니라 실제 코드의 AST(추상 구문 트리) 변화를 분석해 FEATURE/FIX/REFACTOR/DOCS 등으로 자동 분류한다.

**왜 이게 핵심인가**: 커밋 메시지는 사람이 대충 쓰는 경우가 많아 신뢰도가 낮다. "신규 메서드/엔드포인트가 실제로 코드 구조상 추가됐는가"를 봐야 다음 기능(문서 미반영 감지)의 판단 근거가 정확해진다.

**동작 방식**: JavaParser로 커밋 전/후 AST를 비교 → 신규 시그니처 등장 여부, 기존 메서드 바디 변경 여부를 1차 판단 근거로 사용. 커밋 메시지 키워드는 보조 신호로만 사용.

### 기능 3. 문서 갱신 제안 (→ 화면 3: 문서 제안 검토)

**무엇을 하는가**: FEATURE로 분류된 변경 중 문서에 반영되지 않은 항목을 감지해, 자동으로 덮어쓰지 않고 갱신 제안(diff 형태)만 만든다.

**왜 이게 핵심인가**: 문서-코드 간극은 시간이 지날수록 벌어지고 아무도 안 고친다. 그렇다고 AI가 문서를 마음대로 고치게 하면 신뢰할 수 없다 — "제안만 하고 사람이 최종 승인"하는 안전장치가 핵심 설계 포인트다.

**동작 방식**: 문서 감지 에이전트가 "반영 가능성 높음"으로 자체 판단한 항목만 선별 → 선별된 것만 무료 LLM API에 배치 요청해 초안 문구 생성. 사람이 승인해야만 실제 반영.

## 2. 사용자 시나리오 (최종본, 화면 흐름과 연결)

**페르소나**: 본인 — JNU Hub, RoomMarket, rag-pipeline, VR 프로젝트를 동시에 진행하는 학생 개발자

**흐름**

1. **[화면 1: 대시보드]** 월요일 아침, DevPulse를 연다. 등록된 4개 프로젝트가 우선순위 순으로 정렬돼 있다. JNU Hub가 1순위(87점)로 떠 있고, "마지막 커밋 12일 전 · 이슈 3개 · 문서 갱신 필요 2건"이 한눈에 보인다.

2. **[화면 2: 프로젝트 상세]** JNU Hub 카드를 클릭한다. 우선순위 점수가 세 요인(커밋 빈도/이슈/문서 노후도)으로 어떻게 구성됐는지 막대 그래프로 확인한다. 최근 커밋 목록에서 "RAG 기반 학식 Q&A 엔드포인트 추가"가 FEATURE로 분류돼 있는 걸 보고, 지난주 작업한 걸 기억해낸다.

3. **[화면 3: 문서 제안 검토]** "문서 갱신 제안 확인하기"를 누른다. README.md에 새 엔드포인트(`POST /qa/ask`)가 빠져 있다는 걸 diff 형태로 확인한다. 제안 내용이 정확해서 승인을 누른다 — 만약 부정확했다면 거절하고 직접 고쳤을 것이다.

4. **결과**: 4개 레포를 각각 들어가서 확인하는 대신, 이 3단계 흐름만으로 오늘 뭐부터 해야 하는지 판단하고, 밀린 문서까지 안전하게 정리한다.

## 3. 화면 구조 (UI)

### 화면 1 — 대시보드

```
┌─────────────────────────────────────────┐
│ DevPulse                    [펄스 라인]   │
│ 지금 뭘 먼저 봐야 하는지                    │
├─────────────────────────────────────────┤
│ 01  ● JNU Hub            우선순위 87      │
│     마지막 커밋 12일 전 · 이슈 3 · 문서 2   │
├─────────────────────────────────────────┤
│ 02  ● rag-pipeline       우선순위 54      │
│     마지막 커밋 3일 전 · 이슈 1 · 문서 0    │
├─────────────────────────────────────────┤
│ 03  ● VR 협동 프로젝트    우선순위 30       │
│ 04  ● RoomMarket         우선순위 12      │
└─────────────────────────────────────────┘
```
- 카드는 우선순위 점수 내림차순 정렬 (숫자 01/02/03은 실제 순위이므로 의미 있는 표기)
- 상태 점(●) 색상으로 긴급도 구분: 위험(코럴) / 주의(amber) / 양호(teal)
- 카드 클릭 → 화면 2로 이동

### 화면 2 — 프로젝트 상세

```
┌─────────────────────────────────────────┐
│ JNU Hub                                  │
│ 우선순위 87점 · 마지막 분석 2시간 전         │
├─────────────────────────────────────────┤
│ 커밋 빈도   ████████░░  78               │
│ 미해결 이슈  ██████░░░░  65               │
│ 문서 노후도  █████████░  91               │
├─ 최근 커밋 ─────────────────────────────┤
│ [feature] RAG 학식 Q&A 엔드포인트 추가     │
│ [fix]     Kakao Maps 좌표 오류 수정        │
│ [refactor] Qdrant 초기화 로직 정리        │
├─ 미해결 이슈(3) ─────────────────────────┤
│ #42 #39 #35 ...                          │
│                    [문서 갱신 제안 확인하기]│
└─────────────────────────────────────────┘
```
- 점수 막대는 어떤 요인이 우선순위를 끌어올렸는지 시각적으로 보여줌 (문서 노후도 91점이 가장 높음 → 그게 문제의 핵심이라는 걸 즉시 인지)
- 커밋 목록의 배지 색상 = AST 기반 분류 결과
- 하단 버튼 → 화면 3으로 이동

### 화면 3 — 문서 갱신 제안 검토

```
┌─────────────────────────────────────────┐
│ 문서 갱신 제안 — README.md                 │
│ "자동으로 반영되지 않습니다" 안내 배너        │
├───────────────────┬─────────────────────┤
│ 현재 README.md     │ 제안된 갱신본          │
│ - GET /meals       │ - GET /meals          │
│ - GET /congestion  │ - GET /congestion     │
│                    │ + POST /qa/ask (신규) │
├───────────────────┴─────────────────────┤
│              [승인 (반영)]  [거절]         │
└─────────────────────────────────────────┘
```
- 좌우 대조(diff) 구조로 "뭐가 빠졌는지"를 한눈에 보여줌
- 승인 전까지 반영 안 된다는 안전장치를 화면 상단에 항상 노출

## 4. 프로토타입

- 위치: `docs/prototype.html`
- 순수 HTML/CSS로 제작, 외부 라이브러리·JS 없음 (탭 전환은 CSS `:checked` 선택자로 구현)
- 브라우저에서 파일 더블클릭으로 바로 열람 가능 (서버 불필요)
- 3개 탭이 위 3개 화면과 정확히 대응됨: `1. 대시보드` / `2. 프로젝트 상세 (JNU Hub)` / `3. 문서 제안 검토`
- 데이터는 실제 본인 프로젝트(JNU Hub, RoomMarket, rag-pipeline, VR 프로젝트) 기준 예시로 채움
