# @plan 태스크 관리 기능 — 2주차 작업 계획

**기능: 태스크 관리 (서비스의 뼈대)**

설계 결정사항 반영: 담당자 1명, 담당자 없음 허용, 상태 3단계(대기·진행·완료), soft delete, 활동 로그 기록, 진행도 2종(팀/개인). 완료 처리 권한 제한(담당자만)은 로그인 이후 구현이므로 이번 주는 **구조만 준비**하고 강제하지 않는다.

## 작업 목록

| 순서 | 작업 | 구분 | 우선순위 | 완료 기준 |
|------|------|------|----------|-----------|
| 1 | tasks 테이블 설계 + 생성 (id, 제목, 담당자, 마감일, 상태, archived, 생성일) | BE | 🔴 | SQLite에 테이블 생성되고 더미 1건 INSERT 성공 |
| 2 | 태스크 CRUD API — 목록 조회(GET) + 추가(POST) | BE | 🔴 | Postman/브라우저로 추가한 태스크가 목록에 보임 |
| 3 | 태스크 상태 변경 API (PATCH, 대기↔진행↔완료 자유 전환) | BE | 🔴 | 상태 변경 후 재조회 시 반영 확인 |
| 4 | 활동 로그 테이블 + 상태 변경 시 자동 기록 | BE | 🔴 | 완료→미완료 되돌리기 포함 모든 변경이 logs 테이블에 남음 |
| 5 | 태스크 목록 화면 (카드 리스트 + 상태 뱃지) | FE | 🔴 | API 데이터가 화면에 렌더링됨. 완료=초록(`--color-success`) |
| 6 | 태스크 추가 폼 (제목·담당자 선택·마감일) | FE | 🔴 | 폼 제출 → 새로고침 없이 목록에 추가됨. 담당자 미지정 허용 |
| 7 | 상태 변경 UI (클릭/드롭다운으로 3단계 전환) | FE | 🔴 | 클릭 시 API 호출되고 뱃지 색 즉시 갱신 |
| 8 | 진행도 바 2종 — 팀 전체(보라 그라데이션) + 내 것(파랑 그라데이션) | FE | 🟡 | 완료 개수/전체 개수 비율이 바 길이로 표시됨 |
| 9 | 태스크 soft delete (archived 플래그) + 목록에서 숨김 | BE+FE | 🟡 | 삭제 버튼 → DB엔 남고 화면에선 사라짐 |
| 10 | 활동 로그 화면 (누가 언제 뭘 바꿨는지 리스트) | FE | 🟡 | 로그 API 데이터가 시간순으로 표시됨 |
| 11 | 마감임박 표시 (D-1 이하 빨강 — 경고 전용 규칙 준수) | FE | 🟢 | 마감 하루 전 태스크에만 빨간 표시 |

## 의존성

- 1 → 2 → 3 → 4 (BE 순차)
- 2 → 5 → 6 → 7 (FE는 2 완료 후 시작 가능)
- 7 → 8, 3 → 9, 4 → 10

## 추천 진행 순서 (하루 단위)

- **1일차:** 1 + 2 (DB와 기본 API) → 커밋 2회
- **2일차:** 5 + 6 (목록 + 추가 폼) → 눈에 보이는 결과물 확보
- **3일차:** 3 + 7 (상태 변경 BE/FE 세트)
- **4일차:** 4 + 8 (로그 + 진행도 바) ← 여기까지가 "발표 가능한 상태" 최소선
- **5일차:** 9, 10, 11 + 버그 정리, PR 작성

## 주의점

- 각 순서마다 커밋 1개 이상 (몰아서 커밋 금지)
- 진행도 바에 빨강 절대 금지 — 팀=보라, 개인=파랑
- 담당자 권한 체크는 3주차 로그인 붙인 뒤 API에 조건 한 줄 추가하면 되도록, 상태 변경 API에 `userId` 파라미터 자리만 미리 만들어둘 것
