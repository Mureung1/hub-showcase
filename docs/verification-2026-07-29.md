# 2026-07-29 배포 검증 기록

## 검증을 시작한 경위

사용자의 실제 요청은 다음 한 문장이었다.

> 검증해보셈 그리고나서 showcase 작성 해보셈

사용자는 테스트 파일, 테스트 개수나 실행 명령을 지정하지 않았다. Agent가 저장소를 확인해 이미 존재하던 테스트 명령과 테스트 파일을 발견했고, “검증”의 기본 범위로 판단해 전부 실행했다. 이번 검증을 위해 21개·12개 테스트를 새로 만든 것은 아니다.

브라우저 검증 항목은 같은 날 전달받은 수업 미션의 다음 기준에서 가져왔다.

- FE 주소에서 핵심 기능을 처음부터 실행
- 빈 데이터와 잘못된 입력 확인
- 서버 오류가 화면에 어떻게 보이는지 확인
- 새로고침 후 데이터가 남는지 확인

여기에 프로젝트 핵심 기능인 Gemini 정리, 게스트 IndexedDB, 로그인 Supabase 저장과 사진 저장을 추가로 확인했다.

## Agent가 실제로 한 순서

1. `client/package.json`에서 `vitest run`을 확인했다.
2. `server/package.json`에서 `node --test --test-isolation=none`을 확인했다.
3. 기존 클라이언트·서버 테스트를 전부 실행했다.
4. Vite 프로덕션 빌드를 실행했다.
5. Browser Agent로 Vercel 화면과 핵심 기능을 직접 조작했다.
6. Render API와 로그, Supabase 저장 결과를 확인했다.
7. 확인한 항목과 미확인 항목을 나눠 기록했다.

7월 29일에는 위 명령들을 각각 실행했다. 루트의 `npm run verify`는 같은 검사를 다음에도 한 번에 실행할 수 있도록 7월 30일 Workflow 정리 과정에서 추가한 명령이다.
