# Task Checklist

> 스택: Next.js (App Router, 클라이언트 중심) + Tailwind + API Route + localStorage
> 규칙: 항목 하나 = Claude Code 프롬프트 하나. 완료 조건(괄호)이 눈으로 확인되면 체크.

## 1주차 — 화면 뼈대 + 더미 데이터 (기능 B 골격)

### 세팅
- [ ] 프로젝트 생성 (`create-next-app` + Tailwind 옵션, `npm run dev`로 localhost 접속 확인)
- [ ] 모바일 뷰포트 기본 레이아웃 (본문 최대 폭 430px 중앙 정렬, 폰 크기로 줄여도 안 깨지면 완료)
- [ ] CLAUDE.md 작성 (스택, 폴더 구조, "use client 기본, 서버 컴포넌트 안 씀" 등 프로젝트 규칙 명시)
- [ ] 타입 정의 파일 (`types.ts` — 5개 타입: 일정/과제/메모/루틴/식단의 인터페이스, 컴파일만 되면 완료)

### UI 조각 (와이어프레임 위→아래 순서)
- [ ] 헤더 컴포넌트 (로고 "Briefy" + 오늘 날짜 요일 포함 자동 표시)
- [ ] 항목 카드 컴포넌트 (체크박스 + 제목 + 메타 텍스트, props로 내용 주입, 카드 1개 화면에 뜨면 완료)
- [ ] 카드 변형: 서브텍스트 지원 (루틴의 "200 push-up" 같은 둘째 줄, 있을 때만 렌더)
- [ ] 섹션 컴포넌트 (회색 섹션 타이틀 + 카드 목록, 빈 목록이면 "없음" 표시)
- [ ] 하단 입력 바 UI (고정 하단, 입력창 + 음성 입력 버튼(원형) + 전송 버튼(음성 입력 버튼 보다 가로로 길게), 아직 동작 없음)

### 데이터 → 화면
- [ ] 더미 데이터 파일 (`dummy.ts` — 일정 2, 루틴 2, 식단 1, 과제 5, 메모 2개)
- [ ] 오늘 화면 조립 (더미 데이터로 5개 섹션이 와이어프레임 순서대로 렌더링)
- [ ] 과제 섹션 정렬 로직 (마감일 빠른 순 정렬 + 상위 5개만 표시, 더미에 6개 넣어서 5개만 뜨는지 확인)
- [ ] 일정 섹션 정렬 (오늘 날짜 항목만 + 시간순)
- [ ] 완료 체크 토글 (카드 탭 → ☐↔☑ + 취소선, 새로고침하면 풀려도 됨 — 저장은 2주차)

**1주차 완료 기준**: AI 없이 더미 데이터만으로 와이어프레임과 똑같은 화면이 폰 크기 브라우저에 뜬다.

## 2주차 — A-1 저장 파이프라인 (기능 A 심장)

### 저장소
- [ ] localStorage 유틸 (`storage.ts` — 전체 목록 load/save + 항목 add/update/remove 함수)
- [ ] 더미 데이터 → 저장소 교체 (첫 실행 시 더미를 시드로 저장, 새로고침해도 체크 상태 유지되면 완료)

### 파서 (화면 연결 전에 콘솔에서 완성)
- [ ] 파서 프롬프트 초안 (`prompts.ts` — 역할, 5개 타입 정의, JSON 스키마, 오늘 날짜·요일 주입, 모호 시 clarify 응답 규칙)
- [ ] 파서 API Route (`/api/parse` — 문장 받아 Claude API 호출, JSON만 반환, 키는 `.env.local`)
- [ ] 응답 스키마 검증 (필수 필드 누락/이상한 타입이면 에러로 처리, zod 또는 수동 검증)
- [ ] 파서 테스트 10문장 (아래 케이스를 넣고 기대 JSON과 비교, 통과 못 하면 프롬프트 수정 반복)
  - 과제: "금요일까지 팀플 자료 만들기" → type: task, 마감일 변환 확인
  - 일정+리마인더: "다음주 화요일 오후 3시 치과, 전날 알려줘"
  - 메모: "운동화 새로 알아보기"
  - 루틴: "월수금 저녁 8시부터 10시 운동 A, 200 푸시업 300 스쿼트"
  - 식단: "오늘 점심 잡곡밥이랑 닭가슴살"
  - 상대 날짜: "내일까지", "담주 금까지", "모레 저녁 약속"
  - 모호: "운동" → clarify 응답 오는지
  - 완료 표현: "오늘 운동 다 함"

### 화면 연결
- [ ] 클라이언트 호출 함수 (입력창 문장 → `/api/parse` → 응답 JSON, 로딩 중 전송 버튼 스피너)
- [ ] 저장 연결 (파싱 결과를 storage에 저장 → 해당 섹션에 즉시 나타나면 완료)
- [ ] 저장 확인 토스트 ("일정으로 저장했어요" 2초 표시 후 사라짐)
- [ ] 되묻기 UI (clarify 응답 시 입력 바 위에 선택지 버튼 카드, 탭하면 확정 저장)
- [ ] 에러 처리 (API 실패/빈 입력 시 "다시 시도해주세요" 안내, 앱이 죽지 않으면 완료)

**2주차 완료 기준**: "내일까지 과제 제출"이라고 치면 폼 없이 과제 섹션에 나타난다. "운동"이라고 치면 선택지가 뜬다.

## 3주차 — A-2 조회 + A-3 수정·삭제

### 의도 분기
- [ ] 파서 프롬프트 확장 (intent 필드 추가: save/query/update/delete, 기존 10문장 테스트가 여전히 통과하는지 회귀 확인)
- [ ] 분기 테스트 5문장 ("이번 주 마감 뭐 있어?" → query, "치과 4시로 바꿔" → update, "샐러드 메모 지워" → delete 등)

### 조회 (A-2)
- [ ] 조회 실행 (query 의도 시 조건에 맞는 항목을 storage에서 필터)
- [ ] 조회 응답 UI (입력 바 위 말풍선으로 결과 목록 표시, 닫기 버튼)

### 수정·삭제 (A-3)
- [ ] 대상 식별 (파서가 반환한 대상 설명으로 storage 검색 — 1개 매치면 바로, 여러 개면 후보 반환)
- [ ] 후보 선택 UI (되묻기 카드 재사용 — "어느 항목인가요?" + 후보 버튼)
- [ ] 수정 실행 (속성 변경 + "치과를 4시로 바꿨어요" 확인 토스트)
- [ ] 삭제 실행 (자연어 삭제 + 확인 토스트, 카드 길게 눌러 삭제도 추가)
- [ ] 완료 기록 처리 ("오늘 운동 다 함" → 해당 루틴 체크됨)

**3주차 완료 기준**: 저장·조회·수정·삭제가 전부 입력창 하나로 된다. *(밀리면 이 주를 통째로 잘라내고 4주차를 당긴다 — plan.md 리스크 대비)*

## 4주차 — A-4 음성 + 마무리

### 음성 입력
- [ ] STT 훅 (`useSpeech.ts` — Web Speech API, 마이크 버튼 누르면 녹음 시작/끝, ko-KR)
- [ ] 음성 → 입력창 연결 (인식된 텍스트가 입력창에 채워지고, 전송은 사용자가 확인 후)
- [ ] 미지원 브라우저 처리 (API 없으면 🎤 버튼 숨김)

### 마무리
- [ ] 배포 (Vercel — 폰에서 실제 URL 접속, 환경변수 등록 확인)
- [ ] 모바일 실기기 테스트 (터치 영역, 키보드 올라올 때 입력 바 위치, 깨지는 부분 수정)
- [ ] 파서 마지막 조정 (실사용하며 오분류된 문장을 테스트 목록에 추가하고 프롬프트 보완)
- [ ] 데모 시나리오 (발표에서 보여줄 입력 5개 정하고 리허설 — 저장/복합/모호/수정/음성 각 1개)
- [ ] 발표 자료 (문제 → 데모 → 아키텍처 → 확장 계획 순)

**4주차 완료 기준**: 폰에서 말로 "금요일까지 팀플 자료"라고 하면 과제가 등록되는 데모가 된다.
