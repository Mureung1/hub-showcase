# 작업분해 체크리스트 (Work Breakdown)

> 기획서 원문: [plan.md](./plan.md) · 화면 흐름/IA: [wireframe.md](./wireframe.md)

## 전제 조건

- **기능 범위**: `plan.md` 원안 기준 — 핵심 기능 2개(맞춤 공고 추천 / 자소서 초안 생성)만 다룬다.
- **데이터**: 공모전·대외활동·인턴십 공고는 샘플/목업 데이터로 시작한다. 실제 크롤링은 이번 범위 밖이며, 이후 과제로 분리한다. 단, 저장소는 JSON 파일이 아니라 Supabase 테이블이다 — 2주차 미션이 화면→서버→DB 저장·조회 한 사이클(CRUD)을 요구하기 때문.
- **기술스택**: 백엔드/AI 연동 스택 방향은 결정됨(`CLAUDE.md`의 "백엔드 방향" 참고). 실제 셋업은 1주차 T2 이후 진행.
- **진행**: 1인 개발, 4주 기준으로 분해한다.
- **우선순위**: `P0` 핵심(없으면 plan.md 6단계 시나리오가 성립하지 않음) · `P1` 있으면 좋음(완성도/안정성) · `P2` 여유 있으면(4주 내 필수 아님).
- **다음 주(2주차) 목표**: T2~T4(1주차 잔여) 완료 + T5~T6(추천 로직/API) 착수. 2주차 말까지 추천 목록 화면(T7)까지 눈으로 확인 가능한 상태를 목표로 한다. 미션 요구사항상 화면 요청 → 서버 처리 → Supabase 저장 → 응답 → 화면 반영까지 한 사이클을 실제로 검증해야 한다.
