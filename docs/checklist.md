# checklist.md — MBTI 기반 공부법 및 스트레스 관리 웹앱 4주 작업 체크리스트

> 프로젝트명: **MBTI 기반 공부법 및 스트레스 관리 웹앱**
>
> 쪼갠 3축:
>
> - **레이어 축**: 데이터 구조 → 점수 로직 → 추천 로직 → UI
> - **중요도 축**: 점검·추천·실천 카드 코어를 먼저, 기록·디자인 다듬기는 뒤에
> - **완성도 축**: 뼈대(돌아가게) → 정확도(납득되게) → 다듬기(써볼 만하게)
>
> 우선순위 원칙: **(1) 설문 응답 → 행동지표 점수화 → 추천 출력 → 실천 카드** 흐름을 최우선으로 한다.
>
> 가장 어려운 것은 예쁜 화면이 아니라 **추천 로직의 설득력**이다. 따라서 1주차에 추천 로직 초안을 먼저 검증한다.
>
> 단계 경계: 1~4주차는 현재 MVP 완성 범위다. “빅데이터”, 로그인·서버 저장, 대학 플랫폼, OpenAI 기능은 MVP 완료 항목이 아니라 아래의 **검증 베타 게이트**를 통과한 뒤 착수한다.

## 리스크 메모

### 1. 추천이 MBTI 성격풀이처럼 보일 위험

- 대응: 유형명보다 행동지표를 먼저 보여준다.
- 대응: 추천 이유를 설문 응답과 연결한다.

### 2. 스트레스 관리가 의학적 판단처럼 보일 위험

- 대응: 의학적 개입 표현과 심각도 분류 표현을 쓰지 않는다.
- 대응: 피로 신호, 회복 루틴, 주의 패턴으로 표현한다.

### 3. 기능이 커질 위험

- 대응: MVP는 점검, 추천, 실천 카드까지만 한다.
- 대응: 챗봇, 캘린더, 알림, 커뮤니티는 제외한다.

### 4. 화면이 복잡해질 위험

- 대응: 결과 화면에는 핵심 지표와 TOP 3 추천을 먼저 보여준다.
- 대응: 상세 지표는 하단 배치한다.

### 5. 점수 계산이 납득되지 않을 위험

- 대응: 점수는 평가가 아니라 추천 신호라고 설명한다.
- 대응: 사용자 피드백을 받아 가중치를 조정한다.

### 6. 데이터가 많으면 정확해진다는 가정

- 대응: 표본 수보다 결과 변수, 비교 기준, 편향과 결측을 먼저 정의한다.
- 대응: 관측 데이터와 인과적 효과 주장을 구분한다.

### 7. 응답 누락이 무작위라는 가정

- 대응: 단계별 이탈과 무응답을 함께 보고 NMAR 가능성을 민감도 분석한다.
- 대응: 완료 사용자 만족도를 전체 사용자 품질로 일반화하지 않는다.

### 8. 로그인·외부 연동의 조기 도입

- 대응: 데이터 거버넌스와 공식 API 게이트를 통과하기 전에는 구현하지 않는다.
- 대응: 사용자 응답과 자유응답을 Git repository에 저장하지 않는다.

### 9. 만족도를 정확도로 오해할 위험

- 대응: 적합도·이해도·실행 가능성을 수용성 지표로 분리한다.
- 대응: 실행률·지연 인출·오답 변화·부담을 별도 결과로 측정한다.
- 대응: 만족도만으로 추천 가중치를 자동 갱신하지 않는다.

### 10. learning-styles matching 오류

- 대응: 유형별 고정 공부법 표를 만들지 않는다.
- 대응: task/state-only baseline과 MBTI 추가 모델을 비교한다.
- 대응: 선호, 실행 가능성, 실제 학습성과를 구분한다.

### 11. 자체 문항과 공식 MBTI 혼동

- 대응: 공식 결과는 사용자 직접 입력으로만 받는다.
- 대응: 독자 문항은 공식 판정이 아닌 4축 탐색 신호로 표시한다.
- 대응: 공식 문항의 복제·번역·표현 변경을 하지 않는다.
