# 작업분해 체크리스트 (Work Breakdown)

> 기획서 원문: [plan.md](./plan.md) · 화면 흐름/IA: [wireframe.md](./wireframe.md)

## 전제 조건

- **기능 범위**: `plan.md` 원안 기준 — 핵심 기능 2개(맞춤 공고 추천 / 자소서 초안 생성)만 다룬다.
- **데이터**: 공모전·대외활동·인턴십 공고는 샘플/목업 데이터로 시작한다. 실제 크롤링은 이번 범위 밖이며, 이후 과제로 분리한다.
- **기술스택**: 백엔드/AI 연동 스택은 아직 미정이라 1주차에 결정한다.
- **진행**: 1인 개발, 4주 기준으로 분해한다.

## 1주차 — 기반 구축

- [ ] T1. 기술스택 선정 (백엔드 프레임워크, LLM API, 배포 방식) 및 결정 사항 문서화
- [ ] T2. 백엔드 프로젝트 셋업 + 프론트-백엔드 연동 구조 (T1 선행)
- [ ] T3. 목업 공고 데이터셋 설계·작성 (공모전/대외활동/인턴십별 샘플, 자소서 문항 포함)
- [ ] T4. 정보 입력 화면 UI 구현 (전공/부전공/학점/자격증/기타경험 폼) — 기존 `App.jsx`를 이 화면으로 교체

## 2주차 — 공고 추천 기능

- [ ] T5. 사용자 입력 → 공고 매칭/추천 로직 설계 (T3 선행)
- [ ] T6. 추천 API 구현: 입력 받아 추천 목록 + 추천 이유 반환 (T2, T5 선행)
- [ ] T7. 추천 공고 목록 화면 UI (T4, T6 선행)
- [ ] T8. 공고 상세 화면 UI: 추천 이유/주요 조건 표시 (T7 선행)

## 3주차 — 자소서 초안 생성

- [ ] T9. 자소서 문항 분석 로직 (공고별 문항 파싱, T3 데이터 활용)
- [ ] T10. LLM 연동 자소서 초안 생성 API: 사용자 경험 + 문항 반영 프롬프트 설계 (T1, T9 선행)
- [ ] T11. 자기소개서 초안 화면 UI: 문항별 분석 결과, 생성 초안, 편집 영역 (T8, T10 선행)
- [ ] T12. 초안 수정/저장 기능

## 4주차 — 통합 및 마무리

- [ ] T13. 화면 간 흐름/상태관리 정리 (입력 → 추천 → 상세 → 초안 전체 연결)
- [ ] T14. 예외/로딩 처리 (추천 결과 없음, 생성 실패, 입력 오류 등)
- [ ] T15. 전체 시나리오 End-to-End 점검 (plan.md 6단계 시나리오 기준)
- [ ] T16. 데모/발표 준비 (README 갱신, 실행 방법 정리)
