# 3주차 - 자동 알림과 상태 링크

- [ ] 같은 조건의 중복 알림을 막는다.

## 2. 원격 환자 자동 알림

- [ ] 6번째 이하 준비 알림 판정 함수를 만든다.
- [ ] 준비 알림에 현재 순서와 예상 시간을 넣는다.
- [ ] 4번째 이하 입장 요청 판정 함수를 만든다.
- [ ] 입장 요청 시 20분 도착 기한을 저장한다.
- [ ] 6번째를 건너뛰면 준비 알림을 생략한다.
- [ ] 직접 미룬 환자가 다시 4번째가 되면 입장 요청을 다시 보낸다.

## 3. 미도착 처리

- [ ] 차례 도달 미도착을 마지막으로 한 번 이동한다.
- [ ] 미도착 이동이 환자의 직접 미루기 횟수를 소비하지 않게 한다.
- [ ] 최초 도착 기한을 연장하지 않는다.
- [ ] 20분 만료 시 자동 취소한다.
- [ ] 도착 처리와 만료가 동시에 요청될 때 충돌을 처리한다.

## 4. 현장 환자 알림과 링크

- [ ] 현장 등록 완료 알림에 상태 링크를 넣는다.
- [ ] 현장 4번째 진료 임박 알림을 한 번 보낸다.
- [ ] 현장 상태 화면에 병원 정보와 전화하기를 표시한다.
- [ ] `웨이팅 취소는 병원으로 전화해 주세요`를 표시한다.
- [ ] 현장 화면에서 미루기·취소 버튼을 숨긴다.
- [ ] 호출·취소 시 조회 토큰을 즉시 제거한다.
- [ ] 무효 링크에 접수 내용을 노출하지 않는다.

## 5. 환자·직원 동기화

- [ ] 활성 환자·직원 화면을 10초 Polling으로 갱신한다.
- [ ] 호출·취소·보류 후 전체 순서와 예상 시간을 갱신한다.
- [ ] 알림 발송 이력을 직원 상세 영역에 표시한다.
- [ ] 네트워크 실패와 재시도 상태를 표시한다.

## 6. 자동 만료 작업

- [ ] Express 백그라운드 작업을 1분 간격으로 실행한다.
- [ ] PostgreSQL advisory lock으로 중복 실행을 막는다.
- [ ] 만료 취소와 이벤트·mock 알림 기록을 한 트랜잭션으로 처리한다.
- [ ] 동시에 두 작업이 실행돼도 한 번만 취소되는 테스트를 만든다.

- [ ] 실제 가족 인원으로 순서와 예상 시간을 계산한다.
- [ ] 원격 6번째·4번째 mock 알림과 20분 기한이 동작한다.
- [ ] 직원이 원격 환자의 도착과 현장 접수를 처리한다.
