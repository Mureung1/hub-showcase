# 개발 Task (백로그)

앞으로 할 작업을 모아둔 목록. 우선순위를 매겨서 개발 중 방향이 흔들리지 않게 관리한다.

## 우선순위 기준
- **P0 (필수)** — 핵심 기능 2개(매칭 알고리즘, 동행 신청/수락 플로우)가 동작하려면 반드시 있어야 함
- **P1 (중요)** — 안전·신뢰 등 서비스 품질에 중요하지만 코어 로직은 아님
- **P2 (선택)** — 시간이 남으면 진행

## 다음 주(2주차)까지 완료 목표
1주차는 기획·프로토타입·디자인 시스템·개발 환경 준비였고, **2주차부터 본격적인 기능 개발**이 시작된다. 다음 주까지는 매칭 알고리즘(핵심 기능 A)이 실제로 동작하는 것까지를 목표로 한다.

- [ ] `[P0]` DB 스키마 설계 및 Supabase 테이블 생성 (사용자, 거점, 매칭 요청)
- [ ] `[P0]` 학교 이메일 인증 API (인증 메일 발송/검증)
- [ ] `[P0]` 로그인 화면 React 컴포넌트 구현 (프로토타입 디자인 반영)
- [ ] `[P0]` 거점 목록 데이터 세팅 (정문/북문/대구역 등)
- [ ] `[P0]` 출발지·목적지·희망시간·도착 소요시간 등록 폼 UI + 저장 API
- [ ] `[P0]` 매칭 후보 조회 알고리즘 (같은 거점 조합 + 시간대 ±15분 필터링)
- [ ] `[P1]` 등록/매칭 후보 화면에 디자인 시스템(RideSplit, `design_handoff_ridesplit/README.md`) 적용

## 3주차 — 동행 신청/수락 플로우 (핵심 기능 B) + 보조 기능
- [ ] `[P0]` 동행 신청 버튼 및 API
- [ ] `[P0]` 상대방 수락/거절 처리 및 알림
- [ ] `[P0]` 그룹 확정 로직 (정원 체크, 도착 소요시간 기반 우선순위 적용)
- [ ] `[P1]` 그룹 채팅방 UI (기본 텍스트 채팅)
- [ ] `[P1]` 예상 비용 1/N 계산 로직 및 표시
- [ ] `[P1]` 선호 필터 옵션 (동성끼리만 매칭 희망 체크)

## 4주차 — 안전장치 + 마무리
- [ ] `[P1]` 탑승 확인 버튼 + 노쇼/지각/취소 판정 로직
- [ ] `[P1]` 평가 점수 시스템 (지각 소폭 차감 / 노쇼·임박 취소 대폭 차감)
- [ ] `[P1]` 동승 기록 저장 및 마이페이지 이력 화면
- [ ] `[P0]` 전체 통합 테스트 및 버그 수정
- [ ] `[P0]` 발표 자료·데모 시나리오 준비
