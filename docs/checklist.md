- [ ] [P0] 무응답 시 자동으로 skipCount 증가 + 레벨 상승 로직 연결, 레벨이 실제로 오른 순간 사용자가 누르지 않아도 알림이 먼저 뜨도록 처리

## 3주차 — 마이크로태스크 + 회피 이유 맞춤 개입

### 회피 이유 확인

- [ ] [P0] 미룸 감지 시 "회피 이유 확인/수정" UI — Lv1·Lv3 시점에 봇이 먼저 자동으로 물어봄 (사용자가 임의로 누르는 상시 버튼 아님), 할일당 최대 2번 제한
- [ ] [P0] 수정된 회피 이유를 DB에 갱신

### 마이크로태스크 생성 (핵심 기능 ①)

- [ ] [P0] 할일 유형(9종) × 회피 이유(3종+기타) 조합 마이크로태스크 템플릿 정의
- [ ] [P0] 템플릿 기반 마이크로태스크 생성 함수 (`lib/microtask.ts`)
- [ ] [P1] Gemini API 연동으로 마이크로태스크 실시간 생성 (템플릿 대체/보강용) — 이번 스프린트에서 send-push 서버리스 함수가 생기면서 서버 쪽에 API 키를 둘 수 있게 되어 "API 키 노출 문제로 불가능"이라는 기존 사유는 더 이상 유효하지 않음. 다만 3주차 P0가 이미 포화 상태(발송 섹션 P0 7개 포함 총 18개)이므로, P0를 모두 완료한 뒤 여유가 생기면 시도하는 것으로 우선순위 조정

### 넛지 메시지 (Lv1~4 차등, 핵심 기능 ②)

- [ ] [P0] Lv1 메시지 문구 작성 (회피 이유 재확인 + 가벼운 톤, 마이크로태스크 미포함)
- [ ] [P0] Lv2 메시지 문구 작성 (마이크로태스크 포함)
- [ ] [P0] Lv3 메시지 문구 작성: 세션 내 완료 이력 중 같은 회피 이유로 성공한 적 있으면 그때 성공한 마이크로태스크를 그대로 다시 제안("기억 기반 개입"), 없으면 회피 패턴 근거 문구 + 마이크로태스크 — 프로토타입에서 검증된 로직, 실제 DB 이력 기반으로 확장 필요
- [ ] [P0] Lv4 메시지 문구 작성 (실제 마감 D-day 숫자 언급, 톤 상승, "지금 시작하기"만 남기고 다른 선택지 제거)
- [ ] [P0] Lv4 "캘린더에 추가" 카드 UI (지금은 정적 데모 카드로 유지 — 실제 캘린더 히스토리 뷰 연결은 4주차 "캘린더 히스토리 뷰" 작업과 함께 처리)
- [ ] [P1] API 연동: 넛지 메시지 동적 생성 함수 (`lib/nudge.ts`) — 템플릿을 대체하거나 보강
- [ ] [보류] 여러 세션·여러 날에 걸친 장기 히스토리(과거 완료율 등) 기반 넛지 고도화 — 세션 내 기억 개입은 이미 검증됨, 이건 그 이상의 장기 데이터 기반 고도화만 해당

### 발송

데모 증명 포인트("탭이 닫혀 있어도 알림이 온다")를 보여줄 최소 세트와, 그 이후 완성도를 높이는 항목을 나눠서 관리한다.

**P0 (데모 증명용 최소 세트)**

- [ ] [P0] VAPID 키 발급 + 환경변수 세팅
- [ ] [P0] 알림 권한 요청 UI (프로토타입의 Notification API 권한 요청 로직 재사용)
- [ ] [P0] Push 구독(subscription) 등록 — 클라이언트에서 구독 생성
- [ ] [P0] 구독 정보 DB 저장 (1주차 DB 스키마에 없던 새 테이블이므로 이 항목에 스키마 정의도 포함)
- [ ] [P0] 서비스워커에 `push` 이벤트 리스너 추가 (수신 시 알림 표시)
- [ ] [P0] `send-push` 서버리스 함수 (단건 발송)
- [ ] [P0] 레벨 상승 로직에서 `send-push` 직접 호출 — 레벨 상승은 "지금 이 순간" 이벤트이므로 daily-checkin-scan(배치 스캔)을 경유하지 않고 바로 연결

**P1 (완성도/안정성, 데모 필수 아님)**

- [ ] [P1] 발송 실패/재시도 처리, 만료된 구독 갱신
- [ ] [P1] 여러 탭/디바이스 동시 구독 관리
- [ ] [P1] `daily-checkin-scan` ↔ `send-push` 연결 (여러 날에 걸친 세션 재개 시나리오, 라이브 데모로 시연하기 어려운 영역이라 후순위. 완전히 빼는 게 아니라 우선순위만 낮춤)

### 피드백 루프

- [ ] [P0] 넛지 수신 후 "도움됐음" / "귀찮았음" 선택 UI
- [ ] [P0] 피드백 결과 DB 저장 (`feedbacks`: 넛지ID, 사용자 응답)
- [ ] [P1] 피드백을 다음 개입의 에스컬레이션 속도에 반영하는 로직 — 세션 내 버전(같은 회피 이유의 다음 할일 속도 조정)은 프로토타입에서 이미 검증됨. 실제 구현에서는 DB 기반으로 영속화만 하면 됨 (기존에 [보류]였으나 구현 비용이 낮은 것으로 확인되어 P1로 승격)
