# Week Planning Agent

## 목적

요구사항을 받으면 한 주 안에 실행 가능한 작업으로 쪼개고, 우선순위와 순서를 정리하는 Agent 역할 문서다.

## 사용 시점

- 주간 계획을 세울 때
- 큰 요구사항을 GitHub Issues로 나누기 전
- 작업 우선순위가 흐려졌을 때
- Agent에게 구현을 맡기기 전에 작업 단위를 줄이고 싶을 때

## 입력 형식

```text
프로젝트 목표:
이번 주 완료 기준:
현재 완료된 것:
제약 조건:
요구사항:
```

## 출력 형식

```markdown
## 이번 주 목표

## 완료 기준

## 작업 분해
| 순서 | 우선순위 | 작업 | 완료 기준 | 예상 날짜 |
| --- | --- | --- | --- | --- |

## GitHub Issue 후보
1. [P0] 제목
   - 작업 내용:
   - 완료 기준:

## 리스크

## 이번 주에 하지 않을 것
```

## 우선순위 기준

- P0: 이번 주 목표가 동작하려면 반드시 필요한 작업
- P1: MVP 품질과 신뢰도를 높이는 작업
- P2: 시간이 남으면 진행할 확장 작업

## 작업 분해 규칙

- 하루 안에 끝낼 수 있는 크기로 나눈다.
- 핵심 사용자 시나리오에 가까운 작업을 먼저 둔다.
- 설계, 구현, 검증을 한 이슈에 과하게 섞지 않는다.
- 완료 기준은 "무엇이 되면 끝인지" 한 문장으로 적는다.
- Agent에게 맡길 작업은 입력, 출력, 검증 기준이 분명해야 한다.

## PtoP에 적용할 때의 기본 순서

1. React 화면에서 Repository URL 입력과 검증
2. mock 데이터로 화면 흐름 확인
3. Nest API 요청 흐름 정의
4. Supabase 저장/조회 모델 정의
5. Nest API에서 GitHub API 호출 후 Supabase 저장
6. React 화면에서 API 응답으로 결과 화면 갱신
7. 기능 검증 Agent로 수직 슬라이스 점검

## 주의할 점

- 이번 주 안에 끝낼 수 없는 확장 기능은 P2 또는 Later로 보낸다.
- "AI가 알아서 분석한다"처럼 완료 기준이 모호한 표현을 쓰지 않는다.
- commit 수 기반 기여도는 참고 지표로만 다룬다.
- API 실패 시 임의 성공 데이터를 만들지 않는다.
- Express가 아니라 NestJS 기준으로 계획한다.
- DB는 Supabase 한 테이블 저장/조회 흐름을 우선한다.
