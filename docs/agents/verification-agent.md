# 기능 검증 전용 Agent

## 역할

구현된 기능이 요구사항대로 동작하는지 확인한다.

이 Agent는 새 기능을 제안하기보다, 이미 정한 요구사항과 데모 기준에 맞춰 빠진 부분과 실패 케이스를 점검한다.

## 입력

- 기능 요구사항
- GitHub Issue 완료 조건
- 실행 가능한 앱
- API 응답
- Supabase 저장 결과
- 데모 시나리오

## 출력

- 검증 체크리스트
- 실패 케이스 목록
- 통과/실패 결과
- 수정이 필요한 작업 목록

## 2주차 검증 체크리스트

- [x] React 화면에서 감정 텍스트를 입력할 수 있다.
- [x] 빈 입력일 때 정리하기 버튼이 비활성화되거나 400 응답이 반환된다.
- [x] 정리하기를 누르면 Express API에 요청이 간다.
- [x] 서버가 `emotion`, `cause`, `action` 형태의 결과를 만든다.
- [x] 결과 카드 3개가 화면에 표시된다.
- [x] 결과 카드 내용을 수정할 수 있다.
- [x] 저장 버튼을 누르면 Supabase `checkins` 테이블에 저장된다.
- [x] 기록 목록에서 저장된 기록을 다시 조회할 수 있다.
- [x] 최신 기록이 먼저 보인다.
- [x] 서버 에러 응답은 `{ error: { message } }` 형식이다.
- [x] AI 호출이 실패해도 mock fallback으로 데모가 깨지지 않는다.

## 실패 케이스

- 입력값이 비어 있음
- Supabase URL/key가 없음
- Supabase 연결 실패
- 서버가 꺼져 있음
- AI 게이트웨이가 꺼져 있음
- 응답 형식이 예상과 다름

## 데모 전 확인

데모 전에는 아래 흐름을 한 번에 확인한다.

1. 앱 실행
2. 하루 감정 텍스트 입력
3. 결과 카드 확인
4. 결과 일부 수정
5. 저장
6. Supabase 테이블 저장 확인
7. 기록 목록 조회 확인
