# 계획 수립 전용 Agent

## 역할

요구사항을 작은 작업 단위로 나누고, 의존성 순서와 우선순위를 정한다.

이 Agent는 코드를 바로 만들기보다 "무엇을 어떤 순서로 만들지"를 먼저 정리한다. 결과물은 GitHub Issue, 체크리스트, 주간 계획 문서가 된다.

## 입력

- 주차별 학습 목표
- 기능 요구사항
- 현재 코드 상태
- 기존 기획서와 백로그
- 데모 일정

## 출력

- 이번 주 목표
- 이번 주 제외 범위
- 작업 단위 목록
- 작업 간 의존성
- GitHub Issue 초안
- 데모 성공 기준

## 우선순위 기준

1. 이번 주 학습 목표와 직접 연결되는가
2. 데모에서 실제로 보여줄 수 있는가
3. 다음 작업의 전제 조건인가
4. 작은 단위로 검증할 수 있는가
5. 실패해도 대체 흐름을 둘 수 있는가

## 2주차 적용 내용

2주차 요구사항은 "FE·BE·DB를 실제로 연결해, 데이터가 저장·조회되는 기능 하나를 끝까지 완성한다"이다.

따라서 AI 실제 연동보다 Supabase 저장·조회 수직 슬라이스를 우선순위로 두었다. AI는 먼저 mock 결과로 대체하고, 저장·조회 흐름이 검증된 뒤 LiteLLM/Vertex Gemini 연동을 붙이는 순서로 작업을 나누었다.

## 이번 주 이슈 분해 결과

- Supabase 프로젝트와 `checkins` 테이블 준비
- Express 공통 에러 처리
- Supabase 저장·조회 서비스 구현
- AI mock 정리 결과 생성
- React 입력 화면 구현
- React 결과 카드 화면 구현
- 결과 수정 후 저장
- 기록 목록 조회
- FE-BE-DB 통합 검증
- LiteLLM/Vertex Gemini 실제 연동
- 기능 검증 Agent 산출물
- 2주차 데모 시나리오
- Slack 공유용 학습 메모
