# 📘 CalMe 최종 워크플로우 가이드

**4주간의 작업 패턴을 정리한 재사용 가능한 템플릿**

---

## 🎯 핵심 요약

### 세 가지 반복 패턴

1. **매주 기획→구현→발표** (1~4주차)
2. **기능별 설계→구현→리팩토링** (기능 단위)
3. **Mock→실제 연동** (3주→4주 전환)

### 도구 분담

- **Claude:** 90% 기술 구현 (기획/설계/코드/배포)
- **사람:** 10% 의사결정/검증/발표

## 📋 워크플로우 프로세스 (실제 사용 템플릿)

### **1️⃣ 기획 단계 (매주 월요일)**

**입력:**
- 지난주 피드백
- 이번주 목표 (checklist.md에서 추출)

**작업 순서:**
```
1. 관련 문서 읽기 (계획, 설계, 스키마)
2. Claude에게 구현 계획 설명하기
3. 파일/변경 내용 확인
4. 사람이 승인
5. 구현 시작
```

**확인 기준:**
- ✓ 변경 범위 명확
- ✓ 필요한 파일 식별
- ✓ 테스트 방법 정의

**결과물:**
- 구현 계획 문서 (또는 대화)

---

### **2️⃣ 구현 단계 (화~목요일)**

**입력:**
- 승인된 계획
- CLAUDE.md의 규칙

**작업 순서:**
```
1. Claude: 코드 구현
2. 사람: 브라우저에서 테스트
3. 버그 발견 → Claude에게 보고
4. Claude: 버그 수정
5. 최종 검증 후 커밋
```

**확인 기준:**
- ✓ 기능 동작 확인
- ✓ 에러 없음
- ✓ 스타일 적용됨
- ✓ 반응형 검증 (모바일/데스크톱)

**결과물:**
- Git 커밋 (feat/fix/style/refactor)

---

### **3️⃣ 발표 준비 (금요일)**

**입력:**
- 이번주 구현한 기능들
- 지난주 피드백

**작업 순서:**
```
1. Claude: 구현 사항 정리
2. 사람: 발표 자료 작성
3. 사람: 시연 스크립트 준비
4. 금요일: 발표
```

**확인 기준:**
- ✓ 모든 기능 작동 확인
- ✓ 발표 자료 완성
- ✓ 데모 시연 가능

**결과물:**
- 발표 자료
- 영상/스크린샷

## 🔧 문제 발생 시 체크리스트

### **1. 기술이 불명확할 때**
```
증상: "어떻게 구현할지 모르겠어"
확인:
  1. CLAUDE.md에서 규칙 재확인
  2. docs/에서 관련 설계 문서 읽기
  3. 이전 주차에서 비슷한 기능 찾기
해결: 규칙 없으면 사람이 결정 후 CLAUDE.md 업데이트
```

### **2. 작업 범위가 애매할 때**
```
증상: "뭘 해야 할지 모르겠어"
확인:
  1. docs/checklist.md에서 현재 주차 항목 찾기
  2. 상세 설명이 없으면 docs/plan.md 읽기
  3. 이전 주차 커밋과 비교
해결: Claude에게 작업 분해 요청
```

### **3. 구현 오류가 발생했을 때**
```
증상: 컴파일 에러, 기능 미동작, 스타일 깨짐
확인:
  1. 에러 메시지 복사
  2. 개발자 도구에서 에러 로그 확인
  3. 변경 전 코드와 비교
해결: Claude에게 에러 메시지 + 관련 코드 전달 → 수정
```

### **4. 배포 실패했을 때**
```
증상: 배포 안 됨, 데이터 손실, 503 에러
확인:
  1. "배포와 CICD.pdf" 문서 읽기
  2. 환경 변수 확인 (.env 설정)
  3. 데이터베이스 연결 확인
해결: 배포 문서 단계별 재시도
```

### **5. API 비용 초과했을 때**
```
증상: Claude API 사용량 급증
확인:
  1. 프롬프트에서 불필요한 반복 제거
  2. Mock 데이터 사용 가능한지 판단
  3. API 호출 빈도 확인
해결: 프롬프트 최적화 또는 Mock으로 전환
```

## 📈 생산성 지표

### **성공한 패턴**
- ✅ Mock→API 전환 (3주→4주)
  - 비용 절감: 1주 API 사용
  - 안정성: Mock으로 전체 흐름 검증
  - 코드: 변경 최소화

- ✅ 매주 기획→구현→발표
  - 주간 리듬 명확
  - 금요일 발표가 마일스톤
  - 피드백 빠른 반영

- ✅ Claude 중심 구현
  - 개발 속도 향상
  - 코드 품질 유지
  - 문서화 자동화

### **개선 필요 항목**
- ⚠️ 테스트 자동화 부족
  - Mock 데이터만으로는 한계
  - 통합 테스트 코드 추가 필요

- ⚠️ API 비용 모니터링
  - 3주차 조기 연동으로 비용 증가
  - 프롬프트 최적화 필요

- ⚠️ 배포 문서 의존성
  - 배포와 CICD.pdf 전체 숙지 필요
  - 배포 자동화 고려
