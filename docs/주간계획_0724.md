## 이번 트랙 전략 — "P2 3건 마감"

0721까지는 "버림 우선순위"에 있던 P2 3건을, 발표 전에 **확정된 동작 + 검증 가능한 형태**로 닫는다.
스코프를 넘겨 무리하게 실연동으로 바꾸는 게 아니라, **되는 것은 정직하게 실연동, 안 되는 것은 정직한 폴백**으로 마감한다.

핵심 판단 — SNS 자동 게시의 실현 가능성을 실제 API 사양으로 재확인한 결과:

| 채널 | 본인 계정 실게시 | 결정 |
|---|---|---|
| **Instagram** | ✅ 무료. 앱 **개발 모드**에서 본인 프로페셔널 계정엔 App Review 없이 게시 가능 | **실연동**(Solapi 본인번호 패턴) + 실패 시 복사 폴백 |
| **X (트위터)** | ⚠️ 2026년 신규 개발자는 무료 티어 없이 **종량제**(건당 ~$0.015, 크레딧 선구매·결제 등록) | **복사 폴백만** (결제 장벽) |
| 타인 계정(IG·X) | ❌ App Review 2~4주 필요 | **모의 유지** |

> Instagram Content Publishing은 **텍스트만 게시 불가** — 반드시 공개 `image_url`이 필요하다.
> 오늘은 고정 공개 프로모 이미지 + 동적 캡션으로 실게시하고, 캠페인별 카드 이미지 생성은 후속으로 둔다.

## 이번 트랙 항목 (3건)

구현 순서: FE로 검증되는 것 먼저 → 서버 큰 것. (서버 재시작은 마지막에 몰아서.)

### 3-7 · Instagram 본인 계정 실게시 + 복사 폴백 (server+FE)

instagram 채널 발송 시 서버가 **본인 IG 프로페셔널 계정에 실제 게시**를 시도하고,
성공하면 완료 화면에 permalink를, 실패(토큰없음·API오류·이미지없음)하면 캡션 + "문구 복사" 버튼을 준다.
Solapi가 본인 번호에만 실발송하듯, IG도 본인 테스트 계정에만 실게시(타인 계정은 모의 유지).

- **파일**(Solapi 모듈 미러):
  - `packages/shared/src/sns.ts` — `buildSnsCaption({title, copy, promo})` 순수 함수(캡션+해시태그).
    실게시 캡션·복사 폴백·미리보기가 **한 함수**를 써 드리프트 방지(`buildSmsBody`와 같은 패턴).
  - `packages/shared` — `SendCampaignResponse`에 `sns?: { posted, permalink?, caption, error? }` 추가.
  - `apps/server/src/sns/instagram.ts` — `publishToInstagram({caption, imageUrl})`, 2단계 호출
    `POST /{ig-user-id}/media`(image_url+caption) → `/{ig-user-id}/media_publish`(creation_id).
    **best-effort**(예외 안 던짐): 성공 `{posted:true, permalink}`, 실패 `{posted:false, error}`.
  - `apps/server/src/routes/campaigns.ts` — `channels.includes("instagram")`이면 게시 시도, 결과를 `resp.sns`에.
  - `apps/web/src/App.tsx` `SentView` — 게시 성공이면 permalink+복사, 실패면 캡션+"문구 복사"+정직한 안내.
  - `apps/web/src/mocks/scenarios.ts` `CHANNELS` — instagram "본인 계정 자동 게시", x "문구 복사 후 게시"로 정직화.
  - `apps/server/.env.example` — `IG_USER_ID`·`IG_ACCESS_TOKEN`·`IG_API_HOST`·`IG_DEMO_IMAGE_URL`(서버 전용, 커밋 금지).
  - `apps/server/src/sns/instagram.test.ts` — fetch 스텁 주입, 2단계 순서·오류 시 `{posted:false}`(throw 안 함) 단언(CI 결정론).
- **선행 설정(사용자, ~30~60분)**: IG 프로페셔널 계정 + (FB Login 방식이면) FB 페이지 연결 →
  Meta 개발자 앱(개발 모드) → 본인 계정을 tester 추가 → `instagram_business_content_publish`+`instagram_basic`로
  장기 토큰(~60일) 발급 → `.env` 기입. (App Review 불필요.)
- **DoD**: 토큰 세팅 후 instagram 발송 → 본인 IG에 실제 게시물+permalink. 토큰 제거 시 복사 폴백으로 강등,
  발송 플로우 안 깨짐. `buildSnsCaption`·`instagram.ts` 단위 테스트 통과.

### 4-7 · UAT 계측 + 프로토콜 (FE+문서)

"검토 진입 → 발송 완료" 소요 시간을 계측하고, 3명이 따라 할 UAT 대본·결과표를 만든다.
실제 3명 세션은 사용자가 진행하되, 측정 도구와 문서를 준비한다.

- **파일**:
  - `apps/web/src/App.tsx` — `goEdit()`에서 시작 시각 기록, `handleSend()` 성공 시 소요초 계산 →
    항상 `console.info` 기록, `?uat=1`일 때만 완료 화면에 "검토→발송 N초" 표시(프로덕션 노이즈 방지).
  - `docs/UAT_0724.md` — 참가자 3명·과제 대본·성공 기준(완료 ≤30초·오발송 0)·간단 설문·결과 기록 표(빈칸).
- **DoD**: `?uat=1`로 검토→발송 시 소요 시간 화면·콘솔 표시, 30초 내 완료 재현. 문서에 3명분 빈 표 준비.

### 4-6 · LLM 회귀 세트 (server)

날씨×업종 조합에서 LLM 제안이 품질 규칙을 지키는지 회귀로 검증한다.
LLM은 비결정적·유료라 **2계층**으로 나눈다(실호출을 CI에 넣으면 빌드가 랜덤하게 깨지고 토큰 소모).

- **파일**:
  - `apps/server/src/agent/quality.ts` — `checkProposalQuality(proposal, storeName)`: `checkGuardrails` 위에
    한국어 전용(한자·가나·라틴 차단)·copy 내 매출/진단 언급 없음·`channels ⊆ {instagram,x,dangol}`·창작 상호 없음.
  - `apps/server/src/agent/regression.test.ts` — 결정론 픽스처(정상+적대 케이스)를 `generateProposal`에 주입해
    파이프라인이 항상 규칙 통과 제안을 내는지 단언 + `describe.skipIf(!GROQ_API_KEY)`로 날씨4×업종3=12케이스 라이브 매트릭스.
  - `apps/server/package.json` — `test:llm` 스크립트(라이브만 실행).
- **DoD**: `npm test -w apps/server` 초록불(결정론 회귀 포함). `GROQ_API_KEY` 있을 때 `test:llm`이 12케이스 리포트 출력.
