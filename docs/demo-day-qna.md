# 데모데이 부스 구두 답변 메모

> 인쇄용 아님 — 부스에서 "왜 이렇게 했나요?" 질문 받을 때 참고할 개인 메모. A3 포스터엔 공간상 다 못 넣어서 여기로 뺐다. 각 항목의 커밋 해시로 `git show <hash>`하면 원문을 바로 다시 볼 수 있다.

## 운동 데이터의 신뢰도 근거 (51d7bbc)

33개 운동의 관여 부위를 "신뢰도 원칙"에 따라 동료심사 논문·공식 자료만 채택하고 블로그·유튜브·AI 요약은 제외했다. 실제 인용: Fenwick·Brown·McGill (2009, *J Strength Cond Res*), Youdas et al. (2010, *JSCR*), PMC(2025) 등. 근거가 부족한 항목(원암 덤벨로우 등)은 "안전 우선 원칙으로 보수적 포함"이라고 별도 표기해뒀다. → "AI가 대충 판단한 거 아니냐"는 의심에 논문 인용으로 반박 가능.

## wger.de 이미지 매칭은 수작업이었다 (6aa8f11)

33개 중 30개를 매칭했고, 3개(원암 덤벨로우 계열·랜드마인프레스·파머스워크)는 텍스트만 유지. wger API의 이름 검색 엔드포인트가 지금 버전엔 없어서(404) 자동 매칭이 아니라 사람이 직접 확인하고 골랐다. 로컬 파일 확장자(`.jpg`)와 원본 URL 확장자(`.png`)가 자주 어긋나 있던 것도 실제로 겪은 문제. → "왜 자동화 안 했나요?"에 답하기 좋음.

## PPL 7일 순환의 구조적 버그 (735999d)

인접 부위 검증을 온보딩 생성에도 연결하자 "PPL 3주기(Push/Pull/Legs)가 7%3=1이라 월요일과 일요일이 항상 같은 카테고리로 겹친다"는 수학적 문제가 드러났다. 목요일을 강제 휴식으로 비워서 앞뒤 3일씩 완전히 분리된 두 사이클로 재설계했다. → 숫자 근거가 명확해서 설명하기 쉬움.

## 요일 순환 경계 버그 + TDD (c91b790)

"반복 요일 템플릿이라 일요일 다음은 실제로 월요일"인데, 배열 끝과 시작을 이웃으로 안 보던 버그가 있었다. 나머지 연산(`%`)으로 수정했고, 정상/빈 값/경계값(순환 포함)/실패 케이스를 먼저 테스트(Red)한 뒤 구현(Green)했다. → 포스터②의 TDD 사례에 하나 더 추가할 만한 소재.

## CI가 실제 DB를 안 건드리게 만든 이유 (4942521)

Playwright E2E가 프로덕션 Supabase 대신 CI 전용 임시 Postgres + 전용 시드(`seed-e2e.js`)를 써서, 실데이터 위험 없이 어느 요일에 돌려도 같은 결과가 나오게 설계했다. → 배포 안정성 질문에 좋은 답.
