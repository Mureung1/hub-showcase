# 시연 준비 체크리스트

부스·발표 직전에 실행할 것. 위에서부터 순서대로 하면 된다.

배포 주소
- 프론트: https://hub-gogildong.vercel.app
- 서버: https://hub-2bxa.onrender.com

---

## 왜 매번 해야 하나

시연용 DB는 시간이 지나면 저절로 망가진다. 세 가지 이유다.

| 원인 | 증상 |
|---|---|
| 딜의 `pickup_deadline_at`이 지남 (시딩 기준 **8시간**) | **딜 목록이 비어 보인다** |
| 방문자·테스트가 예약을 소진 | 재고 0, 품절만 보임 |
| 소비자 풀 40명이 배정 소진 | 새 방문자가 앞사람과 같은 계정을 받음 |
| Render 무료 티어가 15분 유휴 시 절전 | 첫 접속이 수십 초 멈춤 |

특히 첫 줄이 중요하다. **시딩한 지 8시간이 지나면 목록이 빈다.** 당일 아침에 돌렸다면
오후 발표까지는 대체로 버티지만, 확실히 하려면 발표 직전에 다시 돌린다.

---

## 1. Render 깨우기 (가장 먼저)

절전 상태면 첫 요청이 수십 초 걸린다. 다른 작업을 하는 동안 깨어나도록 제일 먼저 친다.

```bash
curl https://hub-2bxa.onrender.com/api/health
```

`{"ok":true}` 가 나오면 깨어 있다. 응답이 오래 걸려도 정상이다(그 자체가 깨우는 과정).

---

## 2. 배포 DB 초기화

딜 마감시간을 되살리고, 예약·알림·풀 배정을 모두 리셋한다.

`server/.env`의 `DATABASE_URL`이 **로컬 Docker를 가리키고 있으므로**, 배포 DB에 시딩하려면
주소를 바꿔 실행해야 한다. `.env`를 건드리지 않는 한 줄 방식을 권한다(되돌리는 것을 잊지 않도록).

Git Bash:

```bash
DATABASE_URL="$(sed -n 's/^#[[:space:]]*DATABASE_URL=//p' server/.env | head -1)" DATABASE_SSL=true npm run seed -w server
```

PowerShell:

```powershell
$u=(Select-String -Path server\.env -Pattern '^#\s*DATABASE_URL=(.+)$').Matches.Groups[1].Value; $env:DATABASE_URL=$u; $env:DATABASE_SSL='true'; npm run seed -w server; $env:DATABASE_URL=''; $env:DATABASE_SSL=''
```

**실행 직후 첫 줄을 반드시 확인한다.**

```
대상 DB: aws-0-ap-southeast-1.pooler.supabase.com:5432  [배포(원격)]
주의: 원격 DB입니다. 시연용 데이터를 덮어씁니다.
```

`[로컬]`이라고 나오면 배포 DB가 아니라 Docker를 지운 것이다. 주소를 다시 확인한다.

기대 출력:

```
seed 완료: { users: 46, stores: 3, deals: 5, favorites: 2,
             user_interest_categories: 43, demo_pool: 40 }
```

## 3. 확인

세 가지가 모두 맞아야 시연 준비가 끝난 것이다.

```bash
curl -H "X-User-Id: 4" https://hub-2bxa.onrender.com/api/deals/nearby
```

딜 **5건**이 나와야 한다. 비어 있으면 2단계가 배포 DB에 적용되지 않은 것이다.

```bash
curl https://hub-2bxa.onrender.com/api/demo/pool
```

`{"total":40,"assigned":0}` 이어야 한다. `assigned`가 0이 아니면 시딩이 안 된 것이다.

브라우저로 https://hub-gogildong.vercel.app 접속 →
**소비자** 선택 → 목록에 5건이 거리순(0.6 / 0.9 / 1.1km)으로 보이면 정상.

---

## 4. 사장님 축 확인

`신규사장`(user 6)은 **가게 없이** 시딩된다. 가게 등록 화면(W1)을 시연하기 위해서다.

- **사장님** 선택 → 가게 등록 폼이 뜨면 정상 (`등록된 가게가 없습니다` 404는 의도된 동작)
- 누군가 가게를 등록하면 그 흐름은 더 못 보여준다

**다시 보여주려면 사장님 축만 되돌린다.**

```bash
npm run reset:owner -w server
```

이 스크립트는 **배포 DB가 기본 대상**이다(부스 운영용이라). 로컬을 대상으로 하려면
`-- --local` 을 붙인다. 실행 전 첫 줄에 대상이 찍히므로 확인하고 진행한다.

2단계(전체 재시딩)와의 차이:

| | `reset:owner` | `seed` (2단계) |
|---|---|---|
| 신규사장의 가게·딜 | 삭제 | 삭제 |
| **방문자 예약·픽업코드** | **보존** | 삭제 |
| **소비자 풀 배정** | **보존** | 초기화 |
| 시딩 딜 5건 | 보존 | 재생성(마감 8시간 갱신) |

**부스 중간에는 `reset:owner`를 쓴다.** 전체 재시딩을 하면 이미 예약한 방문자의
픽업코드가 사라진다. 딜이 만료돼 목록이 비었을 때만 2단계를 쓴다.

## 5. 시연 중 상태 확인

풀 소진 현황은 언제든 볼 수 있다.

```bash
curl https://hub-2bxa.onrender.com/api/demo/pool
```

`assigned`가 40에 가까워지면 방문자들이 계정을 재사용하기 시작한다(순환된다).
문제는 없지만 예약이 섞여 보일 수 있으니, 여유가 있으면 2단계를 다시 돌린다.

---

## 하지 말 것

- **`UNSAFE_STOCK=1`을 배포 서버에 켜두지 말 것.** 오버셀 비교군 전용이다.
  Render 환경변수에 남아 있으면 실제 시연 데이터에 오버셀이 생긴다.
  → Render Environment에 `UNSAFE_STOCK`이 없는지 확인.
- **부하 테스트(`seed:load`, k6)를 시연 직전에 배포 DB에 돌리지 말 것.**
  `load-user-%` 계정과 `[부하테스트]` 딜이 남는다. 돌렸다면 2단계로 초기화한다.
- **측정 데이터(`seed:geo`)를 지우지 않고 두지 말 것.**
  가게 수천 개가 목록에 섞인다. `npm run seed:geo -w server -- --clean` 후 2단계.

## 로컬로 시연할 경우

네트워크가 불안하면 로컬이 더 안전하다. 지연도 훨씬 짧다(딜 목록 111ms → 15ms).

```bash
docker compose up -d
```

```bash
npm run migrate -w server
```

```bash
npm run seed -w server
```

```bash
npm run dev
```

`server/.env`가 기본적으로 Docker를 가리키므로 추가 설정이 필요 없다.
클라이언트는 http://localhost:5173, 서버는 4000이다.

주의: 로컬은 HTTP라 **FCM 웹 푸시가 동작하지 않는다**(HTTPS 필요).
푸시까지 보여주려면 배포 환경을 써야 한다.
