# 데모 계획 — 핵심 사용자 흐름 하나

> 데모에서 보여줄 **핵심 흐름 하나**를 정하고, 월요일까지 반드시 동작할 것과 이후로 미룰 것을 나눈다.
> 원칙: 화면 다듬기보다 **핵심 흐름의 동작**을 먼저 확인한다.

## 핵심 흐름 (한 문장)
**로그인 → 역기획 작성(실제 게임 검색 + 장르 렌즈) → 챌린지 제출 → AI 자동 채점 → 리더보드.**

## 사용 순서 (화면 → 서버 → DB, 실제 경로)
| # | 사용자가 하는 것 | 화면 | 서버·DB |
|---|---|---|---|
| 1 | 로그인 | 로그인 페이지 | 프론트가 Supabase Auth 직접 호출(anon) → access token → 이후 요청에 `Bearer` |
| 2 | 챌린지에서 "참가하기" | 챌린지 카드 → 에디터 | 링크가 `?game=&system=&category=` 프리필 |
| 3 | "대상 게임" 검색·선택 | 자동완성 드롭다운 | `GET /api/games/search` → 서버가 RAWG 호출·캐시 |
| 4 | (선택 즉시) 장르 렌즈 표시 | "이 장르에서 꼭 짚을 것" 패널 | RAWG 장르 → 우리 11장르 매핑(프론트) |
| 5 | 섹션 작성 후 제출(발행) | 에디터 발행 | `POST/PATCH /api/documents` → `documents` status flip, `author_id` 서버 주입 |
| 6 | AI 자동 채점 | "AI가 검토 중…" | `POST /:id/ai-feedback` → requireAuth+소유자검증+일일한도 → Gemini(responseSchema) → `comments` append + `ai_score` 저장 |
| 7 | 결과 확인 | 상세의 "AI 채점" 패널(총점+항목별) | `GET /api/documents/:id` |
| 8 | 순위 확인 | 챌린지 리더보드 | 발행분을 `ai_score` 내림차순 정렬 |

→ 화면·서버·DB·외부 API(Gemini·RAWG)가 한 흐름에 전부 이어진다.

## 월요일까지 반드시 동작 (필수)
- [x] 로그인/세션 + `Bearer` 재검증
- [x] 게임 검색(RAWG 프록시) + 장르 렌즈 자동 표시
- [x] 역기획 작성 → 발행(status flip, 태그 DB 제약)
- [x] AI 채점(총점+항목별) 저장 + 상세 노출 *(코드·라이브 검증 완료, 데모 시 1콜)*
- [x] 리더보드 점수순 노출
- [x] 커뮤니티 느낌(목데이터): 발행 65편·저자 22명·좋아요·코멘트

## 이후로 미룸
- 배포(Vercel/Render) — 내일부터
- 남은 AI 예시 생성 ~94게임 — Gemini 무료 하루 20건 제약
- 카드·상세에 게임 커버 이미지 영속화(현재 커버는 검색 드롭다운에서만)
- CORS 도메인 제한(배포 후)
- 내부 문서의 옛 이름 '역기획소' 잔재 정리

## 아직 동작하지 않는 것 (알려진 한계)
- **코멘트 동시 쓰기 유실 가능** — `comments`가 jsonb read-modify-write라 두 명이 같은 문서에 동시에 달면 뒤가 앞을 덮음. 코멘트 테이블 정규화가 선결(스키마 변경 필요).
- **RAWG 한글 검색 약함** — 영어 게임명으로 검색해야 정확(예: "Zelda", "Hades").
- **좋아요는 목데이터 표시용 카운트** — 실제 토글은 로그인 필요, 목 문서의 수치는 표시용.
- **AI 일일 한도(무료 20건)** — 데모 중 재채점 남발 시 429. 발표용 한도 보존 필요.
