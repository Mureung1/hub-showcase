# 개발 Task 목록

4주 중 1주차(디자인 시스템·디자인 스킬·개발 환경 구성)는 완료됐다. 이 문서는 2~4주차 실제 개발 task를 정리한 것이다. 기획서(@기획서.md)의 핵심 기능 2개(통증 재편성, 스킵 재편성)와 그 전제조건을 의존관계 순서로 배치했다. 진행하면서 주차별 분량은 조정될 수 있다.

## 2주차 — 기반 다지기 (데이터·화면 골격)

- [ ] 정적 운동 테이블 확정(30~50개) — 스쿼트·데드리프트·벤치프레스는 교차검증 완료, 오버헤드프레스·로우·풀업·런지의 관여 부위만 마저 검증
- [ ] 신체부위 선택 목록 확정 (지금은 무릎/허리/어깨/손목 예시뿐)
- [ ] 분할 프리셋 목록 확정 (지금은 전신/상하체/PPL 예시뿐)
- [ ] Prisma 스키마 설계(User, Exercise, Routine, ExerciseLog, PainReport 등) + 마이그레이션
- [ ] 온보딩 화면(가능일수 입력 → 분할 추천 + 요일별 수정 UI) 구현
- [ ] 오늘의 루틴 허브 화면을 실제 데이터로 렌더링 (`docs/diagrams/AI 운동 루틴 적응 코치/루틴 적응 코치.dc.html` 목업을 실제 React 컴포넌트로)
- [ ] 기본 API 골격 (오늘의 루틴 조회, 세션 완료 기록)

## 3주차 — 핵심 기능 1(통증 재편성) + 핵심 기능 2 착수

- [ ] 통증 부위 선택 화면(바디맵 SVG) 컴포넌트화, 목록 선택과 동기화
- [ ] 관절 필터링 로직(Express) — 선택 부위를 관여 관절로 쓰는 운동 제외
- [ ] 같은 타겟부위 대체 운동 후보 API (LLM 선택 포함, Claude API 호출은 server에서 처리)
- [ ] 대체 운동이 아예 없는 경우 → 스킵 재편성으로 편입시키는 로직
- [ ] 재편성 결과 화면(추천 배지·전문가 상담 고지·수동 교체) 완성 + 확정 시 오늘 세션 반영
- [ ] 인접 세션 부위 중복 금지 검증(같은 부위 최소 48시간 간격) — 통증 재편성과 스킵 재배치가 공유하는 하드 제약
- [ ] 스킵 버튼 — 스킵 시 이번 주 빈 휴식일로 재배치(48시간 간격 검증 포함) 또는 기록만 남기는 로직

## 4주차 — 핵심 기능 2 마무리 + 통합

- [ ] 스킵 재편성 결과 문구(재배치/기록 두 갈래)·확정 흐름(거부권 없음, 확인 버튼만) 완성
- [ ] 운동 기록 화면(세트별 무게·반복수·완수 여부 입력/조회)
- [ ] 재편성 근거 문구 템플릿 정리 (통증·스킵 공통 패턴 점검)
- [ ] Vitest+RTL로 핵심 컴포넌트·로직 테스트 커버 + 버그 수정
- [ ] 전체 플로우 리허설(온보딩→오늘의 루틴→통증 재편성→스킵 재편성→기록)
- [ ] [선택, 여유 있으면] 누적 성과 기반 증량 제안 — 3세션 연속 완수 판단 + StrongLifts식 증량 UI
