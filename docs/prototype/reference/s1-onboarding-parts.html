S1 온보딩 — 미니 시안

레시피 없는 2개 요소만 확정 · 나머지(타이틀·키워드 칩·시작 버튼)는 기존 레시피 재사용
① 이메일 연동 버튼 A/B 비교 · ② 발신처 등록 입력
① 이메일 연동 버튼 — A/B 비교
📧 학교 이메일 연동 (읽기 전용) 메일 내용은 저장하지 않아요
📧 학교 이메일 연동 (읽기 전용) 메일 내용은 저장하지 않아요
A안 (면 채움): 차분한 카드형 — 화면 최하단 "시작하기"(accent primary)와 위계 충돌 없음.
B안 (accent 테두리): 연동이 온보딩의 핵심 행동임을 강조 — 다만 accent 요소가 화면에 2개(연동+시작하기)가 되어 시선 분산 여지.
공통: "읽기 전용" 문구 + 보조 캡션 = 개인정보 최소 수집 원칙을 UI에 명시 (S1 설계 근거).
② 발신처 등록 입력 — 단일안
꼭 알림 받을 발신처 AI가 놓쳐도 이 발신처의 메일은 반드시 알려드려요
예: 학과 사무실, 장학팀…
학과 사무실 × 장학팀 ×
구조: 라벨 + 안전망 설명 + 입력창(placeholder) + 등록된 발신처는 키워드 칩과 동일 컴포넌트로 표시.
근거: 발신처 등록 = 기능 A의 사용자 규칙 그 자체, "AI가 틀려도 동작하는 안전망" (S1 설계 근거) — 안전망이라는 성격을 힌트 문구로 노출.
입력창 스타일: 카드와 같은 surface + line 테두리 — 점선은 "밖으로 나감/추가 유도"(원문 링크, +키워드 추가) 문법이라 입력창엔 실선 사용.
