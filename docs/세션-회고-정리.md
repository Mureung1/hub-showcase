# 세션 회고 정리 — 냉장고 레시피 앱

> 여러 번의 작업 시간에 걸쳐 남긴 메모를 네 덩어리로 겹치는 내용 없이 합친 문서입니다.
> 전체 흐름은 이렇게 이어졌습니다.
> **(1) 문서와 실제 코드가 서로 맞는지 점검하고, 자동 도우미와 저장소 상태를 파악 → (2) 레시피를 종류별로 골라 보는 '카테고리 탭' 기능을 화면부터 데이터 저장소까지 한 번에 만듦 → (3) 코드 점검으로 찾은 버그 10건을 고치고, 목록 정렬·"더보기" 화면 방식을 논의**

---

## 이번에 한 일

**문서와 저장소 상태 파악**

- 남은 할 일 목록(`docs/backlog.md`)과 2주차 계획서를 읽고, 다음에 뭘 할지 후보를 뽑았습니다.
- 실제 코드 파일(`store.js`, `IngredientSheet.jsx` 등)을 직접 열어서, 문서에 적힌 내용과 실제로 만들어진 상태가 서로 맞는지 확인했습니다.
- 반복 작업을 대신 해주는 '자동 도우미'(정해진 순서대로 계획을 세워주는 보조 역할)를 하나 만들어서 불러보려 했는데, 이번 작업 시간에는 등록이 안 돼서 그 순서를 직접 손으로 따라가며 대신 확인했습니다.
- 진짜 공유용 저장소(`hub`)가 며칠 치(3일~6일 차) 작업까지 어디까지 진행됐는지 살펴봤습니다.

**레시피 '카테고리 탭' 기능 (화면 → 서버 → 데이터 저장소를 한 번에)**

- 레시피가 100개까지 늘어날 것에 대비해, 목록 화면 위쪽에 좌우로 밀어서 넘기는 종류별 탭 버튼(국·찌개, 반찬 등)을 넣었습니다.
- 데이터 저장소(레시피 표)에 '요리 종류'를 적어 둘 칸을 새로 추가했습니다.
- 나라에서 공개한 레시피 데이터를 가져올 때, 그 안에 들어 있는 종류 값을 뽑아서 우리 저장소에 맞게 채워 넣도록 수집 스크립트를 고쳤습니다.
- 사용자가 탭을 누르면 그 종류만 서버에 요청하고, 서버는 해당 종류에 맞는 레시피만 골라서 돌려주도록 화면–서버 양쪽을 연결했습니다.

**버그 수정 (코드 점검으로 찾은 10건 — 다 고치고 실제 화면에서 확인까지 끝)**

- 데이터 처리 담당 파일(`store.js`)에서 7건: 서버 응답을 기다리지 않고 넘어가던 문제, 데이터 저장소가 없을 때 대비책이 없던 문제, '기타'로 넣은 재료 이름이 사라지던 문제, 요리를 다 했는데 통조림·라면 같은 가공식품이 줄어들지 않던 문제, 장보기 묶음에서 요리 이름이 잘못 나오던 문제, 지운 재료를 다시 열면 앱이 멈추던 문제, 목록 범위 밖을 건드려 앱이 멈추던 문제.
- 식단 담당 파일에서: 껍데기만 남고 실제로 작동하지 않던 입력값 확인 기능을 되살렸습니다.
- 서버 없이 화면만 볼 때 쓰는 가짜 서버 파일에서: 함수 이름이 서로 안 맞던 것을 맞추고, 앱 멈춤을 막는 안전장치를 똑같이 넣었습니다.
- 인분 설정 화면에서: 숫자 `0`을 '값이 없다'로 잘못 판단하던 문제를 고쳤습니다.

**다음에 할 일 (아직 반영 안 됨)**

- 레시피 목록 순서를 "곧 상하는 재료를 쓰는 요리 먼저 → 지금 가진 재료가 많은 요리 순"으로 바꾸고, 처음엔 위에서 10~15개만 보여준 뒤 "더보기"를 눌러야 나머지가 펼쳐지게 하기. (반찬 종류만 49개라, 탭으로 걸러도 목록이 너무 길어지는 문제 때문입니다.)

## 내가 설명할 수 있는 것

**전체 구조**

- 화면 쪽과 서버 쪽이 왜 따로 나뉘어 있는지, 그리고 파일 한 줄만 바꾸면 '가짜 서버(연습용)'와 '진짜 서버'가 왜 서로 바뀌는지.
- 데이터 처리 파일이 진짜 데이터 저장소가 연결돼 있으면 거기서 읽고, 없으면 미리 넣어둔 예시 데이터로 대신 돌아가는 구조.
- 할 일에 우선순위(급한 것/다음 것/나중 것)를 매기는 이유와 기준.

**기능이 돌아가는 흐름**

- 화면에서 탭을 누르면, 그 선택을 기억해 뒀다가 선택이 바뀔 때마다 서버에 새 목록을 자동으로 다시 불러오는 흐름.
- 좁은 휴대폰 화면에서도 탭 버튼을 좌우로 밀어 넘길 수 있게 만드는 방법.
- 나라에서 받은 투박한 원본 데이터를 그대로 쓰지 않고, 중간에 다듬어서 우리 앱 기준(표준 재료 이름, 종류 이름)에 맞게 바꿔 저장하는 과정.

**도구와 버그**

- 자동 도우미가 '어떤 역할인지 적은 설명 + 지시문'이 담긴 간단한 글 파일 하나로 정해진다는 점.
- 남이 작업 중인 내용을 건드리지 않고, 내 작업만 따로 떼어 나란히 저장하는 방법.
- 이번에 고친 버그가 왜 버그였는지 (예: 서버 응답을 안 기다리고 넘어가면 왜 문제가 되는지).

## 아직 잘 모르는 것

**작업 환경과 협업 방식**

- 만든 자동 도우미가 왜 이번엔 바로 안 불러와졌는지 — 도우미 목록이 언제 정해지는지 정확한 규칙.
- 작업 도중 내 저장소가 5일 차에서 6일 차로 바뀐 이유 — 나 말고 누가/무엇이 동시에 건드리고 있었는지.
- 진짜 공유 저장소와 지금 내 폴더가 실제로 얼마나 달라져 있는지 (이번엔 파일을 하나하나 대조해 보진 않았음).

**데이터를 담는 방식**

- 진짜 데이터 저장소가 없을 때 왜 예시 데이터로 대신 돌아가게 만드는지, 그리고 그 대비책이 왜 여러 군데에 똑같이 반복되는지.
- 신선식품은 '숫자 + 단위'(예: 2개)로, 가공식품은 '자유롭게 쓴 글'(예: 반 봉지)로 나눠서 저장하는 이유.

**아직 안 만든 기능**

- 데이터 저장소 구조를 바꿀 때, 매번 직접 손으로 칸을 추가하는 것 말고 그 변경 내역을 차곡차곡 자동으로 기록·관리하는 체계.
- 목록을 아래로 내리면 다음 내용이 자동으로 계속 이어져 나오는 방식이, 실제로 화면과 서버가 데이터를 조금씩 나눠 주고받으며 어떻게 구현되는지.

## 새로 알게 된 것

**문서와 실제 코드가 어긋나 있던 것**

- 재고 수정 기능은 할 일 목록에는 '아직 안 됨'으로 적혀 있었는데, 실제로는 이미 다 만들어져 연결돼 있었습니다 — 문서가 코드보다 뒤처져 있었던 거죠.
- 공유 저장소가 '7월 9일 이후로 멈춰 있다'고 알고 있었는데, 사실은 5일·6일 차까지 활발히 진행되고 있었습니다.
- 다른 작업 흐름이 나 몰래 서버 쪽을 크게 바꿔놓은 걸 발견했습니다(데이터 저장소 연결, 여러 번 산 재료를 묶어 관리하는 방식, 인분 배수 기능). 그래서 함께 작업할 땐 "코드가 그새 바뀌어 있을 수 있다"를 늘 다시 확인해야 한다는 걸 배웠습니다.

**숨어 있던 버그·함정**

- 특정 설정값을 안 넣으면, 유통기한 남은 날짜를 계산하는 '오늘 날짜'가 7월 8일로 영원히 고정돼 버리는 문제가 있었습니다.
- 숫자 `0`이 정상적인 값인데도 '값이 없다'로 취급돼 다른 값으로 덮어써지는, 흔히 하는 실수를 확인했습니다.

**개발을 보는 눈**

- 화면에 '탭 버튼 하나' 붙이는 것처럼 보여도, 실제로는 ① 저장소에 칸 추가 ② 저장할 데이터 채우기 ③ 서버가 골라주는 방식 손보기 ④ 화면에서 요청할 때 조건 붙이기까지, 화면–서버–저장소를 한 줄로 다 뚫어야 비로소 기능이 완성된다는 걸 깨달았습니다.
- 나라에서 공개한, 언뜻 투박해 보이는 데이터도 잘 다듬으면 내 서비스에 딱 맞는 나만의 데이터로 다시 태어날 수 있다는 걸 배웠습니다.
