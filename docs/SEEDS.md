# 시드 예시 24개 (few-shot 원본)

> **상태: 검수 완료 (2026-07-20).** 상황 8개는 2026-07-08 사용자 확정. 24개 자체 스크리닝과 제3자 블라인드 정렬 8/8·전송 가능성 24/24 완료를 사용자가 승인했다. 검수자 식별정보·원시 검수지는 저장소에 보관하지 않는다. 스키마·작성 기준은 SPEC 4장, 작성·검수 절차는 `/seed` 스킬.
> 2차 개정 반영 사항: ① 전 시드에 `purpose` 태그, ② 톤 공통 라벨(toneLevel 1=기본, 2=더 부드럽게, 3=더 분명하게), ③ 사실 근거 규칙 — message의 모든 구체 사실(요일·시간)은 situationNote에 근거를 둠.
> T19에서 `api/_lib/prompt/seedExamples.ts`의 서버 전용 typed 카탈로그로 이관했다. 이 문서는 검수 원본이며 런타임은 타입 검증된 카탈로그를 사용한다.

## 검수 현황

| 단계 | 상태 |

| 자체 스크리닝 (금지 항목·세트 내 내용 동일성·톤 정합·사실 근거) | ✅ 2026-07-12 재통과 — 감사 3건(G-B tone3·P-A 전 톤·F-A tone3) 수정 후 24개 전수 재스크리닝 |

목적 커버리지: ask 1세트 / suggest 3 / question 1 / apologize 1 / other 2 / **decline 0 — 거절 시드는 이후 보강 후보** (목적은 프롬프트 지시로도 전달되므로 MVP 동작에는 지장 없음).

시드의 사유·사건은 모두 "실제 사실"을 가정한다 (몸살, 시스템 오류 등) — 허위 사유 생성 금지 원칙(EDGE_CASES 6-1).

## 자체 스크리닝 기록 (2026-07-08 최초, 2026-07-11 통과 철회, 2026-07-12 수정·재통과)

2026-07-11 제품 감사 발견 3건을 2026-07-12에 수정하고 24개 전수를 재스크리닝했다.

- G-B tone3: 목요일 확정·회신 기한을 제거하고 tone1·2와 같은 목·금 선택 요청으로 복원 — 세트 내용 동일성 회복
- P-A 전 톤: "첨부해 드리니/첨부하오니"의 행동 단정을 "바로 보내드릴 수 있는데"로 교체 — 상황노트(완성해 둔 상태)에 근거한 의사 표현만 남김
- F-A tone3: 상황에 없는 "내가 밥 살게" 약속을 제거하고 주말 만남 제안(노트 근거)만 유지
- 재스크리닝 관찰: P-B tone3은 "수업 내용 보충" 문장을 생략하나 결석 통보·확인서 제출이라는 핵심 내용은 동일 — 간결성(태도)으로 판정, 블라인드 정렬에서 재확인

- 플레이스홀더(`[...]`, `OO`) 잔존: **0건** — 시드는 상황노트로 사실을 충분히 제공하므로 자리 표시자 불필요 (SPEC 4장 사실 근거 규칙)
- **사실 근거**: message의 모든 구체 사실(금요일 마감, 목·금 후보 시간, 수·금 점심, 주말, 금요일 제안)이 situationNote에 근거함 — 전수 확인
