# 기능 명세

> 조리 팁은 현재 핵심 흐름의 저장·AI·API·ERD 범위에서 제외한 후속 기능이다.

## F-010 로그인

사용자는 자신의 레시피북을 사용하기 위해 로그인할 수 있다. 로그인한 사용자는 자신이 등록한 레시피, 전달받은 레시피, 개인 메모 등을 자신의 계정 기준으로 관리한다.

### 주요 목적

* 사용자별 개인 레시피북 구분
* 전달받은 레시피 저장
* 전해준 사람, 전달받은 날짜 등 관계 정보 저장
* 레시피 수정, 삭제, 공유 권한 판단

### MVP 기준

MVP 초기에는 Firebase Authentication의 Google 로그인만 제공한다. 로그인 성공 후 Firebase ID 토큰으로 사용자를 식별하고, 서버는 해당 사용자 기준으로 레시피북을 관리한다. 핵심 레시피 흐름이 완료된 뒤 같은 Firebase 계정에 이메일/비밀번호와 카카오 로그인을 추가한다.

---

## F-011 회원가입

사용자는 서비스를 처음 사용할 때 계정을 생성할 수 있다. 회원가입을 통해 사용자는 개인 레시피북을 가지게 되며, 이후 레시피 저장 및 공유 기능을 사용할 수 있다.

### 필요한 정보

* 이름 또는 닉네임
* 이메일
* 비밀번호 또는 소셜 로그인 정보

### MVP 기준

초기 MVP에서는 Google 로그인 시 Firebase가 계정을 생성하거나 기존 계정에 연결하므로 별도 회원가입 화면을 제공하지 않는다. 이메일/비밀번호 회원가입은 후속 인증 방식 추가 시 구현한다.

---

## F-020 레시피 목록

사용자는 자신의 레시피북에 저장된 레시피 목록을 확인할 수 있다. 목록에서는 사용자가 직접 등록한 레시피와 전달받은 레시피를 구분해서 보여준다.

### 표시 정보

* 레시피 이름
* 간단한 설명
* 레시피 유형

  * 직접 작성한 레시피
  * 외부 출처로 저장한 레시피
  * 전달받은 레시피
* 출처 정보
* 전해준 사람
* 전달받은 날짜
* 재공유 가능 여부

### 주요 기능

* 전체 레시피 목록 보기
* 내가 등록한 레시피 보기
* 전달받은 레시피 보기
* 레시피 카드 클릭 시 상세 화면으로 이동

### MVP 기준

MVP에서는 검색, 태그, 정렬 기능까지 자세히 구현하지 않아도 된다. 우선 레시피 카드 목록을 통해 사용자가 저장한 레시피를 한눈에 볼 수 있도록 한다.

---

## F-021 레시피 상세

사용자는 저장된 레시피의 상세 내용을 확인할 수 있다. 레시피 상세 화면은 실제 조리할 때 참고할 수 있도록 재료와 조리 순서를 명확하게 보여준다.

### 표시 정보

* 레시피 이름
* 레시피 설명
* 기준 인원
* 예상 조리 시간
* 재료 목록
* 조리 순서
* 출처 정보
* 열람 링크 상태
* 공유 상태
* 전해준 사람
* 전달받은 날짜
* 재공유 가능 여부
* 내 메모

### 레시피 유형별 차이

직접 작성한 레시피와 외부 출처로 저장한 레시피는 사용자가 수정, 삭제, 공유할 수 있다. 전달받은 레시피는 원본 내용을 수정하거나 재공유할 수 없으며, 개인 메모 작성과 내 레시피북에서 제거만 가능하다.

---

## F-030 레시피 추가

사용자는 새로운 레시피를 자신의 레시피북에 추가할 수 있다. 레시피는 직접 작성하거나 외부 URL을 입력하는 방식으로 추가할 수 있다.

### 추가 방식

* 직접 입력

  * 사용자가 자유로운 문장으로 레시피를 작성한다.
  * 예: “김치를 적당히 넣고 돼지고기랑 볶다가 물 넣고 끓인다.”
* URL 입력

  * 유튜브, 블로그, 웹페이지 등의 URL을 입력한다.
  * 입력한 URL은 레시피의 출처로 함께 저장된다.

### 주요 흐름

1. 사용자가 레시피 추가 화면에 진입한다.
2. URL 또는 레시피 원문을 입력한다.
4. AI 정리 요청을 실행한다.
5. AI 정리 결과 확인 화면으로 이동한다.

### MVP 기준

MVP에서는 실제 영상 분석이나 웹페이지 크롤링을 완벽하게 구현하지 않아도 된다. 프로토타입에서는 사용자가 URL 또는 텍스트를 입력하면 미리 준비된 AI 정리 결과 예시가 나타나는 방식으로 흐름을 표현한다.

---

## F-031 레시피 AI 정리

입력된 레시피 내용을 AI가 조리하기 쉬운 구조로 정리한다. 자유로운 문장이나 외부 URL 기반 내용을 음식 이름, 재료, 계량, 조리 순서 등으로 변환한다.

### AI 정리 항목

* 음식 이름
* 간단한 설명
* 기준 인원
* 예상 조리 시간
* 재료
* 재료별 수량
* 조리 순서
* 확인이 필요한 항목
* 출처 정보

### 확인이 필요한 항목 예시

* “김치를 적당히” → 약 2컵 기준으로 정리했습니다.
* “물은 자작하게” → 약 500ml 기준으로 정리했습니다.
* “간장 조금” → 1큰술 기준으로 정리했습니다.

### 주요 원칙

AI가 정리한 결과는 자동으로 저장되지 않는다. 사용자는 AI가 정리한 내용을 확인하고 수정한 뒤 저장한다.

---

## F-032 레시피 정리 결과 확인

사용자는 AI가 정리한 레시피 결과를 저장하기 전에 확인할 수 있다. 이 화면은 AI 결과를 검토하고, 잘못된 부분이나 개인 취향에 맞지 않는 부분을 수정하는 단계이다. 각 항목은 화면에서 바로 수정할 수 있다.

### 표시 정보

* 음식 이름
* 레시피 설명
* 기준 인원
* 예상 조리 시간
* 재료 목록
* 조리 순서
* 확인이 필요한 항목
* 출처 URL
* 저장 버튼

### 주요 기능

* AI 정리 결과 확인
* 레시피 제목 수정
* 재료 및 수량 수정
* 조리 순서 수정
* 확인 필요 항목 확인
* 저장 여부 결정

### MVP 기준

프로토타입에서는 모든 항목을 실제로 편집 가능하게 만들 필요는 없다. 다만 사용자가 “AI 결과를 확인하고 수정한 뒤 저장한다”는 흐름을 이해할 수 있도록 수정 버튼과 저장 버튼을 제공한다.

---

## F-033 레시피 저장

사용자는 AI 정리 결과를 확인한 뒤 자신의 레시피북에 저장할 수 있다. 저장된 레시피는 이후 레시피 목록과 상세 화면에서 다시 확인할 수 있다.

### 저장되는 정보

* 레시피 제목
* 설명
* 기준 인원
* 예상 조리 시간
* 재료
* 조리 순서
* 출처 URL
* 출처 제목
* 출처 작성자 또는 채널명
* 레시피 유형
* 생성일
* 수정일

### 레시피 유형

* 직접 작성한 레시피
* 외부 출처로 저장한 레시피
* 전달받은 레시피

### MVP 기준

MVP에서는 실제 DB 저장이 구현되지 않더라도, 프로토타입에서 저장 버튼 클릭 후 레시피북 목록에 추가된 것처럼 보여주면 된다.

## F-040 열람 공유

사용자는 자신이 등록한 레시피를 다른 사람이 볼 수 있도록 열람 링크를 생성할 수 있다. 열람 공유는 상대방이 레시피를 보기만 하는 방식이며, 상대방의 레시피북에 저장되지는 않는다.

### 주요 특징

* 링크를 가진 사람은 레시피를 열람할 수 있다.
* 열람자는 해당 레시피를 자신의 레시피북에 저장할 수 없다.
* 열람자는 해당 레시피를 수정할 수 없다.
* 열람자는 해당 레시피를 재공유할 수 없다.
* 열람 공유에서는 관계 정보가 저장되지 않는다.
* 레시피 주인은 열람 링크를 비활성화할 수 있다.

### 처리 규칙

* 내가 등록한 레시피만 열람 공유할 수 있다.
* 전달받은 레시피는 열람 공유할 수 없다.
* 링크가 비활성화된 경우 열람자는 레시피를 볼 수 없다.
* 열람 링크로 접근한 사용자는 로그인 여부와 관계없이 보기 전용 화면만 볼 수 있다.

### 사용 예시

성준이 자신이 저장한 감자조림 레시피의 열람 링크를 만든다.
친구는 링크를 통해 감자조림 레시피를 볼 수 있지만, 자신의 레시피북에 저장하거나 다시 공유할 수는 없다.

### MVP 기준

MVP에서는 열람 링크 생성 후 공유 화면을 보여주는 수준으로 구현한다.
프로토타입에서는 실제 링크 권한 검증을 완전하게 구현하지 않아도 되며, 열람 전용 화면으로 이동하는 흐름을 중심으로 표현한다.

## F-041 전달 공유

사용자는 자신이 등록한 레시피를 다른 사용자가 자신의 레시피북에 저장할 수 있도록 전달 초대를 생성할 수 있다. 전달 공유는 열람 공유와 달리, 받은 사용자가 수락하면 해당 레시피가 자신의 레시피북에 저장되는 방식이다.

### 주요 특징

* 내가 등록한 레시피만 전달 공유할 수 있다.
* 전달받은 레시피는 다시 전달 공유할 수 없다.
* 전달 공유를 실행하면 하나의 전달 초대가 생성된다.
* 전달 초대에는 전달 링크와 초대 코드가 함께 제공된다.
* 전달 링크와 초대 코드는 같은 전달 초대 정보를 가리킨다.
* 전달 초대는 생성 시점의 레시피 스냅샷을 가진다.
* 전달 링크와 초대 코드는 1회 저장 후 만료된다.
* 전달받은 레시피는 재공유할 수 없다.

### 생성되는 정보

* 전달 초대 ID
* 원본 레시피 ID
* 레시피 스냅샷
* 원 저장자 정보
* 전달자 정보
* 전달 링크
* 초대 코드
* 사용 여부
* 만료 여부
* 생성일

### 처리 규칙

* 전달 초대 생성 시점의 레시피 내용을 스냅샷으로 저장한다.
* 원본 레시피가 이후 수정되더라도 이미 생성된 전달 초대의 스냅샷 내용은 변경되지 않는다.
* 전달 초대는 한 명의 사용자가 수락하여 저장하면 사용 완료 상태가 된다.
* 이미 사용 완료된 초대는 다시 사용할 수 없다.
* 전달받은 레시피는 다시 열람 공유하거나 전달 공유할 수 없다.

### 사용 예시

엄마가 자신이 등록한 김치찌개 레시피의 전달 초대를 생성한다.
성준이는 전달 링크 또는 초대 코드를 통해 김치찌개 레시피를 미리 확인하고, 수락하면 자신의 레시피북에 저장할 수 있다.

### MVP 기준

MVP에서는 실제 사용자 간 전달 시스템을 완전하게 구현하지 않아도 된다.
프로토타입에서는 전달 초대 생성 화면, 전달 링크와 초대 코드 표시, 전달받은 레시피 미리보기 화면으로 이어지는 핵심 흐름을 표현한다.

## F-042 전달 초대 접근

사용자는 전달 링크 또는 초대 코드를 통해 전달받은 레시피 미리보기 화면으로 진입할 수 있다. 전달 링크와 초대 코드는 같은 전달 초대 정보를 가리키며, 접근 방식만 다르다.

### 진입 방식

* 전달 링크 접속
* 초대 코드 입력

### 주요 특징

* 전달 링크로 접속한 경우 해당 전달 초대 정보를 바로 확인한다.
* 초대 코드로 접근하는 경우 사용자는 별도 코드 입력 화면 또는 모달에서 코드를 입력한다.
* 유효한 전달 링크 또는 초대 코드인 경우 전달받은 레시피 미리보기 화면으로 이동한다.
* 전달받은 레시피 미리보기 단계에서는 아직 레시피가 내 레시피북에 저장되지 않는다.

### 링크 접근 처리 규칙

* 유효한 전달 링크인 경우 전달받은 레시피 미리보기 화면으로 이동한다.
* 존재하지 않는 링크인 경우 오류 화면을 보여준다.
* 이미 사용된 전달 링크인 경우 접근할 수 없다.
* 만료된 전달 링크인 경우 접근할 수 없다.
* 전달 공유를 수락하려면 로그인이 필요하다.
* 로그인하지 않은 사용자가 전달 링크로 접근하면 로그인 화면으로 이동하고, 로그인 후 다시 전달받은 레시피 미리보기 화면으로 돌아온다.

### 코드 입력 처리 규칙

* 레시피 추가 화면에는 초대 코드 입력창을 직접 두지 않는다.
* 레시피 추가 화면에는 “전달받은 레시피가 있나요? 코드로 불러오기” 같은 진입 문구만 제공한다.
* 사용자가 진입 문구를 누르면 전달 초대 코드 입력 화면 또는 모달로 이동한다.
* 초대 코드는 비어 있을 수 없다.
* 유효한 초대 코드인 경우 전달받은 레시피 미리보기 화면으로 이동한다.
* 이미 사용된 코드는 사용할 수 없다.
* 만료된 코드는 사용할 수 없다.
* 잘못된 코드는 오류 메시지를 보여준다.

### 예외 메시지 예시

* 유효하지 않은 전달 링크입니다.
* 유효하지 않은 초대 코드입니다.
* 이미 사용된 초대입니다.
* 만료된 초대입니다.
* 초대 코드를 입력해 주세요.

### MVP 기준

MVP에서는 실제 링크와 코드 검증 로직을 완전하게 구현하지 않아도 된다.
프로토타입에서는 전달 링크 접속 또는 초대 코드 입력 후 전달받은 레시피 미리보기 화면으로 이동하는 흐름을 중심으로 표현한다.

## F-043 전달받은 레시피 미리보기

사용자는 전달 링크 또는 초대 코드를 통해 전달받은 레시피를 저장하기 전에 미리 확인할 수 있다. 이 단계에서는 아직 레시피가 자신의 레시피북에 저장되지 않는다.

### 주요 특징

* 사용자는 전달받은 레시피 내용을 미리 확인할 수 있다.
* 사용자는 수락 또는 거절을 선택할 수 있다.
* 수락하기 전에는 관계 정보 입력 영역을 보여주지 않는다.
* 수락한 경우에만 전해준 사람, 관계 라벨, 내 메모 입력 영역을 보여준다.
* 거절한 경우 레시피는 저장되지 않는다.

### 표시 정보

* 공유한 사용자 정보
* 원 저장자 정보
* 레시피 이름
* 설명
* 기준 인원
* 예상 조리 시간
* 재료 목록
* 조리 순서
* 출처 정보
* 재공유 불가 안내

### 초기 상태 화면 요소

* 레시피 미리보기
* 수락 버튼
* 거절 버튼

### 수락 후 화면 요소

* 전해준 사람 입력창
* 관계 라벨 입력창
* 내 메모 입력창
* 내 레시피북에 저장하기 버튼
* 취소 버튼

### 처리 규칙

* 전달받은 레시피 미리보기 단계에서는 레시피가 저장되지 않는다.
* 사용자가 거절한 경우 레시피는 내 레시피북에 저장되지 않는다.
* MVP에서는 거절만으로 초대를 만료시키지 않는다.
* 초대는 수락 후 저장이 완료될 때만 만료 처리한다.

### MVP 기준

MVP에서는 전달받은 레시피 내용을 확인하고, 수락 또는 거절을 선택하는 흐름을 표현한다.
수락 후 관계 정보 입력 영역이 나타나는 상태 변화를 보여주는 것이 핵심이다.

## F-044 전달받은 레시피 저장

사용자는 전달받은 레시피를 수락한 뒤 관계 정보를 입력하고 자신의 레시피북에 저장할 수 있다. 저장된 레시피는 전달받은 레시피로 분류되며, 원본 내용은 수정할 수 없다.

### 저장 시 입력 정보

* 전해준 사람 표시 이름
* 관계 라벨
* 내 메모

### 저장되는 정보

* 원 저장자 정보
* 전달자 정보
* 전해준 사람 표시 이름
* 관계 라벨
* 전달받은 날짜
* 레시피 스냅샷
* 내 메모
* 재공유 가능 여부: 불가능

### 처리 규칙

* 전해준 사람 표시 이름은 필수 입력값이다.
* 관계 라벨은 필수 입력값이다.
* 내 메모는 선택 입력값이다.
* 저장이 완료되면 전달 초대는 사용 완료 상태가 된다.
* 저장된 레시피는 전달받은 레시피로 분류된다.
* 전달받은 레시피의 원본 내용은 수정할 수 없다.
* 전달받은 레시피에는 개인 메모만 작성하거나 수정할 수 있다.
* 전달받은 레시피는 열람 공유 또는 전달 공유할 수 없다.

### 사용 예시

성준이는 엄마가 보낸 김치찌개 전달 링크를 열고 레시피를 확인한다.
저장할 때 전해준 사람을 “엄마”, 관계 라벨을 “엄마의 레시피”로 입력한다.
저장 후 성준이의 레시피북에는 해당 레시피가 전달받은 레시피로 표시된다.

### MVP 기준

MVP에서는 관계 정보 입력 후 전달받은 레시피 상세 화면으로 이동하는 흐름을 표현한다.
실제 DB 저장이 구현되지 않더라도, 프로토타입에서는 전달받은 레시피가 내 레시피북에 추가된 것처럼 보여준다.

## F-050 메모

사용자는 저장된 레시피에 개인 메모를 남길 수 있다. 메모는 사용자의 개인적인 조리 경험이나 다음에 수정하고 싶은 점을 기록하기 위한 기능이다.

### 주요 목적

* 개인 취향 기록
* 조리 중 느낀 점 저장
* 다음 조리 시 참고할 내용 작성
* 전달받은 레시피를 나만의 경험으로 확장

### 예시

* 다음에는 두부를 더 많이 넣기
* 고춧가루는 반 스푼만 넣어도 충분함
* 국물이 진해서 밥이랑 잘 어울림

### 레시피 유형별 메모 정책

* 내가 등록한 레시피: 메모 작성 가능
* 전달받은 레시피: 메모 작성 가능
* 링크로 열람 중인 레시피: 메모 작성 불가

### MVP 기준

MVP에서는 레시피 상세 화면에 메모 영역을 제공한다. 실제 저장 기능이 없더라도, 프로토타입에서는 메모를 작성할 수 있는 영역을 보여준다.

## F-051 조리 중 보기

사용자는 레시피 상세 화면에서 조리 중 보기 상태를 켤 수 있다. 조리 중 보기는 별도의 조리 모드 화면이 아니라, 레시피 상세 화면에서 관리성 버튼을 숨기고 레시피 내용에 집중할 수 있도록 하는 보기 상태이다.

### 주요 목적

* 조리 중 실수로 수정, 삭제, 공유 버튼을 누르는 일을 방지한다.
* 사용자가 레시피 내용에 집중할 수 있게 한다.
* 별도 조리 모드 화면 없이 모바일 주방 사용성을 보완한다.

### 조리 중 보기 ON 상태에서 숨기는 요소

* 수정 버튼
* 삭제 버튼
* 열람 공유 버튼
* 전달 공유 버튼
* 내 레시피북에서 제거 버튼

### 조리 중 보기 ON 상태에서 유지하는 요소

* 레시피 이름
* 설명
* 기준 인원
* 예상 조리 시간
* 재료 목록
* 조리 순서
* 출처 정보
* 내 메모
* 조리 중 보기 종료 버튼

### 처리 규칙

* 조리 중 보기는 레시피 내용을 수정하지 않는다.
* 조리 중 보기는 화면 표시 상태만 변경한다.
* 사용자는 언제든 조리 중 보기를 종료할 수 있다.
* 조리 중 보기 상태에서도 레시피 내용, 재료, 조리 순서, 메모는 확인할 수 있다.

### MVP 기준

MVP에서는 단계별 조리 모드, 타이머, 음성 조작, 화면 꺼짐 방지 기능은 구현하지 않는다. 조리 중 보기 토글을 통해 상세 화면에서 방해 요소를 줄이는 수준으로 제공한다.


## F-060 레시피 수정

사용자는 자신이 등록한 레시피를 수정할 수 있다. 수정 기능은 AI가 정리한 결과를 보완하거나, 사용자의 취향에 맞게 레시피를 업데이트하기 위해 필요하다.

### 수정 가능한 항목

* 레시피 제목
* 설명
* 기준 인원
* 예상 조리 시간
* 재료
* 수량
* 조리 순서
* 출처 정보
* 열람 링크 상태
* 공유 상태
* 메모

### 레시피 유형별 수정 정책

* 직접 작성한 레시피: 수정 가능
* 외부 출처로 저장한 레시피: 수정 가능
* 전달받은 레시피: 원본 내용 수정 불가, 개인 메모만 수정 가능
* 링크로 열람 중인 레시피: 수정 불가

### MVP 기준

MVP에서는 모든 항목의 완전한 편집 기능을 구현하지 않아도 된다. 우선 수정 버튼과 수정 화면의 흐름을 보여주고, 핵심 항목 일부만 수정 가능하게 해도 충분하다.

## F-061 레시피 삭제

사용자는 더 이상 보관하고 싶지 않은 레시피를 삭제하거나 자신의 레시피북에서 제거할 수 있다. 삭제는 레시피 유형에 따라 의미가 다르다.

### 내가 등록한 레시피 삭제

사용자가 직접 작성했거나 외부 출처로 저장한 레시피는 삭제할 수 있다. 삭제하면 사용자의 레시피북에서 사라진다.

### 전달받은 레시피 제거

전달받은 레시피는 원본을 삭제하는 것이 아니라, 자신의 레시피북에서 제거하는 방식으로 처리한다. 제거해도 원 작성자의 레시피나 다른 사용자가 전달받은 레시피에는 영향을 주지 않는다.

### 링크로 열람 중인 레시피

링크로 열람 중인 레시피는 사용자의 레시피북에 저장된 상태가 아니므로 삭제 대상이 아니다.

### MVP 기준

MVP에서는 삭제와 제거를 구분해서 표현한다.

* 내가 등록한 레시피: 삭제
* 전달받은 레시피: 내 레시피북에서 제거

이를 통해 원본 레시피와 전달받은 기록의 관계를 명확하게 유지한다.
