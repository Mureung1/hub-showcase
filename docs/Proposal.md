# 1. 문제 정의

## 1.1 배경

사람들은 인터넷과 모바일 서비스를 이용하다가 기억하거나, 다시 보거나, 다른 사람에게 공유하기 위해 화면을 캡처한다.

캡처하는 대상은 매우 다양하다.

- 온라인 쇼핑 주문내역
- 구독 결제 화면
- 관심 있는 상품
- 카카오톡 공지
- 약속 일정
- 맛집과 여행지
- 디자인 레퍼런스
- 공부 자료
- 코드와 오류 화면
- 웃긴 사진과 짤
- 계좌번호와 주소
- 기프티콘과 쿠폰
- 나중에 보고 싶은 게시물

스크린샷은 별도의 입력 과정 없이 현재 화면을 그대로 저장할 수 있기 때문에 가장 쉽고 빠른 임시 저장 수단으로 사용된다.

## 1.2 현재의 문제

사용자는 정보를 저장하기 위해 캡처하지만, 캡처 이후의 정리는 직접 해야 한다.

사진첩에서는 구매내역, 구독 화면, 일정, 맛집, 짤, 디자인 참고 이미지가 모두 동일한 이미지 형태로 쌓인다.

이로 인해 다음과 같은 문제가 발생한다.

### 캡처의 목적을 잊는다

캡처 당시에는 저장할 이유가 있었지만 시간이 지나면 왜 캡처했는지 기억하지 못한다.

### 필요한 캡처를 다시 찾기 어렵다

파일명과 폴더가 자동으로 생성되기 때문에 정확한 날짜를 모르면 원하는 이미지를 찾기 어렵다.

### 중요한 정보가 이미지 안에 갇힌다

결제금액, 구독 갱신일, 약속 날짜, 장소, 상품명 등 중요한 정보가 이미지 안에만 존재한다.

사용자가 직접 읽고 메모하거나 캘린더에 옮기지 않으면 활용되지 않는다.

### 관련된 캡처가 서로 연결되지 않는다

같은 구독 서비스의 가입 화면, 결제 화면, 해지 화면을 각각 캡처하더라도 사진첩에서는 별개의 이미지로 저장된다.

같은 상품의 상세페이지, 주문 완료 화면, 실제 구매 화면도 하나의 기록으로 이어지지 않는다.

### 캡처가 쌓일수록 정리 비용이 증가한다

사용자가 직접 앨범을 만들고, 제목과 태그를 입력하고, 필요 없는 캡처를 삭제해야 한다.

정리하려고 캡처했지만 오히려 정리해야 할 데이터가 계속 늘어나는 문제가 생긴다.

## 1.3 기존 해결 방식

사용자는 현재 다음과 같은 방식으로 중요한 정보를 임시 저장한다.

- 사진첩에 스크린샷 저장
- 카카오톡 나와의 채팅에 전송
- 메모장에 링크 붙여넣기
- 브라우저 탭을 닫지 않고 유지
- SNS 게시물 저장 또는 좋아요
- 쇼핑몰 장바구니와 찜 사용
- 캘린더와 알람에 직접 등록
- 메시지와 이메일을 읽지 않은 상태로 유지

하지만 저장 위치가 여러 서비스에 분산되어 있고, 사용자가 직접 분류하고 다시 찾아야 한다.

## 1.4 해결하려는 핵심 문제

> 사용자는 정보를 기억하기 위해 캡처하지만, 캡처된 정보는 자동으로 정리되거나 활용되지 않는다.

본 서비스는 캡처를 단순 이미지가 아니라 검색하고 활용할 수 있는 정보로 변환한다.

사용자는 화면을 캡처해 서비스에 보내기만 한다.

AI가 캡처의 내용과 목적을 분석하여 자동으로 분류하고, 구조화하고, 관련 캡처를 연결한다.

필요한 경우 일정 알림, 구독비 집계, 구매내역 정리와 같은 후속 기능을 제공한다.

## 1.5 서비스가 제공하는 해결 방식

```text
기존 방식

캡처
→ 사진첩에 저장
→ 쌓임
→ 목적을 잊음
→ 다시 찾지 못함
```

```text
서비스 이용 방식

캡처
→ 서비스에 공유
→ AI가 자동 분석
→ 적절한 컬렉션에 저장
→ 검색·알림·집계로 재활용
```

## 1.6 핵심 가치

### 사용자는 정리하지 않아도 된다

폴더, 제목, 카테고리, 태그를 직접 설정하지 않아도 된다.

### 캡처한 이유를 AI가 이해한다

이미지에 무엇이 있는지만 분석하는 것이 아니라, 사용자가 왜 캡처했는지를 추론한다.

### 필요한 순간에 다시 찾을 수 있다

파일명이나 캡처 날짜를 몰라도 자연어로 원하는 정보를 검색할 수 있다.

### 이미지가 실제 정보로 전환된다

구매내역, 구독정보, 일정, 장소 등은 이미지가 아니라 구조화된 카드 형태로 저장된다.

# 2. 사용자 시나리오

## 2.1 기본 사용자 시나리오

### 상황

사용자는 모바일 서비스를 이용하다가 나중에 다시 보고 싶은 정보를 발견한다.

### 사용자 행동

1. 사용자가 현재 화면을 캡처한다.
2. 휴대폰 공유 메뉴에서 서비스를 선택한다.
3. 캡처가 서비스의 인박스로 전달된다.
4. AI가 이미지의 내용과 저장 목적을 분석한다.
5. AI가 적절한 카테고리와 태그를 자동으로 지정한다.
6. 캡처 유형에 따라 주요 정보를 구조화한다.
7. 사용자에게 저장 결과를 짧게 보여준다.
8. 사용자는 필요한 경우에만 결과를 수정한다.
9. 이후 자연어 검색이나 자동 생성된 컬렉션을 통해 캡처를 다시 확인한다.

### 저장 결과 예시

```text
웃긴 짤로 저장했어요.

#개발자
#야근
#고양이
```

```text
Netflix 구독으로 저장했어요.

월 17,000원
매월 21일 결제

현재 월 구독료
68,700원
```

```text
온라인 구매내역으로 저장했어요.

무신사
나이키 페가수스 41
129,000원
```

## 2.2 온라인 구매내역 저장 시나리오

### 상황

사용자가 온라인 쇼핑몰에서 상품을 구매한 후 주문 완료 화면을 캡처한다.

### 사용자 흐름

1. 사용자가 주문 완료 화면을 캡처한다.
2. 캡처를 서비스에 공유한다.
3. AI가 구매처, 상품명, 옵션, 금액, 구매일을 추출한다.
4. 구매내역 컬렉션에 자동 저장한다.
5. 같은 상품이나 같은 주문과 관련된 기존 캡처가 있으면 하나의 기록으로 연결한다.
6. 사용자는 나중에 구매내역을 검색하거나 월별 구매금액을 확인한다.

### 저장되는 정보

- 구매처
- 상품명
- 상품 옵션
- 결제금액
- 구매일
- 주문번호
- 상품 카테고리
- 원본 캡처

### 이용 예시

```text
사용자 질문

“지난달에 무신사에서 산 운동화 찾아줘.”
```

```text
검색 결과

나이키 페가수스 41
무신사
129,000원
2026년 6월 18일 구매
```

## 2.3 구독 관리 시나리오

### 상황

사용자가 새로운 구독 서비스를 신청한 뒤 결제 또는 가입 완료 화면을 캡처한다.

### 사용자 흐름

1. 사용자가 구독 가입 화면을 캡처한다.
2. 캡처를 서비스에 공유한다.
3. AI가 서비스명, 구독료, 결제주기, 시작일, 다음 결제일을 추출한다.
4. 구독 컬렉션에 자동 저장한다.
5. 모든 구독 서비스의 월 결제금액을 합산한다.
6. 다음 결제일이 가까워지면 사용자에게 알려준다.
7. 사용자가 해지 화면을 캡처하면 기존 구독과 연결한다.
8. 해지일과 실제 이용 종료일을 업데이트한다.

### 저장되는 정보

- 구독 서비스명
- 요금제
- 결제금액
- 결제주기
- 이용 시작일
- 다음 결제일
- 해지일
- 이용 가능 마지막 날짜
- 현재 상태

### 구독 상태

- 무료 체험 중
- 이용 중
- 해지 예정
- 해지 완료
- 일시 중지

### 이용 예시

```text
Netflix Premium

월 17,000원
매월 21일 결제

상태
이용 중
```

해지 화면을 추가로 캡처하면 다음과 같이 변경된다.

```text
Netflix Premium

해지일
7월 13일

이용 가능
7월 20일까지

상태
해지 예정
```

### 구독 집계 예시

```text
이번 달 구독료

총 68,700원

Netflix          17,000원
YouTube Premium  14,900원
ChatGPT Plus     29,000원
iCloud            8,800원
```

## 2.4 일정 및 공지 저장 시나리오

### 상황

사용자가 카카오톡 단체방에서 약속 또는 과제 공지를 확인한다.

### 사용자 흐름

1. 공지 또는 대화 화면을 캡처한다.
2. 캡처를 서비스에 공유한다.
3. AI가 날짜, 시간, 장소, 준비물과 마감일을 추출한다.
4. 일정 카드로 자동 저장한다.
5. 사용자에게 캘린더 등록 또는 알림 설정을 제안한다.
6. 사용자는 필요한 기능만 선택한다.

### 저장 결과 예시

```text
프로젝트 회의

7월 18일 오후 7시
동성로 카페 1984

준비물

```

### 사용자가 선택할 수 있는 행동

- 캘린더에 추가
- 하루 전 알림
- 할 일로 등록
- 그대로 보관

## 2.5 일반 이미지 및 짤 저장 시나리오

### 상황

사용자가 인터넷에서 웃긴 사진이나 나중에 다시 보고 싶은 이미지를 발견한다.

### 사용자 흐름

1. 사용자가 이미지를 캡처한다.
2. 캡처를 서비스에 공유한다.
3. AI가 이미지의 주제, 감정, 상황과 주요 문구를 분석한다.
4. 자동으로 태그를 생성한다.
5. 유사한 이미지가 있는 컬렉션에 저장한다.
6. 사용자는 나중에 자연어 검색으로 이미지를 찾는다.

### 저장 결과 예시

```text
웃긴 짤로 저장했어요.

#개발자
#월요일
#퇴근
#현타
```

### 검색 예시

```text
“전에 저장한 개발자 야근 짤 찾아줘.”
```

## 2.6 관심 상품 저장 시나리오

### 상황

사용자가 상품을 바로 구매하지는 않지만 관심이 있어 상품 화면을 캡처한다.

### 사용자 흐름

1. 상품 상세 화면을 캡처한다.
2. AI가 상품명, 브랜드, 가격과 카테고리를 추출한다.
3. 구매내역이 아닌 관심 상품으로 저장한다.
4. 이후 같은 상품의 주문 완료 화면을 캡처하면 기존 관심 상품과 연결한다.
5. 관심 상품 상태를 구매 완료로 변경한다.

### 상태 흐름

```text
관심 상품
→ 구매 고려
→ 구매 완료
```

## 2.7 자연어 검색 시나리오

### 상황

사용자가 이전에 저장한 캡처를 다시 찾고 싶지만 파일명과 날짜를 기억하지 못한다.

### 사용자 흐름

1. 사용자가 검색창에 기억나는 특징을 입력한다.
2. AI가 이미지 내용, OCR 텍스트, 자동 태그와 구조화된 정보를 함께 검색한다.
3. 관련도가 높은 캡처와 컬렉션을 보여준다.

### 검색 예시

- 지난달에 산 운동화 찾아줘.
- 내가 구독 중인 AI 서비스가 뭐야?
- 부산에 저장한 카페 보여줘.
- 파란색 대시보드 디자인 찾아줘.
- 강아지가 나오는 웃긴 짤 보여줘.
- 다음 주에 결제되는 구독 알려줘.

# 3. 핵심 기능

기능을 넓게 구현하지 않고, 문제 정의를 직접 해결하는 세 가지 기능에 집중한다.

## 핵심 기능 1. 캡처 수집

### 기능 목적

사용자가 기존 행동을 크게 바꾸지 않고 캡처를 서비스에 저장할 수 있도록 한다.

### 주요 기능

- 스크린샷 업로드
- 휴대폰 공유 메뉴를 통한 캡처 전달
- 여러 장의 캡처 동시 업로드
- 원본 이미지 보관
- 최근 업로드한 캡처 확인
- 분석 중·분석 완료·확인 필요 상태 표시

### 핵심 사용자 경험

```text
캡처
→ 공유
→ 저장 완료
```

사용자에게 제목, 폴더, 태그 입력을 요구하지 않는다.

### 필수 조건

- 세 번 이내의 사용자 행동으로 저장이 완료되어야 한다.
- 사용자가 앱을 먼저 열 필요가 없어야 한다.
- 저장 직후 AI가 처리한 결과를 짧게 보여줘야 한다.
- AI가 확신하지 못한 경우에만 사용자에게 확인받아야 한다.

### AI가 애매하게 판단한 경우

```text
이 캡처는 어떤 용도로 저장할까요?

[관심 상품]
[구매 기록]
[그냥 보관]
```

---

## 핵심 기능 2. AI 자동 정리

### 기능 목적

스크린샷을 단순 이미지가 아니라 검색하고 활용할 수 있는 정보로 변환한다.

### 2.1 캡처 내용 분석

AI가 이미지에서 다음 정보를 분석한다.

- 이미지 속 텍스트
- 사용 중인 앱 또는 서비스
- 상품과 브랜드
- 날짜와 시간
- 금액
- 장소
- 주요 인물과 사물
- 이미지의 분위기와 상황
- 구매·구독·일정 등 정보 유형

### 2.2 캡처 목적 추론

AI는 이미지에 무엇이 있는지만 확인하지 않고, 사용자가 왜 해당 화면을 캡처했는지 추론한다.

### 캡처 목적 유형

- 구매 기록
- 구독 기록
- 일정 및 마감
- 관심 상품
- 장소 저장
- 참고 자료
- 나중에 볼 콘텐츠
- 웃긴 이미지
- 증거 및 기록
- 일반 보관

### 2.3 자동 분류

분석 결과에 따라 적절한 컬렉션에 자동 저장한다.

### 기본 컬렉션

- 구매
- 구독
- 일정
- 관심 상품
- 장소
- 참고 자료
- 웃긴 이미지
- 일반 보관

사용자가 직접 폴더를 만들지 않아도 된다.

### 2.4 정보 구조화

캡처 유형에 따라 이미지 속 정보를 카드 형태로 변환한다.

#### 구매 카드

- 구매처
- 상품명
- 옵션
- 금액
- 구매일

#### 구독 카드

- 서비스명
- 금액
- 결제주기
- 다음 결제일
- 해지일
- 이용 종료일
- 상태

#### 일정 카드

- 일정명
- 날짜
- 시간
- 장소
- 준비물
- 마감일

#### 일반 이미지 카드

- 이미지 설명
- 주요 문구
- 자동 태그
- 관련 컬렉션

### 2.5 관련 캡처 연결

같은 상품, 구독, 일정 또는 프로젝트에 관한 캡처를 하나의 기록으로 연결한다.

#### 구독 연결 예시

```text
가입 화면
→ 결제 화면
→ 해지 화면
```

세 장의 캡처를 하나의 구독 카드에 연결한다.

```text
YouTube Premium

가입
6월 1일

최근 결제
7월 1일 / 14,900원

해지
7월 10일

이용 가능
7월 31일까지
```

#### 구매 연결 예시

```text
상품 상세 화면
→ 주문 완료 화면
→ 실제 구매 기록
```

각 캡처를 별개의 이미지로 보관하는 것이 아니라 하나의 구매 흐름으로 관리한다.

### 2.6 사용자 확인 및 수정

AI 분석 결과가 실제 일정이나 결제에 영향을 줄 수 있으므로 사용자가 확인할 수 있어야 한다.

```text
다음 결제일을 8월 13일로 인식했습니다.

[맞아요]
[수정하기]
```

신뢰도가 낮은 정보는 자동 알림이나 집계에 바로 반영하지 않는다.

## 핵심 기능 3. 검색 및 재활용

### 기능 목적

저장된 캡처를 필요할 때 다시 찾고 실제로 사용할 수 있도록 한다.

### 3.1 자연어 검색

사용자는 캡처 날짜, 파일명과 정확한 문구를 기억하지 않아도 된다.

이미지의 내용, OCR 텍스트, 태그와 구조화된 정보를 통합 검색한다.

### 검색 예시

- 작년에 샀던 검은 운동화 찾아줘.
- 내가 이용 중인 구독을 보여줘.
- 다음 달에 결제되는 서비스 알려줘.
- 개발자 관련 웃긴 짤 찾아줘.
- 제주도 여행 때 저장한 맛집 보여줘.
- 로그인 화면 디자인 캡처 모아줘.

### 3.2 자동 컬렉션

AI가 관련 캡처를 자동으로 묶어 보여준다.

```text
구매            23개
구독             7개
일정            12개
맛집            31개
웃긴 짤         84개
디자인 참고      46개
```

### 3.3 구독비 집계

현재 이용 중인 구독 서비스의 월 결제금액을 합산한다.

### 제공 정보

- 현재 이용 중인 구독
- 이번 달 구독료 합계
- 연간 예상 구독료
- 다음 결제 예정 구독
- 최근 해지한 구독
- 해지했지만 아직 이용 가능한 구독

구독 관리는 복잡한 계약 분석보다 현재 상태와 비용을 명확히 보여주는 데 집중한다.

### 3.4 구매내역 조회

캡처를 통해 등록된 온라인 구매를 한곳에서 확인한다.

### 제공 정보

- 구매 상품
- 구매처
- 구매금액
- 구매일
- 상품 카테고리
- 월별 구매금액

소비 분석 전체를 제공하는 가계부가 아니라 캡처로 등록된 온라인 구매 기록을 정리하는 기능이다.

### 3.5 일정 재노출

날짜가 포함된 캡처는 필요한 시점에 다시 보여준다.

### 예시

- 약속 하루 전
- 과제 마감 전
- 구독 결제 전
- 무료 체험 종료 전
- 예약 일정 전

모든 캡처에 알림을 설정하지 않는다. 날짜와 행동이 명확한 캡처에만 알림을 제안한다.

# 4. MVP 핵심 범위

## 4.1 MVP 목표

> 사용자가 캡처를 보내면 별도의 정리 없이 자동으로 분류되고, 나중에 자연어로 다시 찾을 수 있는 경험을 검증한다.

## 4.2 MVP 핵심 기능 3개

### 1. 캡처 공유 및 저장

- 이미지 업로드
- 공유 메뉴를 통한 저장
- 원본 캡처 보관

### 2. AI 자동 분석 및 분류

- OCR 및 이미지 이해
- 캡처 목적 추론
- 자동 카테고리 및 태그 생성
- 구매·구독·일정 정보 구조화

### 3. 자연어 검색 및 컬렉션

- 자연어 기반 캡처 검색
- 자동 컬렉션
- 구매내역 조회
- 구독 목록 및 월 구독료 합산

## 4.3 MVP에서 지원할 캡처 유형

### 구매

- 구매처

- 금액
- 구매일

### 구독

- 해지일
- 이용 종료일

### 일정

- 일정명
- 날짜

## 4.5 MVP 기능 판단 기준

새로운 기능을 추가할 때 다음 질문을 적용한다.

### 필수성

> 이 기능이 없으면 사용자가 캡처를 맡기고 다시 찾는 핵심 흐름이 동작하지 않는가?

### 적합성

> 이 기능이 사진첩에 쌓인 캡처를 자동으로 관리한다는 문제를 직접 해결하는가?

두 질문 중 하나라도 명확하게 충족하지 못하면 MVP에서 제외한다.

# 5. 추후 확장 기능

## 5.1 링크 저장 및 분석

스크린샷뿐만 아니라 링크도 서비스로 공유할 수 있도록 확장한다.

### 링크 유형별 처리

- 상품 링크 → 관심 상품
- 맛집 링크 → 저장한 장소
- 유튜브 링크 → 나중에 볼 콘텐츠
- 뉴스 링크 → 읽을거리
- 구독 요금제 링크 → 구독 후보
- 개발 문서 링크 → 개발 참고자료
- 디자인 링크 → 디자인 레퍼런스

### 확장 흐름

```text
링크 공유
→ 본문 및 메타데이터 분석
→ 목적 추론
→ 기존 컬렉션에 자동 저장
```

---

## 5.2 다양한 입력 형식 지원

캡처 중심으로 시작한 뒤 사용자가 임시 저장하는 다양한 형식을 지원한다.

- 링크
- 사진
- 텍스트
- 음성
- PDF
- 파일
- 메시지
- 클립보드 내용

장기적으로 사용자는 형식을 구분하지 않고 서비스에 정보를 전달할 수 있다.

```text
“이거 저장해줘.”
```

AI가 입력 형식과 내용에 따라 적절한 방식으로 관리한다.

---

## 5.3 사진첩 자동 분석

사용자 동의를 받아 기존 스크린샷 폴더를 분석한다.

- 스크린샷 자동 감지
- 중복 캡처 제거
- 오래된 캡처 재분류
- 불필요한 캡처 삭제 추천
- 주요 캡처만 서비스에 등록

모든 사진을 자동 업로드하지 않고, 사용자가 선택한 스크린샷만 처리하도록 개인정보 보호 기능이 필요하다.

---

## 5.4 캡처 기반 개인 리포트

저장된 캡처 데이터를 기반으로 월간 리포트를 제공한다.

### 리포트 예시

```text
7월 캡처 리포트

새로운 구매       8개
구매금액       438,000원

이용 중인 구독     7개
월 구독료        68,700원

저장한 장소       13개
새로운 일정        6개

가장 많이 저장한 주제
개발 디자인
```

단순 통계보다 사용자가 저장했지만 다시 보지 않은 정보를 함께 보여준다.

---

## 5.5 다시 볼 정보 추천

저장 후 오랫동안 열어보지 않은 캡처를 적절한 시점에 다시 제안한다.

### 예시

- 한 달 전에 저장한 관심 상품
- 여행 전에 저장한 해당 지역 맛집
- 프로젝트 시작 시 저장한 디자인 레퍼런스
- 다음 결제일이 가까운 구독
- 아직 보지 않은 콘텐츠

단순한 랜덤 추천이 아니라 현재 일정, 검색과 최근 관심사를 기준으로 재노출한다.

---

## 5.6 사용자 맞춤 분류 학습

사용자가 AI 분류를 수정한 기록을 학습해 개인별 저장 습관을 반영한다.

### 예시

- 사용자가 운동화 화면을 항상 관심 상품으로 저장
- 고양이 이미지를 항상 친구 공유용 짤로 분류
- UI 화면을 특정 프로젝트 레퍼런스로 저장
- 결제 화면을 구매가 아니라 구독으로 수정

사용할수록 사용자에게 맞는 개인 분류 규칙이 만들어진다.

---

## 5.7 프로젝트 및 주제별 공간

사용자가 특정 목적의 캡처를 하나의 공간으로 관리할 수 있도록 한다.

### 예시

- 일본 여행
- TMI 프로젝트
- 자취방 인테리어
- 취업 준비
- 사고 싶은 옷
- 개발 공부
- 다이어트

AI가 캡처 내용을 보고 관련 프로젝트에 자동 연결한다.

---

## 5.8 캡처 공유 및 협업

개인 컬렉션 일부를 다른 사용자와 공유할 수 있도록 한다.

### 활용 사례

- 친구와 여행지 공유
- 팀원과 디자인 레퍼런스 공유
- 가족과 구독 목록 공유
- 연인과 구매 후보 공유
- 스터디원과 학습자료 공유

공유 시 이름, 주소, 전화번호와 주문번호 같은 개인정보를 자동으로 제거해야 한다.

---

## 5.9 외부 서비스 연동

사용자의 선택에 따라 캡처에서 추출한 정보를 외부 서비스로 보낼 수 있다.

- 날짜 → 캘린더
- 장소 → 지도
- 할 일 → 리마인더
- 링크 → 브라우저
- 상품 → 쇼핑몰
- 동영상 → 재생목록
- 디자인 → 프로젝트 보드

서비스가 모든 기능을 직접 구현하기보다 캡처 속 정보를 적절한 서비스로 연결하는 구조다.

---

# 6. 서비스 핵심 원칙

## 사용자는 정리하지 않는다

제목, 폴더, 태그 입력을 기본적으로 요구하지 않는다.

## 애매할 때만 질문한다

AI가 분류할 수 있는 캡처는 자동으로 처리하고, 확신이 낮은 경우에만 사용자에게 선택지를 보여준다.

## 모든 캡처에 행동을 요구하지 않는다

구매와 구독은 구조화하고, 일정은 알림을 제안하며, 웃긴 짤은 검색 가능하게만 저장한다.

캡처 목적에 따라 관리 방식이 달라야 한다.

## 자동화보다 신뢰를 우선한다

결제금액과 일정처럼 중요한 정보는 사용자가 확인하거나 수정할 수 있어야 한다.

## 기능이 아니라 재사용 경험을 제공한다

캡처를 많이 저장하는 것보다 저장된 캡처를 사용자가 실제로 다시 찾고 활용하는 것이 중요하다.

# 7. 핵심 차별점

## 기존 사진첩

```text
이미지를 날짜순으로 보관한다.
```

본 서비스의 차별점은 이미지 속 대상을 인식하는 데서 끝나지 않고 다음 단계를 수행한다는 것이다.

```text
캡처
→ 내용 이해
→ 저장 목적 추론
→ 자동 분류
→ 정보 구조화
→ 관련 캡처 연결
→ 필요할 때 다시 제공
```

# 8. 서비스 최종 정의

## 서비스 주제

AI 기반 캡처 관리 서비스

## 문제

사용자는 중요한 정보를 기억하기 위해 화면을 캡처하지만, 캡처가 사진첩에 뒤섞여 다시 찾지 못하고 활용하지도 못한다.

## 해결 방법

사용자가 캡처를 보내면 AI가 캡처의 내용과 목적을 파악해 자동으로 분류하고, 검색 가능한 정보로 변환한다.

구매와 구독처럼 구조화가 필요한 캡처는 별도의 카드로 정리하고, 일정이 있는 캡처는 필요한 시점에 다시 보여준다. 웃긴 사진이나 참고 이미지는 자동 태그와 컬렉션을 통해 다시 찾을 수 있게 한다.

## 핵심 기능

1. 캡처 수집
2. AI 자동 분석 및 정리
3. 자연어 검색 및 재활용

## 대표 활용 사례

- 온라인 구매내역 정리
- 구독 목록과 월 구독료 관리
- 일정과 마감 저장
- 관심 상품 관리
- 맛집과 장소 저장
- 웃긴 짤 분류
- 디자인과 개발 레퍼런스 관리

## 추후 확장 방향

캡처에서 시작해 링크, 텍스트, 사진, 음성과 파일까지 받을 수 있는 개인 AI 인박스로 확장한다.

## 서비스 핵심 문장

> 사용자는 캡처만 한다. AI가 그다음을 관리한다.
