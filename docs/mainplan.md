# 알바노트 기획서

## 1. 문제 정의

아르바이트 근무 현장에서는 근무 일정 변경, 대타 요청, 근무 시간 확인, 시급 계산 등 여러 관리 업무가 반복적으로 발생한다. 그러나 이러한 정보가 한곳에 정리되어 있지 않으면 알바생과 사장님 모두 일정 변경 상황을 빠르게 파악하기 어렵다.

알바생은 대타가 필요한 상황이 생겼을 때 직접 시간이 비는 사람을 찾아야 하며, 사장님에게 따로 보고하고 승인을 받아야 한다. 이 과정에서 부탁에 대한 부담이나 승인 요청에 대한 심리적 부담이 생길 수 있다.

사장님은 여러 알바생의 근무표, 고정 근무 시간, 시급, 대타 요청 현황을 각각 관리해야 한다. 특히 대타 요청이 발생했을 때 누가 기존 근무자인지, 누가 대타를 신청했는지, 근무표가 어떻게 변경되어야 하는지를 명확하게 확인해야 한다.

알바노트는 이러한 불편을 줄이기 위해 사장님과 알바생이 근무표, 대타 요청, 근무 시간, 시급 정보를 한곳에서 확인하고 관리할 수 있도록 돕는 웹 서비스이다.

## 2. 서비스 개요

- 서비스명: 알바노트
- 서비스 형태: React 기반 SPA 웹 서비스
- 주요 사용자: 사장님, 알바생
- 핵심 가치: 근무표 관리와 대타 요청 과정을 한곳에서 처리하여 매장 근무 관리를 단순화한다.
- 서비스 목표: 알바생의 대타 요청 부담을 줄이고, 사장님의 근무 일정 관리 효율을 높인다.

## 3. 사용자 및 매장 구조

### 사장님

사장님은 여러 개의 매장을 관리할 수 있다. 매장을 선택하면 해당 매장의 근무표, 알바생 정보, 대타 요청 현황을 확인할 수 있으며, 매장에 소속될 알바생을 초대할 수 있다.

또한 사장님은 초대된 알바생의 매장별 근무 정보를 등록하고 관리한다. 이 정보에는 시급, 고정 근무 시간 등 매장 운영에 필요한 기본 정보가 포함된다.

### 알바생

알바생은 회원가입 시 이름, 연락처 등 기본 신상정보를 직접 입력한다. 이후 사장님의 초대를 통해 매장에 소속될 수 있으며, 한 명의 알바생이 여러 매장에서 근무하는 상황도 지원한다.

알바생은 매장을 선택해 해당 매장의 근무표와 자신의 근무 정보를 확인할 수 있다. 대타가 필요한 경우에는 공개 대타 요청을 등록하고, 다른 알바생이 등록한 공개 요청에 신청할 수 있다.

## 4. 사용자 시나리오

### 대타 요청 시나리오

알바생에게 대타가 필요한 상황이 생기면 알바노트에 접속해 자신이 소속된 매장을 선택한다. 이후 메인 페이지의 달력에서 대타가 필요한 날짜를 클릭하고, 해당 날짜의 근무표를 확인한다.

요청자는 근무표를 보며 대타가 필요한 날짜와 시간을 확인한 뒤 공개 대타 요청을 등록한다. 공개 요청에는 날짜, 시간, 원래 근무자, 예상 급여, 요청 사유가 포함된다.

같은 매장에 소속된 알바생은 공개 대타 요청 목록을 확인하고, 가능한 요청에 대타 신청을 할 수 있다. 가장 먼저 신청한 알바생이 대타 후보로 선정되며, 이후 사장님에게 최종 승인 요청이 전달된다.

사장님이 승인하면 근무표는 자동으로 변경되고 대타 요청은 완료된다. 사장님이 요청을 거절하는 경우에는 거절 사유를 입력할 수 있으며, 요청자는 필요에 따라 대타 요청을 다시 등록할 수 있다.

### 근무표 확인 시나리오

사용자는 알바노트에 접속한 뒤 자신이 속한 매장을 선택한다. 메인 페이지에서는 달력 형태의 근무표를 확인할 수 있으며, 특정 날짜를 클릭하면 해당 날짜의 근무 일정이 시간대별로 시각화되어 표시된다.

사장님은 이 화면을 통해 근무 일정을 등록하거나 수정할 수 있다. 알바생은 자신의 근무 일정과 매장 전체의 근무 흐름을 확인하여 대타 요청이나 근무 일정 확인에 활용할 수 있다.

## 5. 핵심 기능

### 5.1 매장 관리

- 사장님은 여러 매장을 등록하고 관리할 수 있다.
- 사장님과 알바생은 모두 여러 매장에 소속될 수 있다.
- 사용자는 매장을 선택한 뒤 해당 매장의 근무표와 관련 정보를 확인한다.

### 5.2 알바생 등록 및 관리

- 알바생은 회원가입 시 기본 신상정보를 직접 입력한다.
- 사장님은 알바생을 매장으로 초대한다.
- 사장님은 초대된 알바생의 매장별 정보를 등록하고 관리한다.
- 매장별 관리 정보에는 시급, 고정 근무 시간 등이 포함된다.

### 5.3 근무표 등록 및 관리

- 사장님은 매장별 근무표를 등록하고 관리한다.
- 근무표는 메인 페이지에서 달력 형태로 표시된다.
- 날짜를 클릭하면 해당 날짜의 근무표가 시간대별로 시각화되어 표시된다.
- 사장님은 날짜별 근무를 직접 등록할 수 있다.
- 반복 근무 등록을 지원한다.

### 5.4 대타 구하기

- 대타 요청자는 근무표를 직접 확인한 뒤 공개 대타 요청을 등록할 수 있다.
- 대타 후보 자동 추천 기능은 제공하지 않는다.
- 같은 매장에 소속된 알바생은 공개 대타 요청 목록을 확인할 수 있다.
- 알바생은 날짜, 시간, 원래 근무자, 급여, 사유를 확인한 뒤 대타 신청을 할 수 있다.
- 가장 먼저 신청한 알바생이 대타 후보로 선정된다.
- 대타 후보 확정 후 사장님에게 최종 승인 요청이 전달된다.
- 사장님이 승인하면 근무표가 자동으로 변경된다.
- 사장님이 거절할 경우 거절 사유를 입력할 수 있다.
- 거절된 경우 요청자는 필요에 따라 대타 요청을 다시 등록할 수 있다.
- 요청자는 대타 요청 상태를 확인하고 필요 시 요청을 취소할 수 있다.

## 6. 보조 기능

### 6.1 시급 계산

- 근무 시간을 바탕으로 예상 급여를 계산한다.
- 초기 버전에서는 단순 계산을 기준으로 한다.
- 기본 계산식은 `근무 시간 × 시급`이다.
- 휴게시간, 야간수당, 주휴수당, 연장수당 등은 추후 확장 기능으로 고려한다.

### 6.2 알림

초기 버전의 알림은 웹 서비스 내부 알림을 기준으로 한다. 알림은 사용자가 대타 요청이나 근무표 변경 상황을 놓치지 않도록 돕는 역할을 한다.

알림이 필요한 상황은 다음과 같다.

- 공개 대타 요청 등록
- 대타 신청
- 사장님 승인
- 사장님 거절
- 근무표 변경
- 근무 시작 전 알림

카카오톡, 문자, 이메일 등 외부 알림은 추후 확장 기능으로 고려한다.

## 7. 서비스 운영 기준

- 초기 서비스는 React 기반 SPA(Single Page Application) 웹 서비스로 제공한다.
- 화면 이동은 새 HTML 문서를 매번 받아오는 방식이 아니라, 하나의 React 앱 안에서 클라이언트 라우팅으로 처리한다.
- 서버는 화면을 직접 렌더링하지 않고 Express API를 통해 필요한 데이터를 제공한다.
- 사장님과 알바생은 모두 여러 매장에 소속될 수 있다.
- 알바생의 기본 신상정보는 알바생이 직접 입력한다.
- 알바생의 매장별 시급, 고정 근무 시간 등은 사장님이 초대 후 작성한다.
- 대타 요청은 특정 알바생에게 직접 보내는 방식이 아니라 공개 요청 등록 방식으로 운영한다.
- 같은 매장에 소속된 알바생은 공개 대타 요청 목록을 확인하고 대타 신청을 할 수 있다.
- 가장 먼저 신청한 알바생이 대타 후보가 된다.
- 사장님 최종 승인 후 근무표가 자동으로 변경된다.
- 사장님이 거절할 경우 거절 사유를 입력할 수 있다.

## 8. MVP 개발 범위

초기 개발은 모든 기능을 한 번에 완성하기보다, 근무표 확인과 공개 대타 요청 흐름이 실제로 동작하는 것을 목표로 한다.

### 8.1 MVP에 포함할 기능

- 회원가입과 로그인
- 사장님/알바생 역할 구분
- 매장 선택
- 사장님의 매장 생성 및 알바생 초대
- 알바생의 매장 소속 확인
- 사장님의 알바생 매장별 정보 등록
- 월간 근무표 조회
- 일간 근무표 상세 조회
- 사장님의 근무 일정 등록, 수정, 삭제
- 반복 근무 등록
- 알바생의 공개 대타 요청 등록
- 같은 매장 알바생의 공개 대타 요청 조회
- 공개 대타 요청 신청
- 가장 먼저 신청한 알바생을 대타 후보로 선정
- 사장님의 대타 승인/거절
- 승인 시 근무표 자동 변경
- 웹 내부 알림 조회
- 기본 예상 급여 계산

### 8.2 MVP에서 제외할 기능

- 카카오톡, 문자, 이메일 등 외부 알림
- 대타 자동 추천
- 대타 가능 ON/OFF 토글
- 휴게시간, 야간수당, 주휴수당, 연장수당 계산
- 복잡한 급여 정산 리포트
- 모바일 앱
- 사장님 외 관리자, 매니저 등 세부 권한

## 9. 개발 전 확정 사항

### 9.1 인증 방식

인증은 Supabase Auth를 사용한다. 이메일과 비밀번호 기반 로그인을 기본으로 하고, 직접 JWT 발급이나 비밀번호 해싱은 구현하지 않는다.

### 9.2 사용자 역할

초기 역할은 사장님과 알바생으로 나눈다.

- 사장님: 매장, 알바생, 근무표, 대타 승인/거절을 관리한다.
- 알바생: 근무표를 확인하고 공개 대타 요청을 등록하거나 신청한다.

추후 매니저, 슈퍼바이저 같은 세부 역할은 확장 가능성으로 남긴다.

### 9.3 권한 기준

- 사용자는 자신이 소속된 매장의 정보만 볼 수 있다.
- 사장님은 자신이 소유한 매장만 관리할 수 있다.
- 알바생은 자신이 소속된 매장의 근무표와 공개 대타 요청만 볼 수 있다.
- 근무표 등록, 수정, 삭제는 사장님만 할 수 있다.
- 대타 요청 등록은 해당 근무의 원래 근무자인 알바생만 할 수 있다.
- 대타 신청은 같은 매장에 소속된 다른 알바생만 할 수 있다.
- 대타 승인/거절은 해당 매장의 사장님만 할 수 있다.

### 9.4 대타 요청 상태별 동작

| 상태 | 의미 | 주요 동작 |
| --- | --- | --- |
| `OPEN` | 공개 요청이 등록되어 신청을 받을 수 있는 상태 | 알바생 신청 가능, 요청자 취소 가능 |
| `PENDING_APPROVAL` | 먼저 신청한 알바생이 있어 사장님 승인 대기 중인 상태 | 사장님 승인/거절 가능 |
| `APPROVED` | 사장님이 승인하여 대타가 확정된 상태 | 근무표 자동 변경 |
| `REJECTED` | 사장님이 거절한 상태 | 거절 사유 확인, 요청자는 새 요청 등록 가능 |
| `CLOSED` | 요청자가 취소했거나 마감된 상태 | 추가 신청 불가 |

### 9.5 SPA 화면 라우팅 기준

알바노트는 SPA로 개발하므로 아래 경로들은 각각 별도 HTML 파일이 아니라 React Router가 관리하는 클라이언트 라우트이다.

- `/`: 비로그인 메인 또는 로그인 후 기본 근무표 화면
- `/login`: 로그인
- `/signup`: 회원가입
- `/stores/select`: 매장 선택
- `/schedule`: 월간 근무표
- `/schedule/:date`: 일간 근무표 상세
- `/substitute-requests`: 공개 대타 요청 목록
- `/substitute-requests/new`: 공개 대타 요청 등록
- `/workers`: 알바생 관리
- `/notifications`: 알림
- `/my-work`: 내 근무 정보

## 10. 추후 추가할 사항

- 대타 신청자가 근무 시간이 겹칠 경우의 자동 경고

## 11. 기대 효과

알바노트는 알바생이 대타를 구하는 과정에서 느끼는 부담을 줄이고, 근무표와 요청 현황을 한곳에서 확인할 수 있도록 돕는다. 사장님은 매장별 근무 일정과 알바생 정보를 체계적으로 관리할 수 있으며, 대타 승인 이후 근무표가 자동으로 변경되어 일정 관리의 번거로움을 줄일 수 있다.

이를 통해 알바노트는 알바생과 사장님 모두에게 더 명확하고 편리한 근무 관리 환경을 제공한다.
