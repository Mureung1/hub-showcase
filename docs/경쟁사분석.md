# 경쟁사 분석 — AI 운동 루틴 적응 코치

> 내부 참고용 문서. 유사 서비스가 어떤 기능을 갖는지 확인하고, 그중 이 프로젝트가 무엇을 의도적으로 채택하지 않았는지와 그 이유를 기록한다.

## 1. 비교 대상 개요

- **Fitbod** (가장 근접한 비교 대상): 과거 훈련 이력, 로그된 근육통, 가용 장비, 시간을 근거로 매 세션 운동을 재계산한다. 근육 피로도를 0~100% 연속값 히트맵으로 추적해 같은 근육을 이틀 연속 쓰지 않게 한다.
- **2026년 AI 트레이너 앱 전반의 공통 트렌드**: 점진적 과부하 자동 조정, 통증/부상 시 운동 대체, 웨어러블(HRV·수면) 기반 강도 자동 조정, 음성/컴퓨터비전 자세 분석, 디로드 주기 관리.

## 2. 기능별 채택 여부와 근거

| 경쟁 서비스 기능 | 이 프로젝트 채택 여부 | 근거 |
|---|---|---|
| 점진적 과부하 자동 증량 제안 | 채택하되 비핵심 P1 stretch로 분류 (여유 있으면 구현) | 이미 기획서에 double progression + StrongLifts 증량 폭으로 구현 계획 있음 |
| 통증/부상 시 운동 대체 | 채택 (핵심기능 1), 단 판단 범위는 축소 | 성숙한 경쟁 앱들은 "계속해도 되는지" 여부까지 판단하려 하지만, 이 프로젝트는 의료 판단 배제 원칙에 따라 "관여 관절 미포함 운동으로 기계적 대체 + 전문가 상담 고지"까지만 한다. 이게 오히려 설계상 의도적 차별점이다. |
| 연속값 근육피로도 히트맵 (Fitbod식) | 미채택, 이진값으로 단순화 | "바로 다음 세션만 회피"하는 이진 규칙으로 충분히 구현 가능하고 4주 범위에 맞는다. |
| 웨어러블 연동 (HRV·수면 기반 강도 조정) | 미채택 | 연동할 웨어러블 데이터 소스 자체가 없고, 문제정의(통증·시간부족·스킵 판단)와 직접 관련 없다. |
| 음성/컴퓨터비전 자세 분석 | 미채택 | 별도 기술 스택(비전 모델)이 필요해 4주 범위를 크게 초과한다. |
| 디로드(deload) 주기 관리 | 미채택 | 보통 4~8주 이상 누적 데이터가 있어야 의미 있는 기능이라, 4주짜리 데모에서 효과를 보여줄 수 없다. |
