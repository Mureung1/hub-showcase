# WI-0003 PP-001 서비스 경계와 사용자 여정 확정

> GitHub Issue: [PP-001 #3](https://github.com/gdh0730/hub/issues/3)

## 문제와 근거

현재 실행 가능한 저장소는 Java 17 백엔드 환경과 Actuator 계약까지만 제공한다.
참고 원문과 독립 HTML 프로토타입에는 추천, 공유, 투표 화면이 있으나 실제 지원할
기능, 사용자 역할, 실패 상태와 완료 경계가 하나의 운영 문서로 확정되어 있지 않다.
이 상태에서 화면이나 Controller부터 만들면 프로토타입의 가짜 데이터, 지원하지 않는
도보 시간과 지하철 출구 정보, 동기 추천 흐름이 구현 정본으로 굳어질 위험이 있다.

## 목적과 성공 기준

목적은 플레이스픽의 완성형 MVP가 해결할 문제와 주최자·참여자의 전체 여정을
검증 가능한 상태 전이로 확정하는 것이다. 다음 조건을 모두 만족하면 성공이다.

- 주최자는 익명 세션에서 자연어 조건을 입력하고 AI가 추출한 초안을 직접 검토·수정·
  확정한 뒤에만 비동기 추천 작업을 시작한다.
- 추천 작업은 근거가 있는 후보 세 개를 제공하고 진행, 완료, 근거 축소 완료, 실패,
  만료 상태를 사용자가 구분할 수 있다.
- 주최자는 추천 결과로 방을 만들고, 참여자는 공유 링크로 투표를 변경·삭제하며,
  주최자만 최종 장소를 확정한다.
- 각 단계의 진입 조건, 성공 결과, 복구 가능 오류와 종료 오류가 HTTP 계약 및 화면
  상태와 연결된다.
- 회원 가입, 관리자 화면, 결제, 지도·길찾기, 네이티브 앱과 유료 클라우드 배포가
  비범위로 명시된다.

## 범위, 비범위와 제약

범위는 서비스 목적, 주최자·참여자 persona, happy path, 실패·만료·재연결 경로,
기능 목록, MVP 완료 정의와 용어 사전이다. 세부 HTTP wire shape, DB 테이블, 점수
가중치, 프런트 컴포넌트와 실제 외부 API 구현은 후속 Task의 책임이다.

개인정보를 요구하지 않는 익명 사용을 유지하고 추천은 사용자의 최종 결정이 아니라
의사결정을 돕는 근거로 표현한다. 기존 HTML과 ProjectIntro 컴포넌트는 참고 자료이며
운영 기능의 존재를 증명하지 않는다.

## 판단 기준과 대안

판단 기준은 사용자의 통제권, 의사결정 시간 단축, 구현 가능한 외부 근거, 익명
사용의 안전성, 실패 복구 가능성과 계약 추적성이다.

- 자연어 입력 즉시 추천을 시작하는 방안은 단계가 짧지만 추출 오류를 확인할 기회가
  없어 제외한다.
- AI 초안을 먼저 보여주고 사용자가 확정하는 방안은 한 단계가 늘지만 잘못된 조건과
  불필요한 외부 호출을 줄이므로 선택한다.
- 결과를 한 개로 단정하는 방안은 선택은 빠르지만 그룹 의사결정이라는 목적과
  충돌하므로 후보 세 개와 근거 비교를 선택한다.
- 로그인 기반 권한은 강하지만 MVP 진입 비용이 커서 제외하고 익명 세션, 공개 share
  token, 별도 organizer capability를 선택한다.

고정 결정은 조건 확인 후 비동기 추천, 근거 기반 세 후보, 링크 기반 익명 투표,
주최자 단독 최종 확정이다. 추천 후보가 세 개 미만이면 부분 성공으로 위장하지 않고
한 번의 통제된 조건 완화 후 명시적으로 실패한다.

## 문제 해결 기록

이 Task를 실행할 때 다음 순서로 판단을 외부화한다.

1. 원문, 프로토타입, 현재 계약에서 사용자 행동과 암묵적 가정을 추출한다.
2. 주최자와 참여자 여정을 명령, 시스템 상태, 사용자에게 보이는 결과로 분해한다.
3. 정상, 근거 축소 완료, 후보 부족, 외부 제공자 실패, 만료와 권한 실패를 상태표로
   작성한다.
4. 각 상태가 PP-002 HTTP 계약과 PP-006 화면 상태에서 표현 가능한지 대조한다.
5. 범위 밖 기능이 계약이나 화면 문구에 남지 않았는지 검토한다.
6. 승인된 결과를 서비스 경계 문서, 아키텍처, 계약과 roadmap에 동기화한다.

## 구현 결과와 검증 증거

현재 status는 planned이며 서비스 경계 문서와 검토 증거는 아직 확보되지 않았다.
완료 판단에는 사용자 여정 상태표, 범위 대조표, 관련 계약 링크, 문서 검증 결과가
필요하다. 최소 검증은 npm run docs:check와 npm run docs:test이며, PP-002와 PP-006
담당자가 모든 여정 상태를 API 및 UI 상태로 매핑할 수 있는지 교차 검토한 기록을
남긴다. 근거 없이 구현 완료나 사용자 가치 달성을 주장하지 않는다.

## AI 사용과 사람의 검증

AI는 원문 비교, 여정 초안, 누락 상태 탐색과 추적성 표 생성을 지원할 수 있다.
사람은 제품 목적, MVP 범위, 실패 표현, 사용자 통제권과 제외 기능을 최종 승인한다.
AI가 프로토타입에 있다는 이유만으로 기능을 채택한 결과는 거절하고, 채택·거절
근거와 사람의 검토 결과만 기록한다.

## 남은 위험과 학습

실사용자 검증 전에는 여정이 실제 의사결정 시간을 줄인다고 단정할 수 없다. 조건
확인 단계의 이탈률이 높거나 후보 세 개가 선택 부담을 키운다는 측정 결과가 생기면
화면 흐름을 재검토하되, 사용자 확정 없이 외부 추천을 시작하지 않는 안전 경계는
별도 ADR 변경 없이 약화하지 않는다.
