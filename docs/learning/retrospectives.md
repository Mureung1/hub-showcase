# 일일 회고

부트캠프 LMS 제출용 초안 기록. 매일 작성 후 여기에도 누적.

## 7/19(일)~7/20(월)

[오늘 잘한 일]
주말에 design-upgrade 브랜치로 화면을 통째로 갈아엎었다 — 무드 피커, 사진 첨부, 캘린더 뷰, 플립 카드, mood/image_url 컬럼까지 붙였다. 오늘은 이걸 실제로 반영하는 작업을 끝까지 갔다: Supabase 컬럼 추가, 브라우저에서 하나씩 직접 눌러보며 확인한 뒤 N114_유승혁에 머지·푸시. 주간 계획도 이슈 여덟 개로 쪼개서 등록했다.

[아쉬운 일]
화면 확인하다가 다른 사람 결과물이랑 비교하면서 내 프론트가 빈약해 보인다고 잠깐 위축됐다.

[다음에 다시 한다면?]
결과물을 남과 비교하기 전에 이번 주 체크리스트가 다 됐는지부터 본다.

## 7/21(화)

[오늘 잘한 일]
Supabase 연동이 이미 끝나 있다는 걸 코드로 다시 확인했다. 수업 자료와 녹음 대본을 먼저 읽고 화면 데이터 흐름 순서로 설계하기, 완료 기준 먼저 정하기, 구현 방법 비교하기, 이해 못한 전략은 통과시키지 않기 절차를 정리한 다음 체크인 삭제 기능 하나에 그대로 적용해봤다. 관련 파일, API 명세, 구현 방법 비교, 완료 기준, 작업 분할, 이슈 초안까지 코드 없이 설계서로 먼저 썼고, 이 절차를 다음 기능에도 반복 쓸 수 있게 스킬로 옮겨뒀다.

[아쉬운 일]
오늘 수업이 뭘 요구하는지 자료와 녹음을 먼저 확인하지 않고 짐작으로 먼저 대답했다가, 원문부터 보라는 말을 듣고 다시 확인했다.

[다음에 다시 한다면?]
설계서 승인받으면 코드부터 짜지 않고 Supabase에 의존하는 checkinService를 어떻게 테스트할지부터 정하고 TDD로 들어간다.

## 7/22(수)

[오늘 잘한 일]
어제 설계한 체크인 삭제 기능을 테스트부터 작성해서 실패를 확인한 뒤 구현했다. 실제 Supabase에 넣었다 지우면서 검증하고, 서버를 직접 켜서 생성부터 삭제까지 curl로 전체 흐름을 확인했다. 2주차에 화면흐름도와 데이터흐름도로 나뉘어 있던 다이어그램을 하나로 합쳐 3주차에 추가된 무드, 사진, 캘린더, 삭제까지 반영해서 다시 그리고 README에 넣었다.

[아쉬운 일]
인증이 당연히 필요하다고 먼저 판단하고 나서야 이번 주 계획과 다른 사람들 사례를 확인했다. 확인이 먼저였어야 했다.

[다음에 다시 한다면?]
새 기능이 필요하다고 느껴지면 바로 시작하지 않고 이번 주 백로그부터 먼저 확인한다.

## 7/23(목)

[오늘 잘한 일]
저장소를 정리해서 안 쓰는 문서와 이미지, 연습 파일을 걷어내고 CLAUDE.md와 백로그, 진행상황 문서를 지금 상태에 맞게 다시 정리했다. 클라이언트에 vitest 테스트 환경을 새로 구축하고, 백로그에 있던 주간 모아보기 기능의 핵심 로직인 이번주 체크인 필터 함수를 테스트부터 작성해서 실패를 확인한 뒤 구현하는 순서로 만들었다. 반복하는 테스트 작성 절차는 스킬로 옮겨두고, 지난주에 만들어둔 검증 에이전트를 새로 만들지 않고 그대로 오늘 기능에 써서 확인했다.

[아쉬운 일]
저장소 정리하면서 README를 새로 다듬어 봤는데 결과가 맞지 않아서 정리 전 버전으로 도로 되돌렸다. 바꾸기 전에 결과를 미리 확인 안 하고 손댄 게 문제였다.

[다음에 다시 한다면?]
문서 정리처럼 되돌리기 번거로운 작업은 바꾸기 전에 결과물을 먼저 보여주고 확인받은 다음 진행한다.

## 7/24(금)

[오늘 잘한 일]
이번 주 Task를 백로그에서 다시 점검해서 끝난 건 체크하고, 남은 로그인과 클라우드 동기화는 멘토링 피드백을 반영해서 게스트 모드 중심으로 다음 주 계획을 다시 짰다. 3주 동안 AI랑 어떻게 일해왔는지, 설계 문서부터 쓰는 것과 테스트부터 쓰는 절차를 스킬로 만들어둔 것, 검증 에이전트를 재사용한 것을 정리해서 발표 자료와 대본으로 만들었고, 그 과정에서 삭제 기능과 주간 필터에서 실제로 막혔던 지점을 코드로 다시 짚어봤다.

[아쉬운 일]
로컬 AI 게이트웨이를 테스트할 때 한글 섞인 요청이 인코딩 문제로 실패해서, 잠깐 게이트웨이 자체가 고장 난 줄 알고 헷갈렸다.

[다음에 다시 한다면?]
뭔가 실패하면 설정부터 의심하지 않고, 테스트 입력값을 더 단순하게 바꿔서 원인부터 좁힌다.
