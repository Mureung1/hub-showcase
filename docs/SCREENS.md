# 화면 · 상태 설계

> **상태: 유저플로우 결정 반영됨 (2026-07-07, 사용자 위임으로 결정).** CLAUDE.md는 DESIGN.md를 "화면/컴포넌트 설계"로 참조하지만 실제 DESIGN.md는 디자인 토큰(색/타이포/간격) 문서다. 화면 구조는 이 문서가 담당한다. 시각 스타일은 DESIGN.md 토큰을 따른다.

## 핵심 결정 3가지

1. **톤 사전 선택 제거 — 후보 3개 = 톤 3단계.** 사용자는 결과를 보기 전엔 톤 단계의 의미를 알 수 없으므로, 톤 축은 입력 UI가 아니라 **결과 화면의 구조**로 옮긴다. 후보 3개를 톤 3단계(기본/더 부드럽게/더 분명하게 — 2026-07-08 2차 개정으로 공통 라벨)로 생성한다 (API 1회).
2. **입력은 목적 선택(필수) + "받은 메시지 붙여넣기"·"상황 설명" 2필드(둘 중 1개 이상 필수).** 붙여넣기가 작문보다 입력 비용이 낮다. 받은 메시지가 있으면 답장, 없으면 먼저 보내는 메시지로 자동 생성한다 (2026-07-08 서비스 정의 확장). 목적 필수 + 텍스트 1개 이상 필수는 2026-07-08 2차 개정 — 시나리오·목적 선택이 입력 비용을 낮게 유지하고, 텍스트 하한이 품질(그대로 전송 가능한 구체성)을 지킨다.
3. **재시도 1차 동선은 리롤.** 톤이 결과 축에 흡수됐으므로 "다시 만들기"(3개 전부 재생성)가 메인, "상황 수정"(S2 복귀, 입력 유지)이 보조.

## 화면 흐름

실제 흐름은 앱 밖에서 시작하고 끝난다:

```
(카톡/메일에서 메시지 수신 또는 보낼 일 발생)
   → 앱 진입
      [S1 시나리오 선택] → [S2 메시지·상황 입력] → [S3 결과 (톤 축 후보 3개)]
              ▲                    ▲    │ 상황 수정         │ 다시 만들기(리롤)
              │                    └────┘◄─────────────────┘
              └────────────── 처음으로 ◄───────────────────┘
   → 복사 → 카톡/메일로 복귀 → 붙여넣기 → 전송
```

- 라우터 없이 단일 페이지 내 단계(step) 전환으로 충분 (MVP 기준). 별도 라우팅 라이브러리 도입은 구조 변경이므로 사전 승인 필요.
- 모바일 퍼스트: 기준 뷰포트 375px, 데스크톱은 중앙 정렬 max-width 컨테이너.
- **상태 유지**: 카톡에서 메시지를 복사해 돌아오는 흐름상 브라우저가 백그라운드에 다녀온다. 입력값·결과는 sessionStorage에 보존해 리로드에도 유지.

## S1. 시나리오 선택

| 요소 | 내용 |
|---|---|
| 구성 | 서비스 한 줄 소개 + 시나리오 카드 4개 (세로 스택, 모바일 기준) |
| 카드 | 시나리오명 + 대표 상황 한 줄 (예: "팀플·조모임 — 할 말은 해야 할 때") |
| 상호작용 | 카드 탭 → S2로 전환. 선택 상태 시각화는 tertiary(#B8422E) 사용 |
| 상태 | 기본 상태만 존재 (데이터 로딩 없음) |

## S2. 메시지 · 상황 입력

| 요소 | 내용 |
|---|---|
| 헤더 | 선택한 시나리오명 + "다시 선택" 링크 (S1 복귀). **시나리오를 변경해도 입력값(목적 포함)은 유지**하고, 이미 생성된 결과는 폐기한다 (2026-07-07 점검에서 확정) |
| 목적 선택 | **필수**, 칩 6개 단일 선택: 부탁하기 / 사과하기 / 거절하기 / 질문하기 / 제안·확인하기 / 기타 (SPEC 1장 — 2026-07-08 2차 개정으로 추가) |
| 받은 메시지 | textarea, 최대 500자 + 남은 글자 수. 라벨: "받은 메시지 붙여넣기". 보조 문구: "먼저 보내는 말이면 비워두세요". placeholder는 시나리오별 예시 |
| 상황 설명 | textarea, 최대 300자 + 남은 글자 수. placeholder로 입력 예시 제시 (예: "벌써 3번째 이런 상황") |
| 입력 조건 | 받은 메시지·상황 설명 중 **1개 이상 필수** (2026-07-08 2차 개정 — EDGE_CASES 1-1 개정) |
| 안내 문구 | "실명 대신 '교수님', '팀원'처럼 적어주세요" 고정 노출 (EDGE_CASES 1-3) |
| 생성 버튼 | 라벨 **"보낼 말 3가지 만들기"** (2026-07-08 문구 확정). 활성 조건: 목적 선택됨 && 텍스트 1개 이상 입력됨. 비활성 상태에서는 버튼 아래 "목적을 고르고, 받은 메시지나 상황 중 하나를 적어주세요" 표시 |
| 상태 | 기본 / **생성 중**(버튼 비활성 + 로딩 표시, 20초 타임아웃) / **실패**(오류 문구 + 다시 시도 버튼, 429는 문구 구분) |

톤 조절 UI는 이 화면에 없다 — 톤은 S3의 결과 축으로 표현된다 (핵심 결정 1).

## S3. 결과 — 톤 축 후보 3개

| 요소 | 내용 |
|---|---|
| 후보 카드 | 3개 고정, **toneLevel 오름차순 = "기본"(가장 무난한 안)이 맨 위** (2026-07-08 2차 개정 — 선택 부담 최소화). 각 카드에 톤 라벨 배지 + 전체 텍스트 + 복사 버튼 |
| 톤 라벨 | SPEC 1장 확정 공통 라벨: **기본 / 더 부드럽게 / 더 분명하게** (전 시나리오 동일 — 2026-07-08 2차 개정) |
| 복사 | 성공 시 "복사됨" 토스트 / 실패 시 해당 텍스트 자동 선택 폴백 (EDGE_CASES 3-1). 복사 성공 = 핵심 과업 완료 — `copy` 이벤트 계측 (SPEC 7장, T24) |
| 자리 표시자 안내 | `[...]`·`OO` 패턴 포함 시 해당 부분 하이라이트 + "빈칸을 채워주세요" 배지 (EDGE_CASES 2-3 개정 — 자리 표시자는 환각 방지를 위한 의도된 출력, 감지 UI는 전송 사고 방지 보조 장치) |
| 재시도 1차 | **"다시 만들기"** — 같은 입력으로 3개 전부 재생성 (리롤, 핵심 결정 3) |
| 재시도 2차 | "상황 수정" 링크 — S2 복귀, 입력값 유지 |
| 상태 (리롤) | **리롤 중**: 다시 만들기·복사 버튼 비활성 + 로딩 표시 (20초 타임아웃, S2와 동일 기준). **리롤 실패**: 기존 후보 3개를 그대로 유지한 채 오류 문구 + "다시 시도" 노출 (429는 문구 구분) — 사용자가 가진 유일한 결과를 실패로 날리지 않는다 (2026-07-07 점검에서 확정) |
| 안내 | 입력이 매우 짧았던 경우 "상황을 조금 더 적으면 더 맞는 보낼 말이 나와요" |
| 이동 | "처음으로" → S1 (입력 초기화) |
| MVP 제외 | 피드백 버튼("효과 있었어요")은 이 화면에 들어올 예정이나 MVP에서는 미구현 — 레이아웃만 자리 고려 |

## 컴포넌트 후보 (구현 시 기준, 확정 아님)

```
App
└─ MessageFlow (step 상태 관리: scenario | input | result, sessionStorage 동기화)
   ├─ ScenarioCardList / ScenarioCard
   ├─ PurposeSelect         (목적 칩 6개, 단일 선택 필수)
   ├─ ReceivedMessageInput  (붙여넣기 textarea)
   ├─ SituationInput        (상황 설명 textarea + 글자수 + 안내)
   ├─ GenerateButton        (기본/로딩/실패 상태)
   └─ ResultList / ResultCard (톤 라벨 배지 + 복사 + 플레이스홀더 하이라이트)
```

## UX 세부 지침

생성 대기(스켈레톤+문구 로테이션), 복사 피드백(버튼 상태 전환+상단 토스트), CTA 하단 고정 등 상호작용 세부는 **docs/UX.md 6장 요약표**를 따른다 (2026-07-07 조사로 확정).

## DESIGN.md 토큰 적용 지침

- 상호작용 요소(선택된 카드/세그먼트, 생성 버튼, 복사 버튼)만 tertiary(#B8422E). 그 외 색 사용 금지 — "단일 액센트" 원칙 유지.
- 본문 Public Sans / 시나리오 라벨·배지류 Space Grotesk(label-caps).
- 카드·버튼 radius는 md(8px), 입력 요소는 sm(4px).
