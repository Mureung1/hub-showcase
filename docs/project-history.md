# 프로젝트 기획 이력

이 문서는 관계형 AI 프로젝트의 초기 문제 정의와 MVP 범위가 현재 구현으로 어떻게
발전했는지 기록합니다. 현재 실행 방법과 기능은 [README](../README.md)를 기준으로 합니다.

## 초기 문제 정의

감정과 상황을 표현한 사용자가 단순 분류 결과만 받으면 대화가 쉽게 끊깁니다. 관계형 AI는
사용자의 상황을 반영한 공감형 반응과 후속 질문으로 생각을 이어갈 수 있는 경험을 목표로
시작했습니다.

초기 대상 사용자는 다음과 같습니다.

* 자신의 감정 상태를 정리하려는 사용자
* 상황에 맞는 공감형 피드백이 필요한 사용자
* 부담 없이 감정 대화를 시작하려는 사용자

## 초기 MVP 범위

초기 포함 범위:

* 사용자 상황과 얼굴·목소리 신호 입력
* React 상태 관리와 결과 화면 표시
* 규칙 기반 Mock 분석 및 응답
* Express API 입력값 검증
* Supabase 분석 기록 저장과 조회
* 로딩, 오류와 대화 복원

초기 제외 범위:

* 회원가입과 로그인
* 실제 음성 입력 및 출력
* 실제 생성형 AI API
* 벡터 데이터베이스와 장기 기억
* 감정 분석 모델 학습
* 다중 사용자 및 복잡한 디자인 시스템

## 작업 분해 원칙

초기 계획은 요구사항 정의, 계획 Agent 작성과 작업 우선순위 검토 순서로 구성했습니다.
기능은 화면 일부만 만드는 수평 작업보다 화면에서 서버와 DB까지 연결되는 수직 슬라이스로
나누고, 각 작업에 우선순위·선행 작업·완료 기준을 작성하는 방식을 사용했습니다.

## 현재 구현으로 발전한 내용

* 브라우저 UUID로 최근 기록을 복원하는 세션 흐름을 추가했습니다.
* MediaPipe 기반 카메라 얼굴 움직임 신호 감지를 추가했습니다.
* 카메라 결과는 감정을 단정하지 않고 관찰 가능한 움직임으로 표시합니다.
* 영상·이미지·랜드마크를 저장하지 않는 제한 저장 정책을 적용했습니다.
* 카메라 입력의 감정형 대표 `face_signal`은 DB에 저장하지 않습니다.
* Helmet, 요청 제한과 데이터 크기 제한을 서버에 적용했습니다.
* 단위·계약·E2E 테스트와 실제 Supabase 검증 스크립트를 구성했습니다.

## 현재도 제외된 범위

* 실제 생성형 AI API
* 실제 음성 분석
* 사용자 인증과 사용자별 데이터 소유권 검증
* 장기 기억과 벡터 검색
* 의료적 또는 심리 진단

외부 배포 전에는 Supabase Auth, 사용자별 RLS, 기록 삭제와 보관 기간 정책이 추가로
필요합니다.
