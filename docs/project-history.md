# 프로젝트 기획 이력

이 문서는 초기 MVP가 현재의 Noa AI로 발전한 방향을 기록합니다. 현재 실행법과 정확한
기능 목록은 [README](../README.md)를 기준으로 합니다.

## 초기 목표

사용자가 감정과 상황을 정리할 때 단순 분류 결과보다 공감하는 반응과 이어지는 질문을
받도록 만드는 것이 출발점이었습니다. 초기 MVP는 React 화면, 규칙 기반 분석과 응답,
Express 입력 검증, Supabase 분석 기록 저장에 집중했습니다.

초기에는 회원가입, 실제 생성형 AI, 카메라 신호, 장기 기억을 범위에서 제외했습니다.

## 현재까지 확장된 기능

- 첫 화면에서 익명 또는 게스트 복구 키 방식을 선택합니다.
- 익명 대화는 현재 탭의 `sessionStorage`에만 남고 탭을 닫으면 사라집니다.
- 게스트 대화는 무작위 복구 키를 발급하고 서버가 키의 해시만 저장합니다.
- 서버는 `X-Guest-Key`를 확인해 해당 게스트의 기록만 조회·저장합니다.
- 게스트가 메시지를 보낼 때만 Gemini 2.5 Flash-Lite를 호출합니다.
- 실패 시 규칙 기반 응답으로 대체하고, 사용량 한도에서는 `Noa는 자고 있어요.`를
  표시합니다.
- MediaPipe로 브라우저 안에서 얼굴 움직임 신호를 계산합니다.
- 카메라 결과는 감정의 확정값이나 진단이 아닌 참고 신호로만 표현합니다.
- 영상, 프레임, 얼굴 좌표와 장치 식별 정보는 서버로 전송하거나 저장하지 않습니다.
- 결과 화면에는 COBE 기반의 자동 회전·드래그 가능한 지구본이 표시됩니다.
- 두 번째와 세 번째 화면에서도 처음 화면으로 돌아갈 수 있습니다.
- 프런트엔드는 Vercel, Express API는 Render, 데이터는 Supabase에 배포합니다.

## 현재도 범위 밖인 기능

- 음성 인식과 음성 합성
- 의료·심리 진단
- Supabase Auth 기반 정식 회원 계정
- 벡터 검색과 무제한 장기 기억
- 얼굴 영상이나 원본 생체 데이터 저장

`conversation_messages` 테이블은 스키마에 준비되어 있지만, 현재 대화 복원은
`emotion_analyses` 기록을 사용합니다. 정식 회원 기능이나 보관 정책을 추가할 때는
사용자별 소유권, 삭제, 만료, RLS 정책을 별도로 설계해야 합니다.
