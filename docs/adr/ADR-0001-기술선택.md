# ADR-0001 — 기술 선택

상태: 채택됨
날짜: 2026-07-10

## 맥락

현재 저장소는 리뷰지기 PRD와 HTML·CSS 프로토타입을 보유하고 있다. 사용자는 하네스 엔지니어링을 시작하기 위해 문서와 작업 규칙을 먼저 정리하려고 한다.

아직 생산용 앱의 프론트엔드, 백엔드, DB, 배포 방식, LLM 연동 방식은 확정되지 않았다. 따라서 지금 `src/`, `app/`, `server/` 같은 구현 폴더를 만들면 이후 스택 결정과 충돌할 가능성이 높다.

## 결정

- 현재 단계의 기술 산출물은 정적 HTML·CSS 프로토타입으로 유지한다.
- 제품 기준은 `docs/PRD.md`로 둔다.
- 실제 앱 소스 구조는 생산용 스택을 결정한 뒤 생성한다.
- 그 전까지는 문서, 테스트 계획, 하네스 작업 루프를 먼저 정리한다.
- MVP 구현 시에도 자동 리뷰 수집과 자동 게시 기능은 만들지 않는다.

## 결과

좋아지는 점:

- 불필요한 구현 폴더와 빈 파일을 만들지 않아 구조가 덜 오염된다.
- PRD와 프로토타입을 기준으로 기능 경계를 먼저 합의할 수 있다.
- 이후 어떤 스택을 선택하더라도 도메인 경계를 유지할 수 있다.

감수할 점:

- 당장 실행 가능한 앱 서버나 빌드 파이프라인은 없다.
- 실제 데이터 저장, AI 호출, 플랫폼 연동은 다음 ADR 이후에 구현해야 한다.

## 대안

### 지금 React 또는 Next.js 앱을 바로 생성

보류했다. 화면은 이미 정적 프로토타입으로 검증 가능하고, 생산용 요구사항이 더 정리되기 전에는 스택 잠금이 빠르다.

### 지금 백엔드 API부터 생성

보류했다. 데이터 모델과 LLM 입출력 계약이 먼저 필요하다.

### 현재 HTML·CSS 프로토타입을 최종 제품으로 확장

보류했다. 프로토타입은 시연과 검토에는 충분하지만, 실제 입력 저장, 분석, AI 연동, 계정 관리에는 별도 앱 구조가 필요하다.
