# ADR 0008. 계보 엣지와 사후 semantic 엣지를 전용 파이프라인이 기록한다

## 맥락

지식 그래프의 쓰기 권한은 지식 구축 에이전트에만 있었고, 지식 구축은 해석·전략·로드맵보다 먼저 실행되었다.

그런데 등록된 엣지 유형 중 상당수는 해석·전략·로드맵의 산출물을 끝점으로 갖는다. `SUPPORTED_BY`, `DERIVED_FROM`, `FILLS`, `PRODUCED_BY`가 계보 층에 있고, `PROVEN_BY`, `USED_IN_CHANNEL`, `TEACHES`가 의미 층에 있다. 이 엣지들을 쓸 수 있는 구성요소는 실행이 이미 끝났고, 내용을 아는 구성요소는 권한이 없다.

동시에 전략 에이전트는 `ProofArtifact`로 이어지는 경로를, 로드맵 에이전트는 `LearningResource`로 이어지는 경로를 탐색하도록 규정되어 있었다. 두 에이전트가 만드는 노드를 두 에이전트가 입력으로 요구했다.

## 결정

A0 helper 파이프라인 하나를 신설해 파생 엣지의 쓰기를 담당한다.

- 계보 기록 파이프라인이 Provenance 층 전체와 사후 semantic 묶음을 기록한다.
- 지식 구축 에이전트는 사전 semantic 묶음만 생성한다.
- 파이프라인은 각 계층의 산출물이 정규 테이블에 저장된 직후 실행한다.
- 파생 엣지의 진실의 원천은 산출물 정규 테이블이며 엣지는 경로 탐색을 위한 표현이다.
- 에이전트는 자신이 생성할 노드로 이어지는 엣지를 탐색 입력으로 받지 않는다.

## 고려한 선택지

| 선택지 | 결과 |
| --- | --- |
| 지식 구축을 사전·사후 두 번 실행 | 오케스트레이터의 실행 순서가 복잡해지고, 탐색 시점의 순환은 그대로 남는다 |
| 각 에이전트에 그래프 쓰기 권한 부여 | 판단이 필요 없는 기록에 A2 권한을 열고, 테이블 단위 권한 경계가 무너진다 |
| 파생 엣지를 온톨로지에서 제거 | 근거 경로 조회가 관계형 조인으로만 가능해지고 경로 캐시를 쓸 수 없다 |
| 전용 A0 파이프라인 | 기록에 판단이 개입하지 않고, 에이전트 간 직접 호출 없이 계층 규칙을 지킨다 |

## 선택 이유

계보 기록은 외래키를 그래프 표현으로 옮기는 결정적 변환이다. 같은 입력에 같은 엣지를 낸다. 판단이 없는 작업을 자율성 등급이 높은 구성요소에 두면 권한 범위만 넓어진다.

의미 층을 생성 시점으로 나누면 탐색 순환도 함께 사라진다. 전략과 로드맵이 실제로 필요로 하는 입력은 요구에서 역량과 선수 역량으로 이어지는 사전 semantic이며, 증명 산출물과 학습 자료는 이들의 출력이다.

## 결과와 제약

- 파생 엣지는 이를 생성한 에이전트의 같은 실행 안에서 사용할 수 없다. 화면의 근거 경로 표시와 다음 분석 버전의 탐색에 사용한다.
- `knowledge_nodes`와 `knowledge_edges`를 두 구성요소가 공유하므로 테이블 단위 `GRANT`로 권한을 분리하지 못한다. `graph_layer`와 유형 목록으로 나누고 repository 경계로 강제한다.
- 정규 테이블과 엣지가 어긋날 수 있다. 검증에서 불일치 엣지를 폐기하고 다시 기록한다.
- 재실행 시 계보 기록은 별도 트리거를 갖지 않고 산출물 저장을 따라 실행한다.
