# ADR 0001. 요구 차원의 승격을 검증 절차로 둔다

## 맥락

직무마다 세어야 할 요구가 다르고, 같은 직무에서도 연도에 따라 새 요구가 등장한다. 요구 차원을 코드에 고정하면 직무 확장과 시간 변화를 표현할 수 없다.

동시에 분류체계가 실행마다 달라지면 기간 비교와 기업군 비교가 성립하지 않는다. 통계의 분모와 집계 키가 흔들리기 때문이다.

## 결정

요구 차원은 자료에서 발견하되, 공식 분류체계 편입은 승격 절차를 거친다.

- 발견은 후보 생성까지 수행한다.
- 후보는 `proposed`에서 `active`까지의 생명주기를 가진다.
- `active` 이전의 후보는 통계에 포함하지 않는다.
- 승격은 독립 공고 수, 독립 회사 수, 평가 세트 대조, 검증 결과, 승인 주체를 기록한다.
- 승격 결과는 `taxonomy_version`으로 발행하고, 해당 데이터셋의 할당을 전량 재계산한다.

## 고려한 선택지

| 선택지 | 결과 |
| --- | --- |
| 차원 목록을 코드에 고정 | 직무 확장 시 코드 변경이 필요하고 새 요구가 등장하지 않는다 |
| 생성 모델이 발견한 차원을 즉시 활성화 | 실행마다 분류가 달라져 기간·기업군 비교가 깨진다 |
| 발견 후 승격 절차 | 발견 능력과 측정 안정성을 함께 확보한다 |

## 선택 이유

통계의 가치는 비교 가능성에서 나온다. 비교 가능성은 집계 키의 안정성을 요구하고, 안정성은 버전 발행으로 확보한다. 발견과 승격을 분리하면 새 어휘를 놓치지 않으면서 집계 키를 고정할 수 있다.

## 결과와 제약

- 승격되지 않은 후보는 통계 화면에 나타나지 않는다.
- 새 차원이 통계에 반영되기까지 승격 심사가 필요하다.
- 분류체계 버전이 다른 수치를 비교하지 않는다.
- 승격 임계값은 `taxonomy_policy_version`으로 관리하고, 변경 시 이전 결과를 보존한다.
