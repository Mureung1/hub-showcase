# ADR 0016. 오케스트레이션 프레임워크를 도입하지 않는다

## 맥락

에이전트 서비스는 실행 순서, 상태 공유, 모델 호출, 재시도를 스스로 정한다. 실행 순서는 [아키텍처](../architecture.md) 7장의 시퀀스, 상태 공유는 같은 문서 5장의 블랙보드와 실행 봉투, 종료 조건은 [에이전트 설계](../agent-design.md) 5장의 근거 슬롯 충족이다.

오케스트레이션 프레임워크는 이 네 가지에 대한 자기 답을 함께 가져온다. 그래프 상태 기계, 프레임워크가 정의하는 상태 객체, 모델 클라이언트 계층, 도구 선택 루프다.

## 결정

LangChain·LangGraph를 비롯한 오케스트레이션 프레임워크를 의존성에 두지 않는다.

- 오케스트레이터는 결정적 스케줄러다(자율성 등급 A0, [아키텍처](../architecture.md) 2.1). 영향 범위로 다시 돌릴 단계를 정하고, 선행 관계 그래프를 위상 정렬해 차례를 세우고, 각 단계에 실행 봉투를 만든다. 구현은 `agent/src/careersignal/orchestration/`이다.
- 상태는 저장소를 블랙보드로 공유한다. 에이전트는 산출물을 서로 전달하지 않고 봉투에 담긴 범위와 버전으로 저장소에서 읽는다.
- 모델 호출은 `Protocol` 뒤의 어댑터가 맡는다. 포트마다 `OpenAI*` 구현과 결정적 대역을 나란히 둔다. 구현은 `agent/src/careersignal/providers/`와 각 에이전트의 `adapter.py`다.
- 도메인 에이전트는 다른 에이전트를 시작하지 못한다. 근거가 부족하면 `research_requests`에 요청을 남기고 오케스트레이터가 수집을 새 실행으로 스케줄링한다.

## 고려한 선택지

| 선택지 | 결과 |
| --- | --- |
| LangGraph의 그래프 상태 기계로 실행 순서를 표현 | 전달할 상태가 없는 구조에 상태 채널이 생기고, 차례의 기준이 문서의 시퀀스와 프레임워크 그래프 두 곳으로 갈린다 |
| LangChain의 에이전트 루프와 도구 선택을 사용 | 종료 조건이 근거 슬롯 충족인데 프레임워크의 루프는 모델이 종료를 정한다 |
| 프레임워크의 모델 클라이언트만 사용 | 단위 검사가 프레임워크의 호출 계층을 거치고, 대역을 끼우는 지점이 어댑터 밖으로 나간다 |
| 직접 만든 스케줄러·블랙보드·어댑터 | 네 가지를 프로젝트의 실행 계약에 맞춰 두고 의존성이 늘지 않는다 |

## 선택 이유

에이전트가 상태를 전달하지 않으므로 그래프 상태 기계가 표현할 상태가 없다. 단계 사이의 화살표는 실행의 차례일 뿐 호출이 아니고, 앞 단계의 결과는 저장소에서 읽는다.

종료 조건이 근거 슬롯 충족이므로 자유로운 도구 선택 루프가 아니다. 각 에이전트는 필수 근거 슬롯을 선언하고 그 슬롯이 채워지면 멈춘다. 반복 횟수의 상한은 봉투의 `budget`이 정한다.

어댑터를 좁게 두면 생성 모델 호출 없이 단위 검사가 돈다. 대역은 판단을 흉내 내지 않고 배선을 확인하는 값만 낸다.

## 결과와 제약

- 추적 화면과 체크포인트를 직접 만들어야 한다. 프레임워크가 제공하는 실행 시각화와 중단 지점 재개가 없다.
- 실행 기록은 `agent_runs`·`agent_run_steps`·`tool_calls`·`retrieval_runs`에 남는다. 이 표들이 추적의 근거이며 계측 기록은 추가 전용이다(`0006_telemetry_triggers`).
- 재시도와 예산 초과 처리는 봉투의 `budget`과 검증의 수리 절차가 맡는다.
- 새 모델 제공자를 더할 때는 각 포트의 `Protocol`을 구현한다. 어댑터 밖의 코드는 모델 클라이언트를 알지 않는다.
