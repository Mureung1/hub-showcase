# ADR 0005. 요구 표현과 차원 할당을 분리해 저장한다

## 맥락

공고에서 추출한 요구 표현은 원문에 근거한다. 그 표현을 어느 차원으로 셀지는 분류체계에 의존한다.

두 정보를 한 테이블에 담으면 분류체계가 확정되기 전에는 추출 결과를 저장할 수 없다. 분류체계는 추출 결과에서 발견되므로 순환이 생긴다.

또한 새 표현을 기존 차원에 강제로 배정하면 새 요구가 통계에 나타나지 않는다.

## 결정

요구 표현과 차원 할당을 두 테이블로 분리한다.

- `requirement_mentions`는 원문 표현, 근거 위치, 공고가 사용한 필수·우대 표기를 담고 차원을 참조하지 않는다.
- `posting_requirement_assignments`는 표현과 차원을 분류체계 버전과 함께 연결한다.
- 집계의 키는 `dimension_id`와 `taxonomy_version_id`다.
- 분류체계 버전이 발행되면 해당 데이터셋의 표현 전체를 다시 할당한다.

## 고려한 선택지

| 선택지 | 결과 |
| --- | --- |
| 단일 테이블에 차원 포함 | 분류체계 확정 전에 추출 결과를 저장할 수 없다 |
| 차원을 나중에 갱신 | 이전 할당 이력이 사라져 버전 간 비교가 불가능하다 |
| 표현과 할당 분리 | 추출과 분류를 독립적으로 진행하고 버전별 할당을 보존한다 |

## 선택 이유

원문 근거는 분류체계와 무관하게 확정할 수 있다. 분리하면 추출을 먼저 수행하고 그 결과에서 분류체계를 발견하는 순서가 성립한다.

할당을 버전별로 보존하면 분류체계 변경 전후의 통계를 각각 재현할 수 있다.

## 결과와 제약

- 검증된 원자 사실을 담는 범용 테이블을 별도로 두지 않는다. 필요한 하위 유형이 나타날 때 추가한다.
- 표현 추출이 완료되어도 할당 전에는 통계를 계산할 수 없다.
- 분류체계 버전 발행마다 재할당 비용이 발생한다.
