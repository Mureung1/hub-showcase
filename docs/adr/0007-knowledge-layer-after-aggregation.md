# ADR 0007. Wiki를 집계 뒤 계층으로 분리한다

## 맥락

데이터 성숙도의 D3은 분류체계, 정규화 할당, 지식 그래프, Wiki를 한 계층에 담고 D4 집계 통계보다 앞에 두었다.

그런데 이 계층의 두 산출물은 집계 결과를 입력으로 받는다. Wiki의 생성 대상은 통계적 우선순위로 판정하고, 그래프 엣지의 `weight`는 통계 지표에서 계산한다. `capability_depth_profiles`도 `depth_distribution` 지표에서 도출되면서 `analysis_version`을 버전 축으로 갖는다.

계층 정의는 D3 → D4였고 실행 순서 다이어그램은 집계 → 지식 구축이었다. 두 기준 문서가 서로 다른 순서를 기술했다.

## 결정

D3을 생성 순서가 다른 두 묶음으로 나눈다.

- D3a는 분류체계, 정규화 할당, 지식 그래프다. 집계의 입력이다.
- D4는 집계 통계, 패턴, 깊이 프로파일이며 버전 축은 `analysis_version`이다.
- D3b는 Wiki이며 버전 축은 `knowledge_version`이다. 집계의 결과를 입력으로 받는다.

`capability_depth_profiles`는 D4에 속하고 집계 파이프라인이 생성한다.

지식 그래프는 할당만 있으면 구축할 수 있으므로 D3a에 둔다. 엣지의 `weight`는 집계 이후에 채우는 후행 값이다.

## 고려한 선택지

| 선택지 | 결과 |
| --- | --- |
| Wiki 생성 조건에서 통계 우선순위 제거 | 계층은 단순해지나 활성 capability 전량에 Wiki를 생성해 비용이 늘고 선별 의도가 사라진다 |
| 지식 그래프와 Wiki를 함께 집계 뒤로 | 그래프 탐색과 근거 집합 최적화가 집계 뒤로 밀려 개발 순서가 뒤집힌다 |
| Wiki만 집계 뒤로 | 계층 정의가 개발 순서와 일치하고, 그래프는 할당 직후 구축할 수 있다 |

## 선택 이유

Wiki만 집계 결과를 필요로 한다. 생성 대상을 통계적 우선순위로 판정하기 때문이다.

지식 그래프의 엣지는 할당과 역량·표준에서 나오므로 집계가 없어도 구축된다. `weight`는 경로 순위에만 쓰이는 값이라 비어 있어도 탐색이 성립한다. 그래프를 집계 뒤로 보내면 그래프 탐색과 근거 집합 최적화까지 함께 밀려 개발 순서가 뒤집힌다.

계층 번호를 전면 재배열하지 않고 D3a와 D3b로 나누면 D5와 D6의 참조를 유지하면서 순서만 정정할 수 있다.

## 결과와 제약

- 계층 표기가 순번대로 읽히지 않는다. D3b는 D4 뒤에 온다.
- 그래프 엣지는 `weight`가 빈 상태로 먼저 저장되고 집계 이후 채워진다. 그 사이의 경로 조회는 순위 없이 반환한다.
- 분류체계 버전 발행은 D3a 재실행과 D4 재집계, D3b 재구축을 함께 요구한다.
- Wiki가 참조하는 `capability_depth_profiles`는 D4 산출물이므로 정의는 Wiki 장에 두고 계층은 D4로 표기한다.
