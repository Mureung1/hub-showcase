# ADR 0014. 평면 공고 표를 `legacy_posting_samples`로 분리한다

## 맥락

수직 슬라이스가 쓰던 평면 공고 표와 분석 모집단의 정규화 공고 표가 같은 이름을 갖는다. 평면 표는 `server/sql/001-postings.sql`이 `postings`로 만들고 기업군 표시명·라벨·스킬 목록을 한 행에 담는다. 정규화 표는 `0001_initial_schema`의 `postings`이며 회사·기간·버전으로 갈라진다.

한 저장소에 같은 이름의 표를 둘 다 둘 수 없다. 데이터베이스 스키마의 기준은 `agent/migrations/`이므로([ADR 0006](0006-migration-ownership.md)) 정규화 표가 `postings`를 갖는다.

평면 표에는 백엔드 공고 표본만 들어 있고 라벨도 백엔드 직무의 것이다.

## 결정

평면 표를 제 이름으로 옮기고 용도를 폴백으로 좁힌다.

- `0025_legacy_posting_samples` migration이 평면 `postings`를 `legacy_posting_samples`로 rename한다. 컬럼이 남아 있으면 rename하고 없으면 같은 모양으로 새로 만든다. 데이터를 잃지 않는다.
- `job_role_id` 컬럼을 더하고 기존 행의 기본값을 `backend`로 둔다. 이 표는 분석 모집단이 아니므로 `job_roles`로 가는 외래키를 두지 않는다.
- 정규화 `postings`는 분석 경로가 쓰고, `legacy_posting_samples`는 Express의 폴백 조회만 쓴다.
- 폴백 경로는 `LEGACY_STATS_FALLBACK` 환경변수로 켜고, 켜져 있어도 백엔드 직무에서만 동작한다.

## 고려한 선택지

| 선택지 | 결과 |
| --- | --- |
| 평면 표를 삭제한다 | 활성 분석 버전이 없을 때 화면을 확인할 경로가 사라진다 |
| 정규화 표의 이름을 바꾼다 | 스키마 기준 문서와 26개 migration이 참조하는 이름이 흔들린다 |
| 평면 표를 정규화 표에 병합한다 | 평면 컬럼이 정규화 스키마의 제약과 맞지 않아 모집단에 검증되지 않은 행이 섞인다 |
| 평면 표를 rename하고 폴백으로 남긴다 | 두 표가 각자의 이름과 용도를 갖고 이름 충돌이 사라진다 |

## 선택 이유

두 표는 같은 대상을 다른 목적으로 담는다. 하나는 지표의 분모가 되는 모집단이고 다른 하나는 화면 확인용 표본이다. 이름을 가르면 어느 표가 통계에 들어가는지가 스키마에서 드러난다.

rename은 표를 다시 만들지 않으므로 이미 적재된 행이 남는다. 폴백 경로가 곧바로 동작한다.

## 결과와 제약

- 폴백 경로는 백엔드 직무의 라벨만 갖는다. 라벨은 `server/data/legacy-backend-labels.json`에 있다.
- 다른 직무가 이 경로로 떨어지면 명시적 오류를 낸다. 백엔드 라벨로 다른 직무의 화면을 채우지 않는다.
- 폴백은 활성 분석 버전이 없을 때만 닿는다. 정상 경로는 [ADR 0013](0013-serving-stored-analysis-outputs.md)의 산출물 조회다.
- `legacy_posting_samples`는 통계에 들어가지 않는다. 지표의 표본 수는 정규화 `postings`에서만 센다.
