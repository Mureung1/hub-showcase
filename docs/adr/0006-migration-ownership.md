# ADR 0006. 데이터베이스 스키마를 에이전트 서비스가 소유한다

## 맥락

Express와 FastAPI 에이전트 서비스가 같은 Supabase 데이터베이스를 사용한다. 두 서비스가 각각 스키마를 정의하면 정의가 갈라지고 어느 쪽이 기준인지 판정할 수 없다.

지식과 분석 데이터의 주 작성자는 에이전트 서비스다. Express는 활성 분석 결과를 조회하고 체크 상태를 조합한다.

## 결정

데이터베이스 스키마의 기준은 `agent/migrations/`다.

- 스키마 변경은 에이전트 서비스의 migration으로만 수행한다.
- Express는 조회 계약만 따르고 스키마를 정의하지 않는다.
- `server/sql/`은 스키마를 정의하지 않고 기준 위치 안내와 참고용 사본만 유지한다.

## 고려한 선택지

| 선택지 | 결과 |
| --- | --- |
| 두 서비스가 각각 정의 | 정의가 갈라지고 배포 순서에 따라 상태가 달라진다 |
| Express가 소유 | 지식·분석 테이블의 주 작성자가 소유하지 않아 변경마다 조율이 필요하다 |
| 에이전트가 소유 | 주 작성자가 스키마를 관리하고 조회 측은 계약을 따른다 |

## 선택 이유

스키마의 소유자는 그 스키마에 가장 많이 쓰는 구성요소가 되는 것이 자연스럽다. 테이블 대부분이 에이전트 실행의 산출물이다.

## 결과와 제약

- Express가 필요로 하는 조회 형태는 에이전트 서비스의 migration에 반영한다.
- 두 서비스의 배포 순서에서 migration이 선행한다.
- 조회 계약 변경은 [아키텍처](../architecture.md) 10장의 화면 API 정의를 따른다.
