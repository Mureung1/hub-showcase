# decisions.md — 주요 기술 결정 기록 (ADR)

> 되돌리기 어렵거나 나중에 "왜 이렇게 했지?"가 생길 결정을 옵션 비교와 함께 남긴다. 형식: 맥락 → 옵션(장점/단점/채택) → 결론. 뒤집힌 결정은 지우지 않고 이력으로 남긴다.

## ADR-001. 저장 계층: localStorage 유지 + 서버는 비식별 부가 (2026-07-14)

**맥락:** 과제가 FE·BE·DB 연결을 요구하나, 우리 원칙은 사용자 응답의 서버 저장을 게이트 뒤로 미룸.

| 옵션 | 장점 | 단점 | 채택 |
|---|---|---|---|
| localStorage만 | 개인정보 위험 0, 단순 | 과제 미충족, 축적 불가 | 1차 저장은 유지 |
| **localStorage + 비식별 서버**(채택) | 과제 충족 + 원칙 유지, 익명 요약만 축적 | 서버 운영 필요 | **채택** |
| 서버에 전체 응답 저장 | 분석 풍부 | PII·동의 문제, 하드룰 위반 | 기각 |

**결론:** localStorage가 1차 저장소. 서버는 **동의 후 비식별 파생 요약(화이트리스트 필드)만** 저장하고 삭제권 제공. 이름·자유응답은 서버로 보내지 않음.

## ADR-002. DB 제공자: 지금 in-memory, 다음에 Supabase (2026-07-14)

**맥락:** 과제 키워드가 `supabase`. 하지만 실제 Supabase 연결엔 프로젝트·키가 필요하고, 오늘은 흐름부터 완성해야 함.

| 옵션 | 장점 | 단점 | 채택 |
|---|---|---|---|
| **in-memory 먼저**(채택) | 키 없이 즉시 동작, 흐름 검증 | 재시작 시 소실(휘발성) | **v1 채택** |
| 지금 Supabase | 영속·과제 완전 충족 | 키·프로젝트 준비 필요, 지연 | v1.5로 |
| 로컬 Postgres | 영속 | 배포·공유 어려움 | 기각 |

**결론:** `backend/src/store.js`를 **함수 인터페이스로 분리**해, 나중에 Supabase 어댑터로 교체만 하면 되게 함(코드 변경 최소화). 실제 연결은 v1.5에서 `@supabase/supabase-js` 추가 + `SUPABASE_URL/KEY`(backend `.env`).

**업데이트(2026-07-15, 스캐폴딩 완료):** 어댑터 교체 구조를 실제로 구현.
- `store.memory.js`(in-memory) + `store.supabase.js`(Supabase) + `store.js`(env 스위치 선택기, 실패 시 in-memory 폴백).
- 테이블 DDL: `backend/db/schema.sql`, 연동 절차: `docs/supabase-setup.md`.
- `@supabase/supabase-js`를 `backend/package.json`에 추가(설치·키 입력은 사용자). 키 없으면 in-memory로 자동 동작 → 앱 무중단.
- 남은 것(사용자): Supabase 테이블 생성 + `.env`에 키 + `npm --prefix backend install`.

## ADR-003. 폴더 구조: frontend/ + backend/ (2026-07-14)

**맥락:** CLAUDE.md가 예고했던 client/server 구조를 실제 도입.

| 옵션 | 장점 | 단점 | 채택 |
|---|---|---|---|
| **frontend/ + backend/**(채택) | 표준 분리, 루트 스크립트로 위임 | 파일 이동으로 diff 큼 | **채택** |
| 루트 유지 + server/만 추가 | 프론트 경로 불변 | 비대칭 구조 | 기각 |
| npm workspaces | 의존성 공유 | 4주 범위엔 과함 | 기각 |

**결론:** `git mv`로 이력 보존하며 `frontend/`로 이동, `backend/` 신설. 루트 `package.json`이 `npm --prefix`로 위임.

## ADR-004. 추천 로직: 규칙 기반 우선, LLM은 게이트 후 (2026-07-14)

**맥락:** 3-에이전트(매칭·스케줄·데이터)를 어떻게 구현할지.

| 옵션 | 장점 | 단점 | 채택 |
|---|---|---|---|
| **규칙 기반 엔진 먼저**(채택) | PII·비용 0, 결정론·검증 쉬움, 즉시 동작 | 표현 유연성 낮음 | **v1 채택** |
| 지금 외부 LLM | 자연어 설명·유연 | PII 외부전송·비용·환각·게이트 | 이후 |

**결론:** 매칭·스케줄·분석을 **규칙 기반**으로 먼저. LLM은 우리 닫힌 기준(matching-criteria·evidence-catalog)을 "설명/적용"만 하도록 설계해 이후 도입 → [llm-agent-plan.md](./llm-agent-plan.md).

## ADR-005. CORS: localhost·127.0.0.1 모두 허용 (2026-07-14)

**맥락:** Safari 등에서 `localhost`/`127.0.0.1` 불일치로 fetch가 CORS 차단됨.

**결론:** `CORS_ORIGIN`을 쉼표 목록으로 파싱하고 기본값에 `http://localhost:5173,http://127.0.0.1:5173`을 둠. origin 없는 요청(curl 등)도 허용.

## ADR-006. 성인 대상 가명 파일럿 허용 (2026-07-15)

**맥락:** 사용자가 "익명·비식별 안전지대"에 머물지 않고 실제 사용자에게 링크를 공유해 파일럿을 하길 원함. 기존 하드룰(`CLAUDE.md:49`)은 서버 저장을 게이트 뒤로 미뤄뒀으나, 실제로는 anonId 기반 비식별 저장(ADR-001)·동의 체크·삭제 API가 이미 구현돼 있어 대부분의 게이트 조건(`evidence-data-roadmap.md` §동의 기반 베타)을 이미 충족한 상태였음.

| 옵션 | 장점 | 단점 | 채택 |
|---|---|---|---|
| **성인 한정 가명 파일럿 지금 허용**(채택) | 이미 구현된 비식별·동의·삭제 인프라로 즉시 가능, 방향성 유지 | 미성년 보호 절차 없음(범위를 성인으로 한정해 대응) | **채택** |
| 로그인·계정 기반 베타로 확장 | 종단 추적 가능 | 게이트 미충족(계정·보안 설계 없음), 과도한 확장 | 기각(계속 게이트 뒤) |
| 게이트 전면 유지(현행) | 안전 | 사용자가 원하는 실제 파일럿을 막음, 방향성과 불일치 | 기각 |

**결론:**
- **대상: 성인만.** 공유 링크 사용자는 전원 성인으로 전제하고 미성년·보호자 동의 절차는 두지 않는다.
- **목적: 교육·자기연구.** IRB·기관 연구윤리 승인이나 논문·학회 발표를 전제하지 않는다. 발표·출판을 하게 되면 그때 별도로 재검토한다.
- **범위: anonId 가명, 서버는 비식별 파생값만**(ADR-001 화이트리스트 유지). 이름·자유응답 서버 저장 금지는 그대로 유지.
- **동의: 사전 고지 강화.** 목적·수집 항목·보존기간·철회/삭제 경로를 명시한 동의 화면(앱)으로 opt-in만 저장.
- 이 결정으로 `CLAUDE.md`·`evidence-data-roadmap.md`·`context.md`를 함께 갱신한다.

## ADR-007. 제품 정체성: MBTI 입구 + 자기조절 무게중심 (2026-07-15)

**맥락:** `evidence-catalog.md`의 H-SRL-1(성과는 MBTI 유형보다 자기조절학습/메타인지 보정으로 더 잘 설명된다)이 참이라면, 제품의 실질적 무게중심을 어디에 둘지 결정이 필요했음.

| 옵션 | 장점 | 단점 | 채택 |
|---|---|---|---|
| **MBTI 입구 + 카피 무게중심은 자기조절**(채택) | 진입장벽 낮음(친숙한 MBTI로 시작)·동기부여, 근거(H-SRL-1)와 정합, 과신 방지 | 두 층위를 계속 구분해 표현해야 하는 부담 | **채택** |
| MBTI 전면·비중도 MBTI 중심 | 단순 | H-SRL-1과 불일치, P-B(선호≠효과) 위반 위험 | 기각 |
| 자기조절 전면(MBTI 최소화) | 근거 정합성 최고 | 진입 동기·친숙함 약화, 기존 UX 전면 개편 필요 | 기각(과도) |

**결론:**
- **입구(화면 흐름·온보딩)**: MBTI를 계속 전면에 둔다. 사용자는 MBTI로 시작해 자신의 성향을 탐색한다.
- **무게중심(설명·카피·근거 인용)**: 추천 이유·피드백·루틴 문구는 메타인지·자기조절 루프(예측→회상→대조, task/state baseline)에 실질적 비중을 둔다. MBTI 매칭은 "약한 힌트"로 명시하고 자기조절 데이터(보정오차·task/state 반영)가 더 근거 있는 신호임을 함께 드러낸다.
- **경계**: "MBTI가 방법을 결정한다"는 표현을 쓰지 않는다(P-B 유지). 이중구조(입구는 MBTI, 근거는 자기조절)를 감추지 않고 명시적으로 드러내는 편이 신뢰를 높인다.

## ADR-008. 외부 LLM 간이 MBTI 추정 채팅 허용 + G6 게이트 개정 (2026-07-20)

**맥락:** 설문이 딱딱해 자신의 유형을 못 고르는 사용자를 위해, 외부 LLM(Gemini)과 **동의 후** 짧게(≈2회) 대화해 MBTI를 **간이 추정**하고, 그 유형을 기존 `matchMethods(mbti)`에 넣어 공부법을 매칭하고자 함. 그런데 기존 게이트 G6([llm-agent-plan.md](./llm-agent-plan.md) §0)는 "원문·자유응답을 외부 LLM에 넣지 않는다(비식별 파생값만)"를 걸어 대화형 판정과 충돌했다. 사용자 결정: **오늘 결정을 주요 원칙으로 하고 게이트를 개정한다.**

| 옵션 | 장점 | 단점 | 채택 |
|---|---|---|---|
| **동의 기반 대화형 간이 추정 허용(게이트 개정)**(채택) | 설문 진입장벽 낮춤, 사용자가 원하는 흐름, 다운스트림(matchMethods)은 불변 | MBTI 자체 신뢰도 한계·외부 전송 프라이버시(동의로 대응) | **채택** |
| 게이트 전면 유지(대화 원문 외부전송 금지) | 프라이버시 보수적 | 사용자가 원하는 기능 불가 | 기각 |
| 프론트에서 직접 LLM 호출 | 단순 | **API 키 노출**(보안 위반) | 기각 |

**결론(개정된 게이트):**
- **간이 추정 인정:** 외부 LLM이 낸 MBTI(예: INTJ)를 "공식 판정 아님, 탐색적 간이 추정"으로 명시하되 매칭 입력으로는 신뢰해 사용한다. 결과 화면에 "간이 추정" 라벨과 MBTI 한계 고지를 함께 둔다(P-B 유지).
- **대화 원문 외부 전송은 이 채팅 경로에 한해, 사전 동의한 사용자만 허용.** 동의 화면에 목적·전송처(외부 LLM)·보존/삭제를 명시한다.
- **유지하는 안전(개정 아님):** ① API 키는 backend `.env`에만, 프론트 직접 호출 금지 — 반드시 **backend 프록시**(`POST /api/mbti-chat`) 경유. ② 실패·타임아웃 시 규칙 기반 설문으로 **폴백**. ③ **연구 데이터/분석 경로(ADR-001 화이트리스트)는 여전히 비식별 파생값만** — 채팅 경로의 원문 허용이 연구 저장 경로로 새지 않게 분리한다. ④ 진단·성적예측·유형 우열 표현 금지.
- **키 조달:** `GEMINI_API_KEY`는 사용자가 발급·주입(Supabase와 동일 패턴). 키 없으면 채팅 기능은 비활성, 규칙 기반 설문만 동작.
- 이 결정으로 `llm-agent-plan.md`(§0 게이트 상태), `plan.md`를 함께 갱신한다.

## ADR-009. 결과의 재정의: 수치 → 회고 가능한 산출물 + 의미 프레임 명시 + LLM 근거 보완 (2026-07-22)

**맥락:** 배포 파일럿·기획 점검에서 "플로우를 끝낸 사용자가 그래서 무엇을 얻었고 다음에 뭘 하는지"가 비어 있다는 문제가 드러났다. 결과 화면은 방법 TOP3·루틴을 주지만, 별도 리포트(`AnalysisReport`, `/api/analysis`)는 `매칭≠baseline 비율`·`평균 보정오차` 같은 **연구자용 집계**만 보여줘 사용자가 자기 결과를 회고·포트폴리오로 쓸 수 없었다. 또 간이 추정 채팅(ADR-008)은 4글자를 내 설문을 **대체**할 뿐, 사용자가 준 일상 근거가 판정 근거로 **보완**되지 않았다.

| 옵션 | 장점 | 단점 | 채택 |
|---|---|---|---|
| **결과를 회고 산출물로 재정의 + 개인 회고 리포트 분리 + 의미 프레임 + LLM 근거 보완**(채택) | 사용자 가치 명확화(ADR-007 자기조절 무게중심과 정합), 프라이버시(로컬 전용), 하드룰 충돌 없음 | 표면·문구가 늘어 유지 부담 | **채택** |
| 연구 집계 화면만 개선 | 작음 | 사용자 관점 부재는 그대로 | 기각 |
| 경쟁·랭킹·게이미피케이션 도입(유사 서비스 차용) | 동기부여 | 하드룰(비교·경쟁·알림 금지) 위반 | 기각 |

**결론:**
- **의미 재정의:** 이 제품은 성격풀이가 아니라 **자기조절 회고 도구**다. "MBTI 입구 → 행동·피로 신호 정리 → 오늘 시도할 방법·루틴 → 예측·결과 대조로 자기 검증 → 회고로 남김". 결과·랜딩에 이 의미를 **명시(의미 프레임)**한다.
- **개인 회고 리포트(신규):** 로컬 데이터(result·records·feedback·calibration)만으로 "오늘의 나 요약·실행 기록·예측 vs 실제·수용 요약·다음 액션"을 보여주고 클립보드 복사를 제공. 연구 집계(`AnalysisReport`)는 "전체 경향(연구 집계)"로 라벨을 분리·명확화한다.
- **놓친 엣지 케이스 대응:** (a) 공식결과 없이 탐색만 한 사용자의 빈약한 산출물, (b) 재방문 시 "지난번 대비" 부재, (c) 결과 저장·회고·공유 형태 부재 → 회고 리포트로 보완.
- **LLM 근거 보완(ADR-008 확장, Gemini만):** 채팅 추정이 `observedSignals`(관찰된 일상 근거 → 행동지표 매핑)를 함께 내도록 하고, 결과·회고에 "간이 추정·공식 아님" 고지와 함께 표시한다. **판정 대체가 아닌 근거 보완**이며 개인 응답이 추천의 중심임을 유지(P-B). OpenAI는 도입하지 않는다(게이트 유지).
