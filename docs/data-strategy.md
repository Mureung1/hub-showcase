# CareerSignal 데이터 전략

## 1. 문서 목적

이 문서는 CareerSignal이 사용하는 자료의 계층, 출처, 획득 방식, 처리 모델, 신뢰도와 에이전트별 소비 관계를 정의한다. 시스템 저장·실행 구조는 [아키텍처](architecture.md), 에이전트의 검색과 생성 동작은 [에이전트 설계](agent-design.md)에서 다룬다.

## 2. 데이터 원칙

- 채용공고 원문과 출처 메타데이터를 분석의 원천으로 보존한다.
- LLM이 생성한 Wiki·요약·관계는 원문을 대체하지 않는다.
- 통계는 실제 채용공고에서 직접 관찰한 요구사항만 집계한다.
- 회사 공식 자료는 공고 해석과 회사 맥락을 보강한다.
- 공공·표준 자료는 직무 기준과 용어 정규화에 사용한다.
- 외부 블로그·영상은 준비 전략에 사용하며 기업의 직접 요구사항으로 간주하지 않는다.
- 모든 주장과 분석 결과는 원문 청크·통계 항목·그래프 노드 중 하나 이상의 근거를 가진다.
- 자료는 직무·기업·기업군·공고·게시일·수집일·데이터 버전으로 추적한다.

## 3. 자료 계층과 허용 용도

| 등급 | 자료 | 요구사항·통계 | 해석 보강 | 준비 전략 |
| --- | --- | --- | --- | --- |
| A | 기업 공식 채용공고 | 직접 사용 | 직접 사용 | 직접 사용 |
| B | 회사 공식 채용·기술·문화 자료 | 통계에 미사용 | 직접 사용 | 직접 사용 |
| C | NCS·직무사전·공공 표준 | 통계에 미사용, 용어 정규화 | 직무 공통 기준 검증 | 직접 사용 |
| D | 작성자와 전문성을 확인한 외부 블로그·영상 | 사용 금지 | 제한적 교차 확인 | 직접 사용 |
| E | 출처·작성자·원문을 확인하기 어려운 자료 | 사용 금지 | 사용 금지 | 후보 탐색만 허용 |

자료의 신뢰도와 용도는 별개다. 외부 전문가 자료가 준비 전략에 유용하더라도 기업의 요구 빈도나 특정 회사의 인재상 근거로 승격하지 않는다.

| 3차 전략 | 학습·프로젝트 자료 | 공식 문서·신뢰 가능한 교육 자료 | OpenAI 웹 검색 후 원문 수집 | OpenAI 웹 검색, GPT-5.6 Terra | 준비 로드맵 |

OpenAI API는 텍스트 분석·구조화 출력·웹 검색에 사용한다. Gemini의 `gemini-3.5-flash` 무료 등급은 공개 YouTube 영상 분석에 한정하고 사용자 개인정보, 자소서, 비공개 자료를 입력하지 않는다. 모델 ID는 환경변수로 관리하고 변경 시 평가 표본을 다시 검증한다. YouTube Data API는 영상 후보의 제목·채널·게시일·URL을 구조화해 수집할 때 사용한다.

사람인·원티드·고용24 채용정보 API는 수집 경로에 포함하지 않는다. 기업 공식 채용 페이지를 채용공고의 핵심 출처로 사용한다. 포털 채용 사이트는 크롤링하지 않는다.

## 5. 자료별 에이전트 소비 관계

`직접`은 해당 에이전트가 원자료나 산출물을 조회한다는 뜻이고, `간접`은 앞 단계 산출물을 통해 영향을 받는다는 뜻이다.

| 자료 | 데이터·지식 | 통계 분석 | 채용공고 해석 | 합격 전략 | 준비 로드맵 |
| --- | --- | --- | --- | --- | --- |
| 개별 채용공고 | 수집·구축 | 직접 | 직접 | 간접, 필요 시 원문 확인 | 간접 |
| 공고 정형 추출 | 저장·인덱스 | 생성 | 직접 | 간접 | 간접 |
| 통계 분석 결과 | 저장·연결 | 생성 | 직접 | 직접 | 직접 |
| 회사 공식 채용 자료 | 수집·구축 | 미사용 | 직접 | 직접 | 필요 시 직접 |
| 회사 공식 기술·제품 자료 | 수집·구축 | 미사용 | 직접 | 직접 | 직접 |
| NCS·직무사전 | 수집·구축 | 용어 정규화 | 직접 | 직접 | 직접 |
| 면접·자소서 전략 자료 | 수집·구축 | 미사용 | 원칙적으로 미사용 | 직접 | 간접 |
| 포트폴리오 전략 자료 | 수집·구축 | 미사용 | 원칙적으로 미사용 | 직접 | 직접 |
| 학습·프로젝트 자료 | 수집·구축 | 미사용 | 미사용 | 일부 직접 | 직접 |
| Wiki·벡터·그래프 | 생성 | 제한적 | 직접 | 직접 | 직접 |
| 공고 해석 결과 | 저장·연결 | 미사용 | 생성 | 직접 | 직접 |
| 합격 전략 결과 | 저장·연결 | 미사용 | 미사용 | 생성 | 직접 |

통계 결과는 채용공고 해석·합격 전략·준비 로드맵의 공유 근거다. 합격 전략과 준비 로드맵이 통계 원문 전체를 매번 입력받는 대신 범위 식별자로 필요한 항목만 조회한다.

## 6. 원문과 출처 저장

원천 자료는 다음 메타데이터를 가진다.

```text
source_id
source_type
source_tier
url
publisher
author
published_at
retrieved_at
job_role_ids
company_id
posting_id
content_hash
raw_content
license_note
robots_policy
reliability_score
allowed_uses
dataset_version
```

동일 URL이라도 내용이 바뀌면 새 원문 버전을 저장한다. `content_hash`가 같으면 중복 원문을 재사용한다. 삭제되거나 접근할 수 없어진 자료도 기존 분석 결과의 근거 추적을 위해 수집 당시의 메타데이터와 허용된 원문 범위를 보존한다.

## 7. Wiki·벡터 인덱스·지식 그래프

### 7.1 Wiki

Wiki는 직무·역량·기업군·회사·준비 전략 단위의 생성 문서다. 각 문단과 주장은 원문 청크 식별자, 생성 모델, 프롬프트, 데이터 버전과 신뢰도를 가진다. Wiki는 여러 원문을 압축한 검색용 지식 자산이며 사실의 최종 원천은 아니다.

### 7.2 벡터 인덱스

원문 청크와 Wiki 청크에 임베딩을 생성한다. 키워드 검색과 벡터 검색 결과를 결합해 표현이 다른 유사 요구사항을 찾는다. 직무·기업·기업군·자료 계층·게시일 필터를 검색 전에 적용한다.

### 7.3 지식 그래프

그래프는 다음 관계를 표현한다.

```text
공고 → 요구사항 → 역량 → 직무 표준
요구사항 → 회사 공식 근거
요구사항 → 증명 산출물 → 포트폴리오·자소서·면접
역량 → 선수 역량 → 학습 자료·프로젝트
프로젝트·학습 → 충족하는 체크리스트 항목
```

노드와 엣지는 원문 또는 검증된 분석 산출물에 연결한다. 데이터·지식 에이전트는 원문·Wiki에서 원천 노드와 관계를 구축한다. 통계 분석·채용공고 해석·합격 전략·준비 로드맵 에이전트는 자기 산출물에서 파생된 관계를 해당 분석 버전에 기록하고, 분석 버전이 활성화될 때 결과와 함께 공개한다.

## 8. 웹과 YouTube 조사 정책

웹 검색은 새 자료를 발견하는 도구이며 검색 결과 요약만으로 최종 근거를 만들지 않는다. 선택한 URL의 원문과 메타데이터를 수집하고 허용 용도와 신뢰도를 평가한 뒤 지식 버전에 포함한다.

YouTube 자료는 다음 절차로 처리한다.

```text
영상 후보 검색
→ 채널·작성자·게시일·설명 확인
→ 공개 영상 분석
→ 주장·요약·관련 구간 구조화
→ 자료 계층·신뢰도 평가
→ 원문 URL과 함께 저장
```

영상 전체 복제본이나 비공개 자막을 저장하지 않는다. 영상에서 추출한 조언은 준비 전략 근거로 사용하고 공식 채용공고의 요구사항으로 집계하지 않는다.

## 9. 데이터셋과 평가 세트

| 데이터 | 정의 | 용도 |
| --- | --- | --- |
| mock | 화면 정보 구조를 검증하는 창작 데이터 | 정적 프로토타입 |
| fixture | 시스템 계약과 수직 슬라이스를 검증하는 고정 응답 | 프론트·서버·DB·에이전트 연결 |
| 평가 세트 | 실제 공고와 사람이 확정한 정답·루브릭 | 에이전트 품질 평가 |
| 서비스 데이터 | 출처·검증·버전이 있는 실제 자료와 분석 결과 | 배포 서비스 |

평가 세트는 직무와 기업군의 패턴을 포함하는 실제 공고 18~30건으로 구성한다. 공고별 기대 추출 결과, 해석 루브릭, 용어 정규화 규칙, 근거 허용 범위를 사람이 확정한다.

평가 지표는 다음을 포함한다.

- 요구사항 추출 정밀도·재현율
- 용어 정규화 정확도
- 통계 수치와 분모 일치
- 근거 정확도와 미지원 주장 비율
- 직무·기업군·공고 범위 일치
- 공고 해석→체크리스트→합격 전략→준비 로드맵 연결 완전성
- Hybrid RAG와 GraphRAG의 근거·관계 성능 차이

## 10. 데이터 갱신 원칙

- 신규·수정·삭제 공고는 해당 직무의 통계와 영향 범위 분석을 갱신한다.
- 회사 공식 자료는 연결된 직무·기업군·공고의 해석 이후 단계를 갱신한다.
- 표준 자료는 용어와 선수 관계에 영향을 받는 직무를 갱신한다.
- 외부 준비 전략 자료는 합격 전략과 준비 로드맵에만 직접 영향을 준다.
- 사용자 입력 공고는 서비스 통계와 직무 기준선에 포함하지 않는다.

세부 재실행 범위와 버전 활성화 절차는 [아키텍처](architecture.md#6-분석-오케스트레이터)를 따른다.
