# 자격증·스펙 취득 경로 플래너 Wiki


---

## 1. 핵심 기능 (Functional Requirements)

### FR-1. 목표 직무 입력 및 채용공고 수집
- **내용**: 사용자가 목표 직무를 입력하면 관련 채용공고를 수집
- **구현 방식**: 사람인 Open API를 Feign 클라이언트로 호출. 실시간 폴링이 아니라 사용자가 직무를 등록/갱신할 때 온디맨드로 수집하고, 이후엔 주기적(예: 1일 1회) 재수집으로 최신 공고 반영
- **참고**: 사람인 API는 베타 상태 — 응답 필드·엔드포인트 스펙이 사전 공지 없이 변경될 수 있음

### FR-2. 자격증/스킬 추출 및 정규화
- **내용**: 공고의 `우대조건`/`자격요건` 자유 텍스트에서 자격증·스킬 명을 추출하고 표준 명칭으로 통일 ("컴활1급" = "컴퓨터활용능력 1급")
- **구현 방식**: 정규화 에이전트가 1차로 룰 기반 사전 매칭을 시도하고, 애매한 표현만 선별해 무료 LLM API에 배치로 정규화 요청. 동시에 "필수"/"우대"/"있으면 좋음" 강조도를 문맥 기반으로 분류

### FR-3. 언급 빈도·강조도 집계 및 랭킹
- **내용**: 직무별로 자격증이 얼마나 자주, 얼마나 강하게 언급됐는지 집계해 랭킹으로 제공
- **구현 방식**: MyBatis로 공고-자격증 매핑 테이블을 join·가중합하는 집계 쿼리 작성. 강조도(필수/우대)에 가중치를 다르게 부여

### FR-4. 자격증 취득 경로 최적화
- **내용**: 선택한 자격증들의 선수조건·응시 일정·남은 학기를 반영해 최적 취득 순서를 계산
- **구현 방식**: 자격증 간 의존관계(선수조건)를 Java에서 그래프(노드=자격증, 엣지=선수조건)로 구성 → 위상 정렬(topological sort)로 순서 제약을 만족하는 취득 순서 산출 → 응시 일정·남은 학기 제약을 반영해 최종 스케줄 계산. 순환 참조(A가 B의 선수조건이고 B가 A의 선수조건인 경우)는 그래프 구성 단계에서 탐지해 에러 처리

### FR-5. 개인 진행 상황 대시보드
- **내용**: 계획한 경로 대비 취득 완료/준비 중/예정 상태를 추적
- **구현 방식**: QueryDsl로 사용자별 진행 상태 동적 필터 조회 (예: "이번 학기 예정 + 미완료만")

### FR-6. 프로젝트 소개 페이지
- **내용**: 프로젝트를 소개하는 정적 페이지
- **구현 방식**: React(순수, 추가 라이브러리 없음)

## 2. 비기능 요구사항 (Non-Functional Requirements)

| 항목 | 요구사항 |
|---|---|
| 비용 | 개발·테스트 전 구간 $0 |
| 실시간성 | 연속 스트리밍 금지 — 사용자 트리거 + 주기적 배치 재수집만 사용 |
| API 호출 효율 | 사람인(일 500건) 한도 내에서 직무별 필요한 공고만 선별 수집 |
| LLM 사용 범위 | 정규화 애매 항목·최종 요약 생성에서만 배치 호출, 무료 tier 한도 내 |
| 확장성 | 추적 직무 수가 늘어나도 수집-정규화-집계 파이프라인이 서로 막히지 않도록 Kafka로 분리 |
| 유지보수성 | 자격증 표준 명칭 사전, 강조도 가중치는 코드 재배포 없이 조정 가능해야 함 |
| 보안 | 사람인 API 키는 환경변수로만 관리 |
| 테스트 용이성 | 본인의 실제 목표 직무(반도체 관련)로 즉시 반복 테스트 가능해야 함 |

## 3. 기술 스택

| 구분 | 기술 | 역할 |
|---|---|---|
| 언어 | Java 17 | 백엔드 전체 |
| 프레임워크 | Spring Boot 3.x | 애플리케이션 기반 |
| CRUD | JPA (Hibernate) | JobPosting, Certification, CertificationMention, UserProgress 등 기본 저장/조회 |
| 동적 조회 | QueryDsl | 사용자별 진행 상황 필터 조회, 직무별 랭킹 조건 조합 조회 |
| 집계 쿼리 | MyBatis | 언급 빈도·강조도 집계(join+가중합) |
| 경로 최적화 | Java (그래프 알고리즘) | 선수조건 그래프 구성, 위상 정렬, 순환 참조 탐지, 일정 제약 반영 스케줄링 |
| DB | PostgreSQL | 전체 데이터 저장 (Docker 로컬) |
| 메시징 | Kafka | 공고 수집 → 정규화 → 집계 파이프라인 비동기 분리 |
| 외부 API 클라이언트 | Feign | 사람인 API, 무료 LLM API |
| 프론트엔드 | React (순수) | 프로젝트 소개 페이지, 대시보드 UI |
| CI/CD | GitHub Actions | 기존 auto-merge.yml 컨벤션 유지 |
| 컨테이너 | Docker Compose | PostgreSQL, Kafka 로컬 실행 |

## 4. 제약조건 (Constraints)

- 개발 환경: 개인 노트북 — 로컬에서 무거운 LLM 실행 불가
- API 비용: 무료 tier만 사용 (사람인, Groq/Gemini)
- 실시간 스트리밍 금지: 사용자 트리거 기반 수집 + 배치 재수집만 허용
- Oracle 미사용: PostgreSQL로 대체
- 개발 기간: 4주 (캠프 일정)
- 잡코리아/인크루트 등 커뮤니티 게시글 크롤링 금지 — 이용약관 문제로 사람인 공식 API만 사용

## 5. 기능별 구현 매핑 요약

| 기능 | 사용 기술/API | 데이터 흐름 |
|---|---|---|
| 채용공고 수집 | 사람인 API (Feign) | 외부 API → Kafka(`jobposting.collected`) → DB(JPA) |
| 자격증 추출·정규화 | 룰 기반 + 무료 LLM API (Feign) | Kafka 컨슈머 → 정규화 결과 `certification_mention` 저장(JPA) |
| 빈도·강조도 집계 | MyBatis | `certification_mention` join 집계 → 직무별 랭킹 저장 |
| 경로 최적화 | Java 그래프 알고리즘 | 선수조건 그래프 구성 → 위상 정렬 → 최적 순서 계산 |
| 진행 상황 조회 | QueryDsl | REST API → 동적 조건 조회 → React 렌더링 |
| 프로젝트 소개 | React | 정적 컴포넌트 |
