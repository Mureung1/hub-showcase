# 데모 시나리오 · 리허설 대본 (T-16)

부스에서 실제로 말하고 누를 것. 발표 직전 준비는 [시연준비.md](./시연준비.md)를 먼저 볼 것.

---

## 0. 관람객은 두 종류다

| | 누구 | 무엇을 | 시간 |
|---|---|---|---|
| **A. 지나가는 사람** | 부스 앞을 스쳐 감 | QR로 직접 체험 (소비자) | 스스로 |
| **B. 멈춰 선 사람** | 심사위원·관심 있는 관람객 | 발표자가 전체 루프 시연 | 3~5분 |

A는 인쇄물 1페이지의 QR이 알아서 처리한다. 이 문서는 **B를 위한 대본**이다.

---

## 1. 장비 배치

```
[인쇄물 1p]  [인쇄물 2p]      [노트북]        [모니터]
 기획·주제    AI 워크플로우    사장님 화면      소비자 화면(폰 미러링)
                              16:9 대시보드    또는 추가 자료
```

**브라우저를 반드시 두 개로 나눈다.** 같은 브라우저면 localStorage 세션이 공유돼
사장님/소비자를 동시에 띄울 수 없다.

| 역할 | 브라우저 | 계정 |
|---|---|---|
| 사장님 | Edge (또는 Chrome 일반 창) | 신규사장 (고정) |
| 소비자 | Chrome (또는 시크릿 창) | 풀에서 배정 |

푸시를 보여주려면 **소비자 쪽에서 알림 권한을 미리 허용**해 둔다. 현장에서 권한 팝업을
띄우면 흐름이 끊긴다.

## 2. 3분 대본 (핵심 루프)

말할 것은 `""`, 누를 것은 화살표로 적었다.

### ① 문제 제기 — 20초 · 인쇄물 1페이지를 가리키며

> "카페나 베이커리는 마감 때 남은 재고를 대부분 버립니다. 사장님은 반값이라도 팔고 싶은데
> 알릴 방법이 없고, 근처 사람은 그런 게 있는지 모릅니다.
> **버려질 재고와 그걸 싸게 살 사람이 서로를 못 찾는 문제**입니다."

### ② 사장님이 상품을 올린다 — 40초 · 노트북

→ 사장님 화면에서 **+ 상품 등록**
→ 상품명 `소금빵`, 카테고리 `베이커리`, 수량 `3`, 원가 `3000` → 할인가 `1500`
→ 픽업 마감 시각 선택 → **등록**

> "마감 임박이라 등록이 빨라야 합니다. 사진 없이 30초 안에 끝나게 만들었습니다."

### ③ 근처 소비자에게 알림이 간다 — 20초 · 소비자 화면

등록 직후 소비자 기기에 **푸시가 뜬다.**

> "관심 카테고리가 베이커리이고, 가게가 설정한 반경 안에 있는 사람에게만 갑니다.
> 조건이 안 맞으면 안 보냅니다 — 알림 피로를 만들면 앱을 지우니까요."

푸시가 안 오면 당황하지 말고 **인앱 알림 목록**을 연다(설계상 폴백이다).

> "푸시는 권한 거부나 미수신이 있을 수 있어서, 앱 안에도 항상 기록이 남습니다."

### ④ 소비자가 예약한다 — 40초 · 소비자 화면

→ 목록에서 방금 올린 `소금빵` (거리순 정렬 확인)
→ 딜 상세 → 수량 선택 → **예약하기**
→ **픽업코드**가 뜬다

> "여기서 재고가 즉시 차감됩니다. 결제는 현장에서 하고, 앱은 예약과 픽업코드까지만 맡습니다."

### ⑤ 사장님 화면이 실시간으로 바뀐다 — 30초 · 노트북

→ 사장님 대시보드로 시선 이동 (자동 갱신됨)

> "픽업 대기가 늘고, 소진 진행률이 움직입니다. 카운터 PC에 하루 종일 띄워두는 화면이라
> 가로형으로 만들었습니다."

→ 픽업 대기 목록의 코드를 **픽업 확인**란에 입력 → 확인

> "손님이 오면 코드만 확인하면 끝입니다. 오늘 매출과 픽업 완료가 바로 반영됩니다."

### ⑥ 마무리 — 20초

> "등록 → 알림 → 예약 → 픽업까지 한 바퀴입니다.
> 여기 QR로 지금 바로 써보실 수 있습니다."

## 3. 기술 하이라이트 — 선착순 동시성 (1분)

관심을 보이는 사람에게만. **인쇄물 2페이지를 짚으며 시작한다.**

> "재고가 3개인데 100명이 동시에 예약을 누르면 어떻게 될까요?"

터미널에서 **로컬로** 실행한다(배포 DB를 건드리지 않고 출력이 깨끗하다).

```bash
npm run seed:load -w server -- --stock=3 --users=100
```

```bash
k6 run -e VUS=100 load/oversell.js
```

```bash
npm run verify:load -w server
```

기대 출력:

```
성공_201       3
품절_409       97

[통과] 오버셀 없음 — 판매 3 / 총 3
[통과] 재고 불변식 — 남은 0 === 3 - 3 = 0
결과: 전 항목 통과
```

> "정확히 3건만 성공합니다. 조건 검사와 차감을 **한 문장**으로 처리해서,
> 행 잠금 안에서 원자적으로 일어나기 때문입니다."

**질문이 나오면**: "락을 안 쓰면요?" → `UNSAFE_STOCK=1`로 서버를 띄우고 같은 명령을 반복한다.
재고 3개에 21건이 성공하는 걸 보여준다. 절차는 [부하테스트.md](./부하테스트.md) §5-B.

> "더 흥미로운 건 이겁니다 — 오버셀이 났는데도 `재고 음수 아님` 검사는 통과합니다.
> DB 제약만 믿으면 못 잡습니다. 그래서 판정을 응답이 아니라 **DB 불변식**으로 합니다."

## 4. 자주 나올 질문

| 질문 | 답 |
|---|---|
| 로그인이 없네요? | MVP 범위 밖으로 **의도적으로** 뺐습니다. 부스에서는 계정 풀 40개를 서버가 순서대로 배정해 방문자끼리 안 섞이게 합니다 |
| 위치는 GPS인가요? | 등록한 기준 주소입니다. 좌표가 고정이라 사전 인덱싱이 가능하다는 이점도 있습니다 |
| 거리 계산은? | PostGIS `ST_DWithin` + GiST 인덱스입니다. 처음엔 Haversine을 직접 썼는데 계산식으론 인덱스를 못 타서 바꿨습니다 |
| 얼마나 빠른가요? | 배포 기준 딜 목록 약 100ms(p50)입니다. 처음엔 248ms였는데 DB 리전을 서버 쪽으로 옮겨 절반 이하로 줄였습니다 |
| 알림은 실제로 가나요? | FCM 웹 푸시입니다. 지금 보신 게 실제 발송입니다 |
| 노쇼는요? | 픽업 마감이 지나면 예약을 만료시키고 재고를 되돌립니다. 페널티는 범위 밖입니다 |

## 5. 실패 시 복구

부스에서 실제로 겪을 수 있는 것만 적었다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 첫 클릭이 수십 초 멈춤 | Render 절전 | 시연 전 헬스체크로 깨워둔다. 이미 멈췄으면 "무료 서버라 절전에서 깨는 중"이라고 말하며 기다린다 |
| 딜 목록이 비어 있음 | 딜 마감시간 경과 | [시연준비.md](./시연준비.md) 2단계 재실행 (30초) |
| 사장님 화면이 대시보드로 직행 | 이미 가게가 등록됨 | W1 시연을 하려면 재시딩. 안 할 거면 그대로 진행 |
| 푸시가 안 옴 | 권한·네트워크 | 인앱 알림 목록으로 전환. **설계된 폴백이라고 설명하면 오히려 플러스** |
| 예약 시 품절 | 앞선 방문자가 소진 | 다른 딜로 진행하거나 재시딩 |

> 무료 티어를 쓰는 건 숨기지 말고 말한다. "비용 0으로 배포했고, 절전은 그 대가"라고 하면
> 변명이 아니라 선택으로 들린다.
