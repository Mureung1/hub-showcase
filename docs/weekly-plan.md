# 주간 계획 (2주차)

## 이번 주 목표
`checklist.md`의 "다음 주(2주차)까지 완료 목표" 기준: **매칭 알고리즘(핵심 기능 A)이 로그인부터 매칭 후보 조회까지 실제로 동작하는 것**. 금요일까지 이 흐름이 화면에서 눈으로 확인 가능해야 한다.

## 요일별 배치
핵심 시나리오(로그인 → 등록 → 매칭 후보 조회) 순서를 그대로 따라가도록 배치. 각 항목은 하루 안에 끝낼 수 있는 크기로 쪼갬.

### 월 — DB 기반 다지기
- [ ] `[P0]` DB 스키마 설계 및 Supabase 테이블 생성 (사용자, 거점, 매칭 요청 테이블)
- **완료 기준**: Supabase 대시보드에서 세 테이블이 보이고, 컬럼 구조가 `plan.md`의 데이터 흐름과 일치함

### 화 — 로그인
- [ ] `[P0]` 학교 이메일 인증 API (인증 메일 발송/검증)
- [ ] `[P0]` 로그인 화면 React 컴포넌트 구현 (RideSplit 디자인 반영)
- **완료 기준**: 브라우저에서 로그인 화면이 프로토타입과 동일한 디자인으로 보이고, 인증 API 호출이 실제로 응답함

### 수 — 이동 정보 등록
- [ ] `[P0]` 거점 목록 데이터 세팅 (정문/북문/대구역 등)
- [ ] `[P0]` 출발지·목적지·희망시간·도착 소요시간 등록 폼 UI (RideSplit 디자인 반영)
- **완료 기준**: 등록 폼에서 칩 선택이 프로토타입과 동일한 디자인·인터랙션으로 동작(로컬 상태만, 저장 API는 목요일)

### 목 — 저장 + 매칭 알고리즘
- [ ] `[P0]` 등록 데이터 저장 API
- [ ] `[P0]` 매칭 후보 조회 알고리즘 (같은 거점 조합 + 시간대 ±15분 필터링)
- **완료 기준**: 등록 폼 제출 시 실제로 DB에 저장되고, 저장된 데이터를 기준으로 후보 조회 API가 올바른 결과를 반환함

### 금 — 매칭 후보 화면 + 통합 점검
- [ ] `[P0]` 매칭 후보 리스트 화면 (RideSplit 디자인 반영)
- [ ] `[P1]` 로그인 → 등록 → 매칭 후보까지 전체 흐름 수동 테스트
- **완료 기준**: 로그인부터 매칭 후보 리스트까지 화면 전환 없이 끊기지 않고 확인 가능

## 점검 방법
매일 저녁, 그날 항목의 체크박스와 완료 기준을 스스로 확인하고 체크. 못 끝낸 항목은 다음날로 이월하되, 왜 늦어졌는지 한 줄 남겨두면 다음 주 계획에 참고 가능.
