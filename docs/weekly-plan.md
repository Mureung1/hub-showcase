### 수요일 완료 목표

- 실제 `DATABASE_URL`을 `apps/api/.env`에 입력한다.
- Supabase Session pooler와 Express의 실제 연결을 확인한다.
- `/api/health/live`와 `/api/health/ready`를 검증한다.
- 시작 재시도, 유휴 연결 오류와 정상 종료 처리를 검증한다.
- DB 연결 Task의 테스트와 문서를 완료한다.

### 목요일 완료 목표

- 병원 선택과 가족 인원 입력을 React 상태로 구현한다.
- mock 원격 웨이팅 등록과 대기 현황을 연결한다.
- 6번째 준비, 4번째 입장 요청과 20분 기한 상태를 표현한다.
- 순서 미루기와 취소가 `useState`로 동작하게 한다.

### 금요일 완료 목표

- 원격·현장 환자가 섞인 관리자 통합 대기열을 구현한다.
- 현장 등록과 도착·호출·보류·취소 상태 변경을 구현한다.
- 환자 모바일 화면과 관리자 데스크톱 화면을 검증한다.
- 완료·미완료 작업을 이슈와 다음 주 계획에 반영한다.

### 범위에서 제외

이번 주 핵심 화면은 서버 없이 mock 데이터로 먼저 검증합니다. 실제 회원가입·인증과 전체 웨이팅 API 연결은 DB 기반과 화면 흐름을 확인한 다음 별도 이슈로 진행합니다.

## 3주차: 수직 슬라이스와 자동 만료

기간: 2026년 7월 20일 월요일 ~ 7월 24일 금요일

### 이번 주 목표

1. 신규 병원 관리자 인증 흐름을 복구하고 입점 진행 화면까지 연결합니다.
2. 미도착 자동 만료 작업을 Express와 PostgreSQL로 완성합니다.
3. 원격 환자와 병원 관리자의 핵심 수직 슬라이스를 실제 화면·서버·DB로 검증합니다.
4. 목요일까지 개발을 마치고 금요일에는 문서, 이슈와 발표 자료를 정리합니다.

### 현재 진도 점검

| 구분 | 판정 | 근거 |
|---|---|---|
| 환자 원격 웨이팅 수직 슬라이스 | 완성 | React 요청이 Express와 Supabase DB를 거쳐 화면에 반영됨 |
| seed 병원 관리자 대기열 관리 | 완성 | 승인된 테스트 관리자 계정으로 통합 대기열 API와 화면이 연결됨 |
| 신규 병원 관리자 가입 흐름 | 보완 필요 | 인증 Redirect와 병원 소속이 없는 계정의 화면 전환이 필요함 |
| 자동 미도착 처리 | 보완 필요 | 판정 로직은 있으나 1분 실행기와 advisory lock이 필요함 |

이번 주에는 기능 범위를 넓히기보다 신규 병원 관리자 흐름과 자동 만료를 먼저 완성합니다.

### 최종 결과

- 신규 병원 관리자 인증과 입점 화면 전환을 완료했습니다.
- 원격 등록부터 직원 도착·호출까지 실제 화면·서버·DB 흐름을 검증했습니다.
- 1분 자동 만료, PostgreSQL advisory lock과 중복 방지 테스트를 완료했습니다.
- 직원 상세 알림 이력과 네트워크 재시도 상태까지 추가로 완료했습니다.
- 세부 결과와 이월 범위는 [주차별 작업 결과](./weekly-summary.md)에 정리했습니다.
