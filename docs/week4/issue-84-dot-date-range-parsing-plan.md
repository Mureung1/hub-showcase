# 마감일 "." 구분자 날짜 범위 파싱 수정 (이슈 #84)

> 작성일: 2026-07-27 (월) · 대상 이슈: [#84 마감일 구분자가 '.'인 날짜 범위가 파싱 안 됨](https://github.com/syd348/hub/issues/84)

## 목표 (한 줄)

**`parseDeadline()`의 날짜 범위 정규식이 "-"뿐 아니라 "." 구분자도 인식하도록 고치고, 이미
잘못 저장된 운영 DB 1건을 수동으로 보정한다.**

## 현재 상태 (전환 전)

- `crawler/src/mapper.ts`의 `DATE_RANGE_PATTERN`이 `-` 구분자만 매칭
- 운영 DB(Supabase `subsidies`, 총 1464건) 직접 조회 결과 `.` 구분자 케이스 1건 확인:
  `id: PBLN_000000000092578`, `deadline: "2020.01.01 ~ 2026.12.31"`, `dday: 9999`
- 실제 bizinfo API 최근 800건 샘플에서는 `.` 구분자 케이스가 0건 — 매우 드문 예외 케이스로
  추정(오래된 공고이거나 데이터 입력 시점의 이례적 케이스)
- 크롤러는 최근 200건만 매일 재수집(`crawler/src/index.ts`)하므로, 오래된 이 1건은 코드 수정
  후에도 다음 크론 실행에서 자동 보정되지 않음

## 범위

### 포함
- `DATE_RANGE_PATTERN`을 `[-.]` 구분자 허용으로 확장
- `mapper.test.ts`에 "." 구분자 케이스 테스트 추가
- 운영 DB의 `PBLN_000000000092578` 1건을 수동으로 올바른 값으로 UPDATE (사용자 확인 후 실행)

### 제외
- 전체 DB 재검증(다른 파싱 이상이 더 있는지) — 이번엔 발견된 1건만 수정
