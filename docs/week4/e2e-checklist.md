# E2E/수동 테스트 체크리스트

> 대상 이슈: [#57](https://github.com/syd348/hub/issues/57) · 살아있는 문서 — 화면이 바뀌면
> 관련 항목만 갱신한다 (AGENTS.md 문서 일관성 원칙)

PR 올리기 전에, 특히 client/온보딩/매칭/상세 화면을 건드린 PR이라면 이 체크리스트를 로컬에서
한 번 따라가며 확인한다. 라우트 단위 테스트(`server/src/routes/*.test.ts`)로 이미 커버되는
API 레벨 케이스는 여기서 반복하지 않고, **화면에서 실제로 보이는 동작** 위주로만 다룬다.

## 사전 준비

```bash
npm run dev   # client(5173) + server(3001) 동시 실행
```

## 골든 패스

- [ ] `/` 접속 → Welcome 화면 → "시작하기" 클릭 → `/onboarding/1`로 이동
- [ ] Step1(업종) 선택 안 하면 "다음으로" 버튼 비활성 → 하나 선택하면 활성화
- [ ] Step2(시·도) 선택 → Step3(구·군)로 이동, 상단에 선택한 시·도 이름이 문구에 반영됨
- [ ] Step3(구·군) 선택 → Step4(직원 수·연매출·업력) 전부 선택해야 "맞춤 지원금 찾기" 활성화
- [ ] Step4 완료 → `/onboarding/complete`에서 입력한 5개 값(업종/지역/직원수/연매출/업력)이
      요약에 정확히 표시됨
- [ ] "맞춤 지원금 보러가기" 클릭 → `/home`으로 이동, 상단에 내 조건(지역·업종·직원수) 표시
- [ ] 매칭 리스트에 카드가 뜨고, 각 카드에 매칭도·마감일·금액이 표시됨
- [ ] 정렬 칩 4종(전체/마감임박순/지원금액순/신규) 각각 클릭 → 리스트 순서가 바뀜
      (마감임박순 클릭 시 D-day가 작은 순으로 재배열되는지 확인)
- [ ] 카드 클릭 → `/subsidies/:id` 상세로 이동, 지원 금액·매칭도·마감일·신청 방식·신청
      자격·필요 서류·신청 방법이 전부 표시됨
- [ ] "신청하러 가기" 클릭 → 새 탭으로 외부 URL(`whereUrl` 또는 기본 bizinfo 링크)이 열림
- [ ] "← 목록으로" 클릭 → `/home`으로 정상 복귀
