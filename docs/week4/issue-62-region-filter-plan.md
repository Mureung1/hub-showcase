# region 불일치 필터링 + 매칭 조건 데이터 커버리지 조사 (이슈 #62)

> 작성일: 2026-07-25 (토) · 대상 이슈: [#62 매칭 시 조건 필터링이 전혀 적용되지 않음](https://github.com/syd348/hub/issues/62)

## 목표 (한 줄)

**region이 안 맞는 지원금은 매칭 결과에서 실제로 제외하고, 나머지 조건(industry/employees/revenue/businessYears/creditScore)은 필터링할 만한 데이터가 실제로 있는지 조사한다.**

## 현재 상태 (전환 전, 조사 완료)

- #43에서 "완전 필터링하면 사용자가 혼란스러울 수 있어 정렬(가중치) 우선"으로 명시적으로 결정
  (`docs/week3/issue-43-match-plan.md`)했고, 지금까지 그 정책 그대로 유지됨
- `scoreForProfile()`(`server/src/db/subsidies-repo.ts:157-171`)는 region 불일치 시
  `REGION_MISMATCH_PENALTY`(20점)만 감점하고 배열에서 제외하지 않음
- `paginate()`의 `total`은 필터링 없는 전체 배열 길이라, 어떤 프로필이든 항상 전체 건수(1554)가 뜸
- industry는 #52에서 감지율 6.6%(33/500)까지 개선했지만 여전히 낮아 가점만 적용, 페널티/필터 없음

## 조사 결과 (2026-07-25) — 온보딩 조건별 데이터 커버리지 전체 조사

region 필터링을 결정하면서, "다른 조건들도 실제로 필터링할 데이터가 있나?"를 사용자가 질문해서
`OnboardingProfile`의 6개 조건 전체를 다시 조사했다.

### 조건별 현재 상태

| 온보딩 조건 | `subsidies` 구조화 데이터 | 상태 |
|---|---|---|
| region(지역) | `region text[]`, ~98% 커버리지 | 있음 — 이번 이슈에서 필터 적용 |
| industry(업종) | `industry text[]`, ~6.6% 커버리지 (#52) | 약함 — 가점만 |
| district(구/군) | 없음 | 매칭에 전혀 안 씀 |
| employees(직원수) | 없음 | 매칭에 전혀 안 씀 |
| revenue(연매출) | 없음 | 매칭에 전혀 안 씀 |
| businessYears(업력) | 없음 | 매칭에 전혀 안 씀 (#51에서 "구조화 컬럼 없어서 범위 밖"으로 명시적으로 미룸) |
| creditScore(신용도) | 없음, UI에도 없음(선택 필드, MVP 미노출) | 수집조차 안 함 |

즉 6개 조건 중 **4개(구/군, 직원수, 연매출, 업력)는 매칭에 반영할 데이터가 아예 없다.**

### bsnsSumryCn(사업개요 원문) 텍스트 마이닝 — 실제 신호가 있는지 확인

정규식으로 뽑아낼 여지가 있는지, 실제 API 응답 300건을 정규식으로 스캔했다(임시 스크립트로
확인 후 삭제, 코드 변경 없음):

| 조건 | 원문 언급 비율 | 예시 |
|---|---|---|
| 업력/창업연차 | **11.7%** (35/300) | "업력 7년 미만 스타트업", "창업 5년 이내 기업" |
| 직원수/상시근로자 | **7.7%** (23/300) | "상시근로자수 5인 이상 300인 미만" |
| 연매출 | 2~6% (패턴에 따라) | "연매출액 3억원 이하 사업자" |
| 신용 | 0.7% | 거의 없음 |

참고로 업력(11.7%)·직원수(7.7%)는 #52에서 반영을 결정한 industry(6.6%)보다 오히려 신호가 더
많다 — 정규식 추출을 시도할 근거가 있다는 뜻.

또한 bizinfo API의 `pldirSportRealmLclasCodeNm`(분야 대분류)가 업종 매칭에 도움될지 확인했으나,
실제 값은 수출/금융/기술/인력/창업/경영/내수/기타 8종(2026-07-25 100건 표본 분포:
수출 36·경영 19·기술 16·내수 13·인력 7·창업 7·금융 1·기타 1)으로, 온보딩 업종 카테고리(음식점/
카페·베이커리/소매·유통/서비스업/제조업)와는 다른 축(지원 목적 분류)이라 **도움 안 됨**으로 결론.

### 다른 사이트(K-Startup, 소진공, 공공데이터포털) 조사 — 데이터 소스를 바꿔도 해결 안 됨

"기업마당 대신/추가로 다른 사이트 데이터를 쓰면 나아지나?"를 확인했다 (WebSearch/WebFetch로 조사,
2026-07-25):

| 소스 | 확인 결과 |
|---|---|
| 공공데이터포털 "중소기업 지원사업 통합정보" | **기업마당(bizinfo) 데이터를 그대로 재포장한 것** — 동일 원본, 새 정보 없음 |
| K-Startup(창업진흥원) Open API | 필드가 "사업개요/지원대상/신청방법" 등 bizinfo와 구조가 거의 동일 — 신청자격도 자유 텍스트, 직원수/매출/업력 구조화 필드 없음 |
| 소진공(소상공인시장진흥공단) Open API | 공개 API는 "상권정보"(가맹점 위치·업종)뿐 — 정책자금 신청자격 API는 없고 자체 웹사이트(ols.semas.or.kr) 화면으로만 안내 |

결론: 한국 정부기관들이 지원사업 신청자격을 공개하는 방식 자체가 대부분 자유 텍스트 설명이라,
소스를 바꿔도 근본적으로 같은 문제(구조화 안 된 텍스트)를 만난다. **bizinfo 특유의 한계가
아니라 데이터 공개 관행 자체의 한계** — 다른 사이트 추가는 이번 이슈 범위에서 제외.

Sources: [K-Startup 오픈 API](https://nidview.k-startup.go.kr/view/public/kisedKstartupService/businessInformation), [창업진흥원_K-Startup 조회서비스 | 공공데이터포털](https://www.data.go.kr/data/15125364/openapi.do), [소상공인시장진흥공단_상가(상권)정보_API | 공공데이터포털](https://www.data.go.kr/data/15012005/openapi.do)

### AI API(Claude 등) 사용 여부 검토

정규식/키워드 대신 AI로 원문을 파싱하는 방안도 검토했다. **정규식 우선으로 결론** — 이유:

- #44(지원금액 추출)에서 이미 같은 딜레마를 겪고 "비용/속도 이유로 정규식 채택, AI는 보류"로
  결정한 전례가 있음 (`docs/week3/issue-44-amount-extraction-plan.md`)
- 업력(11.7%)·직원수(7.7%)는 이미 정규식으로 시도할 만한 신호가 있음 (위 조사 결과)
- 매일 1500여 건을 처리하는 크론에 AI 호출을 추가하면 비용·속도 부담이 생기는데, 정규식으로도
  통하는 신호가 있는 이상 그 비용을 감당할 근거가 약함
- 신용도(0.7%)처럼 신호가 거의 없는 조건은 AI를 쓰더라도 원문 자체에 없는 정보를 만들어낼 수는
  없음 — UI에도 없는 선택 필드라 우선순위도 낮음

**결론: 지금 단계에선 AI API 도입 불필요.** 정규식 추출을 시도해보고, 그래도 커버리지가 낮으면
그때 다시 검토.

## 범위

### 포함 (이번 이슈)
- **region**: 불일치 시 `REGION_MISMATCH_PENALTY` 감점 대신 완전히 필터링(제외)
- **industry**: `분야 대분류` 필드는 도움 안 됨으로 이미 확인됨(위 조사 결과) — 남은 건 기존
  동의어 사전 확장 여지만 확인, 필터링은 도입하지 않음
- **employees/businessYears 정규식 추출 여부** — 아래 리스크 표에서 스코프 결정 대기 중

### 제외 (다음으로)
- industry 필터링 도입 — 감지율이 낮은 한(6.6%) 계속 보류
- region 정보가 전혀 없는(hashtags 미포함) 지원금 처리 방식 변경 — 지금처럼 중립 유지(필터링 대상 아님)
- revenue(연매출)/creditScore 추출 — 신호가 낮아(2~6%, 0.7%) 이번엔 보류
