# 빵지도 — 기술 스택

프로젝트에서 실제로 쓰고 있는 기술을 버전과 함께 정리한 문서. `client/package.json` / `server/package.json` 기준.

## 1. 전체 구조

모노레포(`client/` + `server/`) — 프론트와 백엔드를 분리된 앱으로 두고 저장소만 공유한다. 개발 시 `client`는 5173, `server`는 4000 포트로 각각 뜨고, `vite.config.js`의 프록시로 `/api` 요청을 백엔드로 전달한다.

## 2. 프론트엔드 (`client/`)

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | React 18 + Vite 5 | 데스크톱 브라우저 중심 SPA |
| 라우팅 | React Router 6 | `/`(지도) · `/themes` · `/list` · `/route` · `/mypage` |
| 전역 상태 | Zustand 4 | 선택/찜/로그인/필터/토스트 등 화면 간 공유 상태 (`store/useAppStore.js`) |
| HTTP | Axios | `api/` 폴더에 엔드포인트별 함수로 래핑 |
| 애니메이션 | Framer Motion 12 | **마운트/언마운트에만 사용** (모달, 트레이 카드 추가/제거) — idle/hover는 순수 CSS로 처리해 라이브러리 의존을 최소화 |
| 지도 | 네이버지도 JS SDK (NCP Maps API v3) | npm 래퍼 대신 `utils/loadNaverMaps.js`에서 스크립트를 동적 주입(Promise) — 로드 실패 시 안내 화면 표시 가능하게 하기 위함 |
| 스타일 | 순수 CSS (`styles/index.css`) | 디자인 토큰 기반, 프레임워크 없음. 컨벤션은 `docs/design.md` 참고 |
| 폰트 | Pretendard Variable(본문), JetBrains Mono(숫자/코드성 텍스트), Cloudsofa(로고 워드마크 전용) | |
| 린트 | ESLint 8 | `npm run lint` |

## 3. 백엔드 (`server/`)

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Express 4 | `routes/` → `controllers`(라우터에 직접 구현된 것 포함) → `services`/`db` |
| DB | Supabase(Postgres), `pg` 드라이버 | 연결 정보는 `DATABASE_URL`(Connection String), SSL 필수(`rejectUnauthorized:false`) |
| 인증 | bcrypt + JWT | Supabase Auth는 쓰지 않고 자체 API가 회원가입/로그인 전부 처리 |
| 동선 계산 | 완전탐색(순열) | 선택한 빵집 순서 전체 조합을 계산해 거리 기준 상위 3개 경로 반환(`services/routeService.js`) — 개수가 많아지면 휴리스틱 전환 여지를 남겨둔 구조 |
| 자동 추천 | `services/recommendService.js` | 질문 답변(개수/스타일/커피 여부 등) 기준으로 후보를 추리고, 동일한 동선 계산 로직을 재사용 |
| 개발 서버 | nodemon | `npm run dev` |

### DB 스키마 (`src/db/schema.sql`)

- `bakeries` — 이름/주소/좌표/대표메뉴/코멘트/가격대/영업시간/휴무일/사진/몰리는시간/커피여부(`has_coffee`, 현재 미입력)
- `users` — 아이디/비밀번호 해시
- `user_tastes` — 회원가입 시 고른 빵 취향(다대다)
- `user_bakery_status` — 가본 곳 / 가고 싶은 곳(찜)

시딩은 `server/src/db/seed.js`(`npm run db:seed`)가 `list.csv`에서 주소가 채워진 행만 읽어 NCP Geocoding API로 좌표를 붙여 넣는 방식. 주소 자체를 채우는 일회성 배치는 `server/scripts/fill_addresses.py`(네이버 지역검색 API 이용).

## 4. 외부 API

| API | 용도 | 비고 |
|---|---|---|
| NAVER Cloud Platform Maps API v3 | 지도 렌더링, 마커 | `client/.env`의 `VITE_NAVER_MAP_CLIENT_ID` |
| NCP Geocoding API | 주소 → 좌표 변환 | `server/.env`의 `NCP_CLIENT_ID`/`NCP_CLIENT_SECRET`, `db/seed.js`에서 사용 |
| 네이버 지역검색 API (오픈API) | 주소 자동 채우기 배치 스크립트용 | `server/.env`의 `NAVER_SEARCH_CLIENT_ID`/`NAVER_SEARCH_CLIENT_SECRET` — Maps 키와 발급처가 다름(developers.naver.com) |
| TMap 대중교통 API | 경로결과 화면 "버스" 모드 실제 소요시간 | `server/.env`의 `TMAP_APP_KEY`. 두 지점 사이 경로만 계산해주는 API라 "여러 빵집 방문 순서 최적화"(완전탐색/최근접 이웃, `routeService.js`)는 그대로 두고, 이미 정해진 순서의 구간별 소요시간만 이걸로 대체(`services/transitService.js`). 도보/자동차는 아직 거리 기반 근사치 |

빵집 "자세히 보기" 링크는 외부 API 없이 `client/src/utils/naverMapLink.js`가 이름+주소로 네이버 지도 검색 URL을 그때그때 만들어서 연결한다(업체가 등록한 링크는 신뢰할 수 없어서 폐기한 방식).

## 5. 데이터 중 목데이터인 것

아직 실데이터 수집 전이라 임시로 결정적 생성(같은 빵집은 새로고침해도 항상 같은 값) 값을 쓰는 필드:

- 빵 종류(`category`), 가격대(`priceTier`), 몰리는 시간(`busyHours`), 커피 판매 여부(`hasCoffee`) — `client/src/data/mockBakeryExtras.js`
- 실데이터(주소/좌표/대표메뉴/영업시간/휴무일)가 갖춰진 빵집은 `BY_NAME`에 우선 반영, 나머지는 `bakery.id` 기반 fallback

## 6. 배포 관련

- 프론트/백엔드 모두 아직 프로덕션 배포 전(로컬 개발 환경만 구성됨).
- 환경변수는 `client/.env.example`, `server/.env.example`에 플레이스홀더만 커밋, 실제 키는 커밋하지 않음.
