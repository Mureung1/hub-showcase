# 커밋·이슈 관리 규칙

콕 프로젝트의 커밋 메시지와 GitHub 이슈를 함께 관리하는 규칙이다. 이 문서는 반드시 지킨다. 커밋 타입은 `.claude/skills/commit-convention`을 기반으로 하되, **이 문서가 최종 기준이며 이모지는 쓰지 않는다**(skill 예시의 이모지는 무시한다). 여기에 **이슈 연동·기능 단위 분리** 규칙을 더했다.

> 실제 `git commit`·이슈 생성은 사용자가 직접 실행한다. Agent는 커밋 메시지 문구와 커밋 분리안을 제안한다.

## 0. 절대 규칙 — upstream 금지·현재 위치에서만 작업 (반드시 준수)

> 이 규칙은 다른 모든 규칙보다 우선한다. 어길 경우 팀 공용 저장소를 오염시킬 수 있으므로 예외 없이 지킨다.

- **`upstream`으로 절대 push하지 않는다.** 이 저장소의 원격은 두 개다.
  - `origin` = `imjyong/hub` (개인 포크) — push 허용
  - `upstream` = `connect-AIAgentChallenge-26-1/hub` (팀 원본) — **push 절대 금지**
  - push는 언제나 `origin`으로만 한다. `git push upstream ...`, `git push` 기본 대상이 upstream인 경우 모두 금지.
  - upstream 반영은 GitHub에서 사람이 PR로만 진행한다. Agent가 upstream에 직접 쓰지 않는다.
- **반드시 현재 위치(`team/hub`)에서만 작업한다.** 이 저장소 디렉터리 밖의 파일을 만들거나 고치지 않는다. 상위 디렉터리·다른 저장소·홈 디렉터리 등으로 나가지 않는다.
- 커밋/푸시는 사용자가 요청할 때만 하고, push 전 `git remote -v`와 대상 원격이 `origin`인지 반드시 확인한다.

## 1. 컨벤션은 반드시 지킨다

형식: `<타입>: <한 줄 요약> (#이슈번호)` — **이모지는 쓰지 않는다.**

| 타입 | 용도 |
|---|---|
| feat | 새 기능 추가 |
| fix | 버그 수정 |
| docs | 문서 수정 |
| style | 코드 스타일(포맷팅 등, 로직 변경 없음) |
| refactor | 리팩터링 |
| test | 테스트 추가/수정 |
| chore | 설정·빌드·기타 잡무 |

- 요약은 변경의 "무엇"을 간결하게 쓴다. "왜"가 필요하면 본문에 덧붙인다.
- placeholder 문구("새 기능 추가" 등)를 그대로 쓰지 않고 실제 변경 내용으로 채운다.
- 타입을 빼먹지 않는다. 이모지는 붙이지 않는다(붙이면 컨벤션 위반).

## 2. 이슈와 함께 관리하고, 커밋 메시지에 이슈 번호를 넣는다

- 모든 작업은 GitHub 이슈로 먼저 등록한다. 이슈 하나는 대체로 [backlog.md](../backlog.md)의 Task(T01~T12) 하나에 대응한다.
- 커밋 메시지 요약 끝에 관련 이슈 번호를 `(#N)` 형식으로 붙인다.
  - 예: `feat: Brain Dump 분할 결과에 category 필드 추가 (#12)`
- 이슈를 닫는 커밋(또는 PR)에는 본문에 `Closes #N`을 적어 자동으로 닫히게 한다. 하나의 이슈가 여러 커밋으로 나뉘면, 마지막(또는 PR 머지) 시점에만 `Closes`를 붙이고 중간 커밋은 `(#N)` 참조만 단다.
- 이슈 번호를 아직 모르면 커밋하지 말고 먼저 이슈를 만든다. 번호 없는 커밋을 만들지 않는다.

## 3. 기능에 맞게 커밋을 나눈다

- 커밋은 **의미 있는 변경 단위(기능 하나, 화면 하나)가 끝난 시점**에 나눈다. 작업 중간 버전을 매번 커밋하지 않는다.
- 한 파일을 여러 번 고쳐썼어도 커밋은 기능 단위로만 나누고, 각 커밋엔 그 시점의 최종 내용만 담는다.
- **파일 단위가 아니라 기능 단위**로 나눈다. 한 기능에 여러 파일이 걸치면(컴포넌트 + 그걸 연결한 `page.js` + API route) 같은 커밋에 함께 넣는다.
- 한 커밋에 타입이 섞이면(기능 + 문서) 커밋을 분리한다. 예: 기능 코드는 `feat`, 관련 문서 갱신은 `docs`로 따로.
- 커밋 전 반드시 `git status`로 스테이징 대상이 이번 기능 단위에 맞는지 확인한다. `git add .`로 무관한 작업까지 같이 올리지 않는다.

### 커밋 분리 예시

한 세션에서 "category 추가 + Notion 저장 + 문서 갱신"을 했다면 이렇게 나눈다.

```
feat: Brain Dump 분할 스키마에 category(고정 7종) 추가 (#12)
feat: 분할된 마이크로스텝 Notion 저장 연동 (#12)
docs: T02 완료조건 체크 및 작업 보고 갱신 (#12)
```

## 4. 이 문서는 한국어로 작성·유지한다

커밋 메시지 요약도 한국어로 쓴다(타입은 영문 그대로).

## 요약 (반드시 지킬 것)

0. **upstream push 절대 금지, 현재 위치(`team/hub`)에서만 작업.** push는 `origin`으로만.
1. `<타입>: <요약> (#이슈번호)` 형식을 항상 지킨다. **이모지 금지.**
2. 이슈 먼저 등록 → 커밋에 `(#N)`, 닫을 땐 `Closes #N`.
3. 기능 단위로 커밋을 나누고, `git status`로 스테이징을 확인한다.
4. 한국어로 작성한다.
