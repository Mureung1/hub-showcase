# 다음 기능 설계: 과목 완료 체크 + 히스토리

시험이 끝난 과목을 "완료"로 표시해 우선순위 목록에서 빼되, 지운 게 아니라
따로 모아 볼 수 있게 한다. DB 영속성(미션 1)과 자연스럽게 이어지는 기능이다.

## 1. 화면 (Screen)

### 입력 페이지 (기존 확장)
- 과목 목록의 각 항목에 **"완료" 버튼**을 추가한다.
- 완료를 누르면 그 과목은 활성 목록에서 사라진다.

### 히스토리 (2차 슬라이스)
- "완료한 과목" 섹션(접기/펼치기). 과목명, 시험일, **완료 처리한 날짜** 표시.
- 각 항목에 **"되돌리기"** 버튼 → 다시 활성 목록으로.
- 완료한 과목이 없을 때 빈 상태 안내.

## 2. 데이터 (Data)

`subjects` 테이블에 컬럼 하나만 추가한다. 별도 히스토리 테이블은 두지 않는다.

| 컬럼 | 자료형 | 설명 |
|---|---|---|
| completed_at | text (nullable) | 완료 처리 시각. `NULL`이면 활성, 값이 있으면 완료. |

- 완료는 과목의 **상태**이지 별도 엔티티가 아니므로 컬럼 하나로 충분하다.
- `completed_at` 값 자체가 히스토리에 필요한 "완료한 날짜"가 된다.
- 삭제가 아니라 상태 변경이라 데이터가 남는다 (히스토리의 근거).

## 3. 흐름 (Flow)

1. 사용자가 과목의 "완료" 클릭 → `PATCH /api/subjects/:id/complete` → `completed_at = now`.
2. 활성 목록 조회는 `completed_at IS NULL`만, 히스토리 조회는 `IS NOT NULL`만.
3. 우선순위 계산은 활성 과목만 대상 (완료 과목은 애초에 목록에 없음).
4. 되돌리기 → `PATCH /api/subjects/:id/reopen` → `completed_at = NULL`.

### API
- `GET /api/subjects?status=active|done|all` — 기본값 `active` (완료 과목은 우선순위에서 제외)
- `PATCH /api/subjects/:id/complete`
- `PATCH /api/subjects/:id/reopen`

## 4. 설계 검토 (AI 초안을 그대로 받지 않고 따진 것)

### 크기 — 한 번에 다 넣지 않는다
"완료 체크"와 "히스토리 화면(접기/펼치기·되돌리기)"을 한 PR에 다 넣으면 크다.
→ **슬라이스 1은 "완료 표시 + 활성 목록에서 제외 + DB 저장"까지**. 히스토리 조회 UI와
되돌리기는 슬라이스 2로 뒤로 뺀다. 슬라이스 1만으로도 "완료 처리 → 목록에서 사라지고
새로고침해도 유지"라는 눈에 보이는 가치가 완성된다.

### 순서 — DB → 서버 → 프론트
프론트를 먼저 만들면 붙일 API가 없다. `DB 컬럼/마이그레이션 → 서버 API → 프론트` 순.

### 빠지기 쉬운 것 (초안에 없던 것)
- **기존 DB 마이그레이션.** `CREATE TABLE IF NOT EXISTS`는 이미 있는 파일에 컬럼을
  추가하지 않는다. 앱 시작 시 컬럼 존재를 확인하고 없으면 `ALTER TABLE ADD COLUMN`
  해야 한다. 놓치면 "새 컬럼이 없다" 에러가 난다.
- **GET 기본 동작 변경의 하위호환.** 지금 `GET /api/subjects`는 전체를 준다. 기본값을
  `active`로 바꾸면 동작이 달라지므로 `?status=` 파라미터로 명시적으로 나눈다.
- **오프라인 폴백.** 서버가 없을 때(localStorage 모드)도 완료 토글이 동작해야 한다.
  과목 객체에 `completedAt` 필드를 두고 로컬에서도 같은 규칙으로 거른다.
- **빈 상태.** 완료 과목이 0개일 때 히스토리 안내 문구.

## 5. 작업 분할

### 슬라이스 1 — 완료 체크 (MVP)
1. **DB**: `subjects`에 `completed_at` 컬럼 추가 + 기존 파일 마이그레이션(`ALTER TABLE`).
2. **서버**: `completeSubject(id)` 서비스, `PATCH /api/subjects/:id/complete` 라우트/컨트롤러.
3. **서버**: `GET /api/subjects`에 `?status=active|done|all` 필터 (기본 `active`).
4. **프론트**: `subjectsApi.js`에 `completeSubject(id)` 추가.
5. **프론트**: 입력 페이지 과목 항목에 "완료" 버튼, 완료 시 목록에서 제거. 오프라인 폴백 포함.

### 슬라이스 2 — 히스토리 + 되돌리기
6. **서버**: `reopenSubject(id)` 서비스, `PATCH /api/subjects/:id/reopen`.
7. **프론트**: 히스토리 섹션(완료 과목 조회, 완료 날짜 표시, 접기/펼치기, 빈 상태).
8. **프론트**: "되돌리기" 버튼 → 활성 목록으로 복귀.
