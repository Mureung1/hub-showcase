게임 기획 지망생이 역기획서와 오리지널 기획안을 가이드 템플릿으로 쓰고, 사람과 AI 양쪽에게 피드백·자동 채점을 받고, 챌린지로 겨루는 웹 플랫폼. 오늘은 로컬이 아니라 배포된 주소에서 돌립니다.

문제와 사용자

역기획서 앞에서 세 번 막힙니다

역기획서는 게임 기획 지망생에게 사실상 필수 포트폴리오인데, 처음 쓰는 사람은 매번 같은 세 곳에서 멈춥니다.

완료의 정의 — "코드가 그럴듯하다"가 아니라 요청이 서버를 거쳐 DB에 저장되고 다시 조회돼 화면 데이터로 돌아오는 한 바퀴가 관찰됐다. 이 문장을 문서에 박고, 검사 자체를 Agent에게 맡겼습니다.

Agent · Skill 협업 배치

많이 만들기보다 판단 근거를 고정

Agent 2개 + Skill 1개만 만들고, 셋 다 프로젝트 문서(BACKLOG·기획서·DESIGN_SYSTEM)를 먼저 읽게 했습니다. 그래야 같은 질문에 매번 다른 기준으로 답하지 않습니다.

Agent · 계획

plan-breakdown

주차 목표를 하루 크기로 분해해 표 하나로만 답한다. 파일도 이슈도 만들지 않는다.

  • 2주차: 테이블 2개→1개(JSONB) 지적 반영
  • 크리티컬 패스(Supabase 키) 발견
Agent · 검증

feature-verify

"다 됐다" 직전에 엔드포인트를 직접 두드려 요구사항별 PASS/FAIL. 코드 수정 권한은 없다.

  • 하나라도 FAIL이면 전체 FAIL
  • 검증이 막히면 BLOCKED로 정지
Skill · 디자인

design-guide

새 화면이 토큰·글래스 4요소·game-feel 규칙에서 벗어났는지 8항목 체크리스트로 자체 점검.

  • 스타일이 바뀌면 화면·토큰·문서·Skill을 함께 고친다

역할 구분

사람이 정한 것과 AI가 한 것

사람 (나)

목표 · 범위 · 완료 판정

  • 무슨 문제를 풀지, 무엇을 MVP에서 뺄지
  • P0/P1/P2 확정과 밀릴 때 자르는 순서
  • 데이터 모델·인증 경계 결정(프론트는 Supabase를 인증에만 직접 호출)
  • 디자인 방향 — 쿨톤 글래스, 강조색은 gold 하나
  • 라이브에서 직접 써보고 "쓸 만한가" 판정
AI (Agent · Claude Code)

분해 · 초안 · 검증

  • 주차 목표를 하루 크기 작업으로 분해, 누락·크리티컬 패스 지적
  • 테스트·코드 초안 작성과 리팩터
  • 다이어그램 작성과 매핑표 정리
  • 내 "됐다"를 엔드포인트로 검증해 PASS/FAIL 보고
  • 배포 설정·환경변수 문서화

  • VITE_API_URL 미설정 시 배포본이 자기 도메인의 /api를 호출해 실패
  • Render 무료 인스턴스 콜드스타트 ~50초 → 데모 직전 워밍업을 체크리스트로

  • 프론트가 갖는 키는 공개용 anon 하나뿐
  • service_role · Gemini · RAWG 키는 Render에만
  • 실제 .env는 커밋하지 않고 .env.example만

남은 한계와 마무리

정직하게 남은 것들

  • 코멘트 동시 쓰기 유실 — jsonb read-modify-write. 코멘트 테이블 정규화가 다음 큰 조각
  • AI 예시 96편 잔여 — Gemini 무료 하루 20건. 발표용 한도 보존이 우선
  • CORS 전체 허용 → Vercel 도메인으로 제한(데모 이후)
  • 지인 사용성 테스트 3인 미실시
