## 0. 배경 및 목표

WebView 기반 APK 배포를 앞두고, 웹과 다른 APK 환경의 제약(파일 시스템, OAuth 차단, 터치 인터랙션)을 해소하고 수익화 구조의 첫 단추를 끼운다.

**목표**
1. 인증을 아이디+비밀번호 단일 방식으로 전환 — WebView OAuth 차단 문제 원천 제거
2. CSV 가져오기/내려받기가 PC 브라우저·모바일 브라우저·APK 3개 환경 모두에서 동작
3. 쿠팡 파트너스 기반 영양제 광고가 실제 상품 데이터로 작동
4. 토스 스타일의 절제된 인터랙션으로 앱 완성도 향상

**성공 지표 (데모 기준)**
- 아이디/비번만으로 가입→로그인→데이터 접근 완결, 구글 관련 코드 0줄
- 3개 환경 각각에서 CSV 내보내기→가져오기 왕복 성공
- 식단 탭 광고 배너에서 실제 쿠팡 상품 페이지로 이동 가능
- 탭 전환·버튼 터치가 60fps로 부드럽고 "요란하다"는 피드백 0건

## 1. 인증 방식 전환 — 아이디 + 비밀번호 (P0)

### 1.1 결정 사항
- 구글 로그인 **완전 삭제** (UI, 코드, 의존성, 콘솔 설정 전부)
- 이메일 인증 절차 **완전 제거**
- **기존 구글 계정으로 생성된 계정과 연동 데이터는 전부 삭제** — 마이그레이션 없음
- 로그인 이후의 세션/토큰 발급과 데이터 접근 권한 체계는 **기존 구조 그대로 유지** (인증 수단만 교체)

### 1.2 기능 요구사항

#### FR-1.1 회원가입
- 입력 필드: **아이디 / 비밀번호 / 비밀번호 확인 / 닉네임** — 이 4개 외 어떤 것도 요구하지 않음
- 흐름: 4개 필드 입력 → 유효성 통과 → **[가입하기] 클릭 즉시 가입 완료 + 자동 로그인 상태로 홈 진입**
- 아이디 규칙: 영문 소문자+숫자, 4~20자, 중복 시 즉시 인라인 에러 표시
- 비밀번호 규칙: 8자 이상, 영문+숫자 조합
- 비밀번호 확인: 불일치 시 실시간 인라인 에러 ("비밀번호가 일치하지 않습니다")
- 가입 화면에 1회 고지: **"비밀번호를 잊으면 계정을 복구할 수 없습니다. 안전한 곳에 보관해주세요."** (이메일이 없어 복구 불가하므로 필수)

#### FR-1.2 로그인
- 아이디 + 비밀번호 → 로그인
- 자동 로그인(세션 유지) 기본 ON
- 실패 메시지는 원인 구분 없이 통일: "아이디 또는 비밀번호가 올바르지 않습니다" (계정 존재 여부 노출 방지)
- 동일 아이디 연속 실패 5회 → 1분 잠금 (무차별 대입 최소 방어)

#### FR-1.3 기존 데이터 삭제
- 구글 OAuth로 생성된 모든 계정 레코드와 그에 연결된 식단/분석 데이터 삭제
- 삭제는 되돌릴 수 없으므로 **삭제 전 전체 백업 1회** (백업 파일은 로컬 보관)
- 게스트 계정 데이터는 유지 (게스트 → 신규 가입 시 데이터 승계 동작도 유지)

#### FR-1.4 보안 필수 요건
- 비밀번호 **해시 저장 필수** (bcrypt 또는 백엔드 제공 해시) — 평문/Base64 절대 금지
- 클라이언트에 비밀번호 원문을 저장하거나 로그로 남기지 않음

### 1.3 수용 기준
- [ ] 코드베이스 전체 검색 시 구글 OAuth 관련 코드·패키지·환경변수 0건
- [ ] 아이디/비번/비번확인/닉네임만으로 가입 → 즉시 홈 화면 진입
- [ ] 새로고침·앱 재시작 후에도 로그인 유지
- [ ] APK 환경에서 가입·로그인 정상 동작
- [ ] 저장소에서 비밀번호가 해시 형태임을 확인
- [ ] 기존 구글 연동 데이터가 존재하지 않음 (백업 파일은 별도 보관됨)

## 2. CSV 가져오기 / 내려받기 — 크로스플랫폼 (P0)

### 2.1 기능 요구사항

#### FR-2.1 내려받기 (Export)
| 환경 | 동작 |
|---|---|
| PC 브라우저 | Blob + `<a download>` — 다운로드 폴더 즉시 저장 |
| 모바일 브라우저 | 동일 방식 — 기기 **Download 폴더**에 저장, 완료 토스트 "다운로드 폴더에 저장되었습니다" |
| APK (Capacitor) | `@capacitor/filesystem`으로 공용 다운로드 경로에 저장 → 완료 토스트 + 공유 시트 열기 옵션 |

- 파일명: `mealog_YYYY-MM-DD.csv` (한글 파일명은 일부 환경에서 깨질 수 있어 영문 고정)
- 인코딩: **UTF-8 with BOM** (엑셀 한글 깨짐 방지 — 필수)
- 어떤 환경에서도 무반응(silent fail) 금지 — 성공/실패 토스트 필수

#### FR-2.2 가져오기 (Import)
- 3개 환경 모두 파일 선택기 정상 동작 (APK는 Capacitor 기본 지원, 실기기 검증 필수)
- 헤더 스키마 불일치 → "지원하지 않는 파일 형식입니다" + 올바른 형식 예시 안내
- 중복 날짜 → "덮어쓰기 / 건너뛰기" 선택 다이얼로그
- 행 단위 파싱 실패는 건너뛰고 결과 요약: "42건 가져옴, 2건 실패"

#### FR-2.3 플랫폼 감지 유틸
- `getPlatform(): 'web' | 'mobile-web' | 'apk'` 단일 유틸로 통합, 모든 분기는 이 함수 기준
- APK 감지: `Capacitor.isNativePlatform()`

### 2.2 수용 기준
- [ ] PC 크롬: 내보내기 → 엑셀에서 한글 정상 → 재가져오기 성공
- [ ] 모바일 크롬: "내 파일 > 다운로드"에서 파일 확인
- [ ] APK: 내보내기 → 저장 확인 → 동일 파일 가져오기 성공
- [ ] 1,000행 기준 가져오기 3초 이내

## 3. 영양제 광고 — 쿠팡 파트너스 (P1)

### 3.1 결정 사항
- 광고 방식: **쿠팡 파트너스 제휴 링크 단일 방식**
- 식당 광고: **이번 릴리즈에서 제외**
- 노출 위치: **"오늘의 식단" 탭 내 "부족한 영양소는?" 가로형 소형 배너**

### 3.2 추천 로직 (핵심 스펙)

광고에 표시할 영양제는 아래 **2단계 우선순위**로 결정한다:

**1순위 — 실측 부족 영양소**
- 오늘(또는 최근 N일) 식단 기록 기준, 권장 섭취량 대비 달성률이 가장 낮은 영양소 상위 1~3개
- 해당 영양소와 매핑된 쿠팡 파트너스 상품 노출 (예: 칼슘 달성률 40% → 칼슘 영양제)

**2순위 (폴백) — 필수지만 흔히 섭취가 부족한 비타민·무기질**
- 발동 조건: 식단 기록이 없거나, 기록이 적어 부족 영양소를 신뢰성 있게 판단할 수 없을 때
- 폴백 목록 (한국인 평균 섭취 실태 기준 대표 부족 영양소):
  - **비타민D** (한국인 대다수 부족 — 최우선 폴백)
  - **칼슘**
  - **비타민A**
  - **마그네슘**
  - **오메가-3**
  - **비타민C**
- 폴백 시 이 목록에서 랜덤 또는 순환 방식으로 2~3개 노출

### 3.3 UI 스펙

#### FR-3.1 "부족한 영양소는?" 배너
- 위치: "오늘의 식단" 탭, 식단 요약 아래 (스크롤 최상단 강제 점유 금지)
- 형태: 화면 폭 전체 × 높이 약 80px의 **가로 스크롤 카드 캐러셀**
- 섹션 타이틀: "부족한 영양소는?" + 우측 상단 **"AD" 배지**
- 카드 구성: 상품 썸네일(정사각 소형) + 상품명(1줄 말줄임) + 가격 + 관련 영양소 태그 (예: `칼슘`)
- 카드 탭 → 쿠팡 파트너스 링크로 이동 (APK에서는 외부 브라우저로 열기)
- 하단 소형 고지 문구: *"이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다."* (쿠팡 파트너스 필수 고지 — 문구 변경 금지)

#### FR-3.2 데이터 구조
- 상품 데이터는 코드와 분리: `src/data/coupangProducts.ts` (또는 JSON)
- 스키마: `{ id, nutrient, productName, price, imageUrl, partnersUrl }`
- 영양소당 최소 1개 상품 매핑, 관리(추가/삭제)가 파일 수정만으로 가능해야 함

#### FR-3.3 표시 규칙 및 법적 제약
- "치료", "예방", "개선 보장" 등 의약품 오인 표현 절대 금지 — 상품명 그대로만 표기
- AD 배지와 파트너스 고지 문구는 어떤 상태에서도 생략 불가
- 광고 노출/클릭 수를 로컬 트래킹 (추후 수익 분석용)

### 3.4 수용 기준
- [ ] 식단 기록이 있고 부족 영양소가 있을 때: 해당 영양소 매칭 상품 노출
- [ ] 기록이 없을 때: 폴백 목록(비타민D 등) 기반 상품 노출 — 배너는 항상 표시됨
- [ ] 카드 탭 시 실제 쿠팡 상품 페이지 이동 (APK는 외부 브라우저)
- [ ] AD 배지 + 파트너스 고지 문구 상시 표시
- [ ] 상품 추가가 데이터 파일 수정만으로 가능

## 4. 인터랙션 개선 — 토스 스타일 (P1)

### 4.1 디자인 원칙
1. **짧게**: 150~300ms, 400ms 초과 금지
2. **스프링/ease-out 커브**: 선형 금지, 끝에서 자연 감속
3. **목적 있는 모션만**: 모든 모션은 피드백("눌렸다", "이동했다")이어야 함 — 장식 금지
4. **미세한 스케일**: 버튼 프레스 scale 0.96~0.97
5. **reduce-motion 존중**: OS "동작 줄이기" 시 슬라이드 → 페이드 대체

### 4.2 기능 요구사항

#### FR-4.1 터치/클릭 이펙트
- 대상: 하단 탭 아이콘, 주요 버튼, 카드형 리스트 아이템
- 터치 다운 → `scale(0.96)` + 미세 투명도 변화 → 릴리즈 시 스프링 복원 (총 ~200ms)
- 하단 탭 아이콘 선택 시 1회 바운스 마이크로 인터랙션

#### FR-4.2 탭 전환 슬라이드
- 탭 인덱스 비교로 방향 결정: 오른쪽 탭 이동 → 새 화면 우→좌 슬라이드 인, 기존 화면은 좌측으로 소폭 밀리며 페이드
- 250~300ms, ease-out
- 전환 중 중복 탭 클릭 무시 (애니메이션 큐 꼬임 방지)

#### FR-4.3 성능 제약
- `transform` + `opacity`만 사용 (레이아웃 속성 애니메이션 금지)
- 중저가 안드로이드 기기 60fps 목표 (검증: 크롬 DevTools CPU 4x 스로틀)
- 라이브러리: **framer-motion** (스프링 내장, React 표준) — 번들 영향 확인 후 최종 채택

### 4.3 수용 기준
- [ ] 모든 탭 전환에 방향성 슬라이드, 끊기는 전환 0건
- [ ] 터치 후 100ms 이내 시각 피드백 시작
- [ ] CPU 4x 스로틀에서 프레임 드랍 체감 없음
- [ ] 동작 줄이기 설정 시 페이드로 대체됨

| 순서 | 기능 | 우선순위 | 의존 관계 |

## 6. Out of Scope (이번 릴리즈 제외)

- 식당 추천 광고 (확정 제외)
- 비밀번호 찾기/재설정 (이메일 부재로 불가 — 추후 검토)
- 광고 관리자 페이지 (데이터 파일 수동 관리)
- 쿠팡 상품 API 자동 연동 (파트너스 링크 수동 등록 방식)
- iOS 대응
