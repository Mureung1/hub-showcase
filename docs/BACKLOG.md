# 백로그 BackLog

## 1. 백로그란?

**백로그(Backlog)** 는 "아직 처리하지 않은, 앞으로 해야 할 작업들을 모아둔 목록"이다.
소프트웨어 개발에서는 제품에 필요한 모든 기능, 개선사항, 버그 수정, 기술적 작업을 우선순위 순으로 정리해둔 리스트를 뜻한다.

### 왜 필요한가?
- **한눈에 파악**: 지금 무엇이 남아있고, 무엇부터 해야 하는지 팀 전체가 같은 그림을 본다.
- **우선순위 기반 자원 배분**: 시간은 한정되어 있으므로, 중요한 것부터 먼저 처리하도록 돕는다.
- **흔들리지 않는 계획**: 개발 중 갑자기 떠오른 아이디어나 요청이 있어도, 바로 작업에 끼워넣지 않고 백로그에 추가한 뒤 우선순위를 재검토한다. 즉흥적인 방향 전환을 막아준다.
- **진행 상황 추적**: Todo → In Progress → Done 상태 변화로 프로젝트 진행률을 파악할 수 있다.
- **커뮤니케이션 도구**: 팀원, 이해관계자(교수님, 팀원 등)에게 "지금 무엇을 하고 있고, 무엇이 남았는지" 설명하는 근거가 된다.

### 어떻게 생겼는가?
보통 표(테이블) 형태로 관리하며, 최소한 아래 항목을 포함한다.

| 항목 | 설명 |
|---|---|
| ID | 항목 식별자 (예: T-01) |
| 제목 | 작업 이름 (한 줄 요약) |
| 설명 | 무엇을, 왜 하는지 |
| 우선순위 | P0(필수) / P1(중요) / P2(있으면 좋음) 등 |
| 상태 | Todo / In Progress / Done |
| 예정 주차 | 언제 할 것인지 |
| 비고 | 담당자, 관련 이슈 링크 등 |

Notion, Jira, GitHub Projects, Google Sheet 등 도구 형태는 달라도 구조는 동일하다.

### 어떻게 관리하는가?
1. **작성**: 기획 단계에서 필요한 기능/작업을 먼저 큰 단위로 나열한다 (에픽 단위).
2. **우선순위 부여**: 각 항목에 우선순위를 매긴다. MVP에 꼭 필요한 것(P0)과, 나중에 해도 되는 것(P2)을 구분한다.
3. **정기적인 정리(Grooming/Refinement)**: 매주 또는 스프린트 시작 시 백로그를 다시 검토한다. 끝난 항목은 제거하고, 새로 생긴 요구사항은 추가하며, 우선순위를 재조정한다.
4. **작게 쪼개기**: 처음엔 큰 단위(에픽)로 적어도 되지만, 실제 작업 직전에는 하루~며칠 안에 끝낼 수 있는 크기로 쪼갠다.
5. **한 번에 너무 많이 넣지 않기**: 이번 주/스프린트에 할 것만 명확히 골라서(Sprint Backlog) 집중한다.

## 3. 이번 주(2주차) Sprint Backlog — 다음 주까지 끝낼 것

2주차부터 본격 개발이 시작되므로, 아래 항목을 **다음 주(2주차) 종료 시점까지** 완료하는 것을 목표로 한다.

| ID | Task | 우선순위 | 완료 기준(DoD) |
|---|---|---|---|
| T-01 | 데이터 모델 설계 및 구축 | P0 | 졸업요건/이수과목/사용자 테이블이 실제 DB에 생성되어 있다 |
| T-02 | 졸업요건 계산 엔진 개발 | P0 | 이수내역을 넣으면 부족 학점 수치가 정확히 반환된다 (단위 테스트 통과) |
| T-03 | 요건/이수내역 입력 기능 구현 | P0 | 사용자가 입력한 값이 DB에 저장되고, 재조회 시 그대로 불러와진다 |

T-01, T-02가 이후 모든 작업(대시보드, 바구니, 시뮬레이션)의 기반이므로, 2주차에는 이 둘의 완성도를 가장 우선한다.
