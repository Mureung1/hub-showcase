# 개발 백로그

`docs/PLAN.md`가 "몇 주차에 뭘 하나"라면, 이 문서는 "그 주차 안에서 뭐부터 하고 시간이 부족하면 뭘 자르나"를 정하는 우선순위 문서다. 1주차(디자인 시스템·디자인 스킬·개발 환경 구성)는 이미 완료. 우선순위는 P0(없으면 그 주차 목표 자체가 성립 안 함)/P1(있어야 하지만 임시로 단순화·후순위 가능)/P2(여유 있으면)로 매겼다.

## 2주차 — 기반 다지기 (데이터·화면 골격)

> **DoD**: 정적 운동 테이블·신체부위 목록이 확정되고, 오늘의 루틴 화면이 실제 DB 데이터로 렌더링된다.

| # | Task | 우선순위 | 상태 |
|---|---|---|---|
| 2-1 | 정적 운동 테이블 확정(30~50개) — 두 핵심 기능이 전부 이 테이블에 의존 | P0 | ☑ |
| 2-2 | Prisma 스키마 설계 + 마이그레이션 | P0 | ☑ |
| 2-3 | 기본 API 골격(오늘의 루틴 조회, 세션 완료 기록) | P0 | ☑ |
| 2-4 | 오늘의 루틴 허브 화면 실제 데이터로 렌더링 — 모든 시나리오의 진입점 | P0 | ☑ |
| 2-5 | 신체부위 선택 목록 확정 | P0 | ☑ |
| 2-6 | 분할 프리셋 목록 확정 | P1 | ☐ |
| 2-7 | 온보딩 화면(가능일수 입력 → 분할 추천 + 요일별 수정) | P1 | ☐ |

## 3주차 — 핵심 기능 1(통증 재편성) + 핵심 기능 2 착수

> **DoD**: 통증 부위를 선택하면 관절 필터링을 거친 대체 운동이 화면에 뜨고, 스킵 버튼을 누르면 빈 휴식일로 재배치되거나 안내 메시지가 뜬다.

| # | Task | 우선순위 | 상태 |
|---|---|---|---|
| 3-1 | 관절 필터링 로직(Express) — 선택 부위를 관여 관절로 쓰는 운동 제외 | P0 | ☐ |
| 3-2 | 같은 타겟부위 대체 운동 후보 API(LLM 선택 포함) | P0 | ☐ |
| 3-3 | 재편성 결과 화면 완성 + 확정 시 오늘 세션 반영 | P0 | ☐ |
| 3-4 | 인접 세션 부위 중복 금지 검증(48시간 간격) — 통증·스킵 두 핵심 기능이 공유하는 하드 제약 | P0 | ☐ |
| 3-5 | 스킵 버튼 — 빈 휴식일 재배치/기록 로직 | P0 | ☐ |
| 3-6 | 통증 부위 선택 화면(바디맵 SVG) 컴포넌트화 — 급하면 목록 선택만으로 임시 대체 가능 | P1 | ☐ |
| 3-7 | 대체 운동이 아예 없는 경우 → 스킵 재편성으로 편입 (엣지 케이스) | P1 | ☐ |

## 4주차 — 핵심 기능 2 마무리 + 통합

> **DoD**: 온보딩부터 통증 재편성·스킵 재편성·운동 기록까지 전체 플로우가 끊기지 않고 동작한다.

| # | Task | 우선순위 | 상태 |
|---|---|---|---|
| 4-1 | 스킵 재편성 결과 문구(재배치/기록 두 갈래)·확정 흐름(거부권 없음) 완성 | P0 | ☐ |
| 4-2 | 전체 플로우 리허설(온보딩→오늘의 루틴→통증 재편성→스킵 재편성→기록) | P0 | ☐ |
| 4-3 | 운동 기록 화면(세트별 무게·반복수·완수 여부) | P1 | ☐ |
| 4-4 | 재편성 근거 문구 템플릿 정리(통증·스킵 공통 패턴 점검) | P1 | ☐ |
| 4-5 | Vitest+RTL로 핵심 컴포넌트·로직 테스트 커버 | P1 | ☐ |
| 4-6 | [선택] 누적 성과 기반 증량 제안 — 기획서에 이미 "여유 있으면 구현"으로 명시된 stretch | P2 | ☐ |
| 4-7 | [선택] 대체 운동 운동법 안내 — 생소한 대체 운동에 수행 방법 정보 추가 (동료 피드백, 형식 미정) | P2 | ☐ |
