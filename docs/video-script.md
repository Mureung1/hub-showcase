# 데모 영상 대본 (5분 이내)

녹화 전에 준비: [https://hub-murex-mu.vercel.app](https://hub-murex-mu.vercel.app) 배포 주소로
녹화한다(로컬 아님 — 실제 배포 환경을 보여줘야 설득력 있음). 화면 녹화 + 마이크로
아래 대사를 그대로 읽으면서 진행하면 된다. 각 구간 옆 시간은 목표치.

## 0:00–0:25 — 인트로 (얼굴 또는 화면, 자유)

> "안녕하세요, TideNote를 만든 김민재입니다. TideNote는 새벽처럼 마음이 풀어진
> 시간에 AI에게 털어놓은 이야기를, 다음날 아침 다시 마주할 때는 조금 다르게
> 보여주는 서비스입니다."

## 0:25–0:55 — 문제의식 (슬라이드 또는 화면 텍스트)

> "새벽에 쓴 일기를 아침에 다시 읽으면 낯설게 느껴진 경험, 다들 있으실 거예요.
> 지금의 AI 챗봇은 이런 상태 차이를 전혀 고려하지 않고 대화를 그대로 다시
> 보여줍니다. TideNote는 대화가 만들어진 시점의 상태와, 지금 다시 마주하는
> 시점의 상태 사이 격차가 크면 원문 대신 요약만 먼저 보여주고, 원문은 사용자가
> 직접 선택해야만 열리게 설계했습니다."

## 0:55–1:20 — 화면 1: Tide Check (실제 조작)

**화면**: 배포 주소 접속 → Tide Check 모달이 뜬 상태

> "접속하면 하루 최소 한 번, 지금 상태를 체크인합니다. 숫자가 아니라
> Cloudy-Clear, Calm-Rippling처럼 느낌으로만 입력받습니다."

**동작**: 슬라이더 두 개를 움직이고 Submit 클릭 → 완료 화면 확인

> "제출하면 실제로 Supabase 데이터베이스에 저장됩니다."

## 1:20–2:30 — 화면 2: 실제 채팅 + 잠김/열람 (핵심 시연)

**동작**: 계속하기 → 메인 화면. 채팅 입력창에 메시지 입력 후 전송

> "이어서 실제로 AI와 대화할 수 있습니다. 지금 보낸 메시지는 Groq API를 통해
> 실시간으로 응답을 받고, 그대로 데이터베이스에 저장됩니다."

**동작**: 왼쪽 사이드바에서 미리 잠긴(블러 처리된) 대화 카드 클릭 → 채팅 스트림의 해당 위치로 스크롤됨

> "왼쪽 사이드바에는 지금까지 나눈 대화가 실제로 묶여서 보입니다. 이 카드처럼
> 발화 당시 상태와 지금 상태가 많이 다르면, 원문이 이렇게 블러 처리돼요."

**동작**: 블러 처리된 메시지의 "View original" 버튼 클릭 → 원문 열림

> "원문이 사라진 게 아니라 잠겨 있는 것뿐이라, 이렇게 직접 눌러야만 열립니다."

## 2:30–3:10 — 기술 구조 (화면 텍스트 또는 README 아키텍처 다이어그램 보여주기)

> "구조는 간단합니다. React 화면이 Express 서버에 요청을 보내고, 서버는
> Supabase에 저장·조회하면서 동시에 Groq API로 AI 응답을 받아옵니다. 이
> 서비스는 Vercel과 Render에 실제로 배포되어 있고, 지금 보여드린 화면이
> 배포된 주소 그대로입니다."

## 3:10–4:00 — 주요 문제 해결 과정 (택 1~2개, 너무 많이 넣지 말 것)

> "개발하면서 겪은 문제 중 하나를 말씀드리면, 처음엔 화면이 이상하게
> 가운데 정렬돼서 나왔는데, 알고 보니 제가 건드린 코드가 아니라 프로젝트
> 초기 세팅 때 남아있던 오래된 CSS 파일이 원인이었습니다. 관계없어 보이는
> 파일에도 원인이 있을 수 있다는 걸 배웠습니다."

(선택: 배포할 때 fork/원본 저장소 혼동 문제, Grok/Groq 헷갈린 것 등 원하는 걸로 교체 가능)

## 4:00–4:40 — Agent 활용 방식

> "개발은 Claude Code와 함께했습니다. 계획을 짜주는 Agent, 만든 기능이
> 요구사항대로 되는지 실제로 실행해서 확인하는 검증 Agent, 코드 자체의
> 상태(테스트 존재 여부, 스타일)를 점검하는 Agent를 따로 만들어서 매주
> 단계마다 활용했습니다. 특히 검증 Agent는 '코드가 맞아 보인다'가 아니라
> 실제로 서버를 꺼보거나 curl로 호출해보는 방식으로 동작하게 만들어서,
> 눈으로만 봐서는 못 잡았을 버그(예: 정상 케이스인 404를 에러로 잘못
> 처리할 뻔한 것)를 실제로 잡아냈습니다."

## 4:40–5:00 — 마무리

> "지금은 Tide Check와 실제 채팅, 잠김/열람까지 화면부터 데이터베이스까지
> 전부 연결된 상태입니다. 다음 단계로는 대화 구간을 더 정교하게 나누는
> Episode Segmentation을 발전시키고 싶습니다. 시청해주셔서 감사합니다."

## 촬영 팁

- 화면 녹화 도구: macOS 기본 **Cmd+Shift+5** (화면 녹화 선택) 또는 QuickTime
- 마이크로 대사를 직접 읽거나, 녹화 후 자막을 입혀도 됨 (자막만 있어도 요구사항 충족)
- 중간에 말이 꼬이면 멈추지 말고 이어가기 — 편집으로 자르면 됨
- 녹화 전 브라우저 탭 정리 (알림/개인정보 안 보이게), 배포 주소만 열어두기
- 5분 넘지 않게 — 위 대본대로면 대략 4분 40초~5분
