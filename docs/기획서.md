# 기획서 — AI 운동 루틴 적응 코치

> 내부 개발용 문서. 대회 제출 양식이 아니라 4주 구현의 기준을 잡기 위한 것이다.

## 개요

- 참가자: N001_강민구 (경상국립대 컴퓨터공학과 3학년)
- 프로그램: AI Agent Challenge (네이버 커넥트재단 + 서울대, 코드스쿼드 운영), 2026-07-06 ~ 2026-07-31
- 형식: 개인 프로젝트, 최종 심사는 7/31 데모데이 1회뿐 (중간 발표 없음)


## 1. 문제 정의
**나는 통증이나 시간 부족으로 계획한 운동을 못 할 때, 오늘 뭘 해야 할지 판단하는 데 시간을 쓰거나, 판단을 미루고 그냥 스킵한다.**

1인칭 관찰 기반 서술이다. "운동하는 사람들이 ~한다"는 식의 일반화된 표현은 검증되지 않은 주장이므로 의도적으로 배제했다.

**한 줄 정의**: 사용자의 운동 기록과 컨디션 피드백을 누적 추적하고, 예외 상황(통증·시간 부족·스킵)이 발생하면 하드 제약(통증 부위 제외, 인접 세션 부위 중복 금지) 안에서 루틴을 재편성하는 Agent.

**왜 단순 GPT wrapper가 아닌가**: 매 요청마다 맥락을 재설명해야 하는 단발 LLM 질의와 달리, 이 시스템은 과거 세션 이력을 자동으로 참조해 판단을 바꾼다(예: 이번 주 누적 스킵 횟수 → shift/snap-back 판단). 제약 검증(부위 중복 체크, 통증 부위 필터링)은 결정론적 코드가 담당하고, LLM은 그 안에서 선택과 자연어 설명만 담당하는 역할 분담 구조다.


## 2. 사용자 시나리오
각 시나리오는 "입력 → 판단 → 출력(근거 문구)" 순서로 정리한다. 근거 문구는 LLM이 자유 서술하지 않고, 코드가 계산한 값을 템플릿에 채워 생성한다.

### 시나리오 1 — 온보딩 및 기본 루틴 생성
- **입력**: 사용자가 대시보드 웹앱에 로그인 후 주당 운동 가능 일수를 입력한다.
- **판단**: 가능 일수에 따라 분할 프리셋(전신/상하체/PPL 등)을 추천한다. 분할 자체는 선택지가 아니라 가능 일수에서 도출되는 결과이지만, 이미 자신만의 분할 루틴이 있는 사용자를 위해 요일별 타겟 부위를 부분적으로 수정할 수 있게 한다.
- **출력**: "주 3회 가능하다고 하셔서 전신 분할을 추천합니다. 요일별 타겟 부위는 직접 바꿀 수 있습니다." 형태의 권장안 + 요일별 수정 UI. 수정 시에도 인접 세션 부위 중복 금지(시나리오 2 참고) 하드 제약은 그대로 검증한다.

### 시나리오 2 — 통증 예외
- **입력**: 사용자가 미리 정의된 신체 부위 목록(무릎/허리/어깨/손목 등)에서 통증 부위를 선택한다. 자유 텍스트가 아니라 목록 선택으로 받아, 시스템이 즉시 구조화된 값으로 하드 제약에 연결할 수 있게 한다.
- **판단**: 통증 원인 추정이나 "계속해도 됨" 판단은 하지 않는다. 모든 운동에는 "타겟 부위"와 "관여 관절" 태그가 붙어 있고(운동 데이터 방법론과 동일한 교차검증 대상), 선택된 통증 부위를 관여 관절로 쓰는 운동은 제외한 뒤, 같은 타겟 부위를 가지면서 그 관절을 쓰지 않는 대체 운동을 정적 운동 테이블 안에서 LLM이 고른다. 이 필터는 "이 대체운동이 통증에 안전하다"고 단정하는 게 아니라 구조적으로 해당 관절을 쓰지 않는 운동을 고르는 것뿐이라, 의료 판단 배제 원칙과 충돌하지 않는다.
- **출력**: "무릎 통증으로 스쿼트 대신 레그 컬을 진행합니다. 전문가 상담을 권장합니다." — 제외 부위·대체 운동·고지 문구는 모두 코드가 계산한 사실을 문자열 템플릿에 채운 것이다.

### 시나리오 3 — 스킵 후 복귀 (밀기 vs 되돌아가기)
- **입력**: 사용자가 특정 세션을 스킵한다(시간 부족 등).
- **판단**: 이번 주 누적 스킵이 1회면 복귀(snap-back, 다음 예정 세션을 그대로 진행), 2회 이상이면 밀기(shift, 남은 세션을 뒤로 이동)로 처리한다. 48시간이면 대부분의 근육이 회복되는 시간대라는 점을 기준 삼아, 스킵이 반복되어 회복 간격이 계속 깨지는 상태(2회 이상)와 일회성 예외(1회)를 구분한다.
- **출력**: "이번 주 세션이 밀려서 목요일 루틴을 금요일로 옮겼습니다." 형태로 이동 사유를 명시한다.

### 시나리오 4 — 누적 성과 기반 증량 제안
- **입력**: 사용자가 세션을 완료하고 세트별 무게·반복수·완수 여부를 모두 기록한다.
- **판단**: 3세션 연속으로 목표 세트·반복을 완수했는지(double progression 원리에 따른 객관 지표, 주관적 RPE 아님)를 확인한다. double progression 방법론 자체는 10주 대조 연구에서 rep progression과 유사한 효과가 검증되어 있다.
- **출력**: "최근 3세션 목표를 모두 완수하셨습니다. 데드리프트는 5kg, 그 외 바벨 운동은 2.5kg 늘려볼까요? 부담되면 유지하셔도 됩니다." (StrongLifts 5x5 증량 관행 채택 — 데드리프트만 더 큰 폭, 나머지 바벨 복합관절은 동일 폭. 덤벨/머신은 장비가 제공하는 무게 단위 그대로, 맨몸/고립 운동은 무게 대신 반복수를 먼저 늘린다.) AI가 선언하지 않고 사용자가 최종 결정한다.

## 3. 핵심 기능

네이버 AI Agent Challenge 가이드라인의 두 기준(필수성 — 이게 없으면 서비스가 안 돌아가나, 적합성 — 문제정의를 정확히 해결하나)으로 좁혔다. 문제정의 문장("통증이나 시간 부족으로 계획한 운동을 못 할 때, 판단에 시간을 쓰거나 스킵한다")의 두 절에 정확히 하나씩 대응하는 기능만 핵심으로 남기고, 나머지는 그걸 가능하게 하는 지원 인프라 또는 비핵심 stretch로 분리했다.

### 핵심 기능 (2개 — 문제정의에 직접 대응)

| # | 기능 | 왜 핵심인가 (필수성 + 적합성) |
|---|---|---|
| 1 | **통증 예외 재편성**: 통증 부위 보고(신체부위 목록 선택) → 관여관절 필터링으로 하드 제외 → 같은 타겟부위 대체운동을 정적 테이블 안에서 LLM이 선택 → 전문가 상담 고지 + 템플릿 근거 문구 | 문제정의의 "통증으로 계획한 운동을 못 할 때" 절을 그대로 해결한다. 이게 없으면 통증 발생 시 서비스가 아무 답도 주지 못해 존재 이유가 사라진다 |
| 2 | **스킵/시간부족 예외 재편성**: 세션 스킵 → 이번 주 누적 스킵 횟수(1회=snap-back, 2회 이상=shift)로 판단 → 템플릿 근거 문구 | 문제정의의 "시간 부족으로... 판단을 미루고 스킵한다" 절을 그대로 해결한다. 누적 스킵 횟수를 세어 판단을 바꾸는 것 자체가 "GPT wrapper가 아니라 Agent"라는 논거의 핵심 예시다 |

### 지원 인프라 (핵심 기능의 전제조건 — 그 자체가 차별화 포인트는 아님)

- 온보딩(주당 가능일수만) & 분할 프리셋 추천 + 요일별 부분 수정. 체력수준·목표 입력은 이번 MVP 범위에서 제외(세트·무게 기록으로 간접 파악)
- 운동 기록 누적 추적 (세트별 무게·반복수·완수 여부 모두 저장) — 두 핵심 기능과 증량 제안(아래) 모두가 의존하는 데이터
- 인접 세션(바로 다음 세션) 부위 중복 금지 검증 — 통증 재편성이 의존하는 하드 제약
- 재편성 근거 문구 생성 (계산된 사실 → 템플릿 치환) — LLM 자유 서술의 환각 리스크를 피하는 구현 방식
- 정적 운동 테이블 + LLM 선택 범위 제한 — 운동 목록을 자유 생성하지 않고 정적 데이터 안에서만 고르게 해 환각 방지
- 사용 플랫폼: 대시보드형 웹앱 — 로그인 시 "오늘의 루틴"이 바로 보이고 통증·스킵 보고는 버튼 클릭으로 처리

### 비핵심 (P1 stretch — 여유 있으면 구현)

- **목표 완수 기반 증량 제안** (3세션 연속 완수 시 StrongLifts식 2단계 증량: 데드리프트 +5kg, 나머지 바벨 복합관절 +2.5kg, 덤벨·머신은 장비 단위, 맨몸·고립은 반복수 우선). 필수성·적합성 둘 다 약함 — 문제정의는 "무게를 얼마나 늘릴지"가 아니라 "예외 상황에서 뭘 할지 판단"에 관한 것이라 증량 제안 없이도 핵심 문제는 완전히 해결된다. "Agent다움" 논거도 스킵 재편성 기능(누적 이력 기반 판단)이 이미 충족하므로, 이 기능이 빠져도 핵심 주장은 흔들리지 않는다.

## 출처 / 참고문헌

이 기획서 작성 과정에서 확인한 자료다. 상업적 실무 가이드와 동료심사 연구·프로그램 공식 자료를 구분해서 표기한다.

- **Double progression 방법론 검증 (동료심사 연구)**: [Progressive overload without progressing load? The effects of load or repetition progression on muscular adaptations](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC9528903/) — 10주 대조 연구(비훈련자 39명). 무게 진행과 반복수 진행 모두 1RM을 약 30% 향상시켰고, 무게 진행이 반복 진행보다 약 2kg 더 늘었으나 "실질적 의미는 의심스러운 수준"이라 결론. "목표 반복수 완수 시 무게 증량" 방식 자체가 근거 있는 접근임을 뒷받침.
- **증량 폭 1차 검토 (참고만 하고 최종 채택 안 함 — 상업적 블로그, 동료심사 아님)**: [When to Increase Weights in Gym: A Practical, Evidence-Based Guide](https://setgraph.app/ai-blog/when-to-increase-weights-in-gym) — 상체 +2.5kg, 하체 +5kg이라는 수치를 제시했으나 근거가 블로그 수준이라 아래 두 공식 프로그램 자료로 대체함.
- **증량 폭 최종 채택 근거 (검증된 프로그램 공식 자료)**:
  - [Incremental Increases — Mark Rippetoe, Starting Strength](https://startingstrength.com/article/incremental_increases): 스쿼트 +5lb(~2.5kg), 데드리프트 +10lb(~5kg), 상체 프레스류 +2.5lb(~1.25kg)의 3단계 방식.
  - [Stronglifts 5×5 — How to Progress](https://stronglifts.com/stronglifts-5x5/progress/): 스쿼트·벤치프레스·오버헤드프레스·바벨로우 +5lb(~2.5kg), 데드리프트만 +10lb(~5kg)의 2단계 방식. 구현 단순성 때문에 이 방식을 최종 채택.
