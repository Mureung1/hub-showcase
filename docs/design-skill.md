# 진로 에이전트 서비스 — Design Skill

> 이 문서는 `docs/design-system.md`(색상/타이포/컴포넌트 스펙)를 바탕으로,
> **새 화면을 디자인하거나 구현할 때 지켜야 할 원칙과 판단 기준**을 정리한 가이드입니다.
> 토큰 값이 필요하면 `docs/variables.css`를 참조하세요.

---

## 1. 디자인 목표

이 서비스는 대학생이 자신에게 맞는 공모전·대외활동·인턴십을 추천받고, 자기소개서 초안까지 받아보는 **AI 에이전트형 서비스**입니다. 디자인은 다음을 최우선으로 합니다.

1. **신뢰감** — AI가 왜 이 공고를 추천했는지, 왜 이 문장을 초안으로 제시했는지 "이유"가 항상 눈에 보여야 한다.
2. **부담 없음** — 입력 단계가 길게 느껴지지 않도록, 폼은 담백하고 여백이 넉넉해야 한다.
3. **속도감 있는 다음 행동** — 각 화면은 항상 다음에 뭘 눌러야 할지 명확한 CTA 하나를 갖는다.

디자인이 화려해 보이는 것보다, **"내 정보 → 추천 이유 → 초안"이 자연스럽게 이어지는 흐름**을 우선한다.

---

## 2. 전체 분위기

- 네이버 계열 서비스(카페/블로그/시리즈)에서 참고한 **차분하고 실용적인 카드형 UI**.
- 배경은 옅은 회색(`--color-bg-page`), 콘텐츠는 흰 카드 위에서 진행 — 화면 전체가 "문서/서식"처럼 느껴지지 않고 "서비스 안"처럼 느껴지게 한다.
- 모서리는 넉넉히 둥글게(10~20px), 그림자는 아주 옅고 넓게 — 화면이 묵직해 보이지 않아야 한다.
- 강조는 **색이 아니라 여백과 배지(태그)**로 한다. 화면 하나에 알록달록한 요소를 여러 개 두지 않는다.

---

## 3. 색상 사용 원칙

- **그린(`--color-primary`, #03C75A)은 "행동"과 "브랜드"에만 쓴다** — 주요 CTA 버튼, 활성 스텝, 추천/성공 관련 배지·박스. 화면에서 그린은 항상 "이걸 누르면 다음으로 간다" 또는 "이건 나에게 맞다"는 의미를 갖는다.
- **블루(`--color-accent`, #1B64DA)는 "정보/설명"에만 쓴다** — 마감일 배지, AI 분석 텍스트 박스, 보조 링크. 블루가 CTA로 쓰이는 일은 없다(그린과 역할이 겹치지 않게).
- 그린과 블루는 **한 화면에 항상 함께** 등장하되, 비중은 그린 > 블루로 유지한다. 블루만 단독으로 화면을 지배하지 않는다.
- **에러는 레드(`--color-error`) 하나로만** 표현한다. 경고/성공/정보를 표현하기 위해 노랑, 주황 등 새로운 색을 추가하지 않는다.
- 텍스트는 항상 4단계(`primary` / `secondary` / `tertiary` / `placeholder`)의 회색조 중에서 고른다. 임의의 회색 hex를 새로 만들지 않는다.
- 배경은 `page`(옅은 회색) / `surface`(흰색) / `subtle`(카드 안의 카드) 3단만 사용한다.

**하지 말 것**: 그라디언트 배경, 네온/비비드 컬러, 브랜드 색이 아닌 임의의 강조색 추가.

---

## 4. 버튼 / 입력창 / 카드 사용 원칙

### 버튼
- 화면당 **Primary 버튼은 하나만** 둔다(다음 단계로 넘어가는 행동). 두 개 이상의 강한 CTA가 동시에 필요하면 하나는 반드시 텍스트 링크나 ghost 버튼으로 낮춘다.
- 로딩 상태는 버튼을 숨기거나 스피너로 바꾸지 않고, **배경 톤을 낮추고 라벨 텍스트를 진행형 문장으로 교체**한다(`generateBtnLabel` 패턴 참고).
- 목록에 항목을 추가하는 액션(자격증 추가 등)은 항상 ghost/dashed 스타일로, "지금 화면을 진행시키는" Primary 버튼과 시각적으로 구분한다.

### 입력창
- 라벨은 항상 입력창 위에, 필수 여부(`*필수` / `(선택)`)를 라벨 옆에 병기한다.
- 에러가 나면 **테두리 색만** 바꾸고, 배경·아이콘·플레이스홀더는 그대로 둔다. 에러 문구는 입력창 바로 아래, 캡션 크기로.
- 자유 서술형 입력(경험, 자소서 초안)은 textarea를 쓰고, 최소 높이를 90px 이상 확보해 "짧게 쓰고 끝내는" 느낌을 주지 않는다.

### 카드
- 정보 밀도가 높은 화면(정보입력, 상세)의 메인 콘텐츠는 **그림자 있는 큰 카드 하나**로 감싼다.
- 같은 화면에 여러 개가 반복되는 항목(공고 리스트)은 그림자 없이 **테두리만**으로 구분한다 — 그림자를 여러 개 겹치면 화면이 무거워진다.
- 근거/설명 텍스트(추천 이유, AI 분석)는 항상 tint 배경 박스로 감싸 본문과 시각적으로 분리한다. 박스 안 텍스트는 반드시 해당 톤의 tint-text 색을 쓴다(그린 박스엔 그린 텍스트, 블루 박스엔 블루 텍스트).

## 5. 새 화면을 만들 때 따라야 할 규칙

1. **먼저 스텝퍼에 위치를 정한다.** 이 서비스의 모든 화면은 4단계 흐름(정보입력→추천목록→공고상세→자소서초안) 중 하나이거나 그 사이의 보조 화면이다. 새 화면이 이 흐름의 어디에 속하는지 먼저 결정한다.
2. **컨테이너 폭은 720px로 고정한다.** 표/대시보드 등 예외가 필요하면 별도로 논의하고, 기본은 이 폭을 벗어나지 않는다.
3. **화면 하나 = 핵심 정보 1그룹 + CTA 1개.** 여러 결정을 한 화면에서 요구하지 않는다.
4. **새 색을 추가하지 말고, 기존 토큰(`variables.css`)에서 고른다.** 색이 부족하면 그린/블루의 명도만 조정하고, 새 색상을 브랜드에 추가하기 전엔 반드시 논의한다.
5. **타이포 스케일을 벗어나지 않는다.** `--font-size-*` 10종 안에서만 크기를 고른다. 슬라이드/모바일처럼 예외 매체가 아니면 임의 크기(17px, 19px 등)를 쓰지 않는다.
6. **여백은 4px 스케일(`--space-*`)만 사용한다.** 5px, 15px 같은 어중간한 값은 쓰지 않는다.
7. **AI가 생성/추천한 값은 항상 "왜 그런지" 설명 텍스트와 함께 보여준다.** 추천 결과, 초안 문항 모두 근거 없이 결과만 보여주지 않는다.
8. **되돌아갈 길을 항상 남긴다.** 상세→목록, 초안→목록처럼 이전 화면으로 갈 수 있는 링크를 화면 상단 또는 하단에 명시한다.

## 6. 피해야 할 디자인

- ❌ 그라디언트 배경, 글래스모피즘, 과한 블러 효과
- ❌ 이모지 남용 (배지/버튼에 장식용 이모지 사용 금지 — 안내·팁 문구 앞에 붙는 💡 정도로, 의미를 보조하는 최소 사용만 허용)
- ❌ 그린/블루 외의 임의 강조색 추가(보라, 주황, 청록 등)
- ❌ 카드 안에 카드 안에 카드처럼 중첩 그림자 남용
- ❌ 한 화면에 Primary 버튼 2개 이상
- ❌ 근거 없는 AI 결과 노출(추천 이유·분석 문구 생략)
- ❌ 픽셀 단위로 튀는 임의 radius/spacing 값(토큰에 없는 값 새로 만들기)
- ❌ placeholder 텍스트를 실제 값처럼 진하게(placeholder는 항상 `--color-text-placeholder`)
- ❌ 에러 상태를 레드가 아닌 다른 색으로 표현하거나, 반대로 성공/정보 상태에 레드를 쓰는 것

## 7. 일관성 체크리스트

새 화면/컴포넌트를 만들고 나면 아래 항목을 모두 확인합니다.

- [ ] 배경/텍스트/보더 색이 전부 `variables.css`의 토큰 안에서만 왔는가?
- [ ] 그린은 "행동/브랜드", 블루는 "정보/설명" 역할로만 쓰였는가?
- [ ] 이 화면의 Primary 버튼은 1개뿐인가?
- [ ] 폰트 크기가 10종 스케일(`--font-size-*`) 안에 있는가?
- [ ] 여백이 4px 스케일(`--space-*`) 값인가?
- [ ] radius가 7종 스케일(`--radius-*`) 안에 있는가?
- [ ] 카드에 그림자를 썼다면, 반복되는 리스트 항목이 아닌 "메인 콘텐츠"인가?
- [ ] 에러 표시는 테두리+캡션 문구 방식으로 기존 패턴과 동일한가?
- [ ] AI가 만든 결과(추천/초안) 옆에 근거 설명이 함께 있는가?
- [ ] 이 화면에서 이전 단계로 돌아갈 수 있는 링크가 있는가?
- [ ] 새로운 색상·폰트 크기·간격 값을 추가하지 않고 기존 토큰만 사용했는가?
