# 디자인 컨셉

## 1. 디자인 컨셉 이름

### Blueprint Studio

이 프로젝트의 디자인 컨셉은 **Blueprint Studio**입니다.

복잡하게 흩어진 채용공고의 요구사항을 분석하고, 사용자가 자신의 학습 방향과 커리어 준비 과정을 단계적으로 설계할 수 있도록 돕는 서비스의 성격을 시각적으로 표현합니다.

실제 설계 도면을 그대로 재현하기보다, 설계 과정에서 느껴지는 **구조성, 정밀함, 단계성**을 UI에 적용합니다.

## 2. 핵심 키워드

- 설계
- 구조화
- 신뢰
- 단계적 성장
- 명료함

## 3. 사용자에게 주고 싶은 인상

사용자가 서비스를 처음 접했을 때 다음과 같은 인상을 받는 것을 목표로 합니다.

> 복잡한 채용공고를 대신 정리해 주고, 내가 무엇을 어떤 순서로 준비해야 하는지 체계적으로 설계할 수 있는 도구

지나치게 무거운 취업 플랫폼이나 차가운 데이터 분석 도구보다는, 전문적이지만 접근하기 쉬운 커리어 설계 도구를 지향합니다.

## 4. 디자인 방향

전체 디자인은 **Blueprint 70% + Career Education 30%**의 균형을 목표로 합니다.

Blueprint 요소를 통해 분석적이고 구조적인 느낌을 주되, 대학생 사용자가 부담 없이 이해하고 사용할 수 있도록 정보 구조와 문장은 명확하게 유지합니다.

### 4.1 유지할 분위기

- 전문적인 분석 도구의 신뢰감
- 설계도처럼 체계적인 정보 구조
- 단계별로 진행되는 커리어 준비 흐름
- 채용공고의 요구사항을 학습 계획으로 바꾸는 연결감

### 4.2 피해야 할 분위기

- 개발자용 엔지니어링 콘솔처럼 보이는 화면
- 의미 없는 시스템 지표와 가짜 데이터 장식
- 일반적인 보라색 AI SaaS 디자인
- 과도한 Gradient와 Glassmorphism
- 카드만 반복적으로 나열하는 평범한 대시보드

## 5. 레이아웃 방향

프로토타입의 핵심 흐름은 다음과 같습니다.

1. 관심 직무 선택
2. 요구 역량 분석 보고서 확인
3. 학습 로드맵 확인

각 화면은 독립된 카드 나열이 아니라, 하나의 커리어 설계 과정이 이어지는 느낌을 주어야 합니다.

### 5.1 기본 구조

- 왼쪽에는 3단계 Progress Navigation을 배치합니다.
- 오른쪽에는 현재 단계의 핵심 콘텐츠를 배치합니다.
- 화면 전체에는 밝은 Grid 배경을 사용하되, 콘텐츠 가독성을 방해하지 않도록 약하게 표현합니다.
- 각 콘텐츠 영역은 얇은 Border와 충분한 여백으로 구분합니다.

### 5.2 Progress Navigation

왼쪽 영역은 일반적인 사이드바 메뉴가 아니라 사용자의 현재 진행 단계를 보여주는 역할을 합니다.

```text
01 관심 직무 선택
02 요구 역량 분석
03 학습 로드맵
```

현재 단계는 Orange Accent 또는 Indicator로 강조하고, 완료된 단계는 체크 또는 낮은 대비의 표시로 구분합니다.

## 6. 시각 요소

### 6.1 Blueprint 요소

Blueprint 컨셉은 장식이 아니라 정보 구조를 표현하는 데 사용합니다.

사용 가능한 요소:

- 약한 Grid Pattern
- 얇고 정밀한 Border
- 단계 사이를 연결하는 Line
- `SECTION_01`, `STEP_01` 같은 제한적인 Label
- 번호와 작은 Tag를 활용한 구조화
- 분석 결과와 학습 단계의 연결 관계 표현

주의할 점:

- 화면 전체를 Monospace와 영어 Label로 채우지 않습니다.
- 실제 기능과 관계없는 시스템 상태, 사용자 ID, 의미 없는 지표는 사용하지 않습니다.
- Blueprint 요소가 정보 이해를 방해하면 제거합니다.

### 6.2 색상

기본 색상은 신뢰감과 전문성을 전달하는 Deep Navy 계열을 사용합니다.

배경은 White 또는 매우 밝은 Blue Grey 계열을 사용하여 충분한 가독성을 확보합니다.

강조색은 Orange 계열을 사용하되, 핵심 행동이나 현재 단계 표시처럼 중요한 곳에만 제한적으로 사용합니다.

색상 역할:

- Deep Navy: 주요 제목, 핵심 영역, 강조 카드
- Orange: CTA 버튼, 현재 단계, 주요 포인트
- Light Grey / Blue Grey: 배경, Border, 보조 정보
- White: 콘텐츠 카드와 읽기 영역

### 6.3 타이포그래피

본문과 주요 정보는 가독성이 높은 Sans-serif를 사용합니다.

Monospace 폰트는 다음과 같은 보조 요소에만 제한적으로 사용합니다.

- 작은 Blueprint Label
- 단계 번호
- 기술 키워드
- 분석 수치
- 데이터 기준 표시

주요 제목과 설명은 자연스러운 한국어 중심으로 작성하여 사용자가 시스템 콘솔을 보는 느낌을 줄입니다.

## 7. 화면별 디자인 방향

### 7.1 관심 직무 선택 화면

목적은 사용자가 어렵지 않게 관심 직무를 입력하거나 선택하고 분석을 시작하도록 돕는 것입니다.

포함 요소:

- 관심 직무 입력 영역
- 예시 직무 선택 버튼
- 분석 시작 버튼

디자인 방향:

- 가장 단순하고 여백이 넓은 화면으로 구성합니다.
- 사용자가 해야 할 행동이 `직무 선택 → 분석 시작`임을 명확하게 보여줍니다.
- 예시 직무 버튼은 정밀한 Border를 사용하되, 시스템 명령어처럼 보이지 않도록 자연스러운 한국어로 표현합니다.

### 7.2 요구 역량 분석 보고서 화면

목적은 채용공고 분석 결과를 사용자가 이해할 수 있는 요구 역량 보고서로 보여주는 것입니다.

포함 요소:

- 분석한 채용공고 수
- 반복적으로 등장한 기술 스택
- 기술별 등장 빈도
- 주요 업무 및 경험
- 자격요건 및 우대사항
- 핵심 분석 또는 해석

디자인 방향:

- 단순한 차트보다 `근거 → 해석 → 다음 행동`의 흐름이 보이도록 구성합니다.
- 기술별 빈도는 가로 막대와 수치로 직관적으로 표현합니다.
- 퍼센트만 쓰지 않고 `22 / 24개 공고`처럼 근거를 함께 표시합니다.
- 요구 역량이 실제로 무엇을 의미하는지 설명하는 핵심 해석 영역을 포함합니다.

### 7.3 학습 로드맵 화면

목적은 요구 역량 분석 결과를 바탕으로 사용자가 무엇을 어떤 순서와 수준으로 학습해야 하는지 이해하도록 돕는 것입니다.

포함 요소:

- 우선 준비 역량
- 추천 학습 단계
- 각 단계의 주요 학습 내용
- 권장 학습 수준
- 추천 이유
- 채용공고 분석 근거

디자인 방향:

- 단순한 커리큘럼 목록이 아니라 Career Blueprint처럼 보여야 합니다.
- 각 단계는 `무엇을 → 어느 수준까지 → 왜`를 함께 설명합니다.
- 단계 사이의 연결선을 활용해 학습 순서를 시각적으로 보여줍니다.
- 학습 기간은 확정적인 단일 값보다 `예상 범위` 또는 `기초/실전/심화` 수준으로 표현합니다.

## 8. 디자인 원칙

### 8.1 정보가 장식보다 우선한다

Blueprint 요소는 서비스의 정보를 이해하는 데 도움을 줄 때만 사용합니다.

### 8.2 분석 결과에서 행동으로 이어져야 한다

요구 역량 분석 보고서와 학습 로드맵이 분리된 화면처럼 보이지 않도록, 분석 근거와 학습 추천 사이의 연결 관계를 표현합니다.

### 8.3 전문적이지만 어렵지 않아야 한다

개발자 도구나 관리자 대시보드처럼 지나치게 복잡한 화면을 피하고, 대학생 사용자가 쉽게 이해할 수 있는 정보 구조를 유지합니다.

### 8.4 데이터에는 근거가 보여야 한다

분석 결과에는 가능한 범위에서 분석 공고 수, 등장 빈도, 중요도 등의 근거 정보를 함께 보여줍니다.

### 8.5 다음 행동이 명확해야 한다

사용자가 화면을 본 뒤 무엇을 먼저 해야 하는지 바로 이해할 수 있도록 우선순위와 학습 순서를 명확하게 표현합니다.
