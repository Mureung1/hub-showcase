# Scenario Writing Skill

## Purpose

확정 시나리오의 사건과 선택을 플레이어가 실제로 읽고 조작할 수 있는 대본과
구현 가능한 씬 명세로 구체화한다.

## Scene Composition

- 한 씬은 하나의 입력 대기 지점 또는 하나의 확정 결과 전달 단위로 나눈다.
- 씬 표시 번호와 내부 `scene_id`를 함께 둔다.
- 플레이어 노출 영역은 line ID, 화자, 지문·대사와 선택지 문구를 실행 순서대로
  작성한다.
- 구현 영역은 진입·종료 조건, 다음 씬, 입력 모드, 분기, Outcome, 상태 변화,
  공개 정보와 필요한 참조를 작성한다.
- 제작 영역은 일러스트, 배경, BGM, 효과음, 카메라, 애니메이션과 QA 요구를
  작성하되 미확정 리소스는 `TBD`로 둔다.

## Player Agency

- 플레이어가 아직 선택하지 않은 행동이나 대사를 대신 확정하지 않는다.
- 확정 시나리오가 지정한 오프닝 독백처럼 고정된 표현만 예외로 사용할 수 있다.
- 선택지를 보여준 뒤에는 입력을 기다리며 자동 선택·자동 확정을 추가하지 않는다.
- 분기 결과와 상태 변경은 확정된 Outcome 또는 명시적으로 공개한 창작 제안으로만
  연결한다.

## Data Consistency

- 내부 ID는 기술 문서의 영문 대문자 접두사와 언더스코어 규칙을 따른다.
- `choice_only`와 `choice_and_text`에는 하나 이상의 선택지가 있어야 한다.
- `narrative_only`에는 등록할 `continue_outcome_id`가 필요하다.
- 판정 방식과 수치는 장면별 사용자 확인 대상이므로 근거 없이 확정하지 않는다.
- 일러스트 ID는 등록 여부가 확인되지 않으면 실제 ID처럼 단정하지 않고 `TBD`로 둔다.
- 숨겨진 정보와 미충족 공개 조건은 플레이어 노출 대본에 포함하지 않는다.

## Writing Style

- 기존 프로젝트의 화자 톤과 한국어 문체를 우선한다.
- 한 화면에서 읽기 어려운 장문은 여러 line으로 분리한다.
- 묘사는 현재 장면의 감각과 행동 단서에 집중하고 새로운 정사 설명을 과도하게
  추가하지 않는다.
- 선택지 문구는 행동과 의도가 분명하게 보이도록 작성한다.

## Creative Footnotes

- 직접 근거가 없는 모든 문장과 필드에 각주 표식을 붙인다.
- 각주는 `CW-<chapter>-<number>` 형식을 사용한다.
- 각주 설명은 대상 ID, 창작 내용, 필요한 이유와 영향 범위를 포함한다.
- 창작이 기존 정사·규칙·분기를 변경할 수 있으면 `승인 시 영향`을 명시한다.
- 창작 각주가 없는 항목은 Sources에서 직접 확인할 수 있어야 한다.

## Review

- 사건 순서, 진입·종료 조건과 분기 합류가 원본과 일치하는가
- 플레이어 노출 대본에 스포일러나 내부 ID가 섞이지 않았는가
- input mode, choices와 Outcome 조합이 유효한가
- 창작 항목과 `TBD`가 빠짐없이 공개되었는가
- 승인 전 canonical 문서와 결정·버전 기록을 변경하지 않았는가
