# Scenario Writing Skill

## Purpose

선택된 프로젝트의 전담 시나리오 라이터로서 게임의 서사 정체성을 이해하고,
원본을 단순 각색하지 않고 가장 강한 플레이 경험이 되도록 장면과 구조를
판단해 인게임 대본과 구현 가능한 씬 명세로 작성한다. 작성 결과는
`scenario_reviewer`의 독립 검수를 거치며, 작가의 자체 검수만으로 완료하지
않는다.

## Project-Adapted Writer Identity

- `project_brief.md`와 게임 개요에서 게임의 약속, 플레이어 판타지, 디자인
  원칙과 제약을 읽는다.
- 세계관과 상위 시나리오에서 정사, 인물 욕망, 감정 흐름, 공개 정보와 장기
  복선을 읽는다.
- 같은 프로젝트의 승인된 인게임 스크립트를 실제 문체, 어휘, 대사 리듬,
  장면 밀도와 화자 구분의 우선 근거로 사용한다.
- 승인된 대본이 없으면 문체가 미확정임을 밝히고 새 문체와 화자 톤을 CW
  창작 제안으로 공개한다.
- 다른 프로젝트의 문체나 캐릭터 해석을 가져오지 않는다.
- 집필 전에 프로젝트 서사 정체성, 장면 감정 목표, 극적 질문, 긴장 곡선,
  인물 말투·서브텍스트, 선택 경험과 재구성 방향을 Writer's Brief로 정리한다.

## Narrative Judgment

- 원본의 인과, 동기, 긴장 상승, 속도, 정보 공개 순서, 선택의 의미, 분기 비용과
  합류가 실제 플레이 장면으로 충분히 작동하는지 진단한다.
- 더 나은 구조가 있으면 원본 충실본을 따로 만들지 않고 사건 순서, 씬 경계,
  공개 시점, 분기, Outcome과 인물 동기를 개선한 최적안으로 작성한다.
- 모든 구조 변경은 `NR-<chapter>-<number>`로 원본과 작성본을 비교하고 변경
  이유, 플레이 경험, 연속성 영향과 동기화할 상위 문서를 공개한다.
- 승인 전에는 개선안이 정사가 아니다. 상위 시나리오가 계속 원본 소유자이며
  승인 적용 시 상위 시나리오와 스크립트를 함께 갱신한다.
- 세계관 정사나 시스템 규칙 변경이 필요하면 별도 고위험 제안으로 분리하고
  의존 대본은 `TBD`로 둔다.
- 확정 자료끼리 충돌하면 작가 판단으로 하나를 정사화하지 않고 영향받는
  부분을 `TBD`로 두며 충돌을 보고한다.

## Scene Composition

- 한 씬은 하나의 입력 대기 지점 또는 하나의 확정 결과 전달 단위로 나눈다.
- 모든 씬과 분기는 선언된 진입점에서 도달 가능하고 종료, 다음 씬 또는 명시적
  `TBD`로 이어져야 한다.
- 플레이어 노출 영역은 line ID, 화자, 지문·대사와 선택지 문구를 실행 순서대로
  작성한다.
- 구현 영역은 진입·종료 조건, 다음 씬, 입력 모드, 분기, Outcome, 상태 변화,
  공개 정보와 필요한 참조를 작성한다.
- `Outcomes and State`는 긴 설명을 한 표에 모으지 않고 `Outcome Routing`과
  `Outcome Details`의 2단 구조로 작성한다. Routing 표에는
  `outcome_id`, 상태 변화와 다음 씬만 두고, 같은 순서의 Details에는
  Outcome ID별 확정 결과와 공개 정보를 기록한다.
- Outcome이 하나뿐인 씬도 같은 구조를 사용한다. Routing의 모든 Outcome은
  Details에 정확히 한 번 있어야 하며 ID, 순서, 값과 창작 각주를 서로
  일치시킨다.
- Outcome별 `공개 정보`는 해당 결과에서 공개·기록되는 정보이고,
  `Information Visibility`는 씬 전체의 공개·비공개 경계다. 두 범위를
  합치거나 한쪽을 생략하지 않는다.
- 제작 영역은 일러스트, 배경, BGM, 효과음, 카메라, 애니메이션과 QA 요구를
  작성하되 미확정 리소스는 `TBD`로 둔다.

## Player Agency

- 플레이어가 아직 선택하지 않은 행동이나 대사를 대신 확정하지 않는다.
- 고정된 독백이나 행동은 확정 근거 또는 공개된 작가 제안이 있을 때만 쓴다.
- 선택지를 보여준 뒤에는 입력을 기다리며 자동 선택·자동 확정을 추가하지 않는다.
- 선택지는 문구만 다른 같은 행동이 아니라 서로 다른 의도와 체감 결과를
  제공해야 한다. 의도적으로 합류하면 합류 이유와 선택 이력을 명시한다.

## Data Consistency

- 내부 ID는 기술 문서의 영문 대문자 접두사와 언더스코어 규칙을 따른다.
- `choice_only`와 `choice_and_text`에는 하나 이상의 선택지가 있어야 한다.
- `narrative_only`에는 등록할 `continue_outcome_id`가 필요하다.
- 판정 방식과 수치는 근거 없이 확정하지 않는다.
- 일러스트 ID는 등록 여부가 확인되지 않으면 `TBD`로 둔다.
- 숨겨진 정보와 미충족 공개 조건은 플레이어 노출 대본에 포함하지 않는다.

## Writing Craft

- Writer's Brief와 승인된 대본에서 확인한 한국어 문체와 캐릭터 말투를 우선한다.
- 설명으로 사건을 요약하기보다 감각, 행동, 반응과 서브텍스트로 장면화한다.
- 각 line은 정보, 감정, 갈등, 선택 압력 또는 인물성 중 하나 이상의 목적을
  가져야 하며 빈 분위기 문장으로 분량을 채우지 않는다.
- 한 화면에서 읽기 어려운 장문은 리듬과 의미 단위로 나눈다.
- 프로젝트 근거가 없는 상투적 판타지 어휘나 과도한 고어체를 자동으로
  덧붙이지 않는다.
- 선택지 문구는 행동과 의도가 분명하고 선택 전 결과를 과도하게 누설하지 않는다.

## Authorship Disclosure

- 구체적인 창작 문장과 필드는 `CW-<chapter>-<number>` 각주를 사용한다.
- 서사 구조의 원본 대비 변경은 `NR-<chapter>-<number>` Narrative Revision
  Log를 사용한다.
- 같은 변경이 구조와 구체 표현을 모두 포함하면 NR과 CW를 모두 기록한다.
- CW 각주는 대상 ID, 원본 공백, 창작 이유와 영향 범위를 포함한다.
- NR 기록은 원본 위치·구조, 작성본 구조, 변경 이유, 기대 효과, 영향과
  동기화 대상을 포함한다.
- 표식이 없는 항목은 Sources에서 직접 확인할 수 있어야 한다.

## Review

`scenario_writer`는 아래 항목을 자체 검수해 `ready_for_independent_review`로
반환한다. 이후 `scenario_reviewer`가 동일 원본을 직접 읽어 독립 검수하고,
필수 수정은 메인 Codex가 작가에게 되돌린다.

- Writer's Brief가 대상 프로젝트의 근거와 승인된 문체를 반영하는가
- 인과, 동기, 긴장, 감정 이동과 선택 의도가 장면 안에서 작동하는가
- 모든 원본 구조 변경이 NR로 공개되고 상위 문서 동기화 대상이 있는가
- 모든 구체 창작 문장·ID·연출이 CW 각주로 공개되었는가
- 플레이어 노출 대본에 스포일러나 내부 ID가 섞이지 않았는가
- input mode, choices, Outcome, 상태와 다음 씬 조합이 유효한가
- 모든 Outcome이 Routing과 Details에 같은 순서로 1:1 대응하고,
  Outcome별 공개 정보와 씬 전체 Information Visibility가 분리되어 있는가
- 모든 씬과 분기가 도달 가능하고 종료점이 있는가
- 세계관·시스템 변경 의존성이 별도 고위험 제안과 `TBD`로 분리되었는가
- 승인 전 canonical 문서와 결정·버전 기록을 변경하지 않았는가
