# PtoP 최소 입력 회고 흐름

## 목적

PtoP의 목표는 사용자에게 긴 회고록을 작성하게 하는 것이 아니라, Repository에서 확인할 수 있는 내용을 먼저 정리하고 사용자는 AI가 확인하기 어려운 개인 경험만 짧게 보완하도록 돕는 것이다.

따라서 회고 입력은 필수 설문이 아니라 **최소 입력과 선택적 보완**의 구조로 설계한다.

## 해결하려는 세 가지 문제

### 1. 다른 참여자의 작업이 기술적 도전으로 선택되는 문제

- GitHub OAuth로 확인한 사용자의 GitHub ID를 기본값으로 사용한다.
- 사용자가 직접 GitHub ID를 수정할 수도 있다.
- API는 해당 ID의 commit, PR, issue 활동과 변경 파일만 기술적 도전 분석 컨텍스트에 전달한다.
- 해당 ID의 활동이 없으면 AI에게 후보 생성을 요청하지 않고, 활동이 없다는 상태를 표시한다.
- commit 수는 참고 지표일 뿐 실제 기여도나 난이도의 절대값으로 표현하지 않는다.

### 2. 회고 내용이 최종 결과에 반영되지 않는 문제

회고는 분석 중 임시로 작성하고 끝나는 데이터가 아니라 최종 초안 생성의 입력값으로 사용한다.

```text
Repository URL + GitHub ID
→ Repository 분석
→ 분석 중 포피의 한 질문 입력
→ 기술적 도전 후보 확인
→ 사용자 선택 또는 직접 추가
→ Repository 근거와 회고 내용 병합
→ 포트폴리오 초안 생성
```

Repository에서 확인된 사실과 사용자가 직접 작성한 경험은 구분해서 다룬다.

- Repository 근거: 파일, commit, PR, issue 등 확인 가능한 데이터
- 사용자 경험: 프로젝트를 시작한 이유, 맡은 역할, 기억나는 문제
- AI 결과: 두 입력을 조합한 초안
- 근거 부족 내용: 확정하지 않고 사용자 확인 필요로 표시

### 3. AI가 내가 생각한 기술적 도전을 찾지 못하는 문제

- AI 후보와 별도로 `내가 생각한 기술적 도전 추가` 입력을 제공한다.
- 제목과 짧은 메모만 입력하면 된다.
- AI 후보와 사용자가 직접 추가한 후보를 동일한 선택 목록에서 관리한다.
- MVP에서는 최종 선택 개수를 1개로 제한해 후보, 회고, 포트폴리오 초안을 하나의 흐름으로 연결한다.

## 최소 입력 원칙

필수 입력은 Repository URL로 제한한다. GitHub ID는 로그인 사용자의 ID를 자동으로 채우되, 로그인하지 않았거나 다른 ID를 분석하려는 경우 직접 입력할 수 있다.

회고 질문은 한 화면에 여러 입력창을 노출하지 않는다.

- 질문은 한 번에 하나만 보여준다.
- 답변은 한 문장이어도 충분하다.
- 질문을 건너뛸 수 있다.
- 입력 내용은 Repository별로 자동 임시 저장한다.
- 모든 질문에 답하지 않아도 분석 결과를 확인할 수 있다.

## 현재 MVP 화면 흐름

### 분석 입력 화면

- Repository URL 입력
- 내 GitHub ID 입력
- 분석 시작

### 분석 중 회고 화면

- 민트 기반 분석 상태
- 포피 이미지와 질문 말풍선
- 한 번에 하나의 회고 질문
- 이전, 건너뛰기, 다음 질문

### 결과 화면

- Repository 분석 결과
- AI가 제안한 기술적 도전 후보
- 사용자가 직접 추가한 기술적 도전
- 선택한 도전에 대한 포피의 후속 질문
- 결과에 반영될 사용자 경험 미리보기

### 저장 API

분석 결과 화면에서 회고를 저장할 때는 분석 결과 ID를 기준으로 아래 API를 호출한다.

```text
POST /api/v1/repository-analyses/:analysisId/reflection
```

요청 본문은 `ReflectionDraft` 전체이며, 공통 메모와 선택한 기술적 도전 답변을 한 번에 upsert한다. 같은 분석 결과에서 다시 저장하면 새 행을 만들지 않고 기존 초안을 갱신한다.

저장된 초안은 결과 화면에 다시 진입할 때 아래 API로 복원한다.

```text
GET /api/v1/repository-analyses/:analysisId/reflection
```

아직 저장된 초안이 없으면 빈 응답으로 처리하고, 브라우저의 localStorage 초안을 계속 사용할 수 있도록 구성했다. 따라서 일시적으로 API 조회가 실패해도 작성 중인 회고가 화면에서 사라지지 않는다.

현재 API는 Supabase service role을 사용하는 서버 저장 경계까지 구현되어 있다. 사용자별 소유권 검증과 RLS 정책은 OAuth access token을 API까지 전달하는 인증 작업 이후에 추가한다.

## AI 초안 생성 단계의 입력 계약

다음 단계에서 AI 초안 생성 API를 추가할 때는 아래 세 영역을 함께 전달한다.

```json
{
  "repositoryAnalysisId": "analysis-id",
  "targetGithubLogin": "SubJeeLee",
  "reflection": {
    "motivation": "...",
    "role": "...",
    "memorableProblem": "..."
  },
  "selectedChallenges": [
    {
      "source": "ai",
      "title": "...",
      "evidence": ["..."],
      "answers": {
        "context": "...",
        "decision": "...",
        "contribution": "..."
      }
    }
  ]
}
```

AI는 이 데이터를 이용해 `Background - Problem - Solution - Technical Challenge - Result` 구조의 초안을 만들 수 있지만, 근거가 없는 결과나 사용자의 역할을 새로 만들어서는 안 된다.
