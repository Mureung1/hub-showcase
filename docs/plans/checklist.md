# PtoP 작업 체크리스트

## 1주차 목표

PtoP의 핵심 흐름인 "Git Repository 분석 방법 학습 → 프로젝트 분석 기준 정의 → 분석 결과 확인 → 회고/포트폴리오 초안 확인"을 동작 프로토타입 수준으로 만든다.

## 사전 학습: Git Repository 분석 방법

- [x] Git Repository에서 분석할 수 있는 정보 종류 정리하기
- [x] README에서 추출할 수 있는 정보 정리하기
- [x] 폴더 구조에서 추론할 수 있는 정보 정리하기
- [x] package.json 같은 설정 파일에서 기술 스택을 찾는 방법 정리하기
- [x] 주요 코드 파일을 선별하는 기준 정리하기
- [x] commit log에서 사용자의 작업 흐름을 파악하는 방법 정리하기
- [x] PR, Issue, commit message를 분석하면 얻을 수 있는 정보 정리하기
- [x] 분석 결과를 프로젝트 목적, 기술 스택, 핵심 기능, 역할 후보로 나누는 기준 정리하기
- [x] 학습 내용을 docs/research/repo-analysis-study.md에 정리하기

## 사전 학습: AI 기반 Repository 분석 전략

- [ ] Repository 분석에 사용할 AI 모델 후보 조사하기
- [ ] 각 AI 모델의 입력 토큰 한계와 출력 토큰 한계 정리하기
- [ ] 긴 Repository를 한 번에 넣지 못할 때 파일을 나누는 기준 정리하기
- [ ] README, 설정 파일, 주요 코드 파일, commit log의 우선순위 정하기
- [ ] 전체 코드를 직접 넣는 방식과 요약 후 분석하는 방식 비교하기
- [ ] 파일별 요약 → 프로젝트 전체 요약 → 포트폴리오 초안 생성 흐름 설계하기
- [ ] 토큰 사용량을 줄이기 위해 제외할 파일 기준 정리하기
- [ ] `node_modules`, `dist`, 빌드 산출물, lock file처럼 분석에서 제외할 파일 기준 정리하기
- [ ] AI가 잘못 추론할 수 있는 역할/기여도 항목을 사용자 확인 대상으로 분리하기
- [ ] 분석 결과의 신뢰도를 높이기 위한 근거 표시 방식 정리하기
- [ ] API 비용을 줄이기 위한 캐싱 또는 단계별 분석 전략 조사하기
- [ ] 대용량 Repository 분석 실패 시 fallback 흐름 정리하기
- [ ] 조사 내용을 docs/research/repo-analysis-study.md에 추가하기
