# Modu Brain 최종 완성도 로컬 개발 계획

## 목표와 작업 경계

이 계획의 목표는 배포 없이도 심사·시연·인수인계가 가능한 제품 수준의 로컬 빌드를 만드는 것이다. 기능 수보다 `기록을 가져온다 → 근거가 있는 분석을 실행한다 → 변화와 연결을 이해한다 → 안전하게 공유한다`는 핵심 흐름의 완결성과 실패 복구를 우선한다.

- 이번 작업에서 허용: 로컬 코드·테스트·문서·마이그레이션 개선, 로컬 Supabase와 브라우저 검증
- 이번 작업에서 제외: Git push, PR 수정, Sites·Render 배포, 원격 Supabase migration, 유료 OpenAI live call
- 완료 판단: 코드 존재가 아니라 재현 가능한 로컬 테스트와 사용자가 이해할 수 있는 상태·오류·복구 UI가 함께 있을 때만 완료로 표시

## 최종 완료 기준

### 1. 제품 흐름

- 비로그인 사용자는 샘플 또는 직접 붙여넣기로 비영속 분석을 끝까지 체험한다.
- 로그인 사용자는 프로젝트 생성, 외부 맥락 가져오기, 원문 선택, 분석, 근거 확인, 이력 비교, 지식맵 탐색, 공유와 새로고침 복원을 완료한다.
- 분석 이력과 프로젝트의 삭제는 영향 범위를 알리는 명시적 확인을 거친다.
- 로딩·빈 상태·부분 실패·네트워크 실패·예상하지 못한 렌더 오류에서 다음 행동이 보인다.

### 2. 에이전트 신뢰성

- `source_snapshot → provider_analysis → evidence_validation → result_persistence` 단계를 사용자에게 설명 가능한 실행 기록으로 제공한다.
- 모델의 숨겨진 추론을 저장하거나 표시하지 않고, 단계별 상태·안전한 코드·근거 검증 지표만 보관한다.
- 동일 idempotency key는 같은 실행을 재사용하고 입력이 다르면 충돌로 거부한다.
- 잘못된 인용, provider 실패와 취소는 성공 결과를 덮어쓰지 않는다.
- 사용자 annotation은 불변 검토 기록이며 모델 입력이나 공개 공유 결과에 자동 포함되지 않는다.

### 3. 데이터·보안

- 모든 사용자 데이터는 RLS와 서버의 소유권 재검증으로 격리하고 IDOR는 일관된 `404`로 처리한다.
- 공유 토큰 원문은 DB와 접근 로그에 남기지 않으며 만료·폐기·IP 제한을 검증한다.
- 원문, prompt, 모델 응답과 내부 오류는 실행 이벤트나 서버 로그에 복제하지 않는다.
- DB 장애 시 메모리 저장으로 우회하지 않고 준비 상태와 API에서 명시적 `503`을 반환한다.

### 4. 디자인·접근성

- 데스크톱과 390px 모바일에서 핵심 흐름이 가로 스크롤 없이 동작한다.
- 키보드만으로 탭, 지식맵 보기 전환, 근거 패널, 공유, 확인 대화상자를 사용할 수 있다.
- 포커스 표시, 명시적 label, live region, reduced motion, 충분한 대비를 유지한다.
- 지식맵은 장식이 아니라 검색·필터·선택·근거·백링크를 연결하는 탐색 도구로 동작한다.

### 5. 품질 게이트

- `npm run check`: lint, 단위·통합 테스트와 coverage, 운영 설정 검증, production build 통과
- coverage: statements/lines 80%, branches 75%, functions 75% 이상
- `npm run test:e2e`: 공개 흐름 전체 통과, 인증 흐름은 로컬 Supabase 설정 시 통과
- SQL migration: 빈 DB 적용, down rollback, 재적용 및 RLS/권한 pgTAP 통과
- `git diff --check`와 secret scan 통과

## 우선순위별 진행 순서

### P0 — 시연 중 중단을 막는 완결성

1. 앱 최상위 오류 경계와 안전한 재시도 경로를 제공한다.
2. 분석 이력 삭제를 실제 API와 연결하고, cascade 영향을 알리는 확인 UI를 제공한다.
3. 비대해진 프로젝트 상세의 분석 이력 영역을 독립 컴포넌트로 분리해 회귀 위험을 낮춘다.
4. 전체 로컬 품질 게이트에서 장기 사용자 시나리오의 테스트 시간 예산을 안정화한다.

### P1 — 에이전트 설명 가능성과 지식 탐색

1. 실행 단계 이벤트, 근거 검증 결과와 사용자 annotation을 하나의 읽기 흐름으로 유지한다.
2. 최근 성공 분석과 직전 성공 분석의 변화가 실제 stable ID 기준인지 fixture와 E2E로 고정한다.
3. 지식맵의 검색·필터·선택 노드·근거 패널·백링크가 같은 URL 상태 또는 복원 가능한 상태를 공유하게 한다.
4. 분석 실패·취소·잘못된 인용·중복 요청 시 사용자 메시지와 서버 terminal 상태가 일치하는지 통합 테스트한다.

### P2 — 배포 직전 준비

1. 로컬 Supabase에서 migration apply/down/reapply, 두 사용자 RLS/IDOR, Auth redirect 흐름을 검증한다.
2. 접근성 자동 검사와 키보드 E2E를 핵심 페이지에 추가한다.
3. 사전 데이터가 있는 6~8분 데모 시나리오를 브라우저 테스트와 발표 체크리스트로 고정한다.
4. 운영 환경변수·요금 제한·ready health 조건을 문서와 설정 검증에서 대조한다.

P2까지 로컬에서 통과한 뒤에만 별도 승인 작업으로 push, 원격 CI, Supabase와 웹 배포를 진행한다.
