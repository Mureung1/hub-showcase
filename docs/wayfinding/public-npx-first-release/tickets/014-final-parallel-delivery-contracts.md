## Answer

Implementation은 Ticket 014 직후 바로 열지 않는다. 먼저 [Ticket 015](015-publication-release-gates.md)의 publication input·ordering·reconciliation을 확정하고, 그 결정을 받는 [Ticket 016](016-clean-machine-smoke-protocol.md)의 clean-machine protocol을 닫은 뒤 `/to-spec`과 `/to-tickets`로 전환한다. 구현 base는 coordinator가 직렬로 만드는 `S0` workspace/lock scaffold, `S1` frozen Interface/fixture, `S2` behavior-preserving Server composition split의 세 commit이며 immutable `S2` SHA를 `spineTipSha`로 고정한다. 이후 contract delta는 원래 spine을 재정의하지 않고 별도 `contractTipSha`와 node별 `handoffSha`로 전달한다.

동시 작업은 coordinator 1명과 최대 3명의 lane writer로 제한한다. `C`는 Browser-safe `product-contract`, exact contract file, root/workspace manifest·lockfile와 serial Server composition을, `R`은 Codex Runtime account lifecycle과 Runtime archive evidence를, `A`는 app-wide account/Runtime transition lease를, `B`는 v3 workspace admission·canonical instruction/Skill bundle·fixed `project_root_markers=[]` policy·Runtime/thread/product action 직전 native-context verifier·single-envelope `SetupJourney`와 Ready commit을 소유한다. `D`는 verified Runtime resolver, `H`는 public host, `U`는 Guided→Compact product UI, `L`은 Landing, `G`는 clean exporter·RC generator·legal/release truth, `I`는 repository-only smoke adapter와 cross-surface packed/live QA만 쓴다. `A`는 setup state를 쓰지 않고 `B`만 A-held lease 안에서 Ready를 commit·readback한다. 두 Server router와 B-owned action admission port는 feature owner가 만든 뒤 serial `C1` composition node가 feature logic 없이 mount한다.

Canonical bundle은 `packages/semester-workspace/resources/workspace/**`만 source authority로 삼는다. G-owned generator를 coordinator가 fixed clean RC worktree에서 실행해 ignored `distribution/staging/npm/ay-ple/resources/workspace/**`와 actual tarball을 만들며, source→staging→tarball complete-tree bytes·digest equality와 ambient repository `AGENTS.md`·`.agents/**` 부재를 검사한다. Publish용 `npm-shrinkwrap.json`도 이 isolated staging package 안에서만 만들고 root `package-lock.json`과 tracked source의 실행 전후 identity가 같아야 한다.

Authoritative DAG는 `015 → 016 → S0 → S1 → S2` 뒤 `R1 + B1 + D1`, `A1 + U1 + L1`, `B2 + R2`, serial `C1`, `H1`, 병렬 `I0 + G0`, coordinator-only `G1`, `I1`, `I2`, 사용자 승인 `P1`로 수렴한다. `I0`은 public package에 포함되지 않는 repository-only adapter로 deterministic fresh connected-account read와 setup/Ready/relaunch를 검증한다. `G0`은 reviewed RC generator를 만들고, coordinator가 `G1`에서 이를 fixed clean SHA에 실행해 actual tarball을 accept한다. `I1`은 test hook 없이 exact tarball의 signed-out login offer·workspace 무변경·host shutdown만 black-box 검증하며 Ready를 주장하지 않는다. Full packed Ready와 actual pinned native context는 `I0`·`I1`을 모두 통과한 `I2` live Browser OAuth clean-machine trace에서만 release evidence가 된다.

모든 lane은 exclusive path와 fixed reviewed SHA만 제출하고 coordinator의 single `--no-ff` merge queue를 통과한다. Root four gates, producer/consumer fixture equality, generated-output non-mutation, host composition, deterministic `SetupJourney`, Runtime candidate, local RC assembly, provider-free packed bootstrap, bounded live, publication readback을 순서대로 적용한다. Shared file drift, lease 우회, admitted workspace discard, unverified fallback, dirty export, fixture로 실패 은폐 또는 승인 없는 external write는 즉시 queue를 멈춘다. 상세 file roster, wave, DAG, handoff envelope, review·retry·stop-line protocol은 [최종 병렬 delivery contract 연구](../assets/final-parallel-delivery-contract-research.md)에 기록했다.
