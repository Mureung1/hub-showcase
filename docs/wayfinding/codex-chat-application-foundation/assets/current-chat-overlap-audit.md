## Current HTTP projection

Current application operation은 아래 네 `/api/codex-chat/*` route뿐이다. Shared `OPTIONS` preflight middleware는 별도 application operation이 아니다. Request body는 exact shape로 검증되고 mutation은 local request guard를 거친다. ([contract tests](../../../../apps/server/src/codex-chat-contract.test.ts#L17-L106), [body·Origin tests](../../../../apps/server/src/codex-chat-contract.test.ts#L108-L229))

| Method·route | Current projection |
| --- | --- |
| `GET /api/codex-chat/status` | `unavailable | configured | starting | ready | failed` status와 fixed `deny_all`/`read_only` policy를 반환하고 `Cache-Control: no-store`를 설정한다. Status 조회만으로 Runtime을 시작하지 않는다. ([route](../../../../apps/server/src/codex-chat-http.ts#L27-L69), [status](../../../../apps/server/src/codex-chat-service.ts#L75-L90)) |
| `POST /api/codex-chat/threads` | Exact `{}` body로 새 native thread를 만든다. Idle current handle이 있으면 먼저 local `releaseThread`한 뒤 lease를 교체하고 `201 { threadId }`를 반환한다. Active turn이나 pending thread start와 충돌하면 새 thread를 만들지 않는다. ([route](../../../../apps/server/src/codex-chat-http.ts#L71-L108), [lease replacement](../../../../apps/server/src/codex-chat-service.ts#L102-L135)) |
| `POST /api/codex-chat/threads/:threadId/turns` | Exact `{ text }`의 nonblank UTF-8 text를 최대 131,072 bytes까지 받고 current thread ID를 요구한다. Native `startTurn` acceptance를 기다린 뒤에만 `200 application/x-ndjson`을 commit하고 synthetic `turn.accepted`를 첫 frame으로 보낸 다음 allowlisted delta/item/error/terminal projection을 이어 쓴다. ([route](../../../../apps/server/src/codex-chat-http.ts#L110-L157), [body bound](../../../../apps/server/src/codex-chat-http.ts#L341-L370), [acceptance-first writer](../../../../apps/server/src/codex-chat-http.ts#L240-L264)) |

([route](../../../../apps/server/src/codex-chat-http.ts#L159-L177), [active scope](../../../../apps/server/src/codex-chat-service.ts#L245-L265), [Browser acknowledgment](../../../../apps/chat-shell/src/use-chat-shell.ts#L176-L214)) |

Client가 native acceptance 전에 disconnect하면 Server는 turn reservation을 취소한다. Accepted/streaming turn에서 disconnect하면 interrupt를 요청하고 최대 5초 동안 terminal을 drain하며, deadline까지 terminal이 없을 때만 Runtime을 닫는다. 이는 현재 transport policy이며 native accepted turn의 재접속 semantics는 아니다. ([disconnect handling](../../../../apps/server/src/codex-chat-service.ts#L329-L357), [disconnect regression](../../../../apps/server/src/codex-chat-disconnect.test.ts#L90-L136))

## Exact provenance와 reuse boundary

Current chain은 다음 경계를 갖는다.

1. Primary oracle은 clean [`references/openai-codex`](../../../../references/openai-codex) checkout `8c68d4c87dc54d38861f5114e920c3de2efa5876`, tag `rust-v0.144.4`다. Native contract는 `openai-codex-cli-bin==0.144.4`, Python SDK distribution은 `0.0.0.dev0`다. ([UPSTREAM](../../../../packages/codex-chat-runtime/upstream/UPSTREAM.md#L5-L16))
2. [`python/openai-codex`](../../../../packages/codex-chat-runtime/python/openai-codex)는 exact export·generated output의 immutable **unpatched** SDK snapshot이다. Production wheel은 이 snapshot에 baseline metadata/generation adaptation과 ordered behavioral patch를 적용해 별도로 build한다. ([tracked provenance](../../../../packages/codex-chat-runtime/upstream/UPSTREAM.md#L18-L45))
3. Behavioral patch order는 `0001-response-last-router` → `0002-bounded-notification-routing` → `0003-router-review-corrections` → `0004-notification-opt-out-config` → `0005-strict-response-classification`이다. Production SDK wheel과 native wheel은 manifest가 각각 exact digest로 고정한다. ([patch ledger](../../../../packages/codex-chat-runtime/upstream/PATCHES.md#L17-L28), [production derivation](../../../../packages/codex-chat-runtime/upstream/PATCHES.md#L142-L148), [artifact inputs](../../../../packages/codex-chat-runtime/upstream/UPSTREAM.md#L61-L74))
4. AY-PLE Python bridge는 patch가 아니라 complete patched SDK의 public `AsyncCodex` seam을 소비하는 private external adapter다. 그 위를 `CodexChatRuntime` → Server service/HTTP → Browser API/reducer가 차례로 project한다. ([bridge boundary](../../../../packages/codex-chat-runtime/upstream/PATCHES.md#L146-L148), [runtime factory](../../../../packages/codex-chat-runtime/src/index.ts#L33-L60), [Server composition](../../../../apps/server/src/codex-chat.ts#L10-L43), [Browser hook](../../../../apps/chat-shell/src/use-chat-shell.ts#L42-L57))

Pinned App Server processors/protocol은 exact native binary가 실행하고 SDK가 호출하는 current first-party behavior이며, 그 tests는 이 behavior의 primary evidence다. 반면 Rust client, TUI, CLI macOS desktop code와 experimental daemon은 **first-party application evidence**지만 current application이 import하거나 behavior를 reuse하는 surface는 아니다. Exact SDK/native behavior reuse와 다른 first-party application behavior reuse를 구분한다. 003–008은 이 code를 먼저 읽고 public seam 또는 좁은 port 가능성을 확인해야 한다.

아래 label은 evidence-seeking priority다. `keep`도 survivor 확정이 아니고, `replace`도 donor가 같은 semantics를 제공한다는 판정이 아니며, `research-needed`는 overlap을 아직 모른다는 뜻이다.

## Audit conclusion

Current baseline은 exact official SDK/native runtime 위에 AY-PLE-owned patch·five-command bridge·supervision을 두고, canonical Server가 four-route process-global current conversation/turn `1/1` projection을, Browser가 tab-memory transcript/stream projection을 소유하는 구조다. Account readiness, catalog, cold transcript recovery, replay와 late attach에는 current application owner가 없다.

[001 capability envelope](../tickets/001-foundation-capability-envelope.md#answer)가 채택한 explicit workspace, multi-conversation ownership, cold continuity, accepted-turn rejoin, multi-client sync, activity, pending interaction/approval, local web entry outcome은 이 current limitation과 별도다. 003–008은 위 bounded official·first-party·donor lookup에서 assumption delta를 확인하고, 009만 current custom code의 최종 `keep | replace | delete`와 required surface의 `direct reuse | adapt | narrow port | confirmed residual` disposition을 결정한다.
