## 1. 제품 한 줄 요약

자취 요리 초보가 **냉장고 재고를 보고 → 채우고(영수증) → 요리하고 → 다시 차감되는** 루프를 끊기지 않게 돌려주는 모바일 웹 앱. 핵심 페르소나는 23세 자취 대학생(요리 초보, 재료·채소값 지식 부족, 유통기한 놓침).

**해결하는 4가지 문제**

| 문제 | 앱의 해결 방식 |
|---|---|
| 어떤 재료로 뭘 해먹을지 모름 | 냉장고 재고 기반 레시피 추천 + 난이도 필터(초보/중급/상급) |
| 채소 평균가를 몰라 장보기가 막막 | 식자재별 평균가 정보(매일 갱신) |
| 남는 재료 소진이 어려움 | 최소 구매로 최대 요리 조합 추천(장보기 세트) |
| 냉장고에 뭐가 있는지 기억 안 남 | 나만의 냉장고 + 영수증 촬영 자동 등록 |
| 유통기한을 놓침 | 임박 알림(빨간 글자 + 푸시) + 보관법 팁 |

## 2. 네비게이션 구조

**하단 탭 5개**(`BottomTabBar.jsx`) — 탭 전환 시 백스택 초기화(`tab()`)

| 탭 | 아이콘 | 진입 화면 |
|---|---|---|
| 홈 | 🏠 | `home` |
| 냉장고 | 🧊 | `fridge` |
| 레시피 | 🍳 | `recipe-list` |
| 장보기 | 🛒 | `shopping-sets` |
| 기타 | ⚙️ | `etc-menu` |

**네비게이션 방식** — react-router가 아니라 직접 만든 스택(`AppContext.jsx`): `go(id)`는 현재 화면을 쌓고 전환, `back()`은 pop, `tab(id)`은 스택을 비우고 전환. 화면은 URL이 아니라 문자열 id이며 `App.jsx`의 `SCREENS` 객체가 컴포넌트로 매핑.

**모바일 프레임** — 전체가 390px 고정 폰 프레임(`PhoneFrame.jsx`) 안에서 렌더. 디자인 톤은 톤다운 빈티지(색상·둥근 모서리·그림자 토큰, `styles.css`).

## 3. 화면 지도 (18개 화면)

```
홈 탭
└─ home ──────────── 오늘의 냉장고 요약 + 임박 재료 + 추천 레시피

냉장고 탭
└─ fridge ────────── 재고 목록(임박/신선/가공)
   ├─ receipt-camera ─ 영수증 촬영
   │  └─ receipt-result ─ 인식 결과 확인
   │     └─ expiry-check ─ 유통기한 확인·보정 → 냉장고 반영
   └─ add-item ─────── 재료 직접 추가

레시피 탭
└─ recipe-list ───── 레시피 목록 + 필터
   └─ recipe-detail ─ 레시피 상세(재료·애드온·조리순서)
      ├─ cooking ───── 조리모드(단계별)
      └─ cook-done ─── 요리 완료 → 재고 차감(사용량 보정)

장보기 탭
└─ shopping-sets ─── 추천 재료 세트 + 필터
   └─ shopping-list ─ 장보기 리스트 → 영수증 촬영으로 연결

기타 탭
└─ etc-menu ──────── 기타 메뉴 허브
   ├─ expiry-alerts ─ 유통기한 임박 알림
   ├─ meal-plan-picker ─ 메뉴 2개 고르기
   │  └─ meal-plan ─── 일주일 식단 루틴
   │     └─ meal-shopping-list ─ 이번 주 장보기 리스트
   └─ prices ───────── 식자재 가격 정보
```

범례: **[MVP]** 핵심 기능 · **[확장]** 2차 우선순위

## 4. 화면별 상세 명세

### 4.1 `home` — 홈 [MVP 관문]

- **목적**: 앱을 열자마자 냉장고 상태와 지금 가능한 요리를 한눈에.
- **UI 구성**
  - 앱바: `🥬 냉장고 레시피`
  - Hero 카드 `🧊 오늘의 냉장고` + 통계 3개: **보유 재료 / 유통기한 임박 / 지금 가능한 요리** 개수
  - 배너: `🛒 냉장고 재료가 부족해요!` → 장보기 세트
  - 섹션 `유통기한 임박 재료` (전체보기 → 임박 알림) — 임박 재료 Row 리스트(빨간 D-day 뱃지)
  - 섹션 `오늘의 추천 레시피` (전체보기 → 레시피) — 보유율 높은 상위 2개 카드
- **이동**: 배너→`shopping-sets`, 임박 전체보기→`expiry-alerts`, 임박 Row→`fridge` 탭, 레시피 전체보기→`recipe-list` 탭, 레시피 카드→`recipe-detail`
- **API**: `GET /api/recipes?filter=all&level=all` (보유율 계산). 냉장고 데이터는 전역 상태 사용.

### 4.2 `fridge` — 나만의 냉장고 [MVP]

- **목적**: 모든 기능의 기반이 되는 재고 목록.
- **UI 구성**
  - 앱바: `나만의 냉장고`
  - 상단 버튼: `📷 영수증 촬영` / `＋ 직접 추가`
  - 섹션 `유통기한 임박 🔥`(있을 때만) — 빨간 글자 + 빨간 뱃지
  - 섹션 `신선식품` — Row(이모지·이름·`단위 · 구매일`·D-day 뱃지)
  - 섹션 `가공식품` — 유통기한 미입력 시 회색 `—` 뱃지
- **이동**: `receipt-camera`, `add-item`, Row 탭→재료 상세 바텀시트(`IngredientSheet`)
- **API**: `GET /api/fridge` (전역 fridge 상태)

### 4.3 `add-item` — 재료 직접 추가 [MVP]

- **목적**: 영수증 없이 재료를 수동 등록.
- **UI 구성**: 앱바 `재료 직접 추가`(뒤로가기) · 필드 4개
  - 재료명 (텍스트)
  - 수량 — **실생활 단위 칩**: `한단 / 반단 / 한쪽 / 반쪽 / 1/4쪽 / 1알 / g 직접입력`
  - 구매일 (date), 유통기한 (date)
  - 안내: `💡 신선식품은 구매일 기준 평균 유통기한 자동 입력(여름철 기준·수정 가능)`
  - 하단 고정: `냉장고에 추가` 버튼
- **API**: `POST /api/fridge`
- **⚠️ 알려진 한계**: 단위 칩이 하드코딩(재료 마스터의 `defaultUnitLabels` 미연동). 이름이 같아도 기존 재고와 매칭 안 되고 매번 새 항목 생성 → 중복 누적 (backlog P1).

### 4.4 `receipt-camera` — 영수증 촬영 [MVP]

- **목적**: 냉장고를 채우는 핵심 입력 수단.
- **UI 구성**: 앱바 `영수증 촬영`(뒤로) · 점선 뷰파인더(`🧾`, `점선 안에 영수증 전체가 들어오게`) · 원형 셔터 버튼 · 촬영 중 `인식하는 중…` 로딩
- **이동**: 촬영 성공 → `receipt-result`
- **API**: `POST /api/receipts`
- **⚠️ 알려진 한계**: 실제 OCR 미연동 — **하드코딩 데모 데이터** 반환. 외부 OCR(Naver Clova 등) 연동 필요 (backlog P1).

### 4.5 `receipt-result` — 인식 결과 확인 [MVP]

- **목적**: OCR 인식 품목을 확인하고 재촬영 여부 결정.
- **UI 구성**: 앱바 `인식 결과 확인`(뒤로) · 요약 `상점·날짜·N개 중 M개 인식 성공` · 품목 리스트(✅ 성공 / ⚠️ 실패, 신선/가공 뱃지) · 실패 시 빨간 경고 배너
  - 하단 고정: `📷 재촬영` / `M개 품목 반영`
- **이동**: 재촬영→`back()`, 반영→`expiry-check`
- **API**: `POST /api/receipts` 재요청(재촬영)

### 4.6 `expiry-check` — 유통기한 확인·보정 [MVP]

- **목적**: 신선식품 유통기한 자동 설정 확인 후 냉장고에 최종 반영.
- **UI 구성**: 앱바 `유통기한 확인`(뒤로) · 안내 `🌞 신선식품은 여름철 평균 보관기간 기준 자동 설정`
  - 섹션 `신선식품 — 자동 설정됨`: 재료별 D-day 뱃지 + **날짜 직접 수정(date input)** + 보관기간 노트(예: `자동 설정·냉장 2일`)
  - 섹션 `가공식품 — 직접 입력(선택)`: 회색 `＋ 입력` (선택 사항)
  - 하단 고정: 확정 버튼 → 냉장고 반영
- **이동**: 확정 → `fridge` 탭
- **API**: `POST /api/receipts/:id/confirm`

### 4.7 `recipe-list` — 레시피 목록 & 필터 [MVP]

- **목적**: "재고로 뭘 해먹지"를 풀어주는 지점.
- **UI 구성**: 앱바 `레시피`
  - 매칭 필터 칩: `전체 / ✅ 바로 가능 / 🧂 적은 재료 OK`
  - 난이도 필터 칩: `난이도 전체 / 🟢 초보자 / 🟡 중급자 / 🔴 상급자`
  - 안내 `🔥 임박 재료를 쓰는 요리 우선 · N개 레시피`
  - 레시피 카드 리스트: 보유율(`재료 have/total`), 바로 가능 강조, 부족 재료 표시
  - 결과 없을 때: `🤔` + 장보기 세트 유도 화면
- **💡 레시피 대용량화에 따른 체계화 방안 (상세 스펙)**
  - **1. 상단 통합 검색 바 (UI/UX & API)**
    - *위치*: `recipe-list` 화면의 매칭 필터 바로 위, 최상단에 고정(Sticky).
    - *기능*: 텍스트 입력 시 타이핑 지연(Debounce, 300ms)을 적용하여 실시간으로 필터링된 결과 렌더링.
    - *검색 대상*: 요리명(`title`)뿐만 아니라 주요 재료명(`ingredients`). 예: "돼지고기 김치" 입력 시 두 키워드가 모두 포함된 결과 도출.
    - *API 변경*: `GET /api/recipes?search=키워드` 쿼리 파라미터 지원.
  - **2. 음식 카테고리 탭 분류 (수평 스크롤 탭)**
    - *위치*: 검색 바 하단에 가로 스크롤이 가능한 칩(Chip) 형태의 카테고리 네비게이션 배치.
    - *분류 종류*: `[전체]`, `[국/찌개]`, `[반찬]`, `[일품요리]`, `[면/만두]`, `[밥/죽]`. (식품안전나라 API의 `RCP_PAT2` 요리 종류 데이터 활용)
    - *인터랙션*: 탭 전환 시 새로고침 없이 부드러운 페이드 인/아웃 트랜지션으로 하단 리스트 교체.
  - **3. 다중 정렬 드롭다운 (Sorting)**
    - *위치*: 필터 칩 영역 우측 끝에 작은 드롭다운(⇅) 아이콘 버튼 배치.
    - *정렬 로직 상세*:
      - `추천순(보유율)` [기본값]: `(가진 재료 수 / 전체 필요 재료 수)` 역순 정렬. (유통기한 임박 재료가 포함된 경우 최상단으로 끌어올리는 가중치 적용)
      - `조리시간 짧은순`: API 데이터의 조리시간 오름차순.
      - `난이도 낮은순`: 초보자 → 중급자 → 상급자 순서.
  - **4. 성능 최적화: 무한 스크롤 & 이미지 레이지 로딩**
    - *백엔드 (페이징)*: 전체 목록을 한 번에 반환하지 않고, `page=1&limit=20` 쿼리를 받아 20개씩 쪼개어 반환 및 `hasMore` 플래그 제공.
    - *프론트엔드 (무한 스크롤)*: `IntersectionObserver`를 활용해 리스트 맨 아래의 로딩 스피너가 화면에 보이면 다음 페이지(20개)를 자동으로 가져와 기존 리스트 아래에 병합(`append`).
    - *UI (이미지)*: 100장이 넘는 레시피 썸네일로 인한 메모리 과부하를 막기 위해 `loading="lazy"` 속성을 적용하여 화면에 노출될 때만 이미지를 다운로드.
  - **5. 개인화 기능: 북마크(찜) 보관함**
    - *인터랙션*: 각 레시피 카드 썸네일 우측 상단에 하트(♡/♥) 아이콘을 배치하여, 클릭 즉시 채워지며 서버에 비동기 저장.
    - *모아보기 UI*: `recipe-list` 앱바 우측 또는 `기타` 탭에 `❤️ 내 찜 목록` 버튼을 두어 즐겨찾기한 레시피만 모아보는 전용 뷰 제공.
    - *DB 연동*: Supabase에 `user_bookmarks` 테이블(사용자 ID, 레시피 ID)을 신설하여 유저별 데이터 연동.
- **이동**: 카드→`recipe-detail`, 장보기 세트 보기→`shopping-sets` 탭
- **API**: `GET /api/recipes?filter=all|full|few&level=all|beginner|mid|high`

### 4.8 `recipe-detail` — 레시피 상세 [확장]

- **목적**: 재료·응용 옵션·조리 순서를 보고 조리/완료로 진입.
- **UI 구성**: 앱바 `레시피 상세`(뒤로)
  - Hero 이모지 + 이름 + 난이도 뱃지 + `⏱ N분 · 1인분`
  - 섹션 `필요 재료 (have/total 보유)`: ✅/❌ + 이름 + (선택 재료 뱃지) + 분량
  - 섹션 `더 넣으면 좋아요 — 냉장고에 있어요 🧊`: 애드온 체크박스(체크 시 조리 순서/조리모드에 단계 추가), 임박 재료는 빨간 뱃지
  - 섹션 `조리 순서 요약`: 번호별 요약(애드온 추가 단계는 초록 강조)
  - 하단 고정: `👨‍🍳 조리모드 시작` / `🍽️ 요리 완료`
- **이동**: `cooking`, `cook-done`
- **API**: `GET /api/recipes/:id`

### 4.9 `cooking` — 조리모드 [확장]

- **목적**: 초보도 따라할 수 있는 단계별 조리 안내.
- **UI 구성**: 앱바 `{레시피명} — 조리모드`(뒤로) · 진행바 · `STEP n/N` · 단계 박스(이모지·설명·팁) · **밑줄 팁 링크**(누르면 왕초보 설명 시트 `TipSheet`)
  - 하단 고정: `‹ 이전` / `다음 ›` (마지막 단계는 `🍽️ 식사 완료`)
- **이동**: 마지막 단계 완료 → `cook-done`
- **API**: 없음(상세 조회 시 받은 스텝을 로컬 진행)

### 4.10 `cook-done` — 요리 완료 & 재고 차감 [MVP]

- **목적**: 조리 후 냉장고 재고를 자동 차감(루프의 연결고리).
- **UI 구성**: 앱바 `요리 완료` · Hero `🎉 맛있게 드세요!`
  - 기본 모드 `차감된 재료`(✏️ 사용량 수정): 재료별 `차감 전 → 차감 후`, 소진되면 빨간 글자, 추가 재료 뱃지
  - 수정 모드 `실제 사용량 보정`(✓ 수정 완료): `−/＋` 스텝퍼로 재료별 사용 레벨 조절, `전량 사용` 고정 항목
- **API**: `POST /api/recipes/:id/cook-done` (보정값 `adjustments` 포함 가능). 완료 후 `refreshFridge()`로 냉장고 갱신.

### 4.11 `shopping-sets` — 동적 추천 장보기 세트 [확장]

- **목적**: 장보기 전, 최소 구매로 최대 요리 조합을 유동적으로 추천.
- **UI 구성**: 앱바 `추천 재료 세트`
  - 매칭 필터 칩: `전체 / 임박 재료 구출 / 최소 지출 완성 / 식자재 쉐어링`
  - 난이도 필터 칩: `난이도 전체 / 🟢 초보자 / 🟡 중급자`
  - 안내 `🧊 사용자의 냉장고 상태에 맞춰 실시간 조합된 세트입니다.`
  - 세트 카드: 세트 테마명 + 뱃지 + 난이도 뱃지 + 포함된 요리 리스트
- **이동**: 세트 카드→`shopping-list`
- **핵심 매커니즘 (동적 추천)**:
  - **임박 재료 구출**: 유통기한 임박 재료를 최우선으로 모두 소진할 수 있는 레시피 묶음.
  - **최소 지출 완성**: 현재 재고로 70~80% 완성 가능하여, 1~2개 추가 구매만으로 여러 요리가 가능한 묶음.
  - **식자재 쉐어링**: 대파, 양파 등 하나를 사서 여러 요리에 공통으로 사용할 수 있는 레시피 묶음.
- **수량 누적 산출 로직 (중요)**:
  - 단순히 재료의 보유 유무(Boolean)만 판단하지 않습니다.
  - 세트(일주일치 등) 내의 여러 요리에서 동일한 재료(예: 대파)가 반복 사용될 경우, **모든 요리의 필요 수량을 합산**하여 냉장고 잔량과 비교합니다.
  - 예: 세트 내 7개 메뉴에서 대파를 1개씩 쓴다면 총 7개 필요. 냉장고에 2개만 있다면 장보기 리스트에 '대파 5개 부족'으로 계산되어 추천 및 장바구니에 담깁니다.
- **API**: `GET /api/shopping-sets?filter=...` (동적 알고리즘 반환)

### 4.19 `serving-size-setting` — 내 인분 설정 [새로운 기능]

- **목적**: 사용자의 식사량에 맞춰 전체 레시피와 장보기 목록의 기본 제공량(인분)을 동적으로 조절.
- **UI 구성**: 앱바 `내 인분 설정`(뒤로)
  - 국물류를 제외한 **대표 식사 예시 3가지**(제육볶음, 파전, 김치볶음밥)를 세로 목록으로 하나씩 제시.
  - 각 메뉴별로 1부터 9까지 선택할 수 있는 **구글 폼 형태의 원형 라디오 버튼 UI** 제공.
  - 하단 고정: `설정 저장하기`
- **동작 매커니즘**:
  - **평균 인분 계산**: 세 가지 요리에서 선택한 값(1~9)의 평균을 계산한 후, 숫자 4를 '표준 1인분(1.0)' 기준으로 삼아 배수를 계산 ((선택값 + 1) × 0.2). 계산된 최종 인분은 **소수점 첫째 자리까지 표기**하며, 둘째 자리 이하는 내림 처리 (예: 1.25 -> 1.2인분).
  - 설정 후 **기타 메뉴 화면** 내 `내 인분 설정` 탭 우측 하단에 최종 계산된 인분 표기 (예: `설정된 내 인분: 1.2인분`).
  - 앱 전역의 `레시피 상세` 및 `장보기 추천 세트`, `일주일 식단`에서 이 **인분 배수(Multiplier)를 곱하여 재료 필요량을 재계산**.
  - **최소 단위 반올림 (Rounding 로직)**: 양파, 대파, 두부처럼 소수점으로 쪼개기 모호한 낱개/묶음 재료는 배수 적용 후 **1/4(0.25) 단위로 반올림**하여 표시 (예: 계산 시 1.2개가 나오면 1개 하고 1/4쪽(1.25)으로 표기 및 계산). g 단위(돼지고기 등)는 정수로 표기.
