## 프로젝트명

**AI 분리배출 도우미 (AI Recycling Assistant for Korea)**

### 프로젝트 한 줄 소개

> **사진 한 장으로, 한국의 올바른 분리배출 방법을 공식 데이터와 AI를 통해 쉽고 정확하게 안내하는 서비스**

---

# 프로젝트 배경

한국의 분리배출 규정은 국가 공통 규정과 지자체별 규정이 함께 존재하며, 품목별 처리 방법도 매우 다양하다.

특히 다음과 같은 사용자들은 분리배출 과정에서 많은 어려움을 겪는다.

* 외국인 및 교환학생
* 자취생 및 대학생
* 한국의 분리배출 규정을 처음 접하는 사람
* 애매한 품목(종이팩, 아이스팩, 우산, 전자제품 등)의 처리 방법을 모르는 사용자

대부분의 사용자는 인터넷 검색이나 블로그를 통해 정보를 찾지만,

* 정보가 오래되었거나
* 지역별 규정이 다르거나
* 신뢰하기 어려운 경우가 많다.

본 프로젝트는 **공공데이터포털의 공식 데이터를 Source of Truth로 사용**하고, AI는 이를 쉽고 직관적으로 이해할 수 있도록 설명하는 역할을 수행한다.

사용자가

> "이거 어디에 버려야 하지?"

라는 고민을

으로 해결하는 서비스를 구축한다.

AI는 물체를 인식하고,

공식 정부 데이터를 기반으로

* 올바른 분리배출 방법
* 준비 과정
* 주의사항
* 지역별 규정

을 안내한다.

# 핵심 컨셉

**AI는 분리배출 방법을 '판단'하지 않는다.**

AI의 역할은

* 물체 인식
* 설명
* 번역

이며,

분리배출 규정은 반드시 **공식 정부 데이터**를 기반으로 제공한다.

이를 통해

* 정확성
* 신뢰성
* 유지보수성

을 확보한다.

# 주요 기능

## 1. AI 사진 인식 (핵심 기능) — ✅ 구현 완료

사용자가 사진을 촬영하거나 업로드하면 Vision AI가 물체를 인식한다.

### 처리 흐름

사진 촬영 → Vision AI(품목명 추측) → 카탈로그 매칭 → 정부 API 조회 → 공식 분리배출 정보 → LLM 설명 → 결과 화면

### 결과 화면 예시

**🥤 플라스틱 음료병**

🟢 **PET 재활용**

#### 분리배출 방법

1. 내용물을 비운다.
2. 물로 헹군다.
3. 라벨을 제거한다.
4. 뚜껑을 분리한다.
5. 압착한다.
6. PET 재활용함에 배출한다.

#### 부품별 분리

* 병 몸체 → PET
* 뚜껑 → PP
* 라벨 → 비닐

#### 자주 하는 실수

* 라벨을 제거하지 않고 배출
* 내용물이 남아있는 상태로 배출

#### 왜 이렇게 버려야 하나요?

PET의 재활용 품질을 높이기 위해서는 라벨과 내용물을 제거해야 한다.

---

## 2. 품목 검색 — ✅ 구현 완료

사진 촬영이 어려운 경우 직접 품목명을 검색할 수 있다.

예시: 건전지, 우산, 종이팩, 아이스팩

검색으로 선택한 물품의 결과는 사진 인식 결과와 동일한 화면을 제공한다.

---

## 3. 지역별 분리배출 규정 — ✅ 구현 완료

사용자는 **시/도 → 구/군**을 선택하고, 정부 데이터가 구/군 내부를 동 단위로 세분화해 둔 경우에만 **동**까지 선택한다(구 전체에 규정이 하나뿐인 지역은 동 선택 없이 바로 결과를 보여준다).

예시

부산 → 해운대구 (구 전체 단일 규정 — 동 선택 불필요)

대구 → 북구 → 산격1동 (동별로 규정이 달라 동 선택 필요)

확인 가능한 정보:

* 카테고리별(생활쓰레기 / 음식물쓰레기 / 재활용품 / 대형폐기물) 배출 요일·시간·방법
* 미수거일
* 데이터가 없는 구/군을 선택하면, 같은 시/도 내에서 실제로 데이터가 있는 다른 구/군을 대안으로 안내(임의로 규정을 지어내지 않음)

---

## 4. 다국어 지원 — ✅ 구현 완료 (앱 전체)

한국어를 전혀 모르는 사용자도 앱을 쓸 수 있도록, Translate 토글이 결과 화면뿐 아니라 앱 전체(홈/검색/결과/확인/규정 화면 + 지역 선택 시트)에 적용되어 있다.

- **정적 UI 문구**(버튼/제목/안내 문구): `frontend/src/i18n/{ko,en}.ts`의 타입 안전한 사전(`en.ts`가 `satisfies Record<keyof typeof ko, string>`로 번역 누락을 컴파일 타임에 잡음) + `LanguageContext`(localStorage에 저장돼 페이지를 이동해도 선택한 언어가 유지됨). `PageHeader`가 토글 버튼을 직접 렌더링하므로 `PageHeader`를 쓰는 모든 화면이 자동으로 토글을 갖는다.
- **정부 데이터 기반 설명 텍스트**(`DisposalRule.steps`/`parts`/`commonMistakes`/`reason`): `geminiExplanationClient`가 한/영을 한 번의 호출로 함께 생성해 캐시(`stepsEn`/`partsEn`/`commonMistakesEn`/`reasonEn`)하므로 토글 클릭 시 네트워크 재요청이 없다. 이전에 한국어만 캐시되어 있던 기존 항목은 다음 조회 시 영어 필드만 백필되고 한국어 생성 시각(`explainedAt`)은 그대로 유지된다. 번역 대상은 공식 데이터를 가공한 설명 텍스트뿐이며, 영어 버전도 새 규정이 아니라 한국어 설명의 번역이라는 CLAUDE.md 원칙을 프롬프트로 강제한다.
- **품목명 검색**: `Item.nameEn` 컬럼(731개 카탈로그 전체를 `syncItemNamesEn.ts`로 일괄 번역)을 추가해 `searchItems`가 `name OR nameEn`으로 매칭 — 영어 키워드 검색이 한국어 품목과 자연스럽게 연결된다("battery" → 건전지류, "plastic" → 비닐/플라스틱류 등, 실제 카탈로그로 검증 완료).
- **지역 선택기 지명 표기**(시/도/구/군/동/읍/면): 품목명 번역과 달리 "의미 번역"이 아니라 "표준 로마자 표기"가 필요한 문제라, 규칙 기반 로마자 변환 라이브러리를 먼저 검증했으나 실제 지명("강릉시")을 잘못 표기하는 결함을 발견하고 기각 — 대신 이미 검증된 Gemini 기반 패턴을 재사용했다. 데이터가 로컬에 전량 동기화되어 있는지 여부에 따라 캐싱 전략을 나눔: `RegionDistrict.ctpvNmEn`/`sggNmEn`은 `Item.nameEn`과 동일하게 배치 스크립트(`syncRegionNamesEn.ts`)로 일괄 채움(16개 시/도 + 226개 구/군), `RegionZoneName`(신규 모델)은 동/읍/면이 전량 동기화되어 있지 않아 실제로 조회된 이름만 지연 캐시한다(지역과 무관하게 텍스트 자체로 전국 재사용). "Gyeonggi-do", "Haeundae-gu", "Gangneung-si" 등 실제 지명으로 검증 완료.
- **아직 남은 갭**: `RegionRule.categories[category].method`(지역별 배출방법 원문 텍스트)는 아직 영어 번역이 없어 영어 모드에서도 한국어로 표시됨. 영어 검색이 0건일 때 LLM이 한국어 후보를 추론해 재검색하는 폴백도 아직 없음(현재는 `nameEn` 사전 매칭만). `BulkyPage`/`PointsPage`(아직 빈 스텁)는 범위 밖.

## 5. 대형폐기물 신고 가이드 — 🚧 계획 (미구현)

가구나 가전제품과 같은 대형폐기물은 지역별 신고 절차와 수수료가 다르다. 사용자가 품목 선택 → 지역 선택 → 수수료 확인 → 공식 신고 사이트 이동 → 신고 방법 안내를 받는 흐름을 계획하고 있다.

---

## 6. 주변 수거 장소 안내 — 🚧 계획 (미구현)

건전지, 형광등, 소형가전, 종이팩 등 전용 수거함 위치를 안내하는 기능을 계획하고 있다(1차는 목록, 지도 시각화는 이후 단계).

---

## 7. 오늘의 배출 일정 / 일주일 배출 일정 — ✅ 구현 완료

사용자가 설정한 지역을 기준으로 홈 화면에서 오늘 배출 가능한 품목과 이번 주 7일치 일정을 함께 안내한다. `RegionRule`의 카테고리별 요일 데이터를 클라이언트에서 요일별로 재구성해(`buildWeeklySchedule`) 오늘 카드와 7일 그리드를 렌더링한다(대형폐기물은 요일 개념이 없어 주간 달력에서는 제외).

MVP에는 별도의 Push Notification 없이 앱을 실행하면 바로 확인 가능하도록 설계한다.

# AI 역할

## Vision AI

담당 역할

* 물체 인식
* Top Prediction 생성 (Confidence Score는 사용하지 않음 — 신뢰도 기반 분기 없이 항상 확인 화면으로 진행)

Vision AI는 정부 데이터포털에 실제로 존재하는 품목명 목록을 프롬프트로 함께 전달받아, 그 목록과 정확히 일치하거나 가장 비슷한 한국어 품목명을 답하도록 유도된다.

예시

* "유리병"
* "헤어 스프레이"
* "바나나껍질"

---

## 품목 매칭

Vision AI의 추측 결과를 서비스가 보유한 전체 품목 카탈로그와 대조해 가장 가까운 공식 품목명을 확정한다.

예시

"헤어스프레이"(추측, 띄어쓰기 없음)

↓

"헤어 스프레이"(카탈로그 표기, 공백 제거 후 비교하여 매칭)

이를 통해 정부 API와 안정적으로 연결할 수 있다.

---

## Government API

프로젝트의 **Source of Truth**

담당 역할

* 공식 분리배출 규정 제공
* 지역별 규정 조회
* 수거 정보 제공

AI는 규정을 생성하지 않는다.

---

## LLM

LLM은 공식 정보를

* 이해하기 쉬운 문장으로 변환
* 단계별 안내 생성
* 번역
* 이유 설명

에만 사용한다.

즉, LLM은 규칙을 만드는 것이 아니라 공식 정보를 사용자에게 쉽게 전달하는 역할을 수행한다.

# 핵심 차별점

기존 검색 서비스는 사용자가 여러 웹사이트나 블로그를 찾아 정보를 비교해야 하는 경우가 많다.

본 서비스는 **Vision AI**, **공식 정부 데이터**, **LLM**을 결합하여 한 번의 사진 촬영만으로 정확한 분리배출 정보를 제공한다.

또한 AI가 규칙을 임의로 생성하지 않고, 정부의 공식 데이터를 기반으로 설명과 번역만 수행하도록 설계하여 정확성과 신뢰성을 확보한다.

이를 통해 사용자는 보다 쉽고 빠르게 올바른 분리배출 방법을 확인할 수 있으며, 한국의 복잡한 분리배출 규정을 누구나 이해할 수 있는 형태로 제공하는 것을 목표로 한다.
