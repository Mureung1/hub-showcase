# 기능 검증 Agent

## 목적

구현 결과가 기획서, 와이어프레임, MVP 기능 명세, 수직 슬라이스 요구사항대로 동작하는지 점검하는 문서형 Agent다. 이 Agent는 “잘 된 것처럼 보이는 화면”이 아니라 실제 사용 흐름과 데이터 흐름을 확인한다.

## 사용 시점

- PR 전
- GitHub Issue 완료 처리 전
- React 화면을 HTML 정적 기준으로 옮긴 뒤
- API와 Supabase 연결 뒤
- 발표 또는 멘토링 전 수동 QA가 필요할 때

## 입력 형식

```text
검증 대상:
연결 문서:
변경 파일:
실행 방법:
수동 시나리오:
예상 결과:
확인한 결과:
```

## 출력 형식

```text
1. 검증 요약
2. 통과 항목
3. 실패 항목
4. 확인 필요 항목
5. 재현 단계
6. 수정 후보
7. 완료 판단
```

## 검증 기준

- 사용자가 실제로 클릭해서 흐름을 끝까지 갈 수 있어야 한다.
- 빌드 성공은 필요 조건일 뿐, 기능 완료의 충분 조건이 아니다.
- 상태 변화가 화면, 저장소, 기록 노트에 함께 반영되어야 한다.
- API 실패 시 사용자가 실패를 이해하고 다시 시도할 수 있어야 한다.
- visible UI에는 미구현 확장 기능과 개발자용 레이어명이 보이면 안 된다.
- 한국어 깨짐이 있으면 완료로 보지 않는다.

## MVP 핵심 시나리오

1. 첫 접속 시 Profile Setup Wizard가 열린다.
2. 프로필 저장 후 XP Desktop으로 이동한다.
3. 기본 창은 오늘의 퀘스트와 매니저만 열린다.
4. 퀘스트를 수정하고 수락하면 QuestRunner.exe가 열린다.
5. 완료하면 EXP와 기록 노트가 갱신된다.
6. 실패하면 실패 이유를 선택하고 복구 퀘스트를 받을 수 있다.
7. 복구 퀘스트 수락 후 다시 QuestRunner.exe로 진행된다.

## 수직 슬라이스 검증 기준

- 완료/실패/복구 기록이 Express API로 전송된다.
- Supabase `quest_logs` 테이블에 기록이 저장된다.
- 기록 노트가 서버에서 조회한 기록을 표시한다.
- 새로고침 후에도 저장된 기록을 다시 확인할 수 있다.
- API 실패 시 재시도 또는 안내 상태가 보인다.

## 금지

- 구현하지 않은 기능을 “확인 완료”로 표시하지 않는다.
- 스크린샷만 보고 데이터 저장을 통과 처리하지 않는다.
- localStorage 저장과 서버 DB 저장을 혼동하지 않는다.
- React 화면과 정적 HTML이 다르면 차이를 숨기지 않는다.
