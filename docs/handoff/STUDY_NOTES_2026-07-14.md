## 큰 그림: 오늘 한 일

프로젝트를 **"메인 시스템 = 3-에이전트 파이프라인"** 으로 재정의하고, 그 첫 하부 구현을 만들었다.

```
입력(공식 MBTI + 공부·스트레스 응답)
      │
      ▼
(a) 매칭 에이전트  → MBTI 성향 × 응답을 인지과학 공부법에 매칭      ← 오늘 핵심
      │
      ▼
(b) 스케줄 에이전트 → 매칭 결과를 오늘의 시간블록으로              ← 오늘 시드
      │
      ▼
   실행 → 만족도·효과·메타인지 측정(어제 만든 것)
      │
      ▼
(c) 데이터 에이전트 → 결과를 서버 DB에 수집·분석                  ← 오늘 토대
```

**목적(순차):** ① MBTI 개인화 매칭으로 실제로 돕고 → ② 만족도·효과를 측정해 → ③ DB·문서로 쌓고 분석 → 연구용 빅데이터.
(어제 "반증하겠다"는 학술적 프레임에서, 오늘 "돕고→재고→쌓는" 제품 프레임으로 방향을 바로잡았다.)

## 1. 폴더 구조를 바꿨다 (frontend / backend 분리)

- **전:** 저장소 루트에 Vite 앱이 통째로 있었다.
- **후:** 앱을 `frontend/`로 옮기고, 새로 `backend/`(Express 서버)를 만들었다. 루트 `package.json`은 두 폴더를 대신 실행해 주는 "리모컨" 역할.
  - `npm run dev:frontend` / `npm run dev:backend` / `npm run build` / `npm run lint`
- **왜:** 이번 주 과제가 "FE·BE·DB를 실제로 연결"하라고 요구했고, 서버가 생기니 프론트/백을 나누는 게 표준이다.
- **개념:** `git mv`로 옮기면 파일 **이력이 보존**된다(커밋에 "rename 100%"로 찍힘). 그냥 삭제+생성이 아니다.

## 2. 매칭 에이전트 (a) — 오늘의 핵심

내가 준 논문으로 **MBTI → 인지과학 공부법 매칭 기준**을 실제로 만들었다.

- **기준 문서:** `docs/matching-criteria.md` — Keirsey 4기질(SJ·SP·NT·NF)과 4축을 7개 학습법에 연결한 표 + 논문 출처.
  - SJ(관리자형): 분산·환경설계 (강점) + 교차학습(유연성 보완)
  - SP(실용형): 짧은집중·오답분석 + 분산(꾸준함 보완)
  - NT(분석형): 자기설명·인출 + 분산(반복 보완)
  - NF(이상형): 자기설명·환경 + 오답분석(객관 보완)
- **핵심 설계 = "강점 활용 + 약점 보완".** 논문 [E1]에서 성적 상위권은 자기 유형 선호에만 머물지 않고 **자기조절로 약점을 보완**했기 때문. (그래서 "이 유형엔 이것만" 식의 learning-styles 함정을 피한다.)
- **코드:** `frontend/src/data/mbtiMethodMatching.js`가 매칭표를 코드로, `recommendations.js`가 그걸 **실제 추천 점수에 가중치로 반영**한다. 단, 개인 응답을 압도하지 않게 **상한(+15)** 을 뒀고, MBTI 없는 baseline도 항상 함께 계산해 나중에 비교(②)한다.
- **화면:** 결과에 "MBTI × 공부법 매칭" 섹션(예: "INTJ · 분석형(NT) 맞춤 매칭")이 뜬다.
- **정직 라벨(가볍게):** "선호일 수 있음 · 효과는 실행 결과로 확인" 한 줄. 막지 않되 과장도 안 한다 = 이게 ①→② 루프.

## 3. 스케줄 에이전트 (b) — 시드

- `frontend/src/lib/schedule.js`: 매칭된 TOP 학습법을 **오늘의 시간블록**(예: 분산 25분 · 인출 25분 · 회복 3분)으로 배치.
- 실천 카드에 "오늘의 시간블록(총 N분)"으로 표시. 상세 시간표·에브리타임은 다음 단계.

## 4. 데이터 에이전트 (c) — 서버 수집 토대

과제의 "FE→요청→서버→DB→응답→화면" 한 사이클을 만들었다.

- **백엔드(`backend/`):** Express + CORS + dotenv.
  - `GET /api/health` — 서버 생존 확인(표준 헬스체크. 의료 아님).
  - `POST/GET/DELETE /api/results` — 결과 저장/조회/삭제.
  - 저장소는 **in-memory**(메모리). 나중에 Supabase로 바꿀 수 있게 함수로 분리(`store.js`).
- **개인정보 보호가 핵심:** 서버는 **허용된 필드만**(anonId·mbti·매칭방법·점수 등) 저장하고, **이름·자유응답은 자동으로 버린다**(화이트리스트). 로그인·JWT는 안 만들었다(게이트 이후). 저장은 **동의 체크 후에만**, 삭제 버튼도 있다.
- **프론트(`api.js`):** `VITE_API_BASE_URL`로 서버를 호출. 결과 화면에 "동의 → 익명 저장 / 조회 / 삭제" UI. **서버가 꺼져 있어도 앱은 안 멈춘다**(실패를 잡아 안내만).
- **개념:** `.env`(비밀·설정)는 git에 안 올리고 `.env.example`만 올린다. `CORS`는 "다른 주소(프론트 5173)에서 서버(3001)를 불러도 허용"하는 설정.

## 5. 개발용 에이전트 2개 (과제 산출물)

`.agents/skills/`에 Codex가 쓸 스킬 2개를 추가.
- `feature-planner`: 요구사항을 작업으로 쪼개고 우선순위를 매긴다(코드 X).
- `feature-verifier`: build/lint·헬스체크·PII 차단·결정론 등 "요구대로 되는지" 점검한다.
- 이건 **제품 안의 AI가 아니라 개발을 돕는 AI** — 사용자 데이터를 안 건드려서 지금 만들어도 안전하다. (제품 안 LLM은 개인정보·비용 때문에 나중.)
