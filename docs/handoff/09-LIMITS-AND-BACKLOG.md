## 0. 먼저 알아야 할 것 세 가지

**① 이건 4주 MVP다.** 프로덕션 서비스가 아니다. 아래 한계 대부분은 "몰라서 못 한 것"이 아니라 **"알면서 미룬 것"**이고, 미룬 이유가 각 항목에 적혀 있다.

**② 성능 한계는 모델 특성이다.** 질문 하나에 2~3분이 걸리는 건 버그가 아니다. `qwen3.7-plus`의 추론 토큰이 출력의 88~94%이고 처리량이 약 53토큰/초로 선형이라, 토큰을 줄이지 않는 한 지연은 줄지 않는다. 자세한 근거는 `07-BUILD-HISTORY.md` §3.

**③ 소급 불가능한 것이 하나 있다.** 아래 §4.1을 반드시 먼저 읽어라.

## 1. 배포·보안 — 지금 판단이 필요한 것

### 1.1 로그인 화면에 데모 계정 자격증명이 하드코딩돼 있다

`apps/web/src/features/auth/LoginPage.tsx` (31~32행)

T-018에서 **의도적으로** 넣었고 주석에 "실서비스 전환 전 필수 제거"가 명시돼 있다. 하지만 **배포된 번들에서 누구나 읽을 수 있다.**

**auto-fill을 유지하는 한 이건 못 막는다.** `VITE_` 환경변수로 빼도 번들에 그대로 박힌다.

권장 조치:
- 그 계정이 **데모 전용 폐기 계정**인지 확인 — 다른 곳에 쓰지 않는 이메일·비밀번호여야 한다
- 비밀번호가 재사용된 것이면 **교체**한다
- 코드 주석과 README에 **"의도된 데모 계정"**이라고 명시한다

**지우는 것만이 답은 아니다.** 심사자·평가자에게 자동 입력은 편의 기능이다. 흔적 없이 지우는 것보다 **의도로 문서화하는 것**이 이 프로젝트의 방향(판단 근거를 남긴다)과도 맞는다.

### 1.2 생략 건수가 `context_snapshot`에 저장되지 않는다

SPEC-AI-003 AC9. `CONTEXT_MAX_NOTES = 5`를 넘는 DecisionNote는 Context에서 제외되는데, **몇 개가 생략됐는지 스냅샷에 기록되지 않는다.** 콘솔 로그로만 남는다.

Spec은 "조용한 절단 금지"를 명시하고 있으므로 이건 **Spec 위반**이다.

- 발동 조건: DecisionNote 6건 이상. 데모 규모에서는 안 터진다
- 수정: `saveContextSnapshot`에 `omittedNoteCount`·`contextVersion` 추가. 15~30분
- ⚠️ **`sourceAnswers.controller.ts:230`의 "(스냅샷에도 저장된다)" 주석이 코드와 불일치한다.** 없는 기능보다 나쁘다 — 다음 사람이 그걸 믿고 확인을 건너뛴다. **주석만이라도 먼저 고쳐라(2분).**

## 2. Manager AI (SPEC-AI-002)

### 2.1 성능

| 한계 | 내용 |
|---|---|
| **사용자 대기 2~3분** | 단계 6이 쟁점당 p50 83초. Render cold start 시 추가 |
| **단계 3 지연 하한 ~30초** | 분할 후에도 2사 fixture 12~30초. 모델 특성. `qwen3.7-plus` 유지 확정, SSE 조기 표시로 완화 |
| 판정이 런투런으로 흔들린다 | 기준선 4/4 쟁점에서 관측. 모델 특성. **단일 실행 결과를 근거로 삼지 않는다** |
| 단계 3 배정 잡음 ~7% | 조건과 무관하게 상시. 쟁점 목록 자체는 안정적 |

### 2.2 품질 — 가장 중요한 미해결 질문

**`main_answer`(충돌) 비율이 55~70%다.** 임계값 5%를 크게 넘는다.

쟁점 10개 중 5.5~7개가 사용자 판단 대상이 된다는 뜻이고, 그러면 **"자동 통과"의 의미가 줄어든다.** 이 제품의 핵심 주장이 "합의된 건 넘기고 충돌만 물어본다"인데, 대부분이 충돌로 판정되면 주장이 약해진다.

- 과탐지인지 실제로 그런 건지 **아직 모른다**
- 판단 방법: `conflictAcceptRate` — 사용자가 실제로 어떻게 처리하는지 관찰
- 대안: `MANAGER_CONFLICT_TYPES` 설정으로 `detail_content`(결론 같음·근거 다름)를 합의로 돌릴 수 있다

**이어받는 사람이 가장 먼저 봐야 할 지표가 이것이다.**

### 2.3 미확정·미구현

| 항목 | 상태 |
|---|---|
| `confidence` 임계값 | 미정. 데이터 20~30건 축적 후 판단 (표준편차 baseline 0.0744 / low 0.1229) |
| `multiAssignRate` 0%의 해석 | 미확정 |
| 에스컬레이션(Cascaded Selective Evaluation) | 설정 자리만 마련. 미구현 |
| pivot 쏠림 | `pivotProviderDist`로 감시만. 대응 안 함 |
| **좌초 복구** | **미구현.** Manager 실행 중 서버가 죽으면 `draft` Agenda가 남는다. 시간 기반 정리 대상에 `draft`·`recheck_requested` 포함 예정 |
| `effort: low` 통제 재측정 | 미실행 |
| §11.2 인용 정규화 완화 판단 | 폐기 인용 축적 후. **관측이 상시 작동하므로 강제 실행은 불필요** |
| `grounding.ts:50`의 `not_in_this_agenda` | 선언만 있고 부여 경로가 없는 **사문**. 동작 결함은 아니고 지표 해석에만 영향 |

### 2.4 AC 미충족 2건

**AC2 (단계 3b 누락 회수)** — 특정 섹션만 누락시킬 수단이 없어 경로를 확인하지 못했다.
**AC10 (단계 6 실패 fallback)** — 코드 경로만 확인. 타임아웃이 0건이라 실측이 발생하지 않았다.

둘 다 **"의도적으로 만들 수 없는 실패 상황"**이다. 코드 근거는 완결돼 있다.

## 4. 백로그

### 4.1 ⚠️ 1번 — FinalAnswer 문단↔쟁점 근거 추적 **(소급 불가)**

출력을 문단 배열로 받고 각 문단에 `agendaIds`를 붙이는 것.

**미룬 이유**: 화면 표시를 이번 범위에 넣지 않기로 했으므로, 데이터만 쌓는 셈이 된다.

> **⚠️ 이건 소급이 불가능하다.**
> 문단↔쟁점 매핑은 **생성 시점에만** 알 수 있다. §5.4가 FinalAnswer 재생성을 금지하므로, **이미 만들어진 FinalAnswer에는 영영 매핑을 붙일 수 없다.**

즉 **이 기능을 넣기로 결정하는 순간부터 생성되는 것만** 매핑을 갖는다. 기존 데이터는 영구히 매핑이 없다. **이 결정을 미룰수록 매핑 없는 데이터가 쌓인다.**

| 좌초 복구 (timeout 회수·재구독) | 안정화 |
| BYOK 키 입력·검증·마스킹 UI | SPEC-SETTINGS-001 (미작성) |
