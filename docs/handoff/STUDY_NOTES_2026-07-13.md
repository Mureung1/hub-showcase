## 1. 신뢰성 버그 — 왜 중요한가

우리 최종 목표는 "MBTI가 학습을 개선하는가"를 **데이터로 검증**하는 것이다. 그런데 계산 자체가 들쭉날쭉하면 어떤 데이터도 못 믿는다. 그래서 토대부터 고쳤다.

### (a) 점수가 "응답 순서"에 따라 달라지던 버그

- **무엇이 문제였나:** 점수를 만들 때 각 답변의 가감점을 더할 때마다 **매번 0~100으로 잘라냈다(clamp)**. 그래서 같은 답이라도 처리 순서에 따라 중간에 100에서 잘리고 나면 최종값이 달라졌다.
  - 예: `50 +4 +4 +16 -4 +16 +16` 을 하나씩 자르면, 중간에 100에 걸린 뒤 마지막 `-4`가 적용돼 96이 되지만, 순서가 다르면 100이 나온다.
- **어떻게 고쳤나:** **모든 가감점을 먼저 다 더한 뒤, 마지막에 딱 한 번만** 0~100으로 자른다. 덧셈은 순서를 바꿔도 결과가 같으므로(교환법칙) 이제 순서와 무관하게 항상 같은 값.
- **얼마나 있었나:** 가능한 19,683개 설문 조합을 전수 검사했더니 이전엔 729개(3.7%)에서 값이 흔들렸는데, 수정 후 **0개**.
- **버전 표기:** 계산 의미가 바뀌었으니 알고리즘 버전을 `rules-v2 → rules-v3`로 올렸다(옛 데이터와 섞지 않기 위해).

> 개념 용어: **결정론(determinism)** = 같은 입력이면 항상 같은 출력. 연구·재현성의 기본.

### (b) 결과 ID가 답을 바꿔도 그대로여서 피드백이 엉키던 문제

- **무엇이 문제였나:** 사용자가 뒤로 가 답을 바꿔도 같은 `resultId`를 재사용해서, **이전 결과에 대한 평가가 바뀐 결과에 붙는** 오염이 생길 수 있었다. 또 생성 시각(`createdAt`)이 저장할 때마다 새로 찍혀 의미가 없었다.
- **어떻게 고쳤나:** 입력을 요약한 **지문(fingerprint)** 을 만들어, 입력이 바뀌면 **새 결과로 보고 새 ID·새 생성시각**을 발급한다. 입력이 그대로면 재저장하지 않아 `createdAt`이 안정적으로 유지된다. `updatedAt`(수정시각)은 따로 둔다.

> 개념 용어: **immutable snapshot(불변 스냅샷)** = 한 번 만든 결과는 바꾸지 않고, 바뀌면 새 것으로 만든다.

### (c) 자잘한 정직화

- 화면의 `task/state-only` → **"행동·상태 기반 기준(baseline)"** 으로 정정(우리는 실제 "과제" 입력을 아직 안 받으므로 정직한 이름).
- `confidence`(신뢰도로 오해 소지) → `signalStrength`(신호 세기).
- 루틴 카드의 "예상 시간"이 실제 단계 합계와 안 맞던 것 → **단계 합계로 자동 계산**해 일치.
- 안 쓰는 파일 2개 삭제.

## 2. 메타인지 보정 루프 — 논문이 강하게 지지한 신기능

### 왜 넣었나 (근거)

여러 논문이 한 방향으로 모인다: **학습자는 자기가 안다고 과신하고(지식 착각), 인출연습(스스로 떠올리기)이 이 판단의 정확도를 높인다.**
- 재학습(다시 읽기)은 방금 봐서 머리에 남아 있어 **과신**을 부른다.
- 정답을 보면서 복습하면 "안다는 착각"이 커진다 → **정답을 가리고 먼저 떠올리는 게 낫다.**

### 무엇을 만들었나

실천 카드 뒤에 1분짜리 자기점검을 넣었다:
1. **예측** — 자료를 덮고 "핵심 3개 중 몇 개 떠올릴 수 있을까?"
2. **회상** — 자료 없이 실제로 떠올려 개수 입력
3. **대조** — 예측 − 실제 = **보정 오차**를 기록

- 이건 **점수·능력 판정이 아니라** 한 세션의 자기 점검이다.
- 만족도(적합감 등)와 **다른 저장 공간**에 따로 넣는다 → 아래 원칙 P-A 때문.

> 개념 용어: **메타인지(metacognition)** = 내가 무엇을 알고 모르는지 아는 능력. **보정(calibration)** = 내 예측과 실제가 얼마나 맞는지.

## 3. 오늘 배운 핵심 연구 결론 (프로젝트 원칙으로 박음)

- **P-A. 만족도 ≠ 정확도 ≠ 학습효과.** "마음에 든다"와 "실제로 배웠다"는 다르다. 세 층을 절대 한 숫자로 합치지 않는다.
- **P-B. 선호 ≠ 효과 (learning-styles 신화).** "내 유형/선호에 맞춘 방법이 더 효과적"이라는 주장은 국제적으로 **근거가 없다**(Pashler 2008). 오히려 성적 상위권은 유형과 무관하게 **자기조절·약점 보완** 학습을 한다(이선아·변호승 2020).
- **P-C. 빅데이터 ≠ 타당도.** 데이터가 많다고 정확해지지 않는다. 측정도구·비교군·결과변수·분석계획이 정확도를 만든다.

### 근거로 가장 강한 학습법 (Dunlosky 2013 등)
- **최고 효용: 연습시험(인출연습), 분산학습.** ← 우리 추천 1순위.
- 밑줄·다시읽기·요약은 효용 낮음.
- 단, 인출연습이 재학습보다 낫다는 건 확실하지만 "모든 다른 능동 전략보다 낫다"는 건 아직 미확정(정직하게 표기).

### AI 확장 힌트 (Huang 2025, FSRS)
- 간격 반복을 개인 망각곡선에 맞춰 스케줄하는 건 이미 오픈소스가 있다(**FSRS**, Anki에 탑재). 우리 "AI가 일정 짜주기" 목표의 참고 경로. 단 지금 MVP는 규칙 기반 localStorage.

## 4. 디자인 개편 — 어떻게 만들었나

- **디자인 토큰**이란: 색·폰트·모서리 값을 `--primary`, `--bg` 같은 **변수**로 한 곳에 정의하고 화면 전체가 그걸 참조하는 방식. 그래서 변수 값만 바꾸면 전체 톤이 한 번에 바뀐다.
- 오늘 바꾼 값: 배경을 **크림**(`#f8f2e3`)으로, 강조색을 **블루**로, 제목 폰트를 **세리프(Bookman→Georgia 폴백)**, 악센트를 **스크립트(Snell/Brush)** 로. 페이지 둘레에 **블루 프레임**을 둘렀다.
- 폰트 주의: `Bookman Old Style`이 기기에 있으면 그대로, 없으면 Georgia 세리프로 대체된다. 완전히 고정하려면 폰트 파일을 프로젝트에 넣어야 한다(다음 작업 후보).

## 용어 미니사전

| 용어 | 뜻 |
|---|---|
| 인출연습(retrieval practice) | 보지 않고 스스로 떠올려 답하기 |
| 시험효과(testing effect) | 시험(인출)이 다시 읽기보다 기억을 더 키우는 현상 |
| 전방효과 | 시험을 본 뒤 **새로 배우는 내용**까지 더 잘 배우는 것 |
| 분산학습(spacing) | 몰아서가 아니라 나눠서·간격 두고 복습 |
| 메타인지 | 내가 아는지/모르는지 아는 능력 |
| 과신(overconfidence)·지식 착각 | 실제보다 많이 안다고 느끼는 것 |
| learning-styles 신화 | "선호 방식에 맞추면 더 배운다"는 근거 없는 통념 |
| 결정론 | 같은 입력→항상 같은 출력 |
| NMAR | 응답 안 한 게 무작위가 아닐 수 있음(만족한 사람만 응답 등) |
| 디자인 토큰 | 색·폰트를 변수로 관리해 한 번에 바꾸는 방식 |
