## 2. 고친 결함 (둘 다 재현 → 수정 → 재현으로 검증)

### 🔴 `/api/health` 만 try/catch 가 없었다 → 프로세스 크래시

`backend/src/index.js` — `/api/results`(POST/GET/DELETE)와 `/api/analysis`는 전부 try/catch로 502를 반환하는데 **health만 빠져 있었다.** Express 4는 async 핸들러의 rejection을 잡지 않고, Node는 그때 프로세스를 종료한다. Supabase가 7일 휴면에 들어가면 `countAll()`이 throw → **프로세스 종료 → Render `Exited with status 1` → 502.**

하필 Render가 주기적으로 찌르는 경로라 가장 먼저 터진다.

| | 수정 전 | 수정 후 |
|---|---|---|
| 잘못된 `SUPABASE_URL` + health 1회 | `Error: supabase count: TypeError: fetch failed` → **프로세스 종료**, HTTP `000` | `503 degraded` 응답, **프로세스 생존**(2회 연속 호출 정상) |

같이 넣은 것: 404 핸들러, 전역 에러 미들웨어, `unhandledRejection`·`uncaughtException` 로깅 핸들러(무료 티어는 자동 재시작이 없어 프로세스 종료가 곧 서비스 중단이다).

**부수 효과**: `store.js`의 폴백은 import 실패만 잡으므로 `backend:"supabase"`라는 값이 연결 성공을 보증하지 못한다. 이제 **배포 판정은 `status` 로 한다.**

### 🔴 LLM 타임아웃 시 다음 모델을 시도조차 하지 않았다

`backend/src/lib/llm.js` — `gemini-flash-latest`는 구조화 출력에서 **6~8초가 기본**이라 입력이 조금만 길면 `CALL_TIMEOUT_MS`(12초)를 넘긴다(실측 **12,025ms**). 그런데 타임아웃 오류에는 `status`가 없어서 `isRetriable()`이 false였고, **실측 1.5초로 훨씬 빠른 `gemini-flash-lite-latest`를 시도조차 하지 않고** 규칙 폴백으로 떨어졌다.

수정: `isRetriable()`이 `llm_timeout`도 재시도 대상으로 본다. `MODEL_CHAIN` 길이만큼만 도니 무한루프는 없다. 상한을 늘리는 대신 이 방향을 택한 이유는 **느린 모델을 더 기다리는 것보다 빠른 모델로 넘어가는 게 사용자 대기시간이 짧아서**다. 실패 경로에 `console.warn`도 추가했다 — 전에는 LLM이 죽어도 Render 로그에 아무것도 남지 않았다.

검증: `CALL_TIMEOUT_MS`를 3초로 낮춘 사본으로 강제 재현 → 첫 모델 타임아웃 로그 후 **두 번째 모델로 폴백해 4.6초에 INTJ 정상 응답.**

### 🟡 프런트: 대기 상태·타임아웃이 없었다

`useServerSync.js`·`lib/api.js`·`ProjectIntro.jsx` — 콜드스타트 실측 **15.4초** 동안 화면 반응이 0이었고 버튼이 계속 눌려 중복 저장이 가능했다. `fetch`에는 타임아웃이 없어 백엔드가 죽으면 무한 대기했다.

- 저장·조회·삭제에 `pending` 상태(진행 중 재호출 차단) + "저장 중…"·"삭제 중…" 라벨 + "서버가 잠들어 있으면 첫 응답까지 최대 1분" 안내
- `AbortController` 타임아웃(기본 20초, health·mbti-chat 60초)
- 앱 진입 시 health 워밍업 1회(실패 무시)

## 3. 검증을 5레벨로 체계화했다

`docs/verification-levels.md` 신설. **단위 테스트만으로는 배포된 서비스가 동작한다고 말할 수 없다**는 것이 오늘의 교훈이다 — 위 두 결함 모두 L1이 전부 통과하는 상태에서 살아 있었고, 각각 L5(장애 주입)와 L3(외부 연동 실호출)에서 잡혔다.

| 레벨 | 오늘 결과 |
|---|---|
| L1 단위 | 22개 통과 |
| L2 API 계약 | **로컬 14/14, 배포 백엔드 14/14** — 화이트리스트·CORS 차단 포함 |
| L3 외부 LLM 실호출 | 실제 왕복 6.3/7.1/8.1초 · 보충 모드가 확정 유형 유지 · 하드룰 금칙어 0 · **결함 1건 발견** |
| L4 브라우저 흐름 | 전 구간 완주 · 콘솔 에러 0 · AI 채팅 실호출 200 · pending UI 확인 |
| L5 장애 주입 | DB 다운→503 생존 · 30초 지연→20초 타임아웃 복구 · 백엔드 정지→앱 완주 · LLM 타임아웃→모델 폴백 |

`scripts/verify-api-contract.sh`(= `npm run verify:api`)로 L2를 언제든 재실행할 수 있다. `BASE`·`ORIGIN`을 넘기면 배포 대상도 검사한다.

### 자동 녹화 파이프라인

사람이 화면을 조작하지 않고 **CDP로 배포된 앱을 대본 타이밍에 맞춰 자동 조작**하며 만들었다. 스크래치패드에 있고 커밋하지 않았다(`scratchpad/demo/`).

- `record.mjs` — SRT의 큐 시각을 그대로 타임라인으로 삼아 클릭·스크롤을 배치한다. 자막과 화면이 어긋날 수 없는 구조다
- `overlay.mjs` — **자막과 가짜 마우스 커서를 페이지에 주입**한다. CDP는 이벤트만 주입하고 커서를 그리지 않아서, 시청자가 조작을 따라갈 수 있도록 커서를 직접 그렸다
- `slides.html` — 터미널 로그·아키텍처·Agent 워크플로우는 브라우저로 찍을 수 없으므로 슬라이드로 만들었다. 크래시 로그는 **오늘 실제로 재현한 로그**를 그대로 썼다
- `cdp.mjs` — Node 24 전역 `WebSocket` 기반 최소 CDP 클라이언트(패키지 설치 없음)

> **자막을 ffmpeg으로 굽지 않고 브라우저가 그린다.** Homebrew의 ffmpeg 8.1.2 빌드에는 libass·freetype이 없어 `subtitles`·`drawtext` 필터를 못 쓴다. 브라우저가 그리면 한글 폰트 문제도 없고 스타일도 완전히 제어된다.

### 녹화하며 발견해 고친 것

| 회차 | 문제 | 원인·수정 |
|---|---|---|
| 1차 | 서버 저장 블록에 도달 못 함 | 실천 카드 화면에 **'이전' 버튼이 없고** 사이드바 진행 단계도 `<div>`라 클릭 불가 → 결과 화면 복귀 경로가 없다. **서버 저장을 계획·실천 카드보다 앞으로** 옮기고 SRT 큐 15~17 텍스트 재배치 |
| 2차 | 4축 탐색 신호 고지가 화면에 안 잡힘 | 셀렉터가 푸터 면책 문구에 먼저 걸려 BASELINE 화면에 머물렀다 → `h3` "4축 탐색 신호" 기준으로 카드를 잡고 **고지 문구가 그 카드 안에 있는지 스크립트가 직접 확인**하도록 검증을 넣음 |

> 교훈: **자동 녹화는 "클릭이 성공했는지"를 스크립트가 확인해야 한다.** 요소를 못 찾아도 조용히 지나가면 영상을 다 찍은 뒤에야 알게 된다.

### ⚠ 연구 데이터에 데모 레코드가 섞였다

녹화 때마다 결과 화면에서 "서버에 익명 저장"을 실제로 누르므로 **Supabase에 비식별 요약이 실제로 쌓인다.** `storedCount`가 4 → 5 → 6으로 늘었고, 이 중 **파일럿이 아닌 데모 레코드가 2건**이다.

- 이건 의도한 동작이다 — 그래야 영상에서 `storedCount` 증가를 진짜 증거로 보여줄 수 있다
- 다만 **파일럿 분석에 쓰기 전에 이 2건을 걸러내야 한다.** 녹화용 Chrome 프로필마다 `hub-anon-id`가 새로 생성되므로, 프로필을 지우면 해당 레코드를 API로 삭제할 수 없다
- 다음에 녹화할 때는 **프로필을 지우기 전에 `hub-anon-id`를 기록**하고 `DELETE /api/results?anonId=…`로 정리할 것

## 5. 남은 것 / 다음 착수점

1. **Render 환경변수에 LLM 키가 없다.** 배포 백엔드가 `/api/mbti-chat`에 `available:false`를 반환한다 — AI 근거 보충 기능이 배포에서 꺼져 있다. `showcase.json` techStack에는 "Gemini API"가 들어 있다. 폴백은 정상이라 사용자 흐름은 끊기지 않는다. **대시보드에서 사용자가 직접 추가해야 한다**(키 값은 채팅·문서·커밋에 남기지 않는다).
2. **영상 업로드 후 `showcase.json`에 `demoVideoUrl` 추가.** 스키마상 `^$|^https://` 패턴이라 로컬 경로는 넣을 수 없다. 업로드 플랫폼·시점은 사용자 판단.
3. **가명 ID 잔존 건 결정** — ADR로 남길 것.
4. AI 호출 상한(신규 이슈) · 모바일·접근성 점검 · 파일럿 관찰 요약.

## 6. 하드룰 (바뀐 것만)

- **배포 성공 판정은 `/api/health`의 `status`로 한다.** `backend:"supabase"`라는 값만으로는 연결 성공을 보증하지 못한다(§2 참조). `degraded`면 실패다.
- **배포 반영은 번들 파일명 해시로 판단하지 않는다.** Vercel이 자체 환경에서 다시 빌드해 해시가 달라진다(로컬 `index-CYB5A6Ln.js` vs 배포 `index-D0j9Z8q8.js`, 내용·크기 동일). 내용(문자열·크기)으로 확인한다.
- **`docs/prompt-guide.md`의 Review Prompt가 여전히 "외부 AI API가 들어가지 않았는지 확인"이라고 되어 있다.** ADR-008 이후 `/api/mbti-chat` + Gemini는 정식 허용된 기능이다. 07-23·07-27에 이어 **오늘도 고치지 않았다** — 다음 세션에서 정정할 것.
