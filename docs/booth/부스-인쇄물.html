역할별로 나눠 쓴 서브에이전트

만능 도구 하나가 아니라, 국면마다 다른 역할로

계획 무엇을 · 어떤 순서로
  • planner작업 분해 · 우선순위
  • architect기술 선택 · 스키마
  • feature-slice시연 가능 단위로
구현 코드를 만든다
  • test-writer깨질 지점을 겨냥
  • debugger재현 → 격리 → 최소 수정
  • performance측정 없는 최적화 금지
점검 커밋 전에 걸러낸다
  • reviewer정확성 · 동시성
  • security입력 · 비밀정보
  • docs문서와 코드 불일치
학습 남의 코드로 두지 않기
  • code-tutor개념 단위로 이해
  • tutor-explorer실행 흐름 추적
  • tutor-scribe학습 상태 기록

계획·점검 에이전트는 읽기 전용 권한 — 실수로도 코드를 바꾸지 못하게 도구를 제한했다. planner(무엇을)와 architect(어떻게)를 나눈 것이 역할 분리의 핵심.
