# 발표 대본 — Core Loop Builder (10분 내외)

처음 보는 사람도 이해할 수 있게: 문제 → 서비스 → 작업 과정 → 시연 → 마무리 순서로 말한다. 슬라이드는 아직 없고, 이 문서를 그대로 읽으며 연습하는 대본이다. 시연은 `prototype/index.html`을 브라우저로 직접 열어서 진행한다.

**구간별 목표 시간**: 오프닝 2분 · 서비스 소개 1.5분 · 작업 과정 2분 · 시연 2.5분 · 마무리 2분 (총 10분)

## 대본

게임 기획자를 꿈꾸는 대학생이 가장 먼저 막히는 지점이 뭘까요? 아이디어가 없어서가 아닙니다. 아이디어는 다들 있어요. 문제는 그 아이디어를 플레이어가 반복하게 될 행동으로 구체화하는 부분입니다.

게임 개발에서 가장 기본이 되는 개념이 **코어 루프**입니다. 플레이어가 게임 안에서 반복하게 되는 핵심 행동의 흐름이에요. 전투해서 보상을 얻고, 그 보상으로 성장하고, 더 강한 도전에 나서고, 다시 반복하는 흐름 같은 거죠.

그런데 이 코어 루프는 게임 하나에 하나만 있는 게 아닙니다. Slay the Spire를 예로 들면, 카드 한 장을 내고 효과를 보는 건 몇 초짜리 아주 작은 루프입니다. 전투 하나에 들어가서 적을 처치하고 보상을 고르는 건 몇 분짜리 조금 더 큰 루프고요. 그 전투를 여러 번 거쳐 보스까지 가고, 지더라도 성장 자원이 남아 다음 판에 다시 도전하게 만드는 건 훨씬 더 큰 루프입니다. 작은 것부터 큰 것까지 여러 겹의 루프가 쌓여서 게임 하나를 만드는 거예요.

게임 기획을 준비하는 학생들은 장르는 떠오르는데 이 반복 행동을 정의하기 어렵고, 참고하고 싶은 게임은 있는데 그 재미 구조를 자기 기획으로 옮기기 어렵다는 문제를 겪습니다. 저도 직접 겪은 문제라서, 이걸 AI Agent와 함께 풀어주는 서비스를 4주간 만들고 있습니다.

**Core Loop Builder**는 장르와 참고 게임을 입력하면, AI가 코어 루프 후보를 같이 브레인스토밍하고, 그걸 시각화하고, 포트폴리오용 기획 초안까지 만들어주는 서비스입니다. 방금 말씀드린 여러 크기의 루프 중에서 지금 저희가 다루는 건 '전투 하나' 정도 크기의 중간 루프 하나입니다. 더 작은 루프나 더 큰 루프까지 함께 설계하는 건 이번 4주 이후의 개선 방향으로 남겨뒀습니다.

이 서비스는 기획서를 대신 써주는 도구가 아니라, 기획자의 사고 과정을 단계별로 도와주는 파트너를 지향합니다. 그래서 하나의 거대한 AI 프롬프트가 아니라, Input, Genre Loop, Reference Analysis, Brainstorming, Loop Visualizer, Portfolio Writer, Critic까지 **7단계 Agent 파이프라인**으로 나눠서 작동합니다.

이 서비스를 만드는 과정 자체도 AI Agent, Claude Code와 함께 진행했습니다. 1주차에는 기획서를 확정하고, 서비스 소개 페이지를 만들고, 지금 보여드릴 핵심 흐름 프로토타입을 제작했습니다.

디자인은 glassmorphism에 게임감을 더하는 방향으로 잡았는데, 실제로 색상을 세 번 바꿨습니다. 처음엔 어두운 네온 콘솔 느낌으로 만들었다가 밝은 파스텔 톤으로 바꿨는데, "인스타그램 그라디언트 같다"는 피드백을 받고 블루-바이올렛-시안 쿨톤으로 다시 다듬었어요. 이렇게 나온 판단 기준은 디자인 시스템 문서와 재사용 가능한 체크리스트로 남겼습니다.

개발 구조는 프론트엔드 React, 백엔드 Express로 나눴습니다. 비유하자면 React는 화면을 레고 블록처럼 조립하는 도구고, 여러분이 매일 쓰는 유튜브나 인스타그램 웹 버전도 비슷한 방식으로 만들어져 있습니다. Express는 그 화면이 보낸 요청을 받아 처리하는 창구 역할이고, 배달앱이나 당근마켓 같은 서비스 뒤편에도 비슷한 구조가 있어요. AI 두뇌 역할은 Claude API가 맡는데, 사실 이 발표 자료와 지금까지 보여드린 코드 자체도 Claude Code라는 AI 개발 도구와 함께 만들었습니다. LLM 키는 서버에서만 다루고 클라이언트에는 절대 노출하지 않는다는 규칙도 미리 정해뒀고, 2주차부터 4주차까지 할 일을 우선순위로 나눈 백로그도 미리 정리해서 개발 중 판단이 흔들리지 않게 준비했습니다.

지금부터 핵심 흐름을 프로토타입으로 보여드리겠습니다.

> **[입력 탭]** 장르, 참고 게임, 원하는 플레이 경험을 입력받습니다. 지금은 샘플 값이 채워져 있어요 — 로그라이크 덱빌딩 RPG, 참고 게임은 Slay the Spire와 Hades입니다. 밑에 보시면 AI가 이 입력을 어떻게 요약하는지도 보여줍니다.
>
> **[분석 탭]** 장르 기본 루프와 참고 게임의 반복 구조를 분석합니다. 이 게임이 왜 재밌는지를 반복 구조로 뜯어보는 단계입니다.
>
> **[후보 탭]** 코어 루프 후보 3개를 제안합니다. 하나의 정답이 아니라 여러 방향을 비교할 수 있게 하는 거고, 각 후보에 추천 점수도 같이 보여줍니다. 이 중 후보 B를 선택하겠습니다.
>
> **[루프 탭]** 선택한 루프를 원형 다이어그램으로 시각화합니다. 행동, 보상, 성장, 도전, 반복이 순환하는 구조예요. 아까 말씀드린 '전투 하나' 크기의 중간 루프가 바로 이겁니다. 막연했던 아이디어가 눈에 보이는 순환 구조가 된 거죠.
>
> **[초안 탭]** 선택된 루프를 바탕으로 포트폴리오용 기획 초안을 생성합니다. 게임 콘셉트, 기획 의도, 주요 시스템까지 포트폴리오에 바로 붙일 수 있는 형태로 나옵니다.
>
> **[피드백 탭]** 마지막으로 AI가 루프의 강점과 주의점, 개선 제안을 피드백합니다. 결과만 주고 끝나는 게 아니라 다시 검토할 거리를 던져주는 거죠.

지금 보신 건 흐름을 검증하기 위한 정적 프로토타입입니다. 2주차부터는 이 흐름을 실제 Claude API로 동작하게 만드는 게 목표입니다.

구체적으로, 2주차는 입력부터 후보 생성까지를 실제 Claude API로 동작하게 만드는 주입니다. API 키는 서버에만 두고, 장르 분석과 참고 게임 분석을 각각 맡는 함수 두 개를 만들어서 후보 생성 API 하나로 합칩니다.

여기서 신경 쓰는 부분이 하나 있습니다. 그냥 챗지피티 창에 물어보는 것과 다르려면 프롬프트 자체를 다르게 짜야 한다는 겁니다. 좋은 코어 루프 예시를 프롬프트에 미리 넣어서 구체적인 흐름으로 답하도록 유도하고, 자유 텍스트가 아니라 제목과 단계, 태그가 채워진 정해진 형식으로만 답하게 강제하고, 사용자가 입력한 원하는 플레이 경험을 각 후보가 어떻게 만족하는지 명시하게 만듭니다. 그래서 일반적인 장르 조언이 아니라 이 사용자 조건에 실제로 묶인 답을 받으려고 합니다.

3주차는 시각화와 기획 초안, AI 피드백까지 완성하는 주고, 4주차는 실제 사용자 3명 이상에게 테스트를 받고 피드백을 반영한 뒤 배포와 발표 준비로 마무리합니다.

코어 루프는 게임 기획에서 가장 작지만 가장 중요한 질문에 답합니다 — 플레이어는 무엇을 반복하고, 왜 다시 하게 되는가. Core Loop Builder는 이 질문에 대한 답을 AI와 함께 찾아가는 도구입니다. 감사합니다.

## 예상 질문 대비 메모

발표 본문에서 다루지 않은, 추가로 나올 수 있는 질문에 대한 답변이다.

- **"MVP 범위를 왜 이렇게 잡았나?"** — 4주 안에 "코어 루프 설계 사고 과정을 AI가 얼마나 잘 도와주는가"를 보여주는 게 핵심이라, 로그인/결제/데이터 수집처럼 핵심과 무관한 기능은 전부 제외했다(`project-plan.md` 10번 참고).
- **"AI Agent 구조를 왜 7단계로 나눴나?"** — 하나의 거대 프롬프트로 모든 걸 처리하면 결과를 검증하거나 특정 단계만 다시 실행하기 어렵다. 단계별로 나누면 각 Agent의 책임이 분명해지고, 나중에 특정 단계만 따로 개선할 수 있다.
- **"참고 게임 분석이 부정확하면 어떻게 하나?"** — 사용자가 게임 설명을 직접 보완할 수 있고, 결과를 그대로 확정하는 게 아니라 수정 가능한 초안으로 제공한다(`project-plan.md` 17번 리스크 대응).
- **"디자인은 왜 glassmorphism + 게임감인가?"** — 사용자가 게임 기획자를 꿈꾸는 사람이라, 서비스 자체도 "게임을 설계하는 도구"라는 느낌을 주고 싶었다. 장식적 게임 클리셰 대신 진행바·배지 같은 "성취" 모티프로만 절제해서 표현했다.
- **"여러 크기의 루프를 왜 다 안 다루나?"** — micro/macro loop까지 같이 다루면 화면과 데이터 모델이 훨씬 복잡해진다. 4주 MVP는 meso loop 하나를 잘 설계하는 경험에 집중하고, 나머지는 `docs/BACKLOG.md`의 P2 항목으로 남겨뒀다.
