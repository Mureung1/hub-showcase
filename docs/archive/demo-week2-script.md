## 2. 이번 주에 한 것 + 목차 (25초)

순서는 구조랑 코드 먼저 보고, 데모 돌리고, 다음 계획으로 마무리할게요.

## 3. 전체 구조 (70초)

구조는 다들 비슷할 텐데, Express가 실제로 뭘 하는지는 짚고 갈게요. 저도 처음이라 이걸 이해하는 데 시간이 걸렸어요.

Express로 서버를 만든다는 건, **3001번 포트에서 계속 대기하면서 요청을 기다리는 프로그램**을 하나 띄우는 거예요. 코드로는 `app.listen(3001)` 한 줄이고, `npm run dev` 하면 이 프로그램이 떠서 꺼질 때까지 계속 돌아요. 화면 쪽 5173이랑 서버 쪽 3001, 프로그램 두 개가 동시에 도는 거예요.

이 서버 프로그램이 하는 일은 세 가지예요.

첫째, 요청이 오면 **주소를 보고 담당 함수로 연결**해요. `/api/checkins`로 시작하면 체크인 담당 라우터로 넘기는 식으로요. 우체국에서 주소 보고 분류하는 거랑 같아요.

둘째, **들어온 데이터를 풀어줘요.** 네트워크로 오는 요청 본문은 사실 그냥 글자 덩어리예요. `express.json()` 한 줄을 등록해두면 이걸 자동으로 자바스크립트 객체로 바꿔줘서, 함수 안에서 `req.body.rawText`처럼 바로 꺼내 쓸 수 있어요.

셋째, **에러를 한 곳에 모아요.** 어느 함수에서 에러가 나든 마지막에 에러 처리기 하나로 모여서, 항상 `error.message` 같은 동일한 형식으로 응답해요. 화면 입장에선 실패 응답 모양이 늘 똑같으니까 에러 표시 코드를 한 번만 짜면 돼요.

DB는 Supabase 썼어요. 클라우드에 있는 DB 서비스고, 엑셀처럼 표에 행이 쌓인다고 보면 돼요. 표는 checkins 하나만 만들었어요.

## 4. 코드로 보면 (70초)

저장 버튼 하나 누르면 실제로 어떤 코드가 도는지 세 파일로 정리해봤어요. 나중에 서로 코드 볼 때 참고되라고요.

왼쪽이 화면 코드예요. `/api/checkins` 주소로 POST 방식으로 입력 내용을 보내요. POST는 소포 같은 거예요. GET이 "달라"고만 하는 엽서라면, POST는 body라는 상자에 데이터를 실어 보내는 소포예요. `JSON.stringify`는 그 상자에 넣기 좋게 자바스크립트 데이터를 전송용 글자로 바꾸는 함수고요. 보내고 나서 응답이 올 때까지 기다렸다가, 받은 결과를 목록 맨 위에 끼워 넣어요. 그래서 저장하면 화면이 바로 갱신돼요.

가운데가 방금 말한 Express예요. `router.post('주소', 함수)` — 이 한 덩어리가 API 하나예요. "이 주소로 POST가 오면 이 함수를 실행해라"는 등록이에요. API 만든다는 게 별게 아니라 주소랑 함수를 짝지어주는 거였어요. 함수 안을 보면 순서가 있어요. 먼저 빈 입력인지 검사하고, 통과하면 저장을 시키고, 마지막에 `res.status(201)`로 응답해요. 201은 "새로 만들었다"는 뜻의 성공 번호예요.

오른쪽이 DB 코드인데, 파일을 하나 더 나눠놨어요. 라우터는 접수창구만 하고, 실제 DB 작업은 서비스 파일이 해요. `from`으로 테이블 고르고, `insert`로 행을 추가하고, `select().single()`로 방금 넣은 행을 되돌려받아요. 그걸 그대로 화면에 응답으로 보내는 거예요.

정리하면 세 파일이 릴레이로 돌아요. 화면은 요청만, 라우터는 확인과 전달만, 서비스는 DB 작업만.

## 5. 만든 API 4개 (40초)

제가 만든 API는 이 4개예요.

하나 공유하고 싶은 설계가 있는데, **정리하기랑 저장을 일부러 분리**했어요. 정리하기는 preview라는 주소로 가서 AI 정리만 하고 저장은 안 해요. 왜냐면 AI 결과를 사용자가 고칠 기회를 주고 싶었거든요. 고친 다음에 저장 버튼을 눌러야 그때 진짜 저장 API가 호출돼요. 버튼 하나에 다 몰아넣었으면 수정 기능이 안 나왔을 거예요.

그리고 표에서 보이는 것처럼 `/api/checkins` 주소가 두 번 나와요. GET이면 조회, POST면 저장. 주소가 같아도 방식이 다르면 다른 API더라고요. GET은 "달라", POST는 "받아줘"예요.

## 6~8. 데모 (2분 20초)

실제 화면으로 볼게요.

(브라우저 localhost:5173으로 전환)

**입력.** 오늘 하루를 한두 문장 적어요.

(입력 예시: "오늘 처음 보는 도구가 많아서 계속 막혔다. 그래도 하나씩 확인하면서 여기까지 진행했다.")

참고로 입력을 다 지우면 버튼이 죽어요. 근데 화면 검사는 개발자 도구로 우회할 수 있어서, 서버가 한 번 더 검사해서 빈 값이면 400으로 거절해요. 검증은 서버가 최종이에요.

**정리하기 클릭.** 지금 서버 거쳐서 AI 다녀오는 중이에요.

(결과 카드 3장 뜨면)

여기가 제 주제에서 제일 신경 쓴 부분이에요. 감정 얘기다 보니 AI가 위로하거나 조언하기 시작하면 이상해지거든요. 그래서 **항상 이 세 카드로만 답하게 세 겹으로 강제**했어요.

첫째, 시스템 프롬프트에 규칙을 박았어요. "상담, 진단, 위로 금지. emotion, cause, action 세 문자열만 가진 JSON으로만 답해라."

둘째, AI 호출 옵션에 `response_format: json_object`를 줬어요. 자유 문장 말고 JSON만 뱉게 하는 옵션이 있더라고요.

셋째, 그래도 못 믿어서 서버가 응답을 검사해요. JSON으로 파싱해보고, 세 필드가 다 있는지, 빈 값은 아닌지 확인해요. 하나라도 틀리면 한 번 재시도하고, 그래도 안 되면 mock이라는 임시 결과로 대체해요.

오른쪽 위 배지가 그 표시예요. 지금 "Vertex AI로 정리됨"이라고 떠 있는데, AI가 죽으면 여기가 mock으로 바뀌고 데모는 계속 돌아가요. 발표 중에 AI 서버 끊겨도 안 망하는 거라, 이 fallback은 다들 써먹을 수 있을 것 같아요.

AI는 Vertex Gemini 썼어요. 거창한 이유는 아니고 GCP 가입할 때 3개월 크레딧이 생겨서, 그거 써보려고 공부해서 붙였어요.

**카드 수정.** AI 결과가 마음에 안 들면 저장 전에 직접 고칠 수 있어요. 감정은 본인이 제일 잘 아니까요.

(감정 카드 살짝 수정)

**저장 클릭.** 목록 맨 위에 방금 기록이 올라왔죠. 방금 고친 내용 그대로 저장된 것도 보이고요. 서버가 "사용자가 고친 값이 있으면 AI 재생성 안 하고 그대로 저장"하게 돼 있어요.

**새로고침.** (F5) 그대로 있어요. 화면에 임시로 있던 게 아니라 DB에 들어갔다는 뜻이에요. 목록이 항상 최신순인 건 조회할 때 `created_at` 기준으로 정렬해서 가져오기 때문이고요. 카드 누르면 그날 기록 상세도 보여요.

(슬라이드로 복귀)

## 예상 질문 대비

- **"API를 어떻게 만들었어?"** → Express에서 `router.post('주소', 함수)`. 주소랑 처리 함수를 짝지어주는 건데, 이런 걸 4개 썼어.
- **"DB 저장은 어떻게 해?"** → 서버에서 `from('checkins').insert(...)` 호출하면 테이블에 행이 추가돼. SQL의 INSERT랑 같은 거.
- **"AI한테 JSON 어떻게 강제해?"** → 세 겹. 프롬프트에 규칙 명시 + 호출 옵션 `response_format: json_object` + 서버에서 파싱·필드 검사. 검사 실패하면 재시도 1번, 그래도 안 되면 mock.
- **"왜 화면에서 DB로 바로 안 쓰고 서버를 거쳐?"** → DB 비밀키를 브라우저에 두면 누구나 볼 수 있어서. 키는 서버에만 있고 화면은 서버한테 부탁만 해.
- **"preview랑 저장을 왜 나눴어?"** → AI 결과를 사용자가 고칠 기회를 주려고. 정리는 미리보기, 확정은 저장.
- **"3001, 5173 포트가 뭐야?"** → 한 컴퓨터 안에서 프로그램마다 나눠 갖는 문 번호. IP가 건물 주소면 포트는 호수. 5173은 Vite 기본값이고, 3001은 코드에서 정한 거야(프론트 3000번대 옆에 API 두는 관례).
- **"GET이랑 POST 차이가 뭐야?"** → 요청의 방식. GET은 엽서처럼 "달라"고만 하는 거고(내용물 없음), POST는 소포처럼 body에 데이터를 실어 보내는 거야. 같은 주소여도 방식이 다르면 서버가 다른 함수를 실행해.
- **"이거 나도 접속해서 써볼 수 있어?"** → 지금은 안 돼. localhost는 내 컴퓨터 전용이라 밖에서 못 들어와. 남들이 쓰려면 배포를 해야 하는데 그건 뒤 주차 범위야. 단 DB(Supabase)는 이미 클라우드라 데이터는 내 컴퓨터 꺼도 남아 있어.
