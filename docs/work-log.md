### Agent에게 요청한 것
"데모에 꼭 필요한데 아직 안 되는 기능"을 고르라는 미션 요구사항에 따라,
`docs/backlog.md`에 이미 적어뒀던 gap — "Episodes 사이드바가 실제 messages
테이블과 연결 안 됨, 여전히 mock 데이터" — 를 실제 데이터에 연결해달라고 요청.

### 검토하고 적용한 것
- Agent가 제안한 방식: 메시지를 시간 간격(30분) 기준으로 묶어서 "episode"처럼
  보여주는 순수 함수(`groupMessagesIntoEpisodes`)를 TDD로 먼저 만들고, 그
  결과를 Episodes 사이드바가 쓰게 바꾸는 구조.
- 테스트 시나리오 6개(빈 배열, 30분 이내 묶임, 30분 초과 분리, 최신이 위로,
  24시간 기준 recent/history 구분, 잠긴 메시지가 있으면 episode 전체가
  submerged)를 먼저 검토해서 빠진 케이스 없는지 확인한 뒤 구현을 진행시켰다.
- `App.jsx`가 `messages` state를 들고 있다가 `Episodes`/`ChatView`에 내려주는
  구조 변경도 검토 — 기존엔 `ChatView`가 혼자 fetch하고 있었는데, 사이드바도
  같은 데이터를 봐야 해서 위로 올리는 게 맞다고 판단해 승인했다.
