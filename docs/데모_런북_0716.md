# 데모 런북 — Phase 1~3 발표 (5분: 슬라이드 2분 + 라이브 데모 3분)

> 이 문서는 발표 당일 그대로 따라 하는 실행 순서다. 모든 명령어는 이번 세션에서 실제로
> 성공한 것을 그대로 옮겼다 (한 번 실증된 경로 — 발표 중 실패 리스크가 낮음).
> 슬라이드: [`WeatherPilot_데모발표_0716.pptx`](./WeatherPilot_데모발표_0716.pptx)

## 0. 발표 시작 전 (미리 준비, 발표 5~10분 전)

1. **Solapi 키 확인** — 채팅에 노출됐던 키를 재발급했다면 `apps/server/.env`의
   `SOLAPI_API_KEY`·`SOLAPI_API_SECRET` 값을 새 값으로 갱신.
2. **서버 기동** (리포 루트에서):
   ```bash
   npx tsx --env-file=apps/server/.env apps/server/src/index.ts
   ```
3. **웹 실연동 전환** — `apps/web/.env.local` 파일 생성:
   ```
   VITE_MOCK_MODE=false
   ```
   그 다음 웹 기동:
   ```bash
   npm run dev --workspace web
   ```
4. **기동 확인**:
   ```bash
   curl http://localhost:4000/health
   ```
   `{"ok":true,...}` 나오면 정상.
5. **브라우저 탭 2개 준비**
   - 탭 A: 우리 앱 `http://localhost:5173`
   - 탭 B: 네이버에서 "부산 서면 날씨" 검색 결과 (또는 기상청 홈페이지)
6. **오늘 제안 미리 생성** (라이브 중 LLM 대기시간 없애기 위해 미리 1회 호출):
   ```bash
   curl -X POST http://localhost:4000/proposal/generate -H "Content-Type: application/json" -d '{}'
   ```
   응답의 `campaignId`를 메모해둔다 (아래 4단계 redeem에서 씀).

   > ⚠️ **야간(21:00~08:00) 발표라면**: 위 생성만 해두고, 발송(`/send`)은 **지금 미리 한 번
   > 실행**해서 문자를 미리 받아두자. 라이브 데모에서 "이대로 발송하기"를 누르면 서버가
   > 법적 필터상 야간이라 자동으로 **예약**으로 돌려버려 실시간 수신을 못 보여준다.
   > 이 경우 라이브에서는 "미리 온 문자"를 보여주는 방식으로 4단계를 진행한다.

## 1. 슬라이드 (2분)

`WeatherPilot_데모발표_0716.pptx` 1~6번 슬라이드 발표. (7번 마무리는 데모 후)

## 2. 라이브 데모 (3분)

### ① 날씨 일치 비교 (~30초)
- 탭 A(우리 앱)와 탭 B(네이버 날씨)를 나란히 띄운다.
- 우리 앱 대시보드 상단 카드의 **기온·하늘상태**를 짚으며 네이버 값과 비교.
- "기상청·OpenWeather N개 소스 평균" 배지를 짚어 여러 실제 API를 합친 것임을 강조.

### ② 대시보드 → 오늘 제안 (~40초)
- 0단계에서 미리 생성해둔 오늘 제안이 대시보드에 바로 떠 있다.
- "🤖 에이전트 추천" 카드의 실제 LLM 문구·프로모션(할인율)을 읽어준다.
- 강조 포인트: "이 문구는 저장된 mock이 아니라, 방금 실제 날씨+매출 진단을 보고 Groq가 생성한 것"

### ③ 검토 → 발송 (~60초)
- "제안 검토하기" 클릭 → 문구·채널 확인 → "이대로 발송하기" 클릭.
- (야간이라 이미 미리 보내둔 경우) 대신 폰에 와 있는 문자를 미리 꺼내 보여준다.
- 발송 완료 화면에서 **쿠폰 코드**를 확인하고, 본인 폰의 실제 `(광고) [김사장 카페] ...` 문자를 화면에 보여준다.
- 강조 포인트: "서버가 동의자만 걸러내고 (광고) 표기·수신거부 문구를 자동 삽입 — UI가 아니라 서버가 법을 강제"

### ④ 쿠폰 사용 → 추적 반영 (~30초)
- 발송 완료 화면에 뜬 쿠폰 코드로 redeem 호출 (터미널):
  ```bash
  curl -X POST http://localhost:4000/coupons/<발급된코드>/redeem \
    -H "Content-Type: application/json" -d '{"orderAmount":15000}'
  ```
- 화면 전환 없이 **추적 카드가 1초 폴링으로 즉시 갱신**되는 걸 보여준다 (사용 인원·귀속 매출 숫자 증가).
- 강조 포인트: "실시간처럼 보이지만 실제로는 쿠폰 코드 기반 누적 집계 — 정직하게 표기"

## 3. 마무리 슬라이드 (데모 후, ~10초)

`WeatherPilot_데모발표_0716.pptx` 7번 슬라이드로 전환, 요약 + Phase 4 계획 + 감사 인사.

## 4. 발표 후 정리

```bash
rm -f apps/web/.env.local   # mock 모드로 복귀
```
서버 프로세스 종료 (터미널 Ctrl+C 또는 프로세스 kill).

## 참고 — 사용한 엔드포인트 전체

| 메서드 | 경로 | 용도 |
|---|---|---|
| GET | `/health` | 서버 기동 확인 |
| GET | `/weather/today` | 오늘 앙상블 날씨 |
| POST | `/proposal/generate` | 오늘 제안 생성(LLM) |
| GET | `/proposal/today` | 오늘 제안 조회 (대시보드가 씀) |
| PATCH | `/campaigns/:id` | 승인·문구수정 |
| POST | `/campaigns/:id/send` | 발송(법적필터 통과 후 Solapi) |
| GET | `/campaigns/:id/tracking` | 쿠폰 사용·귀속매출 집계 |
| POST | `/coupons/:code/redeem` | 쿠폰 사용 처리 |
