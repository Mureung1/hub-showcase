# GameForge Agent — UI/UX 설계 문서

> 기존 [GameForge Agent 기획서](./GameForge_Agent.md)의 "13. React Dashboard" 항목을 구체화한 문서.
> 실제 프로토타입(`gameforge-agent-prototype.html`)에서 검증된 화면 흐름과 인터랙션을 기준으로 작성했다.

---

## 1. 전체 화면 흐름

```
Repository 연결
      ↓ (저장소 확인 → Branch/프리셋 활성화)
분석 범위 선택 (빠름 / 기본 / 상세)
      ↓
분석 리포트 열람 (Markdown)
      ↓ Approve
Agent 워크스페이스 (16단계 순차 진행)
```

---

## 2. Repository 연결 화면

> **v2 변경**: URL 직접 입력 + PAT 방식에서 **GitHub OAuth 로그인** 방식으로 전환.

### 흐름
- 로그인 전: **"GitHub로 로그인"** 버튼만 활성화, 저장소/브랜치/프리셋 영역은 모두 잠김
- 로그인 성공: GitHub 아바타 + 계정명 표시, 로그인한 계정이 접근 가능한 **저장소 목록**이 드롭다운(검색 가능)으로 채워짐
- 저장소 선택: 이미 로그인 단계에서 접근 권한이 검증된 목록이라 별도의 "저장소 확인" 버튼이 필요 없음. 선택 즉시 해당 저장소의 **Branch 목록**을 조회해 Branch select를 채운다
- Branch 선택: 분석 범위 프리셋 섹션이 활성화된다
- **"연결 및 분석 시작"** 버튼은 저장소+Branch가 모두 선택된 이후에만 활성화

### 핵심 규칙: 단계적 잠금(Progressive Lock) 패턴
로그인 → 저장소 선택 → Branch 선택 순으로 다음 단계가 열리는 구조는 유지한다. 다만 잠금이 풀리는 트리거가 "확인 버튼 클릭"에서 "로그인 완료 / 항목 선택"으로 바뀐다.

| 단계 | 잠긴 상태 | 풀리는 조건 |
|---|---|---|
| 저장소 선택 | 로그인 전 비활성화 | 로그인 성공 |
| Branch 선택 | 저장소 미선택 시 비활성화 | 저장소 선택 |
| 분석 프리셋 | Branch 미선택 시 비활성화 | Branch 선택 |
| 연결 및 분석 시작 | 위 항목 미완료 시 비활성화 | 저장소+Branch 모두 선택 |

### 분석 범위 프리셋
개별 항목 체크박스 대신, 3단계 프리셋으로 묶어 선택 부담을 줄인다.

| 프리셋 | 설명 | 소요 시간 |
|---|---|---|
| 빠름 | 핵심 의존성 구조만 스캔 | 약 30초 |
| 기본 (권장) | 의존성 + 중복 코드 탐지 | 약 2분 |
| 상세 | Prefab 구조 + 리팩토링 대상까지 전수 분석 | 약 5분+ |

## 3. 분석 리포트 화면

분석이 끝나면 바로 Markdown 리포트(`00_Analysis_Report.md`)를 열람한다.

- 상단에 핵심 지표를 통계 카드로 요약: 클래스 의존성 수 / 중복 코드 블록 수 / 리팩토링 대상 수
- 하단에 리포트 원문을 코드 블록 형태로 미리보기
- **원문 수정** 가능 (아래 5번 항목의 편집 패턴과 동일)
- **Approve하고 Requirements Agent로** 버튼 → 16단계 워크플로우 시작

## 4. Agent 워크스페이스

### 4.1 레이아웃
좌측 사이드바(고정) + 우측 메인 패널의 2단 구성.

**좌측 사이드바**
- 연결된 Repository / Branch 정보
- 16단계 전체 리스트, 각 단계마다:
  - 단계 번호 (2자리, 모노스페이스)
  - 단계 이름
  - 진행률 %

**단계 상태 3종**
| 상태 | 표시 색상 | 클릭 가능 여부 |
|---|---|---|
| 완료 (done) | teal | 가능 — 완료된 문서를 읽기 전용으로 재열람 |
| 진행 중 (active) | amber | 가능 — 현재 작업 중인 화면으로 이동 |
| 대기 (pending) | 회색(mute) | **불가** — 이전 단계 미완료 시 잠김, 툴팁 안내 |

> 워크플로우 순서를 건너뛸 수 없다는 원 기획서의 원칙("각 단계는 사용자의 승인 후 다음 단계로 진행")을 UI 레벨에서 강제한다.

### 4.2 16단계 목록 (변경됨)

기존 계획에서 **"테스트" 단계를 제거**하고, 8번 단계명을 **"리팩토링 및 코드 리뷰"**로 확장했다.

| # | 단계 |
|---|---|
| 1 | 요구사항 분석 |
| 2 | 게임 기획 |
| 3 | 게임 시스템 설계 |
| 4 | 클래스 설계 (UML) |
| 5 | 프로젝트 구조 설계 |
| 6 | ScriptableObject 설계 |
| 7 | 코드 생성 |
| 8 | ~~리팩토링~~ → **리팩토링 및 코드 리뷰** |
| 9 | ~~테스트~~ (제거됨) → **문서화** |

### 4.3 Agent와의 상호작용 — 채팅형 Q&A (변경됨)

**변경 전**: 질문마다 선택지 버튼(객관식)을 제공하는 Form 방식.
**변경 후**: 채팅 인터페이스로 자유 응답.

- Agent 질문과 사용자 답변이 말풍선으로 순서대로 쌓임 (Agent는 왼쪽, 답변은 오른쪽)
- 하단 텍스트 입력창 + 전송 버튼 (Enter 전송 지원)
- 상단에 `AGENT 이름 · 질문 N / 전체` 형태로 진행 상황 표시
- 답변 전송 시 "입력 중…" 상태를 짧게 보여준 뒤 다음 질문이 이어짐
- 준비된 질문을 모두 마치면 Agent가 "지금까지 내용으로 문서를 정리했다"는 안내와 함께 자연스럽게 아래 Markdown 미리보기·승인 단계로 연결

이 방식은 정해진 선택지에 없는 답변(예: 세부 수치, 조건부 답변)도 자유롭게 받을 수 있다는 장점이 있다.

### 4.4 Markdown 문서 편집 및 승인

각 Agent 단계가 끝나면 해당 단계의 Markdown 문서를 미리보기로 보여준다.

- 기본은 읽기 전용 미리보기
- **"✎ 수정"** 클릭 → 원문을 직접 편집할 수 있는 텍스트 영역으로 전환 (편집 중임을 나타내는 강조 테두리)
- **저장** → 수정 내용을 반영하고 미리보기로 복귀 / **취소** → 변경 사항 폐기
- 다른 단계로 이동하면 저장하지 않은 편집 내용은 자동으로 폐기됨
- 최종적으로 **Approve** 버튼을 눌러야 다음 Agent로 진행 (원 기획서의 승인 프로세스와 동일)
- 이 패턴은 문서 하나짜리 산출물(1~6단계, 9단계)에 적용된다. 코드가 여러 파일로 생성되는 7~8단계는 아래 4.5의 별도 화면을 거친다.

### 4.5 커밋 리뷰(Diff) 화면 — 코드 생성 / 리팩토링 단계 전용

**배경**: 7단계(코드 생성)와 8단계(리팩토링 및 코드 리뷰)는 한 번에 여러 파일이 새로 생기거나 수정된다. 4.4의 "문서 1개 Approve = 커밋 1개" 패턴을 그대로 쓰면 관련 없는 변경들이 한 커밋에 뭉쳐 리뷰와 되돌리기가 어려워진다. 그래서 이 두 단계는 **"Approve = 파일 단위로 쪼개진 여러 개의 원자적 커밋"**으로 처리한다.

**화면 구성**
- Markdown 미리보기 자리 대신, **변경 파일 리스트**가 표시된다. 각 항목은:
  - 파일 경로 (모노스페이스)
  - 변경 유형 뱃지 — 신규(teal) / 수정(amber) / 삭제(red)
  - 개별 체크박스 (기본 전체 선택)
  - Agent가 생성한 커밋 메시지 1줄 (예: `refactor: extract IMovable interface`) — 편집 가능
- 파일 클릭 시 우측/하단에 **Diff 미리보기** 확장 (`git add -p` 느낌으로, 추가된 줄은 teal, 삭제된 줄은 red 배경)
- 하단 액션: **선택 항목 커밋 (N개)** — Approve 버튼이 "파일 그룹 수만큼의 커밋을 순차 생성"하는 동작으로 바뀐다. 체크 해제한 파일은 이번 승인에서 제외되고 다음 라운드로 남는다.

**사이드바 진행률과의 관계**: 이 화면에서 전체 파일 중 일부만 Approve해도 되므로, 7~8단계의 진행률 %는 "승인 완료된 파일 수 / 전체 제안된 파일 수"로 계산한다 (다른 단계의 체크리스트 기반 계산과 동일한 원리).

## 5. 비주얼 디자인 시스템

Unity 에디터 감성의 다크 인스펙터 패널 톤을 전 화면에 일관되게 적용했다.

- **배경/패널**: 다크 그레이 계열 (`--bg-page`, `--panel`, `--panel-2`, `--panel-3`)
- **폰트**: 본문은 Inter, 단계 번호·경로·상태 등 기술적인 라벨은 JetBrains Mono
- **상태 색상**: teal(완료·성공) / amber(진행 중·주의) / red(위험·오류) — 의미별로 색을 고정하고 임의로 다른 용도에 재사용하지 않음
- 상세 컴포넌트 규칙(버튼, 카드, 뱃지, 코드 블록, 프리셋 선택기 등)은 별도 스킬 `gameforge-ui-style`로 문서화하여 이후 화면 제작 시 재사용
