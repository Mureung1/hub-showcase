# 범용 AI 대비 경쟁가치 검증

> 상태: **문헌 우선 단계**. [문헌 기반 제품·검수 근거](RESEARCH_REVIEW.md) 뒤 실제 채팅 말투 피드백을 반영해 전체 72문구를 다시 작성했다. 대표 12문구도 바뀌었으므로 이전 내부 판정은 새 버전에 승계하지 않으며, 독립적인 사람 평가자 2인의 블라인드 재검수 전까지 무참여자 모델 벤치마크를 보류한다.

> 2026-07-16 범위 변경: 아래 72문구·24세트 기록은 개인 말투 확장 전 기본 문구의 이력이다. T32 승인으로 T25 최종 분모는 288문구·96세트로 바뀌었고, 새 말투 변형은 먼저 초안을 구현한 뒤 사용자 반복 검토와 외부 전수 검수를 별도로 수행한다. 기존 C1~C4 대표 12문구는 기본 문구 source preflight에는 남지만 288문구 전체 합격 근거로 사용하지 않는다.
>
> 2026-07-20 범위 변경: 카드 기본 경로가 정적 템플릿 즉시 결과에서 `카드 → 질문 1개 → guided AI`로 바뀌었다. 아래 C1~C4 정적 카드 비교 기록은 T25 템플릿 기준선 평가 이력으로만 보존하며 현재 guided 제품 흐름의 경쟁가치 근거로 승계하지 않는다. 새 비교는 T20·T21 guided provider 품질과 T34 모바일 흐름이 통과한 뒤 같은 사실표로 다시 고정한다. 실제 결과 전에는 guided 우위·retrieval 우위를 주장하지 않는다.
>
> 목적: 사용자가 카드에 맞는 상황에서 ChatGPT·Gemini 대신 답냥이를 선택할 이유를 검증하되, 지금은 참여자 인터뷰 없이 문헌·고정 가상 과업·블라인드 품질 평가로 최소 백엔드 투자 여부를 판단한다.
>
> 범위: T20 실 provider 품질 진행 전에는 **카드 경로 무참여자 벤치마크**만 수행한다. provider 비종속 프록시·DB 기반 구현은 이 판정과 독립적으로 진행할 수 있다. T22는 기술 MVP 배포와 분리한 후속 외부 가치 검증이며, 재개할 때만 카드·실 AI 경로의 짧은 사람 대상 과업을 수행한다.

## 1. 검증할 가치

답냥이는 범용 AI보다 더 똑똑한 모델을 제공하는 서비스가 아니다. 사용자가 빈 채팅창에서 관계·상황·출력 형식을 설계하는 일을 제품이 미리 끝내 두고, **최종 전송 가능 문구까지의 시간·입력·수정 부담을 줄이는 서비스**여야 한다.

범용 AI도 반복 지시와 개인화를 지원하므로 “관계별 프롬프트”나 “3톤 출력”만으로는 차별화 근거가 부족하다. R2는 재현 가능한 통제 기준선을 위해 개인화 없는 새 채팅을 쓰고, T22는 참여자가 평소 쓰는 개인화 설정을 임의로 끄지 않은 실제 사용 방식과 겨룬다. 두 결과를 합치지 않는다.

- [ChatGPT 개인화·Memory](https://openai.com/academy/personalization/)
- [ChatGPT Projects](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)
- [ChatGPT GPTs](https://help.openai.com/en/articles/8554407-gpts-faq/)
- [Gemini Gems](https://support.google.com/gemini/answer/15236405?hl=en-GB)

### 사전 가설

| ID | 가설 | 반증 신호 |
| --- | --- | --- |
| H1 | 카드 적합 상황에서 답냥이는 최종 전송 가능 문구까지의 시간과 작성량을 줄인다. | 첫 복사는 빠르지만 후수정 때문에 총시간·작성량 우위가 사라짐 |
| H2 | 속도 이점이 관계 적합성·완결성·사실 충실성 저하로 상쇄되지 않는다. | 전송 가능성 80% 미만 또는 입력 없는 사실·사유·약속 1건 이상 |
| H3 | 사용자는 설명 없이 적절한 카드를 찾고 카드가 받은 원문을 읽지 않는 경계를 이해한다. | 2명 이상 직접입력으로 이탈하거나 원문을 반영한 결과라고 오해 |

문헌과 무참여자 벤치마크는 설계 타당성·출력 품질·입력량만 평가한다. 실제 사용자의 속도·선택·이해·지속 사용을 확인했다는 근거가 아니다. T22의 5명 결과도 **탐색적 형성평가**이며 시장 우월성, 통계적 유의성, 지속 사용을 확정하지 않는다.

### 대표 12문구와 전체 72문구 채팅체 개편

대표 과업은 서비스의 쉬운 면만 고르지 않고 복합 관계와 사실 충실성 위험을 포함한다. 첫 수정본은 관계 hard fail을 줄였지만 실제 대학생 카카오톡보다 지나치게 정중하고 완결돼 AI 문구처럼 보인다는 피드백을 받았다. 2026-07-12에 같은 데이터 구조를 유지한 채 전체 72문구를 다시 작성하고, 대표 12문구 검수지도 새 버전으로 교체했다.

| 과업 | 수정 전 위험 | 반영 | 내부 재감사 |
| --- | --- | --- | --- |
| C1 팀플 감사·확인 | 톤 차이가 약하고 관계 정보 없이 반말 고정 | 확인·감사를 유지한 짧은 `-요`체, 마침표 제거 | 사람 재검수 대기 |
| C2 교수·조교 상담 일정 | 특정 직함 단정과 메일체 | 호칭·날짜를 생략하고 한 호흡 질문으로 축약 | 사람 재검수 대기 |
| C3 선배·동기 말투 허용 | 선택권 없는 명령형과 완결된 문장 | 호칭을 빼고 편한 말·기존 존댓말 선택권을 채팅체로 명시 | 사람 재검수 대기 |
| C4 친구·연인 제안 거절 | 입력에 없는 다음 약속과 설명문 같은 문장 | 이유·향후 약속 없이 짧은 거절만 유지 | 사람 재검수 대기 |

자동 검증은 24개 카드·72개 후보 전수 노출, 비공식 관계 마침표, 공문체·잘못된 호칭·입력 없는 날짜·사유·약속, 후보 중복, 자리 표시자 수를 검사한다. 이전 AI 보조 감사 2건은 개편 전 문구를 평가했으므로 새 버전의 합격 근거로 사용하지 않는다. 새 문구의 자연스러움·톤·관계 적합성은 아래 사람 블라인드 검수에서 다시 판정한다.

R2 재개 조건:

- [x] T25 작업 계획 안에서 전체 72문구와 C1~C4 대표 12문구 채팅체 개편
- [x] 전수 노출, 형식, 공문체·호칭·입력 없는 사실 금지 자동 preflight
- [ ] 작성자가 아닌 한국어 관계 맥락 평가자 2인의 블라인드 검수와 불일치 시 제3자 판정
- [ ] 통과한 콘텐츠 버전 동결과 R2 실행 기록 시작

대표 표본이 통과해도 T25 전체 72문구 완료로 체크하지 않는다.

## 3. T22 후속 참여자와 개인정보 — 현재 미실행

이 절부터 사람 대상 내용은 T18 선행조건이 아니다. T22에서 짧은 과업을 실행할 때만 적용한다.

### 모집 기준

- 만 18세 이상 현재 재학 중인 대학생 5명
- 한국어 메신저를 주로 사용
- 최근 30일 안에 보내기 망설인 메시지 경험 1회 이상
- 최근 3개월 안에 ChatGPT 또는 Gemini로 메시지 초안을 만든 경험 1회 이상
- 가능하면 주사용 도구 ChatGPT 2명 이상, Gemini 2명 이상
- 프로젝트 참여자, 기존 시드·템플릿 검수자, 답냥이 사전 사용자는 제외
- 연구자와 권력관계가 있거나 거절하기 어려운 사람은 제외
- 보상은 완료·평가 결과와 관계없이 고정

### 수집하지 않는 정보

- 실제 카카오톡·DM·메일 원문과 캡처
- 실명, 학교, 학과, 학번, 연락처, 정확한 나이·주소
- 개인 ChatGPT/Gemini 대화 목록과 계정 식별자
- 음성·영상·전체 화면 녹화(별도 동의가 없는 기본 세션)

선택형 인터뷰를 할 때는 실제 원문 대신 관계·상황 범주와 행동 순서만 기록한다. 비교 과업은 아래 가상 사실만 사용한다. 참가자 코드 `P01`~`P05`와 연락·보상 명단은 분리하며 연결표는 보상 완료 후 7일 안에 삭제한다. 비식별 원시 기록은 판정 확정 후 30일 안에 삭제하고, 장기 보관은 집계표·가상 과업·익명 점수만 허용한다. 원치 않은 개인정보가 입력되면 세션을 멈추고 원문은 24시간 안에 삭제한 뒤 `redaction_applied`만 남긴다. 원시 데이터는 Git 저장소에 커밋하지 않는다.

## 4. 선택형 최근 행동 인터뷰 — 필수 아님

참여자가 추가 맥락 제공에 동의하고 운영 여력이 있을 때만 제품 설명과 화면 노출 전에 진행한다. 생략해도 T22 핵심 과업 판정에는 영향을 주지 않는다. 진행한다면 10~15분이며, “답냥이라면 썼을까요?” 같은 가정·유도 질문은 비교 과업이 끝난 뒤에만 묻는다.

### 시작 안내

> 최근 메시지 작성 방식을 알아보는 인터뷰입니다. 실제 원문·실명·학교 정보는 말하지 않아도 됩니다. 기억나는 범위에서 행동 순서와 판단만 알려주세요. 원하지 않는 질문은 건너뛸 수 있고 언제든 중단할 수 있습니다.

### 질문

1. 최근 30일 안에 가장 마지막으로 보내기 망설인 메시지는 언제였나요?
2. 상대와 어떤 관계였고 무엇이 가장 부담스러웠나요? 구체 원문은 말하지 않아도 됩니다.
3. 막힌 순간부터 실제 전송 또는 포기까지 무엇을 어떤 순서로 했나요?
4. 첫 초안은 어디에서 만들었고, 최종 문구까지 대략 얼마나 걸렸나요?
5. 몇 번 고쳤고 주로 무엇을 바꿨나요?
6. AI를 썼다면 왜 그 도구를 열었고 첫 요청에는 어떤 종류의 정보만 넣었나요?
7. 후속 요청은 몇 번 했고 첫 결과를 그대로 쓰지 못한 이유는 무엇이었나요?
8. “이제 보내도 된다”고 판단한 기준은 무엇이었나요?
9. 실제로 보냈나요? 이후 반응을 보고 성공 또는 실패라고 판단한 기준이 있었나요?
10. 비슷한 상황에서 같은 도구로 다시 돌아간 적이 있나요? 돌아갔거나 돌아가지 않은 이유는 무엇인가요?
11. 민감해서 AI에 넣지 않은 정보가 있었나요?

### 기록 코드

자유서술 대신 가능한 한 아래 범주를 우선 사용한다.

- 관계: `groupwork | professor_ta | senior_peer | friend_partner | other`
- 초안 도구: `self | chatgpt | gemini | search | person | other`
- 어려움: `start | politeness | fact_selection | tone | length | refusal | anxiety | other`
- 수정 이유: `relationship | too_long | too_generic | invented_fact | awkward | tone | privacy | other`
- 재사용 이유: `speed | familiarity | memory | quality | low_effort | privacy | other`

## 5. 대표 카드 비교 과업

참여자에게는 **가상 사실과 목표**만 보여준다. 성공 조건과 금지 사실은 진행자·평가자용이다. 과업 문구는 현재 템플릿 답을 포함하지 않는다. 참가자에게 특정 카드나 경로를 알려주지 않으며, 직접입력으로 이탈하면 카드 발견 실패로 그대로 기록한다.

### C1. 팀플·조모임 — 감사·확인

- 의도 경로: `reply → groupwork → thanks_check`
- A 변형: “팀원이 요청했던 참고문헌 목록을 정리해 단톡방에 올렸다. 파일을 확인했고 고맙다고 짧게 답하고 싶다.”
- B 변형: “팀원이 설문 응답 요약표를 정리해 단톡방에 올렸다. 내용을 확인했고 고맙다고 짧게 답하고 싶다.”
- 성공 조건: 확인과 감사가 모두 드러나며 추가 행동을 요구하지 않는 짧은 답장
- 금지 사실: 제출 마감, 품질 평가, 다른 팀원 반응, 이후 사용자가 맡을 작업

### C2. 교수님·조교님 — 일정 조율

- 의도 경로: `initiate → professor → schedule`
- A 변형: “수업 조교에게 과제 피드백 상담이 가능한 시간을 물어보려 한다. 아직 원하는 날짜나 시간은 정하지 않았다.”
- B 변형: “수업 교수에게 발표 자료 상담이 가능한 시간을 물어보려 한다. 아직 원하는 날짜나 시간은 정하지 않았다.”
- 성공 조건: A는 조교, B는 교수 관계에 맞는 호칭을 쓰거나 안전하게 생략하고 상담 가능 시간을 정중하게 질문
- 금지 사실: 특정 요일·시간, A에서 교수님이라는 가정, B에서 조교님이라는 가정, 사전 허가, 과목명·점수

### C3. 선배·동기 — 말 편하게 하자고 하기

- 의도 경로: `initiate → senior → casual_request`
- A 변형: “같은 학과 선배와 서로 계속 존댓말을 쓰고 있다. 선배가 자신에게는 편하게 말해도 괜찮다고 먼저 전하고 싶다.”
- B 변형: “동아리 동기와 서로 계속 존댓말을 쓰고 있다. 자신에게는 편하게 말해도 괜찮다고 먼저 전하고 싶다.”
- 성공 조건: 선배·동기 각각에게 말 편하게 해도 괜찮다는 뜻이 분명하지만 친밀함을 강요하지 않고 선택권을 남김
- 금지 사실: 상대의 선행 요청, 사용자도 바로 반말하겠다는 약속, 관계 기간, 만남 제안

### C4. 친구·연인 — 거절

- 의도 경로: `reply → friend → decline`
- A 변형: “친한 친구가 이번 주말 학교 축제에 같이 가자고 했다. 갈 수 없지만 이유를 자세히 말하거나 다음 약속을 잡고 싶지는 않다.”
- B 변형: “연인이 이번 주말 영화를 같이 보자고 했다. 갈 수 없지만 이유를 자세히 말하거나 다음 약속을 잡고 싶지는 않다.”
- 성공 조건: 제안을 명확히 거절하고 이유를 지어내지 않으며 친구·연인 각각에게 지나치게 딱딱하거나 관계를 단정하지 않음
- 금지 사실: 질병·과제·가족 일정, 다음 약속, 비용·다른 동행자, 대체 날짜

## 6. T22 실 AI 경로 사용성 과업

아래 과업은 시드와 현재 평가 사례의 사건을 반복하지 않는다. T20·T21 전에는 실행하지 않고 과업·루브릭만 잠근다. T22에서 참여자마다 한 과업을 답냥이의 “직접 설명할게요” 선택과 첫 생성 1회로 수행한다. 범용 AI와의 경쟁 비교는 카드 C1~C4에만 적용하며, A1~A4는 직접입력 경로의 무도움 완료·시간·개인정보 이해를 보는 **답냥이 단독 사용성 과업**이다.

## 7. 실 provider 품질 진행 전 무참여자 모델 벤치마크

### 이 단계가 답할 수 있는 것

고정된 가상 과업에서 답냥이 템플릿과 범용 모델의 **원출력 품질·사실 충실성·프롬프트 입력량**을 비교한다. 참여자가 없으므로 실제 E2E 시간, 탐색 난도, 선호, 주인의식, 재사용은 판정하지 않는다. 이 결과의 `Provisional Go`는 T20 실 provider 품질 진행 허용일 뿐 사용자 경쟁가치의 `Go`가 아니다. T18 프록시 기반과 T30 데이터 계층 같은 provider 비종속 백엔드 구현을 막지 않는다.

### 고정 실행 단위

1. R1을 통과한 C1~C4의 A/B 가상 과업 8개를 모두 쓴다.
2. 답냥이는 해당 버전의 결정적 템플릿 세 후보를 한 번 추출한다.
3. ChatGPT·Gemini는 각각 관련 맥락이 없는 새 채팅에서 아래 프롬프트로 과업당 독립 3회 실행한다.
4. 이 통제 기준선에서는 Memory·Custom Instructions·Gem 등 개인화를 사용하지 않는다. 해제 여부를 확인할 수 없으면 `personalization=unknown`으로 남기고 결과를 분리한다.
5. 도구명, 화면에 표시된 모델·플랜, 실행일시, 프롬프트 원문, 첫 결과 원문, 응답 지연을 기록한다. 모델 표기를 확인할 수 없으면 추정하지 않는다.
6. 실패 결과를 다시 뽑아 교체하거나 세 실행 중 좋은 결과만 고르지 않는다.

```text
당신은 한국 대학생이 실제로 보낼 짧은 메시지를 돕습니다.

관계: {task의 관계}
상황: {A 또는 B 가상 사실}
목표: {성공 조건}

바로 보낼 수 있는 한국어 메시지 3개를 제시하세요.
제공된 사실만 사용하고, 없는 날짜·사유·약속·상대 동의를 만들지 마세요.
세 문장은 사실과 의도는 같게 유지하되 기본 / 더 부드럽게 / 더 분명하게 순으로 구분하세요.
메시지 외 설명은 쓰지 마세요.
```

프롬프트의 `{task의 관계}`·`{A 또는 B 가상 사실}`·`{성공 조건}`에는 이 문서의 고정 문구를 그대로 넣는다. 실행 뒤 표현을 다듬지 않는다. 범용 모델에 성공 조건까지 주는 것은 출력 품질에 유리한 통제 조건이며, 그 입력 글자 수 자체를 답냥이의 무입력 카드 경로와 별도 보고한다.

### 비정상 출력·기술 실패 처리

- 허용하는 기계적 정규화는 앞뒤 공백과 전체를 감싼 따옴표·code fence, 선두 번호·불릿·톤 라벨 제거뿐이다. 문장 내용·순서·후보 수는 바꾸지 않는다.
- 정규화 뒤 메시지 본문이 정확히 3개가 아니거나 설명 문단이 섞이면 해당 run은 `format_fail=true`다. 2개 이하는 누락 슬롯을 포함해, 4개 이상은 좋은 세 개를 고르지 않고 **그 run의 후보 슬롯 3개 전부를 `blind_pass=false`**로 둔다. 톤 세트도 실패다.
- 모델의 내용상 refusal은 `refusal=true`와 `format_fail=true`로 기록하고 같은 3개 실패 슬롯을 적용한다. 다시 생성하지 않는다.
- 로그인·네트워크·UI 장애처럼 모델 출력이 아닌 `technical_missing`은 동일 조건으로 한 번만 재시도하고 두 시도를 모두 기록한다. 재시도도 실패하면 품질 실패로 바꾸지 않고 전체 R2 판정을 `Pending`으로 두며, 72개 유효 판단이 채워진 새 실행 회차에서만 gate를 계산한다.
- 원문은 보존하고 정규화본과 `format_fail | refusal | technical_missing`을 함께 기록한다.

### 블라인드 평가와 잠정 판정

- 도구·모델·실행 순서를 제거하고 무작위 ID를 부여한 뒤 11장의 루브릭으로 한국어 맥락 평가자 2명이 독립 채점한다.
- 답냥이는 4개 고유 톤 세트·12개 고유 문구다. 같은 문구를 A/B 각각의 사실표에 대조하므로 품질 평가 단위는 `8 task × 3 candidates = 24 task-conditioned judgments`다. A/B 적용을 24개 고유 출력으로 표현하지 않는다.
- ChatGPT·Gemini는 도구별 `8 task × 3 runs × 3 candidates = 72 judgments`와 `8 task × 3 runs = 24 tone sets`다.
- 후보 합격률은 도구별 `blind_pass 후보 수 / 전체 candidate judgments`로 계산한다. 추가로 task별 합격률은 답냥이 `통과/3`, 범용 모델 `통과/9`로 먼저 계산해 8개 task 분포를 함께 보고한다.
- 답냥이 24개 판단의 `factual_violation`, `relationship_hard_fail`, `force_hard_fail`은 각각 0건이어야 한다.
- 답냥이 블라인드 합격률은 80% 이상이고, ChatGPT·Gemini 각 도구의 전체 후보 합격률보다 10%p를 초과해 낮지 않아야 한다.
- 답냥이의 4개 고유 톤 세트는 모두 블라인드 정렬돼야 한다. 범용 모델의 톤 정렬은 비교 정보로 보고하되 답냥이 gate를 대신하지 않는다.
- 범용 모델 대비 작성 입력 글자 수·세 후보를 얻기 위한 턴 수는 기술 통계로 보고하되, 사용자 시간 절감 수치로 바꾸지 않는다.
- 모델의 3회 반복은 변동성 확인용이며 독립 사용자처럼 세지 않는다. 먼저 `task × tool` 단위로 합격률을 계산하고, 8개 task의 분포와 전체 분자/분모를 함께 보고한다.

| 잠정 판정 | 조건 | 다음 행동 |
| --- | --- | --- |
| Pending | 반복 기술 실패로 도구별 72개 유효 판단 미확보 | T20 실 provider 품질 완료를 보류하고 같은 고정 조건의 새 실행 회차로 분모 확보 |
| Provisional Go | hard fail 0건, 합격률 80% 이상, 각 기준선 대비 -10%p 이내, 톤 4/4 | “사용자 우월성 미검증” 표기를 유지하고 T20 실 provider 품질 진행 가능 |
| Iterate | hard fail 0건이지만 Go 미달. 단, 합격률 70% 이상·톤 3/4 이상 | 카드명·문구·톤 차이를 수정하고 같은 버전 절차 재실행 |
| No-go | hard fail 1건 이상, 합격률 70% 미만, 또는 톤 2/4 이하 중 하나 | T20 실 provider 품질 완료를 보류하고 taxonomy·템플릿 조정안을 별도 제안 |

실제 벤치마크 결과는 13장의 형식으로 별도 비식별 집계 문서에 남긴다. 이 문서에는 실행하지 않은 결과를 채우지 않는다.

## 8. T22 짧은 사람 대상 비교 환경과 교차 배정

### 비교 도구

- 답냥이: 같은 프리뷰 URL과 버전 고정
- 카드 C1~C4의 범용 AI: 참여자가 최근 3개월 안에 실제로 사용한 ChatGPT 또는 Gemini 중 하나
- 실 AI A1~A4: 답냥이 직접입력 경로만 수행하고 범용 AI 결과와 경쟁 집계하지 않음
- 관련 맥락이 없는 새 채팅에서 시작하되 평소 사용 중인 Memory·Custom Instructions·Gem 설정은 임의로 끄지 않는다.
- 도구명, 표시 모델, 플랜 범주, 개인화 사용 여부, 테스트 일시를 기록한다.
- ChatGPT와 Gemini 결과는 합쳐 “범용 AI” 단일 성능으로 계산하지 않고 도구별 원자료를 유지한다.

참여자 개인 계정 사용이 불편하면 해당 개인화 비교는 하지 않는다. 연구용 임시 계정을 사용한 결과는 `controlled_baseline`으로 분리하고 평소 사용 비교와 합치지 않는다. 어느 경우든 가상 과업만 provider에 전송한다.

T22 경쟁 판정에는 **평소 사용 도구로 유효한 짝비교를 완료한 5명**이 필요하다. 개인 계정 비교 거절·반복 기술 결측으로 유효 짝비교가 5명 미만이면 해당 참여자의 답냥이 사용성 결과와 보상은 유지하되 경쟁 표본을 채울 때까지 대체 모집한다. 5건을 확보하지 못하면 `Go | Iterate | No-go`를 내리지 않고 `Pending`으로 남긴다. `controlled_baseline`으로 빈 분모를 채우지 않는다.

### 공정한 출발선

1. 과업 설명을 읽고 이해한 뒤 중립 시작 화면에서 “시작”을 누른다.
2. `trial_start_at`은 도구를 열기 시작한 순간이다.
3. `tool_ready_at`은 해당 도구에서 실제 상호작용할 수 있게 된 순간이다.
4. 두 도구 모두 결과를 공통 편집칸으로 가져와 필요하면 수정한다.
5. “이대로 보내기”를 누르거나 그대로 보내겠다고 확정한 순간을 `final_confirmed_at`으로 기록한다.

주 지표는 접근·로딩·수정을 모두 포함한 `E2E_TTF`다. 앱 내부 시간은 진단용으로 분리한다.

```text
E2E_TTF = final_confirmed_at - trial_start_at
interaction_TTF = final_confirmed_at - tool_ready_at
```

### 사전 고정 배정표

`D`는 답냥이, `B`는 참여자의 범용 AI다. 화살표는 해당 관계에서 먼저 수행할 도구와 변형 순서를 뜻한다. 첫 세션 전에 이 표를 잠그고 결과를 본 뒤 바꾸지 않는다.

| 참여자 | C1 | C2 | C3 | C4 |
| --- | --- | --- | --- | --- |
| P01 | D-A → B-B | B-B → D-A | D-A → B-B | B-B → D-A |
| P02 | B-A → D-B | D-B → B-A | B-A → D-B | D-B → B-A |
| P03 | D-B → B-A | B-A → D-B | D-B → B-A | B-A → D-B |
| P04 | B-B → D-A | D-A → B-B | B-B → D-A | D-A → B-B |
| P05 | D-A → B-B | B-A → D-B | D-B → B-A | B-B → D-A |

| --- | --- |
| P01 | A1 |
| P02 | A2 |
| P03 | A3 |
| P04 | A4 |
| P05 | A4 |

기본 세션은 카드 비교 8회, 답냥이 실 AI 1회, 짧은 회고로 35~50분을 예상한다. 선택형 행동 인터뷰까지 동의한 경우에만 10~15분을 추가한다. 카드 블록은 같은 과업의 A/B를 사용해 답을 기억해 옮기는 효과를 줄인다. 실 AI 과업은 한 사람당 하나라 시나리오별 효과를 추정하지 않고 경로 사용성만 집계한다.

### T22 이해 확인

모든 과업 뒤 화면을 보지 않은 상태에서 다음 세 질문을 중립적으로 묻는다. 먼저 정답을 설명하지 않는다.

1. “상황 카드와 빠른 답변으로 받은 문구는 붙여넣은 원문을 읽고 만든 결과인가요?” — 기대 답: guided 결과는 받은 원문이 아니라 사용자가 고른 카드·option ID만 반영한다. `질문 없이 바로 초안`과 실패 fallback은 세부 option도 반영하지 않은 정적 초안이다.
2. “직접 설명에 적은 내용은 어디에 남고 어디로 전달되나요?” — 기대 답: 현재 탭 `sessionStorage`에 마지막 활동 뒤 30분까지 임시 보관되고 즉시 삭제할 수 있으며, 생성 시 외부 AI provider로 전달된다. 서비스 서버·분석·DB에는 원문을 저장하지 않는다.
3. “교수냥·선배냥·연인냥 카드는 각각 어떤 관계까지 포함한다고 이해했나요?” — 기대 답: 교수님과 조교님, 선배와 동기, 친구와 연인을 각각 함께 포함한다.

각 질문을 힌트 없이 설명하면 순서대로 `card_boundary_understood`, `storage_provider_understood`, `relationship_scope_understood`를 `true`로 기록한다. 틀린 답은 세션 뒤 설명하되 성공으로 소급하지 않는다. 각 항목이 5명 중 4명 미만이면 해당 카드명·입력 안내를 고치고 T22를 다시 수행한다.

### trial 필드

| 구분 | 필드 |
| --- | --- |
| 식별 | `trial_id`, `participant_code`, `tool`, `competitor`, `task_id`, `variant`, `tool_order` |
| 경로 | `scenario`, `mode`, `actual_path`, `manual_escape`, `card_selected` |
| 시간 | `trial_start_at`, `tool_ready_at`, `first_result_at`, `first_copy_at`, `final_confirmed_at` |
| 완료 | `completed`, `assisted`, `assistance_count`, `error_code`, `abandon_reason` |
| 노력 | `source_chars_pasted`, `authored_input_chars`, `submitted_input_chars_total`, `generation_turns`, `selection_clicks` |
| 수정 | `base_text_redacted`, `final_text_redacted`, `edit_distance`, `normalized_edit_rate`, `composed` |
| 평가 | `base_factual_violation`, `final_factual_violation`, `user_introduced_violation`, `relationship_hard_fail`, `force_hard_fail` |
| 사후 | `would_send`, `confidence_1_5`, `mental_effort_1_5`, `authorship_fit_1_5`, `recall_note_code` |

글자 수는 NFC 정규화 후 공백·줄바꿈을 포함한 Unicode code point 수로 계산한다. 과업지의 받은 메시지를 그대로 붙여넣은 글자와 사용자가 새로 작성한 지시·맥락을 분리한다.

```text
submitted_input_chars = 모든 제출 턴의 입력 글자 합
authored_input_chars = submitted_input_chars - 과업지 원문의 단순 붙여넣기 글자
```

새 결과를 발생시킨 제출을 1 generation turn으로 센다. 카드 선택으로 첫 결과를 본 것도 1턴이며 후보 선택·복사는 턴이 아니다.

선택한 원후보와 최종문 사이 수정량은 다음처럼 기록한다.

```text
normalized_edit_rate = edit_distance / max(base_length, final_length, 1)
```

- `0`: 그대로 사용
- `0 초과~0.2`: 경미한 수정
- `0.2 초과`: 대폭 수정
- 여러 후보를 결합: `composed=true`, 수정률 미산출, 대폭 수정으로 별도 집계

`authorship_fit_1_5`는 “이 문구는 내가 실제로 할 말 같다”에 대한 응답이다. 첫 파일럿에서는 탐색값으로 원분포를 보고하며 결과를 본 뒤 합격선을 소급해 만들지 않는다.

## 11. 공통 블라인드 품질 평가

최종문뿐 아니라 사용자가 선택한 원후보도 별도로 평가해 도구 원품질과 사용자 수정 후 품질을 구분한다. 도구명, 참여자, 시간, 원후보/최종문 표기를 제거하고 무작위 `blind_output_id`를 부여한다. 평가자 2명이 과업 사실표와 목표만 보고 독립 채점한다.

| 항목 | 2점 | 1점 | 0점 |
| --- | --- | --- | --- |
| 관계 적합 | 호칭·존댓말·거리감 적합 | 경미한 어색함 | 관계상 부적절·위험 |
| 완결성 | 목적과 요청·응답이 독립적으로 명확 | 한 곳 보완 필요 | 핵심 누락·모호한 지시어 |
| 사실 충실성 | 주어진 사실 또는 명시적 빈칸만 사용 | 확인이 필요한 비본질적 암시 | 없는 날짜·사유·첨부·약속·관계 단정 |
| 톤 적합 | 요청 톤과 관계별 해석이 분명 | 방향은 맞지만 차이가 약함 | 반대 톤·공격·과잉 비굴 |
| 전송 가능 | 그대로 전송 가능 | 의도 유지한 경미 수정 필요 | 대폭 재작성 또는 전송 위험 |

hard fail boolean은 `SPEC.md` 4장의 공통 정의를 사용한다.

| 필드 | 판정 |
| --- | --- |
| `factual_violation` | 과업·카드가 주지 않은 날짜·기한·사유·행동·동의·책임·약속을 완성 사실로 추가 |
| `relationship_hard_fail` | 잘못된 호칭·높임 또는 특정 하위 관계 단정으로 관계 적합 0점 |
| `force_hard_fail` | 상대 선택권을 제거하는 강압적 요청 또는 거절을 수락으로 바꾸는 화행 오류 |
| `user_introduced_violation` | 원후보에는 없던 `factual_violation`을 참여자 편집이 최종문에 새로 추가 |

명시적인 `[자리 표시자]`는 사실 위반이 아니지만 전송 가능 2점을 받을 수 없다. `user_introduced_violation`은 최종문 품질·전송 가능 점수에는 반영하되 제품 원출력 안전 hard gate와 분리한다.

```text
blind_pass =
  total_score >= 8
  AND 모든 항목 >= 1
  AND factual_violation = false
  AND relationship_hard_fail = false
  AND force_hard_fail = false
  AND sendability >= 1
```

사실 위반·합격 판정이 다르거나 두 평가자의 총점 차이가 2점 이상이면 제3자가 판정한다. 원점수와 불일치는 삭제하지 않는다. 후보 3개의 톤 순서는 별도 블라인드 정렬로 검사한다. 결정적 카드 자산은 T25의 24/24, 생성형 실 AI는 T21의 90% 기준을 적용하고 T22 원자료도 경로별로 분리한다.

## 12. T22 집계와 판정

반복 trial을 독립 참여자처럼 세지 않는다. 카드 C1~C4는 각 참여자의 도구별 완료율, 블라인드 합격률, `E2E_TTF` 중앙값, 작성 글자 수 중앙값, 생성 턴 중앙값, 수정률 중앙값을 먼저 계산하고 참여자별 paired 차이를 비교한다. A1~A4는 답냥이 실 AI 경로 사용성으로 별도 집계한다.

ChatGPT와 Gemini 원자료는 분리한다. 참여자마다 다른 주사용 도구를 paired 기준선으로 묶은 값은 **“이 5명의 평소 사용 도구 대비”** 탐색 결과일 뿐이며, ChatGPT 또는 Gemini 각각에 대한 우월성으로 표현하지 않는다.

### Hard gate 1 — 제품 원출력 안전·방법론

- 답냥이 원후보의 `factual_violation`, `relationship_hard_fail`, `force_hard_fail`: 각각 **0건**
- 개인정보 사고: **0건**
- 사전검수하지 않은 템플릿 또는 프로토콜 혼용: **0건**

하나라도 발생하면 수정·재검증 전 No-go다. 속도나 선호로 상쇄하지 않는다. 참여자가 편집으로 추가한 `user_introduced_violation`은 제품 원출력 hard fail 수에 넣지 않지만 최종문 `blind_pass` 실패와 별도 발생 건수로 보고한다.

### Hard gate 2 — 사용성·품질

- 5명 중 4명 이상이 C1~C4 답냥이 카드 과업 중 3개 이상에서 의도 카드를 찾아 도움 없이 최종 전송 가능 문구를 확정
- 답냥이 카드 경로의 앱 내부 S0→결과 시간 중앙값 20초 이내
- 5명 중 4명 이상이 배정된 답냥이 실 AI 과업 A1~A4 하나를 도움 없이 확정하고, 직접입력 경로 S0→`final_confirmed_at` 중앙값 60초 이내
- 답냥이 카드 최종문의 블라인드 합격률 80% 이상이고, 참여자별 비교 도구 최종문 합격률보다 전체 기준 10%p를 초과해 낮지 않음
- 답냥이 실 AI 최종문 블라인드 합격 4/5 이상
- 답냥이 카드·실 AI 최종문의 그대로 전송 또는 경미 수정 비율 각각 80% 이상
- `card_boundary_understood`, `storage_provider_understood`, `relationship_scope_understood`가 각각 4/5 이상

### 경쟁 효율 gate

- 참여자별 답냥이 `E2E_TTF` 중앙값이 범용 AI보다 짧은 참여자: 3/5 이상
- 참여자별 시간 비율의 중앙값 기준 답냥이 최종 문구 도달 시간: 범용 AI보다 **30% 이상 단축**
- 답냥이 최종 작성 글자 수: 범용 AI보다 **50% 이상 감소하면 강한 신호**이며, hard gate는 아님
- 작성 글자 수·생성 턴은 원분포와 중앙값을 보고하되 별도 hard gate로 쓰지 않음

### 선택 gate

- 5명 중 4명 이상이 다음 카드 적합 상황에서 답냥이를 먼저 선택
- 이유가 `speed | low_input | compare | quality | privacy` 중 하나이며 단순 브랜드 선호만으로 계산하지 않음

### 최종 판정

유효한 평소 사용 도구 짝비교가 5명 미만이면 아래 판정을 적용하지 않고 `Pending`이다.

| 판정 | 조건 | 다음 행동 |
| --- | --- | --- |
| Go | 안전·품질 hard gate 전부 + 경쟁 효율의 두 조건 + 선택 gate 통과 | “이 5명의 평소 사용 도구 대비” 범위에서 확인된 가치만 기록하고 후속 제품 판단에 반영 |
| Iterate | 안전·품질 hard gate는 전부 통과했지만 경쟁 효율 gate 또는 선택 gate 중 정확히 하나 미달 | 외부 경쟁가치 주장 보류. 원인에 따라 카드명·문구·UX를 수정하고 영향받은 T21/T22 범위 재검증 |
| No-go | 안전·품질 hard gate 하나 이상 미달, 또는 hard gate 통과 뒤 경쟁 효율과 선택 gate 모두 미달 | 외부 경쟁가치 주장 중단. taxonomy·카드 경계·핵심 타깃 축소안을 별도 구조 변경으로 제안 |

판정은 `안전·품질 hard gate → 경쟁 효율 → 선택` 순서로 적용한다. 결과를 본 뒤 임계값을 낮추지 않는다. 미완료·assisted·실패 사례를 분모에서 빼지 않으며, 성공 시간만 보고할 때도 전체 완료율과 중단까지의 시간을 함께 둔다.

### 계산식 모의 검산

아래 값은 스키마와 판정식을 확인하기 위한 **가상 값이며 참여자 결과가 아니다**.

- 답냥이 `E2E_TTF=18초`, 범용 AI `E2E_TTF=45초`이면 시간 단축률은 `1 - 18/45 = 60%`다.
- 선택 원후보 30자에서 2자를 고쳤다면 `normalized_edit_rate=2/30≈0.067`로 경미한 수정이다.
- 관계·완결성·사실·톤·전송 가능성이 모두 2점이면 총 10점, 사실 위반 없음, `blind_pass=true`다.
