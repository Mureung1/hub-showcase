# 개발 백로그

- 문서 상태: 3주차 진행 중 (원래 계획보다 앞서 P0 전부 + P1 대부분 완료). 남은 작업은 GitHub 이슈(`95x8x9/hub`)로도 등록해 추적 중
- 최종 수정일: 2026-07-20
- 참고: [서비스 기획서](../서비스%20기획서.md) §9 기능 도입 순서

## 백로그란

앞으로 해야 할 작업을 우선순위 순으로 정리해 둔 목록이다. 스프린트를 시작하기 전에 "무엇을, 언제, 왜" 할지 미리 정해두면 개발 중간에 범위가 흔들리지 않는다. 진행하면서 계속 갱신하는 살아있는 문서이며, 완료된 항목은 상태를 바꾸고 새로 발견된 작업은 우선순위를 매겨 추가한다.

## 우선순위 기준

| 등급 | 의미 |
|---|---|
| P0 | 기반 작업. 이게 없으면 다른 작업도 진행할 수 없음(백엔드, DB, 인증 등) |
| P1 | 이번 4주 스프린트 안에 반드시 끝내야 하는 핵심 기능 |
| P2 | 여유가 있으면 진행, 없으면 다음 스프린트로 미룸 |

## Task 목록

### P0 — 기반 작업

| # | Task | 설명 | 현재 상태 |
|---|---|---|---|
| 1 | 백엔드 구현 (API) | React 프론트와 통신할 REST API 서버 기본 구조 (Express) | 완료 — Express 서버 기동 확인, 일정/카테고리/친구/그룹/프로필/마이홈방문 API 전부 동작 확인 |
| 2 | DB화 | 일정/카테고리/친구/게시물/반응 스키마 설계 및 실제 DB 연결 | 완료 — Supabase(서울, `ap-northeast-2`) Postgres 연결, 마이그레이션 8개 적용. 서비스 전체 기능 범위 스키마 설계 후 이번 주에 영상 업로드/프로필/마이홈방문·두두/마이홈꾸미기 컬럼 추가 설계, `FocusSessionParticipant` FK 누락 버그도 수정 |
| 3 | 회원가입·로그인 (인증) | 실제 사용자 계정 개념 도입, 세션/토큰 인증 | 완료 — 커스텀 JWT(access 15분+refresh 30일), `refresh` 응답에 유저 정보를 함께 실어서 페이지 로드 시 인증 확인 왕복을 2회→1회로 축소 |
| 4 | 인증 영상 업로드·저장 | 프론트에서 찍은 영상을 서버/스토리지에 실제 저장 | 완료 — Supabase Storage(S3 호환)에 클라이언트가 presigned URL로 직접 업로드(서버는 URL 발급/DB 기록만, 파일 바이너리 중계 안 함). `POST /api/videos/presign`·`POST /api/videos`·`GET /api/videos/mine`·`DELETE /api/videos/:id`(soft delete + 스토리지 원본 삭제). 실 스토리지로 presign→업로드→재생 URL→삭제 end-to-end 검증 완료 |
| 5 | 인증 영상 코멘트 기능 | 인증 피드에 댓글 작성·조회 | 미착수 (GitHub [#19](https://github.com/95x8x9/hub/issues/19)) — `Comment` 스키마는 이미 있으나 라우트 미구현. 선행 조건이던 Task 4(영상 업로드)는 완료되어 이제 착수 가능 |

> **DB 선택 메모 (Task 2)**: 처음엔 Postgres를 Neon으로 선택했었음(Auth/Storage 미사용이라 가벼운 Neon이 적합하다고 판단). 이후 과제 요구사항이 Supabase를 명시하고 있어 재검토 후 **Supabase로 최종 전환**함. 전환 과정에서 DB 리전이 미국 동부(`us-east-1`)로 되어 있어 쿼리 1건당 ~430ms가 걸리던 것도 함께 확인 — 서울 리전(Supabase `ap-northeast-2`)으로 옮기면서 ~90ms 수준으로 개선됨. Prisma는 `DATABASE_URL`(pooled, 평소 쿼리)과 `DIRECT_URL`(direct, 마이그레이션 전용)을 분리해서 사용.

> **인증 방식 선택 메모 (Task 3)**: 세션 기반 로그인 대신 커스텀 JWT를 선택. 이유: (1) DB 안에서 유저 인증까지 자체 해결해 데이터가 여러 곳으로 쪼개지지 않음. (2) access token(15분)은 서버가 매 요청마다 DB를 조회하지 않고 서명만 검증하면 됨. (3) refresh token(30일)은 해시로 DB에 저장해 로그아웃·탈취 시 즉시 폐기 가능, httpOnly 쿠키로만 전달해 XSS 위험 축소.
