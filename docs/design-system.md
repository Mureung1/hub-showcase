# 바로진료 디자인 시스템

이 문서는 바로진료의 환자 웹, 병원 직원 웹, 플랫폼 관리자 셸에 공통으로 적용하는 시각·상호작용 규칙이다. 구현 가능한 값은 `packages/design-system/styles.css`를 단일 기준으로 사용한다.

## 1. 디자인 목표

바로진료는 환자의 불안과 직원의 반복 업무를 줄이는 운영 도구다. 화면은 다음 인상을 우선한다.

- **신뢰감**: 의료 서비스에 맞는 차분한 색상과 명확한 정보 위계
- **즉시성**: 현재 상태와 다음 행동을 설명 없이 파악할 수 있는 구성
- **효율성**: 직원이 많은 대기 항목을 빠르게 훑고 반복 조작할 수 있는 밀도
- **접근성**: 색상에 의존하지 않는 상태 표현과 충분한 터치 영역
- **일관성**: 환자·직원 화면이 같은 토큰과 상태 언어를 공유

## 3. 디자인 원칙

### 3.1 환자 화면

- 모바일 390px을 먼저 설계하고 넓은 화면으로 확장한다.
- 한 화면에서 하나의 주요 행동만 강조한다.
- 상태, 도착 기한, 앞 대기 환자 수를 입력이나 보조 설명보다 먼저 보여준다.
- 긴 설명보다 짧은 상태 문장과 다음 행동을 사용한다.
- 환자가 병원 밖에서 햇빛 아래 보더라도 읽을 수 있는 대비를 유지한다.

### 3.2 병원 직원 화면

- 데스크톱 1280px 이상을 기본으로 설계한다.
- 통합 대기열 표를 화면의 주 작업 영역으로 사용한다.
- 행 높이와 열 너비를 안정적으로 유지해 상태나 버튼 문구가 레이아웃을 흔들지 않게 한다.
- 현재 상태에서 가능한 다음 동작만 표시한다.
- 상세 정보는 우측 패널에 표시하고 대기열 문맥을 유지한다.

### 3.3 공통

- 장식용 그라데이션, 색상 구체, 과도한 그림자와 마케팅형 Hero를 사용하지 않는다.
- 페이지 섹션을 모두 카드로 만들지 않는다.
- 카드 안에 카드를 중첩하지 않는다.
- 모서리 반경은 기본 6px, 최대 8px을 사용한다.
- 상태는 색상과 함께 아이콘·기호·텍스트를 표시한다.

- 원격과 현장 유형은 각각 정보 파랑과 브랜드 초록을 사용하되 항상 유형 텍스트를 함께 표시한다.

## 5. 타이포그래피

### 5.1 글꼴

```css
font-family: Pretendard, "Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif;
```

- 외부 웹폰트가 준비되지 않은 상태에서도 시스템 한글 글꼴로 읽을 수 있어야 한다.
- 글자 간격은 `0`을 기본으로 한다.
- 긴 숫자는 고정폭 숫자 기능 `font-variant-numeric: tabular-nums`를 적용한다.

### 5.2 크기와 역할

| 역할 | 크기 | 굵기 | 사용 위치 |
| --- | --- | --- | --- |
| Display | 36px | 700 | 환자의 핵심 대기 숫자 |
| Page title | 28px | 700 | 화면 제목 |
| Section title | 20px | 700 | 폼·대기열 섹션 제목 |
| Body | 15px | 400 | 기본 본문과 표 |
| Label | 13px | 600 | 입력 라벨, 표 머리글 |
| Caption | 12px | 400 | 갱신 시각과 보조 정보 |

- 모바일 Page title은 24px까지 줄일 수 있다.
- 버튼과 배지에서 글자가 잘리면 글자 크기를 줄이지 말고 너비나 줄바꿈을 조정한다.

## 6. 간격과 크기

4px 단위 스케일을 사용한다.

```text
4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64px
```

| 항목 | 기준 |
| --- | --- |
| 모바일 좌우 여백 | 20px, 최소 16px |
| 데스크톱 콘텐츠 최대 너비 | 1200px |
| 주요 섹션 간격 | 24–32px |
| 입력창·기본 버튼 높이 | 44px |
| 강조 버튼 높이 | 48px |
| 직원 표 행 높이 | 최소 68px |
| 데스크톱 헤더 | 64px |
| 직원 사이드바 | 208px |
| 직원 상세 패널 | 360px |

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--bj-radius-sm` | 4px | 작은 태그와 내부 요소 |
| `--bj-radius-md` | 6px | 버튼, 입력창, 알림 |
| `--bj-radius-lg` | 8px | 제한된 카드와 패널 |
| `--bj-radius-pill` | 999px | 짧은 상태 배지만 허용 |

- 모달·드로어·핵심 환자 상태 카드에만 낮은 그림자를 사용할 수 있다.
- 그림자로 구분하기 전에 배경, 테두리, 여백으로 구조를 만든다.

## 8. 레이아웃

### 8.1 환자 등록·데스크톱

- 헤더 아래에 최대 1200px 콘텐츠를 배치한다.
- 병원 정보와 웨이팅 등록을 `minmax(0, 1.35fr) minmax(360px, 0.9fr)`로 나눈다.
- 병원 사진은 실제 장소 확인에 도움이 되도록 밝고 선명하게 표시한다.
- 900px 아래에서는 한 열로 전환하고 병원 정보 다음에 등록 폼을 배치한다.

### 8.2 환자 상태·모바일

- 화면 너비 전체를 사용하되 좌우 20px 여백을 유지한다.
- 순서는 `병원·접수번호 → 상태 → 핵심 숫자 → 진행 단계 → 안내 → 행동`이다.
- 주요 버튼은 한 손 조작을 위해 전체 너비로 배치한다.
- 하단 내비게이션이 있다면 콘텐츠를 가리지 않도록 하단 여백을 확보한다.

### 8.3 직원 대기열·데스크톱

- `64px 헤더 + 208px 사이드바 + 유동 콘텐츠 + 선택적 360px 상세 패널` 구조를 사용한다.
- 요약 지표는 한 줄 밴드로 사용하고 개별 부유 카드로 쪼개지 않는다.
- 대기열 표는 수평 스크롤 없이 1280px 기준 핵심 열이 모두 보여야 한다.
- 1024px 아래에서는 상세 패널을 오버레이 드로어로 전환한다.

## 9. 컴포넌트 규칙

### 9.1 버튼

- 한 화면 또는 한 조작 그룹에는 Primary 버튼을 하나만 둔다.
- Primary: 브랜드 초록 배경과 흰색 텍스트
- Secondary: 흰색 배경, 강한 중립 테두리
- Quiet: 배경 없이 보조 텍스트 색상
- Destructive: 흰색 또는 위험 배경과 위험 텍스트. 취소 확인이 필요한 동작에만 사용
- 아이콘만 사용하는 버튼에는 `aria-label`과 툴팁을 제공한다.

### 9.2 입력창

- 항상 보이는 `<label>`을 사용한다.
- Placeholder를 라벨 대신 사용하지 않는다.
- 오류 메시지는 입력 바로 아래에 위험 색상과 텍스트로 표시한다.
- 인원 선택은 숫자 입력보다 `− / 값 / +` 스테퍼를 우선한다.
- 스테퍼 버튼은 최소 44×44px을 유지한다.

### 9.3 상태 배지

- `아이콘 또는 기호 + 상태명` 구조를 사용한다.
- 긴 설명을 배지 안에 넣지 않는다.
- 배지는 상호작용 요소가 아니다.

### 9.4 진행 단계

- 원격 환자 상태 화면은 `원격 대기 → 입장 요청 → 현장 대기 → 대기열 종료` 네 단계를 사용한다.
- 현장 환자 링크 화면은 같은 상태 컴포넌트를 사용하되 직접 미루기·취소 버튼을 표시하지 않는다.
- 완료 단계는 체크 표시, 현재 단계는 숫자와 `현재 단계` 텍스트로 구분한다.
- 색상만으로 완료와 현재를 구분하지 않는다.

### 9.5 통합 대기열 표

- 기본 열: 순서, 접수번호, 유형, 가족 인원, 현재 상태, 등록 시각, 다음 동작
- 개인정보는 기본 표에 노출하지 않는다.
- 현재 상태에서 가능한 다음 동작만 행에 표시한다.
- 행 선택은 연한 브랜드 배경과 좌측 또는 전체 테두리로 표현한다.
- 행마다 메뉴 버튼을 둘 수 있지만 주요 다음 동작을 메뉴 안에 숨기지 않는다.

### 9.6 알림과 안내

- 정보 안내는 정보 파랑, 도착 기한은 주의 주황, 오류는 위험 빨강을 사용한다.
- 제목 한 줄과 설명 최대 두 줄을 기본으로 한다.
- 환자 안내 문장은 무엇을 해야 하는지 동사로 끝낸다.

## 10. 상태 매핑

| 시스템 상태 | 사용자 문구 | 시각 토큰 | 권장 아이콘 |
| --- | --- | --- | --- |
| `remote_waiting` | 원격 대기 | 정보 | `clock` |

## 11. 콘텐츠 원칙

- `진료 완료` 대신 `진료실 호출` 또는 `대기열 종료`를 사용한다.
- `예약` 대신 `원격 웨이팅` 또는 `당일 순번 접수`를 사용한다.
- `대기 팀`이 아니라 `앞에 남은 실제 환자`라고 표현한다.
- 예상 시간에는 항상 `약`, `예상`, `참고용` 중 하나를 포함한다.
- 입장 요청은 `20분 이내 병원 데스크에서 접수해 주세요`처럼 행동과 기한을 함께 쓴다.
- mock 알림은 데모 화면과 발송 이력에서 `Mock`임을 확인할 수 있게 하고 실제 발송 성공으로 오해하게 만들지 않는다.
- 현장 상태 화면에는 `웨이팅 취소는 병원으로 전화해 주세요`와 병원 전화하기 동작을 함께 제공한다.

## 12. 반응형 규칙

- `768px` 미만: 환자 모바일 레이아웃, 한 열, 전체 너비 행동 버튼
- `768–1023px`: 태블릿, 등록 화면 한 열, 직원 상세 패널 오버레이
- `1024px` 이상: 직원 사이드바와 대기열 표
- `1280px` 이상: 직원 상세 패널을 대기열 옆에 고정 가능
- 글자 크기를 뷰포트 너비에 따라 연속적으로 축소하지 않는다.
- 고정 형식 요소는 `minmax`, `grid-template-columns`, `aspect-ratio`로 크기를 안정화한다.

## 13. 접근성

- 일반 텍스트는 WCAG AA 대비를 만족한다.
- 모든 클릭·터치 영역은 최소 44×44px이다.
- 키보드 포커스 링을 제거하지 않는다.
- 상태 변화는 `aria-live` 영역 또는 명확한 포커스 이동으로 알린다.
- 표는 모바일에서 의미 없는 축소를 하지 않고 행 단위 목록으로 재구성한다.
- 오류는 색상, 아이콘, 텍스트를 함께 사용한다.
- 전화번호와 개인정보는 로그·공개 대기열·환자 간 화면에 노출하지 않는다.

## 14. 개발 적용

### 14.1 토큰

React UI에서는 다음 파일을 먼저 불러온다.

```css
@import "./styles/design-tokens.css";
```

컴포넌트 CSS에서 임의의 색상·간격·반경을 만들기 전에 토큰을 사용한다. 새 토큰이 필요하면 화면 파일에 값을 직접 추가하지 말고 `design-tokens.css`와 이 문서를 함께 수정한다.

### 14.2 구현 우선순위

1. 토큰과 전역 타이포그래피
2. 버튼·입력·상태 배지
3. 환자 모바일 상태 화면
4. 환자 등록 화면
5. 직원 앱 셸과 통합 대기열

## 15. 완료 전 점검

- 기준 이미지와 동일한 정보 위계가 유지되는가
- 한 화면에 Primary 버튼이 하나인가
- 상태가 아이콘·텍스트 없이 색상만으로 표시되지 않는가
- 환자 화면을 390px에서 가로 스크롤 없이 사용할 수 있는가
- 직원 표의 버튼과 상태 문구가 행 높이를 바꾸지 않는가
- 카드 안에 카드가 중첩되지 않았는가
- 예상 시간이 확정 진료 시각처럼 보이지 않는가
- 개인정보가 기본 대기열과 환자 응답에 노출되지 않는가
