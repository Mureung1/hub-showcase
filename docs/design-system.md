# 보쇼 디자인 시스템

> 목적: 화면이 늘어나도 일관된 결과물이 나오게 하는 하네스.
> 사람이든 LLM이든, UI를 만들 때 이 문서와 `prototype/tokens.css`를 먼저 읽는다.
> 값의 원본은 tokens.css — 이 문서는 그 값을 **언제, 왜, 어떻게** 쓰는지를 정한다.

---

## 1. 핵심 원칙

1. **히어로는 감성, 리스트는 절제.** 감성 표현(그라데이션, 일러스트 느낌)은 히어로 영역에만 가둔다. 알림 카드·목록·설정 등 기능 영역은 색을 아끼고 위계는 텍스트 크기·굵기·간격으로 만든다.
2. **색에는 의미가 있고, 의미를 섞지 않는다.**
   - `--warn` = 긴급(D-3 이내) **전용**. 다른 강조에 쓰지 않는다.
   - `--accent` = 브랜드/관심 매칭/선택 상태. 긴급 표현에 쓰지 않는다.
   - 장식 목적의 색 사용 금지 — 색이 보이면 사용자에게 의미가 전달돼야 한다.
3. **같은 의미는 같은 모양.** 중요도 3단계(임박/관심/일반)는 어느 화면에서든 동일한 색 체계를 쓴다 (S2 D-day 뱃지 = S5 캘린더 점). 사용자가 배울 규칙은 하나여야 한다.
4. **읽기 우선.** 본문 텍스트(`--text-1`, `--text-2`)는 단색 배경 위에만 놓는다. 그라데이션·이미지 위에는 히어로의 짧은 인사말·날짜만 허용.

## 2. 토큰 사용 규칙

| 토큰 | 용도 | 쓰면 안 되는 곳 |
|---|---|---|
| `--bg` | 앱 배경 | 카드 배경 (구분이 사라짐) |
| `--surface` | 카드 | — |
| `--surface-2` | 칩·뱃지 바탕, 오늘 셀 | 카드 배경 (너무 밝음) |
| `--line` | 구분선, 카드 테두리 | 텍스트 색 |
| `--text-1` | 제목, 핵심 정보 | 보조 정보 (위계 무너짐) |
| `--text-2` | 본문·요약 | — |
| `--text-3` | 출처·날짜·비활성·일반 점 | 본문 (대비 부족) |
| `--accent` | 선택 칩, 관심 뱃지, 활성 탭, 토글 on | 본문 텍스트, 긴급 표현 |
| `--accent-dim` | accent 요소의 배경 | 단독 사용 (반드시 accent 글자와 짝) |
| `--warn` / `--warn-dim` | D-3 이내 임박 표시 **만** | 그 외 전부 |
| `--hero-a/b/c` | 히어로 그라데이션 | 기능 영역 어디에도 |

- 간격은 `--space-*`(4px 배수)만 사용. 홀수 px 금지.
- 글자 크기는 4단계(`--fs-*`)만 사용. 5번째 크기가 필요해 보이면 크기가 아니라 굵기·색으로 해결을 먼저 시도.
- 모서리: 카드 16 / 작은 면 10 / 칩·토글 999. 세 가지 외 값 금지.

## 3. 컴포넌트 규칙

### 칩 (chip) — 하나의 컴포넌트, 상태 변형
- **필터 칩 (S2)**: 기본 `--surface-2`+`--text-2` / 선택 시 `--accent-dim` 배경 + `--accent` 글자·테두리
- **키워드 칩 (S4)**: 선택 상태 모양 + 우측 `×` / 추가 유도는 점선 테두리 + `--text-3`
- 두 화면의 칩은 반드시 같은 패딩(7px 13px)·반경·글자 크기를 공유한다.

### D-day 뱃지 — 중요도 3단계
| 단계 | 조건 | 스타일 |
|---|---|---|
| 임박 | D-3 이내 | `--warn-dim` 배경 + `--warn` 글자 |
| 관심 | 키워드/발신처 매칭 | `--accent-dim` 배경 + `--accent` 글자 |
| 일반 | 그 외 | `--surface-2` 배경 + `--text-3` 글자 |

### 캘린더 점 (S5 확장)
- 위 3단계와 **같은 색**: `--warn` / `--accent` / `--text-3`
- 월간 셀에는 점만(최대 3개), 텍스트 금지. 상세는 일자 탭 → 하단 축소 카드 목록.

### 카드
- `--surface` 배경 + `--line` 1px 테두리 + `--radius-card`, 내부 패딩 `--space-4`
- 구조: 상단(뱃지 + 출처) → 제목(`--fs-title`) → 요약(`--fs-body`, `--text-2`) → 키워드
- 완료 카드: opacity .45 + 제목 취소선 (삭제하지 않고 흐리게 — "다 챙겼다"는 안심 제공)

### 토글
- on: `--accent` 배경 + 흰 원 / off: `--surface-2` 배경 + `--text-3` 원

## 4. 금지 조항 (하네스의 조임쇠)

1. **헥스코드·rgba 직접 사용 금지.** 모든 색은 `var()` 참조. 필요한 색이 없으면 tokens.css에 먼저 추가하고 이 문서에 용도를 기록한 뒤 사용한다.
2. **새 색 추가 전 기존 토큰 재검토.** S5 캘린더도 새 색 0개로 만들어졌다 — 새 색이 필요하다는 느낌은 대부분 의미 체계를 다시 보라는 신호다.
3. **px 값 직접 사용 금지** (간격·글자 크기·반경). 예외: 1px 테두리, 컴포넌트 내부 고정 치수(토글 크기 등)뿐.
4. **그라데이션·이미지 위에 본문 텍스트 금지** (원칙 4).
5. 이 문서와 코드가 어긋나면 **문서를 먼저 고치고** 코드를 따라가게 한다.

## 5. 결정 히스토리

| 결정 | 이유 |
|---|---|
| 다크 테마 + 히어로/리스트 분리 | 레퍼런스 2종 분석: Notion Life Planner(다크 UI의 절제된 기능 영역) + 사진 위 타이포 포스터(감성 연출). 후자를 전면 적용하면 동적 텍스트의 대비(WCAG AA 4.5:1)를 보장할 수 없어, 감성은 히어로에 가두고 기능 영역은 절제하는 구조로 통합 |
| 포인트색: 보라 (#a78bfa) | A(보라)/B(시안) 두 시안을 동일 구조로 비교 후 A 선택 |
| 임박 전용색 분리 (--warn) | 긴급도가 브랜드색에 묻히면 스캔 속도가 떨어짐. 경고는 항상 같은 색이어야 학습됨 |
| 히어로는 CSS 그라데이션 (사진 미사용) | 저작권 걱정 없음 + 로딩 없음 + 토큰으로 색 통제 가능 |
| 중요도 3단계 색 = 캘린더 점 색 | S5 확장을 시안으로 스트레스 테스트한 결과, 새 토큰 없이 기존 의미 체계 재사용으로 충분함을 확인 |
| 폰트: Pretendard Variable | 한글 UI 사실상 표준, 무료, CDN 제공, 가변 굵기로 위계 표현에 유리 |
