# MVP 범위 정의

> **상태: 확정 (2026-07-07 — 사용자가 주차별 구현 계획 수립을 지시하며 진행 확정).** 이 문서의 In/Out 표가 CLAUDE.md "MVP 범위 밖 기능 구현 금지" 규칙의 판단 기준이다. 주차별 실행 계획은 docs/PLAN.md.

## In — MVP에 포함

| # | 기능 | 범위 상세 |
|---|---|---|
| 1 | 시나리오 선택 | 4개 카드 고정 (조모임 무임승차 / 교수님 메일 / 선후배 존댓말 / 소개팅·과CC) |
| 2 | 톤 축 결과 | 톤 사전 선택 UI 없음. **후보 3개 = 시나리오별 톤 축 3단계** — 톤은 결과 화면의 구조로 표현 (SCREENS.md 핵심 결정 1) |
| 3 | 입력 | 2필드 — "받은 메시지 붙여넣기"(500자) + "상황 설명"(300자), **둘 다 선택 입력** ([EDGE_CASES 1-1, 1-2], 먼저 보내는 메시지 케이스 대응) |
| 4 | 답장 생성 | 1회 호출로 톤 3단계 후보 3개 생성. 시나리오+톤별 시드 예시 기반 few-shot 프롬프트 |
| 5 | 결과 복사 | 후보별 복사 버튼 + 복사 실패 폴백 ([EDGE_CASES 3-1]) |
| 6 | 상태 처리 | 로딩 / 실패(재시도) / 플레이스홀더 감지 표시 ([EDGE_CASES 2-1, 2-3]) |
| 7 | 시드 예시 | 4 시나리오 × 3톤 × 2개 = 최소 24개, 팀 직접 작성 |

## Out — MVP에서 제외 (이후 단계)

| 기능 | 제외 사유 |
|---|---|
| 피드백 수집·예시 DB 누적 | PRD에서도 이후 단계 후보. 피드백 시점·오염 문제([EDGE_CASES 4-x])가 먼저 정리되어야 함 |
| 회원가입 / 로그인 | 익명 사용으로 충분. 재방문율 측정은 이후 |
| 생성 히스토리 저장 | 프라이버시 기준 미확정 상태에서 저장 최소화 |
| 시나리오/톤 커스텀 추가 | 4개 고정이 "구조화된 입력" 가치의 전제 |
| 시나리오-입력 불일치 감지 | [EDGE_CASES 1-4] |
| 결제 | CLAUDE.md 절대 금지 |

기존 결정 (2026-07-07, 사용자 위임): 톤 위치(결과 축), 입력 2필드 구성, 재시도 동선(리롤 우선) — 상세는 SCREENS.md "핵심 결정 3가지". 톤 축 문구는 PRD 후보안을 그대로 쓰되 시드 예시 작성 중 조정 허용.

## MVP 완료 기준 (Definition of Done)

- 4개 시나리오 각각에서 "선택 → 입력 → 생성(톤 3단계 후보) → 복사"가 모바일 뷰포트에서 동작
- API 실패 시 재시도 UI가 노출됨 (목 단계에서는 강제 실패 케이스로 확인)
- 테스트 통과 (CLAUDE.md: 테스트 없이 완료 선언 금지 — 테스트 도구 도입 필요, 현재 미설치)
