# MVP 범위 정의

> 이 문서의 In/Out 표가 AGENTS.md "MVP 범위 밖 기능 구현 금지" 규칙의 판단 기준이다. 주차별 실행 계획은 docs/PLAN.md, 현재 내부 진단은 docs/PRODUCT_REVIEW.md. 변경 이력·근거는 docs/LOG.md 참고.

## In — MVP에 포함

| # | 기능 | 범위 상세 |
|---|---|---|
| 1 | 시나리오 선택 | 4개 카드 고정 (팀플·조모임 / 교수님·조교님 / 선배·동기 / 친구·연인) — 카드마다 냥이 조력자 네이밍(팀플냥·교수냥·선배냥·연인냥, SPEC 1장) |
| 2 | 톤 결과 | 톤 사전 선택 UI 없음. **후보 3개 = 톤 3단계 공통 라벨(기본/더 부드럽게/더 분명하게), 기본이 첫 번째** (SCREENS.md 핵심 결정 1) |
| 3 | 입력 | **답장/먼저 연락 여부를 화면 분리로 선택(S0, 필수)** → **상황 카드 선택(S2-a, 시나리오당 6장)** 이 기본, 맞는 카드가 없으면 **"다른 상황이냥?"**으로 목적 6종+모드별 텍스트 입력(S2-b) 후 AI 생성 (EDGE_CASES 1-1) |
| 4 | 보낼 말 생성 | **하이브리드**: 상황 카드 선택 = 전수 검수 가능한 결정적 템플릿 즉시 응답, '다른 상황이냥?' = AI 1회 호출로 톤 3단계 후보 3개 생성. 카드·AI는 각각 T25·T21 합격 후 검수 완료로 표현한다. **입력에 없는 사실 생성 금지 — 자리 표시자 허용** (SPEC 3~5장) |
| 5 | 결과 복사 | 후보별 복사 버튼 + 복사 실패 폴백 ([EDGE_CASES 3-1]). **복사 = 핵심 과업 완료** |
| 6 | 상태 처리 | 로딩 / 실패(재시도) / 자리 표시자 하이라이트·안내 ([EDGE_CASES 2-1, 2-3]) |
| 7 | 콘텐츠 | 시드 24개 + 상황 카드 72문구 **초안**. 시드는 T16 제3자 검수, 템플릿은 T25 관계 호칭·완결성·사실 충실성·톤·모드 전수 검수까지 완료해야 운영 자산이 된다 (SPEC 4장) |
| 8 | 최소 계측 | 현재 Vercel 플랜이 custom events를 지원할 때만 `generate`/`copy` 2종을 적용. 새 유료 플랜은 자동 도입하지 않으며, 미지원이면 T22 외부 파일럿을 MVP 근거로 사용 (SPEC 7장) |

## Out — MVP에서 제외 (이후 단계)

| 기능 | 제외 사유 |
|---|---|
| 피드백 수집·예시 DB 누적 | PRD에서도 이후 단계 후보. 피드백 시점·오염 문제([EDGE_CASES 4-x])가 먼저 정리되어야 함 |
| 회원가입 / 로그인 | 사건 발생형 재사용 가설은 외부 파일럿으로 먼저 검증. 익명 MVP에 영구 식별자를 추가하지 않음 |
| 생성 히스토리 저장 | 프라이버시 기준 미확정 상태에서 저장 최소화 |
| 시나리오/톤 커스텀 추가 | 4개 고정이 "구조화된 입력" 가치의 전제 |
| 시나리오-입력 불일치 감지 | [EDGE_CASES 1-4] |
| 냥이 캐릭터 일러스트·애니메이션 | 3주 계획에 에셋 제작 시간 없음. MVP는 네이밍·카피·이모지 수준까지 |
| 템플릿 슬롯 자동 채움 (사용자 입력 병합) | 오병합이 빈칸보다 위험 — 자리 표시자 하이라이트(T11)로 사용자 채움 안내 (SPEC 4장) |
| 결제 | AGENTS.md 절대 금지 |

## 결정 완료

| 항목 | 결정 | 근거 |
|---|---|---|
| AI 연동 방식 | **목(mock)으로 UI 먼저 완성 → 이후 Vercel 서버리스 함수 1개(`/api/generate`)로 Claude API 호출** | 프론트 직접 호출은 API 키 노출로 금지 ([EDGE_CASES 5-1]). 함수 1개면 충분 — DB·세션 없음. 요청/응답 계약·프롬프트 구조는 SPEC.md 2~3장 |
| 배포 환경 | **Vercel** | Vite 정적 빌드 + `/api` 서버리스 함수가 한 저장소·한 배포로 해결. API 키는 Vercel 환경변수로 서버 보관. 호스팅 플랜과 custom events 지원 여부는 T17·T24에서 별도 확인 |
| AI 모델 선택 | **Haiku 4.5부터 holdout 평가 후 합격하는 가장 빠르고 저렴한 Claude 모델** | Opus 4.8 고정은 짧은 실시간 문구에 과할 수 있다. T21에서 동일한 비시드 holdout으로 톤·전송 가능성·환각·지연·비용을 비교하고, 미달할 때만 상위 모델로 올린다 |
| 엣지케이스 범위 | **MVP 코드 처리 13개 확정** | 상세 목록은 EDGE_CASES.md "MVP 대응 범위 확정" 표 |
| 서비스 정의 | **"상황과 관계에 맞는 메시지 작성 도우미"** — 받은 메시지가 있으면 답장, 없으면 먼저 보내는 메시지를 생성 | 시나리오 4개를 관계형으로 재명명(위 In-표), 사용자 노출 문구는 "답장" 대신 "보낼 말"로 통일(CTA: "보낼 말 3가지 만들기") |
| 하이브리드 생성 | 단일 생성 계약(SPEC 2장)을 유지하고 그 뒤에서 템플릿/AI를 라우팅 — **상황 카드 선택=템플릿, "다른 상황이냥?"=AI** | 채택 근거는 즉시 응답과 경로별 독립 검수 가능성이다. 사용자의 명시적 선택이 라우팅을 결정하므로 추론 휴리스틱이 불필요 (SPEC 2장) |
| 콘텐츠 구성 | 시드 24개(AI few-shot 전용) + 상황 카드 템플릿 72개(카드 경로 전용) — **서로 독립적으로 작성**(파생 관계 아님) | SPEC 4장 |
| 출처 노출 | 카드/AI 경로 구분은 **결과 화면(S3)에 다시 표시하지 않는다** | 선택 시점에 경로와 provider 전송 여부를 충분히 안내한다. 결과 재노출 생략은 각 경로가 자체 검수를 통과한 뒤에만 적용 (SPEC 2장) |

신규 구현 항목: CHECKLIST T25(상황 카드 템플릿 72개) · T26(생성 경로 라우터) · T27(S0 화면).

## MVP 완료 기준 (Definition of Done)

- 4개 시나리오 각각에서 "S0 방식 선택 → 관계 선택 → 상황 카드(또는 다른 상황이냥 → 목적·입력) → 생성(톤 3단계 후보, 기본 먼저) → 복사"가 모바일 뷰포트에서 동작 — **템플릿·AI 두 경로 모두에서 검증** (템플릿: 상황 카드, AI: 다른 상황이냥)
- API 실패 시 재시도 UI가 노출됨 (목 단계에서는 강제 실패 케이스로 확인)
- 실 AI 입력 화면에서 외부 provider 전송과 당시 보존 조건이 안내됨
- `RESEARCH_REVIEW.md`의 문헌 근거·과해석 경계를 반영하고, T25 대표 12문구 뒤 `COMPETITIVE_VALIDATION.md`의 무참여자 모델 벤치마크가 **`Provisional Go`를 통과함**. Iterate/No-go면 T18을 착수하지 않음
- T22의 긴 인터뷰 없는 외부 과업에서 평소 ChatGPT/Gemini와 유효 짝비교를 완료한 대학생 5명을 확보하고 카드 4개 중 3개 이상과 실 AI 1개 무도움 완료·시간·개인정보 이해·“내 말 같다”를 기록함 (PRODUCT_REVIEW)
- 카드 경로는 T22에서 평소 쓰는 ChatGPT/Gemini와 비교하고, 실 AI 경로는 답냥이 단독 사용성을 검증해 **최종 `Go`를 통과함**. Iterate/No-go면 T23·출시를 보류하고, 그 전에는 범용 AI 대비 우월성을 주장하지 않음
- 현재 플랜이 Vercel custom events를 지원하면 `generate`/`copy`를 기록하고, 미지원이면 유료 플랜 없이 제약과 파일럿 대체 근거를 기록함 (SPEC 7장)
- 테스트 통과 (AGENTS.md: 테스트 없이 완료 선언 금지)
