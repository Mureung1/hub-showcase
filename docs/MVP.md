# MVP 범위 정의

> **상태: 확정 (2026-07-07 — 사용자가 주차별 구현 계획 수립을 지시하며 진행 확정).** 이 문서의 In/Out 표가 CLAUDE.md "MVP 범위 밖 기능 구현 금지" 규칙의 판단 기준이다. 주차별 실행 계획은 docs/PLAN.md.

## In — MVP에 포함

| # | 기능 | 범위 상세 |
|---|---|---|
| 1 | 시나리오 선택 | 4개 카드 고정 (팀플·조모임 / 교수님·조교님 / 선배·동기 / 친구·연인) |
| 2 | 톤 결과 | 톤 사전 선택 UI 없음. **후보 3개 = 톤 3단계 공통 라벨(기본/더 부드럽게/더 분명하게), 기본이 첫 번째** (2026-07-08 2차 개정, SCREENS.md 핵심 결정 1) |
| 3 | 입력 | **목적 선택(6종, 필수)** + 2필드 — "받은 메시지 붙여넣기"(500자)·"상황 설명"(300자) 중 **1개 이상 필수** (2026-07-08 2차 개정 — EDGE_CASES 1-1 개정) |
| 4 | 보낼 말 생성 | 1회 호출로 톤 3단계 후보 3개 생성 (받은 메시지가 있으면 답장, 없으면 먼저 보내는 메시지). 시나리오+톤별 시드 예시 기반 few-shot 프롬프트. **입력에 없는 사실 생성 금지 — 자리 표시자 허용** (SPEC 3장) |
| 5 | 결과 복사 | 후보별 복사 버튼 + 복사 실패 폴백 ([EDGE_CASES 3-1]). **복사 = 핵심 과업 완료** |
| 6 | 상태 처리 | 로딩 / 실패(재시도) / 자리 표시자 하이라이트·안내 ([EDGE_CASES 2-1, 2-3 개정]) |
| 7 | 시드 예시 | 4 시나리오 × 3톤 × 2개 = 최소 24개, 팀 직접 작성 (목적 태그 포함) |
| 8 | 최소 계측 | Vercel Analytics 커스텀 이벤트 2종(`generate`/`copy`) — 텍스트 미포함, 선택값 id만 (2026-07-08 2차 개정, SPEC 7장) |

## 결정 완료 (2026-07-07)

| 항목 | 결정 | 근거 |
|---|---|---|
| AI 연동 방식 | **목(mock)으로 UI 먼저 완성 → 3주차에 Vercel 서버리스 함수 1개(`/api/generate`)로 Claude API 호출** | 프론트 직접 호출은 API 키 노출로 금지 ([EDGE_CASES 5-1]). 함수 1개면 충분 — DB·세션 없음. 요청/응답 계약·프롬프트 구조는 SPEC.md 2~3장 |
| 배포 환경 | **Vercel** | Vite 정적 빌드 + `/api` 서버리스 함수가 한 저장소·한 배포로 해결. API 키는 Vercel 환경변수로 서버 보관. 무료 티어로 MVP 트래픽 충분 |
| AI 모델 | **`claude-opus-4-8`** (Claude API) | 짧은 한국어 메시지 후보 3개 생성 기준 1회 약 $0.02~0.03 수준으로 MVP 트래픽에서 비용 부담 없음. 비용이 문제가 되면 `claude-haiku-4-5`($1/$5 per MTok)로 교체 가능 — 교체는 사용자 결정 사항 |
| 엣지케이스 범위 | **MVP 코드 처리 11개 확정** | 상세 목록은 EDGE_CASES.md "MVP 대응 범위 확정" 표 |

기존 결정 (2026-07-07, 사용자 위임): 톤 위치(결과 축), 입력 2필드 구성, 재시도 동선(리롤 우선) — 상세는 SCREENS.md "핵심 결정 3가지". 톤 축 문구는 PRD 후보안을 그대로 쓰되 시드 예시 작성 중 조정 허용.

추가 결정 (2026-07-08, 사용자 확정): 서비스 정의를 "상황과 관계에 맞는 메시지 작성 도우미"로 확장 — 받은 메시지가 있으면 답장, 없으면 먼저 보내는 메시지를 생성. 시나리오 4개를 관계형으로 재명명(위 In-표), 사용자 노출 문구는 "답장" 대신 "보낼 말"로 통일(CTA: "보낼 말 3가지 만들기"). 시드는 관계 카드 안의 대학생 대표 상황 단위로 구체 작성(SPEC 4장).

**2차 개정 (2026-07-08, 사용자 확정)**: ① S2에 메시지 목적 선택 추가(6종, 필수), ② 텍스트 2필드 중 1개 이상 필수 — 1차 결정의 "빈 입력 허용"을 뒤집음(목적 필수가 '선택만으로' 경로를 유지하므로 텍스트 하한으로 품질을 지키는 쪽 선택), ③ 톤 공통 라벨(기본/더 부드럽게/더 분명하게), 기본을 첫 번째로 배치, ④ 입력에 없는 사실 생성 금지 + 자리 표시자 허용(기존 "플레이스홀더 금지"를 교체 — 환각이 빈칸보다 위험), ⑤ 핵심 과업 = 후보 복사, 최소 계측(내용 미포함 이벤트)으로 측정.

## MVP 완료 기준 (Definition of Done)

- 4개 시나리오 각각에서 "선택 → 목적·입력 → 생성(톤 3단계 후보, 기본 먼저) → 복사"가 모바일 뷰포트에서 동작
- API 실패 시 재시도 UI가 노출됨 (목 단계에서는 강제 실패 케이스로 확인)
- `generate`/`copy` 이벤트가 Vercel Analytics에 기록됨 (텍스트 미포함 — SPEC 7장)
- 테스트 통과 (CLAUDE.md: 테스트 없이 완료 선언 금지 — Vitest 도입 완료, 2026-07-08)
