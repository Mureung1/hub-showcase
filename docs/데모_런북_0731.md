# 데모 런북 — 최종 발표 (7/31)

> 발표 당일 그대로 따라 하는 실행 순서. 모든 명령은 실제로 성공한 것만 옮겼다.
> 1~3주차 런북은 [`데모_런북_0716.md`](./데모_런북_0716.md) — 이 문서가 최신이다.

## 이 문서가 막는 것

발표는 날씨를 통제할 수 없다. **당일이 맑으면** 진단이 "+13% 기대"로 나오고
"날씨로 떨어질 매출을 방어한다"는 서사 자체가 성립하지 않는다. 방어할 하락이 없기 때문이다.

그래서 **날씨 입력만** 고정한다(`DEMO_WEATHER`). 그 뒤 진단·LLM 문구·발송·쿠폰 추적은
**전부 실제로 돈다.** 화면 배지도 "데모 고정 날씨 (실제 예보 API 미사용)"로 정직하게 바뀐다.

---

## 0. 결정: 오늘 seed를 켤 것인가

발표 1시간 전에 실제 날씨를 본다.

| 당일 날씨 | 조치 |
|---|---|
| 비·눈 | **seed 끈다.** 실제 예보로 가는 게 가장 강하다 (배지에 "기상청·OpenWeather 2개 소스 평균") |
| 맑음·흐림 | **seed 켠다** (`DEMO_WEATHER=rain`) |

```bash
curl -s http://localhost:4000/weather/today
```

`"condition":"rain"` 또는 `"isPrecipitating":true`면 seed 불필요.

## 1. 준비 (발표 10분 전)

### 1-1. seed 설정 (0단계에서 켜기로 한 경우만)

**로컬**: `apps/server/.env`에 한 줄 추가

```
DEMO_WEATHER=rain
```

**배포(Render)**: 대시보드 → Environment → `DEMO_WEATHER` = `rain` → Save
(저장하면 자동 재배포된다. 완료까지 1~2분.)

> 값: `rain`(기본 데모) · `clear` · `cold` · `heat`
> 오타를 내면 조용히 무시되지 않고 서버 로그에 경고가 뜬 뒤 실제 API로 폴백한다.

### 1-2. 서버 기동 (로컬 데모인 경우)

```bash
DEMO_WEATHER=rain npx tsx --env-file=apps/server/.env apps/server/src/index.ts
```

기동 로그에 아래 두 줄이 보여야 정상:

```
server on http://localhost:4000
[weather] 데모 고정 날씨 사용: rain 18°C (DEMO_WEATHER)
```

### 1-3. ⚠️ 오늘 제안 강제 재생성 (가장 잘 빠뜨리는 단계)

리허설로 이미 한 번 발송했다면 오늘 캠페인이 `sent` 상태다. 이때 서버를 재시작해도
기동 잡이 **사장님이 손댄 캠페인을 보호**하느라 제안을 다시 만들지 않는다
(로그: `[boot] 오늘 제안 유지 — 승인·발송된 캠페인 보호`).
seed를 켜도 화면엔 어제 맑은 날 문구가 그대로 남는다.

강제로 다시 만든다:

```bash
curl -s -X POST http://localhost:4000/proposal/generate -H "Content-Type: application/json" -d '{}'
```

응답에서 확인할 것 — 셋 다 맞아야 한다:

| 필드 | 기대값 |
|---|---|
| `weather.condition` | `rain` |
| `weather.seeded` | `true` |
| `status` | `draft` (발송 전 상태로 복귀) |

`campaignId`를 메모해 둔다 (4단계 redeem에서 쓴다).

### 1-4. 웹 실연동 전환

`apps/web/.env.local` 생성:

```
VITE_MOCK_MODE=false
```

```bash
npm run dev --workspace apps/web
```

대시보드 상단 배지가 **"데모 고정 날씨 (실제 예보 API 미사용)"**로 뜨면 성공.

## 2. 라이브 데모 (3분)

### ① 대시보드 (~40초)

- 날씨 카드 → 진단 카드 → 매출 타일 순으로 짚는다.
- **강조**: "날씨만 고정했고, −23%·687,344원은 이 가게 실제 매출에서 계산된 값입니다."
- **강조**: "문구는 저장된 mock이 아니라 방금 Groq가 이 날씨·진단을 보고 쓴 것입니다."

`DEMO_WEATHER=rain` 기준 화면 값 (숫자를 외워 갈 것):

| 항목 | 값 |
|---|---|
| 진단 배지 | 비 평균 **−23%** |
| 평상시 | 892,655원 |
| 오늘 예측 매출 | **687,344원** |
| 캠페인 방어 목표 | 830,169원 (+142,825원 방어) |
| 진단 문구 | "캠페인 없던 **37일** 기준, 비인 날은 비 안 오는 날 대비 −23%였어요" |

> 매출 데이터가 바뀌면 이 표도 바뀐다. 발표 전날 리허설에서 화면 값과 대조할 것.

**"캠페인 없던 37일"이 뭐냐고 물으면** — 캠페인을 보낸 날은 진단에서 뺐다고 답한다.
안 빼면 캠페인이 성공할수록 비 오는 날 평균이 올라가 진단이 "우린 비 와도 안 떨어져요"로
스스로를 지우고, 임계(−20%)를 못 넘겨 제안이 멈춘다. 이 가게는 **발송 5건만으로 이미
−22%에서 −19%로 흐려져 판정이 뒤집혔다.** 그래서 발송일을 기준선에서 분리했다.
(쓸 수 있는 한 줄: "서비스가 잘 될수록 자기 진단을 망가뜨리는 구조라 그걸 끊어뒀습니다.")

### ② 검토 → 발송 (~60초)

- "제안 검토하기" → 할인율·채널 확인 → "이대로 발송하기"
- 쿠폰 입력칸은 문구 형태에 맞춰 바뀐다 — 비/맑음/폭염은 **쿠폰 할인율(%)**,
  한파(`2,000원 할인`)는 **쿠폰 할인액(원)**. 상한(20% · 3,000원)을 넘기면 경고가 뜨고
  발송 시 서버가 400으로 거부한다. 질문 받으면 "상한은 UI가 아니라 서버가 강제합니다"로 받는다.
- 값을 바꾸면 **쿠폰 라벨·발송 문구·문자 미리보기가 함께** 따라온다. 값을 바꿔 보여주는 것도
  좋은 카드다 — "쿠폰만 바뀌고 문자는 그대로면 손님에게 다른 혜택을 약속하는 문자가 나가니
  같이 묶었습니다."
- 바뀌는 건 할인 숫자뿐이다. 사장님이 손으로 쓴 문장과 `100% 아라비카` 같은 무관한 숫자는
  건드리지 않는다(`할인`이 뒤따르는 숫자만 잡는다).
- **강조**: "서버가 동의자만 걸러내고 (광고)·수신거부를 자동 삽입 — UI가 아니라 서버가 법을 강제합니다."
- 폰에 온 `(광고) [김사장 카페] …` 문자를 화면에 보여준다.

### ③ 채널 역할 구분 (~20초)

- 발송 완료 화면의 SNS 카드 → 인스타 자동 게시 + `📍 매장에서 이 게시물 보여주세요`
- **강조**: "문자는 1인 1코드라 전환을 실측하고, SNS는 공개 채널이라 도달을 맡습니다. 측정 방식을 의도적으로 나눴습니다."

### ④ 쿠폰 사용 → 추적 반영 (~30초)

```bash
curl -X POST http://localhost:4000/coupons/<쿠폰코드>/redeem \
  -H "Content-Type: application/json" -d '{"orderAmount":15000}'
```

- 화면 전환 없이 추적 카드 숫자가 1초 폴링으로 올라간다.
- **강조**: "실시간처럼 보이지만 실제로는 쿠폰 코드 기반 누적 집계입니다."

## 3. 실패 시 폴백 — MOCK_MODE 리허설

서버·네트워크·LLM 중 하나라도 죽으면 **10초 안에** mock으로 갈아탄다.

```bash
rm apps/web/.env.local
```

Vite가 자동 재시작한다. 이후 화면은 `apps/web/src/mocks/scenarios.ts` 데이터로 동작하고
**서버를 한 번도 부르지 않는다.** 상단에 날씨 선택 버튼(비·맑음·한파·폭염)이 나타나
발표 중 시나리오를 바꿔가며 보여줄 수 있다.

> 배포 데모라면 Vercel 환경변수 `VITE_MOCK_MODE`를 `true`로 바꾸고 재배포 —
> 1~2분 걸리므로, 배포 데모 중 사고가 나면 **로컬 mock으로 전환**하는 편이 빠르다.
> 발표 전 로컬 웹을 미리 띄워두면 탭 전환만으로 끝난다.

### 리허설 체크리스트 (발표 전날 1회)

| # | 확인 | 통과 기준 |
|---|---|---|
| 1 | mock 대시보드 | 4개 날씨 버튼이 각각 다른 문구·프로모를 띄운다 |
| 2 | mock 발송 | 쿠폰 코드 5자 발급, 추적 카드가 8초에 걸쳐 0→37명 |
| 3 | 실연동 + seed | 배지가 "데모 고정 날씨", 진단이 실제 매출값 |
| 4 | 실연동 발송 | 폰에 (광고) 문자 수신, 인스타 게시물 생성 |
| 5 | 폴백 전환 | `.env.local` 삭제 후 10초 내 mock 화면 복귀 |

## 3-2. 실패 대본 — 무대에서 터졌을 때 (5-3)

발표 중 사고는 **숨기려 할 때 커진다.** 각 상황의 대사를 미리 정해뒀다.
공통 원칙: **화면을 보며 당황하지 말고, 그 실패가 왜 설계에 이미 반영돼 있는지로 넘긴다.**

### ① 오늘 제안이 안 뜬다 (LLM 지연·날씨 API 장애)

**화면**: `🕐 2026-07-30 제안을 보여주는 중이에요` 배너 + 지난 제안이 그대로 표시됨

이건 사고가 아니라 **설계된 폴백**이다. 서버가 오늘 제안을 못 만들면
`GET /proposal/today`가 마지막 성공분을 대신 주고 `stale: true`로 표시한다.

> **대사**: "지금 오늘 제안 생성이 지연되고 있는데, 화면이 비지 않고 어제 제안을 대신 보여줍니다.
> 중요한 건 **어제 것이라고 화면에 적혀 있다**는 겁니다. 사장님이 오늘 날씨 기준인 줄 알고
> 발송하면 안 되니까요. 준비되면 자동으로 오늘 것으로 바뀝니다."

그대로 진행해도 된다. 발송·쿠폰 추적은 정상 동작한다.

### ② 화면이 "오늘 제안을 만드는 중"에서 안 넘어간다

지난 캠페인조차 없을 때만 나온다(DB가 비었거나 첫 실행). 5초 간격 12회 자동 재시도한다.

> **대사**: "생성에 시간이 걸리네요. 그동안 구조를 먼저 보여드리겠습니다."

→ 60초 지나도 안 되면 **MOCK 폴백(3절)으로 전환**한다.

### ③ 문자가 안 온다

먼저 **시간을 확인한다.** 21~08시면 서버가 야간 차단으로 예약 전환한 것이다 — 정상 동작이다.

> **대사**: "지금이 야간이라 서버가 자동으로 예약으로 돌렸습니다. 정보통신망법상 야간 광고
> 발송이 금지돼 있어서, 이건 화면 체크가 아니라 **서버에서 강제**됩니다. 미리 받아둔 문자를
> 보여드리겠습니다."

야간이 아닌데 안 오면 Solapi 잔액·발신번호 문제다. 캡처해둔 문자로 대체하고 넘어간다.

### ④ 인스타 게시가 실패한다

화면이 자동으로 "복사 후 게시" 폴백으로 강등되고 캡션이 그대로 보인다.

> **대사**: "게시가 실패하면 문구를 잃지 않고 복사 폴백으로 내려갑니다. 실패해도
> 사장님 작업이 날아가지 않는 게 중요합니다."

### ⑤ Render가 안 깨어난다 (첫 요청 60초 초과)

> **대사**: "무료 플랜이라 서버가 절전 상태입니다. 깨우는 동안 아키텍처를 먼저 설명드리겠습니다."

→ 90초 지나면 **MOCK 폴백으로 전환**한다.

### 판단 기준 한 줄

| 남은 시간 | 조치 |
|---|---|
| 여유 있음 | ①~④는 대사로 넘기고 계속 진행 |
| 60초 이상 멈춤 | 즉시 MOCK 폴백 (3절) — 붙잡고 있지 않는다 |

## 4. 발표 후 정리

```bash
rm -f apps/web/.env.local
```

1. `apps/server/.env`에서 `DEMO_WEATHER` 줄 삭제 (또는 값 비우기)
2. Render 대시보드에서 `DEMO_WEATHER` 삭제 — **안 지우면 배포 앱이 계속 가짜 날씨를 쓴다**
3. 서버 프로세스 종료 (Ctrl+C)

## 참고 — 자주 걸리는 것

| 증상 | 원인 | 조치 |
|---|---|---|
| seed를 켰는데 문구가 그대로 | 오늘 캠페인이 `sent`라 기동 잡이 보호 | 1-3 강제 재생성 |
| 배지가 "2개 소스 평균" | seed가 안 걸림 | `DEMO_WEATHER` 오타 — 서버 로그 경고 확인 |
| 대시보드가 "오늘 제안을 만드는 중" | 기동 잡이 아직 LLM 대기 | 5초 간격 12회 자동 재조회. 그래도 안 되면 1-3 |
| 발송이 예약으로 넘어감 | 야간(21~08시) 법적 필터 | 정상 동작. 미리 발송해 둔 문자를 보여준다 |
| Render 첫 요청이 느림 | 무료 플랜 15분 유휴 후 절전 | 발표 5분 전 `/health` 한 번 호출해 깨워둔다 |
| 대시보드 첫 로딩이 2~4초 | 날씨 캐시가 비어 기상청 왕복이 그대로 노출 | 아래 캐시 워밍 |

### 캐시 워밍 (발표 직전 1회)

앙상블 날씨는 서버에 **5분 캐시**된다. 캐시가 차 있으면 대시보드가 즉시 뜬다(실측 55~73ms),
비어 있으면 기상청 왕복을 기다린다(521ms~4.3s).

```bash
curl -s https://weatherpilot-server.onrender.com/weather/today > /dev/null
```

발표 직전에 한 번 부르고, **5분 안에** 데모를 시작한다.
