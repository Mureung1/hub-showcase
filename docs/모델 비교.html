04결론 & 시사점

추천: opus. 보수 규율을 지키면서 "AI 안 쓴 진짜 강점(Git·자기작성 위키)"만 정확히 크레딧해 강점을 무차별 삭제하지 않는다. 갭 분석 목적(뭘 실제로 메우나)에 가장 실용적. · 차선 sonnet(최엄격) · 회피 haiku(낙관 부풀림).
메타 발견 — "작은 모델 = 낙관"은 균일하지 않다. haiku는 낙관(전방위 부풀림), fable은 반대로 과냉(네이버 강점0·기본0). 실패 방향이 정반대. 단 fable은 근거 구체성·aiBar 배치는 상위권 유지.
하네스에 주는 메시지 🎯 — 스키마만 강제해도 fit이 26~70으로 발산 → 스키마 강제만으론 부족. haiku의 실패가 곧 검증기가 잡아야 할 규칙:
  • status가 강점/기본인데 근거 태그(repo/wiki) 없으면 → 반려
  • aiBar는 코드 근거 있는 항목에만, gap 항목엔 금지
  • impl이 concept보다 크게 높으면 → 경고(지원자 전제 위반)
→ 하네스 v1 검증 규칙 = haiku가 틀린 지점들. 통과 못 하면 재생성 → 작은 모델도 opus처럼 수렴하는지가 이번 주 검증 목표.
