## 2. Articles 프로젝트 한눈에

- **문제**: 초보자는 번역기를 써도 낯선 금융 영어 문장 구조를 이해하기
  어렵고, 하루에 쏟아지는 외신 중 무엇이 주가에 실질적 영향을 주는지
  선별할 기준이 없어 쉽게 지치고 포기한다
- **타겟**: 해외주식·영문뉴스 모두 처음인 완전 초보자
- **한 줄 정의**: "번역기 없이 원문을 완독하고, 스스로 판단한 뒤 AI 해석과
  비교하며 배우는 모의투자 학습 도구" (증권사 매매 연동은 스코프 밖)

> 발표 노트: 문제 → 타겟 → 한 줄 정의 순으로 차분히 짚어준다.

## 3. 핵심 기능 4가지

사이드바 + 대시보드 + 리더뷰(+바텀시트) + 인사이트 노트 + 단어장

1. **원문 리더뷰 + 문장 단위 인라인 번역** (최우선) — 팝업이 아닌 문장 아래
   아코디언으로 번역 노출
2. **AI 문단 3줄 요약 + 종목 영향 해설** — `insight`/`marketSentiment`는
   판단을 내리기 전까지 블라인드 처리
3. **투자심리 판단** (Bullish/Neutral/Bearish) → 바텀시트에서 내 선택과
   AI 시장 해석 비교
4. **데일리 단어장** — 기사 분석 시 핵심 용어 3~5개 자동 적재, 최신순

> 발표 노트: "판단 없이 완독만 해도 성공 신호"라는 지표 분리 정책(완독률과
> 판단수행률을 별도 집계) 한 줄 언급.

## 4. 화면 스크린샷

실제 사용 흐름 순서로 4장 배치 (`showcase/screenshots/*.webp`):

1. 대시보드 (`dashboard.webp`)
2. ① 리더뷰 · 문장 번역 (`reader.webp`)
3. ②③ 바텀시트 · 판단 비교 (`bottom-sheet.webp`)
4. ④ 단어장 (`vocabulary.webp`)

> 발표 노트: 실제 화면 흐름 순서(대시보드→리더뷰→바텀시트→단어장)로
> 설명하며, 앞 슬라이드의 기능 번호(①~④)와 연결해준다.

## 5. 기술 스택

- **Frontend**: React 19 + Vite
- **Backend**: Express 5
- **DB + Auth**: Supabase (RLS로 사용자별 단어장·판단 기록 격리)
- **LLM**: Claude API (`claude-haiku-4-5` 고정)

기술 하이라이트:

- Claude 호출 1번으로 문장 번역·용어 선별·문단 요약·insight·
  marketSentiment 5개 필드를 동시에 받아 응답 지연과 비용을 절감
- CNBC RSS 수집 → 본문 분량 필터 → LLM 투자/가독성 점수, 3단계 파이프라인
  으로 대시보드 "오늘의 핵심 기사"를 매일 자동 큐레이션
- 완독과 판단 수행률을 `article_reads` 테이블로 분리 집계

> 발표 노트: 왜 haiku 고정인지 — "요약/번역/용어선별/심리판별이 짧고
> 정형화된 반복 작업이라 저지연·저비용 모델이 적합" 한 줄 근거 제시.

## 8. AI와 일하는 순서 (워크플로)

> "저는 문제 정의, 핵심 기능 우선순위, 화면별 정책(블라인드 처리·저장
> 시점 등)을 정했습니다. AI는 요구사항을 Task로 쪼개고, 구현 코드를
> 작성하고, 구현이 스펙과 실제로 일치하는지 코드와 실행 중인 서버를
> 근거로 검증했습니다."

순서:

1. 기획서(`docs/plan.md`) 확인
2. **feature-slice**로 Task 분해 + 우선순위 부여
3. GitHub Issue 등록
4. 구현
5. **feature-verify**로 스펙 대비 검증
6. `docs/backlog.md`에 진행 상황 기록

> 발표 노트: "역할 분담" 프레임으로 설명 — 사람은 의사결정, AI는 분해·구현·
> 검증.

## 9. 전담 Agent 2개 + Skill 2개

- **`feature-slice`** (2026-07-13 도입, 읽기 전용): 요구사항 → 하루 단위
  Task + 최우선/P0/P1 우선순위. 기존 스펙과 어긋나지 않게 `plan.md`/
  `api-spec.md`를 먼저 확인하고, 스코프 크리프를 경계
- **`feature-verify`** (2026-07-17 도입, Bash 포함): "구현했다" ≠
  "검증됐다" — `checklist.md` 체크박스는 신뢰하지 않고 코드+실행 중인
  서버로 PASS/FAIL 판정, 근거는 항상 파일경로:줄번호
- **`design` Skill** (2026-07-09 도입): 색상/타이포/컴포넌트/인터랙션
  규칙 단일 소스. "자바스크립트 절대 금지, `:focus`/`:checked`/`<details>`
  만" 같은 과거 회귀를 규칙화
- **`testing` Skill** (2026-07-23 도입): Vitest `describe`/`it` 구조
  (정상/빈값/경계값/실패케이스), `it.each`, `vi.spyOn`+`afterEach` 컨벤션

> 발표 노트: 4개가 프로젝트 진행 중 필요해진 시점에 하나씩 추가된
> 순서라는 점(디자인 일관성 → 계획 자동화 → 신뢰성 검증 → 회귀 방지) 강조.
