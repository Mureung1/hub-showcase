# 나를 믿는 너를 믿어 프로젝트 기획서

## Summary

`나를 믿는 너를 믿어`는 사용자의 장기 목표를 주간/일일 퀘스트로 변환하고, 퀘스트 수행 결과에 따라 전자 생물 매니저와 함께 성장하는 자기계발 웹앱이다.

이 서비스의 핵심은 단순 일정 관리가 아니라, 목표를 게임식 퀘스트로 바꾸고 성공/실패 데이터를 바탕으로 다음 퀘스트를 리밸런싱하는 성장 루프다.

사용자는 매니저를 키우고, 매니저는 사용자를 키운다. 매니저는 현실 생물이 아니라 사용자의 성장을 기다리는 전자 생물형 페이스메이커다.

## 문제 정의

10대와 20대는 공부, 운동, 취미, 커리어 등 여러 영역에서 성장해야 하는 시기다. 하지만 자격증 취득, 체력 향상, 포트폴리오 완성처럼 의미 있는 목표는 성취까지 시간이 오래 걸린다. 사용자는 큰 목표를 세우지만, 오늘 해야 할 작은 행동으로 쪼개지 못하거나 즉각적인 보상이 없어서 쉽게 흥미를 잃는다.

이 서비스는 장기 목표를 오늘 수행 가능한 퀘스트로 변환하고, 작은 성취도 전자 생물 매니저의 성장으로 되돌려 사용자가 꾸준히 시도할 수 있게 돕는다.

## 사용자 시나리오

사용자 목표: 정보처리기사 자격증 취득

1. 사용자는 온보딩에서 목표와 생활 패턴을 입력한다.
2. 사용자의 답변을 바탕으로 전자 생물 매니저가 생성된다.
3. 매니저는 목표를 주간 퀘스트로 나눈다.
   - 예: 이번 주 데이터베이스 과목 1회독
4. 주간 퀘스트를 오늘의 퀘스트로 나눈다.
   - 예: 오늘 데이터베이스 개념 15분 공부
5. 사용자는 퀘스트를 수락하기 전 분량, 제한시간, 난이도를 수정한다.
6. 퀘스트를 수락하면 남은 시간이 표시된다.
7. 사용자가 완료하면 매니저가 경험치를 얻고 성장한다.
8. 실패하면 퀘스트는 소멸하고, 사용자는 실패 이유를 선택한다.
9. 매니저는 실패 이유를 바탕으로 더 낮은 부담의 복구 퀘스트를 제안한다.
10. 이 루프를 반복하며 사용자와 매니저가 함께 성장한다.

## 핵심 기능

### 1. 온보딩/매니저 생성

- 목표 입력
- 생활 패턴 입력
- 동기부여 성향 선택
- 전자 생물 매니저 생성
- 매니저 타입은 현실 생물이 아니라 전자 생물형 페이스메이커로 표현

### 2. 목표 등록

- 장기 목표 입력
- 목표 카테고리 선택
  - 공부
  - 운동
  - 취미
  - 커리어
  - 생활습관
- 목표 마감일 또는 희망 기간 입력

### 3. 퀘스트 생성

- 장기 목표를 주간 퀘스트로 분해
- 주간 퀘스트를 일일 퀘스트로 분해
- 퀘스트 유형 분류
  - 시간형: 공부 60분, 운동 20분
  - 양적형: 책 15페이지 정리, 문제 20개 풀이
  - 행동형: 강의 신청, 계획표 작성

### 4. 퀘스트 수정/수락

- AI가 만든 퀘스트를 사용자가 수락 전에 수정
- 수정 가능 항목
  - 제목
  - 분량
  - 제한시간
  - 난이도
  - 보상
  - 퀘스트 유형
- 사용자가 수락하면 활성 퀘스트로 전환

### 5. 완료/실패 처리

- MVP에서는 직접 완료 체크를 기본 성공 기준으로 사용
- 퀘스트 시간이 끝날 때까지 완료하지 않으면 퀘스트 소멸
- 실패 시 실패 이유 선택
- 실패 이유는 다음 퀘스트 리밸런싱에 활용

### 6. 매니저 성장

- 경험치
- 레벨
- 상태 메시지
- 성공을 기다리는 반응
- 실패 시 퇴화나 강한 패널티가 아니라 성장 정체 상태로 처리

### 7. 복구 퀘스트

- 실패한 퀘스트를 그대로 반복하지 않고 더 낮은 부담의 복구 퀘스트 제안
- 복구 퀘스트 성공 시 소량 경험치 지급
- 사용자가 루프에서 완전히 이탈하지 않도록 돕는 안전장치 역할

## 우선순위

| 우선순위 | 기능 | MVP 여부 |
|---:|---|---|
| 1 | 목표 입력 | MVP |
| 2 | 목표 -> 퀘스트 변환 | MVP |
| 3 | 퀘스트 수정/수락 | MVP |
| 4 | 완료/실패 처리 | MVP |
| 5 | 매니저 경험치/레벨 성장 | MVP |
| 6 | 복구 퀘스트 생성 | MVP |
| 7 | 실패 이유 기반 리밸런싱 | 1차 확장 |
| 8 | 비정기 인증 | 1차 확장 |
| 9 | 주간 리포트 | 2차 확장 |
| 10 | 매니저 외형 변화/꾸미기 | 2차 확장 |

## MVP 범위

MVP는 `목표 입력 -> 퀘스트 생성 -> 수정/수락 -> 완료/실패 -> 성장/복구` 루프가 한 번 이상 자연스럽게 작동하는 것을 목표로 한다.

### MVP에 포함

- 온보딩
- 매니저 생성
- 장기 목표 등록
- 주간/일일 퀘스트 생성
- 퀘스트 수정/수락
- 직접 완료 체크
- 실패 이유 선택
- 복구 퀘스트 제안
- 매니저 경험치/레벨 표시

### MVP에서 제외

- 푸시 알림
- 랭킹
- 소셜 경쟁
- 복잡한 보상 상점
- 실제 캘린더 연동
- 강한 패널티 시스템
- 완전 자동 인증

## 기획 결정

### 알림 기능 제외

이 서비스는 사용자를 계속 재촉하는 앱이 아니라, 사용자가 돌아오기를 기다리는 전자 생물이라는 정체성을 가진다. 따라서 MVP에서는 알림 기능을 제외한다.

대신 사용자가 재접속했을 때 매니저가 기다리고 있었다는 반응을 보여준다.

예시:

```text
기다리고 있었어. 오늘 퀘스트를 다시 조정해볼까?
```

### 실패는 리밸런싱 신호로 사용

실패는 사용자를 비난하거나 벌주는 근거가 아니라, 다음 퀘스트를 더 적절하게 조정하기 위한 데이터다.

예시:

```text
오늘 퀘스트는 사라졌어.
하지만 기록은 남았어.
이번엔 60분이 아니라 20분 복구 퀘스트로 다시 잡자.
```

### 쉬운 퀘스트 반복 방지

사용자가 일부러 쉬운 퀘스트만 만드는 경우 성장 시스템이 무너질 수 있다. 이를 막기 위해 쉬운 퀘스트는 보상을 낮게 책정한다.

예시:

| 퀘스트 | 난이도 | 보상 |
|---|---|---|
| 공부 5분 | 낮음 | 경험치 5 |
| 공부 30분 | 보통 | 경험치 20 |
| 공부 60분 | 높음 | 경험치 45 |

### 거짓 완료 처리

MVP에서는 사용자의 완료 체크를 기본적으로 신뢰한다. 이후 확장 기능으로 비정기 인증을 추가한다.

비정기 인증 예시:

- 짧은 메모 작성
- 타이머 기록 확인
- 사진 인증
- 간단한 회고 질문
- 학습 퀴즈

## AI Agent 역할

### 목표 해석 Agent

사용자의 장기 목표를 읽고 더 구체적인 목표로 바꾼다.

예시:

```text
입력: 정보처리기사 따고 싶어
출력: 정보처리기사 필기 시험 대비를 위한 6주 학습 목표
```

### 퀘스트 생성 Agent

목표를 주간/일일 퀘스트로 분해한다.

예시:

```json
{
  "goal": "정보처리기사 취득",
  "weeklyQuest": "데이터베이스 과목 1회독",
  "dailyQuest": "오늘 데이터베이스 개념 15분 공부",
  "questType": "time",
  "difficulty": "easy",
  "rewardExp": 20
}
```

### 리밸런싱 Agent

성공/실패 기록과 실패 이유를 보고 다음 퀘스트의 난이도와 분량을 조정한다.

예시:

```text
실패 이유: 시간이 부족했다
다음 제안: 공부 60분 -> 공부 20분 + 핵심 개념 3개 정리
```

### 피드백 Agent

매니저의 반응 문장을 생성한다. 말투는 나약하거나 과하게 의존적이지 않고, 같이 성장하는 페이스메이커 느낌을 유지한다.

## 엣지케이스

| 상황 | 대응 |
|---|---|
| 사용자가 쉬운 퀘스트만 만드는 경우 | 보상 경험치를 낮춘다 |
| 사용자가 거짓 완료를 누르는 경우 | MVP에서는 신뢰하고, 추후 비정기 인증을 추가한다 |
| 실패가 반복되는 경우 | 비난하지 않고 난이도를 낮추거나 목표를 재분해한다 |
| 퀘스트 유형이 다른 경우 | 시간형, 양적형, 행동형으로 성공 기준을 다르게 둔다 |
| 퀘스트가 소멸된 경우 | 복구 퀘스트를 제안한다 |
| 목표가 너무 추상적인 경우 | 구체화 질문을 먼저 던진다 |
| AI가 만든 퀘스트가 부적절한 경우 | 수락 전 사용자가 수정한다 |
| 실패했을 때 매니저 성장 처리 | 성장 감소는 없고, 성장 정체만 있다 |
| 사용자가 앱을 며칠 안 들어온 경우 | 알림은 보내지 않고, 재접속 시 기다렸다는 반응을 보여준다 |
| 퀘스트 소멸 후 의욕이 떨어지는 경우 | 낮은 난이도의 복구 퀘스트를 제공한다 |

## 추상 목표 처리

사용자가 너무 추상적인 목표를 입력하면 바로 퀘스트를 만들지 않고, 먼저 구체화 질문을 던진다.

예시:

```text
입력: 멋진 사람이 되고 싶다

질문:
1. 공부나 커리어에서 성장하고 싶어?
2. 운동이나 외형 관리를 말하는 거야?
3. 인간관계나 생활 태도를 말하는 거야?
4. 창작이나 취미 실력을 키우고 싶은 거야?
```

구체화 후 목표 예시:

```text
추상 목표: 멋진 사람이 되고 싶다
구체 목표: 매주 3회 운동하고, 매일 20분 독서하기
```

## Acceptance Criteria

- 문제 정의가 서비스 기능과 직접 연결되어 있다.
- 사용자 시나리오가 온보딩부터 성장 루프까지 이어진다.
- 핵심 기능이 MVP와 확장 기능으로 분리되어 있다.
- 퀘스트 성공/실패/복구 흐름이 포함되어 있다.
- 전자 생물 매니저의 정체성이 단순 AI 비서와 구분된다.
- 알림 기능 제외, 실패 시 리밸런싱 중심, 수락 전 수정 가능이라는 기획 결정이 반영되어 있다.
- 사용자가 장기 목표를 입력하면 오늘 수행 가능한 퀘스트로 변환되는 흐름이 설명되어 있다.
- 실패 후 복구 퀘스트를 통해 사용자가 다시 성장 루프에 진입할 수 있다.

## Assumptions

- 1차 타깃은 자기계발 목표를 가진 10~20대 소비자다.
- MVP에서는 직접 완료 체크를 기본 성공 기준으로 사용한다.
- 비정기 인증은 확장 기능으로 둔다.
- 매니저는 현실 생물이 아니라 전자 생물이다.
- 매니저의 성격은 나약하거나 의존적이지 않고, 같이 성장하는 페이스메이커다.
- 실패는 패널티보다 리밸런싱 신호로 사용한다.
- 알림 기능은 MVP에서 제외한다.
- AI Agent 세부 설계는 이 기획 문서 이후 별도 문서에서 구체화한다.
