### Slide 5: 기술 아키텍처 - Claude API 통합
**내용**:
- **2주차**: 텍스트 → Mock 분석 → 결과 표시
- **3주차**: 텍스트 → **Claude API** → 결과 표시 → **수정** → **저장**

**구조**:
```
Frontend (React)
    ↓
Backend (Express)
    ├─ 문본 검증
    ├─ Claude API 호출
    ├─ 응답 정규화
    └─ DB에 임시 저장
    ↓
Frontend
    ├─ 분석 결과 표시
    ├─ 사용자 수정
    └─ 저장 요청
```

---

### Slide 6: Claude API 연결 (기술)
**내용**:
- **프롬프트 엔지니어링**
  - 공지에서 어떤 정보를 추출할지 명확히
  - JSON Schema로 응답 형식 고정
  
- **API 호출**
  - claude-opus-4-8 모델 사용
  - 비동기 처리로 응답 대기
  
- **오류 처리**
  - API 타임아웃
  - 잘못된 JSON 응답
  - 정보 부족 시 경고

---

### Slide 7: 분석 결과 수정 UI
**내용**:
- **표시되는 정보**:
  - 일정명
  - 시작일 / 마감일
  - 장소
  - 제출물
  - 메모
  
- **수정 기능**:
  - 각 필드를 사용자가 직접 수정
  - 잘못 추출된 정보 수정
  - 일정 삭제
  - 새로운 일정 추가

---

### Slide 8: 일정 저장 기능
**내용**:
- **저장 프로세스**:
  1. 사용자가 수정한 일정 확인
  2. 필수 정보 검증 (일정명, 날짜)
  3. 여러 일정 한 번에 저장
  4. DB에 events 테이블에 저장
  
- **DB 구조**:
  - events 테이블 생성
  - notice ↔ events (1:N 관계)
  - 사용자별 데이터 격리

### Slide 9: 중복 일정 감지
**내용**:
