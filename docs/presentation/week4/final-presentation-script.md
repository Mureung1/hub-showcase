# CalMe 최종 발표 대본 (5분)

---

## **Slide 1: 제목 (30초)**

안녕하세요. 

저는 CalMe라는 프로젝트의 4주 개발 여정과 최종 성과를 발표하겠습니다.

CalMe는 **AI 기반 대학생 일정 관리 서비스**로, 현재 https://calme-frontend.vercel.app에서 실제로 서비스 중입니다.

---

## **Slide 2: 문제 & 솔루션 (30초)**

대학생들이 겪는 문제는 이겁니다.

학교 공지, 공모전, 팀플 등 **여러 채널에서 공지를 일일이 확인하면서 중요한 마감일을 자주 놓친다**는 것입니다.

저희의 솔루션은 간단합니다.

**공지를 업로드하면 AI가 자동으로 분석해서 일정을 추출하고, 사용자가 수정한 후 저장**할 수 있도록 하는 것입니다.

---

## **Slide 3: 서비스 흐름 (30초)**

사용자는 먼저 **로그인**합니다.

그 다음 **공지를 텍스트로 직접 입력하거나 PDF 파일을 업로드**합니다.

그럼 **Claude AI가 마감일, 제출물, 장소 같은 정보를 자동으로 추출**해줍니다.

사용자는 **AI 결과를 직접 수정**할 수 있고, **중복 일정이 있는지 감지**한 후 **저장**하면 **캘린더에 자동 등록**됩니다.

---

## **Slide 4: 기술 아키텍처 (30초)**

기술적으로는 **3계층 아키텍처**를 사용했습니다.

**Frontend는 Vercel의 React + Vite**로 사용자 인터페이스를 담당하고,

**Backend는 Render의 Express**로 라우팅과 검증을 담당하고,

**Database는 Supabase의 PostgreSQL**로 데이터를 저장합니다.

여기에 **Claude API**를 통합해서 실제 AI 분석을 수행합니다.

---

## **Slide 5: Claude API 활용 (30초)**

우리는 **프롬프트 엔지니어링**으로 Claude AI를 최적화했습니다.

시스템 프롬프트에서 AI의 역할을 명확히 정의하고, **일정명, 마감일, 제출물 추출 방식을 명시**합니다.

그리고 **JSON Schema로 응답 형식을 고정**해서 파싱 오류를 줄입니다.

이렇게 하면 **정확한 형식으로 일정 정보를 추출**할 수 있습니다.

---

## **Slide 6: 핵심 기능 (1) (40초)**

첫 번째 핵심 기능은 **AI 공지 분석**입니다.

**Claude API (claude-opus-4-8)를 실제로 사용**하고, 프롬프트를 여러 번 최적화해서 **정확도를 높였습니다**.

두 번째는 **PDF 텍스트 추출**입니다.

**pdf-parse 라이브러리로 PDF에서 실제 텍스트를 추출**하고, Multer로 파일을 안전하게 처리합니다.

세 번째는 **사용자가 AI 결과를 직접 수정하고 저장**할 수 있는 기능입니다.

---

## **Slide 7: 핵심 기능 (2) (30초)**

네 번째 기능은 **중복 감지 로직**입니다.

**같은 사용자 + 같은 일정명 + 같은 날짜**라면 중복으로 판단하고 경고 팝업을 띄웁니다.

마지막으로 **데이터 검증**이 중요합니다.

**JSON Schema로 API 응답 형식을 확인**하고, **타임아웃 시 1회 재시도**하며, **다양한 날짜 형식을 통일**합니다.

---

## **Slide 8: 4주 개발 과정 (40초)**

**1주차**에는 기획과 설계를 했습니다. 사용자 시나리오, 기술 아키텍처, UI를 정했습니다.

**2주차**에는 기반을 구축했습니다. JWT 인증을 구현하고, PDF 입력 기능을 만들고, Mock 데이터로 분석 결과를 테스트했습니다.

**3주차**가 가장 중요했습니다. **Claude API를 실제로 통합**하고, **사용자가 수정할 수 있는 UI를 만들고**, **일정을 저장하는 기능을 완성**했습니다.

**4주차**에는 배포 준비를 했습니다. **SQLite에서 PostgreSQL로 마이그레이션**하고, Vercel-Render 환경에 실제로 배포했습니다.

---

## **Slide 9: 배포 & 마이그레이션 (30초)**

**SQLite에서 PostgreSQL로 마이그레이션한 이유**는 3가지입니다.

첫째, **데이터 영속성**입니다. SQLite는 파일 기반이라 서버 재시작 시 손실될 수 있습니다.

둘째, **확장성**입니다. PostgreSQL은 동시성 처리가 우수합니다.

셋째, **자동 백업**입니다. Supabase에서 자동으로 백업하고 복구합니다.

배포는 **Vercel (Frontend), Render (Backend), Supabase (Database)**를 사용했습니다.

---

## **Slide 10: 기술 성취 & 배운 점 (30초)**

저희가 이루어낸 것들입니다.

**Full-Stack 배포**: Vercel-Render-Supabase를 성공적으로 연결했습니다.

**Claude AI 프로덕션 사용**: 단순히 테스트가 아니라 실제 서비스에서 사용 중입니다.

**PDF 텍스트 추출**: 실제 라이브러리로 PDF에서 텍스트를 추출합니다.

**데이터베이스 마이그레이션**: 데이터 손실 없이 성공적으로 마이그레이션했습니다.

**가장 중요한 배운 점**: API 통합할 때는 완벽한 응답을 기대하지 말고, **견고한 검증 로직을 만드는 것이 중요**합니다.
