# PlaceSync 개발 Task 및 백로그

## 1. 문서 목적

이 문서는 PlaceSync의 2주차 이후 개발 작업을 정리하기 위한 백로그 문서입니다.

본격적인 기능 개발을 시작하기 전에 어떤 기능을 먼저 만들고, 어떤 작업을 나중으로 미룰지 정리해 두면 개발 중 방향이 흔들리지 않습니다. PlaceSync는 4주 안에 MVP를 완성하는 것이 목표이므로, 실제 서비스 수준의 모든 기능을 한 번에 구현하기보다 핵심 사용자 흐름을 먼저 완성하는 방식으로 진행합니다.

---

## 2. 백로그란?

백로그는 앞으로 개발해야 할 작업 목록을 우선순위에 따라 정리한 것입니다.

개발을 진행하다 보면 해야 할 일이 계속 늘어나기 때문에, 백로그를 만들어두면 다음 내용을 명확하게 관리할 수 있습니다.

- 지금 가장 먼저 해야 할 작업
- MVP에 반드시 필요한 기능
- 시간이 부족하면 미룰 수 있는 기능
- 현재 진행 중인 작업
- 완료된 작업
- 이후 확장 단계에서 검토할 작업

PlaceSync에서는 백로그를 통해 기획, 디자인, 프론트엔드, 백엔드, 발표 준비 작업을 함께 관리합니다.

## 3. 백로그 관리 기준

### 3.1 우선순위

| 우선순위 | 의미 |
|---|---|
| P0 | MVP에 반드시 필요한 핵심 기능 |
| P1 | 가능하면 구현해야 하는 주요 기능 |
| P2 | 시간이 남으면 구현하거나 이후 확장 단계에서 검토할 기능 |

### 3.2 상태

| 상태 | 의미 |
|---|---|
| Todo | 아직 시작하지 않은 작업 |
| In Progress | 진행 중인 작업 |
| Done | 완료한 작업 |
| Later | 이번 MVP 이후로 미룰 작업 |

## 4. 개발 방향

PlaceSync의 첫 번째 MVP는 실제 네이버, 카카오, 배달앱 API를 바로 연동하는 것이 아니라, **소상공인 사장님이 매장 정보를 수정하고 플랫폼별 적용 결과를 확인하는 흐름**을 완성하는 데 집중합니다.

핵심 사용자 흐름은 다음과 같습니다.

```text
대시보드
→ 매장 정보 수정
→ 플랫폼별 적용값 미리보기
→ 최종 승인
→ 업데이트 결과 확인
→ 실패 플랫폼 수동 수정
```

초기 MVP에서는 실제 DB와 외부 플랫폼 API 대신 Mock 데이터와 Mock API를 사용합니다.

## 10. MVP 범위

### 10.1 MVP에 포함할 기능

이번 MVP에서 반드시 구현할 기능은 다음과 같습니다.

- 매장 정보 조회
- 메뉴 가격 수정
- 플랫폼별 가격 정책 적용
- 메뉴별 가격 예외 적용
- 플랫폼별 적용값 미리보기
- 업데이트 승인
- 업데이트 결과 상태 표시
- 실패 플랫폼 수동 수정 안내

### 10.2 MVP에서 제외할 기능

이번 MVP에서 제외할 기능은 다음과 같습니다.

- 실제 네이버, 카카오, 배달앱 API 연동
- 실제 DB 저장
- 로그인
- 다중 매장 관리
- 결제 기능
- 실제 알림 발송 기능
- 실제 플랫폼 계정 인증 연동

## 13. 작업 관리 방식

PlaceSync의 개발 Task는 우선 Markdown 문서로 관리합니다.

Google Sheet나 Notion을 사용하지 않고 Markdown을 선택한 이유는 다음과 같습니다.

- GitHub에서 바로 확인 가능
- PR에서 변경 내역 확인 가능
- 프로젝트 문서와 같은 저장소에서 관리 가능
- 별도 도구 없이 수정 가능

작업이 많아지거나 팀원과 역할을 나누게 되면 이후 GitHub Issues 또는 Project Board로 확장할 수 있습니다.
