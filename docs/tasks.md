# 개발 Task 관리

`docs/plan.md`(기획)와 `docs/checklist.md`(완료 이력)를 실제 실행 순서로 정리한 문서. 2주차부터 본격적으로 개발을 시작하기 전에, 무엇을 언제 할지 미리 정해두기 위해 작성한다.

## 백로그란?

**왜 필요한가:** 하고 싶은/해야 할 작업을 떠오르는 대로 흘려보내지 않고 한곳에 모아두면, 지금 당장 할 일과 나중에 할 일을 구분할 수 있고, 우선순위를 판단할 근거가 생긴다.

**어떻게 생겼는가:** 보통 "아직 안 한 작업 목록"이며, 각 항목에 제목, 간단한 설명, 우선순위, 상태(할 일/진행 중/완료/보류) 정도가 붙는다. 꼭 정교한 티켓일 필요는 없고, 이 프로젝트에서는 markdown 목록으로도 충분하다.

**어떻게 관리하는가:** 새 아이디어가 생기면 바로 추가하고, 시작할 때 "진행 중"으로, 끝나면 "완료"로 옮긴다. 이 프로젝트는 사실 `docs/checklist.md`의 "동료 피드백 반영(실행 후보/blocked)", "데이터 품질", "향후 확장" 섹션이 이미 백로그 역할을 해왔다 — 이 문서는 그걸 실행 순서(우선순위 + 주차별 계획) 관점으로 재구성한 것이다.

## 관리 위치

Google Sheet/Notion 대신 **markdown**(이 파일)으로 관리한다. 이 프로젝트가 이미 `plan.md`/`checklist.md`를 같은 방식으로 관리해왔고, 별도 도구 계정 없이 레포에서 바로 확인·수정할 수 있기 때문이다. README에서 이 문서로 링크한다.

### 2주차 — 확정된 주간 계획 (2026-07-22)

> 아래는 2주차 월요일 "주간 계획 세우기"를 거쳐 확정한 실제 계획이다. 이전의 AI 챗봇 우선 초안은 폐기 — 실제 주간 목표는 **수직슬라이스(검색 기능, Meilisearch)** 완성이다. Supabase 테이블 작업은 3주차 강의 자료 도착 전까지 의도적으로 제외하고, 이번 주는 Meilisearch 자체를 저장소로 삼아 수직슬라이스를 완성한다.

- **Day 1 (화요일 미션 마무리):** `CommandListPage.jsx` 손코딩 — `useState` 3개(`commands`/`isLoading`/`error`) + `useEffect`로 mock 데이터 fetch 흉내, import 정리, 로딩/에러 렌더링 분기. mock 데이터로 검색 결과 리스트 흐름 확인.
- **Day 2 (수요일 미션):** 화면 다듬기 + 단일 책임 원칙으로 컴포넌트 분리 연습(검색창/결과리스트 분리 등), props/콜백으로 부모-자식 통신 연습, Meilisearch 인덱스에 넣을 필드 스펙 확정(Supabase 컬럼 설계는 3주차로 보류).
- **Day 3 (목요일 미션, 조정):** Meilisearch Cloud 가입 + 인덱스 생성, 정적 `commands.js` 데이터를 인덱스에 업로드(Supabase 거치지 않고 직접), Express `/api/search` 라우트 구현, `searchService.js`를 실제 fetch 호출로 교체, 화면→서버→Meilisearch조회→응답→화면갱신 수직슬라이스 완성, 기능검증 Agent 제작 + 검증.
- **Day 4 (여유/버퍼):** 계획 수립 Agent 제작(월요일 미션 3번), GitHub Project 칸반 정리, PR 마무리.
