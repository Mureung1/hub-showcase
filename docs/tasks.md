# 바로진료 개발 Task 및 백로그

## 1. 문서 목적

이 문서는 바로진료의 4주 개발 범위와 우선순위, 진행 상태를 한곳에서 관리하는 상위 백로그입니다.

- 이 문서: 무엇을 언제 개발할지 관리
- [개발 체크리스트](./checklist.md): 각 Task를 실제 구현 가능한 작은 단위로 분해
- [기능 명세](./feature-spec.md): 기능의 규칙과 완료 조건 확인

## 2. 백로그란?

백로그는 프로젝트에서 구현하거나 검토해야 할 작업을 우선순위에 따라 모아 둔 목록입니다. 새로운 요구사항은 바로 개발하지 않고 먼저 백로그에 추가한 뒤, 문제 정의와 MVP에 필요한지 검토하여 우선순위를 정합니다.

## 3. 관리 기준

### 우선순위

| 우선순위 | 의미 | 적용 기준 |
|---|---|---|
| `P0` | MVP 필수 | 없으면 당일 원격 웨이팅의 핵심 흐름이 동작하지 않음 |
| `P1` | MVP 보완 | 핵심 흐름을 더 안전하고 완성도 있게 만듦 |
| `P2` | 향후 확장 | 외부 API, 운영 자동화 또는 서비스 확장에 필요함 |

### 진행 상태

| 상태 | 의미 |
|---|---|
| `Todo` | 아직 시작하지 않은 작업 |
| `In Progress` | 현재 진행 중인 작업 |
| `Done` | 구현과 확인을 마친 작업 |
| `Later` | MVP 이후로 미룬 작업 |

Task를 완료할 때는 코드 작성만 끝내지 않고 완료 조건을 직접 확인하고, 필요한 자동 테스트와 문서를 함께 갱신합니다.

## 4. 개발 방향

1. 인증과 데이터 기반을 먼저 구성합니다.
2. 원격 환자와 현장 환자가 같은 순서에 들어가는 통합 대기열을 완성합니다.
3. 6번째·4번째 알림, 도착 기한과 미도착 처리를 자동화합니다.
4. 병원 검색과 입점 신청은 mock 데이터로 완성합니다.
5. 실제 알림톡·공공 API·지도·배포는 P2로 분리합니다.

목표: 인증과 대기열 기능을 구현할 수 있는 데이터 기반을 완성합니다.

- [x] React·Express·공통 패키지 개발 환경 구성
- [x] lint·typecheck·test·build 명령 구성
- [x] Supabase 프로젝트, CLI와 migration 구조 구성
- [x] `pg` Repository와 개발용 seed 데이터 구성
- [x] 이메일 인증, Brevo SMTP와 역할별 권한 구현
- [x] 환자 수·순서·예상 시간 계산 및 단위 테스트

목표: 순서 변화에 따른 안내와 미도착 처리를 자동화합니다.

## 8. MVP 범위

### 포함

- 이메일 확인을 거친 환자·병원 관리자 로그인
- 가족 인원을 실제 환자 수로 반영하는 원격 웨이팅
- 병원별 하루 1개 원격·현장 통합 대기열
- 현재 순서와 참고용 예상 대기시간
- 6번째 준비 알림, 4번째 입장 요청과 20분 도착 기한
- 미도착 시 마지막 1회 이동 후 자동 취소
- 현장 환자 상태 링크와 병원 전화 취소 안내
- 병원 검색, 입점 신청과 알림톡의 mock 처리

### 제외

- 예약 진료와 진료 내용 관리
- 실제 카카오 알림톡·SMS 발송
- 실제 공공기관 병원 검증과 지도 API
- 여러 의사·진료과별 대기열
- 병원 전산 시스템 연동
- 플랫폼 관리자 전체 기능
- 외부 공개 배포

## 9. 관리 방법

1. 작업 시작 전에 해당 행의 상태를 `In Progress`로 바꿉니다.
2. 세부 구현은 [개발 체크리스트](./checklist.md)의 항목으로 진행합니다.
3. 완료 조건, 테스트와 문서 반영을 확인한 뒤 `Done`으로 바꿉니다.
4. 새 요구사항은 먼저 이 문서에 추가하고 P0 범위와 교환할 작업이 있는지 확인합니다.
5. P2 항목은 MVP 완료 전에는 구현하지 않습니다.
