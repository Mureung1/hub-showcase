## 1. 도입 (약 30초)

_(ARCHITECTURE.md 맨 위를 띄운 채로)_

"안녕하세요, N011 권혁준입니다. 제가 만드는 건 **역기획소**, 게임 기획자 지망생이 역기획서를 쓰고 사람이랑 AI 양쪽에서 피드백받는 서비스예요.

이번 과제가 **내 서비스 구조를 그림 한 장으로 그려보기**였는데요. 솔직히 처음엔 '이미 내가 짠 코드인데 그린다고 뭐가 나오겠나' 싶었어요. 근데 결론부터 말하면 — **그리다가 권한 구멍을 여섯 개 찾았고, 오늘 그거 메꾸는 게 작업의 절반이었습니다.** 그 이야기를 하려고 해요.

도구는 **mermaid**를 썼어요. 텍스트로 쓰면 그림이 되는 문법인데, 코드처럼 diff가 남아서 구조가 바뀌면 그림도 같이 고칠 수 있고 GitHub README에서 바로 렌더링됩니다."

_(스크롤 ↓ — 다이어그램 ①)_

## 2. 전체 구조 (약 1분 30초)

_(전체 구조 flowchart를 가리키며)_

"먼저 전체 그림이에요. 왼쪽이 화면, 가운데가 서버, 오른쪽이 DB. 세 덩어리입니다.

왼쪽 React 화면이 11개 있는데, 얘네가 데이터를 가져올 때 **전부 `storage.js`라는 파일 하나를 거쳐요.** 화면이 Supabase를 직접 부르는 데가 없습니다. 이게 왜 좋았냐면 — 원래 이 서비스가 localStorage에 저장하던 프로토타입이었거든요. 그걸 실제 서버로 바꿀 때 **함수 이름이랑 모양은 그대로 두고 안쪽만 갈아끼워서**, 화면 코드는 거의 안 건드리고 넘어갔어요.

_(점선을 가리키며)_

근데 딱 하나 예외가 있어요. **이 점선.** 로그인만 화면이 Supabase를 직접 부릅니다. 백엔드를 거치게 하면 비밀번호를 서버가 중계해야 하고 구글 로그인 리다이렉트도 서버가 떠안게 돼서, 여기만 예외로 뒀어요. 대신 받아온 토큰은 **서버가 다시 한 번 검증합니다.** 프론트가 '나 로그인했어요' 한다고 그냥 믿지 않아요.

그리고 오른쪽 아래 빨간 거 — anon 키로 DB 직접 접근하는 건 막혀 있다는 표시인데, 이건 뒤에서 다시 말씀드릴게요. **그리다가 발견한 것 중 하나**예요."

_(스크롤 ↓ — 다이어그램 ②)_

## 3. 발행 → AI 피드백 (약 1분)

_(시퀀스 다이어그램을 가리키며)_

"두 번째는 시간 순서 그림이에요. 사용자가 '발행' 누른 다음에 뭐가 일어나는지.

여기서 설계상 신경 쓴 게 두 개인데요.

하나는 — **발행할 때 새 행을 만들지 않아요.** 쓰던 초안 행의 상태값만 '초안'에서 '발행'으로 뒤집습니다. 새로 만들었으면 작성 중에 달린 코멘트랑 처음 만든 시각이 날아가거든요.

또 하나는 — **AI 코멘트를 서버가 직접 DB에 씁니다.** 프론트가 받아서 다시 저장하는 구조였으면 중복 저장되거나 중간에 유실될 수 있어서, 서버 안에서 끝냈어요.

그리고 여기 보시면 _(AI 실패 분기를 가리키며)_ **AI가 실패해도 발행은 성공으로 처리해요.** Gemini가 안 될 때 글이 안 써지면 안 되니까요. 근데 이것도 뒤에 문제가 있었습니다."

_(스크롤 ↓ — 다이어그램 ③, 인증 표)_

## 4. 그리다 발견한 것 (약 2분) — 여기가 핵심

_(라우트별 인증 표를 가리키며)_

"자, 여기가 오늘 제일 하고 싶은 얘기예요.

세 번째 그림이 인증이랑 권한인데, 그리다가 **'그럼 API마다 로그인이 필요한지 아닌지 표로 정리해볼까' 해서 이 표를 만들었어요.** 라우트 하나씩 적고, 옆에 어떤 미들웨어가 붙는지 적고.

_(comments 줄을 가리키며)_

그러다가 — **이 줄만 비어 있었어요.** 코멘트 다는 API에 아무 미들웨어가 없었던 거예요.

솔직히 코드를 위에서 아래로 읽을 땐 전혀 안 보였어요. 라우트가 열 개 넘는데 각각 몇십 줄씩이고, 순서대로 읽으면 '아 이건 이렇게 동작하는구나' 하고 넘어가거든요. 근데 **표로 같은 축에 정렬하니까 빈 칸이 그냥 튀어나왔어요.**

그래서 뭐가 문제냐면 — 코멘트 만들 때 작성자 이름이랑 'AI가 쓴 건지' 표시를 **클라이언트가 보낸 값을 그대로** 저장하고 있었어요. 그러니까 요청을 조금만 조작하면 **사람이 쓴 댓글을 AI 피드백 배지 달고** 올릴 수 있었던 거예요. 제 서비스는 AI 피드백이 핵심 기능이라, 그 라벨을 믿을 수 없으면 제품 자체가 무너집니다.

_(§4로 스크롤)_

그래서 이걸 고치러 들어갔는데, **같은 성격의 문제가 줄줄이 나왔어요.** 전부 '클라이언트가 보낸 걸 서버가 그냥 믿는다'는 한 가지 패턴이었어요.

- **남의 초안이 다 보였어요.** 초안 목록 API가 로그인 안 해도 전체 초안을 돌려주고 있었어요. 남의 미완성 습작이 열리는 거죠.
- **문서 고쳐서 다시 발행하면 그동안 받은 코멘트가 다 지워졌어요.** 에디터가 발행할 때 '코멘트 빈 배열'을 같이 보내는데 서버가 그걸 그대로 덮어썼거든요. 이건 보안이 아니라 그냥 데이터 날아가는 버그였어요.
- **DB에 옆문이 열려 있었어요.** 아까 그 점선 그리면서 '저 anon 키로 로그인 말고 다른 것도 되나?' 싶어서 확인해봤더니, 되더라고요. 테이블 보안 설정이 꺼져 있어서 그 키만으로 DB를 통째로 읽을 수 있었어요. **백엔드에 권한 검사를 아무리 붙여도 옆문이 열려 있으면 소용이 없죠.**
- **AI 미리보기로 하루 사용 제한을 우회할 수 있었어요.** '저장 안 하니까 안 세도 되겠지' 했는데, 돈 드는 건 저장이 아니라 **호출**이더라고요.

_(회귀 테스트 표를 가리키며)_

이거 다 오늘 고쳤고, **다시 열리지 않게 테스트로 잠갔어요.** 백엔드 테스트 21개 전부 통과합니다."

_(스크롤 ↓)_

## 5. 배운 것 (약 1분)

"정리하면요.

저는 다이어그램이 **다 만든 다음에 남 보여주려고 그리는 것**인 줄 알았어요. 문서 작업, 장식 같은 거요.

근데 아니었어요. **그림은 빈칸을 보이게 하는 도구**였습니다.

제 코드는 다 제가 쓴 거고 다 안다고 생각했는데, 라우트 열 몇 개를 표 하나에 세로로 세우니까 **비어 있는 칸이 그냥 눈에 띄었어요.** 코드를 읽을 땐 각 파일이 따로 놀아서 안 보였던 게, 같은 축에 정렬하니까 보인 거예요.

화살표를 그리면서 '**이 화살표는 왜 있지**' 하고 묻게 되는 것도 컸어요. 프론트에서 Supabase로 가는 점선을 그리면서 '이 키로 다른 것도 되나?' 하고 확인해본 게 DB 옆문 찾은 계기였거든요. 코드만 읽었으면 그 질문 자체를 안 했을 거예요.

그래서 앞으로도 기능 하나 끝날 때마다 그림을 **고치면서** 갈 생각이에요. mermaid로 그린 이유도 그거고요 — 텍스트니까 코드 고치듯 같이 고칠 수 있어서요."

## 6. 남은 것 (약 30초)

"마지막으로 아직 못 고친 게 하나 있는데요.

코멘트를 지금 문서 안에 통째로 넣어놨어요. 그래서 코멘트 하나 달 때마다 **문서 전체를 읽고 → 붙이고 → 다시 쓰는** 구조예요. 두 사람이 동시에 달면 뒤에 쓴 사람이 앞사람 걸 덮어씁니다.

이건 표 하나 새로 만들어서 떼어내야 하는 거라 오늘은 못 했고, 백로그에 올려놨어요. 알림이나 '내가 쓴 코멘트' 기능도 이거 먼저 해야 만들 수 있어서 다음 순서로 갑니다.

여기까지입니다. 감사합니다."

## 예상 질문 대비

**"왜 mermaid예요? Figma나 draw.io 안 쓰고?"**
→ "마우스로 그리면 코드 바뀔 때마다 다시 그려야 하는데, 그럼 결국 안 고치게 되더라고요. mermaid는 텍스트라서 코드랑 같은 PR에 넣고 같이 리뷰할 수 있어요. GitHub README에서 바로 그림으로 보이는 것도 크고요."

**"AI한테 그려달라고 한 거 아니에요?"**
→ "코드 읽고 초안 뽑는 건 AI를 썼어요. 근데 **빈칸을 발견한 건 표를 보면서였고**, 그게 왜 문제인지 판단하고 어떻게 고칠지 정한 건 제가 했어요. 예를 들어 남의 초안 막을 때 403 말고 **404로 숨긴 것** — 403은 '있긴 있다'를 알려주니까요. 그런 판단들이요."

**"보안 구멍이 그렇게 많았으면 원래 설계가 잘못된 거 아니에요?"**
→ "인정해요. 근데 패턴이 하나였어요 — **'클라이언트를 믿는다'.** 문서 CRUD엔 처음부터 권한을 걸었는데, 코멘트나 조회는 '가벼운 거니까' 하고 넘어간 거죠. 이제는 **새 라우트 만들 때마다 저 표에 줄부터 추가**하려고요. 칸을 채우려면 미들웨어를 정해야 하니까 빠뜨릴 수가 없어요."
