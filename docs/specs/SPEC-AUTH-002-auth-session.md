- 상태: **Ready (Step 1~3 확정, 구현 대기)**

## 0. 고정 사항 (정책 확정)

### 0.1 한 줄 목표

로그인 세션이 새로고침·브라우저 재시작 후에도 유지되고, 세션 변화(로그인·로그아웃·만료)에 앱 전체가 즉시 반응하며, 라우트 가드가 로그인 상태에 맞게 동작한다.

### 0.2 기존 문서에서 오는 고정 규칙

- SPEC-AUTH-001 0.3에서 이관된 범위: 새로고침 세션 복원·자동 로그인 유지·토큰 갱신·라우트 가드 고도화.
- React는 Supabase Auth 기능에 한해 Supabase Client를 직접 사용한다. 컴포넌트는 SDK를 직접 호출하지 않고 `features/auth`의 Service/Hook을 거친다 (CLAUDE.md 7장).
- Express JWT 검증·API 연동은 SPEC-AUTH-003. 서비스 데이터(Chat·Question 등)는 이 Spec에서도 여전히 Mock.
- 이메일 인증 완료가 서비스 이용의 필수 조건 (CLAUDE.md 2장). 가입 직후 자동 로그인 없음 (AUTH-001 결정 2-3).
- 현재 구현(T-012): `AuthProvider`가 마운트 시 `getInitialSession()` 1회만 확인. 리로드 시 localStorage 세션 복원은 실측으로 확인됨.

### 0.3 제외 범위

- Express Auth Middleware·API 연동 (→ SPEC-AUTH-003)
- userId의 공통 계약(`@decision-log/shared`) 추가 (→ SPEC-AUTH-003에서 재검토 — 결정 3-1)
- 비밀번호 재설정 (→ SPEC-AUTH-004, 보류)
- 서비스 데이터의 사용자별 저장 (→ SPEC-DB-001)

## 2. 세션 관리

- `AuthProvider`가 마운트 시 `onAuthStateChange`를 구독하고 언마운트 시 해지한다. 초기 세션은 구독 시작과 함께 확인한다 (기존 `getInitialSession` 1회 호출을 대체 또는 보완 — 구현 재량).
- 구독이 반영해야 하는 이벤트: 로그인(SIGNED_IN), 로그아웃(SIGNED_OUT), 토큰 갱신(TOKEN_REFRESHED). 그 외 이벤트는 필요한 경우에만 처리한다.
- Supabase SDK 호출은 기존 원칙대로 `authService`·`useAuth` 경유. 구독 로직도 auth feature 내부에 둔다.
- LoginPage·WorkspacePage가 수동으로 하던 `setSession`/`clearSession` 갱신은 구독으로 일원화할 수 있으면 정리한다 (동작 동일 조건, 과도한 리팩터링 금지).
- 세션 저장·복원은 Supabase 기본(localStorage) 그대로 사용한다 (결정 1-1). 별도 저장 코드를 만들지 않는다.

## 3. 라우트 가드·리다이렉트

- `RequireAuth`(보호 라우트 `/`): 세션 없으면 `/login`. 초기 확인 중에는 중앙 스피너 (결정 2-3, 현재 동작 유지).
- 역방향 가드(신규): 로그인 상태에서 `/login`·`/signup` 진입 시 `/`로 리다이렉트한다 (결정 1-3). `/verify-email`은 대상에서 제외 — 가입 직후 흐름과 직접 진입(결정 2-1) 모두 현재 동작을 유지한다.
- 세션 만료·로그아웃으로 세션이 사라지면 보호 라우트에 있던 화면은 `/login`으로 이동한다.

## 4. 세션 만료·로그아웃 안내

- **만료로 인한 이동**(결정 1-2): `/login` 도착 시 "세션이 만료되었습니다. 다시 로그인해주세요" 안내를 폼 위나 아래에 표시한다. 전달 방식(라우터 state 등)은 구현 재량이되, 새로고침 후에도 문구가 계속 남지 않게 한다.
- **사용자가 직접 로그아웃**한 경우에는 만료 안내를 표시하지 않는다 (AUTH-001의 확인 팝업 → `/login` 흐름 유지).
- **탭 간 동기화**(결정 2-2): 다른 탭의 로그아웃을 구독 이벤트로 감지해 즉시 `/login`으로 이동한다. 이 경우 안내 문구는 만료 문구와 구분하지 않아도 된다 (구현 재량).

## 5. 구현 노트

- 새 패키지 없음. 기존 `features/auth` 구조(authService·AuthContext·useAuth·RequireAuth)를 확장한다.
- 파생 가능한 값을 중복 state로 만들지 않는다 (CLAUDE.md 7장). 세션의 단일 소유자는 AuthProvider.
- 오류를 숨기는 임시 우회 코드를 남기지 않는다. 구독 실패·SDK 미설정(`isSupabaseConfigured=false`) 상태에서도 앱이 크래시 없이 동작해야 한다 (T-012 패턴 유지).

## 6. Acceptance Criteria

- [~] AC1. 로그인 후 브라우저를 완전히 종료하고 다시 열어 `/` 진입 시, 로그인 화면 없이 워크스페이스가 열린다 (세션 복원). — **대체 측정 PASS(2026-07-20)**: 새 탭 `/` 진입·리로드 시 로그인 없이 워크스페이스 열림(구독 INITIAL_SESSION으로 localStorage 세션 복원). **완전 종료 후 복원은 자동화 한계로 미측정 → 사용자 수동 확인 항목**
- [x] AC2. 로그인 상태에서 `/login`·`/signup` 주소로 진입하면 `/`로 리다이렉트된다. — **실측 PASS**: 로그인 상태에서 `/login`·`/signup` 모두 `/`로 리다이렉트(RedirectIfAuthenticated). `/verify-email`은 대상 제외
- [x] AC3. 탭 2개를 열고 한 탭에서 로그아웃하면, 다른 탭도 즉시 `/login`으로 이동한다. — **실측 PASS**: 탭 A 로그아웃 확인 → 탭 B가 상호작용 없이 즉시 `/login`으로 이동(구독 크로스탭 SIGNED_OUT). 탭 간 안내 문구는 표시하지 않음(Spec 4장 구현 재량)
- [x] AC4. 세션 만료 시 `/login`으로 이동하고 "세션이 만료되었습니다" 안내가 표시된다. — **실측 PASS**: localStorage 세션의 `expires_at` 과거·`refresh_token` 무효화 후 리로드 → 갱신 실패 → `/login` 이동 + "세션이 만료되었습니다. 다시 로그인해주세요" 배너. 재리로드 시 배너 소멸(잔존 금지 확인). 직접 로그아웃(탭 A)에는 배너 미표시 확인
- [ ] AC5. (SPEC-AUTH-001 AC4 전반 이관 재측정) Gmail `+별칭` 신규 계정으로 가입(메일 1통, 인증 링크 클릭 금지) 후 로그인 시도 → "이메일 인증을 완료해주세요" + 재발송 버튼이 표시된다(재발송 클릭 금지). 통과 시 SPEC-AUTH-001 7장 AC4를 `[x]`로 갱신한다. — **2차 실측 예정**(메일 발송 제한으로 T-013 1차에서 분리, 메일 미발송)
- [x] AC6. `npm run typecheck / lint / build` 통과. 기존 happy-path(로그인 → 질문 → 충돌 해소 → FinalAnswer → 노트)와 로그아웃 확인 팝업이 회귀 없이 동작한다. — **실측 PASS**: 검사 3종 통과, 재로그인 후 happy-path(질문→충돌 2건 해소→FinalAnswer→DecisionNote) 회귀 없음, 로그아웃 확인 팝업 정상
