# 화면 흐름 정의서

## 1. 문서 목적

이 문서는 나만의 레시피북 MVP의 주요 화면과 사용자 이동 흐름을 정의한다.
각 화면은 PRD에서 정의한 MVP 기능과 정책을 바탕으로 구성한다.

---

## 2. 핵심 사용자 흐름 요약

나만의 레시피북 MVP의 핵심 흐름은 다음과 같다.

1. 사용자가 로그인한다.
2. 내 레시피북에서 저장된 레시피 목록을 확인한다.
3. URL 또는 직접 입력으로 레시피를 추가한다.
4. AI가 정리한 결과를 확인하고 수정한다.
5. 정리된 레시피를 내 레시피북에 저장한다.
6. 저장된 레시피 상세 내용을 확인한다.
7. 내가 등록한 레시피를 열람 공유 또는 전달 공유한다.
8. 전달받은 사용자는 관계 라벨을 입력하고 자신의 레시피북에 저장한다.

---

## 3. 전체 화면 목록

### 3.1 온보딩 / 로그인 화면

서비스에 처음 진입했을 때 보여주는 화면이다.

#### 목적

* 서비스의 핵심 가치를 전달한다.
* 사용자가 Google 로그인을 통해 내 레시피북으로 진입하게 한다.

#### 화면 요소

* 서비스 이름
* 서비스 한 줄 소개
* Google 계정으로 로그인 버튼

#### 예시 문구

> 흩어진 레시피를 AI로 정리하고, 전해준 사람과의 기억까지 함께 보관하세요.

---

### 3.2 내 레시피북 화면

사용자가 저장한 레시피 목록을 확인하는 메인 화면이다.

#### 목적

* 저장된 레시피를 확인한다.
* 내가 등록한 레시피와 전달받은 레시피를 구분한다.
* 새로운 레시피를 추가할 수 있게 한다.

#### 화면 요소

* 서비스 이름
* 사용자 이름
* 레시피 추가 버튼
* 레시피 목록 탭

  * 전체
  * 내가 등록한 레시피
  * 전달받은 레시피
* 레시피 카드 목록

#### 레시피 카드 공통 표시 정보

- 레시피 이름
- 간단한 설명
- 레시피 유형
- 저장일 또는 수정일

#### 내가 등록한 레시피 카드 추가 정보

- 출처 URL 여부에 따라 출처
- 공유 상태

#### 전달받은 레시피 카드 추가 정보

- 전해준 사람
- 관계 라벨
- 전달받은 날짜
- 재공유 불가 표시

#### 예시 카드

```text
김치찌개
엄마에게 받은 레시피
전달받은 날짜: 2026.07.09
재공유 불가
```

---

### 3.3 레시피 추가 화면

사용자가 URL, 직접 입력, 또는 두 가지를 함께 사용해 새로운 레시피를 추가하는 화면이다.  
또한 전달 공유 초대 코드를 입력해 전달받은 레시피 저장 흐름으로 진입할 수 있다.

#### 목적

* 사용자가 외부 URL 또는 직접 입력으로 레시피 정보를 추가한다.
* URL과 직접 입력이 함께 있는 경우 AI가 두 정보를 합쳐 정리한다.
* URL이 입력된 경우 시스템은 해당 URL을 출처로 저장한다.
* URL이 없고 직접 입력만 있는 경우 내가 등록한 레시피로 저장한다.
* 전달받은 레시피 저장 흐름은 별도 초대 코드 입력 화면으로 분리한다.

#### 화면 요소

* URL 입력창
* 레시피 원문 / 추가 메모 입력창
* AI로 정리하기 버튼
* 전달받은 레시피 코드 입력 진입 문구
* 취소 버튼

#### 전달받은 레시피 코드 입력 진입 문구 예시

```text
전달받은 레시피가 있나요? 코드로 불러오기
```

#### 입력 규칙

* URL 또는 직접 입력 중 최소 하나는 입력되어야 한다.
* URL만 입력된 경우 URL을 바탕으로 AI가 정리한다.
* 직접 입력만 있는 경우 입력된 문장을 바탕으로 AI가 정리한다.
* URL과 직접 입력이 모두 있는 경우 AI가 두 정보를 합쳐 정리한다.
* URL이 입력된 경우 출처 URL을 저장한다.
* 공개 `youtube.com`, `youtu.be` 영상 URL은 제목·채널명을 출처로 표시하고 공개 자막을 우선 사용한다. 자막 조회 실패 시 Gemini 영상 분석으로 대체하며, 모든 YouTube 처리 실패 시 기존 오류 상태에서 직접 입력을 안내한다. 썸네일은 표시하거나 저장하지 않는다.
* 블로그나 웹페이지 URL인 경우 가능하면 페이지 제목과 작성자 정보를 출처 정보로 함께 저장한다.
* 전달받은 초대 코드 입력은 레시피 직접 추가와 별개의 흐름으로 처리한다.

#### 사용자 행동

1. 사용자가 URL 또는 레시피 원문을 입력한다.
2. AI로 정리하기 버튼을 누른다.
3. AI 정리 결과 확인 화면으로 이동한다.
4. 전달받은 레시피가 있는 경우 “코드로 불러오기”를 눌러 초대 코드 입력 화면으로 이동한다.

---

### 3.4 AI 정리 결과 확인 화면

AI가 정리한 결과를 저장하기 전에 사용자가 확인하고 수정하는 화면이다.
AI 정리 결과는 최종본이 아니라 사용자가 편집할 수 있는 초안으로 제공된다.

#### 목적

* AI 정리 결과를 확인한다.
* 사용자가 정리된 내용을 바로 수정할 수 있게 한다.
* 수정된 내용을 내 레시피북에 저장할 수 있게 한다.

#### 화면 요소

* 음식 이름 입력 영역
* 레시피 설명 입력 영역
* 기준 인원 입력 영역
* 예상 조리 시간 입력 영역
* 재료 목록 편집 영역
* 조리 순서 편집 영역
* 확인이 필요한 항목
* 출처 정보
* 저장하기 버튼
* 취소 버튼

#### 확인이 필요한 항목 예시

```text
“김치를 적당히” → 약 2컵 기준으로 정리했습니다.
“물은 자작하게” → 약 500ml 기준으로 정리했습니다.
“간장 조금” → 1큰술 기준으로 정리했습니다.
```

#### 사용자 행동

1. 사용자가 AI 정리 결과를 확인한다.
2. 필요한 내용을 화면에서 바로 수정한다.
3. 저장하기 버튼을 누른다.
4. 저장 완료 후 레시피 상세 화면 또는 내 레시피북 화면으로 이동한다.

---

### 3.5 레시피 상세 화면

저장된 레시피의 상세 내용을 확인하는 화면이다.

#### 목적

* 레시피의 재료와 조리 순서를 확인한다.
* 레시피 유형에 따라 가능한 행동을 제공한다.

#### 공통 화면 요소

* 레시피 이름
* 설명
* 기준 인원
* 예상 조리 시간
* 재료
* 조리 순서
* 출처 정보

#### 내가 등록한 레시피의 화면 요소

* 수정 버튼
* 삭제 버튼
* 열람 공유 버튼
* 전달 공유 버튼
* 내 메모
* 열람 링크 상태
  - 공유 안함(생성X)
  - 열람 링크 활성화
  - 열람 링크 비활성화

#### 전달 받은 레시피의 화면 요소

* 전해준 사람
* 관계 라벨
* 전달받은 날짜
* 재공유 불가 표시
* 내 메모
* 내 메모 작성/수정 버튼
* 내 레시피북에서 제거 버튼

#### 링크로 열람 중인 레시피의 화면 요소

* 레시피 내용
* 저장 불가 안내
* 재공유 불가 안내

#### 조리 중 보기 상태

레시피 상세 화면에서 사용자가 실제 조리 중 레시피를 더 편하게 볼 수 있도록 제공하는 보기 상태이다.

MVP에서는 별도의 조리 모드 화면을 만들지 않고, 레시피 상세 화면 안에서 조리 중 보기 토글을 제공한다.

##### 목적

* 조리 중 실수로 수정, 삭제, 공유 버튼을 누르는 일을 방지한다.
* 사용자가 레시피 내용을 방해 없이 확인할 수 있게 한다.
* 별도 조리 모드 화면 없이 모바일 주방 사용성을 보완한다.

##### 조리 중 보기 ON 상태에서 숨기는 요소

* 수정 버튼
* 삭제 버튼
* 열람 공유 버튼
* 전달 공유 버튼
* 내 레시피북에서 제거 버튼

##### 조리 중 보기 ON 상태에서 유지하는 요소

* 레시피 이름
* 설명
* 기준 인원
* 예상 조리 시간
* 재료
* 조리 순서
* 출처 정보
* 내 메모
* 조리 중 보기 종료 버튼

### 3.6 레시피 수정 화면

사용자가 자신이 등록한 레시피를 수정하는 화면이다.

#### 목적

* 저장된 레시피 내용을 수정할 수 있게 한다.

#### 수정 가능한 항목

* 레시피 이름
* 설명
* 기준 인원
* 예상 조리 시간
* 재료
* 조리 순서
* 출처 정보
* 메모

#### 수정 불가능한 경우

전달받은 레시피는 원본 내용을 수정할 수 없다.
전달받은 레시피에서는 개인 메모만 수정할 수 있다.

### 3.7 열람 공유 링크 생성 화면

내가 등록한 레시피를 다른 사람이 보기만 할 수 있도록 링크를 생성하는 화면이다.

#### 목적

* 레시피를 열람 전용으로 공유한다.

#### 화면 요소

* 레시피 이름
* 열람 링크 상태
* 열람 링크 생성 버튼
* 생성된 링크
* 링크 복사 버튼
* 링크 비활성화 버튼
* 열람 공유 안내 문구

#### 안내 문구

```text
이 링크를 가진 사람은 레시피를 볼 수 있지만,
자신의 레시피북에 저장하거나 다시 공유할 수 없습니다.
```

---

### 3.8 열람 공유 화면

다른 사용자가 열람 링크로 접속했을 때 보는 화면이다.

#### 목적

* 링크를 통해 레시피를 열람하게 한다.
* 저장 공유와 열람 공유의 차이를 명확히 보여준다.

#### 화면 요소

* 레시피 이름
* 재료
* 조리 순서
* 출처 정보
* 열람 전용 표시
* 저장 불가 안내
* 재공유 불가 안내

#### 안내 문구

```text
이 레시피는 열람 전용으로 공유되었습니다.
내 레시피북에 저장하거나 다시 공유할 수 없습니다.
```

---

### 3.9 전달 공유 초대 생성 화면

내가 등록한 레시피를 다른 사용자가 자신의 레시피북에 저장할 수 있도록 전달 링크 또는 초대 코드를 생성하는 화면이다.

#### 목적

* 레시피를 다른 사용자에게 전달한다.
* 전달받은 레시피가 관계 정보와 함께 저장되도록 한다.

#### 화면 요소

* 레시피 이름
* 전달 링크 생성 버튼
* 생성된 전달 링크
* 초대 코드
* 링크 복사 버튼
* 코드 복사 버튼
* 전달 공유 안내 문구

#### 안내 문구

```text
전달받은 사용자는 이 레시피를 자신의 레시피북에 저장할 수 있습니다.
저장 시 전해준 사람과 전달받은 날짜가 함께 기록되며,
전달받은 레시피는 다시 공유할 수 없습니다.
```

---

### 3.10 전달 초대 코드 입력 화면

사용자가 전달받은 초대 코드를 입력해 전달받은 레시피 수락 흐름으로 진입하는 화면이다.

#### 목적

* 레시피 추가 흐름과 전달받은 레시피 수락 흐름을 분리한다.
* 사용자가 공유받은 초대 코드를 입력할 수 있게 한다.
* 유효한 코드인 경우 전달받은 레시피 미리보기 화면으로 이동한다.

#### 화면 요소

* 초대 코드 입력창
* 코드 확인 버튼
* 취소 버튼
* 안내 문구

#### 안내 문구 예시

```text
전달받은 초대 코드를 입력하면,
공유된 레시피를 미리 확인한 뒤 내 레시피북에 저장할 수 있습니다.
```

#### 입력 규칙

* 초대 코드는 비어 있을 수 없다.
* 유효한 코드인 경우 전달받은 레시피 미리보기 화면으로 이동한다.
* 이미 사용된 코드는 사용할 수 없다.
* 만료된 코드는 사용할 수 없다.
* 잘못된 코드는 오류 메시지를 보여준다.

#### 사용자 행동

1. 사용자가 초대 코드를 입력한다.
2. 코드 확인 버튼을 누른다.
3. 코드가 유효하면 전달받은 레시피 미리보기 화면으로 이동한다.
4. 코드가 유효하지 않으면 오류 메시지를 확인한다.
5. 취소하면 레시피 추가 화면 또는 내 레시피북 화면으로 돌아간다.

---

### 3.11 전달받은 레시피 미리보기 화면

사용자가 전달 링크나 초대 코드로 접근했을 때, 전달받은 레시피를 저장하기 전에 미리 확인하는 화면이다.

#### 목적

* 전달받은 레시피의 내용을 저장 전에 확인한다.
* 사용자가 수락 또는 거절을 선택할 수 있게 한다.
* 사용자가 수락한 경우에만 관계 정보 입력 영역을 보여준다.
* 관계 정보를 입력한 뒤 자신의 레시피북에 저장할 수 있게 한다.

#### 초기 상태 화면 요소

* 공유한 사용자 정보
* 레시피 미리보기
* 원 저장자 정보
* 재공유 불가 안내
* 수락 버튼
* 거절 버튼

#### 초기 상태 안내 문구 예시

```text
이 레시피를 내 레시피북에 저장할 수 있습니다.
저장한 뒤에는 원본 내용을 수정할 수 없고, 개인 메모만 작성할 수 있습니다.
```

#### 수락 후 상태 화면 요소

사용자가 수락 버튼을 누르면 관계 정보 입력 영역을 표시한다.

* 전해준 사람 입력창
* 관계 라벨 입력창
* 내 메모 입력창
* 내 레시피북에 저장하기 버튼
* 취소 버튼

#### 수락 후 안내 문구 예시

```text
이 레시피를 누구에게서 받았는지 기록해 주세요.
입력한 정보는 내 레시피북에서 이 레시피의 관계 정보로 표시됩니다.
```

#### 입력 규칙

* 전해준 사람은 필수 입력값이다.
* 관계 라벨은 필수 입력값이다.
* 내 메모는 선택 입력값이다.
* 저장이 완료되면 전달 초대는 사용 완료 상태가 된다.
* 전달받은 레시피는 다시 공유할 수 없다.
* 전달받은 레시피의 원본 내용은 수정할 수 없다.

#### 사용자 행동

1. 사용자가 전달 링크에 접속하거나 초대 코드를 입력한다.
2. 전달받은 레시피 미리보기 화면으로 이동한다.
3. 사용자가 레시피 내용을 확인한다.
4. 저장을 원하면 수락 버튼을 누른다.
5. 수락 후 전해준 사람, 관계 라벨, 내 메모 입력 영역이 표시된다.
6. 사용자가 전해준 사람과 관계 라벨을 입력한다.
7. 내 레시피북에 저장하기 버튼을 누른다.
8. 저장 완료 후 전달받은 레시피 상세 화면으로 이동한다.
9. 저장을 원하지 않으면 거절 버튼을 누르고 흐름을 종료한다.

#### 거절 처리

* 거절 시 레시피는 내 레시피북에 저장되지 않는다.
* MVP에서는 거절만으로 초대를 만료시키지 않는다.
* 초대는 수락 완료 시에만 만료 처리한다.


---

### 3.12 저장 완료 안내

레시피 저장이 완료되었음을 사용자에게 알려주는 안내이다.  
저장 완료 안내는 별도 화면, 모달, 또는 토스트 메시지로 제공할 수 있다.
MVP 프로토타입에서는 저장 후 레시피 상세 화면으로 이동하고, 상단에 저장 완료 메시지를 표시한다.
