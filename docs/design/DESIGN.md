# 대학 축제 웹사이트 디자인 시스템

## 기준 시안

- 확정 방향: `Today Simple`
- 대상 화면: 모바일 우선 대학 축제 가이드
- 핵심 목적: 축제 당일 방문객이 현재 상황과 다음 행동을 3초 안에 파악한다.

이 디자인 시스템은 `docs/plan/v1.0.0.md`의 프론트엔드 MVP를 기준으로 한다. MVP의 주요 화면은 홈, 타임테이블, 부스, 공지사항이며, 첫 구현은 모바일 사용성을 우선한다.

## 디자인 원칙

### 1. 한 화면에 하나의 주요 판단만 제공

홈 화면은 모든 정보를 보여주는 대시보드가 아니다. 사용자가 가장 먼저 알아야 할 정보만 크게 보여준다.

- 현재 날짜와 시간
- 부스 운영 상태
- 다음 일정 1개
- 중요 공지 1개
- 주요 기능 진입점

긴 목록, 복잡한 필터, 전체 배치도는 각 상세 화면에서 다룬다.

### 2. 야외 환경에서도 읽히는 시인성

축제 현장은 밝고 산만하다. 작은 장식보다 큰 글자, 높은 대비, 넓은 터치 영역을 우선한다.

- 핵심 숫자와 시간은 크게 표시한다.
- 본문은 14px 미만으로 내려가지 않는다.
- 정보 구분은 색보다 간격과 굵기로 먼저 처리한다.
- 긴 문장은 피하고 짧은 라벨을 사용한다.

### 3. 친근하지만 기능적인 축제 서비스

축제 분위기는 색상과 아이콘으로만 가볍게 표현한다. 포스터처럼 꾸미지 않고, 실제 현장에서 바로 쓰는 모바일 유틸리티처럼 만든다.

- 배경은 흰색 중심으로 유지한다.
- 강조색은 녹색을 기본으로 한다.
- 보조 기능에는 파랑, 주황을 제한적으로 사용한다.
- 그라디언트, 과한 그림자, 장식용 배경 요소는 사용하지 않는다.

## 색상

### 기본 팔레트

| 용도 | 토큰 | 값 | 사용처 |
| --- | --- | --- | --- |
| 배경 | `--color-bg` | `#ffffff` | 전체 화면 배경 |
| 보조 배경 | `--color-surface` | `#f6f8f5` | 다음 일정 카드, 공지 행 |
| 기본 텍스트 | `--color-text` | `#050505` | 제목, 주요 정보 |
| 보조 텍스트 | `--color-muted` | `#4b5563` | 위치, 시간, 설명 |
| 약한 텍스트 | `--color-subtle` | `#6b7280` | 보조 라벨 |
| 선 | `--color-border` | `#e5e7eb` | 구분선, 버튼 테두리 |
| 주요 강조 | `--color-primary` | `#16a34a` | CTA, 활성 상태, 운영 중 |
| 주요 강조 어두움 | `--color-primary-strong` | `#15803d` | 버튼 hover/active |
| 파랑 보조 | `--color-blue` | `#2563eb` | 부스 진입점 |
| 주황 보조 | `--color-orange` | `#f97316` | 공지 진입점 |
| 경고/중요 | `--color-warning` | `#f59e0b` | 날씨, 주의 안내 |

### 사용 규칙

- 녹색은 서비스의 기본 액션과 긍정 상태에만 사용한다.
- 파랑은 부스 관련 진입점에 사용한다.
- 주황은 공지나 주의가 필요한 정보에 사용한다.
- 한 화면에서 강조색은 3개를 넘기지 않는다.
- 배경 전체에 컬러 블록을 깔지 않는다.

## 타이포그래피

### 폰트

시스템 기본 산세리프를 사용한다.

```css
font-family:
  Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont,
  "Segoe UI", sans-serif;
```

추후 한글 가독성을 더 다듬을 경우 `Pretendard` 또는 `Noto Sans KR`을 검토한다.

### 크기 체계

| 토큰 | 크기 | 굵기 | 사용처 |
| --- | --- | --- | --- |
| `display` | 64px | 800 | 현재 시간, 핵심 숫자 |
| `title-xl` | 32px | 800 | 화면 주요 제목 |
| `title-lg` | 26px | 800 | 섹션 제목 |
| `title-md` | 22px | 700 | 카드 제목, 일정명 |
| `body-lg` | 18px | 500 | 주요 상태, 버튼 |
| `body` | 16px | 400 | 기본 본문 |
| `body-sm` | 14px | 400 | 보조 정보 |
| `label` | 14px | 700 | 작은 라벨 |

### 타이포그래피 규칙

- 홈의 현재 시간은 `display`로 크게 표시한다.
- 일정명, 화면명, 주요 CTA는 굵게 표시한다.
- 본문 줄 높이는 1.5 이상으로 둔다.
- 한 줄 라벨은 가능한 12자 내외로 유지한다.

## 레이아웃

### 모바일 기준

- 기준 너비: 390px
- 최소 지원 너비: 320px
- 화면 좌우 여백: 24px
- 섹션 간격: 32px
- 관련 요소 간격: 12px 또는 16px
- 하단 내비게이션 높이: 76px 내외

### 구조

홈 화면은 다음 순서로 구성한다.

1. 상단 헤더
2. 오늘 날짜와 현재 시간
3. 오늘의 축제 상태
4. 다음 일정 카드
5. 중요 공지 행
6. 주요 기능 바로가기
7. 하단 내비게이션

긴 목록 화면은 홈보다 정보 밀도를 높일 수 있지만, 기본적으로 행 단위 리스트와 구분선을 우선한다. 카드 남발은 피한다.

## 형태와 간격

### 반경

- 기본 반경: 8px
- 큰 CTA/카드: 8px
- 작은 pill/status dot: 필요 시 원형

8px보다 큰 둥근 모서리는 사용하지 않는다. 전체 UI가 과하게 앱 카드처럼 보이지 않게 한다.

### 그림자

기본적으로 그림자를 사용하지 않는다. 분리가 필요하면 먼저 배경색, 간격, 구분선을 사용한다.

허용되는 경우:

- 중요한 CTA가 배경과 구분되지 않을 때
- 하단 내비게이션이 콘텐츠와 겹칠 때

그림자를 쓰더라도 매우 약하게 적용한다.

## 아이콘

아이콘은 선형 스타일을 기본으로 한다.

- 권장 라이브러리: `lucide-react`
- 기본 크기: 24px
- 큰 바로가기 아이콘: 32px
- 선 두께: 2px 내외

### 아이콘 매핑

| 기능 | 아이콘 방향 | 색상 |
| --- | --- | --- |
| 홈 | 집 | 녹색 |
| 타임테이블 | 캘린더 | 녹색 |
| 부스 | 매장/텐트 | 파랑 |
| 공지 | 확성기/벨 | 주황 |
| 위치 | 핀 | 보조 텍스트 |
| 시간 | 시계 | 보조 텍스트 |

아이콘만으로 의미를 전달하지 않는다. 주요 액션에는 항상 텍스트 라벨을 함께 둔다.

## 컴포넌트

### Header

상단 헤더는 서비스명과 알림 아이콘만 둔다.

- 서비스명: 굵은 28-32px
- 알림 아이콘: 우측 정렬
- 새 알림은 작은 녹색 점으로 표시

### Today Status

현재 날짜, 시간, 날씨 또는 운영 상태를 보여주는 영역이다.

- 날짜에서 월/일은 녹색으로 강조 가능
- 현재 시간은 가장 큰 시각 요소로 표시
- 날씨는 보조 정보이므로 우측에 작게 배치

날씨 데이터가 없는 MVP에서는 날씨 영역을 생략해도 된다.

### Next Event Card

홈의 핵심 컴포넌트다.

필수 정보:

- 라벨: `다음 일정`
- 시작 시간
- 일정명
- 위치
- 진행 시간
- CTA: `전체 타임테이블 보기`

규칙:

- 카드 안에는 다음 일정 1개만 표시한다.
- CTA는 녹색 채움 버튼으로 한다.
- 부가 설명은 2줄을 넘기지 않는다.

### Notice Row

중요 공지는 한 줄 행으로 처리한다.

- 좌측: 공지 아이콘과 `중요 공지` 라벨
- 중앙: 공지 제목 1줄
- 우측: 이동 화살표

긴 공지 본문은 공지 상세 화면에서만 보여준다.

### Quick Actions

주요 기능 진입점은 3개로 제한한다.

- 타임테이블
- 부스
- 공지

각 항목은 아이콘, 라벨, 이동 표시만 포함한다. 설명 문장은 넣지 않는다.

### Bottom Navigation

하단 내비게이션은 4개 이하로 유지한다.

- 홈
- 타임테이블
- 부스
- 더보기 또는 공지

현재 활성 탭은 녹색 아이콘과 라벨로 표시한다. 비활성 탭은 회색 또는 검정 70% 수준으로 둔다.

## 화면별 적용

### 홈

목표: 지금 필요한 대표 정보를 빠르게 보여준다.

- 현재 시간과 오늘 상태를 가장 크게 표시
- 다음 일정 1개만 노출
- 중요 공지 1개만 노출
- 상세 탐색은 바로가기와 하단 내비게이션으로 이동

### 타임테이블

목표: 날짜와 카테고리별 일정을 빠르게 훑는다.

- 상단에 날짜 선택
- 그 아래 카테고리 탭
- 일정은 시간순 리스트로 표시
- 상세 화면은 MVP 범위에서 만들지 않는다.

### 부스

목표: 부스 위치, 운영 시간, 메뉴와 가격을 찾는다.

- 상단에 날짜 선택
- 검색과 카테고리 필터 제공
- 배치도 이미지는 리스트 위에 단일 영역으로 표시
- 부스 목록은 행 단위로 구성
- 부스 상세에서 메뉴와 가격을 더 자세히 표시

### 공지사항

목표: 축제 운영 안내와 변경 사항을 확인한다.

- 중요 공지는 목록 상단에 먼저 배치
- 목록에는 제목, 날짜, 작성자를 표시
- 상세 화면에는 본문과 작성 정보를 표시

## 접근성

- 모든 터치 대상은 최소 44px 높이를 확보한다.
- 텍스트와 배경 대비는 WCAG AA 수준을 목표로 한다.
- 색상만으로 상태를 구분하지 않는다. `운영 중`, `중요 공지` 같은 텍스트를 함께 제공한다.
- 하단 내비게이션과 주요 CTA는 키보드 포커스 스타일을 제공한다.
- 아이콘 버튼에는 접근 가능한 이름을 제공한다.

### 우선순위

1. 홈 화면의 시인성과 구조를 먼저 고정한다.
2. 타임테이블, 부스, 공지는 같은 헤더/탭/리스트 규칙을 재사용한다.
3. 실제 데이터가 들어오기 전까지는 정적 mock 데이터를 사용한다.
4. 새로운 컴포넌트를 만들기 전에 기존 패턴으로 해결 가능한지 확인한다.
