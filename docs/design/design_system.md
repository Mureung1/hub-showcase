# RecipeBook Design System

버전: 1.0  
기준 구현: `src/App.jsx`, `src/index.css`

## 1. 목적

이 문서는 RecipeBook의 책 콘셉트를 다른 화면에도 일관되게 적용하기 위한 디자인 및 구현 기준이다.

핵심 원칙은 다음과 같다.

- 데스크톱은 펼쳐진 가죽 레시피북처럼 보인다.
- 태블릿과 모바일은 책의 재질과 언어를 유지하되, 한 번에 하나의 작업에 집중한다.
- 종이 위의 정보는 읽기 쉬워야 하며, 장식은 정보보다 앞서지 않는다.
- 화면 바깥으로 스크롤되는 책 오브젝트를 만들지 않는다. 책 자체는 뷰포트 안에 맞춘다.

## 2. 디자인 토큰

### 색상

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--leather-900` | `#102b23` | 가죽 내비게이션, 기본 버튼 |
| `--leather-800` | `#15332a` | 강조 버튼, 선택 탭 |
| `--leather-700` | `#163229` | 가죽 프레임 내부 |
| `--paper-50` | `#fbf7eb` | 밝은 종이, 아이콘 버튼 |
| `--paper-100` | `#f8f5eb` | 페이지 기본 배경 |
| `--paper-line` | `#d8cfbd` | 종이 구분선 |
| `--ink-900` | `#272923` | 제목과 본문 주요 글자 |
| `--ink-600` | `#626157` | 설명 및 보조 텍스트 |
| `--gold-400` | `#e3c580` | 가죽 위 금박 텍스트 |
| `--gold-600` | `#aa8c4b` | 선택 메뉴 테두리 |
| `--memory-red` | `#a5543d` | 기억 카드의 출처와 하트 |

새 화면에서는 파랑, 보라 등 별도의 강조색을 추가하지 않는다. 상태 표현은 가죽의 명도, 금박 테두리, 종이 위의 잉크 농도로 해결한다.

### 타이포그래피

기본 글꼴 순서:

```css
font-family: "Noto Serif KR", "Nanum Myeongjo", "Malgun Gothic", serif;
```

| 역할 | 크기 | 굵기 | 사용 예 |
| --- | ---: | ---: | --- |
| 페이지 제목 | 31px | 600 | 내 레시피북, 레시피명 |
| 섹션 제목 | 17px | 600 | 재료, 만드는 방법 |
| 목록 제목 | 22px | 500 | 레시피 목록 행 |
| 본문 | 11.5~13px | 400 | 조리법, 설명 |
| 메타 정보 | 9~12px | 400 | 날짜, 시간, 출처 |
| 가죽 메뉴 | 15~17px | 400 | 레시피북, 검색 |

한 화면 안에서는 제목에만 넉넉한 자간을 사용한다. 본문과 수치에는 과도한 자간을 적용하지 않는다.

### 모서리와 그림자

- 종이 페이지: `3~5px`
- 입력창, 팁 카드, 기억 카드: `9~10px`
- 가죽 버튼: `8~9px`
- 다음 레시피 버튼: 원형
- 그림자는 검정색 대신 가죽 및 종이의 갈색 계열을 낮은 투명도로 사용한다.


프레임은 데스크톱 및 넓은 태블릿에서만 사용한다. 모바일에서는 화면 공간을 확보하기 위해 제거한다.

## 4. 레이아웃 규칙

### 데스크톱: 1101px 이상

```
┌────────── 가죽 사이드바 ──────────┬──── 왼쪽 종이 ────┬──── 오른쪽 종이 ────┐
│ 브랜드                              │ 레시피 목록       │ 선택된 레시피 상세  │
│ 주요 메뉴                            │ 검색, 목록, 추가  │ 재료, 조리법, 기억   │
│ 목록 필터                            │                   │ 다음 레시피           │
└─────────────────────────────────────┴──────────────────┴─────────────────────┘
```

- 책 프레임은 뷰포트보다 커지지 않는다.
- 책 프레임은 사방 10px 안전 여백을 제외한 뷰포트를 사용한다: `calc(100vw - 20px) × calc(100dvh - 20px)`
- 페이지는 항상 좌우 2면으로 유지한다.
- 사이드바 폭: 186px
- 종이 페이지는 동등한 비율로 나눈다.
- 오른쪽 가장자리의 장 탭은 MVP에서 제외한다.

### 태블릿: 701px~1100px

- 가죽 사이드바와 왼쪽 종이 목록을 우선 표시한다.
- 상세 화면은 목록 항목을 선택한 뒤 단일 페이지로 전환한다.
- 상세 화면에는 `← 목록` 버튼을 노출한다.
- 다음 레시피 버튼은 상세 페이지의 페이지 전환 흐름과 충돌하므로 숨긴다.

### 모바일: 700px 이하

- 상단의 가죽 헤더와 단일 종이 페이지를 사용한다.
- 사이드바는 햄버거 메뉴 안에서 열리는 오프캔버스 메뉴다.
- 목록은 한 화면에 들어오도록 행 높이와 썸네일을 축소한다.
- 목록에서 레시피를 고르면 상세 페이지로 전환하고, 좌측 상단의 `← 목록`으로 돌아온다.
- 상세 내용이 화면보다 길 때는 종이 상세 영역 안에서만 읽을 수 있다. 문서 전체가 스크롤되지 않게 한다.

### 낮은 높이 화면: 높이 840px 이하

- 가죽 메뉴의 행 높이와 종이 패딩을 줄인다.
- 제목, 썸네일, 기억 카드를 한 단계 축소한다.
- 책 프레임 바깥으로 콘텐츠가 넘치지 않도록 `min-height: 0`과 `overflow: hidden`을 유지한다.

## 5. 재사용 컴포넌트

### `BookFrame`

책 전체를 감싸는 최상위 컨테이너다.

필수 규칙:

- `width: calc(100vw - 20px)`
- `height: calc(100dvh - 20px)`
- `overflow: hidden`
- 가죽 프레임과 텍스처는 pseudo-element로 구현한다.
- 내부 Grid 아이템에는 `min-height: 0`을 준다.

### `Sidebar`

가죽 위의 브랜드, 주요 메뉴, 레시피 필터를 제공한다.

- 주요 메뉴: 레시피북, 검색, 새 레시피, 전달 코드, 설정
- 필터: 모든 레시피, 내가 만든, 전해 받은, 최근 펼친
- 필터는 별도 종이 열을 만들지 않고 가죽 메뉴 아래에 둔다.
- 선택 메뉴는 금박 테두리와 낮은 투명도의 밝은 배경을 사용한다.

### `RecipeList`

레시피 목록을 종이 페이지에 표시한다.

필수 props:

```ts
type Recipe = {
  title: string
  note: string
  date: string
  time: string
  memory: string
  image?: boolean
  page?: string
}

type RecipeListProps = {
  selectedRecipe: Recipe
  onSelect: (recipe: Recipe) => void
}
```

행 상태:

- 기본: 종이 구분선만 표시
- Hover: 제목을 `--memory-red` 계열로 변경
- Selected: 금박 테두리로 선택 상태를 표시
- 키보드: Enter 및 Space로 선택 가능해야 한다.

썸네일은 항상 `flex: 0 0 auto`로 유지하고, 좁은 화면에서는 58px까지 축소한다. 텍스트 컨테이너에는 `min-width: 0`을 주어 이미지가 잘리지 않게 한다.

### `RecipeDetail`

선택된 레시피의 제목, 설명, 인분, 시간, 재료, 조리법, 기억을 표시한다.

필수 props:

```ts
type RecipeDetailProps = {
  recipe: Recipe
  onBack: () => void
  onNext: () => void
}
```

구현 규칙:

- 데스크톱에서는 목록의 선택 상태와 즉시 동기화한다.
- 모바일 및 태블릿에서는 상세 진입 시 `← 목록`을 표시한다.
- 우측 하단 원형 화살표는 `다음 레시피`다. 목록으로 돌아가는 역할에 재사용하지 않는다.

### `MemoryCard`

기억 카드에는 다음 순서를 유지한다.

1. `이 레시피와 함께 기억하는 것`
2. 짧은 인용문
3. 하트 아이콘과 출처

인용문은 2줄 안팎을 권장한다. 카드의 높이를 늘려 장식처럼 보이게 하지 않는다.

## 6. 상호작용 규칙

| 행동 | 결과 |
| --- | --- |
| 목록 행 클릭 | 선택 테두리 변경, 상세 페이지 즉시 변경 |
| 목록 행 Enter 또는 Space | 클릭과 동일 |
| 다음 레시피 화살표 | 다음 레시피를 선택하고 상세 변경 |
| 모바일 목록 행 클릭 | 상세 단일 페이지로 전환 |
| 모바일 `← 목록` | 목록 단일 페이지로 복귀 |
| 메뉴 버튼 | 현재 MVP에서는 시각적 메뉴 상태만 제공. 기능 연결 시 라우팅을 추가한다. |

## 7. 페이지별 조합 가이드

### 메인 레시피북

- `BookFrame + Sidebar + RecipeList + RecipeDetail`
- 데스크톱의 기본 화면이다.

### 레시피 추가

- `BookFrame + Sidebar + PaperPage`
- 종이 페이지 안에 `URL 가져오기`, `직접 입력`, `공유 코드 입력`을 세로로 배치한다.
- 주요 CTA는 가죽 버튼을 사용한다.

### 레시피 초안 편집

- 데스크톱: 왼쪽에 입력 필드, 오른쪽에 정리된 미리보기 페이지를 둔다.
- 모바일: 입력을 우선하고, 미리보기는 별도 전환으로 제공한다.
- 저장 버튼은 항상 가죽 질감의 단일 Primary 버튼이다.

### 저장 완료

- 종이 한 면에 저장 완료 메시지와 `gold-book-emblem.png` 또는 `gold-leaf-sprig.png`를 사용한다.
- 장식보다 다음 행동, 예: `레시피북으로 돌아가기`를 우선한다.

## 8. 구현 체크리스트

- [ ] `html`, `body`, `#root`에 `overflow: hidden`이 적용됐는가?
- [ ] `BookFrame`이 `100dvh`를 넘지 않는가?
- [ ] Grid 또는 Flex 자식에 `min-height: 0`이 필요한가?
- [ ] 모바일에서 책 프레임과 9-slice 테두리를 제거했는가?
- [ ] 목록 썸네일이 좁은 화면에서 잘리지 않는가?
- [ ] 목록 선택이 상세 데이터와 연결됐는가?
- [ ] 모바일 상세에 목록 복귀 버튼이 있는가?
- [ ] 다음 레시피와 목록 복귀에 서로 다른 아이콘을 사용했는가?
- [ ] 가죽 버튼의 텍스트 대비가 충분한가?

## 9. 금지 사항

- 종이 필터 열을 다시 추가하지 않는다.
- MVP 화면에 장 분류 탭을 추가하지 않는다.
- 가죽 텍스처를 종이 본문 전체에 사용하지 않는다.
- 같은 화면에서 여러 종류의 강조색을 사용하지 않는다.
- 모바일에서 데스크톱의 펼친 두 면을 억지로 축소하지 않는다.
- 화면 전체 세로 스크롤로 책 오브젝트가 잘리는 상태를 만들지 않는다.
