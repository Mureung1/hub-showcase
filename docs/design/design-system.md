# 디자인 시스템

## 1. 목적

이 문서는 부동산 의사결정 보조 서비스의 UI 일관성을 유지하기 위한 기준이다.

모든 화면과 컴포넌트는 이 문서와 `frontend/src/styles/tokens.css`를 기준으로 구현한다.  
새로운 스타일이 필요할 경우 기존 규칙으로 해결할 수 있는지 먼저 확인하고, 반복될 가능성이 있는 값은 디자인 토큰으로 추가한다.

---

## 2. 디자인 방향

### 핵심 키워드

- 신뢰감 있는
- 차분한
- 정돈된
- 명확한
- 접근 가능한
- 데이터 중심의

### 기본 원칙

- 장식보다 정보 전달을 우선한다.
- 사용자가 다음 행동을 쉽게 이해할 수 있도록 시각적 위계를 명확히 한다.
- 한 화면에서 가장 중요한 행동 하나만 강하게 강조한다.
- 가격, 비용, 거리, 이동 시간, 위험 요소처럼 의사결정에 중요한 정보는 쉽게 비교할 수 있어야 한다.
- 카드, 버튼, 입력창마다 임의의 스타일을 만들지 않고 공통 규칙을 재사용한다.
- 과도한 그림자, 그라데이션, 장식용 효과를 사용하지 않는다.
- 모바일 환경에서도 입력과 확인이 편해야 한다.

---

## 3. 레퍼런스 적용 원칙

메인 UI 레퍼런스의 다음 특징을 적용한다.

- 연한 회색 페이지 배경
- 흰색 카드와 입력 영역
- 파란색 중심의 강조 색상
- 얇은 테두리
- 둥근 모서리
- 넉넉한 여백
- 최소한의 그림자
- 명확한 탭과 선택 상태

다음 요소는 그대로 사용하지 않는다.

- 관리자 페이지용 사이드바
- 불필요한 검색창
- 지나치게 작은 보조 텍스트
- 데스크톱에서 입력 항목을 무리하게 여러 열로 배치하는 방식
- 넓은 화면을 억지로 채우는 레이아웃

레퍼런스와 이 문서의 규칙이 충돌하면 이 문서를 우선한다.

## 4. 색상

### 기본 색상 토큰

| 역할 | 값 | 사용처 |
|---|---:|---|
| Primary | `#2563EB` | 주요 버튼, 진행 상태, 선택 상태 |
| Primary Hover | `#1D4ED8` | 주요 버튼 hover |
| Primary Active | `#1E40AF` | 주요 버튼 active |
| Primary Soft | `#DBEAFE` | 선택된 탭, 선택 카드 배경 |
| Background | `#F7F8FA` | 전체 페이지 배경 |
| Surface | `#FFFFFF` | 카드, 입력 영역, 모달 |
| Text Primary | `#27272A` | 제목과 핵심 정보 |
| Text Secondary | `#71717A` | 설명과 보조 정보 |
| Text Muted | `#A1A1AA` | 비활성 정보, 보조 표시 |
| Border | `#E4E4E7` | 카드와 일반 구분선 |
| Border Strong | `#D4D4D8` | 입력창과 강조 경계 |
| Success | `#16A34A` | 긍정 상태, 완료 |
| Success Soft | `#DCFCE7` | 긍정 상태 배경 |
| Warning | `#D97706` | 주의가 필요한 정보 |
| Warning Soft | `#FEF3C7` | 주의 상태 배경 |
| Danger | `#DC2626` | 오류, 위험 정보 |
| Danger Soft | `#FEE2E2` | 오류 상태 배경 |

### 사용 규칙

- Primary 색상은 주요 행동과 선택 상태에만 사용한다.
- 본문과 제목에 Primary 색상을 과도하게 사용하지 않는다.
- Success, Warning, Danger는 의미가 있는 상태에만 사용한다.
- 색상만으로 상태를 전달하지 않는다. 텍스트, 아이콘, 테두리 등을 함께 사용한다.
- 컴포넌트 내부에 색상값을 직접 하드코딩하지 않고 CSS 변수를 사용한다.

## 5. 타이포그래피

### 기본 폰트

```css
font-family: Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
```

Pretendard가 설치되어 있지 않다면 시스템 폰트를 사용한다.  
별도 요청 없이 외부 폰트 패키지를 추가하지 않는다.

### 글자 크기

| 역할 | 크기 | 굵기 | 줄 높이 |
|---|---:|---:|---:|
| Page Title | `28px` | `600` | `1.3` |
| Step Title | `24px` | `600` | `1.35` |
| Section Title | `20px` | `600` | `1.4` |
| Card Title | `18px` | `600` | `1.4` |
| Body | `16px` | `400` | `1.5` |
| Label | `14px` | `500` | `1.45` |
| Helper Text | `14px` | `400` | `1.5` |
| Caption | `12px` | `400` | `1.4` |
| Button | `14px` 또는 `16px` | `600` | `1` |

### 사용 규칙

- 페이지당 Page Title은 하나만 사용한다.
- 입력 항목의 레이블은 placeholder로 대체하지 않는다.
- 가격, 거리, 시간 등 핵심 수치는 일반 본문보다 굵게 표시할 수 있다.
- 주요 정보를 작은 회색 글씨로 표시하지 않는다.
- 모바일에서는 Page Title을 `24px`까지 줄일 수 있다.

## 6. 간격

4px 기반 간격 체계를 사용한다.

| 토큰 | 값 |
|---|---:|
| Space 1 | `4px` |
| Space 2 | `8px` |
| Space 3 | `12px` |
| Space 4 | `16px` |
| Space 5 | `20px` |
| Space 6 | `24px` |
| Space 8 | `32px` |
| Space 10 | `40px` |
| Space 12 | `48px` |
| Space 16 | `64px` |

### 권장 사용

- 아이콘과 텍스트: `4px` 또는 `8px`
- 레이블과 입력창: `8px`
- 도움말과 입력창: `8px`
- 같은 그룹의 폼 항목: `16px`
- 폼 그룹 사이: `24px`
- 주요 섹션 사이: `32px`
- 페이지 상하 여백: `40px` 이상
- 카드 내부 여백: 모바일 `20px`, 데스크톱 `24px`

임의의 간격값을 반복해서 만들지 않는다.

## 7. 모서리

| 역할 | 값 |
|---|---:|
| Small | `8px` |
| Medium | `12px` |
| Large | `16px` |
| Pill | `999px` |

### 적용 기준

- 버튼과 입력창: `8px`
- 탭과 선택 카드: `12px`
- 큰 카드와 입력 섹션: `16px`
- 상태 배지: Pill 형태 사용 가능

화면마다 새로운 반경값을 임의로 추가하지 않는다.

---

## 8. 그림자

그림자는 계층이 실제로 필요한 경우에만 사용한다.

| 역할 | 값 |
|---|---|
| Small | `0 1px 2px rgb(0 0 0 / 0.04)` |
| Medium | `0 4px 12px rgb(0 0 0 / 0.06)` |

### 사용 규칙

- 일반 카드는 기본적으로 테두리만 사용한다.
- 드롭다운, 팝오버, 모달처럼 떠 있는 요소에만 그림자를 사용한다.
- 모든 카드에 진한 그림자를 적용하지 않는다.

---

## 9. 레이아웃

### 사용자 정보 입력 화면

- 콘텐츠 최대 너비: `760px`
- 폼은 기본적으로 한 열을 사용한다.
- 데스크톱에서는 서로 밀접한 숫자 입력만 두 열로 배치할 수 있다.
- 사용자 입력 플로우에서는 사이드바를 사용하지 않는다.
- 주요 콘텐츠는 화면 중앙에 배치한다.
- 배경은 `Background`, 폼 영역은 `Surface`를 사용한다.

### 페이지 여백

- 모바일: 좌우 `20px`
- 태블릿: 좌우 `24px`
- 데스크톱: 좌우 `32px`

### 구조 예시

1. 상단 헤더 또는 서비스명
2. 현재 단계와 진행 상태
3. 질문 제목
4. 질문 설명
5. 입력 카드
6. 오류 또는 도움말
7. 이전 / 다음 버튼

---

## 10. 반응형 기준

### Mobile

- 기준 너비: `767px` 이하
- 모든 주요 입력을 한 열로 배치한다.
- 버튼 최소 높이는 `48px`로 한다.
- 주요 버튼은 전체 너비로 사용할 수 있다.
- 선택 카드는 한 열 또는 두 열로 배치한다.
- 긴 텍스트와 단위가 잘리지 않도록 한다.
- 하단 이전/다음 버튼 영역을 고정할 경우 콘텐츠가 가려지지 않게 여백을 확보한다.

### Tablet

- 기준 너비: `768px` 이상
- 콘텐츠 최대 너비를 유지한다.
- 선택 카드와 밀접한 입력은 두 열 또는 세 열로 배치할 수 있다.

### Desktop

- 기준 너비: `1024px` 이상
- 콘텐츠 최대 너비는 `760px`를 기본으로 한다.
- 화면이 넓어도 입력 영역을 지나치게 늘리지 않는다.
- 빈 공간을 억지로 카드나 장식으로 채우지 않는다.

---

## 11. 버튼

### 공통 규칙

- 최소 높이: 데스크톱 `44px`, 모바일 `48px`
- 기본 좌우 여백: `20px`
- 기본 반경: `8px`
- 버튼 텍스트 굵기: `600`
- 아이콘이 있다면 텍스트와 `8px` 간격을 둔다.
- 모든 버튼은 `default`, `hover`, `focus`, `active`, `disabled`, `loading` 상태를 고려한다.

### Primary Button

사용처:

- 다음 단계
- 분석 시작
- 저장
- 비교 실행

스타일:

- Primary 배경
- 흰색 텍스트
- 한 화면에 하나를 원칙으로 한다.

### Secondary Button

사용처:

- 이전
- 취소
- 보조 행동

스타일:

- 흰색 배경
- Border Strong 테두리
- Text Primary 텍스트

### Text Button

사용처:

- 건너뛰기
- 자세히 보기
- 낮은 우선순위 행동

스타일:

- 배경 없음
- 테두리 없음
- Primary 또는 Text Secondary 텍스트

### Disabled

- 배경과 텍스트 대비를 낮춘다.
- 클릭 및 포커스가 불가능해야 한다.
- 비활성 이유가 명확하지 않다면 도움말을 제공한다.

### Loading

- 버튼 너비가 변하지 않도록 한다.
- 텍스트와 스피너를 함께 표시할 수 있다.
- 중복 제출을 막는다.

---

## 12. 입력창

### 공통 규칙

- 기본 높이: `46px`
- 모바일 권장 높이: `48px`
- 좌우 내부 여백: `14px`
- 배경: Surface
- 테두리: Border Strong
- 반경: `8px`
- 레이블은 입력창 위에 표시한다.
- placeholder는 예시나 형식 안내 용도로만 사용한다.
- 단위가 있는 경우 입력값과 단위를 명확히 구분한다.

### 상태

#### Default

- Border Strong 테두리
- Text Primary 입력값
- Text Muted placeholder

#### Focus

- Primary 테두리
- `3px` 정도의 연한 Primary 포커스 링

#### Filled

- 기본 테두리를 유지한다.
- 별도 색상 변경은 필수가 아니다.

#### Error

- Danger 테두리
- 입력창 아래에 Danger 색상의 오류 메시지
- 오류 메시지는 해당 입력과 프로그램적으로 연결한다.

#### Disabled

- Background 또는 연한 회색 배경
- Text Muted 텍스트
- 입력 불가

#### Read-only

- 입력 불가임을 시각적으로 표현하되 Disabled보다 내용 가독성을 유지한다.

---

## 13. 선택 카드

설명이 필요한 선택지나 비교가 필요한 선택에 사용한다.

예시:

- 거주 목적
- 계약 유형
- 선호 주거 형태
- 중요 조건
- 피하고 싶은 조건

### 기본 스타일

- 흰색 배경
- Border Strong 테두리
- `12px` 반경
- 내부 여백 `16px`
- 제목과 설명을 구분한다.

### 상태

#### Default

- 회색 테두리
- Text Primary 제목
- Text Secondary 설명

#### Hover

- Border Strong보다 진한 테두리
- 배경을 아주 약하게 변경할 수 있다.

#### Focus

- Primary 포커스 링
- 키보드로 선택 가능해야 한다.

#### Selected

- Primary 테두리
- Primary Soft 배경
- 체크 아이콘 또는 명확한 선택 표시
- 색상만으로 선택 여부를 전달하지 않는다.

#### Disabled

- 낮은 대비
- 선택 불가

---

## 14. 탭과 세그먼트 컨트롤

서로 배타적인 화면 또는 옵션 전환에 사용한다.

### 스타일

- 전체 컨테이너는 흰색 또는 연한 회색 배경
- 선택되지 않은 항목은 Text Secondary
- 선택된 항목은 Primary Soft 배경과 Primary 텍스트
- 반경은 `8px` 또는 `12px`
- 현재 선택 상태를 `aria-selected` 등으로 제공한다.

사용자 정보 입력 단계 자체를 탭으로 자유 이동시키는 경우, 이전 단계 데이터 손실이 없어야 한다.

---

## 15. 진행 표시

사용자가 현재 위치와 남은 단계를 이해할 수 있어야 한다.

### 기본 표시

- `1 / 4` 형태의 현재 단계 텍스트
- 진행 바
- 현재 단계 제목

### 진행 바

- 전체 트랙: Border 또는 연한 회색
- 완료 영역: Primary
- 높이: `4px` 또는 `6px`
- 반경: Pill

진행 상태는 색상뿐 아니라 텍스트로도 제공한다.

---

## 16. 카드

### 일반 카드

- 배경: Surface
- 테두리: Border
- 반경: `16px`
- 그림자 없음 또는 Small
- 내부 여백: `20px`~`24px`

### 정보 카드

가격, 거리, 위험 정보 등을 보여주는 카드에서는 다음을 지킨다.

- 제목과 핵심 수치를 명확히 구분한다.
- 긍정, 주의, 위험 상태는 색상과 텍스트를 함께 사용한다.
- 정보가 없는 경우 `정보 없음` 또는 `확인 필요`를 명확히 표시한다.
- 같은 종류의 수치는 같은 형식과 단위를 사용한다.

---

## 17. 상태 메시지

### Success

- 성공 아이콘 또는 체크 표시
- Success 텍스트와 필요 시 Success Soft 배경
- 다음 행동을 안내할 수 있다.

### Warning

- Warning 아이콘과 텍스트
- 사용자가 확인해야 할 내용을 구체적으로 설명한다.

### Error

- 무엇이 잘못되었는지 설명한다.
- 가능한 해결 방법을 함께 안내한다.
- 단순히 `오류가 발생했습니다`만 표시하지 않는다.

### Empty

- 데이터가 없는 이유를 설명한다.
- 가능한 다음 행동을 제시한다.

### Loading

- 레이아웃이 갑자기 움직이지 않도록 한다.
- 긴 작업에는 진행 상황 또는 처리 중 메시지를 표시한다.

---

## 18. 접근성

- 본문 텍스트 대비는 WCAG AA 수준을 목표로 한다.
- 키보드 포커스 표시를 제거하지 않는다.
- 클릭 가능한 요소의 최소 크기는 `44px × 44px`를 목표로 한다.
- 색상만으로 상태를 전달하지 않는다.
- 아이콘 버튼에는 접근 가능한 이름을 제공한다.
- 모든 입력 요소에는 명확한 레이블을 제공한다.
- 오류 메시지는 해당 입력과 연결한다.
- 버튼과 링크의 역할을 시각적·의미적으로 구분한다.
- 모션은 꼭 필요한 경우에만 사용하고 과도한 애니메이션을 피한다.

---

## 19. 아이콘

- 아이콘 스타일은 하나의 선형 또는 채움 스타일로 통일한다.
- 같은 의미에는 같은 아이콘을 사용한다.
- 장식용 아이콘을 과도하게 사용하지 않는다.
- 아이콘만 있는 버튼은 툴팁 또는 접근 가능한 이름을 제공한다.
- 별도 요청 없이 새로운 아이콘 라이브러리를 설치하지 않는다.

---

## 20. 사용자 정보 입력 페이지 패턴

사용자 정보 입력은 다음 구조를 기본으로 한다.

1. 서비스명 또는 간단한 헤더
2. 현재 단계와 진행 표시
3. 질문 제목
4. 질문의 목적을 설명하는 짧은 문장
5. 입력 또는 선택 영역
6. 도움말과 오류 메시지
7. 이전 버튼
8. 다음 단계 버튼

### 입력 원칙

- 한 단계에 관련된 질문만 묶는다.
- 한 화면에 너무 많은 항목을 배치하지 않는다.
- 사용자가 왜 이 정보를 입력해야 하는지 이해할 수 있도록 설명한다.
- 필수와 선택 항목을 명확히 구분한다.
- 입력값은 다음 단계로 이동해도 유지되어야 한다.
- 마지막 단계에서 입력 내용을 검토할 수 있어야 한다.

## 22. 금지 사항

- 컴포넌트마다 색상값을 직접 하드코딩하지 않는다.
- 임의의 간격값을 반복해서 만들지 않는다.
- 새 화면마다 서로 다른 버튼 스타일을 만들지 않는다.
- 기존 공통 컴포넌트가 있는데 중복 구현하지 않는다.
- 과도한 그림자, 그라데이션, 애니메이션을 사용하지 않는다.
- placeholder를 레이블 대신 사용하지 않는다.
- 중요한 정보를 작은 회색 글씨로 표시하지 않는다.
- 선택 상태를 색상만으로 표현하지 않는다.
- 데스크톱 공간을 채우기 위해 불필요한 요소를 추가하지 않는다.
- 사용자 허락 없이 UI 라이브러리나 스타일링 라이브러리를 설치하지 않는다.

## 23. 확장 원칙

현재 문서는 사용자 정보 입력 화면 구현에 필요한 최소 디자인 시스템이다.

다음 기능을 구현할 때 필요한 규칙을 추가한다.

- 매물 스크린샷 업로드
- AI 분석 진행 상태
- 분석 결과 카드
- 매물 저장 목록
- 매물 비교 테이블
- 위험 요소와 주의 표시
- 지도 및 위치 정보

새로운 UI 패턴이 두 번 이상 반복되면 공통 컴포넌트와 디자인 토큰으로 승격한다.
