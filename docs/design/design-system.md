# PtoP Design System

## 목적

PtoP는 프로젝트 정리를 부담스러운 문서 작업이 아니라, 작은 작업실을 탐색하며 지난 경험을 발견하는 과정으로 표현한다.

디자인은 두 영역을 함께 지원해야 한다.

- **게임 공간:** 캐릭터 이동, 컴퓨터와 NPC 상호작용, 분석 이력 탐색
- **업무 화면:** Repository 입력, 분석 진행, 회고 작성, 분석 결과 확인

게임 표현이 핵심 기능을 가리지 않도록 Repository 분석 결과와 근거는 일반적인 웹 UI로 명확하게 제공한다.

## 디자인 원칙

1. **놀이가 진입을 돕고 정보는 웹 UI로 전달한다.**
2. **필수 직접 입력은 Repository URL로 제한한다.** GitHub ID는 로그인 정보로 채우고 회고는 선택적으로 보완한다.
3. **한 화면에는 하나의 주요 행동만 강조한다.**
4. **캐릭터와 NPC는 상태를 설명하고 핵심 정보를 대신하지 않는다.**
5. **키보드 이동이 어려운 사용자에게 동일 기능의 목록 UI를 제공한다.**

## 브랜드

### 디자인 키워드

- 친근한
- 탐색하는
- 정리된
- 신뢰할 수 있는
- 가볍게 시작할 수 있는

### 컬러 토큰

```css
:root {
  --ink: #151817;
  --muted: #565656;
  --paper: #ffffff;
  --soft-paper: #fbfffd;
  --mint: #62d6a5;
  --mint-dark: #168c68;
  --mint-soft: #e6fbf2;
  --mint-line: #a8d9c3;
  --line: #dce8e2;
  --gray-soft: #f4f5f4;
  --overlay: rgb(15 22 19 / 62%);
  --success: #21875f;
}
```

- 민트는 상호작용 가능 상태, 진행 상태, 주요 행동에 사용한다.
- 검정은 제목과 본문에 사용하되 넓은 배경 면으로 반복하지 않는다.
- 게임 화면 위 패널은 불투명한 흰색 또는 높은 불투명도의 배경을 사용해 읽기 쉽게 한다.
- 오류, 성공, 진행 상태를 색상만으로 구분하지 않고 텍스트와 아이콘을 함께 제공한다.

### 타이포그래피

UI와 분석 결과는 시스템 sans-serif를 사용한다.

```css
font-family:
  Inter,
  ui-sans-serif,
  system-ui,
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  sans-serif;
```

- 게임 그래픽 안에 긴 문장을 직접 렌더링하지 않는다.
- 분석 결과 본문: `0.95rem` 이상
- 대화 질문: `1rem` 이상, 최대 2~3줄
- 상호작용 안내: `0.875rem` 이상
- 페이지 제목은 `3rem`을 넘기지 않는다.
- 긴 Repository 이름은 줄바꿈 또는 말줄임 처리하고 컨테이너를 밀어내지 않는다.

## 공간과 그리드

### 게임 그리드

- 작업실 논리 타일: `32×32px`
- 캐릭터와 가구는 같은 투영 방식의 top-down 에셋을 사용한다.
- Canvas는 CSS로 임의 확대하지 않고 Phaser scale 또는 camera zoom으로 정수 배율을 사용한다.
- `pixelArt: true`, `roundPixels: true`를 적용한다.
- 캐릭터, 상호작용 안내, 로딩 문구가 나타나도 Canvas 크기가 변하지 않게 한다.

### 웹 레이아웃

```css
.content-container {
  width: min(1080px, calc(100% - 40px));
  margin-inline: auto;
}
```

- 게임 작업실은 첫 viewport를 채우는 full-bleed 영역으로 구성한다.
- 모달과 대화창은 viewport 기준으로 배치하며 Canvas 내부 좌표에 의존하지 않는다.
- 분석 결과는 최대 폭을 제한해 긴 문장을 읽기 쉽게 한다.
- 카드 안에 카드를 중첩하지 않는다.

## 화면 구성

### 랜딩 페이지

- 실제 작업실 경험을 보여주는 영상 또는 정적 poster를 첫 화면 배경으로 사용한다.
- 서비스명, 짧은 가치 설명, `GitHub로 시작하기`를 한 화면에서 제공한다.
- 로그인된 사용자는 `내 작업실로 돌아가기`를 제공한다.
- 영상이 준비되지 않았거나 자동 재생이 실패하면 정적 poster를 표시한다.
- 서비스 기능을 설명하는 긴 카드 목록을 첫 viewport에 배치하지 않는다.

### 2D 작업실

- 사용자의 현재 위치, 상호작용 대상, 다음 행동을 구분할 수 있어야 한다.
- 새 분석 컴퓨터는 다른 컴퓨터보다 민트 조명이나 상태 아이콘으로 구분한다.
- 이전 분석 컴퓨터는 Repository 이름을 항상 노출하지 않고 접근 시 안내한다.
- 상호작용 가능 거리에서만 `E` 키 안내를 표시한다.
- 게임 화면의 HUD는 최소화하고 분석과 관련 없는 수치나 장식은 추가하지 않는다.

### Repository 입력 모달

- 입력창, 분석 대상 GitHub ID, 주요 행동 버튼만 우선 노출한다.
- 게임 입력을 일시 중지하고 모달에 focus를 이동한다.
- 닫기 후 상호작용했던 컴퓨터로 focus와 게임 입력을 복원한다.
- URL 오류와 API 오류를 구분해 다음 행동을 안내한다.

### 분석 진행과 Poppy 대화

- 분석 상태와 회고 질문을 동시에 보여주되 서로 경쟁하지 않게 한다.
- 질문은 한 번에 하나만 보여준다.
- 답변은 한 문장으로도 완료할 수 있고 건너뛸 수 있다.
- 분석이 완료되어도 작성 중인 질문을 중단하거나 자동으로 화면을 전환하지 않는다.
- 사용자가 `결과 확인하기`를 선택할 때만 분석 결과로 이동한다.

### 분석 결과

- Repository 근거와 사용자 경험, AI 해석을 시각적으로 구분한다.
- 기여 비율은 commit 수 기반 참고 지표임을 표시한다.
- 기술적 도전에는 근거 파일, commit, PR 또는 사용자 메모를 연결한다.
- 사용자의 역할을 확정적으로 단정하지 않는다.
- 작업실로 돌아가는 행동을 화면 상단과 마지막 영역 중 한 곳에 일관되게 제공한다.

## 컴포넌트 규칙

### 버튼

- 주요 행동은 민트 배경과 흰색 텍스트를 사용한다.
- 보조 행동은 흰 배경, 약한 선, 진한 텍스트를 사용한다.
- 최소 높이 `44px`, 권장 높이 `48px`
- hover, focus-visible, pressed, disabled 상태를 모두 구분한다.
- 게임 상호작용 키는 버튼 안의 텍스트가 아니라 작은 keycap 형태로 표현한다.

### 모달

- border-radius는 `8px`을 기본으로 한다.
- 모달 뒤의 overlay는 전체 viewport를 가려야 한다.
- backdrop click과 `Escape` 닫기 정책을 화면 목적에 맞게 명시한다.
- 중요한 작성 내용이 있을 때는 실수로 닫히지 않도록 확인 절차를 제공한다.

### 대화창

- Poppy 초상화, 질문, 답변 영역, 다음 행동 순으로 읽힌다.
- Poppy 이미지는 대화창의 25%를 넘지 않는다.
- 선택지는 2~4개까지만 제공하고 직접 입력은 별도 선택지로 둔다.
- 텍스트 입력 중에는 Phaser 키 입력을 받지 않는다.

### 정보 패널

- 검정색 두꺼운 border 대신 밝은 배경, 약한 선, 짧은 shadow를 사용한다.
- 각 패널은 하나의 정보 목적만 가진다.
- 수치, 근거, 설명의 시각적 계층을 분명히 한다.

## 에셋 사용 규칙

- 게임 에셋의 출처와 라이선스는 `docs/research/game-asset-license.md`에 기록한다.
- 공식 원문과 라이선스를 확인할 수 없는 에셋은 사용하지 않는다.
- 구매 ZIP, Aseprite 원본, 사용하지 않는 전체 시트는 공개 Repository에 포함하지 않는다.
- 런타임에 필요한 파일만 크롭하고 lossless WebP 또는 PNG로 저장한다.
- 기존 3D Poppy는 랜딩과 대화 초상화에만 사용한다.
- 맵 안 Poppy는 별도의 픽셀 NPC 에셋을 사용한다.

## 모션과 상태

```css
:root {
  --motion-fast: 140ms;
  --motion-base: 220ms;
  --motion-slow: 360ms;
  --ease-standard: cubic-bezier(0.2, 0.8, 0.2, 1);
}
```

- React UI는 `opacity`와 `transform` 중심으로 전환한다.
- 게임 캐릭터 이동과 UI 전환 애니메이션을 같은 요소에 중첩하지 않는다.
- 반복 애니메이션은 분석 중 상태나 상호작용 가능 상태에만 사용한다.
- 화면 흔들림, 빠른 깜빡임, 목적 없는 장식 루프를 사용하지 않는다.

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 반응형과 접근성

- 데스크톱에서는 키보드 기반 작업실을 기본 경험으로 제공한다.
- 모바일과 키보드 이동이 어려운 환경에서는 Repository 컴퓨터 목록 UI를 제공한다.
- Canvas만으로 핵심 기능을 제공하지 않는다.
- 모달은 focus trap, `Escape`, 닫은 뒤 focus 복귀를 지원한다.
- 상호작용 안내와 분석 상태는 스크린 리더가 읽을 수 있는 텍스트로도 제공한다.
- `prefers-reduced-motion`에서는 랜딩 영상을 자동 재생하지 않고 poster를 우선한다.

## 금지 사항

- 게임 Scene에서 분석 API 또는 Supabase를 직접 호출하지 않는다.
- 상호작용 좌표를 React 컴포넌트에 하드코딩하지 않는다.
- 한 파일에서 게임 초기화, 입력, 충돌, API, 모달 상태를 함께 관리하지 않는다.
- 외부 서비스의 맵, 캐릭터, 타일 이미지를 복사하지 않는다.
- 분석 실패 상황에서 mock 데이터를 성공 결과처럼 보여주지 않는다.
- 게임 표현 때문에 분석 근거나 오류 메시지를 축약하거나 숨기지 않는다.

## 점검 체크리스트

- [ ] 게임을 조작하지 않아도 핵심 분석 기능에 접근할 수 있는가?
- [ ] 현재 상호작용 대상과 다음 행동을 알 수 있는가?
- [ ] 모달이나 입력창이 열렸을 때 캐릭터 입력이 멈추는가?
- [ ] 분석 완료가 회고 작성을 강제로 중단하지 않는가?
- [ ] Repository 근거, 사용자 경험, AI 해석이 구분되는가?
- [ ] 32×32 그리드와 픽셀 렌더링 규칙을 지켰는가?
- [ ] 외부 에셋 라이선스와 수정 내용을 기록했는가?
- [ ] 모바일 대체 UI와 키보드 focus를 확인했는가?
