# 디자인 시스템 2

## 1. 목적

이 문서는 `docs/design/references1.png`의 대시보드형 UI 원칙을 집토끼 프로젝트에 맞게 재해석한 보조 디자인 시스템이다.

기존 `docs/design/design-system.md`와 `frontend/src/styles/tokens.css`를 기본 기준으로 유지하되, 분석 결과 화면처럼 카드, 차트, 요약 지표가 많은 화면에서는 이 문서의 레이아웃 규칙을 추가로 적용한다.

---

## 2. 적용 대상

다음 화면에 우선 적용한다.

- AI 분석 결과 화면
- 저장된 매물 상세 화면
- 매물 비교 화면
- 비용, 통학, 점수, 체크리스트처럼 여러 지표를 동시에 보여주는 대시보드 화면

다음 화면에는 우선 적용하지 않는다.

- 사용자 정보 입력 플로우
- OCR 검토와 매물 정보 수정 폼
- 단순 오류 화면
- 온보딩 또는 설명 중심 화면

---

## 3. 레퍼런스에서 가져올 원칙

### 화면 인상

- 밝은 회색 배경 위에 흰색 카드를 배치한다.
- 카드 간 간격을 넉넉하게 두어 정보 그룹을 명확히 구분한다.
- 중요한 수치는 크게, 설명은 짧게, 보조 정보는 작게 표시한다.
- 화면 전체는 차분하지만, 선택 상태와 핵심 지표에는 Primary Blue를 분명하게 사용한다.

### 정보 구조

- 상단에는 화면 제목과 주요 행동 버튼을 둔다.
- 첫 영역에는 핵심 요약 카드를 배치한다.
- 큰 지도/차트 카드와 작은 비용/상태 카드를 조합한다.
- 하단에는 세부 판단 카드들을 2열 또는 3열로 배치한다.
- 사용자가 먼저 볼 정보와 나중에 확인할 정보를 시각적으로 분리한다.

### 카드 구성

카드는 다음 구조를 기본으로 한다.

1. 짧은 카드 제목
2. 핵심 수치 또는 상태
3. 보조 설명 또는 리스트
4. 필요한 경우 차트나 아이콘

카드 안에 설명 문장을 길게 넣지 않는다. 긴 분석은 하단 세부 카드로 내린다.

---

## 4. 가져오지 않을 요소

레퍼런스의 다음 요소는 집토끼에 그대로 적용하지 않는다.

- 검색창: 분석 결과 화면의 핵심 행동이 아니다.
- 프로필 카드: 현재 서비스에는 사용자 프로필 탐색 맥락이 없다.
- 과한 보라색 그라데이션: 기존 Primary Blue 중심 디자인과 충돌한다.
- 장식용 이모지/아바타: 집토끼 ASCII 또는 실제 정보 시각화가 우선이다.
- 월별 막대 차트: 현재 프로젝트의 핵심 판단 단위가 월별 추세가 아니다.

## 5. 색상

기본 색상은 `frontend/src/styles/tokens.css`를 그대로 사용한다.

### 사용 비중

| 역할 | 토큰 | 사용 비중 |
|---|---|---:|
| 페이지 배경 | `--color-background` | 가장 넓게 |
| 카드 배경 | `--color-surface` | 주요 정보 영역 |
| 핵심 강조 | `--color-primary` | 버튼, 선택, 핵심 차트 |
| 보조 강조 | `--color-primary-soft` | 차트 배경, 선택 카드 |
| 성공 | `--color-success` | 추천, 여유, 긍정 |
| 주의 | `--color-warning` | 조건부추천, 확인 필요 |
| 위험 | `--color-danger` | 비추천, 위험 |

### 차트 색상

차트에는 의미가 있는 색상만 사용한다.

- Primary: 핵심 점수, 선택된 이동 방식, 주요 비용
- Success: 긍정 요소, 비용 여유
- Warning: 조건부 확인, 관리비, 추가 확인
- Danger: 위험 요소, 비추천 근거
- Border: 비활성 막대, 차트 트랙

색상을 직접 하드코딩하지 않고 CSS 변수로 지정한다.

---

## 6. 타이포그래피

기존 타이포그래피 토큰을 유지한다.

### 대시보드 화면 권장 위계

| 요소 | 토큰 |
|---|---|
| 페이지 제목 | `--font-size-page-title` |
| 핵심 수치 | `--font-size-page-title` 또는 `--font-size-step-title` |
| 카드 제목 | `--font-size-card-title` |
| 카드 보조 라벨 | `--font-size-label` |
| 차트 보조값 | `--font-size-caption` |

### 규칙

- 한 카드 안에서 가장 큰 글자는 하나만 둔다.
- 핵심 수치와 상태는 한 줄에서 바로 연결되게 배치한다.
- 긴 문장은 카드 상단에 두지 않는다.
- 차트 라벨은 너무 작게 만들지 않는다. 최소 `--font-size-caption`을 사용한다.

---

## 7. 레이아웃

### 데스크톱 기본 폭

대시보드형 화면은 입력 폼보다 넓게 사용한다.

- 최대 콘텐츠 폭: `1120px`에서 `1160px`
- 페이지 좌우 여백: `--space-8`
- 주요 카드 간격: `--space-6`
- 카드 내부 여백: `--space-6`

### 기본 그리드

분석 결과 화면은 다음 구조를 권장한다.

```text
제목                                      보조 버튼 / 주요 버튼

[ 지도 + 이동수단 선택 + 경로 정보 ]       [ 월 예상 비용 + 도넛 차트 ]

[ 종합 점수 + 토끼 ASCII ] [ 레이더 차트 ] [ 핵심 요약 ]

                 상세정보 보기

[ 면적 ]                 [ 주거비용 ]
[ 주거환경 ]             [ 사용자 우선사항 ]

[ 이외 특이사항 ] [ 계약 시 유의사항 ] [ 체크리스트 ]
```

### 카드 크기

- 지도 카드는 가장 넓게 둔다.
- 비용 카드는 지도 카드보다 좁게 둔다.
- 종합 점수 카드는 한 줄 전체를 사용하되 내부를 3영역으로 나눈다.
- 상세 카드는 같은 행에서 높이가 비슷하게 보이도록 최소 높이를 둔다.

## 8. 컴포넌트 규칙

### Dashboard Card

사용처:

- 분석 결과 요약
- 지도/경로
- 월 예상 비용
- 세부 분석 항목

스타일:

- 배경: `--color-surface`
- 테두리: `1px solid --color-border`
- 반경: `--radius-lg`
- 그림자: `--shadow-sm`
- 내부 여백: `--space-6`

카드 안에 또 다른 큰 카드를 중첩하지 않는다.

### Metric Card

사용처:

- 총점
- 월 예상 비용
- 통학 시간
- 위험 개수

규칙:

- 짧은 라벨을 위에 둔다.
- 핵심 수치를 크게 둔다.
- 단위는 수치와 같은 줄에 둔다.
- 보조 설명은 한 문장 이하로 제한한다.

### Donut Chart

사용처:

- 월세, 관리비, 교통비처럼 전체 비용의 구성 비율

규칙:

- 중앙에는 총액을 표시한다.
- 범례는 차트 옆 또는 아래에 둔다.
- 값이 0인 항목도 범례에는 남겨 사용자가 누락이 아님을 알 수 있게 한다.
- 색상만으로 구분하지 않고 라벨과 금액을 함께 표시한다.

### Radar Chart

사용처:

- 면적, 주거비용, 주거환경, 사용자 선호, 안전/신뢰, 통학 등 여러 평가 항목

규칙:

- 그래프와 텍스트 점수 목록을 함께 제공한다.
- SVG가 찌그러지지 않도록 고정 `viewBox`와 `aspect-ratio`를 사용한다.
- 축 라벨은 최소 `--font-size-caption` 이상으로 표시한다.
- 그래프가 카드 밖으로 넘치지 않게 최대 너비를 제한한다.

### Route Tabs

사용처:

- 도보, 버스, 지하철, 대중교통 등 이동 방식 선택

규칙:

- 실제 ARIA tab 패턴을 구현하지 않을 경우 `button` 그룹으로 둔다.
- 선택 상태는 `aria-pressed`와 `.selected` 클래스로 표현한다.
- 모바일 터치 높이는 최소 `--control-height-mobile`을 지킨다.

### Rabbit ASCII

사용처:

- 추천 상태의 브랜드 표현

규칙:

- 점수 또는 추천 상태 바로 옆에 배치한다.
- 장식 요소이므로 스크린리더에서는 `aria-hidden="true"`로 숨긴다.
- 색상은 `--color-primary`를 기본으로 한다.
- 분석 내용을 가리거나 카드의 주요 정보보다 커지면 안 된다.

## 9. 버튼과 행동

### 상단 행동

상단에는 보조 행동을 오른쪽에 둔다.

- 저장
- 다른 매물 분석하기

저장 기능이 아직 구현되지 않았다면 버튼은 비활성화하되, 화면에서 핵심 행동처럼 보이지 않게 Secondary 스타일을 사용한다.

### 상세정보 보기

상세정보 보기는 새 페이지 이동이 아니라 같은 화면의 상세 영역으로 이동하는 앵커로 처리할 수 있다.

- 텍스트는 짧게 유지한다.
- 아래 방향 표시를 함께 둔다.
- 카드처럼 감싸지 않는다.

## 10. 반응형

### Mobile

- 모든 주요 그리드는 한 열로 접는다.
- 상단 버튼은 전체 너비로 쌓는다.
- 지도, 비용, 종합 점수, 상세 카드 순서로 표시한다.
- 차트는 카드 중앙에 배치한다.
- 레이더 점수 목록은 한 열로 표시한다.

### Tablet

- 지도와 비용 카드는 상황에 따라 한 열 또는 2열을 사용할 수 있다.
- 상세 카드는 2열까지 허용한다.

### Desktop

- 지도 + 비용: 2열
- 종합 점수: 3영역
- 상세 카드: 2열
- 하단 체크리스트: 3열

## 11. 문구 원칙

대시보드 화면에서는 설명보다 판단을 우선한다.

좋은 예:

- `집토끼가 매물을 분석했어요`
- `월 예상 비용`
- `종합 점수`
- `계약 시 유의 사항`
- `매물 체크리스트`

피해야 할 예:

- `OCR 원문과 매물 정보를 사용자 조건과 함께 분석해 의사결정에 필요한 항목을 정리합니다.`
- `결과는 참고용이며 계약 전에는 실제 매물과 계약 조건을 직접 확인해야 합니다.`
- `AI가 비용, 지도 기반 통학 시간, 매물 신뢰도, 계약 전 체크리스트를 구조화하고 있습니다.`

긴 안내 문구가 필요하면 오류, 로딩, 법적 고지처럼 맥락이 명확한 상태에서만 사용한다.

## 12. 검증 체크리스트

구현 후 다음을 확인한다.

- 페이지 첫 화면에서 제목, 지도, 비용, 점수가 보이는가?
- 도넛차트가 실제 비용 구성과 연결되는가?
- 레이더 차트가 찌그러지거나 카드 밖으로 나가지 않는가?
- 토끼 ASCII가 점수 옆에 붙어 보이는가?
- 핵심 버튼이 한 화면에 과하게 많지 않은가?
- 모바일에서 카드와 텍스트가 겹치지 않는가?
- `npm run lint`와 `npm run build`가 통과하는가?
