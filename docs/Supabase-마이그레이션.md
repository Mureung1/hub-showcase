# Supabase 데이터베이스 마이그레이션 계획

현재 백엔드 메모리 상에 임시로 저장되던 데이터(냉장고 재고 등)를 실제 데이터베이스인 Supabase로 이관하여 데이터를 영구적으로 보존하도록 시스템 구조를 변경하기 위한 계획서입니다.

## 1. 마이그레이션 대상 데이터

현재 앱에는 크게 두 종류의 데이터가 있습니다.
1. **정적 데이터 (공통)**: 레시피 목록, 식자재 마스터 정보, 기준 가격표 (`recipes.js`, `ingredients.js` 등)
2. **동적 데이터 (개인화)**: 현재 내 냉장고에 있는 재고 정보 (`initialFridge.js`)

**접근법**: 1단계로 **사용자의 냉장고 재고(동적 데이터)만 Supabase로 우선 이관**합니다. 레시피나 기본 가격 정보는 모든 사용자가 동일하게 보는 마스터 데이터이므로 우선 기존의 JSON(정적 파일) 방식을 유지하는 것이 개발 속도와 성능 면에서 유리합니다. 추후 사용자별 커스텀 레시피 추가 기능이 생기면 그때 레시피도 DB로 옮기는 것을 권장합니다.

## 2. Supabase 테이블 스키마 설계 (제안)

**테이블명**: `fridge_items` (사용자의 냉장고 보관 물품 내역)

| 컬럼명 | 타입 | 설명 | 예시 |
|--------|------|------|------|
| `id` | uuid (PK) | 고유 식별자 | 123e4567-e89b-... |
| `ingredient_id` | text | 식자재 고유 ID | `pork`, `onion` |
| `qty_amount` | numeric | 수량(신선식품) | `300`, `0.5` |
| `qty_unit` | text | 수량 단위 | `g`, `모`, `개` |
| `qty_label` | text | 자유 단위(가공식품) | `1병`, `반쯤 남음` |
| `purchased_date` | date | 구매일 | `2026-07-03` |
| `expiry_date` | date | 유통기한 | `2026-07-15` (또는 null) |

## 3. 백엔드 아키텍처 변경점

- **Supabase 클라이언트 추가**: `backend/` 에 `@supabase/supabase-js` 패키지를 설치하고 연동 코드를 작성합니다.
- **비동기화(Async) 처리**: 현재 동기(Synchronous) 방식으로 즉시 리턴되던 `store.js`의 냉장고 로직들이 모두 DB 네트워크 통신을 거쳐야 하므로 비동기(`async/await`) 함수로 전면 수정됩니다.
- **컨트롤러 수정**: `recipesController.js` 등의 컨트롤러도 비동기 응답을 대기하도록 로직을 변경합니다.

## 작업 진행을 위한 사전 준비물

1. **Supabase 프로젝트 생성**: Supabase 사이트에서 회원가입 후 새 프로젝트를 생성합니다.
2. **환경 변수 추출**: 프로젝트 생성 후 `Project URL`과 `API Key (anon/public)`를 복사하여 준비합니다.
3. 이 정보가 준비되면 개발팀에 전달하여 `.env` 파일에 셋팅하고 작업을 시작합니다.
