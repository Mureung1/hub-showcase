# ledger-automation: 전표 입력 → 시산표·재무제표 → Excel 자동 생성 MVP

## Context

- `notes/IDEA.MD` 8번 "회계 장부 자동화 agent"의 첫 코드 슬라이스. `notes/세무조정계산서-결산보고서-research.md` §8 분류 중 **결정론적 그룹**(장부만 있으면 기계적으로 재현 가능한 서식)부터 구현한다.
- 리포에 재사용할 회계 코드·스키마·샘플 데이터 없음(전부 Node/JS) → **완전 신규 모듈**. 참고 패턴: `hometax-guide-extension/server/server.mjs`(ESM+Express 최소 서버), `hometax-guide-extension/server/package.json`(독립 모듈 관행).
- 사용자 확정: ① 스택 위임 ② **전표 직접 입력 웹 UI 포함** ③ 범위 = 뼈대 + 합계잔액시산표 + 재무상태표/손익계산서 ④ 출력 = **Excel 파일**.

## 스택

**Node.js(ESM) + Express + 바닐라 JS UI + exceljs.** 의존성은 `express`, `exceljs` 2개뿐(cors 불필요 — 동일 오리진). 테스트는 내장 `node:test`(Node 24, 통합테스트는 내장 fetch). **금액은 원 단위 정수**(KRW 무소수점 → `Number.isSafeInteger` 검증).

## 핵심 설계 결정

1. **마감분개 없음** — 단일 회계기간이므로 IS에서 `netIncome = Σ수익−Σ비용`을 계산해 BS 자본 섹션에 "당기순이익" 라인으로 반영. 검증 항등식: **`총자산 = 총부채 + 자본(원장) + 당기순이익`** (시산표 대차평균과 수학적 동치임을 테스트로 확인).
2. **샘플 법인은 당기 설립 법인** (개시 전표 = 차)보통예금/대)자본금) → 이월이익잉여금 논점 제거. 375 계정은 마스터에만 두고 다음 슬라이스(이익잉여금처분계산서) 대비.
3. **부가세는 총액 표시**: 매출 전표는 다(多)라인(`차)보통예금 110,000 / 대)매출 100,000+부가세예수금 10,000` — 매출은 반드시 공급가액), 분기 신고·납부 상계 전표 1~2건 포함. "부가세 계정이 IS에 미출현"을 테스트로.
4. **감가상각누계액(차감계정)은 1차 범위 제외** — contra 표시 로직이 필요해서. 결산수정분개 시연이 필요해지면 다음 슬라이스.
5. 잔액 방향은 정석: `net = 차변합계−대변합계`, 부호에 따라 차변잔액/대변잔액 열 배치. 시산표 열 순서는 더존 표준 `[차변잔액|차변합계|계정과목|대변합계|대변잔액]`.
6. 회계기간 = entries 전체가 1개 연도 (export 기간 파라미터 없음). 법인세비용 미계상(당기순이익=법인세차감전순이익, 주석만).

## 구현 스텝 (7스텝 = 데일리 PR 7개, 각 0.5~1일)

| Step | 내용 | 완료 기준 (node:test) |
|---|---|---|
| 1 | 스캐폴드 + `accounts.mjs` + `validate.mjs` | 차대불일치/양쪽금액/둘다0/미등록코드/비정수·음수 거부. 계정 코드 중복 없음 |
| 2 | `store.mjs`(atomic write) + `ledger.mjs` + 샘플 시드 | 샘플 전건 validate 통과; Σ차변=Σ대변; 계정별 net 총합=0 |
| 3 | `trialBalance.mjs` | 차변합계총계=대변합계총계=원장 총차변; 차변잔액총계=대변잔액총계 |
| 4 | `incomeStatement.mjs`+`balanceSheet.mjs` (3과 병렬 가능) | netIncome=Σ수익−Σ비용; 자산=부채+자본+netIncome; 부가세 계정 IS 미출현 |
| 5 | `server.mjs` REST | 내장 fetch 통합테스트: 잘못된 전표 400, 정상 201, GET 목록, DELETE, GET /api/accounts |
| 6 | `excel.mjs` + `/api/export.xlsx` | **라운드트립**: writeBuffer 결과를 exceljs로 재파싱 → 총계 셀=계산 결과 일치 |
| 7 | `public/` 입력 UI (필요 시 7a 폼 / 7b 목록+다운로드 분할) | 수동 체크리스트: 라인 추가/삭제→균형 표시→저장→목록→다운로드 |

PR 형식은 `.github/pull_request_template.md` (`[루카스아이디_실명] - 요약` + 3개 섹션) 준수, auto-merge 봇 규칙 유의.

## 구현 시 함정 메모

- **exceljs**: CJS라 `import ExcelJS from 'exceljs'` (default import). `ws.columns`(width 포함)는 **데이터 삽입 전** 설정. 셀 값은 Number로 넣고 `numFmt='#,##0'`. 2단 헤더는 `mergeCells`. 응답은 스트리밍 대신 **`writeBuffer` → `res.send(Buffer.from(buf))`** (에러 시 헤더 미전송 이점). 한글 파일명은 `Content-Disposition: attachment; filename="report.xlsx"; filename*=UTF-8''${encodeURIComponent('결산보고서_2026.xlsx')}`.
- **UI**: `<template>`+`cloneNode`로 라인 행 복제, 계정 select는 `/api/accounts`로 채움. 별도 state 객체 없이 **DOM이 곧 상태**. `form 'input' 이벤트 위임 1개`로 차/대 합계·차액 실시간 표시, **차액 0일 때만 저장 활성화**. 한 라인 차변 입력 시 대변 clear(이중 방어). 최소 2라인 유지. 금액 input은 `type="text" inputmode="numeric"`(콤마 표시, 휠 오입력 방지).

## 검증

1. `npm test` — 스텝별 항등식 전부 (위 표).
2. E2E: `npm run seed && npm start` → 브라우저에서 전표 1건 입력(차대 불일치 시 저장 비활성 확인) → Excel 다운로드 → 시트 3장(시산표/재무상태표/손익계산서)에서 차변총계=대변총계, 자산=부채+자본 육안 확인.
3. Excel 라운드트립 테스트(Step 6)로 렌더 정확성 자동 검증.
