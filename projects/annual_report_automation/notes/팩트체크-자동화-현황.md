> 조사일: 2026-07-16 · 방법: 서브에이전트 4개 병렬 웹 리서치 (각각 "내 주장을 반증하는 증거를 찾으라"는 지시로 확증편향 차단)

## 1. 명제 A — "0단계 수집엔 이미 사람이 없다" → **절반 틀림**

### 1-1. "온라인 발급 가능" ≠ "자동 수집" [검증됨]

조사의 핵심 문장: **온라인화는 되어 있지만 공개 API가 확인되지 않아, 결산 시즌마다 사람이 직접 로그인 → 메뉴 탐색 → 다운로드해야 한다.**

| 자료 | 발급처 | 온라인? | 필요한 것 | 사람 개입 |
|---|---|---|---|---|
| 법인 통장 거래내역 | 기업인터넷뱅킹 | ✅ (IBK 등 최대 1년 단위) | 법인 인증서 + OTP | 매번 로그인·기간지정·다운로드 |
| 잔액증명서 | 거래은행 | ✅ **결산일 익일부터** | 법인 인증서 | 로그인·클릭 |
| 대출잔액·이자내역 | 거래은행 | ✅ 08~22시 실시간 | 법인 인증서 | 로그인·클릭 |
| 예금이자 원천징수영수증 | 홈택스(익년 3월~) / 은행 | ✅ | 인증서 | 로그인·클릭 |
| 4대보험 납부확인서 | 사회보험 통합징수포털 | ✅ | 사업장 인증서 | 로그인·클릭 |
| 지방세 과세증명 | 위택스 / 정부24 | ✅ 즉시 | 법인 인증서 | 로그인·클릭 |
| 보험증권 | 각 보험사 | ✅ 무료 PDF | 인증서 등 | 로그인·클릭 |

→ **공개 API가 확인된 항목이 하나도 없다.** 전부 웹 UI 셀프서비스다.

### 1-2. 사용자 반론도 절반만 맞았다 [검증됨]

> "은행 같은 데서 자료 요청하는 건 결국 사람이 해야 하는 거 아닌가?"

문자 그대로는 **틀렸다** — 전화하거나 방문해서 "요청"할 필요가 없다. 법인 잔액증명서도 결산일 다음날부터 인터넷뱅킹에서 나온다.
그러나 **핵심은 맞았다** — 자료 수집에는 여전히 사람의 인증서 로그인과 클릭이 개입한다.

지점 방문이 실제로 필요한 경우는 두 가지뿐:
1. **법인 인터넷뱅킹 최초 신청** (OTP 수령) — 1회성
2. **당일자 잔액증명서** (그날 계좌 이용 정지 조건)

### 1-3. 수임동의가 커버하지 않는 것 ★ [검증됨]

수임동의는 **세금계산서·신고내역류에는 강하지만**, 세무사가 매달 필요로 하는 자료의 상당 부분을 **전혀 커버하지 않는다**:

| 구분 | 항목 |
|---|---|
| 수임동의로 조회 가능 | 전자세금계산서, 현금영수증, 신고내역, 신용카드 매출자료, 법인세 신고도움자료 |
| **별도 동의 필요** (금융정보) | **통장 거래내역**, 카드 사용내역, 보험·급여 정보 |
| **조회 자체가 불가능** | 개인 신용정보, **현금 지출 내역**, **사내 비용자료**, 고정자산 관리대장 |

→ **1단계 분개 AI의 핵심 입력인 통장 거래내역은 수임동의 밖이다.** 사람이 받아서 전달해야 한다.

### 1-4. "자동"의 실체 [검증됨]

- 세무사랑Pro 홈택스 간편조회 = 사용자가 메뉴 선택 후 **"F3 불러오기"를 눌러야** 실행
- 홈택스 자체 전자세금계산서 자료신청 = 실시간이 아니라 **신청 다음날 내려받는 배치**

국세청 공식 채널조차 즉시 자동 유입이 아니다.

## 2. 명제 B — "AI 스크래핑은 열등한 재구현" → **틀림** ★ 가장 큰 오류

### 2-1. 기존 "자동 유입"의 정체가 스크래핑이다 [검증됨]

| 증거 | 내용 |
|---|---|
| **WEHAGO(더존) 자체 공지** | "홈택스 **대량 수집(스크래핑)** 시 사이트 접속 과부하로 인한 자료 수집 지연" — 스스로 인정 |
| 더존 Smart A / WEHAGO 설정 | 홈택스 **공동인증서 + 세무대리인 관리번호·비밀번호**를 등록해야 수집 실행 → 사람 대신 로그인해서 긁어오는 구조 |
| CODEF · 팝빌 · 링크허브 | 국세청 공식 파트너가 아니라 **민간 스크래핑 대행업체**. CODEF는 자체 크롤러 "e-Spider" 운영 |
| **국세청 공식 Open API** | 공공데이터포털에 있는 것은 **"사업자등록정보 진위확인 및 상태조회" 단 하나.** 세금계산서·카드·현금영수증은 **전혀 제공하지 않음** |

→ 내가 "열등한 재구현"이라고 폄하한 그 방법이, **업계가 실제로 쓰는 바로 그 방법**이다. 기술적으로 같은 종류다.

### 2-2. 그리고 그것은 회색지대다 [검증됨]

- **2025년 5월** 종소세 신고기간, 홈택스 트래픽 폭주로 삼쩜삼 등 민간 플랫폼 접속 차단. 국세청이 **예고 없이 IP 차단** → "석기시대 발상"이라는 업계 반발
- 국세청, 스크래핑 **원천 차단 정보보안 사업 착수**
- 트래픽 유발 업체(삼쩜삼·토스 등)에 **과금하는 방안 검토 중**
- 대체할 **"국세 오픈 API 시스템"(가칭)은 사업비 5.16억으로 설계 중 — 2026년 7월 현재 미완성**

→ **지금 이 순간 공식적으로 허용된 자동화 경로는 사실상 존재하지 않는다.** 스크래핑이 잠정 묵인되어온 회색지대다.

### 2-3. 결론의 방향은 바뀌지 않는다 (이유가 바뀔 뿐)

"기존도 스크래핑이니 우리도 하자"가 되지 **않는다**. 오히려:
- 국세청이 **적극 단속 중**이고 차단 실사례가 있다
- 우리는 **법인 인증서조차 없다** (fincert-spike의 기존 블로커)
- 업계 대형 벤더도 이 방식의 안정성 때문에 고객에게 지연 공지를 띄운다

**바뀐 것**: "할 필요가 없다(이미 됐으니까)" → **"해서는 안 된다(합법 경로가 없고 단속 중이다)"**

## 3. 명제 C — "세무조정은 이미 자동화됐다" → **과장, 강한 버전은 반증**

### 3-1. 벤더 자신의 2025년 마케팅이 반증이다 ★ [검증됨]

| 벤더 | 시점 | 문구 |
|---|---|---|
| **더존비즈온** | **2025년 2월** | "AI로 법인세 신고 — **반나절 걸리던 세무조정을 3분 만에**" |
| **WEHAGO T** | **2025년 3월 1일** | "AI 법인 세무조정" 출시. 기존 프로세스: **"수임기업별 3시간 이상"**, "고연차 직원만 가능", "입력 실수·서식 누락" |

**이미 자동화됐다면 업계 최대 벤더 두 곳이 2025년에 이걸 신제품으로 팔 이유가 없다.**
기존 상용 프로그램을 쓰면서도 세무조정에 반나절~3시간이 걸렸다는 업계 자백이다.

그리고 AI 버전조차 세무사에게 **"검토만 하세요"**라고 한다 — **AI 초안 + 사람 검토** 구조로, 내가 1단계에 제안한 형태와 동일하다.

### 3-2. 자동화의 경계 [검증됨]

| 자동화된 것 | 자동화 안 된 것 (판단 영역) |
|---|---|
| 서식 채우기, 반복 계산(부가세·감가상각·최저한세), 스크래핑 기반 전표 처리, **"간편조정"** 수준 | 접대비 한도초과 판단, **임원상여·퇴직금 한도**, **소득처분(귀속자 판정 — 상여/배당/기타사외유출 구분)**, **부당행위계산부인**, 이월결손금 활용 전략 |

→ "계정별원장을 넣으면 자동"이 아니라 **사실관계 판단이 선행돼야 하는 항목들**이 남아 있다.

### 3-3. 세무사 전용 B2B 제품이다 ★ [검증됨]

- **세무사랑Pro**: 뉴젠솔루션 공식 페이지 원문 — **"세무회계사무소용 프로그램"**. 한국세무사회 — "중견세무사들의 업무 효율화". 일반 법인 셀프신고 툴로 마케팅하지 않음
- **KcLep(케이렙)**: 자격시험 교육/수험용 무료. **법인조정 모듈 없음**
- **경리나라**: 소상공인 기장용. **법인조정 미지원**
- **이카운트**: **법인조정 프로그램 자체를 제공하지 않음** — "국세청에서 무료로 다운로드하라"고 안내
- **자비스**: 월 기장료와 **별도로 "세무조정료" 청구** → 결국 세무사가 수행

→ **일반 법인이 세무사 없이 결산을 완결하는 시장 자체가 비어 있다.** 기존 벤더는 전부 "세무사무소가 쓰는 도구"이고, 최종 사용자는 세무사이지 법인 대표가 아니다.

### 3-4. 그런데 법적 장벽이 있다 ★ [검증됨]

**외부조정 의무 대상** (법인세법 시행령 **§97조의2**):
- 직전 사업연도 수입금액 **70억원 이상**
- **외감법인**
- 수입금액 **3억원 이상 + 조세특례(세액공제·감면) 적용**
- 수입금액 3억원 이상 + 준비금 잔액 3억원 이상
- 설립 2년 이내 신설법인 + 수입금액 3억원 이상
- 전기 결정·경정 받은 법인, 3년 내 합병·분할, 국외사업장 보유 등

→ **자기조정 가능 법인 = 사실상 매출 3억 미만 + 감면 없음 + 준비금 없음인 극소형뿐.**
매출 3억 넘고 세액감면 하나라도 받으면 세무사를 안 거칠 경우 **신고 자체가 무신고**다.

**조정반** (법인세법 시행령 **§97조의3**): 세무조정계산서는 **조정반 소속자만 작성 가능**. 2인 이상의 세무사·세무법인·회계법인이 대표자를 선임해 지방국세청장 지정을 받아야 함. (2021년 대법원 전합 판결로 세무사 등록 변호사 2인 이상 법무법인도 포함)

## 4. 질문에 없었지만 중요한 발견

### 4-1. 오픈뱅킹이 2025년 1월 2일부터 법인도 된다 [검증됨]

한 은행 채널에서 **전 은행 계좌의 잔액·거래내역 실시간 조회** 가능. 계좌 등록은 인터넷뱅킹으로도 가능(온라인).

**그러나 API 호출은 못 한다** [검증됨]: 금융결제원 **이용기관 등록** 요건이 ① 오픈뱅킹 참가기관 ② 금융위 **핀테크산업 분류업종 기업** ③ 전자금융업자/보조업자 중 하나. **회계 자동화가 목적인 일반 법인은 해당 없음.** 게다가 금융보안원 보안점검 + 이용계약이 필요.

[불확실] 2025년 시작된 법인 조회서비스가 UI 전용인지, 프로그램적 호출도 되는지는 확인 못 함.

### 4-2. 스크래핑은 이미 규제 방향이 정해졌다 ★ [검증됨]

**2022년 1월 5일부터 마이데이터 사업자의 스크린 스크래핑 전면 금지**, API 방식으로만 허용 (신용정보법 §33조의2 전송요구권 근거).
- 뱅크샐러드: 스크래핑 → 오픈뱅킹 API 전환
- 캐시노트: API 기반 마이데이터로 전환 완료 (여신협회 카드매출조회는 2024.5부터 API)
- 자비스 등 클라우드 회계도 오픈뱅킹 API로 입출금 자동 반영

형식적으로는 허가받은 마이데이터 사업자에게만 적용되지만, **금융당국이 "스크래핑은 위험하고 구식"이라고 못박은 정책 신호**다.

### 4-3. 의외 — 은행 표준약관에 크롤링 금지 명문 조항이 없다 [검증됨]

「전자금융거래 이용에 관한 기본약관」(표준약관)과 하나은행 게시본을 직접 확인한 결과, **"크롤링/매크로/자동화 프로그램 접속 금지" 문구는 없었다.**

대신 있는 것:
- §14 접근매체의 사용 — **양도·양수, 대가를 받는 대여, 범죄 목적 대여** 금지
- §8 회사의 책임 — "정보통신망에 침입하여 **부정한 방법으로 획득한 접근매체**의 이용으로 발생한 사고"는 은행 면책

**전자금융거래법 §6③**의 "양도"는 대법원(2011도16167)이 **소유권·처분권의 확정적 이전**으로 해석 → **무상 대여나 일시적 사용 위임은 양도가 아님.** 즉 본인이 본인 인증서로 본인 스크립트를 돌리는 것은 이 조항 위반 소지가 낮다.

[불확실] 다만 국민·신한·우리·하나의 **개별** 인터넷뱅킹 약관 원문(로그인 후에만 열람 가능한 경우 다수)은 확보하지 못했다. 개별 약관에 자동접속 금지 조항이 있을 가능성은 배제 못 함.

## 5. 은행 자동화 판정 — 기술과 법을 분리해서

| 구분 | 판정 | 근거 |
|---|---|---|
| **기술적 가능성** | **부분 가능하나 매우 불안정** | 금융인증서 로그인 자체는 홈택스 사례처럼 될 수 있으나, **키보드보안 플러그인**(nProtect/델피노), **멀티로그인탐지 로그아웃**(KB 실존 — 홈택스 스파이크에서 겪은 동시세션 문제와 동일 패턴), **FDS**(탐지 로직 비공개) 등 다층 방어. **간편인증·OTP는 원천적으로 자동화 불가** (휴대폰 실시간 승인 필요) |
| **법적 허용** | **회색지대 — 안전하지 않음** | 명문 금지 조항은 못 찾았으나, 정보통신망법 §48① "접근권한 초과"의 포괄 법리(대법원은 **약관 등 객관적 사정** 기준으로 판단), 마이데이터 스크래핑 전면금지라는 정책 방향, 판례들이 보여주는 법원의 엄격한 태도 → **명백히 안전하다고 말할 수 없음** |

[확인 안 됨] 개인이 **본인 계좌**를 자동화해 처벌·정지된 구체적 사례는 못 찾았다. 검색된 계좌 지급정지 사례는 전부 보이스피싱·대포통장 등 제3자 피해 건이었다. **"사례가 없다"는 확증이 아니라 "조사 범위에서 확인 못 했다"는 뜻.**

### 합법적 대안 순위 (현실성 기준)

| 순위 | 방법 | 현실성 | 비고 |
|---|---|---|---|
| **1** | **사람이 월 1회 수동 다운로드 → 파일 자동 파싱** | ★★★★★ | 법적 리스크 없음. fincert-spike의 "저빈도 수동 실행" 원칙과 동일 |
| 2 | 펌뱅킹 계약 | ★★☆☆☆ | 정식 B2B. 중소기업도 가입 가능하나 은행과 개별 협상. [불확실] 비용 확인 못 함 |
| 3 | 오픈뱅킹 법인 조회(UI) | ★★☆☆☆ | 사람이 앱에서 통합 조회는 가능. 자동화 연결은 불확실 |
| 4 | 오픈뱅킹 이용기관 등록(API) | ★☆☆☆☆ | 핀테크 업종 기업만. 사실상 불가 |
| 5 | 마이데이터 허가 | ☆☆☆☆☆ | 자본금 5억+금융위 허가. 불가능 |
| — | 헤드리스 스크래핑 | **비권장** | 기술 불안정 + 법적 회색지대. **얻는 이득은 "월 몇 분"** |

### 권고 [조사자 결론]

> **은행 사이트 자동화를 시도하지 말 것.** 리스크 대비 이득이 명백히 낮다. 홈택스 스파이크의 두 교훈(저빈도 수동 실행, 동시세션 로그인 끊김)이 은행에도 적용될 가능성이 높고, 은행은 홈택스보다 인증 단계가 한 겹 더 있다. 반면 얻는 것은 "월 1회 로그인해서 엑셀 받는 몇 분"이다.
>
> 현실적 방향: **사람이 결산 주기에 맞춰 거래내역 엑셀을 수동 다운로드 → 그 파일을 자동 파싱·분개하는 파이프라인.**

## 7. 계획에 미치는 영향

### 7-1. 1단계 분개 AI = 여전히 맞다 (오히려 강화됨)

- 수임동의가 **통장 거래내역을 커버하지 않는다**는 것이 확인됐다 → 통장은 사람이 받아야 하고, 그걸 분개하는 것도 사람 일이다
- 은행 자동화 조사의 권고가 **정확히 이 계획**이다: "사람이 수동 다운로드 → 파일 자동 파싱·분개"
- 더존/WEHAGO의 AI 세무조정도 **"AI 초안 + 사람 검토"** 구조 → 내 설계(규칙+LLM+확인 큐)가 업계 방향과 일치

### 7-2. 4단계 세무조정 = 내가 과소평가했다

- "이미 자동화됐으니 차별점 약함"은 과장이었다. 2025년에야 AI가 나왔고, **판단 항목은 여전히 빈 곳**이다
- **일반 법인용 시장이 비어 있다** — 기존 제품은 전부 세무사무소용 B2B
- → **원래 `PLAN.md`의 2트랙 병렬 구조가 오히려 맞았다.** 4단계를 버릴 이유가 없다

### 7-3. 수집 자동화 = 하지 말 것 (단, 이유가 바뀜)

- **바뀐 근거**: "이미 자동화돼서 할 필요 없다" ❌ → **"합법적 경로가 없고, 국세청·금융당국이 단속·규제 방향이며, 리스크가 이득보다 크다"** ✅
- 이 차이가 중요하다: 만약 국세청 오픈 API가 완성되면(설계 중) 전제가 또 바뀐다. **추적할 사항**

### 7-4. 새로 확인해야 할 것 ★

**사용자님 법인이 외부조정 의무 대상인가?** 이게 프로젝트 포지셔닝을 가른다:
- 판별 방법: 종이 보고서에 ① 성실신고확인서가 철해져 있는가 ② 세액공제·감면을 받았는가 ③ 매출이 3억을 넘는가
- **대상이면**: 세무사 서명이 법적 필수 → "세무사 전달용 완성 초안" 포지셔닝이 맞음 (원래 결정 유지)
- **아니면(극소형)**: 자기조정 가능 → 셀프신고까지 노려볼 수 있고, 비어 있는 시장에 정면으로 들어감

## 8. 확인하지 못한 것 (조사의 한계)

- 수임동의의 정확한 법적 근거 조문 — "홈택스서비스 이용에 관한 규정"(행정규칙) 존재는 확인했으나 원문 미확보
- 홈택스 이용약관의 자동접속/크롤링 금지 **정확한 조항 원문** (정부24는 "매크로 사용자 서비스 제한"을 명시 → 홈택스도 유사 개연성 높으나 미확인)
- 국민·신한·우리·하나의 **개별** 인터넷뱅킹 약관 원문
- 개인이 본인 계좌를 자동화해 제재받은 사례의 존재 여부
- 세무사랑Pro 실제 가격, "간편조정"이 정확히 어떤 법적 케이스에서만 동작하는지
- 4대보험/위택스/보험사의 공개 API 존재 여부 (전부 웹 UI만 확인됨)
- 펌뱅킹 초기 구축비·월 수수료, 소규모 법인의 실제 가입 문턱
- 국세청 "국세 오픈 API 시스템" 완성 시점·최종 스펙 (설계 단계로만 확인)
- 헤드리스 브라우저에서 nProtect/델피노가 실제로 어떻게 반응하는지 실증 데이터
- 세무사무소의 자료 취합이 전체 업무에서 차지하는 **정량적 비중** (실태조사 자료 없음)
