## Step 1 — 실데이터를 git에서 차단하는 안전장치 (2026-07-16 14:20)

**무엇을 했는지 (한 줄)**
프로젝트 뼈대(`package.json`, 폴더들)를 세우고, 개인정보가 든 실제 데이터가 실수로 git에 올라가지 않도록 `data/.gitignore`와 마스킹 규칙 문서(`data/README.md`)를 만들었어요.

**핵심 코드** — `data/.gitignore`

```gitignore
# private/ 내용은 전부 무시하되, 폴더 자체는 .gitkeep으로 유지한다.
private/*
# ↑ private 폴더 "안의 모든 것"을 git이 무시하게 함 (실데이터는 여기에만 둠)
!private/.gitkeep
# ↑ 딱 이 빈 파일 하나만 예외로 추적 → 폴더 구조는 남기되 내용물은 안 올림
```

여기서 트리키한 점: `private/`(슬래시로 끝)라고 쓰면 git이 폴더째 무시해서 `.gitkeep` 예외조차 안 먹혀요. 그래서 `private/*`(안의 것들)로 써야 "폴더는 유지, 내용만 차단"이 됩니다. 실제로 `git check-ignore`로 실데이터는 막히고 `.gitkeep`은 통과하는 걸 확인했어요.

마스킹 규칙(`data/README.md`)의 핵심은 — 주민번호는 **아예 입력하지 않고**, 이름은 `대표A`, 거래처는 `거래처01` 같은 코드로 바꿔 넣습니다. 금액·날짜만 진짜 값으로요.

**새로 나온 용어**
- `.gitignore`: git이 "이 파일들은 추적하지 마"라고 알려주는 목록 파일
- 마스킹(masking): 이름·주민번호 같은 걸 알아볼 수 없는 코드로 바꿔 넣는 것

**확인 질문**
`private/`가 아니라 `private/*`라고 써야 했던 이유를 한 문장으로 설명해보시겠어요?

export function 상각선택(자산, 선택 = {}) {
  if (자산.업무용승용차) {

## Step 4 — 세금 계산 본체, 별지3 (2026-07-16 14:39)

**무엇을 했는지 (한 줄)**
`src/engine/tax.js`에 실제 세금을 뽑는 계산을 넣었어요. 당기순이익에서 시작해 세무조정을 더하고 빼서 과세표준을 구하고, 거기에 누진세율을 적용합니다.

**핵심 코드** — 구간별 누진세액 (`누진세액`)

```javascript
export function 누진세액(과세표준, 세율표) {
  let 이전상한 = 0, 세액 = 0;
  for (const 구간 of 세율표) {
    const 구간액 = Math.max(0, Math.min(과세표준, 구간.상한) - 이전상한);
    // ↑ 이 구간에 "실제로 걸리는 금액"만 잘라냄. 예: 과세표준 3억이면 2억은 첫 구간, 1억은 다음 구간
    if (구간액 > 0) {
      const 부분 = Math.floor(구간액 * 구간.율);
      세액 += 부분;
      // ↑ 각 구간의 세금을 따로 계산해서 누적. 전체에 최고세율을 곱하는 게 아님
    }
    이전상한 = 구간.상한;
    if (과세표준 <= 구간.상한) break;
  }
  return { 세액, 내역 };
}
```

핵심은 "누진"이에요. 3억을 벌었다고 3억 전체에 높은 세율을 매기는 게 아니라, 2억까지는 낮은 세율, 넘는 1억만 높은 세율 — 이렇게 층층이 쌓아 계산합니다.

**새로 나온 용어**
- 당기순이익: 회계상 "올해 번 돈" (수익 − 비용)
- 누진세율: 금액이 클수록 높은 세율이 적용되는 구조 (단, 구간별로 나눠서)
- `Math.floor`: 소수점을 버리고 정수로 내림 (세금은 원 단위라 소수를 버림)

## Step 7 — 백엔드를 JavaScript → Python으로 전면 이관 (2026-07-16 16:30)

**무엇을 했는지 (한 줄)**
Step 1~6에서 JS로 만든 엔진 전체를 Python으로 다시 만들었어요(`taxengine/` 패키지). 계산 결과·테스트 27개·재현 성공은 그대로인데, **금액을 부동소수 대신 `Decimal`로 다뤄서 더 정확해졌고**, 김진영 님이 코드를 읽을 수 있게 됐습니다. 옛 JS(`src/`, `test/`)는 제거했어요.

**왜 바꿨나 — 정확성의 급소**
JS의 숫자(`number`)는 `0.1 + 0.2`가 `0.30000000000000004`가 되는 부동소수 오차가 있어요. 세금은 조정이 여러 해 누적돼서, 작은 오차가 몇 년 뒤 신고서와 원 단위로 어긋날 수 있습니다. Python `Decimal`은 이걸 언어 차원에서 막아줍니다.

**핵심 코드 1** — 금액을 Decimal로 강제 (`taxengine/money.py`, 새 파일)

```python
def 원(v) -> Decimal:
    """숫자·문자열을 원 단위 Decimal로 변환. 천단위 쉼표와 빈 값 허용."""
    if v is None or v == "":
        return Decimal(0)
    if isinstance(v, Decimal):
        return v
    return Decimal(str(v).replace(",", ""))
    # ↑ 핵심: str(v)로 문자열을 거쳐 Decimal을 만듦. float를 거치지 않아 오차가 안 낌

def 절사(d: Decimal) -> Decimal:
    """원 단위 미만 버림 (JS Math.floor에 대응)."""
    return d.quantize(Decimal(1), rounding=ROUND_DOWN)
    # ↑ 반올림 방식을 코드에 명시. 세법은 필드마다 절사/반올림 규칙이 달라서 이렇게 박아둠
```

**핵심 코드 2** — 같은 로직, 언어만 바뀐 예 (`engine/depreciation.py`)

```python
    정률 = 선택["방법"] == "정률"
    취득가 = 원(자산["취득가"])
    기준액 = 취득가 - 원(자산.get("기초누계", 0)) if 정률 else 취득가
    # ↑ JS의 삼항연산자(A ? B : C)가 Python에선 "B if A else C" 순서로 바뀜
    연액 = 절사(기준액 * 율)
    금액 = 절사(연액 * 월수 / 12)
    # ↑ JS의 Math.floor(...) 자리에 절사(...)가 들어감. 계산 결과는 동일
```

JS와 Python은 문법이 다르지만(삼항연산자 순서, `??` → `.get()`, `Math.floor` → `절사`), **로직과 계산 결과는 똑같습니다.** 그래서 테스트 기댓값(1억·5년 정률 = 45,100,000 등)도 그대로 통과하고, 재현도 여전히 정답지와 5/5 일치합니다.

**핵심 코드 3** — 테스트 도구도 바뀜 (`tests/test_depreciation.py`)

```python
class 상각범위액_교과서예제(unittest.TestCase):
    def test_기계장치_1억_5년_정률법_1년차(self):
        자산 = {"취득일": "2020-01-01", "취득가": 100_000_000, "기초누계": 0}
        self.assertEqual(상각범위액(자산, {"방법": "정률", "내용연수": 5}, FY2025)["금액"], D(45_100_000))
        # ↑ JS의 node --test → Python의 unittest. assertEqual로 "엔진값 == 세법 정답" 확인
```

JS의 `node --test`처럼 Python도 표준 라이브러리 `unittest`를 써서 **추가 설치 없이** 테스트가 돌아갑니다.

**새로 나온 용어**
- Decimal: 파이썬의 "정확한 십진 계산" 타입. 돈 계산에 부동소수(float) 대신 씀
- 부동소수(float): 소수를 2진수로 근사 저장하는 방식. 빠르지만 `0.1+0.2` 같은 미세 오차가 생김
- `quantize`: Decimal을 원하는 자릿수로 반올림/절사하는 메서드
- unittest: 파이썬 표준 테스트 도구 (JS의 node --test에 대응)
