# 3단계 계획 — 결산보고서 출력 (재무제표 + 계정별 명세서)

> 작성일: 2026-07-15 · 상위 문서: `../PLAN.md` · 항목 원리: `../notes/세무조정계산서-결산보고서-research.md` §4

---

## 1. 이 단계의 이중 역할 — 먼저 이해할 것

3단계는 다른 단계와 성격이 다르다. **결과물을 이미 종이로 갖고 있기 때문**이다.

```
[역할 A — 정답지 공급]  (지금 당장, 가장 먼저 필요)
   종이책 재무제표·명세서를 구조화 입력
   → 1단계 분개 AI의 채점표
   → 2단계 시산표의 채점표
   → 4단계 세무조정의 재료

[역할 B — 생성기]  (1·2단계가 완성된 뒤)
   시산표 → 재무제표·명세서 자동 생성
   → 종이책과 대조해 채점
```

**즉 3단계 입력 작업이 프로젝트 전체의 출발점이다.** 어느 방향으로 가든 이걸 먼저 해야 한다. 생성기(역할 B)는 기술적으로 가장 쉬운 단계이므로 나중에 해도 된다.

---

## 2. 입력 / 출력 / 정답지

**입력 (역할 B 기준)**: 2단계 수정후시산표 + 계정과목→재무제표 분류 매핑 + 전기 재무상태표(비교표시용) + **이익처분 결의 내용**(사람의 판단)

**출력**: 재무상태표, 손익계산서, 이익잉여금처분계산서, 합계잔액시산표, 계정별 명세서 14종, 표준재무제표 3종

**정답지**: 종이책 전체 (항목 하나하나 직접 대조 — 채점 해상도가 가장 높은 단계)

---

## 3. 생성 난이도별 분류

`보고서-준비물-워크플로우.md` §2-1의 등급 그대로. **대부분 [장] 등급 — 확정된 장부만 있으면 기계적 변환이다. 새 재료가 필요 없다.**

| 그룹 | 항목 | 하는 일 |
|---|---|---|
| **기계적 변환 (쉬움)** | 재무상태표, 손익계산서, 합계잔액시산표 | 계정 잔액을 유동성 배열/단계이익 구조로 재배치 |
| **원장 조회 결과** | 보통예금·기타단기금융상품·미지급금·예수금·단기차입금·미지급세금·임대보증금·기타보증금 명세서 | 계정별원장을 거래처별/계좌별로 나열. **1단계 전표가 있으면 자동으로 나온다** |
| **계산 결과 전재** | 유형자산감가상각비명세서, 선급비용명세서, 선납세금명세서 | 2단계 계산 결과를 서식 형태로 |
| **코드 변환** | 표준재무상태표, 합계 표준재무상태표, 표준손익계산서 | 회사 계정과목 → 국세청 표준코드 매핑 (매핑표 필요) |
| **사람의 판단 개입** | 이익잉여금처분계산서 | 배당·적립 결의가 있어야 함 (§5 R1) |

---

## 4. Step

### 역할 A — 종이책 구조화 입력 (지금 즉시, 최우선)

| # | 담당 | 작업 |
|---|---|---|
| 3A-1 | [클로드] | 입력 CSV 템플릿 설계·생성 (컬럼 정의서 + 예시 행) — 재무상태표/손익계산서/시산표/명세서별 |
| 3A-2 | **[사용자]** | **종이책을 보며 수기 입력** ← 프로젝트 전체의 병목. 서식당 10분~1시간 |
| 3A-3 | [클로드] | **입력 무결성 검증기**: 자산=부채+자본, 차변합계=대변합계, PL 당기순이익 ↔ BS·이잉처 연결, 서식 내 소계 재계산, 명세서 합계 ↔ 재무제표 계정 잔액 교차 대사 |
| 3A-4 | **[공동]** | 검증기가 지적한 항목을 종이 원본과 재확인·수정, 통과할 때까지 반복 |

> 3A-3이 중요하다. 수기 입력은 반드시 오타가 나는데, 재무제표는 **내부 정합성이 강한 구조**라 오타를 기계가 잡아낼 수 있다. 사람이 눈으로 검산할 필요가 없다.

**마스킹**: 거래처명 → 코드(`거래처01`), 이름 → 역할코드(`대표A`), 계좌번호 → 은행명+뒤4자리. 금액·날짜는 그대로. → `data/private/fy2025/`

### 역할 B — 생성기 (1·2단계 완성 후)

| # | 담당 | 작업 |
|---|---|---|
| 3B-1 | [클로드] | 계정과목 → 재무제표 분류 매핑 (유동/비유동, 수익/비용 단계) |
| 3B-2 | [클로드] | 재무상태표·손익계산서 생성기 (전기 비교표시 포함) |
| 3B-3 | **[사용자]** | 이익처분 결의 내용 확인 (배당 유무·금액, 이익준비금 적립) — 종이책 이잉처계산서에서 역산 가능 |
| 3B-4 | [클로드] | 이익잉여금처분계산서 생성기 (상법 §458 이익준비금 한도 검증 포함) |
| 3B-5 | [클로드] | 계정별 명세서 14종 생성기 (원장 조회) |
| 3B-6 | [클로드] | 표준재무제표 코드 변환기 (매핑 테이블) |
| 3B-7 | [공동] | 종이책과 항목별 대조 → 차이 추적 |

---

## 5. 완료 기준

- **역할 A**: 검증기 무오류 통과한 구조화 데이터셋 확보 → 1·2·4단계가 모두 채점 가능해짐
- **역할 B**: 생성된 재무제표·명세서가 종이책과 항목별 일치

---

## 6. 리스크

| # | 리스크 | 대응 |
|---|---|---|
| R1 | 이익잉여금처분계산서는 **의사결정 산출물** — 코드가 만들 수 없음 | 재현 시에는 종이책 값 입력. 배당 규모는 5단계 절세 시나리오의 변수로 승격 |
| R2 | 수기 입력 오타 | 3A-3 검증기로 기계 검출 + 4단계 정답지 대조에서 2차 검출 |
| R3 | 표준계정과목 매핑표를 어디서 구하나 | 국세청 표준계정과목 코드 체계 공개 자료. 회사 계정과목 수가 적으면 수작업 매핑이 더 빠름 |
| R4 | 종이책에 전기 재무상태표가 비교표시로만 있어 정보가 부족할 수 있음 | 재현에는 당기만 필요. 비교표시는 출력 형식 문제 |
