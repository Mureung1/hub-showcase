 ## 🦖 찰흙 모형 비유: 뼈대 먼저 세우기                                     
                                                                             
  이번 단기 MVP의 핵심은 **"찰흙으로 공룡 모형 빚기"**입니다. 처음부터 공룡의
  비늘(화려한 CSS, 회원가입, 좋아요, 카테고리 검색)을 정교하게 조각하려다간  
  내일까지 뼈대도 못 세우고 끝납니다. 우선 머리-몸통-꼬리(입력-저장-목록     
  출력)라는 핵심 뼈대만 투박하게 찰흙으로 뭉쳐서 기능이 실제로 한 바퀴       
  굴러가는지(데이터가 흐르는지) 확인해야 합니다.                             
                                                                             
  ## 📊 원래 계획 vs 비상 압축 계획 비교                                     
                                                                             
   기능 구분     │ 원래 계획 (최소 1주일 소요) │ 비상 압축 계획 (내일 완성)
  ───────────────┼─────────────────────────────┼─────────────────────────────
   데이터베이스  │ PostgreSQL/MySQL 연동 및    │ 단일  db.json  파일을
                 │ 스키마 설계                 │ 활용한 초간단 파일 DB
   회원 관리     │ 회원가입, 로그인, JWT 토큰  │ 닉네임+비밀번호 수동 입력
                 │ 인증 처리                   │ 방식 (비회원 작성/삭제용)
   이미지 업로드 │ AWS S3 연동 및 이미지       │ HTML5 FileReader API 활용 ➔
                 │ 업로드 서버 구축            │ Base64 텍스트 변환 후
                 │                             │ JSON에 직접 저장
   목록/조회     │ 카테고리 필터링, 검색, 무한 │ 최신순 단일 피드 목록 및
		 │ 스크롤, 댓글                │ 모달 상세 조회
  ──────
  ## 🛠️ 기술적 치트키 (Shortcut Hacks)
  
  1. HTML5  FileReader  & Base64 이미지 변환: S3나 이미지 업로드 API 세팅    
  단계를 완전히 건너뜁니다. 유저가 올린 이미지를 브라우저 단에서 Base64      
  텍스트로 즉시 변환하여 텍스트 데이터와 함께 DB에 한 번에 전송합니다.       
  2.  db.json  파일 기반 가상 DB: 별도의 DB 엔진이나 ORM 세팅 없이, Node.js  
  서버에서 JSON 파일을 읽고 쓰는 방식으로 10줄 이내로 DB 처리를 완료합니다.  
  ──────
  ## 📅 데이터 의존성 기반의 4단계 격파 일정
  
  ### 1단계: 프론트엔드 입력 폼 & 이미지 인코딩 구현 (인풋 확보)             
  
  • 태스크: 레시피 이름, 사용 편의점, 재료 설명, 제작 단계, 작성자 닉네임을  
  적는 입력 폼과 이미지 선택 버튼을 만듭니다.
  • 검증: 이미지를 선택했을 때 Base64 코드로 정상 변환되는지 브라우저 콘솔   
  로그로 확인합니다.
  • 의존성: 이 단계에서 데이터 포맷이 확정되어야 2단계 서버에서 데이터를 받을
  수 있습니다.
  
  ### 2단계: 백엔드 API 서버 구축 & 파일 DB 연동 (저장소 연결)
  
  • 태스크: Express.js 등을 이용해  POST /api/recipes  엔드포인트를          
  구현합니다. 들어오는 데이터를  db.json  배열 파일에 추가( fs.writeFile     
  )합니다.
  • 검증: Postman이나 curl로 더미 데이터를 보냈을 때  db.json  파일에 잘     
  써지는지 확인합니다.
  • 의존성: 저장 매커니즘이 완성되어야 3단계에서 불러올 데이터가 생깁니다.   
  
  ### 3단계: 레시피 목록 및 상세 API 구현 (가공 및 반환)
  
  • 태스크:  GET /api/recipes  API를 구현하여  db.json 에 저장된 전체 레시피 
  배열을 최신순으로 반환합니다.
  • 검증: 브라우저에서 해당 API를 호출했을 때 JSON 목록이 잘 나오는지        
  확인합니다.
  • 의존성: 데이터 반환 API가 있어야 4단계에서 화면에 띄울 수 있습니다.      
  
  ### 4단계: 화면 연동 및 한 바퀴 검증 (아웃풋 표출)
  
  • 태스크: 메인 화면에 2단계와 3단계의 API를 연결합니다. 레시피를 작성하면  
  목록에 실시간으로 카드가 추가되도록 붙입니다.
  • 검증: 실제로 모바일이나 PC 브라우저로 접속해서 "불닭 삼각김밥 레시피"를  
  올렸을 때 이미지와 글이 목록에 바로 뜨는지 최종 테스트합니다.
