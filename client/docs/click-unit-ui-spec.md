# Click Unit UI Specification

## 기준

- 이 문서는 나의 책장 MVP의 화면별 클릭, 입력, 상태 변화를 정의한다.
- 제품 정책은 `client/docs/product-prd.md`, 화면 흐름은 `client/docs/user-flow.md`, 컴포넌트 책임은 `client/docs/component-implementation-notes.md`를 따른다.
- P0는 서버 저장이 성공해야 책장과 기록 페이지를 완료 상태로 갱신한다.
- 타이머는 P1의 선택 기능이다. P0의 기록 저장은 타이머와 독립적이다.

## 공통 상태 모델

```text
user
- id
- nickname

book
- id
- userId
- title
- author: nullable
- initialPage
- status: READING | COMPLETED | ARCHIVED — `ARCHIVED`는 P1 이후
- createdAt

readingRecord
- id
- bookId
- userId
- startPage
- endPage
- impression: nullable
- keywords: string[] — P2 이후
- createdAt

uiState
- route: onboarding | bookshelf | bookDetail
- pathname: / | /bookshelf | /books/{bookId}
- selectedBookId
- isAddBookOpen
- isRecordDialogOpen
- isReadingContextActive
- loadingAction
- toast

draftState
- draftNickname
- draftBook
- draftRecord
```

`nextStartPage`는 별도로 저장하지 않는다. `createdAt DESC, id DESC` 기준의 가장 최근 기록 `endPage + 1`을 사용하고, 기록이 없으면 `book.initialPage`를 사용한다.

## 공통 규칙

### 서버 요청 중 버튼

- 조건: 책 등록 또는 세션 기록 저장 요청이 진행 중이다.
- 즉시 화면 반응: 버튼을 비활성화하고 진행 상태를 표시한다.
- 상태 변화: 추가 제출을 막는다.
- 예외: 요청이 실패하면 입력값을 유지하고 다시 제출할 수 있다.

### 서버 요청 실패

- 조건: 네트워크 오류, 서버 오류, 유효성 오류가 발생했다.
- 즉시 화면 반응: 현재 화면과 draft를 유지하고 오류 메시지와 재시도 CTA를 보여 준다.
- 상태 변화: 성공 상태나 책장 목록을 임의로 갱신하지 않는다.
- 사용자 안내: `저장하지 못했어요. 입력한 내용은 그대로 있어요.`

### 저장 응답을 확인할 수 없음

- 조건: 기록 저장 요청의 응답이 시간 초과되거나 네트워크가 끊겨 서버 반영 여부를 알 수 없다.
- 즉시 화면 반응: `저장 여부를 확인하고 있어요.`를 보여 주며 `draftRecord`를 유지한다.
- 상태 변화: 같은 요청을 자동으로 다시 보내지 않고, 책 상세를 재조회한다.
- 예외: 재조회 결과에 같은 새 기록이 있으면 성공 상태로 갱신한다. 없다면 사용자에게 다시 저장을 선택하게 한다.

### 새로고침

- 조건: 어느 화면에서든 새로고침한다.
- 즉시 화면 반응: 서버에서 사용자·책장·책 상세를 다시 조회한다.
- 상태 변화: 열려 있던 dialog와 읽기 준비 상태는 유지하지 않아도 된다.
- 예외: 최근 기록을 기준으로 다음 시작 페이지를 다시 계산한다.

### 키보드와 dialog

- 모든 입력에는 연결된 label을 제공한다.
- dialog가 열리면 첫 입력 필드에 포커스한다.
- 저장 중이 아닐 때 `Esc`는 dialog를 닫을 수 있다.
- 저장 중에는 바깥 클릭과 `Esc`로 dialog를 닫지 않는다.
- dialog는 제목·설명과 연결하고 포커스를 안에 가둔다. 닫힌 뒤에는 호출한 CTA로 포커스를 돌린다.
- 값이 있는 draft를 저장하지 않고 닫으려 하면 `작성 중인 내용이 사라져요.` 확인을 거친다.
- form은 native `<form>`으로 구현해 Enter 제출을 지원한다. 오류 필드는 `aria-invalid`로 표시하고, 제출 뒤 첫 오류 필드로 포커스를 옮긴다.

## 1. 온보딩

### 입력: 닉네임

- 조건: 온보딩 화면이 열려 있다.
- 즉시 화면 반응: 입력값이 `draftNickname`에 반영된다.
- 상태 변화: 유효성 오류가 있었다면 입력 시점에 해제할 수 있다.

### 클릭: 내 책장 시작하기

- 조건: 공백을 제거한 닉네임이 1자 이상이다.
- 즉시 화면 반응: 제출 버튼이 loading 상태가 된다.
- 상태 변화: 사용자 생성 API가 성공하면 `user.id`, `user.nickname`을 이 브라우저에 저장하고 pathname을 `/bookshelf`로 바꾼다. 닉네임은 기존 사용자를 조회하는 데 쓰지 않는다.
- 예외: 닉네임이 비어 있으면 현재 화면에 오류를 표시하고 제출하지 않는다.

## 2. 내 책장

### 클릭: 최근 이어 읽기 CTA

- 조건: 기록이 있는 `READING` 책이 있거나, 기록은 없지만 등록된 `READING` 책이 있다.
- 즉시 화면 반응: 선택한 책의 제목과 현재 위치를 확인할 수 있게 책 상세로 이동하고, `{nextStartPage}쪽부터 읽고, 돌아와서 기록을 남겨 보세요.`를 보여 준다.
- 상태 변화: `selectedBookId`, route, pathname이 책 상세로 바뀌고 `isReadingContextActive = true`가 된다.
- 예외: 기록 없는 새 책은 `처음 읽기`와 `initialPage`를 같은 방식으로 사용한다. 책 조회 실패 시 목록을 유지하고 오류를 보여 준다.

### 클릭: 책등

- 조건: 읽는 중 선반에 책이 표시되어 있다.
- 즉시 화면 반응: 해당 책의 상세를 연다.
- 상태 변화: `selectedBookId`, route, pathname이 책 상세로 바뀐다. `isReadingContextActive`는 시작하지 않는다.
- 예외: 기록이 없는 새 책도 동일하게 열며, 시작 페이지를 기준으로 `처음 읽기`를 안내한다.

### 클릭: 읽고 있는 책 추가

- 조건: 내 책장 화면이 열려 있다.
- 즉시 화면 반응: 책 등록 dialog를 연다.
- 상태 변화: `isAddBookOpen = true`, `draftBook.initialPage = 1`로 초기화한다.
- 예외: 없음.

### 이벤트: 빈 책장

- 조건: `READING` 책이 없다.
- 즉시 화면 반응: `첫 책이 들어올 자리예요.`와 책 추가 CTA를 보여 준다.
- 상태 변화: 없음.
- 예외: 빈 책장을 실패, 경고, 낮은 점수로 표현하지 않는다.

## 3. 책 등록

### 입력: 제목, 저자, 시작 페이지

- 조건: 책 등록 dialog가 열려 있다.
- 즉시 화면 반응: 해당 `draftBook` 필드가 갱신된다.
- 상태 변화: 제목과 시작 페이지 오류가 있다면 입력 중 해제할 수 있다.
- 예외: 저자는 비워 둘 수 있다. 시작 페이지 입력은 항상 `1`로 초기화하며, 서버는 누락된 값도 1로 정규화한다.

### 클릭: 책장에 꽂기

- 조건: 제목이 1자 이상이고 시작 페이지가 1 이상의 정수다.
- 즉시 화면 반응: 제출 버튼이 loading 상태가 된다.
- 상태 변화: `POST /api/books` 성공 뒤 새 책을 books 목록에 추가하고, dialog를 닫고, 해당 책의 상세로 이동한다.
- 예외:
  - 제목이 비어 있으면 제목 필드 오류를 표시한다.
  - 시작 페이지가 1 미만 또는 정수가 아니면 오류를 표시한다.
  - 실패 시 입력값을 유지한다.

### 클릭: 취소 또는 dialog 닫기

- 조건: 저장 중이 아니다.
- 즉시 화면 반응: dialog를 닫는다.
- 상태 변화: 저장되지 않은 `draftBook`은 폐기한다.
- 예외: 입력값이 있으면 `작성 중인 내용이 사라져요.` 확인 뒤 닫는다. 저장 중에는 닫을 수 없다.

## 4. 책 상세과 이어 읽기

### 클릭: 책장으로 돌아가기

- 조건: 책 상세가 열려 있다.
- 즉시 화면 반응: 내 책장으로 이동한다.
- 상태 변화: route를 `bookshelf`로 바꾸고 `selectedBookId`를 해제한다.
- 예외: 기록을 막 저장한 뒤라면 목록에서 해당 책이 최근 읽은 책으로 보인다.

### 클릭: n쪽부터 이어 읽기 또는 처음 읽기

- 조건: 책 상세와 `nextStartPage`가 준비돼 있다.
- 즉시 화면 반응: `{nextStartPage}쪽부터 읽고, 돌아와서 기록을 남겨 보세요.`라는 읽기 준비 상태를 보여 준다.
- 상태 변화: `isReadingContextActive = true`로 바꾼다. 서버 저장은 발생하지 않는다.
- 예외: 브라우저는 독서 여부, 체류 시간, 네트워크 상태를 검증하지 않는다.

### 클릭: 이번 읽기 기록 남기기

- 조건: 책 상세가 열려 있다. 읽기 준비 상태가 아니어도 사용자가 직접 기록을 남길 수 있다.
- 즉시 화면 반응: 세션 기록 dialog를 연다.
- 상태 변화: `isRecordDialogOpen = true`, `draftRecord.endPage = ''`, `draftRecord.startPageOverride = null`로 초기화한다.
- 예외: 기본 시작 위치는 `nextStartPage`로 계산하며, 사용자는 예외 상황에서만 직접 바꿀 수 있다.

### 표시: 세션 기록 페이지

- 조건: 책에 `readingRecord`가 하나 이상 있다.
- 즉시 화면 반응: 기록을 오래된 순서로 표시한다.
- 표시 정보: 날짜, 페이지 범위, 감상이 있을 때만 감상 전문.
- 예외: 동일한 페이지 범위를 다시 기록하는 것을 차단하지 않는다. 다시 읽은 기록도 유효하다. P1의 수정·삭제 행동은 가장 최근 기록에만 표시한다.

### 표시: 마지막 서평 미리보기

- 조건: P0의 책 상세 하단이다.
- 즉시 화면 반응: `완독하면 이 책의 마지막 장에 긴 서평을 남길 수 있어요.`를 표시한다.
- 상태 변화: 없음.
- 예외: P0에서는 클릭 가능한 잠금 해제나 완독 상태 변경을 제공하지 않는다.

## 5. 세션 기록 저장

### 입력: 끝난 페이지

- 조건: 세션 기록 dialog가 열려 있다.
- 즉시 화면 반응: `draftRecord.endPage`를 갱신하고, 자동 시작 위치부터 끝난 페이지까지의 범위와 계산된 페이지 수를 미리 보여 준다.
- 상태 변화: 페이지 검증 오류가 있었다면 입력 시 해제할 수 있다.
- 예외: 끝난 페이지는 기본 또는 직접 지정한 시작 위치보다 작을 수 없다.

### 클릭: 시작 위치 직접 바꾸기

- 조건: 사용자가 다시 읽기나 건너뛰기처럼 자동 시작 위치와 다른 곳에서 읽었다.
- 즉시 화면 반응: 시작 페이지 입력을 추가로 보여 준다.
- 상태 변화: `draftRecord.startPageOverride`를 편집할 수 있다.
- 예외: 이 입력은 기본적으로 접혀 있으며, 비워 두면 `nextStartPage`를 사용한다.

### 입력: 짧은 감상

- 조건: 세션 기록 dialog가 열려 있다.
- 즉시 화면 반응: `draftRecord.impression`을 갱신한다.
- 상태 변화: 없음.
- 사용자 안내: `한 줄이면 충분해요. 비워 두어도 괜찮아요.`

### 입력: 생각 키워드 — P2

- 조건: 세션 기록 dialog가 열려 있다.
- 즉시 화면 반응: 사용자가 입력한 키워드를 칩으로 추가하거나 제거한다.
- 상태 변화: `draftRecord.keywords`에 최대 3개를 유지한다.
- 예외: 앞뒤 공백과 같은 키워드는 정리하고, 키워드가 없어도 기록 저장은 가능하다.

### 클릭: 기록 페이지 추가

- 조건: 끝난 페이지가 1 이상의 정수이고 자동 또는 직접 지정한 시작 위치보다 작지 않다.
- 즉시 화면 반응: 제출 버튼이 loading 상태가 된다.
- 상태 변화:
  - `POST /api/books/{bookId}/records` 성공 후 서버 응답으로 책 상세의 records와 bookmark summary를 갱신한다.
  - dialog를 닫고 `isReadingContextActive = false`로 바꾼다.
  - 갱신된 `nextStartPage`를 보여 준다.
- 예외:
  - 끝난 페이지가 시작 위치보다 작으면 저장하지 않고 필드 오류를 표시한다.
  - 감상이 비어 있어도 저장한다.
  - 저장 실패 시 draft를 유지하고 재시도할 수 있다.

### 클릭: 기록 작성 취소

- 조건: 저장 중이 아니다.
- 즉시 화면 반응: 입력값이 있으면 `작성 중인 내용이 사라져요.` 확인을 보여 준 뒤 dialog를 닫는다.
- 상태 변화: 저장되지 않은 `draftRecord`을 폐기한다. 읽기 준비 상태는 유지할 수 있다.
- 예외: 기존 서버 기록은 변경하지 않는다.

## 6. P1 이후 클릭

### 클릭: 잠시 보관하기

- 조건: `READING` 책의 상세 화면이 열려 있다.
- 즉시 화면 반응: `나중에 마지막 책갈피에서 다시 꺼낼 수 있어요.`라는 안내와 함께 보관 확인 dialog를 연다.
- 상태 변화: 확인 뒤 `PATCH /api/books/{bookId}/status`가 성공하면 상태를 `ARCHIVED`로 바꾸고, 읽는 중 선반에서는 제거해 보관함에 표시한다.
- 예외: 세션 기록과 마지막 책갈피는 삭제하지 않는다. 서버 요청이 실패하면 현재 화면과 책 상태를 유지한다.

### 클릭: 다시 읽는 중으로 옮기기

- 조건: P1의 보관함에서 `ARCHIVED` 책을 열었다.
- 즉시 화면 반응: 복귀 확인을 거쳐 `READING` 선반으로 돌아갈 것을 안내한다.
- 상태 변화: 성공하면 책 상태를 `READING`으로 바꾸고 기존 `nextStartPage`를 그대로 보여 준다.
- 예외: 기록이 없던 책은 처음 등록한 시작 페이지부터 다시 시작한다.

### 클릭: 가장 최근 기록 수정

- 조건: P1에서 책 상세의 가장 최근 세션 기록이다.
- 즉시 화면 반응: 기존 끝난 페이지와 감상을 채운 기록 수정 dialog를 연다.
- 상태 변화: `PATCH /api/books/{bookId}/records/{recordId}` 성공 뒤 서버 응답으로 기록 목록, 마지막 책갈피, `nextStartPage`, 최근 이어 읽기 카드를 갱신한다.
- 예외: 이전 기록에는 수정 행동을 노출하지 않는다. 끝난 페이지는 해당 기록의 시작 페이지보다 작을 수 없다.

### 클릭: 가장 최근 기록 삭제

- 조건: P1에서 책 상세의 가장 최근 세션 기록이다.
- 즉시 화면 반응: 삭제하면 다음 시작 페이지가 다시 계산된다는 확인 dialog를 연다.
- 상태 변화: `DELETE /api/books/{bookId}/records/{recordId}` 성공 뒤 서버 응답으로 기록 목록과 책갈피 요약을 갱신한다.
- 예외: 이전 기록에는 삭제 행동을 노출하지 않는다. 삭제 실패 시 기존 기록을 화면에서 제거하지 않는다.

### 가리키기 또는 포커스: 읽기 기록 달력의 날짜

- 조건: P1에서 책장 화면에 최근 12주의 읽기 기록 달력이 보인다.
- 즉시 화면 반응: 해당 날짜와 저장한 기록 수를 tooltip 또는 접근 가능한 설명으로 보여 준다.
- 상태 변화: 없음. 이 기능은 개인 활동 요약이며 목표·점수·스트릭을 바꾸지 않는다.
- 예외: 기록이 없는 날짜는 오류나 실패로 표현하지 않는다.

### 클릭: 집중 시간 정하기

- 조건: P1에서 사용자가 읽기 준비 상태다.
- 즉시 화면 반응: 15/30/60분 등 선택 가능한 타이머 패널을 연다.
- 상태 변화: 타이머의 일시 UI 상태만 바꾼다.
- 예외: 타이머 종료·중단은 기록 저장 가능 여부를 바꾸지 않는다.

### 클릭: 완독으로 옮기기

- 조건: P1에서 읽는 중 책 상세가 열려 있다.
- 즉시 화면 반응: 완독과 마지막 서평 dialog를 연다.
- 상태 변화: 사용자가 확인하면 책 상태를 `COMPLETED`로 저장하고 완독 선반으로 옮긴다.
- 예외: 긴 서평을 비워 두거나 나중에 작성해도 완독 처리할 수 있다.

## 7. P2 생각 모아보기

### 클릭: 기록 페이지의 생각 키워드

- 조건: 기록에 하나 이상의 키워드가 있다.
- 즉시 화면 반응: 선택한 키워드로 생각 모아보기 화면 또는 패널을 연다.
- 상태 변화: 현재 키워드 필터를 설정하고 해당 키워드의 자기 기록을 조회한다.
- 예외: 다른 사람의 기록, 비공개 세션 감상, 친구 활동은 결과에 포함하지 않는다.
