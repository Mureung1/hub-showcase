# Click Unit UI Specification

## 기준

- 이 문서는 `client/docs/user-flow.md`를 클릭 단위로 쪼갠 UI 명세다.
- 상위 로드맵은 GitHub Wiki의 [Frontend Priority Roadmap](https://github.com/Tapha-K/hub/wiki/Frontend-Priority-Roadmap)을 기준으로 한다.
- 제품 본질, MVP 범위, 용어, 지표, 데이터 정책은 `client/docs/product-prd.md`를 기준으로 한다.
- 컴포넌트별 구현 책임, props, state, handler 후보는 `client/docs/component-implementation-notes.md`에서 분리 관리한다.
- 목적은 화면을 깔끔하게 줄이는 것이 아니라, UI 컴포넌트를 잘게 나눌 수 있도록 가능한 클릭과 상태 변화를 많이 드러내는 것이다.
- 각 항목은 `조건`, `즉시 화면 반응`, `상태 변화`, `다음 화면`, `예외`를 기준으로 작성한다.
- MVP 데이터 저장소는 `localStorage`다.
- 빠른 시작은 방 상세를 `시작 전 확인` 화면으로 먼저 보여주고, 방 상세에서 세션 시작을 한 번 더 누르게 한다.
- 세션은 타이머가 끝난 뒤에만 `기록 작성하기` CTA가 활성화된다.
- `readyToRecord`는 내부 상태명이고, 사용자 화면에서는 `기록 대기`로 표시한다.
- 완료 기록은 책 제목, 시작 페이지, 끝 페이지, 감상을 모두 필수로 받는다.
- 타이머 종료 후 사용자가 바로 기록하지 않고 나가는 `나중에 작성` 흐름을 허용한다.
- 내 기록 화면은 MVP에서 필터와 정렬을 포함하고, 검색은 후보로만 둔다.
- 샘플 데이터는 실제 데이터와 같은 목록에 섞어 보여주되 `샘플` 배지와 필터로 구분한다.
- 기존 active 또는 기록 대기 세션이 있으면 빠른 시작으로 새 방을 만들지 않고 기존 세션 복귀를 우선한다.
- 기록 상세는 별도 화면이 아니라 모달로 연다.

## 공통 클릭 규칙

### 클릭: 로딩 중 버튼

- 조건: 버튼이 loading 상태다.
- 즉시 화면 반응: 추가 클릭을 무시한다.
- 상태 변화: 없음.
- 다음 화면: 없음.
- 예외: 저장 실패 후 loading이 풀리면 다시 클릭할 수 있다.

### 클릭: 모달 바깥 영역

- 조건: 확인 모달이 열려 있고 저장 중이 아니다.
- 즉시 화면 반응: 모달을 닫는다.
- 상태 변화: 없음.
- 다음 화면: 이전 화면 유지.
- 예외: 삭제/초기화처럼 파괴적 작업 모달은 바깥 클릭 닫기를 막을 수 있다.

### 키 입력: `Esc`

- 조건: 모달이 열려 있고 저장 중이 아니다.
- 즉시 화면 반응: 모달을 닫는다.
- 상태 변화: 없음.
- 다음 화면: 이전 화면 유지.
- 예외: 저장 중에는 무시한다.

### 이벤트: 새로고침

- 조건: 어느 화면에서든 발생할 수 있다.
- 즉시 화면 반응: `localStorage` 기준으로 현재 가능한 화면을 복원한다.
- 상태 변화: 타이머 화면이면 `endsAt` 기준으로 남은 시간을 재계산한다.
- 다음 화면: 온보딩 완료 여부, 진행 세션, 기록 대기 세션에 따라 분기한다.
- 예외: 저장 데이터 파싱 실패 시 데이터 복구/초기화 안내 화면을 보여준다.

### 이벤트: `localStorage` 저장 실패

- 조건: quota 초과, 직렬화 실패, 브라우저 저장 제한.
- 즉시 화면 반응: 현재 입력값은 화면에 유지하고 `저장 공간이 부족해요` 오류를 보여준다.
- 상태 변화: 없음.
- 다음 화면: 현재 화면 유지.
- 예외: 샘플 생성 실패도 같은 방식으로 처리한다.

## 1. 온보딩

### 표시 요소 후보

- 서비스 한 줄 설명
- `혼자 읽기보다 같이 읽는 느낌` 보조 카피
- 닉네임 입력 필드
- 최근 사용 닉네임 칩
- 예시 닉네임 보기 링크
- 기능 소개 아코디언
- `로그인 없이 이용 가능` 안내
- `이 앱은 브라우저에만 저장됩니다` 안내
- `시작하기` CTA
- `샘플 데이터로 둘러보기` CTA
- `데이터 초기화` CTA

### 클릭: 닉네임 입력 필드

- 조건: 온보딩 화면이 열려 있다.
- 즉시 화면 반응: 입력 필드에 포커스가 가고 placeholder가 약해진다.
- 상태 변화: `draftNickname` 편집 상태 시작.
- 다음 화면: 없음.
- 예외: 없음.

### 입력: 닉네임 텍스트

- 조건: 닉네임 입력 필드에 포커스가 있다.
- 즉시 화면 반응: 입력값과 글자 수 카운터가 갱신된다.
- 상태 변화: `draftNickname` 갱신.
- 다음 화면: 없음.
- 예외: 20자 초과 시 `닉네임은 20자 이내로 입력해 주세요`를 표시하고 저장을 막는다.

### 클릭: 최근 사용 닉네임 칩

- 조건: `user.lastUsedNickname`이 있다.
- 즉시 화면 반응: 입력 필드에 닉네임이 채워진다.
- 상태 변화: `draftNickname` 갱신.
- 다음 화면: 없음.
- 예외: 저장된 닉네임이 현재 검증 규칙에 맞지 않으면 입력만 채우고 에러를 표시한다.

### 클릭: `예시 닉네임 보기`

- 조건: 없음.
- 즉시 화면 반응: 예시 닉네임 목록을 펼친다.
- 상태 변화: 예시 목록 펼침 상태 토글.
- 다음 화면: 없음.
- 예외: 이미 펼쳐져 있으면 접는다.

### 클릭: 예시 닉네임 항목

- 조건: 예시 닉네임 목록이 펼쳐져 있다.
- 즉시 화면 반응: 선택한 닉네임이 입력 필드에 채워진다.
- 상태 변화: `draftNickname` 갱신.
- 다음 화면: 없음.
- 예외: 없음.

### 클릭: `기능 소개`

- 조건: 기능 소개 아코디언이 있다.
- 즉시 화면 반응: `방 만들기`, `타이머`, `완료 기록`, `내 기록` 설명 패널을 펼친다.
- 상태 변화: 아코디언 펼침 상태 토글.
- 다음 화면: 없음.
- 예외: 다시 누르면 닫는다.

### 클릭: `시작하기`

- 조건: 닉네임이 공백을 제외하고 1자 이상이며 20자 이하다.
- 즉시 화면 반응: 버튼을 loading 상태로 바꾸고 중복 클릭을 막는다.
- 상태 변화: `user.nickname`, `user.lastUsedNickname`, `user.hasOnboarded = true` 저장.
- 다음 화면: 방 목록.
- 예외: 저장 실패 시 현재 화면에 머물고 오류를 표시한다.

### 클릭: `시작하기`

- 조건: 닉네임이 비어 있거나 공백뿐이다.
- 즉시 화면 반응: 입력창 아래 `닉네임을 입력해 주세요` 표시.
- 상태 변화: 없음.
- 다음 화면: 없음.
- 예외: 없음.

### 키 입력: 닉네임 필드에서 `Enter`

- 조건: 닉네임 입력 필드에 포커스가 있다.
- 즉시 화면 반응: `시작하기` 클릭과 동일하게 처리한다.
- 상태 변화: 유효하면 사용자 저장, 무효하면 없음.
- 다음 화면: 유효하면 방 목록.
- 예외: 조합 중인 한글 입력 상태에서는 Enter를 제출로 처리하지 않는다.

### 클릭: `샘플 데이터로 둘러보기`

- 조건: 기존 사용자 데이터가 없다.
- 즉시 화면 반응: 버튼을 loading 상태로 바꾸고 샘플 생성 중 문구를 표시한다.
- 상태 변화: 샘플 `rooms`, `sessions`, `readingRecords` 생성, 닉네임이 없으면 샘플 닉네임 저장.
- 다음 화면: 방 목록.
- 예외: 저장 실패 시 `샘플 데이터를 만들지 못했어요` 표시.

### 클릭: `샘플 데이터로 둘러보기`

- 조건: 기존 사용자 데이터가 있다.
- 즉시 화면 반응: 샘플 덮어쓰기 확인 모달을 연다.
- 상태 변화: 아직 없음.
- 다음 화면: 샘플 덮어쓰기 확인 모달.
- 예외: 없음.

### 클릭: `데이터 초기화`

- 조건: 저장된 MVP 데이터가 있다.
- 즉시 화면 반응: 초기화 확인 모달을 연다.
- 상태 변화: 아직 없음.
- 다음 화면: 초기화 확인 모달.
- 예외: 저장된 데이터가 없으면 버튼을 비활성화한다.

- 다음 화면: 온보딩 또는 이전 화면 유지.
- 예외: 없음.

## 4. 방 목록

### 표시 요소 후보

- 현재 닉네임
- `빠른 시작`, `방 만들기`, `내 기록` 주요 CTA
- 진행 중 세션 복귀 배너
- 기록 대기 배너
- 방 카드 목록
- 최근 본 방 섹션
- 필터 칩: 전체, 입문자 환영, 토론 없음, 토론 가능, 15분, 30분, 60분
- 정렬 드롭다운: 최신순, 짧은 시간순, 참여 많은 순, 감상 많은 순
- 빈 상태 카드
- 샘플 데이터 추가 CTA
- 데이터 초기화 CTA

### 클릭: `빠른 시작`

- 조건: `user.nickname`이 있다.
- 즉시 화면 반응: 빠른 시작 화면으로 전환한다.
- 상태 변화: 없음.
- 다음 화면: 빠른 시작.
- 예외: 닉네임이 없으면 온보딩으로 이동한다.

### 클릭: `방 만들기`

- 조건: `user.nickname`이 있다.
- 즉시 화면 반응: 방 생성 화면으로 전환한다.
- 상태 변화: 없음.
- 다음 화면: 방 생성.
- 예외: 닉네임이 없으면 온보딩으로 이동한다.

### 클릭: `내 기록`

- 조건: `user.nickname`이 있다.
- 즉시 화면 반응: 내 기록 화면으로 전환한다.
- 상태 변화: 없음.
- 다음 화면: 내 기록.
- 예외: 닉네임이 없으면 온보딩으로 이동한다.

### 클릭: `방 카드`

- 조건: `room.id`가 존재한다.
- 즉시 화면 반응: 카드가 선택 강조되고 방 상세로 이동한다.
- 상태 변화: `selectedRoomId` 설정, `recentRoomIds` 갱신.
- 다음 화면: 방 상세.
- 예외: 방을 찾을 수 없으면 해당 카드를 제거하고 `방을 찾을 수 없어요` 배너를 표시한다.

### 클릭: 방 카드의 시간 칩

- 조건: 시간 칩이 클릭 가능하게 설계되어 있다.
- 즉시 화면 반응: 같은 세션 시간 필터를 적용한다.
- 상태 변화: `roomFilter.durationMinutes` 갱신.
- 다음 화면: 방 목록 유지.
- 예외: 필터 결과가 0개면 필터 빈 상태를 보여준다.

### 클릭: 방 카드의 분위기 태그

- 조건: 태그가 클릭 가능하게 설계되어 있다.
- 즉시 화면 반응: 해당 조건 필터를 적용한다.
- 상태 변화: `roomFilter.discussionEnabled` 또는 `roomFilter.beginnerFriendly` 갱신.
- 다음 화면: 방 목록 유지.
- 예외: 필터 결과가 0개면 필터 빈 상태를 보여준다.

### 클릭: 방 카드의 감상 수 배지

- 조건: `room.impressionCount > 0`.
- 즉시 화면 반응: 감상 미리보기 모달을 연다.
- 상태 변화: `activeModal = roomImpressions`.
- 다음 화면: 감상 미리보기 모달.
- 예외: 감상이 없으면 `아직 감상이 없어요` 툴팁을 표시한다.

- `Toast`: 저장 성공, 저장 실패, 복구 안내, 샘플 생성 완료를 표시한다.
- `EmptyStateCard`: 방 없음, 필터 결과 없음, 기록 없음, 데이터 손상을 표시한다.
- `StatusBadge`: 진행 중, 기록 대기, 완료됨, 이탈됨, 샘플, 템플릿 기반을 표시한다.
- `OptionChip`: 시간, 토론 여부, 입문자 환영, 필터를 공통 처리한다.
- `RoomCard`: 방 제목, 설명, 시간, 태그, 통계, 감상 수 액션을 포함한다.
- `QuickStartTemplateCard`: 템플릿 정보, 설명 펼치기, 선택 loading을 포함한다.
- `RoomForm`: 제목, 설명, 시간, 토론 여부, 입문자 여부, 미리보기를 포함한다.
- `RoomSummaryPanel`: 방 상세의 메타 정보와 규칙 패널을 표시한다.
- `SessionTimerDisplay`: `MM:SS`, almost done 색상, 진행률 바를 표시한다.
- `SessionExitModal`: active 이탈과 기록 대기 상태 이탈 문구를 분리한다.
- `RecordForm`: 책 제목, 페이지 범위, 감상, 필드 검증을 포함한다.
- `RecordCard`: 기록 목록의 날짜, 방, 책, 페이지, 감상 요약을 표시한다.
- `RecordDetailModal`: 기록 상세, 방 재입장, 감상 더보기를 제공한다.

## 확정 정책

- 타이머 종료 후 `나중에 작성`을 허용한다.
- `readyToRecord` 세션은 사용자 화면에서 `기록 대기`로 표시한다.
- `readyToRecord` 세션은 방 목록의 `기록 대기` 배너와 내 기록의 `기록 대기` 필터에서 복귀할 수 있게 한다.
- 내 기록 화면은 MVP에서 필터와 정렬을 포함한다.
- 내 기록 검색은 MVP에서 노출하지 않고 후속 후보로 둔다.
- 샘플 데이터는 실제 데이터와 같은 목록에 섞어 보여주되 `샘플` 배지와 필터로 구분하고 목표 진행률에는 포함하지 않는다.
- 빠른 시작 중 기존 active 또는 기록 대기 세션이 있으면 새 방 생성을 허용하지 않고 기존 세션 복귀를 우선한다.
- 빠른 시작으로 만든 방은 세션 시작 전까지 임시 방이며, `다시 고르기`를 누르면 폐기한다.
- 기록 상세는 별도 화면이 아니라 모달로 처리한다.

## 남은 결정 필요 항목

- 방 카드의 감상 수 배지를 클릭해 미리보기 모달을 여는 기능을 MVP에 포함할지 결정해야 한다.
- 방 생성 취소 시 입력값이 있을 때 항상 확인 모달을 띄울지, 단순 폐기할지 결정해야 한다.
- 기록 편집/삭제/복제는 브레인스토밍 후보로 남겼으며 MVP 포함 여부를 별도 결정해야 한다.
- 닉네임 특수문자/금칙어 검증을 둘지, 공백과 길이만 검증할지 결정해야 한다.
