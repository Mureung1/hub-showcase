## 제품 본질

이 서비스는 책을 읽고 싶지만 매번 어디부터 다시 읽을지 망설여 독서를 미루는 사용자가, 마지막 책갈피에서 책을 다시 열고 읽은 흔적을 한 권의 독서 노트에 쌓게 돕는 PC 웹 서비스다.

핵심 루프는 다음과 같다.

```text
책을 내 책장에 등록한다
-> 지난 책갈피에서 책을 다시 연다
-> 끝난 페이지와 짧은 감상을 남긴다
-> 다음 시작 페이지가 갱신된다
-> 같은 책을 다시 이어 읽는다
```

타이머는 집중을 감시하거나 독서 여부를 증명하는 장치가 아니다. 사용자가 읽기 시작을 돕기 위해 선택할 수 있는 보조 기능이다. 타이머를 사용하지 않거나 중단해도 세션 기록을 남길 수 있어야 한다.

## 문제 정의

### 사용자 문제

- 읽고 싶은 책은 있지만, 재방문할 때 무엇을 읽고 있었고 어디까지 읽었는지 기억하기 어렵다.
- 읽은 직후 긴 글을 쓰는 일은 부담스러워 기록 자체를 미루게 한다.
- 일반 타이머는 시간을 남기지만, 어느 책을 어떻게 이어 읽을지 알려 주지 않는다.
- 연속 출석, 점수, 순위는 며칠 쉬었을 때 독서를 다시 시작하는 일을 실패처럼 느끼게 할 수 있다.
- 책장 꾸미기나 친구 기능이 먼저 나오면 독서를 시작하기보다 서비스를 꾸며야 한다는 부담이 생길 수 있다.

### 제품 문제

- 책장 UI가 재개 행동보다 앞서면 장식으로만 보인다.
- 세션 감상을 매번 필수로 받으면 독서보다 기록이 숙제가 된다.
- 이전 기록의 끝 페이지를 그대로 강제하면 다시 읽기나 건너뛰기 같은 실제 독서 흐름을 막는다.
- 친구 서재를 성급하게 추가하면 관계, 공개 범위, 개인정보와 비교 압박까지 함께 설계해야 한다.

## 대상 사용자

### 첫 방문 사용자

- 책을 읽고 싶지만 시작하기 전 설정이 많으면 미루는 대학생.
- 빈 책장에서 `읽고 있는 책 추가` 하나를 보고, 제목만 입력해 첫 독서 흐름에 들어가고 싶다.

### 재방문 사용자

- 여러 권을 띄엄띄엄 읽고, 짧은 페이지 기록과 감상을 남기는 사용자.
- 앱을 열자마자 지난번 읽던 책, 마지막 페이지, 최근 감상을 보고 이어 읽고 싶다.

## MVP 목표

- 사용자가 책을 등록하면 `읽는 중` 책장에 해당 책이 표시된다.
- 사용자가 책 상세에서 이전 기록과 다음 시작 페이지를 확인할 수 있다.
- 사용자가 세션 기록을 저장하면 자동 시작 위치와 끝난 페이지로 구성된 기록 범위와 선택적 감상이 해당 책의 기록 페이지로 추가된다.
- 사용자가 재방문하거나 새로고침해도 서버 데이터 기준으로 같은 책의 마지막 책갈피에서 다시 시작할 수 있다.

## 성공 지표

- 첫 책 등록률: 온보딩을 마친 사용자가 첫 책을 등록한 비율.
- 첫 기록 저장률: 책 상세에 들어간 사용자가 첫 세션 기록을 저장한 비율.
- 이어 읽기 전환율: 최근 이어 읽기 CTA를 누른 사용자의 비율.
- 재방문 재개율: 최근 기록이 있는 사용자가 같은 책에 다음 세션 기록을 추가한 비율.
- 7일 재개율: 최근 기록 뒤 7일 안에 같은 책에 새 기록을 추가한 사용자의 비율.
- 기록 복구 정확도: 새로고침 후 가장 최근 기록의 다음 시작 페이지가 올바르게 제안되는 비율.

점수, 순위, 연속 출석은 성공 지표와 사용자 화면에 사용하지 않는다.

- 책등·서가 테마와 선택형 꾸미기 보상

## 용어 정책

- `책`: 사용자가 읽기 위해 내 책장에 등록한 단위다.
- `보관함`: 더 읽지 않지만 완독 처리하거나 삭제하고 싶지는 않은 책을 잠시 두는 장소다.
- `세션 기록 페이지`: 자동 시작 위치와 사용자가 입력한 끝난 페이지, 선택적인 짧은 감상·글귀·생각 태그를 남기는 독서 노트의 한 장이다. 실제 책의 페이지를 복제하지 않는다.
- `마지막 책갈피`: 가장 최근 세션 기록의 끝 페이지다.
- `다음 시작 페이지`: 마지막 책갈피 + 1을 기본으로 제안하는 값이다.
- `이어 읽기`: 이전 기록을 참고해 같은 책의 새 세션 기록을 시작하는 행동이다.
- `완독 서평`: 사용자가 완독을 선택한 뒤 남길 수 있는 긴 글이다. 세션 감상과 다르며 작성은 선택이다.
- `마음에 남은 글귀`: 사용자가 읽는 동안 기억하고 싶은 책의 일부를 세션 기록에 선택적으로 저장한 텍스트다. 직접 입력하거나 사진 OCR 결과를 확인·수정해 저장한다.
- `생각 태그`: 사용자가 세션 기록에 선택적으로 붙이는 감정·의미 단어 또는 짧은 구다. `위안`, `슬픔`, `따뜻함`, `깨달음` 같은 추천 태그와 직접 입력 태그를 포함한다.
- `생각 모아보기`: 같은 생각 태그를 가진 자신의 세션 기록을 책과 무관하게 모아, 감상과 글귀를 다시 찾는 기능이다.
- `읽기 기록 달력`: 기록을 저장한 날짜를 간단한 격자로 보여 주는 개인 활동 기록이다.
- `독서 발자취`: 읽기 기록 달력보다 확장된 형태로, 점수나 스트릭 없이 사용자가 독서로 돌아온 리듬을 보여 주는 개인 기록이다.

## 데이터 정책

### 현재 사용자 식별

- Google 로그인의 검증된 `sub`를 사용자 식별 기준으로 사용하고 닉네임은 표시명으로만 사용한다.
- 서버가 사용자 ID를 `HttpSession`에 보관하며, 브라우저가 API 요청에 `userId`를 전달하지 않는다.
- 세션이 만료돼도 같은 Google 계정으로 다시 로그인하면 같은 책장을 복구한다.
- 서버는 세션 사용자와 책·기록·글귀의 소유권을 모든 요청에서 확인한다.

### 책

- 책은 책 이름으로 외부 도서 정보를 검색한 뒤 선택해 등록한다.
- 등록 시 사용자는 검색 결과에서 읽고 있는 판본을 선택하고 시작 페이지를 입력한다.
- 새 책은 기본적으로 `READING` 상태로 만든다.
- 첫 시작 페이지는 기본값 1을 사용하되, 이미 읽던 책을 등록하는 사용자는 바꿀 수 있다.
- 책장 목록은 가장 최근 기록의 `createdAt DESC, id DESC` 순서로 보여 준다. 기록이 없는 책끼리는 `createdAt DESC, id DESC` 순서를 사용한다.
- 같은 사용자에게는 같은 ISBN 판본을 한 번만 등록한다. ISBN이 다른 판본은 별도 책으로 등록할 수 있다.
- ISBN이 없는 검색 결과는 provider ID로 판별하며, 기존 수동 등록 책은 자동으로 병합하지 않는다.

### 세션 기록 페이지

- 사용자는 세션 종료 시 끝난 페이지를 1 이상의 정수로 입력한다. 짧은 감상은 선택이다.
- 시작 페이지는 현재 `nextStartPage`를 자동으로 사용한다. 서버는 자동 시작 위치와 입력한 끝난 페이지를 함께 저장한다.
- 끝난 페이지는 자동 시작 위치보다 작을 수 없다.
- 읽은 페이지 수는 `endPage - resolvedStartPage + 1`로 서버와 화면이 계산한다. 사용자는 페이지 수를 직접 계산하거나 입력하지 않는다.
- 감상이 비어 있어도 기록을 저장할 수 있다.
- 다음 시작 페이지는 저장된 끝 페이지 + 1로 제안한다.
- 다시 읽기나 건너뛰기처럼 시작 위치가 다른 경우에만 사용자는 `시작 위치 직접 바꾸기`를 통해 시작 페이지를 수정할 수 있다. 이 입력은 기본 화면에 노출하지 않는다.
- P1에서는 가장 최근 세션 기록만 수정하거나 삭제할 수 있다. 이때 마지막 책갈피와 다음 시작 페이지를 다시 계산한다.
- 이전 기록의 수정·삭제는 기록 순서와 책갈피 계산을 별도로 설계한 뒤 제공한다.
- 가장 최근 기록은 `createdAt DESC, id DESC`로 하나만 결정한다. 이 순서가 마지막 책갈피와 `nextStartPage`의 기준이다.

### 글귀 OCR, 생각 태그와 모아보기 — P2

- 글귀는 세션 기록의 선택 입력이며 직접 입력하거나 카메라·이미지 업로드의 OCR 결과에서 가져올 수 있다.
- OCR 결과는 자동 저장하지 않는다. 사용자가 인식된 문장을 확인·수정하고 원하는 부분만 선택한 뒤 세션에 저장한다.
- 원본 사진은 OCR 처리에만 사용하고 기본적으로 영구 보관하지 않는다. 저장하는 정보는 확인된 글귀 텍스트와 선택적인 책 속 페이지다.
- OCR이 실패하거나 정확도가 낮아도 직접 입력으로 전환할 수 있어야 하며, OCR 사용 여부가 세션 기록 저장을 막지 않는다.
- 생각 태그는 세션 기록의 선택 입력이며, 한 기록에 최대 3개까지만 둔다.
- UI는 `위안`, `슬픔`, `따뜻함`, `깨달음` 같은 추천 태그와 직접 입력을 함께 제공하고, 저장된 태그를 칩으로 표시한다.
- 태그의 앞뒤 공백과 같은 기록 안의 중복을 저장 전에 정리한다.
- `생각 모아보기` 결과에는 태그, 책 제목, 계산된 페이지 범위, 기록 날짜, 짧은 감상과 저장한 글귀를 함께 표시한다.
- 글귀, 생각 태그와 세션 감상은 기본 비공개이며 친구 기능이 추가되어도 자동 공개하지 않는다.

### 완독 서평

- 사용자가 `완독으로 옮기기`를 선택하면 책 상태를 `COMPLETED`로 바꾼다.
- 긴 서평은 완독의 조건이 아니다. 사용자는 서평을 나중에 남기거나 비워둘 수 있다.
- P0에서는 실제 완독 처리·서평 저장 대신, 완독 뒤 열릴 마지막 페이지의 목적지만 조용히 안내한다.

### 읽기 기록 달력, 독서 발자취와 보상

- P1의 읽기 기록 달력은 `reading_records.created_at`에서 파생하며, 최근 12주의 기록 날짜를 GitHub 잔디형 격자로 간단히 보여 준다.
- 같은 날짜에 기록이 여러 개면 격자의 색 농도를 달리할 수 있지만, 읽지 않은 날을 실패나 결석으로 표시하지 않는다.
- 색 농도는 그날 저장한 세션 기록 수만 반영하며, 읽은 시간이나 페이지 수로 사용자를 평가하지 않는다.
- P2의 독서 발자취는 읽기 기록 달력을 확장한 개인 리듬 표현이다.
- 읽지 않은 날을 실패, 결석, 끊김으로 표시하지 않는다.
- 보상은 타인의 평가가 아니라 사용자의 독서 여정에 따른 선택형 꾸미기 보상으로 다룬다.

### 친구와 공개 범위

- 모든 책, 세션 기록의 시작·끝 페이지, 짧은 감상, 저장한 글귀, 생각 태그와 발자취는 기본 비공개다.
- 친구 기능은 P3부터 설계하며, 기본 공개 대상은 사용자가 선택한 완독 책과 완독 서평으로 제한한다.
- 읽는 중인 책, 정확한 페이지, 세션별 감상·글귀·생각 태그, 읽은 시간대, 마지막 활동 시각은 기본 공개하지 않는다.
- 친구 기능을 구현하기 전에는 닉네임과 클라이언트 `userId`만 쓰는 임시 식별을 토큰 기반 인증으로 전환하고, 친구 요청·수락·삭제·차단과 공개 동의를 함께 설계한다.

## 기술과 저장 원칙

- 프론트엔드는 React를 사용한다.
- 서버는 Spring Boot REST API를 사용한다.
- 데이터는 MySQL에 저장하고, Flyway로 스키마 변경을 관리한다.
- P0의 최소 모델은 `users`, `books`, `reading_records`다.
- 닉네임만으로 기존 사용자를 조회하는 API를 만들지 않는다. 클라이언트가 보관한 `userId`가 P0의 책장 조회 기준이다.
- 클라이언트는 서버 응답을 기준으로 책장과 책 상세를 갱신한다. 서버 저장에 성공하기 전에는 완료 상태로 보이지 않는다.
- 기록 저장 응답이 불확실하게 끊기면 클라이언트는 책 상세를 재조회한 뒤 재시도를 제안한다. 확인 없이 같은 기록을 자동으로 다시 저장하지 않는다.

## 핵심 사용자 시나리오

### 첫 책을 책장에 꽂기

1. 사용자는 빈 책장에서 `읽고 있는 책 추가`를 누른다.
2. 책 이름을 검색하고, 제목·저자·ISBN을 확인해 판본을 선택한 뒤 시작 페이지를 입력한다.
3. 책이 `읽는 중` 선반에 표시되고 책 상세로 이동한다.
4. 사용자는 `1쪽부터 읽기` 또는 입력한 시작 페이지부터 읽기를 선택한다.

### 지난 책갈피에서 이어 읽기

1. 사용자는 며칠 뒤 책장을 다시 연다.
2. 상단 최근 이어 읽기 카드에서 지난번 읽은 책, 마지막 페이지, 최근 감상을 확인한다.
3. 사용자는 `59쪽부터 이어 읽기`를 누른다.
4. 화면의 `읽기 준비` 안내를 확인하고 읽는다. P1 이후에는 필요하면 선택적 타이머를 켤 수 있다.
5. 사용자는 `74쪽에서 끝냈어요`와 선택적인 한 줄 감상을 저장한다.
6. 책 상세에는 새 세션 기록 페이지가 추가되고 다음 시작 페이지는 75쪽으로 갱신된다.

### 완독 후 마지막 서평 페이지 — P1

1. 사용자는 마지막 세션 뒤 `완독으로 옮기기`를 선택한다.
2. 책이 완독 선반으로 이동하고, 잠겨 있던 마지막 서평 페이지가 열린다.
3. 사용자는 긴 서평을 지금 쓰거나 나중에 남긴다.
4. 사용자는 세션별 감상을 시간순으로 모아 보며 한 권의 독서 노트를 돌아본다.

### 잠시 보관하고 다시 꺼내기 — P1

1. 사용자는 더 읽지 않는 책에서 `잠시 보관하기`를 선택한다.
2. 책은 읽는 중 선반에서 보관함으로 이동하며, 실패·중단·낮은 점수로 표시되지 않는다.
3. 사용자는 보관함에서 `다시 읽는 중으로 옮기기`를 선택해 마지막 책갈피부터 재개할 수 있다.

### 사진 속 글귀를 저장하고 다시 찾기 — P2

1. 사용자는 세션 기록에서 `마음에 남은 글귀 추가`와 `사진에서 가져오기`를 선택한다.
2. 카메라로 책 페이지를 찍거나 기존 이미지를 올리고 OCR이 제안한 텍스트에서 원하는 문장을 고른다.
3. 사용자는 인식된 문장을 확인·수정하고, 선택적으로 책 속 페이지와 `위안`, `깨달음` 같은 생각 태그를 함께 저장한다.
4. 나중에 `위안` 태그를 선택하면 책과 관계없이 같은 태그를 남긴 자신의 세션 기록이 모인다.
5. 사용자는 각 결과에서 책 제목, 세션 페이지 범위, 날짜, 감상과 글귀를 확인하고 필요한 기록을 다시 연다.

## P0 QA 체크리스트

- 책 이름 없이 검색할 수 없다.
- 검색 결과에서 판본을 선택하지 않으면 책을 등록할 수 없다.
- 판본을 선택하고 시작 페이지를 생략하면 기본값 1을 사용한다.
- 같은 사용자에게 같은 ISBN 판본을 중복 등록할 수 없다.
- 등록한 책은 `읽는 중` 책장과 책 상세에서 보인다.
- 기록 저장 시 끝난 페이지가 1 이상의 정수이고 자동 시작 위치보다 작지 않은지 검증한다.
- 감상이 비어 있어도 끝난 페이지 기록은 저장할 수 있다.
- 저장 후 새 기록 페이지가 책 상세에 보인다.
- 최근 기록의 끝 페이지 + 1이 다음 시작 페이지로 제안된다.
- 같은 시각의 기록이 있어도 `createdAt DESC, id DESC` 기준으로 마지막 책갈피가 일관되게 선택된다.
- 페이지 범위의 읽은 페이지 수는 `끝난 페이지 - 시작 페이지 + 1`로 계산된다.
- 사용자는 예외 상황에서만 시작 위치 직접 바꾸기로 제안된 시작 페이지를 수정해 저장할 수 있다.
- 새로고침 후에도 최근 이어 읽기 카드와 책 상세의 마지막 책갈피가 서버 데이터와 일치한다.
- 닉네임이 같은 다른 사용자의 책장이 열리지 않고, 이 브라우저에 보관한 `userId`로만 책장을 복구한다.
- 타이머를 사용하지 않아도 세션 기록을 저장할 수 있다.
- P1에서 가장 최근 기록을 수정하거나 삭제하면 다음 시작 페이지가 다시 계산된다.
- P1에서 책을 잠시 보관하거나 다시 읽는 중으로 옮겨도 기존 기록은 유지된다.
