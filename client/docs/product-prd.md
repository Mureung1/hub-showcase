- 핵심 흐름 검증용 정적 프로토타입은 [`client/prototype/index.html`](../prototype/index.html)에서 확인한다.

## 프로토타입 바로 보기

- 파일: [`client/prototype/index.html`](../prototype/index.html)
- 로컬 서버: `npm run dev` 실행 후 `http://localhost:5173/prototype/`
- 목적: 실제 구현 전, 핵심 루프가 사용자가 이해할 수 있는 순서로 보이는지 검증한다.
- 범위: `빠른 시작 -> 시작 전 확인 방 상세 -> 타이머 종료/기록 대기 -> 완료 기록 -> 내 기록/다시 읽기`.
- 동료 피드백 반영: 빠른 시작이 바로 타이머로 가지 않는 혼란, `기록 대기` 복귀 경로, 샘플 제외 목표 진행률을 프로토타입에서 우선 확인한다.
- 위치: 프로토타입은 나중에 제거하기 쉽도록 앱 구현 코드와 분리해 `client/prototype/` 아래에 둔다.

## 제품 본질

이 서비스는 책을 꾸준히 읽고 싶지만 혼자서는 자주 미루는 대학생이, 짧은 독서 세션을 시작하고 기록을 남기며 다시 읽기로 돌아오게 만드는 PC 웹 MVP다.

핵심 루프는 다음 하나로 고정한다.

```text
짧게 시작한다
-> 정해진 시간 동안 읽는다
-> 끝난 직후 기록한다
-> 내 기록에서 다시 읽기로 돌아온다
```

독서방은 실시간 커뮤니티 구현이 아니라, 사용자가 혼자 읽더라도 “함께 읽는 서비스처럼” 느끼게 하는 맥락 장치다. MVP에서 독서방은 세션 조건, 분위기, 기록이 모이는 단위다.

## 문제정의

### 사용자 문제

- 사용자는 책을 읽고 싶지만 시작 순간에 자주 미룬다.
- 사용자는 혼자 타이머를 켜는 것보다, 누군가와 같은 형식의 방에 들어가는 느낌에서 더 쉽게 시작한다.
- 사용자는 세션이 끝난 직후 기록이 너무 무거우면 앱을 닫고 돌아오지 않는다.
- 사용자는 내 기록과 샘플 데이터가 섞이면 서비스가 장난감처럼 느껴지고, 내가 쌓은 기록을 믿기 어렵다.
- 사용자는 재방문했을 때 “이전에 하던 일”이 무엇인지 바로 알고 싶어 한다.

### 제품 문제

- 빠른 시작은 빠르게 느껴져야 하지만, MVP에서는 방 상세를 한 번 거쳐야 한다.
- 완료 기록은 데이터 품질을 위해 필수값이 필요하지만, 입력 피로를 낮춰야 한다.
- `localStorage` 기반 MVP는 새로고침, 탭 복제, 저장 실패, 데이터 손상에 취약하다.
- 샘플 데이터는 시연에 필요하지만 실제 목표 진행률과 섞이면 신뢰를 해친다.

## 대상 사용자

### 첫 방문 사용자

- 공강이나 밤 시간에 바로 읽고 싶은 대학생.
- 긴 설정이나 회원가입을 싫어한다.
- `빠른 시작`이라는 말에 즉시 읽기 진입을 기대한다.
- 방 상세를 봐야 한다면 “왜 이 화면이 필요한지”를 바로 이해해야 한다.

### 재방문 사용자

- 이미 세션을 몇 번 끝낸 사용자.
- 기록 대기 상태, 내 기록, 다시 읽기 CTA를 통해 이어서 행동하고 싶다.
- 샘플과 실제 기록이 섞일 때 목표 진행률에 무엇이 반영되는지 민감하다.

### 샘플 체험 사용자

- 실제 데이터를 만들기 전에 흐름을 둘러보고 싶은 사용자.
- 샘플 데이터가 실제 기록과 다르다는 사실을 명확히 알아야 한다.
- 샘플을 지우는 것과 전체 데이터를 초기화하는 것을 구분해야 한다.

## MVP 목표

- 사용자가 닉네임 입력 후 첫 세션을 시작할 수 있다.
- 사용자가 세션 종료 후 기록을 저장하거나 `기록 대기` 상태로 안전하게 남길 수 있다.
- 사용자가 재방문했을 때 진행 중 세션 또는 기록 대기 세션으로 복귀할 수 있다.
- 사용자가 내 기록에서 완료 기록, 기록 대기, 샘플 데이터를 구분할 수 있다.
- 시연자는 샘플 데이터를 추가/교체하더라도 실제 데이터와 목표 진행률이 오염되지 않음을 보여줄 수 있다.

## 성공지표

- 첫 세션 시작률: 온보딩 완료 후 빠른 시작 또는 방 상세에서 세션을 시작한 비율.
- 세션 완료율: `active` 세션 중 `readyToRecord` 또는 `completed`까지 도달한 비율.
- 기록 저장 전환율: `readyToRecord` 세션 중 `completed` 기록으로 저장된 비율.
- 기록 대기 복귀율: `readyToRecord`로 남은 세션이 방 목록 배너 또는 내 기록에서 다시 열린 비율.
- 14일 목표 진행률: 최근 14일 동안 `source = user`이고 `session.status = completed`인 기록 수만 계산한다.
- 새로고침 복구 성공률: 세션 타이머 또는 기록 대기 상태에서 새로고침 후 올바른 화면으로 복구한 비율.
- 샘플 제외 정확도: 샘플 데이터가 목표 진행률, 실제 완료 기록 수, 성공지표에 포함되지 않는지 확인한다.

## 용어 정책

- `readyToRecord`는 내부 상태명이다.
- 사용자에게 노출되는 상태명은 항상 `기록 대기`다.
- `나중에 작성`은 사용자가 누르는 액션명이다.
- `완료 기록 작성 대기`, `미작성`, `readyToRecord`를 사용자 화면에 직접 노출하지 않는다.
- `샘플`은 시연용 데이터 라벨이다.
- `실제 기록`은 사용자가 직접 생성한 `source = user` 기록이다.
- `임시 방`은 빠른 시작 템플릿 선택 후 세션 시작 전까지의 방이다.
- `다시 읽기`는 가능하면 기존 방 상세로 돌아가는 행동이다. 연결된 방이 없을 때만 같은 조건의 새 빠른 시작 방을 만든다.

## 빠른 시작 정책

- 빠른 시작은 즉시 타이머로 보내는 기능이 아니라, 세션 조건 선택을 최소화하는 기능이다.
- 템플릿을 누르면 방 상세로 이동하되, 방 상세는 `시작 전 확인` 화면으로 읽혀야 한다.
- 빠른 시작 유입 방 상세 상단에는 템플릿 결과를 명확히 표시한다.
- 예시 문구: `30분 조용히 읽기 방이 준비됐어요. 아래 내용을 확인하고 바로 시작하세요.`
- 빠른 시작 유입 방의 주요 CTA는 템플릿과 연결한다.
- 예시 CTA: `30분 읽기 시작`, `15분 읽기 시작`
- 빠른 시작으로 만든 방은 세션 시작 전까지 임시 방으로 취급한다.
- 세션 시작 전 `다시 고르기`를 누르면 임시 방은 폐기한다.
- 세션이 시작된 뒤에는 `다시 고르기`를 숨긴다.

## 완료 기록 정책

- 완료 기록은 책 제목, 시작 페이지, 끝 페이지, 감상을 모두 필수로 받는다.
- 입력 부담을 줄이기 위해 화면 순서는 사용자의 회고 흐름을 우선한다.
- 권장 순서: 세션 요약 -> 책 제목 -> 감상 -> 페이지 범위 -> 저장 CTA.
- 페이지 범위는 대략값을 허용한다.
- 보조 문구: `정확하지 않아도 괜찮아요. 오늘 읽은 범위를 대략 남겨주세요.`
- 시작 페이지와 끝 페이지는 1 이상의 정수다.
- 시작 페이지와 끝 페이지가 같은 경우는 허용한다.
- 끝 페이지가 시작 페이지보다 작으면 저장을 막는다.
- 같은 세션에 완료 기록이 이미 있으면 중복 저장하지 않는다.
- 저장 실패 시 사용자가 입력한 값은 유지하고 재시도할 수 있게 한다.

## 기록 대기 정책

- 타이머가 끝났지만 기록을 저장하지 않은 세션은 `readyToRecord`로 남긴다.
- 사용자에게는 `기록 대기`로 보인다.
- 방 목록 최상단에는 `기록 대기` 배너를 보여준다.
- 내 기록에는 `기록 대기` 필터 또는 배지로 표시한다.
- `기록 대기` 세션은 완료 기록 저장 전까지 목표 진행률에 포함하지 않는다.
- `기록 대기` 상태에서 사용자가 나가도 세션은 유지한다.
- `기록 대기` 상태에서 다시 들어오면 바로 완료 기록 화면으로 복귀한다.

## 샘플 데이터 정책

- 샘플 데이터는 실제 데이터와 같은 목록에 표시할 수 있다.
- 모든 샘플 방과 샘플 기록에는 `source = sample`을 붙인다.
- 샘플 데이터는 `샘플` 배지를 표시한다.
- 샘플 데이터는 목표 진행률, 실제 완료 기록 수, 성공지표에서 제외한다.
- 샘플 필터를 제공해 샘플만 보거나 샘플을 제외하고 볼 수 있게 한다.
- `샘플 데이터로 둘러보기`는 샘플 데이터가 없을 때 샘플 세트를 추가한다.
- 기존 실제 데이터가 있으면 보존한다.
- 기존 샘플 데이터가 있으면 샘플 덮어쓰기 확인 모달을 먼저 연다.
- `샘플 다시 만들기`는 샘플만 교체한다.
- `전체 데이터 초기화`는 실제 데이터와 샘플 데이터를 모두 삭제한다.

## 데이터와 복구 정책

- MVP 데이터는 `localStorage`에 저장한다.
- 저장 대상은 `user`, `rooms`, `sessions`, `readingRecords`다.
- 임시 입력값은 저장 전까지 draft state로 다룬다.
- 새로고침 시 `localStorage` 기준으로 가능한 화면을 복원한다.
- 세션 타이머는 `endsAt` 기준으로 남은 시간을 재계산한다.
- 현재 시간이 `endsAt` 이후면 `readyToRecord`로 승격한다.
- 삭제된 방 상세에 접근하면 `존재하지 않는 방이에요` 안내와 방 목록 CTA를 표시한다.
- 삭제된 기록 상세에 접근하면 기록 목록으로 돌아가게 한다.
- 파싱 실패 시 복구 가능한 항목만 복원하고, 손상 항목은 안내 후 제외한다.
- 저장 용량 초과나 저장 제한이 발생하면 현재 입력값을 유지하고 재시도를 허용한다.

## 탭 정책

- MVP는 single writable tab 정책을 따른다.
- 동일 브라우저 프로필에서 여러 탭을 열 수는 있지만, 마지막으로 활성화된 탭만 쓰기 동작을 수행한다.
- 오래된 탭에서 저장을 시도하면 `다른 탭에서 데이터가 변경됐어요. 새로고침 후 다시 시도해 주세요.` 안내를 보여준다.
- 탭 간 실시간 동기화는 MVP 범위가 아니다.

## 핵심 사용자 시나리오

### 첫 방문 공강 시나리오

1. 사용자는 공강 30분이 남아 서비스를 연다.
2. 닉네임을 입력하고 시작한다.
3. 방 목록에서 `빠른 시작`을 누른다.
4. `30분 조용히 읽기` 템플릿을 누른다.
5. 방 상세에서 `30분 조용히 읽기 방이 준비됐어요` 안내를 확인한다.
6. `30분 읽기 시작`을 누른다.
7. 타이머가 끝난다.
8. 책 제목과 감상을 먼저 입력하고, 페이지 범위를 대략 입력한다.
9. 기록 저장 후 내 기록 최상단에서 방금 기록을 확인한다.

### 기록 대기 복귀 시나리오

1. 사용자는 타이머 종료 후 바로 기록하지 않고 `나중에 작성`을 누른다.
2. 방 목록으로 돌아가면 최상단에 `기록 대기` 배너가 보인다.
3. 사용자는 앱을 닫았다가 다시 연다.
4. 방 목록의 `기록 대기` 배너를 누른다.
5. 완료 기록 화면으로 바로 복귀한다.
6. 기록을 저장하면 내 기록의 `기록 대기` 항목이 완료 기록으로 바뀐다.

### 샘플 체험 후 실제 기록 시나리오

1. 사용자는 샘플 데이터로 둘러본다.
2. 방 목록과 내 기록에서 샘플 배지를 확인한다.
3. 목표 카드에는 `샘플 제외` 안내가 표시된다.
4. 사용자가 실제 세션을 시작해 기록을 저장한다.
5. 내 기록에는 샘플과 실제 기록이 함께 보이지만, 목표 진행률은 실제 기록만 반영한다.

### 재방문 다시 읽기 시나리오

1. 사용자는 내 기록에서 이전 완료 기록을 연다.
2. 기록 상세 모달에서 책, 페이지, 감상을 확인한다.
3. `방에 다시 입장` 또는 `같은 방 다시 읽기`를 누른다.
4. 연결된 방이 있으면 기존 방 상세로 이동한다.
5. 연결된 방이 없으면 같은 세션 시간과 분위기의 새 빠른 시작 방을 만든다.

## QA 체크리스트

- 닉네임 공백 입력 시 온보딩에 머물고 오류가 보인다.
- 빠른 시작 템플릿 선택 후 방 상세의 `시작 전 확인` 문구가 보인다.
- 빠른 시작 방의 CTA가 `세션 시작`이 아니라 템플릿 기반 라벨을 사용한다.
- active 세션 또는 기록 대기 세션이 있을 때 빠른 시작은 새 방을 만들지 않고 기존 세션 복귀를 우선한다.
- 타이머 종료 후 상태는 내부적으로 `readyToRecord`, 사용자 화면에서는 `기록 대기`로 보인다.
- 기록 대기 배너에서 완료 기록 화면으로 복귀할 수 있다.
- 샘플 데이터는 목표 진행률에 포함되지 않는다.
- 전체 데이터 초기화와 샘플 다시 만들기 문구가 구분된다.
- 완료 기록에서 시작 페이지와 끝 페이지가 같으면 저장할 수 있다.
- 끝 페이지가 시작 페이지보다 작으면 저장할 수 없다.
- 같은 세션에 기록을 중복 저장할 수 없다.
- 새로고침 후 타이머와 기록 대기 상태가 복구된다.
- stale tab에서 저장 시 충돌 안내가 보인다.
