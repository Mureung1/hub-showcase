# Frontend User Flow

> **상태 안내:** 초기 P0 흐름을 설명하는 부분이 함께 남아 있습니다. 현재는 Google 로그인, 페이지 통합형 3D 책 펼치기, 직접 입력 글귀 배너와 P1 기능이 구현됐습니다. 현재 상태는 [`docs/current-implementation-status.md`](../../docs/current-implementation-status.md)를 우선합니다.

## 기준

- 대상은 PC 웹 MVP다.
- 제품 본질, 범위, 용어와 데이터 정책은 `client/docs/product-prd.md`를 따른다.
- 이 문서는 화면 단위의 사용자 흐름을 정의한다. 클릭과 예외 처리는 `client/docs/click-unit-ui-spec.md`에서, 컴포넌트 책임은 `client/docs/component-implementation-notes.md`에서 구체화한다.
- P0의 서버 데이터는 Spring Boot API와 MySQL을 기준으로 한다. 화면에서 성공으로 보이는 책·기록 상태는 서버 응답 뒤에 갱신한다.
- 책장 연출은 독서 재개를 돕는 맥락이다. 책의 위치·꺼내기·펼치기만 3D로 표현하고 책 상세와 입력은 DOM으로 제공한다.

## 전체 흐름

```text
Google 로그인
-> 내 책장
-> 책 등록
-> 책 상세
-> 지난 책갈피에서 읽기 시작
-> 세션 기록 페이지 저장
-> 책 상세 또는 내 책장
-> 다음 방문에 같은 책 이어 읽기
```

P1의 완독 흐름은 다음과 같다.

```text
책 상세
-> 완독으로 옮기기
-> 완독 선반
-> 마지막 서평 페이지 열기
-> 긴 서평 또는 세션 감상 모아보기
```

P1의 보관 흐름은 다음과 같다.

```text
읽는 중 책
-> 잠시 보관하기
-> 보관함
-> 다시 읽는 중으로 옮기기
-> 마지막 책갈피에서 재개
```

## 공통 원칙

- 가장 중요한 CTA는 언제나 `지난번 그 책을, 다음 페이지부터 다시 읽기`다.
- 타이머는 독서 여부를 검증하지 않으며, 사용자가 타이머 없이 기록을 남길 수 있다.
- 세션 기록의 끝난 페이지는 필수, 짧은 감상은 선택이다.
- 시작 위치는 마지막 책갈피 다음으로 자동 계산하며, 예외 상황에서만 수정할 수 있다.
- 빈 날, 타이머 미사용, 감상 미작성은 실패 상태가 아니다.

## 1. 온보딩

### 사용자 의도

- Google 계정으로 로그인하고 어느 기기에서든 같은 책장을 다시 열고 싶다.
- 아직 읽은 책이 없는 빈 책장이 실패처럼 보이지 않기를 바란다.

### 표시 요소

- 서비스 한 줄 설명: `마지막 책갈피에서 다시 읽기를 시작해요.`
- Google 로그인 버튼

### 다음 흐름

- Google Identity Services가 발급한 ID token을 서버가 검증하면 내 책장으로 이동한다.

### 상태 변화

- 서버가 사용자 ID를 `HttpSession`에 보관한다.
- 현재 route가 `bookshelf`로 바뀐다.
- 다음 방문에는 세션을 복구하고, 세션이 만료됐으면 같은 Google 계정으로 다시 로그인한다.

### 빈 상태 안내

- 책장이 비어 있다는 사실을 경고하지 않는다.
- 다음 화면에서 `지금 읽는 책을 한 권 꽂아 보세요.`와 책 등록 CTA를 제공한다.

## 2. 내 책장

### 사용자 의도

- 지난번 읽은 책을 바로 다시 열고 싶다.
- 읽는 중인 여러 책 중 하나를 고르거나, 새 책을 추가하고 싶다.

### 표시 우선순위

1. 최근 이어 읽기 카드
2. `읽는 중` 선반
3. P1 이후 읽기 기록 달력
4. `읽고 있는 책 추가` CTA
5. P1 이후 `완독` 선반
6. P1 이후 보관함

### 최근 이어 읽기 카드

가장 최근 기록이 있는 `READING` 책이 있으면 표시한다. 그런 책이 없고 새 `READING` 책이 있다면, 가장 최근에 등록한 책을 `처음 읽기` 카드로 표시한다.

- 책 제목
- 마지막 책갈피와 기록 날짜
- 최근 감상이 있는 경우 한 줄
- CTA: `{nextStartPage}쪽부터 이어 읽기`

CTA를 누르면 해당 책의 책 상세로 이동하면서 읽기 준비 상태를 시작한다. `59쪽부터 읽어요. 다 읽고 돌아오면 기록을 남겨 주세요.`와 `이번 읽기 기록 남기기`를 보인다. 일반 책등 클릭은 책 상세만 열고 읽기 준비 상태를 시작하지 않는다.

### 읽는 중 선반

- 책은 최근 기록 순서로 보인다.
- 각 책등은 제목과 다음 시작 페이지 또는 `처음 읽기`를 알 수 있어야 한다. 마지막 기록 날짜와 감상은 재개 카드·책 상세에서 보여 준다.
- 책등을 누르면 책 상세로 이동한다.
- P0에서는 자유 배치나 카테고리 변경을 제공하지 않는다.

### 빈 책장

- 제목: `첫 책이 들어올 자리예요.`
- 설명: `지금 읽고 있는 책을 등록하면, 다음부터 마지막 책갈피에서 바로 이어 읽을 수 있어요.`
- CTA: `읽고 있는 책 추가`

## 3. 책 등록

### 사용자 의도

- 지금 읽는 책을 빠르게 내 책장에 넣고 싶다.
- 이미 읽던 책이라면 현재 페이지부터 기록을 시작하고 싶다.

### 표시 요소

- 책 이름 검색 입력 — 필수
- 외부 도서 검색 결과와 판본 정보
- 검색 결과에서 선택한 책
- 시작 페이지 입력 — 기본값 1, 선택적 변경
- `책장에 꽂기` CTA
- 취소 CTA

### 다음 흐름

- 검색 결과에서 판본을 선택해 저장하면 새 책을 `READING` 상태로 만들고 책 상세로 이동한다.
- 취소하면 이전 내 책장으로 돌아간다.

### 상태 변화

- `GET /api/books/search?q=`로 책 이름을 검색한다.
- `POST /api/books` 성공 후 books 목록에 검색 결과의 판본을 추가한다.
- 서버 저장 실패 시 입력값을 유지하고 같은 화면에서 재시도하게 한다.

## 4. 책 상세 — 펼쳐진 독서 노트

### 사용자 의도

- 이 책을 어디까지 읽었는지 확인하고 다음 읽기를 시작하고 싶다.
- 이전에 남긴 계산된 페이지 범위와 생각을 시간순으로 돌아보고 싶다.

### 표시 우선순위

1. 책 제목과 상태
2. 마지막 책갈피 및 최근 감상
3. `{nextStartPage}쪽부터 이어 읽기` CTA
4. 세션 기록 페이지 목록
5. P1 이후 마지막 서평 페이지

### 마지막 책갈피

- 기록이 있으면 `지난번 {endPage}쪽까지 읽었어요.`를 표시한다.
- 기록이 없으면 등록한 시작 페이지를 제안한다.
- 다음 시작 페이지는 기본값이며, 다시 읽기·건너뛰기 같은 예외에서만 `시작 위치 직접 바꾸기`로 수정할 수 있음을 안내한다.

### 세션 기록 페이지 목록

- 한 세션 기록은 독서 노트의 한 페이지다.
- 각 페이지에는 날짜, 계산된 `startPage–endPage`, `endPage - startPage + 1`로 계산한 `n페이지 읽음`, 선택적으로 짧은 감상을 표시한다.
- 기록은 오래된 순서로 쌓아 읽으며 생각이 변한 흐름을 볼 수 있게 한다.
- 감상이 비어 있으면 페이지 범위와 날짜만 보여 준다.

### 마지막 서평 페이지 — P1

- P0에서는 `완독하면 이 책의 마지막 장에 서평을 남길 수 있어요.`라는 미리보기만 둔다.
- 실제 잠금 해제, 완독 상태, 긴 서평 입력은 P1에서 제공한다.

## 5. 읽기 시작과 세션 기록

### 사용자 의도

- 지난 책갈피 다음부터 읽고, 읽은 범위를 간단히 남기고 싶다.

### 흐름

1. 사용자는 책 상세에서 `{nextStartPage}쪽부터 이어 읽기`를 누른다.
2. 화면은 `다 읽고 돌아오면 기록을 남겨 주세요.`라는 읽기 준비 상태를 보여 준다. P1 이후 사용자는 필요하면 선택적 타이머를 켤 수 있다.
3. 사용자는 앱 안팎에서 책을 읽는다. 브라우저는 집중 여부를 검증하지 않는다.
4. 사용자는 `이번 읽기 기록 남기기`를 눌러 세션 기록 폼을 연다.
5. 끝난 페이지와 선택적 짧은 감상을 저장한다.

### 세션 기록 폼

- 시작 페이지는 `nextStartPage`로 자동 계산해 보여 주며, 기본 입력으로 요구하지 않는다.
- `오늘 끝낸 페이지`는 필수다.
- 짧은 감상은 선택이다. placeholder는 `한 줄이면 충분해요. 비워 두어도 괜찮아요.`를 사용한다.
- P2에서는 선택적으로 직접 입력·OCR 글귀를 추가하고, 생각 태그는 최대 3개까지 붙일 수 있다.
- 끝난 페이지는 1 이상의 정수이며 자동 시작 위치보다 작을 수 없다.
- 사용자가 다시 읽거나 건너뛴 경우에만 `시작 위치 직접 바꾸기`를 열어 시작 페이지를 수정할 수 있다.
- 끝난 페이지를 입력하면 `59–74쪽 · 16쪽 읽음` 같은 결과 범위를 즉시 미리 보여 준다.

### 다음 흐름

- 저장에 성공하면 책 상세로 돌아가 새 기록 페이지와 갱신된 다음 시작 페이지를 보여 준다.
- 사용자는 `책장으로 돌아가기`를 눌러 같은 책이 최근 읽은 책으로 강조된 상태를 볼 수 있다.

### 상태 변화

- `POST /api/books/{bookId}/records` 성공 후 해당 책의 기록 목록과 last bookmark를 서버 응답으로 갱신한다.
- 서버 오류가 나면 입력값을 유지하고 재시도 CTA를 보여 준다. 저장 응답을 확인할 수 없는 경우에는 먼저 책 상세를 재조회하고, 기록이 없을 때만 다시 저장을 제안한다.

## 6. 완독과 마지막 서평 — P1

### 사용자 의도

- 책을 다 읽었다는 사실을 내 책장에 남기고, 원할 때 긴 서평으로 정리하고 싶다.

### 다음 흐름

- 사용자는 책 상세에서 `완독으로 옮기기`를 선택한다.
- 책은 완독 선반으로 이동하고 마지막 서평 페이지가 열린다.
- 사용자는 긴 서평을 지금 쓰거나 `나중에 남기기`를 선택한다.
- 세션별 짧은 감상은 마지막 서평 페이지에서 시간순으로 모아 볼 수 있다.

### 상태 변화

- `PATCH /api/books/{bookId}/status`가 `COMPLETED` 상태와 선택적 긴 서평을 저장한다.
- 긴 서평을 작성하지 않아도 상태 변경은 성공한다.

## 7. 보관과 마지막 기록 정정 — P1

### 잠시 보관하기

- 사용자는 읽는 중 책에서 `잠시 보관하기`를 선택할 수 있다.
- 보관은 삭제나 실패가 아니며, 책과 세션 기록은 보관함에 그대로 남는다.
- 사용자는 보관함에서 `다시 읽는 중으로 옮기기`를 선택해 마지막 책갈피부터 재개한다.

### 가장 최근 기록 수정·삭제

- 사용자는 가장 최근 세션 기록만 수정하거나 삭제할 수 있다.
- 수정·삭제 뒤 책 상세와 최근 이어 읽기 카드의 마지막 책갈피, 다음 시작 페이지를 서버 기준으로 다시 계산한다.
- 이전 기록의 수정·삭제는 P1 범위 밖이다.

## 8. 읽기 기록 달력 — P1

### 사용자 의도

- 최근에 독서를 하러 돌아온 날을 부담 없이 확인하고 싶다.

### 표시 요소

- 최근 12주의 날짜 격자
- 기록이 있는 날의 색 농도
- 날짜를 가리켰을 때 보여 주는 해당 일의 기록 수

### 정책

- 데이터는 세션 기록의 생성 날짜에서 파생한다.
- 기록이 없는 날은 비워 두며, 실패·결석·연속 출석 끊김으로 표현하지 않는다.
- P1에서는 책장 화면의 간단한 활동 요약이다. 독립 목표, 점수, 알림 기능을 붙이지 않는다.

## 9. 글귀, 생각 태그와 모아보기 — P2

### 마음에 남은 글귀 저장

- 사용자는 세션 기록 폼에서 `마음에 남은 글귀 추가`를 선택해 글귀를 직접 입력할 수 있다.
- 카메라 촬영 또는 이미지 업로드를 선택하면 OCR이 이미지 속 문장을 텍스트로 제안한다.
- 사용자는 OCR 결과에서 필요한 문장을 선택하고 오탈자를 수정한 뒤에만 저장한다. 인식 결과는 자동 저장하지 않는다.
- 사용자는 필요하면 글귀가 나온 책 속 페이지를 함께 적을 수 있다.
- OCR이 실패하면 같은 위치에서 직접 입력으로 전환한다. 글귀를 추가하지 않아도 세션 기록은 저장할 수 있다.
- 저장 뒤에는 원본 사진이 아닌 확인된 텍스트를 기록 페이지에 표시한다.

### 세션 기록 생각 태그

- 사용자는 기록 폼에서 생각 태그를 선택적으로 최대 3개 입력한다.
- `위안`, `슬픔`, `따뜻함`, `깨달음` 같은 추천 태그를 고르거나 짧은 태그를 직접 입력할 수 있다.
- 저장된 태그는 기록 페이지의 감상과 글귀 아래에 칩으로 표시한다.
- 감상이나 글귀를 비워도 태그를 남길 수 있고, 태그를 비워도 기록을 저장할 수 있다.

### 생각 모아보기

- 사용자는 태그를 검색하거나 책 상세의 태그 칩을 눌러 같은 태그의 기록을 책과 무관하게 모아 본다.
- 결과 단위는 책이 아니라 세션 기록이며, 책 제목, 세션 페이지 범위, 날짜, 짧은 감상과 저장한 글귀를 함께 보여 준다.
- 감상만 있는 기록, 글귀만 있는 기록, 둘 다 있는 기록을 모두 찾을 수 있다.
- 결과는 기본적으로 자신의 기록만 포함한다.

## 10. 독서 발자취와 친구 서재 — 이후 단계

### 독서 발자취 — P2 이후

- 기록이 있는 날짜만 조용히 보여 준다.
- 빈 날과 연속 출석을 실패로 표시하지 않는다.
- 책장이 `무엇을 읽었는지`를 보여 준다면 발자취는 `어떻게 돌아왔는지`를 보여 준다.

### 친구 서재 — P3

- 친구 추가와 공개 범위 동의 뒤에만 제공한다.
- 친구 기능 전에 토큰 기반 사용자 인증과 친구 요청·수락·삭제·차단 모델을 확정한다.
- 기본적으로 모든 정보는 비공개다.
- 첫 공개 범위는 사용자가 선택한 완독 책과 완독 서평으로 제한한다.
- 읽는 중인 책, 정확한 페이지, 세션별 감상·글귀·생각 태그, 발자취는 공개하지 않는다.
