# Reading Bookshelf Concept: Designer and Frontend Brainstorm

> 이 문서는 새 제품 콘셉트를 결정하기 전, 디자이너와 프론트엔드 개발자 관점에서 정리한 브레인스토밍 기록이다. 구현 기준은 사용자 관점 검토와 합의 이후 `product-prd.md` 등에서 확정한다.

## 공통 제안

기존의 `독서방 → 타이머 → 기록 → 같은 방 재입장` 흐름을, 다음의 책 중심 흐름으로 교체한다.

```text
책을 책장에 등록한다
→ 책을 꺼내 마지막 책갈피를 확인한다
→ 필요하면 타이머를 켜고 읽는다
→ 세션 기록 페이지 한 장을 남긴다
→ 다음 시작 페이지가 갱신된다
→ 기록이 쌓여 완독 서평 페이지에 닿는다
```

타이머는 집중을 검증하거나 신뢰도를 평가하는 수단이 아니라, 독서를 시작하고 마무리하는 선택적 보조 도구다. 사용자가 타이머를 중단하거나 사용하지 않아도 독서 기록을 남길 수 있어야 한다.

## 사용자가 얻는 가치

| 가치 | 제품 장치 | 기대 경험 |
| --- | --- | --- |
| 다시 읽기 쉬움 | 마지막 페이지, 최근 감상, `이어 읽기` CTA | `어디까지 읽었지?`라는 마찰이 사라진다. |
| 작은 성취 축적 | 세션 하나당 기록 페이지 한 장 | 조금 읽은 날도 한 권의 독서 노트에 남는다. |
| 완독의 기대 | 잠겨 있다가 열리는 마지막 서평 페이지 | 책을 끝까지 읽고 싶은 목적지가 생긴다. |
| 정체성과 수집 | 읽는 중/완독 선반에 쌓이는 책 | 내가 어떤 독자인지 보인다. |
| 부담 없는 지속성 | 점수 없는 개인 독서 발자국 | 며칠 쉬어도 실패가 아니라 다시 이어짐을 느낀다. |

## 책 UI의 원칙

- 실제 책의 모든 페이지를 복제하지 않는다. `42–58쪽을 읽고 남긴 감상`처럼 **세션 기록 하나가 책 안의 기록 페이지 한 장**이다.
- 책장에서는 책등으로 상태를 보여 주고, 책 상세에서는 펼쳐진 책처럼 기록 페이지를 오래된 순서로 보여 준다.
- 책의 뒷부분에는 `완독 후 서평` 페이지가 보인다. 완독 전에는 잠겨 있고, 완독 후에는 긴 서평과 세션 감상 모아보기를 제공한다.
- 책장에 꽂힌 책과 펼쳐진 책은 같은 `bookId`를 기준으로 동작한다. 꺼내고 펼치는 모션은 데이터 흐름과 결합하지 않고 이후에 보강한다.

## MVP: 시스템 구현 우선

첫 수직 슬라이스는 다음을 실제 서버와 DB로 완주한다.

```text
책 등록
→ 읽는 중 책장 조회
→ 책 상세와 세션 기록 조회
→ 세션 기록 저장
→ 다음 시작 페이지 제안
→ 새로고침 후 같은 책을 이어 읽기
```

### MVP 포함

- 수동 책 등록: 제목, 선택적 저자
- `읽는 중` 선반과 책장 조회
- 책 상세의 마지막 책갈피와 세션 기록 페이지 목록
- 세션 기록: 시작/끝 페이지, 짧은 감상, 기록 날짜
- 직전 끝 페이지 + 1을 기본값으로 하는 다음 시작 페이지 제안
- 선택적 타이머
- 완독 서평 페이지의 잠긴 목적지 UI

### 다음 단계

- 완독 처리, 긴 서평 저장, 완독 선반
- 책등·서가 테마·컬렉션·사용자 순서 커스터마이징
- 개인 독서 발자국 시각화
- 친구 추가, 공개 범위, 친구 서재 방문, 친구의 책을 읽고 싶은 책으로 담기

친구 기능은 사용자 식별, 관계 요청과 수락, 공개 범위, 삭제 및 차단 같은 권한 모델이 필요하므로 개인 책장 MVP와 분리한다.

## 구현 관점 초안

### 화면과 컴포넌트

```text
내 서재
├─ 최근 이어 읽기
├─ 읽는 중 선반
├─ 책 추가
└─ 완독 선반 (다음 단계)

책 상세
├─ 마지막 책갈피와 이어 읽기
├─ 선택적 타이머
├─ 세션 기록 페이지 목록
└─ 잠긴 또는 열린 마지막 서평 페이지
```

- 화면: `BookshelfScreen`, `BookDetailScreen`
- 입력: `AddBookForm`, `SessionRecordForm`, `CompletionReviewForm`(다음 단계)
- 공통: `BookSpine`, `BookCover`, `ShelfSection`, `ResumeCard`, `SessionRecordPage`, `FinalReviewGate`, `TimerPanel`

### 상태와 데이터 경계

서버 데이터는 `books`, 선택한 `book`의 상세, `readingRecords`다. 화면은 route, 선택한 책/선반, dialog 열림 상태만 유지한다. `nextStartPage`는 가장 최근 기록의 `endPage + 1`에서 파생한다.

초기 모델은 다음처럼 둔다.

```text
users
books
- id, user_id, title, author(nullable)
- status: READING | COMPLETED
- final_review(nullable), created_at, completed_at(nullable)

reading_records
- id, book_id, user_id
- start_page, end_page, impression, created_at
```

시작 페이지는 직전 끝 페이지 다음으로 제안하지만, 다시 읽기와 건너뛰기를 허용하기 위해 서버가 연속성을 강제하지 않는다. 기본 검증은 `1 ≤ startPage ≤ endPage`다.

## 신뢰도에서 독서 발자취로

신뢰도 점수, 랭킹, 끊기면 실패하는 스트릭은 사용하지 않는다.

- 책장은 무엇을 읽고 어떤 생각을 쌓았는지 보여 준다.
- 독서 발자취는 어떤 리듬으로 돌아왔는지 보여 준다.
- MVP에서는 세션 기록의 `createdAt`으로 발자취를 파생하므로 별도의 점수 데이터를 저장하지 않는다.

## 사용자 관점 검토가 필요한 질문

1. 책장과 펼쳐진 책 비유가 독서를 다시 시작하는 데 실제로 도움이 되는가, 아니면 장식으로 느껴지는가?
2. 짧은 세션 감상과 완독 후 긴 서평의 입력 부담은 적절한가?
3. 개인 책장과 독서 발자취 중 재방문 동기에 더 큰 영향을 주는 것은 무엇인가?
4. 친구 서재는 어떤 공개 범위와 행동을 제공할 때 조용한 독서 경험을 해치지 않는가?
5. MVP에서 꼭 보여 주어야 할 보상은 무엇이며, 무엇을 다음 단계로 미뤄도 되는가?
