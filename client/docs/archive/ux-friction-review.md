# UI/UX Friction Review

이 문서는 MVP UI 명세를 만들기 위한 UX 검토 기록이다. 구현 기준 문서는 아니며, 최종 반영된 기준은 `client/docs/product-prd.md`, `client/docs/user-flow.md`, `client/docs/click-unit-ui-spec.md`, `client/docs/component-implementation-notes.md`를 따른다.

## 기준

- 이 문서는 `client/docs/user-flow.md`와 `client/docs/click-unit-ui-spec.md`를 사용자 관점에서 점검한 결과다.
- 반영된 제품 정책은 `client/docs/product-prd.md`, 컴포넌트 구현 책임은 `client/docs/component-implementation-notes.md`를 기준으로 다시 확인한다.
- 색, 타이포그래피, 시각 스타일 같은 디자인 평가는 제외한다.
- 점검 대상은 동작, 화면 전환, 정보 구조, 복구 가능성, 사용자가 다음 행동을 이해할 수 있는지다.
- 심각도는 `High`, `Medium`, `Low`로 구분한다.

## 핵심 요약

- 현재 명세는 클릭과 상태 변화가 많이 발산되어 있지만, 일부 화면은 사용자가 “왜 이 화면으로 왔는지”와 “다음에 뭘 해야 하는지”를 놓칠 수 있다.
- 가장 큰 위험은 빠른 시작이 실제로는 방 상세를 거치는 점, 타이머 종료 후 `기록 대기` 상태가 여러 화면에 걸쳐 남는 점, 샘플 데이터와 실제 데이터가 섞이는 점이다.
- MVP에서는 기능 수를 줄이는 것보다, 각 상태의 안내 문구와 복귀 경로를 명확히 하는 것이 더 중요하다.

## High

### 1. 빠른 시작인데 바로 시작하지 않는 느낌

- 불편 상황: 사용자가 `빠른 시작` 템플릿을 누른 뒤 바로 타이머가 아니라 방 상세로 이동한다.
- 사용자가 겪는 문제: “빠른 시작을 눌렀는데 왜 또 시작 버튼을 눌러야 하지?”라고 느낄 수 있다.
- 권장 수정: 빠른 시작에서 생성된 방 상세 상단에 `시작 전 확인` 성격을 명확히 표시한다.
- 권장 문구: `30분 조용히 읽기 방이 준비됐어요. 아래 내용을 확인하고 세션을 시작하세요.`
- 권장 UI 동작: 방 상세의 주요 CTA를 `세션 시작`보다 `30분 읽기 시작`처럼 템플릿 선택 결과와 연결한다.
- 영향 화면: 빠른 시작, 방 상세.

### 2. 기존 active 또는 기록 대기 세션이 있을 때 빠른 시작이 막히는 이유가 약함

- 불편 상황: 기존 active 또는 기록 대기 세션이 있으면 새 방 생성이 막히고 기존 세션 복귀만 제공된다.
- 사용자가 겪는 문제: 새로 시작하고 싶은 사용자는 “왜 선택지가 없지?”라고 느낄 수 있다.
- 권장 수정: 기존 세션 확인 모달에 막는 이유를 명시한다.
- 권장 문구: active 세션은 `진행 중인 세션이 있어요. MVP에서는 하나의 세션만 이어갈 수 있어요.`, 기록 대기 세션은 `끝난 세션의 기록이 아직 남아 있어요. 먼저 기록을 마무리해 주세요.`
- 권장 UI 동작: `기존 세션으로 돌아가기` 외에 `방 목록으로 돌아가기`를 제공해 사용자가 모달에 갇힌 느낌을 줄인다.
- 영향 화면: 빠른 시작, 기존 세션 확인 모달.

### 3. 타이머 종료 후 `나중에 작성` 상태가 사용자의 기억에 의존함

- 불편 상황: 사용자가 타이머 종료 후 기록하지 않고 나가면 `readyToRecord` 상태가 남는다.
- 사용자가 겪는 문제: 나중에 앱에 돌아왔을 때 이 세션을 왜 기록해야 하는지, 완료된 것인지 미완료인지 헷갈릴 수 있다.
- 권장 수정: 방 목록과 내 기록에서 같은 명칭을 사용한다.
- 권장 용어: `기록 대기`
- 권장 UI 동작: 방 목록 배너, 내 기록 `기록 대기` 필터, 기록 카드 배지 모두 `기록 대기`를 공통으로 사용한다.
- 영향 화면: 방 목록, 완료 기록, 내 기록.

### 4. 완료 기록 필수 입력이 많아 세션 완료 직후 피로할 수 있음

- 불편 상황: 책 제목, 시작 페이지, 끝 페이지, 감상 4개를 모두 필수로 입력해야 한다.
- 사용자가 겪는 문제: 실제 독서 직후에는 “짧게 마무리”하고 싶은데 페이지 입력 때문에 막힌다고 느낄 수 있다.
- 권장 수정: 필수는 유지하되 입력 부담을 줄이는 순서를 적용한다.
- 권장 UI 동작: 책 제목과 감상을 먼저 보이고, 페이지 입력은 같은 줄의 작은 그룹으로 묶는다.
- 권장 보조 문구: `정확하지 않아도 괜찮아요. 오늘 읽은 범위를 대략 남겨주세요.`
- 영향 화면: 완료 기록.

### 5. 샘플 데이터와 실제 데이터가 섞여 신뢰가 떨어질 수 있음

- 불편 상황: 샘플 데이터와 실제 데이터가 같은 목록에 표시된다.
- 사용자가 겪는 문제: 어떤 기록이 내가 만든 것인지 헷갈릴 수 있고, 목표 진행률에 샘플이 섞였는지 의심할 수 있다.
- 권장 수정: 샘플 데이터는 목록에 섞되 목표 진행률에는 포함하지 않는다고 명시한다.
- 권장 UI 동작: 샘플 배지, `샘플 제외` 필터, 목표 카드의 `샘플 제외 기준` 안내 툴팁을 제공한다.
- 영향 화면: 방 목록, 내 기록, 목표 카드.

## Medium

### 6. 방 목록의 카드 내부 클릭이 많아 주 액션이 흐려질 수 있음

- 불편 상황: 방 카드, 시간 칩, 분위기 태그, 감상 수 배지가 모두 클릭 가능하다.
- 사용자가 겪는 문제: 방에 들어가려는 사용자가 카드 안에서 어디를 눌러야 하는지 헷갈릴 수 있다.
- 권장 수정: 카드 전체 클릭은 방 상세 이동으로 유지하고, 필터성 클릭은 명확히 작은 보조 액션으로 둔다.
- 권장 UI 동작: 시간/태그 클릭은 첫 구현에서 비활성 텍스트로 두고, 필터는 방 목록 상단 칩에서만 처리하는 편이 안전하다.
- 영향 화면: 방 목록.

### 7. 방 상세의 `다시 고르기`는 임시 방 폐기 정책이 명확해야 함

- 불편 상황: 빠른 시작 방 상세에서 `다시 고르기`를 누를 때 현재 방이 남는지 삭제되는지 화면에서 알기 어렵다.
- 사용자가 겪는 문제: 사용자는 방이 이미 만들어졌다고 생각하지 못했는데, 목록에 방이 쌓이면 혼란스럽다.
- 권장 수정: 세션 시작 전 빠른 시작 방은 임시 방으로 취급한다.
- 권장 UI 동작: `다시 고르기`를 누르면 아직 시작하지 않은 템플릿 기반 방은 폐기한다.
- 영향 화면: 빠른 시작, 방 상세, 방 목록.

### 8. 방 생성 폼과 빠른 시작 템플릿의 역할이 겹침

- 불편 상황: 방 생성에도 `템플릿으로 채우기`가 있고, 별도 빠른 시작 화면도 있다.
- 사용자가 겪는 문제: “빠른 시작”과 “템플릿으로 채우기”가 같은 기능인지 다른 기능인지 불분명하다.
- 권장 수정: 빠른 시작은 바로 읽기용, 방 생성 템플릿은 직접 방 만들기 보조용으로 문구를 분리한다.
- 권장 문구: 빠른 시작 `지금 읽을 방 고르기`, 방 생성 `입력값 자동 채우기`
- 영향 화면: 빠른 시작, 방 생성.

### 9. 타이머 화면의 `나가기`가 active와 readyToRecord에서 의미가 다름

- 불편 상황: active 상태에서는 이탈이고, readyToRecord 상태에서는 기록 대기로 빠질 수 있다.
- 사용자가 겪는 문제: 같은 `나가기` 버튼인데 결과가 달라 예측하기 어렵다.
- 권장 수정: 상태에 따라 버튼 라벨을 바꾼다.
- 권장 라벨: active는 `세션 나가기`, readyToRecord는 `기록 나중에 작성`
- 영향 화면: 세션 타이머, 기록 대기 상태 이탈 확인 모달.

### 10. 내 기록의 필터와 정렬이 목표 진행률과 충돌할 수 있음

- 불편 상황: 내 기록에서 샘플/기록 대기/최근 7일 필터를 적용하면 목표 카드 수치와 목록 수치가 다르게 보일 수 있다.
- 사용자가 겪는 문제: “왜 목록에는 1개인데 목표는 3개지?”라고 느낄 수 있다.
- 권장 수정: 목표 카드는 항상 전체 실제 완료 기록 기준임을 표시한다.
- 권장 UI 동작: 필터 적용 중에는 목록 상단에 `현재 목록은 필터된 결과입니다` 안내를 표시한다.
- 영향 화면: 내 기록.

### 11. 기록 상세 모달에서 방 이동이 발생하면 현재 필터 맥락을 잃을 수 있음

- 불편 상황: 기록 상세 모달에서 `방에 다시 입장`을 누르면 방 상세로 이동한다.
- 사용자가 겪는 문제: 내 기록 필터 상태로 돌아오고 싶을 때 경로가 불명확하다.
- 권장 수정: 방 상세에 진입 출처를 저장하고 `내 기록으로 돌아가기` 보조 CTA를 제공한다.
- 영향 화면: 기록 상세 모달, 방 상세.

### 12. 데이터 초기화가 여러 화면에 있어 실수 위험이 큼

- 불편 상황: 온보딩, 방 목록, 내 기록에서 데이터 초기화/전체 리셋 CTA가 등장할 수 있다.
- 사용자가 겪는 문제: 샘플만 지우려는 건지 전체 데이터를 지우는 건지 혼동할 수 있다.
- 권장 수정: 초기화 관련 액션 이름을 분리한다.
- 권장 라벨: `샘플 다시 만들기`, `샘플만 삭제`, `전체 데이터 초기화`
- 영향 화면: 온보딩, 방 목록, 내 기록, 초기화 확인 모달.

## Low

### 13. 닉네임 입력에서 최근 닉네임/예시 닉네임이 과할 수 있음

- 불편 상황: 온보딩의 목적은 빠른 시작인데 최근 닉네임, 예시 닉네임, 기능 소개가 함께 있다.
- 사용자가 겪는 문제: 첫 화면에서 선택지가 많아 보일 수 있다.
- 권장 수정: 기본 화면에는 닉네임 입력과 시작 CTA만 강하게 두고, 예시/기능 소개는 보조 영역으로 접는다.
- 영향 화면: 온보딩.

### 14. 방 목록의 최근 본 방은 MVP에서 우선순위가 낮음

- 불편 상황: 빠른 시작, 방 만들기, 진행 세션 복귀, 기록 대기, 최근 본 방이 동시에 있을 수 있다.
- 사용자가 겪는 문제: 지금 해야 할 행동보다 보조 정보가 앞설 수 있다.
- 권장 수정: 우선순위는 `진행 세션 복귀 > 기록 대기 > 빠른 시작 > 방 만들기 > 최근 본 방`으로 둔다.
- 영향 화면: 방 목록.

### 15. 완료 기록 저장 후 바로 내 기록으로 이동하면 저장 결과 확인은 되지만 다음 행동이 약함

- 불편 상황: 저장 성공 후 내 기록으로 이동한다.
- 사용자가 겪는 문제: “이제 뭘 하지?”가 약할 수 있다.
- 권장 수정: 내 기록 최상단에 방금 저장한 기록을 강조하고 `같은 방 다시 읽기`, `방 목록으로` CTA를 제공한다.
- 영향 화면: 완료 기록, 내 기록.

### 16. localStorage 안내가 너무 자주 나오면 불안감을 줄 수 있음

- 불편 상황: 브라우저 저장, 저장 공간 부족, 데이터 손상/복구 안내가 여러 곳에 등장한다.
- 사용자가 겪는 문제: 서비스가 불안정하다고 느낄 수 있다.
- 권장 수정: 기본 안내는 온보딩과 오류 상황에만 노출하고, 정상 흐름에서는 숨긴다.
- 영향 화면: 온보딩, 데이터 손상/복구 화면.

## 권장 우선순위

1. `기록 대기` 상태 용어와 복귀 경로를 통일한다.
2. 빠른 시작에서 방 상세로 넘어가는 이유를 명확히 설명한다.
3. 샘플 데이터가 목표 진행률에 포함되지 않는다는 기준을 세운다.
4. active/readyToRecord 상태에서 타이머 화면의 버튼 라벨을 다르게 한다.
5. 방 목록의 카드 내부 클릭을 줄이고 주 액션을 선명하게 한다.

## 반영 상태

- `client/docs/product-prd.md`에 제품 본질, MVP 목표, 성공지표, 용어, 샘플, 기록 대기, 빠른 시작 정책을 추가했다.
- `client/docs/click-unit-ui-spec.md`에 `기록 대기` 사용자 노출 문구, 빠른 시작 `시작 전 확인`, 내 기록 `샘플 제외` 기준, 상태별 타이머 버튼 라벨을 반영했다.
- `client/docs/component-implementation-notes.md`에 주요 컴포넌트별 책임, props/state, handler, 표시 조건을 분리했다.
- 남은 구현 판단: 방 목록 카드 내부의 시간/태그/감상 수 클릭을 MVP에서 실제 인터랙션으로 둘지, 상단 필터 칩으로만 제한할지 결정해야 한다.
