# Reading Bookshelf Concept: User Review and Decision

> 이 문서는 `reading-bookshelf-expert-brainstorm.md`를 바탕으로 첫 방문 사용자와 재방문 사용자 관점에서 검토한 기록이다. 이후의 구현 기준은 README와 제품 문서에서 확정한다.

## 사용자 관점의 공통 결론

책장 은유는 좋지만, 사용자의 첫 질문인 `무슨 책을 읽고 있었지?`, `몇 쪽부터였지?`에 즉시 답하지 못하면 장식으로 느껴진다. 따라서 책장은 정체성과 수집을 돕는 보조 구조로 두고, 재방문 시 가장 위에 **최근 이어 읽기**를 배치한다.

```text
『데미안』
지난번 58쪽까지 읽었어요 · 4일 전
“혼란스러운 문장이 지금 상태와 잘 맞았다.”

[59쪽부터 이어 읽기]
```

## 합의한 제품 원칙

1. **재개가 시각 연출보다 먼저다.**
   - 빈 책장에서는 `읽고 있는 책 추가` 하나를 가장 강한 행동으로 둔다.
   - 재방문 사용자는 최근 이어 읽기 카드에서 바로 마지막 책갈피로 돌아간다.

2. **기록은 가볍고 회복 가능해야 한다.**
   - 페이지 범위는 필수이며, 시작 페이지는 이전 끝 페이지 + 1을 제안하되 수정할 수 있다.
   - 짧은 감상은 선택 입력이다. 감상이 없어도 `42–58쪽 읽음`이라는 세션 기록 페이지는 남는다.
   - 타이머를 쓰지 않거나 중단해도 기록 저장을 막지 않는다.
   - 잘못 입력한 기록을 정정하는 경로는 후속 구현에서 반드시 고려한다.

3. **완독 서평은 목적지이지 의무가 아니다.**
   - 완독 후 긴 서평 페이지가 열리는 구조는 유지한다.
   - 사용자는 서평을 바로 쓰지 않아도 책을 완독 선반으로 옮길 수 있어야 한다.
   - 첫 수직 슬라이스에서는 실제 완독·서평 저장보다, 이 목적지를 조용히 예고하는 데 그친다.

4. **신뢰도는 점수가 아닌 개인 독서 발자취다.**
   - 랭킹, 비교, 결석 표시, 끊긴 스트릭을 사용하지 않는다.
   - 발자취는 이후 `reading_records.createdAt`에서 파생한다. 개인 책장 루프를 먼저 검증한다.

5. **친구 서재는 공개보다 비공개가 기본이다.**
   - 현재 읽는 책, 페이지, 세션 감상, 읽은 시간대, 발자취는 기본 비공개다.
   - 친구 기능의 첫 범위는 친구 요청·수락 뒤 사용자가 공개한 완독 책장과 서평만 방문하는 것이다.
   - 좋아요, 랭킹, 실시간 피드, 타이머 동기화는 이후에도 신중히 검토한다.

## 단계별 범위 합의

### P0: 개인 책장의 독서 재개 수직 슬라이스

- 책 등록
- 읽는 중 책장 조회
- 최근 이어 읽기 카드
- 책 상세와 세션 기록 페이지 조회
- 세션 기록 저장
- 다음 시작 페이지 제안
- 새로고침 후 같은 책을 이어 읽기

### P1: 완독과 보조 집중

- 완독 처리와 완독 선반
- 긴 서평 저장과 세션별 감상 모아보기
- 마지막 서평 페이지 열림
- 선택적 타이머

### P2: 개인화와 발자취

- 독서 발자취 시각화
- 책등·서가 테마와 선택형 보상
- 컬렉션, 순서 변경, 선반 관리

### P3: 친구 서재

- 친구 요청·수락과 관계 관리
- 공개한 완독 책장과 서평 방문
- 책별 공개 범위

## 문서 반영 결정

- README는 프로젝트 정의와 첫 수직 슬라이스를 P0 기준으로 바꾼다.
- Product PRD와 사용자 흐름은 `책장 → 책 상세 → 세션 기록 → 다음 페이지 재개`로 전면 교체한다.
- 컴포넌트와 클릭 단위 명세는 새 시나리오 합의 뒤 재작성한다.
- 기존 독서방/신뢰도 문서는 이전 콘셉트의 의사결정 기록으로 archive에 보관한다.
