# 4주차 계획 — 전공필수 크라우드소싱 + 이번 주 배포

> 1개월 프로젝트의 마지막 주(금요일 데모데이) 계획. 학과 확장 시 코드를 계속 고쳐야 하는 문제를
> "전공필수 크라우드소싱 신고" 기능으로 완화하고, 남은 요일은 배포에 집중한다.

## Context

Campus Scheduler는 원래 모든 학교·학과를 지원하는 걸 목표로 했지만, 전공필수/선수과목 같은
"커리큘럼 지식"은 학교 API가 주지 않아서 결국 `backend/src/data/requiredCourses.js`에 컴퓨터학부만
수기로 하드코딩된 상태로 굳어버렸다. 실제 병목은 DB 스키마나 추천 알고리즘이 아니다 —
`backend/src/db/schema.sql`의 `lecture.required` 컬럼과 `frontend/src/algo/recommendTimetable.js`는
이미 학과 무관하게 동작한다. 문제는 딱 하나, "이 과목이 전공필수다"라는 지식을 코드 파일이 아니라
DB 데이터로 넣는 방법이 없다는 것.

이번 스프린트에서는 이 지식을 **(1) 학교 API의 교과구분(`sbjetSctnm`)에 이미 있는 "전공필수/교양필수"
값을 자동으로 활용 + (2) 그걸로도 못 채우는 나머지는 사용자가 직접 신고(크라우드소싱)** 하는 두
장치로 채운다. 여러 학교 지원은 이번 범위 밖이고, "같은 학교 내 다른 학과"로 확장 가능한 구조를
만드는 것까지가 목표다. 기능 확장보다 배포 안정성이 우선이며, 새 기능은 화요일 배포를 막지 않는
선에서 최소 범위로 구현한다.

## 진행 상황 (2026-07-27 기준)

**코드 작업 완료 (테스트 통과: 백엔드 40개, 프론트엔드 27개)**
- `required_course_report` 테이블 정의 (`schema.sql`)
- `GET /api/lectures`에서 신고된 과목을 `required: true`로 병합
- `POST /api/lectures/required-report` 신고 API 추가 (`requireUser` 미들웨어를 `backend/src/middleware/requireUser.js`로 공용화)
- `seedLectures.js`의 `isRequired()`에 교과구분 기반 fallback 추가
- `PreferenceScreen.jsx`에 "전공필수예요" 신고 버튼 추가
- 배포 블로커 수정: `PORT`를 `process.env.PORT`로, `backend/package.json`에 `start` 스크립트 추가

**⚠️ 남은 조치 (사용자 직접 실행 필요)**
- 위 코드가 참조하는 `required_course_report` 테이블이 **실제 Supabase 프로젝트에는 아직 없음**.
  Supabase 대시보드 → SQL Editor에서 아래 SQL 실행 필요:
  ```sql
  CREATE TABLE IF NOT EXISTS required_course_report (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    department TEXT NOT NULL,
    course_name TEXT NOT NULL,
    user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ DEFAULT NOW()
  );

  CREATE UNIQUE INDEX IF NOT EXISTS idx_required_course_report_unique ON required_course_report(department, course_name);
  ```
  실행 전까지는 `GET /api/lectures`가 500 에러를 낸다 (로컬 개발 서버에서 확인됨).

## 월요일 — 핵심 기능 완료 + 배포 준비

### 1. 전공필수 크라우드소싱 신고 (신규 기능)

- **DB**: `schema.sql`에 `required_course_report` 테이블 추가
  - 컬럼: `id, department TEXT, course_name TEXT, user_id UUID REFERENCES auth.users(id), created_at`
  - `UNIQUE(department, course_name)` — 첫 신고가 그대로 확정 (투표/모더레이션은 이번 범위 밖)
- **시딩 단계 개선**: `seedLectures.js`의 `isRequired()`에 fallback 추가
  — `requiredCoursesByDepartment`에 없는 학과는 `category`(API의 `sbjetSctnm`)에 "필수"가 포함되면
  자동으로 `required=true`. 컴퓨터학부처럼 이미 수기 큐레이션된 학과는 기존 목록이 우선(더 정확하므로
  그대로 유지, 예: "알고리즘1만 필수, 알고리즘2는 아님" 같은 미묘한 케이스는 API 카테고리만으론 못 잡음).
- **읽기 시점 병합**: `lectures.js` GET 라우트에서 `required_course_report`를 department 기준으로
  조회해서, 해당 course_name과 일치하는 강의는 `required: true`로 덮어써서 응답.
  → 신고가 들어오면 재시딩 없이 바로 다음 조회부터 반영됨.
- **신규 라우트**: `POST /api/lectures/required-report { department, courseName }`.
  `timetables.js`의 `requireUser` 미들웨어와, `/:id/recommend`에서 쓰인
  "insert 실패 23505 = 중복이니 그냥 무시" 패턴을 그대로 재사용.
- **프론트**: `PreferenceScreen.jsx`의 "이미 들은 과목" 목록 옆에 과목별로 작은 "전공필수예요" 신고
  버튼 추가 (토글/취소 없이 1회성 제보, 클릭 시 텍스트를 "제보 완료"로 교체하는 정도의 최소 UI).
  `frontend/src/api/lectures.js`에 `reportRequiredCourse()` 함수 추가.
- 학과 드롭다운은 이번 주엔 컴퓨터학부 유지 (실제 2번째 학과 데이터 확보는 목/금 여유 있을 때 스트레치 목표로 아래 참고).

### 2. 배포 준비 (블로커만)

- `index.js`: `PORT`가 3000으로 하드코딩되어 있음 → `process.env.PORT || 3000`으로 변경
  (Render는 동적 포트를 할당하므로 이거 안 고치면 배포 후 그냥 안 뜸).
- `backend/package.json`에 `"start": "node src/index.js"` 스크립트 추가 (Render 기본 시작 명령).
- 환경변수 목록 정리만 해두기 (실제 입력은 화요일):
  - Render(backend): `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `GEMINI_API_KEY`
  - Vercel(frontend): `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_API_BASE_URL`(화요일 Render 배포 URL 나온 뒤 채움)
- CORS는 지금 `cors()`(전체 오픈)라 월요일엔 손대지 않음 — 데모 단계에서 굳이 좁힐 필요 없음, 시간 아끼기.
- `frontend`/`backend` 양쪽 `npm run test:run` 전체 통과 확인.

## 화요일 — Vercel·Render 첫 배포

- **Render**: New Web Service, root directory `backend/`, build `npm install`, start `npm start`,
  위 3개 env var 등록.
- **Vercel**: New Project, root directory `frontend/` (Vite 자동 감지), 위 3개 env var 등록
  (`VITE_API_BASE_URL`은 Render URL 확정 후 입력).
- 배포 후 실 URL에서 스모크 테스트 1회: 회원가입/로그인 → 조건 입력(강의 목록 로딩 확인) →
  추천 결과 → 확정 → 캘린더 → 공유 → 홈에서 선배 시간표 추천(좋아요) 전체 플로우.
- Supabase RLS 정책이 로컬과 동일하게(막혀서 조용히 빈 배열/에러 나는 일 없이) 열려있는지 재확인 —
  로컬에서만 잘 되고 배포 후 "왜 강의가 안 보이지" 하는 흔한 함정.

## 수·목 — 보완 + 재배포 + 워크플로우 정리 + 영상 제출(수)

- 화요일 스모크 테스트에서 나온 버그 수정 → 재배포. **영상 제출이 수요일이므로, 늦어도 화요일 밤까지
  크리티컬 버그는 없어야 함** — 목요일 작업은 영상에는 못 담기니 우선순위 낮게.
- 문서화(README/CLAUDE.md): "학기 바뀌면 `npm run seed:lectures` 재실행", "학과 추가하려면
  `seedLectures.js`의 `TARGETS`에 학과코드만 추가하면 됨(코드 수정 없음, 전공필수는 카테고리
  자동 인식 + 크라우드소싱으로 채워짐)" — 데모 발표에서 "확장성" 설명할 때 그대로 재사용 가능.
- **(스트레치, 여유 있을 때만)** 두 번째 학과 강의 데이터 시딩 — `estblDprtnCd`(학과코드)를 실제로
  알아내서 `TARGETS`에 한 줄 추가하고, `requiredCoursesByDepartment`에 없는 상태로도 카테고리 fallback +
  크라우드소싱만으로 전공필수 필터링이 동작하는 걸 실증. 시간 부족하면 과감히 스킵 — 데모는
  "코드는 이미 이렇게 짜여 있다"는 설명 + 컴퓨터학부 시연만으로도 충분함.

## 금요일 — 데모데이

- `backend`: `npm run test:run` / `frontend`: `npm run test:run` (기존 라우터가 supabase/gemini를
