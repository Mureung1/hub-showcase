# T22 현장 실행 체크리스트

> 실행 규칙의 정본은 [`docs/COMPETITIVE_VALIDATION.md`](../../../docs/COMPETITIVE_VALIDATION.md) 3·5·6·8~13장이다. 이 체크리스트는 순서 누락을 막는 운영용 색인이며, 과업·배정·필드·임계값이 다르면 정본을 따른다.
>
> 실제 참여자 행, 연락·보상 명단, 도구 원출력, 계정 정보는 이 파일이나 Git 저장소에 기록하지 않는다.
>
> 모집·시작·종료 안내는 [`participant-brief.md`](participant-brief.md)를 사용한다.
>
> 2026-07-23 사용자 결정으로 대학생 5명 과업은 실행하지 않는다. 이 문서는 향후 결정을 바꿀 때를 위한 준비본이며 현재 세션 모집에 사용하지 않는다.

## 0. 실행 중지 조건

다음 중 하나라도 충족하지 않으면 세션을 예약하거나 시작하지 않는다.

- [ ] 모집 기준을 충족하고 제외 기준에 해당하지 않는 대학생 후보가 있다.
- [ ] 평소 사용 중인 ChatGPT 또는 Gemini로 가상 과업을 수행하는 데 동의했다.
- [ ] 같은 답냥이 Preview URL·콘텐츠·provider 버전을 모든 세션에서 유지할 수 있다.
- [ ] 접근 제한 저장소에 원시 기록표와 연락·보상 명단을 분리해 둘 수 있다.
- [ ] 평가자 2명과 불일치 시 제3자 판정 경로가 확보됐다.

개인 계정 비교 거절이나 반복 기술 결측으로 유효 짝비교가 5명 미만이면 `Go | Iterate | No-go`를 내리지 않고 `Pending`으로 둔다. `controlled_baseline`은 부족한 분모를 채우지 않는다.

## 1. 첫 세션 전 버전 동결

아래 값은 접근 제한 실행 기록에 적고, Git에는 식별정보 없는 버전 근거만 집계한다.

- [ ] study version
- [ ] 동의·안내 version
- [ ] 답냥이 배포 URL과 콘텐츠 commit 또는 배포 version
- [ ] Gemini provider 표시 모델·프롬프트·템플릿 version
- [ ] 세션 기기·브라우저와 테스트 일시
- [ ] P01~P05 교차 배정표와 A1~A4 배정이 정본 8장과 일치
- [ ] 결과를 보기 전에 정본 12장의 gate와 판정 순서를 다시 확인

버전·과업·배정 오류가 발견되면 버전을 올리고 변경 전후 결과를 합치지 않는다.

### 2026-07-23 배포 후보 확인

- 공개 도메인: `https://dabnyang.vercel.app/` — HTTP 200
- GitHub Production deployment: `5564774983`, `success`
- 배포 SHA와 현재 로컬 HEAD: `b9d6b2563d666b57a39894d74c106090dc301329`
- 고유 Vercel URL: `https://dabnyang-6qf611ryw-jinhyunjis-projects.vercel.app/`
- 접근 제약: 고유 URL은 Vercel 로그인으로 이동해 외부 참여자용 고정 URL로 바로 사용할 수 없다.

따라서 위 값은 세션 version 후보일 뿐 아직 동결 완료가 아니다. 사용자는 고정 Preview 대신 공개 Production을 쓰고 세션 기간 SHA를 동결하는 방식을 승인했다. 다만 같은 응답에서 대학생 5명 과업을 실행하지 않기로 결정했으므로 실제 동결·모집은 수행하지 않는다. 향후 재개하면 Production Branch push를 멈추고, 각 세션 시작 전 공개 도메인이 같은 deployment ID·SHA를 가리키는지 재확인한다.

## 2. 제품·접근성 사전점검

### 자동·배포 점검

- [ ] 고정 version에서 전체 테스트, 프론트/API 타입검사, lint, production build 통과
- [ ] C1~C4 카드 경로가 `S0 → 관계 → 카드 → 질문/기본 초안 → 3톤 → 최종 확정`까지 동작
- [ ] A1~A4 직접 설명 경로가 provider 고지 뒤 실 AI 3톤을 반환
- [ ] 강제 API 실패에서 재시도와 기존 후보 보존·안전 fallback이 계약대로 동작
- [ ] 브라우저에 provider·DB 비밀이 노출되지 않고 원문이 서비스 DB·분석에 저장되지 않음

### 키보드·스크린리더 점검

- [ ] 키보드만으로 S0부터 카드 결과와 직접 설명 결과까지 도달·선택·수정·복사·뒤로가기 가능
- [ ] 선택 카드, 질문, 생성 중, 생성 성공·실패, 복사 성공, 이전 초안 전환 때 초점과 live 안내가 중복·누락 없이 전달
- [ ] 라디오/탭/버튼의 이름·상태·순서가 시각 정보 없이 구분됨
- [ ] 오류 뒤 재시도 대상과 보존된 입력·후보를 스크린리더로 이해 가능
- [ ] 실제 검증한 OS·브라우저·스크린리더·viewport와 발견 사항을 비식별 검증 기록에 남김

## 3. 참여자별 세션

### 시작 전

- [ ] 만 18세 이상 재학생, 한국어 메신저 주사용, 최근 메시지 망설임과 AI 초안 경험 조건 확인
- [ ] 프로젝트 참여자·기존 검수자·답냥이 사전 사용자가 아님을 확인
- [ ] 실제 원문·캡처·실명·학교·학과·학번·연락처·개인 대화 목록을 수집하지 않는다고 안내
- [ ] 중단·질문 건너뛰기·결과와 무관한 고정 보상 원칙 안내
- [ ] 연락·보상 연결표와 연구 코드 `P01`~`P05`를 분리

### 카드 비교 C1~C4

- [ ] 정본 8장의 참여자별 `D/B`, A/B 변형, 순서를 그대로 사용
- [ ] 도구를 열기 시작한 `trial_start_at`과 상호작용 가능한 `tool_ready_at`을 분리
- [ ] 두 도구 결과를 같은 공통 편집칸에서 수정하고 `final_confirmed_at`까지 기록
- [ ] 진행자는 통일 문구만 읽고 카드·프롬프트·정답을 추천하지 않음
- [ ] 30초 정지 또는 도움 요청 2회 뒤 표준 힌트 1회만 제공하고 `assisted=true` 기록
- [ ] 네트워크·로그인 장애만 `technical_missing`으로 한 번 재시작

### 답냥이 실 AI A1~A4

- [ ] 정본 배정표의 한 과업만 `직접 설명할게요`와 첫 생성 1회로 수행
- [ ] 범용 AI와 경쟁 집계하지 않고 무도움 완료·시간·개인정보 이해를 답냥이 단독으로 기록
- [ ] 과업에 없는 실제 정보나 개인정보를 입력하지 않도록 관찰

### 과업 직후

- [ ] `would_send`, confidence, mental effort, `authorship_fit_1_5`, 수정·작성량·생성 턴 기록
- [ ] 화면을 보지 않고 카드 원문 경계, 탭 보관·provider 전송, 복합 관계 범위 세 질문을 중립적으로 확인
- [ ] 틀린 답은 세션 뒤 설명하되 성공으로 소급하지 않음
- [ ] 다음 카드 적합 상황에서 먼저 고를 도구와 이유를 기록
- [ ] 철회·불편·개인정보 노출 시 즉시 중단하고 보상은 유지

## 4. 세션 뒤 데이터 처리

- [ ] 실제 원문이나 개인정보가 우발 입력되면 세션을 중단하고 24시간 안에 삭제한 뒤 `redaction_applied`만 유지
- [ ] 연락·보상 연결표는 보상 완료 후 7일 안에 삭제
- [ ] 비식별 원시 기록은 판정 확정 후 30일 안에 삭제
- [ ] Git에는 집계표·가상 과업·익명 점수와 판정 근거만 남김
- [ ] 원후보와 최종문에서 도구·참여자·시간·원후보/최종문 표기를 제거하고 무작위 `blind_output_id` 부여

## 5. 블라인드 평가와 판정

- [ ] 평가자 2명이 관계 적합·완결성·사실 충실성·톤 적합·전송 가능을 독립 채점
- [ ] 사실 위반·합격 판정 불일치 또는 총점 차이 2점 이상이면 제3자 판정
- [ ] 원점수와 불일치를 삭제하지 않음
- [ ] 참여자별 완료율·E2E 중앙값·작성량·턴·수정률을 먼저 계산하고 trial을 독립 참여자처럼 세지 않음
- [ ] `안전·품질 hard gate → 경쟁 효율 → 선택` 순서로 판정
- [ ] ChatGPT와 Gemini 원자료를 분리하고 결과 표현을 “이 5명의 평소 사용 도구 대비”로 제한
- [ ] 실제 결과와 프로토콜 이탈을 `docs/COMPETITIVE_VALIDATION.md` 13장 템플릿 구조로 집계

## 6. T22 종료 조건

다음이 모두 충족될 때만 검증 보고서를 `통과`로 바꾸고 CHECKLIST T22를 체크한다.

- [ ] 유효한 평소 사용 도구 짝비교 5명
- [ ] MVP DoD와 고정 version 전체 자동 품질 gate 통과
- [ ] 키보드 전 흐름·스크린리더 단계 전환 수동 검증 통과
- [ ] 카드·실 AI 무도움 완료, 품질, 경계 이해, 경쟁 효율, 선택 gate 통과
- [ ] 최종 판정 `Go`
- [ ] 원시 데이터·개인정보가 Git diff에 없음

`Iterate` 또는 `No-go`이면 외부 가치 주장을 보류하고 결과에 따라 변경안을 별도 제안한다. 기술 배포 완료와는 별도 판정하며 임계값은 결과를 본 뒤 낮추지 않는다.
