## 1. 목표와 완료조건

- 해결할 사용자/제품 문제: 교수·조교에게 이메일을 보내는 상황은 짧은 메신저 문구보다 더 격식 있는 제목·자기소개·목적·가능 시간·맺음말이 필요한데 현재 흐름은 매체를 구분하지 않는다.
- 목표 결과: 교수·조교 관계에서 메신저와 이메일을 명시적으로 고르고, 이메일이면 필요한 사실을 안내 입력한 뒤 제목과 본문이 분리된 세 후보를 결정적으로 받는다.

## 3. 작업트리 기준선

- 시작 상태: T33 구현은 이미 존재하고 현재 관련 2파일 93테스트가 통과한다. T32·T26·사용자 피드백 미커밋 변경을 그대로 보존하며 `src/features/cat-stage/**`, T26 compiler, 사용자 미추적 파일은 소유하지 않는다.
- 평가자 정보가 있을 수 있는 미추적 T25 설문 CSV는 읽기·수정·추적하지 않는다.
- PM 소유: 공유 타입·카탈로그, 정본 문서, T33 하네스, CHECKLIST, LOG, 최종 통합.
- 제품 디자이너 소유: 이메일 18후보와 사용자 검토표.
- 프론트엔드 소유: 연락 형식·이메일 상황/입력/결과/복사 UI와 App 테스트·CSS.
- 백엔드/AI 비활성: 이번 이메일 경로는 로컬 결정적 템플릿만 사용하며 서버 AI 스키마를 바꾸지 않는다.

## 5. 변경 경계와 위험

- 허용: 교수 전용 연락 형식, 이메일 6상황·18후보 초안, 안내 입력, 제목/본문 결과·복사, 30분 세션 상태, 정본·테스트·검토표.
- 제외: 이메일 자유 설명 AI 호출, 실제 메일 전송, 주소록·첨부·예약 발송, 학교 계정 인증, 다른 관계의 채널 선택, provider/DB 변경.
- 승인된 구조 변경: `contactChannel`과 이메일 `subject/body` 결과를 클라이언트 로컬 템플릿 경로에 추가한다.
- 위험: 학번·이름 입력은 개인정보이므로 provider나 로그로 전송하지 않고 현재 탭 sessionStorage에만 30분 보존한다. 문구 자연스러움은 자동 검사로 합격 처리하지 않는다.
- 교수·조교 호칭은 관계 ID로 추측하지 않고 `recipientName`에 사용자가 입력한 성함+호칭을 그대로 사용한다.
- 감사·후속 샘플의 감사 과반복과 요청 없는 확인 문구는 2026-07-22에 최소 보완했다. 그 밖의 자연스러움은 자동 테스트로 합격 처리하지 않고 사용자 판정을 기다린다.
