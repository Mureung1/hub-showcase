## 검토 기준

- 관계·상황 카드 뒤에 묻기 자연스러운 핵심 질문인가?
- 세 보기가 서로 다르고, 해당 상황에서 자주 필요한 선택인가?
- 옵션은 사용자가 고른 의도만 담고 날짜·이유·약속·상대 동의를 지어내지 않는가?
- 옵션에 없는 구체 사실이 필요할 때 `내 상황을 직접 설명하기`로 이동해도 되는 범위인가?

## 팀플·조모임

### groupwork / schedule

**질문:** 어떻게 일정을 맞출까요?

- 가능한 시간 묻기 — 상대가 가능한 시간을 질문한다. 특정 후보 시간은 만들지 않는다.
- 정해둔 시간 확인 — 앞서 논의한 시간을 확인한다. 정확한 시간이나 최종 확정은 만들지 않는다.
- 다시 같이 정하기 — 일정을 다시 함께 조율하자고 제안한다. 취소나 갈등 원인은 만들지 않는다.

### groupwork / thanks_check

**질문:** 어떤 말을 더 앞에 둘까요?

- 확인했다는 말 — 공유된 내용을 확인했다고 말한다. 동의나 과업 완료는 만들지 않는다.
- 공유해준 점에 감사 — 무언가를 공유해 준 점에 감사한다. 자료 품질이나 노력 정도는 평가하지 않는다.
- 도와준 점에 감사 — 도움을 받은 점에 감사한다. 도움의 범위나 결과는 만들지 않는다.

### groupwork / ask

**질문:** 어떤 도움을 부탁할까요?

- 자료 공유 부탁 — 팀 자료 공유를 부탁한다. 파일명이나 상대의 소유 여부는 만들지 않는다.
- 검토·의견 부탁 — 검토와 의견을 부탁한다. 범위, 기한, 긍정 평가는 만들지 않는다.
- 맡은 일 관련 도움 — 자신이 맡은 일과 관련해 도움을 부탁한다. 실패나 상대 책임은 만들지 않는다.

### groupwork / apologize

**질문:** 어느 점을 사과할까요?

- 답장이 늦은 점 — 답장이 늦은 점을 사과한다. 이유나 지연 기간은 만들지 않는다.
- 확인이 늦은 점 — 확인이 늦은 점을 사과한다. 고의나 영향은 만들지 않는다.
- 팀 진행을 늦춘 점까지 — 자신의 지연이 팀 진행을 늦춘 점까지 인정한다. 피해 정도나 마감 위반은 만들지 않는다.

### groupwork / decline

**질문:** 무엇이 어렵다고 전할까요?

- 이번 부탁 — 이번 부탁을 거절한다. 이유나 향후 수락 약속은 만들지 않는다.
- 제안된 일정 — 제안된 일정 참여가 어렵다고 말한다. 다른 일정도 모두 불가능하다고 만들지 않는다.
- 추가 역할 — 추가 역할을 맡기 어렵다고 말한다. 역량 부족이나 타인 책임은 만들지 않는다.

### groupwork / contribution_check

**질문:** 무엇을 확인할까요?

- 진행 상황 — 현재 진행 상황을 묻는다. 미진행이라고 단정하지 않는다.
- 공유 가능한 시점 — 공유 가능한 시점을 묻는다. 임의의 마감이나 약속은 만들지 않는다.
- 막힌 점이나 도움 필요 여부 — 막힌 점이나 도움이 필요한지 묻는다. 실제 문제가 있다고 단정하지 않는다.
