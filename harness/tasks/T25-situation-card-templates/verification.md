## B/S/C 자체 preflight

- B는 추가 쿠션 없이 예의와 화행이 드러나는 기본 문구로 작성했다.
- S는 각 세트에 선택권·부담 완화 또는 관계상 자연스러운 완화 표지 하나만 사용했다.
- C는 핵심 의사를 앞에 두고 S보다 길지 않게 작성했다.
- 자동 검사는 문자열 규칙을 보장할 뿐, 사실·의도 동일성과 소리 내어 읽었을 때의 자연스러움은 사람 평가를 대신하지 않는다.
- `thanks_check`처럼 선택권이 없는 감사 화행의 S는 `덕분에` 또는 `정말` 한 개만 사용했다.

## 말투 취향 후속 방향

- `습니다체 / 이다체 / 다나까체`는 서로 배타적인 선택지가 아니다. 하십시오체 안에 `합니다/합니까`가 함께 있고 `-다`는 관계·화행에 따라 낮춤으로 읽힐 수 있어 전 관계 공통 축으로 쓰지 않는다.
- 이번 72개와 생성 계약에 별도 말투 필드를 추가하지 않았다.
- 결과 화면에서 `어떤 말투로 보낼까냥?`이라고 묻고, 관계별 높임을 먼저 지킨 B/S/C 세 후보를 고르게 한다.
- 문법 어미 취향 축은 T22에서 실제 요구가 확인되고 관계별 허용 범위와 별도 검수 분모를 승인받은 뒤에만 후속 설계한다.

## 2026-07-12 1차 검수 반영 수정

1차 검수(최종 의견: 수정 후 재검수, hard fail 0건, 자연 1점 약 27개)의 우선 수정 4범주를 16개 문구에 반영했다.

- 조건부 사과 4건 제거: `기다리게 했다면/해드렸다면/기다렸으면` → 무조건 사과 `기다리게 해서/해드려` (GW·PF·SR·FR APO S)
- 교수·조교 딱딱함 5건: 거절 세트 3건을 `어렵습니다` 단정에서 `어려울 것 같습니다/어렵겠습니다`로, `문의드립니다` 공문체 제거(ABS S), `혹시` 이중 완곡 제거(ASK S)
- 완곡 표현 중복 3건: `괜찮으시다면…알려주실 수 있을까요` 이중 완곡을 유연성 제안(`편하신 시간에 맞추겠습니다`)으로(SCH S), `부담되지 않으시면`→`시간 되실 때`(GW ASK S), `혹시 괜찮으시면`→`바쁘지 않으시면`(SR ASK S)로 분산
- 감사 톤 차이 2세트: GW THX를 B=알려주셔서/S=챙겨주신 덕분에/C=간결 확인으로 재작성(C1 대표 세트 — 내부 preflight 재기록), PF THX S에 `큰 도움이 됐습니다` 추가
- 판정 기준 명확화: `full-review.md`에 합격 집계는 `F/R/X`·모드·관계·전송·톤으로만 계산하고 `자연` 점수는 재작성 우선순위 참고 정보임을 명시 (1차 검수의 자연 점수↔합격선 해석 간극 제거)
- 테스트 동기화: 조건부 사과 3패턴을 금지 목록으로 이동, 완화 표현 목록에 신규 5종 추가, 대표 세트(C1·C2) 원문 갱신
- C1·C2 대표 문구가 바뀌었으므로 `representative-review.md` 동기화 — R1 평가자 2인 검수는 이 버전으로 수행한다

'답장/먼저 보내기 모두 통과' 평가 기준 수정(1차 검수 의견 5번)은 SPEC 계약 변경이라 반영하지 않았고 별도 제안 대기.
