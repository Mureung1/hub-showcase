## 0. 말투 선택 조사와 제품 결정

- 국립국어원 상대 높임법 분류에서 하십시오체의 평서·의문형은 `합니다/합니까`다. 따라서 사용자 표현인 `습니다체`와 `다나까체`는 서로 배타적인 말투 축이 아니다.
- `-다`는 해라체 평서형에 해당해 교수·조교 요청이나 질문까지 일관되게 적용할 독립 스타일로 보기 어렵다.
- [한국어 공손성 표현 연구](https://www.kci.go.kr/kciportal/landing/article.kci?arti_id=ART002235411)는 문법적 공손 등급만 높여도 실제 공손성이나 사용 빈도가 함께 높아지지 않으며, 친근감·부담 완화 같은 화용 요소가 중요하다고 보고한다.
- [모바일 메신저 공손 전략 연구](https://www.kci.go.kr/kciportal/landing/article.kci?arti_id=ART001912614)는 관계와 대화 분위기에 따라 격식적인 문어체부터 비표준 친근체까지 전환된다고 분석한다.
- 결론: `습니다체 / 이다체 / 다나까체` 선택 필드는 T25에 추가하지 않는다. 결과 화면 질문을 `어떤 말투로 보낼까냥?`으로 바꾸고, 관계별 높임을 먼저 지킨 `기본 / 더 부드럽게 / 더 분명하게` 세 후보를 그대로 선택지로 사용한다.

## 1. 폼 문항 수정안

### 1-1. 사실 추가 문항 — 방향을 오독할 수 없게

현행: "상황 A에 대입했을 때, 상황에 나오지 않은 날짜, 행동, 기한, 약속 등의 사실을 완성된 사실처럼 추가했나요?"

수정안:

> **[C1-A] 이 문구 안에 상황 A에 없는 새로운 정보가 들어 있나요?** (날짜·기한·이유·행동·약속 등)
>
> - 예 — 문구에 상황에 없는 정보가 있다 (**문제 있음**)
> - 아니오 — 문구에 새로운 정보가 없다
>
> 설명문: 예시 — 상황에 마감 얘기가 없는데 문구에 "내일까지"가 있으면 "예"입니다. 문구가 짧고 아무 정보도 덧붙이지 않으면 "아니오"입니다.

### 1-2. 문제 발견/사용 가능 문항 구획 분리

"예"의 의미가 문항마다 뒤집히는 것이 오독의 원인이므로, 후보마다 두 구획으로 나누고 구획 제목을 붙인다.

> **① 문제 찾기 — 문제가 보일 때만 "예"** (3문항: 사실 추가 / 부적절한 호칭·말투 / 선택권·거절 의도 강제)
>
> **② 사용 가능성 — 가능할 때 "예"** (3문항: 수정 없이 전송 / 답장으로 사용 / 먼저 보내는 첫 메시지로 사용)

### 1-3. 보정용 연습 문항 추가 (첫 페이지)

응답 품질을 사후 판별할 기준점으로, 정답이 명백한 연습 후보 1개를 넣는다.

> 연습 상황: "팀원이 자료를 올렸고 고맙다고 답하고 싶다."
> 연습 문구: "고마워요 **내일 3시까지** 제가 정리해서 올릴게요"
> 문항: 위 1-1과 동일. **기대 답 "예"** (상황에 없는 기한·후속 작업 추가)

연습 문항을 틀린 응답은 재안내 후 재응답을 받거나, 해당 회차를 무효 처리한다. 기대 답은 평가자에게 사전 공개하지 않는다.

### 1-4. 톤 정렬 — 중복 선택 차단

현행: 드롭다운 3개(가장 직접 / 중간 / 가장 완곡) — 같은 후보 중복 선택 가능.

수정안: Google Forms **객관식 그리드** 1개로 교체.

- 행 = 후보 3개, 열 = `가장 직접적 / 중간 / 가장 완곡`
- 설정: "각 행에 응답 1개 필요" + **"열당 응답 1개로 제한"** — 순열이 강제됨
- 문항 문구: "세 후보를 **직접성 순서**로 한 번씩만 배치해 주세요. 표현 선호가 아니라, 얼마나 돌려 말하지 않고 핵심 의도를 드러내는지를 기준으로 판단합니다."

### 1-5. 자격 선별 문항 추가 (첫 페이지)

> "이 설문의 평가 대상 문구를 작성하거나 수정하는 데 참여한 적이 있나요?" — "예"면 제출 종료(섹션 분기).

기존 독립 수행 확인 문항("다른 평가자와 상의하지 않고…")은 유지한다.

## 2. 대표 문구·톤 반영 내용

### 2-1. C3 (선배·동기, casual_request) toneLevel 재배치·재작성

양 평가자가 독립적으로 C3-A를 가장 직접적이라고 판단한 결과를 반영했다. `존댓말도 괜찮아요`의 갑작스러운 병렬과 `원하시면`을 자연스러운 선택권 문장으로 다듬었다.

| 현행 문구 | 수정 toneLevel | 반영 문구 |
|---|---|---|
| 저한테는 편하게 말씀하셔도 괜찮아요 | **3 (더 분명하게)** | 저한테는 편하게 말씀하셔도 괜찮아요 |
| 말 편하게 하셔도 돼요 존댓말도 괜찮아요 | **1 (기본)** | 저한테는 말 편하게 하셔도 되고 존댓말로 하셔도 괜찮아요 |
| 원하시면 저한테는 편하게 말씀하셔도 돼요 | **2 (더 부드럽게)** | 혹시 편하시면 저한테는 말 편하게 하셔도 괜찮아요 |

### 2-2. C2 면담 세트 목적·사실 정합 보강

E1이 지적한 면담 목적 누락은 한 후보만 고치면 세 톤의 내용이 달라진다. 세 후보 모두 `여쭤볼 내용`이 있음을 밝히고, 특정 과목·주제는 지어내지 않았다. 기존 S의 `편하신 시간에 맞추겠습니다`라는 행동 약속은 `편하실 때`로 바꿨다.

- 기본: `안녕하세요 여쭤볼 내용이 있는데 면담 가능한 시간을 알려주실 수 있을까요?`
- 더 부드럽게: `안녕하세요 여쭤볼 내용이 있는데 편하실 때 면담 가능한 시간을 알려주실 수 있을까요?`
- 더 분명하게: `안녕하세요 여쭤볼 내용이 있습니다 면담 가능한 시간이 언제일까요?`

자리 표시자를 쓰면 수정 없이 전송 가능 판정이 불가능해지므로 쓰지 않는다.

### 2-3. 결과 화면 안내 문구

- 제목: `어떤 말투로 보낼까냥?`
- 설명: 관계에 맞춰 같은 뜻을 세 가지 말투로 준비했다는 점을 명시
- 선택 축: `기본 · 더 부드럽게 · 더 분명하게`
- 새 선택 단계나 `style` 필드는 만들지 않아 72개 구조와 R1 분모를 유지

### 2-4. 보류 — 이번에 바꾸지 않는 것

- **C1 톤 정렬**: 양쪽 모두 중복 선택으로 무효였다. 폼 수정(1-4) 후 재판정 결과로만 결정한다.
- **C4 쿠션 추가**: E1 한 명의 제안만 있어 직접 톤의 판별력을 유지하고 재검수에서 재현되는지 본다.
- **전반 72문구 재작성**: 작성자 본인 n=1의 자연스러움 점수만으로 확대하지 않는다. 외부 평가자 2인 재실행 결과가 같은 방향이면 별도 수정 계획을 세운다.

## 3. 재실행 절차

1. `situationTemplates.ts`·전수 검수지·대표 검수지·R2 실행 킷 동기화와 자동 preflight를 완료한다.
2. 1장 수정안대로 Google Forms를 수정한다(연습 문항·선별 문항·그리드 제한).
3. **작성자 아닌 외부 평가자 2인**이 독립 응답한다(E1 재참여 가능 — 새 회차로 취급).
4. 집계는 run1과 같은 절차로 하고, hard fail·전송 가능·모드 공유·하위 관계 호환·톤 순서 중 하나라도 불일치하면 제3자가 판정한다.
5. 통과 시 콘텐츠 버전을 동결한 뒤 R2 무참여자 모델 벤치마크를 시작한다.
