## 1. 목표와 완료조건

- 해결할 사용자/제품 문제: 직접 설명 경로의 AI 호출이 관계·목적·사실 충실성·안전·출력 형식을 일관되게 적용할 서버 전용 프롬프트 경계를 아직 갖지 못했다.
- 목표 결과: 검수 완료 예시를 나중에 주입할 수 있는 provider 비종속 프롬프트 골격을 만들고, 사용자 입력 격리·구조화 출력·정상 완료 판별·런타임 검증을 자동 테스트한다.

## 5. 변경 경계와 위험

- 허용된 변경: provider 비종속 프롬프트 규칙/조립/검증 모듈, 합성 fixture 단위 테스트, T19 정본·하네스 기록.
- 명시적으로 제외한 변경: `docs/SEEDS.md` 24개를 코드로 복사, `/seed` 검수 대체, provider SDK·키·모델 연결, handler 연결, 프론트 목→실 전환, DB, 배포·커밋·푸시.
- 구조·계약·의존성 승인이 필요한 지점: 공용 요청/응답 변경, 새 패키지·provider·DB 추가, 프론트 라우팅 변경, 실제 시드 이관은 별도 게이트와 승인이 필요하다.
- 예상 위험과 대응: XML 태그는 완전한 주입 차단이 아니므로 이스케이프·상충 지시·structured output·런타임 검증을 겹치고 보안 완화로만 표현한다. JSON Schema만 믿지 않고 정상 `stop_reason`과 공용 validator를 재검사한다. 예시 인터페이스가 검수 미완료 데이터를 승인한 것처럼 보이지 않도록 운영 상수는 만들지 않는다.
