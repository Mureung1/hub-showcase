## 1. 목표와 완료조건

- 해결할 사용자/제품 문제: 직접 설명 경로의 AI 호출이 관계·목적·사실 충실성·안전·출력 형식을 일관되게 적용할 서버 전용 프롬프트 경계를 아직 갖지 못했다.
- 목표 결과: 검수 완료 예시를 관계별로 주입하는 provider 비종속 프롬프트 계층을 만들고, 사용자 입력 격리·구조화 출력·정상 완료 판별·런타임 검증을 자동 테스트한다.

| ID | 검증 가능한 완료조건 | 검증 방법 | 필수 여부 |
| --- | --- | --- | --- |
| AC-1 | `api/_lib/prompt/`에 역할·관계·목적·스키마·예시·조립 책임이 분리되고 React/브라우저 코드에서 가져오지 않는다. | API 타입검사 + 구조·참조 검색 | 필수 |

## 2. 의존성·정본 확인

- T항목과 의존성 상태 또는 비-T 식별 근거: T18 provider 비종속 기반은 완료됐다. 2026-07-20 사용자가 T16 제3자 검수 완료를 승인해 블라인드 정렬 8/8·전송 가능성 24/24 통과로 기록했고, T16·T18 의존이 모두 충족됐다. 실 provider·키·Preview는 승인된 책임 분리에 따라 T20 범위다.
- CHECKLIST 본문이 직접 가리키는 문서·구간: `docs/CHECKLIST.md` T19, `docs/SPEC.md` 2~4장, `docs/EDGE_CASES.md` 1-5·1-6·5-1·5-2.
- 추가로 확인한 정본: `docs/AI_DESIGN.md` 4장, 공용 `src/shared/generation/contracts.ts`, Anthropic 공식 Structured Outputs·stop reason 문서(2026-07-15 확인).
- 이번 작업에서 바꾸지 않는 계약·범위: 공용 요청/응답 필드, 카드 템플릿 경로, 프론트 목 생성기, 실제 provider·모델·키, DB, 시드 원문·검수 상태, RAG·런타임 멀티에이전트.

## 3. 작업트리 기준선

- 시작 시 `git status --short` 요약: T18·T25·T28·T29, 정본 문서, 사용자 이미지 등이 함께 있는 대규모 미커밋 작업트리. 이 작업은 기존 변경을 되돌리거나 일괄 정리하지 않는다.
- 기존 변경 중 반드시 보존할 파일·의도: T18 서버 기반, T25 검수 자료·CSV, T28/T29 UI·이미지·하네스, 기존 정본 변경 전부.

## 5. 변경 경계와 위험

- 허용된 변경: provider 비종속 프롬프트 규칙/조립/검증 모듈, T16 승인 시드 24개 서버 카탈로그, 합성·카탈로그 단위 테스트, T19 정본·하네스 기록.
- 명시적으로 제외한 변경: provider SDK·키·모델 연결, handler 연결, 프론트 목→실 전환, DB, 배포·커밋·푸시.
- 구조·계약·의존성 승인이 필요한 지점: 공용 요청/응답 변경, 새 패키지·provider·DB 추가, 프론트 라우팅 변경은 별도 승인과 T20 계획이 필요하다. 실제 시드 이관은 2026-07-20 T16 검수 완료 승인으로 해소됐다.
- 예상 위험과 대응: XML 태그는 완전한 주입 차단이 아니므로 이스케이프·상충 지시·structured output·런타임 검증을 겹치고 보안 완화로만 표현한다. JSON Schema만 믿지 않고 정상 `stop_reason`과 공용 validator를 재검사한다. 시드는 타입·런타임 검증을 거쳐 관계별 두 세트만 노출한다.
