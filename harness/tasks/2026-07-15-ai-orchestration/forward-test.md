## FT-1 — UX·카피 전용 요청

- 요청: S3 `어떤 말투로 보낼까냥?`의 자연스러움을 UX·카피 관점에서 검토안만 작성
- 기대: PM+디자이너만 활성, 프론트·백엔드 비활성, 읽기 전용 표준 인계
- 결과: 통과. 디자이너가 정본·현재 구현을 읽기 전용으로 비교하고 대안·사용자 검증 위험을 인계했다. 변경 경로는 없고, 향후 승인 시 PM 정본 갱신→프론트 단일 소유 순서를 제시했다.

## FT-2 — 프론트·백엔드 교차 수직 작업

- 요청: 확정 계약을 사용하는 교수님 직접입력 폼과 `/api/generate` 연결의 역할·통합 순서 설계
- 기대: 의존성 게이트와 계약 소유자를 먼저 확인하고, 구현 가능할 때만 디자인·프론트·백엔드 역할을 분리
- 결과: 통과. T17·T25 R1·R2 등 선행 게이트 미완료를 확인해 구현 역할을 활성화하지 않았다. 향후 계약 소유자, 디자인 읽기 전용 검토, `api/**` 백엔드 소유, 클라이언트 생성 서비스·MessageFlow 프론트 소유와 통합 검증을 분리했다.
- 부가 발견: 문서가 과거 `src/services/generation/contracts.ts`를 가리키지만 현행 코드는 `src/shared/generation/contracts.ts`를 사용한다. 이번 절차 작업 범위에서는 수정하지 않고 후속 T18 계약 확정 항목으로 인계한다.

## FT-3 — DB migration 전용 요청

- 요청: UI·메시지 생성 계약을 바꾸지 않고 `generation_runs` migration만 추가
- 기대: PM+백엔드/AI만 활성, 디자이너·프론트 비활성, 원문 비저장·migration 검증 포함
- 결과: 통과. T30의 T17·T18 의존 미완료와 Drizzle scaffold/schema 부재를 차단사항으로 반환했다. 허용/금지 컬럼, JSON 자유 payload 금지, DB 제약·migration 재현 검증을 제안하고 파일은 수정하지 않았다.

## 판정과 보정

- 세 테스트 모두 필요한 역할만 선택하고 표준 인계, 기존 diff 보존, 완료 판정 제한을 지켰다.
- 정본 확인 시간이 길어질 수 있어 SKILL에 정확한 구간만 targeted search로 읽도록 보강했다.
- 의존성 미완료 상태에서 계획용 전문 역할까지 불필요하게 실행하지 않도록, 구현 역할 spawn 전 dependency gate를 명시했다.
