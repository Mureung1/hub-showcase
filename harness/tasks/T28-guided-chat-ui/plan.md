## 4. 5요소 계획

| 요소 | 계획 |
| --- | --- |
| 맥락 | React+TypeScript+Vite 가이드형 UI의 자동검증 완료 상태에서 인앱 브라우저로 모바일·접근성 수동 게이트를 닫는다. `any`, 범위 확장, 임의 Playwright 우회를 금지한다. |
| 구체성 | 로컬 Vite 앱을 열어 375×667·320×568의 셸, 헤더, 질문, 선택 카드, 사용자 요약 말풍선, 결과 꾸러미를 검사한다. keyboard와 reduced-motion을 같은 브라우저 표면에서 검증한다. |
| 역할·예시 | PM이 브라우저 검증과 통합을 소유한다. 예: Tab으로 `먼저 연락할래요`에 도달→Enter→`누구에게 먼저 연락하냥?` 제목 초점. 결함 시 디자이너 읽기 전용, 프론트만 해당 경로 수정. |
| 단계화 | ① 하네스·서버 → ② 브라우저 연결 → ③ 375 첫 화면 → ④ 320 흐름·2열 → ⑤ 키보드·초점 → ⑥ reduced-motion → ⑦ 최소 수정·회귀 → ⑧ 완료 기록 |
| 검증 | 각 AC에 viewport·DOM·computed style·스크린샷/관찰값을 연결하고 최종 `npm test`, lint, build, diff를 실행한다. 브라우저 불가 시 T28을 체크하지 않는다. |

## 5. 변경 경계와 위험

- 허용된 변경: 검증 기록, 기존 T28 계약을 충족하기 위한 최소 UI/CSS/테스트 결함 수정, 통과 시 완료 현황·LOG
- 명시적으로 제외한 변경: 새 챗 기능, 새 캐릭터 기능, API/DB, 카피 재설계, 앱 구조·의존성 변경
- 구조·계약·의존성 승인이 필요한 지점: 테스트 중 기존 정본 변경이나 새 라이브러리가 필요하면 중단·제안
- 예상 위험과 대응: Browser runtime이 다시 없을 수 있다. 공식 Browser 연결/복구 절차까지만 시도하고 별도 Playwright로 우회하지 않는다. T29 캐릭터가 레이아웃에 함께 보이므로 Canvas 비차단은 관찰하되 T29 완료 판정은 T31에 유지한다.
