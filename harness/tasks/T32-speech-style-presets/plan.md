## 1. 목표와 완료조건

- 해결할 사용자/제품 문제: 후보의 의미는 맞아도 평소 말끝과 달라 사용자가 다시 써야 하는 문제를 줄인다.
- 목표 결과: 상황 카드와 `직접 설명할게요` 양쪽에서 사용자가 네 말투 중 하나를 명시적으로 고르고, 카드의 결정적 후보와 AI 세 톤 후보에 같은 선택이 일관되게 반영된다.

| ID | 검증 가능한 완료조건 | 검증 방법 | 필수 여부 |
| --- | --- | --- | --- |
| AC-1 | `습니다체 / 요체 / 이다체 / 용용체`의 타입·라벨·예시와 런타임 guard가 존재한다 | 도메인·계약 테스트 | 필수 |
| AC-2 | 네 말투가 네 관계의 카드·직접 설명 경로에 모두 제공된다 | 카탈로그·UI·계약 테스트 | 필수 |

## 2. 의존성·정본 확인

- 의존: T3 생성 계약, T8 직접입력 생성 파이프라인 완료. T25 사람 검수는 미완료지만 사용자가 288문구를 먼저 생성하고 반복 검토하도록 승인했으므로 초안 구현은 진행하고 완료 체크는 보류한다.
- CHECKLIST 직접 참조: T25·T32와 SPEC 1~4장, SCREENS S2-a·S2-b·S3, EDGE_CASES 1-1·1-7.
- 추가 정본: MVP In/Out, AI_DESIGN의 단일 structured output·원문 비저장 경계.
- 변경하지 않는 계약: 카드 즉시 로컬 조회, 후보 3개와 toneLevel, provider/DB 연결, 영구 사용자 프로필, 자유 말투 입력.

## 3. 작업트리 기준선

- 시작 상태: `harness/tasks/T25-situation-card-templates/plan.md`는 이번 사용자 승인 기록으로 수정됨. 평가자 개인정보가 포함될 수 있는 T25 CSV 1개는 미추적 상태이며 읽기 전용·커밋 제외한다.
- 기준선: 1차 T32 구현 뒤 `npm test` 15개 파일 130개 통과. jsdom `scrollTo` 경고는 기존 비차단 경고다.
- PM 소유: 정본 문서, 공유 타입·계약, T32 계획·검증, CHECKLIST, LOG, 최종 통합.
- 제품 디자이너 소유: `src/entities/message/situationTemplates.ts`와 말투별 카드 검토 자료. 288문구는 검수 완료가 아닌 초안으로 작성한다.
- 프론트엔드 소유: `src/features/situation-select/SituationSelect.tsx`, `src/pages/message-flow/MessageFlow.tsx`, `src/app/App.css`, `src/app/App.test.tsx`.
- 백엔드/AI 소유: `api/_lib/prompt/speechStyleRules.ts`, 관련 prompt·handler 테스트. 실 provider·응답 schema는 바꾸지 않는다.

## 4. 5요소 계획

## 5. 변경 경계와 위험

- 허용: 카드 288문구 초안, 양 경로 공통 말투 선택, sessionStorage 상태, 공유 요청·prompt/mock 반영, 검토 자료와 관련 정본·테스트.
- 제외: 런타임 템플릿 말끝 자동 변환, 자유 예시 입력, 로그인·DB·영구 프로필, provider 연결, 새 계측 속성.
- 관계 정책: 사용자 승인에 따라 네 말투를 네 관계에 모두 제공한다. 선택 가능 자체를 관계 적합성 합격으로 간주하지 않으며, 사람 검토에서 부적합 문구를 반복 수정한다.
- 위험: 288문구의 기계적 어미 치환과 관계 부적합을 자동 합격 처리하지 않는다. 정적 초안과 검토표를 함께 두고 T25는 외부 검토 전까지 미완료로 유지한다.
