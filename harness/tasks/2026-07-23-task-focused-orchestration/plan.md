## 1. 목표와 완료조건

- 해결할 문제: 작은 T항목을 에이전트 작업 단위와 동일시하거나 역할별 에이전트를 상시 호출하면 인계·상태 기록·공유 작업트리 충돌 비용이 병렬화 이득을 넘을 수 있다.
- 목표 결과: T항목은 의존성·완료조건 단위로 유지하고, 하나의 사용자 결과를 만드는 실행 묶음 안에서 독립성·계약·쓰기 경로·효율을 통과한 작업만 선택적으로 위임한다.

| ID | 검증 가능한 완료조건 | 검증 방법 | 필수 여부 |
| --- | --- | --- | --- |
| AC-1 | `AGENTS.md`·`CLAUDE.md`와 하네스가 T항목, 실행 묶음, 에이전트 작업, 역할을 구분한다. | 미러 비교·문서 검토 | 필수 |
| AC-2 | 오케스트레이션 스킬이 독립 산출물·고정 계약·비중첩 쓰기·순효율의 네 위임 게이트와 단일 writer 기본값을 강제한다. | 스킬·역할 참조 검토 | 필수 |
| AC-3 | 읽기 중심 병렬화를 우선하고 병렬 writer는 최대 2명, 중첩·공유 계약 편집은 금지하며 PM만 통합·완료 판정한다. | 충돌·순차 작업 시나리오 점검 | 필수 |

| AC-7 | 스킬 형식·UI 메타데이터·로컬 링크·공백이 검증된다. | `quick_validate.py`, 링크·diff 검사 | 필수 |

- 외부 참고: Codex subagent 운영, OpenCode primary/subagent 권한 분리, OpenClaw isolated subagent·제한된 도구 원칙.
