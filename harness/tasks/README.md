# 작업별 기록

이 폴더는 장기 계획과 검증 근거를 저장한다. 기능 완료 현황은 `docs/CHECKLIST.md`, 세션 이력은 `docs/LOG.md`가 계속 정본이며, 여기에는 작업을 재개하거나 독립 검토할 때 필요한 상세 내용만 둔다.

## 경로 규칙

- T항목: `T<번호>-<짧은-이름>/plan.md`, `T<번호>-<짧은-이름>/verification.md`
- 비-T 작업: `YYYY-MM-DD-<짧은-이름>/plan.md`, `YYYY-MM-DD-<짧은-이름>/verification.md`
- 이름은 소문자 영문·숫자·하이픈을 사용한다 (T항목의 `T` 접두사만 대문자).
- 같은 작업을 재개할 때 `v2` 파일을 만들지 않고 기존 파일의 최종 갱신일·진행·검증 내용을 갱신한다.
- 외부 평가자 응답(블라인드 검수지 등)은 배포용 원본을 그대로 두고, 응답을 수정 없이 옮긴 `<검수지 이름>-R<평가자 번호>.md` 사본으로 같은 작업 폴더에 저장한다. 집계·판정은 그 폴더의 `verification.md`에 기록한다.

## 기록 규칙

1. `harness/templates/`의 두 파일을 작업 폴더에 복사한다.
2. 계획 승인 전에는 제품 구현을 시작하지 않는다.
3. 승인된 범위가 달라지면 중단하고 계획에 변경과 재승인을 기록한다.
4. 검증 보고서가 `통과`한 뒤에만 계획을 `종료`하고 CHECKLIST·LOG를 갱신한다.
5. LOG에는 이 폴더의 계획서와 검증 보고서 상대 링크를 남긴다.

별도 인덱스나 상태판은 만들지 않는다. 현재 T 상태는 CHECKLIST에서, 시간순 이력과 비-T 작업은 LOG에서 찾는다.
