# Discussion 1. 프로젝트 방향 변경

## 초기 아이디어

프로젝트 초기에는 AI가 편의점 FF(Fresh Food) 상품의 적정 발주량을 추천하는 서비스를 만드는 것을 목표로 하였다.

하지만 실제 GS25 점포 운영 방식을 확인하면서 이미 GS25 내부에는 자동발주 시스템과 상품별 추천 로직이 존재한다는 점을 확인하였다.

동일한 기능을 다시 구현하는 것은 프로젝트의 차별성이 부족하며, 기존 시스템을 대체하는 것도 현실적인 목표가 아니라고 판단하였다.

## 최종 결정

SmartFF는 자동발주 시스템을 대체하는 서비스가 아니라,

**점주의 최종 발주 의사결정을 지원하는 AI Agent(DSS)** 를 목표로 한다.

AI는 점주의 경험을 대신하는 것이 아니라 판매 데이터와 재고 데이터를 분석하여 더 합리적인 판단을 내릴 수 있도록 지원한다.

---

# Discussion 2. 상품 추천 대신 카테고리별 적정 발주량을 추천

## 초기 아이디어

처음에는 상품별 적정 발주량을 추천하는 서비스를 고려하였다.

## 논의 과정

실제 점포 운영에서는 점주가 먼저 도시락, 삼각김밥, 김밥 등 카테고리별 전체 발주량을 결정한 뒤, GS25 자동발주 결과를 참고하여 어떤 상품을 추가하거나 제외할지를 판단한다.

즉, 점주의 중요한 의사결정은 개별 상품보다 카테고리 단위에서 이루어진다는 점을 확인하였다.

## 최종 결정

SmartFF는 상품 추천이 아니라

**카테고리별 적정 발주량을 제안하는 서비스**로 개발한다.

이를 통해 기존 자동발주 시스템과 역할을 구분하고, 점주의 실제 업무 흐름에도 자연스럽게 적용될 수 있도록 한다.

---

# Discussion 3. 회계적 관점을 포함하기로 결정

프로젝트는 단순히 판매량을 예측하는 서비스가 아니라,

점주의 경영 의사결정을 지원하는 서비스를 목표로 한다.

따라서 추천 결과와 함께

- 재고 부담
- 폐기 위험
- 판매 기회 손실 가능성

등을 함께 제공하여 데이터를 경영적인 관점에서 해석할 수 있도록 한다.

현재 보유한 데이터만으로는 정확한 손실액이나 절감액을 계산하기 어렵기 때문에,

MVP에서는 금액을 단정하기보다 위험도와 의사결정에 필요한 정보를 중심으로 제공하기로 하였다.

---

# Discussion 4. 현재 보유 데이터를 기준으로 MVP 범위 설정

현재 확보한 데이터는 다음과 같다.

- 판매 데이터
- 재고 데이터
- 발주 데이터
- 폐기 데이터

반면 다음 데이터는 확보하지 못하였다.

- 품절 데이터
- 일별 폐기 데이터
- 고객 방문 데이터

따라서 현재 보유한 데이터만으로 구현 가능한 기능을 중심으로 MVP를 설계하기로 하였다.

데이터가 없는 부분은 억지로 예측하기보다 프로젝트 범위에서 제외하거나 향후 고도화 기능으로 남겨두기로 결정하였다.

---

# Discussion 5. MVP에서 제외한 기능

다음 기능들은 프로젝트 범위를 고려하여 MVP에서 제외하였다.

- GS25 내부 시스템(API) 연동
- 자동발주 기능
- 상품별 추천 기능
- 정확한 절감액 계산
- 실시간 발주 시뮬레이션
- POS 실시간 연동

위 기능들은 프로젝트의 완성도를 높일 수 있지만,

4주라는 개발 기간과 현재 확보한 데이터를 고려하여 추후 고도화 기능으로 분류하였다.

---

# Discussion 6. AI의 역할 정의

프로젝트에서 AI는 단순히 숫자를 계산하는 역할이 아니다.

적정 발주량 계산 자체는 규칙 기반 로직과 데이터를 활용하여 수행할 수 있다.

AI는 계산 결과를 점주가 이해하기 쉬운 형태로 설명하고,

왜 이러한 결과가 나왔는지를 자연어로 제공하는 역할을 담당한다.

예를 들어,

- 최근 판매량이 증가한 이유
- 현재 재고 수준이 적절한 이유
- 추천 수량을 제안한 근거

등을 설명하여 점주가 AI의 추천을 신뢰하고 최종 의사결정을 내릴 수 있도록 돕는다.

# Project Principles

SmartFF는 자동발주 시스템을 대체하는 서비스가 아니다.

SmartFF는 판매 데이터와 재고 데이터를 분석하여 점주가 더 나은 발주 의사결정을 할 수 있도록 지원하는 AI Agent를 목표로 한다.

새로운 기능을 추가할 때에는 항상 다음 질문을 기준으로 판단한다.

> **"이 기능이 점주의 의사결정을 더 잘하게 만드는가?"**

이 질문에 대한 답이 "예"인 기능만 프로젝트에 포함한다.
