# Financial 매출원가 추정 로직

> Backend 개발 시 참고용 계산 스펙
>
> 최종 업데이트: 2026-07-10

---

## 문제 정의

Financial 페이지의 "마진액"(매출 − 매출원가)을 계산하려면 **매출원가**가 필요하다. 그러나 raw 데이터에는 매출원가가 직접 존재하지 않는다.

| 파일 | 보유 정보 | 원가 여부 |
|------|----------|-----------|
| `sales_*.xlsx` | 판매수량, 매출액 | ❌ 원가 없음 |
| `waste_*.xlsx` | 원가, 폐기수량, 폐기금액 | ✅ 원가 있음 (폐기된 상품만) |
| `inventory_*.xlsx` | 매가, 재고수량 | ❌ 원가 없음 (매가만) |

**핵심 문제**: `waste` 파일은 **폐기 이력이 있는 상품만** 원가를 기록한다. 폐기가 한 번도 발생하지 않은 상품은 원가를 알 수 없다 → 상품 단위로 정확히 매칭하면 매출원가가 과소 계산된다 (일부 상품 원가 누락).

---

## 계산 로직 (합의된 방식)

개별 상품 매칭 대신, **카테고리 평균 원가율**로 추정한다.

```
1. 폐기 이력이 있는 상품 대상으로 원가율 계산
   원가율 = 원가(waste) ÷ 매가(inventory)   ← 상품코드로 매칭

2. 카테고리별 평균 원가율 산출
   예: 도시락 카테고리 평균 원가율 = 65%

3. 카테고리 총매출원가(추정) = 카테고리 총매출액(sales) × 평균 원가율

4. 마진액 = 총매출액 − 총매출원가(추정)
```

### 장점
- 폐기 이력이 없는 상품도 카테고리 평균으로 원가가 대체되어, 전체 매출에 대해 계산 가능
- 상품 단위 매칭보다 로직이 단순하고 안정적

---

## 가정 및 한계

**가정**: "폐기된 상품들의 원가율이 그 카테고리 전체를 대표한다."

**한계**:
- 폐기가 특정 상품(예: 고가 프리미엄 상품)에서 유독 자주 발생하면, 그 상품들의 원가율이 카테고리 평균보다 높거나 낮게 왜곡될 수 있음
- 폐기 이력 상품 수가 적을수록(표본이 작을수록) 이 편향 위험이 커짐
- MVP 단계에서는 합리적인 근사치로 채택하되, 정밀도가 중요해지면 상품별 원가 마스터 데이터를 별도로 확보하는 것을 고려해야 함

---

## Financial 페이지 표기와의 연결

이 추정 로직으로 계산된 마진액은 Financial 페이지의 **"추정 순이익"** 표기와 동일한 불확실성 범주에 속한다.

```
순이익(추정) = 마진액(추정) − 폐기손실
```

- 마진액 자체가 이미 카테고리 평균 원가율 기반 추정치이므로, 순이익도 자연히 추정치임
- 인건비·전기세·로열티 등 운영비 미포함이라는 기존 한계에 더해, 매출원가 자체도 추정값이라는 점을 추가로 인지해야 함
