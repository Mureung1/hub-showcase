# 구현 검증 (사람 → Codex)

구현된 코드가 설계와 일치하고 하네스를 통과하는지 확인한다. 구현한 Claude Code가 아니라 Codex가 본다.

역할: **Codex가 검증**한다. 만든 AI가 자기 코드를 검증하지 않는다.

---

```
너는 이 프로젝트의 구현 검증 담당이다.
아래 구현이 설계대로인지, 하네스를 통과하는지 확인해줘.

## 확정된 설계
<구현의 기준이 된 설계와 완료 기준을 붙여넣는다>

## 변경 내용
<변경한 파일 목록, 또는 이 브랜치 vs dev diff>

## 검증 항목
1. 설계의 완료 기준을 전부 충족하는가
2. docs/quality/ 의 관련 기준을 통과하는가
   - 실패해야 정상인 케이스가 실제로 실패하는가 (401, 422, RLS 차단)
3. 요청하지 않은 기능이 추가되지 않았는가
4. 도메인 값이 DB 제약과 일치하는가
5. 구현 담당이 설계를 바꿨다면, 변경 사유가 기록되어 있는가

## 판단 기준
- AI의 설명이 아니라 검증 결과로 판단한다. "될 것이다"가 아니라 실제로 되는지 본다.
- 최종 판단은 하네스의 기대 결과와 MVP 범위 기준으로 한다.

## 출력
- 통과 / 실패 항목
- 실패한 경우 무엇이 어떻게 달랐는지 (기대값과 실제값)
- 재검증이 필요한 항목
```

---

## 채우는 요령

- **"실패해야 정상인 케이스"의 통과 여부를 반드시 확인하게 한다.** 성공 케이스만 보면 뚫려 있어도 통과한다.
- 검증에 쓸 스크립트가 있으면 함께 알린다 (`uv run scripts/smoke_api.py`, `verify_supabase.py`).
- 실패 항목은 구현 단계로 되돌아가 고친다.
