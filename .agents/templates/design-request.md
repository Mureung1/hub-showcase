# 설계 요청 (사람 → Codex)

작업을 시작하기 전에 설계를 먼저 확정한다. 이 템플릿을 복사해 빈칸을 채우고 Codex에게 준다.

역할: **Codex가 설계**한다. Claude Code는 다음 단계에서 이 설계를 검증한다. 한 AI에게 설계와 검증을 동시에 맡기지 않는다.

## 작업
<무엇을 만들 것인가. GitHub 이슈 번호가 있으면 적는다>

## 배경 / 참고 문서
- docs/plan/ 의 관련 문서
- docs/DEVELOPMENT.md (아키텍처, API 계약, 키 규칙)
- 관련 DB 테이블과 제약

## 정해야 할 것
- API: 엔드포인트, 요청/응답 스키마, 상태 코드
- DB: 읽고 쓰는 테이블, RLS가 적용되는가
- 화면: 흐름과 상태
- 완료 기준: 무엇이 되면 끝인가 (실패해야 정상인 케이스 포함)

## 제약
- MVP 범위를 넘지 않는다. 요청하지 않은 기능을 추가하지 않는다.
- 도메인 값의 기준은 DB의 check 제약이다. 추측하지 말고 스키마를 확인한다.
- 결정이 필요한 지점은 임의로 정하지 말고 선택지와 트레이드오프를 제시한다.

## 출력
- 설계 요약
- 완료 기준 체크리스트

---

## 채우는 요령

- **"정해야 할 것"에서 해당 없는 항목은 지운다.** 문서 작업이면 API/DB/화면은 뺀다.
- **완료 기준을 반드시 요청한다.** 이것이 다음 단계(구현)가 맞춰야 할 목표가 된다.
- 설계에 빈틈이 있으면 다음 단계인 설계 검증에서 걸러진다.
