# UI 레퍼런스 기반 설계 및 구현

## 목적

제공된 디자인 레퍼런스를 그대로 복제하지 않고,
그 안의 정보 구조, 시각적 위계, 간격, 컴포넌트 패턴과 상호작용 원칙을 분석하여
현재 프로젝트에 맞는 일관된 UI와 UX로 변환한다.

## 작업 전 확인

작업을 시작하기 전에 다음을 확인한다.

1. `AGENTS.md`
2. `docs/plan.md`
3. `docs/project.md`
4. 관련된 기존 페이지와 컴포넌트
5. `frontend/package.json`
6. 제공된 Figma 레퍼런스, 이미지 또는 디자인 문서

레퍼런스가 충분하지 않으면 임의로 특정 디자인을 복제하지 말고,
필요한 화면이나 상태가 무엇인지 먼저 설명한다.

## 레퍼런스 분석

각 레퍼런스에서 다음 항목을 분리해서 분석한다.

- 화면의 주요 목적
- 사용자가 수행하는 핵심 행동
- 정보의 우선순위
- 페이지 레이아웃
- 내비게이션 방식
- 컴포넌트 종류
- 간격과 정렬
- 타이포그래피 위계
- 색상 사용 목적
- 상호작용과 피드백
- 빈 상태, 오류 상태, 로딩 상태
- 모바일과 데스크톱 대응 방식

겉모습만 묘사하지 말고,
각 디자인 선택이 사용자 행동에 어떤 영향을 주는지 설명한다.

## 디자인 변환 원칙

- 레퍼런스를 픽셀 단위로 복제하지 않는다.
- 여러 레퍼런스에서 공통된 좋은 원칙을 추출한다.
- 현재 서비스의 목적과 사용자 흐름을 우선한다.
- 프로젝트의 기존 컴포넌트와 스타일을 가능한 한 재사용한다.
- 디자인의 일관성을 위해 반복되는 수치를 토큰 또는 CSS 변수로 정리한다.
- 장식보다 정보 전달과 행동의 명확성을 우선한다.
- 부동산 정보의 비교와 판단이 쉬워야 한다.
- 중요한 가격, 비용, 이동시간, 위험 정보는 시각적으로 구분한다.
- 추천 결과에는 판단 근거가 함께 보여야 한다.

## 구현 전 산출물

여러 파일을 수정하는 작업이라면 구현 전에 다음을 제시한다.

1. 레퍼런스에서 가져올 원칙
2. 가져오지 않을 요소와 이유
3. 제안하는 화면 구조
4. 필요한 컴포넌트
5. 변경될 파일
6. 반응형 처리 방식

## 구현 규칙

- React 함수형 컴포넌트를 사용한다.
- 현재 프로젝트의 CSS 방식을 유지한다.
- 새 UI 라이브러리를 사용자 허락 없이 설치하지 않는다.
- 재사용 가능한 컴포넌트를 먼저 확인한다.
- 컴포넌트의 역할과 이름을 명확히 한다.
- 단순한 화면을 과도하게 분리하지 않는다.
- 필요한 경우 CSS 변수로 색상, 간격, 반경과 그림자를 관리한다.
- 데스크톱만 구현하지 말고 모바일 레이아웃도 고려한다.

## UX 상태 확인

데이터를 표시하는 화면에서는 가능한 경우 다음 상태를 고려한다.

- 기본 상태
- 로딩 상태
- 데이터 없음
- 오류 상태
- 선택됨
- 비활성화됨
- 긴 텍스트
- 값이 누락된 경우
- 모바일 화면

## 접근성

- 텍스트와 배경의 대비를 확인한다.
- 색상만으로 상태를 전달하지 않는다.
- 버튼과 링크의 역할을 구분한다.
- 클릭 가능한 요소에 키보드 포커스를 제공한다.
- 폼 요소에는 이해할 수 있는 레이블을 제공한다.
- 아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다.
- 사용자 행동에 대한 피드백을 명확히 제공한다.
