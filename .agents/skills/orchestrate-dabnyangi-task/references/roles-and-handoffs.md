# 역할·작업 카드·인계 계약

PM은 전문 역할을 호출하기 전에 이 계약을 작업별 계획으로 구체화한다. 아래 경로는 기본값일 뿐이며 실제 소유권은 매 작업 카드의 정확한 경로 목록이 우선한다.

## 역할 경계

| 역할 | 기본 책임 | 기본 산출물 | 하지 않는 일 |
| --- | --- | --- | --- |
| PM·통합자 | 사용자 의도, 의존성, 승인, 정본, AC, 경로 소유권, 통합·최종 검증 | harness 계획/검증, 공유 계약, CHECKLIST/LOG 판정 | 별도 PM 생성, 근거 없는 완료 선언, 미승인 범위 확장 |
| 제품 디자이너 | 화면 흐름, 정보 위계, 카피, 접근성, 모바일 상태, 시각 검수 | `docs/SCREENS.md`, `docs/DESIGN.md`, `docs/UX.md` 제안 또는 읽기 전용 리뷰 | API/DB 구현, 승인 없는 제품 구조 변경, 장식 목적 기능 추가 |
| 프론트엔드 개발자 | React/TypeScript UI, 클라이언트 상태, 접근성, 컴포넌트·통합 테스트 | 할당된 `src/app`, `src/pages`, `src/features`, 클라이언트 계약 소비부 | 서버 비밀·DB 접근, 공유 계약 임의 변경, 무관 리팩터링 |
| 백엔드·AI 개발자 | 서버 API, DB/migration, provider, 프롬프트·검증기, 개인정보 경계, 서버 테스트 | 할당된 `api`/서버/DB 경로와 관련 테스트 | UI 임의 변경, 브라우저 DB 연결, 원문 저장, 런타임 자율 agent/RAG 추가 |

공유 타입·`docs/SPEC.md`·`docs/AI_DESIGN.md`처럼 양쪽이 소비하는 파일은 PM이 소유하거나 한 명에게만 순차적으로 배정한다.

## 역할 활성화 기준

- PM은 항상 활성화한다.
- 디자이너는 사용자 흐름·카피·접근성·시각 판단이 바뀌거나 실물 리뷰가 필요할 때 활성화한다.
- 프론트엔드는 브라우저 렌더·상태·상호작용·클라이언트 계약이 바뀔 때 활성화한다.
- 백엔드·AI는 서버·DB·provider·프롬프트·운영 메타데이터·보안 경계가 바뀔 때 활성화한다.
- 검토할 산출물이 없는 역할은 호출하지 않는다. 역할 수 자체를 성과로 취급하지 않는다.

## 작업 카드

전문 역할 프롬프트에 아래 필드를 모두 넣는다.

```text
역할:
작업 목표:
승인된 범위:
완료조건:
선행 계약과 읽을 정본:
쓰기 소유 경로:
읽기 전용 경로:
제외 경로·금지 사항:
의존하는 다른 역할 출력:
실행할 검증:
PM에게 돌려줄 인계 형식:
```

쓰기 소유 경로가 비어 있으면 명시적으로 `읽기 전용 검토`라고 적는다. glob처럼 넓은 표현보다 파일 또는 가장 좁은 디렉터리를 적는다.

## 표준 인계

모든 전문 역할은 다음 형식으로 반환한다.

```text
역할:
상태: 완료 | 부분 완료 | 차단
확인한 정본:
변경한 경로:
변경 요약:
실행한 검증과 결과:
발견한 기존 변경·충돌:
남은 위험·수동 확인:
PM 결정이 필요한 항목:
```

읽기 전용 검토는 `변경한 경로: 없음`으로 기록하고 관찰한 근거 위치를 제시한다. 차단 상태는 추측으로 우회하지 않고 필요한 승인·계약·외부 상태를 구체적으로 적는다.

## 충돌 처리

1. 담당 경로에서 예상하지 못한 기존 diff를 발견하면 해당 파일 쓰기를 멈춘다.
2. 다른 역할의 소유 경로가 필요하면 직접 수정하지 말고 PM에게 경로와 이유를 알린다.
3. 공유 계약 변경이 필요하면 의존 구현을 멈추고 PM이 단일 소유자를 지정할 때까지 기다린다.
4. PM은 사용자 작업 보존 여부와 승인 범위를 확인한 뒤 소유권 표를 갱신한다.
5. 계약 갱신 뒤 영향받은 역할만 재실행한다.

## 통합 검토표

| 교차점 | 필수 검토 |
| --- | --- |
| 디자인 ↔ 프론트 | 문구·상태·320/375 모바일·키보드·reduced-motion·색 외 구분 |
| 프론트 ↔ 백엔드 | 요청/응답 타입·상태 코드·오류·재시도·로딩/취소·원문 경계 |
| 백엔드 ↔ AI | structured output·validator·제한 재시도·provider 보존·로그/DB 비저장 |
| 전체 ↔ PM | 승인 범위·AC·실제 diff·테스트·문서 정합성·남은 수동 게이트 |
