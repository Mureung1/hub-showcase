# Git Assistant (자동 커밋/푸시 비서) 지침

이 스킬은 사용자가 Git 커밋 및 푸시 작업을 요청할 때 활성화됩니다. 안전하고 모범적인 실무 Git 워크플로우를 대행합니다.

## 1. 사전 분석 단계 (승인 받기 전)
사용자가 커밋을 요청하면, 터미널 도구(`run_command`)로 `git status`를 실행하여 어떤 파일들이 수정/추가되었는지 파악합니다.

## 2. 분할 커밋 및 브랜치 계획 수립
변경된 파일들의 성격을 분석하여, 하나의 거대한 커밋이 아닌 **의미 있는 논리적 단위(기능, 버그수정, 설정 등)**로 쪼개어 커밋 계획을 세웁니다.
*   **💡 [융통성 조항]**: 문서 수정, 설정 변경, 스킬 추가 등 **규모가 작고 단순한 작업(Chore, Docs)**은 굳이 기능 브랜치를 파지 않고, 현재 브랜치(주로 `develop`)에 다이렉트로 커밋하도록 계획합니다.
*   **기능 브랜치(Feature)**: 코드가 크게 변경되는 핵심 개발 건에 한해서만 영문 브랜치명(예: `feature/post-creation`)을 제안합니다.
*   **커밋 메시지**: Semantic Commit 규약을 따름 (`feat: ...`, `fix: ...`, `chore: ...`, `refactor: ...`)

## 3. 🚨 [매우 중요] 사용자 컨펌 (Approval) 🚨
에이전트는 **절대로 임의로 커밋을 진행해서는 안 됩니다.**
수립한 브랜치명과 각 커밋 메시지 초안을 채팅창에 출력하여 사용자에게 먼저 보여주어야 합니다.
*   "다음과 같이 커밋을 진행할 예정입니다. 메시지를 수정하고 싶으신 부분이 있나요?"라고 반드시 물어봅니다.
*   사용자가 "그대로 해줘" 혹은 수정을 지시하여 최종 승인(Confirm)이 떨어지기 전까지는 `git` 명령어를 실행하지 마세요.

## 4. 실행 및 자동화 워크플로우 (승인 후)
사용자의 승인이 떨어지면, 다음 순서대로 터미널(`run_command`)을 사용하여 순차적으로 명령을 실행합니다.

1.  **기능 브랜치 생성 및 이동**: `git checkout -b <제안한 브랜치명>`
2.  **분할 커밋 진행 (반복)**:
    *   `git add <해당 그룹의 파일들>`
    *   `git commit -m "<승인받은 메시지>"`
3.  **메인 브랜치 병합**:
    *   `git checkout develop`
    *   `git merge <제안한 브랜치명>`
4.  **원격 저장소 전송**:
    *   `git push origin develop`

## 5. 결과 보고
모든 Git 명령어가 성공적으로 실행되었는지 확인하고, 사용자에게 성공적으로 푸시되었음을 간략히 보고합니다. 에러(예: Merge Conflict) 발생 시 즉시 `git merge --abort` 등으로 원상복구 후 사용자에게 보고합니다.
