# 집토끼 기능 개발 워크플로우

## 목적

집토끼 프로젝트에서 복수 파일, 상태 관리, 페이지 전환, 데이터 흐름, UI 구조가 얽힌 기능을 안전하게 개발한다. 서브에이전트는 계획과 검토만 담당하고, 실제 구현과 수정은 메인 에이전트 하나가 수행한다.

## 사용 기준

이 스킬을 사용한다:
- 새 기능이 여러 파일 또는 여러 계층(`pages`, `components`, `hooks`, `utils`, `server`)에 걸친다.
- React state, localStorage, OCR, 분석 API, 페이지 전환, 저장/비교 흐름이 관련된다.
- UI 구조 변경과 디자인 시스템 검토가 필요하다.
- 구현 전 사용자 승인과 구현 후 독립 리뷰가 필요한 작업이다.

이 스킬을 사용하지 않는다:
- 사소한 문구 수정.
- 단일 CSS 값 또는 단일 스타일 수정.
- 한 파일 안에서 끝나는 작은 버그 수정.
- 단순 질문 답변 또는 코드 설명.

## 필수 사전 확인

작업 시작 시 메인 에이전트가 다음을 읽는다:
1. `AGENTS.md`
2. `docs/plan.md`
3. `docs/project.md`
4. 관련 작업이 사용자 정보라면 `docs/flow/user-info.md`
5. UI 작업이면 `docs/design/design-system.md`
6. 관련 `frontend/src` 코드
7. 필요 시 `server/index.js`

문서와 현재 구현이 다르면 임의로 선택하지 말고 차이를 사용자에게 설명한다.

## 워크플로우

1. 요구사항을 요약하고 관련 문서와 코드를 확인한다.
2. `planner` 서브에이전트를 호출해 구현 계획을 받는다.
3. UI 작업이면 구현 전에 `ui_reviewer`에게 계획 또는 예상 UI 구조 검토를 요청한다.
4. 메인 에이전트가 planner와 필요한 UI 사전 검토를 정리해 사용자에게 계획을 제시한다.
5. 사용자 승인을 기다린다.
6. 승인 후 메인 에이전트가 직접 구현한다.
7. 구현 후 `code_reviewer`와, UI 변경이 있으면 `ui_reviewer`를 병렬 호출한다.
8. 모든 서브에이전트가 끝날 때까지 기다린다.
9. 리뷰 결과를 중복 제거하고 심각도순으로 정리한다.
10. 필요한 수정만 메인 에이전트가 수행한다.
11. `frontend/`에서 `npm run lint`와 `npm run build`를 실행한다.
12. 변경 파일, 설계 판단, 검증 결과, 남은 문제를 보고한다.

## 서브에이전트 규칙

- `planner`, `ui_reviewer`, `code_reviewer`는 읽기 전용이다.
- 서브에이전트는 파일을 생성, 수정, 삭제하지 않는다.
- 여러 에이전트가 동시에 코드를 수정하지 않게 한다.
- 실제 구현과 리뷰 반영 수정은 메인 에이전트 하나만 한다.
- 새 라이브러리는 사용자 허락 없이 설치하지 않는다.
- 모델은 임의로 고정하지 않고 부모 세션 설정을 상속한다.

## UI 작업 규칙

- UI 작업에서는 반드시 `docs/design/design-system.md`와 `frontend/src/styles/tokens.css`를 확인한다.
- 기존 `ui-reference-implementation` 스킬은 Figma/이미지 레퍼런스를 실제 화면으로 변환할 때 사용한다.
- 이 스킬의 `ui_reviewer`는 구현 전후 검토 역할만 한다.
- 집토끼 ASCII 브랜드 표현을 추가하거나 수정할 때는 사용자의 핵심 행동을 방해하지 않는지 확인한다.

## 최종 보고 형식

최종 응답에는 다음을 포함한다:
- 변경 파일
- 핵심 설계 판단
- 서브에이전트 리뷰 결과 요약
- 반영한 수정
- `npm run lint` 결과
- `npm run build` 결과
- 남은 문제 또는 후속 작업
