# Generate Tests

## 원칙

- 요구사항과 수용 기준에서 관찰 가능한 동작을 먼저 추출한다.
- 기존 테스트 도구, 파일 배치, 명명 규칙을 재사용한다.
- 테스트를 통과시키기 위해 제품 요구사항을 바꾸지 않는다.
- 한 기능은 가능하면 실패 테스트를 먼저 확인한 뒤 최소 구현으로 통과시킨다.
- 외부 연결이 필요한 검사는 단위 테스트와 분리하고 실행 조건을 명시한다.

## 절차

1. 관련 구현과 기존 테스트를 읽는다.
2. 정상, 경계, 실패, 권한, 오류 응답, 회귀 사례를 분류한다.
3. 가장 낮고 빠른 테스트 계층에서 검증할 수 있는 사례를 우선한다.
4. 파일 위치와 테스트 이름을 포함한 테스트 계획을 제안한다.
5. 승인된 구현 범위에서 테스트를 작성한다.
6. TDD 대상은 새 테스트가 의도한 이유로 실패하는지 먼저 확인한다.
7. 최소 구현 뒤 대상 테스트와 관련 회귀 테스트를 실행한다.
8. 통과, 실패, 미실행 항목과 원인을 보고한다.

## 실행 환경

- `product/`: ESLint와 Vite production build를 사용하고 필요한 화면 동작은 브라우저에서 확인한다.
- `server/`: 기존 Vitest 구성을 사용해 API, 정규화, 조합 규칙을 검증한다.
- `agent/`: 기존 pytest 구성을 사용해 순수 로직은 단위 테스트로, Supabase 연결은 통합 테스트로 분리한다.
- `prototype/`: 정적 HTML/CSS 구조와 시각 결과를 확인한다.

## 승인 경계

- 기본 출력은 테스트 사례와 대상 파일 계획이다.
- 사용자가 테스트 코드 작성을 요청한 경우에만 테스트 파일을 수정한다.
- 테스트에 필요한 제품 변경이 승인 범위를 넓히면 구현 전에 다시 확인한다.

## 출력

- 검증할 요구사항
- 테스트 계층과 대상 파일
- 정상·경계·실패 테스트 목록
- 실행 명령
- 실행 결과
- 미실행 검사와 잔여 위험
