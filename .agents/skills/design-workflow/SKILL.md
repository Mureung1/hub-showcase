# Design Workflow

## 원칙

- 먼저 `AGENTS.md`, `docs/design-concept.md`, `docs/design-tokens.md`와 수정 대상 화면을 읽는다.
- 화면 구성을 바꾸기 전에 저장소 밖에 판단용 HTML 시안을 만든다.
- 사용자가 시안을 승인하기 전에는 제품 화면을 수정하지 않는다.
- 기존 컴포넌트와 디자인 토큰을 우선 재사용한다.
- `prototype/`에서는 JavaScript와 React를 사용하지 않는다.

## 절차

1. 사용자 목표, 대상 화면, 핵심 정보, 성공 조건을 한 문단으로 정리한다.
2. 기존 화면의 정보 위계, 컴포넌트, 색상, 간격, 반응형 규칙을 조사한다.
3. 정상, 로딩, 빈 결과, 오류 상태를 포함한 화면 구조를 제안한다.
4. 저장소 밖의 임시 경로에 HTML/CSS 시안을 만들고 사용자에게 보여준다.
5. 사용자 피드백을 반영해 시안을 수정하고 명시적 승인을 받는다.
6. 승인된 범위만 해당 실행 환경에 구현한다.
7. 실제 화면을 렌더링해 데스크톱과 좁은 화면을 시각적으로 확인한다.
8. 승인된 시안과 구현의 차이, 미확인 상태, 검증 결과를 보고한다.

## 승인 경계

- 시안 제작은 제품 코드 변경을 승인받은 것으로 간주하지 않는다.
- 승인 이후에도 새로운 화면, 기능, 라이브러리 또는 디자인 체계가 필요하면 다시 확인한다.
- 삭제, 이동, 이름 변경은 대상 경로를 확인하고 별도 승인을 받는다.

## 출력

- 디자인 목표와 대상 사용자
- 화면 구조와 주요 상태
- 시안 위치 또는 이미지
- 사용자 피드백과 반영 결정
- 구현 범위
- 시각 검증 결과와 남은 위험
