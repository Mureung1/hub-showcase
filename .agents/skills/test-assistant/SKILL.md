# 🧪 테스트 워크플로우 스킬 (Test Assistant)

이 스킬은 **(1) 테스트 대상 선별 → (2) 테스트 계획 수립 → (3) 테스트 코드 작성 및 실행 검증**의 3단계 프로세스를 체계적으로 수행하여 안정적인 테스트 슈트를 구축합니다.

---

## 📌 3단계 테스트 체계

### Step 1: 테스트 대상 선별 (Target Selection)
프로젝트 내 코드베이스를 분석하여 테스트 우선순위가 높은 대상을 선별합니다.

1. **선별 기준**:
   - **핵심 비즈니스 로직 (Critical Path)**: 회원가입/로그인, 게시글 작성/수정, 결제, 상태 변경 등
   - **유효성 검사 및 필터링 (Validation & Filter)**: 폼 입력값 검사, 태그/검색 조건 필터링 로직
   - **복잡한 상태 관리 (State Management)**: Redux/Zustand/Context, 모달 열림/닫힘, 비동기 상태 변화
   - **외부 API 통신 부 (API & Data Flow)**: fetch/axios 통신, 에러 핸들링, 데이터 파싱
2. **우선순위 산정**:
   - P0 (필수): 결함 발생 시 주요 서비스 이용 불가 (예: 게시글 작성 모달, 로그인 폼)
   - P1 (권장): 사용자 경험 핵심 요소 (예: 카테고리/태그 필터링, 검색)
   - P2 (선택): 단순 UI 렌더링, 헬퍼 유틸 함수

---

### Step 2: 테스트 계획 수립 (Test Planning)
선별된 대상에 대해 **4대 검증 범주**를 기준으로 체계적인 테스트 시나리오를 설계합니다.

1. **정상 동작 (Happy Path)**:
   - 모든 필수 값이 올바르게 입력되었을 때의 정상 동작 및 결과 검증
   - 성공적인 API 호출 및 데이터 업데이트, 성공 콜백 동작
2. **입력 유효성 검사 (Validation & Boundary)**:
   - 필수 입력값 누락(빈 문자열, null, undefined) 시 경고/에러 검증
   - 경계값 테스트 (최대/최소 글자 수 제한, 선택 개수 제한 등)
3. **에러 및 실패 케이스 (Failure Cases & Error Handling)**:
   - 서버 4xx/500 에러, 네트워크 끊김, 예외 발생 시 방어적 처리 및 사용자 알림 검증
4. **상태 변화 및 엣지 케이스 (Edge Cases)**:
   - 초기 비활성 상태, 닫힘/숨김 상태, 중복 클릭(더블 서브밋) 방지 등

---

### Step 3: 테스트 코드 작성 및 검증 (Implementation & Verification)
수립된 테스트 계획에 맞춰 정석 테스트 코드를 작성하고 실제 런타임 검증을 완료합니다.

1. **테스트 환경 설정 확인**:
   - 프론트엔드: Vitest + React Testing Library (jsdom 환경)
   - 백엔드: Jest + Supertest / Node Test Runner
2. **테스트 작성 원칙**:
   - 모킹(Mocking) 명확화: API `fetch`, `window.alert`, `console.error` 등 필요한 사이드이펙트 격리
   - 독립성 확보: `beforeEach(() => { vi.clearAllMocks(); })`로 테스트 간 상호 영향 방지
   - 가독성 높은 시나리오 작성: `describe` - `it` 구조로 의도를 한글로 명확히 서술
3. **런타임 검증 필수 실행**:
   - `npm test` 또는 `npx vitest run <path>` 명령어로 작성된 테스트를 즉시 실행
   - 100% Pass 완료 후 검증 결과를 사용자에게 보고

## 📋 자가 체크리스트 (Checklist)

- [ ] 테스트 대상의 비즈니스 중요도(P0~P2)가 선별되었는가?
- [ ] Happy Path, Validation, Failure Case, Edge Case 4가지 시나리오가 포함되었는가?
- [ ] 사이드이펙트(alert, console, fetch 등)가 적절히 모킹되었는가?
- [ ] 테스트 코드를 작성한 후 실제 실행 명령어를 돌려 Pass 여부를 직접 검증하였는가?
