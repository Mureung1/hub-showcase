# 팀플, 이지! (Team Project, Easy!)

> 대학생 팀 프로젝트의 '킥오프 1시간'을 AI가 중립적 중재자로 대신해, 15분 만에 팀 전원이 납득하는 계획과 역할 분담을 만들어주는 웹 서비스

---

## 📌 프로젝트 개요

대학생 팀 프로젝트는 시작 단계에서 실패합니다. 서로 잘 모르는 팀원들이 위계도 경험도 없이 첫 회의에서 계획과 역할을 정해야 하고, 이 과정이 어색함과 눈치보기 속에 흐지부지되면서 계획 없는 프로젝트와 불공정한 분담이 굳어집니다.

**팀플, 이지!**는 AI를 "관리자"가 아니라 **아무도 하기 싫은 말을 대신 해주는 중립적 중재자**로 세워, 첫 회의 자리에서 계획 수립부터 역할 배정까지 끝내는 킥오프 도구입니다.

상세 기획은 [plan.md](./plan.md)를 참고하세요.

### 현재 상태: v1 프로토타입 완성 → v2 실서비스 전환 개발 중 (2주차 / 4주차)

**v1 (완성)** — 데모용 프로토타입 (화면 5개):

- **프론트 온리**: 백엔드 없이 React + localStorage로 동작
- **목(mock) LLM**: 과제 유형별 사전 제작 응답 + 로딩 연출 (`src/services/mockAi.js`의 함수만 교체하면 실제 LLM API 연동 가능)
- **단일 브라우저 시뮬레이션**: 팀원 설문을 한 화면에서 팀원을 전환하며 제출

**v2 (개발 중)** — React + Express + Supabase(Postgres/Storage) + Claude API 풀스택. 아이디/비밀번호 로그인과 초대 링크로 팀원 각자의 기기에서 사용하는 실서비스 구조로 전환합니다. 확정 설계는 아래 **v2 확정 설계** 섹션과 [plan.md](./plan.md) 참고.

## 🔄 사용자 흐름

### v1 (구현 완료 — 화면 5개)

```
① 프로젝트 생성  →  ② AI 계획 검토  →  ③ 팀원 설문  →  ④ 역할 배정  →  ⑤ 대시보드
   (위저드 3스텝)     (수정·승인)        (비공개 2분)     (AI 설명·스왑)    (칸반·진행률)
```

1. **프로젝트 생성**: 과제 유형(발표/개발/보고서) 카드 선택 → 목표 한 문장·마감일 → 팀원 수(3~8명)·닉네임 입력
2. **AI 계획 검토**: 플래너 에이전트가 마일스톤·태스크를 제안 (목 학사일정 기반 **시험 주간 회피**). 태스크 인라인 수정·삭제·추가 후 "이대로 확정" 또는 "다시 제안받기"
3. **팀원 설문**: 팀원별로 선호 역할 1~3순위(탭 순서로 지정), 기피 역할(최대 1개), 역할 경험, 리더 의향을 제출. 데모용 "랜덤 채우기" 지원, 미제출자는 '상관없음' 처리
4. **역할 배정**: 결정적 로직이 배정하고 AI가 **팀 단위 서술**로 이유를 설명 (개인 응답 비공개 유지). 전원 기피 역할은 타협안(로테이션 등) 제안, 48시간 내 1회 스왑 가능 *(v2에서는 "공개 후 10분 내 1회, 생성자가 맞교환"으로 변경)*
5. **대시보드**: 전체 진행률 + D-day, 3열 고정 칸반(내 태스크 강조), 마일스톤별 진행률. 태스크 상태는 카드의 ‹ › 버튼으로 이동

### v2 확정 흐름 (개발 중)

```
랜딩 → 생성자 가입(아이디+비밀번호) → 위저드(주제 200자·유형 힌트·마감·인원·사진/PDF·기피 기간)
  → AI 계획 검토(태스크·역할 인라인 수정, 다시 제안받기 3회) → "이대로 확정" = 초대 링크 발급
  → 팀원: 링크 접속 → 즉시 가입 + 닉네임 → 설문 (전원 제출 시 자동 마감 / 생성자 수동 마감, n/5 표시)
  → 역할 배정 + AI 설명 → 생성자 "프로젝트 생성 완료" = 결과 공개 (공개 후 10분 내 1회 역할 맞교환)
  → 사이드바 앱: 대시보드(팀 현황) / 프로젝트 진행(내 태스크·파일·링크 업로드·참여 잔디) / 프로젝트 관리(내 프로젝트·[메인]·순서 변경)
```

## 🎯 핵심 설계: 역할 배정 구조

**0단 — 플래너의 역할 정의 생성** (v2, Claude API)

주제·유형 힌트·첨부 파일을 근거로 역할 정의(`{id, name, emoji, min, max}`)를 마일스톤·태스크와 함께 생성합니다. 서버가 '조장' 역할 포함과 "역할별 min 합 ≤ 인원 수 ≤ max 합"을 검증하고, 실패 시 유형별 기본 역할 세트(`src/data/templates.js`)로 폴백합니다.

**1단 — 결정적 점수 매트릭스** (`src/logic/assignRoles.js`, LLM 미사용)

```
점수 = 선호 1순위 +3 / 2순위 +2 / 3순위 +1
     + 경험 있음 +1
     + 기피 역할 -10
     + (조장 한정) 리더 의향 예 +2 / 아니오 -10
→ 역할별 최소/최대 인원 규칙을 지키는 그리디 배정
```

같은 입력이면 항상 같은 결과가 나와 재현성과 공정성이 보장됩니다. 인원 ≠ 역할 수인 경우 1인 다역·다인 1역으로 처리합니다.

**2단 — LLM 설명** (`src/services/mockAi.js`, 현재 목 응답 — v2에서 실제 Claude API로 교체)

배정 결과의 이유를 개인 응답 인용 없이 팀 단위 통계로만 서술하고, 전원 기피 역할이 있으면 타협안을 제안합니다. v2에서는 1단 배정 로직과 통계 계산이 서버로 이동해 설문 비공개가 실제로 보장됩니다.

## 🚀 실행 방법

### 사전 요구사항
- **Node.js** (v18 이상 권장)

### 설치 및 실행

```bash
# 1. 의존성 설치
npm install

# 2. 개발 서버 실행
npm run dev
```

실행 후 브라우저에서 **http://localhost:5173** 으로 접속합니다.

### 기타 명령어

```bash
npm run lint      # 코드 린트 검사
npm run build     # 프로덕션 빌드
npm run preview   # 빌드 결과물 미리보기
```

> **v2 예고**: 백엔드 도입 시 `.env`가 필요합니다 — `ANTHROPIC_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `JWT_SECRET` (`.env.example` 제공 예정).

### 데모 시나리오 (5분)

1. "전공 발표 과제, 마감 4주 뒤, 5명"으로 프로젝트 생성 → AI 계획 생성 확인 (마감일을 10월 말 이후로 잡으면 시험 주간 회피 동작을 볼 수 있음)
2. 태스크 하나를 즉석에서 수정 → "이대로 확정"
3. 팀원 탭을 전환하며 설문 제출 (또는 "랜덤 채우기")
4. 배정 결과 + AI 설명 확인 — 전원이 '발표'를 기피하면 타협안 카드 표시
5. 대시보드에서 태스크 상태 이동 → 진행률 갱신 확인

데이터는 localStorage에 저장되며, 헤더의 "처음부터 다시" 버튼으로 초기화할 수 있습니다.
