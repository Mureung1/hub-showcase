# Newssist 📰

---

## 1. 프로젝트 개요

#### 프로젝트명 : Newssist
: 여러 매체에 흩어진 뉴스를 키워드로 모아보고, AI가 즉시 해설하며, 시사 흐름까지 분석해주는 서비스

---

## 2. 문제 정의 및 차별화

### 문제점
* 면접이나 프로젝트를 위해 시사 흐름을 알고 싶은데 단편적인 뉴스 기사를 찾아보는 것으로는 전체적인 시장 흐름을 파악하기가 힘들다.
* 시사 흐름을 알기 위해 어떤 뉴스를 주기적으로 찾아봐야 할지 모르겠다.
* 뉴스를 읽어보려고 해도 어려운 용어가 너무 많아서 읽는데 시간이 너무 오래 걸리거나 포기하게 된다.

### 기존 서비스와의 차이

| 기능 | 기존 서비스 | Newssist |
|---|---|---|
| 키워드 뉴스 수집 | 네이버 뉴스, Google Alerts | 동일 + AI 해설 결합 |
| AI 해설 | LilysAI (영상 콘텐츠 대상) | 텍스트 뉴스 대상, 난이도 조절 가능 |
| 개인화 분석 | 없음 | 읽은 기사 임베딩 → 클러스터링 → 내가 읽은 기사들을 엮어 시장 흐름을 설명 |

---

### 타겟 페르소나
- **취준생 A**: 면접 전 지원 분야 시사 이슈를 빠르게 훑고 싶음 → 난이도 조절, 트렌드 랭킹, 시사 흐름 분석이 필요
- **직장인 B**: 매일 출퇴근길에 업계 뉴스 확인 → 키워드 피드, 주간 리포트가 중요

## 3. 개발 방향 (스코프 조정 원칙)


| 기능 | README 원안 | 1개월 완성용 조정안 |
|---|---|---|
| 키워드 뉴스 피드(기반) | 실시간 다매체 수집 | NewsAPI + 네이버 뉴스 API, 관심 키워드 5~10개로 제한 |
| 뉴스 요약 난이도 조절 | GPT-4o 실시간 해설, 난이도 조절 | 난이도 3단계(입문/일반/전문가)로 프롬프트 템플릿화 |
| 키워드 트렌드 랭킹 | 실시간 급상승 감지 | 최근 일정 기간 기사 언급량 기준으로 키워드 순위를 매겨 랭킹 리스트로 노출 (네이버 실검/X 트렌드 방식, 차트 불필요) |
| 개인화 분석(임베딩/클러스터링) | 실시간 반영 | **일 1회 배치**로 임베딩·K-Means·UMAP 계산 후, 클러스터별로 GPT가 "이 기사들이 어떤 흐름을 이루는지" 설명 텍스트 생성 + 시각화 |
| 주간 리포트 | 자동 스케줄링 | 주간 읽음 이력 + 클러스터 변화를 GPT 프롬프트에 넣어 리포트 텍스트 생성 (버튼 클릭 트리거) |

## 4. 기능 명세

| 기능 | 입력 | 처리 | 출력 |
|---|---|---|---|
| 키워드 피드(기반) | 관심 키워드 목록 | NewsAPI/네이버뉴스 API 호출 | 기사 카드 리스트 |
| 뉴스 요약 난이도 조절 | 기사 본문 + "요약"/"쉽게 설명" 버튼 | GPT-4o-mini 프롬프트 호출(난이도 파라미터) | 우측 사이드패널에 난이도별 요약 표시 |
| 인터랙티브 용어 해설 | 기사 본문 중 드래그 선택한 단어/구절 | 선택 텍스트+주변 문맥을 GPT-4o-mini에 전달, 1~2문장 정의 요청 | 드래그 위치 근처 툴팁형 용어 설명 |
| 연관 기사 추천 | 오늘 읽은 기사 임베딩 + 과거 읽음 이력 임베딩 | pgvector 코사인 유사도로 상위 N개 검색 → GPT로 연관성 한 줄 설명 생성 | 메인 화면에 연관 기사 카드 + AI 연관성 설명 문구 |
| 트렌드 랭킹 | 키워드 목록 | 최근 기간 언급량(기사 수) 집계 후 순위 정렬 | 순위 리스트(1~10위, 전 순위 대비 등락 표시) |
| 개인화 클러스터링(시장 흐름 설명) | 읽음 이력(기사 ID 로그) | 임베딩(OpenAI) → K-Means → UMAP (일 1회 배치) → 클러스터별 대표 기사/키워드를 GPT에 전달해 흐름 설명 생성 | 2D 좌표 + 클러스터 라벨 + 클러스터별 시장 흐름 설명 텍스트 |
| 주간 리포트 | 주간 읽음 이력 + 클러스터 요약 | GPT 프롬프트 | 리포트 텍스트 |

## 5. 정보구조(IA) / 화면 목록

- 피드 페이지 (홈) — 키워드 필터, 기사 리스트, "오늘 읽은 기사" + 연관 기사 추천 섹션
- 기사 상세 (본문 + 우측 AI 사이드패널) — 드래그 시 용어 툴팁, "요약"/"쉽게 설명" 버튼으로 사이드패널 오픈(난이도 토글)
- 트렌드 페이지 — 키워드 트렌드 랭킹(순위 리스트) → 키워드 클릭 시 관련 기사 그리드
- 인사이트 페이지 — 이슈 흐름 맵(클러스터 시각화 + 클러스터별 시장 흐름 설명), 주간 리포트
- 마이페이지 — 읽은 기사 제목 리스트(날짜순)
- 설정 — 관심 키워드 관리

## 6. 유저 시나리오

**1. 메인 진입 및 기사 열람**<br>
1-1. 사용자가 서비스에 접속해 로그인한다. (최초 로그인 시 관심 키워드 3-5개를 선택하는 온보딩 진행)<br>
1-2. 메인 피드에서 오늘 이슈가 된 기사 목록 중 몇 개를 읽는다.<br>
1-3. 기사 본문에서 모르는 단어나 구절을 드래그하면, 그 위치 근처에 툴팁 형태로 짧은 용어 설명이 즉시 뜬다. (선택한 텍스트 + 주변 문맥을 GPT-4o-mini에 보내 1~2문장 정의를 받아옴)<br>
1-4. 기사 상단(또는 우측)의 "요약" / "쉽게 설명" 버튼을 누르면, 화면 우측에 AI 사이드패널이 열리며 난이도별 설명을 보여준다. (현재 구글 제미나이처럼 본문을 가리지 않고 나란히 노출되는 패널 형태)<br>
1-5. 기사를 다 읽고 메인 화면으로 돌아오면, "오늘 읽은 기사" 영역과 함께 "연관 기사" 섹션이 뜬다. 오늘 읽은 기사의 임베딩과 과거 읽음 이력의 임베딩을 비교해 유사도 높은 기사를 추천하고, 왜 연관되는지 AI가 한 줄로 설명한다. (예: "두 기사 모두 반도체 수출 규제를 다루고 있어요")

**2. 트렌드 랭킹 탐색**<br>
2-1. 메인 화면 한 켠에 실시간 이슈 키워드가 순위 리스트 형태로 노출된다. (네이버 실검/X 트렌드 방식 — 순위 + 전 순위 대비 등락 표시, 차트 아님)<br>
2-2. 리스트에서 특정 키워드를 클릭하면 해당 키워드 관련 기사가 그리드 형태로 펼쳐진다.

**3. 마이페이지**<br>
3-1. 마이페이지에 들어가면 지금까지 읽은 기사가 제목 리스트(날짜순)로 표시된다.<br>
3-2. 마이페이지에서 이슈 흐름 맵(내가 읽은 기사들을 엮은 시장 흐름 설명)과 주간 리포트로 이동하는 진입점을 둔다.

## 7. 기술 스택 및 아키텍처

| 영역 | 최종 선택 | 검토했던 대안 | 선택 이유 |
|---|---|---|---|
| 프론트엔드 | React(CRA, 기 세팅됨) + react-router | Next.js | 이미 세팅된 CRA 유지가 빠름. SSR/SEO가 필요 없는 개인 프로젝트라 마이그레이션 비용이 낭비 |
| 상태관리 | Context + useReducer | Redux, Zustand | 전역으로 공유할 상태가 키워드/읽음이력 정도뿐이라 과설계 방지 |
| 시각화 | **Recharts** (클러스터 맵 산점도 전용) | Visx, Plotly | 클러스터 산점도가 수백~수천 개 포인트 수준(Recharts는 1만개 이하에서 무난)이라 학습곡선 낮은 Recharts로 충분. Visx는 커스터마이징은 좋지만 이 규모엔 과함. ※ 트렌드는 랭킹 리스트 UI로 변경되어 차트 라이브러리 불필요 |
| 백엔드 | Node.js + Express | — | API 키 은닉용 프록시. Supabase 클라이언트와 궁합 좋음 |
| DB/Auth | **Supabase(Postgres) + pgvector 확장** | Firebase, 별도 벡터DB(Pinecone 등) | Supabase 무료 티어는 API 요청 수 제한이 없고 비용이 예측 가능(SQL). pgvector 확장을 켜면 임베딩 유사도 검색(연관 기사 추천)을 별도 벡터DB 없이 SQL 인덱스(ivfflat)로 처리 가능 — 인프라 하나 더 늘리지 않아도 됨 |
| 뉴스 수집 | **네이버 뉴스 검색 API**(주력) | NewsAPI, 빅카인즈 | 네이버 오픈API는 무료, 앱당 일 25,000회 쿼터로 개인 프로젝트엔 충분. 국내 뉴스 커버리지가 핵심이라 네이버가 주력, NewsAPI는 선택적 보조 |
| AI 해설/리포트 | **GPT-4o-mini (OpenAI)** | Gemini 2.5 Flash, Claude Haiku 4.5 | 저트래픽이라 절대 비용 차이는 미미(월 몇 달러 이내) — 그보다 임베딩과 같은 OpenAI 계정/키로 통일되는 편의성을 우선. 품질을 더 높이고 싶으면 Claude Haiku 4.5로 교체 가능(가격은 더 높지만 요약 품질 우수하다는 평가), 비용 최적화가 최우선이면 Gemini 2.5 Flash가 더 저렴 |
| 임베딩 | **OpenAI text-embedding-3-small** | KoSBERT, Qwen3-Embedding | 1536차원, $0.02/1M 토큰으로 매우 저렴하고 한국어 성능도 실사용에 충분. KoSBERT/Qwen3는 로컬 서빙 세팅 부담이 커서 제외 — LLM과 같은 API 키로 관리되는 단순함이 1인 개발엔 더 중요 |
| 클러스터링 | Python(scikit-learn K-Means, umap-learn) | — | 배치 스크립트로 별도 실행 |
| 클러스터링 실행 스케줄 | **GitHub Actions 스케줄 워크플로우**(1일 1회) | Render Cron Job | 완전 무료. 상시 서버를 띄우지 않고 하루 1번만 실행해 임베딩→클러스터링 결과를 Supabase에 직접 저장 |
| 배포(프론트) | Vercel | Netlify | 무료 티어로 충분, CRA 배포 간단 |
| 배포(백엔드) | **Render(Free)** | Railway | Render는 신용카드 없이 진짜 무료 티어 제공(포트폴리오 목적엔 충분). 단점: 15분 미사용 시 슬립 → 재기동 30~50초 걸림(데모 시 감안). Railway는 DX는 좋지만 영구 무료 티어가 없고 월 $5부터 과금 |

```
[React(Vercel)] → [Express API(Render)] → [네이버 뉴스 API / NewsAPI / GPT-4o-mini]
                        ↓
                  [Supabase(Postgres)]
                        ↑
     [GitHub Actions(1일 1회 스케줄): 임베딩(OpenAI) → K-Means/UMAP → Supabase 저장]
```
