# 프로젝트 CJMT — 식단 분석·추천 웹서비스 기획서

> **CJMT** = **C**hungnam **J**ust-eat **M**eal **T**racker
> 눈앞의 메뉴를 찍으면, 내 몸 기준으로 "지금 뭘 더 먹어야 하는지" 알려주는 웹서비스

---

## 1. 문제 발견 (Problem Discovery)

관찰에서 출발한 실제 불편함:

- **대학 식당·주변 식당 메뉴가 영양 정보를 안 알려준다.** 학식판이나 자취 근처 식당엔 칼로리·영양성분표가 없다. "이거 먹으면 오늘 균형이 맞나?"를 알 방법이 없음.
- **매번 직접 칼로리·영양을 계산하는 게 귀찮다.** 기존 식단 앱은 음식을 일일이 검색해서 등록해야 한다. 진입 장벽이 높아서 며칠 쓰다 만다.
- **내 몸에 지금 뭐가 부족한지 몰라서 뭘 먹을지 못 정한다.** 정보를 안다 해도, 그게 "나에게" 부족한 영양소인지 판단이 안 된다.

**핵심 관찰**: 기존 식단 앱은 *기록*은 잘하지만, *"지금 눈앞의 이 메뉴가 나에게 맞는가"* 라는 실시간 판단은 못 해준다.

---

## 2. 문제 정의 (Problem Statement)

> **충남대 자취·기숙사 학생**이 **밖에서 밥을 먹을 때**, 눈앞의 메뉴가 자기 몸에 맞는지·뭐가 부족한지 알 수 없어 **매 끼니 영양 균형을 놓치는** 문제를 겪는다.

- **누가**: 충남대 대덕캠퍼스 자취·기숙사 학생
- **어떤 상황**: 학식·주변 식당에서 끼니를 해결하는 순간 (영양표 없음, 계산 귀찮음)
- **무슨 불편**: 이 메뉴가 나에게 맞는지 모르고, 부족분을 뭘로 채워야 할지 모른다

---

## 3. 사용자·시나리오 (User Scenario)

**페르소나**: 김현빈, 충남대 자취생. 요리는 거의 안 하고 학식·근처 식당·배달로 끼니 해결. 건강은 챙기고 싶지만 영양 계산은 귀찮다.

**시나리오 흐름**:

1. **(최초 1회)** 회원가입 후 신체 정보 입력 — 나이, 키, 몸무게, 성별, 활동량, 기저질환. → 시스템이 나의 하루 권장 영양소량을 계산해둔다.
2. **(점심 때)** 학식 식판을 받고 사진을 찍는다. 메뉴 이름·브랜드를 함께 입력.
3. **(즉시)** AI가 사진을 분석해 메뉴별 영양성분을 뽑아준다. (프랜차이즈면 공식 영양표, 아니면 표준 조리법 기반 추정)
4. **(판단)** "오늘 권장량 대비 단백질 30g, 식이섬유 12g 부족" 처럼 **내 몸 기준 남은 영양소**를 보여준다.
5. **(추천)** 부족한 영양소를 채울 저녁 메뉴를 추천한다. → *(확장)* 반경 3km 내 가게도 함께 추천.
6. **(기록)** 오늘 먹은 기록이 달력에 자동 저장돼, 나중에 언제든 돌아본다.

---

## 4. 핵심 기능 도출 (Feature List)

시나리오를 굴리는 데 필요한 기능:

| # | 기능 | 시나리오 단계 | 비고 |
|---|------|--------------|------|
| F1 | 회원가입 / 로그인 | 1 | ID·PW 방식 |
| F2 | 신체 정보 입력 & 권장 영양소 계산 | 1 | 나이·키·몸무게·기저질환 등 |
| F3 | **사진 → 메뉴 영양분석 (AI 인식)** | 2~3 | 프랜차이즈 영양표 / 표준 조리법 추정 |
| F4 | **내 몸 기준 부족 영양소 계산·추천** | 4~5 | 이 프로젝트의 차별점 |
| F5 | 주변 가게 추천 (네이버 지도 API) | 5 | 반경 3km, 소상공인 우선 |
| F6 | 날짜별 기록 저장 (달력) | 6 | 개인 저장소 연결 |

---

## 5. 우선순위 · MVP (Priority & MVP)

**4주 안에 완성도 있게 보여줄 핵심 2개로 좁힘:**

### 🎯 MVP (반드시 구현)
1. **F3 — 사진 → 메뉴 영양분석 (AI 인식)**
   서비스의 진입점. 이게 안 되면 아무것도 안 굴러감.
2. **F4 — 내 몸 기준 부족 영양소 계산·추천**
   **차별점.** "사진 영양분석"만 하는 앱은 이미 많음(그램, Cal AI 등). "내 몸 기준으로 지금 뭘 더 먹어야 하는지"가 이 서비스의 셀링 포인트.

> F4가 돌아가려면 F1(로그인)·F2(신체정보)가 최소한으로 필요 → MVP에 얇게 포함.

### 🔜 확장 (MVP 성공 후)
- **F5 — 주변 가게 추천 (네이버 지도 API)**: 발표에서 화려하지만, API 연동·소상공인 데이터 확보에 시간이 걸림. MVP 이후.
- **F6 — 달력 기록**: 리텐션용. 핵심 가치 증명 후 추가.

### MVP 한 줄 정의
> **"음식 사진 한 장 → 내 몸 기준 부족 영양소와 보충 메뉴를 알려주는 웹"**
