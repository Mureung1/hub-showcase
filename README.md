# 끼니픽

자취생·1인 가구가 냉장고에 있는 재료로 뭘 해먹을지 고민할 때, 보유 재료로 바로 완성되는 요리와 조금만 더 사면 완성되는 요리를 구분해 추천하고, 부족한 재료는 네이버쇼핑 실시간 최저가 구매 링크로 바로 연결하는 서비스입니다.

냉장고 화면에서 지금 있는 재료를 체크하면 홈 화면에서 "지금 바로 만들 수 있어요" / "재료 조금만 사면 돼요" / "전체 둘러보기(가격순)" 세 섹션으로 나뉜 추천 리스트를 볼 수 있고, 요리를 클릭하면 재료 목록(보유/구매 필요 구분)과 유튜브 임베드 영상, 부족한 재료의 실시간 구매 링크를 확인할 수 있습니다.

## 라이브 데모

- **FE**: https://hub-pyo3.vercel.app
- **BE**: https://hub-20ox.onrender.com (`/health`로 상태 확인 — 무료 플랜 특성상 유휴 시 슬립, 첫 요청은 최대 50초+ 지연될 수 있음)

## 핵심 기능 시연 순서

1. **냉장고 화면**(첫 화면)에서 지금 냉장고에 있는 재료를 체크하고 "완료"
2. **홈 화면**에서 추천 리스트 확인 — 보유 재료만으로 완성되는 요리 / 1~2개만 사면 되는 요리가 구분되어 표시됨 (각 섹션 가격순 정렬, 음식종류·시간 필터로 좁히기 가능)
3. 요리 하나를 클릭해 **레시피 상세**로 이동 — 상단에 트랙 안내, 재료 목록(보유/구매 필요), 총 재료비, 유튜브 영상 인라인 재생
4. "구매 필요" 재료를 클릭해 **네이버쇼핑 실시간 최저가 비교** 패널 확인, 체크박스로 여러 상품을 골라 한 번에 구매 링크 열기
5. (선택) **재료픽**(`/shop`) 탭에서 카테고리별 개별 재료 가격 비교

## 기술 스택

- 프론트엔드: React 19 + Vite + Tailwind CSS v4 + React Router — Vercel에 정적 배포
- 백엔드: Express 5 — Render에 별도 프로세스로 배포 (`server/app.js`가 앱 본체, `scripts/dev-server.js`로 로컬·Render 실행, `api/index.js`는 Vercel 서버리스 진입점으로 남아있으나 이번 배포에서는 사용하지 않음)
- 데이터 저장: Supabase(Postgres) `recipes` 테이블, 프론트는 Express API(`/api/recipes`)를 통해서만 조회
- 구매 연결: 네이버쇼핑 검색 오픈API로 실시간 판매처·가격 조회 (`/api/naver/search`), 묶음상품·대용량 상품 필터링과 단가 계산 포함
- 시세 참고: 공공데이터포털 KAMIS 농산물유통정보 오픈API (농산물 한정, 참고 구매가가 평균 시세보다 싼지 비교하는 용도)

## 실행 방법

```bash
npm install
npm run dev       # 프론트엔드 개발 서버 (Vite, 5173)
npm run dev:api   # 백엔드 Express 로컬 서버 (3001) — 프론트와 함께 별도 터미널로 실행
npm run build     # 프로덕션 빌드
npm run preview   # 빌드 결과 미리보기
npm run lint      # oxlint로 코드 검사
npm test          # Vitest 단위·컴포넌트 테스트
```

## Agent 협업 방식

Claude Code와 페어 프로그래밍 방식으로 개발했습니다. `task-planner` 에이전트로 요구사항을 실행 단위로 쪼개고, `design-system` 스킬로 UI 작업마다 디자인 토큰 일관성을 확인했습니다. 배포 단계에서는 에러 로그·스크린샷을 근거로 원인을 진단받고(예: SPA 라우팅 404, 커밋 이메일 비공개 문제) 수정하는 과정을 반복했습니다.

4주간의 반복 작업 패턴, Agent·Skill 협업 상세, 그리고 매주 겪은 어려움과 해결 과정은 [WORKFLOW.md](./WORKFLOW.md)에 정리했습니다.
