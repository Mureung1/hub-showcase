# 취미·성향 기반 대학생 매칭 플랫폼 — 우리결

학교 인증을 받은 대학생을 위한 **과팅(그룹 매칭) + 룸메이트 매칭** 서비스입니다.
하나의 취미·성향 테스트 엔진을 기반으로 두 가지 매칭 카테고리(과팅 / 룸메이트)를 제공합니다.

---

## 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 서비스명(가칭) | 우리결 |
| 주요 사용자 | 과팅 상대를 찾는 대학생 / 룸메이트를 찾는 대학생 (학교 인증 필수) |
| 구현 목표 | 학교 인증 · 성향 테스트 · 매칭 기능이 실제로 작동하는 웹사이트 |
| 기술 스택 | React (프론트엔드) / Node.js + Express (백엔드) / MySQL (데이터베이스) |
| 개발 형태 | 1인 개발, 4주 개발 계획 |

---

## 해결하려는 문제

- [ ] **과팅**: 같이 나갈 사람이 없거나 이어줄 사람이 없음. 에브리타임 등으로 아무나 만나면 성향이 전혀 다른 사람을 만날 가능성이 있음
- [ ] **룸메이트**: 무작위 배정은 성향 불일치 위험이 크고, 에브리타임에서 성향 맞는 사람을 찾으려 해도 정렬 안 된 사진 게시글을 하나씩 확인해야 해서 불편함

## 서비스 흐름 체크리스트

### 룸메이트 매칭 흐름
- [ ] 가입 · 인증 (학교 인증 + 취미 발견 테스트)
- [ ] 분기 (연애 / 생활 성향 중 생활 성향 선택 → 생활 성향 테스트)
- [ ] 세부 분기 (친구같은 룸메 = 취미+생활 성향 / 비즈니스 룸메 = 생활 성향만)
- [ ] 매칭 · 탐색 (알고리즘 기반 리스트업 → 프로필 확인 → 채팅방 생성)

### 과팅(3대3) 매칭 흐름
- [ ] 개설 (과팅 인원 선택 1:1~3:3 → 연애 성향 테스트)
- [ ] 동성 그룹 매칭 (취미·연애 성향 고려 알고리즘으로 동성 리스트업)
- [ ] 팀 구성 (프로필 확인 → 채팅방 생성 → 팀 확정)
- [ ] 이성 그룹 매칭 (팀 단위 취미+연애 성향 유사도로 상대 팀 매칭)
- [ ] 오프라인 연결 (채팅 → 장소 조율 → 만남 → 애프터) *— MVP 범위 밖*

## 핵심 기능 체크리스트

- [ ] 취미 발견 테스트 (공통 온보딩, 과팅/룸메이트 두 카테고리 모두에 반영)
- [ ] 연애 / 생활 성향 테스트 (카테고리 선택에 따라 분기 진행)
- [ ] 룸메이트 매칭 (생활 성향 단독 또는 취미+생활 성향)
- [ ] 과팅 - 동성 매칭 (취미·연애 성향 고려 알고리즘)
- [ ] 과팅 - 이성 매칭 (팀 단위 취미+연애 성향 유사도 기반)
- [ ] 채팅방 (매칭 성사 후 생성, 폴링 방식 — 당근마켓 형태 참고, 실시간 소켓 아님)

## 4주 개발 로드맵

- [ ] **1주차** — 기획 확정 + 환경 세팅 + DB 설계 + 프로토타입(화면 흐름) 제작
- [ ] **2주차** — 성향 테스트 + 매칭 알고리즘, 프로토타입에 진짜 로직 붙이기
- [ ] **3주차** — 전체 기능 통합 + 테스트 → MVP 완성 + 최종보고서
- [ ] **4주차** — 배포 + 최종 QA + 사업계획서/발표자료 정리

- [ ] 매칭 알고리즘 구현 — 룸메(개인 대 개인) 우선 → 과팅(동성 → 이성) 확장
