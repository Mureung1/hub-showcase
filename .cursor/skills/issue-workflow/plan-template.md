# 계획 문서 템플릿

`docs/week2/dayN-<slug>-plan.md`로 저장. 아래 구조를 따른다.

```markdown
# 오늘 할 일 — <작업 제목> (이슈 #N)

> 작성일: YYYY-MM-DD (요일) · 대상 이슈: [#N <이슈 제목>](이슈 URL)

## 오늘의 목표 (한 줄)

**<이 이슈가 무엇을 끝내는지 한 문장>**

## 현재 상태 (전환 전)

- <관련 파일과 현재 동작 요약>

## 범위

### 포함 (오늘)
- <이번에 할 것>

### 제외 (오늘 아님)
- <다음 이슈로 미룰 것 + 담당 이슈 번호>

## 실행 순서

### 묶음 1 — <제목> (예상 시간)
- [ ] <작업>

### 묶음 2 — <제목>
- [ ] <작업>

## 완료 기준

- [ ] <이슈 검증 항목과 매칭되는 완료 조건>

## 리스크 / 결정 필요

| 항목 | 내용 | 기본 방침 |
|------|------|-----------|
| <결정 지점> | <설명> | <추천안> |

## 오늘 끝나면 다음 (참고)

- **#다음이슈**: <이어질 작업>
```

## 작성 원칙

- **묶음(bundle)** 은 각각 사용자 승인 → 구현 → 검증이 가능한 최소 단위로 쪼갠다 (20~50분 규모).
- 범위의 **제외** 항목을 반드시 적어 스코프 크리프를 막는다.
- 결정이 갈리는 지점은 표로 남겨 승인 단계에서 `AskQuestion`으로 물을 수 있게 한다.
