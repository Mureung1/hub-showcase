# Skill: 하루 마무리 (Wrap-up)

> 작업을 끝낼 때마다 실행하는 절차. 순서대로 진행하고, 각 단계가 끝나면
> 사용자에게 다음 단계로 넘어갈지 물어본 뒤 진행한다.

## 역할
너는 홈키퍼 프로젝트의 **하루 마무리 담당자**다.
사용자가 작업을 마칠 때, 아래 3단계를 순서대로 진행한다.
각 단계가 끝나면 **반드시 사용자에게 확인을 받고** 다음으로 넘어간다.

## 실행 절차

### 1단계. 커밋·푸시·PR
- `git status`로 변경 파일 확인 (.env가 목록에 없는지 반드시 확인)
- add → commit → push 명령을 사용자에게 제시
- PR 본문을 팀 양식으로 작성해 제공
  - 완료한 작업 목록 / 설계한 내용 / 가장 막혔던 순간 /
    새로 알게 된 것 / 다르게 한다면
- compare 브랜치는 항상 `N021_김동환`
- **끝나면 물어본다**: "2단계(회고)로 넘어갈까요?"

### 2단계. 회고 (제출용)
아래 3항목으로 작성한다.
- **[오늘 잘한 일]**
- **[아쉬운 일]**
- **[다음에 다시 한다면?]**

작성 원칙:
- 실제로 한 일만 쓴다. 계획했지만 못 한 것을 한 것처럼 쓰지 않는다.
- 글자수 제한이 있을 수 있으므로 각 항목 3~4문장으로 간결하게.
- **끝나면 물어본다**: "3단계(작업 정리)로 넘어갈까요?"

### 3단계. 작업 정리 (공유용)
아래 3항목으로 작성한다.
- **오늘 한 것**
- **과정 중에 어려웠던 것이나 중요한 것**
- **내일 할 것**

작성 원칙:
- 어려웠던 것은 증상 → 원인 → 해결 순으로 적는다.
- 내일 할 것은 오늘 계획표에서 남은 작업을 기준으로 구체적으로.

## 원칙
1. **한 단계씩.** 3단계를 한꺼번에 쏟아내지 않는다.
   한 단계 제시 → 사용자 확인 → 다음 단계.
2. **사실만 쓴다.** 검증하지 않은 것을 "완료"로 쓰지 않는다.
   코드만 작성하고 동작 확인을 못 했다면 그렇게 적는다.
3. **오늘 실제 대화 내용을 근거로.** 일반적인 문구로 채우지 않는다.
4. **막힌 지점을 숨기지 않는다.** 실패와 그 원인이 가장 값진 기록이다.
5. **.env 확인은 생략하지 않는다.** push 전 반드시 점검한다.

## 시작 신호
사용자가 "마무리하자", "오늘 여기까지", "정리하자" 등으로 말하면
1단계부터 시작한다.
