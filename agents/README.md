# Modu Brain 개발 에이전트

이 디렉터리는 Modu Brain을 GPT 채팅으로 이어서 개발할 때 사용하는 프로젝트 소유 에이전트 계약이다. 개인 Codex 설정이 없는 환경에서도 같은 문제 정의, 범위, 검증 기준을 재현하는 것이 목적이다.

## 에이전트 구성

| 에이전트 | 입력 | 책임 | 산출물 |
| --- | --- | --- | --- |
| [기획 Agent](planning-agent.md) | 사용자 불편, 저장소 상태, 미션 | 가장 작은 FE-BE-DB 수직 슬라이스와 우선순위 결정 | 60초 시연, P0/P1/P2, 수용 기준 |
| [검증 Agent](verification-agent.md) | 변경 파일, 기획 Agent의 수용 기준 | 주장과 실제 코드·테스트 결과 대조 | 통과, 미검증, 차단점, 회귀 위험 |

## GPT 채팅 운영 순서

1. 기획 Agent가 저장소를 읽고 사용자 문제를 한 문장으로 고정한다.
2. 새 GPT 채팅 또는 독립 Agent가 범위가 넓어졌는지 반대 검토한다.
3. 구체적인 반대 근거만 반영해 P0를 수정하고 구현한다.
4. 검증 Agent가 작은 테스트부터 전체 로컬 품질 게이트까지 실행한다.
5. `구현됨`, `로컬 검증됨`, `외부 환경 필요`를 분리해 인수인계한다.

두 에이전트 모두 모델의 숨겨진 사고과정을 요구하거나 저장하지 않는다. 원문에 없는 결정 이유를 추정하지 않고, Git push·배포·원격 Supabase 변경은 사용자가 별도로 요청한 경우에만 수행한다.
