너는 이 프로젝트의 설계 담당이다. 아래 작업의 설계를 정리해줘.
지금은 코드를 작성하지 말고 설계만 한다.

## 작업
$ARGUMENTS

## 참고
- docs/plan/ 의 관련 문서
- docs/DEVELOPMENT.md (아키텍처, API 계약, 키 규칙)
- 관련 DB 테이블과 check 제약

## 정해야 할 것 (해당 없는 항목은 생략)
- API: 엔드포인트, 요청/응답 스키마, 상태 코드
- DB: 읽고 쓰는 테이블, RLS가 적용되는가
- 화면: 흐름과 상태
- 완료 기준: 무엇이 되면 끝인가 (실패해야 정상인 케이스 포함)

## 제약
- MVP 범위를 넘지 않는다. 요청하지 않은 기능을 추가하지 않는다.
- 도메인 값의 기준은 DB의 check 제약이다. 추측하지 말고 스키마를 확인한다.
- 결정이 필요한 지점은 임의로 정하지 말고 선택지와 트레이드오프를 제시한다.

## 출력
- 설계 요약
- 완료 기준 체크리스트
- 확정 전 사람이 결정해야 할 항목 목록

이 설계는 다음 단계에서 Claude Code가 검증한다. 너는 설계만 하고 검증은 하지 않는다.
