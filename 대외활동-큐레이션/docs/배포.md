# 배포 (Vercel)

이 앱은 두 조각으로 Vercel에 올라간다.

- **정적 프론트**: `vite build` 결과물 `dist/`. Vercel이 Vite를 자동 인식해 그대로 서빙한다.
- **서버리스 함수**: 루트 `api/recommend.js`. 배포하면 `https://<도메인>/api/recommend`로 자동으로 뜬다.
  자연어 추천의 Gemini 호출을 이 함수가 대신 한다(키를 브라우저에 안 내보내려고).

프론트는 로컬 개발이면 `http://localhost:8787`(server/api-server.js), 배포면 같은 도메인 `/api/recommend`를
자동으로 부른다(src/recommendClient.js, `import.meta.env.DEV`로 구분).

## 환경변수

Vercel 프로젝트 Settings > Environment Variables에 아래를 넣는다. **VITE_ 접두사 유무가 핵심이다.**
VITE_는 빌드 때 번들에 박혀 브라우저에 공개되니 공개해도 되는 값만, 나머지는 서버(함수)에서만 읽혀 안전하다.

| 이름 | 값 | 쓰는 곳 | 공개 여부 |
|---|---|---|---|
| `GEMINI_API_KEY` | Gemini 키 | 함수 | 비밀(서버에서만) |
| `SUPABASE_URL` | Supabase 프로젝트 URL | 함수 | 비밀 취급 |
| `SUPABASE_SERVICE_KEY` | Supabase service_role 키 | 함수 | **절대 비밀** |
| `VITE_SUPABASE_URL` | 같은 Supabase URL | 프론트 빌드 | 공개됨 |
| `VITE_SUPABASE_ANON_KEY` | Supabase anon 키 | 프론트 빌드 | 공개돼도 안전(anon) |

`.env`와 `server/.env`는 gitignore라 배포에 안 실린다. 값은 위 대시보드에만 넣는다.

## 올리는 순서 (대시보드)

1. 저장소를 GitHub에 push(이미 jaeho9338-code/activity-curation).
2. vercel.com > Add New Project > 이 저장소 Import.
3. Framework는 Vite로 자동 인식(Build `vite build`, Output `dist`). 손댈 것 없음.
4. 위 환경변수 5개 등록.
5. Deploy. `dist/`와 `api/recommend`가 같이 올라간다.

CLI로 하려면: `npm i -g vercel` > `vercel`(링크) > 환경변수 등록 > `vercel --prod`.

## 확인

- 배포된 주소 열기 > "AI에게 물어보기"에 문장 넣고 추천이 뜨는지.
- 브라우저 개발자도구 Network에서 `/api/recommend`가 200인지.
- 페이지 소스에 Gemini/서비스 키가 안 보이는지(함수에만 있어야 함).

## 함수가 느리면

추천은 Gemini 2콜 + Supabase 전체 스캔이라 보통 5초 안쪽이다. 혹시 10초를 넘겨 타임아웃이 나면
`api/recommend.js` 맨 위에 `export const maxDuration = 30;` 한 줄을 더한다(Vercel 함수 제한시간 연장).
