# 개발 백로그 (작업 목록)

앞으로 할 일을 우선순위 순으로 쌓아둔 목록이다. 주차마다 위에서부터 꺼내 그 주에 끝낸다.
상황이 바뀌면 순서를 다시 매기고, 못 끝낸 건 다음 주로 넘긴다. 설계 단일 소스는 docs/schema.md,
수집 세부는 docs/데이터-수집.md, 전체 맥락은 CLAUDE.md.

## 우선순위

- P0 필수: 없으면 서비스가 성립하지 않는다. 먼저 한다.
- P1 중요: 신뢰와 완성도. P0 다음에 한다.
- P2 나중: 여유되면 한다.

## 4주 로드맵

| 주차 | 목표 |
|---|---|
| 1주차 (이번 주) | 기획, 설계, 디자인, 개발 환경 (완료) |
| 2주차 | 데이터가 실제로 들어오게 (수집, 파싱, 저장) |
| 3주차 | 사용자가 보게 (배치, 조회 API, 화면, 매칭) |
| 4주차 | 믿을 수 있게 (정확도, 상세 근거, 다듬기, 배포) |

**다음 주(2주차)까지 반드시 끝낼 것**: 한 소스에서 공고를 실제로 긁어와 원문을 저장하고, LLM으로 조건을 뽑아 완성본 DB에 넣는 데까지. 화면은 아직 없어도 데이터는 파이프라인을 실제로 통과한 상태로 만든다.

## 2주차 - 데이터가 들어오게

- [ ] (P0) 준비: npm install, server/.env 채우기(Supabase, OpenAI 키), Supabase 프로젝트 생성
- [ ] (P0) 테이블 생성 (schema.md 부록1: profiles, sources, raw_postings, postings, parse_logs)
- [ ] (P0) 수집기: 목록에서 공고 기본정보 모으고, 상세에서 원문 가져오기 (데이터-수집.md)
- [ ] (P0) 원문 raw 저장 (source_url 유일 키로 중복 방지)
- [ ] (P0) LLM 파싱: 분류와 추출, 근거 문장과 신뢰도, 넓은 표현 펼치기 (schema.md 프롬프트)
- [ ] (P0) 완성본 저장, 실패와 저신뢰는 needs_review로 격리 (parse_logs 기록)
- [ ] (P1) 예의: 요청 사이 간격, User-Agent 명시

## 3주차 - 사용자가 보게

- [ ] (P0) 새벽 배치로 수집 -> 파싱 -> 저장 한 번에 연결 (중복은 source_url로 덮어쓰기)
- [ ] (P1) 깨짐 감지 (0건이거나 빈 필드 급증하면 알림)
- [ ] (P0) 조회 API: GET /postings, 프로필로 가능/불가/확인 필요 분류 + 페이지 (schema.md 핵심 규칙)
- [ ] (P0) 조건 입력 화면 (학년, 전공 8, 지역 13, 나이, 재학상태, 장학 토글로 소득과 학점)
- [ ] (P0) 결과 화면: 가능, 확인 필요, 거의 가능(조건 1개 차이), API 연결 (design/시안 기준)
- [ ] (P1) 불가 사유 자리에서 프로필 수정하면 즉시 재매칭
