# Pick My Clothes 개발 Task 문서

## 1. 백로그란?

백로그(Backlog)는 프로젝트를 완성하기 위해 앞으로 해야 할 작업 목록이다.  
단순한 할 일 목록이 아니라, 기능 개발·디자인 개선·버그 수정·문서 작성 등 프로젝트에 필요한 모든 작업을 우선순위와 함께 관리하는 문서이다.

백로그가 필요한 이유는 개발 중 방향이 흔들리지 않도록 하기 위해서이다.  
특히 AI Agent를 활용해 개발할 때는 무엇을 만들지 명확하지 않으면 Agent가 불필요한 기능을 만들거나 프로젝트 방향과 다른 결과물을 생성할 수 있다.  
따라서 백로그를 통해 핵심 기능을 먼저 정리하고, 어떤 작업을 언제 진행할지 미리 계획하는 것이 중요하다.

---

## 2. 프로젝트 개요

프로젝트명: Pick My Clothes

Pick My Clothes는 사용자의 날씨, 장소, 상황, 선호 스타일을 바탕으로 AI Agent가 오늘의 코디를 추천해주는 웹 서비스이다.  
프로젝트 컨셉은 “나의 코디 다이어리”이며, 사용자가 하루의 코디를 일기처럼 기록하고 저장하는 감성적인 경험을 제공하는 것을 목표로 한다.

---

## 3. 개발 우선순위 기준

### P0: 반드시 구현해야 하는 핵심 기능
서비스의 기본 흐름을 구성하는 기능이다.  
이 기능이 없으면 프로젝트의 핵심 가치가 드러나지 않는다.

### P1: 중요하지만 P0 이후 구현할 기능
서비스 완성도를 높이는 기능이다.  
핵심 기능 구현 후 추가한다.

### P2: 시간이 남으면 구현할 기능
부가 기능 또는 고도화 기능이다.  
프로젝트 완성 이후 여유가 있을 때 진행한다.

---

## 4. 핵심 사용자 흐름

1. 사용자가 메인 화면에 접속한다.
2. 사용자는 코디 추천을 시작한다.
3. 날씨, 장소, 상황, 선호 스타일을 선택하거나 입력한다.
4. AI Agent가 입력된 조건을 바탕으로 코디를 추천한다.
5. 사용자는 추천 결과와 추천 이유를 확인한다.
6. 마음에 드는 코디를 저장한다.
7. 추후 저장한 코디를 다시 확인할 수 있다.

# 9. 코드 컨벤션

프로젝트의 일관성과 가독성을 높이기 위해 아래와 같은 코드 작성 규칙을 적용한다.

## 9.1 파일명 규칙

React 컴포넌트 파일은 **PascalCase**를 사용한다.

예시

- HomePage.tsx
- RecommendPage.tsx
- ResultPage.tsx
- DiaryPage.tsx

CSS 파일은 컴포넌트 이름과 동일하게 작성한다.

예시

- HomePage.css
- RecommendPage.css

---

## 9.2 변수명 규칙

변수명은 **camelCase**를 사용한다.

예시

```tsx
const selectedWeather
const selectedPlace
const selectedSituation
const recommendedOutfit
const userCloset
```

---

## 9.3 함수명 규칙

함수명은 동작이 명확하게 드러나도록 작성한다.

예시

```tsx
handleSelectWeather()

handleRecommend()

saveOutfit()

fetchRecommendation()

uploadClosetImage()
```

---

## 9.4 컴포넌트 작성 규칙

- 하나의 컴포넌트는 하나의 역할만 담당한다.
- 재사용 가능한 컴포넌트로 분리한다.
- 코드 중복을 최소화한다.
- Props를 활용하여 필요한 데이터를 전달한다.

---

## 9.5 CSS 작성 규칙

- 클래스명은 의미 있는 이름을 사용한다.
- 공통 스타일은 재사용한다.
- 디자인 시스템을 유지한다.
- 지나치게 긴 CSS 작성은 지양한다.

예시

```css
.recommend-button

.outfit-card

.diary-page

.weather-chip
```

---

## 9.6 Git 브랜치 규칙

개발은 개인 브랜치에서 진행한다.

예시

```
N013_김경민
```

작업 완료 후 Pull Request를 생성한다.

# 10. 커밋 로그 규칙

커밋 메시지는 작업 내용을 쉽게 파악할 수 있도록 아래 규칙을 따른다.

| 태그 | 의미 | 예시 |
|------|------|------|
| feat | 새로운 기능 추가 | feat: 코디 추천 화면 구현 |

| style | UI 및 CSS 수정 | style: 버튼 디자인 개선 |
| docs | 문서 수정 | docs: Task 문서 작성 |
| refactor | 코드 구조 개선 | refactor: Recommend 컴포넌트 분리 |
| chore | 환경 설정 | chore: React 개발 환경 구성 |

# 11. 개발 중 관리 방법

개발 과정에서 프로젝트를 효율적으로 관리하기 위해 다음과 같은 원칙을 따른다.

- 우선순위가 높은 Task(P0)부터 구현한다.
- 하루 개발 목표를 미리 정하고 작업한다.
- 기능 단위로 Commit을 진행한다.
- 구현이 완료되면 Pull Request를 생성한다.
- 그룹원 및 마스터 피드백을 적극적으로 반영한다.
- 새로운 기능을 추가하기 전 기존 코드 구조를 먼저 확인한다.
- 문제가 발생하면 원인을 먼저 분석하고 해결 과정을 기록한다.
- AI Agent를 사용할 때에는 CLAUDE.md와 Design Skill을 참고하여 일관된 결과를 유지한다.

이번 주에는 Google Stitch를 활용한 UI 디자인, React와 Express 개발 환경 구성, GitHub Pages 배포 등 처음 경험하는 기술을 많이 접할 수 있었다. 개발 환경을 구축하는 과정에서 여러 오류를 해결하며 문제 해결 능력의 중요성을 느꼈고, AI Agent를 적극적으로 활용하여 시행착오를 줄일 수 있었다.

다음 주에는 환경 설정에 머무르지 않고 실제 기능 구현에 집중하여 프로젝트의 핵심 기능을 하나씩 완성해 나갈 계획이다. 또한 React의 상태 관리와 Express 서버의 동작 방식을 더욱 깊이 이해하여 보다 안정적인 서비스를 개발하는 것을 목표로 한다.
