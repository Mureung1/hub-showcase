# Planning Agent Skill

## Overview (개요)
이 스킬은 복잡하고 모호한 제품 기획서 및 개발 요구사항을 분석하여, 개발자가 단계별로 신속하게 구현 및 검증할 수 있도록 최소 기능 단위(Vertical Slice 등)로 쪼개고 우선순위를 부여하여 체계적인 작업 계획(GitHub Issues)을 설계하는 역할을 정의합니다.

## When to Use (사용 시점)
- 새로운 기능 구현이나 프로젝트 스프린트를 시작하기 전, 구체적인 작업 순서가 모호할 때.
- 큰 볼륨의 비즈니스 로직을 프론트엔드(FE), 백엔드(BE), 데이터베이스(DB)가 한 흐름으로 이어지는 수직 슬라이스(Vertical Slice) 형태로 세분화하고 싶을 때.
- 깃허브 이슈(GitHub Issues)에 작업 백로그와 검증 체크리스트를 등록하고자 할 때.

## Process (수행 절차)

### 1단계: 명세 분석 및 데이터 흐름 도출
- 전달된 기획서의 핵심 사용자 시나리오(예: "사용자가 버튼을 클릭하면 실시간 반영된다")를 읽고 필요한 데이터(FE State, API Request Payload, DB Table Schema)를 식별합니다.

### 2단계: 수직 슬라이스(Vertical Slice) 식별
- 기획 전체를 프론트엔드 따로, 백엔드 따로 완성하는 수평적 구현 대신, **"FE 컴포넌트 ➡️ API 통신 ➡️ DB 쿼리 및 저장 ➡️ 결과 리턴 및 FE 상태 갱신"**의 단일 루프가 처음부터 끝까지 연결되는 최소 기능 단위를 식별합니다.

### 3단계: 작업 세분화 및 우선순위(Priority) 지정
- 식별된 요소들을 기준으로 작업을 세분화하고 다음과 같이 분류합니다:
  - **P0 (Essential Core)**: 수직 슬라이스의 동작을 보장하는 기초 설계, DB 설정 및 필수 API/화면 연동.
  - **P1 (Graceful UX & Security)**: 예외 처리, 보안 제한(Rate Limit), 데드라인 검증 로직, August* 디자인 가이드 적용 및 다이내믹 피드백.
  - **P2 (Nice-to-Have)**: 부가 기능, 어드민 시뮬레이션 개선, 로컬 캐싱 등.

### 4단계: 이슈 템플릿(Issue Template) 설계
- 각 작업별로 GitHub Issues에 바로 기재할 수 있도록 다음 양식을 충족하여 산출합니다:
  - **제목**: `[우선순위] 작업 요약` (예: `[P0] [Vertical Slice] 투표 생성 API 개발 및 DB 연동`)
  - **설명**: 작업의 배경 목적과 기대 결과.
  - **체크리스트(TODO)**: 진행도를 쪼개어 체크할 수 있는 체크박스(`- [ ]`).

## Common Rationalizations (흔한 합리화)
- *"작업이 사소하니 계획서 없이 그냥 바로 코딩부터 하자"* ➡️ **오류**. 사소한 기능이라도 FE, BE, DB의 데이터 정합성을 일치시키지 않으면 디버깅에 더 오랜 시간이 걸립니다.
- *"프론트엔드 디자인 마감부터 먼저 완벽히 하고 백엔드를 만들자"* ➡️ **오류**. 화면만 아름답고 서버와 연동되지 않는다면 수직 슬라이스 검증이 불가능합니다. 항상 Mock 데이터를 이용해 화면 흐름을 먼저 확인하되 백엔드 API 연동을 병행하여 쪼갭니다.

## Red Flags (금지 사항)
- 구체적인 인수 조건(Acceptance Criteria)이나 할 일(TODO) 목록 없이 뭉뚱그려 "대시보드 개발하기" 처럼 포괄적으로만 작성하는 행위.
- DB 연결 설정이나 API 주소 정의 없이 코드 작성 단계로 그냥 넘어가는 행위.

## Verification (검증 방법)
- [ ] 쪼개진 태스크 간에 종속 관계(Dependency)가 선후 관계로 명확히 정의되어 있는가?
- [ ] 각 태스크 카드가 하나의 명확한 목표만을 설명하며, 검증 가능한 TODO 항목을 3개 이상 포함하는가?
- [ ] P0로 정의된 태스크들만 완수했을 때도 핵심 기능의 기본 사이클이 1회 완벽히 동작하는가?
