# 동네병원 원격 웨이팅 정적 프로토타입

초기 비회원·수동 방문 요청 흐름을 검증했던 순수 HTML/CSS 프로토타입입니다. JavaScript, 프레임워크, 외부 CDN, API를 사용하지 않습니다.

현재 기획은 회원가입·로그인, 자동 6번째 준비 알림과 4번째 입장 요청, 현장 환자 상태 링크로 변경되었습니다. 따라서 이 프로토타입은 시각적 참고 자료이며 현재 [`docs/plan.md`](../docs/plan.md)와 [`docs/ux-structure.md`](../docs/ux-structure.md)의 확정 흐름과 일치하지 않습니다.

## 실행

웹 서버 없이 [`index.html`](./index.html)을 브라우저에서 직접 열면 됩니다.

## 화면

| 파일 | 역할 |
| --- | --- |
| `index.html` | 환자의 가족 단위 원격 웨이팅 등록 |
| `waiting.html` | 환자의 순번·예상 시간·상태 확인 |
| `staff.html` | 병원 직원의 원격·현장 통합 대기열 관리 |
| `onsite.html` | 병원 직원의 현장 환자 등록 |

## 기존 데모 흐름

1. `index.html`에서 대표자 정보와 가족 인원을 입력하고 원격 웨이팅을 등록합니다.
2. `waiting.html` 상단에서 환자에게 보이는 상태 변화를 확인합니다.
3. `staff.html`에서 13번의 `방문 요청 → 도착 확인 → 접수 완료 → 진료실 호출`을 순서대로 선택합니다.
4. 각 단계의 `환자 화면` 링크로 병원 조작이 환자에게 어떻게 보이는지 확인합니다.
5. `onsite.html`에서 현장 환자를 등록하고 같은 통합 대기열에 추가되는 화면을 확인합니다.

## 정적 프로토타입의 한계

- 폼 입력값과 상태 변경은 저장되지 않습니다.
- 환자 화면과 직원 화면은 실제로 동기화되지 않으며 미리 준비된 상태로 이동합니다.
- 예상 시간과 접수번호는 Mock 데이터입니다.
- 실제 알림톡, SMS, 휴대전화 인증, 병원 전산 API를 사용하지 않습니다.
- 환자 회원가입·로그인과 계정당 활성 웨이팅 제한이 없습니다.
- 자동 알림 기준과 현장 환자 상태 조회 링크가 반영되지 않았습니다.
- 병원 입점 신청과 mock 승인 화면이 없습니다.
