# PlaceSync 정적 프로토타입

`docs/plan.md`, `docs/feature-spec.md`, `docs/checklist.md`에 정리된 핵심 흐름을
**순수 HTML/CSS**만으로 검증하기 위한 화면 프로토타입입니다.
JavaScript, 프레임워크, 외부 CDN을 사용하지 않았습니다.

## 실행 방법

1. 이 저장소를 내려받거나 클론합니다.
2. `prototype/index.html` 파일을 웹 브라우저로 직접 엽니다. (더블클릭 또는 브라우저의 "파일 열기")
3. 별도의 설치, 빌드, 서버 실행이 필요하지 않습니다.

## 화면 구성 및 흐름

```
index.html (대시보드)
  → edit.html (통합 정보 편집)
    → preview.html (플랫폼별 적용값 미리보기 · 승인)
      → result.html (업데이트 결과)
        → manual.html (배달앱 수동 수정 안내)
          → index.html / result.html 로 복귀
```

| 파일 | 화면 | 설명 |
|---|---|---|
| `index.html` | 대시보드 | 플랫폼 연결 상태, 매장 정보 요약, 불일치 알림 확인 |
| `edit.html` | 통합 정보 편집 | 영업정보·메뉴·가격·노출 정책·공지를 한 번에 수정 |
| `preview.html` | 적용값 미리보기 | 플랫폼별로 실제 반영될 값을 미리 확인하고 최종 승인 |
| `result.html` | 업데이트 결과 | 플랫폼별 성공/검토 중/실패 상태 확인 |
| `manual.html` | 수동 수정 안내 | 자동 반영이 실패한 플랫폼의 수정 내용을 복사해 지원 |

모든 화면은 `styles.css` 하나를 공유하며, 좌측 사이드바(모바일은 상단 메뉴)로
언제든 대시보드나 정보 수정 화면으로 이동할 수 있습니다.

## 정적 프로토타입이라 실제로 동작하지 않는 부분

- 모든 데이터는 Mock 데이터이며, 실제 저장이나 API 연동은 없습니다.
- `수동 검사`, `다시 시도`, `배달앱 수정 사이트 열기` 버튼은 비활성화된 형태로만 표현되며 클릭해도 상태가 바뀌지 않습니다.
- 메뉴·가격 입력창, 체크박스, 라디오는 브라우저 기본 동작으로 값을 바꿔볼 수 있지만 실제로 저장되지는 않습니다.
- 복사 기능은 자동화되어 있지 않으며, 읽기 전용 텍스트 상자에서 사용자가 직접 선택해 복사해야 합니다.
- 새로고침하면 항상 동일한 초기 Mock 상태로 보입니다(별도의 저장소나 세션이 없습니다).

## 공통 Mock 데이터 기준

- 매장: 카페 하루 / 영업시간 10:00~21:00 / 정기휴무 매주 월요일 / 등록 메뉴 12개
- 가격: 아메리카노 4,000→4,500원, 카페라테 4,800→5,000원, 치즈케이크 5,500원 유지
- 배달앱 정책: 음료 +500원, 디저트 +1,000원, 아메리카노 개별 예외 +300원
  - 배달앱 최종가: 아메리카노 4,800원 / 카페라테 5,500원 / 치즈케이크 6,500원
- 대시보드 기준 배달앱은 연결됨 상태이며, 업데이트를 실행하는 도중 계정 인증이 만료되어
  결과 화면에서 반영 실패로 표시됩니다.
- 결과: 네이버 플레이스 반영 완료, 카카오맵 검토 중, 배달앱 반영 실패(업데이트 처리 중 계정 인증 만료)
