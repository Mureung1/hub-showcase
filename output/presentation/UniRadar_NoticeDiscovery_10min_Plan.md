# UniRadar 10분 발표 계획

## 한 문장 메시지

UniRadar는 등록된 공개 공지에서 후보를 안전하게 찾고, 사용자가 원문을 확인한 뒤 분석과 지원 준비로 이어가게 한다.

## 진행 순서

| 슬라이드 | 시간 | 전달할 핵심 |
| --- | ---: | --- |
| 1. UniRadar | 0:00-0:40 | 이번 업데이트는 공지 탐색을 분석 흐름 앞에 안전하게 추가한 작업이다. |
| 2. 문제 | 0:40-1:40 | 학생은 공지를 발견해도 조건 판단, 기억, 준비 단계에서 다시 시간을 쓴다. |
| 3. 사용자 흐름 | 1:40-2:45 | 프로필부터 탐색, 원문 확인, 분석, 태스크까지 한 흐름으로 연결했다. |
| 4. 화면 경험 | 2:45-3:40 | 대시보드에서 다음 행동이 보이도록 탐색과 분석 입력을 바로 연결했다. |
| 5. 구조 | 3:40-4:50 | React는 화면을, Express는 등록 출처·검증·AI 호출을 담당하도록 분리했다. |
| 6. 공지 탐색 | 4:50-6:20 | 등록 출처만 조회하고 후보 링크를 분석 화면으로 넘긴다. 이 슬라이드에 가장 오래 쓴다. |
| 7. 분석 결과 | 6:20-7:35 | 본문 입력 뒤 표준 JSON, 프로필 매칭, 태스크 생성으로 이어진다. |
| 8. 신뢰성 | 7:35-8:40 | allowlist, HTML 검증, timeout, 캐시, fallback으로 위험과 실패를 관리한다. |
| 9. 결과와 다음 | 8:40-9:45 | 이번에 검증한 범위와 다음 통합 우선순위를 정리한다. |
| 마무리 | 9:45-10:00 | “공지 확인을 지원 준비로 바꾼다”는 문장으로 끝내고 질문을 받는다. |

## 시연 포인트

1. `지원 공지 탐색`에서 경북대학교 공지사항을 선택한다.
2. `공지 찾기`로 후보 카드의 제목, 게시일, 원문 링크를 보여준다.
3. `분석 화면으로`를 눌러 링크가 입력란으로 이동하는 것을 보여준다.
4. 이 동작만으로 Gemini가 호출되지 않는다고 설명한다.
5. 원문을 붙여넣은 뒤 분석 결과의 `opportunity`, `match`, `tasks`를 짧게 보여준다.

## 발표 팁

- 기능 목록을 길게 읽지 말고, “왜 탐색과 분석을 분리했는가”를 중심으로 말한다.
- 6번 슬라이드에서 임의 URL을 서버가 가져오지 않는다는 점을 한 문장으로 강조한다.
- 실제 Gemini 상태가 불안정하면 mock fallback 화면을 보여주고, 실패에도 결과 흐름이 끊기지 않는다고 설명한다.
