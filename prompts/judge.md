# 1단계 · 판단 (judge)

> 이 파일은 런타임에 로드되는 자산이다. 코드에 프롬프트를 박지 않는다.
> 바꿀 때는 [CHANGELOG.md](./CHANGELOG.md)에 무엇을·왜·결과를 남긴다.

**목적** 수집한 논문 중 무엇이 중요한지 고르고, **버린 것의 이유까지** 만든다.
**중요** 제외 사유는 부산물이 아니라 결과물이다. 이게 없으면 서비스의 핵심 가치가 증명되지 않는다.

**입력** `topic`, `papers[]` (title + abstract 앞 500자)
**출력**
```json
{"picked": [{"index": 0, "score": 4, "reason": "한 문장"}],
 "excluded": [{"index": 3, "reason": "한 문장"}]}
```
**fallback** `{"picked": [], "excluded": []}` → 상위에서 "판단 실패"로 처리하고 `error` 종결

## 프롬프트
```text
너는 AI 연구자를 돕는 논문 큐레이터다.
아래 논문 목록에서 '{topic}' 주제에 중요한 논문을 골라라.

기준:
- 주제와 직결되는 새 방법론·이론·벤치마크를 우선한다.
- 일반 서베이, 단순 응용 사례, 주제와 스친 논문은 제외한다.
- 3~5편을 고른다. 억지로 채우지 마라. 정말 없으면 적게 골라도 된다.

모든 논문에 대해 골랐든 뺐든 한 문장 이유를 반드시 쓴다.
제외 사유는 "관련 없음" 같은 말이 아니라, 무엇이 어떻게 맞지 않는지 구체적으로 쓴다.
사용자는 제외 목록도 열어본다.

반드시 아래 JSON만 출력하라. 설명·마크다운 코드블록 금지.
{"picked":[{"index":0,"score":1-5,"reason":"..."}],"excluded":[{"index":3,"reason":"..."}]}

논문 목록:
{papers_json}
```

> **주의** `picked + excluded`가 입력 전체를 덮어야 한다. LLM이 일부를 통째로 빠뜨리는 일이 잦다.
> 코드에서 개수를 검증하고, 누락된 index는 `excluded`에 "판단 누락"으로 채운다.
