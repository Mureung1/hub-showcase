# 프롬프트 변경 기록 · 공통 규칙

> `prompts/`가 이 프로젝트의 사실상 소스코드다. 에이전트의 판단·도구 선택·자기 검증·추론이 전부 여기서 나온다.
> Python은 이걸 호출하고 결과를 파싱하는 배관일 뿐이다.
>
> **규칙:** 프롬프트를 `.py`에 문자열로 박지 않는다. 코드는 `prompts/*.md`에서 로드한다.
> 바꿀 때는 아래 §버전 기록에 **무엇을 왜 바꿨고 결과가 어땠는지** 남긴다. 안 남기면 되돌릴 수 없다.

각 단계: [judge](./judge.md) · [select_tool](./select_tool.md) · [summarize](./summarize.md) · [verify](./verify.md) · [trend](./trend.md)

## 공통 규칙

**모든 프롬프트는 JSON만 출력하도록 강제한다.** 코드가 파싱해야 하기 때문이다.

```text
반드시 아래 JSON 형식으로만 답하라. 설명·인사·마크다운 코드블록 금지.
```

**그래도 LLM은 형식을 어긴다.** 그래서 모든 호출은 `ask_llm_json(prompt, fallback)`을 쓴다.
파싱 실패 시 fallback으로 넘어가고 에이전트는 죽지 않는다.

**fallback은 "안전한 쪽"으로 정한다.** 판단이 안 되면 비싼 쪽이 아니라 싼 쪽, 무한루프가 아니라 종료로.

## 버전 기록

> **바꿀 때마다 반드시 추가한다.** 이유와 결과를 안 적으면 되돌릴 수 없고, 같은 실수를 반복한다.
> 데모데이·포트폴리오에서 "프롬프트를 이렇게 개선했다"고 보여줄 자료이기도 하다.

|  |  |  |  |  |

> `2026-07-08 | 5단계 | flows에 papers 배열 필수화 | "최근 연구가 활발하다" 같은 근거 없는 흐름이 계속 나옴 | 무의미한 흐름 사라짐. 대신 flows가 3개→2개로 줄어듦 (허용)`

## 튜닝 노트

프롬프트를 고칠 때 참고할 것. 겪은 것을 여기 쌓는다.

- **JSON 강제는 한 번으로 안 된다.** "설명 금지", "마크다운 코드블록 금지"를 명시해도 LLM은 코드블록으로 감싼다. 파싱 쪽에서 벗겨내는 게 확실하다.
- **"억지로 채우지 마라"가 효과 있다.** 개수를 지정하면 LLM은 무조건 그 수를 맞추려고 관련 없는 것을 끼워넣는다.
- **fallback 방향에 원칙이 있다.** 2단계는 `false`(안 읽음)로, 4단계는 `true`(통과)로. 둘 다 "판단 불가 시 비용이 덜 드는 쪽". 이 원칙을 깨지 말 것.
- **온도(temperature)는 낮게.** 판단·검증은 일관성이 중요하다. 창의성이 필요한 단계가 없다.
