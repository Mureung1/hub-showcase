# Campus Flow PPT 제작용 상세 브리프

## 1. 발표 제목

**Campus Flow: 공공데이터 기반 대학 정류장 이용 집중도 대시보드**

부제 후보:

- 전국 거점국립대 주요 정류장을 방향별·시간대별로 비교하는 캠퍼스 이동 도우미
- 버스 내부 혼잡도가 아닌 정류장 이용 흐름을 보여주는 공공데이터 시각화 프로젝트

발표자:

- N056 김진영

## 2. 프로젝트 한 줄 요약

Campus Flow는 전국 10개 거점국립대의 주요 버스 정류장 30곳을 지도에 표시하고, 공공데이터 기반 월별 승·하차 통계를 이용해 방향별·시간대별 정류장 이용 집중도를 비교하는 웹 대시보드이다.

## 3. 문제 정의

학생들은 등교하거나 캠퍼스 주변을 이동할 때 어느 정류장이 덜 붐비는지 알기 어렵다.

기존 지도 서비스는 정류장의 위치와 노선 정보는 보여주지만, 시간대별로 어느 정류장에 이용자가 몰리는지 비교하기 어렵다. 공공데이터포털에는 정류장별 승·하차 통계가 존재하지만 API 형태라 일반 사용자가 바로 해석하기 어렵고, 정류장의 도로 방향별 차이도 직접 정리해야 한다.

핵심 문제:

- 같은 학교 주변에도 여러 정류장이 있어 어떤 정류장을 선택해야 할지 판단하기 어렵다.
- 같은 이름의 정류장도 도로 양쪽 방향에 따라 이용량이 다를 수 있다.
- 공공데이터는 원자료 형태라 사용자가 바로 이동 판단에 쓰기 어렵다.
- 실시간 혼잡도와 통계 기반 이용량을 구분하지 않으면 잘못된 정보를 줄 수 있다.

## 4. 해결 아이디어

공공데이터의 정류장별 월간 승·하차량을 시간대별 이용량으로 변환하고, 이를 캠퍼스 내부에서 비교 가능한 0~100점의 이용 집중도 점수로 환산한다.

서비스는 사용자가 학교를 선택하면 지도 위에서 주요 정류장 3곳을 보여주고, A 방향과 C 방향을 전환하면서 각 방향의 시간대별 이용 집중도를 비교할 수 있게 한다.

첫 화면에서는 현재 시간대 기준으로 각 대학의 방향별 추천 정류장을 보여준다.

## 5. 주요 기능

### 5.1 전국 대학 선택 화면

- 전국 거점국립대 10곳을 카드 형태로 제공한다.
- 각 대학 카드에는 대표 심볼, 지역, 통계 제공 여부가 표시된다.
- 현재 시간대 기준으로 A 방향 1개, C 방향 1개의 추천 정류장을 보여준다.
- 추천 정류장은 해당 시간대 이용 집중도 점수가 가장 낮은 정류장이다.
- 히어로 영역 오른쪽에는 현재 로컬시각을 보여주는 아날로그 시계가 있다.

강조할 점:

- 사용자는 상세 화면에 들어가기 전부터 지금 시간대에 어느 정류장이 상대적으로 여유로운지 알 수 있다.

### 5.2 캠퍼스 지도

- 각 대학의 실제 캠퍼스 경계를 OpenStreetMap 기반으로 표시한다.
- 주요 정류장 3곳을 지도 위 핀과 라벨로 표시한다.
- 정류장 연결선은 단순 직선이 아니라 일부 대학은 OSRM 기반 실제 도로 경로로 표시한다.
- 지도 핀 색상은 현재 선택한 방향과 시간대의 이용 집중도 등급을 반영한다.

강조할 점:

- 단순 표가 아니라 지도와 그래프가 함께 움직이는 시각적 대시보드이다.

### 5.3 방향 전환

- 정류장 이용량은 A 방향과 C 방향으로 분리한다.
- 사용자가 방향 버튼을 누르면 지도 핀, 비교 막대, 24시간 그래프가 동시에 갱신된다.
- 방향 버튼에는 예를 들어 `북문 방향`, `정문 방향`, `한나·소나무 방향`처럼 실제 끝점 이름을 사용한다.

강조할 점:

- 같은 정류장이라도 도로 방향에 따라 이용량이 달라지는 문제를 반영했다.

### 5.4 시간대별 정류장 비교

- 사용자는 0시부터 23시까지 시간 슬라이더를 움직일 수 있다.
- 선택한 시간대의 정류장별 이용 집중도가 막대 그래프로 표시된다.
- 점수는 0~100점이며 색상과 라벨로 `여유`, `보통`, `혼잡`을 보여준다.

등급 기준:

```text
0~39점   여유
40~69점  보통
70~100점 혼잡
```

### 5.5 24시간 이용 패턴 그래프

- 선택한 정류장의 하루 24시간 이용 집중도 변화를 막대 그래프로 보여준다.
- 현재 선택된 시간대는 강조 표시된다.
- 승차량과 하차량을 합산한 월별 대표 패턴이다.

## 6. 혼잡도 계산 원리

이 프로젝트의 혼잡도는 실시간 버스 내부 인원이 아니다.

공공데이터포털의 정류장별 월간 승·하차 통계를 기반으로 계산한 **정류장 이용 집중도**이다.

계산 흐름:

```text
시간대별 이용량 = 승차량 + 하차량
```

같은 캠퍼스의 모든 정류장, 모든 방향, 24시간 이용량을 모은 뒤 95백분위값(P95)을 기준값으로 사용한다.

```text
캠퍼스 기준값 = 캠퍼스 내 모든 방향·정류장·시간대 이용량의 P95
```

최종 점수:

```text
이용 집중도 = min(100, round(이용량 / 캠퍼스 기준값 * 100))
```

P95를 사용하는 이유:

- 단순 최대값을 기준으로 잡으면 극단적으로 큰 한 시간대 때문에 다른 값들이 모두 작아 보일 수 있다.
- 정류장마다 개별 최대값을 기준으로 잡으면 모든 정류장의 최고 시간이 100점이 되어 방향 간 비교가 어려워진다.
- 캠퍼스 공통 P95를 사용하면 같은 캠퍼스 안에서 정류장과 방향을 같은 눈금으로 비교할 수 있다.

## 7. 데이터 처리 방식

사용 데이터:

- 국토교통부 정류장별 이용량 API
- 국토교통부 버스정류장 API
- OpenStreetMap 캠퍼스 경계 및 정류장 위치
- OSRM 실제 도로 경로

데이터 파이프라인:

```text
공공데이터 API
→ 정류장 후보 검색
→ A/C 방향 매핑
→ 월별 이용량 수집
→ 시간대별 승·하차량 합산
→ 캠퍼스 공통 P95 기준 점수화
→ 정적 JSON 생성
→ 웹사이트에서 JSON만 읽기
```

보안 처리:

- API 키는 `.env.local`에서만 읽는다.
- 브라우저에는 API 키를 전달하지 않는다.
- 웹사이트는 생성된 정적 JSON만 사용한다.
- 생성 JSON과 빌드 결과에 인증키가 포함되지 않는지 검증한다.

## 8. 결측 처리 원칙

자료가 없는 정류장을 0점으로 표시하지 않는다.

이유:

- 자료 없음과 실제 이용량 0은 의미가 다르다.
- 자료 없음 정류장을 `0점·여유`로 표시하면 사용자가 잘못된 판단을 할 수 있다.

처리 방식:

- 매핑 실패: `방향 자료 없음`
- API 0건: `해당 월 자료 없음`
- 지원 지역 외: `지도만 제공`
- 정상 데이터만 점수와 등급 계산에 사용

## 9. 전북대 정류장 개선 사례

전북대는 기존 후보 중 `금암광장`이 학교와 너무 멀어 정류장 구조를 다시 검토했다.

최종 구조:

```text
A 지점: 사대부고사거리
B 지점: 전북대종점
C 지점: 전북대학교.한나·소나무
```

공공데이터 매핑:

- 사대부고사거리: `2507690`
- 전북대종점: `2509860`
- 한나여성병원앞: `2550260`
- 소나무한의원앞: `2550080`

특징:

- 사대부고사거리는 여러 로컬 정류장이 병합된 대표값으로 판단했다.
- 이용량이 극히 작은 사대부고사거리 후보는 버스 1대 수준으로 보고 제외했다.
- 전북대도 OSRM 실제 도로 기반 연결선에 포함했다.

## 10. 실제 도로 기반 연결선

초기에는 정류장 3개를 A-B-C 직선으로 연결했다.

개선 후:

- 경북대, 부산대, 서울대, 제주대, 충북대, 전남대, 전북대는 OSRM 기반 실제 도로 경로를 사용한다.
- 브라우저에서 라우팅 API를 호출하지 않는다.
- 생성 스크립트가 미리 경로를 받아 `generated-road-routes.json`에 저장한다.
- 지도에서는 정적 JSON 좌표를 SVG 좌표로 변환해 도로선을 그린다.

장점:

- 지도 위 정류장 흐름이 실제 도로 형태와 더 가깝다.
- 런타임 API 호출이 없어 빠르고 안정적이다.
- API 키나 외부 라우팅 의존성을 사용자 브라우저에 노출하지 않는다.

## 15. 한계

이 프로젝트의 값은 실시간 혼잡도가 아니다.

한계:

- 차량 내부 승객 수를 직접 계산하지 않는다.
- 월별 AI 합성 교통카드 통계 기반 대표 패턴이다.
- 일부 지역은 공공데이터 정류장 ID가 병합되어 있다.
- 일부 정류장은 정확한 반대편 방향 ID를 찾기 어렵다.
- 셔틀버스나 교내 순환버스는 공공데이터와 정확히 매칭되지 않을 수 있다.
