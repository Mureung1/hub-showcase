# Phase 06 — MVP 통합 검증 (기능 아님)

이 Phase는 새 제품 기능을 만들지 않는다. Phase 00~05로 구현된 로그인·리뷰 수동 입력·리뷰 유형 분류·톤앤매너·답글 초안 생성·리뷰 분석·블랙컨슈머 대응이 실제로 하나의 제품으로 맞물려 동작하는지만 증명한다. `frontend`, `supabase`는 `allowed_paths`에 없으므로 이 Phase에서 기능 코드를 고치지 않는다.

## `mvp-integration`

로컬 Supabase(`supabase start`, 테스트 전용으로 초기화된 DB)와 `LLM_PROVIDER=fake` 모드의 Edge Functions로 `docs/PRD.md` 3장의 S1~S4 시나리오를 통합 수준에서 재현한다(`tests/integration/test_mvp_flows.ts`, Vitest).

포함해야 할 것:

- S1 최초 설정: 가입·로그인 → 매장 프로필 저장 → 과거 리뷰 일괄 입력 → 일괄 분류 → 홈 통계 반영
- S2 일상 사용: 일괄 붙여넣기 부분 실패, 리뷰함 필터, 초안 확인·수정·재생성, 복사 → 완료 처리, 완료 후 대기 건수 차감
- S3 악성 리뷰: 악성 의심에는 초안 미생성, 위험도 확인, 오탐 조정 시 답글 흐름 복귀, 매뉴얼 4단계 진행, 사례 아카이빙
- S4 주간 리뷰: 분석 리포트 기간별 집계, 콜드 스타트(10건 미만) 경계
- 횡단 조건: 계정 2개로 매장 간 데이터 격리(RLS) 실제 검증, 재조회 후 상태 지속, 저확신 리뷰의 확인 필요 처리

발견된 기능 결함은 이 Phase에서 수정하지 않는다. 관측 사실과 재현 명령을 Failure로 남기고, 해당 기능 Phase(01~05)로 돌아가 새 Attempt로 고친 뒤 이 Phase를 다시 실행한다.

`docs/quality/MVP_COMPLETE.md`에 시나리오별 통과 증거와 실행 명령을 요약하고 "자동 게시 없음"을 명시한다. 비밀이나 고객 원문은 남기지 않는다.

이 Phase가 통과하면 실행 가능한 리뷰지기 MVP 프로젝트 하나가 완성된 상태다.
