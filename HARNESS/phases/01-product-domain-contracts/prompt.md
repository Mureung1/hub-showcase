# Phase 01 — Product and domain contracts

controller가 지정한 `step_id`만 수행한다. `phase.json`의 컨텍스트를 먼저 읽고 `allowed_paths`만 수정한다. JSON 산출물은 실제 Draft 2020-12 JSON Schema로 작성하고 파싱과 대표 예시 검증이 가능해야 한다. 상태와 성공 판정은 controller 소유다.

## `domain-state-contracts`

- Review 입력 필드, 유형, 복합 플래그, 세부 카테고리, 분류 근거와 저확신 상태를 정의한다.
- ReplyDraft 상태는 `초안 대기`, `확인 필요`, `완료`의 허용 전이와 금지 전이를 명시한다.
- 악성 의심은 초안 부재가 불변조건이다. 위험도 ①·②로 사장님이 조정했을 때만 일반 흐름으로 돌아간다.
- StoreProfile은 문의 답변의 유일한 출처이며 이벤트 시작·종료일과 금지 표현을 포함한다.
- ResponseCase는 4단계 체크리스트, 증거 메타데이터, 위험도 변경과 사례 기록을 포함하되 자동 신고·자동 게시 동작은 포함하지 않는다.

## `ai-io-contracts`

- 분류 출력은 유형, 카테고리, 근거, 신뢰도와 확인 필요 여부를 구조화한다.
- 답글 출력은 본문, 톤, 글자 수, 사용한 프로필 근거, 안전 검사 결과를 구조화한다.
- 위험도 출력은 ①·②·③, 감지 근거와 불확실성을 구조화한다.
- 파싱 실패, 스키마 불일치, 저확신, 금지 표현 감지 시의 fail-closed 동작을 명시한다.
- 보상·환불 약속, 확인되지 않은 사실, 프로필 밖 정보, 법적 판단, 위협 표현을 차단한다.

## `identity-privacy-contracts`

- 사용자와 매장의 소유·접근 경계, 다매장 확장 여지를 정의한다.
- 닉네임·주문 정보·증거 파일은 목적 제한, 최소 수집, 역할별 접근, 보존 기간, 삭제와 감사 기록을 정의한다.
- 법률 검토가 필요한 항목은 제품 로직으로 확정하지 말고 검토 상태로 표시하되 구현 가능한 보수적 기본값을 제시한다.

검증 실패 시 현상과 원인 가설을 분리하고 근거 파일을 보고한다.
