# Phase 03 — 답글 초안 생성 (PRD 2.3)

현재 step만 수행하고 `allowed_paths` 밖은 수정하지 않는다. LLM 호출은 `generate-reply` Edge Function 안에서만 하고 `supabase/functions/_shared/llm` adapter를 재사용한다(`LLM_PROVIDER=fake` 지원). 금칙 검사는 LLM prompt가 아니라 결정적 정책 모듈(순수 TS, Vitest 검증)로 강제한다.

## 공통 불변조건 (금칙)

1. 보상·환불 약속 금지 ("서비스 드리겠습니다" 류). 보상 언급은 사장님 직접 수정으로만 추가된다.
2. 확인되지 않은 사실 단정 금지 (조리 상태, 배달 지연 원인 등).
3. 매장 프로필에 없는 이벤트·정보 언급 금지. 문의는 운영 정보 등록 항목만 답하고, 미등록 질문은 "확인 후 안내드리겠습니다" 형태의 안전 문구로 생성한다.
4. 법적 판단·위협성 표현 금지.
5. 사장님 등록 금지 표현 포함 시 자동 재생성. 재생성 한도를 두고 초과 시 "확인 필요"로 fail-closed 한다.

- 악성 의심 리뷰에는 초안을 생성하지 않는다. 위험도 ①·②로 조정된 뒤에만 생성할 수 있다.
- 답글 구조는 유형별로 따른다: 칭찬(감사→구체 언급→재방문), 불만(공감·사과→확인된 원인만→개선), 복합(감사→사과→개선), 문의(운영 정보 기반 답변→감사).
- 길이 기본 100~200자, 톤 "짧게"는 80자 내외. 톤 3종(기본/더 정중하게/짧게), "다시 생성" 무제한.

## `draft-engine`

`supabase/functions/generate-reply`에 유형별 초안 생성, 금칙 정책 모듈, 자동 재생성을 구현하고 reply_drafts 저장 마이그레이션을 추가한다. 골든 안전 사례(`tests/golden/reply-safety-cases.json`)로 금칙 회귀를 고정한다.

## `draft-ui-copy-flow`

③ 리뷰 상세 에디터를 구현한다(`frontend/src/features/reply-draft`): 톤 칩 전환·다시 생성·글자수·직접 수정, "답글 복사하기"(1차 버튼) → "배민 사장님 페이지에 붙여넣어 주세요" 안내 → "완료로 표시" 상태 종결. clipboard 실패·API 오류·저장 중 상태를 명시한다. 자동 게시처럼 보이는 버튼·문구는 만들지 않는다. 악성 의심 리뷰는 에디터 대신 경고 배너를 표시한다(대응 센터 연결은 Phase 05에서 완성).
