# Phase 05 — UX completeness

현재 step만 수행하며 manifest의 `allowed_paths` 밖을 바꾸지 않는다. UI는 한국어 존댓말, 큰 본문, 낮은 정보 밀도와 명확한 다음 행동을 사용한다. 색상만으로 위험 상태를 구분하지 않는다. controller가 실제 test/build/E2E 결과를 판정한다.

## `complete-user-experience`

PRD 화면 ①~⑦을 실제 데이터 흐름으로 완성한다.

- 홈: 처리 대기, 악성 우선 큐와 대기 0건 종결 상태
- 리뷰함: 유형·상태 필터, 페이지네이션, 0건 CTA
- 리뷰 입력: 단건과 일괄 붙여넣기 분리 미리보기, 행별 오류와 부분 성공
- 상세: 분류 근거, 수정 가능한 초안, 글자 수, 세 톤, 재생성, clipboard 성공·실패, 완료 처리
- 분석: 주간·월간·직접 기간, 10건 미만 진행 표시, 10건 이상 차트와 최대 3개 인사이트
- 대응 센터: 위험도 직접 조정, 4단계 체크 저장, 증거 첨부·인쇄, 사례 기록과 법률 자문 아님 고지
- 설정: 프로필 5개 그룹, 즉시 미리보기, 만료 이벤트, Phase 2 자동화 선택의 비활성 안내

각 비동기 화면에 loading, empty, validation error, server error와 retry 상태를 둔다. 악성 의심 상세에는 편집기를 렌더링하지 않는다.

## `accessibility-responsive-e2e`

키보드 탐색, focus 표시, label·heading 구조, 상태 알림, 대비, 200% 확대와 모바일 폭을 확인한다. S1~S4, 저확신, 일괄 부분 실패, clipboard 실패, 콜드 스타트, 악성 오탐 복귀, 증거 리포트 인쇄를 브라우저 E2E로 검증한다. 실제 배민 게시·신고를 자동화하지 않는다.

감사 문서에는 확인한 viewport, 브라우저, 명령, 남은 제한과 증거 경로를 적는다. 스크린샷에는 고객·자격증명 데이터를 사용하지 않는다.
