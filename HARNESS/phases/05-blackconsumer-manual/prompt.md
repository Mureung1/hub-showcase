# Phase 05 — 블랙컨슈머 대응 (PRD 2.5)

현재 step만 수행하고 `allowed_paths` 밖은 수정하지 않는다. 시스템은 안내와 기록까지만 한다. 답글 게시·신고·보상·법적 판단의 실행 주체는 항상 사장님이며 자동 처리를 만들지 않는다. LLM 호출은 `assess-risk` Edge Function 안에서만 한다(`LLM_PROVIDER=fake` 지원).

## 공통 불변조건

- 위험도 3단계: ① 단순 불만(일반 답글 흐름 복귀), ② 정당한 클레임(복귀 + 클레임 처리 가이드), ③ 악성(매뉴얼 4단계).
- 사장님이 위험도를 직접 조정할 수 있고, ①·②로 조정하면 답글 초안 생성으로 자동 복귀한다.
- 매뉴얼 4단계: 답글 가이드 예시문+복사 → 배민 신고 절차 체크리스트 → 증거 수집 체크리스트(첨부·리포트 인쇄) → 법적 대응 일반 안내.
- 법적 안내 영역에는 "일반적인 정보 안내이며 법률 자문이 아닙니다" 고지를 상시 노출한다.
- 사례 아카이빙(리뷰 원문·위험도·수행 단계·증거)은 최소 수집 원칙을 따르고, 동일 닉네임 재발 시 알림만 한다.
- 위험도 판정의 LLM 구조화 출력은 스키마 검증과 "확인 필요" fail-closed를 적용한다.
- 증거 파일은 Supabase Storage 버킷에 저장하고 RLS로 본인 매장 사건의 증거만 접근하게 한다.

## `risk-case-data`

`supabase/functions/assess-risk`에 위험도 판정을 구현하고, `supabase/migrations`에 response_cases 스키마·단계 체크 저장·증거 버킷 정책을 추가한다. `frontend/src/features/blackconsumer`에 사건 생성·조회·위험도 조정·재발 감지 연결을 구현한다.

## `response-center-ui`

⑥ 대응 센터 화면을 구현한다: 위험도 필터 사건 리스트, 고위험 감지 배너와 감지 사유, 매뉴얼 4단계 위에서 아래로 진행·단계별 체크 저장, 위험도 ①·② 조정 시 ③ 리뷰 상세로 복귀, 증거 첨부와 리포트 인쇄.

이 Phase가 통과하면 MVP 5개 기능 구현이 모두 끝난 상태다. 전체가 하나의 제품으로 맞물려 동작하는지는 Phase 06(검증)에서 확인한다.
