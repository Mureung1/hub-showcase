# loop

작업은 계획 → 구현 → 검토 → 수정 → 보고 순서로 진행한다.

## 1. 계획

- 요청을 `router.md`로 분류한다.
- 범위가 MVP인지 Phase 2인지 확인한다.
- 바꿀 파일과 읽을 파일을 정한다.
- 필요한 경우만 사용자에게 질문한다. 합리적 가정이 가능하면 가정하고 진행한다.

## 2. 구현

- 기존 파일을 먼저 읽는다.
- 변경은 요청 범위에 맞게 작게 만든다.
- 관련 없는 파일과 기존 사용자 변경은 건드리지 않는다.
- 문서 변경이 필요한 코드 변경이면 문서도 함께 갱신한다.

## 3. 검토

다음 관점으로 자체 검토한다.

- PRD와 맞는가?
- MVP 범위를 넘지 않았는가?
- 악성 리뷰·법률·개인정보·자동화 리스크를 만들지 않았는가?
- UI 문구가 사장님에게 이해 가능한가?
- 테스트 또는 수동 검증을 할 수 있는가?

## 4. 수정

- 검토에서 발견한 문제를 고친다.
- 수정 후 필요한 검증을 다시 한다.
- 테스트를 실행할 수 없으면 이유와 대체 검증을 남긴다.

## 5. 보고

최종 보고에는 다음을 포함한다.

- 무엇을 변경했는지
- 어떤 파일을 만들거나 수정했는지
- 검증 결과
- 남은 결정 또는 다음 작업

불필요한 구현 과정 나열보다 결과와 다음 행동을 우선한다.
