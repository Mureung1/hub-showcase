# done

작업 완료는 “파일을 수정했다”가 아니라 “요청한 결과가 PRD와 품질 기준을 만족한다”는 뜻이다.

## 완료 기준

작업은 다음 조건을 모두 만족해야 완료다.

- 요청한 산출물이 존재한다.
- PRD의 MVP 범위와 충돌하지 않는다.
- 관련 문서와 코드가 서로 모순되지 않는다.
- 악성 리뷰, 법률 안내, 개인정보, 자동화 관련 금지 패턴을 만들지 않았다.
- 검증 가능한 작업은 검증했다.
- 검증하지 못한 부분은 이유와 남은 작업을 명확히 남겼다.
- `TODO.md`와 `LOG.md`가 현재 상태를 반영한다.
- 관련 없는 사용자 변경을 건드리지 않았다.

## 문서 작업 완료 기준

- 문서마다 목적과 사용 시점이 분명하다.
- 같은 내용이 여러 문서에 불필요하게 중복되지 않는다.
- 기준 문서와 참고 문서의 우선순위가 명확하다.
- 추후 구현자가 다음 파일을 어디서 찾아야 하는지 알 수 있다.

## 코드 작업 완료 기준

- 진입점과 영향 범위가 `docs/CODE_MAP.md`와 맞는다.
- 사용자 흐름이 `docs/TEST_PLAN.md` 기준으로 확인 가능하다.
- 실패 상태, 빈 상태, 확인 필요 상태를 고려했다.
- PRD에 있는 금칙과 리스크 대응을 우회하지 않는다.

## 최종 보고 형식

최종 보고는 짧게 쓴다.

- 완료한 일
- 생성·수정한 주요 파일
- 검증 결과
- 다음에 해야 할 일
