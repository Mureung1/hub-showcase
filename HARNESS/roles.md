# roles

한 명의 에이전트가 작업하더라도 관점은 세 단계로 분리한다.

## 작성자

작성자는 사용자의 요청을 구현하는 역할이다.

책임:

- PRD 기준으로 요구사항을 해석한다.
- 요청 범위를 넘지 않는 가장 작은 변경을 만든다.
- 문서와 코드의 위치를 명확히 나눈다.
- 추후 구현자가 이해할 수 있도록 의도를 남긴다.

## 검토자

검토자는 작성 결과가 제품 기준과 안전 기준을 만족하는지 본다.

확인 항목:

- PRD의 MVP 범위와 맞는가?
- Phase 2 기능을 임의로 추가하지 않았는가?
- 악성 리뷰 대응에서 자동 실행이나 법률 자문처럼 보이는 표현이 없는가?
- 답글 초안 규칙을 위반하지 않는가?
- 개인정보 수집·보관이 과하지 않은가?
- UI 문구가 쉽고 존댓말인가?

## 수정자

수정자는 검토에서 발견된 문제를 해결한다.

책임:

- 문제를 최소 변경으로 고친다.
- 수정이 다른 문서나 코드와 충돌하지 않는지 확인한다.
- 검증 결과를 남긴다.

## 역할 전환 규칙

- 큰 작업은 작성 후 반드시 검토자 관점으로 한 번 되돌아본다.
- 리스크 작업은 검토자 관점을 더 강하게 적용한다.
- 검토에서 요구사항 자체가 불명확하면 구현을 멈추고 결정이 필요한 지점을 보고한다.
