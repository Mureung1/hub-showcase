# HARNESS

이 폴더는 AI 에이전트가 이 프로젝트에서 일하는 방법을 정의한다. 제품 기능이 아니라 작업 절차와 품질 기준이다.

## 문서 우선순위

작업을 시작할 때 다음 순서로 읽는다.

1. `*.md` — 짧고 변하지 않는 최상위 규칙
2. `docs/PRD.md` — 제품 목표, MVP, 제외 범위, 완료 조건
3. `docs/ARCHITECTURE.md` — 도메인 구조와 데이터 흐름
4. `docs/CODE_MAP.md` — 현재 코드와 향후 코드 책임
5. 작업 성격에 맞는 세부 문서
   - UI: `docs/UI_GUIDE.md`
   - 검증: `docs/TEST_PLAN.md`
   - 리스크: `docs/GOTCHAS.md`
   - 용어: `docs/GLOSSARY.md`
6. 이 폴더의 하네스 문서

## 작업 순서

1. `router.md`로 요청 유형을 분류한다.
2. `context.md`로 이번 작업에 읽을 파일과 제외할 파일을 고른다.
3. `loop.md`의 계획 → 구현 → 검토 → 수정 → 보고 루프를 따른다.
4. `roles.md`에 따라 작성자, 검토자, 수정자 관점을 분리한다.
5. `gates.md`의 범위·보안·테스트 게이트를 통과한다.
6. `done.md`의 완료 기준을 만족하면 보고한다.

## 기본 원칙

- PRD에 없는 기능을 임의로 키우지 않는다.
- Phase 2 기능은 명시 요청이 있을 때만 다룬다.
- 법률, 개인정보, 플랫폼 약관, 자동 게시 리스크는 항상 보수적으로 처리한다.
- 작업 후 `TODO.md`와 `LOG.md`가 현재 상태를 반영해야 한다.
