## 오늘의 목적

배포가 끝난 ThingDong의 핵심 흐름을 다시 확인하고, 4주 동안 사용한 Agent·Skill·문서를 하나의 재사용 가능한 워크플로우로 정리한다.

## 오류와 해결 기록

| 오류 또는 발견 | 원인 | 검토·적용한 해결 | 성공 확인 |
| --- | --- | --- | --- |
| Vercel에서 `vite: command not found` | 프론트 루트와 빌드 명령이 올바르게 설정되지 않음 | Root Directory를 `Project/frontend`, Build Command를 `npm run build`로 설정 | Vercel 배포가 Ready 상태가 되고 서비스 화면이 열림 |
| Render에서 `ENOTFOUND mysql.railway.internal` | Railway 내부 DNS는 Render에서 해석할 수 없음 | `MYSQL_PUBLIC_URL`에서 외부 호스트·포트·DB 값으로 `DB_*` 환경변수 설정 | Render 로그의 `[db] MySQL connected`와 `/health` 200 확인 |
| SQL import 중 한글 깨짐·`ASCII '\\0'` 오류 | PowerShell의 텍스트 리다이렉션과 `Get-Content`가 SQL 파일을 다시 인코딩함 | `cmd /c`로 dump 파일을 만들고 Docker 컨테이너에 파일을 복사해 MySQL이 직접 읽도록 변경 | 외부 DB에서 게시글 조회 API가 실제 데이터 반환 |
| 배포 화면에서 개발자 로그인 실패 | `fetch('/auth/dev-login')`가 Vercel 도메인으로 요청됨 | `Header.jsx`에서 공통 `apiClient`로 로그인 요청 변경 | Vercel에서 민지·서준·다은 개발자 로그인 확인 |

## Agent에게 요청한 내용과 적용 판단

| 요청 | 받은 제안 | 검토 후 적용한 내용 |
| --- | --- | --- |
| 기능 요구사항을 일주일 단위 이슈로 나누기 | 수직 슬라이스와 P0/P1/P2 우선순위 제안 | DB 보존·참여 취소를 P0으로 먼저 진행하고, 마이페이지·문서는 P1으로 배치 |
| TDD 대상과 케이스 찾기 | 가격 계산·상태 필터 함수의 정상·빈 값·경계값 제안 | `calculatePerPersonPrice`, `filterPurchasesByActivity` 테스트를 먼저 작성 |
| 배포 오류 원인 찾기 | Root Directory, CORS, Railway Public URL, 환경변수 확인 순서 제안 | 로그와 실제 설정 화면을 대조해 필요한 항목만 수정 |
| 데모 흐름 구성 | 방장 등록 → 참여자 참여 → 입금 → 상태 변경 순서 제안 | 인원 2명으로 준비해 모집 완료가 즉시 보이도록 조정 |

2. 외부 DB 이전은 테스트용 데이터로 한 번 먼저 실행한다.
3. 배포 후 `/health` → 목록 조회 → 로그인 → 핵심 행동 순서로 확인한다.
4. 브라우저 오류는 Network 요청 URL, Render 로그, DB 값 순서로 분리해 확인한다.
5. 검증이 끝난 뒤에만 데모 영상과 showcase 정보를 갱신한다.
