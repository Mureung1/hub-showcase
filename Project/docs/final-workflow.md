# ThingDong 나만의 개발·배포 워크플로우

## 목적

요구사항을 작은 수직 슬라이스로 나누고, 테스트·배포·회고까지 같은 순서로 반복한다. 이 문서는 다음 기능에서도 그대로 사용하는 개인 작업 순서다.

## 입력과 결과물

| 구분 | 내용 |
| --- | --- |
| 입력 | 사용자 문제, 화면 요구사항, 상태 규칙, 우선순위 |
| 중간 결과 | 이슈 목록, 테스트 시나리오, 코드 변경, 검증 결과 |
| 최종 결과 | 작은 커밋, PR 기록, 배포 URL, 회고 |

## 반복 작업 순서

1. **문제와 완료 기준을 정한다.**
   - 내가 사용자 흐름과 이번 주 우선순위를 결정한다.
   - `feature-slice` Agent에게 하루 안에 끝나는 화면→API→DB 단위로 나눠 달라고 요청한다.
   - 결과에서 범위가 큰 항목, 의존성, 빠진 실패 상황을 내가 다시 확인한다.

2. **테스트 가능한 규칙을 먼저 정한다.**
   - 계산, 필터, 권한, 상태 전이처럼 규칙이 분명한 기능을 고른다.
   - `test-first-generator` Skill의 순서로 정상·빈 값·경계·실패 케이스를 먼저 목록화한다.
   - 테스트를 먼저 작성해 Red를 확인하고, 최소 구현으로 Green을 만든 뒤 중복을 정리한다.

3. **작은 수직 슬라이스로 구현한다.**
   - 프론트 API 모듈 → Express Route/Controller/Service → Sequelize Model → 화면 반영 순서로 연결한다.
   - 상태·인원 수처럼 동시에 바뀌는 값은 Service의 트랜잭션과 잠금 규칙을 우선 확인한다.
   - 화면의 임시 데이터가 실제 API 결과를 가리지 않는지 점검한다.

4. **코드와 실제 흐름을 검증한다.**
   - 백엔드는 Jest/Supertest, 프론트 계산·필터는 Vitest, 프론트 전체는 Vite build로 확인한다.
   - `feature-verify` 또는 `vertical-slice-auditor` Agent에게 완료 기준과 코드·테스트를 대조하게 한다.
   - 브라우저에서 방장 등록 → 참여자 참여 → 입금 → 상태 변경처럼 실제 사용자 흐름을 실행한다.

5. **작게 커밋하고 기록한다.**
   - 한 기능 단위로 `<scope>: <한글 명사형 내용>` 형식의 커밋을 만든다.
   - PR에는 동작 화면, 테스트 결과, 설명 가능한 코드 한 곳, 아직 어려운 부분을 남긴다.
   - 회고에는 잘한 점·아쉬운 점·다음 행동을 기록한다.

6. **배포 환경에서 다시 확인한다.**
   - Vercel에는 `VITE_API_BASE_URL`, Kakao JavaScript 키를 설정한다.
   - Render에는 DB 값, `JWT_ACCESS_SECRET`, `CORS_ORIGINS`를 설정한다.
   - `/health`, 목록 조회, 로그인, 핵심 사용자 흐름을 배포 URL에서 다시 확인한다.

## 문제가 생겼을 때 되돌아갈 순서

| 증상 | 먼저 확인할 곳 | 다음 조치 |
| --- | --- | --- |
| 화면에 데이터가 안 보임 | 브라우저 Network, `VITE_API_BASE_URL` | Render `/health`와 목록 API를 직접 확인 |
| CORS 오류 | Render `CORS_ORIGINS` | Vercel 주소를 프로토콜까지 포함해 등록 후 재배포 |
| 로그인 실패 | 프론트 요청 URL, `ENABLE_DEV_LOGIN` | 상대 경로가 아닌 공통 API 클라이언트를 사용하는지 확인 |
| DB 연결 실패 | `DB_HOST`, `DB_PORT`, DB 공개 접속 주소 | Railway 내부 주소가 아닌 Public URL의 호스트·포트 사용 |
| 데이터 이전 실패 | SQL 파일 인코딩, 대상 DB 상태 | PowerShell 텍스트 파이프 대신 Docker 컨테이너에서 SQL 파일 직접 import |

## 완료 확인 기준

- [ ] 테스트와 프론트 build가 통과한다.
- [ ] 새로고침 후에도 DB 데이터가 남는다.
- [ ] 화면·API·DB를 거치는 핵심 흐름을 배포 주소에서 실행했다.
- [ ] 비밀 값과 SQL 백업 파일을 Git에 올리지 않았다.
- [ ] 커밋, PR, 회고에 검증 근거를 남겼다.
