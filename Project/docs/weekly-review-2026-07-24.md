## 이번 주에 실제로 끝낸 사용자 흐름

1. 방장이 공동구매 글을 작성하면 총 금액과 모집 인원을 기준으로 1인 금액이 계산되고 MySQL에 저장된다.
2. 이웃은 모집 중인 글에 참여하거나 참여를 취소할 수 있다. 정원이 차면 모집 상태가 완료로 바뀐다.
3. 방장은 주문 완료 → 픽업 가능 → 공동구매 완료 순서로 상태를 바꾼다.
4. 참여자는 픽업 가능 상태에서 수령 완료를 기록한다. 모두 수령 완료해야 방장이 공동구매를 종료할 수 있다.
5. 마이페이지에서는 내가 만든/참여한 공동구매를 전체·진행 중·마감으로 나눠 본다.
6. 마감 시간을 넘긴 모집 중 공동구매는 스케줄러가 `FAILED`로 자동 전환한다.

## 이번 주 회고

처음에는 화면 기능을 늘리는 데 집중했지만, 이번 주에는 “버튼을 눌렀을 때 DB에 남고 다시 화면에 보이는가”를 기준으로 기능을 확인했다. 특히 테스트를 먼저 작성하니 완료 기준이 분명해졌고, Agent에게도 모호하지 않은 요구사항을 전달할 수 있었다. 다음 주에는 외부 API 키처럼 코드 밖에서 막히는 부분을 체크리스트로 먼저 확인하겠다.
