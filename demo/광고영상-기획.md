# Mealyze 데모데이 30초 소개 영상 — 기획

## 이 문서의 위치에 대해

프로젝트 문서(`docs/` 4개 파일)에는 넣지 않았다. 이건 제품 문서가 아니라 **데모 당일에만 쓰는
발표 자료**이고, 영상 본체(`ad30.html`)와 같은 폴더에 있어야 둘이 같이 움직인다. 나중에 프로젝트
기록으로 남길 가치가 생기면 `docs/04-프로젝트설명.md`로 접어 넣으면 된다.

## 1. 목표와 제약

| 항목 | 내용 |
|---|---|
| 길이 | **정확히 30.0초** (루프 재생 가능) |
| 화면비 | **16:9 / 1920×1080** — 데모데이 빔프로젝터 기준 |
| 등장인물 | **없음.** 앱 화면 재현만 |
| 소리 | **없음.** 발표자가 말하는 동안 뒤에 트는 것을 전제 |
| 자막 | 한글, 프로젝터에서 읽히도록 본문 최소 32px(1080p 기준) |

**"사람 안 나오게 앱 실행 상황을 재현"** 을 어떻게 풀었는지:
실기기 화면 녹화 대신 **앱의 실제 디자인 토큰(`src/styles/theme.js`)과 실제 컴포넌트 구조로 화면을
다시 그려서** 타임라인에 맞춰 자동 재생시켰다. 손가락도 사람도 안 나오고, 탭·입력은 화면 안의
누름 효과로만 표현한다. 실기기 녹화보다 나은 점 세 가지:

- 30초 안에 딱 맞춘다 (녹화는 매번 길이가 다르다)
- 네트워크 지연·로딩 실패·오타 없는 화면이 **항상 똑같이** 나온다
- 시연 중 앱이 느려도 영상은 영향받지 않는다

## 2. 소개할 핵심 기능 — 4개만

30초에 다 넣으면 아무것도 안 남는다. **사용자가 겪는 순서 그대로 4단계**만 보여준다.

| # | 기능 | 넣은 이유 |
|---|---|---|
| ① | 사진 촬영 → 음식·양 자동 인식 | 이 앱을 쓰는 **유일한 입구**. 여기가 안 와닿으면 뒤는 의미 없다 |
| ② | 식약처 공식 데이터 기반 영양 계산 | **다른 앱과 갈리는 지점.** "AI가 대충 찍은 숫자"가 아니라는 근거 |
| ③ | 오늘 부족한 영양소 진단 | 기록만 하는 앱이 아니라 **판단해주는** 앱이라는 증거 |
| ④ | 부족분을 채워줄 근처 식당 추천 | 진단이 **행동으로 이어지는** 마무리. 이 앱만 하는 것 |

### 뺀 것과 이유

| 뺀 기능 | 이유 |
|---|---|
| 레벨·경험치·뱃지·퀘스트·리더보드 | 재미 요소지 **구매 이유가 아니다.** 30초에서 6초를 쓸 값어치가 없다 |
| 학교 급식 자동 연동 | 강력하지만 **설명에 시간이 든다**(학교 등록 → 그날 식단 → 공식 수치). 발표에서 말로 보완 |
| 회원가입·로그인 | 로그인 없이도 다 되는 게 장점인데, 화면에 띄우면 오히려 **가입해야 하는 앱**으로 읽힌다 |
| 데이터 백업/내보내기, 챗봇, 퀴즈, 바코드 | 부가 기능. 있으면 좋지만 첫인상에 넣을 자리가 아니다 |

## 3. 30초 타임라인

| 시간 | 장면 | 폰 화면 | 자막(큰 글씨 / 작은 글씨) |
|---|---|---|---|
| **0.0 – 3.2** | 훅 | 1.5초에 폰이 떠오르고 2.4초에 홈 화면이 켜진다 | **오늘 뭘 먹었는지는 알아도** / 뭐가 부족한지는 모릅니다 |
| **3.2 – 9.0** | ① 촬영 | 촬영 버튼 누름 → 사진이 슬롯을 채움 → 분석 시작 → 분석 중 화면 | **사진 한 장이면 끝** / 찍기만 하면 음식과 먹은 양을 알아서 알아냅니다 |
| **9.0 – 15.2** | ② 분석 | 결과 카드가 같은 자리에서 교체 · 686kcal 카운트업 · 영양소 6개 막대가 차례로 채워짐 | **어림짐작이 아닙니다** / 식약처 공식 영양 데이터에서 실제 값을 찾아옵니다 |
| **15.2 – 21.0** | ③ 진단 | 식단 탭으로 슬라이드 · 부족 항목(단백질·식이섬유)이 주황으로 · "얼마나 더 필요한지" 문구 | **오늘 부족한 게 뭔지 바로** / 칼로리 말고 6가지 영양소를 한눈에 |
| **21.0 – 26.2** | ④ 추천 | 지도 탭 · 핀이 떨어지고 · 하단 시트가 올라오며 식당 3곳 | **부족한 걸 채워줄 / 식당까지** / 지금 있는 위치에서 가까운 순으로 알려줍니다 |
| **26.2 – 30.0** | 클로징 | 폰이 사라지고 로고 + 앱 이름 | **찍고, 알고, 채운다** / Mealyze |

### 장면 안 세부 동작 (② 구간이 이 영상의 클라이맥스)

```
 9.0   결과 카드가 촬영 카드 자리를 그대로 대체 (앱의 실제 동작과 같음)
 9.4   "식약처DB" 파란 배지 + "정확도 높음" 배지가 먼저 뜬다  ← 근거를 먼저 보여준다
 9.8   총 칼로리 0 → 686 카운트업 (1.2초)
10.6   영양소 막대 6개가 0.18초 간격으로 차례로 채워짐 — 식이섬유만 주황
13.6   저장하기 버튼 누름 효과
```

**왜 배지를 숫자보다 먼저 띄우는가**: 이 영상에서 파는 건 "숫자가 나온다"가 아니라
**"이 숫자를 믿어도 된다"** 다. 숫자가 먼저 나오면 그냥 또 하나의 칼로리 앱이 된다.

**왜 식이섬유 막대만 주황인가**: 여기서 부족했던 항목이 ③에서 "19g 더 필요해요"가 되고,
④에서 "식이섬유 ↑" 태그가 붙은 식당 추천으로 이어진다. 네 장면이 **한 사람의 하루**로 읽히게
숫자를 전부 맞춰놨다:

| | 값 | 이어지는 곳 |
|---|---|---|
| 아침까지 누적 | 700 kcal (홈 "오늘 요약" 33%) | + 이번 끼니 |
| 이번 끼니 | 686 kcal (제육볶음·쌀밥·배추김치) | = |
| 하루 누적 | 1,386 / 2,150 kcal (식단 탭) | 부족 3개 |
| 부족 항목 | 단백질 20g · 식이섬유 19g | 지도 탭 추천 근거 |

⚠️ 숫자를 하나 고치면 **네 화면을 같이 고쳐야 한다.** 값은 `ad30.html`의 `MEAL` / `DAY` /
`PLACES` 상수와 홈 화면 "오늘 요약" 카드에 흩어져 있다.

## 5. 재생·녹화 방법

### 방법 A — 그냥 HTML을 띄운다 (**데모 당일 이걸 추천**)

```
demo/ad30.html 을 크롬으로 열고 → F 키(전체화면) → Space 로 재생
```

- 영상 파일 변환·인코딩이 필요 없다
- 화질이 화면 해상도 그대로다 (압축 손실 없음)
- 노트북만 있으면 되고 **인터넷도 필요 없다**
- `L` 키를 누르면 무한 반복 — 부스 배경으로 계속 틀어둘 때

### 방법 B — 영상 파일(.webm)로 뽑는다

같은 페이지 우하단 **`영상으로 저장`** 버튼 → 크롬이 "탭 공유" 창을 띄우면
**이 탭**을 선택 → 30초 뒤 자동으로 `mealyze-30s.webm` 파일이 다운로드된다.
(크롬 기본 기능만 쓴다. 별도 프로그램 설치 없음)

mp4가 꼭 필요하면 이 저장소엔 변환 도구가 없으므로 온라인 변환기나 별도 설치가 필요하다 —
**대부분의 경우 방법 A로 충분하니 굳이 안 만드는 걸 권한다.**

### 조작키

| 키 | 동작 |
|---|---|
| `Space` | 재생 / 일시정지 |
| `R` | 처음부터 다시 |
| `F` | 전체화면 |
| `L` | 반복 재생 켜기/끄기 |
| `←` `→` | 1초 뒤로 / 앞으로 |
| `H` | 하단 조작 버튼 숨기기 |

주소 뒤에 붙이는 옵션:

| 옵션 | 동작 |
|---|---|
| `?clean=1` | 조작 버튼 없이 바로 반복 재생 (녹화·부스 배경용) |
| `?t=12.5` | 그 시점 한 장면만 멈춰서 보여준다 (자막 확인, 발표자료용 스크린샷 뽑을 때) |
| `?t=24&clean=1` | 둘을 같이 쓰면 조작 버튼 없는 정지 화면 |

## 6. 데모 당일 운영

- **발표 시작 3분 전에 한 번 재생해 본다.** 폰트·이미지가 다 뜨는지 확인하는 용도
- 노트북 화면비가 16:9가 아니어도 자동으로 맞춰 축소되니 그대로 두면 된다
- 영상이 도는 30초 동안 발표자가 말할 것 = 자막에 없는 것:
  - **왜 만들었나** (학식 먹으면서 오늘 뭐가 부족한지 몰랐다)
  - **얼마나 정확한가** (실제 메뉴 이름 667개로 측정, DB 도달률 63.3%)
  - **어디까지 됐나** (웹 배포 완료, 안드로이드 앱 배포용 파일 서명까지 완료)
- 영상이 끝나면 **실기기로 바로 넘어간다.** 영상은 문맥을 깔아주는 용도지 시연을 대신하지 않는다

## 7. 유지보수

앱 화면이 바뀌면 `ad30.html` 안의 `/* ===== 앱 화면 =====` 구역만 고치면 된다.
색·간격·둥근 정도는 `src/styles/theme.js` 값을 그대로 옮겨 적어놨고, 파일 맨 위 `:root` 변수
한 곳에 모여 있다 — theme.js가 바뀌면 여기 변수만 맞추면 전체가 따라온다.
