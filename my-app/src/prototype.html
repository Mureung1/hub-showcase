이 화면이 보여주는 것

① 동네 핫딜 (Tab 1)

  • 돌발 상황을 4개 태그로 분류, 상단 필터 칩으로 태그별 조회
  • 첫 카드 썸네일의 "재능헬퍼 결과물" 배지 — Tab2 결과물이 Tab1 홍보 이미지로 재사용되는 선순환 구조
  • 마감 시각·남은 수량 표기로 당일성 강조, 지역은 프리셋 드롭다운(○○대 앞)
기획서 3-2절 · 7절 태그 체계 대응

② 핫딜 올리기 + AI (Tab 1)

  • 사장님은 상황 한 줄만 입력 → 홍보 문구·태그 자동 생성
  • 사진이 없으면 재능헬퍼 결과물이 자동 첨부 — 선순환의 실제 접점
  • AI 초안은 반드시 사장님 확인 후 게시 — 자동 게시 아님
기획서 8절 AI 활용 방침 · 9절 리스크 4번 대응

③ 재능 헬퍼 (Tab 2 · 핵심)

  • 학생 스킬 ↔ 식사권 물물교환 피드 — 본 서비스의 진짜 차별점
  • 보상을 절취선 있는 식권 티켓으로 시각화 (서비스 시그니처)
  • 상태 배지(모집중·지원 수 / 매칭완료)로 채팅 없이 상태값만으로 운영
기획서 3-1절 · 첫 번째 카드를 누르면 상세 화면

④ 요청 상세 = 신뢰 장치의 집합

  • 상단 스텝바: 요청등록 → 매칭 → 완료대기 → 완료·지급 상태값 흐름
  • 기대 결과물 예시가 상세에 고정 노출 — 기대치 분쟁 예방
  • 수정 1회 규칙 + 양측 확인 버튼 + 무응답 자동 처리 안내
기획서 6절 신뢰·분쟁 장치 · 시나리오 A/B 대응 · "헬퍼 확인하기"를 누르면 완료 화면

⑤ 완료 · 상호 평점 (신규)

  • 양측 확인 성립 → 식사권 지급 완료 티켓이 초록으로 전환
  • 별점 + 한줄후기 상호 평점 — 결제 없는 구조의 신뢰 자산
  • 결과물이 학생 포트폴리오에 자동 저장 — 가치 비대칭 리스크의 비금전 보상
기획서 6절 5항 · 9절 리스크 1번 대응 · 시나리오 A-6 / B-4

⑥ 요청 등록 폼

  • 분쟁 예방 규칙을 필드 자체에 내장: 기대 예시 첨부 필수, 수정 1회 기본 명시
  • 식사권 수량 스테퍼에 시세 힌트(보통 4~6장) — 보상 기준점 제공
  • 태그·완료 희망일·지역 프리셋 — Tab2 게시글 필드 상세설계의 초안
