## 진행 원칙

- 하루 3~4시간이라 세션당 **작업 1~2개**로 제한한다. 끝나지 않으면 다음 세션으로 넘기지 말고 범위를 좁힌다.

- 네이버 블로그 실 연동, 사진 분석(이미지 업로드 후 AI 배치 추천), 실제 발행 연동은 12일 범위에서 제외하고 **7. 이후 과제**로 이월한다. 시간이 남으면 앞당겨도 됨.
- LLM 연동은 브랜드 요약/키워드, 홍보글, 공지사항, 브리핑 추천 문구, 발행 시간 추천 이유 순으로 우선순위를 둔다.

12개 Day를 성격별로 5개 스프린트로 묶는다. 스프린트 단위로 "여기까지는 끝내자"는 체크포인트로 쓴다.

| 스프린트 | 기간 | Day | 목표 |
| --- | --- | --- | --- |
| Sprint 1 — 프론트 마무리 | 07-13 ~ 07-14 | Day 1~2 | 공지사항 화면 추가, 전체 페이지 라우팅 연결 |
| Sprint 2 — 백엔드 구축 | 07-15 ~ 07-22 | Day 3~7 | Express 서버 셋업 + BrandProfile/Post/예약발행/브리핑/인사이트 API (콘텐츠는 규칙 기반) |
| Sprint 3 — 프론트-백엔드 연동 | 07-23 ~ 07-27 | Day 8~9 | 목업 훅을 실제 API 호출로 전면 교체 |
| Sprint 4 — LLM 연동 | 07-28 ~ 07-29 | Day 10~11 | LLM 폴백 구조 설계 + 생성 기능 전반에 연결, 프롬프트 다듬기 |
| Sprint 5 — 통합 점검 | 07-30 | Day 12 | e2e 테스트, 예외 처리, README 정리 |

**스프린트 완료 기준**

- Sprint 1: 온보딩부터 예약 발행까지 화면 이동이 mock 데이터로나마 끊기지 않고 전부 연결됨
