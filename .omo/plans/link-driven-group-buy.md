## 목표

상품을 먼저 검색해 기존 모집 글과 비슷한 모집을 확인하고, 적절한 글이 없으면 상품 링크를 이용해 새 공동구매 글을 작성한다. 링크에서 상품명·대표 이미지·가격을 가능한 범위에서 자동으로 불러오고, 무료배송 금액을 채우기 위한 최소 모집 인원을 계산해 제안한다.

## 사용자 흐름

1. `/group-buys`의 넓어진 검색창에 상품명을 입력한다.
2. 정확히 일치하는 검색 결과와 함께 `비슷한 공동구매 추천`을 최대 3개 확인한다.
3. 참여할 글이 없다면 `새 공동구매 만들기`를 눌러 `/group-buys/new`로 이동한다.
4. 상품 링크를 붙여 넣고 `상품 정보 불러오기`를 누른다.
5. 서버가 상품명, 대표 이미지, 가격을 가능한 만큼 찾아 채운다.
6. 사용자는 자동 입력된 내용을 직접 수정하고 1인당 수량과 무료배송 기준 금액을 입력한다.
7. 화면이 `무료배송을 위해 최소 4명이 필요해요`처럼 추천 인원을 보여준다.
8. `4명으로 적용`을 누르면 목표 인원이 바뀌고, 저장 후 목록과 상세 화면에서 상품 이미지와 정보가 보인다.

## 확정한 기준

- 실제 LLM API는 추가하지 않는다. 현재 데이터에서 상품명과 카테고리를 비교하는 예측 가능한 추천을 사용하고 UI에는 `비슷한 공동구매 추천`으로 표현한다.
- 검색 결과와 추천을 동시에 노출한다. 정확한 결과가 없어도 추천은 보여주며, 새 글 작성 버튼은 항상 이용할 수 있게 한다.
- 추천 대상은 `모집 중`인 다른 공동구매이며 최대 3개다.
- 유사도는 정규화한 검색어의 부분 일치, 상품명 토큰 일치, 카테고리 일치 순으로 점수를 계산한다. 동일한 점수는 모집 달성률이 높은 순으로 정렬한다.
- 링크 자동 분석은 보조 기능이다. 실패하거나 일부 값만 나와도 작성 화면은 그대로 사용 가능하다.
- 상품 URL, 이미지 URL, 상품명, 가격 등 자동 입력값은 모두 수정할 수 있다.
- 가격은 원화 정수만 사용한다. 여러 가격이 있으면 JSON-LD의 판매가, Open Graph/meta 상품 가격 순으로 사용한다.
- 1인당 수량 기본값은 1이다.
- 추천 목표 인원은 `ceil(무료배송 기준 금액 / (상품 단가 × 1인당 수량))`로 계산하고, 기존 목표 인원을 자동 덮어쓰지 않는다.
- 무료배송 기준이 없거나 0이면 추천을 표시하지 않는다. 계산 결과는 기존 서버 허용 범위인 2~50명 안에서만 적용한다.
- `shippingFee`는 기존 정산 호환성을 위해 유지한다. 무료배송 추천 인원을 적용한 새 글은 배송비 기본값을 0원으로 제안하되 사용자가 수정할 수 있다.
- 기존 글은 신규 컬럼이 없어도 정상 표시되도록 모든 신규 DB 컬럼을 nullable/default 방식으로 추가한다.

## 작업 2. 안전한 상품 링크 미리보기 서버 기능

**파일**

- `server/product-preview.js` 신규
- `server/product-preview.test.js` 신규
- `server/demo.js`
- `package.json`

**API**

- `POST /api/products/preview`
- 인증 필요
- 요청: `{ "url": "https://..." }`
- 성공: `{ "product": { "sourceUrl", "title", "imageUrl", "unitPrice" }, "warnings": [] }`
- 일부 추출 성공도 HTTP 200으로 응답하며 없는 값은 `null`로 반환한다.
- URL이 잘못되었거나 안전하지 않으면 400, 시간 초과/외부 사이트 실패는 422로 응답한다.

**추출 우선순위**

- 제목: JSON-LD `Product.name` → `og:title` → `<title>`
- 이미지: JSON-LD `Product.image` → `og:image` → `twitter:image`
- 가격: JSON-LD `Offer.price` → `product:price:amount` 계열 meta
- 상대 이미지 주소는 최종 상품 URL 기준의 절대 주소로 변환한다.

**보안 제한**

- `http`와 `https`만 허용하고 사용자정보가 포함된 URL은 거부한다.
- URL은 최대 2,048자, 이미지 URL은 최대 2,048자로 제한한다.
- 기본 포트 외 비표준 포트는 거부한다.
- DNS 조회 결과가 loopback, private, link-local, multicast, reserved, IPv4-mapped IPv6에 해당하면 요청하지 않는다.
- 리다이렉트는 자동 추적하지 않고 최대 3회 직접 처리하며 매 단계의 URL과 DNS를 다시 검사한다.
- 5초 후 요청을 중단하고 응답 본문은 최대 1MB까지만 읽는다.
- `text/html` 또는 `application/xhtml+xml`만 분석한다.
- 요청마다 재조회한 허용 IP로 연결되는지 확인해 DNS rebinding 가능성을 낮춘다.
- 간단한 메모리 기준 사용자별 요청 제한(예: 1분 10회)을 적용하고 서버 재시작 시 초기화한다.
- HTML 파싱은 정규식 누적보다 검증된 소형 파서 의존성을 선택하고 잠금 파일까지 반영한다.

**완료 기준**

- 공개 HTTPS 상품 페이지의 일부 메타데이터를 반환한다.
- localhost, `127.0.0.1`, 사설 IP, 자격정보 포함 URL, 사설 IP로 향하는 리다이렉트를 차단한다.
- 느린 응답, 큰 응답, HTML이 아닌 응답에서 서버가 멈추지 않고 한국어 오류를 반환한다.
- 외부 네트워크 없이 fixture 기반 단위 테스트가 실행된다.

**수동 시나리오**

1. 로그인 후 `단백질 쉐이크`를 검색해 정확 결과와 유사 추천을 확인한다.

4. 상품 단가 15,000원, 1인당 1개, 무료배송 50,000원을 입력해 4명 추천을 확인하고 적용한다.
5. 저장 후 목록과 상세에서 이미지, 목표 4명, 상품 정보가 보이는지 확인한다.
6. 새로고침 및 Express 재시작 후 같은 데이터가 유지되는지 확인한다.
7. localhost URL과 깨진 상품 링크를 입력해 차단/직접 입력 fallback을 확인한다.
8. 기존 글의 조회·참여·수령장소 투표가 계속 동작하는지 확인한다.

**배포 호환 순서**

1. nullable/default 컬럼 마이그레이션 적용
2. 하위 호환되는 Express 서버 배포
3. React 프론트엔드 배포

롤백 시 프론트와 서버는 신규 필드를 무시할 수 있고, 추가 컬럼은 즉시 삭제하지 않는다.

## 이번 범위에서 제외

- 실제 AI/LLM 추천 API
- 쇼핑몰별 전용 크롤러와 로그인이 필요한 상품 페이지
- 결제, 주문, 배송 추적 자동화
- 무료배송 달성 시 실제 주문을 자동 실행하는 기능
- 이미지 파일 자체를 Supabase Storage에 복사하는 기능
