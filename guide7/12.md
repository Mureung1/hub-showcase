# 7월 12일 작업 가이드: 기획 재검토와 검증 기준 설립

## 1. 문서 목적

이 문서는 **MBTI 기반 공부법 및 스트레스 관리 웹앱**을 현재 형태로 재구성한 사고 과정과 구현 흐름을 기록합니다.

이번 작업의 핵심은 MBTI 유형별 공부법을 곧바로 정답처럼 제시하는 것이 아니라, 다음 연구 질문을 검증할 수 있는 제품·데이터 구조를 만드는 것이었습니다.

> 과제와 현재 상태만 이용한 추천에 MBTI 정보를 추가했을 때, 실제 학습 실행과 지연 학습성과, 스트레스 관리 결과가 추가로 개선되는가?

따라서 현재 앱은 완성된 MBTI 진단 서비스가 아니라, **기초 추천과 MBTI 추가 추천을 비교하고 결과 자료를 축적하기 위한 연구 지향 프로토타입**입니다.

## 2. 작업 전 아이디어와 발견한 문제

### 2.1 출발점

초기 아이디어에는 다음 목표가 함께 포함되어 있었습니다.

- MBTI와 인지과학적 학습 과정을 연결한 자료 수집
- 사용자 평가를 누적하여 MBTI와 공부법의 관계를 개선
- 공부법, 스트레스 관리, 시간표, 포모도로, 인강 커리큘럼, 논문 탐색으로 확장
- 에브리타임이나 학교 사이트의 부가 기능으로 발전
- 로그인과 저장 기능을 바탕으로 장기 데이터 확보

### 2.2 기획상 핵심 위험

검토 과정에서 다음 문제를 명시적으로 분리해야 한다고 판단했습니다.

1. **자체 문항을 공식 MBTI 검사처럼 제시할 수 없음**
   - 공식 검사지 문항을 복제·변형하여 사용하는 것은 허가와 저작권·상표 검토가 필요합니다.
   - 짧은 자체 문항만으로 공식 MBTI 유형을 정확히 판정한다고 주장할 근거도 부족합니다.

2. **사용자 만족도는 알고리즘 정확도가 아님**
   - 추천이 마음에 든다는 평가와 실제 학습성과 개선은 서로 다른 결과 변수입니다.
   - 만족도, 이해도, 실행 가능성은 제품 경험 지표로만 따로 기록해야 합니다.

3. **MBTI별 공부법 매칭은 learning-styles 오류를 반복할 수 있음**
   - 개인이 선호하는 방식과 그 방식이 실제 성과를 높이는지는 다릅니다.
   - 유형별 맞춤 추천의 효과는 비교 실험 없이 전제해서는 안 됩니다.

4. **MBTI 추가 가치의 비교 기준이 없었음**
   - MBTI를 사용한 모델만 제시하면, MBTI 없이도 같은 추천이 나왔는지 판단할 수 없습니다.
   - 먼저 `task/state-only baseline`을 만들고 MBTI 정보를 추가했을 때의 증분 가치를 측정해야 합니다.

5. **선택적으로 들어오는 만족도 자료에는 NMAR 위험이 있음**
   - 만족하거나 불만족한 사용자만 응답할 가능성이 있어 결측이 무작위가 아닐 수 있습니다.
   - 응답률, 이탈률, 지연 추적, 결측 민감도 분석을 함께 설계해야 합니다.

## 3. 사용자 의도 재해석과 기준 설립

추가 논의를 통해 입력 절차와 ‘정확도’의 의미를 다음처럼 재정의했습니다.

### 3.1 입력 절차

1. 사용자가 외부의 공식 평가에서 얻은 MBTI 결과가 있으면 직접 입력합니다.
2. 공식 결과가 없으면 입력하지 않고 계속할 수 있습니다.
3. 앱의 짧은 공부 습관 자체 검사는 학습 상황과 선호 단서를 파악하는 **독자적인 문항**입니다.
4. 자체 검사에서는 MBTI와 비슷한 네 축의 탐색적 신호를 계산할 수 있지만, 공식 MBTI 판정으로 표시하지 않습니다.
5. 탐색적 신호가 불분명하면 억지로 이분하지 않고 `X`를 허용합니다.

### 3.2 정확도의 의미

여기서 목표로 삼는 정확도는 “짧은 검사로 공식 MBTI를 맞히는 정확도”가 아닙니다.

- 축적된 MBTI 자기보고와 활동·생활·학습 지표 사이에 재현 가능한 관계가 있는지 검증
- MBTI 정보가 과제·상태 기반 모델을 넘어 추가 설명력 또는 예측력을 가지는지 검증
- 추천 이후의 실행률, 지연 학습성과, 스트레스 회복 결과가 실제로 개선되는지 검증
- 결과가 다른 표본과 시점에서도 반복되는지 검증

즉, MBTI의 유용성은 **귀납적으로 축적된 관찰 및 비교 실험 결과**로 판단하며, 미리 사실로 가정하지 않습니다.

### 3.3 문항 개발 원칙

- 공식 문항을 복제·축약·의역하지 않는 clean-room 방식으로 독자 문항을 개발합니다.
- 문항마다 측정하려는 학습 상황, 행동 단서, 해석 한계를 기록합니다.
- 내용 타당도 검토, 인지 인터뷰, 파일럿, 신뢰도와 측정불변성 검토를 거칩니다.
- 공식 MBTI와의 관계를 검증하려면 적법하게 확보한 공식 평가 결과와 별도의 동의 절차가 필요합니다.
- 연구 전에는 법률·라이선스 검토와 연구윤리 절차를 별도로 확인합니다.

### 4.1 `docs/plan.md`

최종 목표를 단일 추천 앱이 아니라 **검증 가능한 개인화 연구 플랫폼**으로 재정의했습니다.

- 공식 MBTI 결과 자기입력 경로와 미입력 경로 분리
- 자체 공부 습관 검사의 역할과 한계 명시
- `task/state-only baseline`과 MBTI 추가 모델 비교
- 만족도와 실제 성과 변수 분리
- 장기적으로 실행률·지연 학습성과·스트레스 결과를 수집하는 구조 제시
- NMAR, 선택 편향, 이탈과 결측 민감도 분석 포함
- 에브리타임·학교 사이트·시간표·포모도로 등은 효과 검증 이후의 확장 단계로 배치

### 4.2 `docs/checklist.md`

기획을 실제 작업 단위로 바꾸었습니다.

- 공식 결과 입력과 탐색적 신호 분리
- 기준 모델과 MBTI 추가 모델의 출력 비교
- 추천 근거와 알고리즘 버전 저장
- 만족도·이해도·실행 가능성 분리 저장
- 결과와 피드백을 `resultId`로 연결
- 개인정보·동의·철회·삭제·보존 정책
- 종단 결과와 결측 분석을 포함한 연구 체크리스트

### 4.3 나머지 관련 문서

- `README.md`: 프로젝트의 현재 정체성, 핵심 경계, 실행법, `plan.md`와 `checklist.md` 링크를 요약

- `docs/prompt-guide.md`: 이후 에이전트가 과도한 MBTI 주장을 만들지 않도록 프롬프트 기준 보강
- `AGENTS.md`, `CLAUDE.md`, `.agents/skills/*`: 동일한 연구·법적 경계를 작업 지침에 반영

## 5. 프로토타입 재설계

### 5.1 입력 모델

- `mbtiSource`: `official-self-report` 또는 `not-provided`
- `officialMbti`: 사용자가 입력한 외부 공식 평가 결과
- `ExploratoryPreferenceProfile`: 자체 공부 습관 문항에서 계산한 비공식 탐색 신호
- 자체 검사 신호는 현재 추천 점수에 직접 투입하지 않아 검증 전의 순환 논리를 피했습니다.

### 5.2 추천 모델 `rules-v2`

기존 규칙은 방법별 점수 척도가 서로 달랐고, 특정 방법이 거의 항상 우세해지는 문제가 있었습니다. 전수 조합 점검에서 `selfExplanation`이 사실상 대부분의 경우 1위였고, 추천마다 같은 근거 문구가 공유되는 현상도 확인했습니다.

이를 다음처럼 수정했습니다.

- 일곱 학습법을 비교 가능한 공통 점수 구조로 정규화
- 학습 과제와 현재 상태를 이용한 baseline 점수 계산
- 공식 MBTI가 입력된 경우에만 작은 크기의 보조 가중치 적용
- MBTI 가중치가 과제·상태 신호를 압도하지 못하도록 상한 설정
- 각 추천의 실제 점수 원인에 따라 `basedOn`과 설명을 동적으로 생성
- 추천 결과에 알고리즘 버전과 사용한 입력 출처 저장

현재 학습법 후보는 다음과 같습니다.

- Retrieval Practice
- Spacing
- Interleaving
- Self-Explanation
- Short Study Blocks
- Error Analysis
- Environment Design

### 5.3 비교 화면

결과 화면에는 다음 두 출력을 함께 표시합니다.

1. 과제·상태만 사용한 기준 추천
2. 공식 MBTI 자기입력 정보를 약하게 추가한 추천

두 결과가 바뀌었다는 사실 자체는 효과 입증이 아닙니다. 변화는 MBTI 정보가 모델 출력에 영향을 주었다는 의미일 뿐이며, 실제 가치는 후속 행동과 성과 자료로 검증해야 합니다.

### 5.4 피드백과 저장

피드백을 하나의 만족도 점수로 합치지 않고 다음 세 항목으로 나누었습니다.

- 적합감
- 이해도
- 실행 가능성

각 피드백은 `resultId`로 해당 추천 결과와 연결하며, 같은 결과에 대한 재응답은 중복 추가 대신 갱신합니다. 저장 자료에는 다음 항목이 포함됩니다.

- MBTI 입력 출처와 공식 결과 자기입력값
- 탐색적 선호 코드
- baseline 추천과 MBTI 추가 추천의 ID
- 알고리즘 버전
- 실천 루틴과 결과 연결 정보

현재 저장은 브라우저 로컬 저장소 기반의 프로토타입입니다. 실제 계정, 서버 데이터베이스, 동의 철회, 삭제 요청, 접근통제는 다음 개발 단계입니다.

## 6. 반례 중심 검증 결과

### 6.1 정적 검사와 빌드

- `npm run lint`: 성공
- `npm run build`: 성공
- `git diff --check`: 성공
- 문서 링크 대상 존재 여부: 확인

### 6.2 저장 로직 검사

가짜 `localStorage` 환경에서 다음 동작을 확인했습니다.

- 결과 저장과 불러오기
- 동일 `resultId` 피드백의 갱신 처리
- 전체 데이터 초기화

### 6.3 추천 규칙 전수 조합 검사

공부 습관 설문의 가능한 19,683개 응답 조합을 생성하고, 각 조합에 MBTI 미입력 및 16개 공식 결과를 적용해 총 334,611개 출력을 점검했습니다.

- `NaN` 또는 비정상 점수: 0
- 한 결과 내 중복 추천: 0
- 추천 간 동일 근거의 잘못된 공유: 0
- 탐색적 코드가 공식 MBTI 입력으로 유출된 경우: 0
- 일곱 학습법 모두 추천 결과에 등장
- MBTI 입력 전후 상위 3개 구성이 달라진 비율: 약 16.9%
- 1순위가 달라진 비율: 약 3.9%

이 수치는 **구현 균형과 규칙 민감도에 대한 점검**입니다. 학습효과나 심리측정 타당도를 입증하는 결과가 아닙니다.

## 8. 현재 범위와 남은 과제

### 현재 구현한 범위

- 공식 MBTI 결과 자기입력 또는 미입력
- 짧은 독자적 공부 습관 자체 검사
- 비공식 탐색 신호
- 과제·상태 baseline과 MBTI 추가 추천 비교
- 로컬 결과·루틴·피드백 저장
- 만족도와 효과 검증의 명시적 분리

### 아직 입증하거나 구현하지 않은 범위

- 공식 MBTI 검사 제공 또는 공식 유형 판정
- 자체 문항의 심리측정 타당도와 공식 평가와의 수렴 타당도
- MBTI 개인화의 학습성과·스트레스 결과 개선 효과
- 서버 계정, 데이터베이스, 동의 철회와 삭제 처리
- 학교·에브리타임·인강·논문 검색 서비스 연동
- 임상적 스트레스 진단 또는 치료 기능

### 다음 우선순위

1. 측정도구와 데이터 사전 확정
2. 동의·개인정보·연구윤리 설계
3. 계정과 서버 저장 구조 구현
4. baseline 대 MBTI 추가 모델의 파일럿 비교
5. 즉시 만족도가 아닌 지연 실행률·학습성과·스트레스 결과 수집
