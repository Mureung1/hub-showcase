# DB 마이그레이션 (Supabase)

이 폴더는 **DB 스키마를 바꾼 SQL을 순서대로 기록**한 곳이다.
"누가 언제 무슨 SQL을 쳤나"를 코드처럼 버전 관리하기 위함.

## 규칙
- 파일은 **번호 순서(0001, 0002, …)** 로 적용한다. 앞에서 뒤로.
- 한 번 적용/커밋한 파일은 **고치지 않는다.** 바꿀 게 생기면 **새 번호 파일**을 추가.
- 각 파일은 "앞으로 나아가는" 변경 하나(테이블 생성, 컬럼 추가 등).

## 적용 이력
| 파일 | 내용 | 적용일 |
|---|---|---|
| `0001_create_interests.sql` | interests 테이블 생성 | 2026-07-20 |
| `0002_add_jd_column.sql` | jd(공고 내용) 컬럼 추가 | 2026-07-20 |

## 어떻게 적용했나
지금은 **Supabase 대시보드 → SQL Editor에 붙여넣고 수동 실행**했다.
→ 그래서 이 폴더는 "무슨 SQL을 쳤는지"의 **기록(수동 관리)**.

## 나중에 자동화하려면 (Supabase CLI)
```bash
supabase migration new create_interests   # 새 마이그레이션 파일 생성
supabase db push                           # 아직 안 올린 마이그레이션을 DB에 적용
```
→ CLI를 쓰면 "어디까지 적용됐나"를 Supabase가 추적해서, 새 파일만 자동으로 올려준다.
