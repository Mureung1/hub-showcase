# 03. Conditional Edges — 되돌아가는 화살표(순환)

> 한 줄 요약: **지금까지 엣지는 "무조건 정해진 다음"이었다. 조건부 엣지는 State를 보고 다음 노드를 고른다 — 그래서 뒤로 되돌아가는 순환(루프)이 처음으로 가능해진다.** Verifier가 "검증 실패면 다시 추출해" 하고 되돌리는 게 바로 이것.

## 왜 이게 필요한가 — Verifier의 자리
미리캣 아키텍처: `Scout → 추출 ⇄ Verifier → Analyst`. 여기서 `⇄`(양방향)가 핵심.
- 추출(Gemini)은 **가끔 틀린다** — 필드를 비워두거나, 원문에 없는 노선을 지어내거나.
- structured output은 *모양*만 보장하지 *내용 정확성*은 아님(→ [[02-structured-output-스키마]]). 그 빈틈을 Verifier가 메운다.
- Verifier = "추출 결과 ↔ 원문 대조. 이상하면 **다시 추출하게 되돌린다.**" 이 "되돌린다"가 순환.

## 지금까지의 그래프엔 왜 순환이 없었나
`mini_graph.py`의 invoke는:
```python
현재 = edges[현재]      # edges = {이름: 다음이름} — 다음이 '하나로 고정'
```
- `edges["extract"] = END` 처럼 다음이 **미리 딱 정해져** 있음. State가 뭐든 무조건 그리로.
- 그래서 scout→extract→END 한 방향밖에 못 감. **State를 보고 갈림길을 고를** 방법이 없었음.

## 조건부 엣지의 원리 = "다음을 함수가 정한다"
고정 엣지: `다음 = edges[현재]` (딕셔너리 조회, 값 하나)
조건부 엣지: `다음 = mapping[ router(state) ]` (**함수가 State 보고 키를 리턴 → 그 키로 다음 결정**)

```
verify 노드 다음엔 ↓
  router(state) 가 "ok" 리턴  → mapping["ok"]    = END
  router(state) 가 "retry" 리턴 → mapping["retry"] = "extract"   ← 되돌아감!
```
- 라우터는 **노드가 아니다.** State를 받아 **문자열(키)만** 리턴하는 판단 함수. 그림을 안 바꾸고 "어느 선을 탈지"만 고른다.
- 되돌아갈 대상이 이미 지난 노드(extract)여도 됨 → 그게 순환.

## 무한루프 방지 = 상한은 필수 짝
되돌아가는 화살표를 만들면 **영원히 돌 위험**이 생긴다 (추출이 계속 실패하면 extract↔verify 무한 왕복).
→ State에 **재시도 카운터**(`tries`)를 두고, 라우터가 `tries >= MAX`면 실패라도 END로 보낸다("포기").
- 조건부 엣지와 카운터는 **항상 세트.** 순환을 열면 반드시 탈출구도 같이 판다.

## invoke 루프는 어떻게 바뀌나 (mini_graph 기준)
지금 한 줄(`현재 = edges[현재]`)이 갈림길을 갖게:
```
다음 정할 때:
  현재 노드가 '조건부 엣지'를 가졌으면 → 라우터(state) 호출해서 키 얻고 → mapping[키]
  아니면 (평범한 고정 엣지) → 기존처럼 edges[현재]
```
- 즉 엣지 저장소가 두 종류가 됨: 고정(`edges`) + 조건부(`cond_edges = {이름: (라우터, mapping)}`).

## 실제 LangGraph 문법 (graph.py에 나중에 얹을 때)
장난감에서 감 잡은 뒤 실제론 이 한 줄:
```python
builder.add_conditional_edges(
    "verify",              # 이 노드 다음에
    route_fn,              # State 보고 키 리턴하는 함수
    {"retry": "extract", "ok": END},   # 키 → 다음 노드 매핑
)
```
- 개념은 mini_graph와 **완전히 같다.** LangGraph는 while 루프를 대신 돌려줄 뿐, 라우터+매핑 구조는 우리가 손으로 짠 그대로.

## 걸리기 쉬운 함정 (미리 기록)
- **탈출구 없이 순환만 열면 무한루프.** 카운터 먼저 설계.
- 라우터가 **State를 바꾸려 하면 안 됨** — 판단만(키 리턴), 값 변경은 노드가. 역할 섞으면 디버깅 지옥.
- `tries` 증가를 **어디서 하냐**(verify 노드에서 +1 vs extract에서) 정해두기. 안 그러면 카운터가 안 늘어 무한루프.
- 라우터가 리턴한 키가 mapping에 없으면 `KeyError` → 키 후보를 mapping과 정확히 맞추기.
