# 미리캣 (Miricat) — 내 출근길의 보초

> 이동 경로 상시 감시 에이전트. 고정 경로를 등록해두면 에이전트가 매일 대신 확인하고,
> 이상 없으면 한 줄 보고 / 영향 있으면 근거 담긴 경보를 보낸다.
> 미어캣 무리가 보초를 세우듯, "내 출근길의 보초".

- 개발자: 정재현 · Naver AI Agent Challenge (2026.07)
- 기간: 2026-07-06 ~ 2026-07-31

## 한 줄 문제 정의
축제·공사·사고·행사로 버스 우회/도로 통제가 생기면 지자체·버스조합 게시판에 **공지가 한 번 올라오고 묻힌다.**
공지 시점과 필요 시점(이동 직전)이 어긋나 있고, 소스도 여러 게시판에 흩어져 있어 사람이 매번 챙기는 건 비현실적.
→ **확인 주체를 사용자에서 에이전트로 넘긴다 (Pull → Push).**

## 절대 원칙 (바꾸지 말 것)
- **예측하지 않는다.** 이미 공지된 사실만 찾아서 경로 맥락과 결합해 전달. 혼잡 예측 금지.
- 이상 없는 날에도 한 줄 보낸다 (+ 확인한 소스·시각). "이상 없음"을 검증 가능한 보고로 만들고, 보초가 서 있다는 증거.
- 모든 경보에 원문 출처를 붙인다.
- 알림 남발 방지: 경보는 드물게, 그래서 한 통이 무겁다.

## 왜 이 스택인가 (정직한 버전)
이 문제의 가장 쉬운 풀이는 크론 잡 + 함수 몇 개 + LLM API 호출이다. 그걸 인정하고 시작한다.
- **LangGraph** — 학습 목적이 절반이다. 상태 기반 오케스트레이션(자기검증 실패 → 재추출 루프)을 실전 규모로 배우는 게 이 부트캠프에서의 목표. 오버엔지니어링 비용을 인지하고 **노드 5개 이하 최소 규모**로만 쓴다. "필요해서 썼다"고 우기지 않는다 — 함수 체인으로도 풀리는 문제다.
- **Langfuse** (셀프호스트) — 이건 학습이 아니라 **개발 도구**. LLM 추출 디버깅("이 공지에서 왜 틀렸지")에 print 대신 트레이싱을 쓰는 것. 리포트의 조사 과정 뷰어 데이터 겸용.
- **평가 하네스** — 공지 10건에 ground truth 라벨 → 프롬프트/모델 바꿀 때마다 추출 정확도 회귀 테스트.
- **LangChain은 안 쓴다.** LangGraph가 딛는 부품(모델 래퍼, 구조화 출력)만 가져다 쓰고 따로 내세우지 않는다.

## 아키텍처
```
[등록 1회] 출발지/도착지/시간대 → 경로 API → 후보 선택
          → 경로 객체 저장 {경유 도로, 이용 노선, 경유 정류장, 좌표열, 시간대} (안 고른 후보도 저장 = 대안용)
          API: GET /api/route-candidates (조회, 저장 없음) / POST /api/routes (등록)

[매일] 스케줄러 → LangGraph 그래프 (Python 워커, API 서버와 분리)
   Planner(관할 소스 결정) → Scout(게시판 탐색 + LLM 구조화 추출)
     ⇄ Verifier(추출 결과 ↔ 원문 대조, 실패 시 Scout로 되돌림, 재시도 횟수 제한)
     → Analyst(4단계 매칭 + 알림 판단) → Reporter(보고/경보/리포트 생성)
   전 단계 Langfuse 트레이싱 · 평가셋으로 추출 회귀 테스트
       │ 경보 or 매일 확인 보고
   디스코드 웹훅 ──링크──▶ 웹(경로 등록 + 리포트 열람실)
```

### 감시 소스 (2층)
- **Tier 1 — 공식 통제/우회 공지 (영향 확정):** 대전광역시 교통 공지, 대전버스운송조합, 세종교통공사. 비정형 → LLM 추출.
- **Tier 2 — 인파 이벤트 일정 (영향 가능성):** KBO 대전 경기 일정(정형·쉬움), 콘서트. "일정이 있고 시공간이 겹친다"까지만. 무예측 유지.

### 4단계 매칭
1. 노선 (공지의 "B1 우회" ↔ 내 이용 노선) — 문자열, 확실
2. 정류장 (미정차/이설 ↔ 내 경유 정류장)
3. 도로명 (통제 도로 ↔ 내 경유 도로, 자차용)
4. 반경 (폴백: 지오코딩 + 좌표열 거리 + 기간 겹침) — 애매한 것 안전망

### 알림 정책
- 경보: Tier1은 매칭되면 바로. Tier2는 규모+근접+시간 다 겹칠 때만. 반복 이벤트(홈경기)는 유형 음소거 옵션.
- 확인 보고: 영향 없는 날 한 줄. 수준 매일(기본)/주간/영향 시만 (MVP는 매일 고정).

## 기술 스택
- Frontend: React + Vite
- Backend(API 서버): **Express (Node)** — 2주차 미션 지정 스택
- DB: **Supabase** — 스키마 = 경로 객체 / 수집정보 / 알림이력 / 조사기록
- 에이전트: LangGraph — **Python 워커로 분리** (3주차 구축, API 서버 ↔ 에이전트 워커 분리 구조). 스케줄러(APScheduler)는 워커 쪽
- 관측성: Langfuse(docker) · 평가: 공지 평가셋 + 회귀 스크립트
- 경로/지오코딩: 네이버지도 Directions(도로명 포함, 자차) · 대중교통: ODsay(노선번호/정류장) — 검증3에서 4단계 매칭 성립 확인
- 알림: 디스코드 웹훅(MVP). 메일/텔레그램은 확장

## 데모 시나리오
1. **메인 (Tier1):** 갑천도시고속도로 경유 경로 등록 → 첫날 "이상 없음" → 원촌육교 통제 공지(실제 3월 원문) 주입 → 그래프 조사 실시간 흐름(Verifier 통과 포함) → 디스코드 경보 → 리포트(통제구간 지도 + "경로 B로 우회하세요" + 조사 과정). **클라이맥스 = 리포트.**
2. **보조 (Tier2):** 대전역 인근 경로 → 당일 한화 홈경기 감지 → "이동 시간대에 경로 인근 경기(18:30, KBO)" 알림. 실데이터 라이브.

# UI / 디자인

## ⚠️ 사용자 UI 원칙 (대화에서 확정 — 매우 중요)
- **일반인 대상 서비스다. 화면에 개발자 용어를 절대 노출하지 않는다.**
  - ❌ LangGraph, Langfuse, Verifier, Planner/Scout/Analyst/Reporter, JSON, trace, Tier1/Tier2
  - ✅ "미리캣이 확인하는 중", "살펴볼 곳 정하기 → 공지 찾아보기 → 내용 다시 확인 → 내 경로와 맞춰보기 → 결과 알려주기"
  - ✅ 추출 결과는 JSON 대신 "💬 쉽게 말하면…" 한 문장 요약
  - ✅ 조사 과정은 "미리캣이 이렇게 확인했어요" (담당 노드명 없이 문장)
  - → 기술 스택 스토리(LangGraph/Langfuse/평가셋)는 **발표자료(심사위원용)에서만** 강조. 제품 UI에는 안 넣는다.
- **캐릭터(미어캣)는 무조건 등장.** 브랜드 핵심.
- 가짜 브라우저 크롬(신호등 점 + URL 주소창)을 카드에 넣지 않는다 — "웹 속의 웹"처럼 어색함.
- 데모는 단일 화면에 다 욱여넣지 말고 **사용자가 겪는 흐름대로 여러 화면**으로.
- 대안 경로는 소극적("괜찮아요")이 아니라 **명확한 추천**("오늘은 경로 B로 우회하세요" + 소요시간).
- 리포트 지도에서 막히는 곳은 빨간색, 그 옆에 미어캣이 서서 "지켜보는 중".
- 눈 깜빡임 애니메이션은 시도했다가 **뺐음**(안 예쁨). 두리번 동작·레이더 핑도 뺌. 미어캣은 정적.
