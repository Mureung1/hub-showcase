## 총평

현재 프로토타입은 프론트엔드 1차 MVP로 적합하다.

기획서의 핵심 범위인 홈, 타임테이블, 부스, 부스 상세, 공지 목록, 공지 상세가 모두 구현되어 있고, 백엔드/인증/관리자 기능 없이 정적 mock 데이터로 흐름을 검증한다는 MVP 전제에도 맞는다.

다만 실제 축제 운영에 바로 쓰는 수준은 아니다. 실제 날짜/장소/배치도 이미지/운영 데이터가 아직 없고, 현재 시간과 날씨도 mock 값이다. 따라서 현재 상태는 "사용자 흐름과 UI 구조를 검증하는 1차 프론트엔드 프로토타입"으로 보는 것이 정확하다.

## UX 및 디자인 평가

### 강점

- 홈은 `Today Simple` 방향을 유지하며 한 화면에 과도한 정보를 넣지 않는다.
- 가장 중요한 다음 일정 CTA가 명확하다.
- 하단 내비게이션으로 주요 기능 접근이 쉽다.
- 목록 화면은 행 단위 구분과 충분한 여백으로 모바일 시인성이 좋다.
- 부스 상세는 메뉴와 가격을 빠르게 확인하기 쉽다.

### 개선 필요

- 홈의 `더보기` 탭이 실제로 공지사항으로 연결된다. MVP에서는 동작 가능하지만, 사용자는 `공지` 탭을 기대할 수 있으므로 하단 라벨을 `공지`로 바꾸는 편이 더 명확하다.
- 부스 배치도는 기획서상 핵심 자료인데 현재는 `오늘의 배치도` 텍스트 요약만 있다. 실제 이미지가 들어오면 우선 반영해야 한다.
- 홈의 현재 시간, 날씨, 축제 날짜가 모두 정적 값이다. MVP 데모에는 적합하지만 실제 운영 전에는 데이터 출처를 결정해야 한다.
- 홈에서 "오늘 운영 부스"의 구체 목록은 노출하지 않는다. 디자인 방향에는 맞지만, 사용자 시나리오의 "오늘 운영 중인 부스 빠르게 확인"을 더 강하게 충족하려면 운영 부스 수나 대표 부스 1개 정도를 추가할 수 있다.

## 접근성 리스크

- 버튼은 실제 `button` 요소이고, 주요 아이콘 버튼에는 접근 가능한 이름이 있다.
- 텍스트 대비와 터치 영역은 대체로 양호하다.
- 색상만으로 상태를 전달하지 않고 `운영 중`, `중요` 같은 텍스트를 함께 쓴다.
- 스크린샷만으로 키보드 탐색 순서와 스크린리더 낭독 품질은 완전히 검증할 수 없다. 별도 키보드/스크린리더 점검이 필요하다.

## MVP 적합성 판단

판정: 적합

현재 상태는 1차 MVP의 목적에 맞다.

- 핵심 화면이 모두 존재한다.
- 핵심 흐름이 클릭으로 이어진다.
- 정적 데이터 기반 프론트엔드 MVP라는 범위를 넘지 않는다.
- 디자인 시스템의 모바일 우선, 고시인성, 단순 홈 원칙을 따른다.

출시 전 또는 다음 이터레이션에서 우선 처리할 항목은 다음 순서가 적절하다.

1. 하단 `더보기`를 `공지`로 변경해 정보 구조를 명확히 한다.
2. 실제 축제 데이터 구조를 확정한다.
3. 부스 배치도 이미지를 실제 자산으로 교체한다.
4. 날짜/현재 시간/운영 상태를 실제 데이터 또는 계산값으로 연결한다.
5. 키보드 탐색과 스크린리더 접근성 점검을 추가한다.
