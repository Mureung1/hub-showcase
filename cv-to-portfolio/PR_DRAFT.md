## 주요 작업 리스트

- React(Vite) 최소 환경 구성 — 라우터/상태관리/UI 라이브러리 없이 `react`, `react-dom`만 사용
- **CV → 포트폴리오 생성기** 프로토타입 (`cv-to-portfolio/` 서브폴더), 기능별 커밋 6개
  - `chore` 환경/앱 셸 → `feat` CV 업로드·파싱 → `feat` DESIGN.md 선택 → `feat` 생성 엔진 → `feat` 미리보기·다운로드 → `docs`
- 4단계 흐름: ① CV 업로드 → ② DESIGN.md 테마 선택 → ③ 생성 → ④ 미리보기 & HTML 다운로드
- 디자인 테마 5종 + 샘플 CV 2종 (멀티 에이전트로 생성)
- (스크린샷 첨부 예정) 테마별 생성 결과 화면

## 내가 설명할 수 있는 부분

`generatePortfolio(cv, theme)` 가 핵심입니다. 파싱된 CV 객체와 선택한 테마의
**디자인 토큰**(색·폰트·레이아웃)을 받아, 토큰을 CSS 변수(`:root`)로 주입한
**독립 실행형 HTML 문자열**을 만들어 반환합니다. 레이아웃(single-column/timeline/
two-column/sidebar)과 헤더 스타일에 따라 본문 조립 방식을 분기하고, 사용자 입력은
`esc()`로 이스케이프해 마크업이 깨지지 않게 했습니다. "AI가 생성"하는 느낌은
`Generating` 컴포넌트의 단계 표시로 주되, 프로토타입에선 결정적 렌더러가 즉시
결과를 만들기 때문에 **백엔드·API 키 없이도 브라우저만으로 완결**됩니다.

## 아직 이해 못 한 부분

- 실서비스에서 LLM에 HTML 생성을 맡길 때(`generateWithAI.js` seam), **응답 HTML의
  안전성·일관성 보장** 방법(프롬프트 인젝션·깨진 마크업 대응)을 아직 정리 못 했습니다.
- PDF/DOCX 이력서 파싱은 브라우저만으로 한계가 있어 **문서 변환 파이프라인**을 어디에 둘지
  (클라이언트 vs 서버) 판단이 필요합니다.
- hub 레포의 **참가자별 폴더 컨벤션**을 아직 확인 못 해, 우선 `cv-to-portfolio/`
  서브폴더로 올렸습니다. (다른 위치를 원하면 옮기겠습니다)

## 새로 알게 된 것

- Vite의 `?raw` 임포트로 `.md` 파일을 문자열로 불러와 화면에 그대로 보여줄 수 있다.
- "디자인을 데이터로" 다루면(디자인 토큰) 하나의 렌더러가 여러 테마를 만들어낼 수 있다.
- Claude Messages API는 `x-api-key` + `anthropic-version` 헤더로 호출하며, **API 키는
  절대 브라우저에 노출하면 안 되고** 반드시 백엔드에서 호출해야 한다.
- 사용자 입력을 HTML로 렌더링할 때 `&<>"` 이스케이프가 필수라는 점.
